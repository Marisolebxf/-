# 第一章 OAuth2.0 模块

> 基础路径：`/admin-api/system/oauth2`
>
> 所有接口需要通过 Basic Auth 或请求参数传递客户端凭证（client_id + client_secret）

---

## 通用认证方式

本模块接口统一采用 **Basic Auth** 认证客户端身份，支持以下两种方式传递 `client_id` 和 `client_secret`：

| 方式 | 说明 |
|------|------|
| 请求头 | `Authorization: Basic {base64(client_id:client_secret)}` |
| 请求参数 | `client_id=xxx&client_secret=xxx` |

**示例**：假设 `client_id=default`，`client_secret=admin123`，则 Base64 编码结果为 `ZGVmYXVsdDphZG1pbjEyMw==`，请求头为：

```
Authorization: Basic ZGVmYXVsdDphZG1pbjEyMw==
```

## 流程

### 授权码模式（Authorization Code）

```
1. 用户访问三方应用，三方应用携带client_id、redirect_uri、state重定向到 SSO 登录页（测试环境：https://edu.itic-sci.com/uc/sso/login，生产环境：https://生产环境域名/uc/sso/login）
2. 用户确认授权，前端调用 POST /system/oauth2/authorize 提交授权              ← 接口1.1【由用户中心调用，三方系统无需调用此接口】
3. 获取授权码 code 后，三方服务端调用 POST /system/oauth2/token 换取 token    ← 接口1.2
4. 三方系统使用 access_token 调用业务接口
   - 校验令牌：POST /system/oauth2/check-token                                ← 接口1.3
   - 获取权限：GET /system/oauth2/v1/get-permission-info                         ← 接口1.4
   - 保持续期：POST /system/oauth2/renew-token                                ← 接口1.8（滑动过期，延长 access_token 有效期）
5. access_token 过期后，使用 refresh_token 调用 POST /system/oauth2/token 刷新 ← 接口1.2
6. 用户登出，调用 GET /system/oauth2/logout 撤销令牌                          ← 接口1.5
```

**SSO登录页地址：**：

测试：https://edu.itic-sci.com/uc/sso/login

生产：https://生产环境域名/uc/sso/login



### 门户子系统登录态共享流程

**前提条件**：

- 门户系统已完成上方"授权码模式"登录流程，获取到 `access_token`
- 门户系统将 `access_token` 写入浏览器 cookie
- 子系统与门户部署在同一主域名下，cookie 可在子系统请求中自动携带

**子系统获取登录态与权限信息流程**：

```
1. 门户系统完成 OAuth2.0 授权码登录，获取 access_token，写入浏览器 cookie
2. 用户在浏览器中访问子系统页面（同域名，cookie 自动携带 access_token）
3. 子系统前端从 cookie 中读取 access_token，传递给子系统后端
4. 子系统后端使用 access_token 调用统一用户中心接口校验令牌有效性：
   - POST /admin-api/system/oauth2/check-token?token={access_token}             ← 接口1.3
   返回令牌基础信息（user_id、user_type、tenant_id、client_id、scopes、exp 等）
5. 子系统后端使用 access_token 调用统一用户中心接口获取用户权限信息（如需要）：
   - GET /admin-api/system/oauth2/v1/get-permission-info?token={access_token}    ← 接口1.4
   返回用户主体信息、角色列表、菜单列表、权限标识集合、关联机构列表
6. 子系统根据返回的权限信息，构建本地会话（或直接渲染页面/控制接口访问权限）
7. access_token 失效时（check-token 返回错误或 exp 已过期），提示用户重新登录
```

## 1.1  申请授权

用户在 SSO 授权页面提交授权请求，支持授权码模式。
【**注意：该接口是由用户中心调用，三方系统不需要调。放这里是为了让整个流程更清晰**】

### 基本信息

| 项目 | 说明 |
|------|------|
| URL | `POST /admin-api/system/oauth2/authorize` |
| Content-Type | `application/x-www-form-urlencoded` |
| 认证方式 | Bearer Token（需用户已登录） |
| 是否需要登录 | 是 |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
|--------|------|------|------|--------|
| response_type | String | 是 | 响应类型：`code`（授权码模式） | `code` |
| client_id | String | 是 | 客户端编号 | `default` |
| redirect_uri | String | 是 | 重定向 URI | `https://www.iocoder.cn` |
| state | String | 否 | 状态参数 | `1` |

### 响应结果

**授权码模式（response_type=code）**：返回重定向 URL，URL 中包含授权码

```json
{
  "code": 0,
  "msg": "",
  "data": "https://www.iocoder.cn?code=189956c07a174588a97157eabef2f93a&state=1"
}
```

**用户拒绝授权**：返回错误重定向 URL

```json
{
  "code": 0,
  "msg": "",
  "data": "https://www.iocoder.cn?error=access_denied&error_description=User%20denied%20access&state=1"
}
```

**无法自动授权**：返回空 URL，前端不进行跳转

```json
{
  "code": 0,
  "msg": "",
  "data": null
}
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| data | String | 重定向 URL，前端获取后执行跳转；`null` 表示无法自动授权，需用户手动确认 |

### 请求示例

**授权码模式**：

```http
POST /admin-api/system/oauth2/authorize
Content-Type: application/x-www-form-urlencoded
Authorization: Bearer {{token}}

response_type=code&client_id=default&scope={"user.read":true}&redirect_uri=https://www.iocoder.cn&auto_approve=false
```

## 1.2 获得访问令牌

通过不同授权模式获取访问令牌（access_token）。

### 基本信息

| 项目 | 说明 |
|------|------|
| URL | `POST /admin-api/system/oauth2/token` |
| Content-Type | `application/x-www-form-urlencoded` |
| 认证方式 | Basic Auth |
| 是否需要登录 | 否 |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
|--------|------|------|------|--------|
| grant_type | String | 是 | 授权类型，可选值：`authorization_code`、`refresh_token` | `authorization_code` |
| code | String | 是 | 授权码 | `189956c07a174588a97157eabef2f93a` |
| redirect_uri | String | 是 | 重定向 URI（授权码模式必填） | `https://www.test.cn` |
| state | String | 否 | 状态参数 | `1` |
| refresh_token | String | 否 | 刷新令牌（grant_type=refresh_token时必填） | `00895465d6994f72a9d926ceeed0f588` |

### 各授权模式参数组合

| 授权模式 | grant_type | 必填参数 | 可选参数 |
|----------|-----------|----------|----------|
| 授权码模式 | `authorization_code` | code, redirect_uri | state |
| 刷新模式 | `refresh_token` | refresh_token | - |

### 响应结果

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "access_token": "620d307c5b4148df8a98dd6c6c547106",
    "refresh_token": "00895465d6994f72a9d926ceeed0f588",
    "token_type": "bearer",
    "expires_in": 42430,
    "scope": "user_info"
  }
}
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| access_token | String | 访问令牌 |
| refresh_token | String | 刷新令牌 |
| token_type | String | 令牌类型，固定为 `bearer` |
| expires_in | Long | 过期时间，单位：秒 |
| scope | String | 授权范围，多个使用空格分隔 |

### 请求示例

**授权码模式**：

```http
POST /admin-api/system/oauth2/token
Content-Type: application/x-www-form-urlencoded
Authorization: Basic ZGVmYXVsdDphZG1pbjEyMw==

grant_type=authorization_code&redirect_uri=https://www.iocoder.cn&code=189956c07a174588a97157eabef2f93a
```

**刷新模式**：

```http
POST /admin-api/system/oauth2/token
Content-Type: application/x-www-form-urlencoded
Authorization: Basic ZGVmYXVsdDphZG1pbjEyMw==

grant_type=refresh_token&refresh_token=00895465d6994f72a9d926ceeed0f588
```

## 1.3  校验访问令牌

校验访问令牌的有效性，并返回令牌基础信息。

### 基本信息

| 项目 | 说明 |
|------|------|
| URL | `POST /admin-api/system/oauth2/check-token` |
| 认证方式 | Basic Auth |
| 是否需要登录 | 否 |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
|--------|------|------|------|--------|
| token | String | 是 | 访问令牌 | `620d307c5b4148df8a98dd6c6c547106` |

### 响应结果

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "user_id": 1,
    "user_type": 1,
    "tenant_id": 1,
    "client_id": "default",
    "scopes": ["user_info"],
    "access_token": "620d307c5b4148df8a98dd6c6c547106",
    "exp": 1593092157
  }
}
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | Long | 用户编号 |
| user_type | Integer | 用户类型（1-系统用户，2-机构用户） |
| tenant_id | Long | 租户编号 |
| client_id | String | 客户端编号 |
| scopes | List\<String\> | 授权范围列表 |
| access_token | String | 访问令牌 |
| exp | Long | 过期时间，Unix 时间戳（秒） |

### 请求示例

```http
POST /admin-api/system/oauth2/check-token?token=620d307c5b4148df8a98dd6c6c547106
Authorization: Basic ZGVmYXVsdDphZG1pbjEyMw==
```

### 基本信息

| 项目 | 说明 |
|------|------|
| URL | `GET /admin-api/system/oauth2/v1/get-permission-info` |
| 认证方式 | Basic Auth |
| 是否需要登录 | 否 |

| 参数名 | 类型 | 必填 | 说明 | 示例值 |

## 1.6 令牌交换

使用当前系统的 access_token 换取目标系统的授权码，实现系统间无感跳转。A 系统登录后获取 token，跳转到 B 系统时调用此接口获取 B 系统的 authorization_code，B 系统再通过授权码换取自己的 access_token。

### 基本信息

| 项目         | 说明                                           |
| ------------ | ---------------------------------------------- |
| URL          | `POST /admin-api/system/oauth2/token-exchange` |
| Content-Type | `application/x-www-form-urlencoded`            |
| 认证方式     | Basic Auth                                     |
| 是否需要登录 | 否                                             |

### 请求参数

| 参数名           | 类型   | 必填 | 说明                         | 示例值                             |
| ---------------- | ------ | ---- | ---------------------------- | ---------------------------------- |
| token            | String | 是   | 当前系统的访问令牌（A 系统） | `620d307c5b4148df8a98dd6c6c547106` |
| target_client_id | String | 是   | 目标客户端编号（B 系统）     | `client_b`                         |
| redirect_uri     | String | 是   | 目标系统的重定向 URI         | `https://b-system.com/callback`    |
| scope            | String | 否   | 授权范围，多个使用空格分隔   | `user.read user.write`             |
| state            | String | 否   | 状态值（防 CSRF）            | `abc123`                           |

### 响应结果

返回重定向 URL，code 和 state 拼接在 redirect_uri 的查询参数中，与 `/authorize` 接口格式一致。

```json
{
  "code": 0,
  "msg": "",
  "data": "https://b-system.com/callback?code=189956c07a174588a97157eabef2f93a&state=abc123"
}
```

### 响应字段说明

| 字段 | 类型   | 说明                                                         |
| ---- | ------ | ------------------------------------------------------------ |
| data | String | 重定向 URL，code 和 state 已拼接到 redirect_uri 的查询参数中，前端获取后可直接执行跳转 |

### 请求示例

```http
POST /admin-api/system/oauth2/token-exchange
Content-Type: application/x-www-form-urlencoded
Authorization: Basic ZGVmYXVsdDphZG1pbjEyMw==

token=620d307c5b4148df8a98dd6c6c547106&target_client_id=client_b&redirect_uri=https://b-system.com/callback&scope=user.read&state=abc123
```

### 令牌交换流程

```
1. 用户在 A 系统已登录，持有 A 系统的 access_token
2. A 系统前端需要跳转到 B 系统，调用本接口获取 B 系统的授权码
3. 本接口校验 A 系统的 access_token 有效性，并验证 A、B 系统间的信任关系
4. 返回重定向 URL（code 和 state 拼在 redirect_uri 查询参数中）
5. A 系统前端获取重定向 URL 后直接执行跳转
6. B 系统后端使用 code 调用 POST /admin-api/system/oauth2/token 换取 B 系统的 access_token
```

## 1.8 续期访问令牌

滑动续期访问令牌（access_token）的有效期：每次调用将有效期延长至 **当前时间 + 配置时长**（默认 30 分钟）。超过令牌的绝对有效期上限（自令牌创建起算，默认 7 天，可由服务端配置）后，接口拒绝续期，需重新登录。

**与刷新模式（refresh_token）的区别**：

| 项目 | 续期（本接口） | 刷新（grant_type=refresh_token） |
|------|--------------|--------------------------------|
| 令牌变化 | access_token 不变，仅延长有效期 | 换发全新的 access_token（旧令牌删除） |
| 依赖凭证 | access_token 自身 | refresh_token |
| 有效期上限 | 受绝对上限约束（默认 7 天），到期强制重新登录 | 新令牌重新计算有效期 |

**使用建议**：

1. 开启滑动过期后，三方系统在业务调用中携带 token 校验（`check-token` 等）即可自动续期，无需额外调用本接口
2. 长时间无业务交互但需保活的场景（如用户长时间停留页面浏览、编辑等），可定时调用本接口主动续期

### 基本信息

| 项目 | 说明 |
|------|------|
| URL | `POST /admin-api/system/oauth2/renew-token` |
| 认证方式 | Basic Auth |
| 是否需要登录 | 否 |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
|--------|------|------|------|--------|
| token | String | 是 | 访问令牌（须与 Basic Auth 的 client_id 匹配） | `620d307c5b4148df8a98dd6c6c547106` |

### 响应结果

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "access_token": "620d307c5b4148df8a98dd6c6c547106",
    "expires_in": 1800
  }
}
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| access_token | String | 访问令牌（与请求的 token 相同，续期不换发新令牌） |
| expires_in | Long | 续期后的剩余有效期，单位：秒 |

### 请求示例


## 通用签名校验

### 签名参数（公共）

每个接口的请求体除业务参数外，均需携带以下 4 个公共签名参数：

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
|--------|------|------|------|--------|
| clientId | String | 是 | 客户端编号 | `sso-dom` |
| timestamp | Long | 是 | 请求时间戳（毫秒），与服务端时间差不得超过 5 分钟，否则视为过期 | `1718900000000` |
| nonce | String | 是 | 随机字符串（建议 16-32 位），同一 clientId 在 5 分钟窗口内不可重复，用于防重放 | `5f4dcc3b5aa765d61d8327deb882cf99` |
| signature | String | 是 | 签名值，HMAC-SHA256 算法计算，`client_secret` 作为密钥，输出十六进制小写 | `a1b2c3d4e5f6...` |

### 签名生成与验签示例（Java）

第三方可参照以下 Java 代码生成签名，并使用 `verifySignature` 方法在本地自测签名是否正确（无需依赖服务端）：

> 依赖：Hutool 工具类（`cn.hutool.crypto.SecureUtil`、`cn.hutool.crypto.digest.HmacAlgorithm`、`cn.hutool.core.util.IdUtil`、`cn.hutool.core.util.StrUtil`）。

```java
import cn.hutool.core.util.IdUtil;
import cn.hutool.core.util.StrUtil;
import cn.hutool.crypto.SecureUtil;
import cn.hutool.crypto.digest.HmacAlgorithm;

import java.nio.charset.StandardCharsets;
import java.util.TreeMap;

public class OpenApiSignatureDemo {


    public static void main(String[] args) {
        // ========== 测试数据（请替换为实际分配的 client_id / client_secret） ==========
        String clientId = "sso-dom";
        String clientSecret = "123456";  // 仅在客户端本地使用，禁止明文传输

        System.out.println("========== 开放接口签名验签 Demo ==========");
        System.out.println("clientId      = " + clientId);
        System.out.println("clientSecret  = " + clientSecret);
        System.out.println();

        // ========== 1. client 端：生成签名 ==========
        long timestamp = System.currentTimeMillis();
        String nonce = IdUtil.fastSimpleUUID();  // 或 UUID.randomUUID().toString().replace("-", "")
        String signature = generateSignature(clientId, timestamp, nonce, clientSecret);

        System.out.println("========== 1. client 端生成签名 ==========");
        System.out.println("timestamp     = " + timestamp);
        System.out.println("nonce         = " + nonce);
        System.out.println("signature     = " + signature);
        System.out.println("签名 payload  = " + buildPayload(clientId, timestamp, nonce));
        System.out.println();

        // ========== 2. 服务端：验证签名（本地自测，无需依赖真实服务） ==========
        System.out.println("========== 2. 服务端验证签名 ==========");
        boolean valid = verifySignature(clientId, timestamp, nonce, signature, clientSecret);
        System.out.println("验签结果      = " + (valid ? "✅ 通过" : "❌ 失败"));
    }

    // ======================== client 端：签名生成 ========================

    /**
     * 生成签名（与服务端算法保持一致）
     *
     * 说明：业务参数不参与签名计算，签名仅覆盖公共参数（clientId、timestamp、nonce），
     *      用于校验客户端身份与防重放。业务参数的合法性由各接口自行校验。
     *
     * @param clientId     客户端编号
     * @param timestamp    时间戳（毫秒）
     * @param nonce        随机字符串
     * @param clientSecret 客户端密钥（作为 HMAC-SHA256 密钥）
     * @return 签名字符串（十六进制小写）
     */
    private static String generateSignature(String clientId, Long timestamp, String nonce, String clientSecret) {
        String payload = buildPayload(clientId, timestamp, nonce);
        // 使用 HMAC-SHA256 计算签名，client_secret 作为密钥，输出十六进制小写
        return SecureUtil.hmac(HmacAlgorithm.HmacSHA256, clientSecret.getBytes(StandardCharsets.UTF_8))
                .digestHex(payload, StandardCharsets.UTF_8);
    }

    /**
     * 构造签名 payload（仅公共参数按 ASCII 字典序拼接，业务参数不参与）
     *
     * @param clientId  客户端编号
     * @param timestamp 时间戳
     * @param nonce     随机字符串
     * @return 拼接后的 payload 字符串
     */
    private static String buildPayload(String clientId, Long timestamp, String nonce) {
        // 1. 仅收集公共签名参数到 TreeMap（自动按 key 字典序排序），业务参数不参与签名
        TreeMap<String, String> allParams = new TreeMap<>();
        allParams.put("clientId", clientId);
        allParams.put("timestamp", String.valueOf(timestamp));
        allParams.put("nonce", nonce);
        // 2. 拼接成 key1=value1&key2=value2&...&keyN=valueN
        StringBuilder sb = new StringBuilder();
        allParams.forEach((k, v) -> {
            if (StrUtil.isNotBlank(v)) {
                if (sb.length() > 0) {
                    sb.append("&");
                }
                sb.append(k).append("=").append(v);
            }
        });
        return sb.toString();
    }

    // ======================== 服务端：签名验证 ========================

    /**
     * 验证签名（本地自测用，模拟服务端校验逻辑）
     *
     * 校验顺序与服务端 OpenApiSignatureService 保持一致：
     * 1. 校验时间戳（防重放）
     * 2. 重新计算预期签名
     * 3. 与客户端传入的 signature 比对
     *
     * 说明：nonce 防重放依赖 Redis，本地自测时可跳过，实际线上由服务端校验。
     *
     * @param clientId     客户端编号
     * @param timestamp    时间戳（毫秒）
     * @param nonce        随机字符串
     * @param signature    客户端传入的签名
     * @param clientSecret 客户端密钥
     * @return true 表示验签通过，false 表示验签失败
     */
    private static boolean verifySignature(String clientId, Long timestamp, String nonce, String signature,
                                           String clientSecret) {
        // 1. 计算预期签名（与 client 端 generateSignature 算法一致，仅使用公共参数）
        String expectedSignature = generateSignature(clientId, timestamp, nonce, clientSecret);
        // 2. 与客户端传入的 signature 比对
        if (!StrUtil.equals(expectedSignature, signature)) {
            System.out.println("  [x] 签名比对失败");
            System.out.println("  expected = " + expectedSignature);
            System.out.println("  actual   = " + signature);
            return false;
        }
        return true;
    }


}
```

**输出示例**：

```

signature     = a1b2c3d4e5f6...
```

## 2.6 获取预置角色菜单数据权限

供第三方系统调用，查询系统预置角色对应的菜单数据权限（角色信息 + 完整菜单树 + 按钮权限标识集合）。

| Content-Type | `application/json` |

### 请求参数

**Body 参数（JSON）**

**公共签名参数**

| 参数名 | 类型 | 必填 | 说明 | 示例值 |

| clientId | String | 是 | 客户端编号 | `sso-dom` |

| nonce | String | 是 | 随机字符串，5 分钟内同一 clientId 不可重复 | `5f4dcc3b5aa765d61d8327deb882cf99` |
| signature | String | 是 | 签名值（详见本章「通用签名校验」） | `a1b2c3d4e5f6...` |
