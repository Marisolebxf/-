## 4. 铁律与注意点（违反即返工）

1. **范围**：只读 bid 指定章节叶子，**不新增/不删减**（scope-baseline ±10%）；越界前先 PM 评审。
2. **ODS 进度 ≠ 本侧数据**：`SUPPLIER-LOAD-PROGRESS.md` 是供应方侧进度，**验收仍以本侧 `gkxlumenx_ods` 回签为准**。
3. **8/20 Phase 分界（2026-07-28 决策）**：
   - **Phase 1（现在 ~ 8/20，ODS 未稳定）**：项目自研 DWD 自行设计（不与甲方 ODS 一一对应）；`source_tables[]` 指向项目 DWD；`mapping_status` 统一标 `⏳ pending_ods`。
   - **Phase 2（8/20 后）**：GDF 统一做 ODS→DWD 字段映射 → lineage-subcoord 验证 → 升级状态。
4. **指标溯源**：每个统计数字旁必有 ⓘ（MetricSpecCard）；8 件套缺一不可；`metric_id` 命名 `M_{ELEMENT}_{INDICATOR}_{PERIOD?}`，ELEMENT 用字母助记码，禁止中文/拼音/过短。
5. **业务口径决策只能甲方拍板**：有歧义 → 登记 `客户决策清单跟踪表.md`（🟡）+ 界面对应位置加 ⚠️ "待甲方确认" 角标；AI/团队成员/PM 均不得替甲方拍板。
6. **UI 硬约束**：React + Vite + **Arco Design**，主色 `#165DFF`、页面底色 `#D8E7FC`、正文 14px、控件高 32px；Wave 0 阶段 Mock 数据必有 🧪 MockBadge；交互/无障碍按 `UX-UE 通用交互组件规范.md`。
7. **供应方约束**：只消费 `dwd_` 打头表，`ods_*` 不得依赖；六技术字段不当业务字段；`is_deleted=0` 默认过滤；字段未定稿标 `🟡待定`，禁止写死契约。
8. **git 纪律**：commit message 必含 `[agent:<role>]` 或 `[human:<name>]`；禁止 force push 到 main/dev；**demo-* 与 lumen-* 一律 `origin/dev` 直推**（禁 `main`）。
9. **成本**：handoff 必回填 4 个 cost 字段（actual_tokens / model_used / actual_cost / cost_warn）；> $10 暂停复盘，> $20 hard stop。
