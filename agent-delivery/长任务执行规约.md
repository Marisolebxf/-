# 长任务执行规约

> **版本**：v1.13 · 2026-08-18  
> **维护**：PM + coordinator  
> **拍板**：项目负责人（淮政玮）  
> **案例**：产业链 A–D（2026-08-13/14 过夜）· D12 `lumen-topic-py`  
> **关联**：`自动派单与确认规约.md` · `task-claiming-guide.md` · `智能体编排与派单手册.md` §十七 · `team-collaboration-playbook.md` · `observability.md` §9 · `.cursor/rules/qa.mdc`  
> **模板**：`templates/long-task-control-template.md` · `templates/long-task-e-defect-pack.md` · `templates/change-playbook.md`（基线之后的变更总控；分类表以该模板为准，不在本规约展开）

---

## 0. 一句话

> **长任务可以直接连夜跑，但每一叶仍是派单体系里的一条 task。**  
> 总控一次授权 ≠ 可以不建单、不认领、不写 handoff、不走 MCP。  
> 禁止「开一个超长会话，按感觉连续改代码」。

日常短任务：scan → confirm → 加厚 → 每叶向监管人报备 → `/goal`。  
长任务：**总控一次授权**后，coordinator 按 DAG 连续升 ready、认领、派 coding agent；**签收可以积压，主链不停**。

---

## 1. 什么时候用长任务

同时满足再开长任务模式，否则走日常短任务：

1. 跨仓闭环（灌数 → 算法 → Java → 前端），或同仓连续 ≥3 叶、预计过夜。  
2. 监管人（花名册 `can_supervise_agent` 或项目负责人）在 **长任务总控** 写明「不必再问」。  
3. 已拍板项能写进总控（仓、分支、库、调用链、废作清单），执行 agent 不必现场选型。

**不是长任务**：把 14 张 Python 合成 1 个 registry ID；无总控的「连夜私干」。

---

## 2. 与日常短任务的差别

| 项 | 日常短任务 | 长任务 |
|----|------------|--------|
| 授权粒度 | 每叶报备，未确认不改 registry | **总控一次授权**；后续叶不再问聊天 |
| 认领类型 | `pull` 或 `coordinator_dispatch` | 默认 `coordinator_dispatch` |
| `lock_hours` | 4 | **24**（lease 过期同一监管人续领，不改设计） |
| 下游解锁 | `depends_on` 全部 `done` + confirm | **联调闸门**（§6），不卡在签收 |
| 签收 `ready_to_sign→done` | 可卡主链 | **可积压**，禁止插进主链 |
| 拆单 | 一页/一接口一叶可以 | **按仓切段**；A/B 仍少叶；**C 一 REST 路径一叶、D 一实施权威故事一叶**（2026-08-18 拍板）。禁止旧 13 GET / 废止父故事 |
| 同仓并行 | Convoy 检测 | **同仓同时只派一张 coding 单** |
| 停工条件 | 常见「等用户选」 | 仅 §7 红线；已拍板禁止回问 |

日常 confirm / 派单条加厚铁律 **仍然有效**。长任务只是把「每叶问人」收成「总控一次问人」。

## 3. 仍必须走派单体系（红线）

下列任一条缺失 = 违规，coordinator 拒收、可 `needs-revision`：

1. **每叶有 registry ID**。用 MCP `task-create` / `task-claim` / `task-update-status` / `task-update-fields`；**禁止**手改 `task-registry.yaml`。  
2. **先认领、后动手**。`claimed_by` + `supervised_by=human:{真名}` + `claim_type` + `lock_until` 写完再改业务仓。  
3. **厚包先于编码**。至少有：长任务总控 + 本段总派单（派单包）+ 薄派单条。禁止只凭派单条开工。  
4. **每叶一份 handoff**：`agent-handoffs/{模块}/{task-id}.md`，含 `ponytail:`、cost 四字段、架构合规。  
5. **状态机照走**：`ready → claimed → in_progress → … → pending_test / ready_to_sign`。AV-0 / AV-1 照旧。  
6. **DoD 在 registry**，总控不替代各叶 DoD。  
7. **coding `/goal` 必含** `强度：ponytail …`、仓、分支、监管人、必读总控路径。  
8. **git**：commit `[agent:<role>]`；禁止 force；lumen-* 默认 `origin/dev`；总控写明的 demo 仓分支以总控为准。

「可以直接跑」只免除 **逐叶聊天确认**，不免除上表。

## 4. 「可以直接跑」怎么授权

### 4.1 总控落盘（开工前）

路径建议：`agent-handoffs/{模块}/…-长任务总控.md`。必须写清：

| 字段 | 要求 |
|------|------|
| 授权人 | `human:{真名}`（本管线 `supervised_by`） |
| 日期 | ISO 日 |
| 目标 | 一句话闭环 |
| 段/叶表 | 仓 · 分支 · task-id · 依赖门 |
| 已拍板 | 仓切法、库名、调用链、废作清单 |
| 升级人 | 结构歧义默认 `human:李伟`（可改） |
| 锁 | `lock_hours=24` |
| 授权句 | **「后续认领不必再问」** |

总控授权 = 本管线的一次 confirm。下游叶 **不必** 再让用户在聊天里点头。

### 4.2 授权后 coordinator 可以

- 按总控 DAG 把已满足联调闸门的叶标 `ready`。  
- `task-claim`：`claim_type=coordinator_dispatch`，`supervised_by` 用总控授权人。  
- 新开会话或 Task 子代理粘贴该叶 `/goal`（头来自段总派单）。  
- AV 推进到 `pending_test` / `ready_to_sign`；**不要**替淮政玮标 `done`（`chore` 除外）。  
- **禁止逐叶派 QA**。D 按 **§9.1**；闸4（P0 故事叶+壳 ≥ pending_test）后按 **§11** 派段 E。旧 E `ready_to_sign` 不算本轮完成。

### 4.3 授权后仍然禁止

- 无 ID 改代码；把 14 叶做进一张单却只交一份 handoff。  
- 改已拍板仓/引擎/库（例如把 B 段改回 `demo-algo-science`）。  
- 无闸门写正式 `gkxlumenx_*`。  
- 用「等用户看一眼」卡住下一叶。

## 5. 切法（方法论 · 按仓分段）

跨仓闭环默认 **A → B → C → D → E**。A–D 按仓交货；**E 不是第五编码仓**，是管线末闭环冒烟（§12）。不要按旧 13 GET / 旧 CP 页切：

| 段 | 职责 | 典型仓 / 角色 | 拆单原则 |
|----|------|----------------|----------|
| **A 存储 + 灌数** | Demo 库可测：建表/种子/闸门 | `demo-algo-science`（+ 管理端灌数页若需要） | 少叶；对标已批准灌数口径；禁止写正式库 |
| **B 算法/读面/Runner** | `/internal/*`；不建业务表；不自签 Job 快照 | `lumen-algo-py` | 按能力切（SHARED → 读面/指标/图 → Runtime → 各 Job）；同仓串行 |
| **C Java 门面 + Job** | 前端只调本仓；Feign Python；签发 snapshot | `lumen-svc-platform` | **一对外 REST 路径一叶**（同一 path 的 GET+POST 可同叶）。模块/网关 BOOT 可单独一叶或复用已有骨架 fan-in。禁止再把「查询门面 / Job」打成两张厚包。同仓仍串行 |
| **D 专题前端** | 复刻已评审 Demo（**布局+交互+样式+评审+Mock 开关**，见 `templates/fe-replica-visual-dod.md`）；只调 Java | `lumen-ui-topic` | **CHAIN/SVC 施工真源 = 实施权威 USM 一故事一叶**（2026-08-18；废止父故事勿派）。共享壳（侧栏/路由/权限、wait_view）各一叶。每叶 DoD = 该故事 AC + 五维 + V1–V7。禁止 ENTRY/WORKSPACE 当完成叶；禁止只改 Hero/页底。其它模块仍可按 §5.1 粒度自选 |
| **E 闭环冒烟** | 已发布环境走 USM 金路径；失败用 trace-id 测试驱动修 | E0 `devops-agent` · E1 `qa-agent` · 修单按仓 coding | **整条管线末一次**；金路径 5–8 条写进总控；QA **不改业务代码** |

### 5.1 专题前端 D · 复刻五维与拆单

CHAIN 段 D「入口 + 工作区各一张」导致路由在、页面壳。完成标准永远是 **`/goal` 范围清单 + 五维**，不以厚包标题当完成。

1. **CHAIN/SVC（2026-08-18）**：施工真源 = **一实施权威故事一叶** + 共享壳；见各模块 `*-CD-细叶拆单.md`。coordinator **不得**再派 ENTRY/WORKSPACE 当完成叶，也不得因「不是横切」拒派故事叶。  
   **其它模块**：粒度仍可自选（按路由 / 键 / 能力 / 多页一叶），`/goal` 写清范围。  
2. **仍不算完成**：范围只写「壳 / 铺齐」且无区块清单；占位路由当复刻完成；只改 Hero。  
3. **复刻五维**（本叶范围内缺一不算完成）：布局、交互、样式、评审模式（`@/review`）、Mock 开关数据。  
4. **`USE_MOCK=false`（或未开全局 Mock）**：禁止硬 mock，禁止用 `@/mock/**` 或 Demo fixture 填数；只渲染 Java 实包，无字段=可见空态。  
5. 语法：Vue 3 `<script setup>` + TS；禁止贴 JSX。地图复用 Leaflet + 天地图封装（`UnifiedLeafletMap` / 已有封装），禁止页面再 `new L.map`。  
6. 仅当本模块 `src/api/{module}` **不存在**时，允许一张契约薄单。禁止本叶唯一产物是「抽齐组件」。组件抽离发生在第一张用到它的叶。  
7. 下一叶解锁仍走 §6.2 联调闸门。**不**把人审截图当作 ready 条件（现有约束无此闸，不新增）。

**同仓 Convoy**：`lumen-algo-py` / `lumen-svc-platform` / `lumen-ui-topic`（及本管线点名的其它仓）**同时只派一张 coding 单**。做完 handoff 再领下一叶。

**废作**：总控必须列出旧 task-id / 旧路径，执行 agent 不得当依赖、不得再派。

**数据**：联调用 `demo_gkxlumenx_*`。缺 Demo 行 → 空态/角标，禁止造假。

## 6. 依赖与状态机（联调闸门）

### 6.1 问题

registry `depends_on` 常写成前序 `done`。feature 的 `ready_to_sign→done` 只有淮政玮能点。若死等 `done`，过夜主链会停在签收。

### 6.2 长任务允许的解锁

coordinator 可将下游标 `ready` 并派单，当且仅当：

1. 前序 **已有 handoff**；且  
2. 前序状态 ≥ **`integration`**（有联调证据）或 **`pending_test`** / `testing` / `ready_to_sign`；且  
3. 契约已交：路径、字段、禁止项在段总派单里，下游读得懂。

**禁止**：前序仍 `in_progress`、无 handoff 就派下游。  
**禁止**：把 `ready_to_sign→done` 当主链门。签收积压是默认。  
**禁止**：D 复刻叶用「等人审截图」卡住下一叶。收单看 handoff 五维/V1–V7 是否勾齐；人眼走查看差了再开补单。

同段 DAG（如 SHARED → SEARCH → C FACADE）仍按总控箭头，只是「箭头上的完成」按本条，不按签收。

日常短任务 **不**自动享受本条；未写总控则仍等 `done` + confirm。

### 6.3 AV 与 QA

- AV-0 / AV-1 照宪章跑。  
- **禁止**给 A–D 每一叶各派一张 QA。  
- D 联调闸门后走 **§11 段 E**（一张冒烟 + 按需修单）。  
- **长任务循环里**（`claim_type=coordinator_dispatch`）：coordinator **自己调动 qa-agent** 做测（转 `testing` + 派 QA 子智能体）。**禁止**等 `human:黄敬洲` 领取而卡住。日常短任务闸门不变。见 §11.5.3。  
- 不要把管线标 `done` 充完成。

## 7. 无人值守（违反才停）

1. **已拍板不回问**（仓、分支、库、调用链、Bid 叶子是否做）。  
2. **QC / PDR / 甲方 🟡**：诚实降级（空值、角标、缺口 ID），不停工等纪要。  
3. **结构歧义**（新表、改主键、新 ES 索引）：该叶 `blocked` + 升级总控写明的人（默认李伟）；**同段其它不依赖该点的叶继续**。  
4. **缺数据**：A 未绿不得写正式库、不得用旧表冒充；B/C/D 读空就空态。  
5. **卡住只允许**：真环境不通、正式库误写风险、结构升级项。  
6. lease 过期：同一 `supervised_by` 重新 `task-claim` 继续，不改设计。
7. 功能设计完善修改（FDE）以 `产品实现规程.md` §4.2.0 和 §4.2.5 为准：先判断是需求、问题还是监管人方案，方案有瑕疵先出选择卡；通过后按当前状况出执行计划，监管人确认后才跑；运行中命中停机条件才停，停时给「选项 + 推荐」的选择卡，选完续跑。

## 8. 产物与会话

| 产物 | 谁写 | 作用 |
|------|------|------|
| `…-长任务总控.md` | 监管人 / coordinator | 授权 + DAG + 无人值守 |
| `{段}-总派单.md`（厚包） | 同上 | 铁律、DoD 要点、`/goal` 头 |
| `{段}-派单条.md` | confirm 或手写薄条 | 审计；**不能**单独开工 |
| `{task-id}.md` handoff | 执行 agent | 每叶一份 |

Coordinator 可用 **一个长会话** 连续派多叶；coding 用 **一叶一会话**（或 Task 子代理），同仓排队。不要让一个 coding 会话同时改两个 lumen 仓。

## 9. Coordinator 过夜循环

```text
1. 总控已授权？否则停，写总控，不要私派。
2. MCP 查本管线状态；前序满足 §6.2 → 下游 ready。
3. 同仓无 in_progress coding → claim 下一叶 → /goal。
4. 收 handoff → AV；签收不点 done。
5. 结构项 blocked 记升级人；其它叶继续。
6. 段完成（各叶至少 pending_test）→ 开下一段，仍要各叶 ID。
7. **D 段按 §9.1**：一故事一叶内循环；禁止 ENTRY 厚包当完成；禁止逐叶 QA。
8. **D 的 P0 故事叶+壳 全部满足联调闸门 → 段 E**（§11）：E0 发布门绿 → `e2e:chain-gold`（或总控点名 job）= E1 → 红则失败分类 → C1 由 coordinator 派修（分诊助手无提交权）→ 点名 deploy 绿 = E0 → 只复测失败故事。禁止等黄敬洲领取。
   旧 E0/E1 已 `ready_to_sign` **不等于** 本轮 D 完成。
```

预算：单叶 >$10 暂停该叶复盘；>$20 hard stop。总控授权 **不能** 突破 cost 硬闸。

### 9.1 段 D 内循环（CHAIN/SVC · 2026-08-18）

旧 loop 把 D 收成 ENTRY+WORKSPACE 两张厚包，视觉闸被挤到 SKIN/LAYOUT/VISUAL-C1，E 提前按「能出记录或诚实空」判绿。本条替换该 loop。

**施工真源**：各模块 `*-CD-细叶拆单.md`。ENTRY / WORKSPACE / SKIN / LAYOUT / VISUAL-C* / SEARCH-REPLICA-C2 / REPLICA-FIX **不进「下一张」队列**（骨架 fan-in；`needs-revision` 返工除外）。

```text
闸0 同仓
  lumen-ui-topic 全工作区同时只 1 张 frontend coding（CHAIN 与 SVC 互斥）
  默认抢仓序：CHAIN P0 D 先于 SVC（总控授权人可改序）

闸1 C→D（按路径叶，不按 FACADE 厚包）
  SHELL    ← 本管线壳依赖的 C 路径叶 ≥ integration
  故事叶   ← 该故事 depends_on 的 C 路径叶 ≥ integration（可在 C 中途穿插，不必等整段 C）
  WAITVIEW ← TASK-GET + TASK-RESULT ≥ integration
  禁止：用 JAVA-FACADE / JAVA-JOB 厚包代替路径叶闸门

闸2 叶内（每张相同，缺一不得放行下一张）
  前序 §6.2 → ready → claim frontend-agent lock 24h
  /goal 必含：故事 ID + 路由 + Demo 区块清单 + 手册 §9.0c + 五维
  收单硬闸：R1–R5；查询/Hub 另 V1–V7；工作区另 W1–W3；本叶 AC；USE_MOCK=false 自检
  轻量表格 / 只改 Hero / 占位路由 / 无区块清单 → needs-revision（同一叶重开）
  过 → AV-0 integration → 槽空 → 下一张
  禁止本叶派 QA；禁止等人审截图

闸3 选下一张（逻辑可并行，执行仍串行）
  候选 = 拆单 DAG 依赖已闸门 且 非禁选 ID
  优先：总控金路径故事 > 同页前置故事（如 OV-02 等 OV-01）> 其余 P0 > P1
  CHAIN 金路径默认：TOPIC-01 → OV-01/06 → PANORAMA-01 → DIAG-03/04 → SZ-03
  SVC 金路径必须是真实 US-SVC-*（禁止占位「能出记录或诚实空」）

闸4 出 D → E
  触发：SHELL + WAITVIEW + 全部 P0 故事叶 ≥ pending_test（P1 不挡）
  然后才 E0（本轮点名 deploy）→ E1（金路径）
  旧 E 叶不删、不算本轮完成；P0 故事叶齐后必须重开 E0/E1
  金路径绿 ≠ 复刻完成（未进金路径的 P0 故事叶仍要做）

闸5 缺口
  本叶范围内五维缺口 → 同一叶 needs-revision，不开 SKIN 类补单
  清单外缺口 → 另开补单（仍一叶、仍过 V1–V7），不假装本叶已铺齐模块
```

## 10. 禁止清单（摘）

- 无 task-id 连夜写业务仓。  
- 跳过 MCP 直接改 registry。  
- 仅凭派单条编码。  
- 问用户选仓 / 选引擎 / 要不要做已拍板 Bid。  
- 前端直连 Python；Java 写算法；产业查询为页面新建 ES（除非总控明文）。  
- 无闸门写正式库。  
- 用签收积压当阻塞。  
- **等黄敬洲领取**而卡住长任务 `pending_test → testing`。  
- **逐叶**派 QA，或把 feature 标 `done`。  
- QA / coordinator / 分诊助手改业务代码。  
- 新建「全栈 agent」规则去写三仓，或让 architect 当调度器。  
- 用本机 `localhost` / `pnpm dev` 当 E1 证据。  
- 无 trace-id 的「感觉修」。

## 11. 段 E · 闭环冒烟（管线末一次）

> 拍板（2026-08-14 `human:淮政玮`）：整条 A–D **末尾一次** E；QA **不改代码**；冒烟只认 **K8s dev 已发布前端**；金路径写进总控；缺陷包（含 trace-id）**测试驱动**全栈调度去派修。

E 对应实现规程 **I2-02 主路径 walkthrough** 的无人值守缩小版。不是 I3 里程碑，不是 bid-reference 90% 验收，不是逐叶 QA。

```text
D 联调闸门
  → E0 devops：本次需要的服务已在 K8s dev 健康发布
  → E1：GitLab `e2e:chain-gold` 打已发布前端（红则 QA 抄 trace 出缺陷包）
       过 → 主体链路闭环（A–D 仍可积压签收）
       不过 → 缺陷包（C1 必含 X-Trace-Id）
            → §11.4 失败分类
            → C1：coordinator 分诊（可派无提交权助手读 Tempo）→ bugfix 叶 → 点名 deploy 自动绿（=E0）→ `e2e:chain-gold` 只复测失败故事
            → C2：只重开 E0，不派业务修
            → C3：记缺口，不开修
            → C4：总控授权人改期望
            → C5：blocked + 李伟
            → C6：blocked + 总控授权人
```

### 11.1 固定两叶 + 按需修单

| 叶 | agent | 干什么 | 不干什么 |
|----|-------|--------|----------|
| **E0 发布门** | `devops-agent` / **CI deploy job** | 首轮：总控点名服务 Pipeline 绿、rollout 健康、URL 是 lumen 已发布、库 `demo_gkxlumenx_*`。**C1 之后**：所涉仓点名 deploy job 绿（tag=短 SHA + rollout + healthz）即 E0，**不等聊天「已经滚了」** | 不写业务；没绿则 `blocked` / **C2**，E1 不开工 |
| **E1 冒烟** | GitLab `e2e:chain-gold`（默认）· `qa-agent`（兜底） | 总控 **5–8 条 USM 金路径**；失败必抄 `X-Trace-Id` + Tempo/Loki 链接 | **不改** `lumen-*` / `demo-*` 业务代码；不扩成全量 USM / 视觉回归 / P95 |
| **E2… 修单** | 分诊后的 coding | 一问题一叶，`/goal` 必贴缺陷包 | 不跨仓乱修；同仓 Convoy 一单 |

人从已发布页自己抄到 trace-id：可 **跳过重跑 E1**，直接交缺陷包进调度。仍须建 bugfix 叶，禁止无 ID 热修。

### 11.2 环境铁律

- E1 **只认 K8s dev 已发布前端**（Ingress / NodePort / 总控写明的 URL）。  
- **禁止** `localhost`、`pnpm dev`、未 rollout 的旧镜像当证据。  
- 修完必须再过 E0：见 **§11.5.2**（点名 deploy 自动绿 = 已滚动），再复测。禁止等人喊「镜像滚了」。

### 11.3 金路径

总控必须列出金路径表（故事 ID · 路由 · **期望** · **允许的空态**）。QA 不得自行加到全量 USM。

**期望未发生必红**（2026-08-14 `human:淮政玮` 拍板）：

1. **神谕 = 该行「期望」原文。** 期望里写的状态/动作没有发生 → **FAIL**。禁止用「页面报了失败」「非 5xx」「诚实降级」把未发生的期望改判 PASS。红了之后先走 **§11.4 失败分类**，不得直接当 C1 开修。
2. **空态白名单只看总控该行。** 「允许的空态 / 或诚实空」必须写进该行期望（或同表「允许的空态」列）。写了才算过（须可见空态，不是 500）。没写 → 空、Job failed、过程页红字都是红。
3. **谁都不能把红改绿。** QA / coordinator / coding agent 不得缩小期望。只有：同一故事复测变绿，或总控授权人改该行期望原文。
4. **仍算不过（即使期望含空态）**：HTTP 5xx、打到 `demo-*`（破 D12）、自动跳过 wait_view、无对比结果仍空跑深圳发展。

反例（CHAIN #4）：期望是「succeeded 后 wait_view 点查看结果」；Job 在 `freeze` failed、未到 succeeded → **FAIL**。过程页诚实显示失败只能证明没造假，不能代替期望。

正例（CHAIN #2）：期望是「无数则空态，不造假 KPI」；可见空态 + 非 5xx → PASS。

报告下载、OPS 写侧、七键全开、区域两键：默认 P1，不挡「主体链路闭环」，除非总控写进金路径。

### 11.4 失败分类（2026-08-14 `human:淮政玮` 拍板）

红了先分类，再决定开不开修。QA 在缺陷包填**建议类**；**coordinator 确认类**后才派单。禁止跳过本表直接改三仓。

| 类 | 名称 | 判据 | 动作 | 禁止 |
|----|------|------|------|------|
| **C1** | 产品/代码 | 期望未发生且**不是**本行允许的空态；5xx；白屏/错跳；Job failed / 未 succeeded；跳过 wait_view；D12 打到 `demo-*`；helm/Feign/nginx 配错需提交 | 缺陷包（**必含 X-Trace-Id**）→ Tempo 分诊 → `bugfix` 一叶一层：FE=`frontend` · Java=`api` · Python=`algorithm` · 配错需提交=`devops`。修完 **§11.5.2：点名 deploy 绿 = E0 → coordinator 自动只复测该故事** | 不改金路径凑绿；不跨仓乱修；不等人喊镜像 |
| **C2** | 发布/环境 | 点名服务不健康；镜像未滚（测到旧 tag）；URL 不是总控 lumen 已发布地址；打到旧 Pod | **只重开/只跑 E0**。E0 不过 → 该叶 `blocked`，E1 不继续。不建业务 bugfix | 不改业务代码「绕开发布」 |
| **C3** | 白名单空态 | 总控该行「允许的空态」命中；可见空态；非 5xx | **PASS**。记缺口 / Q056 / 🟡，不开 bugfix | 不造假数；不把 C1 收成 C3 |
| **C4** | 用例/总控错 | 期望写错、故事已废、路由已迁、金路径与已评审页不一致 | **停循环**。升级总控授权人改该行期望原文后再测 | 不改产品去凑旧期望 |
| **C5** | 结构/库闸 | 新表 / 改主键 / 新 ES；有无闸门写正式 `gkxlumenx_*` 的风险 | 该叶 `blocked` + 升级 `human:李伟`（总控可改升级人） | agent 猜 DDL、写正式库 |
| **C6** | 未知 | 不像 C2 却无业务 `X-Trace-Id`；Tempo 分不出层；同一故事已 3 轮仍红；单叶 cost 触 $10/$20 | `blocked` + 升级总控授权人 | 猜着改三仓；把红改绿 |

并列时取**更停**的类：C5 > C6 > C4 > C2 > C1；C3 只在白名单命中时用，与 C1 互斥。

抖动：无代码/无发布变更下同一故事连续两次结果不一致 → **再跑 1 次**；仍红按 C1（或仍无 trace 按 C6）。

CHAIN 例：#4 `freeze` failed、期望含 succeeded → **C1**（怀疑层 Python/Java），不是 C3。mock 登录网关 404 若金路径未写「必须真 PigX 登录」→ 不挡已写明的故事；若总控把真登录写进期望则 C1。

### 11.5 测试驱动调度（QA 不改代码）

「全栈调度」= **coordinator 跨层分诊 + 按仓派单**，不是一个人写 FE/Java/Python。

1. QA（或人）产出缺陷包，模板 `templates/long-task-e-defect-pack.md`。必填：故事 ID、已发布 URL、操作步骤、期望、现象、**失败分类（C1–C6）**、怀疑层。**C1 必填** `X-Trace-Id` + Tempo 链接；C2 用 E0/rollout 证据，可无业务 trace。  
2. 调度会话默认 `agent:coordinator-agent`（**不写业务代码、不 git commit/push 三仓**）。输入 = 缺陷包。先确认分类，C1 才派修。  
3. C1：按 `observability.md` §9 查 Tempo → MCP `task-create`（`task_type=bugfix`）→ `task-claim` → `/goal` 派 **一个**专项 agent；`/goal` 正文粘贴缺陷包。  
4. **禁止**：QA 改业务代码；调度会话自己改三仓；C1 无 trace-id 开修；把 C5/C6 当 C1 派。  
5. 同一故事最多 **3 轮**（E1 失败 → 修 → E0 → 复测）。单叶 cost 仍 $10 暂停 / $20 hard stop。超限按 **C6** `blocked`。

#### 11.5.1 全栈分诊助手（2026-08-14 `human:淮政玮` 拍板）

C1 链路看不懂时，coordinator **可以**另开一个只读助手（Cursor 子会话即可，**不建** `fullstack-agent` 角色、**不写** `.cursor/rules/fullstack.mdc`）。

| 可以 | 不可以 |
|------|--------|
| 读 Tempo / Loki / 缺陷包 / 已发布 URL | `git commit` / `push`；改 `lumen-*` / `demo-*` 业务代码或 helm 业务值 |
| 建议失败分类、怀疑层、该派哪个专项 | 自己 MCP 把任务标绿 / 改金路径期望 / 标 PASS |
| 起草缺陷包字段给 coordinator 确认 | 当第三种调度器（代替 coordinator）或代替 architect 做铁律签字 |
| — | architect-agent 兼任本助手去派单（architect 仍只评审，见 `architect.mdc`） |

助手产出 = 分诊备忘（建议类 + 怀疑层 + trace 摘要）。**提交权仍在专项 coding 叶。** 调度人格只有 coordinator。

#### 11.5.2 C1 后自动发布 → 检测 → 复测（2026-08-14 `human:淮政玮` 拍板：点名服务）

不想等人等镜像。闭环接在 **CI deploy job** 上，不另造「等 tag」聊天门。

```text
C1 push origin/dev
  → GitLab：test 绿 → 镜像 tag=短 SHA
  → 点名 deploy **自动**（rollout + healthz）     ← 这就是本轮 E0
  → 点名 deploy job 绿
  → 同 Pipeline（或跨仓 trigger）`e2e:chain-gold` 打已发布 30892
       绿 = 本轮 E1 / 复测
       红 = 缺陷包 + §11.4；QA 子智能体抄 artifact / trace（CI 无浏览器时兜底）
```

| 仓 / 范围 | origin/dev | 说明 |
|-----------|------------|------|
| `lumen-algo-py` `deploy:api` + `deploy:worker` | **自动** | CHAIN Python。禁止 innov/entan 搭车。绿后 **trigger** `lumen-ui-topic` `e2e:chain-gold` |
| `lumen-svc-platform` `deploy:topic-chain` + `deploy:topic-async-service` | **自动** | CHAIN Java 门面 + Job。禁止 `helm:deploy` / gateway / innov / topic 搭车。绿后 **trigger** 同上 |
| 同仓其余 deploy / `helm:deploy` | **仍 manual** | 仅 `FULL_PIPELINE=true` 或修单碰到它们才自动 |
| `lumen-ui-topic` `deploy:k8s` | 保持自动 | 绿后同 Pipeline 跑 `e2e:chain-gold` |
| 金路径 wait_view | **`e2e:chain-gold`** | 只点 `http://10.50.69.111:30892`；`CHAIN_GOLD_ONLY=true` 跳过 build；`CHAIN_GOLD_GREP` / `CHAIN_GOLD_STORY` 只复测失败故事。禁止把全量 USM / 视觉回归塞进本 job |

**E0 证据** = 点名 deploy job 绿（镜像 tag = 本次 commit 短 SHA + `rollout status`；Python 另打 `/healthz`）。coordinator 轮询该 Pipeline（`glab` / GitLab API）；**禁止**等聊天「已经滚了」。超时：Python 默认 **20 min**，Java 默认 **40 min**（Maven），总控可改。超时或 deploy 红 → **C2**，只重开 E0，不派业务修。

首轮管线 E0 仍核总控点名的**整组**服务。C1 之后只核**本轮 push 所涉**点名 job。

#### 11.5.3 调度者调动 qa-agent（2026-08-14 `human:淮政玮` 拍板）

长任务循环里 **不要卡在** `pending_test → testing`。日常短任务仍认 qa-agent / `human:黄敬洲`；**本条只覆盖** `claim_type=coordinator_dispatch`。

`e2e:chain-gold` 绿 = 本轮 E1，**不必**再派 QA 子智能体。coordinator **禁止等黄敬洲领取**；CI 红 / 无浏览器时才派 qa-agent 抄 artifact + trace。

```text
修单 / E1 叶到 pending_test
  → 点名 deploy 绿后 `e2e:chain-gold` 已跑：绿则不必派 QA 子智能体
  → 红 / CI 无浏览器：coordinator 转 testing 并派 qa-agent 抄 artifact + trace 出缺陷包
       actor=agent:coordinator-agent（或先 task-claim claimed_by=qa-agent）
```

| 可以 | 不可以 |
|------|--------|
| coordinator 转 `testing`；CI 绿当 E1 证据；红才派 QA 子智能体 | 空转 `testing` 却不派 QA、把测过当没测；CI 绿仍派子智能体重跑一遍 |
| `supervised_by` 保持总控授权人（不必改成黄敬洲） | QA / coordinator 改业务代码 |
| 日常短任务仍走黄敬洲闸门 | 用本条给非长任务绕过 QA 闸门 |

MCP 闸门：`scripts/lib/task-registry-lib.mjs` `checkTransitionGate`。
