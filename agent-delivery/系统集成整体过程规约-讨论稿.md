## 2. 五项工作（按优先级）

编号小的先做。当日表、WBS、过程夹都带这个编号。一项一条沟通线和一份方案；项内的菜单是方案里的节，不各开一夹。

第 1、3、4 项开发完成后，都要到总集统一权限配置后台配置菜单和用户权限。这项配置写进该叶的完成条件，不单独再开一类工作。

### 1. 自研模块

合同范围内、除第 5 项所列菜单以外的菜单，做全链路功能开发（前端 → Java → Python `/internal/*`）。

方案用定义包和门 3 DG，不另开「系统集成技术方案」。过程记录留在现有实现纪要、handoff 和智树进度夹里该系统页。

### 2. 对接三要素

对端是北京久新。范围是专题系统里的三条垂向维度：技术 / 技术链、人才、科研机构。对接和嵌入同时覆盖展示系统、专题系统、数据和指标。

已有分析总控：[`SCI-INT-长任务总控.md`](agent-handoffs/展示系统三要素集成-SCI-INT/SCI-INT-长任务总控.md)。该总控已梳理展示侧态势 8 页与人才 4 子页（283 个 SRS 叶）的页面、指标与算法、数据、集成测试，并汇总对久新的接口需求。专题侧的三要素不在那份总控的页面范围内，方案任务要单列专题侧缺口，不把展示侧卡片当成专题已覆盖。

过程夹：`04-系统集成/02-对接三要素/`。方案任务：`系统集成技术方案_对接三要素`。

### 3. 专题系统集成

第 2 项以外的专题系统集成，分三块。

1. **基础数据管理。** 智树负责，通过接口对接，当前已在对接。
2. **内部管理，四个菜单。** 产业全景内容管理、专题服务内容管理、企业发展内容管理、政策扶持内容管理。初步契约：[`PORTAL-CMS-字段与读接口契约.md`](agent-handoffs/平台基建-PLATFORM/产物/PORTAL-CMS-字段与读接口契约.md)（企业发展已确认，其余三份为草案）。

内容管理四菜单与现网用词还没对齐，方案任务里先收口名称再拆开发叶：

| 本稿菜单 | 契约文件 | 现网菜单（专题内容运营 · 门户内容管理） |

## 3. 阶段序

```text
1. PM 建档
2. 方案就绪 → 待签收
3. 项目负责人签收
4. 拆 WBS，写明监管人，认领执行
5. 子项达到可对端条件就联调，回写进度
6. 任何人可按维度问进度、沟通史和三份方案材料
```

```mermaid
flowchart LR
  A["1 建档"] --> B["2 方案任务"]
  B --> C["3 签收 done"]
  C --> D["4 WBS 到监管人"]
  D --> E["5 分项联调"]
  E --> F["6 过程夹可查询"]
  D --> F
```

签收前可以开会、收对方文档、记风险、记双方同意的时点。签收前不建开发叶、不派编码。

第 1 项的方案和签收用已经通过的门 3 DG，不平行再签一份技术方案。拆 WBS 之后走《产品实现规程》的 I1 / I2 / I3。阶段序里的联调，在第 1 项指调用链可演示，按子项开 I2，不等整模块页面排完。第 2 至第 5 项用「系统集成技术方案_{项名}」过签收。

## 5. 对接维度的过程夹

采纳本稿之后，`工程过程/04-产品集成.md` 改为跳转页，活记录进 `工程过程/04-系统集成/`。这是和卷 `02` 同类的例外：过程记录生在本夹。已有方案正文留在原路径（门户建议稿、0702、CMS 评估、GDF），主文件只链接。

工程过程索引里「只索引、不搬家」对卷 `04` 的这条例外，随本稿会签时一并写明。

```text
工程过程/04-系统集成/
  INDEX.md                          # 维度登记
  {维度}/
    README.md                       # 主文件
    沟通流水.md
    纪要/YYYY-MM-DD-题目.md
    对接文档/我方/
    对接文档/对端/
    约定时点.md
    风险.md
    进度.md
```

PM 用 skill 从模板生成。空文件也要有标题，避免后来的人另起一份。

### 5.1 `INDEX.md`

一行一个已建档维度：名称、对端、智树角色（实现 / 对接 / 只分析）、方案任务 ID、阶段（建档 / 待签收 / 已签收 / 执行中）、主文件链接。

### 5.2 `README.md`（主文件）

顶部始终是「当前」，下面是入口，不把流水贴进来。

- 阶段、方案任务 ID、签收日
- 开发叶 ID 列表（签收后才有）
- 三份材料入口：整体技术方案、我方对接文档、对端对接文档
- 进度文件、流水、约定时点、风险的链接
- 智树在本维做什么、不做什么（对齐 scope-baseline，不在本页改范围）

### 5.3 其余文件

| 文件 | 谁写 | 怎么写 |
|---|---|---|
| `沟通流水.md` | PM、参会人 | 只追加。一条含日期、谁、何事、指向哪份纪要或文档 |
| `纪要/` | PM | 一场会一份。结论、未决、下次时间 |
| `对接文档/我方/` | PM 收口 | 我方发出的字段、时序、环境、验收条件 |
| `对接文档/对端/` | PM 落盘 | 对端发出的原文或导出，文件名带收到日期 |
| `约定时点.md` | 只 PM | 双方说过的日期。旁边写出来源（纪要或邮件）。智树内部需要日单独成节，不写进约定 |
| `风险.md` | PM，监管人可追加事实 | 事项、影响、应对、负责人、状态。不另建风险登记簿；甲方口径仍以 [`客户决策清单跟踪表.md`](客户决策清单跟踪表.md) 为准，这里只链 |
| `进度.md` | skill 写快照；监管人报子项 | 顶部「当前」；下面按日追加，不覆盖旧日 |

## 7. WBS

签收当天或下一个工作日，PM 给出 WBS 列表，coordinator 建叶。

每一叶写明：监管人、仓、依赖（`depends_on` 含方案任务 ID）、完成时什么叫可对端。一叶是一个可联调子项，不是一份对方接口文档里的每一个字段。

展示页面施工序仍以 [`05-展示系统集成工作计划.md`](工程过程/02-策划与监控/02-智树工作计划/02-进度/05-展示系统集成工作计划.md) 为页面排期。它不代替对接维度的 WBS。两边冲突时，未签收的对接子项在页面上用空态，任务可以排，不把对方未承诺的数据写成已接入。

某一叶若要连夜跑，那一叶再按《长任务执行规约》做总控。总控不改变本规约的签收和回写。

## 8. 当日表（代替飞书手填）

飞书表现在的八列保持不变。真源改到仓内一份按日文件，skill 生成，PM 只跑命令、不抄格子。

```text
工程过程/当日进展/YYYY-MM-DD.md
```

同一天只保留这一份。按负责人分节，节内是表。负责人取任务的 `supervised_by`。一个人名下再按模块分块（如李伟 / 科技发展态势），模块名取任务所属系统或对接维度。

| 飞书列 | 从哪来 | 谁维护 |
|---|---|---|
| 负责人 | `supervised_by` | 建叶时写一次 |
| 任务内容 | 任务标题 + 范围一句 | 建叶时写一次 |
| 完成时间 | 建叶时写入的计划完成日 | 改期才改，不每天重填 |
| 完成状态 | 任务状态，见下表颜色 | skill 每天读 MCP |
| 当日任务 | 该叶当天仍在执行则带出标题；监管人另说了「今日做」则用原话 | 不说则用标题 |
| 当日进展 | 监管人当天在 Cursor 说的那一句 | **只有这列每天要人开口**。当天没说，写「今日未报」，不代写 |
| 测试情况 | 联调结论或测试状态 | 没记录就写「未见测试记录」 |
| 其他备注 | 方案、流水、发布证据、阻塞原因的链接 | skill 带链接 |

完成状态颜色与任务状态：

| 任务状态 | 格内文字 | 颜色 |
|---|---|---|
| `done` 且有发布证据 | 完成 | 绿 |
| `done` 无发布证据 | 任务关闭，未见发布 | 黄 |
| `in_progress` / `claimed` / `testing` | 进行中 | 黄 |
| `ready_to_sign` | 待签收 | 黄 |
| `blocked`，或当日进展里人声明数据/对端未到位 | 阻塞 | 红 |
| 当天没有口令 | 状态仍按上一行，当日进展为「今日未报」 | 不另造红 |

`done` 不等于已发布。没有流水线、环境或提交，发布栏写「未见发布证据」。

skill 不把各子项百分比收成一个人的完成率。百分比若出现，只写在该叶的当日进展里，并带声明人。

阻塞句（如总集承诺的数据未到位、对接方 1%）由监管人或 PM 在口令里说出，skill 把它放进当日进展并标红，同时在该维度 `风险.md` 追加一条。skill 不自己判断该不该标红。

### 8.1 PM 每天做什么

每个工作日 PM 跑一次「今日快照」。skill：

1. 用 MCP 读取执行中的任务（按监管人，不读注册表全文进回答）。
2. 收集当天已经落盘的口令。
3. 覆盖写入 `工程过程/当日进展/当天日期.md`。
4. 把同一行人追加到所属模块或对接维度的 `进度.md`，并刷新该 `README.md` 顶部「当前」。

PM 不开口，skill 不写文件。第一版不做定时任务，也不回写飞书。会签后飞书表改为指向仓内当日文件，停止在格子里改字。

### 8.2 监管人口令

对接叶：

> 集成进度：{维度} / {子项} {n}%。今日做：{一句}。发布：{环境、流水线或提交}。可对端：是/否。测试：{一句或未见}。

自研叶：

> 开发进度：{模块} / {子项}。今日做：{一句}。发布：{证据或未见}。测试：{一句或未见}。

有阻塞时加一句：`阻塞：{原因}`。这句话成为当日进展的红字。

口令落在当日表对应行，并追加到该模块或该维度的进度文件。记录声明人、日期、原话。

## 9. 分项联调

子项同时满足三条，就可以记联调，不必等兄弟任务发布：

1. 边界已经写进已签收方案或我方对接文档
2. 测试环境可调，或 `约定时点.md` 里写了这一段用空态 / 桩
3. 该子项已发布，或监管人声明这一段不依赖发布（例如菜单跳转）

联调记两处：`进度.md` 一节（通过 / 阻塞 / 对方未到），`沟通流水.md` 一条。阻塞升级走现有任务状态 `blocked`，原因与过程夹同一句话。

对方说「无法提供」时，一个工作日内由 PM 写成三选一：替代源、降级空态、范围变更。变更范围仍由项目负责人和 scope-baseline 决定，不在流水里改口径。

## 10. 对话查询

问「今天到哪了」时，skill 读 `工程过程/当日进展/` 里最新一份，按负责人复述八列。没有当天文件就说明还没跑快照。

问「某维度到哪了、谈过什么、方案在哪」时，skill 再读：

1. `04-系统集成/INDEX.md` 定位目录
2. 该维度 `README.md`、`进度.md` 顶部、`沟通流水.md` 最近记录、`风险.md`、`约定时点.md`
3. README 列出的任务 ID，经 MCP `task-get`

回答里必须带出三份材料的路径：整体技术方案、我方对接文档、对端对接文档。某一份还没有，就说「还没有」，不拿别的维度的文档填上。

不读 `task-registry.yaml` 全文，不把其他维度的流水混进回答。
