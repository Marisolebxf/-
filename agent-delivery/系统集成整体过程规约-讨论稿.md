## 3. 阶段序

```text
1. PM 建档
2. 方案就绪 → 待签收
3. 项目负责人签收
4. 拆 WBS，写明监管人，认领执行
5. 子项达到可对端条件就联调，回写进度
6. 任何人可按维度问进度、沟通史和三份方案材料
```

```mermaid
flowchart LR
  A["1 建档"] --> B["2 方案任务"]
  B --> C["3 签收 done"]
  C --> D["4 WBS 到监管人"]
  D --> E["5 分项联调"]
  E --> F["6 过程夹可查询"]
  D --> F
```

## 8. 当日表（代替飞书手填）

飞书表现在的八列保持不变。真源改到仓内一份按日文件，skill 生成，PM 只跑命令、不抄格子。

```text
工程过程/当日进展/YYYY-MM-DD.md
```

同一天只保留这一份。按负责人分节，节内是表。负责人取任务的 `supervised_by`。一个人名下再按模块分块（如李伟 / 科技发展态势），模块名取任务所属系统或对接维度。

| 飞书列 | 从哪来 | 谁维护 |
|---|---|---|
| 负责人 | `supervised_by` | 建叶时写一次 |
| 任务内容 | 任务标题 + 范围一句 | 建叶时写一次 |
| 完成时间 | 建叶时写入的计划完成日 | 改期才改，不每天重填 |
| 完成状态 | 任务状态，见下表颜色 | skill 每天读 MCP |
| 当日任务 | 该叶当天仍在执行则带出标题；监管人另说了「今日做」则用原话 | 不说则用标题 |
| 当日进展 | 监管人当天在 Cursor 说的那一句 | **只有这列每天要人开口**。当天没说，写「今日未报」，不代写 |
| 测试情况 | 联调结论或测试状态 | 没记录就写「未见测试记录」 |
| 其他备注 | 方案、流水、发布证据、阻塞原因的链接 | skill 带链接 |

完成状态颜色与任务状态：

| 任务状态 | 格内文字 | 颜色 |
|---|---|---|
| `done` 且有发布证据 | 完成 | 绿 |
| `done` 无发布证据 | 任务关闭，未见发布 | 黄 |
| `in_progress` / `claimed` / `testing` | 进行中 | 黄 |
| `ready_to_sign` | 待签收 | 黄 |
| `blocked`，或当日进展里人声明数据/对端未到位 | 阻塞 | 红 |
| 当天没有口令 | 状态仍按上一行，当日进展为「今日未报」 | 不另造红 |

`done` 不等于已发布。没有流水线、环境或提交，发布栏写「未见发布证据」。

skill 不把各子项百分比收成一个人的完成率。百分比若出现，只写在该叶的当日进展里，并带声明人。

阻塞句（如总集承诺的数据未到位、对接方 1%）由监管人或 PM 在口令里说出，skill 把它放进当日进展并标红，同时在该维度 `风险.md` 追加一条。skill 不自己判断该不该标红。

### 8.1 PM 每天做什么

每个工作日 PM 跑一次「今日快照」。skill：

1. 用 MCP 读取执行中的任务（按监管人，不读注册表全文进回答）。
2. 收集当天已经落盘的口令。
3. 覆盖写入 `工程过程/当日进展/当天日期.md`。
4. 把同一行人追加到所属模块或对接维度的 `进度.md`，并刷新该 `README.md` 顶部「当前」。

PM 不开口，skill 不写文件。第一版不做定时任务，也不回写飞书。会签后飞书表改为指向仓内当日文件，停止在格子里改字。

### 8.2 监管人口令

对接叶：

> 集成进度：{维度} / {子项} {n}%。今日做：{一句}。发布：{环境、流水线或提交}。可对端：是/否。测试：{一句或未见}。

自研叶：

> 开发进度：{模块} / {子项}。今日做：{一句}。发布：{证据或未见}。测试：{一句或未见}。

有阻塞时加一句：`阻塞：{原因}`。这句话成为当日进展的红字。

口令落在当日表对应行，并追加到该模块或该维度的进度文件。记录声明人、日期、原话。

## 9. 领导周报（会签后再生成）

给领导的周报按 2026-10-22 提供的飞书周报版式，栏目顺序固定。2026-W37（9/16～9/23）是版式样例，原文在附录 D。样例里的风险、百分比、扣分扣款是那一周的原话，不写入以后每一期。

本稿只定栏目和边界。会签前不建 skill、不落周报文件、不补写 W37。

会签后的真源：

```text
工程过程/领导周报/YYYY-Www.md
```

一周一份。PM 跑「本周领导周报」。skill 先读这一周的 `当日进展/`、各维 `进度.md` / `风险.md`、当周仍有效的里程碑；对不上的栏目写成「待 PM 补」。PM 确认之前，文件标「草稿，未发」。

周报不代替 §8 当日表。当日表按人按天；周报按周给领导，从这一周已经落盘的事实收口。

### 9.1 栏目（顺序固定）

1. 标题：`YYYY-Www（M/D～M/D）`
2. **本周进度**：`□ 按计划  □ 超前  □ 滞后（滞后需说明）`。三选一。勾「滞后」时，关键风险里要有说明。skill 不勾选，由 PM 或项目负责人说。
3. **关键风险**：编号列表。样例里的 ⚠️、@人、扣分扣款，只在当周有人这样说时才写入，不作为固定结尾。
4. **关键进展**：编号列表。一条一个已发生的事实，带来源。
5. **里程碑对照**：

   | 里程碑 | 计划完成时间 | 实际状态 | 关键产出 | 进度百分比说明 |
   |---|---|---|---|---|

   行取当周仍有效的里程碑，不把附录 D 的八行冻成永久清单。实际状态用：已完成 / 进行中 / 延后 / 待启动。百分比只抄当日进展或监管人口令里的原话；没有原话就写「未见百分比」，不估算。关键产出可以链到截图或清单，不把样例里的那张图当成每期都有。

6. **本周工作内容**：

   | 系统 | 上周工作 | 本周工作计划 |
   |---|---|---|

一行一个系统。样例只有「04-科技信息展示系统」，期数变了就按当周范围增行，不固定这一行。「上周工作」对照上一份周报的「本周工作计划」和这一周的当日进展；没做的写未做。「本周工作计划」由 PM 收口，不把任务标题自动写成承诺。

7. **关键问题及解决情况**：编号列表。
8. **重点工作**：编号列表。
9. **风险与求助**：先写有没有红色风险，再编号写仍要协调的事。样例开头是「暂无红色风险，需持续协调外部依赖」。没有红色风险时可以沿用这句；后面的条目必须是当周事实。
10. **下一步重点**：编号列表。
11. **红色风险直通通道（条例第十六条）**：没有就写「暂无」。条例原文的链接会签时补，本稿不编条文。
12. **投入与人天**：样例在飞书里是文档外的块，导出没有带出表体。栏名会签时对照原帖定。仓内第一版先留同名一节；没有工时口令就写「待补」，不估人天。
13. **可复用资产沉淀**：没有就写「暂无」。

### 9.2 不写入周报的

- 口令、流水、风险文件里没有的百分比、人天、滞后、扣分、扣款
- 把智树内部需要日写成对方承诺
- 用附录 D 的原句填下一期（包括「连续 2 周无开发进展」「启动扣分、扣款流程」）

## 10. 分项联调

子项同时满足三条，就可以记联调，不必等兄弟任务发布：

1. 边界已经写进已签收方案或我方对接文档
2. 测试环境可调，或 `约定时点.md` 里写了这一段用空态 / 桩
3. 该子项已发布，或监管人声明这一段不依赖发布（例如菜单跳转）

联调记两处：`进度.md` 一节（通过 / 阻塞 / 对方未到），`沟通流水.md` 一条。阻塞升级走现有任务状态 `blocked`，原因与过程夹同一句话。

对方说「无法提供」时，一个工作日内由 PM 写成三选一：替代源、降级空态、范围变更。变更范围仍由项目负责人和 scope-baseline 决定，不在流水里改口径。
