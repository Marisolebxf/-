# {PIPELINE} · 变更总控（基线之后）

> **复制到**：`agent-handoffs/{模块}/{PIPELINE}-变更总控.md`  
> **日期**：YYYY-MM-DD  
> **授权**：`human:{真名}`（本管线监管人；后续认领不必再问）  
> **分类确认人**：`{coordinator / 数据 lead / architect / schema_owner}`  
> **效力**：本管线施工合同，不是全局铁律。  
> **规约**：[`长任务执行规约.md`](../长任务执行规约.md)（联调闸门、同仓一单、段 E、C1–C6）

**何时用本模板**：初次长任务（或等价 as-built）已立，还要动契约、结构或调用边界。  
**何时不用**：

| 情况 | 去哪 |
|------|------|
| 还没有基线，要把链路第一次跑通 | `templates/long-task-control-template.md` |
| 金路径红了，但契约与结构未变 | `templates/long-task-e-defect-pack.md`（禁止用本模板开迷你长任务） |

三者互斥：同一变更只走一条。

国科信层名对照（仅旁注）：存储≈A · 计算≈B · API≈C · UI≈D · 验证≈E。正文按五层填写，不要把未冲击段再开一遍。

## 0. 分类（必填）

四选一。写清**为什么不是邻类**。缺陷禁止填本表往下施工。

| 类 | 何时 | 拍板 | 任务形态 |
|----|------|------|----------|
| 缺陷 | 行为错 / 5xx / 错跳；契约与结构未变 | coordinator 确认失败分类 | **停**。改走缺陷包 |
| 兼容扩展 | 加列 / 加字段 / 加只读接口；旧客户端可忽略 | 数据 lead 改 mapping 与指标 version；architect 知情 | 迷你链：真源 → 受影响层 → 故事差集 → 相关金路径 |
| 破坏性结构 | 改主键、拆表、换索引、改 Job 快照语义 | `schema_owner`（例：`human:李伟`）闸门；正式库另走库闸 | 新迷你长任务 + expand → migrate → contract |
| 架构边界 | 换调用链、拆模块、迁仓、换门面目标 | architect RFC + PM 双签；先改 `architecture-baseline` | 新总控；门面切流（扩展新路 → 切读 → 停旧 → 删旧） |

| 字段 | 值 |
|------|-----|
| 本轮分类 | 兼容扩展 / 破坏性结构 / 架构边界 |
| 不是邻类因为 | |
| 分类确认人 | `human:{真名}` |

## 2. 爆破半径

未冲击层写「本轮不开」。从被破坏的那一层往下游开，上游已稳定默认不动。

| 层 | 国科信对照 | 本轮 | 要点 |
|----|------------|------|------|
| 存储 | A | 动 / 不开 | |
| 计算 | B | 动 / 不开 | |
| API | C | 动 / 不开 | 一 REST 路径一叶（若本轮动 C） |
| UI | D | 动 / 不开 | **差集**；禁止从零复刻人审页 |
| 验证 | E | 动 / 不开 | 只重开被冲击金路径 |

## 6. 并行变更（仅破坏性结构 / 架构边界）

三步：**expand**（新结构并存）→ **migrate**（调用方迁到新）→ **contract**（删旧）。

**默认不是双写。** 双写 = 同一次业务操作往两套并行结构各写一遍。无共享事务时失败会永久不一致。

| 默认 | 本轮怎么做 |
|------|------------|
| 一个真源写入 | |
| 下游派生（ETL / Job / CDC） | |
| 读切到新结构的条件 | |
| 删旧截止日期 | YYYY-MM-DD；到日必须有删旧叶 |

若仍要短窗口双写（须同一事务或可对账），必填下面三格，否则禁止开工：

| 双写窗口 | 对账方法 | 停写旧的日期 | 删旧叶 ID |
|----------|----------|--------------|-----------|
| | | | |

架构切流另写：新路铺上 → 切读（可金丝雀）→ 停写旧 → 拆旧。切流中不得破已拍板调用链（前端仍只调 Java 等）。

## 7. 红线

1. 禁止把初次 A–E 再跑一遍。  
2. 禁止推倒已人审前端；D 只差集。  
3. 禁止无闸门写正式库。  
4. 禁止缺陷走本模板。  
5. 禁止把双写写成无对账、无删旧日的默认第 2 步。  
6. git：commit `[agent:<role>]`；禁止 force；默认 `origin/dev`。

锁：`lock_hours=24`。`claim_type=coordinator_dispatch`。每叶 handoff + `ponytail:` + cost 四字段。
