## 2. 字段角色怎么读（第 5 列，单独一列）

| 角色 | 判定 | 例子 |
|---|---|---|
| **主指标**（黄底） | 页面看板/卡片直接展示的结果数 | 瓶颈堵点数、城市平均技术力、重点企业全景图里的重点企业总数 |
| **依赖指标** | 计算主指标用到的下层维度/子指标，页面以"维度行"呈现，不是独立 KPI | 产业瓶颈堵点识别的「技术」「人才」维（统一演示位 `M_CHAIN_BOTTLENECK_TYPE_DIST`）、痛难点类型卡 |
| **计算入参指标** | 分析配置页用户可调（或只读确认）的参数/权重，任务提交时冻结 | 周期分析的「市场规模/市场增长率/利润率/技术成熟度」、评估模板五维权重、招引判定模型三维 |

同一行里三者的关系：**主指标 = f(计算入参, 依赖指标)**；「依赖哪些久新数据」列给的是**整个算式**用到的久新候选，不区分角色（角色看第 5 列）。

## 3. 核心澄清：页面上的「技术」「人才」不是独立指标

以「产业瓶颈堵点识别」页为例：配置里五维（技术/人才/市场需求/资本/政策）**统一挂在同一个页面演示位** `M_CHAIN_BOTTLENECK_TYPE_DIST` 上，「技术」「人才」是该指标**计算逻辑里的依赖维度**（支撑指标：技术成熟度、关键设备、材料替代 / 人才供给量、岗位缺口、人才流动），不是 573 指标库里的独立条目。

本报告已按你的阅读习惯**把依赖维度单独拆行**，并用第 5 列标出角色：

| 页面位置 | 本报告的行（角色） | 久新候选 |
|---|---|---|
| 产业瓶颈堵点识别 · 分析配置 · 「技术」维 | 依赖指标（是·技术） | `M_TECH_MATURITY_LEVEL` → `ads_technology_stage_assessment` 等 |
| 产业瓶颈堵点识别 · 分析配置 · 「人才」维 | 依赖指标（是·人才） | `M_TALENT_SUPPLY_STRUCT` → `ads_talent_yearly_metrics`（原料在） |
| 产业瓶颈堵点识别 · 分析结果看板 | 主指标：瓶颈堵点数 / 瓶颈严重度 | 结果指标，五维聚合后产出 |
| 产业瓶颈堵点识别 · 分析配置 · 市场/资本/政策维 | 依赖指标（否） | 非三要素，本项不对接 |
