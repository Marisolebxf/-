## 0. 一分钟读法（给淮政玮）

1. 打开 xlsx 的 **`UI页面指标总表`** sheet，按「菜单 → 页面」筛选你要看的页面（如 产业瓶颈堵点识别）。
2. 每一行就是一个**页面上出现的指标或维度**，四列直接回答你的问题：
   - **「怎么算」**：口径/公式要点（来自我方 20261028 指标库调研 md，蓝色字可点开原文）；
   - **「依赖哪些久新数据」**：该指标的计算过程依赖哪些维度，其中哪些维度久新库有现成候选（候选 metric_id + 候选表）；
   - **「久新 schema 章节 / 公式章节」**：蓝色字直开对端 [ADS_SCHEMA-5.11.0 快照](../../../../../工程过程/04-系统集成/02-对接三要素/对接文档/对端/2026-10-22-ADS_SCHEMA-5.11.0.md) 的对应行；
   - **「怎么补/怎么mock」**：按「结果表在 / 原料在 / 无候选」三档给出补数路径与 mock 建议。
3. 想看某个依赖维度的久新候选细节（字段粒度），切到 **`三要素依赖×久新明细`** sheet（103 行，一候选一行）。

## 1. 核心澄清：页面上的「技术」「人才」不是独立指标

以「产业瓶颈堵点识别」页为例：配置里五维（技术/人才/市场需求/资本/政策）**统一挂在同一个页面演示位** `M_CHAIN_BOTTLENECK_TYPE_DIST` 上，「技术」「人才」是该指标**计算逻辑里的依赖维度**（支撑指标：技术成熟度、关键设备、材料替代 / 人才供给量、岗位缺口、人才流动），不是 573 指标库里的独立条目。

本报告已按你的阅读习惯**把依赖维度单独拆行**：

| 页面显示 | 本报告的行 | 久新候选 |
|---|---|---|
| 产业瓶颈堵点识别 · 「技术」维 | 依赖维度行（是·技术） | `M_TECH_MATURITY_LEVEL` → `ads_technology_stage_assessment` 等 |
| 产业瓶颈堵点识别 · 「人才」维 | 依赖维度行（是·人才） | `M_TALENT_SUPPLY_STRUCT` → `ads_talent_yearly_metrics`（原料在） |
| 产业瓶颈堵点识别 · 市场/资本/政策维 | 依赖维度行（否） | 非三要素，本项不对接 |

## 3. 「怎么补 / 怎么mock」四档口径（总表第 16 列）

| 档 | 判据 | 建议 |
|---|---|---|
| ① 直读 | 久新候选「结果表在」 | 结果表直读 + 口径映射（未对齐需换算）；mock 先按该表行造演示值并标注「演示」 |
| ② 自算 | 久新候选「原料在」 | 从久新原料表现算；字段缺口见 schema 章节；mock 用权重演示值 |
| ③ 等灌库 | 三要素依赖但 93 条无直接候选 | 先 mock / 空态，等 WBS-02-04 ADS 灌库；禁止用演示默认冒充久新数 |
| ④ 非三要素 | 企业/市场/资本/政策维 | 走我方开发库 / ADS 预填 / 页面手填；mock 用演示默认值 |
