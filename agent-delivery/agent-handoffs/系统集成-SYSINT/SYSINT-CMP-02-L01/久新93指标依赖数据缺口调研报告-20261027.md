# 久新 93 指标依赖数据缺口深度分析（2026-10-27）

> 任务：`SYSINT-CMP-02-L01`（久新 vs 本地 565 指标设计对照）补充交付物。  
> 回答的问题：**对本地版 93 个三要素指标逐条来看，其依赖的指标/数据在久新 130 张表里缺什么、缺到什么程度**。  
> 证据来源：本目录 `分析过程文件/_final_scores.json`（93 指标逐依赖映射）、`_local_miss_v2.json`（缺口叙事与四级查证）、`_local_miss_in130.json`（口径性缺口 9 条）。  
> 配套明细表：[久新93指标依赖数据缺口分析-20261027.xlsx](./久新93指标依赖数据缺口分析-20261027.xlsx)（4 sheet，下文逐一说明）。

## 1. 缺口分级口径

对每个指标，先从其设计 md 提取依赖表/维度清单，再逐个到久新 130 表中核对（同名 → 同义 → 语义映射三步），按缺口严重度分 5 级：

| 等级 | 含义 | 条数(93 指标共 370 条依赖中) |
|------|------|------|
| **L0 两库均无** | 第三方库与久新 130 表都拿不到，该依赖无解 | 2 |
| **L1 三方库有但 130 表无** | 本地设计用了三方库表，久新库未建对应表；按久新版走此依赖缺失 | 12 |
| **L2 三方库弱且 130 表无** | 三方库仅残量（约 10 行），久新库也无——两版都缺 | 5 |
| **L3 130 表未映射** | 久新 130 表无同名/同义承载表，逐表核对未命中 | 188 |
| **L4 已映射但身份口径不同** | 有映射但实体身份体系不同（如 OpenAlex 论文身份），数值需对账折算 | 26 |
| 其他 | 语义特殊映射（如 `dwd_source is_core`→CWTS 标记），逐条见 xlsx | 1 |
| ✓ 已映射 | 依赖可由 130 表直接承载 | 136 |

> **一句话结论：370 条依赖中，只有 136 条（37%）能被久新 130 表直接承载；近半数（188 条，51%）在久新库里根本找不到承载表。**

## 2. 指标级结论（93 项分布）

按"该指标最严重缺口等级"统计：

| 最严重缺口等级 | 指标数 |
|------|------|
| 完全可映射（所有依赖都有 130 表承载） | 20 |
| L4 身份口径不同 | 1 |
| L3 130 表未映射 | 55 |
| L2 三方库弱且 130 表无 | 3 |
| L1 三方库有但 130 表无 | 12 |
| L0 两库均无 | 2 |

即：**73 项指标（78%）至少有一个依赖在久新 130 表无法直接承载**；只有 20 项全部依赖可由 130 表映射（集中在技术链图谱/成熟度域与人才流动/关系域）。逐指标明细见 xlsx Sheet1「93指标依赖缺口总览」。

## 3. 最严重的缺口（逐条点名）

### 3.1 L0 两库均无（2 条，无解）

| 主指标 | 缺失依赖 | 影响 |
|--------|----------|------|
| `M_TECH_DEEP_130_1` | `dwd_event`（事件表） | 技术链事件类指标无法计算，两版数据源都没有 |
| `M_TECH_DEEP_132_1` | `dwd_event`（事件表） | 同上 |

处置建议：这两项指标需改口径（去掉事件维）或推动数据源建设，二选一，不能沿用现设计直接上线。

### 3.2 L1 三方库有但 130 表无（12 条，久新库结构性缺口）

**`dwd_org_annual_financial_info`（机构年度财务信息）** 被最多指标引用且久新 130 表完全没有——这是久新库最大的单点缺口：

| 主指标 | 依赖支撑度 |
|--------|-----------|
| `M_ORG_TECH_SCORE` | **0/2（全缺）** |
| `M_ORG_BASE_99_1` | 8/10 |
| `M_ORG_CULTIVATE_SCORE` | 2/4 |
| `M_ORG_DEEP_149_1` | 3/4 |
| `M_ORG_DEEP_151_1` | 4/6 |
| `M_ORG_DEEP_154_1` | 1/2 |
| `M_ORG_DEEP_155_1` | 4/5 |
| `M_ORG_GRAPH_114_1` | 4/6 |
| `M_ORG_PERF_QUERY` | 1/2 |
| `M_TECH_INVEST_AMOUNT` | 2/5 |
| `M_TALENT_DEEP_156_1`、`M_TALENT_DEEP_159_1` | 与 dwd_job 叠加缺失 |

**`dwd_job`（招聘岗位表）** 三方库也仅约 10 行残量，久新库亦无：影响 `M_TALENT_ATTRACT_SCORE`(7/9)、`M_TALENT_DEEP_156_1`(7/10)、`M_TALENT_DEEP_157_1`(4/5)、`M_TALENT_DEEP_159_1`(3/6)、`M_TALENT_DEEP_161_1`(2/4)。

**含义**：财务与招聘两类数据是「科研机构域」「人才吸引力域」的本地设计刚需，久新库完全没有建设。若采用久新版走这些指标，等于降级为无财务/招聘信号的残缺口径。

### 3.3 L3 130 表未映射（188 条，量大面广）

量最大的模式是：本地设计大量引用三方库 DWD 明细表，久新 130 表是按**自家指标公式**建的结果/原料表，没有这些明细层。被引用最多的未映射依赖 Top 5：

| 缺失依赖 | 被 N 个指标引用 | 典型影响域 |
|--------|------|------|
| `dwd_zh_project`（中文项目表） | 20 | 人才科研项目、机构项目 |
| `dwd_patent_transfer`（专利转让） | 15 | 技术转化、专利运营 |
| `dwd_scholar_talent_flag`（人才称号标记） | 12 | 人才认定类指标 |
| `dwd_research_institute_base_info`（研究院所基础信息） | 10 | 机构画像 |
| `dwd_org_recruit_info`（机构招聘信息） | 9 | 机构引才 |

> 注：`dwd_zh_paper`（26 个指标引用）在 130 表有 OpenAlex 映射但身份口径不同，计入 L4，见 3.4。

典型样例（`M_TECH_BASE_96_1`，8 个依赖仅 1 个有映射）：

```
dwd_bid_base_out→未映射; dwd_deal→未映射; dwd_industry_chain_news_info→未映射;
dwd_patent→ads_patent_profile[130表]; dwd_patent_transfer→未映射;
dwd_zh_author→未映射; dwd_zh_paper→ads_paper_profile(OpenAlex)[口径不同]; dwd_zh_paper_classification→未映射
```

这正是四轮裁决中 R1（需规度）淘汰久新 48 条的底层原因：**久新没有按我方需求文档的依赖结构建表，而是按自家 93 指标的公式重建**。

### 3.4 L4 已映射但身份口径不同（26 条，数值不可直接比）

主要是论文/专利/学者三类实体：

- `dwd_zh_paper → ads_paper_profile(OpenAlex)`：久新用 OpenAlex 学术身份体系，我方用中文学术库（zh 前缀），同一篇论文两库身份不同，**引用数/期刊字段需对账折算**；
- `dwd_patent → ads_patent_profile → ads_talent_patent → ads_institution_patent`：专利链路可通，但申请人/发明人实体需要对齐；
- `dwd_source is_core → CWTS Core`：我方「期刊影响力/影响因子」维度，久新库只有 CWTS 收录标记（是/否），**没有 IF 数值**——`M_TECH_COMPOSITE_SCORE`、`M_TALENT_ACADEMIC_SCORE` 的五维口径因此被迫降维。

### 3.5 口径性缺口速查（`_local_miss_in130.json` 全部 9 条）

| 主指标 | 缺失的维度/表 | 130 表现状 |
|--------|--------------|-----------|
| `M_TECH_EDGE_STRENGTH` / `M_TECH_ENTITY_REL` | `dwd_patent` | 需经 ads_patent_profile→ads_talent_patent→ads_institution_patent 三跳换身份 |
| `M_TECH_DEEP_130_1` | tech_chain_edge / tech_chain_node / tech_domain | 有 ads_technology_graph_edge/node，tech_domain 仅候选簇 |
| `M_TALENT_CULTIVATE_SCORE` | `dwd_scholar` | 走 ads_talent_profile→ads_talent_yearly_metrics |
| `M_ORG_GRAPH_114_1` / `M_TECH_DEEP_135_1` / `M_TECH_BASE_96_1` | 学科维 | 130 表用 OpenAlex Topic 体系，无我方学科分类 |
| `M_TECH_PAPER_PATENT_CNT` / `M_TECH_COMPOSITE_SCORE` | tech_domain / 期刊影响力 | 候选簇 / CWTS 标记非 IF |

## 4. 依赖四级查证（21 项重点指标的结构+数据双重核对）

对 21 项重点指标做了「直接结构 / 直接数据 / 依赖结构 / 依赖数据」四级查证（xlsx Sheet4），共性结论：

- **依赖结构普遍具备**（学者主档、论文面、专利面三列齐全）；
- **依赖数据普遍"部分"**：典型如 `M_TALENT_ACADEMIC_SCORE`——论文/被引/H 指数三维 100% 非空，但**期刊影响力整列为空**、合作广度只有计数无维度；`M_TALENT_DEEP_164_1` 的「产品匹配度」**零字段**；
- **没有任何一项拿到"直接结果表"**：久新 130 表中没有与我方 93 指标同名的现成结果表，全部需要按我方口径重算。

## 5. 对决策的三点支撑

1. **四轮裁决数据侧复核**：本地胜 65 / 久新胜 26 的格局与本缺口分布一致——久新胜出的 26 条全部是"久新已算好落表"且依赖可映射的项；
2. **接入 130 表时的对账范围**：L4 的 26 条依赖（OpenAlex 论文身份、专利实体、CWTS 收录标记）是数值对账的重点清单；
3. **数据源建设清单**：L0/L1/L2 涉及的 `dwd_event`、`dwd_org_annual_financial_info`、`dwd_job` 三张表，是无论采用哪方设计都缺的公共缺口，建议单独立项补数据。
