## 0. 结论先行

1. **130 张表没有发现一张「mock 假数据表」。** 用户假设的第四类——「字段名和接口名一模一样、无来源无计算、直接出结果分」——经全表扫描后**数量为 0**。九新的工程纪律是：算不出来就 NULL + 状态字段披露（`coverage_status` / `unavailable_reason` / `mapping_status`），大模型结果就带完整溯源（provider / model / prompt_version / input_hash）发布，从不静默造数。
2. **但「直接抄第三方库」的表也几乎没有**——130 表里没有任何一张是三方库表的原样复制。九新的真实做法是：**把 OpenAlex 等外部学术数据源 + 甲方三方库的原料，按自己的公式加工成「以 talent_id / institution_id / technology_node_id 为主键的结果表」**。三方库的字段名只保留在描述性列上（名称、日期、DOI、地址）。
3. 四级分类结果（逐表证据见 xlsx sheet 1）：

| 类 | 表数 | 行数合计 | 含义 |
|---|---:|---:|---|
| **A 直接来自第三方库**（描述性直采/画像） | 50 | 52,372,062 | 字段与总集要素库同名（≥半数字段命中），如论文/专利 profile、机构画像的名称地址列 |
| **B 久新公式计算**（schema 有完整公式章节） | 14 | 32,790,879 | 学术力/潜力/技术力/热度/阶段/堵点/流动/合作等，公式含权重+标准化+NULL 语义 |
| **B⁻ 公式计算（弱证据）** | 22 | 9,879,193 | schema 有加工/去重/证据约束描述但无独立公式节（产业参与、地区年度、图谱演进等） |
| **B-LLM 生成（带溯源）** | 8 | 48,192 | DeepSeek 二阶段判断：月度估算、语义关系、机构匹配、战略建议等，`AUTO_APPROVED_LLM` |
| **C 久新自有原料/中间表** | 31 | 27,040,345 | 无公式章节无强溯源词，key+计数+日期结构，多为明细关联表 |
| **E 空表**（预留/证据未到） | 5 | 0 | 月度事实表、堵点/政策证据表等 |

4. **必须澄清的一个事实**：用户提到「久新根据**第三方库**的表计算」——实测发现九新的主原料**主要不是甲方三方库，而是 OpenAlex 学术图谱**（论文、作者、机构、Topic/Domain 学科体系、CWTS Core 期刊列表），辅以甲方三方库的专利/项目/机构数据。`ads_discipline_*` 四张学科表的 `openalex_domain_id` 注释「仅作来源映射」是直接证据；schema 学术力公式也明确「固定 400 万篇 MVP core 论文及其固定 OpenAlex Source Snapshot」。三方库 180 张表中 93 张在久新库还没有同主题主体（调研记录 §4），两库主键（`patent_id` 同名不同义）也未打通。

## 1. 调研过程与证据采集方法

### 1.1 数据底座

| 步骤 | 方法 | 产物 |
|---|---|---|

| ④ schema 溯源扫描 | 对 ADS_SCHEMA 快照 80 个表章节做来源关键词统计（OpenAlex/dwd_/CWTS/MVP/LLM/DeepSeek/模拟/预留…） | `_work/_schema_kw.json` |
| ⑤ 公式章节人工核实 | 逐个阅读 §4.0.1/4.0.2/16.1/17.1/17.3/17.4/20/21/22/24.4-24.8/25/26-29 | 本文档 §2/§3 |
| ⑥ 反向验证 | 对初判「疑似 mock」的 31 表逐表回读 schema 原文，核实后大部分改判（见 §4） | 本文档 §4 |

### 1.2 分类的证据标准

- **A**：≥50% 字段与三方库同名，且评分类字段（score/rank/level/stage…）≤1 —— 描述性画像/直采；
- **B（强）**：schema 有独立公式章节（含权重、标准化公式、NULL 语义、版本号），且库内有结果行；
- **B⁻（弱）**：schema 有来源/加工描述（去重顺序、证据约束、覆盖率状态）但无独立公式节；
- **B-LLM**：schema §26–29 声明 DeepSeek 生成，带 `inference_provider/model/prompt_version/input_hash/generated_at` 五件溯源字段；
- **C**：无公式章节、无强溯源词、字段结构为 key+计数+日期的明细/中间表；
- **E**：实测 0 行。

## 3. A 类：与第三方库的关联性（「直接来自」的真实含义）

### 3.1 实测：129/130 表共 337 个字段与总集三方库同名

xlsx sheet 2 逐字段标注了命中（如 `ads_paper_profile` 的 `paper_id/doi/title/publication_date`、`ads_patent_profile` 的 `patent_id/publication_number/application_number`、`ads_institution_profile` 的 `name/country_code/province_name/city_name/latitude/longitude`、`ads_talent_profile` 的 `name/gender/title/email`）。**但同名 ≠ 同值同源**：

- 调研记录 §4 抽查：学者主表同名字段 6 个、机构主表 0 个、外文论文 7 个、专利 3 个、国内项目 0 个；`patent_id` 同名但是**两套不同 ID**；
- 久新人才主键 `talent_id`，三方库 `dwd_scholar` 主键 `dwd_id`——不同套；
- 三方库 180 张表里 93 张在久新库没有同主题主体（金融/产业链/医药/化学/海洋/量子专题/报告/政策等久新全都没有）。

### 3.2 真实来源结构（比「第三方库」更准确的说法）

```
OpenAlex（论文/作者/机构/Topic/CWTS Core）──┐
甲方三方库（专利/项目/机构/政策…）─────────┼──> 久新 DWD 加工（dwd_author/dwd_source 等）
九新自有清单（400 问题、研究簇候选、产业分类）──┘        │
                                                        ▼ 公式计算（§4-29）
                                              130 张 ads_* 结果表（talent_id/institution_id/
                                              technology_node_id/problem_id 主键体系）
```

证据：`ads_discipline_domain.openalex_domain_id` 注释「仅作来源映射」；学术力公式绑定「固定 OpenAlex Source Snapshot」；`ads_paper_profile` 身份是 OpenAlex work（`paper_id` 缺失时用 `openalex:` 来源 ID 回退并标 `SOURCE_ID_FALLBACK`，§27.6）；`ads_industry` 首版来自「国家知识产权局 2018 年 IPC–国民经济行业参照表 GB/T 4754—2017」（§17.3，这是九新自有参照表，非甲方三方库）。

**给用户的准确表述**：A 类 50 表不是「直接复制三方库的表」，而是「以 OpenAlex/三方库为原料、按久新自己的主键体系重建的画像/事实表，描述性字段与三方库同名」。

## 4. 「疑似 mock」的排除过程（第四类的证伪）

初判规则（score 字段 ≥3 且无溯源词）曾命中 31 表，逐表回读 schema 原文后全部改判：

| 初判 D 的表 | 回读证据 | 终判 |
|---|---|---|
| `ads_talent_collaborator`（505 万行） | §8：合作计数按论文/项目/专利分别去重，`collaboration_score` 有口径与版本字段（`patent_metric_definition_version`、as_of 日期） | B⁻ |
| `ads_talent_topic_profile`（685 万行） | §7：Topic 计数/覆盖率/引用全有定义，`paper_coverage_ratio` 分母 0 为 NULL 且注明「跨 Topic 之和可大于 1」 | B⁻ |
| `ads_technology_profile`（19,430 行） | §24.12.1：`research_cluster_id` 来源 ETO 研究簇，`tech_id` 空是**显式状态**（`mapping_status`），中文译名空因为未审核 | C（候选簇事实表） |
| `ads_research_problem_strategic_advice`（406 行） | §28：**骨架表**，priority/action 分「当前 NULL」，明确写「不用热点分静默替代战略优先级」 | B-LLM 骨架 |
| `ads_institution_industry`（135 万行） | §17.3：IPC 证据+发明人任职约束生成 | B⁻ |
| `ads_research_problem_*` 明细 20+ 表 | §26/27：发布带 Iceberg/Doris 双端行数对账、重复 Key=0、26 项语义校验=0 | B⁻/C |

**九新的「不可计算」处理模式**（这是判断不是 mock 的关键证据）：`ads_research_problem_monthly_metrics` 真实月度事实表**保持 0 行**，另开 `monthly_estimate` 估算表并标 `LLM_TEMPORAL_DISTRIBUTION`；政策/堵点证据表 0 行并注明「外部证据未到，0 行不能解释成没有政策」（调研记录 §3 转述 schema）；§27 总则「所有不可计算值使用 NULL 或零行空表，必须同时给出 coverage_status/unavailable_reason」。

**最接近「虚」的三处**（如实披露，但都有显式声明）：① 战略建议/部署骨架表大面积 NULL；② 月度估算是模型分布估算非事实；③ 技术节点仍是候选簇（`tech_id` 空、UNMAPPED、中文名未审核）。这三处 schema 均有状态字段自我披露——属「诚实空值」，不是 mock。

## 5. C 类 31 表清单与风险

多为明细关联/中间表：问题域 `ads_research_problem_paper/project/patent/keyword/discipline/yearly_metrics` 等 20+ 表（§26 声明「发布使用固定 DWD Snapshot，大模型仅生成说明性增强字段」）、`ads_talent_experience`（经历：教育/工作，注释「仅知年份时不伪造具体日期」）、`ads_talent_collaborator`、`ads_technology_application_case`（「不是已验证市场应用」，case 固定 RESEARCH_PROJECT）等。判断：来自 OpenAlex/三方库加工但**公式未写进 schema**，消费前要么问九新要方法，要么按黑盒对账。

## 6. 残留风险与行动建议

1. **口径黑盒**：C 类 31 表 + B⁻ 22 表公式未完整披露（53/130）——向九新要「计算方法补充文档」或接受抽样对账；
2. **主键桥**：talent_id/institution_id/technology_node_id/problem_id 四套主键与我方 dwd_* 全部不同套；`patent_id` 同名不同义——必须建映射桥，不能靠字段名对上；
3. **tech_id 依赖**：正式技术目录映射未发布（schema §24.10 自列 12 项缺失：政策/市场/产品落地/供应链/专家验证/中文译名等）；
4. **LLM 表使用纪律**：8 张 B-LLM 表只作增强，读溯源字段，NULL 骨架不当 0 用；
5. **甲方三方库≠久新原料**：93/180 张三方库表久新没有对应主体；不要假设「久新算过三方库的所有数据」。
