## 0. 结论先行（决策建议）

**裁决方法**：不采用单纯加权求和，而是**四轮逐级裁决**（前一轮分出胜负即终止）：
R1 需规度淘汰（未严格按需求文档设计的一方出局）→ R2 比依赖指标支撑度 → R3 比权威引用摘录 → R4 加权求和兜底。

**总体推荐：以本地 565 指标设计为主干、久新 130 表作为数据供给层接入，不整体改用久新指标体系。**

| 决策维度 | 结果 |
|---|---|
| 四轮裁决后逐条胜负（93 条） | **本地 65 / 久新 26 / 相当 2** |
| R1 需规度淘汰 | **48 条久新版直接出局**：这 48 条久新只有原料表（42）或连数据都没有（6），即久新根本没为这些指标做设计（无公式无结果），需规度 0.55<0.7 不达标 |
| R2 支撑度决胜 | 18 条久新胜（双方需规均达标、久新版依赖指标支撑度 1.0 高于本地版 0.33~0.86——因为结果已算好落表） |
| R3 权威引用决胜 | 25 条定胜负：本地 21 / 久新 4（技术链阶段/热点/潜力族本地 md 权威引用偏少处，久新靠 OpenAlex/CWTS 数据源锚胜出） |
| R4 加权求和兜底 | 仅 2 条打到兜底轮，均记「相当」（`M_TECH_HEAT_QUERY`、`M_TALENT_GRAPH_110_1`） |

**对久新版胜出 26 条的处置原则**：其中 18 条 R2 胜出的本质是「久新已经把结果算出来了」，不是设计更优——**口径正本仍在本地 8 件套，数值消费久新结果表 + 对账通过后使用**；R3 胜出的 4 条（技术阶段/热点等）可参考久新的数据源选择（OpenAlex 标签投影）改进本地公式，但不照抄自建 MVP 方法。

| 分类 | 条数 | 说明 |

| ⑤ 找不到且没必要 | 0（93 内） | **但有一个域外重要发现**：久新 130 表中体量最大的「研究问题」域（45 张表，`ads_research_problem_*`）在三份需求文档（《科技信息展示系统和科技专题服务系统》《政策对比功能升级核增需求》《科技专题服务算法库》）中**0 次命中**——这 45 张表支撑的指标完全是久新自行设计、无任何需求文档出处，属标准⑤类。若未来有人提议接入，按⑤类处置：无需求依据，不接 |

## 2. 三维优劣性对比（要求的第二项分析）

### 2.1 需规度（第一轮裁决用，最重要）

**评分设计（两边分开计分）**：
- **本地版需规度** = 挂需求叶 0.5 + 需求文档原文行号 0.2 + 需求维度展开 0.2 + 需求对象逐一对照 0.1 → 93 条全部满分 1.0；
- **久新版需规度** = 挂需求叶 0.5 + 为该指标做出公式设计 0.2 + 维度覆盖 0.05~0.15 + 需求文档引用 0（久新 schema 零需求文档引用）→ 仅「久新已算好」的 45 条达标（0.70~0.85），「只有原料表/没有数据」的 48 条不达标（0.55）出局。
达标线 0.7。

定性结论：
- **本地**：每份 md 有「需求定义概述」节，逐句拆需求原文点名对象（如学术力把「学术影响力、h 指数、学科贡献度」三个被点名对象逐一对照），并显式声明偏离（如「seed 要求不展开公式，本文属实现层展开」）——**需求可追溯性是本地设计最强的部分**；
- **久新**：schema 只描述表和算法，不引用需求文档；其符合需求的证据是「覆盖了同一批 seq 库叶」这个间接事实。**例外**：久新在需求要求的「必须依赖指标」上更完整——例如学术力需求的五维（论文/被引/H/期刊/合作广度），久新五维全建模（期刊维用 CWTS Core 覆盖近似、合作维有 `collaborating_expert_count`），本地因三方库两维缺数据直接降级交三维。

### 2.2 依赖指标支撑度（第二轮裁决用）——本次分析的关键新发现

**方法**：拆出两边各自指标的依赖指标/依赖表，在「三方库 + 久新 130 表」合并数据面上找承载，算「足够支撑计算的依赖指标占比」。

- **本地侧**：93 份 md 点名的依赖表（`dwd_scholar`、`dwd_patent`、`dwd_zh_project` 等 40+ 张）先查三方库（原本地设计只考虑三方库，支撑率仅 0.52），**再补查 130 表**：`dwd_scholar→ads_talent_profile`、`dwd_zh_project→ads_project_profile`、`dwd_patent_cited→ads_patent_cited_paper`、`dwd_scholar_edu→ads_talent_experience`、`dwd_org_tech_tag→ads_institution_discipline_profile` 等逐一语义映射（完整映射链见 xlsx sheet 1 列 M 与 `分析过程文件/_match5_cover.json`）。合并后支撑率升至 **0.82**；
- **久新侧**：按库内支持档折算（结果表在=1.0 / 原料在=0.5 / 还没有=0），均值 **0.71**；
- **原先「本地两库均无」的表在 130 表中找到候选承载的典型**（要求中专门点名的分析）：
  - 学术力的期刊影响力维：本地 md 写「`dwd_zh_journal.impact_score` 整列为空」→ 130 表 `dwd_source.is_core`（CWTS Core 覆盖）可作近似承载（非 IF，久新自己也声明「不表示 JCR 分区/影响因子」）；
  - 合作广度维：本地只有合著计数 → 130 表 `ads_talent_collaborator.collaborating_expert_count` 同样只有计数（两边此维都弱）；
  - 机构痛点/成果提炼类：本地写「横向课题、技术服务合同没有进表」→ 130 表同样无（久新 schema §24.10 自列「市场事实/供应链/专家验证」缺失）；
  - 技术链结果面：本地写 `tech_chain_node/edge` 零命中 → 130 表 `ads_technology_graph_node/edge` 有数据（但 `tech_id` UNMAPPED，属候选簇）。
- **仍然两边都缺**：招聘（`dwd_job` 10 行 / 130 表无）、事件流、证券/并购/招投标/融资（三方库有、130 表无）、政策证据（130 表仅 LLM 关联 1,213 行）。

### 2.3 权威性（第三轮裁决用）

**评分设计**：本地 = md 中权威方法引用密度（OECD《弗拉斯卡蒂手册》、ESI、Hirsch h 指数、PageRank/介数中心性、TRL、GB/T 国标、软科/QS/THE 等，5 处满分 1.0）；久新 = 公式完备度 0.4 + 权威数据源锚（OpenAlex/CWTS）0.3。均值：**本地 0.62 / 久新 0.55**。

定性对比：
- **本地强在方法学引用**：如技术阶段判定本地引用 TRL 概念并声明替代关系、学术力引用 Hirsch h 指数与 ESI 分区、中心性类引用 PageRank/介数；
- **久新弱在方法自建**：版本号即自白——`talent_academic_mvp_v1`、`talent_potential_mvp_v1`、机构技术力「四指标 MVP」；阶段研判明确「规则基线，不是 TRL，也不是大模型结论」；热点「标签投影，不是全文短语抽取」。这些方法可用但学术/官方权威性不足；
- **久新强在数据源权威与工程严谨**：OpenAlex 学术图谱 + CWTS Core 期刊清单是国际公认源；平均名次标准化（处理并列值）是学界的标准做法，比本地部分指标的 min-max 更稳健；版本化发布（Iceberg/Doris 双端对账、input_hash 溯源、NULL 状态披露）达到生产级工程权威性。

## 3. 分域决策建议

| 域 | 胜负 | 建议 |
|---|---|---|
| 人才（32） | 本地 24 / 久新 5 / 相当 3 | 以本地为主干。学术力采用「本地五维框架 + 久新平均名次标准化方法 + 130 表五维数据」三者合成——本地唯一输在两维无数据，130 表恰好补上（近似承载），方法学取久新长处 |
| 技术链（39） | 本地 25 / 久新 11 / 相当 3 | 阶段/热点/潜力/堵点 4 族共 11 条直接消费久新结果表（对账后 D4 升 live），公式不照抄；图谱/路径类本地设计已够；`tech_id` 未正式映射前不接图谱联动 |
| 科研机构（22） | 本地 15 / 久新 5 / 相当 2 | 技术力/Topic 布局/合作链接久新结果；痛点/优势分析保持本地（久新也无）；机构口径统一过滤 `institution_type_id='company'` |

**三条通用原则**：
1. **口径正本永远在本地 8 件套**——久新结果进 `ads_sci_result_snapshot` 时必须带 `metric_id` 并通过对账，禁止前端直连久新语义；
2. **久新的 21 条胜出多因「结果已算出」而非「设计更优」**——消费其结果、消化其方法（平均名次标准化、NULL 状态披露、版本化发布），不迁移其指标体系；
3. **研究问题域 45 表（⑤类）暂不接入**，除非甲方新增需求；若接入需先过「需求文档补充 + 口径 8 件套注册」两道门。
