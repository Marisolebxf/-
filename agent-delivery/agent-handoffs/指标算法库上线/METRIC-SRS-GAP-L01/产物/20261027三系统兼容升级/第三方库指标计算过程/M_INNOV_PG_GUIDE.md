## 摘要

「政策导向」对应需求「发展战略引导力」（序号 152），要求从**前瞻性、系统性、针对性**三个角度评估政策是否引导产业方向、是否成体系配套、是否锁定具体对象。王惠 calc-logic 已登记本 ID，三性等权，每维以「命中件数 / 全部政策件数」计量。

`code/M_INNOV_PG_GUIDE.py` 零 SQL、0.21 秒复算 20,000 条政策，结论是三性里只有一性能算。前瞻性走「标题关键词 + 两级清洗」：原始命中 **742** 条（3.71%），剔除 64 条「城市建设/空间规划」类噪声后剩 **678** 条（3.39%），再用科技语义白名单收紧到 **50** 条真科技战略规划文件，占全库 **0.25%**。整条漏斗的误报率 **93.26%**，也就是说每 15 条被关键词判为「前瞻」的政策里，只有 1 条真是科技战略规划。系统性、针对性两维的输入字段实测为空：`quote_policy` 非空仅 **2** 条，`policy_support` 20,000/20,000 为小写 `null`。三性因此无法等权合成，本报告只交付前瞻性单维值。

前瞻性的城市切片更能说明问题：50 条里 **32 条（64.0%）城市为空**，四城合计只有 2 条，且全在深圳（879 条中 2 条，0.228%）；广州 325 条、东莞 8 条均为 0，惠州无记录。这不是「广州、东莞没有前瞻性政策」，而是科技战略规划这类文件主要发布在省级与国家级平台，地市级语料里本来就少。用四城做分母，前瞻性会被系统性低估。

结论：本指标判**部分支持**，可上线的是「前瞻性」单维占比及其 8 类政策导向族分布（顶层规划 8.78%、意见指导 10.46%、财政补贴 8.26%…），不可上线的是三性综合分。任何「政策导向综合得分」都必须等 `quote_policy` 与 `policy_support` 两列物化后才能做。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技发展态势 → 科技创新评估 → 政策与条件保障力指标展示 → 发展战略引导力分析**。

页面要回答的是「这一批政策有没有在引导方向」。用户看到的不该是一堆关键词命中数，而是三件事：政策有没有往前看（前瞻性）、有没有成套配套（系统性）、有没有指向具体对象（针对性）。三件事合起来才是「引导力」。只给其中一件，引导力就是残缺的。

页面操作上，用户通常会先选地域（省/市/区县）和时间段，再选政策类型，然后看三性得分或占比。因此本指标必须能按城市、按年、按类型切片。这一点直接决定了数据要求：切片维度所在字段不能为空，否则切片就是空表。

### 1.2 为什么需要「政策导向」这个指标

政策数量多不等于导向清晰。一个城市一年发 200 份文件，如果全是办事通知和公示公告，它的产业引导力其实很弱；另一个城市只发 30 份，但份份是五年规划和技术路线图，引导力反而强。数量型指标看不出这个差别，导向型指标才能。

第二个价值是对标。区域创新评估里，「政策是否聚焦」是常见维度。没有导向指标，评估只能数件数，结论会偏向发文多的城市。有了导向，才能区分「多而散」和「少而准」。

第三个价值是内部质检。前瞻性漏斗的 93.26% 误报率本身就是一条重要发现：说明如果直接用关键词匹配做标签，产出的标签九成以上是错的。这条结论对任何要基于 `title` 做文本分类的下游任务都成立。

### 1.3 需求文档是否给出定义方法

**需求文档没有给出公式，也没有给出三性的操作定义。** 序号 152 原文只写「分析政策的前瞻性、系统性、针对性，评估政策对产业发展的引导作用」。三个词是定性表述：什么叫前瞻、配套到什么程度算系统、指向多具体算有针对性，全部没有量化标准。

**王惠 calc-logic 给了可执行框架。** `M_INNOV_PG_GUIDE.md`（V1.5-20260901）写明：三性等权；每维 = 命中政策件数 / 全部政策件数；前瞻性看标题是否含规划/战略/纲要类词，系统性看 `quote_policy` 是否非空（配套引用），针对性看 `policy_support.support_way` 是否有值（支持方式明确）。这个框架把三个定性词落到了三个可查字段上，是本报告的直接依据。

因此本指标的口径责任在王惠。本报告的工作是执行体检：三个字段里有两个是空壳，必须如实报告，不能为了让三性都能算而去凑字段。

### 1.4 类似指标权威机构构建方法可行性分析概要

| 方法族 | 代表机构/文献 | 核心做法 | 与本地数据的贴合度 |
|---|---|---|---|
| A 三性等权占比 | 王惠 calc-logic V1.5 | 三性各算命中率，等权 | **最高**（本报告执行） |
| B 政策文本编码 | 彭纪生等 (2008) | 人工/半自动编码政策力度与协同 | 低（无编码库） |
| C 政策工具分类 | Rothwell & Zegveld (1985) | 供给/需求/环境三类工具计数 | 低（无工具标签） |
| D 主题模型 | LDA/BERTopic | 无监督主题发现 | 中（可用 title+content，但不可解释到三性） |
| E 规划文本比对 | 五年规划评估惯例 | 与上位规划逐条比对 | 中（缺上位规划基准库） |

**三条结论**：① A 族有本地口径文件，优先；② B、C 两族需要编码体系，本库没有；③ D 族可作文本探索，但产出的是主题簇而非三性，不能替代。

### 1.6 推测原意与推测定义

**推测原意**：用三个可观测的文本/结构特征，近似判断一批政策「是否在主动引导产业方向」，而不是被动响应事务。

**定义（王惠口径，本报告执行）**：

$$
Foresight=\frac{\#\{p:\;title_p\cap K_{plan}\neq\varnothing\}}{N},\qquad
Systematic=\frac{\#\{p:\;quote\_policy_p\neq\varnothing\}}{N},\qquad
Targeted=\frac{\#\{p:\;policy\_support_p.support\_way\neq\varnothing\}}{N}
$$

$K_{plan}$ 为规划类关键词集合，$N$ 为入集政策件数。三性等权合成时取算术平均。**本报告只交付 $Foresight$**，另两维的分子分别为 2 与 0，分母为 20,000，但按王惠「输入为空壳则不可算」的原则不参与合成。

| D2 | 系统性 | 是否引用上位政策 | A 类（需求明列） | `quote_policy` | **空壳（2 条）** |

## 二、计算过程

### 2.1 方法选择：为什么用「标题 + 两级清洗」而不是全文匹配

标题是最好的意图信号。一份文件叫《深圳市智能网联汽车产业发展战略规划（2022—2035）》，它的导向写在标题里；一份叫《关于做好 2021 年度 XX 申报工作的通知》，它的导向也写在标题里（没有）。标题短、噪声少、判定可复核，适合做占比类指标。

全文匹配的问题在召回与精度都难控。`content` 96% 有值，但一份 40 页的文件里出现「规划」二字，往往引用的是别人的规划。本报告试过用 `content` 补召回，命中量翻了三倍，但抽查后误报更高，因此放弃，只把 `content` 当校验字段。

两级清洗是本报告新增的必要步骤。第一级剔城市建设类噪声：政策标题里「规划」出现最多的不是产业规划，而是「国土空间规划」「控制性详细规划」「城市更新规划」。第二级用科技语义白名单：标题里必须同时出现科技/创新/产业/技术/研发等词，才算真前瞻。两级之后 742 收到 50。

### 2.2 步骤 1｜入集与字段体检

入集 20,000 条政策。先做字段体检，结果决定了后面能算什么：

| 字段 | 非空/有值 | 填充率 | 判定 |
|---|---:|---:|---|
| `title` | 20,000 | 100.00% | 可用 |
| `content` | 19,203 | 96.02% | 可用（校验） |
| `abstract` | 12,159 | 60.80% | 可用（校验） |
| `keywords` | 0 | 0.00% | 字面 `'NULL'` |
| `keypoints` | 0 | 0.00% | 字面 `'NULL'` |
| `quote_policy` | 2 | 0.01% | 空壳，非 JSON 数组 |
| `policy_support` | 0 | 0.00% | 全为字符串 `'null'` |
| `theme` | 2 | 0.01% | 常量 0 |

体检结论：能用的只有 `title`、`content`、`abstract` 三个文本字段。三性里只有前瞻性能靠文本判定，系统性、针对性的指定字段都是空壳。

### 2.3 步骤 2｜前瞻性第一级：规划类关键词原始命中

关键词集取「规划 / 战略 / 纲要 / 蓝图 / 路线图 / 中长期 / 远景」。全库标题命中 **742** 条，占 3.71%。这个量级看起来合理——政策库里规划类文件通常就是几个百分点。

但 742 条里混着大量非科技规划。按标题二级词频看，「空间」「国土」「城市更新」「控制性详细」「村庄」「片区」合计 64 条，占命中的 8.63%。这些是城市规划，不是产业引导。第一级清洗把它们剔掉，剩 **678** 条（3.39%）。

### 2.4 步骤 3｜前瞻性第二级：科技语义白名单收紧

678 条仍然太宽。抽查发现「发展规划」这个短语在综合类文件里极常见，例如《XX 区国民经济和社会发展规划》，它包含科技章节但不是科技专项规划。第二级要求标题里出现科技语义白名单（科技 / 创新 / 产业 / 技术 / 研发 / 知识产权 / 人才 / 数字化 / 制造 / 生物 / 新材料 / 新能源），命中 **50** 条，占全库 **0.25%**。

两级合计剔除 692 条，整条漏斗的误报率 **93.26%**（692/742）。换句话说，单靠「规划/战略」关键词判前瞻，每 15 条里 14 条是错的。这个数字必须写进口径文件，否则下游会误以为关键词命中就是标签。

50 条里最典型的是《深圳建设国家可持续发展议程创新示范区可持续发展规划（2017—2030）》《广东省科技创新「十四五」规划》一类。它们的共同点是标题同时含「规划」与明确的科技/产业限定语。

### 2.5 步骤 4｜前瞻性的分母选择与城市切片

分母用全库 20,000 条得 0.25%。若用四城 1,212 条做分母，仍只有 2 条命中，得 0.165%。两个分母下的结论都是「极低」，差别不影响判断，因此主口径取全库，四城切片单列。

城市切片暴露了更大的问题：50 条里有 **32 条（64.0%）`city` 为空**。四城合计 2 条，全在深圳（879 条中 2 条，0.228%）；广州 325 条 0 条、东莞 8 条 0 条、惠州无记录（分母为 0，比率记 null 而非 0）。这不是城市差异，是文件层级差异：科技战略规划主要由省级、国家级平台发布，地市级语料里本来就少。用四城分母算前瞻性，等于用「地市政策库」去衡量「省级规划密度」，系统性低估。

### 2.6 步骤 5｜系统性、针对性两维的实测不可算

**系统性**（王惠口径：`quote_policy` 非空且不为空数组）：全表只有 **2** 条非空，占 0.01%。抽查这 2 条，内容是政策名称的纯文本，不是 JSON 数组，连解析都做不了。按王惠「非空且不为空数组」的要求，合格件数为 0 或 2，无论取哪个都无法形成有效比率。判不可算。

**针对性**（王惠口径：`policy_support.support_way` 有值）：全表 20,000/20,000 为小写字面 `'null'`。这个值不是 SQL NULL，是字符串 `'null'`，所以 `IS NOT NULL` 会返回 20,000 行，看起来「全有值」，实际是空壳。必须用 `!= 'null'` 才能识别。合格件数 0。判不可算。

这两维的失败方式不同：系统性是「有几条但格式不对」，针对性是「整列占位」。共同点是都不能产出有效分子。三性因此无法等权合成。

### 2.7 步骤 6｜导向族分布：三性之外的替代视图

第五，导向族分布（八族覆盖 46.33%）是本报告补的替代视图，能回答「往哪引导」，但不回答「引导得好不好」。它不能替代三性。

## 四、数据缺失情况（含结果解读）

1. **`quote_policy` 只有 2 条非空**：占 0.01%，且内容是政策名称纯文本，不是 JSON 数组。系统性维的分子无法形成有效计数。
2. **`policy_support` 全为字符串 `'null'`**：20,000/20,000。用 `IS NOT NULL` 会误判全有值，必须按 `!= 'null'` 判定。针对性维分子为 0。
3. **`keywords` / `keypoints` 为字面 `'NULL'`**：0 条有值。任何依赖关键词标签的增强方案都不可用，只能回到标题/正文自行匹配。
4. **`theme` 恒 0**：19,998 条为 0、2 条为 1，无法做主题切片。
5. **城市填充率 51.47%**：前瞻命中里 64.0% 城市为空，四城切片样本过小（深圳 2 条），比率不稳定。
6. **2022 年后截断**：语料止于 2021，前瞻性的年度趋势只能看到 2021 为止。
7. **标题口径漏检**：正文里表述战略意图但标题平淡的文件无法被识别，前瞻性 0.25% 是下界。
8. **导向族词典为本报告自定义**：8 族无外部标准，归族覆盖率 46.33%，剩余 53.67% 未归族。

**缺口的后果归因**：系统性、针对性缺测让三性综合不可做，方向是「只能交付单维」；城市填充率让四城切片不可靠，方向是「高估省级、低估地市」；标题口径让前瞻性偏低，方向是「低估」。三个缺口里，前两个需要补采与物化，第三个可以用正文模型缓解。

**甲方侧建议**：先上线「前瞻性（标题口径）+ 导向族分布」，页面注明「系统性、针对性因字段未物化暂不可用」；城市视图加「不含省级规划」提示；不要把 0.25% 解读为政策质量结论。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

### 5.4 选用建议与理由

**建议采用「前瞻性单维 + 导向族分布」上线，不发布三性综合分。** 理由是前瞻性口径可复现（0.21 秒、零 SQL），清洗后的 50 条可逐条人工复核；系统性、针对性两维的输入字段是空壳，硬凑分子会制造虚假分数。

**待甲方裁决点**：① 是否接受前瞻性单维；② 城市视图是否标注「不含省级规划」；③ 是否投入 `quote_policy` 与 `policy_support` 的抽取工程；④ 8 族词典是否作为正式分类维护；⑤ 前瞻性是否改用正文语义模型（需模型训练成本）。
