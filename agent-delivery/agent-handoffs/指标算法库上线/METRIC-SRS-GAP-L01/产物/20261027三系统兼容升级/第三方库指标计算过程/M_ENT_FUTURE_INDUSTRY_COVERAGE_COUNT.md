## 摘要

本件回答一个看板问题：**现有产业目录接住了几类未来产业？** 目录有 5 类（未来制造、未来信息、未来能源、未来空间、未来健康），12 条链的语义映射接住 4 类，覆盖率 **4/5 = 80.0%**；缺的是 `CL-FUT-03` 未来能源——不是企业没覆盖，是 12 条链里没有能源链，目录根本没有入口。

企业侧的数字更值得警惕：4,561 家名单里 **2,291 家**至少命中 1 类未来产业（50.2302%，`derived.enterprise_set_with_future_pct`），而这个数**恰好等于上链企业数**。分布是 1 类 1,170 家、2 类 1,079 家、3 类 42 家、4—5 类 0 家、0 类 2,270 家。2,291 家与上链企业完全重合不是巧合：映射规则是「链 → 类」，只要企业挂上 12 条链中的任意一条，就必然命中至少 1 类。因此 80% 是**目录级覆盖率**，不是企业级渗透率；企业级渗透率的分母若用 4,561，只有 50.2302% 有标签，但那是「上链率」的另一种写法。

第三个数字来自王惠 v5.1 的对照：按「深圳 20+8」的 8 类未来产业做 `industry_name` 正则归并，只接住 **2 类**（生物制造、物理智能），覆盖率 **25.0%**。8 类比 5 类更细，口径不同，25% 与 80% 不矛盾——它们回答的不是同一个目录的问题。

敏感性检验给出一个硬结论：12 条链里**任意删掉 11 条中的任何一条，覆盖率仍是 4/5；唯独删掉低空经济，覆盖率掉到 3/5（60.0%，`derived.sensitivity_min_covered_ratio_pct`）**。因为 `CL-FUT-04` 未来空间只有低空经济一条代理链。80% 由一个只有 50 家企业的链独自支撑，这是本件最脆弱的环节。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

未来产业看板（E-34）顶部的环形图：圆心写「4/5」，外环五段分别代表五类未来产业，已覆盖的段填色、未覆盖的段置灰并标注「目录无入口」。点某一段，下钻到该类的代理链与企业清单。

本件不产出企业明细，只产出「类 → 是否覆盖 + 代理链 + 企业数」五行，外加一个企业侧分布。它是典型的**目录覆盖率**指标，不是企业规模指标。

### 1.2 为什么需要这个指标

第一，**它回答「产业布局有没有空白」**。五类未来产业里缺哪一类，是规划问题，不是数据问题；把缺口显式画出来，比让用户自己在 12 条链里找更直接。

第二，**它给「未来产业」这个宽词一个可核对的边界**。未来产业没有统一目录，5 类、8 类、15 类都能说；本件把用的目录、映射、覆盖率一并写清，避免「80%」被当成普适结论。

第三，**它是典型的「覆盖率幻觉」案例**。4/5 看起来不错，但其中一类只靠 50 家企业的低空经济撑着；删掉这条链就掉到 3/5。指标必须带敏感性，否则会误导规划。

### 1.3 需求文档是否给出定义方法

**给了「覆盖未来产业数」这个名字，没给目录、映射与计算公式。** 这是本件与同批其他四件最大的不同：其他四件至少有 calc-logic 的公式与六类码，本件只有名称与王惠 v5.1 的 8 类归并规则。

原始 calc-logic 目录里没有独立文件；注册表登记为「覆盖未来产业数」，目标表指向 `enterprise_future_industry_coverage`（缺口：无此表）。因此本件的口径是**自建**的：5 类目录取自「未来制造 / 信息 / 能源 / 空间 / 健康」的通用五分法，映射取自 12 条链的链名语义。这两项都必须在报告里明写，不能伪装成库内标准。

### 1.6 本报告的口径与边界（须与甲方会签）

设未来产业目录为 $\mathcal{C}=\{c_1,\dots,c_5\}$，链目录为 $\mathcal{L}$（12 条），映射 $\mu:\mathcal{L}\to 2^{\mathcal{C}}$ 由链名语义给出。覆盖率定义为：

$$\mathrm{Cov}=\frac{\left|\{\,c\in\mathcal{C}:\ \exists \ell\in\mathcal{L},\ c\in\mu(\ell)\,\}\right|}{|\mathcal{C}|}=\frac{4}{5}=80.0\%$$

企业 $i$ 命中的类别数：

$$k_i=\left|\{\,c\in\mathcal{C}:\ \exists \ell\in\mathcal{L},\ i\ \text{上链}\ \ell,\ c\in\mu(\ell)\,\}\right|$$

**五条边界**：

1. **覆盖率的分母是 5 类，不是企业数。** 80% 与 4,561 无关。
2. **语义映射是自建的。** gkx 无 `cluster_id`、无 `cluster_group`、无 `industry_cluster_map`；映射表在本报告 §三，可逐条复核。
3. **企业侧 2,291 与上链企业完全重合。** 这是映射规则的必然结果，不是独立发现。
4. **5 类与 8 类不可直接比较。** 80% 与 25% 是两个目录各自的覆盖率。
5. **80% 的支撑极不均衡。** `CL-FUT-04` 只有低空经济一条链、50 家企业；删掉它即掉到 60%。

## 二、计算过程

### 2.1 五类目录与 12 条链的映射

| 类 | 名称 | 代理链 | 链数 | 名单企业 | 名单链配对 | 全库链配对 |
|---|---|---|---:|---:|---:|---:|
| `CL-FUT-01` | 未来制造 | 机器人、具身智能、智能终端、传感器、智能网联汽车 | 5 | 1,692 | 2,890 | 195,802 |
| `CL-FUT-02` | 未来信息 | 人工智能、软件与信息服务、集成电路、数字创意 | 4 | 1,613 | 2,321 | 1,323,550 |
| `CL-FUT-03` | 未来能源 | ——（无） | 0 | 0 | 0 | 0 |
| `CL-FUT-04` | 未来空间 | 低空经济 | 1 | 50 | 50 | 4,034 |
| `CL-FUT-05` | 未来健康 | 生物医药、合成生物 | 2 | 99 | 119 | 191,071 |

映射的两条原则：①**一条链只进一类**，避免同一企业因跨类映射被重复计入多个未来产业；②**链名直命优先**，例如「低空经济 → 未来空间」「生物医药 → 未来健康」，不做行业码二次推断。

映射后 12 条链全部有归口，5 类里 4 类有链、1 类无链。这是覆盖率 80% 的**全部来源**：它是目录级的「有没有链」，不是企业级的「有多少家企业」。

### 2.2 覆盖率 80% 的计算

```
covered = [c for c in catalog if any(chain in mapping[c] for chain in chains)]
cov = len(covered) / len(catalog) = 4 / 5 = 0.8
```

`probes.covered_category_ids` = `["CL-FUT-01","CL-FUT-02","CL-FUT-04","CL-FUT-05"]`，`missing_category` = `["CL-FUT-03"]`。没有四舍五入，80.0 是精确值。

### 2.3 企业侧分布：2,291 与 2,270

| 命中类数 | 企业数 | 占 4,561 |
|---:|---:|---:|
| 0 | 2,270 | 49.7698% |
| 1 | 1,170 | 25.6523% |
| 2 | 1,079 | 23.6571% |
| 3 | 42 | 0.9209% |
| 4 | 0 | 0.0% |
| 5 | 0 | 0.0% |

2,270 + 1,170 + 1,079 + 42 = 4,561。命中 ≥1 类的 2,291 家，与 `shared_base.in_chain_n` 完全相同。

为什么不可能有 4 类或 5 类？因为映射是「一条链只进一类」，一家企业最多挂 12 条链、但每条链只贡献 1 类，要命中 4 类必须同时挂 4 个不同类的链。名单里确实有跨 3 类的企业（42 家），但没有跨 4 类的。这是数据事实，不是规则限制——规则允许 5 类，只是没人做到。

### 2.4 全库对照：覆盖率不是名单造成的

用全库 1,714,457 条「企业×链」配对重算，`population_covered_category_n` 仍是 **4**。这说明 80% 不是 4,561 家代理名单的偏差——即使把 gkx 全部 189,116 家企业都算进来，能接住的还是 4 类，因为缺的是链，不是企业。

这个对照很重要：它把「覆盖率缺口」的归因从「企业样本不足」排除掉，锁定为「目录缺入口」。

### 2.5 敏感性：80% 靠谁撑着

| 删除的链 | 剩余覆盖类数 | 覆盖率 |
|---|---:|---:|
| 机器人 / 具身智能 / 智能终端 / 传感器 / 智能网联汽车 | 4 | 80.0% |
| 人工智能 / 软件 / 集成电路 / 数字创意 | 4 | 80.0% |
| **低空经济** | **3** | **60.0%** |
| 生物医药 / 合成生物 | 4 | 80.0% |

11 条链删任何一条都不影响 4/5；只有低空经济是 `CL-FUT-04` 的唯一入口。低空经济在名单里只有 50 家企业（占 1.0963%，`derived.low_altitude_share_of_roster_pct`），却独自承担 20% 的覆盖率。这是典型的「单点支撑」：一旦低空经济链改名或合并，覆盖率会瞬间掉到 60%，而企业侧几乎无感。

### 2.6 与王惠 v5.1「20+8」的对照

| 王惠 8 类 | 匹配链 | 名单企业 | 是否覆盖 |
|---|---|---:|---|
| 生物制造 | 合成生物 | 80 | 是 |
| 物理智能 | 机器人、具身智能 | 727 | 是 |
| 光计算与光载信息 | 无 | 0 | 否 |
| 第六代移动通信 | 无 | 0 | 否 |
| 脑科学与脑机工程 | 无 | 0 | 否 |
| 量子科技 | 无 | 0 | 否 |
| 未来能源 | 无 | 0 | 否 |
| 深海矿产 | 无 | 0 | 否 |

覆盖率 **2/8 = 25.0%**。8 类里 6 类在 12 条链中找不到语义对应：光计算、6G、脑机、量子、能源、深海。这不是「企业没有」，是「链目录没有」。王惠规则对 `industry_name` 做正则归并，本件对链名做语义归并，两种方法都受同一个约束：**目录里没有的，映射不出来**。

25% 与 80% 不矛盾，但**不能并排展示**。若页面同时放两个覆盖率，必须分别标注目录（5 类 / 8 类），否则用户会以为数据打架。

### 2.8 结果自检：三条交叉验证

第一，**企业分布求和 = 4,561**：2,270 + 1,170 + 1,079 + 42 + 0 + 0 = 4,561。

第二，**命中 ≥1 类企业数 = 上链企业数**：2,291 = 2,291。这条不是巧合，是映射的必然；若两者不等，说明有企业挂了链但链没进映射，或反之。

第三，**类级企业数之和 ≥ 去重企业数**：1,692 + 1,613 + 50 + 99 = 3,454 ≥ 2,291，差额 1,163 是跨类企业重复计数。符合预期。

### 2.9 与相邻指标的边界

`M_ENT_KEYPANO_MATCH_COUNT` 数「上链企业」，本件数「目录覆盖类数」；前者 2,291 是本件企业侧的母体，但本件的核心输出 4/5 与母体无关。`M_CHAIN_*` 系列数单链企业，本件做链到类的折叠。两者不可互相替代：单链企业数回答「这条链有多少家」，本件回答「五类未来产业有没有入口」。

### 2.10 三条口径的优先顺序

同一份数据可以产出三个不同的「覆盖率」，发布时必须指定用哪一个：

| 口径 | 分子 / 分母 | 值 | 回答的问题 |
|---|---|---|---|
| 目录覆盖（5 类） | 4 / 5 | 80.0% | 五类未来产业有没有链入口 |
| 企业覆盖（名单） | 2,291 / 4,561 | 50.2302%（`derived.enterprise_set_with_future_pct`） | 名单里有多少家至少挂一条链 |
| 王惠目录（8 类） | 2 / 8 | 25.0% | 深圳 20+8 口径下有几类有链名对应 |

三者的分子分母都不同，**不能相互校验**。唯一可做的交叉检查是「全库覆盖类数」：把名单换成 189,116 家、链配对换成 1,714,457 条，覆盖率仍是 4/5，说明目录缺口与样本无关。这条检查已在本件 §2.4 执行，结果一致。

### 2.11 前端取数约定

前端只需要两个字段：`covered_category_n`（整数 4）与 `catalog_category_n`（整数 5），自行拼「4/5」；不要直接消费 `coverage_ratio_pct` 再二次四舍五入，否则会出现「80.0%」与「4/5」并列但显示不一致。缺失类的文案取 `missing_reason`，不要由前端拼「暂无数据」——那会把目录缺口说成数据缺口。

## 四、数据缺失情况

### 4.1 缺口的后果归因

**缺口一：未来产业目录不在。** gkx 无 `industry_cluster`，live 无对应表。后果：5 类目录是自建的，不是库内标准。

**缺口二：映射表不在。** 无 `industry_cluster_map`，链到类的对应靠链名语义。后果：映射可复核但不可仲裁。

**缺口三：未来能源无链。** 12 条链里没有能源链，`CL-FUT-03` 永久为 0。补企业补不出来，只能补链目录。

**缺口四：王惠 8 类里 6 类无链。** 光计算、6G、脑机、量子、能源、深海都无入口；8 类口径下覆盖率只有 25%。

**缺口五：单点支撑。** `CL-FUT-04` 只有低空经济一条链，删链即掉 20 个百分点。

### 4.2 数据陷阱（本批实测）

**陷阱一：把 80% 当企业渗透率。** 80% 是 4/5 类，企业侧有标签的只有 2,291/4,561 = 50.2302%（`derived.enterprise_set_with_future_pct`），且这 50.23% 就是上链率。

**陷阱二：把 2,291 当独立发现。** 它等于上链企业数，是映射规则的必然结果。报告若写「发现 2,291 家企业属于未来产业」，是把链成员换了个名字。

**陷阱三：把 25% 与 80% 并排。** 两个目录不同（8 类 vs 5 类），并排必须标注，否则像数据冲突。

**陷阱四：忽略单点支撑。** 4/5 里有 1 类只靠 50 家企业；不做敏感性就会高估稳健性。

**陷阱五：用 4,561 做类级占比分母。** 未来制造 1,692/4,561 = 37.10%（`derived.counterexample_fut_make_over_roster_pct`），这个数没有业务含义；类级企业数之间有重叠，正确读法是「多少家（人次）」而非「占比」。

### 4.3 可构建但存在缺口（不是「无法构建」）

若甲方接受「5 类目录 + 链名语义映射」，本件现在就能出 4/5，且全库对照稳定，属**可构建**。但「未来能源」这一类永远为 0，且映射无库内标准，故不能判完全转换支持。

### 4.4 若甲方补齐后的口径升级路径

第一步补 `industry_cluster`（5 类或 8 类目录），第二步补 `industry_cluster_map`（链/行业码 → 类），第三步补能源链或能源行业码入口，第四步物化 `enterprise_future_industry_coverage`。四步完成后，覆盖率可升为完全转换支持；在此之前，80% 只能作为「目录覆盖」口径发布。

## 五、结论与发布建议

### 5.1 结论

**4/5 是真的，但它量的是目录不是企业。** 五类未来产业里四类有链，缺口是未来能源；企业侧 2,291 家与上链企业完全重合，说明「有未来产业标签」在这套映射下等价于「上了 12 条链之一」。

**80% 不稳健。** 低空经济一条链独自支撑未来空间，删掉即 60%。发布时必须带敏感性说明，否则规划部门会把它当成「五类里已有四类企业基础」的证据。

### 5.2 与王惠 V3-2 的对照

王惠 V3-2 未单列本 ID，只有 v5.1 的 8 类归并规则可对照。8 类口径下覆盖率 2/8 = 25.0%，比 5 类口径低 55 个百分点，差异全部来自目录粒度与链名可命中性，不是企业数据差异。

| 维度 | 王惠 v5.1 | 本版 | 说明 |
|---|---|---|---|
| 目录 | 8 类（20+8） | 5 类 | 粒度不同 |
| 方法 | `industry_name` 正则 | 链名语义 | 都无库内映射 |
| 覆盖 | 2/8 = 25.0% | 4/5 = 80.0% | 不可直接比较 |
| 缺口 | 6 类无链 | 1 类无链 | 8 类更细 |

### 5.3 选用建议与理由

**建议采用 5 类口径做主展示，8 类口径做副表。** 主展示的 4/5 与官方未来产业六方向可对齐（材料并入制造），用户容易理解；副表放 8 类的 2/8，满足深圳本地口径。两个数必须各自标注目录，不能合并成一个「覆盖率」。

**建议把「未来能源无入口」做成显式缺口卡**，而不是一个灰色的 0。这个缺口的性质是目录缺失，不是企业缺失；文案应引导「补链」而不是「补企业」。
