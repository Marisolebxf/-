### 1.2 为什么需要「协同绩效」

创新生态页不可能把 8 万个机构全列出来。需要一个分数把「协同做得好」的机构排到前面，用于：① 生态总览的 Top 榜；② 协同网络图的节点着色；③ 机构详情页的一句话评价。

「协同」在这里有三层含义：产出多（P）、连接广（N）、合作产出占比高（S）。三层缺一层，分数就会偏——只看产出会把「单打独斗的大厂」排到前面，只看连接会把「什么都沾一点的中介」排到前面，只看占比会把「只发 2 篇但都合作」的小机构排到前面。三维等权是对这三类偏差的折中。

### 1.3 口径定义

对机构 $i$，定义三个维度：

$$P_i=\text{论文数}_i+\text{专利数}_i,\qquad N_i=|\{j:(i,j)\in E_{\text{paper}}\cup E_{\text{patent}}\}|$$

$$S_i=\frac{\text{合作论文数}_i}{\text{论文数}_i}\times100$$

三维各自 min-max 归一化到 $[0,1]$ 后等权平均再乘 100：

$$\text{Score}_i=100\times\frac{1}{3}\left(\tilde P_i+\tilde N_i+\tilde S_i\right)$$

评分门槛：论文数 $\ge 2$。专利侧不单独设门槛，但专利数为 0 的机构 $P$ 维只算论文。

### 1.4 计算公式与本批实现式

```python
# 论文侧
papers = read(a25_paper_panel)                      # 100,900 篇, 含机构列表
inst_papers[i]  = 篇数
inst_collab[i]  = 合作篇数（同篇 ≥2 机构）
paper_edges     = 同篇机构两两配对                 # 126,849 条

# 专利侧（代理）
pat_agg[applicant] = 专利件数（全表聚合）
patent_edges       = 同 pn 多申请人两两配对        # 7,773 条

# 评分
universe = {i: papers_i >= 2}
P = papers + patents;  N = 邻居数;  S = collab/papers*100
score = 100 * mean(minmax(P), minmax(N), minmax(S))
```

参数：`min_papers = 2`、`min_patents_only = 5`（专利侧独有机构不评分的记录门槛）、`weights = 等权 1/3`、`normalization = 评分集内 min-max`。

## 二、计算过程

### 2.1 论文侧：从共著到邻居

`dwd_zh_paper` 100,900 篇，机构字段是作者单位串。按篇解析出机构列表后：① 每篇的机构计数进 `inst_papers`；② 机构数 ≥2 的篇，两两配对进 `paper_edges`；③ 每篇里「有合作者的机构」计数进 `inst_collab`。

结果：84,320 个机构名，126,849 条共著边。边数远大于机构数，说明共著网很密——平均每个机构有 3 个以上邻居。

### 2.2 专利侧：聚合与代理边

`dwd_patent` 2,939,895 行的申请人字段不是规范化的机构表，只有名字串。本件对全表做申请人名聚合，得 169,226 个名字与各自件数；`dwd_patent_applicants` 22,198 行明细里，同一 `pn` 有 ≥2 个申请人的有 6,477 个（32.385%），两两配对得 7,773 条共申边。

这 7,773 条边是**代理**：同一件专利有多个申请人，说明它们共同申请了这项专利，但「共同申请」不等于「协同创新」——可能是母子公司、可能是联合体投标、也可能是专利转让后的挂名。本件把它标为 `专利共申（代理）`，只进 N 维，不改变档位。

### 2.3 评分集的构造

84,320 个论文机构里论文 ≥2 篇的有 20,436 个（24.2362%）。这个门槛的作用是剔除「1 篇论文」的机构——1 篇论文的 S 维只能是 0% 或 100%，没有区分度。

20,436 个机构里 4,039 个有专利（19.7641%），16,397 个纯论文（80.2359%）。纯论文机构的 P 维只算论文，专利贡献为 0；这不是缺失，是事实。

专利侧独有机构 79,532 个（占 169,226 个申请人名的 46.9975%），它们没有论文，S 维无定义，不评分。加上「专利 ≥5 件」的记录门槛后仍不评——因为没有分母，任何 S 都是编的。

### 2.4 三维分布

| 维度 | 中位 | P90 | 最大 | 均值 |
|---|---:|---:|---:|---:|
| P（产出） | 3 | 32 | 81,457 | 52.0657 |
| N（邻居） | 4 | 14 | 400 | 6.6963 |
| S（合作占比 %） | 100.0 | 100.0 | 100.0 | 75.3999 |

S 维的中位与 P90 都是 100.0——超过一半的机构「所有论文都是合作论文」。这是共著文化的产物：多作者论文是常态，单作者论文少见。S 维因此区分度很低（均值 75.3999，最低 0），min-max 后大部分机构挤在高位。

N 维的中位只有 4，最大 400（广州中医药大学第一附属医院）。400 这个数不是「400 个不同机构」，而是去重后的邻居数，说明该院在中西医结合领域与大量机构有共著。

P 维的最大 81,457（华为）是中位的 27,152 倍以上。min-max 后华为 P 维接近 1，绝大多数机构接近 0——P 维实际上只区分「头部」与「其余」。

### 2.5 分数的形状

20,436 个机构的分数：最小 0、P10 5.7907、中位 33.5、P90 34.0008、最大 68.5874、均值 25.7118。

P10 到 P90 只差 28.21 分，且 P50 与 P90 只差 0.5008 分——分数在 33—34 之间高度聚集。原因：S 维挤在高位、N 维大部分是 1—14、P 维大部分接近 0，三者叠加后大量机构落在同一个窄带。真正拉开差距的是 P 维的头部（华为、OPPO、比亚迪、华南理工）。

这个形状说明分数**适合排序头部、不适合做绝对评价**。发布时必须提示：33.5 分不代表「绩效 33.5%」，只代表「在这 20,436 个机构里的相对位置」。

## 四、数据缺失情况

### 4.1 载体实体表不存在

需求原文的评估对象是「创新载体」——园区、平台、新型研发机构。gkx 没有载体表：`enterprise_base` 逐字命中 0，模糊词 `carrier` / `platform` / `park` 表名命中 0。本件只能评「机构名」，不能评「载体」。这是本件判「部分支持」的第一条硬理由。

### 4.2 企业合作边逐字命中 0

| 表 | 检索条件 | 命中 |
|---|---|---:|
| `enterprise_cooperation` | `table_schema='gkx' AND table_name='enterprise_cooperation'` | 0 |
| `enterprise_supply_chain` | 同上 | 0 |
| `enterprise_centrality` | 同上 | 0 |
| `enterprise_base` | 同上 | 0 |
| `dwd_zh_project` | 同上 | 1 |

企业合作边不存在，本件的 N 维只能用「论文共著 + 专利共申」。论文共著是真实的协同关系，专利共申是代理。两者都不是「企业合作」。

### 4.3 项目合作维不可建

`funded_institution` 整列为空（100.0%），多机构行 29 行（0.0496%）。项目维的三条可能路径全部断掉：① 资助机构→参与机构（资助列空）；② 参与机构之间的合作（多机构行几乎没有）；③ 项目数作为产出（项目本身不是协同成果）。

### 4.4 专利侧独有机构不评分

79,532 个机构只在专利侧出现（46.9975%），它们不评分。若强行评分，S 维没有分母（没有论文），只能记 0 或 100，两种都会失真。本件选择不评，并在 `caveats` 里写明「硬算会把分数压成 0—5 的常数带」。

### 4.5 名称未归并

机构名是原始串，没有别名表、没有上下级关系。同名院系会被合并（多个学校的「土木工程学院」可能撞名），不同写法会被拆开（「华南理工」与「华南理工大学」）。这条误差无法在当前数据面消除。

### 4.6 不得外推的三件事

1. **不得读作「载体绩效」**：评分对象是机构名，不是园区/平台。
2. **不得读作「企业合作强度」**：N 维是共著+共申，其中共申是代理。
3. **不得跨版本比分数**：min-max 依赖评分集，换集合分数平移。

### 4.7 停用与重估条件

出现以下任一情况应重估：① 载体实体表建成；② 企业合作边表建成；③ 项目表资助/参与字段补齐；④ 机构别名主数据建成；⑤ 专利申请人规范化。

## 五、结果与解读

### 5.1 头部能对上直觉，但形状不同

华为第一靠专利（81,376 件），广中医一附院第二靠论文与邻居（751 篇、400 邻居），华南理工第三两者都强。三种形状都能进前三，说明分数不是单一维度的代理。但 OPPO 第八（5 篇论文、25,765 件专利、9 个邻居）暴露了 P 维的支配性——专利体量足够大时，N 维和 S 维可以被忽略。

### 5.2 分数怎么用

第一，做**生态总览 Top 榜**：前 15 名，配合三维分解。第二，做**节点着色**：协同网络图按 score 分档着色。第三，做**机构详情**：展示 P/N/S 三维分位，而不是只给一个总分。

第四，不要用分数做**准入**：33.5 是中位，不代表及格线。分数是相对位置，不是绝对绩效。

### 5.3 三维的贡献

| 维度 | 区分度 | 主要贡献 |
|---|---|---|
| P | 高（头部极值 81,457） | 决定前十 |
| N | 中（4—400） | 决定 10—50 名 |
| S | 低（中位 100.0） | 几乎不区分 |

S 维的低区分度是结构性的：共著文化下大部分机构 S 都在 70%—100%。若要提高区分度，应改用「跨机构合作强度」或「跨地域合作占比」，而不是「合作论文占比」。

### 5.4 反常识点

**反常识一：中位数 33.5，P90 只有 34.0008。** 一半机构与 P90 只差 0.5008 分——分数在 33—34 之间堆了一层。这说明大部分机构的三维组合几乎一样。

**反常识二：华为的邻居只有 107，排不进邻居榜前 15。** 专利多不等于合作广：81,376 件专利大部分是独立申请，共申边只有 7,773 条覆盖 6,477 件专利。

**反常识三：专利名与论文机构名的精确匹配率只有 4.2612%。** 这不是数据错，是命名体系不同——公司全称与院系名本来就不一样。

**反常识四：`participating_institution` 只有 1 行空值，但多机构行只有 29 行。** 字段「不空」不等于「可用」：绝大多数行只有一个机构名，没有分隔符。

### 5.5 与其它指标的联动

与 `M_SYNTH_DS_23_GRAPH_ALGO_013`：那件划分社群，本件给机构打分。社群 + 分数可以回答「哪个社群的头部机构强」。

与 `M_SYNTH_DS_23_GRAPH_ALGO_009`：PageRank 是单一中心性，本件是三维综合。两者排名会不同，差异本身有信息量。

与 `M_ENT_RELATION_STRENGTH`：那件看企业投资关系，本件看论文/专利协同。投资强不等于协同强。

## 六、结论与发布建议

### 6.1 可用结论

第一，20,436 个论文机构可评分，均值 25.7118、头部华为 68.5874。第二，三维齐全 100.0%，N 维覆盖 91.0305%。第三，载体粒度不可交付、项目合作维不可建、企业合作边不存在。第四，专利共申是代理，不抬档。

### 6.2 发布口径（逐条写死）

| 项 | 必须写明的口径 |
|---|---|
| 评分对象 | 机构名（非载体） |
| 评分集 | 论文 ≥2 篇，20,436 个（24.2362%） |
| 三维 | P 产出 / N 邻居 / S 合作占比，等权 |
| 归一化 | 评分集内 min-max |
| 边 | 论文共著（真实）+ 专利共申（代理） |
| 项目维 | 不可建（资助列全空、多机构行 29） |
| 专利独有 | 79,532 个不评分 |

### 6.3 后续

三条路径：① 载体实体表（换评分对象）；② 企业合作边（换 N 维）；③ 机构别名表（提匹配率）。三者都会改变分数，需重跑。
