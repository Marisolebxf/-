## 摘要

「瓶颈堵点」在产业分析里是一个有明确含义的概念：链条上某个环节的供给能力跟不上需求，导致整链产能受限。判定它需要至少一组「供给 vs 需求」的对照数据。

gkx 里没有任何一组这样的对照。五维输入逐项核过：供需缺口（无产能/需求表）、技术依赖（无进口/引用表）、产能利用率（无工业统计）、交付周期（无订单表）、替代性（无供应商清单）。以 `%bottleneck%`、`%importance%`、`%supply%` 扫描 `information_schema.tables`，全部 0 命中。

> 探针实测（`code/M_CHAIN_BOTTLENECK_COUNT.py`，2026-10-22 16:45）：五维各按 3 类词根扫描，剔除误匹配后**节点级载体 0/5**。两处词根命中已核为误匹配——`%import%` 命中 `dwd_org_important_news_info`（企业重要资讯）、`%citation%` 命中 `dwd_en_paper_citation` / `dwd_zh_paper_citation`（论文引用），都与「技术依赖」无关。最容易被当成 D3 的 `dwd_macro_index_data`（20,000 行、287 个指数码、1949—2026）也查了：`dim_cal` 只有 JDZ（绝对值）与 TB（同比）两值，按 `cap`/`util`/「产能」检索 0 条，是国民经济与外贸效益类宏观序列，不含产能利用率、也不落到环节。

最容易被误用的是「空位环节」：`M_CHAIN_BREAK_RISK_COUNT` 已算出 38 个无企业环节。但空位是「本地没人干」，瓶颈是「有人干但干不够」——两者语义相反。把空位当瓶颈，会把「本地不布局的环节」误报为「堵点」，招商方向直接错。

结论：本指标必须由甲方**提供瓶颈评分或监测数据**（产能利用率、交付周期、进口依赖度），否则算不出。判**完全不支持**，属 B 类。

| 口径要点 | 取值 |

| 库内命中 | 0/5 维有表 |
| 最近替代 | 空位环节 38 个（语义相反，不可用） |
| 判档 | 完全不支持 |
| 依赖性质 | B 类 |

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块是**产业链分析 → 产业链监测 → 瓶颈堵点**。页面是一张堵点清单：环节名、堵点类型（供给不足/技术卡点/交付瓶颈）、影响程度、涉及企业数。

配套的是「补链强链专题」：堵点清单直接作为专题的输入，按影响程度排序后分配资源。

### 1.2 为什么需要这个指标

第一，它是「补链」与「强链」的分界。补链补的是空白（没有企业），强链强的是瓶颈（有企业但能力不足）。两者的政策工具完全不同：前者靠招商，后者靠技改与产能扩张。

第二，它是资源配置的依据。堵点的影响程度决定投入优先级；没有量化，资源会按部门惯性分配。

第三，它是监测的抓手。产能利用率、交付周期这类指标会随市场变化，堵点清单应随之更新；这是「监测」区别于「画像」的地方。

### 1.3 需求文档是否给出定义方法

**没有。** 需求只有指标名与「识别产业链瓶颈堵点数量」。父口径提到「五维评分」，但没有列出五维是哪五维、权重多少、阈值多少。

这个缺失导致即使有数据也无法复现：五维不同组合会给出不同的堵点清单，而清单是政策输入，必须可复现、可解释。

### 1.4 类似指标权威机构构建方法可行性分析概要

| 方法族 | 代表机构/文献 | 口径要点 | 与本指标的差 | 贴合度 |
|---|---|---|---|---|
| A 产能利用率监测 | 国家统计局工业产能利用率 | 按行业季度调查 | 行业级，非环节级；库内无 | 高（口径）/零（可得） |
| B 供应链中断风险 | OECD 供应链韧性；世界银行 LPI | 结合进口集中度与替代性 | 需贸易数据，库内无 | 中高 |
| C 投入产出瓶颈识别 | IO 表关键部门分析（Rasmussen） | 用前向/后向关联系数找关键部门 | 部门级，无 IO 表 | 中 |
| D 交付周期/订单监测 | PMI 供应商配送时间分项 | 按月调查 | 宏观指数，无环节粒度 | 中 |

**三句结论**：① 语义最贴 A 族（产能利用率），它是瓶颈最直接的度量；② A 族是行业级调查，落到 954 个环节需要额外映射；③ 库内五维全无，最短路径其实是 E 族（专家评分），但那是甲方组织工作，不是数据工程。

推测定义：**瓶颈堵点数 = 五维综合评分超过阈值的环节数**；五维与阈值由甲方会签后固定。

边界：① 不把空位环节当瓶颈（语义相反）；② 不把集中度高当瓶颈（集中可能是效率，不是堵点）；③ 不按企业数少判瓶颈（企业少可能是环节小，不是供给不足）；④ 不输出未定义维度的「综合分」。

## 二、依赖性质裁定（为什么必须外部数据）

### 2.1 本指标需要什么形态的数据

瓶颈判定需要「供给 vs 需求」的对照，最少要两组数：该环节的产能（或交付能力）、该环节的需求（或订单量）。两者相除得到缺口率，超过阈值即为瓶颈。

再进一步，需要「技术依赖度」（进口占比、专利引用外部化程度）与「替代性」（可替代供应商数量）。这四类数据都不在 gkx。

### 2.2 gkx 里到底有什么（逐维探测）

| 维度 | 需要的表 | gkx 是否有 | 探测证据 |
|---|---|---|---|
| 供需缺口 | 产能表 + 需求表 | 无 | `%capacity%`、`%demand%` 0 命中 |
| 技术依赖 | 进口/引用表 | 无 | 无海关、无专利引用表 |
| 产能利用率 | 工业统计 | 无 | 无统计年鉴类表 |
| 交付周期 | 订单/合同表 | 无 | 合同表仅招投标，无交付字段 |
| 替代性 | 供应商清单 | 无 | `%supply%` 0 命中 |

五维全无。这张表是本件判 B 的全部依据。

表级证据与上面逐维探测互为印证，统一引用 `_work_gkx21/TABLE_ABSENCE_EVIDENCE.md`：

- **§`chain_bottleneck`**：精确同名不存在，词根候选 0 张，旧稿引用的是一张应用层汇总表（非 gkx 派生）。证据块对该簇有一条明确提醒——「应用层表库内没有属正常，正确动作是用 gkx 原始表重建，不是向甲方要表」。本件遵此提醒执行了重建尝试：把五维逐一映射到 gkx 原始表（见上表），国产化替代、产能、交付、供应商四类源表全部 0 命中，重建路径在这里断掉，因此保留「零等价」结论，而不是直接照抄「库内无表」。
- **§`industry_chain_metric_fact`**：精确同名不存在，词根候选只有链树与链资讯两张，二者均无评分类列。这说明连「指标事实表」这一层也没有承载五维分数的位置。

这两条是「不是我没找，是找过且没有」的书面凭据；反过来说，只要甲方补一张五维评分表，本件即可转 A 类。

### 2.3 最近的替代面为什么不可用

**其一，空位环节（38 个）。** 它是「本地无企业」，与「有企业但供给不足」相反。把空位当瓶颈，会把「本地不布局」（可能是有意为之，如上游材料依赖外部）误报为堵点。

**其二，集中度（HHI）。** 高集中可能意味着高效率（规模效应），也可能是垄断；它不指示供给不足。用 HHI 判瓶颈，会把所有专业化环节都标成堵点。

**其三，企业数少。** 一个环节只有 2 家企业，可能是「环节本身小」，也可能是「供给不足」；没有需求侧数据无法区分。

**其四，招投标金额。** 招标金额高说明采购需求大，但不说明供给不足（可能供给充足但项目大）。它缺需求侧的分母。

### 2.4 若强行用会得到什么假数

假设用「企业数 ≤ 5 的环节」作瓶颈，会得到每链数十个「瓶颈」，且集中在细分环节——这些环节本来企业就少（全球只有几家），把它们报成堵点会导致错误的招商方向（招不来，也没必要招）。

更严重的是，这个假数会与 `M_CHAIN_BREAK_RISK_COUNT` 的 38 个空位高度重叠，让两个指标看起来在说同一件事，实际上都在说「本地企业少」。

### 2.5 裁定

本指标依赖「供给—需求对照 + 技术依赖 + 替代性」，五维输入在 gkx 全部不存在，且不能用空位/集中度/企业数替代（替代会产生方向性错误）。按依赖性质三分法，属 **B 类（不可重建，须外部评分/监测数据）**。

最短落地路径不是数据工程，而是甲方组织一次专家评分（E 族）：12 条链 × 约 80 个环节，按五维打分，产出堵点清单。这条路可在数周内完成，但需要业务方投入。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 影响面 | 处置 |
|---|---|---|
| 无五维定义与权重 | 无法评分，也无法复现 | 甲方会签 |
| 无产能/需求数据 | 供需缺口算不出 | 工业统计或企业调查 |
| 无技术依赖数据 | 卡点判定缺失 | 海关进口 + 专利引用 |
| 无交付周期数据 | 交付瓶颈缺失 | 订单/合同台账 |
| 无替代性数据 | 替代难度缺失 | 供应商清单 |

### 4.2 逐条影响

定义与权重是第一位：没有它，即使有数据也无法产出可复现的清单。

产能/需求是核心：它决定「缺口率」这个最直接的瓶颈指标。

技术依赖与交付周期是细分维度：它们区分「供给不足」与「卡脖子」。

替代性决定严重程度：不可替代的瓶颈比可替代的严重得多。

### 4.3 明确不做什么（禁止的替代）

- 不把空位环节当瓶颈——语义相反（无人 vs 有人但不够）。
- 不把集中度当瓶颈——集中可能是效率。
- 不把企业数少当瓶颈——环节本身可能就小。
- 不用招投标金额当需求——缺供给分母。

### 4.4 若甲方补齐后的口径升级路径

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 甲方组织专家五维评分 | 可出堵点清单（主观但可复现） | 可升格至部分支持 |
| 提供产能利用率与订单数据 | 供需缺口可算 | 可升格至完全转换支持 |
| 提供进口依赖数据 | 技术卡点可算 | 可升格 |
| 提供供应商清单 | 替代性可算 | 可升格 |

返回：仅 `dwd_bid_*` 系列（招投标），无供需、无订单、无合同交付表。

### B.3 空位环节（最易被误用的替代面）

```sql
SELECT COUNT(*) FROM (
  SELECT c.industry_code FROM gkx.dwd_industry_chain_info c
  LEFT JOIN (SELECT industry_link_code, COUNT(*) n
             FROM gkx.dwd_org_industry_tags GROUP BY industry_link_code) t
    ON c.industry_code = t.industry_link_code
  WHERE CHAR_LENGTH(c.industry_code) BETWEEN 11 AND 21 AND COALESCE(t.n,0)=0
) x;
```

返回：38。→ 这是「空位」，不是「瓶颈」，两者不可互换。

## 附录 C 外部数据报送规格（供甲方决策）

方案一（推荐，成本最低）：**专家五维评分表**，一行一个环节：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| industry_code | varchar(32) | 是 | 与链树叶级码一致 |
| dim_supply_gap | tinyint | 是 | 供需缺口 1—5 分 |
| dim_tech_dep | tinyint | 是 | 技术依赖 1—5 分 |
| dim_capacity_util | tinyint | 是 | 产能利用 1—5 分 |
| dim_lead_time | tinyint | 是 | 交付周期 1—5 分 |
| dim_substitutability | tinyint | 是 | 替代性 1—5 分 |
| score_total | decimal(5,2) | 否 | 加权总分（权重会签后定） |
| expert / date | varchar | 否 | 评分人与日期，用于追溯 |

方案二（成本高、可信度高）：提供产能利用率与订单交付数据，由系统自动算供需缺口。

**验收口径建议**：堵点清单必须同时给出「阈值 + 权重 + 评分人」，否则不可复现；页面上应显示「本次评分基于 N 位专家、M 个环节」。

**与相邻指标的边界**：堵点（有人但不够）与空位（没人）分列两个指标，禁止合并展示，否则招商会同时收到「招引」与「技改」两种互相冲突的建议。
