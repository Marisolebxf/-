## 摘要

「多城市对标排名」把多个城市在三个维度上的差距压缩成一个名次：企业规模占 40%、企业密度占 30%、产业链完整度占 30%，每维先做极值归一化，再加权求和、降序排序。

三个维度的数据命运完全不同。规模维的营收原料在 `dwd_org_annual_financial_info` 里有 90,926 行，但营收大于 0 的只有 2,191 行（2.41%），能算出城市均值的企业只覆盖四个广东城市，各市覆盖率 0.31%—0.75%；注册资本字段反而填充得很好，四城都在 99% 以上，可作为规模维的替代原料。完整度维是唯一「结构与数据都够」的一维：`dwd_org_industry_tags` 2,283,762 行、链目录 1,273 行、叶子 954，全国 k/K = 940/954（98.53%），深圳探针 712/954（74.63%）。密度维恒缺——城市面积在 gkx 不存在。评分维恒缺——全库 `%score%` / `%rank%` / `%evaluat%` / `%rating%` 表名扫描 0 命中。

因此本件**不出名次**。产物里 `composite_rank.computed = false`、`rows = 0`，理由写明「密度与评分恒缺，合成值会由唯一有值的维度单独决定」。另给一份 `scale_only_demo`：只按注册资本均值排的四城顺序（广州 81,841,830.72 元、深圳 62,686,419.18 元、惠州 42,604,799.49 元、东莞 17,242,685.19 元），并明确标注「不是本件排名口径，不得对外称城市排名」。

还有一个结构性问题比缺维更根本：66 个城市里 62 个不足 1,000 家企业，四城合计占 99.82%。极值归一化下，深圳几乎必然取到企业数最大值，北京 163 家、上海 16 家贴近最小值——名次由「谁在库里有样本」决定，不由「谁更竞争力」决定。

结论是**部分支持**：一维可算、一维部分可算、两维恒缺，权重 40/30/30 亦未甲方闭合（Q014），名次不可交付。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业分析 → 区域对标 → 多城市排名**。页面形态是一张城市名次表：名次、城市、三维得分、综合得分；点开某城可见三维分解与与对标城市的差距。

它是区域对标的收敛层：对标值矩阵回答「差多少」，本件回答「排第几」。名次的价值在于可考核——「保三争二」这类目标只能建立在名次上，不能建立在矩阵上。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业分析 → 区域对标 → 多城市排名 |
| 页面载体 | 名次表 + 三维分解 |
| 输出形态 | 城市 → 综合得分 / 名次 / 三维得分 |
| 更新频率 | 年度 |
| 粒度 | 城市（预设对标集合内） |

### 1.2 为什么需要这个指标

第一，名次是决策语言。矩阵要读六个数才能判断谁强，名次一眼就够。政策场景里，能被引用的通常是名次，不是矩阵。

第二，名次驱动问责。同一套权重下，今年第三、去年第五，进步是可见的；矩阵的进步要逐维解释，传播成本高。

第三，名次是外部对标的接口。各类城市评价报告发布的都是名次，本件是内部口径与外部榜单对话的接口——虽然本库样本不支持数值对标，但形态可比。

### 1.3 需求文档是否给出定义方法

**需求文档没给排名公式，口径来自王惠底稿。** 展示系统原文只写「多城市对比、计算三类指标、识别优势短板」，没有「排名」二字，也没有权重。王惠底稿把它固化为三维 40/30/30，并注明「依照需求文档提供的构建方法」——这句自述与原文检索结果不符，属项目内部推导。

本件的处置：沿用三维与权重，但把权重状态写进产物（`weights_status`：王惠底稿值，Q014 未甲方闭合）；不自行改权重；不在缺维时用「有值的那维」凑一个名次。三条都是为了避免「看起来有排名、实际只有一个维度在起作用」。

### 1.4 类似指标权威机构构建方法可行性

城市综合排名在国际与国内都有成熟范式：标准化 + 固定权重 + 排序。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 加权合成排名 | IMD 世界竞争力排名 | STD 标准化 + 分层锁定权重 | 高（王惠三维的直接范式） |
| B 官方评价排名 | 工信部国家高新区评价 | 指标体系加权 + 分组排名 | 高（分组可缓解样本差） |
| C 极值熵权 | 中文方法论文献 | 极值归一 + 客观赋权 | 中（要求各维完整） |
| D 综合指数手册 | OECD 综合指标手册 | 十步流程 + 稳健性检验 | 高（流程检查表） |

**A 族是本件采用的方法。** 极值归一化把三个量纲不同的城市值压到 [0,1]，固定权重表达政策先验，排序输出名次。这套范式与王惠底稿一致。

**B 族**的分组排名值得借鉴：先按规模档分组，再在组内排名，可以缓解「62 城样本不足」的问题。本件未采用，因为分组规则本身需要甲方确认，属新增口径。

**C 族**的熵权要求各维样本完整，当前两维恒缺，熵权会把权重全压到完整度维，产生失真排名。本件不用。

**D 族**的十步流程最有价值的是「缺失值处理」与「稳健性检验」两步。本件在缺维时直接不出名次，正是这两步的底线版本。

## 二、计算过程

### 2.1 总体思路与数据流

三维各自算城市值，各自极值归一，再加权求和。缺一维则合成不执行——这是本件的第一原则，宁可没有名次，也不给一个由单维决定的名次。

本件的实际流程停在「维度可得性矩阵」这一步：把四维的原料量、覆盖率、可算性逐一列出，再判定合成是否可行。这不是「没做完」，是「做完了该做的判断」——在分母恒缺的情况下，正确的交付是缺口清单，不是凑出来的名次。

| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| D1 规模 | 财务表 + 注册资本 | 城市均值 | 四城有值 |
| D2 密度 | 面积表 | 取值 | **缺** |
| D3 完整度 | tags + 链目录 | k/K | 全国与深圳有值 |
| D4 评分 | 评分表 | 扫描 | **0 张** |
| 合成 | 四维 | 加权 | 未执行 |

### 2.2 口径定义与公式

三维加权合成的定义：

$$S_{c}=0.4\cdot \tilde{s}_{c}+0.3\cdot \tilde{d}_{c}+0.3\cdot \tilde{k}_{c}$$

其中 $\tilde{s}$、$\tilde{d}$、$\tilde{k}$ 分别是规模、密度、完整度的极值归一值：

$$\tilde{x}_{c}=\frac{x_{c}-\min x}{\max x-\min x}$$

极值归一化的一个性质必须说清：它对缺失值极其敏感。若某维只有四个城市有值，其余城市在这一维上要么被填 0（等价于最差）、要么被跳过（等价于不参与），两种处理会给出完全不同的名次。OECD 手册要求显式声明缺值规则，本件在缺维时直接不合成，等于把这条规则推到极端——不猜。

名次的定义是标准竞争排名：

$$R_{c}=1+\#\{c':\ S_{c'}>S_{c}\}$$

同分并列、下一名跳号。本件未执行到这一步，公式只作口径登记。

| 参数 | 取值 | 状态 |
|---|---|---|
| 规模权重 | 0.4 | 王惠底稿，未闭合 |
| 密度权重 | 0.3 | 王惠底稿，未闭合 |
| 完整度权重 | 0.3 | 王惠底稿，未闭合 |
| 归一化 | 极值 | 王惠底稿 |
| 缺值规则 | 不合成 | 本件自定义、待甲方确认 |

### 2.3 累计口径与年度切分的区别

本件是截面排名：按最新可得年数据合成，不做年度序列。

排名做年际比较有一个天然陷阱：权重不变、城市集合不变，但数据年变了，名次变化里混着「真实进步」与「数据更新」两种成分。要做年际比较，必须先固定数据年，再逐年重算——本库连单年完整数据都没有，谈不上年际。

| 口径 | 含义 | 本件是否采用 |
|---|---|---|
| 截面排名 | 最新年一次合成 | 拟采用（未执行） |
| 年度排名序列 | 逐年合成再比较 | 否（数据不支持） |
| 分组排名 | 按规模档分组 | 否（规则未闭合） |

### 2.4 计算步骤（脚本逐步实现）

1）读城市计数快照；2）查注册资本填充与均值；3）读财务面板算城市营收均值与覆盖率；4）扫评分表；5）读同口径完整度产物；6）组装维度矩阵，判定合成可行性；7）写产物（含 `composite_rank.computed = false`）。

第 7 步是本件的核心交付。它不是说「算不出」，是说「四维里两维恒缺、一维只覆盖 0.3%—0.8%，合成出来的名次不可解释」——这是一个有依据的判断，不是放弃。

| 步骤 | 实现 | 校验 |
|---|---|---|
| 城市计数 | 快照聚合 | 66 城 |
| 注册资本 | SQL 聚合 | 四城填充 > 99% |
| 营收均值 | 面板聚合 | 四城有值 |
| 评分表扫描 | `information_schema` | 0 张 |
| 完整度 | 读同口径产物 | 98.53 / 74.63 |

### 2.5 结果与维度矩阵

四维的实测状态：规模维「部分可算」、密度维「恒缺」、完整度维「可算」、评分维「恒缺」。两缺两有，合成不成立。

规模维的细节值得看：营收覆盖深圳 0.7061%、广州 0.7540%、东莞 0.3126%、惠州 0.3808%，四城都在 1% 以下；注册资本填充反而都在 99% 以上（深圳 99.6444%、广州 99.0707%、东莞 99.6844%、惠州 99.2785%）。这说明「规模」并不是没有原料，而是「营收」这条原料太薄、「注册资本」这条原料很厚——用哪条，是口径选择，必须甲方定。

| 维度 | 权重 | 状态 | 关键实测 |
|---|---|---|---|
| D1 规模 | 0.4 | 部分可算 | 营收覆盖 0.31%—0.75%；注册资本填充 > 99% |
| D2 密度 | 0.3 | 恒缺 | 面积列 0 命中 |
| D3 完整度 | 0.3 | 可算 | tags 2,283,762 行；全国 98.53%；深圳 74.63% |
| D4 评分 | — | 恒缺 | 评分表 0 张 |

### 2.6 关键中间量与校验

五个中间量：66 城、62 城不足 1,000 家、四城 188,774 家（99.82%）、营收 > 0 2,191 行、评分表 0 张。

校验一：四城之和 188,774 ≤ 全库 189,116，通过。校验二：62 + 4 = 66，通过。校验三：营收 > 0 2,191 / 90,926 = 2.41%，与规模维「部分可算」的结论一致。校验四：评分表扫描 0 张，与「评分维恒缺」一致。

| 量 | 取值 | 校验方式 |
|---|---|---|
| 城市数 | 66 | 去重取值 |
| 样本不足 1,000 家的城市 | 62 | 计数 |
| 四城合计 | 188,774 | 小于等于全库 |
| 营收 > 0 行 | 2,191 | 占财务表 2.41% |
| 评分表 | 0 | 表名扫描 |

### 2.8 与旧稿的差异

旧稿在开发库口径下引用了两张评分表（技术评分与商业评分），本稿在 gkx 扫描 `%score%` / `%rank%` / `%evaluat%` / `%rating%` 表名，命中 0 张——两张表在 gkx 都不存在。

第二处差异是密度维。旧稿引用 `dim.code_region.area`（该表在 gkx 不存在），本稿改用「全库面积列扫描 0 命中」的否定性证据。证据形态从「表在列空」变成「列不存在」。

第三处差异是本稿新增注册资本维的实测填充率（四城 > 99%），这是旧稿没有的信息——它意味着规模维有替代原料，只是替换口径需要甲方确认。

| 项 | 旧稿 | 本稿 | 差异原因 |

| 评分表 | 引用两张 | 0 张 | 表在 gkx 不存在 |
| 面积来源 | `dim.code_region` | 全库扫描 0 命中 | 口径换轨 |
| 规模原料 | 仅营收 | 营收 + 注册资本 | 新增实测 |
| 名次 | 未合成 | 未合成 | 结论未变 |

### 3.1 依赖表与可得性

其中标签表最厚：2,283,762 行，链目录 1,273 行、12 个链根、954 个叶子。这是本件唯一「现在就能算」的一维。

### 3.2 四判定落表

结构与数据都在「二维成立、二维不成立」的状态。按四档定义，只要有必需维度恒缺，就不能落完全转换支持。

| 判定项 | 结论 | 证据 |
|---|---|---|
| 表结构直接支持（开发库+三方库） | 否 | 无排名结果面 |
| 表数据直接支持（开发库+三方库） | 否 | 同上 |
| 依赖表结构支持（开发库/三方库） | 二维是 / 二维否 | 面积与评分无载体 |
| 依赖表数据支持（开发库/三方库） | 一维足 / 一维薄 | tags 足、营收薄 |
| 聚合结论 | 部分支持 | 合成不成立 |

### 3.3 数据量、覆盖与代表性

样本结构是本件最根本的约束：66 个城市里 62 个不足 1,000 家企业，四城合计占 99.82%。极值归一化在这种分布下会把北京、上海压到接近最小值，名次由「样本量」而非「竞争力」决定。

这个约束不是数据质量问题，是「本库是广东库」这个事实的必然结果。换任何归一化方法、任何权重，都改不了「62 个城市几乎没有样本」这件事。

### 3.4 结构支持判定

结构侧的问题是「缺两张表」：面积表与评分表。面积表决定密度维，评分表决定评分维。两张表都不是本库能自造的——面积要外部统计，评分要建模。

另一层结构问题是「权重未闭合」。即便四维齐备，40/30/30 仍是王惠底稿值，没有甲方会签，名次就只是「一种可能的权重下的名次」，不是官方口径。

### 3.5 与开发库 live 的差异

开发库有评分表与区域维表，gkx 都没有。这意味着同一个指标在两个库里「缺什么」不同：开发库缺的是数据量，gkx 缺的是表。

上线需先补两张表（面积、评分），再由甲方闭合权重与对标城市集合（Q014 / Q016），才谈得上出第一个正式名次。

## 四、数据缺失情况

### 4.1 缺口清单

六个缺口。前两个是维度缺，第三个是样本缺，后三个是口径缺。

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| 城市面积表 | 密度维不可算 | 维度标 absent | 甲方提供 |
| 评分表 | 评分维不可算 | 表名扫描 0 张 | 需建模新建 |
| 62 城样本不足 | 名次不可解释 | 只做四城示意 | 扩样本 |
| 权重未闭合 | 名次非官方 | 标注待确认 | 甲方会签 Q014 |
| 对标集合未闭合 | 参评城市未定 | 用四城 | 甲方定 Q016 |
| 营收覆盖 < 1% | 规模维薄 | 用注册资本替代 | 提升披露率 |

### 4.2 逐条影响

**面积表缺失**让密度维整维失效，而密度维占 30% 权重。这不是「少一个数」，是「少三分之一的权重」。

**评分表缺失**让评分维失效。旧稿把评分作为规模维的子项，本稿把它单列为第四维，因为它在 gkx 完全不存在——单列才能让缺口可见。

**62 城样本不足**是最难补的缺口。面积与评分可以买、可以建，样本只能靠时间积累。在这个约束下，即使四维齐备，名次也只在前四城内有意义。

### 4.3 明确不做什么（禁止的替代）

- 不用「有值的那一维」充当综合得分——那是完整度排名，不是城市排名。
- 不用人口密度反解面积——`a77361` 只有 30 行、14 国、止于 2021。
- 不自造权重——40/30/30 是王惠底稿值，改动须甲方会签。
- 不用注册资本直接替换营收而不声明——两者语义不同，替换是口径变更。
- 不把 62 个样本不足的城市放进同一极值归一化——它们会定义极值端点。

五条禁令的共同点是「不要用一个能算的东西冒充想算的东西」。能算的是完整度与注册资本，想算的是综合竞争力，两者不是一回事。

### 4.4 若甲方补齐后的口径升级路径

补齐分三步：先补表（面积、评分），再闭口径（权重、对标集合），最后才出排名。三步顺序不能颠倒——先闭口径再补表，会得到一个「权重定了但没数」的空转；先补表再闭口径，至少能出敏感性分析。

补齐后仍需处理样本问题：62 城不足 1,000 家，建议按规模档分组排名（B 族做法），而不是全局极值归一。

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 补面积表 | 密度维可算 | 三维成立，仍缺评分 |
| 补评分表 | 四维齐备 | 可升完全转换支持 |
| 闭合权重 | 名次具官方性 | 同上 |
| 闭合对标集合 | 参评城市确定 | 同上 |
| 扩样本 | 名次可解释 | 同上 |

**基期声明**：`base_years_used` = []；`base_years_missing` = []。本件是截面排名，按最新可得年数据合成；因名次未出，不涉及基期序列。

## 五、王惠方法对照

王惠底稿给出三维 40/30/30 与极值归一化，本件完整沿用，未改权重、未改归一化。差异在数据侧：底稿假定三维原料齐备，本件实测两维恒缺、一维覆盖不足 1%。

第二处差异是评分维的处理。底稿把技术评分与商业评分作为规模的子项，本件把它们单列为第四维并标 absent——因为它们在 gkx 连表都没有，混在规模维里会让缺口不可见。

**选用建议**：三维构成、权重、极值归一化三项沿用王惠；密度与评分两维在补齐前不合成；注册资本作为规模维的替代原料需甲方确认后再用；名次在权重闭合前只作内部试算，不对外称官方排名。
