## 摘要

技术影响力评估按 calc-logic 是两项等权合成：

$$\mathrm{Score}=0.5\times S_{\text{citation}}+0.5\times S_{\text{SEP}}$$

本次只交付 $S_{\text{citation}}$，因为 $S_{\text{SEP}}$ **无法测量**——不是测出来为 0，是没有表。等权合成若把缺失维按 0 摊入，会把所有链的分数砍半，制造「技术影响力普遍偏低」的假象。产物因此显式写 `composite_status="not_computable"`，只出子项。

被引子项的结果：9 条链有可回连专利，3 条链（智能网联汽车、低空经济、数字创意）为 0 件。子项 0—100 由链内篇均被引做 min-max 得到：机器人 **100.0**（1 件专利、9 次被引）、智能终端 **47.5411**（61 件 / 261 次）、集成电路 **44.4444**（2 件 / 8 次）、传感器 **17.7778**（5 件 / 8 次）、人工智能 **14.0433**（72 件 / 91 次）、具身智能 **11.1111**（10 件 / 10 次）、合成生物 **10.6278**（23 件 / 22 次）、生物医药 **4.9378**（9 件 / 4 次）、软件与信息服务 **3.1744**（7 件 / 2 次）。

样本链路的每一层都在收窄：`dwd_patent_cited` 有 **20,515** 行、覆盖 **20,000** 件专利，只占 `dwd_patent` 2,939,895 件的 **0.6803%**；用 `pn` 回连 `dwd_patent` 成功 **467** 件（**2.335%**）；再按权利人映射到底册与 12 条链，落到链内的只有 **190** 件、**415** 次被引（占 467 件的 **40.6852%**）。剩下 **277** 件、**471** 次被引找不到链归口——这部分占已回连被引的 **53.1603%**，比链内还多。换句话说，**一半以上的可用被引数据无法归到 12 条链**。

集中度极高：被引前 10 件专利合计 **482** 次，占全部被引 **10,786** 次的 **4.4688%**；华为一家 41 件专利、224 次被引，单独撑起智能终端链的 85.82%（224/261）。这让「链均篇被引」更像「头部企业篇被引」，而不是链的整体技术水平。

SEP 侧的否定性证据：gkx **280 张表**里以 standard/SEP 命名的表 **0 张**，仅 2 个列名含 `standard_product_name`（招标标的表，非专利 SEP）；live DWD 137 张、ADS 95 张表里 SEP 类表 **0 张**。所以 SEP 只能记「未测」，不能记 0。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

产业潜力评估（DS-07）的「技术影响力」模块。页面左侧是 12 条链的雷达图，五个轴分别是技术影响力、市场潜力、创新活跃度、资本热度、政策匹配；技术影响力轴由本件供给，右侧再拆成两个子轴：被引影响力（0—100）与 SEP 拥有度（0—100）。

被引子项的数据流是：专利被引表 → 专利主表（`pn` 回连）→ 权利人 → 底册/链 → 链级聚合 → min-max 归一。SEP 子项的数据流本应是：标准必要专利声明表 → 专利主表 → 链，但第一张表不存在，整条流断在起点。

### 1.2 为什么需要这个指标

第一，**它是「技术影响力」唯一可量化的外部验证**。专利数量可以被策略性堆砌，被引次数不能；引用是第三方专利用脚投票的结果。

第二，**它能暴露「数量大、影响小」的链**。软件与信息服务链有 7 件可回连专利、只有 2 次被引，篇均 0.2857；人工智能 72 件、91 次，篇均 1.2639。两条链的专利量差 10 倍，影响力却没有同比例上升。

第三，**它必须带样本说明，否则会被当成全库结论**。被引表只覆盖 2 万件专利；把它当成 294 万件专利的全样本，会得出「99.3% 的专利从未被引」这种错误结论。

### 1.3 需求文档是否给出定义方法

**给了合成公式，没给数据可行性与 SEP 口径。** calc-logic 原文：

```
技术影响力 = 0.5 × 被引子项 + 0.5 × SEP 子项
被引子项：链内专利篇均被引，min-max 归一到 0—100
SEP 子项：标准必要专利占比 × 100
```

原文没有回答三个问题：①被引表覆盖多少专利；②SEP 表在哪；③无专利的链怎么处理。本件的处理是：①如实披露 0.6803%；②用否定性探针证明两库无表，记 `not_measurable`；③保留 0 值但在报告里标注「无可回连样本，不是影响力为 0」。

### 1.6 本报告的口径与边界（须与甲方会签）

第 $c$ 条链的被引子项：

$$S_{\text{citation}}(c)=100\times\frac{\bar{x}_c-\min_{c'}\bar{x}_{c'}}{\max_{c'}\bar{x}_{c'}-\min_{c'}\bar{x}_{c'}},\qquad \bar{x}_c=\frac{\sum_{p\in P_c}\mathrm{cited}(p)}{|P_c|}$$

其中 $P_c$ 是链 $c$ 内「可回连且去重」的专利件集合。合成总分：

$$\mathrm{Score}(c)=0.5\times S_{\text{citation}}(c)+0.5\times S_{\text{SEP}}(c)$$

**六条边界**：

1. **样本不是全库。** 被引表 20,000 件 / 2,939,895 件 = 0.6803%；所有结论只在这 2 万件内成立。
2. **链内池只有 190 件。** 篇均与份额的分母是 190 件 / 415 次，不是 2,939,895 件，也不是 189,116 家。
3. **零链不是零影响力。** 3 条链没有可回连专利，标 0 是「无样本」，不是「被引为 0」。
4. **min-max 受极值支配。** 机器人只有 1 件专利、9 次被引，却因为篇均最高被定为 100；这个 100 的含义是「本样本内相对最高」，不是「技术影响力满分」。
5. **SEP 未测。** 记 `not_measurable`，不记 0，不参与合成。
6. **不做年份归一。** 2021—2023 混算；早申请专利的被引窗口更长，天然占优。

## 二、计算过程

### 2.1 被引样本：20,515 行 / 20,000 件

`dwd_patent_cited` 的结构是「被引专利 × 引用方」明细。按 `pn` 去重后 20,000 件，被引次数合计 **10,786**。分布极度右偏：

| 统计量 | 值 |
|---|---:|
| 被引行 | 20,515 |
| 去重专利 | 20,000 |
| 被引合计 | 10,786 |
| 均值 | 0.5393 |
| 中位数 | 0.0 |
| 正被引专利 | 3,581 |
| 正被引率 | 17.905% |
| 正被引中位数 | 2.0 |
| P90 | 2.0 |
| 最大值 | 55 |

均值 0.5393、中位数 0，说明 **82.095% 的专利在这份样本里一次都没被引**（`derived.zero_cited_pct`）；被引集中在少数专利上。正被引专利的篇均被引是 10,786 / 3,581 = 3.0120（`probes.positive_mean_cited`），是中位数的 1.5 倍，右尾很长。

### 2.2 回连专利主表：467 件

用 `pn` 把 20,000 件被引专利回连 `dwd_patent`，成功 **467** 件，回连率 **2.335%**。回连失败的 19,533 件（`derived.unmatched_in_patent_n`）不是「专利不存在」，而是 `dwd_patent_cited` 的 `pn` 与 `dwd_patent` 的 `pn` 格式/范围不一致（含大量外部引用、PCT 阶段号、法律状态变更号）。

467 件的被引合计 **886** 次，占 10,786 的 8.2144%。也就是说，**能回连的专利只承载了 8.21% 的被引**；剩下 91.79% 的被引落在无法回连的专利上，本件无法使用。

### 2.3 权利人映射：140 → 98 → 35

467 件专利对应 **140** 个权利人。按名称精确匹配 `dwd_org_base_info`，**98** 家落在 189,116 家底册内（70.0%）；再按 12 条链的成员索引匹配，**35** 家落在链内（25.0%）。

三步收窄的损耗：140 → 98 损失 42 家（名称写法差异、子公司未合并）；98 → 35 损失 63 家（底册企业在链外，或链成员按专利阈值截取时未纳入）。最终只有 35 家企业的专利进入链级计算。

### 2.4 链归属：190 件 / 415 次，277 件无法归链

35 家链内企业对应 **190** 件可回连专利、**415** 次被引，占 467 件的 **40.6852%**、886 次的 **46.8397%**。剩余 **277** 件、**471** 次被引的权利人不在链内，无法归到 12 条链——这 471 次占已回连被引的 **53.1603%**。

这个比例说明：**链归属是本件最大的损耗点，不是被引表本身**。即使被引表覆盖完整，只要权利人不在 12 条链内，数据就用不上。

### 2.6 子项归一：min-max 的三处失真

子项公式是链内篇均被引的 min-max。这个选择有三个已知失真：

第一，**极值支配**。机器人 1 件专利、9 次被引，篇均 9.0 为全样本最高，子项直接 100；智能终端 61 件、261 次，篇均 4.2787，子项只有 47.5411。专利量差 61 倍，子项差 2.1 倍，方向相反。

第二，**零链拉低最小值**。3 条零链的篇均记 0，成为 min；如果没有零链，最小值是软件的 0.2857，所有子项都会被压低。零链在这里扮演了「分母锚点」，但它的 0 是「无样本」不是「低影响力」。

第三，**未做年份归一**。样本集中在 2021—2023：2021 年 289 件、494 次被引；2022 年 164 件、382 次；2023 年 14 件、10 次。2021 年申请专利的被引窗口比 2023 年长约两年，篇均天然更高。本件没有按申请年做期望被引校正，子项在年份维度上不可比。

### 2.7 SEP 子项：为什么是 `not_measurable` 而不是 0

| 探针 | gkx | live |
|---|---|---|
| 表名含 standard/SEP | 0 / 280 张 | DWD 0 / 137；ADS 0 / 95 |
| 列名含 standard/SEP | 2 个（`standard_product_name`） | —— |
| SEP 声明表 | 无 | 无 |
| SEP 专利标记 | 无 | 无 |

两个 `standard_product_name` 列在 `dwd_bid_target_item_out` 及其备份表里，是**招标标的的标准产品名**，与标准必要专利无关。把它当 SEP 标记会得出「所有招标产品都是 SEP」的荒谬结论。

因此 `sep_patent_n=null`、`sep_share_pct=null`、`sep_status="not_measurable"`。这不是保守，是唯一诚实的记法：0 会被下游读成「已测且没有 SEP」，而事实是「没有测」。

### 2.8 合成为什么不输出

`composite_formula` 仍是 `0.5 * citation_subindex + 0.5 * SEP_subindex`，但 `composite_status="not_computable"`。原因是等权合成的语义要求两维都可测；把 SEP 当 0，会让所有链的总分不超过 50，且链间差异被压缩一半。产物只出 `citation_subindex_0_100`，前端雷达图的 SEP 轴置灰。

## 四、数据缺失情况

### 4.1 缺口的后果归因

**缺口一：被引表只覆盖 0.6803%。** 20,000 / 2,939,895。后果：所有结论只在这 2 万件内成立；不能外推全库。

**缺口二：回连率 2.335%。** 20,000 件里只有 467 件能回连专利主表。后果：即使被引表扩大，`pn` 格式不一致仍会卡住回连。

**缺口三：链归属损耗 53.16%。** 471 / 886 次被引的权利人不在链内。后果：链级篇均被引只代表「链内可回连的 190 件」，不代表链的整体技术影响力。

**缺口四：SEP 两库无表。** 后果：总分不可算，SEP 轴只能置灰。

**缺口五：3 条链零样本。** 智能网联汽车、低空经济、数字创意没有可回连专利。后果：子项 0 是「无样本」，不是「无影响力」。

### 4.2 数据陷阱（本批实测）

**陷阱一：把 0.5393 当全库篇均被引。** 它是 2 万件样本的均值，不是 294 万件的均值。全库若按 0 摊入未覆盖专利，篇均会被稀释到 0.0037（`derived.pooled_mean_cited_uncovered_as_zero`）。

**陷阱二：把 SEP 记 0。** 0 会被读成「已测且没有」，实际是「无表」。正确记法是 `null` + `not_measurable`。

**陷阱三：用 189,116 或 2,939,895 做链内份额分母。** 链内份额的分母是 415 次 / 190 件；用大分母会把所有链压成 0.0%。

**陷阱四：把机器人的 100 当满分。** 它是 1 件专利、9 次被引的 min-max 结果；样本极小，置信度极低。

**陷阱五：把 2023 年的 14 件当断崖。** 是截断偏差，不是技术衰退。

**陷阱六：把链外高校的高被引算进链内。** 北京航空航天大学 40 次、上海交大 39 次都因权利人不在链内被排除；若强行按专利文本关键词归链，会把基础研究算成产业技术。

### 4.3 可构建但存在缺口（不是「无法构建」）

被引子项现在就能算，9 条链有值；这是「可构建」。但样本覆盖 0.6803%、链归属 40.6852%、SEP 无表，三项都无法通过加工消除，故不能判完全转换支持。

### 4.4 若甲方补齐后的口径升级路径

第一步扩大被引表覆盖（目标 ≥30% 专利），第二步统一 `pn` 格式把回连率提到 ≥80%，第三步补权利人别名表把链归属提到 ≥70%，第四步接 ETSI/信通院 SEP 声明库，第五步按申请年做期望被引归一。五步完成后，本件可升为完全转换支持，总分才可输出。

## 五、结论与发布建议

### 5.1 结论

**被引子项可算，但只代表 190 件专利。** 9 条链有值、3 条零样本；机器人 100 是极小样本的极值，智能终端 47.5411 是唯一「样本量 + 影响力」都还过得去的链（61 件 / 261 次）。

**SEP 子项不可测，总分不可算。** 这不是实现问题，是数据面缺失；任何声称输出总分的实现，都在把缺失维当 0。

### 5.2 与王惠 V3-2 的对照

王惠 V3-2 未单列本 ID，也没有 DS-07 的技术影响力子项；本件只有 calc-logic 的合成公式可对照。对照结论是：公式可复现，但两个子项一个样本受限、一个结构缺失，公式在当前数据面上不可完整执行。

| 维度 | 王惠 V3-2 | 本版 | 说明 |
|---|---|---|---|
| 正本 | 无 | calc-logic 有 | 无同 ID 对照 |
| 被引样本 | —— | 20,000 件（0.6803%） | 样本受限 |
| 链内池 | —— | 190 件 / 415 次 | 归属损耗 |
| SEP | —— | `not_measurable` | 两库无表 |
| 总分 | —— | `not_computable` | 缺维不合成 |

### 5.3 选用建议与理由

**建议前端只展示被引子项，SEP 轴置灰并写明「未测」。** 不要用「0」占位，也不要用「—」而不解释；两种都会被读成「没有 SEP」。

**建议给每条链加样本量标签**（如「61 件 / 261 次」）。篇均被引离开样本量就没有意义；机器人的 100 与智能终端的 47.5411 并排而不标样本量，会误导用户。

**建议不做链间排名。** 3 条零链、样本量差 61 倍、年份未归一，三者叠加使排名不稳；按子项分档（高 / 中 / 低 / 无样本）比排名更诚实。
