## 摘要

「区域企业数量」是省、市、县三级区域键上的去重家数，回答「这个市有多少家企业」。它在产品上是地理透视页的主表，也是所有区域类指标（密度、排名、集中度）的分子底座。

实测 gkx 主档 189,116 行，`org_id` 全表唯一（189,116 个不同值），因此按行计数与按主体去重计数逐位相等，不存在重复计数风险。省级 30 个取值求和 189,116、市级 66 个取值求和 189,116，闭包差为 0；区县级 142 个名称覆盖 155,444 行（82.20%），缺口全部来自主档未填区县。

分布高度集中：广东 188,776 家（99.82%），其中深圳 95,600（50.55%）、广州 49,605（26.23%）、东莞 33,590（17.76%）、惠州 9,979（5.28%）四城合计 188,774 行（99.82%）；省外最大的是北京 163 家，上海 16 家。这个结构决定了本指标在页面上只能讲「粤港澳都市圈的三级透视」，不能讲「全国区域对比」。

区域码可以绑定：城市名到 12 位区划码的绑定覆盖 189,115/189,116（99.9995%），区县名到码的绑定覆盖 152,407/155,444（98.05%），未绑定的 3,037 行里 3,027 行是「深圳市/坪山区」（字典里写作坪山新区）。因此判**完全转换支持**：结构与数据都够、现在就能算出三级表，缺的只是目标落表与国外国别字段。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业分析 → 企业总览 / 重点企业类型分析**的「三级地理透视」区域。页面形态是一张可下钻的表：省 → 市 → 区县，每级显示家数与占比；点开某市可见其区县分布。

它是一个计数指标，不带权重、不带评分。计数指标的好处是可复核——任何一级的数字都能用同一张主档重算出来；坏处是无法表达「企业质量」，所以它必须与规模、密度类指标配合使用，不能单独当区域竞争力的结论。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业分析 → 企业总览 → 区域分布 |
| 页面载体 | 三级下钻表 + 区域热力 |
| 输出形态 | 省 / 市 / 区县 → 家数 + 占比 + 区划码 |
| 更新频率 | 建议月度（主档增量驱动） |
| 粒度 | 行政区划（省 2 位 / 市 4 位 / 县 6 位） |

### 1.2 为什么需要这个指标

第一，它是所有区域指标的底座。密度要分子、排名要分子、集中度要分子，三个指标的分母或权重各不相同，但分子都是本件算出的这个家数。先把分子做实，后三个才有意义。

第二，它是数据质量的第一道体检。省级求和是否等于总行数、市级求和是否等于总行数、区县填充率是多少——这三个数一摆出来，主档的完整性立刻可见。本件把三个闭包值都写进产物，就是为了让复核者不必信任叙述。

第三，它是甲方最容易验收的指标。名字叫「区域企业数量」，交付的就是每个区域的家数，没有口径解释空间。相比之下，密度和排名都要先解释分母与权重，验收成本高得多。

### 1.3 需求文档是否给出定义方法

**给了分组维度，没给去重规则与国外边界。** calc-logic 写的是：按行政区划对企业去重计数，省、市、县三级都出，国外单列国家计数。三级与「国外单列」是明确的；未明确的是：去重键用 `org_id` 还是统一社会信用代码、分支机构是否计入母公司、存续与注销是否分开。

本件的处置：去重键用 `org_id`（主档主键，189,116 行全唯一，用信用代码反而会因空值丢行）；分支机构按独立主档计入其注册地（不并入母公司）；存续与注销不分开计，但把存续家数单列为 `alive_rows`，需要时可直接切。三条都在产物 `proxy_deviation` 与本节写明，不默认甲方已知。

### 1.4 类似指标权威机构构建方法可行性

区域企业计数在业界有三套常见口径：市场监管部门的登记统计（按登记机关辖区）、统计部门的法人单位统计（按经营地）、商业数据库的注册地聚合（按注册地址）。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 登记辖区统计 | 市场监管总局经营主体统计 | 按登记机关与注册地分层计数 | 高（本件采用，字段同构） |
| B 法人单位统计 | 国家统计局法人单位清查 | 按经营地（实际所在地）计数 | 中（经营地字段本库没有） |
| C 商业库聚合 | 企业信息服务机构 | 注册地址解析 + 去重 | 中高（做法一致，口径不公开） |

**A 族是本件采用的方法。** 主档的 `province` / `city` / `area` 就是登记住所的行政区划名，与「按登记辖区计数」同构。差别在于本库不记登记机关辖区，只记住所地，两者在绝大多数企业上一致，在跨区登记（如在市局登记、住所在区）时会差一级，这是已知且可解释的偏差。

**B 族的经营地口径在本库不可得。** 主档只有 `address` 文本，没有结构化的经营地字段，从地址文本反解经营地需要地址解析服务，本批不做。所以本件交付的是「注册地口径」，页面文案不能写「实际分布」。

**C 族**的做法（地址解析 + 去重）与本件一致，但它们的区域归属常由地址文本推断，误差率不公开。本件用字段直取，反而更可复核。

## 二、计算过程

### 2.1 总体思路与数据流

一次 `GROUP BY province, city, area` 拿到三级计数，再在内存里按级求和。不在 SQL 里分三次查，是因为三次全表扫的成本是三次约 100 秒；一次扫完在 Python 里聚合，成本是一次。

聚合结果落盘为快照，后续重跑读快照。快照里带 `source` 字段（库名、主机、表名、查询、拉取时刻），任何一份数字都能追到「什么时候、从哪张表、用什么语句」取的。这是本件可复现的关键：数字不是「跑出来的」，是「可追溯地算出来的」。

| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 拉取 | `dwd_org_base_info` | 一次 GROUP BY 三级 | 152 组计数 |
| 省级 | 152 组 | 按 `province` 求和 | 30 行 |
| 市级 | 152 组 | 按 `(province, city)` 求和 | 66 行 |
| 区县级 | 152 组中 `area` 非空 | 按 `(province, city, area)` 求和 | 146 组 / 142 名 |
| 绑定 | `dwd_dim_admin_area` | 中文名等值 → 12 位码 | 三份码表 |
| 校验 | 三级求和 | 与总行数比对 | 闭包差 0 |

### 2.2 口径定义与公式

三级计数是同一件事在不同粒度上的求和：

$$N_{p}=\sum_{i \in p} 1,\qquad N_{c}=\sum_{i \in c} 1,\qquad N_{d}=\sum_{i \in d} 1$$

占比按同一分母（全库企业数 $N$）计算，便于横向比较；区县另给一个「占本市比」，用于看市内结构：

$$s_{c}=\frac{N_{c}}{N}\times 100\%,\qquad s_{d\mid c}=\frac{N_{d}}{N_{c}}\times 100\%$$

去重键的选择值得单说。主档 189,116 行、`org_id` 189,116 个不同值，行数等于主体数，所以 $\sum 1$ 与 `COUNT(DISTINCT org_id)` 完全等价。如果改用统一社会信用代码去重，会因 `external_id` 有空值而丢行——这是本件刻意避开的一个坑。

| 量 | 取值 | 含义 |
|---|---|---|
| $N$ | 189,116 | 全库企业行数 = 主体数 |
| 省数 | 30 | `province` 去重取值 |
| 市数 | 66 | `(province, city)` 去重取值 |
| 区县名 | 142 | `area` 去重取值（跨市同名只算一次） |
| 区县三元组 | 146 | `(province, city, area)` 去重取值 |

### 2.3 累计口径与年度切分的区别

本件是**截面**指标：数的是「当前主档里有多少家」，不是「某年新增多少家」。两者不能混：截面随注销与迁址变动，年度新增只增不减。

为什么不做年度序列：主档没有「区域变更历史」表，`updated_time` 只记最后一次改动时间，无法还原「某企业 2023 年在深圳、2025 年迁到东莞」。强行按 `incorporation_year` 切区域，会得到「按注册年分布的当前区域」，语义是错的——那等于假设企业从未迁址。

这个选择让本指标适合做「现状透视」，不适合做「区域迁移趋势」。要做后者，必须先有区域变更流水，库内没有。

| 口径 | 含义 | 本件是否采用 |
|---|---|---|
| 截面家数 | 当前主档按区域计数 | 是 |
| 按注册年切分 | 每年新设企业的当前区域 | 否（会与迁址混淆） |
| 存续口径 | 仅 `reg_status` 含「存续」 | 单列 `alive_rows`，不替换主口径 |

### 2.4 计算步骤（脚本逐步实现）

1）读三级计数快照（未命中则现查 gkx 并落盘）；2）按省、市、区县三级分别求和；3）读区划字典，建三份「中文名 → 码」映射；4）逐行绑定码，统计绑定覆盖；5）算占比与规模分档；6）写闭包校验与产物。

第 4 步的绑定用中文名等值，不用模糊匹配。原因是区划名在主档与字典里高度一致（市级 99.9995% 命中），模糊匹配只会引入错配；剩下 0.0005% 的未命中宁可留空，也不猜。

| 步骤 | 实现 | 校验 |
|---|---|---|
| 三级求和 | dict 累加 | 三份行数 |
| 码绑定 | `name → code` 等值 | 覆盖率 |
| 占比 | 除法 + 四位小数 | 合计 100% 附近 |
| 分档 | 阈值计数 | 66 个市全覆盖 |

### 2.6 关键中间量与校验

四个中间量支撑全部结论：总行数 189,116（分母）、省级求和 189,116（闭包一）、市级求和 189,116（闭包二）、区县填充 155,444（三级可用量）。

校验一：省级求和 = 总行数，差 0，通过。校验二：市级求和 = 总行数，差 0，通过。校验三：区县填充 155,444 + 空值 33,672 = 189,116，通过。校验四：城市码绑定 189,115 + 未绑定 1 = 189,116，通过。

| 量 | 取值 | 校验方式 |

| 省级闭包 | 189,116 | 与总行数相等 |

### 3.1 依赖表与可得性

本件只依赖一张主档与一张维表。主档提供区域键与状态，维表提供区划码。两张表都在、都有数，这是它能算出来的根据。

主档的成本在扫描：`province` / `city` / `area` 三列没有索引，一次 GROUP BY 全表扫约 100 秒。这不是数据问题，是查询成本问题，处置方式是落快照复用，而不是把查询拆碎。

| 依赖维度 | 实测状态 | 关键证据 | 缺口与修复路径 |
|---|---|---|---|
| 省级键 | 可用 | 30 个取值，闭包 189,116 | 无 |
| 市级键 | 可用 | 66 个取值，闭包 189,116 | 无 |
| 区县级键 | 部分可用 | 155,444 行填充（82.20%） | 主档补区县，或按地址解析 |

### 3.2 四判定落表

四判定里，结构过、数据过，唯一不过的是「国外国别」这一子维度。它不影响三级主口径，所以不拉低档位，但必须在 §四 单列，否则甲方会以为「全球区域分布」已经交付。

| 聚合结论 | 完全转换支持 | 闭包差 0 |

### 3.3 数据量、覆盖与代表性

覆盖上，189,116 行全量进入三级计数，没有抽样、没有截断。省级与市级是 100% 覆盖；区县级覆盖 82.20%，缺的 17.80% 不是随机缺失——东莞 33,590 行全部没有区县（东莞不设区县，只有镇街），这是行政区划制度造成的结构性空值，不是数据质量问题。

代表性上，广东占 99.82%，这个比例决定了本指标只能讲都市圈内部结构，不能讲全国。任何「全国各省企业数排名」的用法都会得到一个只有第一名有意义的表。

规模分档显示：66 个市里，3 个市超过 10,000 家（深圳、广州、东莞），1 个市在 1,000—9,999（惠州），1 个市在 100—999（北京），4 个市在 10—99，57 个市不足 10 家。长尾极长，是典型的「一个省 + 一个尾巴」分布。

### 3.4 结构支持判定

结构侧够用：区域键是原生字段、区划码有现成字典、去重键唯一。三件事合起来，任何一个区域的家数都能用一条 SQL 复算。

局限在「区域」的语义：登记住所不等于经营地。一家企业在深圳注册、工厂在惠州，本件把它计入深圳。这是登记口径的固有偏差，不是本件的实现缺陷；要修正必须有经营地字段，库内没有。

### 3.5 与开发库 live 的差异

开发库有区域维表与汇总面，gkx 只有明细。上线需把三级计数物化成宽表（`region_code, level, cnt, share, stat_date`），并保留 `alive_cnt` 一列，让使用方自己选「全部」还是「存续」。

建议物化时同时存「全部」与「存续」两套，并在表注释里写明「注册地口径」，避免下游把它当经营地分布使用。

## 四、数据缺失情况

### 4.1 缺口清单

本件有六个缺口，按影响从大到小排。前两个影响可用性，后四个影响解释力，但都不影响三级主口径的成立。

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| 国外国别全空 | 全球分布不可交付 | 只给国外总量，国别标缺口 | 甲方补 `country` 字段 |
| 区县填充 82.20% | 17.80% 企业无区县 | 区县表只统计有值行 | 主档补区县 / 地址解析 |
| 登记地 ≠ 经营地 | 区域归属偏差 | 正文声明注册地口径 | 需经营地字段 |
| 坪山区未绑定 | 3,027 行区县码为空 | 保留名称、码留空 | 字典补「坪山新区」别名 |
| 省名简称未绑定 | 4 个省无省码 | 保留名称、码留空 | 字典补简称映射 |
| 无区域变更流水 | 不能做迁移趋势 | 不做年度切分 | 新建变更表 |

### 4.2 逐条影响

**国外国别全空**是最硬的缺口。20,000 行国外主档，`country` 列没有一行有值，意味着「国外按国家计数」这一支完全不可交付。本件把它单列为 `foreign.rows = 20000`，不给任何国别表——给空表会被误读成「没有国外企业」。

**区县填充 82.20%** 的影响是结构性的：东莞全域无区县，所以东莞的 33,590 家在任何区县视图里都不出现。区县表的合计永远小于全市合计，这不是算错，是口径决定的。

**坪山区**是绑定层的一个具体缺陷：主档写「坪山区」，字典写「坪山新区」，等值匹配失败，3,027 行的区县码为空。名称保留、码留空是正确处置——猜一个码比留空更危险。

### 4.3 明确不做什么（禁止的替代）

- 不把登记地当经营地——字段语义不同，混用会让区域分布整体偏移。
- 不用统一社会信用代码去重——有空值，会静默丢行。
- 不给国外国别空表——空表会被读成「零」，而事实是「未采集」。
- 不用地址文本反解区县——没有地址解析服务，正则截取会造出大量错配。
- 不把区县合计当全市合计——两者差 17.80%，混用会对不上账。

五条禁令的共同点是「不要把可数的东西说成想说的东西」。主档能数的是登记住所，需求想要的可能是经营分布，两者相关但不相同。

### 4.4 若甲方补齐后的口径升级路径

补齐分两条：一条补字段（国别、区县、经营地），一条补表（区域变更流水）。前者让现有口径更完整，后者让指标从截面升级为时序。

只补国别与区县，档位不变（仍是完全转换支持），但可交付范围从「国内三级」扩到「全球三级」。补了经营地，才谈得上「实际分布」；补了变更流水，才谈得上「区域迁移」。

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 补国别字段 | 国外可按国家计数 | 已是完全转换支持，范围扩大 |
| 补区县填充 | 区县覆盖升至接近 100% | 同上 |
| 补经营地字段 | 注册地 → 经营地双口径 | 同上，但语义更准 |
| 补变更流水 | 可做区域迁移时序 | 另立指标 |

**基期声明**：`base_years_used` = []；`base_years_missing` = []。本件是截面指标，按当前主档全量计数，不做年度切窗，故无基期年份；存续口径另有 `alive_rows = 168,830` 单列，需要时可直接切。

## 五、王惠方法对照

王惠原稿把区域企业数定义为「按行政区划去重计数，省市县三级 + 国外按国家」，与本件一致。差异在实现层：原稿假定区划码由维表直接给出，本件发现 gkx 的区划码需要中文名等值绑定，且绑定不是 100%。

第二处差异是国外：原稿假定 `country` 有值，本件实测全空。这不是口径分歧，是数据现实分歧，处置方式是在正文标缺口而不是改口径。

**选用建议**：三级口径、去重键、存续单列三项沿用王惠；区划码绑定改为「等值匹配 + 覆盖率披露」；国外国别在字段补齐前不交付，只给总量。若甲方坚持要国别表，应先补 `country` 字段，而不是用名称里的国名去猜。

## 六、运行、验收与变更
