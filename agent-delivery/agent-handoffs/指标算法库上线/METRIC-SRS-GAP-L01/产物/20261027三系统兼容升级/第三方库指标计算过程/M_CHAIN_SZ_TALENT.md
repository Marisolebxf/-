## 摘要

「深圳人才维度」是**深圳产业情况分析对比 → 综合优势**下的一维评分，需求原文要求把深圳的「人才」数据抽出来与北京、上海对比。需求文档**没有给出该指标的计算公式、权重与阈值**，calc-logic 给出王惠口径「人才数量 + 硕博占比」两维，本文在其基础上加入 BRIEF §3.4 的 ID 断裂约束后重建（`code/M_CHAIN_SZ_TALENT.py`，实测耗时 32.6 秒（首跑，跨网读取 gkx），输出 `code/M_CHAIN_SZ_TALENT_out.json`）。

核心实测：学者主档 21,316 人，深圳按机构名归集 **199 人**、按学者名归集 194 人、并集 **251 人**（占主档 **1.178%**）；广州 863 人、东莞 10 人。深圳学者中有学位记录的仅 **29 人**（占深圳 251 人的 11.55%），其中博士 27 人（93.1%）。人才属性表（`talent_flag` 20,030）与主档交集 **1,858（8.72%）**，教育表与主档交集 1,853。

结论：人才**数量**可以按机构名现算，但① ID 断裂使「分子/分母」不能跨表相除，② 学位结构的分母只有 29 人，③ 学者表无链归属字段使「产业链人才」不可切片 → 按 §〇 判**部分支持**；本指标不能对外表述为「深圳产业人才总量」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**产业链分析 → 深圳产业情况分析对比 → 综合优势**（需求编号 1.1.1.2.4.2.2.6 / 1.1.1.2.4.2.2.6.1）。

产品任务是：在指定产业链上，展示深圳的人才规模与结构（学历层次、称号层次），并与北京、上海等标杆区域对比，作为「综合优势」三维（专利/政策/人才）之一。人才维与专利维的区别是：专利反映**已发生的技术产出**，人才反映**可持续的研发能力**，二者共同回答「这条链深圳还能不能继续做下去」。

### 1.2 为什么需要「深圳人才维度」这个指标

人才是所有产业指标里最「上游」的一个：企业可以注册、专利可以申请、政策可以发文，但研发人才需要长期积累。对政府侧用户来说，人才维回答两个具体问题：**这条链深圳有没有人**（数量）、**这些人是什么层次**（结构）。前者决定能不能招商落地，后者决定能不能做高端环节。

在本项目里它还有一层特殊作用：深圳的产业研发力量**主要在企业**（华为、比亚迪、腾讯等），而学者库覆盖的是**高校与院所**。因此人才维天然会低估深圳——这个偏差必须在使用说明里写清，否则会被读成「深圳人才不如广州」。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**

三份需求说明书中，「深圳人才维度」这一**指标名未出现**；只在 1.1.1.2.4.2.2.6.1 出现「自动提取深圳在目标产业的企业、专利、政策、**人才**等数据，并与北京、上海等区域对比」。该句未规定：

- 人才的范围（学者 / 工程师 / 技能人才 / 全部从业者）；
- 人才的归属（现任职机构 / 毕业院校 / 户籍）；
- 数量的去重口径（人 / 人次 / 机构-人）；
- 结构的层级（学历 / 职称 / 人才称号）；
- 产业链归属规则（学科 / 院系 / 研究方向 / 任职企业的主营业务）。

calc-logic 的王惠口径补上了「人才数量 + 硕博占比」两维，但**没有处理**学者 ID 断裂问题（见 §2.2），也没有说明产业链如何切片。

### 1.4 类似指标权威机构构建方法可行性分析概要

| 方法族 | 代表机构/文献 | 核心做法 | 与本地数据的贴合度 |
|---|---|---|---|
| 人才政策目标口径 | 深圳市《关于实施更加积极更加开放更加有效的人才政策…的意见》(2023) | 以「杰出人才/基础研究人才/核心技术人才」等分层定义人才 | **中**：提供分层语义，但无统计口径 |
| 人才认定办法 | 深府规〔2024〕5 号《杰出科技创新人才选拔培养实施办法》 | 以称号/奖项（院士、国家最高科技奖等）界定高层次人才 | **中高**：`talent_flag.academician` 可对应「院士」一类 |
| 科技人才统计 | 科技部/地方科技统计年报惯用 | 按 R&D 人员全时当量、学历结构统计 | **低**：本库无 R&D 人员当量、无职称 |
| 学者计量（文献计量） | 学术惯例（ORCID/机构署名消歧） | 以唯一 ID 归并学者，按机构署名统计 | **中**：有 `scholar_id`，但属性表 ID 不连通 |

#### 1.4.1 五族方法谱系与本指标的落位（补强）

上表四行走的是「深圳本地政策 + 文献计量」两条线，还缺国际官方统计、国内科技统计与商业人才库三条线。把它们补齐后，才能判断「本指标的方法血缘到底是谁的」：

**五族的三个分歧点（对照分析）**：这张表如果只看「贴合度」，会误以为 E 最该选；真正的分歧在三个口径上，而它们决定了能不能相除：

| 分歧点 | A/B（官方统计） | C（政策认定） | D（文献计量） | E（商业库） | 本库现状 |
|---|---|---|---|---|---|
| 计量对象 | 人 / 全时当量（FTE） | 获认定的人 | 有发表记录的人 | 有职业档案的人 | 只有「人」，无 FTE、无认定、无档案 |
| 归属依据 | 单位上报 | 认定单位/推荐单位 | 论文机构署名 | 在职企业 | 机构名（`org_id` 全空） |
| 结构维度 | 学历 × 岗位 × 职称 | 称号层级 | 学历 + 学科 | 岗位 × 技能 × 职级 | 只有学历层次，无学科/岗位/职称 |
| 分母口径 | 区域从业人员 | 区域人才总量 | 学者库 | 平台注册用户 | 学者主档 21,316 |

**逐族落位**：

- **A 与 B 给出的是「人才」的官方定义，但都要求单位上报的岗位/当量数据**。本库没有这一类登记源，因此这两族只能用来**界定口径边界**，不能产出数字。
- **C 是唯一能落到「人」的官方口径**，但它的载体是称号名单；库内只有院士一列（112 人），且属性表无机构字段，无法落到深圳。它决定了结构维「称号层次」这一支的可行性上限。
- **D 是唯一能现算出数的族**：21,316 名学者、机构名 97.72% 非空，按名称匹配可出城市计数。但它的口径天然是「有发表记录的学者」，不等于产业研发人员。
- **E 才是需求语义最贴的族**（「在目标产业的企业研发人才」），但库内无源；它的缺席正是深圳被系统性低估的根因。

**由分歧点推出的三条「不可相除」禁令**：① **FTE 与 headcount 不可相加**——官方统计的「全时当量」与本库的「人数」是两种量纲，混加会同时重复计人与低估兼职；② **认定名单与学者库不可互作分母**——C 族的认定人群是政策选择的结果，不是随机样本，用它做分母等于把「获评率」说成「人才占比」；③ **平台用户数不可作区域人才总量**——E 族的注册用户含跨地域、非在职与重复账号，量级不可校准。本库唯一满足「同一总体」的一对是「深圳学者 ∩ 主档」与「学者主档 21,316」，这也是 §2.5 双基线唯一允许的除法。

**贴合度与可迁移性为什么必须分开看**：贴合度回答「这个方法是不是甲方想要的」，可迁移性回答「库里能不能跑」。五族里贴合度最高的是 E 与 A，可迁移性最高的是 D——两者不重合，正是本指标「判部分支持而不是完全转换支持」的方法论原因。若只看贴合度选型，会得到一个没有数据的完美方法；若只看可迁移性选型，会得到一个口径过窄但能跑的原型。本报告的选择是「用 D 出数、用 A/B/C 界定边界、用 E 命名缺口」。

**三句结论**：① **最贴需求的是 E（商业人才库）+ A（HRST 双路线），但两者在开发库都不可落地**；② 能落地的只有 D（学术文献计量），它给出的是「高校/院所学者口径」的数量与学历结构；③ 落地后差的是「企业研发人才」「岗位/技能维」「学科—产业链映射」三块，前两块靠采购，第三块靠甲方提供挂接表。

### 1.6 推测原意与推测定义（仿王惠口径写法）

**推测原意**：在指定产业链上，衡量「深圳在该链上拥有的研发人才规模，以及人才的学历层次」，用于判断该链在深圳是「有人才储备」还是「靠外部输入」，并与北京、上海对比找出差距。

**推测定义**（非正式甲方闭合口径，含 P4.3 约束）：

设深圳学者集合 $S_{SZ}=\{s: s.scholar\_org\_name\_zh \text{ 命中深圳机构名}\}$，主档 $S$（21,316）：

$$N_{SZ}=|S_{SZ}|,\qquad Share_{SZ}=\frac{N_{SZ}}{|S|}\times 100$$

结构维只在「同宇宙可交叉」的子集上计算：

$$PhD\%=\frac{|\{s\in S_{SZ}\cap E: degree=\text{博士}\}|}{|S_{SZ}\cap E|}\times 100$$

其中 $E$ 为教育表可交叉主档的学者集合（$|E|=1,853$），分母 $|S_{SZ}\cap E|=29$。**禁止**用 $27 / 251$ 或 $27 / 21{,}316$ 这类跨宇宙除法。

链切片：学者表无链字段，只能按机构所属学科/名称做关键词代理，本报告不输出链级人才数，只输出城市级与机构级。与王惠口径的差异见 §五。

## 二、计算过程

### 2.1 方法选择：先测 ID 连通性，再谈口径

人才类指标最常见的错误不是公式写错，而是**分子分母来自两个不连通的人宇宙**。BRIEF §3.4 与 SKILL P4.3 都把这列为强制检查项，原因是在本库上它确实发生了：身份主档 `dwd_scholar`（21,316 人）与人才属性表 `dwd_scholar_talent_flag`（20,030 人）**ID 交集只有 1,858 人（8.72%）**；教育表 `education_background`（20,025）与工作经历表（20,028）与属性表同源，同样与主档不对齐。

因此本报告的第一步不是算指标，而是**测交集**：`flag ∩ 主档 = 1,858`、`edu ∩ 主档 = 1,853`、`flag ∩ edu = 20,025`（后两者同源，几乎完全重合）。这三条数决定了后续所有比值的分母：

- 若算「深圳学者中有多少人拥有某类人才称号」，分母只能用 1,858 中属于深圳的那部分，不能用 251；
- 若算「深圳学者的学历结构」，分母只能用 29（深圳学者 ∩ 教育表），不能用 251；
- 若算「深圳学者占全国学者比例」，分母用 21,316（同为主档），这是唯一可以放心相除的一对。

### 2.2 步骤 1｜学者数量与机构归属（org_id 整列为空）

`dwd_scholar` 21,316 行，关键字段填充：`scholar_org_name_zh` **20,829（97.72%）**、`h_index` 20,914（98.11%）、**`scholar_org_id` 0（0.00%）**。第三项是全表最致命的空缺：calc-logic 期望用 `scholar_org_id` 关联 `dwd_org_heis_info.org_id` / `dwd_research_institute_base_info.org_id` 来取城市，但该列**整列为空**，关联路径直接断裂。

因此城市归属只能用**机构名称字符串匹配**。实测三种口径：按机构名匹配深圳 → **199 人**；按学者名（`scholar_name` 含「深圳」）→ 194 人；两者并集 → **251 人**。三种口径的差异说明名称匹配不稳定：机构名口径漏掉「在深圳工作但机构名不含深圳」的学者，学者名口径漏掉同名误判，并集又可能重复计入。

三种口径都保留在 `_out.json` 里，本报告**主口径取 199（机构名）**，理由是它最贴近「单位属地」这一语义；251 作为上界、194 作为下界，任何对外表述都应给出区间而不是单点。

城市对比（同口径）：广州 **863**、深圳 **199**、东莞 **10**。广州是深圳的 4.34 倍——这个反直觉的结果不是「广州人才强」，而是**学者库的机构构成偏斜**：广州集中了中山大学、华南理工、暨南大学等一批综合性高校，深圳的高校数量与体量都小得多，而深圳的研发主力在企业，企业研发人员不进学者库。这条偏差必须写进使用说明。

深圳机构 Top3：深圳大学 **88**、中国科学院深圳先进技术研究院 **35**、哈尔滨工业大学（深圳）**11**，三所合计 134 人，占深圳 199 人的 **67.34%**。集中度极高，说明「深圳人才数」实际上主要反映这三家机构的规模。

### 2.3 步骤 2｜人才属性宇宙与交集

`dwd_scholar_talent_flag` 20,030 行，字段 `academician` 取值为 1 的 **112 人**、为 0 的 **19,918 人**。这是本库唯一可直接使用的「人才称号」信号（院士）。

但该表与主档的交集只有 **1,858 人**：也就是说，20,030 个「有属性的人」里，只有 1,858 人能在身份主档中找到对应身份；反过来，主档 21,316 人里 **91.28% 没有任何人才属性记录**。这不是「大部分人不是人才」，而是**两套人才库没有打通**——属性表（20,030）、教育表（20,025）、工作经历表（20,028）三者行数高度接近，说明它们同源于另一套人才库，而不是主档的扩展表。

后果是：任何「深圳有多少院士」的问题在本库**无法回答**。院士 112 人分布在属性宇宙里，若要落到深圳，必须先确定这 112 人中有多少能与主档的深圳 199/251 人交叉——本报告未做该交叉（样本过小，且属性表无机构字段），按两跳止步规则记为缺口。

### 2.4 步骤 3｜学历结构（分母只有 29）

教育表 `degree_zh` 全库分布：博士 **13,763**、硕士 1,317、其他 417、学士 354（有学位记录者合计 15,851）。这是「属性宇宙」内部的学历结构，硕博合计 15,080，占比 **95.14%**——明显偏高，说明该人才库本身是**高层次人才库**，不是全员学者库。

限定到深圳（学者 ∩ 教育表）：**29 人**有学位记录。**按 `degree_zh` 单列读**是博士 27、学士 1、空 1（**27+1+1=29**，此前正文「27+1=28 与 29 差 1」的写法容易误读，实为三类相加恰为 29）。**但「学士 1」与「空 1」两例经复核都是 PhD**——`degree_zh` 为空而 `degree_en` 有值，中文列缺译导致漏判（详见下条口径说明）。按 **`degree_zh` + `degree_en` 双语回填**重算：**29 人全部为博士（100%）**。两个数字并列呈现：**93.10%（单语口径，偏低）/ 100%（双语口径）**。

> **学位判定必须双列合读（2026-10-21 主控复核新增）**。`dwd_scholar_education_background` 的中文列 `degree_zh` 与英文列 `degree_en` **并非互为镜像**：> 全表 43,766 行中，**`degree_zh` 为空但 `degree_en` 有值者 7,789 行（17.80%）**，反向（zh 有值、en 为空）仅 187 行。> 只看中文列会把近 1.8 成记录打成「未知」。深圳这两例即是典型：`4u1t6362` 写 `degree_zh=本科 / degree_en=Bachelor` 与 `degree_zh=直博 / degree_en=Doctor (Direct PhD)`；> `5s514Vu0` 三条 `degree_zh` 全空、`degree_en` 分别为 Bachelor / Joint-PhD / PhD。二者按人取最高学位都是**博士**。
>
> 全库按双语回填后的学位分布（行级）：博士 **17,484**、硕士 **9,665**、学士 **8,717**、其他 5,864、未知 **2,036**（合计 43,766）；> 对照单语 `degree_zh` 口径为博士 14,894 / 硕士 8,215 / 学士 7,516 / 其他 3,316 / 未知 9,825。**博士低估 2,590 条（−17.4%）、未知高估 7,789 条（+283%）**，> 博士占比由 34.0% 变为 **39.95%**。该差异只会强化「这是高层次人才库」的判断，故档位不受影响。

这个 93.10% **不能**表述为「深圳学者 93% 是博士」——按双语口径应为 100%，同样不能直接外推为「深圳学者都是博士」（29 人样本、且属属性宇宙）。原因有三：

1. 分母只有 29 人，占深圳学者 251 人的 **11.55%**，其余 88.45% 无教育记录，缺失极可能非随机（年轻学者、企业背景学者更可能没有学位记录）；
2. 29 人是从「属性宇宙 ∩ 主档 ∩ 深圳」三重过滤后的残余样本，选择偏差无法估计；
3. 93.10% 与属性宇宙整体的 95.14% 几乎一致，说明它反映的是**人才库的层次**，而不是深圳的特征。

因此本报告把学历结构定位为「**小样本参考值**」，在 §2.7 与 §四 双重标注，不进入综合评分。

### 2.5 步骤 4｜双基线披露（P4.3 强制）

按 BRIEF §3.4，人才域必须给出双基线，且禁止跨表除。本报告的两条同宇宙基线是：

| 基线 | 分子 | 分母 | 比值 | 语义 |
|---|---:|---:|---:|---|
| 主档口径 | 深圳 251（并集）/ 199（机构名） | 21,316 | **1.178%** / 0.933% | 深圳学者占全部学者主档的比例 |
| 教育宇宙口径 | 深圳 29（有学位记录） | 1,853（教育表 ∩ 主档） | **1.565%** | 在「可交叉教育记录」这一子宇宙内，深圳的占比 |

两条基线都满足「分子分母同一宇宙」，但含义不同：前者是「深圳在学者库中的分量」，后者是「深圳在有学历记录者中的分量」。二者不能相加、不能互相校验，只能并列披露。**唯一禁止的做法**是拿 27（深圳博士）除以 21,316（主档）或除以 251（深圳学者）——前者把分子缩小了 700 倍，后者把分母缩小了 8.7 倍，都会得到无意义的数。

### 2.6 步骤 5｜链切片为何不做

calc-logic 的源表字段里列了 `dwd_industry_chain_info` 与 `dwd_org_industry_tags`，意图是把学者按任职企业/机构挂到产业链上。实测这条路走不通：

- `dwd_scholar` 没有 `industry_code` / `chain_code` 字段；
- `scholar_org_id` 为空，无法与 `dwd_org_industry_tags.credit_code` 或机构表 `external_id` 连接；
- 学者机构以高校/院所为主，而 `dwd_org_industry_tags` 覆盖的是**企业**（2,283,762 行），两者主体类型不同；
- 唯一可用的弱信号是学者表里的院系/简介字段（填充 15,495 / 19,109），但那是自由文本，无法稳定映射到 15 条顶层链。

因此本报告**不输出链级人才数**，只输出城市级与机构级。这不是偷懒，而是遵守 P2.1：链归属是需求明列的依赖（「在目标产业」），已做一层拆解（院系/简介字段），拆解后发现无稳定映射，到此止步，记缺口，不再追「学者—链权威挂接表」（库中不存在）。

## 四、数据缺失情况

### 4.1 可构建但存在缺口（不是「无法构建」）

1. **两套学者 ID 不连通**（影响最大）。主档 21,316 与属性表 20,030 交集 1,858（8.72%），教育表 1,853。这使「深圳有多少院士」「深圳博士占比」这类问题在严格口径下**无法回答**。建议甲方提供 ID 映射表（可用姓名 + 机构 + 学科三元组做模糊匹配，再人工校验）。
2. **`scholar_org_id` 整列为空**。机构归属只能名称字符串匹配，三种口径差 57 人（194–251）。建议补 `org_id` 回填，这是成本最低、收益最大的一项修复。
3. **学历记录覆盖率低**。深圳 251 人中仅 29 人有教育记录（11.55%），结构结论不可外推。建议补采学位数据，或明确「结构维只作参考」。
4. **链归属无字段**。学者表无 `industry_code`，院系/简介为自由文本，无法稳定映射 15 链。建议甲方提供「学者—链」或「机构—链」挂接表。
5. **无北京/上海对比基础**。底册 99.82% 在广东，学者库以广东高校为主，省外样本不足，无法做需求要求的「与北京、上海对比」。

### 4.2 数据陷阱（本批实测，须写入任何下游复用说明）

- **`scholar_org_id` 全空但列存在**：`WHERE scholar_org_id IS NOT NULL` 返回 0 行；若脚本不检查填充率，会静默产出空结果。
- **20,030 不是「20,030 位有称号的学者」**：它是另一套人才库的人数，与主档仅 8.72% 重合；写「20,030 位学者中 X%」即为失真。
- **广州 863 vs 深圳 199 不能读作「广州人才更多」**：学者库偏高校，深圳研发主力在企业。
- **93.10% 博士占比来自 29 人**：小样本 + 选择偏差，不能对外称「深圳学者博士率 93%」。
- **院士 112 人不可落城市**：属性表无机构字段，与主档不连通。

### 4.3 缺口的后果归因（往哪偏、偏多少、能否交叉验证）

§4.1 说的是「缺什么」，这里说「缺了会把我误导到哪」。五条缺口逐项给方向、幅度与复核路径；凡无实测的幅度一律写「未取证，不得假设」。

1. **机构名匹配替代 `org_id` → 深圳数在 194–251 之间摆动，方向双向**。漏配发生在「在深圳工作但机构名不含深圳」的学者（如外地机构深圳分院、英文名机构），方向是**低估**；误配发生在人名/机构名恰含「深圳」但主体不在深圳的情况，方向是**高估**。幅度可定量：三种口径极差 **57 人**，相对区间 **22.7%–29.4%**（57/251 与 57/194），这个区间远大于任何统计噪声，因此对外只能给区间、不能给单点。
2. **ID 断裂（8.72%）→ 称号与学历维整体收窄**。1,858/21,316 的可交叉子集意味着「深圳有多少院士」严格口径下不可答；若强行按属性宇宙报数，方向是**高估深圳在全国称号人群中的占比**（因为分母被换成了 20,030）。幅度：交集率 8.72%，即 91.28% 的主档人口没有属性记录，**缺失极可能非随机**，偏向量级未取证。
3. **学历记录只覆盖 29 人 → 结构结论偏向高学历**。属性宇宙本身硕博占 95.14%（15,080/15,851），是「高层次人才库」而非全员库；把这 29 人的 93.10% 当深圳特征，方向是**系统性高估深圳学者的博士比例**。幅度：29/251=11.55% 的覆盖率，样本量不足以给置信区间，只能作参考值。
4. **链归属无字段 → 若用关键词硬挂，会向高校优势学科偏**。机构名关键词只能识别「大学/学院/研究院」，这些机构天然集中在基础学科；用它做链切片，方向是**高估与高校学科对应的链（如生物医药、材料）、低估企业主导的链（如智能终端、机器人）**。幅度不可估，因为库内没有任何链级人才真值可作分母。
5. **无北京/上海可比样本 → 对比维不是「有偏」而是「无定义」**。省外学者样本极少，任何「深圳 vs 北京」的比值都等于拿一个都市圈底册去比几个机构，方向无法先验判断。此项**未取证，不得假设**，只能标注「不可计算」。

**交叉验证路径与预期差异**：

| 复核路径 | 做法 | 预期结果 | 能验证什么 |
|---|---|---|---|
| 城市口径三法互校 | 机构名 199 / 学者名 194 / 并集 251 并列 | 极差 57 人，排序不变（深圳仍低于广州 863） | 验证「量级稳定、单点不稳」 |
| 与 `M_TALENT_BASE_98_1` 省域对账 | 该文 D1 覆盖 26 省、广东合计未单列 | 省域计数应 ≥ 城市计数之和 | 验证没有把城市当省域 |
| 与 `M_TALENT_DEEP_162_1` 深圳子榜对账 | 该文按机构名得 194 人 | 与本文 194 完全一致（同列同值） | 同源复核，**不构成独立验证** |
| 学历结构对属性宇宙 | 29 人 93.10% vs 属性宇宙 95.14% | 两者接近，说明反映的是库的层次而非深圳特征 | 验证「不能外推为深圳特征」 |

**一句话结论**：数量维的误差是「区间级」（±57 人），结构维的误差是「样本级」（n=29），链维的误差是「定义级」（无字段）。三者不能混为一谈：区间级可以用双基线披露，样本级只能加角标，定义级必须拒答。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

出处：`gkx-orchestration/agent-delivery/metrics/calc-logic/CHAIN/M_CHAIN_SZ_TALENT.md`（王惠调研结果规范化迁移）。

- 口径定义：「从人才数量与结构等维度评估深圳人才相对优势。」
- 计算逻辑：「人才数量、人才结构等维度加权评分。权重待甲方确认。」
- 数量维：**深圳市人才总量**，源字段 `dwd_scholar(scholar_id, scholar_org_name_zh)` + `dwd_org_heis_info(city)` + `dwd_research_institute_base_info(city)`。
- 结构维：**硕博人员占比**，源字段 `dwd_scholar_education_background(degree_zh, degree_en)`。
- 链范围：`dwd_industry_chain_info` + `dwd_org_industry_tags`（意图按链上企业挂学者）。
- 待建字段：「无」。

王惠口径的依赖集合为 {学者身份, 机构城市, 学历, 链归属}，与本报告新方法**完全同维**，差别在于新方法显式加入了 P4.3 的 ID 交集约束。

### 5.2 新方法概述

新方法（§二）保留王惠的两维，但做了三处强制约束：① 城市归属用机构名三种口径并列（199/194/251），不给单点；② 学历结构的分母限定为「深圳 ∩ 教育表」的 29 人，禁止跨宇宙除；③ 链切片因无字段直接不做，记缺口而不是用关键词硬挂。

### 5.3 逐维对照表

| 维度 | 王惠口径 | 新口径 | 数据支撑差异 | 可复现性差异 |
|---|---|---|---|---|
| 数量 | 深圳学者总量（`scholar_org_name_zh` + 机构表城市） | 同左，但输出 199/194/251 三口径 | 共用 `dwd_scholar`；机构表 JOIN 因 `org_id` 空失效 | 王惠 JOIN 路径**断裂**；新口径用名称匹配可跑 |
| 结构 | 硕博占比（教育表 degree） | 博士占比，分母限 29 | 王惠若用 251 或 21,316 作分母 → 跨宇宙 | 王惠口径**不可复现**（分母无定义）；新口径可复现但 n=29 |
| 城市 | 机构表 `city` | 机构名匹配深圳（三种口径） | 机构表有 city，但无 ID 可连 | 新口径可跑，误差 57 人 |
| 链归属 | `dwd_industry_chain_info` + tags | 不做（无字段） | 学者表无 `industry_code` | 两者都不可行 |
| 权重 | 待甲方确认 | 不做综合分 | 无差异 | 均待确认 |

### 5.4 选用建议与理由

**建议采用「王惠维度骨架 + P4.3 约束」的混合口径**，公式定义人记「仿王惠 ai-1020」。理由逐条对应判定规则：

1. 王惠口径的维度集合（数量 + 结构）**语义正确**，新方法完全沿用，没有另起一套；差异只在「分母如何取」这一执行细节。
2. 但王惠口径**按字面无法复现**：机构表 JOIN 依赖 `scholar_org_id`（0 填充），硕博占比的分母未定义（若用主档即跨宇宙）。按规则第 2 条「当前库表同样可复现」，不满足，因此不能直接记「王惠」。
3. 新方法的三处约束都是**数据现实逼出来的**，不是方法偏好：ID 断裂是实测 8.72%，org_id 空是实测 0 填充，链字段缺失是表结构事实。因此属于「尊重原意的最小改造」。

**待甲方裁决点**：① 是否提供学者 ID 映射表（决定能否做称号/学历的严格口径）；② 是否回填 `scholar_org_id`（决定城市归属能否从名称匹配升级为键连接）；③ 是否接受「本指标只覆盖高校/院所人才，不含企业研发人员」这一范围声明。

#### C.3.1 逐族的数据要求、计算步骤与局限（补厚）

- **M1 人才分层政策口径**：数据要求是「称号/项目认定名单 + 分层规则」；计算步骤是「按认定层级归类 → 按地区计数 → 与总量比值」；局限是名单不公开、层级之间不互斥，且只覆盖获认定者（selection bias 极强）。**为什么不能照搬**：库内只有院士一列，没有「杰出人才/基础研究人才/核心技术人才」的认定字段，照搬只能造层级。
- **M2 杰出人才认定**：数据要求是「院士/国家大奖获得者名单 + 任职单位」；计算步骤是「名单匹配 → 去重 → 按城市归属」；局限是名单更新滞后、同名难消歧。**为什么不能照搬**：属性宇宙 112 名院士无机构字段，与主档只有 8.72% 交集，落不到深圳。
- **M3 科技人才统计（R&D 人员当量）**：数据要求是「单位上报的 R&D 人员数、全时当量、学历结构」；计算步骤是「单位汇总 → 按地区/行业归集 → 换算 FTE」；局限是依赖统计年报制度、口径随制度调整。**为什么不能照搬**：库内没有任何单位上报面，连近似字段都没有。
- **M4 学者计量（ID + 机构署名）**：数据要求是「唯一学者 ID、机构署名、学历」；计算步骤是「ID 归并 → 机构归属 → 分组计数」；局限是只覆盖有发表记录者、机构名需消歧、跨库 ID 不通用。**为什么不能照搬**：ID 有（`scholar_id`）但 `scholar_org_id` 全空、属性表不连通，只能降级为名称匹配。
- **M5 国际官方 HRST（补充族，Canberra Manual）**：数据要求是「学历资格 + 职业岗位」双字段，或单位上报的 S&T 人员；计算步骤是「两路线识别 → 去重并集 → 存量/流量分开报告」；局限是分类体系完备性要求高、非正规就业难归入 (OECD, 1995)。**为什么不能照搬**：本库只有学历层次（无学科）与「学者」这一职业子集（无岗位类别），两条路线都缺字段；若强行并集，会把 43,766 条学历行与 21,316 人相加，重复计人。

#### C.3.2 逐族「为什么不能直接照搬」的横向比较

| 方法族 | 与本指标语义距离 | 照搬后的直接后果 | 本报告处置 |
|---|---|---|---|
| M1 政策分层 | 中（分层语义对得上） | 会造出库内不存在的「杰出/领军/青年」层级 | 只借分层思想，不造层级 |
| M2 杰出人才认定 | 中高（院士可对应） | 会把 112 名院士当成可落深圳的数 | 记缺口，不用称号包装 |
| M3 R&D 人员当量 | 高（就是「人才总量」） | 无源，硬做只能拿学者数冒充 | 拒绝代理，明确不可算 |
| M4 学者计量 | 中高（唯一有明细） | 会把「学者数」当「产业人才数」 | 采用但限定口径与区间 |
| M5 HRST | 高（国际母定义） | 两路线并集会重复计人 | 作口径校验尺，不入算 |

读法：**方法越贴需求，数据越缺**——M3/M5 语义最正但零字段，M4 唯一能跑却口径最窄。这不是选型失败，而是本库人才数据的结构性事实；因此本指标的合理定位是「学者口径的深圳人才参考值」，而不是「深圳产业人才总量」。

### C.5 推荐构建方案（工程可执行）

1. 先做 ID 对齐：以「姓名 + 机构 + 学科」三元组对 21,316 与 20,030 做候选匹配，人工校验 Top 机构，目标把交集从 8.72% 提到 60% 以上。
2. 回填 `scholar_org_id`：用机构名精确/模糊匹配 `dwd_org_heis_info` 与 `dwd_research_institute_base_info`，落 `org_id` 与 `city`。
3. 指标层落三列：`scholar_n`（数量）、`phd_ratio`（仅在有教育记录的子集）、`edu_coverage`（覆盖率，必须与比值同时展示）。
4. 展示层：数量给区间（199–251），结构给「n=29」的角标，链级留空并标注「无数据」。
5. 若要覆盖企业研发人才，需引入招聘/专利发明人数据，属另一个指标（不在本指标范围）。

### C.6 风险与残余不确定性

- **范围风险**：只覆盖高校/院所，企业研发人才缺失，深圳被系统性低估。
- **ID 风险**：8.72% 交集使称号类结论不可靠。
- **样本风险**：29 人的学历结构，置信区间极宽。
- **匹配风险**：机构名三种口径差 57 人，跨城市比较对匹配规则敏感。

### C.7 可行性总判（完整版结论）

数量维可算（199–251，占主档 0.93%–1.18%），结构维只能在小样本（29 人）上给出参考值，链级不可做，称号不可落城市。综合判**部分支持**。

**升级路径的三档拆解（2026-10-21 主控修正）**。原稿写「若甲方回填 `org_id` 并对齐两套 ID，可升入完全转换支持」，这个说法**过度乐观，已收回**。逐条对需求核：① `org_id` 回填 + ID 对齐只解决「人→机构→城市」的归属精度，属**必要非充分**条件；② 需求明列「**目标产业**」的链切片，而 `dwd_scholar` 全表无任何链字段（无 `chain_code`/`chain_name`/`node_id`），链归属需另建「学者→企业→链」映射，库内无此路径；③ 需求含企业研发人才，库内人才主体是学者库，企业侧仅有 `rd_staff_count`/`rd_staff_ratio` 两个计数列、无个体记录，**永远无法补出个体层**。故正确的分档表述是：

| 补数动作 | 可解锁 | 不能解锁 | 判档 |
|---|---|---|---|
| 仅回填 `org_id` + 对齐两套 ID | 城市归属精度、跨城市可比性 | 链归属、企业人才、称号 | **仍部分支持** |
| 上述 + 建「学者→企业→链」映射 | 链级人才数量的**代理口径**（非真链归属） | 企业人才个体、称号城市落位 | 可议「部分支持（上沿）」 |
| 上述 + 接入企业人才库（个体级） | 需求四要素齐 | — | 才具备升「完全转换支持」的条件 |

一句话：**单靠 ID 对齐不足以升档**，第三行的企业人才个体源才是决定项。

### C.8 对甲方四问的逐条回答

**① 这个指标现在能不能出数？** 能出「数量」：按机构名匹配深圳 199 人、按学者名 194 人、并集 251 人，占主档 1.178%；同口径广州 863、东莞 10，机构 Top3（深大 88、中科院深圳先进院 35、哈工大深圳 11）可复核。结构维只能出参考值：深圳 ∩ 教育表 29 人，其中博士 27、学士 1、学位为空 1。

**② 出的是不是甲方要的那个东西？** 不是完整版。需求要的是「目标产业链上的深圳人才 + 与北京上海对比」；现在出的是「深圳高校/院所学者（无链切片）+ 与广州东莞的同省对照」。企业研发人才（深圳的研发主力）不可见，链归属无字段，北京/上海样本不足——三条都不满足。

**③ 要补齐还差什么、谁能给？** 四件：`scholar_org_id` 回填（甲方/ETL，成本最低）；两套学者 ID 映射表（甲方提供或按姓名+机构+学科匹配后人工校验）；「学者—链」或「机构—链」挂接表（甲方业务方）；企业研发人才与岗位数据（商业人才库采购）。前两件能把数量从「名称匹配」升级为「键连接」，后两件决定链级与产业口径能否成立。

**④ 补不齐的话，替代口径是什么、还叫不叫这个名字？** 替代口径是「深圳高校与科研机构学者参考值」，数量给 199–251 区间、结构加 n=29 角标、对比只做广州/东莞。名字建议改为「深圳学者人才维度（高校院所口径）」；若甲方坚持叫「深圳产业人才总量」并要求链级数，则本指标**不具备验收条件**，应按验收口径重新定档，而不是用名称匹配的数硬撑。
