## 摘要

本件把 `TYPE_COUNT` 的「6/6」拆开，回答「这 6 类各有多少家」。粒度是 `(chain_code, node_stage, tag_code)`：12 条链 × 3 个链位 × 6 类 = **216** 个理论组合，其中 **180** 个非零（**83.3333%**）、**36** 个零（**16.6667%**）。格级（把六个类的家数相加）合计 **14,308** 人次；按 5,196 条成员行摊，平均每条成员行带 **2.7537** 类。

头部位是「具身智能·上游·高新」：**568 家 / 640 家 = 88.75%**。第二位「机器人·上游·高新」480/534 = 89.8876%——家数少但占比更高。第三位「软件与信息服务·下游·高新」446/545 = 81.8349%。前 15 行里 7 行是高新、6 行是专精特新、2 行是小微，说明**高新与专精特新是这份名单的两根主梁**。

六类在全国名单上的家数：高新 **2,801**（61.412%）、专精特新 **2,059**（45.1436%）、小微代理 **1,611**（35.3212%）、小巨人 **868**（19.0309%）、上市 **772**（16.9261%）、外资 **472**（10.3486%）。六类合计 8,583，去重并集 2,981，重叠倍率 **2.8792**（`derived.tag_per_union_firm`）。重叠倍率是理解本件的钥匙：一家企业平均带近三类资质，所以「每类家数」之间不是互斥的，堆叠条的六段之和会大于企业总数。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

重点企业全景页（E-33）的**资质构成**模块。选中一条链、一个链位后，页面右侧出现一条六段堆叠条（外资 / 高新 / 小微 / 上市 / 专精特新 / 小巨人），每段长度是该类家数；下方表格逐类列出家数、格内占比、代表企业。不选链位时，堆叠条退化到链级（三格合并）。

本件与 `TYPE_COUNT` 是同一批成员行的「展开 / 折叠」关系：那件把六类压成一个 0—6 的标量，本件保留六个分量。前端两个组件读同一个 `_out.json` 的不同段，不允许各算一套。

### 1.2 为什么需要这个指标

第一，**覆盖数饱和后必须看结构**。31 个非空格里 28 格是 6/6，覆盖数没有区分度；同样是 6/6，具身智能上游的高新占 88.75%，低空经济下游的高新只占 50%。结构才是链位之间的差异所在。

第二，**它是招商补位的直接依据**。「这格缺外资」与「这格外资只有 1 家」是两种不同的缺口，前者要引进来，后者要扩存量。只有每类家数能区分。

第三，**它支撑「资质重叠」的解释**。六类不独立：小巨人 868 家全部同时是高新（Jaccard 0.3099），专精特新与高新的交集 2,048 家（Jaccard 0.7283）。不理解重叠，就会把六段之和当成企业总数，得出「资质企业比名单还多」的荒谬结论。

### 1.3 需求文档是否给出定义方法

**给了分组键与六类码，没给名单、字典、链位。** calc-logic 原文的分组是 `(chain_code, node_stage, tag_code)`，值是 `COUNT(DISTINCT org_id)`，六类码与 `TYPE_COUNT` 完全一致，禁止项也一致（禁 `honor_type`、禁把类型分布当匹配数、只国内）。

需求还附带一条容易被忽略的约束：**类型分布之和 ≠ 匹配企业数**。这条不是建议，是硬约束；本件的 `tag_sum` 与 `chain_firm_n` 并列展示时必须带「人次 / 家」两个单位。

### 1.6 本报告的口径与边界（须与甲方会签）

第 $c$ 条链、第 $s$ 个链位、第 $\tau$ 类资质的家数：

$$N_{c,s,\tau}=\left|\{\,i\in R:\ i\ \text{上链}\ c,\ \text{链位含}\ s,\ i\ \text{带标签}\ \tau\,\}\right|$$

格内占比：

$$p_{c,s,\tau}=\frac{N_{c,s,\tau}}{F_{c,s}},\qquad F_{c,s}=\left|\{\,i\in R:\ i\ \text{上链}\ c,\ \text{链位含}\ s\,\}\right|$$

重叠倍率（链级）：

$$\rho_c=\frac{\sum_{\tau}N_{c,\cdot,\tau}}{\left|\bigcup_{\tau}\{i:\ i\ \text{上链}\ c,\ i\ \text{带}\ \tau\}\right|}$$

**四条边界**：

1. **六段之和不是企业数。** $\sum_\tau N_{c,s,\tau}$ 是人次；一企可进多类，$\rho$ 平均 2.88。
2. **格内占比的分母是格内企业数，不是 4,561。** $F_{c,s}$ 从 2 到 640 不等，用 4,561 会把占比压成 0.1% 量级。
3. **零值分两类。** 整格 0 家（30 行）与小样本 0 家（6 行）成因不同，前端文案不应都写「暂无数据」。
4. **链级含无链位企业。** 链级 `tag_sum` 14,630 略高于格级 14,308，差额 322 来自 186 家只有链根、没有链位码的企业。

## 二、计算过程

### 2.1 从 36 格到 216 行

`TYPE_COUNT` 的产物是 36 个格子；本件在每个格子里再按六类展开，得到 216 行。实现上不是重新查库，而是复用同一份 `keypano_base` 快照：每家企业有六个布尔位（`foreign` / `high_tech` / `sme` / `listed` / `little_giant` / `little_giant_pro`），按 `(chain, stage)` 分组后对每个布尔位求和。

这个设计保证了两个件永远同源：`TYPE_COUNT` 的 `tag_counts` 与本件的六行是同一组数，只是排布不同。任何一件改口径，另一件必须同步重跑。

- 格级只统计 2,105 家有链位码的企业；
- 链级把 2,291 家有链标签的企业全部纳入，其中 186 家只有链根、没有一级环节码。

这 186 家贡献 322 人次，平均每家 1.73 类。差额虽小，但说明**链级视图与格级视图的母体不同**；页面在链级与格级之间切换时，数字会跳，必须给口径提示。

## 四、数据缺失情况

### 4.1 缺口的后果归因

**缺口一：名单。** `key_enterprise` gkx 无表，live DWD 无表，ADS 87 行演示。后果：企业数、占比都带代理前缀。

**缺口二：字典。** `tag_dict` gkx 无表、live DWD 0 行。后果：六类码是 55 个中文标签的归并，`foreign` / `listed` 是代理列。

**缺口三：链位。** `node_stage` 不是库内字段，41 个一级环节的映射由本件自建。

**缺口四：30 行整格零值。** 4 条链没有下游环节，补企业补不出来，只能补目录。

**缺口五：6 行小样本零值。** 低空经济上游（5 家）、低空经济下游（2 家）、数字创意下游（4 家）各缺 1—3 类。这些格对单个企业极敏感，任何名单变动都会翻红或翻绿。

### 4.2 数据陷阱（本批实测）

**陷阱一：把六段之和当企业数。** 机器人上游 1,346 人次 vs 534 家，差 2.52 倍。

**陷阱二：用 4,561 做格内占比分母。** 具身智能上游高新 568/4,561 = 12.45%（`derived.counterexample_max_row_over_roster_pct`），与真实格内占比 88.75% 差 7 倍。

**陷阱三：把「小巨人全部是高企」当巧合。** 这是认定链条决定的：小巨人申报前置条件含高企。解读时不能把它当独立发现。

**陷阱四：把链级与格级混着比。** 链级 14,630、格级 14,308，差 322，母体不同。

**陷阱五：把 36 个零行都标「暂无数据」。** 30 行是「无企业」，6 行是「有企业但无该类」，文案应不同。

### 4.3 可构建但存在缺口（不是「无法构建」）

若只要求「按链×链位统计每类资质家数」，一条 `GROUP BY` 即可，数据量足，属完全转换支持。加上「重点名单」「`tag_code` 字典」「链位」后判部分支持。

### 4.4 若甲方补齐后的口径升级路径

补名单 → 补字典 → 补链位 → 物化 `enterprise_keypano_chain_node_type(chain_code, node_stage, tag_code, ent_count, share)` 216 行。四步完成后可升为完全转换支持；否则本件长期停留在「可算但带三个代理」。

## 五、结论与发布建议

### 5.1 结论

**结构比覆盖数有信息量，但仍受名单与字典限制。** 216 行里 180 行非零，头部集中在高新与专精特新；外资是最独立的一维，也是最能区分链位的维度。

**三类零值要分开运营。** 整格空的 5 个格是目录问题；小样本零值的 3 个格是招商问题；六类重叠导致的「看似很多、实际集中」是解读问题。

### 5.2 与王惠 V3-2 的对照

王惠 V3-2 无 `M_ENT_KEYPANO_TYPE_STRUCTURE` 正本；本件只有 calc-logic（COVER-STAT-L01）。因此没有同 ID 对照，只有「类型数」与「类型分布」的父子关系可核。

| 维度 | 王惠 V3-2 | 本版 | 说明 |
|---|---|---|---|
| 正本 | 无 | calc-logic 有 | 无同 ID 对照 |
| 粒度 | —— | 三元组 216 行 | 比 TYPE_COUNT 细 |
| 六类 | —— | 55 标签归并 | 字典缺失 |
| 交叉验证 | —— | QUAL 72 对 0 不一致 | 链级一致 |

### 5.3 选用建议与理由

**建议采用 216 行结构，页面只展示「格内占比」不展示「全局占比」。** 格内占比的分母是格内企业数（2—640），全局占比的分母是 4,561；后者会把所有格子压成个位数百分比，失去比较意义。

**建议把外资单独做成一条趋势线。** 外资与其余五类的 Jaccard 都低于 0.12，是唯一不随高新走的维度；它在链位间的波动最能说明「这条链开不开放」。
