## 摘要

「政策与条件保障力综合评估」是政策与条件保障力指标展示下的综合件（§1.1.1.1.4.1.7.4.6），产品任务是把同一模块内「发展战略引导力、政策扶持力度、经费支持、项目支持、政策实施效果」五项分指标合成**一个可加权、可排名**的综合得分，权重由用户自定义。需求原文明确了「可自定义权重 + 综合得分 + 排名」三项产品要求，但未给默认权重、无量纲化规则、无阈值。

本报告按王惠五维口径复现：在 `gkx.dwd_policy_base` 20,000 条有效政策上，引导力维 2.71（继承 001 实测）、级别覆盖维 3/4=0.75（国家级/省级/市级有值、区县级缺失）、可见度维 20,000/20,000=100%，经费与项目两维无台账、时效性维因双日期空壳不可算；按等权合成得 **59.24 分**。out.json 原记录的 148.67 分系 0–100 与 0–1 两种刻度混用平均所致，本报告已按统一刻度重算并在产物中留下 `correction` 块留痕。

必须同时报告一个比分数更关键的诊断：三个可算维中**可见度维恒为 100%**（`link` 全表非空），**引导力维仅 2.71**，综合分几乎完全由级别覆盖一维决定——也就是说，现有字段下的综合得分**不具排名区分力**，与需求「提供综合评估结果和排名」存在实质差距。结论：**部分支持**；口径采用王惠（维度集合未变），但需向甲方明确「当前分数不可用于排名」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

本指标挂接《科技信息展示系统和科技专题服务系统》**科技创新评估 → 政策与条件保障力指标展示 → 政策与条件保障力综合评估**（§1.1.1.1.4.1.7.4.6）。上位模块的建设目标是「通过收集和分析发展战略的引导力、政策扶持力度以及经费与项目支持力度等关键指标，构建政策与条件保障力评估体系」，其服务对象是需要判断「某产业领域的政策环境好不好」的决策者。

本指标的产品形态是一个**可配权的综合评分页**：用户在页面上看到五项分指标的当前值（引导力、扶持力度、经费支持、项目支持、实施效果），可拖动权重或输入权重，系统即时给出综合得分与区域/领域排名，并支持下钻到分项。它是同模块七项功能中唯一的「合成件」，其余六项是它的输入或输出（输入：引导力、扶持力度、经费、项目、实施效果；输出：政策优化建议）。

### 1.2 为什么需要本指标

五项分指标各自回答一个局部问题：引导力问「规划写得好不好」，扶持力度问「政策发得多不多、层级全不全」，经费与项目问「钱和项目投了多少」，实施效果问「政策还在不在有效期、能不能找到原文」。但决策者面对的从来不是单维问题——「这个领域的政策保障够不够」是一个多目标判断，必须先把五维压成一个可比数，才能排名、才能跨领域比较、才能进考核。

更重要的是，需求明确要求「用户可自定义指标权重」。这不是界面装饰，而是承认**权重本身是价值判断**：产业部门可能更看重经费与项目（真金白银），科技部门可能更看重引导力（顶层设计），园区可能更看重实施效果（政策是否可及）。综合评估的技术任务不是替用户决定权重，而是提供一个**权重可变、分项透明、结果可解释**的合成框架。这也是本指标与 001（单维评分）的根本区别：001 输出一个维度的分数，008 输出一个可配置的评价系统。

### 1.3 需求文档是否给出定义方法

**需求文档给出了五维构成与「自定义权重」的产品要求，但没有给出计算方法。** 原文只写到「将政策与条件保障力的各项指标进行综合展示，用户可自定义指标权重，系统根据权重计算综合得分，提供政策与条件保障力的综合评估结果和排名」，未给默认权重、归一化方法、缺维处理规则与阈值。

- 《科技信息展示系统和科技专题服务系统.md》：指标名出现于 §1.1.1.1.4.1.7.4.6，同模块 §1.1.1.1.4.1.7.4.2–.5 分别定义扶持力度、经费支持、项目支持、实施效果四项分指标，**均无公式**。

### 1.6 推测原意与推测定义

**推测原意**：编写人要的是一块「政策保障力仪表盘」——五维各有一个读数，用户按自己的价值取向配权，得到一个可排名、可对外解释的综合分。它服务的场景不是单次分析，而是**周期性比较**（哪个区、哪个产业的保障力在改善）。

## 二、计算过程

> **口径说明**：本报告以王惠五维口径为主轨（理由见 §五），脚本 `code/M_POLICY_DS_07_POLICY_GUARD_008.py` 于 2026-10-21 跑通，结果见 `M_POLICY_DS_07_POLICY_GUARD_008_out.json`（含 `correction` 刻度纠偏块）。文内 (Author) 与文末参考文献对应；计数均在清洗字面 `'NULL'` 与 `0000-00-00` 占位后取得。

### 2.1 方法选择：为何是「归一 + 加权」而不是「原始计数并列」

综合评估最朴素的做法是把五项原始值直接相加或并列展示——政策数、级别数、经费额、项目数、链接率放在一张看板上。但量纲完全不同：政策数是万级，级别数是 1–4，链接率是 0–1，经费是亿元。直接相加在数学上无意义，在解释上会得出「政策数量决定一切」的荒谬结论。因此必须先归一。

归一之后是加权。加权综合指数的历史很长，国际组织与国内财政绩效评价都采用「分维指标 + 权重 + 合成」的三段式：财政部《项目支出绩效评价管理办法》就规定一级指标权重原则上为「预算执行率 10%、产出指标 50%、效益指标 30%、服务对象满意度 10%」，并明确「评价结果采取评分和评级相结合」(财政部, 2020)。这说明加权合成不是学术发明，而是中国公共部门绩效评价的标准工艺；差别只在于本指标把权重交给用户。

至于每维的测量口径，经费支持维有成熟的国际标准：OECD《Frascati Manual 2015》专设「Government budget allocations for R&D（GBARD）」一章，用政府研发预算拨款度量公共部门对研发的经费保障 (OECD, 2015)；中国对应的官方口径是国家统计局、科技部、财政部联合发布的《全国科技经费投入统计公报》，其「国家财政科学技术支出」2023 年为 11,995.8 亿元 (国家统计局等, 2023)。这两个口径共同说明：经费保障必须用**预算/支出类台账**度量，而不是用政策文本里的金额词频代理——这也正是本维当前无法计算的根因（库内无台账）。

### 2.2 步骤 1｜入集与字段可用性盘点

入集沿用王惠规则：`dwd_policy_base` 取 `status='有效'`、按 `id` 去重、仅国内（QPOL-05）。实测 N=20,000，`status` 为单值「有效」，故「有效政策占比」在全库口径下恒为 100%（这一事实在 §2.6 会直接导致一个恒值维，需提前注意）。

字段可用性盘点必须在清洗后做。该表大量字段的名义非空率为 100%，实为字面 `'NULL'` 或 `'0000-00-00'` 占位。本指标用到的字段实测真实值如下：

| 字段 | 名义非空 | 清洗后真实值 | 服务维度 | 判定 |
|---|---:|---:|---|---|
| `rank`（政策级别） | 20,000 | **20,000** | D2b | 可用 |
| `type`（政策类型） | 20,000 | 18,138（90.69%） | 需求要求但王惠未用 | 可用（增强项） |
| `publish_year` | 20,000 | 19,997 | D2a 筛选 | 可用 |
| `link` | 20,000 | **20,000** | D5b | 可用但**恒值** |
| `implementation_date` | 20,000 | **0** | D5a | 不可用 |
| `expire_date` | 20,000 | **0** | D5a | 不可用 |

这张表已经预告了本指标的结局：五维里能算的三维（引导力、级别覆盖、可见度）中，两个是「常数型」——可见度 100%、引导力极低且由 001 继承，真正带信息的只有级别覆盖。这不是脚本的错，是字段的现状。

### 2.3 步骤 2｜引导力维（D1）：跨指标继承与一致性约束

引导力维不重算，直接读 `M_POLICY_DS_07_POLICY_GUARD_001` 的结果（2.71）。这是王惠口径的明确要求，也是综合指数设计的常见做法：分项指标各自维护一份口径，综合层只做引用，避免同一概念在两处算出不同数。

这样做的好处是可审计——若甲方质疑「为什么引导力这么低」，答案可以直接追到 001 的三维明细（前瞻 5.42%、承接 0.01%、扶持缺失）。风险是**误差传递**：001 的字段空壳问题（`quote_policy` 仅 2 行、`policy_support` 0 行）会原样进入综合分，且因 001 的分数极低（2.71/100），它在等权平均中几乎等同于「一票否决」——五维变四维后，一个 2.71 分的维度会把总分拉低约 24 个百分点（0.0271 与其余维均值之差 ÷ 3）。

因此本维的正确用法是**加权而非等权**：若用户把引导力权重设为 0.1，其对总分的影响约 0.27 分，可接受；若等权 0.2，则影响 0.54 分且被字段空壳放大。这一点在 §四建议中提出，供权重裁决参考。

### 2.4 步骤 3｜扶持力度维（D2）：数量密度与级别覆盖

需求把扶持力度表述为「政策数量、政策类型、政策覆盖面」，并要「评估扶持的广度和深度」。王惠把它拆成两个子项：政策数量密度（组级基数，直接取符合条件的政策总数）与政策级别覆盖度（级别去重数 ÷ 4）。前者度量「广度」，后者度量「层级完整性」——一个领域如果只有市级文件、没有国家和省级依据，其政策体系的纵深是可疑的，这正是覆盖度想捕捉的东西。

$$S_{D2b}=\frac{\bigl|\{\text{rank}\ \text{去重}\}\cap\{\text{国家级},\text{省级},\text{市级},\text{区县级}\}\bigr|}{4}$$

实测 `rank` 真实值 20,000 全部可读，去重后命中**国家级、省级、市级**三类，缺**区县级** → $S_{D2b}=3/4=0.75$。政策数量密度为 N=20,000（组级基数，不是比率，故不进入平均，只作分子/基数展示）。

这里有一个需要向甲方说清的口径问题：20,000 是**全库**政策数，不是某个领域的政策数。需求要求的是「特定领域」的扶持力度，而库内缺产业标签，因此当前 20,000 只能作为「全域基数」展示，不能解释为某产业的政策密度。级别覆盖同理——3/4 是全库的层级结构，不是某领域的。这两项在接入产业锚定表之前，只能作**库级描述**，不能作领域评价，§四已列为缺口。

### 2.5 步骤 4｜经费与项目维：为何必须「缺维」而不是「记 0」

经费支持与项目支持是五维中最「实」的两维，也是需求着墨最多的两维（§1.1.1.1.4.1.7.4.3 与 .4 各自成节，要求按来源、方向、时间多维查看，并给出饼图/柱状图）。王惠口径对这两维的处理是「待建直读」——`rd_fund_amount`（科研经费/产业基金/补贴台账）与 `project_grant_amount`（科技项目资助金额）在两侧库内均无表无字段。

按王惠合成规则，无台账则**缺维、不补 0、不进平均**。这个处理在评估方法论上是正确的：把「没有数据」记成「零投入」，等于用缺失惩罚被评对象，会系统性低估所有领域，并使排名失去意义。财政部绩效评价办法也强调指标应「数据可采集、可获得」(财政部, 2020)，即不可采集的指标不应强行入分。

但缺维的代价必须讲清：五维去两维后只剩三维，而三维中还有一维恒值（见 §2.6），综合分的实际信息量进一步压缩。这就是本指标「能算但不能排名」的技术根源。真正的解法不是改公式，而是建台账——`rd_fund_amount` 可以从财政预算公开、科技经费统计公报、产业基金备案信息采集；`project_grant_amount` 可从科技计划项目库采集。两者都是**可获取的公开数据**，属工程投入问题。

### 2.6 步骤 5｜实施效果维：时效性空壳与可见度恒值的双重退化

需求把实施效果表述为「基于政策实施后的数据变化，评估政策的实际效果」，并要「查看政策实施前后的关键指标对比」——这是一个准实验设计的语义（政策前后对比）。但王惠口径把它降级为两个可算代理：实施时效性（统计日是否落在实施日与失效日之间）与政策可见度（`link` 非空率）。这是务实的妥协：真正的因果评估需要企业/产业面板数据，库内没有。

两个代理的实测结果都不理想。时效性需要 `implementation_date` 与 `expire_date` 同时有效，而两列真实值均为 **0**（全为 `0000-00-00` 占位），故命中 0 条、该子项记缺失而非 0。可见度则为 20,000/20,000=**100%**，`link` 全表为真实 URL（已用 `GROUP BY` 复验无 `'NULL'` 占位组）。

可见度 100% 在评估上是一个**恒值维**：所有对象同分，不提供任何区分信息。它在数学上合法（`link` 确实全部非空），在信息论上无价值。这也解释了为什么综合分 59.24 看起来「中等偏上」，实际上几乎完全由级别覆盖 0.75 决定——把恒值维剔除后，真实有区分度的只有 0.75 与 0.0271 两个数。

政府信息公开的制度视角可以解释为什么 link 会满值：按《政府信息公开条例》，政府信息「以主动公开和依申请公开的方式」公开，且公开工作机构负责「维护和更新本行政机关公开的政府信息」(国务院, 2019)。政策文件属主动公开范畴，链接齐备是合规的常态；反过来说，**链接齐备不能证明政策可及**——它只证明发布渠道存在，不证明内容可检索、可理解。因此本维若保留，应改为「链接有效性（可访问性）抽检」而非「非空率」。

#### 2.7.3 结果解读

第一，**分数必须纠偏后才能用**。148.67 超出 0–100 定义域，是刻度混用的直接后果；重算 59.24 才是可解释的综合分。本报告选择保留原始字段、新增 `correction` 记录，而不是覆盖原值，以保证任何第三方都能复核这次纠偏。

第二，**59.24 不可读作「保障力中等」**。它由 0.0271、0.75、1.00 三个数平均而来，其中 1.00 是恒值、0.0271 来自字段空壳的 001。把它当作「59 分、刚过及格线」会得出完全错误的政策结论。正确读法是：现有字段下，该指标只能反映「政策层级覆盖 75%」这一条信息。

第三，**排名功能不成立**。需求要求「综合评估结果和排名」，但排名需要对象间有差异。当前若按领域/区域分组，可见度全为 1、引导力由同一 001 分数继承、级别覆盖在全库层面是同一个 3/4——组间几乎无差异，排名会是噪声。这是本指标最需要向甲方披露的一条。

第四，**缺维处理正确但信息量代价大**。经费与项目两维记缺失符合评估伦理，但使三维承担了五维的职能；在台账建成之前，建议产品侧只展示分项读数、暂不展示综合排名。

## 四、数据缺失情况

1. **经费台账缺失（最高优先）**：`rd_fund_amount` 无表。建议接财政预算公开数据、科技经费统计公报、政府投资基金备案信息，按「领域—年度—来源」建维。
2. **项目台账缺失（次高）**：`project_grant_amount` 无表。建议接科技计划项目库（国家重点研发计划、省市科技计划）的立项与资助金额。
3. **双日期空壳**：`implementation_date`/`expire_date` 真实值 0，时效性维不可算。建议 ETL 从正文抽取「自 X 年 X 月 X 日起施行」「有效期至 X 年 X 月 X 日」并回填日期列。
4. **可见度维恒值**：`link` 100% 非空使该维无区分度。建议改为链接有效性抽检（HTTP 可达 + 正文可读），或直接降低其默认权重。
5. **无领域/产业标签**：需求要求「特定领域」评估，库内只有行政区划与 `type`（真实 18,138）。需接产业链锚定表，否则密度与覆盖度只能作库级描述。

## 附录 C　政策保障力综合评估权威构建方法可行性报告（完整版）

### C.1 报告目的与范围

回答：官方机构/国际统计体系如何构造「政策与资源保障力」类综合指数；本项目库表能否支撑；应落何档支持度。范围限定为**保障条件**（政策供给 + 资源投入 + 可及性），不含政策实施后的效果评价（属 `M_POLICY_EFFECT_SCORE`）。

### C.2 需求语义锚定

需求把保障力拆为「引导力 / 扶持力度 / 经费与项目 / 实施效果」，并要求可配权、可排名。语义核心是「条件是否齐备」，不是「效果是否显著」。筛选标准：方法能否给出分维可核查读数并支持加权合成。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A/B：研发经费统计与财政科技支出

**代表**：OECD《Frascati Manual 2015》政府研发预算拨款（GBARD）章 (OECD, 2015)；国家统计局等《2023 年全国科技经费投入统计公报》(国家统计局等, 2023)。**构架**：以政府研发预算/财政科技支出为经费保障的法定统计口径，按活动类型、主体、地区分解。**可迁移性**：高，直接对应 D3；本项目缺台账，属数据缺口而非方法缺口。**数据需求**：经费台账（来源、方向、年度、金额）。

#### C.3.2 方法族 C：科技投入保障制度

**代表**：《关于改革完善中央财政科研经费管理的若干意见》（国办发〔2021〕32号）(国务院办公厅, 2021)。**构架**：以「扩大自主权 + 简化预算 + 提高间接费用比例 + 强化绩效与监督」四条主线规范科研经费保障，明确经费拨付机制与绩效导向。**可迁移性**：中高，为 D3/D4 提供制度合法性；但文件只规定「应当保障」，不给度量公式，度量仍需台账。

#### C.3.3 方法族 D：政府信息公开（可见度）

**代表**：《政府信息公开条例》第四条（公开工作机构职责含「维护和更新」）、第十三条（主动公开与依申请公开）(国务院, 2019)。**构架**：以公开渠道的存在与维护状况衡量政策可及性。**可迁移性**：高，对应 D5b；但「非空率」只能证明渠道存在，不能证明内容可及，宜升级为有效性抽检。

#### C.3.4 方法族 E：多指标加权合成

**代表**：财政部《项目支出绩效评价管理办法》第十三条（一级指标权重示例：预算执行率 10%、产出 50%、效益 30%、满意度 10%）与第十八条（评分 + 四档评级）(财政部, 2020)；王惠等权规则。**构架**：分维归一 → 权重 → 合成 → 分档。**可迁移性**：高（合成层直接采用）。**启示**：权重不是技术参数而是政策取向，故需求要求「用户自定义」是合理的制度设计。
