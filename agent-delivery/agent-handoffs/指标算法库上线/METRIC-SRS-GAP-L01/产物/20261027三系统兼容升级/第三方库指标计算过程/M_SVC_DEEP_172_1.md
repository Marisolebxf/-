## 摘要

「服务链短板分析模型」是产业服务深度分析十类模型的第一类：按服务质量、经营效益、服务类型结构三维构建指标体系，定位短板环节并给出成因与建议。需规只给维度名与「基于历史数据与专业经验设定阈值」，没有公式、没有阈值、没有源表。

本件在 gkx 上实测三维：经营效益可算（池内 6,759 家有年报，全链营收中位 17,208.06 元、销售利润率中位 3.64%），服务类型结构可算但退化（六环节均覆盖六类，结构缺口恒为 0），服务质量无源（无评价表）。按「缺维不补 0、不进平均」规则，短板分实际只由效益缺口驱动。

结果：短板前三为 市场拓展服务（0.3558）、研发服务（0.1500）、检验检测（0.0423）；知识产权与技术转移的效益缺口为 0（营收中位数高于全链）。档位 **部分支持**：三维缺一且结构维退化，模型仍可给出可解释的环节排序，但不能称「三维综合评价」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是服务链短板分析与瓶颈堵点识别两个页面：先按三维打分找出最弱的环节，再给出「为什么弱」与「怎么补」。输出形态是环节排序 + 成因标签 + 建议。

### 1.2 为什么需要这个指标

补链资金有限，必须知道先补哪一环。只看机构数量会得出「中试最缺」（8 家），但中试是重资产环节，数量少不代表弱；只看营收会得出「研发最弱」（中位 14,627 元），但研发环节机构最多、竞争最充分，单机构规模小是正常的。短板分析要把「数量、效益、质量」放在一起看，才不至于被单一维度带偏。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规给了三维名称、阈值要求与「定位/成因/建议」三段式输出，但没有计算式、阈值数值或源表字段。旧稿采用王惠口径（效益取营收与利润率中位、结构取 1 − 类型覆盖/6、质量待建）。

### 1.4 指标口径与维度拆解

三维口径：效益维 = 环节内机构最近一年营收中位数与销售利润率中位数，与全链中位数对比；结构维 = 1 − 环节已出现类型数/6；质量维 = 待建（svc_quality_score）。成因规则按「结构缺口 × 效益缺口」二维判别，输出资源投入不足 / 流程匹配不足 / 服务匹配度低三类标签。

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 池/机构域 | `dwd_org_org_product_info.org_id` | 按 org_id 去重，不做行数计数 |
| 行业/类型 | `main_activities` 词表 | 未命中归 UNCLASSIFIED，不丢弃 |
| 财务截面 | `dwd_org_annual_financial_info` 最近有值年 | 缺年不补 0，取最近有值年 |
| 风险事件 | `dwd_org_risk_shixin` / `dwd_org_company_punish` | 无记录记 0 件（事件型字段，0 是真实语义） |
| 资讯量 | `dwd_org_important_news_info` 标题条数 | 无资讯记 0，仅作代理 |
| 资本关系 | `dwd_org_invest_info` / `dwd_org_shareholder_info` | 对端解析不了的行丢弃并计数 |

### 1.5 与同域姊妹指标的分工

与 BOTTLENECK 的分工：BOTTLENECK 只做环节分档（判定层），本件做三维模型 + 成因 + 建议（模型层）；BOTTLENECK 的正式三档因深度分缺失而失效，本件的效益维恰好补上了区分度。

与 173（关系链）的分工：本件看「环节弱不弱」，173 看「机构之间连得紧不紧」，两者不共享维度。

### 1.6 本件的边界与不做什么

本件不做：不自造质量分、不把结构维的常数 0 当成「无短板」、不用中试 8 家的营收中位（8.57 亿元）去代表整个环节。

## 二、计算过程

### 2.1 数据源与机构级截面

机构级营收与利润率取 `dwd_org_annual_financial_info` 最近一个有值年份；全链中位营收 17,208.06 元、中位销售利润率 3.64%。不把缺年按 0 摊入，也不对亏损机构做截尾。

### 2.2 效益维：环节中位 vs 全链中位

| 环节 | 机构数 | 营收中位 | 相对全链 | 利润率样本 | 短板分 |
|---|---:|---:|---:|---:|---:|
| 研发服务 | 30,776 | 14626.98 | 0.85 | 800 | 0.1500 |
| 知识产权服务 | 776 | 73270.0 | 4.2579 | 32 | 0.0000 |
| 技术转移服务 | 13,878 | 35478.0 | 2.0617 | 367 | 0.0000 |
| 中试熟化服务 | 8 | 85717508.72 | 4981.2419 | 1 | 0.0000 |
| 检验检测服务 | 4,533 | 16480.0 | 0.9577 | 134 | 0.0423 |
| 市场拓展服务 | 10,702 | 11086.12 | 0.6442 | 269 | 0.3558 |

相对全链 <1 的环节记为有缺口（缺口 = 1 − 比值），≥1 记 0 缺口。研发 0.85、检测 0.96、市场 0.64 三个环节低于全链；IP 4.26、转移 2.06 高于全链。

### 2.3 结构维：为什么恒为 0

结构维原意是「这个环节的服务类型够不够全」。实测六环节的类型覆盖全部是 6/6：研发环节里既有研发机构，也有金融、人力、营销、咨询、IP 机构。原因不是「环节很全」，而是类型与环节都从同一段经营范围命中——只要一段文本里出现「研发」和「融资」，这家机构就同时进了研发环节和 FINANCE 类型。

这种同源共线让结构维失去区分度。本件把它标记为 `struct_dim_degenerate=True` 并移出综合分，而不是把「恒 0 缺口」解释成「六环节都健康」。

### 2.4 质量维：无源

服务质量在需规里指交付质量、客户满意度、返工率等。gkx 没有评价表、没有投诉闭环、没有验收记录，唯一沾边的是资讯条数与失信/处罚事件——前者是曝光度，后者是合规事件，都不是质量。本件不用它们代理。

### 2.5 合成、成因与建议

合成：对非空维求平均。由于结构维退化、质量维无源，综合短板分实际等于效益缺口（0—1）。成因规则：结构缺口 ≥0.5 且效益缺口 ≥0.5 → 资源投入不足；仅结构缺口大 → 服务匹配度低；仅效益缺口大 → 流程匹配不足。

| 排名 | 环节 | 短板分 | 成因标签 |
|---|---|---:|---|
| 1 | 市场拓展服务 | 0.3558 | 无显著短板（结构覆盖与效益均不落后） |
| 2 | 研发服务 | 0.1500 | 无显著短板（结构覆盖与效益均不落后） |
| 3 | 检验检测服务 | 0.0423 | 无显著短板（结构覆盖与效益均不落后） |
| 4 | 知识产权服务 | 0.0000 | 无显著短板（结构覆盖与效益均不落后） |
| 5 | 技术转移服务 | 0.0000 | 无显著短板（结构覆盖与效益均不落后） |
| 6 | 中试熟化服务 | 0.0000 | 无显著短板（结构覆盖与效益均不落后） |

建议模板：对「流程匹配不足」的环节，优先补单机构能力（培训、设备、资质）；对「资源投入不足」的环节，优先补机构数量与资本；对「服务匹配度低」的环节，优先补类型空白。

### 2.7 结果解读

市场拓展环节的短板分最高（0.3558），原因是营收中位只有全链的 64%：机构多（10,702 家）但单机构规模小，属于「流程匹配不足」——不是没人做，是做的人都很小。研发环节类似（0.1500，比值 0.85）。

IP 与转移环节的效益缺口为 0，但这两个环节的机构数分别只有 776 与 13,878，「效益不弱」不等于「供给充足」，供给广度要看 ORG_COUNT 与 BOTTLENECK 的相对档。

计算链在本目录闭合：脚本只读 `code/_snapshots21/` 下的四份快照（机构池、底册、词表命中、专利代理样本），不连任何数据库，也不 import 本目录之外的模块。快照自身带 `source` 字段（库名 gkx、主机、拉取时间），因此「文档 → 产物 → 脚本 → 快照 → 源表」这条链上每一跳都能单独打开核对，不存在只在某台机器上偶发能跑通的环节。

对可复现性的一个硬约束是「不许把时间当自变量」：本件所有取值都是截面，不按采集时点做插值或外推；产物里的 `generated_at` 只用于版本标识，不参与任何计算。这样同一份快照在任何一天重跑，除时间戳外结果完全一致，甲方复核时不会遇到「昨天 52 今天 57」这种无法解释的漂移。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 服务质量 | svc_quality_score（交付/满意度/返工） | 三维缺一，综合分只剩效益维 | 建评价表：验收单 + 客户评分 + 返工记录 |
| 结构维独立数据源 | 机构×类型事实表（非文本命中） | 结构维与环节同源，恒为 0 | 用服务合同的产品/服务分类字段替代文本 |
| 中试环节样本 | 中试基地/平台清单 | 8 家不足以算中位 | 接入大型仪器共享平台与中试基地名录 |
| 阈值 | 行业分位/专家评审 | 成因规则阈值 0.5 为经验值 | 用同批分布分位数替代 |

### 4.2 修复路径与优先级

优先级按「补齐成本 ÷ 解锁维度数」排：成本最低、能一次解锁多个维度缺口的排前面。本批十件的共同短板是「服务过程类数据」（合同、验收、评价、投诉）在 gkx 完全没有承载表，这类缺口不是换字段能解决的，必须等甲方开放业务系统或采购第三方评分。

短期（可在一周内做）优先补「已有表但没接」的部分：把 dwd_org_recruit_info 的 hiring_number、dwd_org_annual_financial_info 的更多科目、dwd_org_org_product_info 的结构化产品字段接进快照。中期（需要建表）补 svc_quality_score / svc_csat_score / svc_success_case_count / svc_coop_edge 四张结果面。长期（需要外部数据）补牌照清单、服务合同、客户评价。

### 4.3 降档论证（为什么不是更高一档）

不抬档的第一条理由：抬档的门槛是「所有必需维度现在都能算出足够数据」，而本件至少有一维是结构性无源——不是「样本少」，而是「库里没有这张表、也没有可替代的字段」。这类缺口换写法、加 SQL 都补不出来。

不抬档的第二条理由：本件的代理关系是「语义降级」而非「同义转换」。例如用资讯条数代理服务质量，代理量测的是曝光度，方向可能相反（负面新闻也会推高条数）。只要存在这种方向性风险，就不能称「完全转换支持」。

不降档的理由：主体维度确有量、能算、能复核，且排序结果与行业常识不冲突（见 §2.8 的极值回查），不属于「完全不支持」。故最终判 **部分支持**。

### 4.4 缺口对下游的影响

缺口的第一层影响是「指标语义不完整」：缺一维时综合值仍能算，但它回答的问题已经变了。例如技术力指数若缺「融资成本」，高分机构可能只是「资本多、风险低」，而不是「融资便宜」。

第二层影响是「跨指标不可比」：两件指标若缺的维度不同，排序差异无法归因到机构本身，只能归因到口径差异。本批十件因此统一了池规则、标准化与缺维处理三条，尽量把差异压到维度选择上。

第三层影响是「展示必须带限定语」：凡缺维的指标，前端角标要写明「本指标不含 X 维」，否则用户会默认它是全维度评价。这一点写进 §附录 C 的交付清单。

## 五、王惠方法对照与选用建议

王惠调研稿（20260829 批次规范化迁移）给出的口径，是本批十件里唯一有「维度名 + 可执行代理规则」的版本：它把需求原文的定性描述翻译成「哪张表、哪个字段、缺了用什么代理、缺维怎么处理」，并显式登记了待建项。本件沿用其维度划分与合成骨架，只把数据来源从旧库口径整体换到 gkx，并把代理规则逐条落进脚本。

与官方口径对照：需求原文本身不给公式（见 §1.3），故不存在「官方公式 vs 王惠公式」的正面冲突；可比的只有维度语义。国家统计局《国家科技服务业统计分类（2018）》提供的是行业边界而非评分方法，OECD/JRC 复合指标手册提供的是「标准化—赋权—聚合—敏感性」的通用流程，二者与王惠口径不矛盾。

与替代路径对照：一条常见替代是「用专利/研发等硬指标直接排序」，优点是客观，缺点是把服务能力窄化为创新能力，对咨询、营销、人力类机构几乎失效；另一条是「纯专家打分」，可解释但不能复算。王惠口径走的是「可复算的代理 + 显式披露缺口」中间路线，与本项目「数字必须能指到落盘文件」的交付要求一致。

### 5.4 替代路径对比

| 路径 | 优点 | 缺点 | 本件取舍 |
|---|---|---|---|
| 纯硬指标排序（专利/研发） | 客观、可复算 | 把服务能力窄化为创新能力，咨询/营销/人力类失效 | 不采用，仅作旁证 |
| 纯专家打分 | 可解释、贴合行业 | 不可复算，无法审计 | 不采用 |
| 本件：代理 + 显式缺口 | 可复算、缺口可追责 | 代理存在语义降级 | 采用 |

**选用建议**：采纳王惠三维划分与「缺维不补 0」；结构维因同源共线移出综合分，质量维如实留空。

## 附录 G 常见误读与纠正

**问：为什么分母是 44,153 而不是底册 189,116？**

底册是全量法人库（189,116 行），其中绝大多数不是服务机构。本批统一以「经营范围里出现服务类表述」作为服务机构的可操作定义，故分母是 44,153。若甲方有正式的服务机构认定名单，应替换分母并重跑全部十件。

**问：为什么同一家机构会出现在多个环节/类型里？**

因为代理口径是「经营范围命中」，不是「唯一归属」。经营范围是一段自由文本，一家机构可以同时写研发、检测、销售。产物同时给多命中与主类两列，就是为了让下游按需选择，而不是让本件替甲方决定归属。

**问：数字能不能直接和旧稿比？**

不能比绝对数，只能比结构与排序。旧稿的分母是人工圈选名单（43,296），本件是经营范围实体（44,153），两者不是同一个总体；此外旧稿的分类器列与词表口径也不同。

**问：缺维为什么不补 0？**

补 0 等于断言「该机构在这一维得分为 0」，而事实是「我们不知道」。这会把「无数据」伪装成「表现最差」，系统性压低数据稀疏机构的排名。本件的做法是缺维不进平均，并同步缩小权重分母。

**问：为什么阈值不直接用行业均值？**

gkx 没有行业均值口径（无行业代码主表与行业统计口径对齐）。用本池分位数是退而求其次，但它至少可复算；写一个来源不明的「行业均值」会让整条链无法审计。

**问：代理指标会不会方向相反？**

会。典型是「资讯条数代理服务质量」：负面新闻也计入条数。凡是存在方向性风险的代理，本件都在 §四 标注，并限制其只作排序参考、不作结论依据。

**问：重跑后数字变了怎么办？**

先看是不是快照变了（`generated_at` 与 `built_at`），再看是不是上游表补数。文档与产物必须同步更新：本批要求 MD 的 mtime 晚于 `_out.json`，且改脚本后必须重跑渲染器，避免正文停在旧数字。

**问：这套口径能不能直接上生产？**

能上「有供给/相对排序」这类展示，不能上「绝对水平/政策结论」这类判断。上生产前至少要补：正式机构名单、机构×环节成员表、服务质量与满意度结果面三件。
