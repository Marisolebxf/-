## 〇、数据支持度与四判定口径

### 0.1 数据支持度四档

### 0.3 本指标套用（一句话）

「城市对比指标值」不是单一数字，而是「城市 × 小项」的多格面板（3 小项 × 8 行 = 24 格）。24 格里只有「深圳 × orgCount」一格可发布（25,597，与 `M_SVC_PT_SZ_TOTAL` 同数）；外市 orgCount 在同池内可数但池 100% 落广东、北京/上海 0 家；avgTechScore 因模型未签且两子指标分子整列为空而整列不可发布；networkDensity 因无服务机构间边源而整列不可发布。24 格里只有 1 格可发布，故判 **部分支持**。

## 摘要

「城市对比指标值」是深圳对比页的取值面板：横轴是城市（深圳、广州、东莞、惠州、北京、上海、全国平均），纵轴是三个小项（服务机构数量、平均技术力得分、服务网络密度）。calc-logic 0.2.0 对这一面板的判定是「部分闭合」，并明确了一条硬规则：同一批 ADS 写入最多只允许「深圳 × orgCount」一行，且数值必须等于当期深圳总量。

实测结果比 calc-logic 的判定更严格一点：24 格里只有 1 格可发布。深圳 orgCount 为 **25,597**（占池 57.97%）；广州 12,641、东莞 4,300、惠州 1,594 在同池内可数，但它们是「同一个广东样本框里的其它城市」，不是城市基准，只能作样本值、不能作发布格；北京、上海各 0 家（底册 44,132 行回联后 100% 是广东省）；全国平均无定义。技术力整列置空：三个子指标里研发投入与研发人员的分子列（90,926 行）整列为空，模型定义卡未签。密度整列置空：两库都没有「服务机构 A —服务关系— 服务机构 B」的边，投资边 41,888 条与股东边 372,205 条表达的是资本关系，不能冒充服务关系。

判档为 **部分支持**：面板里有一格是硬数且可复算，其余 23 格各有各的阻断，且阻断层不同（样本、结构、算法）。本件因此把「哪一格能上、哪一格不能上、为什么」逐格写清，而不是给一个笼统的「部分支持」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是产业服务链分析 → 服务链分析 → 深圳对比 → 对比柱。展示形态是一组并排柱：深圳一根、外市若干根、全国平均一根，每根柱按三个小项切换。算法侧是服务机构基础指标模型的横向对比取值件，与「深圳梯队位置」「服务链完整度」共用同一批城市取值。

这个面板与普通分布件的差别在于它是「多格」而不是「单值」：每一格都要独立判定可发布性。一格不可发布不等于整个面板不可发布，一格可发布也不等于面板闭合。本件的核心工作因此是逐格判定，而不是算一个总数。

### 1.2 为什么需要这个指标

深圳对比页要让决策者一眼看出「深圳的服务机构数量相对其它城市是多还是少」。这个判断需要对照物：只有深圳一个数，无法判断 25,597 是多还是少；有了北京、上海、全国平均，才有参照。面板的价值在于把「绝对数」转成「相对位置」。

面板类指标的风险在于「格子混口径」。最常见的错误是深圳用服务机构圈定池、北京上海用全量工商按城 COUNT，两根柱子的分母完全不同却画在一起，读者会以为在比较同一件事。calc-logic 明确禁止这种混用：对比柱上的机构数必须是服务机构圈定池，不是全量工商。本件沿用这条纪律，并进一步规定「池外的城市不灌数」——宁可缺格，不可混口径。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法，calc-logic 0.2.0 给了「部分闭合」的判定但没有给完整公式。** calc-logic 正本（`gkx-orchestration/agent-delivery/metrics/calc-logic/SVC/M_SVC_SZ_COMPARE_METRIC.md`）对三小项的真实情况写得很直白：orgCount「仅深圳可 live」，avgTechScore「拿不到真数（MODEL 未签）」，networkDensity「拿不到真数（无服务边）」；并给出可执行部分只有一句——深圳 orgCount 与 `M_SVC_PT_SZ_TOTAL` 同一 COUNT。

因此本件的口径是「calc-logic 的可执行部分 + 逐格状态标注」。可执行部分照做（深圳格子与总量同数）；不可执行部分不发明公式，只写阻断层与证据。这个处理方式与 calc-logic 的「部分闭合」判定一致，也避免了在算法未签时自造一套技术力或密度公式。

### 1.4 指标口径与维度拆解

面板结构是 3 小项 × 8 行（深圳、广州、东莞、惠州、北京、上海、全国平均、未回联底册）。

| 小项 | key | 定义 | 本件可得 |
|---|---|---|---|
| 服务机构数量 | `orgCount` | 服务机构池 ∩ `city` 的机构数 | 深圳 25,597 可发布；四市样本值；京沪 0；全国平均无定义 |
| 平均技术力得分 | `avgTechScore` | `M_SVC_ORG_TECH_SCORE` 的城市均值 | 不可得（模型未签 + 两子指标分子为空） |
| 服务网络密度 | `networkDensity` | 服务机构间边数 ÷ 可能边数 | 不可得（无边源） |

口径边界有四条：其一，**机构数只能用服务机构池**，不能用全量工商按城 COUNT；其二，**深圳格必须与总量件同数**，25,597 是同一池同一规则；其三，**外市不灌数**，广州/东莞/惠州的池内计数只作样本披露，不作发布格；其四，**完整度不属本面板**，它是独立指标 `M_SVC_SZ_CHAIN_COMPLETENESS`。

### 1.5 与同域姊妹指标的分工

与 `M_SVC_PT_SZ_TOTAL` 的分工：后者是深圳总量件（25,597），本件的深圳 orgCount 格直接引用同一 COUNT，不重算。两件必须同数，这是 calc-logic 明写的硬规则。

与 `M_SVC_SZ_TIER` 的分工：TIER 用本面板的三小项作维度输入，再按 30/40/30 分档。本件只给取值，不给名次；TIER 的名次之所以置空，正是因为本面板 24 格里只有 1 格可发布。

与 `M_SVC_GRAPH_DENSITY` 的分工：密度是独立图谱指标，本件的 density 格只是它的城市维投影。该件的边源同样缺失，两件的阻断理由必须一致——不能一件说「无服务边」、另一件说「用投资边代理」。

### 1.6 本件的边界与不做什么

本件不做五件事：不用全量工商按城 COUNT 冒充服务机构对比；不用投资/股东边算服务密度；不在模型未签时自造技术力公式；不把广州/东莞/惠州的样本值当城市基准发布；不把完整度塞进本面板（完整度另件）。

## 二、计算过程

### 2.1 方法选择：逐格判定，而不是整表判定

选择「逐格判定」而不是「整表一刀切判不支持」，理由是面板里确实有一格是硬数。深圳 orgCount 25,597 不依赖任何缺失维度：池在、`city` 在、计数规则明确、与总量件同数。若因为另外两小项不可得就把整表判不支持，等于把一个可发布的事实也一起丢掉。

反过来，也不能因为一格可发布就把整表判「完全转换支持」。24 格里 23 格不可发布，其中技术力与密度是「整列无源」，外市是「整行无样本」，这两类阻断不是补一补覆盖率就能解决的。按四档定义，「始终有部分依赖维度无法得到足够数据」正是部分支持。

放弃的方案是「用代理把空格填满」。例如用专利件数当技术力、用投资边当密度，确实能把 24 格填满，但填进去的不是指标本身：专利件数是技术力的一个子指标，投资边是资本关系不是服务关系。填满的面板比缺格的面板更危险，因为它看起来完整。

### 2.2 步骤 1｜深圳 orgCount 格（D1）

深圳格取值 25,597 家，与 `M_SVC_PT_SZ_TOTAL` 同一 COUNT、同一池、同一 `city` 过滤。占服务机构池 44,153 家的 57.97%；若只算四个有池内机构的城市（合计 44,132 家，等于池减去 21 家未回联），深圳占 58.00%。

这个格子是本件唯一可发布的格，也是 calc-logic 明确允许写入 ADS 的唯一一行。它的可发布性来自三点：池定义稳定（`M_SVC_ORG_TOTAL` §2.2）、城市过滤是等值匹配、与总量件逐位相等。任何一次池变更都必须同步改这一格，不能只改一件。

### 2.3 步骤 2｜外市 orgCount 格（D2）

广州 12,641、东莞 4,300、惠州 1,594，三市都是池内可数的真实计数，分别占池 28.63%、9.74%、3.61%。这三个数不是猜的，也不是代理，但本件仍不给它们「可发布」状态，原因是它们不构成城市基准：三市与深圳同属一个广东样本框，样本框本身不是按城市分层抽的，因此「深圳比广州多一倍」这句话只在「gkx 经营范围池」这个样本内成立，不能推广成「深圳的服务机构是广州的两倍」。

北京、上海各 0 家，这个 0 不是「北京没有服务机构」，而是「池里没有北京机构」：底册 44,132 行回联后省份 100% 是广东省（深圳、广州、东莞、惠州），北京上海一行都没有。把 0 画成柱子会让读者以为「北京的服务机构数是 0」，这是最严重的一类误读，因此京沪两行标注为「不可发布（0 家）」并附原因。

### 2.4 步骤 3｜avgTechScore 整列（D3）

技术力整列不可发布，阻断点有三层。第一层是算法：`M_SVC_ORG_TECH_SCORE` 的定义卡未签（Q-SVCCHAIN-01 / 唐绍祖），三子指标的权重、归一化方式、缺失处置都没有定。第二层是结构：三个子指标里研发投入强度的分子列与研发人才结构的分子列，在 `dwd_org_annual_financial_info` 全表 90,926 行里 0 行非空——列存在、类型对、就是没有值。第三层是数据：唯一可算的创新产出只有专利聚合（深圳 13,378 家有记录、505,417 件授权），且没有专利类型与法律状态，无法只取有效发明专利。

三层阻断里最硬的是第二层。算法可以签、口径可以定，但「整列为空」意味着即使定义卡签了，分子仍然算不出来；这不是工程问题，是数据供给问题。因此本件把技术力整列置空，并在 §4.1 写明解挂需要的是「研发费用与研发人员两列灌数」，而不是「再算一遍」。

### 2.5 步骤 4｜networkDensity 整列（D4）

密度整列不可发布，原因是边源不存在。密度的定义是「服务机构 A —服务关系— 服务机构 B」的边数除以可能边数；gkx 里没有任何一张表承载这种边：280 张表中 `svc_*` 0 张，招投标表里的 `bidding_stage` 是招标阶段不是服务关系，投资表与股东表是资本关系。

本件做了反证：投资边共 41,888 条，其中触及深圳机构的 24,830 条；股东边共 372,205 条，其中从深圳机构出发的 232,198 条。这两组数很大，足够「算出」一个看起来很象样的密度值，但它们不是服务关系：投资边连接的是投资方与被投方，股东边连接的是股东与公司，两端大量不是服务机构，方向与语义都与「服务供给关系」不同。用它们算密度，等于把资本网络冒充服务网络。

### 2.6 步骤 5｜全国平均格与未回联行（D5）

全国平均格无定义：要算全国平均，先要有全国城市集合的服务机构取值，而池 100% 落广东。用底册 189,116 行全量工商按城平均是错误口径——那会把制造业、批发零售、房地产都算进服务业，得出的「全国平均服务机构数」没有意义。

未回联底册的 21 家单列一行、状态为「不入格」：它们没有 `city`，不能归入任何城市。21 家占池 0.05%，单列不影响任何一格，但必须出现在面板的脚注里，否则「四市合计 44,132」与「池 44,153」差 21 家会被当成对账错误。

### 3.7 面板的三类阻断
| 阻断类型 | 涉及格 | 性质 | 解挂条件 |
|---|---|---|---|
| 样本阻断 | 京、沪、全国平均 | 池 100% 广东 | 甲方指定城市基准源（Q-SVCCHAIN-04） |
| 结构阻断 | 全列 avgTechScore | 研发两列整列为空 | 研发费用/人员两列灌数 + 定义卡签 |
| 算法阻断 | 全列 networkDensity | 无服务机构间边 | 供方交付服务关系边（SVC-P1-1） |

三类阻断的修复路径完全不同：样本阻断靠甲方拍板、结构阻断靠数据灌入、算法阻断靠供方交付边表。把三类混成一句「数据不足」会让甲方无从下手，因此本件分行列出。

### 3.8 面板的更新频率与刷新边界

calc-logic 给本件的更新频率是「日（仅可 live 格随圈定；其余格不适用）」。这条定义包含两层意思：可发布的那一格每天随池圈定刷新，不可发布的格不参与刷新调度。

工程上这意味着三件事。其一，深圳格必须绑定池版本号，池一变、格立即变，不能有缓存窗口。其二，外市样本值即使可数，也不进刷新任务——它们不是发布值，刷新只会徒增跑批成本。其三，技术力与密度两列在解挂前不建调度，避免每天跑一次必然为空的作业。

刷新边界还影响对账：日频刷新会让「昨天的 25,597」与「今天的 25,597」看起来一样，但背后的池可能已经变了。因此产物里必须带池版本与生成时间，让下游能判断自己消费的是哪一批。

### 3.9 反证：为什么投资/股东边不能当密度

投资边 41,888 条、股东边 372,205 条，数量上完全够算一个密度值。但密度的语义是「服务机构之间的服务供给关系」，而投资边的两端是「投资方—被投方」、股东边的两端是「股东—公司」。用它们算密度会产生三个错误：其一，分母里的机构大量不是服务机构（被投方可能是制造企业）；其二，方向错（投资是资本流向，不是服务流向）；其三，含义错（一家机构被十家资本持股，不代表它有十个服务伙伴）。

这三条错误里任何一条都足以让密度值失去解释力。因此本件把它们只作反证披露：它们证明「库里有边，但不是我们要的边」，而不是「库里有边，可以凑合用」。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 城市基准源 | 北京/上海/省会城市的同口径服务机构取值 | 6 格外市/全国平均不可发布 | 甲方指定（Q-SVCCHAIN-04） |
| 技术力模型 | `M_SVC_ORG_TECH_SCORE` 定义卡 | avgTechScore 整列不可发布 | 唐绍祖签定义卡（Q-SVCCHAIN-01） |
| 研发投入分子 | 研发经费内部支出列整列为空 | 技术力 1/3 子指标不可算 | 接入研发费用数据 |
| 研发人员分子 | 研发人员数列整列为空 | 技术力 1/3 子指标不可算 | 接入社保/年报人数 |
| 服务关系边 | 服务机构 A—B 边表 | networkDensity 整列不可发布 | 供方交付（SVC-P1-1） |
| 未回联 21 家 | `city` 缺失 | 不入任何城市格 | 核对 org_id 或补底册行 |

### 4.2 修复路径与优先级

短期（一周内）优先做一件成本最低的事：把深圳格与总量件的绑定做成脚本断言，任何一次池变更都让两件同时失败、同时修。中期（需要建表）补研发费用与研发人员两列，这是技术力整列唯一的解挂路径。长期（需要外部数据）补城市基准源与服务关系边表，前者靠甲方、后者靠供方。

### 4.3 降档论证（为什么不是更高/更低一档）

不抬到「完全转换支持」的理由：24 格里 23 格不可发布，且不可发布的原因分三类（样本、结构、算法），没有一类是「再加工一下就能出」。

不降到「完全不支持」的理由：深圳 orgCount 这一格是硬数、可复算、与总量件同数，且它正是 calc-logic 明确允许 live 的唯一一行。一格可发布即不满足「完全不支持」的定义。

### 4.4 缺口对下游的影响

第一层影响是「对比页只能画一根柱」：深圳可画，外市与全国平均不可画，页面必须用「缺口声明」替代柱子，而不是画 0。第二层影响是「梯队连带」：`M_SVC_SZ_TIER` 的三维都依赖本面板的取值，本面板 23 格空，TIER 的名次也就无法产出。第三层影响是「缓存一致性」：旧 fixture 必须下架，否则会出现总量与对比柱不一致。

| 期望字段 | gkx 是否有等价列 | 处置 |
|---|---|---|
| 城市基准取值 | 无 | 待甲方指定 |

| 服务关系边 | 无 | 待供方交付 |
| 全国平均分母 | 无 | 无定义，不做 |
| 城市分层权重 | 无 | 待抽样框说明 |

### 4.6 口径变更的影响矩阵

| 若口径改为 | 面板变化 | 下游需要重算的件 |
|---|---|---|
| 允许外市样本值发布 | 4 格可发布 | COMPARE / TIER |
| 用全量工商按城 COUNT | 京沪有数但语义错 | 禁止，全部失效 |

| 全国平均改为「池内均值」 | 只有 4 市均值 | 需重命名，不可叫全国平均 |

## 五、结论与发布建议

本件可以发布一格：深圳 orgCount = 25,597。这一格必须与 `M_SVC_PT_SZ_TOTAL` 同批刷新，并在 API 响应里带 `basis = "服务机构池 ∩ city=深圳市"`。

其余 23 格不得发布，且不得用 0 填充。前端应把外市与技术力/密度柱替换为「缺口声明」，声明里写清三类阻断：样本（池 100% 广东）、结构（研发两列整列为空）、算法（无服务关系边）。等三类阻断各自解挂后，再逐格放开。

## 附录 G　常见误读与纠正

**问：为什么北京上海的柱子是 0？北京不可能没有服务机构。** 0 是「池内 0 家」，不是现实 0 家。池 100% 落广东，京沪一行都没有。柱子应替换为「缺口声明」，不能画 0。

**问：广州 12,641 明明是算出来的，为什么不发布？** 因为它是「同一个广东样本框里的广州」，不是「按城市分层抽样的广州」。发布它会让人以为深圳是广州的两倍，这个结论只在样本内成立。

**问：技术力能不能先用专利顶上？** 不能。专利是技术力三子指标之一，用它顶替整列等于改了权重，得到的分与定义不是同一个东西。

**问：投资边 41,888 条，密度为什么算不出？** 因为投资边不是服务边。密度要的是「服务机构之间提供过服务」的关系，投资边连接的是资本。

**问：24 格只有 1 格能发布，这个指标还有意义吗？** 有，因为那一格是最常用的一格。对比页可以先只亮深圳，其余用缺口声明，等三类阻断各自解挂再逐格放开。

**问：旧页面上那套完整面板怎么办？** 下架。旧面板的外市格与技术力/密度格都是 fixture，留着会与总量件自相矛盾。
