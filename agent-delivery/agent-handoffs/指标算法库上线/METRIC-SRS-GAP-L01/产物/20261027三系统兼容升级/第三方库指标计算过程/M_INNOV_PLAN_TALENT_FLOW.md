## 摘要

「科技人才流动」要回答的是「有多少核心技术人才在学术界与产业界之间换过边」，并按年给出流向与预警。它是一个**方向 × 时间**的双维指标，空间维是附加观察（calc-logic 只要求两方向，不要求城市），但本批把空间维也纳入了判档，因为它决定了「人才流到哪里」能不能讲。

实测的硬约束有三层。第一层是**人**：21,316 名学者里 20,028 人有工作经历（57,117 段），但只有 12,427 人有 ≥2 段（58.2%），另外 7,601 人只有一段，无法识别「流动」；`start_time` 可解析为年份的只有 49,637 段（86.9%），7,480 段没有起始年，流动年不可定位。第二层是**性质**：45,890 段判为学术（80.3%）、2,400 段判为产业（4.2%）、8,827 段（15.45%）判不出性质，按口径必须跳过——这会系统性漏掉外文小机构与非常规命名。第三层是**空间**：机构名与 189,116 行工商底册的命中只有 456 条（0.8%），原因是底册只收企业，高校/院所/海外机构不在其中，所以「机构→城市」这条链在源头就断了。

口径要求对象是「核心技术人才」，即院士或 `h_index ≥ 池内 P70`。本文实测 P70 = 24，核心池 6,580 人（占学者池 30.9%）。**限定核心池后，跨界事件只有 82 次**（学界→产业 31、产业→学界 51），分布在 2005—2023 的 16 个年份上，单年最多 7 次（2016 年，产业→学界）、多数年份 0—2 次。全池口径有 1,681 次（747 / 934），数量级高 20 倍，但那是「全部学者」不是「核心人才」，不能拿它当主口径。两个数都写进 `_out.json`，主口径用 82。

预警维在 82 次事件上不可解释：近窗 2022—2024 共 6 次（学界→产业 3、产业→学界 3），基线 2017—2021 共 3 次（1 / 2），分母取 `max(基线均值, 1)` 后 burst 分别为 0.8 与 0.6、加权 0.7，落在「1 关注」。这个等级由个位数计数决定，任何一个事件的有无都会翻转结论，因此本文只把它标为「待观察」，明确不作为对外预警。这条披露是本文件最重要的限制说明。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技发展态势 → 科技发展规划 → 核心技术人才监控 → 人才流动分析**（需求序号 182）。

需求原文（第 1119 行）是：「对核心技术人才信息进行全面监控，用户可查看科技人才在产业界和学术界的流动情况，提供人才流动趋势分析和预警功能。」这句话里三个关键词决定了指标形态：**核心技术人才**（不是全部学者）、**产业界与学术界**（只有两类性质，不含同业跳槽）、**趋势与预警**（要年序列，还要一个阈值灯）。

| 页面任务 | 对指标的要求 |
|---|---|
| 双方向流动柱状图 | 学界→产业、产业→学界两条年序列 |
| 人才流动明细 | 可下钻到人（学者 ID、机构、起止年） |
| 趋势分析 | 年序列至少覆盖近 8 年 |
| 预警灯 | 近窗相对基线的 burst，分 0/1/2 三级 |
| 空间分布 | 流动人才落在哪些城市（附加） |

### 1.2 为什么需要「科技人才流动」这个指标

人才流动是创新链上最直接的「知识搬运」：一位学者从高校进企业，带过去的不只是人，还有方法、网络与隐性知识。需求把它放在「科技发展规划」而不是「科技创新评估」下，说明它服务的是**规划**而不是**评价**——看的是流向与趋势，用来判断人才政策是否起作用，而不是给某个人打分。

只有存量没有流量，会漏掉最重要的信号。库内 21,316 名学者是一个静态快照，看不出谁在动；57,117 段经历才让「动」变得可见。但「动」不等于「跨界」：同一所大学换一个学院、同一集团换一个子公司，都不是本条要计的事件。口径因此要求「相邻两段的任职性质发生变化」，这也是为什么本文必须先做机构性质判定，再做流动识别。

第三个理由是预警的价值取决于分母是否稳定。如果一年只有 1—2 次事件，任何「同比翻倍」都是噪声；如果一年有几百次，burst 才有统计意义。本文实测核心池只有 82 次总事件，这个量级决定了预警只能作「待观察」，不能作「红黄灯」。把这个限制写清楚，比给一个好看的灯更重要。

### 1.3 需求文档是否给出定义方法

**需求给了对象与两个方向，没给判定规则。**

原文只写「产业界和学术界的流动情况」「趋势分析和预警功能」，没有写：核心技术人才怎么界定（院士？职称？h 指数？）、机构性质怎么判（名称关键词？行业码？人工标注？）、相邻两段怎么算（按 `seq_no` 还是按时间）、跨界的年份取新单位起始年还是旧单位结束年、预警阈值是多少。

calc-logic 补了四条：对象 = 院士或 `h_index ≥ 池内 P70`；性质由机构名对齐现表判定，不另建字段；只计学界↔产业界；预警 = 近窗相对基线，burst ≥1 为 2 级、≥0.5 为 1 级、否则 0 级。这四条本文照用，未改阈值。

仍未闭合的是：机构名对齐哪张现表（工商底册只收企业，高校/院所/海外机构缺位）、判不出性质时是跳过还是归「其他」、多段经历里出现「学术→未知→产业」时要不要跨过未知段连算。本文的选择是：工商底册 + 名称关键词双判、判不出即跳过（不归「其他」）、遇到未知段则断开链条（不跨段连算）。这三条都是工程决策，写进 §2.5。

### 1.6 推测原意与推测定义

**推测原意**：产品要的是一张「核心人才流向图」，用来判断人才政策是否让人往产业走、产业人才是否回流学术。它服务规划，不服务个人评价。

**推测定义（本文采用）**：

> 设核心人才集合 $S=\{s: \text{academician}_s=1 \lor h_s\ge P70\}$，学者 $s$ 的经历按 `seq_no` 升序排列为 $e_1,\dots,e_k$，每段性质 $c_i\in\{A,I,\varnothing\}$。若存在相邻两段 $c_i\ne c_{i+1}$ 且两者均非空、且 $e_{i+1}$ 的年份 $y$ 可解析，则记一次流动事件，方向由 $(c_i,c_{i+1})$ 决定：
> $$
> N_{A\to I}(y)=\#\{s\in S:\ \exists i,\ c_i=A,\ c_{i+1}=I,\ y_{i+1}=y\}
>
$$
> $$
> \text{burst}=\frac{\overline{N}^{(2022\text{—}2024)}-\overline{N}^{(2017\text{—}2021)}}{\max(\overline{N}^{(2017\text{—}2021)},1)}
>
$$

**为什么限定核心池**：口径写的是「核心技术人才」，若用全池 20,028 人，事件数会从 82 跳到 1,681，但其中大量是普通讲师、博士后、工程师的常规流动，与「核心人才」不是一件事。本文把全池序列作为灵敏度对照单独输出，主口径只用 6,580 人。

**为什么未知段要断开**：如果允许跨过未知段连算（学术→未知→产业），那么「学术→未知」这一段可能是同业跳槽，也可能是离职，会把非跨界事件误计为跨界。断开链条会漏掉一部分真实流动，但不会造假；在 15.45% 未知率下，宁可漏不可错。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是 calc-logic 的四条口径（对象、性质判定、两方向、burst 分级）。本文没有改动阈值，只补了三件原文未写的事：性质判定的关键词表与优先序、未知段的处理、核心池的 P70 取值。之所以必须补，是因为「机构名对齐现表」这句话在工程上有两种完全不同的实现：查底册行业码，或用名称关键词。前者精确但覆盖窄（0.8%），后者覆盖宽但会误判（把「XX 大学科技园有限公司」判成产业）。本文两者并用，先查底册、再退关键词。

本文做的降级只有一处：**不交付空间维**。0.8% 的机构—城市命中率意味着任何城市排行都只代表 456 段经历，不是 57,117 段。本文没有做的降级包括：没有把未知性质归到「其他」再算流动、没有跨未知段连算、没有把全池 1,681 次当主口径、没有为了让预警灯变红而调低 burst 阈值。

### 2.2 口径拆解：对象、集合、归一

**对象**：核心人才（学者 ID）。21,316 名学者中，院士 112 人、`h_index ≥ 24` 的 6,469 人（含重叠），合并去重后核心池 6,580 人。这个池是「相对位置」定义（池内 P70），不是绝对学术水平线；换一批学者，P70 会变。

**集合**：核心池中有 ≥2 段经历的人。全池有 12,427 人 ≥2 段，核心池里更少；只有一段经历的人无法识别「变化」，按定义不进事件集。这一点决定了事件的绝对量必然远小于「有经历人数」。

**归一**：不做 min-max，也不做人均。方向维输出「事件数」与「去重人数」两个口径（82 次事件 / 部分年份人数少于事件数，说明有人一年内多次流动）。burst 是唯一的比率计算，分母取 `max(基线年均, 1)`，避免 0 除，也避免基数为 0.2 时把比率放大到 10 倍。

**性质判定的优先序**：先查工商底册的行业一级码，若命中「教育 / 研究和试验发展 / 科学研究和技术服务业」判学术，其余判产业；底册未命中时用中文关键词（大学、学院、研究院、研究所、科学院、医院、实验室等判学术；有限公司、股份、集团、公司、厂、银行等判产业），再用英文关键词（university、college、institute、academy、hospital、ltd、inc、gmbh 等）。两级都不命中即未知。

| 1 | 学者主档：h 指数 | `gkx.dwd_scholar` | 21,316 行 |
| 1 | 院士标识 | `gkx.dwd_scholar_talent_flag` | 20,030 行，112 人为院士 |
| 1 | 机构性质与城市 | `dwd_org_base_info`（189,116 行） | 命中 456 段（0.8%） |
| 2 | 高校/院所/海外机构主数据 | `dwd_research_institute_base_info`、`dwd_forg_university_org_info` | 口径要求的三张对齐表，本批**未接入**（见 §四） |

「两跳停」的意思是：本指标只走到「经历 + 学者 + 底册」这一层，不再往论文署名或项目履历走。原因是论文署名推断流动需要全量三元组与单位规范化，而库内 `dwd_zh_author` 只有 62,002 行、单位串未规范化；一旦引入，会把「机构性质」问题变成「单位名对齐」问题，误差更大。

### 2.4 算路 / SQL

全流程 2 条 SQL，均落在小表：

```sql
-- Q1 工作经历全量窄列（57,117 行）
SELECT scholar_id, seq_no, start_time, end_time, is_current, org_name_zh, org_name_en, status
FROM gkx.dwd_scholar_work_experience;

-- Q2 院士名单（112 行）
SELECT scholar_id FROM gkx.dwd_scholar_talent_flag WHERE academician = 1;
```

两条都带 `SET SESSION max_execution_time=60000`。工商底册 189,116 行不现查（该表全表 `COUNT(*)` 实测 87.7 秒，见 `DATA_FACTS_gkx21.md` §3.2），改用 `code/_snapshots21/star_base_rows_gkx.json` 的本地快照建 `名称转行业一级码` 字典。

本地计算顺序：按 `scholar_id` 聚合经历并按 `seq_no` 排序；逐段判性质；相邻两段性质不同且后段年份可解析时记事件；核心池内汇总成年序列；最后算近窗/基线的 burst。全部在内存完成，没有对经历表做 GROUP BY 大列。

### 2.5 清洗规则

| 规则 | 处理 | 影响行数 |
|---|---|---|
| `seq_no` 为空 | 记 0，排在最前 | 少量 |
| `start_time` 非年份 | 该段不产生事件（无法定年） | 7,480 段 |
| 机构名为空 | 性质记为未知，断开链条 | 含在 8,827 段内 |
| 性质判不出 | 跳过，不归「其他」 | 8,827 段（15.45%） |
| 相邻两段性质相同 | 不计事件（同业跳槽） | — |
| 学术转未知转产业 | 断开，不跨段连算 | — |
| 一年内多次流动 | 事件计多次，人数去重 | 见 `people_*` |
| 2025 年 | 保留在序列，但不进 burst 分母 | 全池 13 次、核心池 0 次 |
| 2026 年 | 无完整段，不进序列 | 0 |
| 全池 vs 核心池 | 主口径核心池，全池单独输出 | 82 vs 1,681 |

清洗原则是「宁可漏事件，不可造方向」。把未知段跨过去连算，会凭空造出一批「学术转产业」；把未知归「其他」再算，会造出「学术转其他转产业」的两段伪流动。两种做法都能让图更好看，但都会让结论失真，本文都不做。

### 2.6 结果解读

**方向与总量（核心池）**：82 次跨界事件，学界转产业 31 次、产业转学界 51 次。产业转学界略多，比例约 1.65:1。这个方向性与「高校抢人」的直觉相反，但由于总量只有 82 次，不能据此判断「回流潮」。

**年序列（核心池，2005—2025）**：2005 年 0/2、2006 年 1/1、2008 年 1/5、2009 年 0/2、2010 年 1/3、2011 年 3/0、2012 年 1/2、2013 年 2/2、2014 年 1/3、2015 年 2/1、2016 年 2/7、2017 年 1/0、2018 年 0/1、2019 年 0/1、2020 年 0/0、2021 年 0/0、2022 年 2/1、2023 年 1/2、2024 年 0/0、2025 年 0/0（格式为 学界转产业 / 产业转学界）。单年峰值是 2016 年的 7 次（产业转学界），多数年份在 0—3 次之间；2020—2021 与 2024—2025 连续为零。

**全池灵敏度**：1,681 次（747 / 934），年序列 2017 年 49/51、2018 年 58/47、2019 年 43/53、2022 年 58/46、2023 年 42/36，单年 60—110 次。数量级是核心池的 20 倍，形态更平滑，但它回答的是「所有学者」而不是「核心人才」。

**预警**：近窗 2022—2024 核心池 6 次（3 / 3），基线 2017—2021 共 3 次（1 / 2）；学界转产业 burst 0.8、产业转学界 0.6、加权 0.7，落「1 关注」。这个灯由 6 对 3 的个位数比较得出，任何一个事件的有无都会把它推到 0 或 2，因此本文标注为「待观察」，不建议对外展示。

**空间维**：不交付。机构名与工商底册命中 456 段（0.8%），按命中样本排出的城市 Top 5 是北京 752、香港 479、上海 410、南京 260、武汉 224（此处计数为机构名出现次数，含未判定性质的机构），样本只覆盖 0.8%，不足以支撑「人才流到哪」的结论。

### 4.1 缺失清单

| 缺失项 | 现状 | 影响 | 修复建议 |
|---|---|---|---|

| 起始年 | 7,480 段缺失（13.1%） | 流动年不可定，事件漏计 | 回填或由 `end_time` 反推 |

### 4.2 对结论的影响边界

上述缺失**不改变方向与时间两维的可算性**：82 次事件、21 年序列、两个方向都能出，且性质三分对账闭合。它们改变的是**结论强度**：82 次不足以支撑「趋势判断」，更不足以支撑「预警」；空间维完全不可交付。这三个边界必须在页面上分区标注，不能把「有数」当成「可信」。

### 4.3 不可外推的三件事

第一，不能把 82 次当成「全国核心人才跨界总量」。核心池是库内 6,580 人，不是全国核心人才总体；库的采集面以高校与中科院系为主，产业侧样本偏少（性质判为产业的只有 2,400 段，占 4.2%）。

第二，不能把「1 关注」当成政策信号。这个等级由 6 对 3 的个位数比较得出，换一年做 T 就会翻转；它只能提示「值得再看一眼」，不能进简报。

第三，不能把机构名命中的 456 段城市分布当成「人才流向」。0.8% 的命中率意味着 99.2% 的经历根本没有城市，排出的城市榜只是那 456 段的分布，不是 57,117 段的分布。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

王惠 calc-logic 的结构是：

| 二级 | 三级 | 口径 | 计算逻辑 | 源字段 |
|---|---|---|---|---|
| 学界→产业 | — | 学术界转入产业界的去重学者数 | `COUNT(DISTINCT scholar_id)` WHERE 旧=学术 AND 新=产业 | `dwd_scholar_work_experience` + 三张机构对齐表 |
| 产业→学界 | — | 产业界转入学术界的去重学者数 | `COUNT(DISTINCT scholar_id)` WHERE 旧=产业 AND 新=学术 | 同上 |
| 流动预警 | — | 近窗流动人数相对基线突增 | burst≥1 为 2；≥0.5 为 1；否则 0 | 上两年序列 |

并写明「任职性质由机构名对齐现表判定，不另建性质/方向字段」「只计学术界↔产业界」。

### 5.2 新方法概述

新方法保留两方向与三级预警，补四件事：核心池按 P70 显式定义、性质判定用「底册行业码优先 + 中英文关键词兜底」、未知段断链不连算、全池序列作灵敏度对照。输出除年序列外，还有性质三分对账、核心池规模、burst 的分子分母。

### 5.3 逐维对照表

| 维度 | 王惠原法 | 本文实现 | 差异与理由 |
|---|---|---|---|
| 对象 | 核心技术人才 | 院士 + h≥P70（24），6,580 人 | 原法未给阈值，本文用池内分位 |
| 性质判定 | 机构名对齐现表 | 底册行业码 + 中英文关键词 | 底册只覆盖企业，必须兜底 |
| 学界→产业 | 去重学者数 | 事件 31 次（人数另列） | 事件与人数并列，避免一人多次被压平 |
| 产业→学界 | 去重学者数 | 事件 51 次 | 同上 |
| 预警 | burst 三级 | 同，落 1 级但标「待观察」 | 82 次事件不足以支撑预警 |
| 空间维 | 机构→城市 | 不交付（0.8%） | 命中率过低 |
| 未知段 | 未提 | 断链，不跨段连算 | 避免造方向 |

### 5.4 选用建议与理由

**建议采纳本文实现，但只发布方向与时间两维，预警维标「待观察」，空间维不发布。** 理由：方向与时间两维有 82 次事件与 21 年序列，可复核、可下钻到人；预警维的统计基础太薄，发布出去会被当成政策信号；空间维的 0.8% 命中率不足以支撑任何城市结论。

**不建议**为了让预警「有内容」而改用全池 1,681 次的口径——那会改变对象定义（从核心人才变成全部学者），属于口径漂移，需要甲方重新签字。也不建议接入论文署名推断流动来补事件量，因为那会把「机构性质」问题变成「单位名对齐」问题，误差更大。

## 附录 C　科技人才流动类似指标权威构建方法可行性报告（完整版）

### C.1 报告目的与范围

本附录回答：在只有 57,117 段经历、且机构主数据不全的条件下，「核心人才跨界流动」能做到什么程度，以及权威方法族为什么只能部分照搬。范围限定在两个方向与年序列，不扩展到职级、薪酬、团队规模。

### C.2 需求语义锚定

需求用的词是「流动」，不是「跳槽」也不是「迁移」。在科技政策语境里，人才流动特指**部门间**（学界/产业界/政府）的移动，而不是地理迁移或单位内晋升。这决定了性质判定必须是「机构类型」而不是「城市变化」。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：履历事件法

ORCID、OpenAlex、微软学术图谱都用「任职记录 + 起止年」构造事件序列。它们的共同前提是：每条任职有机构 ID、有起止年、机构有类型标签。本文的经历表有前两条的一半（机构名、起始年 86.9%），缺机构 ID 与类型标签，只能靠名称关键词补，这是 15.45% 未知率的来源。

#### C.3.2 方法族 B：论文署名变迁法

以作者单位在论文上的年度变化推断流动，代表做法是学者—机构二部图的年度差分。它不依赖履历表，但依赖单位名规范化与全量署名。本文的 `dwd_zh_author` 只有 62,002 行，覆盖 100,900 篇论文的一部分，不足以构造连续轨迹。

#### C.3.3 方法族 C：履历文本挖掘

LinkedIn 类履历解析用 BERT 判岗位与机构类型。库内没有职级、没有自由文本履历，只有机构名与起止年，方法族 C 不可行。

#### C.3.4 方法族 D：项目迁移法

以项目承担单位变更推断流动，需要项目—负责人跨年表。`dwd_zh_project` 58,453 行，但没有「负责人迁移链」，无法判断同一人是否换了单位。

### C.4 数据可行性详细分析

#### C.4.1 经历本体

57,117 段 / 20,028 人，人均 2.85 段；但分布极不均，12,427 人有 ≥2 段，7,601 人只有 1 段。只有一段的人无法识别流动，这是事件量偏低的第一个原因。

#### C.4.2 性质判定

学术 45,890（80.3%）、产业 2,400（4.2%）、未知 8,827（15.45%）。产业占比极低，说明库内学者以高校/院所为主，产业侧样本天然稀缺；这也意味着「学界→产业」的事件数会被系统性低估。

#### C.4.3 时间维

49,637 段可定年，7,480 段缺起始年。缺年段主要集中在英文机构（外文履历常只写年份区间或「至今」），这会让早期事件偏向国内机构。

#### C.4.4 空间维

工商底册命中 456 段（0.8%），因为底册只收企业，高校/院所/海外机构不在其中。口径要求的三张对齐表（工商、科研机构、海外高校）本批只接了第一张，这是空间维不可用的直接原因。

#### C.4.5 方法—数据对照矩阵

| 方法 | 需要的输入 | 库内状态 | 可行性 |
|---|---|---|---|
| A 履历事件 | 机构 ID、起止年、类型 | 缺 ID 与类型 | 部分可行 |
| B 署名变迁 | 全量署名 + 单位规范化 | 62,002 行，未规范 | 不可行 |
| C 文本挖掘 | 职级、履历文本 | 无 | 不可行 |
| D 项目迁移 | 负责人跨年链 | 无 | 不可行 |

### C.5 推荐构建方案（工程可执行）

1. 以经历表为唯一事件源，核心池按 P70 切；
2. 性质判定用「底册行业码优先 + 中英文关键词兜底」，未知段断链；
3. 输出两方向年序列、事件数与人数、burst 的分子分母；
4. 空间维在接入科研机构与海外高校主数据前不交付。

### C.6 风险与残余不确定性

- 产业侧样本只占 4.2%，「学界→产业」会被低估；
- 未知段 15.45%，断链会漏事件，但不会造方向；
- 82 次事件的年序列波动极大，任何趋势判断都不稳；
- 预警等级由个位数决定，不可对外。

### C.7 可行性总判（完整版结论）

方法族 A 在**方向与时间**两维可落地，**空间维**因主数据缺位不可落地，故判「部分支持」。补齐三张机构对齐表并把起始年回填到 95% 以上后，可升级为「完全转换支持」，口径与阈值无需改动。
