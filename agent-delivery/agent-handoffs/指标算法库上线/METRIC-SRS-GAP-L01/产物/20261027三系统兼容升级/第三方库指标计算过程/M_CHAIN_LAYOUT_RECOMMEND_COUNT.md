> **数据源口径**：本件支持度按「开发库 + 三方库（gkx，183.240.141.251:3318 只读）」评估，仅排除 `demo_*`；本机开发库事实面为空壳（`gkxlumenx_dwd/ods/ads` 逐表实测非空 0 张），实际取数面为 gkx。

判「部分支持」而不是「完全不支持」，是因为本件有一条完整的结构侧可算路径：954 个叶级环节、每叶的全国与深圳企业数、12 条链的中位门槛都在 gkx 快照里，把「全国有规模、属关键叶、深圳相对缺位」写成三条布尔规则后，可以逐环节复算、逐链汇总，给出 251 这个可核计数。

判「部分支持」而不是「完全转换支持」，原因不是「数据量不够」，而是**对象与语义对不上**：

1. calc-logic v0.2.0 的对象是「单链发展方案条数」——`object_type='chain'`，一条链可以有 N 个方案，值是模型写进 `industry_chain_metric_fact` 的标量。gkx 侧这张表不存在，live 侧 0 行，方案条数不可得。
2. 王惠 V2 的对象是「产业」——先算布局优先级评分，再把 ≥60 分或高于深圳均值的产业计为推荐，最多 12 条链。它的四个指标（增长率、市场占有率、研发强度、产业规模）依赖营收与研发数据；gkx 的 `annual_fin_pool_20261021.json` 只有 91 个主体、其中 2 个有财务值，无法支撑 1,714,457 家企业的链级汇总。
3. 本件的对象是「叶级环节」——954 个叶里筛出 251 个建议布局的环节。它与「方案条数」和「推荐产业数」都不是同一个计数对象。

三句话合起来说明：不是算不出数，而是算出的数不是原指标的数。所以档位只能是部分支持，且必须在页面与产物里同时标注「环节数，不是方案条数」。

### 0.3 一句话结论

按 $R_1 \land R_2 \land R_3$（全国 ≥ 10 家、≥ 该链中位、深圳 0 家或占比 < 7.952%）筛 954 个叶级环节，得 **251 个**建议布局环节（Tier A 空白强 22、Tier B 空白中 27、Tier C 单点缺口 202），占全部叶的 **26.31%**；生物医药 70 个最多、具身智能 4 个最少。原模型的方案条数与优先级评分不可得，本件是结构侧清单，不是发布快照直读。

## 摘要

「产业链重点布局推荐数」在 calc-logic v0.2.0 里是一个**读表指标**：按 `chain_id` 从 `industry_chain_metric_fact` 取 `metric_id='M_CHAIN_LAYOUT_RECOMMEND_COUNT'`、`object_type='chain'` 的最新发布快照，`metric_value` 就是该链的发展方案条数。2026-10-14 徐滕强拍板方案A，明确「统计对象 = 单链发展方案条数」，并废止旧稿「全局被推荐链数」的口径。

这条读表路径在 gkx 侧不存在。280 张表里 layout / recommend / node_scoring / chain_stage / priority 关键词全部 0 命中，链相关表只有 `dwd_industry_chain_info`（1,273 节点）与 `dwd_industry_chain_news_info`（98,103 个链×年单元）。live 开发库侧 `industry_chain_metric_fact` 0 行、`industry_chain_model_result_detail` 0 行；`chain_node_scoring` 只有 41 行、`chain_panorama_nodes` 41 行，都是 8 条未来产业样例的节点，与 12 链不匹配。两库都没有可直读的结果面。

王惠 V2 给了另一条路：用营收增长率、市场占有率、研发强度、产业规模四个指标算布局优先级评分，≥60 分或高于深圳均值即推荐。这条路在本库也走不通：四个指标都要营收与研发数据，gkx 的年度财务快照 `annual_fin_pool_20261021.json` 只有 91 个主体、其中 2 个有财务值，链级汇总会变成「少数上市公司代表整条链」。因此 V2 的阈值法只能作为口径参照，不能作为取数路径。

本件因此改写为一条**结构侧可复算规则**：对 954 个叶级环节，先看全国规模（≥10 家），再看是否属关键叶（≥该链正样本叶的中位数），最后看深圳覆盖（0 家，或深圳占全国比低于 7.952% 的全国基准）。三条同时满足记一个建议布局环节。结果是 251 个，其中空白 49 个（22 个全国 ≥50 家的强空白 + 27 个 10—49 家的中空白）、单点缺口 202 个。

这个数能逐环节追溯：产物 `recommended` 数组给出每个环节的链码、环节码、环节名、全国企业数、深圳企业数、深圳占比、档位与是否关键叶。审计时任取一行都能回到链树与叶级企业分布快照重算，不需要模型。

必须说清三条限制。其一，**计数对象不同**：本件数的是「环节」，calc-logic 数的是「方案」，王惠数的是「产业」；251 不能当方案条数用。其二，**规则是本件自拟**：三条布尔条件与两个档位阈值（50、10）都没有模型依据，只是可解释的结构筛选。其三，**深圳判定是登记地口径**：信用码第 3—6 位 4403，跨市经营会偏差。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**产业链分析 → 深圳产业发展分析 → 布局推荐**，页面形态是深圳产业链页的「重点布局」数字卡，点开是一张按链分组的推荐环节清单，可下钻到环节详情与企业列表。

| 项目 | 内容 |
|---|---|
| 功能路径 | 产业链分析 → 深圳产业发展分析 → 布局推荐 |
| 页面载体 | 深圳产业链页·重点布局卡；链详情页·推荐环节列表 |
| 输出形态 | 每链一个整数；下钻为推荐环节清单 |
| 更新频率 | 周（calc-logic 标注，随布局模型跑批） |
| 粒度 | 链（12 条）→ 环节（954 叶，其中 251 个被推荐） |
| 关联 Q | 无（calc-logic 的「关联Q编号」为 `-`） |

同族三件要分清：本件是「建议布局哪些环节」，`M_CHAIN_SZ_PROBLEM_COUNT` 是「深圳缺哪些环节」，`M_CHAIN_SZ_KEY_NODE_COVERAGE` 是「关键环节覆盖率」。三者共用链树与叶级企业分布，但判定方向不同：问题件只判「深圳 0—2 家」，本件还要求「属关键叶」且「深圳占比低于基准」；覆盖率件看「关键叶有没有企业」，不筛规模。页面上三个数并排时，用户最容易问「为什么问题 231、布局推荐 251」——因为问题件允许 1—2 家算问题，本件把 1—7.951% 的缺口也算进来，两个集合有交集但不相等。

### 1.2 为什么需要这个指标

第一个用途是**布局清单**。深圳的产业政策需要一张「全国有规模、深圳明显薄弱」的环节名单，251 个环节就是这张名单的底表；没有它，布局建议只能靠人工研判。

第二个用途是**分档**。同样是缺口，深圳 0 家且全国 ≥50 家的环节（Tier A，22 个）与深圳已有 1—2 家但占比很低的环节（Tier C，202 个）优先级不同。分档让页面能先推 22 个强空白，再推 27 个中空白，最后推 202 个补强项。

第三个用途是**链级比较**。12 条链的推荐数从 4 到 70，直接反映各链的结构缺口密度；生物医药 70 个（47.95% 的叶被推荐）、具身智能 4 个（6.9%），这个排序与「哪些链的本地供应最薄」高度相关。

### 1.3 需求文档是否给出定义方法

calc-logic 给的是**读表口径**，不是计算公式：

```sql
SELECT f.metric_value AS layout_recommend_cnt
FROM industry_chain_metric_fact f
WHERE f.is_deleted = 0 AND f.publish_status = 'published'
  AND f.metric_id = 'M_CHAIN_LAYOUT_RECOMMEND_COUNT'
  AND f.object_type = 'chain' AND f.object_id = :chain_code
ORDER BY f.stat_period DESC, f.id DESC
LIMIT 1;
```

它明写「2026-10-14 human:徐滕强 拍板方案A：统计对象 = 单链发展方案条数（`object_type='chain'`，带链参数），贴 demo 页面『发展方案 N 项』语义。旧稿 `COUNT(DISTINCT chain_id) WHERE 评分>=阈值`（全局被推荐链数）废止——阈值是查询参数不是口径，模型输出已固化在发布快照」。

这段话有三层信息。第一，指标要的是**方案条数**，不是环节数；第二，阈值不是口径，模型已经把推荐结果固化；第三，旧稿的「全局链数」已被明确废止。本件严格遵守第一层与第二层：不去猜阈值，也不把「12 条链里有几条被推荐」当答案。

王惠 V2 是另一套方法：四指标标准化 → 产业增长维度（增长率、市场占有率）与产业竞争力维度（研发强度、产业规模）→ 加权得分布局优先级评分 → ≥60 分或高于深圳均值即推荐。它的对象是「产业」，输出最多 12 条。两套口径的差别不是版本新旧，而是**计数对象**不同：一个数方案，一个数产业。本件两个都不数，数环节，所以必须在正文把差异写透，不能让读者以为 251 是方案条数。

### 1.4 类似指标权威机构构建方法可行性

「重点布局推荐」在实践中有五种做法：

| 方法族 | 代表机构/实践 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 模型方案读表 | calc-logic v0.2.0 | 模型输出方案条数，落 metric_fact | **最高（原口径）** |
| B 评分阈值法 | 王惠 V2 | 四指标评分 ≥60 或高于均值 | 高（对象是产业） |
| C 结构缺口法 | 工信部「产业基础再造」 | 按环节企业数/覆盖缺口筛选 | 高（本件采用） |
| D 投入产出法 | 区域投入产出表 | 中间品净流入率 | 低（无投入产出表） |
| E 专家研判 | 地方产业链专班 | 专家打分/访谈 | 低（不可复现） |

A 族是原口径，但结果面两库都没有；B 族需要营收与研发，gkx 覆盖不足（91 个主体、2 个有值）；D 族缺投入产出表；E 族不可复现。C 族是唯一能在现有快照上闭环的路：它不判断「该不该布局」，只判断「这个环节全国有规模、深圳覆盖薄」，因此适合做布局清单的底表。

C 族的局限也要写明：它没有「产业增长」「市场占有率」「研发强度」「产业规模」四个维度，因此不能复现王惠的评分，也不能回答「布局优先级多高」。它只回答「哪些环节值得看」。

### 1.6 推测原意与推测定义

推测原意是：**深圳应该优先布局哪些产业环节**。它要的是一张可执行的清单，而不是一个抽象的优先级分数；分数可以后补，清单必须先有。

据此给出主定义与两个对照定义：

$$
L_{rec} = \#\{v \in L : N_v \ge 10 \land N_v \ge \mathrm{med}(N_{c(v)}) \land (S_v = 0 \lor \frac{S_v}{N_v} < 7.952\%)\}
$$

$$
L_{blank} = \#\{v \in L_{rec} : S_v = 0\}, \qquad
L_{gap} = \#\{v \in L_{rec} : S_v > 0\}
$$

其中 $L$ 为 954 个叶级环节，$N_v$ 为环节 $v$ 的全国链属企业数，$S_v$ 为深圳企业数，$\mathrm{med}(N_{c(v)})$ 为环节所属链的正样本叶企业数中位数，7.952% 为深圳挂链 136,326 占全国 1,714,457 的份额。

本件交付 $L_{rec}=251$、$L_{blank}=49$、$L_{gap}=202$。三档定义为：

| 档 | 条件 | 数量 | 含义 |
|---|---|---:|---|
| Tier A | $S_v=0 \land N_v \ge 50$ | 22 | 全国有规模、深圳完全空白 |
| Tier B | $S_v=0 \land 10 \le N_v < 50$ | 27 | 全国中等规模、深圳空白 |
| Tier C | $S_v>0 \land S_v/N_v < 7.952\% \land N_v \ge 10$ | 202 | 深圳有企业但占比低于全国基准 |

依赖维度如下：

| 代号 | 依赖维度 | 类型 | 本件实测 |
|---|---|---|---|
| D1 | 链树与叶级划分 | 核心 | 可得，1,273 节点 / 954 叶 |
| D2 | 叶级全国企业数 | 核心 | 可得，916 叶有正企业数 |
| D3 | 叶级深圳企业数 | 核心 | 可得，按信用码 4403 切 |
| D4 | 方案条数（模型） | 语义 | 不可得（结果面两库均无） |
| D5 | 布局优先级评分 | 语义 | 不可得（四指标无数据） |
| D6 | 推荐权重/档位阈值 | 语义 | 不可得（模型参数未给出） |
| D7 | 营收/研发 | 佐证 | 极弱（91 主体、2 有值） |

D4—D6 的缺失决定档位；D1—D3 的齐备决定「不是完全不支持」。

## 二、计算过程

### 2.1 总体思路与数据流

整条链路零 DB，五步完成：定母体、算门槛、判三条规则、分档汇总、敏感性。

| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 1 | `chain_tree_20261021.json` | 取 12 链根、按父子边取 954 叶 | 环节集合 |
| 2 | `chain_stage_leaf_20261021.json` | 取 `leaf_firm_counts` 与 `cell_leaf_firm_counts['<链>\|深圳市']` | 每叶全国/深圳数 |
| 3 | 步骤 2 | 逐链算正样本叶中位数 | 12 个门槛 |
| 4 | 步骤 2+3 | 判 $R_1 \land R_2 \land R_3$、分 A/B/C | 251 个环节 |
| 5 | 步骤 2 | 换全国门槛重算 | 敏感性 4 档 |

关键在第一步。链树的 `level` 列全为 0、`node_company_count` 全为 0（已在 `M_ENT_KEY_NODE_COUNT` 披露），所以叶必须由「没有子节点的节点」推出来，不能读 `level`。用父子边推出的叶是 954 个，与全批一致。**本件没有任何企业规模维度**：`node_company_count` 为 0，不能用它给环节加权，也不能假装链树自带规模。

### 2.2 步骤 1｜母体与统一口径

| 量 | 值 | 口径 |
|---|---:|---|
| 链树节点 | 1,273 | `dwd_industry_chain_info` 全表 |
| 链根 | 12 | 7 位 `INB` 码 |
| 内部节点 | 307 | 有子节点的非根节点 |
| 叶级环节 | 954 | 无子节点的非根节点 |
| 有正企业数的叶 | 916 | 全国企业数 > 0 |
| 清洗后链属企业 | 1,714,457 | 18 位信用码正则过筛、按信用码去重 |
| 深圳挂链 | 136,326 | `credit_code[2:6]='4403'` 的挂接 |
| 全国基准 | 7.952% | 136,326 / 1,714,457 |

深圳切片取 `credit_code[2:6]='4403'`，是登记地口径。挂接是「企业—链」对，多链企业按链各计一次，所以 136,326 是挂链次数，不是去重企业数；12 条链的 `sz_memberships` 之和等于 136,326（`checks` 外可逐行相加验证）。

叶级深圳挂接与链级深圳挂接不是同一层：叶级只统计挂在叶节点上的企业，挂在链根或内部节点的企业不进叶级。产物 `by_chain[].sz_sum` 是叶级合计，可能大于也可能小于 `sz_memberships`——例如生物医药叶级 1,293、链级 1,231，软件叶级 33,520、链级 60,045。两个数不能互相替代，也不能相加。

### 2.3 步骤 2｜三条布尔规则

规则逐字如下：

| 条件 | 布尔表达式 | 含义 |
|---|---|---|
| R1 全国有规模 | $N_v \ge 10$ | 全国不到 10 家的环节，不进入布局清单 |
| R2 属关键叶 | $N_v \ge \mathrm{med}(N_{c(v)})$ | 该链正样本叶企业数的中位数 |
| R3 深圳缺位 | $S_v = 0 \lor S_v/N_v < 7.952\%$ | 空白，或占比低于全国基准 |
| 推荐 | $R1 \land R2 \land R3$ | 记 1 个推荐环节 |

三个条件各有理由。R1 去掉「全国都只有几家」的碎片环节；R2 去掉「低于该链中位规模」的长尾环节，避免把每条链的几十个小叶都算进来；R3 用全国基准而不是「深圳 0 家」，因为深圳有 1—2 家但占比远低于全国份额，同样是布局缺口。

12 条链的中位门槛差异很大：低空经济 8 家、集成电路 11 家、软件与人工智能 122 家、数字创意 764 家。门槛越高，关键叶越窄，推荐数越少。这不是链之间的偏见，而是各链环节粒度不同：数字创意的叶级企业数普遍很大，中位数自然高。

### 2.4 步骤 3｜分档

| 档 | 条件 | 数量 | 处理建议 |
|---|---|---:|---|
| Tier A | $S_v=0 \land N_v \ge 50$ | 22 | 优先招引，全国有足够标的 |
| Tier B | $S_v=0 \land 10 \le N_v < 50$ | 27 | 次优先，标的较少 |
| Tier C | $S_v>0 \land S_v/N_v<7.952\%$ | 202 | 补强现有企业，提升本地份额 |

A 与 B 的界线 50 家是本件自拟：全国 50 家以上说明该环节有足够的可招引标的；10—49 家说明有标的但不多。C 档不再按占比细分，因为 202 个环节的占比从 0.177% 到 7.951% 连续分布，再切一刀没有自然断点。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| 方案条数 | 无法复现原指标 | 环节清单替代 | 模型跑批 + 落 metric_fact |
| 布局优先级评分 | 无优先级排序 | 用 A/B/C 结构分档 | 补四指标数据 + 权重 |
| 推荐权重/档位阈值 | 档位只能自拟 | 50/10 两个阈值 | 模型参数文档 |
| 营收/研发 | V2 路线不可行 | 不走 V2 | 补年报覆盖 |
| 环节级企业规模 | 无法按规模加权 | 只用企业数 | 修 `node_company_count` |
| 实际经营地 | 深圳判定偏窄 | 信用码 4403 | 经营地字段 |
| 环节政策归属 | 无法做政策匹配 | 不纳入 | node 级政策标注 |

### 4.2 逐条影响

**方案条数缺失是根缺口。** 它决定了本件不可能复现 calc-logic 的原语义——不是规则不会写，而是没有模型输出。这条缺口也解释了为什么档位是部分支持：完全转换支持要求「现在就能加工出该指标」，而方案条数不是加工能得到的，它需要模型跑批。

**布局优先级评分缺失影响排序。** 本件的 A/B/C 是结构分档，不是优先级评分；A 档不一定比 C 档「更重要」，只是「深圳更空」。页面若要按优先级排序，需要模型分或甲方权重。

**营收/研发缺失堵死 V2 路线。** 91 个主体、2 个有值，连「深圳全产业均值」都算不出来，更不用说链级增长率与研发强度。这条缺口不是补几张年报能解决的，需要全量企业的年度财务数据。

**环节级企业规模缺失影响加权。** `node_company_count` 全为 0，`level` 全为 0，链树没有规模维度；本件只能用叶级企业数（来自标签表）代替，不能用链树自带的规模。

**实际经营地缺失影响深圳判定。** 信用码 4403 只覆盖注册地在深圳的主体；在深圳设厂但注册在东莞、惠州的企业不会被计入，反之亦然。方向不确定，幅度不可量化。

### 4.3 明确不做什么（禁止的替代）

- 不把 live 的 8 行 `-demo` 样例当 12 链结果——链维、粒度、数值三者都不匹配。
- 不把 251 说成「方案条数」——它是环节数，对象不同，页面必须标注。
- 不把 A/B/C 说成「布局优先级」——它是结构分档，不是模型评分。
- 不用营收快照硬算 V2 评分——91 个主体、2 个有值，代表性不成立。
- 不用 `level` 或 `node_company_count` 做层级/规模加权——两列全为 0。
- 不把空白叶全算进推荐——R1 与 R2 会挡掉 241 个碎片环节。
- 不引用 `demo_*` 表——正文与产物均无 demo 表名作为数据来源。
- 不把演示库的造数结果面当数据来源：`industry_chain_metric_fact` 在 gkx 侧不存在、live 侧 0 行，引用它只能用于说明「读表路径断了」。

| 补齐条件 | 口径变化 | 档位变化 |
|---|---|---|
| 模型跑批并落 metric_fact | 可直读方案条数 | 部分支持 → 完全直接支持 |
| 补布局优先级评分 | 可按分排序、按阈值筛 | 部分支持 → 完全转换支持 |

## 五、结论与发布建议

结论分三层。第一层是**可发布的结构清单**：251 个建议布局环节（A 22、B 27、C 202），可按 12 链汇总、可逐环节下钻，规则可复算。第二层是**不可发布的模型语义**：方案条数、布局优先级评分、推荐档位都不在，任何「模型推荐了 N 项」的表述都超出本件能力。第三层是**使用边界**：本件数的是环节，不是方案；A 档是「深圳空白」，不是「深圳最该布局」——后者还要看战略重要性、产业链带动、政策约束，本件没有这些输入。

发布建议：深圳产业链页的「重点布局」卡可以先上 251，但必须在同屏注明「环节数、结构侧替代口径、非方案条数」；链详情页的推荐清单可以直接用 `recommended` 数组，按档位与全国规模排序，A 档置顶。不要把 251 与问题件的 231 并列成「问题 vs 布局」漏斗——两个集合不是包含关系。

对甲方的三条明示：其一，方案条数需模型跑批后才能出，本件不能替代模型验收；其二，A/B/C 阈值（50、10）是本件自拟，不能写进考核；其三，深圳判定是登记地口径，跨市经营会偏差。

## 附录 F 口径问答

**问：251 是「布局方案数」吗？**

答：不是。它是「建议布局的叶级环节数」。calc-logic 的方案条数是模型输出，一条链可以有 N 个方案；本件数的是环节，对象不同。

**问：为什么生物医药有 70 个，具身智能只有 4 个？**

答：生物医药有 146 个叶、中位门槛 21.5 家，环节粒度细且深圳覆盖薄；具身智能只有 58 个叶、深圳挂链占比 20.23%（1,647/8,140），大部分环节的占比高于 7.952% 基准，所以推荐少。

**问：A/B/C 是模型档位吗？**

答：不是。它们是本件按「深圳是否空白」与「全国规模」自拟的结构分档，阈值 50/10 没有模型依据。模型档位（`priority_level`）不可得。

**问：为什么不用王惠 V2 的四指标评分？**

答：四指标都要营收/研发，gkx 的财务快照只有 91 个主体、2 个有值，链级汇总没有代表性。V2 只能作口径参照。

**问：7.952% 基准可以改吗？**

答：可以，但改基准会直接改 C 档规模：基准降到 0，推荐数从 251 降到 49。基准是口径选择，不是自然常数，必须在页面标注。
