## 摘要

这条指标不是一个「分数」，而是一组基础统计：人才在哪儿（省/市）、来自哪些机构、做什么方向、什么学历、哪一年毕业。需求在「人才分布图」与「人才洞察分析」里要的就是这些分组计数，本文按四族交付：D1 属地分布、D2 机构分布、D3 研究方向分布、D4 学历与毕业年结构。

四族的规模分别是：D1 覆盖 21,316 条学者记录、17,761 条可归属到省级（83.32%）；D2 去重出 2,108 个机构、其中 554 个能对上全国高校名录；D3 展开 97,249 个去重方向标签、命中 163,470 次；D4 有 43,766 行学历记录、覆盖 20,025 名学者、博士占 37.5%。这些数字都能在本机一次跑出来，且不需要发一条 SQL。

但「能出数」不等于「能切片」。三张子表（履历 57,117 行、学历 43,766 行、方向 20,030 行）的 `scholar_id` 与主档只有 9.3% 的交集，且子表没有姓名列可做二次桥接，因此「某省博士学历学者的方向分布」这种交叉表在当前数据上做不出来，只能做单族分组。这一点必须在页面上写清楚，否则用户点开「北京市 × 博士 × 人工智能」会看到空表。

另有两处必须提前说明的形态问题。第一，D4 的年度序列从 2015 年的 1,615 行一路降到 2024 年的 339 行，看起来像「人才供给断崖」，实际是「存量学者的毕业年回溯 + 采集年份截断」的必然结果，不能当供给趋势发布。第二，D1 的省级归属有 2,760 条无法识别（13.25%），其中 308 条是海外机构，其余是机构名不含地名且不在高校名录/企业底册里，这部分在页面上应归入「未识别」而不是「其他省」。

结论：四族单维统计可直接发布，交叉切片与增长率不可发布。判「部分支持」的理由不是「数字不够」，而是「维度之间连不起来」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技人才态势 → 全球领域人才态势 → 人才分布图**（需求 1.1.1.1.4.3.1.1，第 1467—1535 行）与 **人才洞察分析**（1.1.1.1.4.3.1.2，第 1537—1573 行）。

需求原文的关键句有三处：「用户可以在地图上查看各国家或地区的人才分布概览，通过颜色深浅或热力显示不同地区的人才密度」「支持点击地区或城市，弹出该地具体人才分布详情，包括行业、学历、类型等统计数据」「允许用户由全球视角逐级放大至各大洲、国家或城市，查看不同地区的科技人才分布及结构变化」。三句话对应三类计数：**区域计数**、**区域 × 属性计数**、**区域 × 时间计数**。

| 页面任务 | 对指标的要求 |
|---|---|
| 热力图 | 省/市粒度的人才数 |
| 城市详情弹窗 | 机构数、学历结构、方向结构 |
| 层级下钻 | 全球→国家→省→市，每级都要有分母 |
| 结构变化 | 需要年份列 |
| 产研对比 | 需要「高校 / 企业」机构类型 |

### 1.2 为什么需要「人才分布与结构基础统计」这个指标

所有人才类指标都需要一个分母。学术力指数回答「谁强」，引进推荐回答「该挖谁」，但没有「人在哪儿、在什么机构、做什么方向」这层底表，前两类指标就只是榜单，无法落到地图与结构图上。D1—D4 就是这层底表。

第二个理由是它是唯一能支撑「结构」叙述的产物。需求反复出现「结构变化」「产研结构」「学历结构」三个词，结构叙述的前提是分组计数；没有分组计数，页面上只能放单个人的画像，放不出「深圳博士占比多少」这种句子。

第三个理由是它最容易把「存量」说成「流量」。学历表的毕业年序列看起来像年度供给曲线，实际是「今天在库的学者，当年什么时候毕业」，越靠近采集年，样本越少是必然的。本文把这条写进 §2.6 与 §4.3，是因为这类误读一旦进入政策叙事，纠正成本极高。

### 1.3 需求文档是否给出定义方法

**需求给了统计对象与展示形态，没给分组口径、没给属地判定规则、没给时间窗；注册表 seed 只写「以需规文本为准」，公式未签（见 §0.4）。**

原文写「包括行业、学历、类型等统计数据」，但没有写：省/市按机构所在地还是按学者籍贯、机构类型怎么分（高校/院所/企业）、学历按最高学历还是按全部学历、方向标签怎么切分（分号还是逗号）、年份取毕业年还是入职年。这五个口径决策本文都做了选择，并在 §2.2 逐条说明理由。

本文的选择是：属地按**现机构所在地**；机构类型按**高校名录 / 企业法人 / 未识别**三分；学历按**全部学历行**计数（不做最高学历去重）；方向按**分号切分后展开**；年份取**毕业年**并只对完整年出数。

### 1.6 推测原意与推测定义

**推测原意**：产品要一张能下钻的人才地图，加几张结构卡。它服务「哪里人多、哪里博士多、哪里企业人才多」这类问题，不服务个体评价，也不服务精确的人口统计。

**推测定义（本文采用，四族并列，不加权）**：

> **D1 属地分布**：对学者 $i$，由现机构名 $o_i$ 解析出省 $p_i$、市 $c_i$，统计 $n(p)=\sum_i \mathbf{1}[p_i=p]$。
> **D2 机构分布**：对去重机构名 $o$，统计学者数 $n(o)$，并按高校名录/企业法人/未识别三分。
> **D3 方向分布**：把 `fields` 按分号切分为标签集合 $T_i$，统计 $n(t)=\sum_i \mathbf{1}[t\in T_i]$。
> **D4 学历结构**：按学位 $d$ 与毕业年 $y$ 统计行数 $n(d,y)$，只对完整年出数。

**为什么不做加权合成**：四族回答的是四个不同问题，合成一个「人才结构指数」既没有需求依据，也会把「人多」和「学历高」混成一个不可解释的数。基础统计的价值在于可加、可交叉、可核对，一旦加权就失去了这三条。

**为什么 D4 只出完整年**：2025 年 208 行、2026 年 23 行是采集截断的残年，把它们放进趋势线会让最后两年出现「断崖」。本文只取 2015 与 2024 两个完整年做对比，并在 `base_years_used` 里写死 `[2015, 2024]`、`base_years_missing` 写空数组——不是没有缺失年，而是这两年之间每年都有数据，缺失发生在 2025/2026 的**完整性**上，已在 `partial_years` 里单列。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是本文 §1.6 的自建口径。降级发生在两处：① 交叉切片不可做（子表 ID 与主档 9.3% 可连），所以只交四张单族表，不交「省 × 学历 × 方向」的三维立方；② 增长率不可算（D2/D3 无年份列，D1 无建档年），所以只交截面，不交环比。

本文没有做的降级包括：没有用毕业年当「人才流入年」推算省域增长、没有用机构数变化推算「机构增长」、没有把 2025/2026 的残年按比例放大成全年。这三件事都能让页面「有趋势线」，但都会在数据层面制造假信号。

### 2.2 口径拆解：对象、集合、归一

**对象**：D1/D2 的对象是「学者记录」（21,316 条），D3 的对象是「方向标签命中」（163,470 次），D4 的对象是「学历行」（43,766 行）。四族的分母不同，页面不能把它们放进同一个饼图。

**集合**：D1 的分母是全池 21,316 条；D2 的分母是去重机构 2,108 个；D3 的分母是 19,514 名有方向标签的学者（另 1,802 条无标签）；D4 的分母是 20,025 名有学历记录的学者（另 1,291 条无学历记录）。

**属地判定**：优先级为「高校名录精确匹配 → 高校名录前缀匹配 → 城市关键词 → 企业底册精确匹配 → 企业底册前缀匹配 → 海外模式 → 未识别」。实测命中分布为：高校精确 16,033、高校前缀 957、城市关键词 663、企业底册精确 107、企业底册前缀 1、海外 308、未识别 2,760。这个顺序的理由是「精确优先、底册次之、关键词兜底」，避免「深圳」这种词把「深圳大学」和「深圳某公司」混到同一级。

**机构分类**：高校名录（3,501 条 `dwd_org_heis_info`）命中 554 个机构，标「全国普通高等学校名单」；机构名含公司/集团/有限/股份等字样标「企业/其他法人」44 个；能属地但不在名录的 364 个标「未入名录（机构名可属地）」；剩余 1,146 个标「未识别」。

**方向切分**：`fields` 用分号（中英文分号）切分后去空白，展开成标签集合。19,331 名学者的标签数 ≥2（99.06%），说明这一列是多值字段，不能整串当一个标签。

**学历归一**：`degree_zh` 与 `degree_en` 双语归一，`degree_zh` 空的 9,825 行里有 7,789 行能从 `degree_en` 恢复（博士/硕士/学士/其他），剩余 2,036 行标「未知」。归一后的五类是博士 16,424、硕士 8,996、学士 8,222、其他 8,088、未知 2,036，加总 43,766 与行数相等。

| 1 | 企业底册 | `_snapshots21/base_20261021.json`（189,116 行） | 可算 |
| 1 | 研究方向 | `dwd_scholar_research_direction.fields`（20,030 行） | 可算（单族） |
| 1 | 学历 | `dwd_scholar_education_background`（43,766 行） | 可算（单族） |
| 2 | 子表 ↔ 主档 | `scholar_id` 交集 | **断在第 2 跳**：9.3% |
| 2 | 年份 × 属地 | 子表无年份 + 主档无建档年 | **断在第 2 跳**：无年份列 |

「两跳停」的含义是：本文只做「主档自带的机构名 + 子表自身的分组」，不再尝试「子表 JOIN 主档再按省切片」。因为这条 JOIN 的命中率只有 9.3%，做出来的交叉表会有 90% 的样本掉在地上，而页面上看不出这个缺口。

### 2.4 算路 / SQL

本指标**零 SQL**：D1/D2 读 `_snapshots21/probe_a26_20261022.json` 与 `base_20261021.json`，D3/D4 读 `_snapshots21/probe_talent21_20261022.json`（履历 57,117 行、学历 43,766 行、方向 20,030 行、院士 112 行、高校名录 3,501 行）。

```text

SELECT scholar_id, school_name, degree_zh, degree_en, start_date, end_date, major
```

本地计算：属地解析（高校名录 → 底册 → 关键词 → 海外）→ 省/市计数 → 机构去重与分类 → 标签展开 → 学位归一 × 毕业年计数。耗时 1.6 秒。

### 2.6 结果解读

**D1 属地**：17,761 条可归属到 32 个省级单元（含港澳台按名录归属）。省级前五为北京 2,934、江苏 1,991、上海 1,604、广东 1,221、湖北 1,109；城市前五为北京 2,934、上海 1,604、南京 1,341、武汉 1,059、广州 930。广东 1,221 人里深圳占多少、广州占多少，取决于机构名是否含城市名，因此「广东省」与「深圳市」两个口径在页面上必须分开写，不能相加。

**D2 机构**：2,108 个去重机构，学者数前五为中国科学院 728、上海交通大学 703、北京大学 364、清华大学 323、浙江大学 291。机构类型分布为高校名录 554、未入名录但可属地 364、企业/其他法人 44、未识别 1,146——**未识别占 54.4%**，这是 D2 最需要披露的一条：一半以上的机构名无法判断类型，页面上「产研结构」只能覆盖 44 家企业 + 554 所高校，不能宣称「全量产研对比」。

**D3 方向**：19,514 名学者贡献 163,470 次标签命中、97,249 个去重标签。前五为 AI for Life Science 860、Electrocatalysis 335、Medical Image Analysis 298、Photocatalysis 210、Computer Vision 196。标签是英文自由文本，同一概念可能有多种写法（如 ML 与 Machine Learning 并存），本文不做同义词合并，只在 §4.1 列为修复项。

**D4 学历**：43,766 行，博士 16,424（37.53%）、硕士 8,996（20.55%）、学士 8,222（18.79%）、其他 8,088（18.48%）、未知 2,036（4.65%）。毕业年序列 2015 年 1,615 行（博士 635）、2024 年 339 行（博士 339？不，博士 339、总 494），2020 年后逐年下降。**这不是供给下降**：它统计的是「今天在库的学者当年何时毕业」，越早毕业的人越可能已经功成名就、越容易被收录，越晚毕业的人越可能还没进入这个库；再加上采集年份截断，2025/2026 必然残年。因此这条序列只能当「存量年龄结构」读，不能当「年度毕业生供给」读。

**交叉不可做**：履历 57,117 行与主档交集 1,856、学历 43,766 行交集 1,853、方向 20,030 行交集 1,853，均在 9.3% 左右。这意味着「北京市 × 博士 × 人工智能」这类交叉表只能覆盖 9.3% 的样本，且这 9.3% 不是随机子集（ID 域偏移可能集中在某个批次），不能外推。

### 4.2 对结论的影响边界

缺失改变的是**可切片的维度数**，不是单族计数的可信度。四张单族表都能加总回原表、都能复核，因此可以发布；但任何「A × B」的交叉表都只能覆盖 9.3% 的样本，不能发布。这个边界必须在页面上以「暂不支持交叉筛选」的形式写出来，而不是让用户点了筛选之后看到空表。

D4 的年度序列还改变了「结构变化」这句话的含义：它只能读成「存量学者的毕业年代结构」，不能读成「年度人才供给」。如果产品一定要供给趋势，必须换数据源（毕业生就业数据库、招聘平台流量），而不是在这条序列上做外推。

### 4.3 不可外推的三件事

第一，不能把 D1 的省级计数当「全国人才分布」。它只覆盖 `dwd_scholar` 里的学者，且 12.95% 无法属地；企业研发人员、技能人才、海外华人都不在内。

第二，不能把 D4 的毕业年下降当「人才供给下降」。这是存量回溯 + 采集截断的合成结果，2015 年 1,615 行不代表 2015 年毕业的人多，只代表「2015 年毕业且今天还在库」的人多。

第三，不能把 D2 的机构数当「机构总量」。2,108 个机构是「有学者记录的机构」，未识别 1,146 个说明一半以上的机构名无法判断类型；深圳的国家高新技术企业有 2.4 万家，这里的 44 家企业只是冰山一角。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

**calc-logic 无实现，registry seed 有身份但未给字段口径。** calc-logic 目录里没有 `M_TALENT_BASE_98_1`；registry seed 只写「对应算法库 SRS ALGO-TALENT-BASE-98，统计窗口与对象范围以需规文本为准」，`metric-srs-map.yaml` 指向 SRS-02 seq 243（见 §0.4）；需求原文只给了「区域分布概览」「城市详情」「学历/行业/类型统计」三类展示要求。因此本文没有「王惠原方法」可还原，只能把需求原文当上游口径，把四族定义与五条口径决策（属地优先级、机构三分、学历全量、方向展开、完整年）显式写出。

### 5.2 新方法概述

新方法 = 四族分组计数 + 属地七级判定 + 机构四分 + 标签展开 + 双语学位归一 + 完整年门槛，输出四张表加 `id_gap` 与 `base_years`。不加权、不合成、不出增长率。

### 5.3 逐维对照表

| 维度 | 需求原文 | 本文实现 | 差异与理由 |
|---|---|---|---|
| 区域分布 | 国家/省/市热力 | 省/市两级计数 | 无区县字段 |

### 5.4 选用建议与理由

**建议：四张单族表可直接发布为「人才分布」「机构分布」「方向分布」「学历结构」四张卡；交叉筛选、迁徙图、产研对比三块暂不发布。** 理由：单族表可加总、可复核、缺口已显性化；交叉与迁徙依赖 9.3% 的 ID 交集，做出来会误导。

**不建议**用 D4 的毕业年序列做「人才供给趋势」，也不建议用 D2 的机构数做「机构增长」。前者是存量回溯，后者无年份列。等供应方补齐 `scholar_id` 域、机构 ID、区县码与建档年之后，再解锁交叉与增长，代码结构不需要重写，只需在 `D1`—`D4` 上各加一个分组键。

## 附录 C　人才分布与结构基础统计可行性报告（完整版）

### C.1 报告目的与范围

本附录回答：在「四族可算、交叉不可算」的条件下，基础统计能交付到什么粒度，以及哪些看起来能画的图必须撤掉。范围限定在分组计数与属地解析，不扩展到人才政策评估。

### C.2 需求语义锚定

需求用了「分布」「结构」「迁徙」三个词。分布是空间计数，结构是属性计数，迁徙是时间 + 空间的有向流量。前两者只需要分组，第三类需要「同一人先后在两个机构」的连线——这正是 9.3% ID 交集打死的那一层。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：分组计数

统计年鉴与 OECD Scoreboard 的基础表都是「行政单元 × 属性」的计数矩阵。它们不追求单一指数，追求可加总、可核对。本文的四族表属于这一族。

#### C.3.2 方法族 B：空间集中度

区位商、Herfindahl、Gini 都需要「区域份额」作输入。D1 已经给出份额，因此集中度可以算；但本文没有算，因为需求没有要求，且集中度对「未识别 12.95%」非常敏感。

#### C.3.3 方法族 C：结构占比

学历结构、产研结构都是组内份额。D4 的五类学位可以直接出占比；D2 的产研结构因企业样本只有 44 个，占比没有代表性。

#### C.3.4 方法族 D：流动网络

迁徙图需要「人—机构—时间」三元组。履历表有起止年，但与主档 ID 只有 9.3% 可连，且机构名未标准化，做出来的网络会断裂且不可解释。

### C.4 数据可行性详细分析

#### C.4.1 属地维

七级判定后 83.32% 可归属，省级 32 个单元。缺口集中在「机构名不含地名」与「海外机构」两类。

#### C.4.2 机构维

2,108 个去重机构，54.36% 无法判断类型。机构名未标准化，改名与重名都会拆分计数。

#### C.4.3 方向维

97,249 个标签、99.06% 的学者有多个标签。自由文本、无同义词合并、无层级。

#### C.4.4 学历维

43,766 行、五类学位、37,683 行有毕业年。双语归一救回 7,789 行，仍有 2,036 行未知。

#### C.4.5 方法—数据对照矩阵

| 方法 | 需要的输入 | 库内状态 | 可行性 |
|---|---|---|---|
| A 分组计数 | 单族主键 + 属性 | 四族齐全 | 可行 |
| B 空间集中度 | 区域份额 | D1 可给 | 可行但未交付 |
| C 结构占比 | 组内分类 | D4 可行、D2 不足 | 部分可行 |
| D 流动网络 | 人—机构—时间 | ID 9.3% | 不可行 |

### C.5 推荐构建方案（工程可执行）

1. 先发四张单族表，页面标注「暂不支持交叉筛选」；
2. D4 只展示占比与完整年对比，不画趋势线；
3. D2 的产研结构限定在高校 554 所内，企业侧等主数据补齐；
4. 供应方补 `scholar_id` 域、机构 ID、区县码、建档年后，再解锁交叉与增长。

### C.6 风险与残余不确定性

- 12.95% 属地未识别会被误读为「无人」；
- D4 毕业年下降会被误读为「供给下降」；
- D2 未识别 54% 会让产研结构失真；
- 标签无同义词合并会让方向计数分散；
- 交叉表覆盖 9.3% 且非随机子集。

### C.7 可行性总判（完整版结论）

四族单维计数可交付，交叉、迁徙、增长率不可交付；数据量足够支撑「分布与结构」的静态叙述，不足以支撑「流动与变化」的动态叙述。判「部分支持」。
