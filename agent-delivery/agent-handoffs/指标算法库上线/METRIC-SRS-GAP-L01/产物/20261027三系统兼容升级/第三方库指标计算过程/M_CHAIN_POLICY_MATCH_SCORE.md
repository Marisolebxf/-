### 0.3 本指标套用（一句话）

三维里「标签匹配」只剩 `title` 可读（`keywords`/`keypoints` 各 0 行有值、`theme` 仅 2 行）， 「支持覆盖」整维不可算（`policy_support` 20,000 行全为小写 `'null'`）， 「支持强度」只能用 `level=4` 占比代理；**两维可得、一维永久缺失**，故判**部分支持**。

### 0.4 本报告的证据纪律

1. 匹配词典是本件自拟的，全文落在 `out.json` 的 `probes.lexicon`，可逐词复核；不把词典说成甲方口径。
2. 命中是**多标签**：一条政策可同时命中多条链，命中数之和（202）大于去重政策数（190）。
3. 「匹配度」是**供给侧文本匹配**，不是「企业需求被满足」；企业画像与政策条款的匹配需要 `policy_support` 或申报数据，本件没有。
4. 所有百分比都给分子分母，读者可当场复算。

## 摘要

「产业政策匹配度」原口径是三维等权：政策标签匹配度、政策支持覆盖度、政策支持强度。拿到 `gkx.dwd_policy_base` 之后，第一件事是看这三维各自有没有列：`keywords` 和 `keypoints` 各有 0 行非空，`theme` 只有 2 行非空，`policy_support` 20,000 行全部是小写字符串 `'null'`（不是 SQL NULL，是占位符）。三维里有两维的原料没了，只剩「标题命中」与「政策级别」可用。

本件的做法是把口径降为两维，并把降级写在明面上：标签维只读 `title`；支持覆盖度维置 null；支持强度维用「国家级（level=4）命中占比」代理，不用权重表。匹配词典按 12 条链各给 3—6 个锚词，共命中 202 对（去重 190 条政策）。词典全文在产物里，任何人换一套词都能重算——这也是本件最容易被质疑的地方，必须先说清楚。

结果：集成电路匹配度 95.45 最高（34 条命中、12 条国家级、密度 2.8267 条/千家），智能网联汽车 90.91 第二（18 条、密度 2.9920），机器人 68.19 第三（18 条、密度 2.1055）；软件与信息服务虽然命中 61 条最多，但链企业 917,842 家，密度只有 0.0665，匹配度 54.55；具身智能 0 条命中，匹配度 0.00。

必须提醒的一件事：**命中数多不等于政策更匹配**。软件链 61 条命中是 12 条链里最多的，但它的企业基数也最大；集成电路 34 条命中却因为企业少（12,028 家）而密度最高。页面如果只显示命中数，会把「大链」误读成「政策最匹配的链」。

| 口径要点 | 取值 |
|---|---|
| 政策总行 / 可比文本 | 20,000 / 12,497 |
| 命中对数 / 去重政策 | 202 / 190 |
| 多链命中政策 | 12 条 |
| 最高 / 最低匹配度 | 95.45（集成电路）/ 0.00（具身智能） |
| 两维秩相关（密度 vs 合成） | 0.8112 |
| `policy_support` 为 `'null'` | 20,000 / 20,000 |
| 判档 | 部分支持 |

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块是**产业链分析 → 深圳产业发展分析 → 产业政策匹配度**。UI 是链详情页的一个 0—100 仪表，旁边列出「命中政策数 / 国家级数 / 深圳市政策数」三个小卡；政策专题页可按链筛选政策清单。

本件交付的是**链级两维相对指数**，不交付政策原文推荐、不交付企业—政策匹配、不交付「政策资金可申报额度」。

### 1.2 为什么需要这个指标

第一，它回答「这条链在政策文本里被提得多不多、提得高不高」。企业数、专利数回答不了这个问题；政策是外生变量，必须单独观测。

第二，它要给招商与政策申报做优先级。集成电路、智能网联汽车在国家级政策里出现频率高，说明这两条链的申报窗口多；具身智能在标题里一次都没出现，说明它还没有形成独立的政策口径（可能被归在「人工智能」或「机器人」下）。

第三，它要能识别「大链陷阱」。软件链政策命中 61 条，绝对数第一，但密度只有 0.0665 条/千家；如果按命中数排名，软件链会被误判为「政策最匹配」，实际它只是企业最多。

### 1.3 需求文档是否给出定义方法

给了三维框架与等权公式，但没有给「怎么算命中」。`gkx-orchestration/agent-delivery/metrics/calc-logic/CHAIN/M_CHAIN_POLICY_MATCH_SCORE.md` 写明：

$$M=\frac{1}{3}(标签匹配度+支持覆盖度+支持强度)$$

三维各 min-max 到 0—100。它把标签维写成「产业名/环节名命中 title/keywords/keypoints/theme」，把覆盖度写成「policy_support 命中产业主体」，把强度写成「按 rank 加权」。实际表里 `keywords`/`keypoints` 全空、`policy_support` 全为 `'null'`、没有 `rank` 列（只有 `level`），所以三维里两维的原料不存在。

### 1.4 类似指标权威机构构建方法可行性分析概要

国家信息中心的产业政策匹配评估通常做三步：政策文本结构化（支持对象、支持方式、支持强度）、产业主体画像、双向匹配。本件只能做第一步的「标题级」，第二步（企业画像）与第三步（双向匹配）都没有数据。

赛迪的政策强度评估用「发文层级 × 政策工具类型」加权。本件有层级（level），没有政策工具类型（`policy_support` 全空），所以只能用层级占比，不能用工具加权。

### 1.5 引用来源（可核验）

| 来源 | 用途 | 核验方式 |
|---|---|---|
| `gkx-orchestration/agent-delivery/metrics/calc-logic/CHAIN/M_CHAIN_POLICY_MATCH_SCORE.md` | 三维框架与等权公式 | 文件存在，逐条对照 |

| `code/_snapshots21/chain_firm_index_20261023.json` | 12 链企业数（密度分母） | 同批新建 |

### 1.6 推测原意与推测定义（仿王惠口径写法）

原意是「给定产业链，政策文本对它有多匹配、支持有多强」。本件把可算的两维定义为：

$$d_c=\frac{h_c}{F_c}\times 1000, \quad s_c=\frac{h_c^{nat}}{h_c}\times 100$$

其中 $h_c$ 是链 $c$ 的标题命中政策数，$F_c$ 是链企业数，$h_c^{nat}$ 是 `level=4` 的命中数。两维各取百分位秩后等权：

$$score_c=0.5 \times \mathrm{pct}(d_c)+0.5 \times \mathrm{pct}(s_c)$$

支持覆盖度维：

$$coverage_c=\mathrm{null}$$

这不是「暂缺」，是 `policy_support` 整列没有有效值，任何数值化都是编造。

## 二、计算过程

### 2.1 先证明三维里哪几维有原料

| 维度 | 需要的列 | 实际填充 | 可用性 |
|---|---|---|---|
| 标签匹配度 | `title` / `keywords` / `keypoints` / `theme` | title 100%；keywords 0；keypoints 0；theme 2 行 | 只剩 title |
| 支持覆盖度 | `policy_support` | 20,000 行全为 `'null'` | 不可算 |
| 支持强度 | `rank` / `level` | 无 `rank`；`level` 五档齐全 | 用 level 代理 |

`policy_support` 的 `'null'` 是小写字符串，不是 SQL NULL。只写 `policy_support IS NOT NULL` 会得到「20,000 行有值」的假象，进而造出一个「支持覆盖度 100%」的假维度。正确写法是 `UPPER(TRIM(policy_support)) NOT IN ('NULL','','NONE','-')`，结果为 0 行。

### 2.2 入集：时间窗与非政策文本剔除

政策表是存量表，日期从 1981-04-07 到 2024-02-18。本件取 **2015-01-01—2024-12-31**：

1. 1981—2014 年的政策太多是「通知/批复」且与当前产业链口径无关，纳入会把 2015 年后的结构冲淡；
2. 2025/2026 年零行，表内最晚 2024-02-18，不存在「残年」问题，但也不能声称覆盖 2025；
3. 3 行日期为 `0000-00-00`，剔除。

窗口内 13,117 条。再剔除采购/招标/展会/安保通告等非产业政策文本，剔除词 12 个（`招标`、`采购`、`中标`、`成交`、`竞争性磋商`、`询价`、`招聘`、`培训服务`、`博览会`、`展会`、`安全管理`、`通告`），剔除 620 条，剩 **12,497 条**可比政策文本。

为什么剔除这 620 条？因为低空经济的初版词典命中里，前几条是「无人机等低慢小航空器安全管理通告」「无人机培训服务竞争性磋商公告」「长春通用航空博览会搭建项目招标公告」。这些不是产业政策，是采购/安保文本；不剔除会让低空经济的命中从 1 条虚增到 5 条以上，且金额/级别完全不可比。

三个刻意的取舍：

1. **不把「新能源汽车」放进智能网联汽车**。新能源汽车是更大的口径，会把整车政策全部吸进来；本件只保留「智能网联/自动驾驶/车联网/智能汽车」四个词，宁可少命中。
2. **不把「人形机器人」放进机器人**。人形机器人归具身智能，机器人只保留「机器人/工业机器人/服务机器人」；一条政策同时提「机器人」与「人形机器人」时两条链都命中，这是有意的多标签。
3. **软件链保留「软件」这个宽词**。它是 61 条命中的主要来源，也是软件链密度低的原因；换成「工业软件」会只剩个位数，但会漏掉大量政务/行业软件政策。宽词的选择已披露，甲方可换词典重算。

### 2.4 命中与多标签

一条政策只要标题包含任一锚词，就记为该链命中。结果：

| 口径 | 数量 |
|---|---:|
| 可比政策文本 | 12,497 |
| 命中对数 | 202 |
| 去重命中政策 | 190 |
| 多链命中政策 | 12 |
| 未命中政策 | 12,307 |

多链命中的 12 条主要是「人工智能+机器人」「集成电路+智能终端」「生物医药+合成生物」这类复合标题。本件不做互斥拆分（没有字段能判断主链），按多标签各计一次；这会让 12 条链的命中数之和略大于去重政策数，是已知的口径差。

### 2.5 两维归一：密度与国家级占比

密度：

$$d_c=\frac{h_c}{F_c}\times 1000$$

分母 $F_c$ 用 `chain_firm_index_20261023.json` 的链企业数，与《投融资总额》《区域融资》同一份母体；不用政策数做分母，因为政策数是分子的一部分，会自相关。

国家级占比：

$$s_c=\frac{h_c^{nat}}{h_c}\times 100$$

`level=4` 为国家级（2,174 条），`level=3` 省级（9,922 条），`level=2` 市级（6,149 条），`level=1` 区县级（1,398 条），`level=0` 未知（357 条）。`level` 是表内字段，不是本件推的 `rank`；两者语义接近但不完全一致，正文一律写 `level`。

两维各取百分位秩（0—100），等权：

$$score_c=0.5 \times \mathrm{pct}(d_c)+0.5 \times \mathrm{pct}(s_c)$$

为什么等权？原口径三维等权；现在只剩两维，若改成 0.6/0.4 会引入本件自定的权重，无法与原文对齐。等权至少保持「每一维同权」的原则。代价是国家级占比与密度同权，可能让「命中少但都是国家级」的链排在「命中多但都是市级」的链前面——这是有意的，因为国家级政策的申报价值更高。

两维秩相关（密度序 vs 合成序）为 **0.8112**，说明国家级占比确实改变了排序：机器人从密度的第 3 升到合成第 3（不变），智能终端从密度第 9 升到第 5（国家级占比 25%），生物医药从密度第 5 降到第 8（31 条命中但 0 条国家级）。

### 2.7 敏感性：换词典会不会翻盘

做了两组对照：

1. **去掉宽词「软件」**：软件链命中从 61 降到 8（只剩「信息技术服务/工业软件/开源/信息系统集成」四条锚词）。命中数掉到原来的 13.11%，排名必然从第 6 掉到后段；本件只落命中数，不重算全表分数（`probes.sensitivity`）。这说明软件链的分数高度依赖宽词选择，是本件最不稳的一条链。
2. **把「新能源汽车」加进智能网联汽车**：命中从 18 增到 85（4.72 倍），排名会显著上移。本件没有加，因为新能源汽车不等于智能网联汽车；这条取舍必须让甲方知道。

结论：集成电路、机器人、具身智能的排名对词典不敏感（锚词唯一性强）；软件、智能网联汽车、生物医药的排名对词典敏感。发布时不要把「匹配度」当成客观物理量，它是一套可替换词典下的相对序。

## 四、数据缺失情况与结论边界

### 4.1 缺口的后果归因（往哪偏、偏多少）

1. **支持覆盖度缺失 → 匹配度只反映「被提到」，不反映「被支持」**。一条政策标题提到「集成电路」但支持对象是园区基建，本件仍计命中；真实支持覆盖可能是 0。方向是高估，幅度不可估。
2. **keywords/keypoints 全空 → 标签维退化为标题维**。正文里明确支持某链但标题没写的政策会漏掉；方向是低估，漏多少无法算。
3. **多标签不互斥 → 命中数之和大于去重数**。202 vs 190，差 12 条；对单链分数影响小，对「总命中率」有 6.3% 的高估。
4. **词典自拟 → 排名可被替换**。软件链对「软件」宽词高度敏感，智能网联汽车对「新能源汽车」高度敏感；换词典后排名会变。
5. **level 代理强度 → 国家级占比高不等于资金多**。国家级政策可能是「规划/指导意见」，没有资金；市级政策可能是「专项资金申报」。本件没有资金字段，不能把层级当金额。

### 4.2 可构建但存在缺口（不是「无法构建」）

能稳定构建：

- 12 条链的标题命中数、国家级命中数、深圳市命中数；
- 密度（每千家企业命中数）与国家级占比；
- 两维相对指数与排名；
- 每条链的示例政策标题（产物 `examples`）。

不能稳定构建：

- 政策支持覆盖度；
- 政策资金强度；
- 企业—政策需求匹配；
- 政策工具类型分布；
- 正文级语义匹配（未做，不是不能做，是需要分词与阈值）。

### 4.3 数据陷阱（本批实测，须写入任何下游复用说明）

1. **`'null'` 是字符串**：`policy_support` 全表 20,000 行都是小写 `'null'`，`IS NOT NULL` 判不出缺失。
2. **大小写不统一**：`theme`/`keypoints` 用大写 `'NULL'`，`policy_support` 用小写 `'null'`；统一写法是 `UPPER(TRIM(col)) NOT IN ('NULL','','NONE','-')`。
3. **`level=4` 才是国家级**：不要用 `rank`（表里没有），也不要把 `level=3` 当国家级。
4. **城市用中文全称**：`city='深圳市'`，不是 `'深圳'`；`'NULL'` 占位符 9,706 行。
5. **政策表是存量表**：按年截断会把老政策砍掉，本件用 2015—2024 全窗口，不按年取最新。
6. **采购/招标文本混在政策表里**：不剔除会让低空经济等新链虚增命中。

### 4.4 结论与边界

**可以对外说**：

- 2015—2024 年 12,497 条可比政策里，190 条标题命中 12 条链；集成电路命中 34 条、其中 12 条国家级，匹配度 95.45 最高。
- 具身智能 0 条命中，说明「具身智能」尚未成为独立的政策标题口径；这不等于没有支持，可能被归在人工智能/机器人下。
- 软件与信息服务命中 61 条最多，但密度仅 0.0665 条/千家，匹配度 54.55；命中数排名与密度排名不是一回事。

**不可以对外说**：

- 「政策对具身智能的支持为 0」——只能说是「标题未命中」，支持覆盖度维不可算。
- 「集成电路政策资金最多」——本件没有资金字段，95.45 是文本匹配相对指数。
- 「软件链政策匹配度低于集成电路，所以政策支持少」——软件链是企业基数大导致密度低，绝对命中数仍是第一。
- 「匹配度 95.45 表示 95.45% 的政策都支持集成电路」——它是两维百分位秩的等权合成，不是比例。

## 附录 C　可行性完整版

### C.1 报告目的与范围

回答「政策匹配度三维在 gkx 上能不能做」。范围限 12 条链的链级匹配，不含企业级、不含资金额。

### C.2 可算闭环

1. 标题命中：词典 + 12,497 条可比文本，确定。
2. 密度：命中 / 链企业数，确定。
3. 国家级占比：`level=4` / 命中，确定。

1. 支持覆盖度：`policy_support` 全 `'null'`。

### C.4 结论

按四档定义判**部分支持**。两维可交付，第三维需要甲方补结构化支持对象。若把 `'null'` 当有效值，会得到「支持覆盖度 100%」的假维度；本件明确拒绝这种做法。
