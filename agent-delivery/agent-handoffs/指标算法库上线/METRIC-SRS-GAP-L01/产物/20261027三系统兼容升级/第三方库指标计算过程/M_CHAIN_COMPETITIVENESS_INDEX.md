### 0.3 本指标套用（一句话）

八项依赖里，**五项**（人均营收、研发强度、论文、人才、机构）要么分子分母交集不足、要么没有「主体—链」桥；**两项**（有效专利、融资事件）全量可用；**一项**（政策覆盖）连链标签都没有。合成只能用「企业规模 + 创新密度 + 创新广度 + 资本活跃 + 环节覆盖」五条代理，故按 §〇 判**部分支持**。

## 摘要

「产业链竞争力指数」要回答的是链对比页上最直白的问题：12 条链，谁强谁弱。王惠的三维八项给了骨架——企业维看人均营收、研发强度、有效专利，学术维看论文、人才、机构，生态维看政策覆盖、融资事件。骨架没有问题，问题是**八项里只有两项在 gkx 有全量源**。

本件先逐项做可得性核查，再决定算不算。结论是：**有效专利**（2,939,895 件申请、169,226 个申请人，可按申请人名挂链）与**融资事件**（25,654 行，可按企业名挂链 14,626 行）两项全量可用；**人均营收**两项都不缺、但交集太小且单位不齐：员工数在 `dwd_org_stock_finance_info` 的 40,239 行里 0 行有值、在 `dwd_org_annual_financial_info` 的 3,170 行 >0，营收在同表 2,191 行 >0，两者同时 >0 仅 **1,288 行 / 850 家企业**（底册 0.45%），而营收同列量级跨 12 个数量级（0.06 → 2.72e10，另有 -443.71 负值），人均中位仅 120.57 元/人；**研发强度**的字段存在但只有 876 家企业（占底册 0.46%）有正值；**论文**侧 2,070 家机构里只有 1 家能挂到链；**人才**与**机构**没有「主体—链」桥；**政策覆盖**没有链标签。

于是本件改用五条可算子项做等权合成：企业规模（企业数 log10）、创新密度（每千家企业专利申请量）、创新广度（有专利企业占比）、资本活跃度（每千家企业融资事件数）、环节覆盖（有企业的叶级环节占比）。12 条链全部有值，指数区间 **25.96—77.71**，均值 **45.26**、中位 **43.28**。

排名前三是具身智能 **77.71**、机器人 **70.18**、集成电路 **53.98**；末三是生物医药 **31.00**、软件与信息服务 **32.03**、传感器 **25.96**。这个排序与直觉有出入：软件与信息服务有 917,842 家企业（全库最大），却只排第 10。原因是它的专利密度只有 184.74 件/千家、融资密度 3.56 起/千家，规模被「密度」拉平——这正是合成指数与「按企业数排序」的区别，也是必须把五子项同时展示的原因。

必须同时说清一件事：**这个指数不是「竞争力」，它是「规模 + 创新 + 资本活跃度 + 覆盖度」的合成**。学术产出与政策环境这两面（恰恰是「竞争力」里最讲质量的两面）完全缺席。对外发布时必须带这句话，否则「竞争力第 1」会被读成「综合最强」。

| 口径要点 | 取值 |
|---|---|
| 王惠八项可得 | 2/8 全量；2/8 有字段但覆盖极低；4/8 无桥 |
| 本件合成子项 | 5 条（规模/专利密度/专利广度/融资密度/环节覆盖） |
| 权重 | 等权 0.2（本件自定义、待甲方确认） |
| 归一化 | 12 条链内 min-max |
| 指数区间 | 25.96—77.71，均值 45.26 |
| 判档 | 部分支持 |

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块是**产业链分析 → 产业链总览 → 链间比较**。页面是一张排序表：链名、综合指数、五个子项条、名次。它的下游是链对比页的默认排序与「重点链」筛选。

产品上它是「一张表定优先级」的工具：政策资源有限时，先看哪条链。因此它的错误代价不是「显示不好看」，而是**资源投错链**。

### 1.2 为什么需要这个指标

第一，跨链比较缺少统一尺度。12 条链的企业数从 4,034 到 917,842，差 227 倍；专利数从 7,530 到 368,298，差 49 倍。单看任何一个绝对量，都会得出「企业多的链最强」。

第二，单一指标会被单点异常带偏。只看专利，集成电路与智能终端会霸榜；只看融资，人工智能会霸榜（5,024 起）。合成的作用是把「规模」「密度」「活跃度」三种视角压到一个尺度上，让异常点互相制衡。

第三，它给「补短板」提供方向。五个子项里哪一项低，就补哪一项：密度低补研发，覆盖低补招商，融资低补资本对接。这比一个总分更有用。

### 1.3 需求文档是否给出定义方法

**给了骨架，没给可执行口径。** 王惠 V2 的三维八项写清了「看哪八项」，但没有写：① 每项的度量（人均营收用哪年、研发强度用费用还是人数）；② 权重；③ 缺失维怎么处理（记 0？记 50？剔除？）；④ 归一化方式。

这四条里，第③条最关键：如果缺失维记 0，学术维三项全缺的链会被系统性压低；如果记 50，等于给所有链发同样的分（`M_CHAIN_SZ_ADVANTAGE_SCORE` 已经踩过这个坑，四维里有三维退化成常数 50）。本件的选择是**不填补**：只对可算的五项合成，缺的五项在 §四 逐条披露，不参与计算。

### 1.6 本报告的口径与边界（须与甲方会签）

**推测定义**：设链 $c$ 的第 $k$ 个子项原始值为 $x_{ck}$，在 12 条链内做极差归一：

$$z_{ck}=\frac{x_{ck}-\min_{c'}x_{c'k}}{\max_{c'}x_{c'k}-\min_{c'}x_{c'k}}$$

指数为五子项等权平均：

$$CI_c=100\times\frac{1}{5}\sum_{k=1}^{5}z_{ck}$$

五个子项的原始值为：

| 子项 | 原始值 | 公式 |
|---|---|---|
| S1 企业规模 | $\log_{10}F_c$ | $F_c$ 为链内企业数 |
| S2 创新密度 | $1000\cdot P_c/F_c$ | $P_c$ 为链内专利申请量 |
| S3 创新广度 | $F^{pat}_c/F_c$ | $F^{pat}_c$ 为有专利的企业数 |
| S4 资本活跃度 | $1000\cdot E_c/F_c$ | $E_c$ 为链内融资事件数 |
| S5 环节覆盖 | $L^{+}_c/L_c$ | 有企业的叶级环节 / 全部叶级环节 |

**边界**：① 权重等权是本件自定义，不是王惠原口径；② min-max 让指数**只在 12 条链内有意义**，不能跨期比较、不能跨库比较；③ 缺的五项不填补、不记 0、不记 50；④ 指数名保留「竞争力」，但对外必须同时说明它只覆盖规模与创新两面。

## 二、计算过程

### 2.1 方法选择：为什么等权 + min-max，而不用 PCA 或熵权

样本只有 12 个（链），分项只有 5 个。PCA 在这种规模下会给出一个由第一主成分主导的权重向量，而第一主成分通常就是「规模」——等于把五个子项压成企业数排序，失去合成的意义。熵值法同理：12 个观测的离散度估计方差极大，权重会随一次数据更新大幅跳动。

等权 + min-max 的优点是**可解释、可复现、可争议**：任何一条链的名次都能用手算复核，权重争议可以直接讨论「要不要给创新加权重」，而不是讨论「PCA 的第二主成分为什么是负的」。

代价是等权隐含「五项同样重要」的假设。这个假设不成立——规模与创新显然不该同权。所以本件在 §2.5 做了加权敏感性对照，把等权结果与「创新加权」结果并列，供会签时选择。

### 2.2 子项定义与分母口径

五个子项的分母全部是**链内企业数** $F_c$，不是叶级企业数、不是底册总数。原因：五个子项要可比，分母必须同源。链内企业数来自 `chain_panel21.json` 的 `firms` 字段（12 条链合计 1,714,458 家）。

专利分子 $P_c$ 是「申请人名能挂到该链」的申请量（12 条链合计 1,127,340 件）。这里有一个容易忽略的口径问题：全库 2,939,895 件申请里，可挂链 1,127,340 件，余下 $2{,}939{,}895-1{,}127{,}340=1{,}812{,}555$ 件（61.65%）的申请人名不在链标签表里，无法挂链。本件只在「已挂链」子集内比较，分子分母同源，但结论不能外推到全量专利——这一点在 §四 会再强调一次。

融资分子 $E_c$ 是「企业名能挂到该链」的融资事件数（14,626 / 25,654 = 57.01%）。

### 2.3 逐项计算（以两条链为例）

以**具身智能**（第 1）与**软件与信息服务**（第 10）对照，能看清指数的行为：

$$\text{S1}:\ \log_{10}8140=3.9106\ \ \text{vs}\ \ \log_{10}917842=5.9628$$

$$\text{S2}:\ \frac{74416}{8140}\times1000=9142.01\ \ \text{vs}\ \ \frac{169564}{917842}\times1000=184.74$$

$$\text{S3}:\ \frac{1263}{8140}=0.1552\ \ \text{vs}\ \ \frac{7398}{917842}=0.0081$$

$$\text{S4}:\ \frac{634}{8140}\times1000=77.89\ \ \text{vs}\ \ \frac{3272}{917842}\times1000=3.56$$

$$\text{S5}:\ \frac{58}{58}=1.0000\ \ \text{vs}\ \ \frac{66}{70}=0.9429$$

软件在 S1（规模）上遥遥领先，却在 S2/S3/S4（三项密度）上垫底；具身智能相反。等权合成后，具身智能 77.71、软件 32.03。这不是「软件不强」，而是**等权把「密度」放到了与「规模」同等的位置**——一个 91 万家企业的链，其密度天然会被大分母压低。

这个现象是指数设计里最需要会签的一点：**规模与密度等权，等于惩罚大链**。如果甲方的意图是「谁体量大谁强」，权重应改为 S1 独大；如果意图是「谁的单位效率高谁强」，则现在的等权更合适。

等权是本件自定义，必须有敏感性对照，否则无法判断名次是否稳健。做一次「创新加权」：S2/S3 各 0.3、S1 0.2、S4/S5 各 0.1。

### 3.3 结构支持判定

链树、企业标签、专利申请人、融资事件四张表都带可挂链的键（链码、企业名/信用码、申请人名），这是本件能算五子项的结构基础。缺的五项不是「表不存在」，而是「表里没有链键」——这属于**桥接缺失**，不是结构缺失。两者的区别很重要：桥接可以补，结构不能。

## 四、数据缺失情况

### 4.1 缺口的后果归因

**缺学术维 → 指数偏向「产业规模」而非「创新质量」。** 一个论文产出高但企业少的链（如合成生物）在现有指数里只能靠专利密度拿分，学术贡献完全不被计价。方向是**低估基础研究型链**。

**缺研发强度 → 无法区分「买技术」与「做技术」。** 有效专利只看数量，不看研发投入；一个靠收购获得专利的链与一个自主研发的链，在 S2/S3 上得分相同。

**缺政策覆盖 → 无法反映「政策是不是在支持」。** 生态维只剩融资一项，等于把「生态」缩小成「资本市场」。

**人均营收交集成交 1,288 行 / 850 家（0.45%）→ 即便强行算，样本也不到千分之一。** 这 850 家集中在有年报的大企业，会把「有年报」误当「链的代表」；更要紧的是营收列量级不齐（0.06 → 2.72e10），同一列里既像「元」又像「万元」，不统一单位就没法横比。

### 4.2 数据陷阱（本批实测，须写入下游复用说明）

- **「无字段」是错的，「覆盖低」才对**：`dwd_org_stock_finance_info` 有 `research_development_amount`（19,585 行 >0）与 `employees_number`（0 行有值）；`dwd_org_annual_financial_info` 有 `employees_number`（3,170 行 >0）与 `arch_development_am`（0 行有值）。第一版草稿把研发强度写成「无字段」，被 `information_schema` 推翻。
- **「缺人数」也是错的，「交集 + 单位」才对**：annual 表里营收>0 2,191 行、员工>0 3,170 行，同时>0 仅 1,288 行；且 `operating_revenue` 最小值 0.06、最大值 109,056,497,066.48、另有 -443.71 负值，人均营收算出 0.0059—93,967,560 元/人、**中位仅 120.57 元/人**（只有 1,258/1,288 行落在 1—1e7）；分桶为 <1:5 / 1—1e4:790 / 1e4—1e8:1,138 / ≥1e8:258。中位 120 元/人低于任何合理年报口径的营收/人，说明该列在元与万元/亿元之间混用。第二版理由「缺的是人，不是钱」因此也被推翻。
- **`dwd_org_base_info.org_size` 整列为 0**：189,116 行里没有一行有非零规模，任何「按 org_size 分区」的写法都会得到单一分区。
- **专利挂链率 61.65% 是分母问题**：$2{,}939{,}895-1{,}127{,}340=1{,}812{,}555$ 件申请挂不上链，S2/S3 的绝对值被系统性低估，只能做链间相对比较。
- **融资挂链率 57.01%**：未挂链的 11,028 行多为投资方名称，S4 偏向「已被打标的链内企业」。
- **等权惩罚大链**：软件 917,842 家企业排第 10，不是因为它弱，而是密度被大分母压低。

### 4.3 可构建但存在缺口（不是「无法构建」）

1. **人均营收**：差两样——人数覆盖（现 850 家）与营收单位统一（现同列混量级）。两样补齐后 S1 才可从「企业数」升级为「人均营收」。
2. **研发强度**：已有 876 家上市公司口径，可作为「上市口径研发强度」单列，不与全量混算。
3. **论文**：论文机构快照只有 2,070 家、100,900 篇（6.8% 抽样），且与企业名几乎不重合，需要独立的主体映射。
4. **政策**：20,000 条政策无链标签，但可用「政策主题词—链」人工映射做一版，须标注为人工映射。

### 4.4 若甲方补齐后的口径升级路径

|---|---|---|

## 五、口径对照与选用建议

### 5.1 王惠 V2 原口径还原

出处：`calc-logic/CHAIN/M_CHAIN_COMPETITIVENESS_INDEX.md`。要点：三维八项、等权（原稿未给权重，默认等权）、输出 0—100 综合分与名次；缺失维原稿未定义处理方式。

### 5.2 新方法概述

本件保留「0—100 综合分 + 名次」的输出形态，把八项裁剪为五项可算子项（规模、专利密度、专利广度、融资密度、环节覆盖），min-max 归一后等权合成。裁剪的判断依据是 §2.6 的计数表，不是主观取舍。

### 5.3 逐维对照表

| 维度 | 王惠原口径 | 本件口径 | 差异原因 | 可复现性 |
|---|---|---|---|---|
| 企业维 | 人均营收、研发强度、有效专利 | 企业数、专利密度、专利广度 | 人数交集 0.45%、研发覆盖 0.46% | 本件更稳 |
| 学术维 | 论文、人才、机构 | **缺** | 无主体—链桥 | — |
| 生态维 | 政策覆盖、融资事件 | 融资密度、环节覆盖 | 政策无链标签 | 本件更稳 |
| 权重 | 未定义 | 等权（自定义） | 需会签 | 可复现 |
| 归一化 | 未定义 | 链内 min-max | 需会签 | 可复现 |

### 5.4 选用建议与理由

**建议采用「五子项等权指数」作为过渡口径，同时把学术维与政策维列为待补项。** 理由：① 五子项全部有全量或近全量源，12 条链都能算；② 头部三名对权重不敏感，可用于「优势链」判断；③ 尾部名次不稳，只能做「待观察」，不能做资源分配依据；④ 学术与政策两面缺失是硬缺口，不能靠权重调整掩盖。

**待甲方裁决点**：① 是否接受「规模与密度等权」（这会惩罚大链）；② 尾部名次是否允许展示；③ 学术维缺失期间，指数是否改名（如「产业强度指数」）以避免误读；④ 权重表由谁签。

## 附录 C　竞争力指数类似指标可行性报告（完整版）

### C.1 报告目的与范围

回答三个问题：① 王惠八项里哪几项在 gkx 可落地；② 可落地的部分能合成出什么；③ 从「五项代理」升级到「八项原口径」还差什么。范围限定链树、标签、专利、融资、财务五类表。

### C.2 需求语义锚定

「竞争力」在需求里没有定义。三种可能语义——规模竞争力（谁大）、效率竞争力（谁单位产出高）、创新竞争力（谁技术强）——对应三套权重。本件用等权，等于默认三者同等重要；这与「竞争力」的通常理解（效率与创新优先）并不一致，是需要会签的第一件事。

### C.3 权威与学术构建方法谱系

#### C.3.1 族 A：等权合成（HDI）

数据要求：各分项归一后的 0—1 值。步骤：定分项 → 归一 → 等权平均。局限：隐含等重要性。借法：归一与合成方式。

#### C.3.2 族 B：PCA / 因子分析

数据要求：足够样本（通常 ≥50）与完整面板。步骤：相关矩阵 → 主成分 → 权重。局限：12 个样本下退化。为何不用：第一主成分即规模。

#### C.3.3 族 C：熵值法

数据要求：观测数足够以稳定估计离散度。局限：小样本权重不稳。为何不用：12 条链。

#### C.3.4 族 D：集群竞争力（Porter / EU Scoreboard）

数据要求：要素条件、需求条件、相关产业、企业战略四组指标，含贸易与投入产出。局限：本库无贸易与 IO。借法：维度划分思路。
