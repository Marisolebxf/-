### 0.4 注册表口径（seed）与本文偏离声明

第二处偏离：需求隐含「全口径人才」，本文的池是**学者库**（`dwd_scholar`），不含企业研发人员、工程师、技能人才。企业侧在 `gkx` 里只有企业名录（189,116 行）与专利发明人姓名（403,743 个姓名），没有职称、没有职级、没有薪酬。

第三处偏离：需求没有说阈值，本文**不用绝对分 60**，改用池内分位（p95 / p80）。实测绝对分 60 会切出 4,820 人（23.6%），「重点」二字失去筛选意义，这一点在 §2.6 与 §5.4 都写明。

## 摘要

重点人才识别模型要回答的是「在现有学者库里，哪些人应当被优先看到」。需求给的是「结合论文、项目、荣誉等维度识别」，但没有给公式、没有给权重、没有给阈值；本文把它落成三因子：学术深度 h 0.40、被引影响 0.35、论文产出 0.25，全部取生涯累计值，`log1p` 后池内 min-max 归一，合成 0—100 分。

全池 20,420 名有姓名学者（`dwd_scholar` 21,316 行，896 行无姓名被排除），分数均值 50.86、中位 52.63、P90 65.84、P99 79.88、最高 100。分档按池内分位切：重点人才（K≥70.3592，即 p95）1,021 人、关注人才（61.2297≤K<70.3592，p80—p95）3,063 人、其余 16,336 人。

榜首是陈军（南开大学，h=286、被引 328,858、论文 2,487，K=100.0）；深圳切片第一是唐本忠（香港中文大学（深圳），h=219、被引 257,865、K=97.35），其后是张晗（深圳大学，89.64）、陈宇综（深圳湾实验室，84.32）。深圳切片共 182 行（机构名含「深圳」；若按五级地名归属含南方科技大学、华为等，则为 213 人，见 §2.2 的口径说明）。

外部校验：`dwd_scholar_talent_flag` 的院士标识 112 行中 80 行能挂到主档（71.43%），这 80 人在全池的分数中位分位是 98.8，Top100 里命中 21 人（26.25%）——院士确实集中在头部，但院士只占 Top100 的五分之一，说明「重点人才」不等于「院士」。

结论：这条指标可以作「学者库内优先级排序 + 深圳切片」的线索工具，可以支撑「哪些人值得先看画像」的运营动作，不能作「重点人才认定」，也不能回答「企业里有哪些重点人才」——后者需要企业人才库与职称/职级数据，一列都没有。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技人才态势 → 人才洞察分析 → 重点人才识别**（对应需求 1.1.1.1.4.3.1 节）。需求原文写「结合论文、项目、荣誉等多维数据识别重点人才」，并在同一段要求「支持按区域、机构、学科筛选」。

| 页面任务 | 对指标的要求 |
|---|---|
| 重点人才名单 | 一人一分 + 排序，支持区域/机构筛选 |
| 分档展示 | 至少要两档（重点/关注），档位要有业务含义 |
| 深圳切片 | 能单独看深圳机构的人 |
| 领域标签 | 一人可多簇，能按 20+8 过滤 |
| 人才认定 | 需要职称、荣誉、项目负责人身份（库内缺） |

### 1.2 为什么需要「重点人才识别模型」这个指标

第一个理由是页面入口需要一个「先看谁」的排序。学者库有 21,316 行，运营与招商人员不可能逐条翻；没有排序，所有筛选器都只是「按字母表列出」。

第二个理由是它把「学术影响力」显性化成可比较的分数。单看 h 指数，做实验科学的与做数学的不可比；单看被引，综述型学者的被引会虚高；单看论文数，灌水型学者会排在前面。三因子加权至少把三种偏差摊平了一部分。

第三个理由是它必须被限制在「线索」而不是「认定」。认定需要职称、荣誉、项目负责人身份与同行评议，库内只有论文三列与一个 112 行的院士标识。本文在 §4.3 明确三条不可外推，核心就是防止「K 分高」被读成「官方认定」。

### 1.3 需求文档是否给出定义方法

**需求给了「论文、项目、荣誉等多维」，但没有给公式、权重、阈值与池子。**

原文没有写：重点人才的对象是企业还是学者、论文按生涯累计还是近五年、h 与被引怎么合成、阈值定在多少、区域筛选按机构名还是按地名。本文补的五条决策是：① 池子取 `dwd_scholar` 有姓名全池（20,420）；② 三列都取生涯累计（表内只有累计值，没有年度序列）；③ 权重 0.40/0.35/0.25（h 最稳、被引最有区分度、论文数最易灌水，故权重递减）；④ 阈值取池内 p95 / p80；⑤ 区域筛选同时提供「机构名含深圳」与「五级地名归属」两种口径，正文以严格的机构名子串为主。

### 1.6 推测原意与推测定义

**推测原意**：产品要一张「重点人才候选表」：给定区域或机构，能列出分数最高的一批人，并能看到分数由哪几块构成。它服务人才洞察页的首屏名单与招商引才的初筛，不服务官方人才认定。

**推测定义（本文采用）**：

> 对学者 $i$，三因子原值为 h 指数 $H_i$、被引 $C_i$、论文数 $P_i$；归一后合成
> $$
> K_i=100\times\left(0.40\tilde H_i+0.35\tilde C_i+0.25\tilde P_i\right),\quad
> \tilde x_i=\frac{\log(1+x_i)-\min_j\log(1+x_j)}{\max_j\log(1+x_j)-\min_j\log(1+x_j)}
>
$$

**为什么 h 权重最高**：三列里 h 最难被短期操作（要有一批论文各自攒够被引），被引可以被一两篇爆款拉高（池内最高 328,858，是 P99 的 9 倍），论文数最容易被批量生产（池内最高 2,487）。权重按「抗操纵性」排序，是本文唯一能自洽的排序依据。

**为什么用 log1p + min-max 而不是 z 分**：三列都是重尾分布（被引 P99 35,947.83、最高 328,858），直接 z 分会把 99% 的人压到 -0.1 附近，分数几乎全由头部几个人决定；log 之后重尾被压平，min-max 再把量纲拉回 0—1，头部仍然领先但不再垄断。

**为什么阈值取分位而不是绝对分**：需求没有给阈值。若按直觉取 60 分，池内 4,820 人（23.6%）入选，「重点人才」变成「前四分之一」，名单失去筛选意义；取 p95 得 1,021 人（5.0%），与「重点」的字面含义相符，且分位阈值不随池子规模漂移。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是本文 §1.6 的自建口径，不是 calc-logic、也不是甲方给定。降级发生在三处：① 需求的多维（论文 + 项目 + 荣誉）降为论文单类三列，因为项目无负责人 ID、荣誉只有 112 行院士标识；② 「重点人才」的对象从「全口径人才」降为「学者库」，因为企业侧无人才表；③ 阈值从「业务给定」降为「池内分位」，因为需求没给数值。

本文没有做的降级包括：没有把院士标识塞进权重（会让 99.45% 的人缺测）、没有用专利件数补「技术产出」（专利与论文量纲不同，且发明人只能按姓名匹配）、没有用「机构名含大学」推断学术身份（会把 5,000 多家企业研究院误判）。这三条都属于「补一个维度、毁掉整个分布」的做法，本文宁可少一维。

### 2.2 口径拆解：对象、集合、归一

**对象**：学者，`dwd_scholar` 一行。全表 21,316 行，其中有姓名 20,420 行、无姓名 896 行。无姓名的行被排除，因为下游所有展示都要显示人名，且论文/专利匹配也依赖姓名。

**集合**：归一池取全池 20,420 人，不按区域或学科分层。理由是分位阈值要在同一个池内定义，若按城市分别归一，石家庄的第一名与北京的第一名会拿到同样的 100 分，跨城比较失效。

**区域口径（两种，必须区分）**：口径 A「机构名含深圳」——182 人，严格、可复核、不会误纳；口径 B「五级地名归属」——213 人，会把「南方科技大学」「华为技术有限公司」等 55 行不含「深圳」字样的机构补进来。正文的深圳切片用口径 A（182 人），§2.6 同时给出 B 口径的差异，避免读者以为两个数字矛盾。

**三列取值**：`h_index`（0—286）、`citation_nums`（0—328,858）、`paper_nums`（0—2,487），均为**生涯累计**。表内没有年度序列，所以本件没有「近五年」口径，也不能算增长率；这一点写在 `base_years_note` 里：基期为空集，因为不存在年度窗口。

**归一**：三列各自 `log1p` 后在全池做 min-max。零值不特殊处理（`log1p(0)=0`），因此零产出的人得 0 分而不是缺测——这三列是真零，不是「查不到」。

| 2 | 企业人才 | 无表（`dwd_job` 仅 10 行） | **断在第 1 跳** |

「两跳停」在这里的含义是：本文只走到「学者主档三列 + 论文面板」这一层，不再去 `dwd_org_annual_financial_info` 找研发人员数、也不去 `dwd_org_recruit_info` 找岗位。前者的人均研发人员列整列为空（TALENT 族已知缺陷），后者的岗位是「岗位流水」而不是「在职人数」，两者都不能当「人才存量」。

### 2.4 算路 / SQL

本指标**零 SQL**：学者读 `probe_a26_20261022.json`（21,316 行快照），子表读 `probe_talent21_20261022.json`，论文面板读 `a25_paper_panel.json`（100,900 篇）。

```text
-- 快照的原始形态（已落盘，本文不再发）
SELECT scholar_id, name, org_name_zh, h_index, citation_nums, paper_nums
FROM gkx.dwd_scholar;                    -- 21,316 行，三列 100% 非空
SELECT scholar_id, academician FROM gkx.dwd_scholar_talent_flag;   -- 112 行
```

本地计算：三列 log1p → 全池 min-max → 加权合成 → 分位切档 → 榜单 → 院士校验 → 领域簇汇总（姓名 + 机构前缀双锚定论文，13,955 人可判簇）。脚本耗时 6.2 秒。

**为什么不在 SQL 里算**：min-max 的分母是全池极值，SQL 侧要先跑一次聚合再回填，等于两次全表扫描；论文侧的机构前缀匹配与 28 类字典匹配更不适合在 SQL 里做（作者列表是 JSON 长文本，字典有 200 多个关键词）。快照已在 20261022 落盘，本地算 6 秒。

### 2.5 清洗规则

| 规则 | 处理 | 影响 |
|---|---|---|
| 姓名为空 | 排除出池 | 896 行 |
| h / 被引为 0 | 保留（真实零） | h 为 0 共 392 人 |
| 论文数为 0 | 保留 | 15 人 |
| 机构名为空 | 保留，区域记「未归属」 | 少量 |
| 池内同名 | 保留多行，榜单标同名数 | 见 §2.6 |
| 同一人双记录 | 保留（如李清泉两条） | 深圳 Top10 内 1 例 |
| 院士标识挂不上主档 | 只统计可挂的 80 行 | 32 行未挂 |

清洗原则是「真零保留、缺测显性、重名披露」：三列的真零是「确实没有产出」，不是「没查到」，所以保留为 0；姓名为空无法展示也无法匹配，只能排除；重名与双记录不合并，因为合并需要唯一 ID，而库内没有跨表的唯一人 ID。

### 2.6 结果解读

**分布**：20,420 人，K 均值 50.86、中位 52.63、P10 32.64、P90 65.84、P99 79.88、最高 100、最低 0。分布接近对称（均值与中位差 1.77），这是 min-max 与 log 共同作用的结果：三列都被拉到 0—1，加权和自然集中在 50 附近。分数不是「人才概率」，只是池内相对位置。

## 四、数据缺失情况

### 4.1 缺失清单

| 缺失项 | 现状 | 影响 | 修复建议 |
|---|---|---|---|
| 企业人才库 | 无表 | 识别池只剩学者 | 接入企业研发人员/职称库 |

| 子表 ID | 与主档交集 1,853—1,856 | 学历/履历/研究方向不能落到人 | 统一 scholar_id 码域 |
| 年度序列 | 三列只有累计值 | 无趋势、无「近五年」 | 补年度快照 |
| 招聘/薪资 | `dwd_job` 仅 10 行 | 市场信号不可用 | 接入招聘平台数据 |

### 4.2 对结论的影响边界

缺失把这条指标从「重点人才认定」压成「学者库内优先级排序」：它能回答「这批学者里谁该先看」，不能回答「深圳全市有哪些重点人才」。分档的绝对含义也随之消失——p95 切出来的 1,021 人是「池内前 5%」，不是「达到某个水平」。

企业侧缺失还让「区域筛选」只剩高校与院所：深圳 182 行里绝大多数是高校与中科院系，华为、腾讯、比亚迪的研发人员一个都不在池内。页面若把「深圳重点人才 182 人」当成全市总量，会严重低估。

### 4.3 不可外推的三件事

第一，不能把 K 分当「人才水平」。三列都是文献计量，做工程、做临床、做政策研究的人天然吃亏；K 分高只说明「论文三列高」，不说明「贡献大」。

第二，不能把 Top 榜当「引进名单」。榜单里同名多记录（王伟、李清泉等），双记录会让同一人占两个位次；且榜单是全国池，深圳切片只有 182 行，跨城挖人需要先核机构与在职状态。

第三，不能把「重点人才 1,021 人」当「深圳的重点人才」。这 1,021 人是全国池的 p95，深圳在其中只占 182 行（0.89%）；Top20 里机构名含「深圳」的只有 2 人（唐本忠、张晗，均深圳大学），按地名归属再加朱健康（南方科技大学）共 3 人。城市对比必须分池计算。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

**calc-logic 无实现；注册表 seed 只有一句「结合论文、项目、荣誉等维度识别重点人才」，没有公式、权重与阈值。** 王惠系在同类指标上惯用的做法是「帽子优先 + 论文辅助」：先看院士/杰青/长江，再用论文排序补足。本文没有沿用，原因是库内帽子只有 112 行（0.55%），按帽子优先会把 99.45% 的人打成「非重点」，名单失去区分度。

### 5.2 新方法概述

新方法 = 三列（h / 被引 / 论文数）log1p + 全池 min-max + 0.40/0.35/0.25 加权 + 池内 p95/p80 分档 + 院士外部校验 + 28 簇归属 + 两种区域口径对照。

### 5.3 逐维对照表

| 维度 | 需求语义 | 本文实现 | 差异与理由 |
|---|---|---|---|
| 论文 | 「论文」 | h + 被引 + 论文数三列 | 比单看论文数更抗灌水 |
| 项目 | 「项目」 | 未交付 | 无负责人 ID |
| 荣誉 | 「荣誉」 | 未入权重，仅校验 | 只有 112 行院士标识 |
| 权重 | 未给 | 0.40/0.35/0.25 | 按抗操纵性排序 |
| 阈值 | 未给 | p95 / p80 | 绝对 60 会切出 23.6% |
| 对象 | 未限定 | 学者库 20,420 | 企业侧无表 |

### 5.4 选用建议与理由

**建议：本产物作为「学者库内重点人才线索表」使用，页面展示 K 分、三列原值与分档，档位标注为「池内前 5% / 前 20%」，不发布「重点人才认定名单」。** 理由：分档是相对位置，不是绝对水平；企业与项目两维缺失，认定所需的证据链不完整。

**不建议**把院士标识直接加进权重，也不建议用「机构名含大学」补学术身份。前者会让 99.45% 的人缺测，后者会把 5,000 多家企业研究院误判为高校。等甲方补齐职称、荣誉、项目负责人三类数据后，再把三因子扩成五因子，代码只需改 `W` 与归一函数。

需求用了「论文」「项目」「荣誉」「识别」四个词。论文对应文献计量，项目对应承担课题，荣誉对应称号，识别对应排序与筛选。库内只有第一项完整，第二项缺负责人 ID，第三项缺名单，第四项只能做相对排序。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：文献计量复合指数

Clarivate 的高被引科学家按学科分位的被引次数选人，ESI 用高被引论文阈值。共同点是「分位 + 学科归一」，不是绝对分。本文借用分位思想，但没有做学科归一（库内无学科代码），这是与权威方法最大的差别。

#### C.3.2 方法族 B：多因子加权

大学排名普遍用 z 分加权，权重由专家或主成分确定。本文用 min-max 而非 z 分，原因是重尾；权重由「抗操纵性」排序，不是专家打分。

#### C.3.3 方法族 C：荣誉驱动

以院士、杰青、长江等称号直接定档，优点是权威，缺点是覆盖极低。库内 112 行院士标识只覆盖 0.55%，无法支撑名单。

#### C.3.4 方法族 D：同行评议

专家打分最权威，但库内没有任何评议数据，且无法批量复现。

### C.4 数据可行性详细分析

#### C.4.1 三列可用性

h、被引、论文数在 20,420 行上 100% 非空；h 为 0 的 392 人、论文数为 0 的 15 人属真零，保留。三列的极值分别为 286、328,858、2,487，重尾明显，log 变换必要。
