## 摘要

「企业培育评分」回答的是「本地的苗子值不值得投」。它的候选集刻意收窄到成立 3—15 年的企业：3 年以内太早期、15 年以上已过培育窗口。四维是成立年限（成长空间）、专利规模（潜力）、IPC4 广度（技术面）、融资/被投（资本认可）。

候选集 93,628 家，权重 0.35/0.30/0.20/0.15。首位是荣耀终端 0.859（2020 年成立、8,971 件专利、112 个 IPC4、7 次融资），第二是华为数字能源 0.743（2021 年成立、4,693 件专利）。两家都是「新成立 + 高专利 + 有融资」的组合，符合这个评分的设计意图。

代理关系要说清楚：成立年限替代「成长性」，但年限长不等于长得快；专利替代「潜力」，但专利多不等于商业化能力强；融资替代「恢复」，但融资次数不等于经营恢复。三项代理各自能解释一部分，合起来不等于上游指数的三维。

结论是「部分支持」：榜可用于筛苗子，但不能回答「这家企业三年后会不会成」。脚本 `code/M_ENT_CULTIVATE_SCORE.py` 只读快照，重跑 0.3 秒。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业服务 → 培育推荐**。页面形态是一张「高成长企业池」：企业名、分数、四维分解、成立年。用户从池里挑企业进入培育计划（场地、补贴、贷款贴息）。

它与 `M_ENT_ATTRACT_SCORE` 互为镜像：招引看外部、培育看本地；招引不限年限、培育限 3—15 年；招引的成长维用资本、培育用年限。两件共用专利与资本数据，因此头部会有重叠（如荣耀在培育榜第一，在招引榜也在前列）。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业服务 → 培育推荐 → 高成长企业池 |
| 页面载体 | 培育推荐列表、企业画像卡 |
| 输出形态 | 企业 × 分数 + 四维分解 + 排名 |
| 更新频率 | 建议半年 |
| 粒度 | 企业级（3—15 年） |

### 1.2 为什么需要这个指标

培育资源有限：场地、补贴、贴息贷款都按名额分配。把资源给「已经很大」的企业是浪费，给「太早期」的企业风险高。3—15 年窗口 + 四维打分，是在资源约束下做筛选的最小可行方案。

第二个用途是政策效果评估。培育计划入选企业的分数分布、一年后的存续与融资情况，可以用来检验「高分是否真的高成长」。本件没有做这个回溯，但分数结构支持后续做。

第三个用途是发现「沉默的好苗子」：专利不少、融资不多、年限在窗口内的企业。这类企业往往被招商忽略，但技术底子好，是培育计划最该覆盖的。

### 1.3 需求文档是否给出定义方法

**需求文档给了维度但没给窗口与权重。** calc-logic 写的是：

> 企业培育评分：综合企业成长潜力、技术创新与资本认可，输出培育优先级。

「成长潜力」怎么算没有说。本件用成立年限代理，这是一个有争议的选择：年限短意味着成长空间大，但也意味着不确定性高。3—15 年窗口是项目经验值，不是甲方给定值。

权重同样未给。本件用 0.35/0.30/0.20/0.15，偏向「年限 + 专利」，因为培育计划主要看技术苗子。

### 1.4 类似指标权威机构构建方法可行性

高成长企业识别在实践中有三类做法：官方的高新技术企业认定、商业的「瞪羚/独角兽」榜单、以及学术的成长模型。三者的共同点是都需要营收或人员增长数据，而库内没有。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 高企认定 | 科技部高新技术企业认定 | 按研发投入占比、专利数、高新收入占比认定 | 认定是二值，且需企业申报 | 中（专利口径可借） |
| B 瞪羚/独角兽榜 | 长城战略咨询等 | 按营收增速、估值筛选 | 需营收与估值，库内无 | 低 |
| C 成长模型 | Penrose 企业成长理论；Gibrat 定律 | 按规模、年龄、创新解释成长 | 需面板数据做回归 | 中（年龄变量可借） |
| D 年龄+专利代理 | 本件做法 | 年限 + 专利 + 广度 + 融资 | 四维均为代理 | 高（可落地） |
| E 上游指数转发 | 项目内培育指数 | 直接转发三维得分 | 上游未出数 | 低（不可用） |

**C 族（Gibrat 定律）**给了一个重要提醒：企业成长率与规模、年龄的关系在实证上很弱。这意味着「年限」作为成长代理的解释力有限——它更像「剩余成长空间」而不是「成长速度」。本件用它是不得已，不是因为它在理论上成立。

**A 族（高企认定）**的专利口径可借：它要求一定数量的发明专利，与本件的专利维同向。但认定是二值，不产出连续分。

**B 族（瞪羚榜）**是最贴业务需求的做法，但它要营收增速与估值。库内营收覆盖 0.734%，估值完全没有，所以这条路走不通。

## 二、计算过程

### 2.1 总体思路与数据流

先按成立年筛候选（3—15 年），再四维取数、归一、加权。筛选在前是因为它决定了榜单的业务含义：同样的公式，窗口改成 0—10 年会得到完全不同的企业池。

四维取数与招引榜共用同一批快照，区别只在年限分与权重。共用是为了让两份榜单可比：同一家企业在两榜的专利分应该一致。

| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 筛候选 | 主档成立年 | 3—15 年 + 有信号 | 93,628 家 |
| 取数 | 专利/资本快照 | 按 org_id 聚合 | 四维原值 |
| 归一 | 候选集 | minmax | 0—1 |
| 加权 | 四维 + 权重 | 求和排序 | top100 |

### 2.2 口径定义与公式

`score = 0.35*growth + 0.30*innov + 0.20*breadth + 0.15*capital`。growth = `1 - (age - 3) / 12`，innov = minmax(log1p(patents))，breadth = minmax(ipc4)，capital = minmax(log1p(events + edges))。

年限分是唯一不需要归一的一维，因为它天然落在 0—1。这也意味着它的分布是均匀的，而其他三维是长尾的——加权后年限分对总分的影响比 0.35 看起来更大。

| 参数 | 取值 | 说明 |
|---|---|---|
| 窗口 | 3—15 年 | 项目经验值 |
| 权重 | 0.35/0.30/0.20/0.15 | 项目默认 |
| 年限分 | 线性递减 | 3 年=1，15 年=0 |
| 候选 | 93,628 | 有信号的窗口内企业 |

### 2.3 候选集与非企业排除

候选集从 43,751 家有成立年的企业出发，筛 3—15 年，再排除非企业主体（高校、机关、社会组织）与无信号企业。剩 93,628 家。

非企业排除在本件尤其重要：高校的成立年往往落在窗口内（如某学院 2010 年成立），专利又多，不排除会占据榜首。这与招引榜的污染机制相同，但后果更严重——培育榜的窗口正好覆盖高校的建校年份。

| 项 | 数量 | 说明 |
|---|---|---|
| 有成立年 | 43,751 | 主档覆盖 |
| 窗口内候选 | 93,628 | 含资本信号补充 |
| 非企业 | 2,462 | 已排除 |
| 年龄窗口 | 3—15 | 年 |

### 2.4 计算步骤（脚本逐步实现）

1）读主档与快照；2）算 age = 2025 - est_year；3）筛 3—15 年并排除非企业；4）四维归一；5）加权排序取 top100。

第 2 步用 2025 做基准年而不是当前年，是为了与专利窗口（2021—2024）对齐。若用 2026，所有企业年龄 +1，窗口边界会移动。

| 步骤 | 实现 | 校验 |
|---|---|---|
| 年龄 | 2025 - est_year | 非负 |
| 筛选 | 3 ≤ age ≤ 15 | 93,628 |
| 归一 | minmax | 0—1 |
| 排序 | 降序 | top100 无并列 |

## 三、数据支撑情况

### 3.1 依赖表与可得性

四维都有数据，但没有一维是「成长」的直接度量。年限是「剩余空间」、专利是「技术存量」、融资是「资本认可」，三者都不是「长得多快」。这是本件判部分的根本原因。

下表逐维列实测状态。要注意年限分的覆盖：只有 43,751/189,116 家有成立年，其余靠资本信号补入候选，这会改变候选集的构成。

| 依赖维度 | 实测状态 | 关键证据 | 缺口与修复路径 |
|---|---|---|---|
| 成立年 | 可用（覆盖 23.1%） | 43,751/189,116 | 回填登记日期 |
| 专利 | 可用 | 134,152 家 | 无 |
| IPC4 广度 | 可用 | 634 类 | 无 |
| 融资/被投 | 可用（代理） | 25,654 + 46,967 | 补营收做真成长 |
| 营收增速 | 不可用 | 覆盖 0.734% | 需甲方提供财报 |

### 3.2 四判定落表

结构齐、数据有，但语义不齐。这是「部分支持」的典型形态：不是缺表，是缺正确的变量。任何用「年限」当「成长」的评分，都会把「老但没长」的企业排低、把「新但还没证明」的企业排高。

| 判定项 | 结论 | 证据 |
|---|---|---|
| 表结构直接支持（开发库+三方库） | 否 | 无培育评分结果面 |
| 表数据直接支持（开发库+三方库） | 否 | 上游指数未出数 |
| 依赖表结构支持（开发库/三方库） | 是 | 主档/专利/资本齐全 |
| 依赖表数据支持（开发库/三方库） | 部分 | 成立年 23.1%、营收不可用 |
| 聚合结论 | 部分支持 | 可筛苗子不可预测成长 |

### 3.3 数据量、覆盖与代表性

覆盖上，93,628 家覆盖了窗口内有信号的企业，无抽样。但「有信号」筛选掉了无专利无融资的企业，这类企业可能是真正的「沉默苗子」。

代表性上，头部集中在「新成立 + 高专利」的企业，符合设计意图，但忽略了「慢成长但稳健」的企业。后者在培育场景里同样重要，只是这个评分看不见它们。

### 3.4 结构支持判定

结构侧够用：主档有成立年、专利表有申请人、融资表有主体。三张表能按 org_id 聚合。

缺的是「营收增速」字段。利润表有营收，但覆盖 0.734%，且集中在上市公司——用它做增速会让榜单只剩上市公司。这不是结构缺失，是数据不可用。

### 3.5 与开发库 live 的差异

开发库无此结果面，live 不产出。上线需落数仓并保存四维分解与窗口参数。

建议物化时保存 `candidates.age_window`。只存分数会让「为什么这家没上榜」无法回答（可能是年龄不在窗口）。

## 四、数据缺失情况

### 4.1 缺口清单

缺口有三类：上游指数缺数（已代理）、营收增速不可用（无法补）、权重未裁定（默认值）。第一类已绕过、第二类无解、第三类待决策。

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| 上游培育指数 | 三维无出数 | 四维代理 | 上游出数后替换 |
| 营收增速 | 无法度量真实成长 | 用年限替代 | 甲方提供财报或统计口径 |
| 权重 | 非甲方认可 | 默认值 | 甲方裁定 |
| 非企业污染 | 高校会占榜 | 类型过滤 | 无（已解决） |
| 外地企业 | 培育资源应给本地 | 未过滤 | 加 city 过滤 |

### 4.2 逐条影响

年限分的偏差方向是明确的：它奖励「年轻」。一家 2012 年成立、十年稳定增长的企业，年限分只有 0.25；一家 2022 年成立、还没营收的企业，年限分是 1.0。这在「培育苗子」的语境下可以接受，但在「识别高成长企业」的语境下是错的。

营收覆盖率 0.734% 这个数字值得再看一眼：它意味着 189,116 家企业里只有 1,388 家有可用营收（全期），2014 年之后逐年塌陷。任何试图用营收做增速的指标，都会退化成「上市公司分析」。

外地企业未过滤也是一个业务问题。培育计划是地方财政支出，给外地企业打分没有意义。本件保留全量是为了让榜单可用于「招引 + 培育」联动，但页面使用时应该加城市过滤。

### 4.3 明确不做什么（禁止的替代）

- 不把年限当成长速度——它只是剩余成长空间
- 不把高校排进培育榜——建校年份会落进窗口
- 不把代理分当验收值——上游指数未出数
- 不用营收算增速——覆盖 0.734%，会退化成上市公司榜
- 不把外地企业纳入本地培育池

## 五、与既有口径的对照

**先纠正一处出处错误。** 本件早期版本把口径写成「王惠三维：成长潜力／技术创新／资本认可」，并引 `指标计算逻辑-V2/M_ENT_CULTIVATE_SCORE.md`。该文件在整个仓库里不存在，属编造出处。真实的 calc-logic 文件是 `calc-logic/ENT/M_ENT_CULTIVATE_SCORE.md`，它的定义是：

1. `cultivate_score = M_ENT_CULTIVATION_INDEX`——本指标是综合指数的**别名**；
2. 三维（产业相关度、政策匹配度、企业潜力）**只在 INDEX 叶算**，本条不重写，也禁止「另算一套三维」或拿增长率类指标顶替。

所以本件的三维加权不是既有口径的实现，而是本报告在缺 INDEX 的情况下自建的替代算法。验收按「按维度重建」的标准看，不按「按公式实现」看。

本件三维都出了，但成长用年限代理，这是最大的偏差。

对照要承认：年限不是成长。Gibrat 定律的实证结论是「成长率与年龄关系弱」，用它做代理在理论上就站不住。本件用它，是因为没有更好的选择。

如果甲方要求真实成长性，正确做法是等 INDEX 批次出数后读指数，而不是继续给代理维度加权。

**选用建议**：指标语义沿用需求原文，数据源按本件实测替换；两者冲突处（缺表、缺字段、缺年份）以实测为准，并在附录 K 登记为待甲方裁定项，不自行改写指标名与业务含义。**三维权重属本件自定义，待甲方确认。**
