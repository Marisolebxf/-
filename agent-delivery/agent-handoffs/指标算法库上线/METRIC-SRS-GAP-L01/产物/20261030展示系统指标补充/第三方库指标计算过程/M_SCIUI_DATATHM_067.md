### 1.2 为什么需要本指标

资源总量回答「平台积攒了多少家底」：它是总览 KPI 的**规模主读数**——类型数（宽度）与主题库数（组织）都以它为背景；年度趋势线把它展开为**存量序列**（累计口径 total + 流量口径 added 双线），管理者看 13.8% 的增速衰减判断平台进入成熟期还是饱和期；下钻汇总（30,398/21,198）提供按来源/主题的分解视图。需求语境 seq 330「类型与数量……年度增长趋势」——本件是「数量」的主形态。权威对应物是数据资产管理口径（DAMA-DMBOK）：资产总量的标准双形态——资产条目数（计数维）与存储量（容量/行数维）——两维并行登记是资产报表惯例。本库场景下，该读数要求资源目录（计数维）或目录×行数登记（记录维）存在——两维三源均无承载面。

### 1.3 需求文档是否给出定义方法

**需求文档未给出总量的定义方法。**「资源总量」字面三份说明书无独立立项项（seq 330「类型与数量」的数量维是其最近锚；「年度增长趋势」提供序列语境）；**「（记录）」后缀无需求侧来源**——UI 全部读数单位是「个」（资源计数维），记录维（行数）在需求与 mock 均零出现，该后缀应是 UI 指标清单编者的口径注记（意图把总量锚到存储记录维）。**总量口径三无**：计数维（资源个数 vs 存储记录数——两维可差 3-6 个数量级：30,398 个 vs dev Σ≈985.6 万行/gkx Σ≈6,581.5 万行）；累计规则（存量累计 vs 当期在架——趋势线 total 是累计口径）；行数归属（一资源多表时行数怎么归并——表是载体非资源）。UI 的 30,398 是 mock 手写值，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

资源总量的权威方法分三层。其一，数据资产管理口径（R1 DAMA-DMBOK）：资产总量双维并行——条目计数（COUNT 目录）+ 存储量（Σ 容量/行数）——两维各自登记不互换；其二，数据治理平台工程口径（R2 Dataphin/Atlas）：资产盘点报告的存储量统计——表级 ROW_COUNT/存储容量聚合，粒度=表（一表一资产口径下表行数即资产行数）；其三，统计口径国标（R3 GB/T 33850）：资源统计以登记台账为准——登记什么算什么。方法族对照：

| 方法族 | 原料 | 总量机制 | 与三源匹配 |
|---|---|---|---|
| 目录计数+存储量双维（R1） | 资源目录+行数登记 | COUNT + Σ 双读数 | **目录双缺**（承 063） |
| 表级行数聚合（R2） | 元数据库 ROW_COUNT | Σ 表行数 | **部分有**（dev 估算/gkx 缓存/久新可 COUNT）——口径混杂 |
| 台账统计（R3） | 归集台账 | COUNT | **无台账** |
| 前端演示 | mock 常量 | 手写 5 年链 | 结构披露（不作源） |

结论：R1 双维的第一层原料（目录+行数登记）三源无承载；R2 表级行数聚合**部分可得**——dev Σtable_rows≈9,855,673（InnoDB 估算）、gkx 缓存 280 表 Σ≈65,814,945（采样外推含）、久新 215 张可逐表 COUNT（本件抽验两张）——但三源口径混杂（dev 含系统面/gkx 是要素明细/久新是论文聚合），合并值不发布。「表级近似可得、资源粒度缺位、两维断裂」构成本件部分支持的判定结构。与 063（计数维总量——同根正面件）、065/066（类型轴）、056（覆盖——混同母体链）连坐。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：按 R1→R3 路径推测，总量有双维形态——

$$N_{\text{total}} = \text{COUNT}(\*) \; \text{FROM 资源目录} \; R \qquad \text{（计数维——UI 呈现维，单位「个」）}$$

$$V_{\text{records}} = \sum_{r \in R} \text{ROW\_COUNT}(r) \qquad \text{（记录维——指标名「（记录）」维，单位「行/条」）}$$

UI 挂载的是计数维（30,398 个）；指标名带「（记录）」暗示记录维——两维并行登记不互换（R1 双维惯例）。**表级近似**（若裁定总量=全库行数）：$V \approx$ Σ 三源表行数——dev 9,855,673（估算）/gkx 65,814,945（外推含）/久新未全量——**口径混杂不合并**（系统面/要素明细/论文聚合三语义不同层）。**口径三未裁**：计数主维（个 vs 行——单位断裂）、累计规则（存量累计 vs 当期在架）、行数归属（一资源多表归并）。**前提是资源目录（±行数登记）存在，三源实测无（承 063）**——公式列示仅作口径锚（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①资源目录立项（含行数/容量字段）→ COUNT 与 Σ 双维直查 → 升**完全直接支持**；②甲方裁定「总量=全库行数」+ 三源精确 COUNT（gkx 去外推/久新逐表）→ 表级转正 → 升**完全转换支持**；③维持现状 → 部分支持（KPI/趋势建议标注演示值或「暂无数据」；「（记录）」后缀建议从清单撤下或注明待裁）。

seq 330「类型与数量」的数量主形态+「年度增长趋势」——**不满足**（资源粒度与行数登记双缺、逐年序列 base_years 全缺）；「全库行数参考」——部分满足（dev 估算值可挂参考位，须标注估算+系统面含入）。预评与触发器对齐：目录立项（含行数字段）则 063/067 计数双维齐升。

## 四、数据缺失情况

### 4.1 目录×行数登记零承载（结构级，记录维判定性缺口）

资源目录（计数维）承 063 缺位；目录×行数登记（记录维）三源亦零承载——dev table_rows 是表级估算（载体粒度），gkx 缓存是要素明细行数（要素粒度），久新是聚合指标行（指标粒度）——**三源行数的语义粒度互不相同**，均非「资源记录数」。**本件的连坐面**：与 063 是同根双维件（目录立项则计数维双升；行数字段补齐则记录维独升）；056 的覆盖率分母、065 的分布分母都吃本件总量口径的裁定结果。**四缺失情形归属「表不存在」**：修复动作是资产目录立项 schema 含行数/容量字段（或元数据采集器行数回填——Dataphin 式采集体检）。

### 4.2 计数维与记录维单位断裂未裁（口径级，本件独有判定性缺口）

本件降档的口径层根因：**「个」与「行」差 3-6 个数量级**——UI 呈现 30,398 个（资源计数维），指标名「（记录）」指向行数维（dev Σ≈985.6 万/gkx Σ≈6,581.5 万）——不裁主维则任何「总量」读数都无唯一解。正式版须裁定：①计数主维（资源个数 vs 存储记录数 vs 双维并行——R1 双维惯例可参考）；②累计规则（存量累计 vs 当期在架——趋势线是累计口径）；③行数归属（一资源多表的归并规则）+ 三源行数的语义粒度统一（系统面剔/要素明细/聚合面剔）。此裁定与目录立项解耦，可先行。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 资源目录立项（含行数/容量字段） | 数据工程立项 | 本件 + 063/064/065/066/056 | 触发器①（目录族共享；行数字段是本件记录维独有要件） |
| 计数主维裁定（个 vs 行 vs 双维） | 口径裁定 | 本件 | 单位断裂实证在前，可先行（即期一纸） |
| 三源精确 COUNT 工程（gkx 去外推/久新逐表） | 数据工程配套 | 本件 | 触发器②（若裁定总量=全库行数） |
| UI KPI/趋势标注演示值或空态 | 展示规范 | 本件 UI | 30,398 及 5 年链建议撤下（循环自证链） |

档位后果：目录+行数字段 → **完全直接支持**（COUNT/Σ 双维直查）；裁定行数维+精确 COUNT → **完全转换支持**；现状 → 部分支持。推荐顺序：主维裁定（即期）→ 目录立项（含行数字段）→ 三源精确 COUNT（若走行数维）。
