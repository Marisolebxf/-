## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/技术发展跟踪（下游页面：科技发展规划/科技指数/技术创新评价）。挂载点 `techDevelopmentPlan.js:300`：`buildMetrics(planRecords)` 的第五个 KPI——`{ key: 'rising', label: '上行占比', value: Math.round((risingCount / count) * 100), unit: '%', direction: …, trend: … }`，其中 `risingCount = records.filter(item => item.growth >= 0).length`（`:292`），`count = Math.max(1, records.length)`（`:291`）。同型实现另有两处：`techIndex.js:320`「上行占比」与 `techInnovationEvaluation.js:297`「上行对象占比」，公式同构。

UI 实现给了两个关键语义锚点：其一，**分子含 0**（`growth >= 0`，持平计入上行）——这是「改善面」口径（不恶化占比），不是「增长面」口径；其二，**对象域是规划记录**（planRecords，mock 7 条规划方向）。这两点构成本件复刻口径的基准（§2.2），同时 0 值归属作为口径敏感点双口径并列（B10）。

### 1.2 为什么需要本指标

规划页 KPI 条已有绝对量（优先级均值、热点数、潜力均值、预警数），「上行占比」补的是**方向面**：不是「现在多好」，而是「有多大比例的对象在变好」。它是资源配置的信心指标——上行占比高说明面上改善、可维持投入节奏；低则说明改善集中少数对象、需排查面上恶化原因。官方叙事同型先例：国家统计局发布中国创新指数时逐领域报「5 个评价指标指数全部实现增长」「四升一平」（R4）——「几升几平几降」的计数式表述就是这个指标语义的官方形态。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** SRS《技术发展跟踪》8 叶无「上行」字样（seq 48–55 全叶核对）；《科技全域态势》16 叶亦无；《科技信息展示系统和科技专题服务系统.md》rg 检索「上行」0 命中。指标名、分子含 0 口径、对象域定义全部来自 UI 实现（techDevelopmentPlan.js），属前端自造。

### 1.4 类似指标权威方法可行性分析概要

「上行/改善占比」在官方统计中的先例是国家统计局中国创新指数的领域指标升降表述（R4：「创新环境指数 5 个评价指标指数全部实现增长」「创新成效指数 5 个评价指标指数四升一平」）；OECD MSTI 则以复合年均增长率（CAGR）作趋势口径（R2）。方法族对照：

| 方法族 | 比较口径 | 0 值归属 | 与本库匹配 |
|---|---|---|---|
| 升降计数（官方叙事型，R4） | 逐指标同比 ±/0 计数 | 并列报「几平」 | **高**（节点同比计数即得） |
| UI 同构（≥0 含持平） | growth>=0 占比 | 计入上行 | 高（复刻口径 A） |
| 严格增长（>0） | growth>0 占比 | 排除 | 高（口径 B） |
| CAGR（OECD 型） | 多年期年均增速 | 不适用 | 中（多年期窗口另议） |

结论：升降计数族三口径全部现转可得，本件以 UI 同构为主口径、严格增长并列、官方叙事型（升/平/降三分计数）作解读语言。完整版见附录 C。

## 二、计算过程

### 2.1 方法选择（文献依据）

采用「同对象两期比较 + 升降计数占比」：以官方「几升几平几降」计数叙事为语义基准（R4），分子定义复刻 UI 实现（`growth >= 0`，techDevelopmentPlan.js:292 实测代码），同时并列严格上行口径。选择理由：其一，该口径有 UI 实现作需求侧锚点（前端作者已把「含持平」写成代码，这是比 SRS 更强的口径证据）；其二，两期比较只需面板表相邻两年交集，无外部参数、无权重设定，转换链最短；其三，双口径并列把 0 值归属的裁定权显式交给甲方（B10），避免单口径交付后被推翻。

### 2.2 分步构建

**Step 1（面板装载与年份选择）**：久新 `ads_technology_yearly_metrics` 按 `statistics_year` 计数（`facts.jiuxin_tech_yearly_metrics_by_year`）：2026:3,450 / 2025:12,278 / 2024:12,698 / 2023:14,054 / 2022:14,147 / 2021:14,526 / 2020:11,725 / 2019:9,186。终年选 2025（12,278 节点、写入完整），基年选 2024（12,698）——2026 年仅 3,450 节点、尚在写入期（不选作终年，产物 base_years_note 写明理由）。

**Step 2（交集）**：同节点 2024∩2025 自 JOIN，交集 **9,280** 节点（`facts.jiuxin_overlap_2024_2025_nodes`）——两并集的 75% 左右，交集规模远超样板基准（≥100），数据量判定足额。

**Step 3（升降计数）**：在交集上比较 `paper_count`：`b.paper_count >= a.paper_count`（口径 A）命中 **6,270**；`>`（口径 B）**1,514**；`<`（下降）**3,010**（`facts.jiuxin_rising_ge0_paper_2024_2025` / `…gt0…` / `jiuxin_falling_paper_2024_2025`）。三分计数 6,270/3,010 与交集对账：6,270+3,010=9,280 ✓（口径 A 分子含持平 4,756，持平 = 6,270−1,514 = 4,756，可复算核对）。

**Step 4（占比）**：口径 A **67.5647%**（6,270/9,280）、口径 B **16.3147%**（1,514/9,280）（`derived[0]/[1]`，分子分母同 JOIN 同交集，share_basis=两年交集面板）。

**Step 5（可推广性验证）**：换 `institution_count` 列复算口径 A 得 **5,949**、占比 **64.1056%**（`derived[2]`）——方法对其他指标列可推广，且两列读数同向（约 2/3 节点不下降），交叉印证面板质量。

## 四、数据缺失情况

### 4.1 「规划记录」对象域无承载（对象域级，主待裁定项）
