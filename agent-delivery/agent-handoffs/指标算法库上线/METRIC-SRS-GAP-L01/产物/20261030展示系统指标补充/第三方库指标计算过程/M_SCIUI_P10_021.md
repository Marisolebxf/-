## 一、需求定义概述

### 1.1 所属功能模块

科技信息展示系统 → 科技成果展示 → 创新载体孵化载体（New 页族）→ 运行绩效与增长趋势智能监控 tab →「用户评价与满意度报告」卡（`IncubationCarrierNewPage.jsx:1330` SectionCard）。卡结构双面：`:1339-1343` 评分面（`operations.satisfaction.score` 4.6 + `<Rate readonly allowHalf>` + `responses` 386 份·满分 5 分）；`:1345-1353` 归纳面（优势项 `advantages` 4 Tag 绿色 IconCheckCircleFill / 改进建议 `improvements` 3 Tag 橙色）。页尾 KpiTile（`:1505`）为同数据的摘要位（P10_008 件）。mock 源 `mockData.js:828-834`。

### 1.2 为什么需要本指标

满意度报告是载体服务的反馈闭环与改进依据：评分面给总体水位，优劣项归纳给改进优先级（SRS 556 需规原文「为载体升级服务标准、增强品牌影响力提供数据支撑」）——归纳面是「报告」二字的核心（评分只是数字，优劣项才是行动指南）。

### 1.3 需求文档是否给出定义方法

**三份说明书未给出该指标的计算方法。** SRS 556 只给功能行为（循环收集评价和评分、自动归纳服务优劣项及改进建议），无归纳口径（优劣项判据/聚类方法/条数）、无量表、无批次规则。mock 优劣项为静态文本数组，连演示算法都不存在。

### 1.4 类似指标权威方法可行性分析概要

权威口径方法族（完整版指向附录 C）：①火炬统计调查制度（在孵企业满意度问卷字段——采集锚，与 P10_008/ SOFTSCI_012 同锚）；②政府网站/公共服务绩效评估（满意率+意见归类双报告制）；③文本主题归纳（LDA/聚类方法族，归纳面的方法学）。①②需采集系统；③需原文流——三源零承载下均不可落地。完整版见附录 C。

### 4.3 影响面

绩效监控 tab 报告卡双面全 mock；SRS 556「循环收集+自动归纳」承诺整链无数据支撑（采集与 NLP 双缺）。
