## 摘要

「供应方调用量占总量百分比」是应用视窗「数据供应方数据被调用情况」族的结构占比读数：mock 给 5 家供应方（中科院/清华/深圳市政府/华为/北大）share 43.8/23.8/16.0/10.9/5.5（合计恰 100.0，分母 2,856,000 为 5 家 totalCalls 之和）。指标名三份说明书 0 命中（语义锚 SRS 应用视窗 seq 388-391 供应方功能族）。数据侧判定核心是按供应方归集的调用日志面：三源词族逐一 0 命中；dev 的 supplier 唯一命中是造数关系整表（禁引）；gkx 唯一现成切面 `table_data_source` 实测标签全 NULL（zh_paper 非空 0 行/scholar 全 'gkx_ods' ETL 标记/patent 采样框全 NULL）——静态标签无调用量信息，替代路径也不通。分子分母两侧承载面均不存在，判**完全不支持**。脚本已跑通（含替代切面实测），产物与正文数字逐一对应。

- 需求判定：**UI 派生读数**（指标名 0 命中；供应方功能族 seq 388-391 在、占比算式无）。
- 复现状态：脚本已跑通；三源词族排除 + gkx 来源标签切面实测全落产物。
- 档位结论：**完全不支持**（供应方维度调用流水三源零承载，替代切面实测不可用）。
- 关键事实：`table_data_source` 是本组判「来源维度有无」的现成切面——100,900 行论文标签 0 非空，说明 gkx 侧连静态来源分布都无，更无调用侧流水；该读数同时服务 016/023/024/026 的同族判断。
- 升档路径：API 网关日志接入（含供应方/资源归属维度）→ 完全直接支持（触发器①）；供应方登记面+静态折算 → 部分支持（触发器②，口径披露「静态折算非实测」）。

### 1.2 为什么需要本指标

供应方占比回答「数据从谁家来、被用得多不多」：饼图（getSupplierPieOption 用 totalCalls 作值）+ 排行榜（supplierRankColumns 含占比列）+ 累计表三视图共用 share 读数，管理者据此识别供给集中度（头部供应方是否垄断）、定位数据供应源（部门归集卡）、评估各供应方资产活跃度。权威对应物是国家数据局《公共数据资源授权运营监测评估指南》（R1）的「授权运营数据条目占比」（授权运营数据 ÷ 全部公共数据资源）与数源部门覆盖率族——官方监测评估在资源汇聚维同样用「部分÷全部」的结构占比口径，但分子的计量单位是**数据条目/资源数**而非调用量（因官方口径同样依赖调用流水，全国层面以共享枢纽调用次数总量披露为主，R3 政务数据共享枢纽累计支撑调用超 5,500 亿次）。本库场景下该读数要求按供应方归集的调用日志存在——与 020（接口平均响应时长）同根于「API 调用日志面缺失」缺口，本件要的是其中的**供应方归属维 × 次数维**。

### 1.3 需求文档是否给出定义方法

**三份需求说明书未出现「供应方调用量占总量百分比」指标名。**语义锚四叶功能在：SRS seq 389「基于实时调用日志和历史行为数据，自动统计每个供应方的数据累计被调用次数，支持按时间区段、业务类型、数据产品等多维度切换」——「累计被调用次数」是功能分句、占比算式无；seq 388「对所有供应方进行智能归类，对调用数据的部门归属自动识别和展示」；主需求 :2555「资源应用状态的具体功能包括应用系统状态监控、资源接口状态跟踪、资源应用主体详细列表、累计调用与趋势分析」；:2861 供应方/需求方/业务应用三详情叶总述。核心需求文档《科技信息展示系统和科技专题服务系统.md》与核增、算法库 0 命中（附录 A.2）。UI 的 share 是 mock 演示值，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

占比口径的权威锚分三层。其一，国家数据局监测评估（R1）：公共数据资源授权运营的「汇聚范围」维用授权运营数据条目占比（分子=纳入授权运营范围的目录条目数，分母=全部可汇聚数据资源总条目）——官方「占比」的结构与 B3 同基要求一致（分子分母同目录体系）。其二，全国数据资源调查（R3）：调用量侧只披露全国总量（政务数据共享枢纽累计调用超 5,500 亿次），不披露分供应方占比——侧面证明分主体调用量占比需要平台级流水台账，国家级调查也只能拿到总量。其三，平台运营实践（R2 上海平台）：数据指数页展示接入数据部门/资源数量/下载次数等统计，应用注册制下的典型应用库可数「应用数」——平台侧统计的可行口径是登记面计数 + 接口调用总量，分供应方调用占比需网关日志。方法族对照：

| 方法族 | 代表 | 原料 | 口径 | 与三源匹配 |
|---|---|---|---|---|
| 监测评估占比 | R1（NDA 指南） | 资源目录 | 条目占比（部分÷全部同目录） | 无目录面 |
| 全国调查总量 | R3（数据资源调查） | 平台上报 | 调用次数总量 | 无流水面 |
| 平台统计面 | R2（上海平台） | 登记面+调用统计 | 部门数/下载次数 | 无登记面 |
| 前端演示 | UI share 43.8% | mock 常量 | — | 结构披露（不作源） |

结论：三条权威路径的原料（资源目录/调用流水/登记面）三源均无承载。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：按 UI 同基设计推测

$$\text{Share}_s = \frac{\text{Calls}_s}{\sum_{s' \in S}\text{Calls}_{s'}} \times 100\%,\quad S=\text{当前筛选集内全部供应方}$$

即供应方 s 的被调用量占当前口径全平台调用量的百分比（分子分母同筛选集同时间窗——UI :433-436 即此设计，保留 1 位小数）。**前提是按供应方归集的调用日志面存在，三源实测无（§3.3）**——公式列示仅作口径锚，不构成可执行计算（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①API 网关日志接入且含供应方/资源归属维度 → 升**完全直接支持**（工程立项，与 020/021/022 族共用）；②建供应方登记面 + 按资源归属静态折算 → 升**部分支持**（口径须披露「静态折算非实测调用量」）；③维持现状 → 完全不支持（UI 该位建议保留「暂无数据」而非 mock 43.8）。

## 四、数据缺失情况

### 4.1 调用日志面与供应方登记面双缺（结构级，判定性）

占比的分子分母同根于一张按供应方归集的调用日志（供应方 × 资源 × 时间戳 × 次数）。三源实测零承载（§3.3）——与 020/021/022 同族：需求 :2563 把「API日志采集」写进功能描述（工程前提自宣）而 dev 库内无承载表。比 020 更深一层：本件还需要**供应方归属维**——即便接入通用调用日志，若日志不携带资源→供应方映射，占比仍不可算（需供应方登记面联表）。**四缺失情形归属「表不存在」**：修复动作是 API 网关日志接入（带资源归属）或「网关日志 + 供应方登记面」两件套——族级共用工程（020/021/022/013 四件一次升档）。

### 4.2 gkx 来源标签不可用（数据级，替代路径排除）

派单书提示的 `table_data_source` 切面实测三层不可用（§3.2）：标签全空（zh_paper 0 非空）、唯一非空值是 ETL 批次号（scholar 'gkx_ods'）、静态标签无调用量信息。该结论对同批同族件（016/023/024/026 的「来源维度有无」判断）同样成立——gkx 侧无任何可用的主体/来源归属维度。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| API 网关日志接入（含供应方/资源归属维） | 监控工程立项 | 本件 + 020/021/022 族 | 触发器①（族级共用） |
| 供应方登记面 + 静态折算 | 数据工程 | 本件 + 023/024/026 登记面族 | 触发器②（口径披露「静态折算非实测」） |
| UI 暂无数据态 | 展示规范 | 本件 | mock 43.8 建议替换为「暂无数据」 |

档位后果：网关日志带归属维 → **完全直接支持**；登记面+静态折算 → **部分支持**；现状 → 完全不支持。推荐顺序：网关日志为主线（四件共用），登记面随主体族（023/024/026）立项同步建。
