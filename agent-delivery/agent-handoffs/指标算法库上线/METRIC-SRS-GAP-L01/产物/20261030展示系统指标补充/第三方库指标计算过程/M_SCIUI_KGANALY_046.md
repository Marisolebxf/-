### 1.1 所属功能模块

### 1.2 为什么需要本指标

静态社群划分回答「现在有哪些圈子」，演变追踪回答「圈子怎么来的、往哪去」：形成（新领域诞生）、扩展（热度上升人才涌入）、分裂（方向分化）、消亡（领域衰落）——是技术生命周期管理和技术布局时机判断的时序依据（seq 436 原文「揭示知识演进的过程和社群生命周期规律」）。对管理者的价值：新兴社群（born_year 近+斜率陡）是前瞻布局信号；大社群增长停滞是成熟期信号；消亡风险社群的成员去向是人才流动预警。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**SRS《算法展示.md》seq 436 写「支持追踪社群随时间的形成、扩展、分裂与消亡等动态变化，揭示知识演进的过程和社群生命周期规律」——四类事件的判定标准（什么算分裂？成员流失超 X%？连通性断开？）、时间粒度（半年/年）、社群同一性（跨期怎么认定是同一个社群）全部未言明。UI mock 用模板规则（idx=1 分裂/末位消亡）占位。检索记录见附录 A.2。

### 1.4 类似指标权威方法可行性分析概要

社群演化追踪是动态社群发现（dynamic community detection）领域，权威锚三重。其一，动态社群综述（R1 Rossetti & Cazabet 2018《A Community Discovery Approach for Explaining Biological Networks》：社群事件分类学——form/grow/shrink/merge/split/die 六事件的经典分类（与需求四类几乎一一对应）；其二，时序网络方法（R2 Holme & Saramäki 2012 Temporal Networks 综述）：快照序列（snapshot sequence）vs 流式（streaming）两种建模范式——快照法需要多期图快照，流式用事件流；其三，NetworkX/CDLib 生态（R3 CDLib dynamic 模块）：事件检测的工程实现形态。本库现状适配评估：无多期图快照（单截面），但有**节点级时间锚**（first/latest_publication_year）——可走「入场时间锚的累计规模演变」（本件实算口径：R1 事件分类中的 form/grow 可算，shrink/split/die 需快照序列）。方法族对照：

| 方法族 | 代表 | 本库承载 | 贴合度 |
|---|---|---|---|
| 事件分类学（R1） | form/grow/shrink/split/die | form/grow **可算**（入场锚）；后三需快照 | 中（部分可算） |
| 时序网络（R2） | 快照/流式 | 无快照无事件流；有节点时间锚 | 中（锚替代） |
| 工程生态（R3） | CDLib dynamic | 算法可移植 | 中 |
| 前端演示 | mock 六期 | 线性放大 | 纯占位 |

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**定义（本件按入场时间锚重建，推测定义）**：

$$\text{Size}(c, t) = |\{v \in c : \text{first\_publication\_year}(v) \leq t\}|$$

社群 $c$ 在 $t$ 年的规模=入场年不晚于 $t$ 的成员累计数。形成年 born(c)=min 入场年；扩展斜率=ΔSize/Δt。**待裁项**：时间锚选择（入场锚 first vs 活跃锚 latest——双列都在且 100%，本件用入场锚）；事件判定阈值（分裂/消亡的标准）；社群同一性（跨快照对齐——当前单截面免议）。

**降档/升档触发器（B10 模板）**：①现状入场锚可算（本件已验证）→ 维持完全转换支持（form/grow 两事件可交付）；②甲方要求分裂/消亡事件 → 需图快照序列（graph_release_id 多版本落库）→ 当前不可算，该两事件**超出本件档位承诺**（披露为能力边界非数据缺失）；③快照序列落库 → 升完全直接支持+全事件可算；④久新图下线 → gkx 无时间维，降部分支持。

### 2.3 读数解释与双锚披露

**形成/扩展可算**：born_year 是「该技术首篇论文发表年」（社群的学术起点），累计曲线的爬升段即扩展期。Top3 社群 born 于 1852-1901——这些是经典基础领域（长周期累积）；近端 2015-2021 入场的节点挂在哪些社群，曲线斜率即「新兴 vs 传统」的分野。**双锚披露（B10）**：first_publication_year（入场锚）与 latest_publication_year（活跃锚，同样 100% 覆盖）给出两种演变叙事——入场锚答「成员什么时候加入」，活跃锚答「社群什么时候还活跃」；本件实算用入场锚（与「规模演变」语义最近），活跃锚口径（如「社群活跃年窗」）同源可算待裁。**不可算披露**：分裂/消亡事件需要成员退出维（当前图谱节点只进不出）或多期快照对比——mock 的事件模板（idx=1 必分裂）无数据支撑，本件不交付该两事件（§1.6 触发器②）。

### 2.4 与 UI 演示形态的衔接

UI 现状六期 mock（2023-H1..2026-H1）。接入真数据路径：本件序列（132 年年度轴）按展示需求截窗——近 10 年窗口（2016-2026）覆盖 95%+ 入场量（直方图近端密集）；折线图数据结构（社群×时点×规模三元组）与本件 `top5_series` 同构，前端 `buildCommunityLifecycle` 换 API 数据即可；Timeline 事件卡只保留「形成（born_year）+扩展（斜率分段）」两类真事件，分裂/消亡卡在快照序列上线前隐藏。全图 SQL 秒级——无需夜批。

### 2.5 稳健性与口径敏感性

**（a）年份长尾**：1776-1900 的年份值是论文发表年长尾（早期年均 <5 篇），不是数据错误；序列对此不敏感（累计曲线在早期平坦）。若甲方要求近窗口（如 2000+），截窗即可。**（b）社群同一性**：本件社群归属是**当前截面**的 community_id（上游算法一次性划分）——历史「本应属于别的社群后来迁移」不可见（单截面固有限制，非数据缺失）；快照序列上线后可做跨期对齐。**（c）单例社群**：1,708 个单例社群（1 节点）的「演变序列」是常数 1——本件 Top5 序列只呈现非单例大社群；单例社群的演变语义（孤立技术点）单列披露不混入曲线。

## 四、数据缺失情况

### 4.2 快照序列缺失（能力边界级，非本件档位缺口）

分裂/消亡事件需要**多期图快照**（同一图谱的历史版本对比）或成员退出维。现状：`graph_release_id` 列在边表存在（版本号机制有设计）但本库只有单一版本数据（无历史快照表）；节点表无退出标记（图谱只进不出）。**这不是本件判档缺口**（form/grow 已足额交付）而是 seq 436 后两事件的能力边界——按 B10 触发器②登记：快照序列落库后可升完全直接支持+全事件可算。

### 4.3 修复建议与影响面
