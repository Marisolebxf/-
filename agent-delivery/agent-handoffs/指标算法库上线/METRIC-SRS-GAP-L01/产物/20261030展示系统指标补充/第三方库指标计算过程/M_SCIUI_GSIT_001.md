## 摘要

- 需求判定：三份说明书未出现「论文总数」指标名（SRS 16 叶逐一核对，最近叶 seq 10「统计指标展示功能」为功能级描述）——UI 自造指标名。

- 档位结论：**完全直接支持**（两源主档直查，零加工）。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/科技全域态势/科创要素/统计指标展示功能（SRS seq 10，excel_row 13）。页面形态是多图层 GIS 全景大屏：顶部 KPI 条给出「论文总数 / 专利申请 / 创新机构 / 科技项目」四个数字读数（`buildStats()` 按 base×scale 计算，`overviewData.js:578`），页面下方要素趋势区另有「论文总数」七年序列（`trendSeriesByFactor.paper`，`overviewData.js:54`，rawValues 979.0→1296.0 万篇、rawUnit 万篇）。

两处挂载的语义不同值得分开记录：KPI 位是「当前时点库存总量」一个数；趋势位是「逐年存量演进」七个数。mock 侧两套数字也不同源——KPI 位 base=2,960,000（篇），趋势位 1,296.0 万篇（2026 年值）——说明前端作者自己就把「存量口径」与「演示口径」写岔了。本件按 KPI 位语义（库存总量）判档，趋势位序列属同域下游（逐年切片），数据面同源支持。

### 1.2 为什么需要本指标

论文是科创要素体系的第一个产出要素（SRS seq 9 基础信息查看功能把论文列为九类要素之首）。全景大屏的叙事是「先给总量、再给分布」：论文总数回答「这个系统里有多大体量的论文资产」，是用户建立规模信任的第一读数——后续分布比例、增长趋势、关联分析都以它为分母或基线。没有这个总数，要素图层的密度与热度就没有量纲锚点。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** SRS《科技全域态势》16 叶中无「论文总数」字样；seq 10 统计指标展示功能仅给功能行为（「数量统计、分布比例、增长趋势」「柱状图、饼图、折线图」），未点名任何具体指标名，更无计数口径（收录库范围？语种？年份切片？）。《科技信息展示系统和科技专题服务系统.md》rg 检索「论文总数」0 命中。

### 1.4 类似指标权威方法可行性分析概要

「论文总数」的权威口径由中信所《中国科技论文统计报告》体系定义（R1/R2）：以国际权威检索数据库（SCI/Ei/CPCI-S/SSCI）与《中国科技论文与引文数据库》（CSTPCD）收录为准，按「检索库收录量」计数，2024 年中国作者 SCI 论文 86.68 万篇、卓越科技论文 75.95 万篇（R1）。方法族对照：

| 方法族 | 计数基准 | 与本库匹配 |
|---|---|---|
| 检索库收录量（中信所） | SCI/CSTPCD 收录条数 | **高**（久新池即 OpenAlex 收录池；gkx 池即中文库收录池） |
| 年度流量（Web of Science 出版年） | 按出版年切片 | 高（两池年份列均可用） |
| 卓越论文筛选（R1 方法三） | 各学科前列期刊论文 | 中（需期刊维加工，超本件范围） |

结论：本指标语义最贴「检索库收录量」方法族，库内两张主档就是收录池本身，直查即得。完整版见附录 C。

## 二、计算过程

### 2.1 方法选择（文献依据）

采用中信所「检索库收录量」口径（R1/R2）：论文总数 = 收录池行数。选择依据有三：其一，该口径是中国官方科技论文统计的法定路径（统计结果编入国家统计局与科技部《中国科技统计年鉴》，R3 检索记录见附录 C）；其二，库内两张主档本身就是收录池（久新池字段 `openalex_work_id`/`doi` 表明其 OpenAlex work 身份，gkx 池为中文论文库），「池行数」与「收录量」语义 100% 一致；其三，零加工直查满足「完全直接支持」的档位定义，无需引入任何代理或模型。

### 2.2 开发库探测：无论文承载（absence_probe）

`gkxlumenx_dwd` 上 `SHOW TABLES LIKE '%paper%'` 返回 0 行（共享快照 `dims.dev` 同读数，零漂移）。开发库的论文要素确无承载——这不是「表在数缺」，是「表不存在」（B4 情形①），修复动作是建表或接同步，与本件档位无关（另两源已足）。

### 2.3 gkx 中文池：行数与年份列陷阱

`gkx.dwd_zh_paper` 精确行数 **100,900**（`facts.gkx_dwd_zh_paper_rows`）。年份列有两个 B9 级陷阱已被规避：一是列名不叫 `publish_year` 也不叫 `year`，而是 `cover_year_start` 且类型 varchar(22)（共享快照 `fix_20261101[0]` 曾以 `publish_year` 探测报 1054 错，本件直查列定义确认）；二是 varchar 年份必须 `REGEXP '^[0-9]{4}$'` 过滤脏值——实测 20 万采样（全表仅 100,900 行，LIMIT 200000 未截断，等同全表）四位年有效率 **100,900/100,900 = 100%**（`facts.gkx_dwd_zh_paper_year4_valid`），无脏值。年份分布 Top5：2024:32,379 / 2025:6,548 / 2023:6,651 / 2017:6,903（`facts.gkx_dwd_zh_paper_year_dist_top10`）——2024 年呈尖峰（占 32.1%），符合「近完工年集中入库」的采集特征。

### 2.4 久新全语种池：行数、年份与语种

`ads_paper_profile` 精确行数 **4,000,000**（`facts.jiuxin_ads_paper_profile_rows`）。三组质量读数全部落产物：`publication_year` 空值 **0 行**（`facts.jiuxin_ads_paper_profile_year_null`，年份维 100% 可用）；年份分布 Top5：2025:858,620 / 2024:616,335 / 2023:440,998 / 2022:354,080 / 2021:306,284（`facts.jiuxin_ads_paper_profile_year_dist_top10`）；语种分布：en 3,828,053（95.7%）/ 空值 81,888 / de 19,799 / fr 12,188 / es 9,980（`facts.jiuxin_ads_paper_profile_language_top5`）。400 万整的行数与 OpenAlex 快照装载特征一致（池身份见 20261026 久新 130 表调研：`paper_id` 缺失时以 `openalex:` 来源 ID 回退并标 `SOURCE_ID_FALLBACK`）。

### 2.5 双池关系与「合计」口径警示

两池规模比约 39.6:1（4,000,000/100,900）。产物给出合计键 `derived[0].paper_total_jiuxin_plus_gkx = 4,100,900`，但 note 写死三条：其一，两池是不同收录体系（OpenAlex vs 中文库），中文论文可能被双方同时收录（gkx 池标题含中文、久新池 en 占 95.7% 但并非无中文）；其二，无 DOI 交叉去重链前，4,100,900 只能读作「规模上界」；其三，对外展示应单池直读（全语种口径 400 万 / 中文口径 10.09 万），不建议展示合计。这是 B10 双口径并列的标准处置。

### 2.6 稳健性与确定性

本件全部读数为 `COUNT(*)` 与 `GROUP BY` 聚合（按键排序），无浮点链、无 set 迭代序依赖（B5）；两次重跑逐位一致。唯一敏感性是「选池」（§2.5 已披露），数值本身无敏感性。

## 四、数据缺失情况

### 4.1 开发库无论文表（结构级，不影响档位）

`gkxlumenx_dwd` `SHOW TABLES LIKE '%paper%'` 0 命中（absence_probe 三件套在案：查了什么=论文表、条件=表名 LIKE、命中=0）。属 B4 情形①（表不存在）。修复动作：若要求开发库承载，需建论文主档表并接久新/gkx 同步——这是工程立项事项，不是本指标的数据缺口；在三源铁律下，jiuxin+gkx 双承载已使本件达到最高档。

### 4.2 双池去重链缺失（口径级，仅影响「合计」口径）

两池无 DOI/title 交叉去重链，「全球+中文合计」口径（4,100,900）存在重复收录风险。该缺口只影响 §1.6 列出的第三种口径选择，单池直读的两口径不受影响。修复建议：以 `doi` 等值 JOIN 两池抽样估算重叠率（抽样 1 万行即可给出区间），重叠率 <2% 时合计口径可升为可用；在此之前合计值仅作上界（B10 保守交付）。

### 4.3 缺口与影响面小结

| 缺失项 | 类型 | 对档位的影响 |
|---|---|---|
| 开发库论文表 | 结构缺失（表不存在） | 无（jiuxin+gkx 双承载足额） |
| 双池 DOI 去重链 | 口径工程 | 仅「合计」口径受限；单池口径不受影响 |
| 卓越论文筛选维（R1 方法三） | 加工链缺失 | 仅影响「卓越论文数」衍生口径，非本件语义 |
