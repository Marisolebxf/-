## 摘要

「强化产业转化效率」是资源配置优化建议卡的方案 B 标题，mock 配 expectedEffect '+22.9%' / resourceGap '-19.8%'——**它是方案卡文案不是公式**，但方案语义背后是「转化效率」这个真实指标需求。三源探测：开发库 `org_achievement_year`/`enterprise_fund_project` 结构在但 0 行；gkx 唯一转化侧承载是 `dwd_patent_transfer` 22,809 行专利权利转移事件；久新 `ads_technology_application_case` 181,735 行（全为科研项目案例代理，市场验证全表未通过）+ `ads_technology_bottleneck_assessment` 92,544 行证据缺口诊断。本报告双口径复现：口径 A（gkx 2021+ 专利转移事件 22,522 ÷ 专利总量 2,939,895）= **0.7661%**；口径 B（久新 2023+ 案例 24,799 ÷ 全案例 181,735）= **13.6457%**。两口径均非权威「成果转化率」语义（R1 的两条公设：分子分母同标准、分子⊆分母——A 的转移事件不是专利总量的转化子集语义，B 的新鲜度是时序结构非效率），判**部分支持**：权威分子侧三源无承载，需外部转化认定数据源或甲方接受代理口径。

- 需求判定：**UI 推导叶**（指标名三份说明书未出现；SRS seq 190 资源配置优化建议叶「支持方案模拟和效果预测」为功能句）。
- 复现状态：脚本已跑通；双口径比值 + 转移年份分布落产物。
- 档位结论：**部分支持**（权威分子缺失 + 代理口径语义有偏双因）。
- 关键事实：久新案例表 market_status 181,735 行全部 `NOT_VERIFIED_AS_MARKET_APPLICATION`——「项目关联」不等于「转化成功」，任何把案例数当转化数的读数都越界。
- 升档路径：接入成果登记/技术合同认定类外部源（权威分子）→ 可升完全转换支持。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/**科技发展规划**/重点领域规划/资源配置优化建议（SRS seq 190，excel_row 193）。UI 挂载点 `TechDevelopmentPlan.tsx:858`：`keyAreaScenarioPlans` 方案 B 卡 `{ title: '强化产业转化效率', priority: '高', expectedEffect: '+22.9%', resourceGap: '-19.8%', actions: ['完善产业链配套','提升成果转化服务','打通应用示范场景'] }`——三张方案卡（A 提升创新策源能力/B 本件/C 优化空间协同布局）并排，每张给预期效果与资源缺口两个百分比常量。同页多维度指标体系卡的成果库分组（`:815-821`）有「转化成果 2,860 / +8.9%」分项——是「转化成果数」的直读位（与 011 件共 consume）。

**mock 全部为前端常量，演示值，不参与支持度结论。**值得记录的组件行为：方案卡的 expectedEffect 是「方案杠杆」语义（执行方案后期望提升多少），不是现状效率读数——即 UI 自己也没有把「转化效率」当现状指标展示，而是把「强化转化效率」当方案目标。这决定了数据侧的本分调查重心：不是「算出一个效率现状值」，而是「效率类读数有没有可信的构建路径，供方案卡基线与效果测算用」。

### 1.2 为什么需要本指标

转化效率是创新链最后一公里的标尺：研发投入形成成果后，多大比例走向了产业应用，直接决定「补研发」还是「补转化」的资源配置判断。方案 B 把它立为标题，actions 三条（产业链配套/转化服务/应用示范场景）全是供给侧抓手——背后隐含的因果链是「转化服务密度↑ → 转化效率↑」。要验证这条链、要给 '+22.9%' 一个可信的基线，都需要效率读数可算、可比、可复测。

数据侧本件是批内「口径风险」最重的件之一：R3（中国科学技术发展战略研究院李修全）明确指出「科技成果转化率」在全社会层面是统计条件不成熟的口径——成果无统一定义、转化阶段划分学界分歧、分子分母跨源错配是三大坑。本报告把这段方法论警示作为调查框架：先验三源能否满足 R1 的两条公设，再谈代理口径。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「强化产业转化效率」指标名三份说明书未出现。最近的需求原文是 SRS《科技发展规划.md》seq 190 资源配置优化建议叶：「基于空间布局和竞争力分析，提供资源配置优化建议，用户可查看资源投入建议、空间布局优化方案等内容，支持方案模拟和效果预测。」——「效果预测」是功能句，无效率公式。主需求文档有「成果转化」字样多处（如 seq 179 多维度指标体系叶的成果库描述），均无转化效率定义。

### 1.4 类似指标权威方法可行性分析概要

转化效率的官方口径谱系：中国科学技术发展战略研究院给出「科技成果转化率 = 已转化科技成果数 / 应转化科技成果数」并强调两条公设（可统计、分子⊆分母）（R1）；国家科技成果登记统计制度把「应用状态」分为产业化应用/小批量应用/试用/应用后停用/未应用五档，「转化方式」含转让/许可/作价投资/合作开发等（R2 登记表 ZH01/ZH03 字段）——这是权威分子的统计载体；李修全的辨析文（R3）进一步论证全社会转化率是「伪指标」，只能在明确分子分母界定的小范围内测算。方法族对照：

| 方法族 | 分子/分母 | 数据要求 | 与三源匹配 |
|---|---|---|---|
| 登记认定口径（R1/R2） | 登记成果的应用状态判定 | 成果登记+应用状态字段 | **无（三源无成果登记表）** |
| 专利转移代理（本件口径 A） | 转移事件/专利总量 | 权利变更流水+专利主档 | **有（gkx 双表）**，高估方向 |
| 项目案例代理（本件口径 B） | 近期案例/全案例 | 案例时序表 | **有（久新案例表）**，非效率语义 |
| 技术合同成交额口径（火炬统计惯例） | 技术合同成交额/R&D 投入 | 合同认定登记流水 | 无（需外部源） |

结论：权威登记口径三源无承载；可行的只有两个代理口径（A/B），都偏离效率语义，只能作趋势参照。完整版见附录 C。

### 1.6 推测原意与推测定义

## 二、计算过程

### 2.1 装载与规模校验

gkx 侧（经 `_gkxdb.py`）：`dwd_patent_transfer` 全表 22,809 行（facts.gkx_patent_transfer_rows）——量级对「近5年转移率」计算充足；专利总量分母 2,939,895 直接复用共享快照（`_shared_probe_s3_01_out.json` dims.gkx[2]，B11 零漂移，不重复打库）。久新侧：`ads_technology_application_case` 181,735 行（与共享快照 jiuxin 组同值零漂移）、`ads_technology_bottleneck_assessment` 92,544 行（19,430 节点全覆盖）。开发库侧两空表探针见 §3.3。

### 2.2 年份治理（B9 陷阱规避）

`transfer_effective_date` 是 **varchar**（不是 DATE）——直接 YEAR() 会因 '0' 等脏值报错或错算。治理协议：`SUBSTRING(...,1,4)` 取前四位 + `REGEXP '^[12][0-9]{3}$'` 定界过滤；脏值（空串/'0'/非年份）287 行单独计数（facts.gkx_patent_transfer_invalid_year_rows），不从「总行数里静默消失」。有效年份分布（facts.gkx_patent_transfer_by_year）：2026: 3,246 / 2025: 5,799 / 2024: 7,711 / 2023: 3,770 / 2022: 1,670 / 2021: 326——2021 起的近5年+ 当年在途合计 22,522（facts.gkx_patent_transfer_rows_2021plus）。分布形态（2024 峰值、2021 几乎为零）更像**数据覆盖爬坡**而非真实转移潮汐，读数解读须带此前提。

### 2.3 口径 A：专利转移转化率

$\text{rate} = 22{,}522 / 2{,}939{,}895 \times 100 = 0.7661\%$（derived.gkx_patent_transfer_rate_2021plus；分子分母均 gkx 库）。B3 同基注记：分子是「2021+ 生效的转移事件」，分母是「专利全量存量」——**不是同窗口同批**（存量里含 2021 前申请的老专利，其中部分转移发生在 2021 前已完毕），所以该比值是「存量的近5年转移活跃度」而非严格转化率。这个口径弱点已写进 derived note，供甲方裁定时知情。

### 2.4 口径 B：案例新鲜度

$\text{ratio} = 24{,}799 / 181{,}735 \times 100 = 13.6457\%$（derived.jiuxin_case_recency_ratio；同表同源）。案例年份分布（facts.jiuxin_application_stage_dist 等键 + 年份探针）：2021 峰值 29,905 / 2020 25,992 / 2019 19,356，2023+ 骤降到 24,799——上游项目数据的收录时滞所致（项目结项到入库的延迟），新鲜度读数受收录节奏影响，非转化活动真实放缓。

### 2.5 过程面：堵点诊断的可复用读数

`ads_technology_bottleneck_assessment` 92,544 行的 bottleneck_code 分布（facts.jiuxin_bottleneck_code_dist）：PROJECT_EVIDENCE_GAP 38,860 / MARKET_DATA_UNAVAILABLE 38,860 / ENTERPRISE_PARTICIPATION_GAP 14,824——**每个技术节点都带「市场数据不可用」堵点**，schema §24.8 明言「这些结果不能显示成专家确认的因果堵点」。对本件的意义：久新体系自己也承认市场侧转化证据缺席，与本件「权威分子缺失」的判断互证；同时这组分布可服务 022 件（转化流程追踪）的堵点视图，批内复用。

### 2.6 稳健性与口径敏感性

其一，窗口敏感性——口径 A 窗口放宽到全量（含 2020- 脏值剔除后）分母不变分子增约 20%，读数上移但量级不变（<1%）；其二，事件去重——`dwd_patent_transfer` 一件专利多次转移会重复计（pn 维度未去重，行级事件口径），若改按 DISTINCT pn 计分子，读数再降——本报告保持行级事件口径（转移行为计数语义）并披露；其三，案例时滞——口径 B 的收录时滞使「新鲜度」部分反映 ETL 节奏，建议正式使用前做入库时间校正（表有 update_time 可用）。负结论侧：gkx `%transfer%/%convers%/%transformat%` 表扫仅命中 patent_transfer 一张（facts.gkx_transfer_like_tables），dev 两表 0 行——转化面在三源的贫瘠是全域性的，不是检索遗漏。

## 四、数据缺失情况

### 4.1 权威转化分子缺失（判定级，主因）

三源无「已转化成果」认定承载。修复建议：优先接入国家科技成果登记/技术合同认定类外部数据源（R2 登记表的 ZH01 应用状态/ZH03 转化方式字段即权威分子结构）；次选由业务侧定义内部转化判定规则（如「专利转移至企业受让人且非关联更名」）在 gkx 转移表上落一个判定列——前者权威但需数据采购，后者即期但需业务认账。影响面：本件 + 011 件「转化成果 2,860」位 + 科技成果展示模块的转化类读数。

### 4.2 内部流量结构表空置（结构级）

dev `org_achievement_year`（年度×机构×成果类型结构，本可直接承载效率时序）0 行、`enterprise_fund_project` 0 行。修复：若上游灌数计划存在，本件可升档；若无，久新案例表可替代时序面（已用）。影响面：本件时序读数 + 014 件（评估数据收集量，同 dev 空表族）。

### 4.3 收录时滞未校正（质量级）

口径 B 的案例年份受 ETL 收录节奏影响（2023+ 骤降）。修复：用 update_time 与 effective_start_year 差分布做时滞校正系数，正式读数前完成。影响面：本件口径 B + 012 件资讯频率（同为大表时序读数，但 012 用入库即有字段无此问题）。

|---|---|---|
| 权威转化分子 | 判定级 | 效率语义不可闭合 → 主降档因 |
| dev 流量表空置 | 结构级 | 内部时序面缺 → 次降档因 |
| 案例收录时滞 | 质量级 | 口径 B 失真 → 校正后可用 |
