## 摘要

「可靠性当前占比」是总体视窗·资源来源分析（需规 seq 331）「结构组成环比对比」图的当期条——UI mock `structureCompare` 给出 currentPeriod 2026-05 与五来源类型当期值（国内数据库 22.4%/国外数据库 15.0%/科研院所 27.1%/企业 17.2%/开源平台 18.3%），且与同组件「来源结构组成分析」段的 share 值同源同值（演示面自洽）。本件与 DATATHM_007 构成「可靠性环比双件」：同一张图的两条序列、同一组三依赖缺口（评分面/来源登记/期维），词族探针与 007 逐键一致（族内零漂移实跑核验）。差异在期位：本件单期即可算——但单期评估面三源同样不存在，判**完全不支持**；升档顺序本件在先（评估面建成即有当期读数）。脚本已跑通，产物与正文数字逐一对应。

- 需求判定：**UI 派生读数**（指标名 0 命中；seq 331「来源可靠性」功能分句是语义锚）。
- 复现状态：脚本已跑通；三源词族排除 + 期维缺口 + 族内对账 + mock 自洽披露全落产物。
- 档位结论：**完全不支持**（与 007 同根三依赖全缺；本件是族内先升档件）。
- 关键事实：mock 的 current 值与 sourceTypes.share 同源同值——前端作者把「结构占比」与「可靠性占比」做成同一组数（share 即 current），两者语义本应不同（结构占比无阈值、可靠性占比有达标判定）——演示面自身的口径混同是正式版须拆开的点。
- 升档路径：来源可靠性评估面立项 → 本件先升完全直接支持（007 待两期积累）。

与 007 完全同根（§3.3）：「来源×评分×期次」评估登记面三源零承载，评估三件套（规则库/稽核流水/评估报告）一件都没有。**四缺失情形归属「表不存在」**：修复动作同 007——来源可靠性评估面立项（族级并项，一次建设双件受益）。本件在修复路线中的位置：**首期评估即交付**（当期读数不依赖期次序列），是族内的先行交付件。

### 4.2 口径拆分缺口（mock 混同的正式版处置）

mock 将结构占比与可靠性占比复用同一组数（§3.2）——正式版须拆开两个读数：结构占比走来源登记分母直除（无阈值）；可靠性占比需先登记判定规则（阈值 θ、评估范围 R、评分维度）再算达标占比。若甲方接受「以结构占比近似可靠性占比」的降维口径，须明示该裁定并披露语义损失（无达标判定语义）——本件按 B10 不擅自定案，登记为待裁定口径。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 来源可靠性评估面（首期快照优先） | 数据工程立项（族级） | 本件 + 007 | 触发器①（本件先升档） |
| 来源结构登记 | 数据工程 | 本件 + 007 + DATAIN_002/003 | 分母侧共用 |
| 结构占比 vs 可靠性占比口径裁定 | 口径裁定 | 本件 UI | 拆分或降维近似（B10 待裁） |
| UI 暂无数据态 | 展示规范 | 本件 UI | mock 22.4-27.1 当期值建议替换为「暂无数据」 |
