## 摘要

「创新指数提升」是政策效果推演语境的需业务建模件（裁定 NEW：旧创新指数 MD 属区域创新监测语境、无政策变量，本件要求「政策实施后」的因果提升幅度，语义不同不可搬判档）。它的依赖链分三层：指数合成口径（无承载——三源均无区域创新指数结果面，gkx 宏观面是国民经济统计、dev 创新促进得分列空表、久新指数表 0 行）；指数输入维（有量——久新 geo 年度指标 171,736 行 27 期）；政策归因框架（无承载——处理组结构缺失，DID/合成控制不可建）。分层结果是有原料、无口径、无归因：合成工程可立项（R4 区域创新能力四级指标体系是权威方法锚），判**部分支持**。gkx 侧最有价值的排除证据是 a77 系「高技术制造业 R&D」代维——名称像创新统计，但区域维是国际国别码（054/049/484…）且深圳仅 30 码 25 行，国内区域创新统计值无承载。

- 需求判定：三份需求真源未出现「创新指数提升」；主需求 1.1.1.1.4.2.3.1「创新促进等方面」是上位语。
- 复现状态：负结论登记键（uplift=null）+ 输入维覆盖读数（R&D 码 601/867）落产物；无可算提升值。
- 档位结论：**部分支持**（输入维有量；指数口径与归因结构双缺，工程可立项）。
- 关键事实：dev `policy_effect_eval.innovation_promotion_score` 列存在但全表 0 行——「结构在、数据空」是本件最典型的缺口形态（补数据可解）。
- 升档路径：久新 geo 输入维 + R4 指标体系合成指数 → 指数闭合；政策实施清单结构化 + DID/合成控制 → 归因闭合；两者齐备升完全转换支持。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技政策跟踪/**多维政策对比**（核增新模块 1.1.1.1.4.2.4，裁定 NEW 语境）/创新指数提升。与 POLCMP_002 同挂 `policySimulationParams`（`policyData.js:1819-1836`）：`indicators` 五槽位的第 3 位 `{ key: 'innovationIndex', label: '创新指数提升', unit: '分' }`——单位「分」暗示指数制读数（0–100 或百分制分值）而非百分比。消费方 `EstimateWorkbench.jsx` 用前端演示模型（`SIMPLE_EFFECT_MODEL` 系数表）按参数（政策类型/覆盖范围/支持力度/实施周期/目标产业）折算各指标演示值。第二处语境 `:2067`：推演解读报告 mock「预期效果」段写「Wave0 Mock：一年内 GDP 贡献约 +2.5%，就业带动约 1.2 万人，**创新指数提升约 5 分**」——mock 作者对口径的想象是「一年窗口、指数分值差」。

### 1.2 为什么需要本指标

政策仿真五指标（GDP/就业/创新/企业/税收）里，创新指数提升是最「科技政策本色」的一个：资金类政策的中间目标是创新活动（研发投入、专利产出、人才集聚），最终目标是经济结果——创新指数是中间目标的合成读数，回答「政策的科技含量兑现了没有」。放多维政策对比语境下，它支持工具比选：研发补贴类政策的创新指数弹性理论上高于基建类，仿真对比正是要量化这种弹性差。它的政务对应物是国家创新调查制度（R4：区域创新能力评价报告——四级指标体系 5/20/40/138，科技部支持连续 25 年发布）。

### 1.3 需求文档是否给出定义方法

**需求文档没提及该指标定义方法。**三份需求真源检索记录：主需求与 SRS `政策效果推演.md` seq 232（未出台政策仿真模拟）仅说「预测政策实施后可能产生的效果，包括经济效益、社会影响、**创新促进**等方面」——创新指数提升是「创新促进」的具体化但无字段无公式；核增需求 17 叶逐一核对无创新指数条目（PC-13 政策深度分析说「开展政策实施效果、社会经济效益、产业影响、发展趋势的深度分析，结合行业数据与模型算法形成专业分析结论」——是任务描述非指标定义）。指标的口径线索全部来自 UI：单位「分」（指数制）+ mock「约 5 分」（量级锚）。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（两段式，均未闭合）**：

$$\text{提升} = I_{t_1} - I_{t_0},\quad I_t = \sum_{k} w_k \cdot x_{k,t}^{norm}$$

其中 $I_t$ 是区域创新指数（$x_k$ 为归一化输入指标——论文/专利/人才/机构活动量，$w_k$ 为权重），$t_0/t_1$ 是政策实施前/后窗口。仿真语境下 $t_1$ 是虚拟实施期末（mock 想象：一年窗口约 5 分）；实操语境下需再叠一层归因：$\text{提升}^{causal} = (I_{t_1} - I_{t_0})_{处理组} - (I_{t_1} - I_{t_0})_{对照组}$（DID 形式）。**当前两段均不可算**：指数面无承载（$w_k$ 无源）、处理组结构无承载。

**降档/升档触发器**：①按 R4 体系（或其城市版子集）在久新 geo 输入维上构建指数合成并落地 `ads_geo_yearly_index` 类结果面 → 指数段闭合；②政策实施清单结构化（政策×区域×实施时间窗——核增 PC-06/PC-04 拆解产物可供给）+ DID/合成控制 → 归因段闭合；两段齐备升**完全转换支持**。若甲方接受「无归因的前后差分」（简单 $I_{t_1}-I_{t_0}$，不扣对照组趋势）→ 归因段免建，仅指数段闭合即可升档，但读数语义降为「伴随变化」须随行披露；若接受前端演示模型系数 → 那是 mock，本件不接受。

## 二、计算过程

### 2.1 方法选择（文献依据）

两段式框架（合成→归因）：合成段采用国家创新调查制度的综合评价指标体系法（R4——四级指标 5/20/40/138，官方连续 25 年、贴合度最高）；归因段采用 DID 双重差分（R5/R6——政策评估计量的主流识别策略，核心假设平行趋势）。选择理由：R4 是中国官方区域创新评价的唯一连续权威体系（科技部支持），其指标域（知识创造/知识获取/企业创新/创新环境/创新绩效）与久新 geo 输入维（论文=知识创造、专利=知识获取/企业创新、人才/机构=创新环境）有直接映射位；DID 是国内政策效果评估应用最广的方法（R5 综述在案）。

### 2.2 指数合成段：输入维盘点与口径缺口

输入维实测：久新 `ads_geo_yearly_metrics` 171,736 行（本件实测，31 列结构在案：`location_id`/`statistics_year`/`location_level` 定位三列 + paper/cited_by/project/talent/institution/mobility 六族计数列 + coverage 状态列 + 版本列；Lane4 同日探针 A1–A6 互证四层分布 CITY 132,975/PROVINCE 33,518/COUNTRY 5,081/CONTINENT 162；年份 2000–2026 共 27 期）。映射到 R4 一级指标：论文→知识创造、专利（geo 面经 institution 间接）→知识获取、机构→创新环境、人才→创新环境——**四个映射位可占，但 138 基础指标的大部分（R&D 经费、新产品销售收入、技术市场成交额等经济统计类）在 geo 面无承载**；权重体系（R4 未公开完整权重表）与归一化基准（全国均值/最大值）均无源。合成段结论：原料可用面约覆盖 R4 体系的知识侧子集，完整口径不可建。

### 2.3 gkx 宏观面的排除证据

gkx 侧唯一的指数类承载是 `dwd_macro_index_data`（20,000 行）+ 三张 dim 维表。数据域分布（产物键 `gkx_macro_index_code_domains`）：gmjj（国民经济：增加值/指数类）10,046 行、dwjj（对外经济：进出口）5,129 行、a77 系（国际高技术制造业 R&D）3,000+ 行。867 个指标码（`dwd_dim_index_attribute`）逐一扫名称「创新指数/创新能力」命中 **0**（`gkx_attribute_innovation_index_names=[]`）；R&D/研发类名称 601 码（占 867 的 69.3%——但集中在 a77 系）。**a77 的区域语义陷阱**：其 area_code 是国际国别码（054/049/484/76/840/EU…，产物键 `gkx_a77_area_sample`），深圳前缀 4403 在 macro 面共 1,524 行但 a77 系仅 30 码 25 行——国内区域（含深圳）的 R&D 统计值实质无承载。宏观面是「有码无区」：不能当深圳创新指数输入。

### 2.4 归因段：处理组结构缺口

DID 需要处理组×时间×结果变量的面板。本件的潜在处理变量是「政策实施」（某区域在某时点落地某政策）——政策侧 gkx `dwd_policy_base` 有 province（17,476 非空）/city（10,294 非空）/publish_date（19,999 非空）可构造粗粒度「区域×时点」，但 implementation_date 非空 0 行（发布≠实施，时点语义断裂）；结果变量段（指数）如 §2.2 不可建。合成控制（DID 的替代）同样需要结果变量的长时序——geo 面 27 期时序可用，但前提仍是先有指数。归因段结论：结构性依赖（实施时间窗）缺失，框架不可建。

### 2.5 政策文本叙述面边界

## 四、数据缺失情况

### 4.1 指数合成口径缺失（方法级，主因一）

三源无区域创新指数结果面（§3.3 三源逐一留证）。合成的三要素缺二：输入维有（久新 geo 27 期，但仅覆盖 R4 体系知识侧子集——R&D 经费/新产品销售等经济统计类输入无承载）；权重体系无（R4 报告发布排名不发布完整权重表）；归一化基准无。修复路径是**裁剪口径**：用 geo 可覆盖的子集（论文/专利/人才/机构四域）建「科技活动指数」而非完整「创新能力指数」，权重用等权或熵权法起步（方法论成熟），并在交付物中明确「非 R4 全口径」。这个裁剪指数足以支撑政策仿真的对比语义（同一口径下的相对提升），只是不能与官方排名对表。

### 4.2 政策归因结构缺失（结构级，主因二）

「政策实施后」的提升要求处理组×时间窗。政策侧发布时间（publish_date 19,999 非空）可作粗时点，但实施时间（implementation_date 0 非空）缺失——发布到实施通常滞后数月，用发布时点做事件研究会引入时点误差；处理组单元（哪些区域受政策覆盖）需 policy×region 映射，province/city 有量但粒度到省/市，与 geo 面的 CITY 层可对齐。修复路径：短期用「发布年±窗口」的粗 DID（误差随行披露）；中期依赖核增 PC-06 拆解产出政策适用范围结构化（PC-04「适用范围」维正是该结构位）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| geo 裁剪指数合成（等权/熵权起步） | 建模工程 | 本件 + POLCMP_022（评估维） | 久新 geo 输入维直接可用 |
| 政策实施清单结构化 | 依赖 PC-06/PC-04 产物 | 本件 + POLCMP_019（同比） | 归因段闭合 |
| dev 效果表数据回流 | 数据工程 | 本件 + POLCMP_016/022 | 结构已在只缺写入 |

档位后果：裁剪指数+粗 DID → **完全转换支持**（口径随行披露「非 R4 全口径+发布时点代理」）；再配实施清单 → 因果语义闭合；仅 dev 表回流 → 仍部分支持（表是结果落位不是计算引擎）。推荐组合：先做裁剪指数（1–2 周级工程），归因段随核增模块实施节奏跟进。
