## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/科技指数/指标展示/指标树数据/**产业影响力**（UI 拆件叶，row_01 203）。UI 挂载点 `mockData.js:132`：`indicatorTreeData` 三级指标树的 L2 节点——`{ id: '2-2', name: '产业影响力', level: 2, weight: 0.40 }`，父节点为 L1「科技影响力」（`mockData.js:85`，weight 0.30，calculation「学术影响力×0.6 + 产业影响力×0.4」）。树节点在指标展示 Tab 的 `IndicatorTree` 组件展开渲染，点击节点弹出 `IndicatorDetail`（显示 description/calculation/significance 三段）；权重展示弹窗（INDEX_013 语境）逐节点标注同级权重。本节点三个 L3 子项：技术转让收入（0.50）/ 带动产业增值（0.30）/ 标准制定（0.20），mock 自带 calculation 三条（技术合同成交额（万元）/ 相关产业新增产值/1000万 / 国际标准×5+国家标准×3+行业标准×1）——注意这些是**前端作者的演示公式，不是招标口径**（需求文档未出现该树，见 §1.3）。

### 1.2 为什么需要本指标

科技指数的四维叙事（创新/影响/潜力/保障）里，「科技影响力」维拆学术/产业两翼：学术影响力回答「成果被学界认多少」，产业影响力回答「成果被产业用多少」——后者是成果转化叙事的量化锚点，直接服务技术转移政策与产业化资源配置的决策参照。没有产业翼的影响力评价会被质疑「只算论文不算钱」，这正是树作者把它放进 L1「科技影响力」并给 0.40 父维内权重的原因。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「产业影响力」作为科技指数指标树节点未独立出现在三份需求真源（SRS《科技指数.md》19 叶无此名）；主需求文档中「产业影响力」出现 2 处（:3697 创新载体孵化载体语境的叙述性用法、:4903/:4909 科技专题服务系统 1.1.1.2.4.2.5.7.2「产业影响力排行」人才产业力评估语境）——**均非本展示系统科技指数页的口径**。mock 的三分项公式（技术转让收入×0.5+带动产业增值×0.3+标准制定×0.2）是前端作者的演示实现。检索记录见附录 A。

**降档/升档触发器（B10 模板）**：甲方接受口径 A → 升**完全转换支持**（代理分现转可算+偏移标注）；坚持口径 B → 维持部分支持，直至经济/标准化数据源接入（外部源立项）；若要求与 INDEX_016 学术分同表同构合成 → 需在久新体系外新建产业评分面（与口径 B 同工程）。

### 2.1 装载与承载面盘点

### 2.2 三分项承载的逐一排除

mock 三分项的承载检索按「列级→表级→域级」三层展开：**技术转让收入**——技术合同成交额属技术市场登记域（全国技术合同网上登记系统），久新 130 表（`_jiuxin130_fields.json` 全量核对）无技术合同/成交额类表，gkx 280 表无 transfer/contract 命中（absence_probe[2]），dev 仅产业链关联面（`dev_chain_tables` 12 张：chain/chain_enterprise/chain_investment 等，无技术交易金额表）；**带动产业增值**——产业增加值属国民经济核算域，三源同缺；**标准制定**——标准数量属标准化目录域（GB/ISO 目录库），同缺。三层排除的探针记录全部落 absence_probe（§3.3）。

### 2.3 代理轴原料的量化盘点

产业影响力若走代理口径（口径 A），可用原料实测：①久新 `ads_technology_institution` is_company=1 子池 99,821 行（facts `jiuxin_tech_inst_company_rows`）——企业主体在技术节点上的参与记录（paper/patent/project 三证据列在案），可合成「企业技术参与度」分；②久新 `ads_institution_industry` 1,354,245 行 IPC 产业参与画像（覆盖率列可归一）；③gkx `dwd_patent` 2,939,895 行（facts `gkx_patent_rows`，与共享快照零漂移）——三源最大专利明细面，产业映射后可算专利强度。三组原料构成代理分的全部底座，但产物 notes 已写死：代理分语义=「产业参与深度」，不得以「产业影响力」名义对外。

### 2.4 黑名单与空表披露

dev 侧同名域表复核：`gkxlumenx_ads.enterprise_ranking`/`enterprise_score` 实测均 0 行（facts `dev_blacklist_tables_rows`）——两表属 skill P4.1 造数黑名单（分值禁止引用），本批实测确认空壳，「表存在但 0 行」独立披露，值不参与判档。dev 真实产业侧承载为 `gkxlumenx_dwd` 产业链族 12 张表（facts `dev_chain_tables`），其中 `chain_investment`/`enterprise_chain_kpi` 等有产业关联语义但均为企业-产业链映射面，无主体级产业影响力得分。

### 2.5 稳健性与口径敏感性

代理口径的两向偏差定性：**高估**——专利密集但转化低效的主体（论文型企业的专利囤积）会被代理分高估；**低估**——以技术秘密/技术服务实现转化而不申请专利的主体会被系统性低估。经济口径（本尊）无此偏差但无数据。两口径的读数方向可能背离（专利强者未必收入强者），产物 notes 已列「不得混用、不得互推」。

### 3.2 D2/D3：经济域数据的结构性缺位

三分项的缺失不是「表在数少」而是「域不在库」：久新是 OpenAlex 学术数据体系（论文/被引/人才/主题），gkx 是产业要素库（企业/专利/投融资/新闻/政策），dev 是项目自建派生面——三个体系都不采集技术合同成交额（技术市场登记属火炬统计/技术合同认定登记体系）、产业增加值（国家统计局核算域）、标准数量（标准目录库）。这决定了修复路径只能是外部源接入，不是库内补数。

## 四、数据缺失情况

### 4.1 经济三分项缺失（数据源级，主因）

技术转让收入/带动产业增值/标准制定三列在三源任何表中均不存在（§3.3 探针在案）。修复路径：①技术合同登记数据接入（全国技术合同网上登记系统地方分中心数据）；②标准目录库接入（国家标准全文公开系统/ISO Catalogue）；③产业增值走规上企业经济统计代理。三项均为外部源立项，工程量在数据采购与合规，不在技术。

### 4.2 代理口径的语义缺口（次因）

口径 A 原料（99,821 企业参与+1,354,245 产业画像+2,939,895 专利）可合成「产业参与深度」分，但与「产业影响力」的语义差（参与≠影响、专利≠转化）无法在库内闭合（§2.5 两向偏差）。若甲方接受代理叙事，此缺口以标注方式消化；不接受则回到 4.1 外部源路径。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 口径 A 代理分先行 | 数据工程 | 本件即期 | 参与度合成+偏移标注 |
| 技术合同/标准库接入 | 外部数据源 | 本件+X_001/X_018/X_027 产值族 | 经济域一次接入多件受益 |
