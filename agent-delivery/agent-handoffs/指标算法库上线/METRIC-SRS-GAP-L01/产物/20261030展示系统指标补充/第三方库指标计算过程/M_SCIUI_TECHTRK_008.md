## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/**科技发展规划**/重点领域规划/竞争力水平与潜力评估（SRS seq 186，excel_row 189）。UI 挂载点 `TechDevelopmentPlan.tsx:3041`「对标区域排名」小节：`.tzp-benchmark-table` 三列表（区域/综合指数/排名），数据源 `keyAreaBenchmarkRows`（`:878-883` 常量五行：南山区 78.5/1、深圳湾合作区 74.2/2、广州天河区 71.3/3、香港科技园 69.1/4、珠海横琴新区 66.8/5），前三名高亮 rank-1/2/3 样式。同卡左半区是「维度得分（TOP5）」进度条（创新资源 92/科研产出 88…，:870-875）与顶部五枚竞争力指标（综合指数 78.5、创新能力 88…，:862-868）——对标排名表是这组评估读数的收口。

筛选器 `:754` `compareRegion`（对标区域）：默认「粤港澳大湾区」，选项长三角/京津冀/全球平均——即 UI 设想的完整交互是「选定对标区域组 → 表内切换排名对象」。**mock 全部为前端常量，演示值，不参与支持度结论。**

两点组件行为值得记录：其一，排名表粒度是**混合粒度**（南山区是区级、广州天河区是跨市区级、香港科技园是园区级）——前端作者没有坚持统一行政区级，说明需求原意是「对标对象列表」而非严格行政排名，这给数据侧口径选择留了灵活度；其二，表标题挂在「竞争力水平与潜力评估」卡下，与久新 region_assessment 的 potential/rank 语义天然对齐（评估表族的区域切面）。

### 1.2 为什么需要本指标

对标是规划的起点：知道自己在同类区域中排第几、差多少分，资源配置方案（同页方案 A/B/C 卡）才有靶心。排名表把「综合指数」压成单值 + 名次，配合 Top3 高亮，服务决策汇报「我们第几、追谁、差几分」的三连问。需求原文（seq 186）「提供与对标区域的对比分析」明确了对标语义；「排名」是 UI 把对比分析落成的最直观形态。

数据侧本件的张力在「综合指数」四个字：任何区域排名都先要一个**单一可比的分**。官方先例（中国区域创新能力评价报告，R4/R5）用四级指标体系 138 个基础指标合成；库内现状是久新「技术×城市」粒度的百分位分——折叠成城市分就绕不开「城市间技术组合结构差异」的口径问题（深圳 6,233 个节点偏产业化、北京 10,959 个节点覆盖更广，均值直比会把结构差当成分差）。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「对标区域排名」指标名三份说明书未出现。最接近的需求原文是 SRS《科技发展规划.md》seq 186 竞争力水平与潜力评估叶：「评估区域科技创新的竞争力水平和潜力情况，用户可查看竞争力指标体系和评估结果，提供与对标区域的对比分析。」——功能句，无指数构成、无排名算法定义。《全球创新监测.md》seq 74「城市创新能力排名计算」是相近叶但属全球创新监测页面（另一指标族，Lane 5/6/7 的 INNOV 系承接），本件不混用。主需求文档 L851 有对标城市趋势对比描述，亦无算法。

### 1.4 类似指标权威方法可行性分析概要

区域创新排名的权威方法是《中国区域创新能力评价报告》体系（中国科技发展战略研究小组，连续 26 年）：四级指标（5 一级/20 二级/40 三级/138 基础），覆盖知识创造、知识获取、企业创新、创新环境、创新绩效，对 31 省综合评分排名（R4/R5）；学术变体用熵权法、TOPSIS、DANP-MOORA 等多属性决策法构权与排序（R6）。对标分析（benchmarking）的标准做法是「综合排名 + 分项得分 + 排名变动」三读数并置（R5 的发布实践即此形态）。方法族对照：

| 方法族 | 构分方式 | 数据要求 | 与三源匹配 |
|---|---|---|---|
| 四级指标体系合成（R4/R5） | 加权合成综合指数 | 跨域指标体系（投入/产出/环境） | **无（三源无区域级指标体系表）** |
| 多属性决策（DANP-MOORA 等，R6） | 客观赋权+差距比 | 属性矩阵 | 部分（可从久新证据计数构造属性矩阵，工程量大） |
| 百分位分折叠（久新现行底座） | 技术分→城市聚合 | 技术×城市评分表 | **有（region_assessment 2,708,162 行）** |
| 名次直读（UI mock 语义） | 已有名次列 | 区域+名次结果面 | dev policy_support_rank 结构同构但 0 行 |

结论：权威体系合成法需三源没有的区域指标体系；可行路径是久新百分位分折叠（口径 A/B）或等 dev rank 表灌数。完整版见附录 C。

## 二、计算过程

### 2.1 装载与规模校验

经久新 Doris 只读连接。`ads_technology_region_assessment` 全表 2,708,162 行（facts.jiuxin_region_assessment_rows），覆盖 7,816 个 location_id（facts.jiuxin_region_assessment_locations）；双模型版本各 1,354,081 行（facts.jiuxin_region_assessment_model_versions，v1 与 v2_eto_cluster_technology 各半）。行数 = 7,816 位置中有效组合 × 19,430 节点 × 2 版本的结构在量级上自洽（非全组合，按证据命中）。城市节点覆盖 Top10（facts.jiuxin_top10_cities_by_nodes）：北京市 10,959 / 上海 8,368 / 南京市 6,902 / 广州市 6,794 / 杭州市 6,603 / 武汉 6,310 / 深圳 6,233 / 西安 5,362 / 成都市 5,256——另有 18,809 节点的 `location_name_zh` 为空（未治理中文名的城市行），口径 A 聚合时被 WHERE 过滤，已在读数中排除并披露。

### 2.2 口径 A：城市综合潜力榜

对城市聚合 `AVG(regional_potential_score)`（节点数 ≥1,000 门槛过滤小样本城市），按均值降序、节点数降序双键定序（B5），取 Top5（facts.jiuxin_city_avg_potential_top5）：北京市 48.8899（10,959 节点）、上海 47.9260（8,368）、广州市 47.0593（6,794）、深圳 47.0550（6,233）、南京市 46.6981（6,902）。榜首与第五名分差仅 2.19 分——城市间均值高度压缩，这正是百分位分折叠的数学后果（每城内部 0–100 全谱，城市均值向 50 收敛），读数解读必须带着这个性质：**榜序可用，榜分差不可过度解读**。

```sql
SELECT location_name_zh, COUNT(DISTINCT technology_node_id) nodes,
       ROUND(AVG(regional_potential_score),4) avg_score
FROM ads_technology_region_assessment
WHERE location_name_zh IS NOT NULL
GROUP BY location_name_zh HAVING nodes >= 1000
ORDER BY avg_score DESC, nodes DESC LIMIT 5;
-- → 北京市 48.8899/10959 | 上海 47.9260/8368 | 广州市 47.0593/6794
--   深圳 47.0550/6233 | 南京市 46.6981/6902
```

### 2.3 口径 B：深圳对标技术榜

### 2.5 稳健性与口径敏感性

## 四、数据缺失情况

### 4.1 区域综合指数结果面缺失（语义级，主因）

三源无「一行=一区域，含综合分与名次」的同构面。dev `policy_support_rank` 是最接近的空壳（结构 21 列与 UI 表语义同构）——修复有两条路：等上游灌数（依赖不明），或以久新 D1 折叠口径 A 自建 ADS 视图（推荐，工程小）。影响面：本件 + 018（同卡顶部综合指数 78.5 同语义）+ 科技政策跟踪模块的标杆比对功能（若复用该表）。

### 4.2 折叠口径未裁定（口径级，次因）

城市榜的均值/加权/Top-N 截断三选一未定，直接影响榜序与分差。修复建议：产品侧出一页口径说明（建议加权=机构证据数，理由：抗小样本技术拉偏），工程侧半日改 SQL 重算。影响面：本件口径 A 的全部读数。

### 4.3 对标区域组映射缺失（配置级）

§3.4 所述城市组映射表（含港澳覆盖核验）需产品+数据双侧确认。影响面：compareRegion 筛选器的全部选项交互。

| 缺失项 | 类型 | 对档位的影响 |
|---|---|---|
| 区域综合指数结果面 | 语义级 | 同构面无 → 主降档因（可折叠替代） |
| 折叠口径裁定 | 口径级 | 榜序分差悬空 → 待裁定交付 |
| 对标区域组映射 | 配置级 | 筛选交互受限 → 附加缺口 |
| gkx 排名面 | 源级 | 该源不可贡献 → 双源变单源 |

修复组合推荐：即期口径 A/B + coverage 披露上线，同期推口径裁定与城市组映射确认，中期视 dev rank 表灌数情况决定是否切换同构面。
