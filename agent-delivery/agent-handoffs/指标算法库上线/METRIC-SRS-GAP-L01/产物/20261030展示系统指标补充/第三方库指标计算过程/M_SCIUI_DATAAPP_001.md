### 1.2 为什么需要本指标

主题数据被调用情况 Tab（seq 384-387 四叶）的管理命题是「**哪些主题的数据在被用、被谁用、怎么用**」：本件（seq 384）是主题维的调用量构成——饼图回答「调用量在主题间怎么分布」，是 Tab 内其他三件（用户追踪 seq 385/趋势周期 seq 386/排行对比 seq 387）的总量基底。权威对应物是数据开放平台的「接口调用统计」（R2 浙江：统计每个接口的调用量/调用用户/调用时间/调用频率）——把接口维度换成主题维度即本件语义。本件的双依赖结构（调用日志×主题登记）决定了它是 Tab 内工程前提最重的一件：没有调用日志无从计数，没有主题登记无从分组。

### 1.4 类似指标权威方法可行性分析概要

「主题调用统计」的权威方法锚分三层。其一，数据基础设施国标（R1 国家数据局连接器技术要求）：接入连接器应支持按用户定义规则记录**数据调用次数、使用时长、使用量**——调用计量是数据基础设施的合规要件（日志留存满足法规要求）；其二，公共数据开放平台工程口径（R2 浙江规范 5.5.4）：「统计每个接口的调用量、调用用户、调用时间、调用频率，超出设置阈值进行消息提醒」——接口维四要素与本件主题维五字段同构；其三，API 网关日志规范（R3 杭州 DB3301 表 A.14）：API 接口调用日志 31 字段（时间/源目 IP/URI/请求响应/响应码/耗时/来源用户名/接口分级）——调用日志的字段级国标形态。方法族对照：

| 方法族 | 代表 | 计量单元 | 数据要求 | 与三源匹配 |
|---|---|---|---|---|
| 连接器计量（R1） | 国家数据局 | 数据调用次数 | 连接器日志 | **无（连接器未部署）** |
| 平台调用统计（R2） | 浙江规范 | 接口×用户×时间 | 调用日志+阈值 | **无日志** |
| 网关日志格式（R3） | DB3301 A.14 | 请求级日志 | 网关采集 | **无网关日志** |
| 前端演示 | UI 饼图 5 主题 | mock 常量 | — | 结构披露（不作源） |

结论：三条权威路径的原料（连接器日志/平台调用统计模块/网关日志）三源均无承载——本件与 DATAAPP 族共用「调用日志工程前提未建」缺口。完整版见附录 C。

## 四、数据缺失情况

### 4.1 调用日志面与主题登记轴双缺（结构级，判定性缺口）

本件的双依赖结构决定其缺口是**复合型**：其一，主题级调用日志面——「自动收集」（seq 384 自宣机制）要求调用日志采集工程（API 网关/连接器计量层，R1/R3 的合规要件），三源零承载；其二，平台主题库登记轴——调用量按主题分组的前提是主题集合有登记（哪些主题、什么层级），三源同样零承载（与 DATATHM_004 主题库总数件共享的目录缺口）。**四缺失情形归属「表不存在」**：修复动作是调用日志工程立项（DATAAPP 族级共用，一次建设 001/002/004/005/006/007 六件受益）+ 主题登记面建设（主题 Tab 四件 + DATATHM_004/029 受益）。

### 4.2 前端演示主题字典的口径风险（披露级）

前端三处（饼图/明细表/趋势序列）自建了一套 5 主题演示字典（基础科学/医学健康/工程技术/农业科技/能源环境）——该字典不来自任何库内登记。正式版若直接沿用前端主题名，会出现「UI 有主题、库内无登记」的悬挂口径：调用量日志建成后仍需先落主题登记轴才能分组。建议正式版以主题库登记面为唯一主题字典源（前端从接口取，不再硬编码）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| API 网关/调用日志接入（含主题标识） | 监控工程立项（族级） | 本件 + DATAAPP_002/004/005/006/007 + DATATHM_013/034/052 | 触发器①（一次建设多件受益） |
| 平台主题库登记面 | 数据工程立项 | 本件 + 主题 Tab 四件 + DATATHM_004/029 | 主题字典唯一源（前端硬编码回调） |
| 主题资源引用代理口径 | 轻量替代 | 本件即期 | 触发器②（口径披露非真实调用） |
| UI 暂无数据态 | 展示规范 | 本件 | mock 饼图建议替换为「暂无数据」 |

档位后果：调用日志+主题登记 → **完全直接支持**；代理口径 → **完全转换支持**（口径披露）；现状 → 完全不支持。推荐顺序：调用日志工程为主线（族级并项），主题登记面同步立项，代理口径作即期过渡（标签「主题资源引用」非「主题调用」）。
