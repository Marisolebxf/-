## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技政策跟踪/**政策效果推演·效果预估·多维度效果评估**（主需求 1.1.1.1.4.2.3.1.4）。UI 实际容器是政策效果推演工作台（`simulation/estimate/EstimateWorkbench.jsx`）的「multi」Tab：`:590` 起 `AlertBanner` 复述需规（「经济 / 社会 / 环境 / 创新四维评估 · 各维指标与得分 · 雷达图 / 柱状图」）；`ReviewOnly` 包裹「各维评估已完成」Switch（评审态演示开关，默认关——开则显示 Empty「未完成各维度评估，不可展示综合效果」）；开后市面三级结构——左列四维雷达图卡（`MultiDimensionRadarChart`，带 MockBadge）+ 分项柱状图卡（`MultiDimensionBarChart`，MockBadge），右列四维明细卡（每维一张 Card：维度名+总分 Tag+3 个子指标行，如经济维「GDP 贡献指数 88」）。数据源 `policyData.js:1839-1888` `multiDimensionEvalData`（注释自认「DS-12 · 多维度效果评估（经济 / 社会 / 环境 / 创新）」）。整条链路无 API 调用。

### 1.2 为什么需要本指标

政策效果推演的方法论痛点是「综合分失真」：单一综合分（如 PG_COMPOSITE 语义）把经济拉动与环境代价压成一个数，方向相反的效应互相抵消——多维度效果评估把效果拆到经济/社会/环境/创新四个正交面，回答「这项政策好在哪一面、差在哪一面」。需求原文（:1417-1419）的设计意图即此：四维各自给「评估指标+得分」，雷达图四边形直观呈现效果形状（经济强创新弱的「偏科政策」一眼可辨）。在核增 PC-09 交叉对比语境下，四维形状对比（两政策的雷达叠加）比单一综合分对比信息量更大——这正是「多维对比新语义」（父代理裁定 NEW）的产品逻辑。它的政务对应物是中央财政科技计划绩效评估的多维评估内容（经济性/效率性/效果性 + 创新影响）与 T/CASTEM 1010-2023 的「过程—内容—结果」多维框架。

### 1.3 需求文档是否给出定义方法

**需求文档给出维度结构但未给出评分算法。**主需求 :1417-1419（1.1.1.1.4.2.3.1.4 多维度效果评估）原文：

> 从经济、社会、环境、创新等多个维度对政策效果进行评估，用户可查看各维度的评估指标和得分，了解政策在不同方面的综合效果，系统提供雷达图、柱状图等多种可视化形式展示评估结果。

「等多个维度」给出四维基集（经济/社会/环境/创新——「等」字开放扩展），「各维的评估指标和得分」给出两层结构（每维下挂指标），可视化形式（雷达/柱状）与 UI 实现一一对应；但**每维怎么打分、四维怎么合成**一个字未给。SRS 政策效果推演叶（seq 235）同文转述。核增需求 17 叶无该名——本叶属原方案效果预估，核增升级的是对比功能（PC-09 语境），父代理裁定 NEW 即指此语境迁移。另注：派单表述的挂载组件 EstimateHome.jsx 在仓库中不存在，实际组件为 EstimateWorkbench.jsx（`simulation/estimate/` 目录单文件），已按实查修正。

## 四、数据缺失情况

### 4.1 效果评估批次零运行（数据级，主因一）

四维分值是效果评估模型运行时产物（政策×批次×维×分值）。当前链路断在源头——评估模型未立项、评估活动从未发生，dev 四处落位 0 行（UI 的 Empty 空态「未完成各维度评估」是产品侧的同义自证）。修复路径：评估体系立项（四维指标集定版——可直接采用 dev 落位列名，需求「等」字维的取舍一并定版）→ 首批评估批次运行 → 写入 `policy_effect_eval`。这一缺口与 POLCMP_016 **完全同源**（同一评估族、同一落位表）——两件是同一接入工程的两个读数面（016 快照五维加权、本件效果四维形状）；与 POLCMP_008/007 共享推演工作台语境旁支。

### 4.2 合成规则未立项（方法级，主因二）

即便评估面有数据，「四维→综合效果」的呈现规则也待定版：保守口径（只出雷达形状不合成——需求「综合效果」的全景语义）vs 合成口径（等权/加权）。本件比 POLCMP_016 的口径缺口浅一层：016 必须合成（单一得分语义），本件可以不合成（形状即交付）——**因此本件的近期可交付形态是「四维分值雷达」而非「综合分」**，合成规则可后置。每维 3 指标集（UI 演示配置）的定版随评估体系立项一并解决。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 效果评估模型立项（四维指标集+呈现规则） | 建模立项 | **本件 + POLCMP_016（同族）** | 指标集可采 dev 落位列名（§3.2） |
| 首批评估批次运行+写入 | 评估工程 | 同上 | `policy_effect_eval` 直查可算 |
| 因果推断路径另立项 | 依赖工程 | 本件中期增强 | 依赖兑现台账（POLCMP_021 族）接入后 DID/合成控制 |
| 雷达形状先行（不合成口径） | 产品决策 | 本件近期形态 | 触发器①闭合后即可交付 |

档位后果：评估立项+批次运行 → **完全直接支持**（四维分值直查，雷达即出）；因果路径台账接入 → 增强为因果归因版（另立项）；两者皆无（现状）→ 完全不支持。推荐顺序：与 POLCMP_016 合并立项，四维形状先行交付，合成口径后置裁定。
