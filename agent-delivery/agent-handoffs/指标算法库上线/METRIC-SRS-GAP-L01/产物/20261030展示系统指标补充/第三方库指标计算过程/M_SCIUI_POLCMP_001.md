## 摘要

「政策落实率（兑现/应享）」是政策分析评价页的负结论件：UI 有完整的分地区落实率表（8 地区 rate/funded/declared/delayed 四列）与多媒体解读的落实率线系列，但全部为 mock。三源探针逐一留证兑现事件零承载——gkx 唯一 claim 表是专利权利要求书（表名陷阱）；dev 兑现台账 `enterprise_fund_project` 0 行、政策效果五表 0 行；久新 203 表无兑现语义列（4 个无关命中：人才荣誉 honors/推荐方案 implementation_plan）。应享侧仅有 gkx 政策存量（20,000 行）与申报通知子集（1,910 行）作上界原料。权威口径对照（国务院第三方评估 R1、工信部应享尽享调查 R2、深圳免申即享 R3/R4）全部依赖政务台账/调查数据——兑现数据天然在财政/政务侧，不在科技要素库，这是数据源属性决定的缺口。判**完全不支持**。

- 需求判定：三份需求真源未出现「落实率/兑现/应享」；语义源是 UI mock 实现层 + 主需求政策实施效果跟踪（1.1.1.1.4.2.1.3.3）语境。
- 复现状态：负结论件无可算值；三源四件探针读数落产物。
- 档位结论：**完全不支持**（分子零承载，分母仅上界）。
- 关键事实：`dwd_patent_claim` 的 'claim' 是专利权利要求——表名命中但语义无关，是本件最重要的排除证据。
- 升档路径：政务兑现台账（免申即享兑付/财政拨付流水）接入 → 分子闭合升完全转换支持。

## 一、需求定义概述

### 1.1 所属功能模块

UI 两处挂载：其一，`ImplementationByRegion.jsx:31` Card「分地区落实率」——Table 列：地区/落实率（Progress 条 + 阈值配色：≥88 绿/≥80 蓝/≥75 黄/其余橙）/资金到位/申报完成/延期项，mock 数据 `implementationByRegionData`（`policyData.js:2244`：北京 88%/上海 85%/深圳 91%/广州 82% 等 8 地区）。其二，`MultimediaAssistPanel.jsx:129` 图例与 `:156` 线系列——「短板指标动态演示」中落实率线（70→86 六期动画）。

### 1.2 为什么需要本指标

政策生命周期三问：发布了吗（政策库有 4 万行）、兑现了吗（本件）、见效了吗（效果评估族）。落实率是三问中最具政务刚性的一个——「政策兑现了没有」直接对应营商环境考核（免申即享改革的核心 KPI）与企业获得感（应享未享是投诉高发区）。分地区落点（UI 的 8 地区表）服务市级对标督办：哪个区延期项多、哪个区资金到位慢，一目了然。

### 1.3 需求文档是否给出定义方法

**需求文档没提及该指标。**三份需求真源检索记录：主需求与 SRS 政策族（科创政策全景/政策分析评价/政策效果推演）无「落实率/兑现/应享」字样（政策实施效果跟踪 seq 209 仅说「评估政策落地情况」）；核增需求《科技信息展示系统(政策对比功能升级)核增需求.md》17 个 PC 叶（政策数据治理/智能政策拆解/多维政策对比/智能研报生成）逐一核对亦无。指标的语义定义完全来自 UI mock 实现层（rate/funded/declared 三列暗示「兑现率/资金到位率/申报完成率」子结构）。

### 1.4 类似指标权威方法可行性分析概要

落实率/兑现率在官方体系的口径先例：其一，**国务院第三方评估**（R1，2014 年制度化——企业座谈 1,693 家/实地走访 278 家/有效问卷 3,044 份的实地调查法，评估「简政放权」等政策落地）；其二，**应享尽享率企业自报**（R2，国务院减轻企业负担部际联席会议委托第三方机构调查——小型微利所得税优惠等减税政策「应享尽享率均在八成以上」）；其三，**深圳免申即享兑付台账**（R3/R4，龙华区五批 116 项补贴/累计兑现 20.5 亿元/惠及 82.79 万人——政务系统内的兑付流水直接计数）。

| 方法族 | 代表 | 兑现数据源 | 与本库匹配 |
|---|---|---|---|
| 第三方评估调查 | 国务院（R1） | 座谈/问卷/回访 | **无（需新调查）** |
| 应享尽享企业自报 | 联席会议第三方调查（R2） | 调查问卷 | **无（需调查源）** |

三族共同点：**兑现数据从不来自政策文本库**——它在财政拨付系统、政务服务平台、或专项调查里。本库三源（科技要素库 gkx/开发库/久新分析库）均非其位。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（不可实现，仅登记语义）**：

$$\text{落实率} = \frac{\text{已兑现事项数（拨付到账/办结）}}{\text{应享事项数（符合条件应兑现）}}$$

UI mock 暗示子结构：rate（总落实率）/funded（资金到位率）/declared（申报完成率）——三个子口径共享「分子=完成态事件计数、分母=应办态清单计数」的骨架。**本件不写伪计算过程**（F4：口径未闭合且无法复现时计算过程从缺）——分子的事件数据三源零承载（§3.3），分母的应享对象清单需政策条款×企业资质的匹配引擎（POLCMP_003 免申即享占比的依赖面，亦无承载）。

**降档/升档触发器**：接入政务兑现台账（免申即享兑付记录/财政拨付流水/企事速办工单闭环记录）→ 分子闭合，配合应享清单可升**完全转换支持**；若采用第三方调查口径（R1/R2 企业自报应享尽享率）→ 需年度调查数据源，单独立项；若甲方接受「政策发布存量/申报通知量」作过程性代理 → 语义已非落实率（发布≠兑现），本件保守不接受该代理。
