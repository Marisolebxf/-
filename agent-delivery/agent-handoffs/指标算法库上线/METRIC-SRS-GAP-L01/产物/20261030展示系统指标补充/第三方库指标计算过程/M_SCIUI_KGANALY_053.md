## 一、需求定义概述

### 1.1 所属功能模块

科技信息展示系统/科技知识图谱/中心性计算展示——`CentralityPanel.jsx` 五 Tab 分析面板。本件挂 compare Tab 右卡「综合评分雷达（Top5）」（`:850`），雷达 option 构建于 `:291-310`：indicator 四轴 `[度中心性 max:1, 紧密中心性 max:1, 中介中心性 max:1, PageRank×5 max:1]`，series data 取 `rows.slice(0, 5)`（综合分排序后前五）每节点 `[r.degree, r.closeness, r.betweenness, Math.min(1, r.pagerank * 5)]`。另度 Tab 有一张同构雷达（`:689`，三轴度归一/紧密/PR×5）。算法真身 `centralityAlgo.js:361-468 runCentralityAnalysis`：四算子全图计算→归一→composite 排序。注意辨析：度 Tab 雷达（`:689`）与 compare Tab 雷达（`:850`）是两个挂载实例，本件以派单书指定的 `:850` 为准。

### 1.2 为什么需要本指标

综合分榜单（049）回答「谁综合最强」，雷达回答「强在哪个维度」——Top5 头部节点的四维强弱叠图一屏可比：某节点度满轴但中介弱（局部富豪）、某节点中介满轴但紧密低（远端桥梁）、某节点 PR 饱和（被重要者指向）。管理场景用途：关键节点画像对比（Top5 叠图）、权重调整决策辅助（compare Tab 调权重前后雷达形态变化）、汇报演示（雷达图是管理层友好形态）。对展示系统的价值：把四 Tab 的数字榜单翻译成形态语言。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**SRS《算法展示.md》seq 436 写「整合多维度中心性指标，通过加权计算形成综合评分」（附录 A）——雷达是 UI 对综合评分的可视化扩展形态，维度清单/归一法/PR×5 拼装式全部未言明。UI 前端 `runCentralityAnalysis`+`radarOption` 给出了完整真实现（min-max 归一+四维等权+第四轴 PR×5 截断），是**事实上的公式定义人**；本件按权威多指标合成方法（min-max 归一）锚定，UI 的 PR×5 拼装作口径差披露。检索记录见附录 A.2。

### 1.4 类似指标权威方法可行性分析概要

雷达图（radar chart）是多维属性对比展示的标准形态，权威锚三重。其一，中心性方法族（R1 Freeman 1978）：度/紧密/中介三经典中心性奠基——雷达前三轴的方法源；其二，多属性决策归一（R2 Hwang & Yoon 1981）：属性 min-max 归一后对比——雷达轴归一的规范框架；其三，PageRank（R3 Brin & Page 1998）：第四轴方法源（与 001/049 同构）。方法族对照：
