## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技数据资源/应用视窗·数据应用排行榜（seq 376：资产调用排行；「支持按时间、应用主体或业务领域进行排序」）。UI 实际挂载（派单 mount 行 208，实查确认）：`ApplicationWindow.jsx:208` assetColumns `{ title: '环比', dataIndex: 'growth', align: 'center', render: v => <span style={{ color: v >= 0 ? ### 1.2 为什么需要本指标

环比增速是资产价值的**动量读数**：排行（存量 calls）回答「谁最大」、环比回答「谁在涨」——增长型资产（环比高）值得扩容、衰退型（连续负环比）触发治理。红绿箭头的视觉语法直接服务管理决策（涨=绿关注、跌=红预警——注意 mock 配色绿涨红跌，与国内股市红涨绿跌相反，属 UI 设计选择）。权威对应物：环比（MoM/period-over-period）是统计与业务分析的标准增速口径（国家统计局月度指标体系）；API 分析的 traffic growth（Kong/Cloudflare 网关报告）；SaaS 的 usage growth（用量增长——计费与续约的核心预测因子）。

### 1.3 需求文档是否给出定义方法

**指标名级三份真源 0 命中。**「环比」为 UI 列题名。应用视窗功能句的时间维度词（seq 376「按时间…排序」/seq 381 供应方「按时间区段」）在，但环比口径三无：期定义（周环比/月环比？）、粒度（单资产/分类/全库？）、基数规则（上期=自然期还是对齐期？）。核增需求与算法库 0 命中（附录 A.2）。

### 1.4 类似指标权威方法可行性分析概要

「环比增速」的权威方法锚分三层。其一，统计口径（R1，国家统计局/统计实务）：MoM=(本期/上期−1)×100%——期=自然月，逢节假日季节性需季调（X-13-ARIMA-SEATS 法，科技数据调用场景可不用）；其二，网关分析（R2，Kong/Cloudflare）：traffic period-over-period——request 计数按期聚合后相除；其三，SaaS 用量分析（R3，OpenView/Amplitude）：usage growth rate——计费周期用量环比。方法族对照：

| 方法族 | 代表 | 原料 | 与三源匹配 |
|---|---|---|---|
| 统计 MoM | R1（统计实务） | 期聚合序列 | **无序列**（041 复用） |
| 网关 traffic | R2（Kong/CF） | request 日志 | **无业务日志**（sys_log 语义排除） |
| SaaS usage | R3（Amplitude） | 用量事件 | 无事件面 |
| 前端演示 | UI mock | growth 常量 | 无基数不可复算（不作源） |

结论：三层方法的原料同为「按期聚合的调用量序列」——一阶断（序列无）则二阶（环比）断，与 041/049/050/053 构成调用族五连判。完整版见附录 C。
