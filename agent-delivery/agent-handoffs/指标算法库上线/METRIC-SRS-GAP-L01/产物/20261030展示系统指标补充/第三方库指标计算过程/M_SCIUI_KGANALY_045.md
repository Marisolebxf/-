## 一、需求定义概述

### 1.1 所属功能模块

科技信息展示系统/科技知识图谱/指标展示/优化决策模型——`OptimizeDecisionPanel.jsx` 第四 Tab「决策反馈闭环」（`:369-412`）：四张 Statistic（反馈均分/反馈后准确率/目标误报率/应用反馈优化按钮）+反馈 List（部门·结果·星级·时间·决策 ID·建议）+闭环建议行。目标误报率读 `feedbackAdj.falsePositiveRate`——`decisionModel.js applyFeedbackLoop` 从 4 条 mock 反馈算：valid（结果含「有效/确认」）=3、falsePos（结果含「误」）=1 → max(1, 8−3+1×1.5)=6.5→toFixed(1)=**6.5%**？——实测 UI mock 值为 4.5（8−3−1×1.5+...——mock 公式带取整与小数位细节以 decisionModel.js:57 原式为准：`Math.max(1, +(8 - valid.length + falsePos.length * 1.5).toFixed(1))`=8−3+1.5=6.5；UI 展示值随 mock 数据态演化，本件以原式登记）。**「目标域」语义**：这是反馈调优后的目标基线（下一轮模型迭代的误报率 KPI 目标），非实测误报率——目标值与实测值的区分是本件口径核心。

### 1.2 为什么需要本指标

误报是风控的运营成本：误报（FP）多则人工复核工作量爆炸、业务部门对告警疲劳（alert fatigue），最终真告警也被忽略。「目标误报率」把误报管理从被动统计变为主动目标管理：反馈闭环收集「这条告警是误判」的业务意见，模型迭代瞄准「下一版把误报率降到 X%」。seq 422 原文「确保模型始终贴合真实业务需求和风险防控目标」——目标值就是「风险防控目标」的量化位。它与反馈均分（KGANALY_015，L1 批件）同 Tab：均分度量反馈质量，目标误报率度量调优方向。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**SRS seq 422 写「搭建完善的决策反馈机制，对每一次模型决策的实际效果进行追踪和评估。通过收集并分析业务部门的反馈信息，不断优化和调整决策逻辑、规则和指标参数」——「目标误报率」未出现（UI 拆件名），误报的判定（复核结果含「误」即 FP？）、目标值设定机制（公式算出还是人工定）全部未言明。UI 公式是 mock 占位。检索记录见附录 A.2。

### 1.4 类似指标权威方法可行性分析概要

误报率=FPR/假阳性率族，权威锚齐备。其一，统计学习标准（R1 Hastie et al. ESL）：FPR=FP/(FP+TN)——工程上告警场景常简化为 FP/告警总数（precision 的补），两口径须注明；其二，风控运营框架（R2 中国银保监会《商业银行互联网贷款管理暂行办法》类监管文本）：人工复核与模型预警的配比要求——误报治理的监管语境（复核对模型输出的否决率）；其三，scikit-learn（R3 `false_positive_rate`）：工程实现形态。UI 的「目标域」语义在 OKR/KPI 管理框架里有近亲（目标值 vs 实测值的分离），但无单独文献锚——以 R1-R3 的实测口径+目标管理实践并列。方法族对照：

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（UI mock 未闭合，需求无公式）**：

$$\text{FPR}_{target} = \text{下一迭代的目标误报率}; \qquad \text{FPR}_{actual} = \frac{FP}{\text{告警总数（复核完毕集）}}$$

实测口径=复核完毕的告警中判误占比；目标口径=按反馈调优后为下一版设定的基线（UI 公式试图从反馈条目外推——占位算术）。**待裁项**：误报判定（复核结果含「误」的标签口径）、FPR 形态（FP/(FP+TN) vs FP/告警总数）、目标值设定机制（公式/人工/OKR 节奏）。

**降档/升档触发器（B10 模板）**：①现状两翼缺 → **完全不支持**；②告警明细+反馈复核台账双落（seq 422 数据化）→ 升**完全转换支持**（JOIN 直算 FP 占比+目标值人工设定）；③仅反馈台账无告警明细 → 部分支持（有 FP 计数无分母）；④与 042/043/044 共用升档工程（预测明细表一表多用）。

## 四、数据缺失情况

### 4.1 两翼皆缺+目标无锚（结构级，判定性）

误报率可构建性=「告警明细（分母）×复核判定（分子）」配对。三源现状：告警明细 043 已证零立项；复核判定本件证零立项（审计语义排除）。「目标域」进一步要求实测值有历史序列才能定目标——当前连单点实测都无。**结构与数据双缺**，判完全不支持。与 044 对比：本件 FP 侧只需复核闭环（内部流程数据），044 FN 侧需外部证实源（外部数据）——本件升档工程门槛低一档，是模型面四件中建议最先数据化的一件（连同 015）。

### 4.2 反馈台账的 schema 前瞻（披露级）

UI mock 已给出反馈台账最小 schema：`decisionFeedbackItems`（feedback_id/time/dept/decision_id/result/rating/suggestion）——result 四态（有效拦截/确认违约风险/误判/有效预警）即混淆矩阵标签的业务语言。建表建议直接采用并加 reviewer/review_channel 字段（人工复核 vs 系统自动）。该表落库后：015（均分=rating 均值）、045（FP 率=误判数/复核总数）、044（TP 侧=确认数）三件同时激活。
