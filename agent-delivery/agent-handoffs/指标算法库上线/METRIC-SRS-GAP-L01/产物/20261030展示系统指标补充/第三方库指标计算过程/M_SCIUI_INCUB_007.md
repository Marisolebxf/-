## 摘要

「使用热度」在 UI 上是一字段三用：推荐面板读数（%）、地图热力图层分档（80/60 两道阈值）、KPI 平均使用率（均值聚合）——三处共用 `usageRate`。该字段的物理口径是机时利用率（科技部考核细则的「仪器运行机时」，R1），数据源是设备管理系统的机时日志。三源探针：usage/utiliz/machine_hour/heat/hot/freq 词族在 dev 17 schema / gkx 280 表 / 久新 218 表（现场实数）表名+列名双扫全部 0 命中；语义最近的久新 `hotspot_score`（`ads_research_problem_monthly_metrics` 等）是科研问题热度（论文/专利增长驱动），与仪器机时无关；gkx 医疗器械 15 列断言无热度列。判**完全不支持**；修复与 INCUB_008（机时利用率）同案：机时日志接入。

- 需求判定：**UI 挂载件**（SRS 无同名；上位叶两处覆盖）。
- 复现状态：断言脚本已跑通（`heat_like == []`）。
- 档位结论：**完全不支持**（机时派生字段零承载）。
- 关键事实：UI 分档阈值 ≥80 高热 / ≥60 中热（`:220` 实查）；久新学术热度不可代理。
- 升档路径：机时日志接入 → usageRate 可算 → 热度分档/均值/KPI 三用同步升档（连 INCUB_019）。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技成果展示/大型科学仪器共享/**机构能力窗·推荐面板**。「使用热度」是推荐项六规则之一（`buildRecommendationItems` 的 `usage` 键，`:503`）：`value: ${instrument.usageRate}%`，`reason: "使用率反映机构能力释放和需求强度"`。同字段另两处消费：①地图分布层 `buildInstrumentMapRegions`（`:242`）在 heat 图层开启时以 `getInstrumentHeatLevel(item)` 定级（high/medium/low 三色点）；②KPI 概览条 `buildOverviewMetrics`（`:173`）「平均使用率」= `Math.round(Σ usageRate / total)`。

mock usageRate 分布 52–92（演示值），分档函数实查阈值 80/60（`InstrumentSharingPage.jsx:220-233`）。

### 1.2 为什么需要本指标

热度回答「哪台仪器值得重点保障/推荐」：管理者按热度调配排期与维护优先级（高热仪器扩容、低热仪器盘活——科技部对连续低使用率仪器有调配划拨机制，R1 第十一条），创业者按热度预判排队时长。它是推荐面板的核心排序理由之一，也是地图热力图层的唯一定量输入。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「使用热度」指标名未出现；SRS 上位叶只给行为（「自动收集用户对仪器使用后的反馈评价及使用频率」「系统高亮显示热门资源」），没有热度的定义（使用率口径、时间窗、分档阈值）。

### 4.1 机时日志零承载（主因）

机时日志（有效工作机时/可用机时）是共享平台设备管理系统的运行数据，三源无镜像。四缺失情形归属：**表不存在**。修复动作是设备管理系统对接（机时接口），库内无法构建。
