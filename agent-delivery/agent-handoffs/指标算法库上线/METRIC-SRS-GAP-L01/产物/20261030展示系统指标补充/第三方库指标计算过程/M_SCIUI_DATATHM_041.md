## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技数据资源/接入视窗/问题资源情况（1.1.1.1.4.4.2.3，SRS seq 364-367）·问题资源可视化统计报表·**月度趋势导出 sheet**。UI 实际挂载（派单 mount 行 556，实查确认）：`AccessWindow.jsx:519-563` 问题资源可视化统计报表 Card 的 extra ExportButton——sheets 第四项 `{ name: '月度趋势', rows: problemResourceStats.monthlyTrend, fields: [月份/问题总数/已解决] }`（:557-564，name 在 :556）。mock 语义源 `mockData.js:1708-1714` `problemResourceStats.monthlyTrend`：5 点双序列（total 18/22/25/20/23 + resolved 15/18/20/17/16）。同 Card 主体「动态历史趋势可视化」子卡（:573-577，problemTrendOption 折线）是同数据的图表位。mock 结构披露：month 字段用中文月串（'1月'）非日期——导出后不可直接排序聚合（B9）；数值为演示常量，不作数据证据（B10）。

### 1.2 为什么需要本指标

月度趋势 sheet 服务问题资源治理的「**节奏监控**」：管理者按月回看问题发现-解决的双序列差（total-resolved=期末未解决存量），识别治理是否跟上发现。派单名「调用量月度趋势」对应的是同一图形在调用监控语境的形态（021/022 同族）——月×量序列是运维监控的标准时序面（Prometheus/CloudWatch 的 range query 形态，R2）。需求侧的工程前提在 :2563 写明：「通过API日志采集与接口调用分析，动态跟踪每个资源接口的连接活跃度、调用频率和失败率」——月度趋势的前提是逐笔日志（或逐月台账），三源均未建。

### 1.3 需求文档是否给出定义方法

**三份需求说明书未出现「调用量月度趋势」。**「月度趋势」是 UI 导出 sheet 名（:556）。调用口径语义锚：主需求 :2563（API日志采集前提）、:2571（调用趋势分析——021/022 已承接，均判完全不支持）；问题资源口径语义锚：seq 367 问题资源情况总览功能（M_SCIUI_DATATHM_017 同族已证问题计数口径无定义）。两量纲的月度聚合口径（自然月边界？含本月未结束期？）均无定义。核增需求与算法库 0 命中（附录 A.2）。

### 1.4 类似指标权威方法可行性分析概要

「月度量序列」的权威方法锚分三层。其一，时序监控口径（R2，Prometheus）：range query 按 step 聚合 counter 增量——月度序列=日志逐笔在月窗内聚合，前提是**逐笔日志或至少逐期快照**；其二，国家数据开放统计（R1，公共数据开放报告）：按月/按年的调用与下载量序列上报——制度化形态是平台侧逐月统计台账；其三，库内代理路径：无日志时以任何带时间戳的流水表按月聚合——但三源的时间戳流水面语义全部错位（§3.2）。方法族对照：

| 方法族 | 代表 | 原料 | 与三源匹配 |
|---|---|---|---|
| 时序监控聚合 | R2（Prometheus） | 逐笔调用日志 | **无日志**（020 族证） |
| 逐月统计台账 | R1（开放数据报告） | 月度统计面 | **无台账** |
| 时间戳流水代理 | 库内近似 | 任意流水表 | 语义全错位（§3.2） |
| 前端演示 | UI monthlyTrend | mock | 结构披露（不作源） |

结论：两量纲的原料（调用日志/问题台账）三源均无，代理面语义全错位。完整版见附录 C。

## 四、数据缺失情况

### 4.1 月度序列面零承载（结构级，判定性缺口）

月度趋势的唯一原料是「带时间戳的流水面」或「逐月统计台账」（§1.6 公式的 ts 归月聚合）。调用口径：三源 0 命中（调用监控族四件 020/021/022/本件同根）；问题口径：问题资源台账三源零承载（L4 族探针 + period 词族双证）。**四缺失情形归属「表不存在」**：修复动作是 APM 日志接入（调用口径，族级四件共用）或问题台账立项（挂载位口径）。

### 4.2 时间维代理全错位（语义级，次因）

即便放宽到「任何时间戳流水按月聚合」的代理路径，三源仅有的三个候选全部不合格（§3.2）：sys_log 语义排除（认证端点）、enterprise_news 单点（批次不成序列）、久新快照单日一期（无逐月期）。「月」这个时间粒度在全库没有可用的承载形态——这是比缺某张表更深的缺口：时间维基础设施缺位。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| API 调用日志/APM 接入 | 监控工程立项（族级） | 本件 + 020/021/022 + seq 343-344 族 | 触发器①（四件共用） |
| 问题资源台账立项 | 数据工程 | 本件挂载位 + 017/069 | 触发器②（问题族共用） |
| UI 空数据态 | 展示规范 | 本件 | mock 5 点双序列建议替换空态 |

档位后果：APM → 调用量口径**完全直接支持**；问题台账 → 挂载位口径**完全直接支持**；现状 → 完全不支持。推荐：随调用监控族主线（APM）并项推进。
