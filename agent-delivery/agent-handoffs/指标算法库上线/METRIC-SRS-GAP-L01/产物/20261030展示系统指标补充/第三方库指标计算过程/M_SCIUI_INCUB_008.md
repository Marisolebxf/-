## 摘要

仪器共享页以「使用率」为核心读数贯穿全页（KPI 均值、抽屉、推荐面板、排行榜、热力分档、表格进度条、相似仪器、阶段视图共 17 处消费点），指标名在三源与三份需求说明书中均 0 命中，属 UI 演示层自设指标。三源探针证明机时日志零承载：分子（有效工作机时）与分母（可用机时）均来自设备运行系统，三源无任何承载表。唯一设备主表 `gkx.dwd_medical_device` 为静态注册台账（10,000 行、15 列、无运行态字段），不可代理。判完全不支持；接入机时日志（设备开机数据/预约核销）后可升档。

## 一、需求定义概述

### 1.1 所属功能模块

科技信息展示系统 → 科技成果展示 → 大型科学仪器共享（`InstrumentSharingPage.jsx`）。

### 1.2 为什么需要本指标

用户遴选共享仪器时需知道设备忙闲状态：使用率直接决定排队预期与择机推荐排序；管理侧需以机时利用率考核开放共享绩效（科技部评价考核 R1「仪器运行机时」15 分权重）。

### 1.3 需求文档是否给出定义方法

否。三份需求说明书未出现「使用率/机时利用率」指标名；SRS 1.1.1.1.4.6.4.1.3「系统自动统计共享率及使用频率」为上位功能覆盖，未给出机时口径。

### 1.4 类似指标权威方法可行性分析概要

科技部大型科研仪器开放共享评价考核（R1 仪器运行机时，权重 15 分）提供权威口径：年有效工作机时 ÷ 年可用机时；年可用机时 = 年日历机时 − 计划维护停机 − 节假日停机。可行性取决于机时日志——三源均无，权威方法不可落地（探针见 §二/附录 B）。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

- **推测原意**：以机时利用率标识设备忙闲，支撑推荐排序与共享绩效考核。
- **操作化定义（权威重建式）**：机时利用率 = 年有效工作机时 ÷ 年可用机时 ×100%；年可用机时 = 年日历机时 − 计划维护停机 − 法定节假日停机（按设备开机窗口折算）；页面聚合 = 全部在网设备单台利用率的简单算术平均（与 `:172` 现有 UI 聚合一致）。
- **降档触发器**：已到底档（完全不支持），无降档空间。
- **升档触发器**：接入设备机时日志/预约核销流水（设备管理系统对接）→ 部分支持（单台可算）；机时日志完整覆盖在网设备 → 完全转换支持。

### 1.7 需求叶定位与相近叶关系

- 本叶：仪器共享·使用率（机时利用率），UI 根字段 usageRate 的根字段件。
- 相近叶：INCUB_007（使用热度，同 usageRate 字段族热力分档）与 INCUB_019（全市平均使用率）共享根因、各自独立留证；SOFTSCI_004/010/015（运行态字段族：服务次数/预约流水/故障率）同判完全不支持。

## 四、数据缺失情况

### 4.1 缺口清单

①机时日志无表（分子分母双缺）；②设备管理系统未对接（开机/维护数据不入库）；③静态台账无运行态列（`dwd_medical_device` 0 空值纯注册面）；④需求侧无限定口径（SRS 仅上位功能句，无机时定义）。

### 4.2 修复建议与影响面

短期：对接设备管理系统机时接口（或预约核销流水近似）→ 部分支持。中期：按科技部考核口径建设机时采集（年有效机时/年可用机时）→ 完全转换支持。远期：接入大型科研仪器国家网络管理平台使用率读数 → 完全直接支持。INCUB_007（使用热度）、INCUB_019（全市均值）联动受益（同根字段）。

### 4.3 影响面

仪器共享页 17 处 usageRate 消费点全部走 mock 演示态；「平均使用率」KPI、使用排行、热力分档、推荐排序均无真实读数支撑。
