## 摘要

「应用使用热度值」是总体视窗·累计调用与趋势分析卡（seq 346）右侧「按资源类型 · 热度与生命周期」表格的「应用热度」列（`CumulativeCallTrendAnalysis.jsx:107-118`，四档 Tag：高热红/中热橙/升温金/低热默认）。指标名三份需求说明书 0 命中，语义锚在 seq 346 功能句「帮助用户判断资源应用热度和生命周期」——「热度」是研判目标词，分档阈值与算式无定义。数据侧判定核心是资源调用台账（资源类型×累计调用量）存在与否：三源词族逐一排除（dev 5 张命中全 0 行且语义为产业链/企业/政策面；gkx 0 命中；久新 14 张命中全为科研问题/技术热点文献热度，语义排除）。判**完全不支持**。脚本已跑通（三源排除证据全落产物），产物与正文数字逐一对应。

- 需求判定：**需求功能分句派生**（seq 346 研判目标词在；「应用使用热度值」名与算式无）。
- 复现状态：脚本已跑通；三源词族排除探针 + 久新语义排除证据全落产物。
- 档位结论：**完全不支持**（资源调用台账三源零承载，热度分档前置依赖未建）。
- 关键事实：久新有 14 张「热度」词族表，但度量对象全是科研问题热度分量（`ads_research_problem_heat_component` 812 行评估面）与技术热点信号（`ads_technology_hotspot_*`）——「有热度表」≠「有资源调用热度」，这是本件最重要的语义排障。
- 升档路径：API 网关/调用台账接入 → 完全直接支持（触发器①，与 020/021/022/032/034/035 族级共用）；自建分档阈值+第三方调用监测 → 完全转换支持（触发器②，阈值须甲方裁定）。

### 1.2 为什么需要本指标

累计调用与趋势分析卡（seq 346）的管理命题是「**资源运维策略参考**」（卡 extra 自述「热度研判 · 生命周期 · 运维策略参考」）：高热资源要保障供给、升温资源要重点培育、低热资源要评估下线。权威对应物是公共数据开放平台的「热点数据/最热接口」实践（R2 深圳 / R3 北京）：按调用量对数据服务排序分级是开放平台运营标配——调用量 Top 榜与热度分层互为表里。本库场景下，该读数要求资源调用台账存在且含资源类型维——没有台账，任何热度分档都无从谈起。

### 1.3 需求文档是否给出定义方法

**三份需求说明书未出现「应用使用热度值」指标名。**语义锚一处：SRS 总体视窗.md seq 346（excel_row 349，:241-252）「采用大数据统计技术，自动归集各类数据资源自上线以来的累计调用量，并按时间区段进行趋势分析，帮助用户判断资源应用热度和生命周期，优化资源运维策略」——「热度」是趋势分析的**研判目标词**，热度分几档、每档阈值（调用量还是占比？绝对值还是相对值？）均无定义。核增需求与算法库 0 命中（附录 A.2）。UI 的四档 Tag 是前端演示约定，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

「资源使用热度」的权威方法锚分三层。其一，国家数据资源统计面（R1 国家数据局 2025 调查报告）：政务数据共享枢纽累计调用超 5,500 亿次、词元（Token）调用量 21100 万亿——调用量是官方数据资源统计的**核心动作量纲**，但其前提是调用日志采集制度。其二，地方开放平台热点实践（R2 深圳 / R3 北京）：按接口调用量排「最热接口/热点数据 TOP10」——热度=调用量的排序分层，工程上要求接口级调用日志。其三，久新库内热度面：科研问题热度分量（文献计量加权）——方法族存在但度量对象是「科研问题/技术主题」而非「数据资源」。方法族对照：

## 四、数据缺失情况

### 4.1 资源调用台账零承载（结构级，判定性缺口）

热度分档的唯一原料是资源调用台账（资源类型×累计调用量×时间）。三源实测零承载（§3.3）——这不是数据量问题而是**调用监控工程缺位**：数据资源被谁调用多少次从未在网关/台账层记录。需求 seq 346 把「自动归集各类数据资源自上线以来的累计调用量」写进功能描述（工程前提自宣），但三源无对应承载表。**四缺失情形归属「表不存在」**：修复动作是 API 网关日志/调用台账接入——本批 020/021/022（调用监控三件套）+032/034/035（区段/榜单族）与本件共享此工程，一次接入族内六件升档。

### 4.2 资源类型编目轴零承载（结构级，次生缺口）

热度分档的分组轴是「资源类型」（结构化/非结构化/半结构化/实时流）。三源无资源编目面（DATAOV_001 资产目录缺口同根，族内互引不重复展开）——即便调用台账建成，类型轴仍需资源登记面补齐。两缺口叠加是本件完全不支持的双重根因。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| API 网关/调用台账接入 | 监控工程立项（族级） | 本件 + 020/021/022/032/034/035 + seq 343-346 族 | 触发器①（一次建设族内六件升档） |
| 资源登记面（类型轴） | 数据工程立项 | 本件 D2 + DATAOV_001 族 | 类型分组轴补齐 |
| 热度分档阈值裁定 | 口径裁定 | 本件 | 四档阈值（占比/绝对量）须甲方定 |
| UI 暂无数据态 | 展示规范 | 本件 | mock 四档建议替换为「暂无数据」 |

档位后果：台账+类型轴建成 → **完全直接支持**；第三方监测+阈值裁定 → **完全转换支持**；现状 → 完全不支持。推荐顺序：台账立项为主线（族级共用），阈值裁定并行（零成本），UI 暂无数据态即期执行。
