## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技知识图谱/算法展示/中心性计算展示/度中心性计算与展示（1.1.1.1.5.2.1.1；SRS seq 428、excel_row 431）。UI 实际挂载：`CentralityPanel.jsx:664` 度中心性 Tab「按节点类型分组比较」卡，条形图 option `typeBarOption`（`:372-385` useMemo，`:380` yAxis name='平均度数'），数据源 `result.byType`——`centralityAlgo.js:426-434` 在 15 节点 23 边演示图上按 type 分组：`g.avgDegree = +(g.sum/g.count).toFixed(2)`（sum 累计 degreeRaw 原始度数）。同 Tab 配套：度中心性热力图（`:660`）、度数时间趋势（`:669`）、高影响力节点排序表（`:673`）。本件指标即分组比较条形图的**纵轴统计量**——「平均度数」本身。

### 1.2 为什么需要本指标

度数是图节点最基础的重要性度量（直接连接数）。分组平均度数回答的是**结构对比**问题：哪类节点是图谱的「枢纽类」——演示图里机构节点度数显著高于论文节点（机构连多人、论文连少量作者），分组条形图把这个结构直觉量化。对管理者的价值：技术知识图谱中若「技术类节点平均度数」远高于「专家类」，说明图谱偏技术关联沉淀、人的画像偏薄——分组比较是图谱建设方向的体检表。seq 428 原文点名这个能力位：「还可按节点类型如人员、机构、论文等进行分组统计和比较」。

### 1.3 需求文档是否给出定义方法

**需求文档给了指标名但未给计算式。**seq 428 写「按……分组统计和比较」，平均度数的定义（度=无向图邻居数；平均=组内算术均值）由图论标准定义+UI 实现（sum/count）闭合——本件无口径悬念，唯一待裁项是**加权 vs 无权**（久新预计算列是加权度，UI 演示是无权度，双口径并列 §2.4）与**分组维**（UI 按节点类型，久新节点表无 type 列、有 community_id，§4.2）。

### 1.4 类似指标权威方法可行性分析概要

度数与平均度数是图论最基础的统计量，权威锚清晰。其一，图论教材标准（R1 Diestel《Graph Theory》）：度=关联边数，平均度=2E/N（无权简单图）；其二，NetworkX 工程标准（R2 networkx.degree 文档）：`G.degree()` 节点迭代器+统计库均值——UI 的 sum/count 同构；其三，加权网络扩展（R3 Opsahl et al. 2010 加权度）：节点强度 strength=Σw(e)——久新 `weighted_degree` 列即此口径的预计算落盘。方法族对照：

| 方法族 | 代表 | 本库承载 | 贴合度 |
|---|---|---|---|
| 无权平均度 2E/N（R1/R2） | Diestel/NetworkX | 边表直查可推（60.448） | 锚 |
| 加权节点强度（R3） | Opsahl 2010 | weighted_degree 列直查（10.0604） | 高（库内预计算） |
| 分组均值（UI 同构） | centralityAlgo.js | 社区分组实算 | 高（类型分组待补维） |

结论：方法零悬念，数据侧双口径齐备——加权列直查是库内最短路径。

**定义（双口径并列）**：无权口径 $\bar{d}=2|E|/|N|$（无向简单图）；加权口径 $\bar{s}=\frac{1}{|N|}\sum_{v}\text{weighted\_degree}(v)$（节点强度均值，含 0 度节点在分母——孤立点披露）。分组位：$\bar{d}_g=\text{avg}(\text{weighted\_degree}) \text{ GROUP BY } g$（分组维 $g$：UI 意图=节点类型；库内可行=community_id）。

### 2.2 全图平均加权度（主读数）

$\bar{s}=\sum_v \text{weighted\_degree}(v)/|N|=195{,}473.58897153/19{,}430=\mathbf{10.0604}$（产物 `derived[0]`，denominator_note 落盘）。分布特征：min=0（孤立点）/max=**1,010.91**（最高强度节点——框内枢纽）/零值 1,708 个。

### 2.3 无权口径交叉验证（2E/N）

## 四、数据缺失情况

### 4.1 现成汇总结果行缺失（唯一结构缺口，非判定性）

三源无「平均度数」指标行（`absence_probe`）——完全转换支持而非完全直接支持的唯一原因。修复最轻：夜批一行 SQL（AVG 落图统计表）。

### 4.2 节点类型维缺失（分组位口径级）

UI 按节点类型（人员/机构/论文/技术/项目）分组，久新技术图是纯技术层单域图——节点全是技术节点、无类型列（`jiuxin_node_type_col=null`）。分组位两解：①多域混图（需跨域边，KGANALY_001 §4.2 同款待裁项）；②社区分组代理（本件已实算，语义=技术社区强度分层）。gkx 侧学者合作网节点同人不同构（学者主档无 type 列，机构维度在边表 org 列）——严格类型分组三源均需补维。此为分组位口径缺口，不影响全图均值位的完全转换支持判定。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 夜批 AVG 落图统计表 | 数据工程（最轻） | 本件 + 025/026/033/034 | 升完全直接支持 |
| 节点类型维补齐（多域混图或 type 列） | 口径裁定+数据工程 | 本件分组位 + 033/034 + 001 | §1.6 触发器③ |
