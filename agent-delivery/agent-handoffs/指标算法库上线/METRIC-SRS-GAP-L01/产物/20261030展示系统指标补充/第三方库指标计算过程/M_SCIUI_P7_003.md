## 二、计算过程

### 2.1 装载与规模校验

pymysql 直连久新只读库。主面 `ads_institution_yearly_metrics` 816,120 行——乘积自洽校验：68,010 机构×12 年=816,120（B11 乘积对账在案）；年份分布 2015–2026 十二年每年恒 68,010 行（facts `jiuxin_institution_yearly_by_year`）。姊妹面 `ads_technology_yearly_metrics` 年份分布 2021–2026 递减（14,526→3,450，facts `jiuxin_technology_yearly_by_year`）——技术节点池逐年扩张（新节点无历史），与机构表的满铺形态不同，作序列底座时机构表优先。

### 2.2 序列完整性：长度分布实测

对 68,010 机构逐家 `COUNT(*)` 聚合（小表 GROUP BY，非大表全扫）：序列长度分布**恒 12**（`{12: 68,010}`，facts `jiuxin_institution_seq_len_distribution`）——无断年、无孤儿年。这一读数是本件最重要的质量证据：序列面不是「有行就行」，而是每家机构都有完整十二年链，同比/环比/移动平均等任何窗口函数可直接施用，无须补齐工程。

### 2.3 六年窗口复现（对齐 UI 轴）

演示对象选取（B5 确定性：`ORDER BY SUM(paper_count) DESC, institution_id` 双键破平局）取论文总量最大机构，拉全序列后切 2020–2025 窗口：六年全占（facts `jiuxin_demo_institution_window_2020_2025` 六项，paper/patent/talent/project 四指标列随行）。窗口同比派生（B3 同基）：`jiuxin_demo_institution_paper_yoy_pct` =（末年−上年）/上年，分子分母同一机构同表序列。UI 的「柱+增长率线」双轴在此形态上直配。

```sql
SELECT statistics_year, paper_count, patent_count, talent_count, project_count
FROM ads_institution_yearly_metrics
WHERE institution_id = %s ORDER BY statistics_year;
-- → 演示机构 12 行全序列；2020–2025 窗口六年全
```

### 2.4 指标列覆盖

机构表 19 列中指标列 14 个（paper/cited_by/citation/talent/new_talent/patent/project/collaborator/international_paper/open_access_paper 计数 10 个 + fwci/avg_citations_per_paper 均值 2 个 + 年份/版本列）——覆盖 UI 仿真卡片的「技术供给」（paper/patent）、「产业需求」（project）两仿真变量族；「政策资源/区域承载力」两变量在序列面无对应列（缺口归 §四）。

UI 仿真卡片四变量族中「政策资源/区域承载力」两族在久新序列面无列——历史序列只能画「技术供给/产业需求」侧的指标。修复路径：其一，政策资源侧接 gkx 政策表按年聚合（`dwd_policy_base` 20,000 行含发布日期，年度计数可聚合，S3-01 快照在案）；其二，区域承载力侧久新 `ads_geo_yearly_metrics` 族存在（schema 在案）但本件未深探——列级缺口而非源级缺口。

### 4.2 「指标」口径不闭合（需求级）

评估页的「指标」未定义（§1.3），本件以机构论文数序列作演示。这不是数据缺口而是口径缺口：闭合后（评估四维分/单项产出/环境变量）三档去向见 §1.6 触发器——现有序列面在两种最可能口径下均可供数，风险敞口小。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 机构序列直供 v1 | 数据工程 | 本件+P7_004 | 窗口切分 API 化，2026 剔除在途 |
| 政策资源年度面聚合 | 数据工程 | 本件+仿真族 | gkx 政策表按年 GROUP BY |
| 口径闭合会签 | 产品决策 | 本件+P7_004+TECHTRK_024 | 三件同口径 |
