## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技数据资源/总体视窗·资源接入总览仪表盘（「一键展示仪表盘」展开态第三卡；挂靠 seq 359 总览功能句——SRS 总体视窗.md:14「可一键展示当前已接入的所有科技数据资源类型与数量，在仪表盘上直观呈现各类资源的分布比例、年度增长趋势和不同来源机构的接入活跃度」）。UI 实际挂载（派单 mount 行 626，实查确认）：`OverviewWindow.jsx:626` Card title「来源机构接入活跃度」（extra `<Tag color="blue">近12个月</Tag>`）；图函数 `:128-172` getSourceActivityOption——横条图（y 类目五机构 inverse、x 值轴「活跃度（分）」max 100、分色 `>=70 '#165dff' / >=50 '#ffb020' / '#86909c'`、tooltip 双读数 `${accessCount} 次 + ${activity} 分（${status}）`）。mock 语义源 `mockData.js:81-87` overviewSourceActivity 五机构。mock 结构披露：activity 与 accessCount 两量纲并列（分/次）；分色阈值与 status 三档（活跃/一般/较低）是前端自定，无 SRS 依据（B9）。

### 1.2 为什么需要本指标

来源机构活跃度是供给侧管理的**分级运营读数**：管理者按活跃度对数据供给方分级（重点保障高活跃机构、激活低活跃机构、淘汰僵尸源）——mock 的分色（蓝/橙/灰）就是三级运营的视觉形态。权威对应物：RFM 模型的 Recency/Frequency 双因子活跃度（客户活跃度分析的经典框架——接入语境=最近接入距今天数+接入频次）；数据目录的 provider 维度统计（DCAT dataset 按 publisher 聚合）；供应链管理（SRM）的供应商绩效评分（评分卡模型）。

### 1.3 需求文档是否给出定义方法

**指标名级三份真源 0 命中。**总体视窗总览功能句含「不同来源机构的接入活跃度」功能词——功能在，但：评分模型（0-100 分制？分几档？因子有哪些——频次/近度/量/质量？权重几何？）、「接入」的计数对象（批次/笔/资源？）、「近12个月」窗（滚动 365 天？自然 12 月？）均无定义。UI 的 96/88/76/58/36 是演示常量，无因子可考。核增需求与算法库 0 命中（附录 A.2）。

### 1.4 类似指标权威方法可行性分析概要

「机构活跃度」的权威方法锚分三层。其一，RFM 框架（R1，客户分析经典）：Recency（最近一次接入距今天数）+Frequency（窗内接入次数）双因子打分合成——零售/金融客户活跃度标准做法，接入语境可直接迁移（最近接入日+月均接入批次）；其二，数据目录聚合（R2，DCAT）：`dcat:dataset` 按 `dct:publisher` 聚合数据集数与更新时间——目录形态的供给方画像；其三，供应商评分卡（R3，SRM 采购管理）：多因子加权（交付及时率×质量合格率×响应速度）——最接近 mock「合成分」形态但因子定义须先裁定。方法族对照：

| 方法族 | 代表 | 原料 | 与三源匹配 |
|---|---|---|---|
| RFM 双因子 | R1（客户活跃度） | 最近接入日+接入序列 | **无动作序列**（台账 0 张） |
| 目录 publisher 聚合 | R2（DCAT） | dataset×publisher | **无来源标签**（lane3：全 NULL/单值） |
| 供应商评分卡 | R3（SRM） | 多因子流水 | 无流水+模型未裁定 |
| 机构存量清单 | 库内可得 | org 维度表 | **有**（56 张+189,116 行——仅「是谁」） |
| 前端演示 | UI mock | 五机构常量 | 两量纲常量（不作源） |

结论：三方法族原料（动作序列/来源标签/评分模型）全缺；机构维度面只解决三元组最轻的一元。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露模型未裁定）**：按 RFM 双因子简化版推测

$$A(o) = w_R \cdot s_R(\text{recency}_o) + w_F \cdot s_F(\text{freq}_o) \times 100,\quad o \in \text{来源机构}$$

其中 recency=机构 o 最近接入距今天数、freq=窗内（近 12 个月）接入批次数，$s_R/s_F$ 为分段得分函数，权重 $w_R+w_F=1$。**前提三重：动作台账（recency/freq 原料）+来源标签（动作挂到机构）+模型裁定（分段/权重），三源实测三缺**（§3.3）——mock 的分制（0-100）与三档（活跃/一般/较低）只提供输出形态锚。公式列示仅作口径锚（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①评分模型裁定（一纸文件：因子+分段+权重）+接入台账落地（逐笔带机构标签）→ 升**完全直接支持**；②无台账但以「挂库动作」代动作（es_sync/表级 update_time 挂机构维度）→ 至多**部分支持**（挂库节奏≠接入节奏，标签「代理」）；③维持现状 → 完全不支持（UI 卡暂无数据态；机构存量清单可先上——列表无评分）。

## 四、数据缺失情况

### 4.1 接入动作台账+来源标签双缺（判定性，比台账缺席更深）

活跃度输入端两层断：动作台账（0 张——频次/近度无原料）+来源标签（三面全空——动作即便有也挂不到机构）。**四缺失情形归属**：台账「表不存在」；标签「结构在但语义缺位」——后者更深：gkx 供库时未带来源标注，历史数据回填需溯源（成本高）。修复动作：接入登记环节强制来源机构字段（增量堵漏）+存量按采购合同/供库清单批量回填（历史溯源）。

### 4.2 评分模型缺位（口径级，前置裁定）

0-100 分制的因子构成无定义。建议裁定（RFM 简化版）：Recency（最近接入距今天数，分段 0-100）40% + Frequency（近 12 月接入批次，分段 0-100）60%——两因子原料均依赖台账落地，模型文件可先行发布（等数据到位即启用）。分档建议沿 UI 现行阈值（>=70 活跃/50-69 一般/<50 较低）保持视觉连续。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 接入登记强制来源机构字段 | 制度+数据工程 | 本件 + 042/045/047 | 台账落地时同步（增量堵漏） |
| 存量来源标签回填（合同溯源） | 数据工程 | 本件 | 历史数据批处理 |
| 评分模型裁定（RFM 简化版） | 口径裁定 | 本件 | 一纸文件可先行 |
| 机构存量清单先上（无评分） | 展示降级 | 本件 | 56 张维度表可支撑列表形态 |

档位后果：台账+标签+模型三前提齐 → **完全直接支持**；挂库动作代理（标签「代理」）→ 至多**部分支持**；现状 → 完全不支持。推荐：模型文件即期，标签字段随台账落地，存量回填立项评估。
