### 1.2 为什么需要本指标

质量均分回答「哪类来源的数据整体更可信」：管理者按来源比较质量水位（国外数据库 94 vs 开源平台 84——差 10 分）、决定渠道权重与接入策略；可靠性卡片把它与 reliability 并列，构成「来源画像」的双读数（质量均分+可靠性分）。需求语义锚同 058：渠道归集明细属性项（seq 352「数据质量等级」）在来源维上的聚合——行级枚举/评分向上汇成组级均值。权威对应物是 R2（Dataphin）：项目/数据源质量分 = Σ(表权重×表质量分)/Σ(表权重)——聚合质量分是数据治理平台的标准读数形态（分层：表→项目/数据源），但工程上要求资源级评分先行。本库场景下，该读数要求「资源×评分」稽核面 + 分组聚合两层——没有稽核面，任何来源级均分都无从聚合。

### 1.3 需求文档是否给出定义方法

**需求文档未给出均值的定义方法。**「质量均分/资源质量平均分/平均质量」字面三份说明书 0 命中——本读数仅见 UI 列名与卡片标签。语义锚承 058：SRS 接入视窗 seq 352「支持查询并浏览每个渠道归集数据的详细信息，包括数据类型、采集时间、数据质量等级、关联项目、所属领域等元数据」（行级属性项——本件是其聚合形态）；主需求 :2629「内置智能数据质量评估算法，实时检测各项数据指标准确性、完整性和一致性」（工程前提）。SRS seq 357「质量状况」为分区属性项（分布语义，非均值）。**均值口径三无**：分组键（来源/主题/渠道——mock 两维并存）、加权否（等权 AVG vs R2 按表权重加权）、舍入规则（整数/一位小数——mock 全整数，区域分布面另有 93.2/91.5 一位小数形态）均无定义。UI 的「质量均分」是前端作者的演示约定，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

聚合质量分的权威方法分三层。其一，数据治理平台工程口径（R2 Dataphin 质量分）：项目/数据源质量分 = Σ(表权重×表质量分)/Σ(表权重)（满分 100）——**加权聚合**的标准范式，权重按资产重要级（1-10）；其二，国标评价框架（R1 GB/T 36344-2018）：质量评价在维度指标层展开（规范性/完整性/准确性/一致性/时效性/可访问性），聚合到对象级评分再分级——维度权重由评价方案裁定；其三，汇交审核制度（R3 GB/T 39912-2021）：管理方对汇交数据做质量审核——审核结论以汇交批次为单位汇总，是「按批次聚合」的制度形态。方法族对照：

| 方法族 | 原料 | 聚合机制 | 与三源匹配 |
|---|---|---|---|
| 加权质量分（R2） | 资源级评分+权重 | Σ(w×s)/Σw 分层上卷 | **无资源级评分** |
| 六维评价（R1） | 评价表+维度指标 | 维度加权→对象评分 | **无评价表** |
| 汇交批次审核（R3） | 审核台账 | 按批次汇总结论 | **无审核台账** |
| 前端演示 | mock 常量 | 三套分组常量并存 | 结构披露（不作源） |

结论：三条权威路径的第一层原料（资源级评分/评价表/审核台账）三源均无承载——本件是 058 同根的「聚合层缺口」：基座（资源×评分）未建，聚合（AVG GROUP BY）无从执行。与 DATATHM_017（问题总数——同为稽核流水缺失）、061（单资源评分——同为资源级评分缺失）共享基建。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：按 R2→R1 路径推测，均分是资源级质量评分的分组聚合——

$$\bar{q}(g) = \frac{\sum_{r \in g} w_r \cdot s(r)}{\sum_{r \in g} w_r} \; \xrightarrow{\;w_r \equiv 1\;} \; \frac{1}{|g|} \sum_{r \in g} s(r)$$

其中 $s(r)$ 为资源 r 的质量评分（058 同源），$g$ 为分组键（来源类型五维，UI 表格/卡片维；主题七维为另一分组形态），$w_r$ 为资源权重（R2 按资产重要级；等权时退化为 AVG）。**口径三未裁**：分组键（来源 vs 主题两维并存）、加权否（R2 加权 vs UI 等权暗示——mock 无权重字段）、舍入（整数 vs 一位小数）。**前提是资源级稽核结果面存在（资源×评分），三源实测无（§3.3）**——公式列示仅作口径锚（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①质量稽核结果面立项（规则库+资源级跑批+评分登记）→ `AVG(score) GROUP BY 来源` 直查 → 升**完全直接支持**；②乙方自建稽核规则跑批（资源级核查+评分登记+分组聚合）→ 升**完全转换支持**（分组键与加权规则须登记裁定）；③维持现状 → 完全不支持（UI 该读数建议「暂无数据」）。

## 四、数据缺失情况

### 4.1 资源质量稽核结果面零承载（结构级，判定性缺口）

资源级评分面三源零承载（§3.3）——本件是 058 同根的**聚合层缺口**：基座（资源×评分）未建 → `AVG GROUP BY 来源` 无从执行。主需求 :2629 把「智能数据质量评估算法」写进功能描述（工程前提自宣），但三源无规则库、无校验流水、无评分登记——来源级质量水位从未被算法化算出。**四缺失情形归属「表不存在」**：修复动作是质量稽核结果面立项（规则库+资源级跑批+评分登记三件套）；R1 六维可直接作规则库底稿。本缺口与 058（等级）/060（分布）/061（单资源分）/069（问题数）/017（问题总数）共享同一基建：一次立项族内升档。

### 4.2 均值口径三未裁（口径级，即便建成也须先裁）

均值口径三无定义（§1.3）：**分组键**（来源五维 vs 主题七维两套并存——mock 两维都给了常量，正式版须裁定主维或双维并存）、**加权否**（R2 按表权重加权 vs UI 等权暗示——mock 无权重字段，区域分布面 93.2/91.5 是一位小数形态）、**舍入规则**（整数 vs 一位小数）。正式版须一纸裁定——此裁定与稽核面立项解耦，可先行。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 质量稽核结果面（规则库+跑批+评分登记） | 数据工程立项 | 本件 + 058/060/061/069/017 | 触发器①（质量组共享基建） |
| 均值口径裁定（分组键/加权/舍入） | 口径裁定 | 本件 + 060 | UI 两维并存须并一，可先行 |
| UI 暂无数据态 | 展示规范 | 本件 UI | mock 均分常量建议替换为「暂无数据」 |

档位后果：稽核面 → **完全直接支持**（AVG 直查）；自建规则跑批 → **完全转换支持**；现状 → 完全不支持。推荐顺序：口径裁定先行（即期一纸）→ 稽核面立项（族级主线，六件受益）。
