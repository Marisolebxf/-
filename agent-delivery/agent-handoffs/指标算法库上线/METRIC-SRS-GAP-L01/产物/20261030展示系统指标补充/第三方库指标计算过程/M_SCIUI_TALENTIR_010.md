## 摘要

「风险与合规性评估」是人才尽调报告与推荐的第六功能叶（主需求 1.1.1.1.4.3.4.4.6）：支持智能分析专家在合作风险、学术诚信、成果有效性等方面的信息，为单位规避引进风险、优化用才决策提供支撑。UI 侧它是尽调报告的风险点维度（`ReportTab.jsx` RISK_ICONS 消费 riskLevel 枚举渲染红黄绿灯），能力映射清单 `talentRecommendSpec.js:56` 登记为 L6 项；风险值由 mock 生成器 `data.js:1503-1511` 拼装——riskLevel pick(['green','yellow','green','green','red'])、risks 四维 pick(['low','low','low','medium'])，纯演示枚举。数据侧双缺：风险事件面三源零承载（撤稿 0/无诚信表/无冲突表/机构合作预留表 0 行）+ 口径未立项（三方面信息源与等级算式无定义）。但结构侧三件可用：撤稿位（列在值零）、合作史代理底料（5,051,578 行）、政治倾向保守默认分先例（0.10 权重/50 分默认，99,996 行全默认状态）。判**部分支持**（参照 POLCMP_016 双缺+结构证据写法）。脚本已跑通，产物与正文数字逐一对应。

- 需求判定：**需求明列叶**（主需求 :2441/:2463-2465），功能行为在、信息源与算式无。
- 复现状态：脚本已跑通；六词族三源探针 + 撤稿位实测 + 结构侧三件登记全落产物。
- 档位结论：**部分支持**（事件面零承载 + 结构侧可用件并存）。
- 关键事实：dev 侧 30 张企业风险表（risk_dishonest/risk_lawsuit/risk_limit_high 等）证明风险数据工程在库内已有成熟范式——人才侧复用该范式的表结构设计可直接借鉴，缺的只是人才侧事件源。
- 升档路径：接入撤稿数据源（Retraction Watch 等）→ 成果有效性维转换可算；三维全接源+权重立项 → 完全直接支持。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技人才态势/**人才引进推荐评估·人才尽调报告与推荐/风险与合规性评估**（主需求 1.1.1.1.4.3.4.4.6）。UI 实际容器是尽调报告 Tab：`ReportTab.jsx` 顶部的定制维度复选组含风险点默认维度（`DEFAULT_DIMS` 内），生成的尽调报告用 `RISK_ICONS`（`ReportTab.jsx:10` 起）把 `riskLevel`（green/yellow/red）渲染为红黄绿灯，`risks` 四维枚举（low/medium/high）渲染为分项风险条；这些值全部由 mock 生成器 `data.js:1503-1511` pick 产出。能力映射清单 `talentRecommendSpec.js:56` 把「风险与合规性评估」登记为 L6 项——与 S3-02 的 POLCMP_016/022 同型：**结构在、mock 值不写伪分**（B10）。需求原文三方面（合作风险/学术诚信/成果有效性）正好对应 UI 的 risks 四维枚举减一（IP/合规维是 UI 自加），本件按需求三方面组织数据调研。

### 1.2 为什么需要本指标

尽调报告的业务问题是「引进决策的下行风险」：学术能力评分回答「他有多好」，风险合规评估回答「他会不会出事」——撤稿、学术不端、合作纠纷任何一项都可能让引进投入沉没且连带机构声誉。需求把风险合规列为尽调报告四核心能力的收尾环：画像/评分/推荐都是正向证据，**风险合规是负向证据的守门员**。官方对应物是《科研失信行为调查处理规则（试行）》（R1，国科发监〔2022〕221 号）——抄袭剽窃、伪造篡改、代写代投等失信行为的调查处理框架，学术诚信维的国内制度锚；国际侧 Retraction Watch/Crossref 撤稿数据库（R2）是成果有效性维的开放数据源（2023 年起由 Crossref 公开运营，每个工作日更新）。本件的调研重心是「负向信号的结构化数据在三源有没有」：风险维度的特点是零事件≠零风险（可能没采集），absence 的证据学比 presence 更要紧。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**主需求 :2463-2465 给出的是功能行为：「支持智能分析专家在合作风险、学术诚信、成果有效性等方面的信息，为单位规避引进风险、优化用才决策提供有力支撑」——三方面点名了，但每方面的信息源（哪里查冲突/哪里查诚信）、风险等级怎么定（事件计数？加权？红灯阈值？）一个字都没有。核增需求与算法库两份真源检索 0 命中（附录 A.2）。UI 的 pick 枚举是前端演示值，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

「风险与合规性评估」的方法锚分三层。其一，制度框架：科研失信调查处理规则（R1）定义了失信行为的封闭清单（抄袭/伪造/代投/买卖代写等）与调查处理流程——学术诚信维的事件分类学直接可援引。其二，开放数据源：Retraction Watch 数据库（R2，Crossref 运营）5 万+ 撤稿记录含原因受控词表（RetractionNature/Reason 列）——成果有效性维的可接入源，Crossref REST API 按 DOI `update-to` 字段或 GitLab CSV 全量获取。其三，库内先例：capability 面的政治倾向维（0.10 权重、无数据统一 50 分默认）展示了「无事件=保守默认分」的处理范式——风险维可援引同策略（无事件=默认低风险而非零风险）。方法族对照：

| 方法族 | 代表 | 维度结构 | 数据要求 | 与三源匹配 |
|---|---|---|---|---|
| 失信行为框架 | 国科发监 221 号（R1） | 失信行为封闭清单 | 事件记录 | **无**（三源无诚信事件表） |
| 撤稿开放数据 | Retraction Watch（R2） | 撤稿原因词表 | 撤稿标记 | **位在值零**（is_retracted 0/400 万） |
| 保守默认分 | 库内政治倾向维 | 无数据=默认分 | 状态位 | **有**（99,996 全默认先例） |
| 企业风险范式 | dev 30 表 risk 族 | 失信/诉讼/执行清单 | 事件记录 | 结构可借鉴（人才侧无源） |
| 前端演示 | UI risks pick | 四维枚举 | mock 常量 | 结构披露（不作源） |

结论：方法框架与开放数据源都在三源之外（制度文本/Retraction Watch），库内只有结构位与保守处理先例——典型「口径未立项+事件无源」双缺。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：

$$S_{risk} = 100 - \sum_{d=1}^{3} w_d \cdot penalty_d,\quad penalty_d \in [0,100]$$

三方面扣分版：合作风险/学术诚信/成果有效性各建 0-100 惩罚分（事件计数→分段惩罚），加权后从满分倒扣——**此算式当前无从落地**（三方面事件源零承载，权重未立项）。库内可援引的保守处理范式：无事件=默认低风险（对应政治倾向维的无数据=50 分默认策略，99,996 行全默认状态的工程先例）。撤稿维的即期可算读数：撤稿率万分比 0.0（0/4,000,000）——负向信号位在值零，读数登记非风险结论（零事件可能意味零采集）。

**降档/升档触发器**：①接入撤稿数据源（Retraction Watch CSV 按 paper_id/DOI 对齐回填 is_retracted）→ 成果有效性维转换可算；②合作冲突事件源（项目结题异常/纠纷记录）立项 → 合作风险维可算；③甲方裁定风险口径=撤稿+合作史代理双维 → 部分支持升**完全转换支持**（诚信维降维披露）；④三维全接源+权重立项 → **完全直接支持**。

## 二、计算过程

### 2.1 方法选择（文献依据）

若事件源接入，方法选**封闭清单扣分制（失信行为框架的落地版）**：三方面各按封闭事件清单计数（R1 的失信行为分类学定义诚信维清单；R2 的撤稿原因受控词表定义有效性维清单），分段惩罚加权倒扣。选择理由：其一，风险评估的行业标准是「封闭清单+扣分」而非「开放评分」——事件必须可枚举可举证（尽调报告的法律审慎属性）；其二，库内政治倾向维的保守默认分先例（0.10 权重/50 分默认/99,996 全默认状态）证明「无数据维不硬算」的工程纪律在库内已确立，风险维援引同策略（无事件=默认低风险+状态标注）比硬造零风险诚实；其三，Retraction Watch 的原因受控词表（R2）给撤稿维提供了现成的分级依据（学术不端类撤稿 vs 出版方撤稿的惩罚不同档）。撤稿率读数（0.0/万）按读数登记不作风险结论。

### 2.2 装载与撤稿位实测

经 `_gkxdb.py` 连 gkx、直连 dev 与久新（三源串行只读）。论文面 `ads_paper_profile` 4,000,000 行，`is_retracted` 实测 **0** 行（撤稿率万分比 0.0，派生键 `jiuxin_retraction_rate_per_10k`，分子分母同表全量）；`is_paratext` 同测 0 行（版面材料非风险信号，登记对照）。这一「位在值零」的解读须双面披露：MVP core 发布口径可能本身排除了撤稿论文（schema 口径：撤稿和 paratext 不进入有效论文总体），也可能撤稿标记未同步——**零事件不能直接读作零风险**，这是风险维数据调研的方法论要点（B4：负结论带探针——位在值零与位不在是两种不同的缺）。

### 2.3 三源风险词族排除

**gkx**：280 表 risk/integrity/misconduct/retract/fraud/compliance 六词族命中 7 张——逐表定性全部是企业侧：`dwd_org_risk_shixin`（失信 76,035 行）+ bak 2 张、`dwd_org_risk_tax_punish`（税务处罚）+ bak 1 张、`dwd_org_risk_zhixing`（被执行）+ bak 1 张——**人才侧无任何风险事件表**。**dev**：同六词族命中 30 张（gkxlumenx_dwd.risk_* 25 张 + enterprise_risk 2 张 + gkxlumenx_ods 3 张）——失信/破产/抵押/开庭/立案/公告/诉讼/被执行/行政处罚/股权冻结/司法拍卖全谱系，**全部企业主体**（多表带 _party 关联表），无人才侧。**久新**：203 表六词族 0 命中（`jiuxin_risk_like_tables=[]`）。三方共识：风险数据工程在库内有成熟范式（dev 30 表的企业风险全谱系），但主体全是企业——人才侧风险事件源是空白。

### 2.4 结构侧三件可用登记

其一，撤稿位：`ads_paper_profile.is_retracted` 列在（值零待回填）——成果有效性维的对齐键就是 paper_id/DOI，Retraction Watch CSV（R2）按 DOI 匹配即可回填。其二，合作史底料：`ads_talent_collaborator` 5,051,578 行（与 X_015 产物零漂移）——合作史强度/广度可算，但「冲突」（合作破裂/纠纷）事件无承载，代理语义弱（强合作史≠低冲突风险），只登记为代理底料不派生。其三，机构合作预留表：`ads_talent_institution_cooperation` schema 标注「预留」实测 **0 行**——B4 情形②（表在值空）的标准登记。其四，合规近邻维：capability 模型政治倾向维 weight=0.10、无数据统一 50 分（`jiuxin_political_orientation_model={'weight':0.1,'default_score':50.0}`），状态分布 99,996 行全 NO_DATA_DEFAULT_AVERAGE——保守默认分策略的库内工程先例。

### 2.5 稳健性与口径敏感性

三方面扣分制的敏感性定性：撤稿维惩罚对「单篇撤稿但高产的学者」应按撤稿率而非绝对数（否则高产者更易触雷）；诚信维若接 R1 清单，事件的时效衰减要定义（十年前的失信事件是否仍计满分惩罚）；合作风险维的代理（合作史强度）与真实冲突的相关性未证实——强合作网络的学者冲突暴露面反而更大（方向可能反）。政治倾向默认分策略的启示：99,996 行全默认说明该维实质无数据但模型未删维——风险维若照搬，UI 必须展示状态位（NO_DATA_DEFAULT）而非裸分，否则用户会把默认低风险读成实证低风险。这些敏感性全部登记给口径裁定方，本件不预设结论。

### 2.6 需求原文与 UI 演示值边界

需求三方面（合作风险/学术诚信/成果有效性）与 UI risks 四维枚举（合作/诚信/有效性/IP 合规）不完全一致——UI 多出 IP/合规维。mock 生成器 `data.js:1503-1511` 的 pick 枚举（riskLevel 五选一偏 green、risks 四维偏 low）暗示前端对风险分布的直觉假设（多数低风险+偶发红灯），但这是演示设计不是数据结论（B10 登记披露）。`ReportTab` 的 RISK_ICONS 渲染逻辑（green/yellow/red 三态灯）定义了 UI 侧的消费形态：等级枚举而非连续分——若数据侧产出连续风险分，需定义分段阈值（如 ≥80 绿/60-80 黄/<60 红），阈值口径同样待裁定。

## 四、数据缺失情况

### 4.1 人才侧风险事件面零承载（结构级，主因）

需求三方面的结构化事件数据在三源全部缺失：学术诚信（失信通报/调查记录）无表；合作冲突（纠纷/破裂/结题异常）无表；成果有效性（撤稿）位在值零。三源的现成风险数据全部是企业主体（gkx 失信/税务/执行 3 族、dev 30 表全谱系）——企业风险工程的成熟度反衬人才侧的空白。修复动作分三路：撤稿维接 Retraction Watch（R2，开放数据每日更新，DOI 对齐路径明确）；诚信维接科研失信处理通报的公开记录（R1 制度框架下的通报文本，需解析工程）；冲突维需立项自采（无现成公开源）。三路难度递增，撤稿维是唯一即期可动工的。

### 4.2 口径未立项（方法级，次因）

三方面的风险等级算式无定义：事件怎么分级（撤稿原因受控词表可分学术不端/出版方撤稿两档）、怎么加权、红灯阈值在哪——全部待裁定。UI 侧的消费形态（green/yellow/red 三态 + 四维 low/medium/high 枚举）给出输出契约的暗示（等级枚举而非连续分），但分段阈值仍需口径方定义。库内可援引的范式：政治倾向维的保守默认分（无事件=默认低风险+NO_DATA_DEFAULT 状态位展示）——这保证口径未闭合期间 UI 可以诚实展示「无数据」而非伪低风险。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| Retraction Watch 接入回填撤稿位 | 外部数据源 | 本件 + 005 质量分件 | 触发器①（DOI 对齐，增量同步） |
| 科研失信通报解析接入 | 外部数据源 | 本件诚信维 | R1 框架下的通报文本解析 |
| 合作冲突事件立项自采 | 数据立项 | 本件合作维 | 无公开源，需用人单位侧记录 |
| 甲方裁定双维口径（撤稿+合作史代理） | 口径裁定 | 本件升档 | 触发器③（诚信维降维披露） |
| 机构合作预留表灌数 | 上游回填 | 本件 + 族内合作件 | 上游已规划（预留标注在案） |

档位后果：撤稿源接入 → 成果有效性维转换可算（仍部分支持，诚信/冲突缺）；双维口径裁定 → **完全转换支持**；三维全接源+权重立项 → **完全直接支持**。推荐顺序：先接 Retraction Watch（开放源即期可动工），再裁双维口径，诚信/冲突源列远期。
