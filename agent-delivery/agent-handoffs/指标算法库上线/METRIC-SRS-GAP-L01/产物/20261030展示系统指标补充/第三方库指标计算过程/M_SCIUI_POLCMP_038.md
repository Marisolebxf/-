## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技政策跟踪/**政策分析评价**·人才画像（DS-11 政策/企业/人才三画像）·留用意愿指数。UI 容器是 `PortraitTrio.jsx`（三卡+Drawer 详情）：人才画像卡（`policyData.js:2218` 起）KPI 位是「留用意愿指数 78 分」（`:2224`，本件），点开 Drawer 后 detail.metrics 含「3 年留用率 68%」（`:2231`）等行为读数。组件行为：纯展示 mock，无后端取数。挂载形态说明 UI 语义层把「意愿指数」设计为画像卡的**头部综合分**——先于具体行为指标的综合评价位。

### 1.2 为什么需要本指标

人才留用是区域科技政策效果的终极检验之一：引进政策（补贴/住房/落户）的回报取决于人才是否留下。画像卡把留用意愿放 KPI 位，业务意图是给政策对比提供「人才粘性」的前瞻维——离职率是滞后指标（人已走），意愿是先行指标（还可干预）。这与 HR 调研体系的实践一致（中智/美世以意愿与离职倾向题项做组织健康预警），也解释了 mock 作者为何把意愿指数放在行为留用率之上。

### 1.3 需求文档是否给出定义方法

**需求文档未提及该指标定义方法。**「留用意愿」在三份需求真源 0 命中；最接近的「留用」出现在算法库 :934（深圳人才优势短板模型）：「……针对人才引进、培养、**留用**等环节的策略建议」——是策略环节语非指标定义。export 行自认「对某方面意愿或状态的量化评价（科技人才场景）——各维度怎么构成、权重怎么定，需要立项调研后才能确定」。

意愿测量两族先例：①**问卷直测系**（学界标准）：李克特量表留任意向题项（「未来 1-3 年打算留下」），组织行为学留任承诺量表（OCQ）族——需调查数据，三源无；②**行为代理系**（业界常用）：主动离职率逆指标（中智 2021：深圳 11.2%、高科技 11.4%、研发技术 7.9%）、高层次人才流动率（NSFC 杰青更换单位占比 14.94%）——久新 mobility 可算但语义是流动/留任率非意愿。两族都给不出意愿直测的三源路径。完整版见附录 C。

## 四、数据缺失情况

### 4.1 意愿直测面缺失（结构级+数据级，主因）

三源无任何人群态度/意愿承载（§3.3 三件留证）。这不是「数据没回填」而是「采集通道不存在」：意愿数据产生于问卷/调研/访谈流程，科技要素库、开发数据仓、久新分析仓的边界都不含此流程。与 POLCMP_008 同型（主观评价面双缺），且本件更远——008 至少有语义对位的空结构（`policy_public_opinion`），本件连空结构都语义错位。

### 4.2 行为代理面的换义禁令（B10）

久新 `ads_talent_mobility_event` 298,384 行是三源最丰富的邻接原料——若放宽语义可算「3 年留任率」类读数。但行为≠意愿：流动是意愿、机会、制度三因混合（家庭/薪酬/平台/政策都可能驱动同一流动事件），用行为逆推意愿是语义换轨。mock 作者的分列设计（:2224 意愿 78 分 ≠ :2231 留用率 68%）恰好佐证 UI 语义层也认为两者不可互替。处置：本件不采（负结论登记），行为代理另立指标路径在 §4.3 建议。
