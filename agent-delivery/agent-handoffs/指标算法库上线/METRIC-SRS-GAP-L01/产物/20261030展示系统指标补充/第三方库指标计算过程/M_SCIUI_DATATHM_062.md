## 摘要

「资源分布可视化」是主题视窗·主题库列表右侧的饼图卡：`ThemeWindow.jsx:534-536` `<Card title="资源分布可视化"><ReactECharts option={getThemeDistributionOption()}/></Card>`——七主题资源量环形饼图（基础科学 4,230/工程技术 3,890/医学健康 3,156/农业科技 2,845/能源环境 2,634/信息技术 2,456/材料科学 1,987，Σ=21,198）。数据侧判定分两层：**可视化本体零成本**（ECharts 展示层，任何分布对都能画饼——「可视化」三字不参与判档）；**分布对的承载**才是重量——主题归属面（资源→主题映射登记）三源无承载（dev topic_enterprise 21 表企业主题域语义排除/gkx 0/久新 theme 0，与 037/004「业务库边界无登记」同根），但久新 `ads_discipline_*` 四级学科域面（domain/subfield/field/topic）结构+数据双在——**近似承载存在而映射缺登记**（学科分类树→资源量计数的转换阻断）。判**部分支持**。本件核心披露：**mock 双源同值**（组件硬编码与 mockData 七对逐对复制，assert 防漂移）+ **分布Σ21,198 ≠ 总量 30,398**（差 9,200 归属未覆盖——mock 自身不闭合）。脚本已跑通（词族排除+学科域近似承载登记+双源同值 assert 落产物）。

- 需求判定：**UI 派生读数**（「资源分布可视化」字面 0 命中；主题视窗语境——分组键七类为 mock 自定）。
- 复现状态：脚本已跑通；词族排除 + 一处语义排除 + 学科域近似承载登记 + 双源同值 assert 全落产物。
- 档位结论：**部分支持**（归属面无承载 ⇒ 不可直查；学科域近似承载在 ⇒ 转换路径存在但缺映射登记）。
- 关键事实：**mock 双源同值复制** + **分布Σ21,198 ≠ 总量 30,398**（归属不闭合）——本件最重要的口径发现。
- 升档路径：主题归属面立项 → 完全直接支持；学科域→资源映射裁定 → 完全转换支持。

### 1.4 类似指标权威方法可行性分析概要

主题分布的权威方法分三层。其一，学科分类国标（R1 GB/T 13745-2009）：学科分类与代码——58 一级学科树形体系，资源按学科归类是科技资源统计的标准形态；其二，资源核心元数据国标（R2 GB/T 30523-2023）：科技资源核心元数据含学科分类属性——归属登记的元数据规范；其三，数据资产管理口径（R3 DAMA 资产目录）：资产按业务域/主题分组的目录树——归属面的工程形态。方法族对照：

| 方法族 | 原料 | 分布机制 | 与三源匹配 |
|---|---|---|---|
| 学科分类统计（R1） | 资源×学科归类 | 按学科树 GROUP BY | **无归属登记**（近似：久新学科域面） |

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

$$D(t) = \bigl|\{\, r : \text{theme}(r) = t \,\}\bigr|, \quad t \in T; \qquad \text{占比}(t) = D(t) \Big/ \textstyle\sum_{t' \in T} D(t')$$

其中 $\text{theme}(r)$ 为资源 r 的主题归属（归属面登记——三源无），$T$ 为主题枚举域（mock 七类——**与 GB/T 13745 学科体系的层级对应无登记**；久新 discipline 四级树可作底稿）。饼图占比由 ECharts 自动算（同基 Σ 内分割）。**口径三未裁**：主题枚举域（七类聚簇 vs 学科一级 58 类 vs 二级）、计数维（资源量·个）、覆盖范围（Σ21,198 vs 总量 30,398 的差 9,200 归属未覆盖）。**前提是主题归属面存在，三源实测无（§3.3）**——公式列示仅作口径锚（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①主题归属面立项（资源→主题映射登记，R2 元数据学科属性规范）→ `GROUP BY theme` 直查 → 升**完全直接支持**；②学科域→资源映射裁定（久新 discipline 四级为底稿+登记映射规则）→ 升**完全转换支持**（映射规则与主题枚举域须登记）；③维持现状 → 部分支持（UI 饼图建议空态或挂学科域近似分布）。

## 二、计算过程

### 2.1 口径裁定（B10 多口径并列）

本件读数「资源分布可视化」要求主题×资源量分布对，B10 并列登记两个承载路径：**口径 A（正式口径）**——资源→主题归属映射登记面 GROUP BY theme 计数；三源无归属面（§2.2），**不可得**，指标键 `resource_distribution_visualization = null` 留空。**口径 B（近似承载）**——久新 4 级学科分类面（ads_discipline_*）结构+数据双在，但「学科域→数据资源量」映射无登记（转换阻断件，`facts.jiuxin_discipline_note`），不转正。**mock 侧**双源分布对（Σ=21,198）只作 UI 需求证据（B10 不作数据源）。

### 2.2 排除实测：主题归属面三源逐一留证

判「无承载」前的三源探针（037 件先例+lane7 快照复用，B8）：**dev** 542 表——`gkxlumenx_topic_enterprise` 21 表（`facts.dev_topic_schema_table_count`）是企业主题域（粒度=企业主题非资源归属，`facts.dev_topic_schema_note`），语义排除；**gkx** 280 表 theme/subject 词族 0 命中（`facts.theme_registration_absence_note`——与 DATATHM_004 同根）；**久新** 210 张快照 theme 词族 0 命中（同 note）。三源结论：资源→主题归属登记面 0（语义级），口径 A 无从 GROUP BY。

## 四、数据缺失情况

### 4.1 主题归属面零承载（结构级，判定性缺口——最后一公里映射）

主题归属面三源零承载（§3.3）——与 037/004 同根（业务库边界/资产目录缺口族）。**本件的缺口形态**：分类树**在**（久新 discipline 四级面——R1 学科体系的库内承载）、资源**在**（三源表清单）、**「资源挂到树」的映射无**——最后一公里缺失。**四缺失情形归属「表不存在」**：修复动作是归属面立项（资源→主题映射登记表）；R2 GB/T 30523 核心元数据的学科分类属性可直接作登记规范底稿。本缺口与 037（库含表数）/004/065（类型分布的表级映射）共享资产目录基建——目录立项多件受益。

### 4.2 分布口径三未裁（口径级，即便建成也须先裁）

分布口径三无定义（§1.3/§1.6）：**主题枚举域**（mock 七类聚簇 vs GB/T 13745 一级 58 类 vs 二级——层级未裁）、**计数维**（资源量·个——表数/记录数未排除）、**覆盖范围**（部分覆盖 Σ21,198 vs 全量 30,398——mock 差 9,200 不闭合的正式版须先答「分布覆盖全体还是已归类子集」）。正式版须一纸裁定——此裁定与归属面立项解耦，可先行。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 主题归属面立项（资源→主题映射登记） | 数据工程立项 | 本件 + 037/004/065 + 资产目录族 | 触发器①（资产目录基建，多件受益） |

| UI 空态或学科域近似挂载 | 展示规范 | 本件 UI | 双源同值演示值建议撤下 |
