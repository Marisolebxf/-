## 摘要

「就业率变化（政策后较政策前）」是政策效果推演（Bid 标注的仿真指标组）的负结论件：UI 在 `policyData.js:711` 给它留了 pp 单位的槽位（baseline 0.8 / target 1.5，三情景 1.8/1.2/0.4 pp 均为前端演示常量），主需求在「区域经济发展空间模拟」段枚举了指标名（「包括GDP增长、产业结构变化、就业率变化等指标」）但无定义。就业率序列（劳动力调查/社保口径）与处理组界定（政策×企业名单）双双零承载：gkx 唯一大体量就业语义邻接面是 798 万行岗位发布表（需求侧非在岗侧）；dev 是其 1,000 行镜像；久新唯一 employment 列是学者 ORCID 履历计数。判**完全不支持**，升档路径是区域劳动力调查/社保序列 + 兑现台账双接入。

- 需求判定：指标名在主需求 1.1.1.1.4.2.3.1.3 被枚举（语境级出现，无定义方法）；核增需求与算法库 0 命中。
- 复现状态：负结论件无可算值；三源探针读数与代理面边界读数落产物。
- 档位结论：**完全不支持**（就业率序列 + 处理组双缺失）。
- 关键事实：`dwd_org_recruit_info` 798 万行是「企业想招多少人」不是「实际雇了多少人」——需求≠存量的量纲分界是本件最重要的排除证据。
- 升档路径：区域就业统计（劳动力调查/社保）+ 政策×企业台账接入 → 差分运算平凡，升完全转换支持。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技政策跟踪/**政策效果推演·空间模拟语境**/就业率变化。挂靠结构：`_phase3_screen_v3.json` 将其归入「多维政策对比」（l2），UI 实际挂载点是政策跟踪域共用的仿真指标结构 `simulationIndicators`（`policyData.js:708-712`）——注释明写「推演结果指标（Bid · GDP增长 / 产业结构变化 / 就业率变化 等）」：四个指标槽位依次为 GDP增长（%）、产业结构变化（%）、**就业率变化（pp，本件）**、空间协同指数（分，POLCMP_042 姊妹件）。它与 `simulationScenarios` 三情景（乐观/基准/保守，`results.employmentChange` 1.8/1.2/0.4 pp）联动，消费方 `simulation/sharedCharts.jsx:26` 引入后在 `:95`（雷达 indicator）、`:144-146`（对比条形 baseline/target）渲染——注意这套结构与 `policySimulationParams`（POLCMP_002/041 的五槽位组，`:1819-1836`）是**两个不同的仿真结构**：前者带 baseline/target 双值，后者只有 label/unit 槽位。

单位 'pp'（percentage point，百分点）是本件口径的关键线索：它声明自己是**差分读数**（后−前），不是增长率（%）——与指标名「政策后较政策前」的差分语义严格一致。

### 1.2 为什么需要本指标

政策效果推演的产出侧三问：经济贡献多大（GDP）、结构变化多少（产业）、民生改善多少（就业）。就业是三问中最具社会刚性的一个——稳就业是宏观调控的首要目标（官方语境「就业优先」），产业类政策的立项论证几乎都要回答「带动多少就业」。把就业率变化做成 pp 差分读数，供方案比选（A 方案就业带动强 vs B 方案 GDP 贡献大），是政策仿真记分卡的标准配置。这个读数的政务对应物是人社部门的城镇调查失业率/城镇新增就业序列（官方按月发布）。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**主需求《科技信息展示系统和科技专题服务系统.md》1.1.1.1.4.2.3.1.3（区域经济发展空间模拟）只枚举指标名：「系统模拟政策对该区域经济发展的影响，包括GDP增长、产业结构变化、就业率变化等指标，以热力图、三维地图等形式直观展示空间分布特征」——就业率怎么统计（调查失业率口径？就业人口/常住人口？企业用工口径？）、前后窗口怎么取（政策实施年±N 年？）、pp 还是 %，全部未给。核增需求《科技信息展示系统(政策对比功能升级)核增需求.md》17 叶与《科技专题服务算法库.md》均无「就业率」字样。

### 1.4 类似指标权威方法可行性分析概要

就业率（及失业率）的官方统计口径与政策前后评估方法有三族先例。其一，**调查失业率口径**（国家统计局劳动力调查制度）：月度全国城镇调查失业率（2021/2023/2024 年均值均 5.1%，2026 前三季度 5.2%），政策效果评估时官方明确「失业率受季节、毕业季、天气和外部冲击影响，不能简单按前后数值直接归因」（R1/R2/R3）——即权威口径本身就要求**控制组/季节调整**，不是裸差分。其二，**政策前后差分的准实验方法族**（DID 双重差分）：Y_it = α + βD_i + γT_t + δ(D_i×T_t) + ε_it，δ 即政策净效应，前提是平行趋势假设（R4/R5）——需要处理组×对照组×多期面板。其三，**稳就业政策效果的动作量化口径**（人社部）：城镇新增就业人数、稳岗返还户数与金额等过程指标（2024 年新增就业 1,256 万人、向 665 万户次企业发放稳岗资金 386 亿元，R6）——政务侧用「新增就业人数」而非「就业率变化」评估政策。

| 方法族 | 代表 | 就业数据源 | 与本库匹配 |
|---|---|---|---|
| 调查失业率 | 国家统计局劳动力调查（R1/R2/R3） | 月度住户调查 | **无（需统计局序列）** |
| DID 前后差分 | 准实验方法族（R4/R5） | 处理组×对照组面板 | **无（处理组与面板双缺）** |
| 新增就业过程量 | 人社部稳就业统计（R6） | 就业登记/稳岗台账 | **无（需政务台账）** |
| 岗位发布代理 | 本库唯一邻接面 | 招聘表 798 万行 | 有但**语义错位**（需求≠存量） |

三族权威口径的就业数据全部在政务/统计侧；本库招聘面只覆盖第四行（代理），而代理的量纲错误见 §2/§3.2。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（不可实现，仅登记语义）**：

$$\Delta\text{Emp}_{p} = \text{EmpRate}_{post(p)} - \text{EmpRate}_{pre(p)}$$

其中 EmpRate 是目标区域/群体在第 $p$ 项政策实施前窗口与后窗口的就业率（pp 为单位）。若按 DID 规范则应升级为 $\hat\delta$（处理组前后变化 − 对照组前后变化，R4），处理组 = 受政策影响企业群。**本件不写伪计算过程**（F4）——EmpRate 序列与处理组界定三源零承载（§3.3），岗位发布量差分冒充就业率会犯「需求≠存量」的量纲错误（§3.2 已定量登记反例读数）。

**降档/升档触发器**：接入区域劳动力调查/社保缴纳序列（EmpRate 闭合）+ 政策×企业兑现台账（处理组闭合）→ 可升**完全转换支持**（差分/DID 运算平凡）；若甲方接受「岗位发布量同比」作代理 → 语义已换（发布≠在岗），本件保守不接受；若采用全国调查失业率官方序列 → 需外接统计局数据源且粒度是全国月度非政策区域，单独立项。

### 3.2 代理面边界：两个定量反例读数

**岗位发布面**（`dwd_org_recruit_info`，20 万行采样，非全表）：年度发布条数 2026:32,689 / 2025:51,453 / 2024:37,183 / 2023:40,482 / 2022:38,193（`gkx_recruit_by_year_200k_sample`；三元组第三列为当年 `hiring_number` 非零行数：2026:4,160 / 2025:6,054 / 2024:7,957 / 2023:14,042 / 2022:5,169，合计 37,382）。若强行用「政策前后差分」的骨架套这个面，2025 vs 2024 的同比是 **+38.3778%**（派生键 `gkx_recruit_2025_yoy_pct_200k_sample`，14,270/37,183 同采样池）——这个数字精确、可复算、且方向看起来合理，但它度量的是「企业发布岗位的意愿变化」（需求侧，受宏观经济与季节影响），不是「在岗就业的变化」（存量侧）。把 +38.38% 展示为「就业率变化」会让用户读出「就业率上升了 38 个百分点」的荒谬结论——量纲（条数 vs 比率）与语义（需求 vs 存量）双重错位。同表 `hiring_number` 质量佐证需求侧属性：20 万采样中明确给出招聘人数的仅 37,382 行（18.7%），发布条数本身就是主信号。

**政策文本叙述面**：含「就业」的政策 1,576 行（占 20,000 的 7.88%，派生键 `gkx_policy_text_jiuye_share_pct`，同表同池）——政策文本谈就业（稳就业目标、带动就业预期）是政策意图声明，不是就业结果度量。

**在岗窄面**（`employees_number`）：3,170 行非零、648 家有 ≥2 年序列——这是本库唯一的真实「在岗人数」字段，但覆盖面极窄（90,926 行财务面中 3.5%）且与政策零关联（没有政策×企业关系可界定哪些企业的用工变化归因于政策）。它能支撑「企业用工规模」的个案研究，撑不起「政策前后就业率」的区域读数。

### 3.3 absence_probe 全记录（三源五件——本件核心证据）

**① gkx 就业率/社保/劳动力结果面**：`SHOW TABLES FROM gkx`（280 表）+ 正则扫 employ/hiring/recruit/job/labor/social/staff/salary/wage/unemploy → 命中 `dwd_org_recruit_info`（7,981,643 行，19 列全清单在产物 `gkx_recruit_cols`：job_title/job_description/release_date/hiring_number——全是岗位发布字段，无在岗/离职/失业字段）与 `dwd_job`（10 行，BioNTech/GSK 医学联络官岗位页测试数据，B4 情形③样例级）。四种缺失情形归属：**语义错位**（有大体量表但度量对象不同），修复动作是接入劳动力调查序列而非补招聘数据。**② gkx 政策×企业关联**：`dwd_policy_base` 33 列扫 enjoy/benefit/enterprise/org/company/employ → 0 列命中（`gkx_policy_enterprise_like_cols=[]`）——政策表连一个企业 ID 类列都没有，处理组零承载。**③ dev 就业面**：四 schema 扫同词典 → 仅 `gkxlumenx_dwd.enterprise_recruit`（1,000 行，12 列与 gkx 招聘表同构：enterprise_name/job_title/release_date/hiring_number）与 `gkxlumenx_ods.dwd_org_recruit_info`（同源镜像）；政策族兑现/执行类全 0 行（`dev_policy_family_rows`：policy_effect_eval=0、policy_simulation_result=0、enterprise_fund_project=0）。**④ 久新就业面**：203 表名扫 → 命中 4 张 collaboration 表（collaboration=合作非雇佣）；全表 DESC 列扫唯一 employment 命中 `ads_talent_yearly_location.orcid_employment_count`——实测分布 0 条:108,319 / 1 条:96,102 / 2 条:6,520 / 3 条:533 / 4 条:147（产物 `jiuxin_orcid_employment_dist`），即一半学者履历里一条雇佣记录都没有——这是 ORCID 履历完整度问题，与区域就业率无关。**⑤ 需求定义**：三份需求真源 rg「就业率」→ 主需求 1 处枚举（:1415），核增需求/算法库 0 处；无任何窗口/口径/处理组定义。

## 四、数据缺失情况

### 4.1 缺口清单（不可构建的根因）

| 缺失项 | 类型 | 对档位的影响 |
|---|---|---|
| 区域就业率序列（本体） | **数据源缺（三源零承载）** | **主判完全不支持根因①** |
| 处理组界定（政策×企业名单） | 数据源缺（族级缺口） | **主判完全不支持根因②** |
| 在岗用工覆盖 | 覆盖不足（3.5% 窄面） | 窄面代理不可外推 |
| 岗位发布面 | 语义错位（需求≠存量） | 代理被定量证伪（§3.2） |

两个主因独立成立：即便接入劳动力调查序列（闭合①），没有处理组界定就只能算「全区域就业率变化」而非「政策后较政策前」；即便接入兑现台账（闭合②），没有就业率序列也只能算「受惠企业用工变化」而非「就业率变化」。官方口径（R1-R3）还要求第三件——控制组/季节调整（否则「不能简单按前后数值直接归因」）——这属于方法层要求，在数据闭合后按 DID 规范（R4/R5）补齐。

### 4.2 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 接入区域劳动力调查/社保序列 | 外部数据源 | 本件（就业率闭合） | 统计局月度序列或社保缴纳面 |
| 接入政务兑现台账 | 外部数据源（族级） | 本件 + POLCMP_001/002/021/029/037/041 | 处理组闭合，族内七件受益 |
| 按 DID 规范补对照组 | 方法工程 | 本件 | 平行趋势检验 + 事件研究图（R4/R5） |
| 招聘面降级为辅助读数 | 产品决策 | 本件 | 「岗位发布量」单独成指标并改量纲标注 |

前两条是决定性的；第三条保证因果解释合规；第四条让 798 万行数据发挥正确语义的辅助价值。
