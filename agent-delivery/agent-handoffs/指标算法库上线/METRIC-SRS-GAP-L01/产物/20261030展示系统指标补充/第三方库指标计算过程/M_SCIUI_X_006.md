## 摘要

「技术创新空间分布」是需求明列叶（SRS seq 144：「基于专利数据的地域信息，分析技术创新力的空间分布特征，用户可查看热力图、区域排名」），UI 在科技创新评估页技术创新力指标展示下以「热力图+区域排名」双图落地，维度是深圳九区。三源探测揭示需求语义（专利×地域）与数据承载（企业×区级 / 集群×专利）的错位：专利与行政区在所有源都接不上——开发库专利明细三表空载，gkx 专利无省市列且 country 列是受理局维度，久新专利分析面只到机构归属国（覆盖率 1.93%）。本报告交付两条现转口径：口径 A 用开发库 `enterprise_base` 出深圳九区企业密度分布（宝安 25,192 家居首，Top1 占 26.36%、Top3 占 61.39%）；口径 B 用久新深圳产业集群表出 15 集群专利榜（未来健康 601,624 件居首，Top1 占 16.74%）。判**部分支持**：区级维与集群维各自现转可行，但「专利×区级」的需求语义本体三源无承载。

- 需求判定：**需求明列叶**（seq 144，excel_row 147）。
- 复现状态：脚本跑通；九区分布+热力值+15 集群榜落产物。
- 档位结论：**部分支持**（专利×区级链三段断）。
- 关键事实：gkx 293.99 万专利 55 列无省市列——「技术创新空间分布」的字面口径在最大专利源上结构性缺失。
- 升档路径：久新专利机构面解析覆盖率提升，或专利申请人→企业库（26.9 万家带区级）名称匹配链立项。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/科技创新评估/**技术创新力指标展示**/技术创新空间分布（1.1.1.1.4.1.7.2.6；SRS seq 144、excel_row 147）。UI 实现在 `TechInnovationEvaluationPage.tsx`：主 Tab「技术创新力」下六个子 Tab 的第 5 个（`:2963` `['spatial','技术创新空间分布']`），面板 `:3699-3705` 渲染双图——`spatialHeatmapOption`（九区×指数热力图，色带 42-99）与 `spatialOption`（横向条形区域排名）。数据源 `spatialRegionRows`（`:1508-1529`）以深圳九区（`SHENZHEN_DISTRICT_OPTIONS`）为行，value 由 `clamp(42..99, round((66+hashLift+selectedLift+positionLift)×volumeScale))` 生成——**纯演示值**（mock），不参与支持度结论。同页专利数量统计的 region 维（`:2144`）复用同一 rows（申请量=值×4.2，同为 mock）。

值得记录的 UI 细节：空间分布子 Tab 与「专利数量统计」（region 维）共用 `spatialRegionRows`，说明前端作者把「专利的区域分布」与「技术创新空间分布」视为同一数据面——这正是需求原文「基于专利数据的地域信息」的组件化表达。评估条件（`evaluationSnapshot.districtKeys`）可勾选区集，行集随之收缩——「区级」是本件的最小展示粒度，六行截断（`.slice(0,6)`）。

### 1.2 为什么需要本指标

空间分布回答「技术创新在哪里发生、集中度多高」：热力图给直观密度，区域排名给精确次序，两者共同支撑「地域集中度和外溢不足」的判断（UI 副标题原文）。在科技创新评估叙事里，它与专利数量（规模）、专利质量（成色）、市场潜力（商业化）并列，是技术创新力四维中唯一带地理属性的读数——决策者据此定位创新资源集聚区与洼地。

数据侧本件的难点在「专利」与「地域」的连接：专利的地理属性在数据世界有四种落法（受理局/申请人地址/发明人居住地/机构归属地），需求只说「专利数据的地域信息」没有指定哪一种（§1.3）。三源恰好四种落法各缺一角——这正是本件调研重心：把每条链路的断点定位到库、到列、到行数。

### 1.3 需求文档是否给出定义方法

**需求文档没给出可计算的口径。** SRS seq 144 给了数据源限定（「基于专利数据的地域信息」）与展示形态（「热力图、区域排名」「地域集中度和差异」），但「地域」的粒度（国/省/市/区）与归属轴（申请人地址/发明人居住地/受理局）未定义。需求主文档 `:905-907` 同文复述。UI 实现自行选择深圳九区+申请人侧语义——这是组件作者的口径假设，不是需求裁定。

### 1.4 类似指标权威方法可行性分析概要

专利空间分布的权威方法族分三支：OECD/WIPO 的**发明人居住国**口径（PCT 指南按发明人地址归属，多国发明人分数计数，最能代表创新发生地）；国知局年报的**省份双口径**（受理局口径+申请人地址口径，后者以工商注册地为准）；以及区域创新体系研究常用的**机构归属地**口径（专利权人注册地，与产业统计对齐最好）。方法族对照：

| 方法族 | 地域轴 | 数据要求 | 与本库匹配 |
|---|---|---|---|
| 发明人居住地（OECD/WIPO） | 发明人地址 | 专利表发明人地理列 | **无**（gkx 发明人列纯姓名无地址） |
| 申请人地址（国知局） | 第一申请人地址 | 专利表申请人省市列 | **无列**（gkx 55 列实查） |
| 机构归属地（RIS 族） | 专利权人注册地 | 专利权人→机构库→区级 | **断链**（久新 coverage 1.93%） |
| 企业密度代理（本件口径 A） | 企业注册区 | 企业库区级列 | **有**（26.9 万行，语义降级） |

结论：三条权威链路在本库全断，唯一现转是企业密度代理与集群维。完整版见附录 C。

## 二、计算过程

### 2.1 装载与规模校验

三源连接经统一入口（开发库 pymysql 直连新机、gkx 经 `_gkxdb.py`、久新 Doris 直连）。规模锚点：开发库 `enterprise_base` 269,511 行（脚本 assert 与探针 e-dev 对账零漂移）；gkx `dwd_patent` 2,939,895 行（共享快照 `dims.gkx[2]` 原值）；久新 `ads_sz_gkx_industry_cluster` 15 行全量。

### 2.2 区级维探测：企业库现成、专利链断

开发库 `enterprise_base` 六列区级语义（province/city/district/region_id/headquarters_city/headquarters_district），深圳市 95,600 家、九区全有数（宝安 25,192 / 龙岗 17,445 / 南山 16,039 / 龙华 13,879 / 福田 8,810 / 光明 6,879 / 罗湖 3,630 / 坪山 3,027 / 盐田 680）——区级维度本身结构+数据双达标。但专利侧：`enterprise_patent_detail` / `enterprise_patent_history` / `enterprise_chain_patent` 三表 0 行，`enterprise_patent_org_rel` 969 行纯 org↔patent 关系无任何计数列——「每区多少件专利」在开发库无承载。

### 2.3 gkx 专利地域列：结构缺失+数据单一化双证

`dwd_patent` 55 列逐一核对（探针 a 全列清单在案）：无 province/city/addr/region/district 任何列；唯二地域列 `country`/`country_code` 的 20 万行采样分布 Top5 全为 CN 单值（`gkx_patent_countrycode_sample_top5`）——受理局维度。另一条理论通路「申请人名解析省份」（如「广东省深圳市…」前缀）采样 2,000 行仅 21 行含省市级前缀（命中率约 1%，采样非全表）——绝大多数申请人名是纯企业名无地址串，解析不可行。

### 2.4 口径 A：区级企业密度分布（主读数）

九区计数+min-max 映射 42-99（对齐 UI 热力色标区间，纯展示层归一）：

```sql
SELECT district, COUNT(*) c FROM gkxlumenx_dwd.enterprise_base
WHERE city LIKE '%深圳%' AND district IS NOT NULL AND district!=''
GROUP BY district ORDER BY c DESC;
-- 宝安 25192 / 龙岗 17445 / 南山 16039 / 龙华 13879 / 福田 8810
--   光明 6879 / 罗湖 3630 / 坪山 3027 / 盐田 680
```

热力映射后宝安 99.0 / 龙岗 80.99 / 南山 77.72 / 龙华 72.69——与 UI mock 的「南山领先」叙事不同：真实企业库密度头名是宝安（制造业企业体量），南山（科技服务）第三。这一差异本身就是口径 A 语义降级的实证：企业注册密度 ≠ 技术创新产出密度。

### 2.5 口径 B：产业集群专利分布（对照面）

久新 `ads_sz_gkx_industry_cluster`（15 集群，深圳战新+未来产业口径，2026-10-27 版）：专利数 Top5 = 未来健康 601,624 / 生物产业 591,801 / 新一代信息技术 438,713 / 智能网联新能源汽车 387,910 / 数字经济 377,312（全榜见产物 `jiuxin_sz_clusters`）。集群是产业维度非行政区维度，但它是三源唯一「现成专利计数×深圳语义」的面——作为「技术创新的空间格局（产业视角）」对照交付。

### 2.6 集中度读数（B3 同基）

三比分子分母同表同源：Top1 区占深圳企业 26.36%（25,192/95,600）、Top3 区占 61.39%（58,676/95,600）——空间集中度「过半在三区」的结构性判断成立；Top1 集群占 15 集群专利 16.74%（601,624/3,593,207）——产业维分布比行政区维均衡。两个集中度并列，恰好展示「空间分布」在两种维度下的不同形态。

## 四、数据缺失情况

### 4.1 专利×区级链（结构级，主因）

需求的字面口径「专利数据的地域信息」在区级粒度上三源无承载：开发库专利明细空载（三表 0 行）；gkx 专利无省市列（唯一理论通路申请人名解析实测 1% 命中不可行）；久新专利面只到机构归属国。四情形归属「列不存在/表空载」混合——修复不是补数据而是建链路（专利→企业→区级匹配工程）。

### 4.2 语义降级（口径 A 的内生缺口）

即便口径 A 即期回填，其语义是主体密度非产出密度——「技术创新空间分布」被替换为「创新主体空间分布」。这一降级不可通过数据工程消除，只能通过口径 C（匹配链）或需求侧改写闭合。UI 若直接回填，须在图题/tooltip 加「按企业注册密度」限定语。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 口径 A 即期回填（带限定语） | 产品决策 | 本件即期可交付 | 九区密度榜+热力 |
| 久新深圳集群表接入 | 数据接入 | 本件+SZINNOV 族 | 集群维对照面 |
| 专利→企业匹配链立项 | 数据工程 | 本件+INNOV_001/011 | 申请人名×enterprise_base 名称对齐 |
| 久新 resolution 覆盖率提升 | 供应商协同 | 全专利区域族 | coverage 1.93%→提升后归属国维可用 |

档位后果：口径 A 交付 → 仍部分支持（语义披露）；匹配链建成 → 可升完全转换支持。
