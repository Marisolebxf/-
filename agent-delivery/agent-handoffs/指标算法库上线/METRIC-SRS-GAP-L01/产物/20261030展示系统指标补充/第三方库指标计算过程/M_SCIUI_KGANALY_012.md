## 摘要

「分析洞察」是图查询资产深入分析抽屉（Drawer）的收尾卡片：对选中资产输出三条洞察——核心发现（领域内桥接节点数+建议）、关联提示（标签×场景）、数据说明（来源+Mock 披露）。UI 现状是纯前端生成：`buildDeepAnalysis` 用 hashSeed 种子随机数造出节点/边/密度/桥接/社群/跨域占比六参数，灌进三条固定文案模板（asset-001 实测：桥接 7/社群 5/跨域 34%——与真图无对应关系）。数据侧判定：**部分支持**——本件把「洞察」拆成数值参数层与生成链层：参数层三指标在久新真图 5000 节点框（38,383 边）内全部实算在案（桥接节点 3,973=跨社区边 13,132 条端点去重、社群数 460=community_id 去重、跨社区边占比 34.21%）；生成链层的断点是**资产登记面缺失**——UI 六条资产（AI 产学研合作子图等）在三源均无 DB 面，「按资产生成洞察」的分析对象不可寻址，洞察文本也无落盘面（UI 自注「正式环境由图分析服务返回」，该服务三源未见）。

- 需求判定：**需求明列叶**（seq 447 图表详情与预览——深入分析能力位），指标语义=资产级洞察输出。
- 复现状态：脚本已跑通；真图实算三参数+UI 生成器移植复现（asset-001 同值）全落产物。
- 档位结论：**部分支持**（数值参数可实算、资产实体链断裂——探针两件在案）。
- 关键事实：UI 模板的「跨域边占比 18-42%」演示区间恰与真图跨社区边占比 34.21% 同量级——但这是巧合非对齐：真图「多关系类型复合边」实测 0 条（占比 0.0%），两种「跨域」口径已分开披露（B10）。
- 升档路径：资产登记面立项（资产→子图定义/查询参数映射）→ 参数层实算即可挂资产粒度输出，升完全转换支持。

### 1.2 为什么需要本指标

「深入分析」抽屉的用户意图是**决策辅助**而非看数：KPI 和图表回答「这个资产长什么样」，洞察回答「所以我该做什么」——核心发现给行动建议（优先关注跨机构合作边）、关联提示给复用方向（标签相关子结构可用于某场景）、数据说明给可信度边界（来源+Mock 披露）。这是 seq 447「初步判断图表内容的价值和适用性，决定是否深入分析或使用」的直接落点：洞察文本是资产价值判断的浓缩输出。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**seq 447 只给行为（「点击具体的查询结果后，弹出详细页面，展示图表的完整结构、数据来源、分析流程、关联标签、使用场景说明等详细信息」），「分析洞察」的输出结构（三条式：发现/提示/说明）与参数（桥接节点/社群数/跨域边占比）由 UI 生成器闭合。定义侧的开放点在两个无 UI 定义的术语（桥接节点/跨域边）——本件按图分析标准口径落点并披露（§2.2/B10）。

### 1.4 类似指标权威方法可行性分析概要

图分析洞察生成有工业范式。其一，图分析平台标准（R1 Neo4j Graph Data Science）：桥接节点分析对应 betweenness/社区桥接度量，社区计数对应 Louvain/Label Propagation；其二，网络科学权威（R2 Newman《Networks》）：跨社区边占比是社区结构强度的标准度量（modularity 相关）；其三，BI 洞察生成范式（R3 Microsoft Power BI insights）：模板化洞察=数据特征×文案模板。方法族对照：

| 方法族 | 代表 | 本库承载 | 贴合度 |
|---|---|---|---|
| 桥接/社区度量（R1/R2） | Neo4j GDS / Newman | **久新真图可算**（本件已实算） | 参数层贴合 |
| 模板化洞察（R3） | Power BI insights | UI 已有模板；缺资产寻址层 | 生成链缺实体面 |

结论：数值参数方法成熟且久新真图已实算；「洞察」作为产品形态的断点不在算法在**资产实体面**——这是登记面立项问题，非算法问题。

## 二、计算过程

### 2.1 计算对象与输入

- **对象**：久新真图 `ads_technology_graph_node`（19,430 节点，含 community_id）/`ads_technology_graph_edge`（587,252 边，含 relation_type）。
- **采样框**：ORDER BY technology_node_id LIMIT 5000（001 同款确定性框）→ 框内诱导边 38,383 条（`WHERE source IN 框 AND target IN 框`）。
- **UI 复现输入**：asset-001（AI 产学研合作子图，field=人工智能，tags=[合作网络,产学研,项目]，scenario=风险核查单 URL 跳转预览，source=ADS_KG_SUBGRAPH）。

### 2.2 计算公式与关键参数

1. **桥接节点数**：B = |{n : ∃(n,m)∈E_框, comm(n)≠comm(m)}|——跨社区边端点去重（图分析桥接口径落点：删之则跨社区连通受损；UI 无定义，本件口径落点披露 B10）。
2. **社群数**：C = |{comm(n) : n∈框}|——社区标注去重（直读图库，非算法重算——重算口径见 2.6 边界披露）。
3. **跨域边占比**（两口径分披）：
   - 口径 A（社区域）：cross_comm_edges/|E_框|（UI「跨域」语义的最近似——社区即域划分）；
   - 口径 B（关系类型域）：多 relation_type 复合边/|E_框|（「跨域=多种关系叠加」口径，真图实测 0——单一类型边占绝对主导）。
4. **UI 生成器移植**：hashSeed（h=h*31+charCode 滚动，>>>0 截 32 位）→ seededInt(seed,min,max)=floor(min+n*(max-min+1))，n=(hash%1000)/1000——Python 端口与 JS 逐值一致（确定性）。

### 2.3 计算步骤（脚本流水）

步骤：①连久新拉 5000 节点框+框内诱导边（含 relation_type）+框内节点 community_id → ②按公式 1 扫边统计跨社区边与端点 → ③按公式 2 community_id 去重 → ④按公式 3 两口径分别统计 → ⑤UI 生成器移植跑 asset-001 → ⑥落盘。全程只读。

### 2.4 计算结果

| 参数 | UI 模拟（asset-001） | 真图实算（5000 框） | 说明 |
|---|---|---|---|
| 桥接节点数 | 7 | **3,973** | 真图=跨社区边 13,132 条端点去重 |
| 社群数 | 5 | **460** | 真图=community_id 去重（Top3 社区 1,046/960/921 节点） |
| 跨域边占比 | 34% | **34.21%**（口径 A）/ 0.0%（口径 B） | 口径 A 跨社区边占比；口径 B 多类型复合边 0 条 |
| 节点/边（参照） | 61/176 | 5,000/38,383 | UI 资产级 vs 真图域级框 |

洞察文本复现（asset-001，灌实算参数即得域级洞察示例）：「在『人工智能』领域识别 3,973 个桥接节点，建议优先关注跨机构合作边。」——注意域级框桥接数远大于 UI 演示区间（2-9），因 UI 参数是资产子图级（几十节点）而真图框是域级（5000 节点）——量纲差异披露（B9）。

### 2.5 结果解读与业务含义

真图框的社区结构高度碎片化（460 社区/5000 节点，平均社区仅 ~11 节点）且跨社区边占 1/3（34.21%）——技术知识图谱的技术社区呈「小而互联」形态，桥接节点（3,973 个，79.5% 的框内节点沾跨社区边）是跨域技术转移的通道候选。这与 UI 洞察模板的运营建议（「优先关注跨机构合作边」）在真图上成立：跨社区边就是模板所指的跨域合作边实体。

### 2.6 边界与不确定性披露

- **采样框边界**：5000/19,430 节点（25.7%），框内诱导边 38,383/587,252（6.5%）——桥接/占比均为框内口径，全图值未算（框外边不计入，跨社区边占比可能因框切割而低估——边界效应披露）。
- **社区口径**：社群数直读图库 community_id 标注（非本件重算）——标注算法/版本久新侧未披露；若需算法重算（Louvain/LPA），同框可跑但结果可能与标注不一致。
- **桥接口径**：跨社区边端点是「社区桥」的宽松口径（非 cut vertex/brandes betweenness 严格口径）——严格口径全图代价高（028 族披露），本件取宽松口径并披露。
- **「跨域」双口径**：UI 无定义，A（社区域 34.21%）/B（关系类型域 0.0%）分披——正文引用均注明口径。

## 四、数据缺失情况

### 4.1 资产登记面缺失（生成链断点，主因）

「分析洞察」是资产粒度输出，资产实体（graphQueryAssets 六条所示：AI 产学研合作子图/量子计算技术演进报告/…）在 dev/gkx/久新均无登记面（`absence_probe[0]`）——分析对象不可寻址：不知「量子计算技术演进报告」对应哪个子图/查询，参数实算无从挂载。修复路径：**资产登记面立项**（资产→子图定义/查询参数映射落 DB）——新面工程，非现有库表转换。落盘面（D4）同理：洞察结果三源无落盘，图分析服务（UI 自注「正式环境由图分析服务返回」）未见立项。

### 4.2 缺失对指标的影响

参数层无缺失（久新真图结构+数据均足，本件已实算）；断链使「按资产生成洞察」降级为「按域生成洞察」（可用但语义降级——UI 是资产粒度文案）。同抽屉其他卡片（KPI/结构指标表）共享此断点：数值参数可算（本件三参数+006 度数族），资产粒度挂载缺登记面——抽屉整体判档跟随本件部分支持。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 资产登记面立项 | **新面** | 本件 + 同抽屉卡片（KPI/结构指标） | 资产→子图/查询映射，升完全转换支持 |
| 图分析服务立项（洞察落盘） | 新服务 | 本件 | 直查洞察面（升完全直接支持） |
| 域级洞察先行 | 现状可用 | 本件 | 本件脚本（参数+模板）即域级雏形 |

档位后果：资产面 → 完全转换支持；+洞察落盘 → 完全直接支持；现状 → 部分支持（域级可用）。
