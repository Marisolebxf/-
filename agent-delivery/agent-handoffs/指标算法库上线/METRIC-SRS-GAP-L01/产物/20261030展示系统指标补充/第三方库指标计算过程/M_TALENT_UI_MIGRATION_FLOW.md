### 1.2 为什么需要本指标

分布与占比读数都是存量截面，唯有迁徙读数给出人才池的**流向**：流入热点指示争夺机会（哪里的人正在汇聚），流出风险提示本地人才流失（哪里正在失血）。需求例句"近年 AI 人才从硅谷流向新加坡"就是典型用法——它是引才策略时效性最强的一个读数，页面按年份切片也正是为了支持"近年"这个时间语感。

迁徙读数还有两个衍生产值点：其一，流动对榜（"从 A 到 B 有 N 人"）直接就是引才目标的候选清单——流出地是搜索池，流入地是竞争参照；其二，年度桶序列与政策事件的时间对齐（如人才新政发布年是否出现流入抬升）是政策效果评估的天然实验素材。这两个衍生场景都不需要新的口径，只需要本件的事件表按不同维度聚合，产物的 `transitions_by_year` 与（待扩盘的）国别差分就是它们的直接原料。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**SRS seq 252 给出的是展示行为（动画、高亮），未定义什么是"一次迁徙"（换机构算？跨国算？离职再入职算？）、净流入的分母与时间窗。主需求文档「迁徙人次」「净流入」均 0 命中。UI mock（`data.js:140-167`）以年度 growth 系数伪造总量曲线、用 ±0.015–0.06 的随机数伪造净流入——前端作者完全没有定义口径，只是画了一条像样的曲线。

### 1.4 类似指标权威方法可行性分析概要

国际权威口径有两支。其一，OECD International Migration Database 发布年度 migration flows/stocks 序列（R4），以"跨国常住变更"为事件、以行政登记为源；其二，OECD DIOC 以出生国×目的国的存量普查推 emigration rates by skill level（R3），粒度是五年一轮的存量差分。两支都以"跨国常住地变更"为迁徙事件本体。本库的对应物是履历变更（机构级事件）+ 机构国别（事件的方向标签），事件粒度定义一致，但国家标签覆盖只有四成。国内口径方面，教育部留学统计（R1/R2）以"出入境+认证"计回国人流，是国家级年流的另一权威源，但库内无逐人记录可对齐。完整版见附录 C。

### 1.6 推测原意与推测定义

**推测定义（非甲方闭合口径）**：

- **迁徙事件**：同一学者按 `start_time` 排序的相邻两段履历，机构名不同 → 记 1 次迁徙；
- **迁徙人次（年 $y$）**：$\text{mig}_y = |\{ \text{事件} : \text{event\_year} = y \}|$，事件年取新履历的 start_time 年份；
- **净流入（国家 $c$，年 $y$）**：$\text{net}_c^y = \text{in}_c^y - \text{out}_c^y$，入/出按事件前后机构的国别差分；
- **机构级 vs 国家级**：机构级迁徙不需要国别标签，全量可得；国家级净流入（UI 热点卡语义）只在有国别标签的子盘上可算。

**降档/升档触发器（B10 模板）**：若甲方确认"迁徙"仅指机构级流动（不要求国别）→ 整件可升「完全转换支持」（机构级数据量足且已跑通）；若甲方要求国家级净流入 → 维持部分支持直至机构主数据补齐。

## 二、计算过程

### 2.1 装载与规模校验

经 `_gkxdb.py` 连接 gkx 只读库。履历表 `dwd_scholar_work_experience` 实测 57,117 行，与共享快照及 20261021 轮库存零漂移。三项基本面：`start_time` 非空 57,117（100%）；`is_current = 1` 的在任段 21,515；履历覆盖去重学者 20,028（主档 21,316 的 93.95%）。多人多段是迁徙事件的前提：`GROUP BY scholar_id HAVING COUNT(*) >= 2` 得 **12,427 名学者**（58.30%）至少有两段履历——即近六成学者具备产生迁徙事件的履历深度，样本面充足。

### 2.2 迁徙事件推导（机构级）

全量 57,117 段按 `scholar_id, start_time` 排序后在 Python 侧做相邻对差分：同一学者的相邻两段，`org_name_en` 去首尾空格后不等即记一次机构变迁。结果：相邻对 37,089 对，其中跨机构变迁 **27,805 次**（75.0%）。75% 这个比例本身就说明该学者池流动性极高——采集源（以高校官网学者页为主）天然偏向"换过机构"的学者，正文按事实披露，不做流动性推断。

```python
# 全量拉取（57,117 段，Python 侧排序差分无性能压力）
cur.execute("SELECT we.scholar_id, we.start_time, we.org_name_en "
            "FROM gkx.dwd_scholar_work_experience we "
            "WHERE we.start_time IS NOT NULL "
            "ORDER BY we.scholar_id, we.start_time")
rows = cur.fetchall()

events = cross_org = 0
prev = None
for sid, st, org in rows:
    if prev is not None and prev[0] == sid:
        if org and prev[2] and org.strip() != prev[2].strip():
            cross_org += 1          # 迁徙事件
        events += 1                 # 相邻对
    prev = (sid, st, org)
# → events=37089 ; cross_org=27805（75.0%）
```

`strip()` 是必要的：实测存在尾随空格的机构名，不 strip 会把纯空白差异误判为迁徙（个位数级，但确定性纪律要求消除）。

### 2.3 年度桶与时间解析陷阱

`start_time` 实测为**字符串**而非 DATE：样例 `'2017.04'`、`'2020'`、`'2018.01'`——精度混合年与年月。年度桶按"前 4 位数字解析年份"（解析函数做 1900–2100 合法性校验，无法解析的行不计桶、不影响事件总数）。解析后年度序列 2015–2024 完整连续：2022 年 1,597 / 2019 年 1,583 / 2018 年 1,500 / 2021 年 1,482 / 2023 年 1,445 / 2020 年 1,433 / 2017 年 1,370 / 2016 年 1,287 / 2015 年 1,130 / 2024 年 1,114。曲线形态：2015 年起持续爬升、2019–2022 高位平台、2023–2024 回落——回落段须警惕"履历采集滞后"（最新任职尚未回填），2024 年读数在产物 notes 标注为**下界**。

```python
def parse_year(v):
    # 实测形态：'2017.04' / '2020' / '2018.01'（字符串，非 DATE）
    s = str(v).strip()
    for head in s.replace("–", ".").replace("-", ".").split("."):
        if head.isdigit() and 1900 <= int(head) <= 2100:
            return int(head)
    digits = "".join(ch for ch in s if ch.isdigit())[:4]
    return int(digits) if digits.isdigit() and 1900 <= int(digits) <= 2100 else None

# → transitions_by_year Top5:
#   2022:1597 / 2019:1583 / 2018:1500 / 2021:1482 / 2023:1445
```

### 2.4 国家维：从机构级到国家级的折损

跨国净流入要求事件的两侧机构都有国别标签。以大学表 `country` 精确等值 JOIN 实测：可标签履历 23,175 段，占全量 57,117 的 **40.5746%**。折损来源与 `M_TALENT_UI_GLOBAL_STOCK` §2.4 完全一致（企业/研究院所履历无国家编码 + 大学表仅 20,000 行高校），两件共享同一缺口登记。在子盘内，事件的 in/out 国别差分即可产出 $\text{net}_c^y$ 序列——SQL 已在脚本中验证可行（同链路同 JOIN），产物给出的是可标签面的事实与覆盖比，子盘净流入表留待主数据工程后一键展开。

```sql
SELECT COUNT(*) FROM (
  SELECT we.id
  FROM gkx.dwd_scholar_work_experience we
  JOIN gkx.dwd_forg_university_org_info u
    ON CONVERT(u.name_std USING utf8mb4) COLLATE utf8mb4_general_ci
       = CONVERT(we.org_name_en USING utf8mb4) COLLATE utf8mb4_general_ci
  WHERE we.start_time IS NOT NULL
    AND u.country IS NOT NULL AND u.country != ''
) t;
-- → 23175（40.5746% of 57117）
```

### 2.5 稳健性与口径敏感性

三组敏感性测试。其一，事件判定的空白容差：机构名先做 `strip()` 再比较，若不 strip 会把纯空格差异误判为迁徙——实测影响个位数事件，已修正。其二，年度口径：按新履历 start_time 计事件年；若按旧履历 end_time 计（离职口径），2024 年读数会更高（离职登记通常晚于到任回填），两口径差已在 notes 披露。其三，多人同年多跳：同一学者同年多次换机构的场景存在但稀少，事件计数按"次"不按"人"，与 UI"迁徙人次"语义一致（人次=事件数）。曲线对 growth 系数的敏感性问题不存在于真实口径（mock 才有），正式版删除随机缩放后曲线即为库内实数。

### 2.6 与 UI mock 的对照及展示口径

UI mock 时序图把"人才总量"（数万级假值）与"迁徙人次"（千级）画在同一坐标，读数完全失真；真实口径下两者量级为 21,316（存量）vs 年迁徙 1,100–1,600（流量），双轴图可行且形态合理。流入热点/流出风险卡在真实口径下建议：v1 只做机构级 Top 流动对（"从清华到 MIT：N 人"式表述，全量可得），v2 待国家标签补齐后升级为国别净流入榜（需求原文的"硅谷→新加坡"叙事属国家级）。页面年份切片与真实年度桶直接对齐，无改造。

### 3.2 D1 履历事件面：机构级迁徙的全量承载

57,117 段履历覆盖 20,028 名学者（93.95% 主档），其中 12,427 人（58.30%）至少两段履历——这是迁徙事件的样本面。事件推导在同一学者的相邻履历对上做机构名差分：37,089 对相邻段中跨机构变迁 27,805 次（75.0%）。75% 的高流动率首先要归因于采集选择偏差：以高校官网学者页为源的采集天然偏好"履历漂亮的学者"，一路平步青云的学者反而不多见。这个偏差不阻止事件计算，但"全球人才流动率"的外推解读必须带上它。

### 3.3 D2 时间维：字符串年份的解析纪律

`start_time` 全部 57,117 行非空，但类型是字符串，实测形态 `'2017.04'` / `'2020'` / `'2018.01'`——年与年月混合精度。解析规则：取点分段后首个 1900–2100 合法四位数；兜底取前 4 位数字。解析失败（无合法年份）的行不计入年度桶，事件总数不受影响。年度桶 2015–2024 十年连续：2022 年 1,597 / 2019 年 1,583 / 2018 年 1,500 / 2021 年 1,482 / 2023 年 1,445 / 2020 年 1,433 / 2017 年 1,370 / 2016 年 1,287 / 2015 年 1,130 / 2024 年 1,114。2023–2024 的回落要警惕采集滞后（最新任职未回填），2024 年读数标注为下界。

### 3.4 D3 国家标签：从机构级到国家级的折损

跨国净流入要求事件前后两个机构都有国别标签。大学表 `country` 精确等值 JOIN 实测：可标签履历 23,175 段，占全量 40.5746%。折损构成与 `M_TALENT_UI_GLOBAL_STOCK` §3.4 完全同源——非高校机构无国家编码、大学表仅 20,000 行高校。也就是说，四成的国家标签几乎全部来自高校间的流动，企业间、校企间、海外企业侧的流动在国家维不可见。这决定了 UI"流入热点/流出风险"卡的 v1 版本只能在子盘上交付，且必须标注"基于高校履历子盘"。

### 3.5 流出判定的结构盲区

履历表 `end_time` 存在但大量空值/在任状态（is_current=1 的 21,515 段语义上没有流出事件），"离开某机构"的时点只能以"下一段履历的 start_time"近似。最后一段履历（在任）没有后续段，天然无流出——这是履历差分法的结构性盲区：近期离职但未更新履历的学者会被记为"仍在任"，流出规模被低估。对照 OECD 的行政登记口径（R4：以登记变更为准），履历法的滞后性是方法内生的，正文与 UI 均按"以到任事件计"的口径表述。

## 四、数据缺失情况

### 4.1 国家标签覆盖缺口（主因，决定国家级档位）

履历国家标签 40.5746%——23,175 段可标签、33,942 段不可标签。缺口构成与修复路径同 `M_TALENT_UI_GLOBAL_STOCK` §4.1（非高校机构地理编码工程），两件共享同一缺口台账，不重复立项。对 UI 的直接影响：流入热点/流出风险卡的 v1 只能基于高校子盘，"硅谷→新加坡"这类企业侧流动叙事（需求原句）在子盘内天然缺席——硅谷的企业人才恰是高校表覆盖不到的主体。

### 4.2 流出时点的结构盲区（方法内生）

履历差分以"下一段到任"近似"上一段离职"，最后一段在任履历无流出事件：21,515 段在任履历语义上没有流 出记录。这导致两个偏差：其一，流出总量被低估（离职未更新履历的学者计为在任）；其二，流出时点滞后（实际离职与下一段到任之间可能有 gap 期）。OECD 行政登记口径（R4）以登记变更为准，无此盲区；履历法是该盲区的内生代价，只能披露不能消除。缓解：end_time 非空的行可做"离职口径"交叉验证（本件未做，登记为扩展）。

### 4.3 时间精度混合（年度桶无碍、流向判定受限）

start_time 年/年月混合精度（'2020' vs '2017.04'）：年度桶按年份归并无影响；但同年多段履历的先后排序在月精度缺失时只能按字典序破平局（B5 确定性纪律），个别"同年双跳"事件的流向判定存在顺序歧义。实测同年多跳事件占比极小（<1%），不影响年度桶与 Top 流动对榜；若未来做路径动画（需求原文的动画叙事），须先治理 month 精度。

### 4.4 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 非高校机构地理编码 | 主数据工程（同 GLOBAL_STOCK） | 本件国家级面 | 40.57% → 目标 80%+ |
| end_time 回填治理 | 数据源治理 | 流出时点精度 | 减少盲区 |
| 机构级 v1 先行 | 产品决策 | 即期交付 | Top 流动对榜全量可得 |

与 CHINESE_RATIO 的口径 B 一样，机构级 v1 是即期可交付项：Top 流动对（"从 A 机构到 B 机构 N 人"）全量可得且无覆盖折扣，建议作为 UI 迁徙 Tab 的首个正式读数。

本件的档位切分是批内最清晰的：同一个数据面（履历）支撑两个粒度（机构级/国家级），粒度不同、档位不同。机构级三条件全齐（完全转换支持），国家级卡在标签覆盖（部分支持）。若甲方在验收时确认"迁徙=人才在机构间的流动"（机构级语义），整件即刻升档——这个触发器比数据工程更快，也是验收时最可能发生的情形。
