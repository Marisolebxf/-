## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/技术发展跟踪（下游页面：科技发展规划）。挂载点是 `TechDevelopmentPlan.tsx:1961` 的指标雷达（ECharts radar）：indicator 数组给出六个维度名——技术发展/产业规模/**机构数量**/人才储备/成果产出/创新能力，深圳序列 [92,85,88,90,86,89]、全球平均 [78,82,75,80,77,79]。雷达维度是 0–100 相对分（mock），「机构数量」作为维度名把「机构的多寡」纳入六维画像之一。

雷达语义值得展开：它不要求绝对计数，要求的是「深圳 vs 全球平均」的相对差。但相对分的分母必须是真实计数——mock 直接写 88/75 两个常数，正式版要回填时，路径只能是把机构计数做归一化（如 log 缩放或分位映射）后进雷达。本件按「机构计数 + 可归一化」两层语义判档：计数层直查即得，归一层是展示端加工。

### 1.2 为什么需要本指标

机构是创新活动的组织载体：论文挂在机构、专利申请人是机构、项目由机构承担。六维雷达里「机构数量」回答的是「这个区域/领域有多少组织在参与创新」——它是产业规模的 proxy（机构多→生态厚），也是资源配置的瞄准镜（机构少→需要引育）。政府侧用户看雷达第一眼问的往往是「深圳的机构维为什么高/低」，这要求背后的计数可解释、可下钻。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** SRS《技术发展跟踪》8 叶无「机构数量」字样（最近叶 seq 49 地理分布图展示为功能级描述）；《科技信息展示系统和科技专题服务系统.md》rg 检索「机构数量」命中的 4 处全部在科技专题服务系统章节（服务链机构统计、新增服务机构统计等语境），非本系统雷达维度语境。计数口径（什么算机构？含不含企业？含不含医院？）无任何定义。

### 1.4 类似指标权威方法可行性分析概要

官方「机构数」口径有明确先例：《中国科技统计年鉴》「研究与开发机构基本情况」表的「机构数」口径为**地级及以上独立核算的政府属科学研究与技术开发机构、科技信息和文献机构**（2023 年 2,890 个，R1/R2）——即官方口径本身就是一个「类型筛选后的子集计数」，不是全量底册。OECD 侧无「机构总数」官方指标，但 Frascati 手册的机构部门分类（企业/政府/高校/私人非营利）是类型维的方法基准（R3）。方法族对照：

| 方法族 | 计数口径 | 与本库匹配 |
|---|---|---|
| 官方 R&D 机构口径（年鉴） | 政府属科研发机构子集 | **中**（需按类型筛选，久新类型维可筛） |
| 全量底册口径 | 收录池全量 | 高（83,745 直查） |
| 部门分类口径（Frascati） | 按执行部门分列 | 高（类型码表即部门近似） |

结论：库内可同时支持「全量」与「类型子集」两种口径，官方口径倾向后者。完整版见附录 C。

## 二、计算过程

### 2.1 方法选择（文献依据）

采用「底册切片计数」方法：机构数量 = 底册按 scope 的 COUNT(*)。类型子集口径对齐《中国科技统计年鉴》「机构数」的类型筛选先例（R1：官方口径=政府属科研机构子集 2,890 个，非全量）；类型维本身采用久新 `ads_institution_type` 码表（OpenAlex 机构类型体系，10 类，含中文映射与定义文案——每类带 `https://openalex.org/institution-types/*` 来源链接，是自带出处的分类标准）。选择理由：底册+码表双表直查即得，且类型定义可溯源，满足「完全直接支持」零加工要求。

### 2.2 开发库探测：无机构底册（absence_probe）

`gkxlumenx_dwd` 上 `SHOW TABLES LIKE '%institute%'` 与 `'%univ%'` 双探针均 0 命中（`facts.dev_dwd_institute_tables=0`、`facts.dev_dwd_university_tables=0`）。库内最大的机构形态表是 `enterprise_base`（269,511 行）——但它是企业库（含大量非科研经营主体），语义是「企业数量」不是「机构数量」，本件不将其计入承载（若混入会把机构数虚增 3 倍以上，B3 混池陷阱）。另有 `enterprise_forg_base` 20,000 行为海外企业侧表、`org_achievement_year` 0 行（表在数空）。结论：开发库无本指标承载，B4 情形①（表不存在）。

### 2.3 gkx 四表对照池：有量无维

gkx 机构侧四表行数：`dwd_forg_university_org_info`（大学）20,000、`dwd_research_institute_base_info`（院所）2,074、`dwd_forg_research_org_info`（科研机构）20,000、`dwd_forg_base_info`（海外机构底册）20,000，合计 62,074（`facts.gkx_*_rows` 四键）。两个结构缺口使它只能作对照池：其一，四表各自为政，无统一机构类型维（「大学」「院所」是表级分类不是字段级分类）；其二，地理维不可用——`dwd_forg_base_info.country` 在 20 万采样（覆盖全表）中唯一值 NULL×20,000（absence_probe 在案）。gkx 口径的「机构数量」只能给全量 62,074 或按表拆四数，无法按类型/区域切片。

### 2.4 久新主读数：总数、类型分布与科研类口径

`ads_institution_profile` 全表 **83,745** 行（`facts.jiuxin_ads_institution_profile_rows`）。类型分布（JOIN `ads_institution_type`，`facts.jiuxin_ads_institution_profile_by_type`）：教育机构 16,991 / 未知类型 15,516 / 企业 15,392 / 医疗机构 11,228 / 科研设施 9,317 / 非营利 6,210 / 政府 4,312 / 其他 3,404 / 档案与文化 1,071 / 科研资助 304。两个口径并列落产物：口径 A 全量 83,745；口径 B 科研类五型（education+facility+government+nonprofit+funder）**37,134** 行（`facts.jiuxin_institution_research_type_rows`），占比 44.3418%（`derived[0]`）。

### 2.5 地理切片：深圳/广东/中国三级读数

城市切片：`city_name='深圳'` **135** 家（`facts.jiuxin_institution_city_shenzhen`）；省份切片：`province_name LIKE '%广东%'` **448** 家；国家切片：`country_name='中国'` **9,845** 家。深圳占广东 30.1339%（`derived[1]`，同表同池：分子=深圳、分母=广东，share_basis=广东省内底册）。科研类口径下深圳 **47** 家（`facts.jiuxin_institution_research_type_city_shenzhen`）——全类型 135 与科研类 47 的差值主要由企业/医疗类构成，两读数并列可解释深圳「机构多但科研机构占比一般」的结构。

### 2.6 稳健性与确定性

全部读数为 COUNT 与 GROUP BY（按类型中文名/城市名排序输出），无迭代序依赖；「未知机构类型」15,516 行（18.5%）作为独立类别如实报出、不摊派到其他类——这是类型维缺口的诚实呈现，避免「排除未知后占比虚高」的 B3 类错误。

## 四、数据缺失情况

### 4.1 开发库无底册（结构级，不影响档位）

`gkxlumenx_dwd` institute/univ 双探针 0 命中（absence_probe 三件套在案）。B4 情形①。修复动作：开发库如需承载，建机构底册表并接久新同步——工程立项事项；三源铁律下久新+gkx 已足额。

### 4.2 类型维「未知」占 18.5%（数据级，须随行披露）

`unknown` 类型 15,516 行（占 18.5%）。这不是错误值而是分类未完成态——OpenAlex 体系里来源信息不足的机构归 unknown。影响：按类型的任何对外读数，未知类必须并报（不能静默剔除，否则其余类占比分母失真）。修复路径：以机构名关键词规则（如含「大学/学院」→education）做半自动回填，预计可消化大部分 unknown；回填前口径 B（科研类 37,134）与口径 A（全量 83,745）都如实包含未知类的存在披露。

### 4.3 机构×领域切片维未探（范围级，另件处理）

雷达位语义是「产业分类>机构数量」——若「产业分类」指领域切片而非类型切片，则需机构×领域关联表（`ads_institution_topic_entry`/`ads_institution_industry`）。该维属下游件范围（技术领域族），本件不展开、不下「不支持」结论（未探不判，B4 纪律）。
