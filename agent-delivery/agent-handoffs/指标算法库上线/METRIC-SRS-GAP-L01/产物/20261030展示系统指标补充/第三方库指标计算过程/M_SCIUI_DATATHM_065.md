### 1.2 为什么需要本指标

类型分布比例回答「平台接入的资源在形态上长什么样」：结构化 41.38% vs 实时流 10.68%——管理者据此判断资源结构的健康度（结构化占主导意味着可 SQL 服务的能力盘；实时流占比低意味着时效性资源是短板）；它也是 KPI 卡「资源类型数 4 类」的展开形态（066 的分布版）。seq 330 把它列为一键总览的第一图——全局数据态势的**结构切面**（与年度增长的时间切面、来源活跃度的机构切面并列）。权威对应物是数据资产管理口径（DAMA-DMBOK）：资产按形式/结构分类的分布是资产画像的标准维度（structured/unstructured 是资产清单的标准分类字段）。本库场景下，该读数要求资源目录含类型字段——没有类型字段，任何分布都无从 GROUP BY。

### 1.3 需求文档是否给出定义方法

**需求文档给出立项锚但未给出定义方法。** seq 330/:2489 原文「可一键展示当前已接入的所有科技数据资源**类型与数量**，在仪表盘上直观呈现各类资源的**分布比例**」——「类型与数量」「分布比例」是立项级命名（本批计数组唯一），但：**类型枚举域无定义**（「科技数据资源类型」是存储形态轴——mock 饼图 4 类，还是要素域轴——同 mock 文件 dataType 值域含专利/论文/项目/情报/实验数据 5 要素类 + 4 存储形态类共 9 类，两轴在 mock 内混用无裁定）；**占比公式无定义**（按条数 count 还是按体量 volume——同组件归集侧 count/volume 双维并存承 063；分母是全部资源还是当期接入）；**舍入规则无定义**（mock {d}% 是 ECharts 默认整数百分比，正则实算精确值 41.38/29.38/18.56/10.68）。UI 的四分型是前端作者的演示约定，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

类型分布的权威方法分三层。其一，数据资产管理口径（R1 DAMA-DMBOK）：资产清单按 format/structure 分类字段的 GROUP BY 计数占比——structured/unstructured/semi-structured 是资产登记的标准分类法；其二，数据治理平台工程口径（R2 Dataphin/Atlas）：资产地图按表类型（物理表/视图/API/文件）分布——元数据采集附带类型登记，类型枚举随采集器落地；其三，数据分类分级标准（R3 GB/T 43697 数据分类分级）：分类维度先行登记——类型轴是分类分级的前置件。方法族对照：

| 方法族 | 原料 | 分布机制 | 与三源匹配 |
|---|---|---|---|
| 资产分类分布（R1） | 资产目录+类型字段 | GROUP BY format | **无目录**（词族命中全语义排除，§3.3） |
| 元数据类型登记（R2） | 元数据库 | 采集器类型字段 | **表级近似有**（1,032 表清单）**但两轴不兼容**（dwd 前缀=要素域） |
| 分类分级先行（R3） | 分类维度登记 | 维度表+映射 | **无维度表**（久新 institution_type 是机构类型轴） |
| 前端演示 | mock 常量 | 手写四分型 | 结构披露（不作源） |

结论：三条权威路径的第一层原料（含类型字段的资源目录/维度表）三源均无承载——分布口径不可交付；表级近似有表清单但**两轴不兼容**（要素域前缀 vs 存储形态四分型）——映射规则无登记，连分组近似也不可得（与 064 的「归属缺位」同构，本件是「类型缺位+两轴不兼容」双阻断）。「目录缺、类型轴断」构成本件部分支持的判定结构。与 063（总量）、064（分组——归属缺位同构件）、066（类型数——同轴连坐）、067（总量记录维）同根。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：按 R1→R3 路径推测，类型分布比例是资源目录按类型枚举的分组占比——

$$P(t) = \frac{\text{COUNT}(\*)\;\text{WHERE}\;R.\text{type}=t}{\sum_{t' \in T}\text{COUNT}(\*)\;\text{WHERE}\;R.\text{type}=t'} \times 100\%, \qquad \sum_{t \in T} P(t) = 100\%$$

其中 $T$ 为类型枚举域（mock 饼图四分型：结构化/非结构化/半结构化/实时流——存储形态轴）。**表级近似**（若资源≈表）：$T$ 的候选轴是 dwd 表名前缀（patent/paper/talent/org/fund——要素域轴），与存储形态轴**不兼容**——除非登记「要素域→存储形态」映射规则（如 patent→结构化），否则表级分组不可交付。**口径三未裁**：类型枚举域（存储形态轴 vs 要素域轴 vs 双轴并列——mock 两套并存）、计数维（条数 count vs 体量 volume——承 063 双维）、舍入规则（整数 % vs 两位小数）。**前提是含类型字段的资源目录存在，三源实测无（§3.3）**——公式列示仅作口径锚（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①资源目录立项（含类型字段，类型主轴裁定）→ `GROUP BY type` 直查 → 升**完全直接支持**；②「要素域→存储形态」映射规则登记 + 表级映射 → 表级近似转正（值=按前缀分组的表数占比）→ 升**完全转换支持**；③仅表级映射（无两轴规则）→ 两轴不兼容维持不可分组 → 部分支持；④维持现状 → 部分支持（饼图建议「暂无数据」或改挂要素域轴表级近似并披露口径差异）。

## 四、数据缺失情况

### 4.1 含类型字段的资源目录零承载（结构级，分布口径判定性缺口）

资源×类型登记面三源零承载（§3.3）——dev 最近邻是表结构模板，gkx 最近邻是内容标签/资讯条目，久新最近邻是机构类型轴。**本件的连坐面**：计数组五件共享目录缺位，本件与 066（类型数）是**同轴连坐**（一个类型字段两件读数：枚举计数=066、分组占比=本件）——目录立项含 type 字段则两件连升。**四缺失情形归属「表不存在」**：修复动作是资产目录立项 + 类型主轴裁定（schema 的 type 字段枚举域先行定义——存储形态四分型或要素域轴或双字段并存）。

### 4.2 类型主轴未裁与两轴映射缺位（口径级，双阻断）

本件降档的口径层根因是**双阻断**：①**类型主轴未裁**——mock 内存储形态轴（4 类）与要素域轴（dataType 9 类值域）混用，需求原文「科技数据资源类型」未指明哪一轴；②**两轴映射缺位**——表级近似（dwd 前缀=要素域轴）与 UI 演示轴（存储形态）之间无映射规则，「patent→结构化」这类规则无任何登记，两轴不兼容使表级分组近似也不可得。正式版须裁定：类型主轴（或双轴双字段）；若保留存储形态轴，须同步登记要素域→存储形态映射规则；占比计数维（count vs volume——承 063）与舍入规则。此裁定与目录立项解耦，可先行。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 资源目录立项（含 type 字段+主轴裁定） | 数据工程立项 | 本件 + 063/064/066/067 | 触发器①（065/066 同轴连升） |
| 类型主轴裁定（存储形态/要素域/双轴） | 口径裁定 | 本件 + 066 | mock 双轴断裂实证在前，可先行 |
| 要素域→存储形态映射规则登记 | 数据工程配套 | 本件 | 触发器②（表级近似转正的独有要件） |
| UI 饼图改挂或空态 | 展示规范 | 本件 UI | 41.38% 等演示值建议撤下 |

档位后果：目录+主轴 → **完全直接支持**（GROUP BY 直查）；映射规则+表级映射 → **完全转换支持**；现状 → 部分支持。推荐顺序：主轴裁定（即期一纸）→ 目录立项（type 字段）→ 映射规则（若保留双轴）。
