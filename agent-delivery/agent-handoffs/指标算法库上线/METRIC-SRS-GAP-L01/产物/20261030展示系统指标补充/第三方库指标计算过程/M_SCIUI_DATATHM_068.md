### 1.2 为什么需要本指标

连接活跃度回答「数据链路活着吗、活得多满」：接入渠道的数据连接（API/文件传输/数据库同步/物联网采集）若长期空闲或半死，归集就是空转——活跃度是链路健康度的第一眼读数；与调用频率（强度）、失败率（质量）构成监控三件套，挂在一起正是 USE/RED 方法在数据接入域的落地形态。需求语义锚 seq 344「资源接口状态跟踪」——状态跟踪能力立项，三指标是 mock 作者对它的具体化（注释自标）。权威对应物是 USE 方法（Utilization/Saturation/Errors）——活跃度是 Utilization 维；GB/T 33850-2017 服务监控把状态类指标纳入周期采集规范。本库场景下，该读数要求连接状态监测面（连接×时间戳×状态）存在——没有监测面，「活跃」无从界定。

### 1.3 需求文档是否给出定义方法

**需求文档未给出活跃度的定义方法。**「连接活跃度」字面三份说明书 0 命中——本读数仅见 mock 值与 UI label。语义锚 SRS seq 344「资源接口状态跟踪」（能力描述——跟踪什么、怎么算活跃均无）；mock 注释自标「seq 344：连接活跃度/调用频率/失败率」——三指标是前端作者对状态跟踪的具体化。**活跃度口径三无**：算式形态（活跃连接数/总连接数——连接占比？活跃时长/监测时长——时长占比？两种形态量纲不同）、统计周期（实时 vs 日均）、活跃判据（有调用即活跃？阈值？）均无定义。**本件与 057 的悬空度对比**：057 日均的分子分母字段在 seq 391 语境可辨（calls/activeDays）；本件 92.4% 连分子分母的字段形态都无从指认——这是「UI 派生读数」中悬空度最高的一档。

### 1.4 类似指标权威方法可行性分析概要

连接活跃度的权威方法分三层。其一，可观测性方法（R1 USE 方法）：Utilization=使用率（忙时间/总时间）——活跃度的工程形态与分母定义（时长占比）；其二，服务监控国标（R2 GB/T 33850-2017）：状态类指标周期采集（可用性/存活探测）——监测面的采集规范；其三，数据工程运维口径（R3 数据接入监控/心跳探针）：连接心跳（定时探测+状态上报）——监测面的最小实现形态。方法族对照：

| 方法族 | 原料 | 活跃度机制 | 与三源匹配 |
|---|---|---|---|
| USE Utilization（R1） | 忙/闲时间计数 | 忙时间/总时间 | **无时间计数** |
| 周期采集（R2） | 探测记录 | 状态周期采样 | **无探测记录** |
| 心跳探针（R3） | 心跳流水 | 有心跳即活跃 | **无心跳流水** |
| 前端演示 | mock 常量 | — | 结构披露（不作源） |

结论：三条权威路径的第一层原料（时间计数/探测记录/心跳流水）三源均无承载——本件与 056/057 同根（调用/连接监测面未立项）且**悬空度最高**（算式形态无定义）。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：按 R1→R3 路径推测，活跃度两种候选形态——

$$U_{\text{conn}} = \frac{|\{\, c \in C : \text{active}(c, T) \,\}|}{|C|} \quad (\text{连接占比形态}); \qquad U_{\text{time}} = \frac{\sum_{c} t_{\text{busy}}(c, T)}{\sum_{c} t_{\text{total}}(c, T)} \quad (\text{时长占比形态，R1 USE})$$

其中 $C$ 为连接全集，$\text{active}(c,T)$ 为窗口 T 内活跃判据（**未定义**：有调用即活跃？阈值？），$t_{\text{busy}}$ 为忙时长。**口径三未裁**：算式形态（连接占比 vs 时长占比——量纲不同）、统计周期（实时/日/月）、活跃判据。**前提是连接状态监测面存在（连接×时间戳×状态/心跳），三源实测无（§3.3）**——公式列示仅作口径锚（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①连接监测面立项（网关/探针心跳：连接×时间戳×状态）→ 活跃度直查（两种形态任选）→ 升**完全直接支持**；②乙方自建拨测（定时探测连接可用性+登记）→ 升**完全转换支持**（拨测周期与算式形态须登记）；③维持现状 → 完全不支持（UI 三指标建议「暂无数据」）。

## 四、数据缺失情况

### 4.1 连接状态监测面零承载（结构级，判定性缺口——悬空度最高）

连接监测面与连接台账三源零承载（§3.3）——与 056/057 同根（L4 探针共享），且本件**悬空度最高**：057 日均的分子分母字段尚可辨（seq 391 calls/activeDays），本件活跃度连算式形态都无定义（分母悬空）。**三指标连坐**：interfaceStatusMetrics 三指标共享监测前提——057（调用频率）已判、本件（活跃度）同判、失败率若族内立项同判。**四缺失情形归属「表不存在」**：修复动作是连接监控立项两件套（探针心跳流水：连接×时间戳×状态 + 连接登记台账：连接全集 C）；USE 时间计数与 blackbox 探针可直接作底稿。监测面建成后 056/057/068 三件齐升。

### 4.2 活跃度口径三未裁（口径级，悬空度最高——须从算式形态裁起）

活跃度口径三无定义（§1.3/§1.6）——且悬空度高于族内其他件：**算式形态**（连接占比 vs 时长占比——两种形态量纲不同，是最先要裁的一刀）、**统计周期**（实时/日/月）、**活跃判据**（有调用即活跃？阈值？）。正式版须一纸裁定——此裁定与监测立项解耦，但**必须从算式形态裁起**（否则监测面建成也不知道采什么数）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 连接监控立项（探针心跳+连接台账） | 数据工程立项 | 本件 + 056/057 + DATAOV/DATAIN 族 | 触发器①（流水/监测族共享主线，三件齐升） |
| 活跃度口径裁定（算式形态先行） | 口径裁定 | 本件 | 两形态量纲不同——最先要裁的一刀，可先行 |
| UI 暂无数据态 | 展示规范 | 本件 UI 三指标 | 演示值建议撤下（全 good 圆润披露） |

档位后果：监测面 → **完全直接支持**（两形态任选直查）；自建拨测 → **完全转换支持**；现状 → 完全不支持。推荐顺序：**口径裁定从算式形态裁起**（即期一纸）→ 监测立项（运营监控主线，056/057/068 三件受益）。
