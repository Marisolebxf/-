## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统·科技数据资源·总体视窗。挂载：资源接入情况总览（1.1.1.1.4.4.1；SRS seq 330）一键仪表盘 KPI 三卡排首卡——`mockData.js:1655-1658` overviewKPIs 首卡（资源类型数 4 类，change 0）；渲染链 `OverviewWindow.jsx:603-613`（overviewKPIs.map → KPICard，:605），KPI 点击无 key（首卡无 key 字段——资源总量卡 key='total'/主题库 key='theme' 有跳转，类型数卡纯展示）；`:631` 收起态文案「资源类型与数量、分布比例……」（seq 330 原文复述）。KPI 行下方三图排首图即 065 的分布饼图（`:616`）——本件是它的枚举计数卡。

### 1.2 为什么需要本指标

类型数回答「平台资源在形态/域上有几种」：它是 KPI 层最简的结构读数——一眼看资源结构的**宽度**（4 类还是 9 类），与资源总量（规模）、主题库数量（组织形态）构成总览三卡；它也是 065 分布的维度声明（分布 |T| 类的 |T|）。change:0 的静态语义（类型数不随月波动）使其成为三卡中唯一无趋势维的——枚举域的稳定性本身是信息（类型体系是否在扩张）。seq 330 把「类型与数量」并列命名——本件是「类型」的最简读数形态。权威对应物是数据资产管理口径（DAMA-DMBOK）：资产分类体系的类目基数（taxonomy size）——分类先行，基数是分类健康度的度量。本库场景下，该读数要求类型枚举域已裁定且资源目录含类型字段——没有枚举域，COUNT DISTINCT 无从谈起。

### 1.3 需求文档是否给出定义方法

**需求文档给出立项锚但未给出定义方法。** seq 330/:2489「可一键展示当前已接入的所有科技数据资源**类型与数量**」——「类型」是立项级命名（与 065「分布比例」同句），但**枚举域无定义**：mock 内两套轴并存（KPI/饼图 4 类存储形态轴 vs dataType 值域 9 类混合轴）且互不引用——「科技数据资源类型」指哪一轴，需求原文未指明；gkx 侧还有第三候选（dwd 要素域 11 域）。**计数前提无定义**：COUNT DISTINCT 的对象（资源行数还是类型字典行数）、空类型处理（未标注资源的归属）、枚举时点（快照 vs 累计曾出现——change:0 暗示快照）均无定义。UI 的 4 是前端作者的演示约定，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

类型数的权威方法分三层。其一，数据资产管理口径（R1 DAMA-DMBOK）：分类体系类目基数——taxonomy/字典表的 COUNT(*)，前提是分类体系已登记；其二，元数据管理口径（R2 Dataphin/Atlas）：资产类型注册表——类型随采集器注册（物理表/视图/API/文件），基数=注册表行数；其三，数据分类分级标准（R3 GB/T 43697）：分类维度表先行——维度不登记，基数无定义。方法族对照：

| 方法族 | 原料 | 计数机制 | 与三源匹配 |
|---|---|---|---|
| 分类体系基数（R1） | 类型字典表 | COUNT(*) | **无字典**（类型词族全语义排除承 065） |
| 类型注册表（R2） | 采集器注册 | 注册行数 | **无注册表**（dev schema 域轴是系统功能域非类型轴） |
| 维度表先行（R3） | 分类维度登记 | 维度行数 | **无维度表**（久新 institution_type 是机构轴/学科轴承 062） |
| 表名前缀实算（工程近似） | 表清单 | 前缀 COUNT DISTINCT | **候选有**（gkx dwd 11 域/121 表——两轴不兼容承 065） |
| 前端演示 | mock 常量 | 手写 4 | 结构披露（不作源） |

结论：三条权威路径的第一层原料（类型字典/注册表/维度表）三源均无承载——正式口径不可交付；表名前缀实算是第四条工程近似路径（本件新增实算）——要素域轴可数（11 域）但轴语义与 UI 演示轴不同。「字典缺、前缀可数」构成本件部分支持的判定结构。与 065（分布——同轴同源对）、063/064（总量/分组——目录族）、067（总量记录维）同根。完整版见附录 C。

## 二、计算过程

### 2.1 口径裁定（B10 多口径并列）

本件读数「数据资源类型数」是类型枚举域基数，B10 并列登记三个口径：**口径 A（正式口径）**——资源目录 `COUNT(DISTINCT type)`（枚举主轴已裁定为前提）；主轴未裁+目录无承载（§2.2），**不可得**，指标键 `data_resource_type_count = null` 留空。**口径 B（表级候选·要素域轴）**——gkx dwd 表名前缀 `COUNT(DISTINCT 域)` = **11**（derived `data_resource_type_count_domain_axis_approx`，白名单 15 域在册实匹配）；与 UI 存储形态轴不同轴（两轴不兼容承 065），**仅候选登记不作正式值**。**口径 C（UI 演示）**——KPI 卡 4 类，演示值不作数据证据（B10）。

### 2.2 排除实测：类型枚举面三源逐一留证（排除复用+域轴实算）

## 四、数据缺失情况

### 4.1 类型字典/注册表面零承载（结构级，枚举口径判定性缺口）

类型枚举登记面三源零承载（§3.3）——dev schema 域轴是系统功能域，gkx 前缀是命名约定非字典，久新是机构/学科轴。**本件的连坐面**：与 065 同轴连坐（一个 type 字段两件读数），且是计数组**唯一存在「口径未裁」类缺口**的件（D2 枚举主轴——非数据工程可修复，须需求侧一纸裁定）。**四缺失情形归属「表不存在」+「口径未裁」双缺**：修复动作是类型字典立项（或目录 type 字段枚举域定义）+ 主轴裁定先行。

### 4.2 枚举主轴未裁（口径级，本件独有判定性缺口）

本件降档的口径层根因：**枚举域三值并存无裁定**——UI 形态轴 4/mock 混合值域 9/gkx 要素域 11，需求原文「科技数据资源类型」未指明哪一轴；三轴语义不同层（存储形态 vs 要素域 vs 混合），无映射则 COUNT DISTINCT 无唯一解。正式版须裁定：①枚举主轴（形态/要素域/双轴双字段）；②计数对象（目录行去重 vs 字典直计）；③空类型归属与枚举时点（快照 vs 累计）。此裁定是**纯口径动作**（零数据工程），可即期先行——且一次裁定同时解锁 065（分布）与本件（基数）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 类型主轴裁定（形态/要素域/双轴一纸） | 口径裁定（即期） | 本件 + 065 | 三值并存实证在前——零工程量，最高性价比 |
| 类型字典立项（或目录 type 字段+枚举域定义） | 数据工程立项 | 本件 + 063/064/065/067 | 触发器①（目录族共享） |
| 裁定类型=要素域 → 前缀白名单转正 | 口径裁定+配套 | 本件 | 触发器②（11 域实算在册，附白名单注记） |
| UI KPI 卡改挂或空态 | 展示规范 | 本件 UI | 4 演示值建议撤下（三值并存下尤甚） |

档位后果：目录+主轴 → **完全直接支持**（COUNT DISTINCT 直查）；裁定要素域 → **完全转换支持**（前缀 11 域转正）；裁定形态轴且无目录 → 维持部分支持。推荐顺序：主轴裁定（即期一纸）→ 字典/目录立项 → 前缀白名单维护（若走要素域）。
