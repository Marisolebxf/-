## 摘要

「数据量及其期际变化」是主题视窗·资源来源分析与详情组件「来源结构组成分析」卡的条形图视图：`ResourceSourceAnalysisDetail.jsx:396` Segmented 切「数据量与变化」后由 `getStructureBarOption`（:89-107）渲染五类来源（国内数据库/国外数据库/科研院所/企业/开源平台）的 volume 横条，条尾标签给 change% 环比读数（mock 14.2/8.6/12.5/18.3/22.1，全为正）。数据侧判定核心是「同来源类×至少两期量」序列面：三源逐一排除——dev 唯一 growth 命中是 0 行空表（enterprise_growth_trend，年月序列结构在但对象分叉）；gkx 标签轴空载+growth 词族 0 命中；久新命中均为研究问题演变面。全库唯一时间维代理（enterprise_base 月维）只有 2026-08/2026-09 两点且 9 月仅 348 行——期际序列不可构建。判**完全不支持**。脚本已跑通，产物与正文数字逐一对应。

- 需求判定：**UI 派生读数**（「数据量与变化」为 Segmented 选项文案；三份真源 0 命中）。
- 复现状态：脚本已跑通；三源词族排除 + 空表结构近邻 + 月维两点代理全落产物。
- 档位结论：**完全不支持**（期际变化维三源零承载；量维可数但分组轴缺位）。
- 关键事实：mock 的 change 五值全为正增长（8.6-22.1%）——演示形态隐含「持续增长」叙事，而库内月维现实是批次式灌库（8 月一笔 269,163 + 9 月零星 348），不存在任何可对比的期际序列——演示形态与库内现实结构性脱钩。

### 1.2 为什么需要本指标

来源结构组成卡的管理命题是「**数据从哪来、来得快不快**」：结构占比（pie 视图）回答构成，数据量与变化（bar 视图）回答规模与动能——量条+变化标签的组合让管理者一眼识别「哪类来源是主力、哪类在加速」（开源平台 volume 第五但 change 22.1% 第一=高成长信号）。这与总体视窗的 DATAOV_002 年度增长趋势同属「增长叙事」族，但本件多了来源类分组维。权威对应物是国家科学数据中心的分中心汇交量序列（R1）：按中心×年度的汇交量上报序列，即可算各中心体量与增速——序列面（主体×期×量）是一切期际变化读数的原料。

### 1.3 需求文档是否给出定义方法

**三份需求说明书未出现「数据量及其期际变化」。**「数据量与变化」是 UI Segmented 选项文案（:396）；「环比变化」是表格列题（:240）。最接近的需求语义：主需求 :2729「每个数据集显示其元数据，包括名称、所属主题库、数据类型、**数据量**、来源单位……」——数据量是数据集级元数据属性项，非「平台按来源类的期际量变化」指标；seq 349「评估数据汇聚规模和**历史变化趋势**」是接入视窗的总量趋势功能（DATAIN_002 承接），无来源类分组与变化率口径。核增需求与算法库 0 命中（附录 A.2）。UI 的 change 常量是前端演示约定，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

「量的期际变化」的权威方法锚分三层。其一，国家科学数据中心体系（R1）：分中心×年度汇交量序列——增速=（本期-上期）/上期，序列面是制度化的汇交台账；其二，统计口径（R2/R3）：环比增速=（本期-上期）/上期×100%（月距）或同比增速（年距）——国家统计局 GDP 环比增速的方法论锚，前提是**分期序列存在**；其三，库内代理路径：无台账时以 update_time 月维分布近似分期——但月维是「最后修改时间」，批次重刷会整体漂移（DATAIN_002 §2.5 已披露脱钩机制）。方法族对照：

| 方法族 | 代表 | 原料 | 与三源匹配 |
|---|---|---|---|
| 汇交台账序列 | R1（分中心上报） | 主体×期×量台账 | **无台账** |
| 环比/同比公式 | R2/R3（统计局） | 分期序列 | **无序列**（月维仅 2 点不成期） |
| update_time 月维代理 | 库内近似 | update_time | 2 点且语义脱钩（批次面） |
| 前端演示 | UI change 常量 | mock | 结构披露（不作源） |

结论：权威路径的原料（台账/分期序列）三源均无——本件是「序列面缺失」型缺口，量维可数也救不了期际维。完整版见附录 C。

## 四、数据缺失情况

### 4.1 来源类×期际序列零承载（结构级，判定性缺口）

期际变化率的唯一原料是「同来源类×至少两期量」序列（§1.6 公式的 $V^{(t)}$ 与 $V^{(t-1)}$）。三源实测零承载（§3.3）：dev 唯一序列结构近邻是 0 行空表；gkx 分组轴本身空载（无序列可言）；久新命中面研究对象错位。**四缺失情形归属「表不存在」**：修复动作是来源台账立项（来源类×量×期流水）——与 DATAOV_002/DATAIN_001/003/027 族级共用（一次建设多件受益），本件是族内对「分组×期际双维」要求最全的一件。

### 4.2 月维代理不成期（数据级，次因）

即便退到总量期际（放弃来源类分组），月维代理也只有 2026-08:269,163 / 2026-09:348 两点——9 月 348 行是长尾补录不是「第二期接入」，强算环比得 -99.87% 的批次伪读数。这是 dev 全库的共性形态（DATAIN_001 已证三大批次日集中 8 月），非本件特有——台账缺位下「趋势/变化」类读数（本件+DATAOV_002+053）全部同根受阻。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 来源台账立项（来源类×量×期） | 数据工程立项（族级） | 本件 + 053 + DATAOV_002 + DATAIN_001/003/027 | 触发器①（族级共用主线） |
| 血缘分组+批次期口径裁定 | 口径裁定 | 本件零成本近档 | 触发器②（data_source 5 组×月维，语义降维披露） |
| UI 暂无数据态 | 展示规范 | 本件 | mock change 建议替换「暂无数据」（全正增长演示形态误导） |

档位后果：台账建成 → **完全直接支持**；血缘口径裁定 → **完全转换支持**（披露）；现状 → 完全不支持。推荐顺序：台账立项为主线（族级），血缘口径作即期内部参考（不对外标「环比」）。
