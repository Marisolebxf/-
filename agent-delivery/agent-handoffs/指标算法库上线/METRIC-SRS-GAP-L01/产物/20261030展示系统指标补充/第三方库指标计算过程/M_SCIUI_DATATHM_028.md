## 摘要

- 需求判定：**UI 派生读数**（指标名 0 命中；seq 354 分组功能在、分组键的数据承载与合计口径无定义）。
- 复现状态：脚本已跑通；mock 分组复算（三组维+双恒等校验）+ 质量轴排除探针 + 血缘维分组读数全落产物。

### 1.2 为什么需要本指标

seq 354 的管理命题是「**针对性分析与批量管理**」：总览读数（027 总量）回答「多少」，分组合计回答「**结构**」——按渠道分组看供数结构、按种类分组看内容结构、按质量分组看治理结构；组级合计+组内可展开（expandedRowRender）形成「结构→明细」的下钻链。seq 355（导出）把分组结果随明细导出（:476-492 ExportButton fields 含「归集数据量」）——分组合计是汇报材料的行项。官方对应物是 R2 的分主体体量序列（项目汇交 4,325 个按主体分列）——「总量+分组结构」是资源统计的标准双联呈现，本件是分组联。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「分组归集量合计」指标名三份真源 0 命中（附录 A.2）。功能语义叶 seq 354：「支持根据来源渠道、数据种类、时间、质量等多种维度对资源进行筛选和分组，方便用户实现针对性分析或批量管理各类数据来源」——分组维度是举例式列举（等），合计口径（求和？计数？）、分组键的取值域（质量等级分几档）、时间维的粒度均无定义。核增需求与算法库 0 命中。UI 的三选项分组下拉与 volume 求和是前端实现约定，不构成口径证据。

## 二、计算过程

### 2.1 方法选择（文献依据）

方法选**分组聚合复算 + 血缘维分组交付**（R1 台账分组的算法同构 + R3 目录聚合的目标态参照）：其一，按 UI `groupedData` 同构算法复算 mock 三组维（渠道/种类/质量）——验证分组语义的算法面（组内求和+排序+恒等）；其二，血缘维（data_source）分组作为即期交付口径（组级合计=组行数）；其三，双恒等校验（mock Σ组=Σ明细；dev Σ组=总行数）给分组读数完备性背书（B3 同基）。需求维分组因明细面不存在不做方法选型（F4 禁伪公式——不伪造「按质量等级」的分组读数）。

### 2.2 mock 分组聚合复算（三组维+双恒等校验）

## 四、数据缺失情况

### 4.1 资源级明细登记面零承载（结构级，主因）

seq 352 要求的资源元数据（名称/数据类型/采集时间/质量等级/关联项目/所属领域+volume）是分组功能的语义支点——三源零承载（§3.3）。**四缺失情形归属「表不存在」**：修复动作是明细登记面立项（字段清单可直接采用 seq 352 原文+mock details 八字段参照）——这是族内**最深层的缺口**：027 可用存量近似、003 可用表级体量代理，本件的分组结构只能靠血缘近似。登记面建成时 027/028/033/003 四件+seq 352/354/355 三叶同时受益（并项建议）。

### 4.2 分组键轴编目缺位（口径级，次因）

即便明细面缓建，分组键的值域编目（渠道字典/种类字典/质量档位表）也须先裁——与 027/003 的 taxonomy 分叉、DATAOV_001 的资产目录同根。血缘维虽可即期分组，但其「表血缘+供应商代号」语义与需求维度不同构（§2.5）——正式版若按血缘呈现，须重标签为「库内血缘分组」并披露语义降维。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 资源级明细登记面（seq 352 字段清单） | 数据工程立项（族级） | 本件 + 027/033/003 + seq 352/355 | 触发器①（第一性缺口，字段清单现成） |
| 分组键编目（渠道/种类/质量三字典） | 数据治理 | 本件 + 027/003/018/031 | taxonomy 分叉族级共用 |
| 血缘维分组升格/重标 | 口径裁定 | 本件即期交付 | 触发器②（标签「库内血缘」） |
| mock details 结构参照纳入立项 | 设计输入 | 登记面 schema | 八字段参照（演示结构非数据源） |

档位后果：明细面+字典 → **完全直接支持**；血缘维裁定 → **完全转换支持**；现状 → 部分支持。推荐顺序：血缘维裁定即期（零成本）→ 明细登记面立项（族级主线，字段清单现成）→ 三字典随 taxonomy 裁定。
