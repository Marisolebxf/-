## 四、数据缺失情况

### 4.1 竞赛台账与评审面零承载（结构级，主因）

评审得分是竞赛评价体系的输出，三源既无竞赛台账（参赛项目面）也无评审结果面（项目×得分），地基与主体双缺。四缺失情形归属：**表不存在**。修复动作是**办赛/评审数据源接入**（对接办赛平台或主办方评审系统导出），库内无法构建。

### 4.2 评价模型连带缺失

评审维度集（创新性/技术难度/完成度等）、权重、分制均无定义——清单自注「需要立项调研后才能确定」即官方确认。即使评审面接入，得分口径仍需模型落定（与 THINK_002/INCUB_043/047 评分族同构）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 接入办赛平台/评审系统 | 外部数据源 | 本件 + THINK_004/005/013/014 + CONTEST_001 | 竞赛族六件一揽子（台账是共同地基） |
| 评审模型立项 | 业务建模 | 本件 | 维度/权重/分制（可参照互联网+大赛多维加权） |
| 排行榜切真 | 数据工程 | 本件 + THINK_014 | 得分面落库即排行激活 |

档位后果：评审面 + 模型双落定 → 完全转换支持；评审 API 直连 → 完全直接支持；无动作 → 维持完全不支持。推荐：竞赛族合并推办赛数据源接入（一源解六件）。
