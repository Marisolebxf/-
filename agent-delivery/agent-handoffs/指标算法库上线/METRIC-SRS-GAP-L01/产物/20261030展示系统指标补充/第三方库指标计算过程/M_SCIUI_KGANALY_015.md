## 摘要

「反馈均分」是优化决策模型面板「决策反馈闭环」Tab 的核心读数：业务部门对决策动作（拦截/预警/推送）复核后的评分均值（五分制），与反馈后准确率/目标误报率构成闭环三读数。UI 现状是两层 mock：mockData 写死四条部门反馈（风控部 5 分有效拦截/信贷审批 4 分确认违约/客服 2 分误判/合规 5 分有效预警），`applyFeedbackLoop` 对全量求均（含误判项）得 4.0/5。数据侧判定：**完全不支持**——反馈评分的计算原料三源皆无，且断点是双重的：下游评分面无承载（feedback 词族三源 0 命中）、上游预警记录更无（blacklist/trigger 0 命中）——没有决策动作记录，评分对象本身就不存在。本件与 010/011（召回率/准确率）共享「无决策记录面」负证据族：三件同挂优化决策面板，同吃一条「预警→复核→评分→反哺模型」数据流，整链三源无立项。

- 需求判定：**需求明列叶**（seq 453「图分析结果能直接与业务流程系统对接…将分析洞察落地至具体操作」——反馈闭环读数位）。
- 复现状态：脚本已跑通；均分公式移植复现（4.0）+三源词族负证据全落产物。
- 档位结论：**完全不支持**（negative_evidence，探针三件套在案）。
- 关键事实：即使最宽松的「任意业务评分折算」口径也无原料——三源连一条评分记录都没有（不只是没有决策外键）。

## 四、数据缺失情况

### 4.1 评分面+预警面双缺（结构级，主因）

反馈评分记录三源不存在（`absence_probe` 三件——D1/D2 全为「表不存在」级缺失）。修复路径：**algo 决策管线立项**——预警落盘表（alertId/type/target/score/status/time）+ 复核评分表（alertId/dept/result/rating/suggestion/time，形态即 decisionFeedbackItems）。这是新数据源工程，非现有库表转换可得。折中路径不存在：无任何评分记录则代理指标（评分量/参与部门数）也无从算起。

### 4.2 UI 面板的连带影响

优化决策面板整链（010/011/015 + 未派件的反馈后准确率/目标误报率/风险预警四读数）共享「无决策记录面」负证据——本件探针对面板全族直接适用。面板整体在数据侧落空，UI 现状 mock 是唯一「数据源」。建议：面板先标注「演示」，待决策管线立项后整链接入。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| algo 决策管线立项（预警落盘+评分面） | **新数据源** | 本件 + 010/011 + 面板全族 | 唯一满足反馈闭环语义的路径 |
| 预警落盘先行（评分面缓建） | 数据工程 | 风险预警族 | 本件仍不支持（评分无承载） |
| 面板标注「演示」 | 前端 | 面板全族 | 防误导 |

档位后果：管线+评分面 → 完全转换支持；仅预警落盘 → 本件仍完全不支持；现状 → 完全不支持。
