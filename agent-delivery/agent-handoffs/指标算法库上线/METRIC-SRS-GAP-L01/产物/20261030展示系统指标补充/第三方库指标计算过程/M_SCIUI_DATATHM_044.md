### 1.2 为什么需要本指标

更新成功率是接入链路的**质量主读数**：与异常数（043）同源不同维（043 数失败绝对量、本件算成功相对率），两者构成运行质量的「量率双读」。渠道级成功率列（seq 361 承接位）进一步下钻到「哪条渠道质量差」（mock 人工录入 92.3 最低）。权威对应物：Airflow 的 ti_successes/ti_failures 计数器与成功率派生（R2）；Prometheus 的 record 规则聚合成功率（R3）；GB/T 36344 数据质量框架（R1）——三者原料都是逐次运行记录。

### 1.3 需求文档是否给出定义方法

**指标名级三份真源 0 命中。**seq 362 功能句含「更新成功率」功能词（「动态跟踪接入量、更新成功率与异常情况的历史变化」）——功能在，但：分子分母口径（成功运行次数/总运行次数？成功任务数/总任务数？成功记录数/总记录数？）、**partial（部分成功）是否计入成功**、统计窗（月/周/全程）均无定义。核增需求与算法库 0 命中（附录 A.2）。UI 的 75.0 是演示常量，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

「任务成功率」的权威方法锚分三层。其一，调度监控（R2，Airflow）：成功率=ti_successes/(ti_successes+ti_failures)——两计数器同源于任务实例日志，按 dag/task 打标可下钻（渠道级成功率的工程形态）；其二，监控聚合（R3，Prometheus）：record 规则预聚合成功率时序——range query 按窗聚合；其三，数据质量框架（R1，GB/T 36344）：成功率属于质量监控域指标，须先定义质量规则（何为成功/partial）。方法族对照：

| 方法族 | 代表 | 原料 | 与三源匹配 |
|---|---|---|---|
| 调度成功率 | R2（Airflow） | 任务实例日志 | **无日志**（xxl 0 行） |
| 监控聚合 | R3（Prometheus） | 指标时序 | 无指标面 |
| 状态快照占比 | 库内可行近似 | es_sync 状态三列 | **有结构有数据**（模块级、非次数口径） |
| 前端演示 | UI mock 三组 | mock | 内部不闭合（不作源） |

结论：权威口径原料（任务日志）三源无；库内状态快照语义错位（模块占比≠次数成功率）。完整版见附录 C。

mock 三组演示值的关系核验（脚本算出，`ui_mock_pie_*` 键）：summary.successRate=**75.0**；updateStatus 饼图（成功 7/部分成功 3/失败 2，合计 12 条）的两种候选口径——仅成功 **7/12=58.3%**（`ui_mock_pie_success_only_share_pct`）、成功+部分 **(7+3)/12=83.3%**（`ui_mock_pie_success_plus_partial_share_pct`）——**75.0 与两口径均不闭合**（差 16.7pp/8.3pp）。结论：前端演示值不是从状态明细算出的（各自为政的常量），且「partial 是否计入成功」在 mock 内也无一致行为。渠道级五值（98.2/95.6/97.8/92.3/96.8，`ui_mock_cycle_success_rates_sorted`）与 summary 75.0 也不闭合（五渠道均值 96.14）——三处演示值三个口径。这是「演示值先于口径」的典型形态，正式版必须先裁定 partial 规则再分位交付。

## 四、数据缺失情况

### 4.1 运行次数日志零承载（结构级，判定性缺口）

成功率公式的分母（总运行次数）要求逐次运行记录存在（§1.6）。dev 调度器全链空载体（xxl 三表 0 行）；es_sync_watermark 是覆盖式快照（**设计上不留历史**——每次同步覆盖前笔状态，分母退化为模块数）。**四缺失情形归属「表存在但数据为空」**（xxl）+「序列语义不存在」（es_sync 设计形态）：修复动作是 xxl 实装（首选，任务级粒度）或 es_sync 逐次留痕表（次选，模块级粒度）——与 043/019 共用触发器。

### 4.2 partial 计入规则缺位（口径级，前置裁定）

「部分成功」算不算成功直接决定读数（mock 内 58.3% vs 83.3% 差 25pp）。需求无定义、mock 无一致行为、es_sync 无 partial 分级（两态）——三重缺位。正式口径须按 R1 质量框架先行裁定：建议 partial 不计入成功但单列（三态呈现：成功率/部分成功率/失败率），避免单一读数掩盖部分成功风险。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| xxl 调度器实装留日志 | 调度工程 | 本件 + 043 + 019 | 触发器①（运行日志族共用主线） |
| partial 计入规则裁定（三态呈现） | 口径裁定 | 本件前置 | R1 框架先行（一纸文件） |
| es_sync 逐次留痕 | 数据工程 | 本件 + 043 | 触发器②（模块级备选） |
| UI 暂无数据态+快照参考位 | 展示规范 | 本件 | 75.0 替换；92.86% 标签「当前正常模块占比」 |

档位后果：xxl+裁定 → **完全直接支持**；es_sync 留痕+裁定 → **完全转换支持**；现状 → 完全不支持。推荐：partial 裁定即期（一纸文件），xxl 实装随族级主线。
