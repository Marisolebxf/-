## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技政策跟踪/**政策效果推演·空间模拟语境**/空间协同指数。挂靠结构：`_phase3_screen_v3.json` 将其归入「多维政策对比」（l2），UI 实际挂载点是政策跟踪域共用的仿真指标结构 `simulationIndicators`（`policyData.js:708-713`）——注释明写「推演结果指标（Bid · GDP增长 / 产业结构变化 / 就业率变化 等）」：四个指标槽位依次为 GDP增长（%）、产业结构变化（%）、就业率变化（pp，POLCMP_024 姊妹件）、**空间协同指数（分，本件）**。它与 `simulationScenarios` 三情景（乐观/基准/保守，`results.spatialIndex` 92/84/68）联动，消费方 `simulation/sharedCharts.jsx:26` 引入后在 `:95`（雷达 indicator）、`:144-146`（对比条形 baseline/target）渲染。

单位「分」+ baseline 72/target 88 的双值结构声明它是**综合评价分**：不是单一可观测量的读数（如 GDP 增长的 %），而是多维合成的 0-100 分——这正是 cat 判「需业务建模类」的依据：分从哪几维合、权重怎么定，需求与 UI 均未给，须立项调研。

### 1.2 为什么需要本指标

政策效果推演的产出侧四问：经济贡献（GDP）、结构变化（产业）、民生（就业）之后是第四问——**空间格局**：政策是让目标区域与周边形成协同（要素流动、产业分工、创新联动），还是造成虹吸（资源单向外流）？空间协同指数把这一问做成可比较的分数，供方案比选：两个 GDP 贡献相近的方案，协同分高的更符合区域协调发展导向。这个读数的政务对应物是京津冀协同发展统计监测（R1/R2）——官方对「区域协同」的量化已有成熟范式，但那是区域发展综合评价，政策推演语境的空间协同指数是其**缩小版**（聚焦单政策的空间效应）。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「空间协同指数」三份需求真源 0 命中（附录 A.2）。最接近的语境有两处，均非定义：其一，主需求 1.1.1.1.4.2.3.1.3 区域经济发展空间模拟（:1415）枚举「包括GDP增长、产业结构变化、就业率变化等指标」——「等」字之后没有空间协同（UI 的 Bid 标注把本指标挂进此语境属于前端作者扩展）；其二，1.1.1.1.4.2.3.2.4 政策关联分析「把握政策的协同效应」（:1443）——定性叙述非量化定义。「协同指数」另见主需求 :5211 产学研合作语境（「基于联合专利、合作项目等数据计算协同指数」——企业-机构科研协同，不同物但方法论可参照）。

### 1.4 类似指标权威方法可行性分析概要

区域协同的量化评价有三族权威先例。其一，**京津冀区域协同发展指数**（国家统计局 R1/R2）：5 个一级指标（创新/协调/绿色/开放/共享，均等权重各 20 分）×43 个三级指标（专家赋权），基期 2014=100，正逆指标标准化后指数加权合成 $S=\sum P_i W_i$——2023 年总指数 148.8、2024 年继续提升；其中「协调发展」域含**城市群空间联系强度、京津冀互相输出技术合同成交额、区域合作与转让专利数**等真正的跨区交互指标。其二，**政策耦合协调度模型**（R3）：中央与地方政策子系统综合评价指数计算耦合协调度，测算央地/区域政策协同水平。其三，**产学研协同指数**（主需求 :5211 语境）：联合专利/合作项目/人才流动等协同指标加权。三族的共同数据门槛：**区域间成对交互序列**（技术合同跨区流向、联合专利跨区署名、要素流动量）——这正是三源缺口。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（不可实现，仅登记语义）**：

$$\text{SpatialIdx}_{p} = \sum_{k} w_k \cdot \text{norm}\big(\text{CrossRegionFlow}_{k,post(p)}\big/\text{CrossRegionFlow}_{k,pre(p)}\big)\times 100$$

其中 $p$ 为政策，$k$ 遍历跨区交互维（技术合同跨区流向/联合专利跨区署名/要素流动等，维度集须建模立项），norm 为参照京津冀范式（R1/R2）的标准化（正逆指标分式、基期=100），$w_k$ 为专家赋权。**本件不写伪计算过程**（F4）——跨区交互的政策归因版三源零承载（§3.3），合成层无数据基础；UI 的 72/88/92/84/68 均为前端虚构的指数形态。

**降档/升档触发器**：①久新 `ads_technology_policy_evidence` 装载（政策×技术节点×地理结构已在）+ 交互序列接入 → 可升**部分支持**（建模立项仍需）；②族级兑现台账+跨区交互序列双接入 → 合成运算可复现，升**完全转换支持**；③甲方若接受「科研跨区合作密度」作空间协同代理读数 → 语义已换（科研协同≠政策实施的空间协同），须**另立件**并显式披露口径差（久新 1,438 万行协同网络现成可算，代理件门槛低但口径须甲方裁定）。

### 3.2 代理面边界：科研协同网络的真实与错位

**久新机构协同网络**（本族唯一大体量真实跨区交互面）：`ads_institution_collaboration_yearly` 14,380,246 行（`jiuxin_inst_collab_yearly_rows` 在案），42 列结构（`jiuxin_inst_collab_yearly_cols` 在案）含机构对×年的共同论文/专利/项目计数（co_paper_count/co_patent_count/co_project_count）、合作强度（collaboration_strength）与**跨区协同标志**（is_cross_region_collaboration）——实测该标志=1 的行 4,790,298，占全表 33.3117%（派生键 `jiuxin_inst_collab_cross_region_share_pct`，分子分母同表同池）。这张表证明「跨区交互数据本体」在久新真实存在且体量充足；但它的语义是**科研协同**（机构间论文/专利共现），空间协同指数需要的是**政策实施后的区域协同**（技术合同跨区流向、产业分工变化等）——两者之间隔着政策归因这一层：没有任何列把合作对关联到政策。把它直接算成空间协同指数，等于假定「科研合作密度=政策协同效果」，这是甲方须裁定的口径替换（§1.6 触发器③）。同库 subfield 版 `ads_institution_collaboration_subfield_yearly` 23,363,790 行同构细分。
