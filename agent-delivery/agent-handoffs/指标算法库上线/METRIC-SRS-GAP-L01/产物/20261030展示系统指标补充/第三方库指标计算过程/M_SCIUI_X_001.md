值得记录的 UI 语义细节：旧版 subtitle「按时间与企业类型对照」给了两个切片维（时间/企业类型），新版 `getEnterpriseScaleFactor/getEnterpriseTypeFactor` 把企业规模/类型做成缩放因子乘进 mock 值——前端用乘法模拟切片，说明需求侧预期产值面是「产业×年×企业类型」三维立方，而非单序列。

### 1.2 为什么需要本指标

产值是产业发展潜力的「产出维」硬指标：投入（研发/固投/人才）与成熟度（技术/市场）最终都要兑现在产值上，「总产值→增加值→利润」三序列递进刻画产业的规模、质量、盈利能力——总产值看盘子、增加值看贡献、利润看可持续。需求把它与科学影响力（seq 149）/技术影响力（seq 150）并列为产业发展潜力的三个评估面，说明业务叙事要「经济面+学术面+技术面」三视图互证。

数据侧本件是产值族（X_001/X_002/X_018/X_027 四件）的主链件：派单书 §0.2 特别裁定「真实经济指标语义——探针须覆盖开发库经济/产值类表与久新产业维；专利/论文代理口径只能作为对照面，不得当主口径」。这条裁定直接改变了本件的探针策略：不以科技产出（专利量/论文量）充当产值，而是穷尽三源的经济计量面——gkx 宏观指标库（统计口径的经济码值体系）、dev 企业财务史（微观口径的营收利润）、久新产业维（专利映射对照面）。

### 1.3 需求文档是否给出定义方法

**需求文档给出三序列枚举但未给计量口径。**SRS seq 148（excel_row 151）原文：「收集并统计特定产业的总产值、增加值、利润等经济指标，用户可按时间范围、地域、企业类型等维度查看产业产值情况，系统提供柱状图、折线图等可视化形式展示产值变化趋势。」——**三序列（总产值/增加值/利润）与三切片（时间/地域/企业类型）明文**，这是全批口径最明确的经济指标需求；但「特定产业」怎么划（国民经济行业？战略性新兴分类？）、总产值是现价还是不变价、利润是营业利润还是利润总额，仍未定义。主需求文档 :935-937 逐字同文。计量细节的空白由 gkx 宏观库的既成口径（unit_use=元的绝对值序列）与 UI 演示形态（亿元轴）共同锚定。

### 1.4 类似指标权威方法可行性分析概要

产业产值统计的权威口径三层：我国统计体系的**规模以上工业统计**——总产值按「生产法」当期成品价值加总（现价/不变价双轨）、增加值按「收入法/生产法」核算、利润总额取财务报表（R1，国家统计局限上口径，与 gkx 宏观码 `gmjj_jjzl_01_02_01_01 规上工业企业增加值` 同族）；深圳市「20+8」产业体系的**产业运行监测**——战略性新兴产业集群增加值按市统计局口径逐年发布（R2，gkx 17 个产业增加值码与此族对应：网络与通信/半导体与集成电路/超高清视频显示/智能终端/智能传感器/软件与信息服务/高端医疗器械/生物医药/大健康/新能源/海洋经济/智能网联汽车/低空经济与空天/新材料/绿色低碳/数字创意/现代时尚——正是深圳战新产业的官方分类）；OECD 产业结构统计手册（SNA2008）把总产出/增加值/营业盈余定义为国民账户三件套（R3）。方法族对照：

| 方法族 | 计量轴 | 数据要求 | 与三源匹配 |
|---|---|---|---|
| 规上工业统计（R1） | 总产值/增加值/利润总额 | 统计年鉴限上库 | **部分（gkx 增加值码在；总产值/利润 0 码）** |
| 战新产业监测（R2） | 产业增加值 | 产业口径核算库 | **有（gkx 17 产业 JDZ，散点化）** |
| SNA 三件套（R3） | 总产出/增加值/盈余 | 国民账户 | 部分（GDP 序列在但质量伤） |
| 企业报表汇总（dev 侧） | 营收/利润总额 | 企业财务史 | **部分（列在、覆盖 0.49%）** |

结论：增加值族是 gkx 与官方口径（R1/R2）的重叠区；总产值与利润两序列三源均无结构承载。完整版见附录 C。

### 1.6 推测原意与推测定义

本件是产值族四件的锚：X_002 的加权底册、X_018 的增长率分母、X_027 的总产值语义都引用本件主链读数（B11 批内互推）。17 产业 JDZ 表（`facts.gkx_sz_industry_added_value`）是族内共享事实——X_002 的 `gkx_sz_industry_av_latest_yi` 与本件同 SQL 同值。

## 二、计算过程

### 2.1 方法选择

产值面检索按「表名关键词 → 指标字典语义 → 量纲/口径甄别」三级漏斗：先扫三源经济类表名（output/value/economic/gdp/profit/macro 六词，gkx 命中 3 表），再在 gkx 指标字典按产值/增加值/生产总值/营收四词命中深圳侧码值，最后对命中的码做 JDZ（绝对值）与报告期双滤——第三级是本件方法关键：`dwd_macro_index_data` 的 dim_cal 有 JDZ（绝对值）/JZZ（增长率）等维度，`occur_period` 是累计报告期（202109=2021 前三季累计），年度值须 `MOD(occur_period,100)=12` 双滤，否则季度/半年累计会被误当年度值（B9）。量纲换算统一到亿元（unit_use=元 ÷ 1e8，与 UI y 轴亿元对齐）。

### 2.2 gkx 经济表扫描与语义甄别

gkx 280 表按六关键词扫描命中 3 表（`facts.gkx_econ_table_scan`）：`dwd_macro_index_data`（宏观指标值——本件主面）、`dwd_zh_project_output`/`dwd_en_project_output`（项目成果）。语义甄别：`dwd_zh_project_output` 20,133 行（`facts.gkx_zh_project_output_rows`）是**课题成果计数**（论文/专利/获奖数）非经济产值——表名带 output 但语义不同物，探针留证排除（GBA 近亲断言的复核）。dev 侧 output/gdp/added/value 表名 0 命中（`facts.dev_output_gdp_tables=[]`），仅 finance_history 三表族；久新 203 表 SHOW TABLES 六关键词 0 命中（`facts.jiuxin_econ_tables=[]`）。

### 2.3 深圳侧 28 码族谱与 17 产业增加值表（口径 A 主读数）

`dwd_macro_index_data` JOIN `dwd_dim_index_attribute` 按 area_code LIKE '4403%' + 指标名四词过滤：**28 个经济码命中**（`facts.gkx_sz_econ_index_codes`，族谱 Top：规上工业增加值 `gmjj_jjzl_01_02_01_01` 180 行 / 地区生产总值 `gmjj_jjzl_01` 98 行 / 二产增加值 67 行 / 一产 60 行 / 三产 44 行 + 23 个产业增加值码）。其中**产业增加值码有 JDZ 绝对值行者 17 个产业 24 行**（`facts.gkx_sz_industry_added_value`，每产业含 rows_jdz/latest_period/latest_yi/period_span），按最新值降序：

17 产业名与深圳市「20+8」战新产业分类高度对应（§1.4 R2 族）——分类学对齐是本件口径 A 的语义合法性来源。**报告期形态是最大硬伤**：仅 4 个产业有年末值（网络与通信/数字创意/新材料/智能网联汽车/高端医疗器械 5 个），多数停在季度/半年累计——「按年看产值」的年度立方只有零星格。

```sql
SELECT d.index_name, m.occur_period, m.index_value/1e8 AS yi
FROM gkx.dwd_macro_index_data m
JOIN gkx.dwd_dim_index_attribute d ON d.index_code = m.index_code
WHERE m.area_code LIKE '4403%' AND d.index_name LIKE '%产业增加值%'
  AND m.dim_cal = 'JDZ'
ORDER BY d.index_name, m.occur_period DESC;
-- → 17 产业 24 行 JDZ；网络与通信 202112=2046.53 亿居年度值之首
```

### 2.4 年度对齐面与 GDP 序列质量复核

产业增加值 JDZ 的年度值（%100=12）落年仅 2021/2022/2024（`base_years_used=[2021,2023,2024,2025]` 含季度最近期，`base_years_missing=[2019,2020,2022]`——2019/2020/2022 三年无任何产业年末 JDZ 行）；与 GDP 年度 JDZ 的对齐年份 = **3 年**（`derived.gkx_sz_industry_gdp_aligned_year_count`=3.0/2021+2022+2024，B10 判档依据：远够不上 UI 七年双序列）。GDP 序列自身质量伤复核（GBA 件先验零漂移）：2021 年同键 **4 个值**（`facts.gkx_sz_gdp_multi_value_years`：760.49/8,873.67/70.91/30,664.85 亿元，相差 40 倍——多源入库未清洗）、2008 年 7,806.54 亿 → 2009 年 2,336.12 亿（倒退 70%）——城市级 GDP 序列不可直接对外，产业对齐面以「有值年份计数」为口径规避绝对值引用。

### 2.5 dev 企业财务面（口径 B）：唯一「企业类型」切片候选

`enterprise_finance_history` 90,926 行 × 8,127 企业 × data_year 2014-2025（`facts.dev_fin_history_rows`/`dev_fin_history_orgs`）。按年覆盖（`facts.dev_fin_history_yearly`）：行数稳定（2014 年 5,876 → 2025 年 6,908）但**营收非空塌缩**——2014 年 752 行 → 2015 年 471 → 2019 年 65 → 2025 年 **34 行**（利润列同构：30 行）；2025 覆盖率 34/6,908=**0.49%**（`derived.dev_fin_2025_revenue_coverage_pct`，B3 同表同年）。营收样本（`facts.dev_revenue_sample`）：2025 年 Top 值 298,009/89,863/35,555 等，量纲疑似**万元**（298,009 万元=29.8 亿，与深圳中型企业量级吻合）但无字段注释佐证（B9 登记为待证量纲）。产业维 join 前提核验（`facts.dev_industry_join_tables`）：产业链映射表 `enterprise_industry_chain` 仅 **100 行**、分布表 0 行、汇总表 0 行——企业×产业关联面不足 1%，产业聚合不可行。结论：口径 B 只能作「单企业零星读数」（如某企业 2025 营收 29.8 亿），无法撑序列与聚合。

### 2.6 久新对照面与三源负证据

久新 203 表无经济金额表（`facts.jiuxin_econ_tables=[]`）；`ads_industry` 1,971 行 + `ads_institution_industry` 1,354,245 行（`facts.jiuxin_ads_industry_rows`/`jiuxin_ads_institution_industry_rows`）是**专利-产业映射维**（机构×产业×专利计数），无经济金额列——按派单书 §0.2「专利/论文只能作对照面」纪律，登记为对照面不作主口径。三源负证据汇总：总产值 gkx 深圳侧 0 码（28 码全为生产总值/增加值族）、利润 gkx 全库 0 码（`facts.gkx_profit_index_codes=[]`，字典级检索）、久新 0 经济表、dev 无产值表（仅财务史）。

### 2.7 稳健性与口径敏感性

产值读数的三个敏感性方向：**报告期敏感性**——同一产业取「最近期累计」vs「年末值」读数不同（新能源 2023Q3 753.89 亿是前三季累计，全年值应更高但无数据），横比 17 产业时报告期错位（2018H1 vs 2025Q3）使绝对值比较含时间偏移，v1 交付须带报告期标注列；**口径宽窄敏感性**——战略性新兴（4,146 亿）是 20 产业的合集口径，与其余 16 个单产业不可直接横比，图例须分层；**量纲敏感性**——unit_show（万元）与 unit_use（元）4 数量级差是全库性陷阱（B9），本件全部换算以 unit_use=元为基准并抽行验证（2021 网络与通信 204,653,000,000 元 = 2,046.53 亿，与深圳官方口径量级吻合，换算链自证）。

### 3.2 D1 增加值序列：gkx 主承载的形态与限度

17 个产业增加值码是 gkx 宏观库与深圳官方战新产业分类（R2 族）的对齐产物——分类学合法性直接来自码值体系（指标名即产业名）。限度三重：行数薄（24 行/17 产业，多数产业仅 1-2 个报告期）；报告期错位（2018H1 至 2025Q3 横跨七年）；年度值稀缺（年末 %100=12 仅 5 个产业）。「按产业横比最近期值」是当前数据形态下最稳的交付面（口径 A），「按年看趋势」只有网络与通信等 5 产业可画两点以上的稀疏线。

### 3.3 D2/D3 总产值与利润的 absence_probe 记录

否定性证据三件套：**查了什么**——总产值：gkx 指标字典深圳侧 28 码逐名核对（全为生产总值/增加值族，「产值」二字独立于「增加值」出现 0 次）+ dev/久新表名扫描；利润：gkx 指标字典全库 `index_name LIKE '%利润%'`（不限深圳）。**条件**——指标码/表名的语义级存在。**命中**——总产值 0 码 0 表；利润 0 码（dev total_profit 列 30 行级零星值是唯一残留）。四缺失情形归属：**表存在但关键语义不存在**（宏观库在、产值/利润码族不在）——修复动作是扩码（统计源接入后入 macro 体系）而非建表。

### 3.4 B9 量纲陷阱与 GDP 质量面（跨件互证）

两处全局性陷阱在本件的落证：**量纲双轨**——`dwd_dim_index_attribute.unit_show`=万元 vs `dwd_macro_index_data.unit_use`=元，同指标两处差 4 个数量级（X_001 探针抽 23 码全数核验），全批凡引用宏观库的件（GBA 系/X_002）共用此结论；**GDP 多值**——2021 年深圳 GDP 同键 4 值（76,048,720,000 至 3,066,485,000,000 元）说明宏观库多源入库未做冲突清洗，城市级绝对值引用须先过「同键唯一性」闸（本件以计数口径规避）。两陷阱均与 GBA 件先验零漂移（B11）。

## 四、数据缺失情况

### 4.1 总产值与利润序列缺失（结构级，主因）

三序列有二从缺：总产值在 gkx 无码（官方战新监测只核增加值，总产值属工业统计口径未入库）、利润在 gkx 全库无码（财政口径指标族整体缺席）；dev 的 revenue/total_profit 列是微观残留（覆盖 0.49%）且量纲未证。修复路径单一：外部统计源接入（深圳统计年鉴产业卷/工信部门产业数据库——UI 自注源 `indicatorIntro.sources` 第 1/2 项正是「国家统计数据」「工信部门产业数据库」，需求侧与升档路径指向一致）。

### 4.2 年度时间面与切片维缺失（数据级，次因）

即便增加值序列，年度对齐也仅 3/7（2019/2020/2022 三年无产业年末值）；企业类型切片（需求明文三维之一）在 dev 侧覆盖塌缩+join 面 100 行双重不足。修复动作：宏观库补采年末值（2022/2019/2020 回填）是 gkx 采集侧工程；企业类型切片需 dev 财务史的营收回填（2019-2025 年覆盖从 <1% 修复到可用水平）+ 产业映射表扩容（100 行→全量企业）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 统计年鉴/工信库接入 | 外部数据源 | 本件+X_002+X_018+X_027 | 总产值/利润序列+年度值补齐，产值族四件共同升档 |
| 宏观库年末值补采 | gkx 采集工程 | 本件 | 2022/2019/2020 产业 JDZ 年末行 |
| dev 营收回填+产业映射扩容 | dev 数据工程 | 本件+X_018+X_027 | 企业类型切片复活（0.49%→可用） |
| GDP 多源清洗 | gkx 治理工程 | 本件+GBA 系 | 同键 4 值冲突消除 |

档位后果：外部源接入 → 三序列闭合+七年满窗，升完全转换支持；仅年末值补采 → 增加值序列趋势线可用（2/3 序列仍缺，维持部分支持）；dev 面修复 → 切片维复活但序列主缺口不动。
