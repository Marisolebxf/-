## 摘要

「异常关系密度」是黑名单触发工作台「图谱指标实时监测」四卡之一（UI desc：异常边/局部边集占比，演示值 0.62 阈值 0.55，status=alert）。需求（seq 408）把它列为异常数据监测的图谱计算指标例证。数据侧判定：**部分支持**——「异常边」的业务标注真值三源全无（这是需业务建模类的典型缺口）；但久新真图的边表自带两类可疑性证据可做操作化代理：LOW 证据边占比 **0.629079**（369,428/587,252，全图口径；框内 0.626293 同向）、时间冲突边占比 **0.337860**（198,409/587,252）——两口径都已实算落产物，数值巧合地一高一低跨过 UI 阈值 0.55，恰好说明**口径选择决定告警与否**，终裁必须回甲方。

- 需求判定：**需求明列叶**（seq 408 点名「异常关系密度」），无判定方法。
- 复现状态：脚本已实算；双口径密度+分布落产物。
- 档位结论：**部分支持**（代理可算、语义真值缺位）。
- 关键事实：UI 值 0.62 是 mock 写死；LOW 口径 0.629 与之几乎重合纯属巧合（无血缘）。
- 升档路径：甲方裁定操作化口径（A/B/新设）→ 完全转换支持；标注数据落表 → 完全直接支持。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技知识图谱/指标展示/黑名单触发/异常数据监测（1.1.1.1.5.2.1.1；SRS seq 408、excel_row 411）。UI 挂载两处：黑名单触发工作台 `BlacklistTriggerPanel.jsx:147`（触发事件表列「异常关系密度」Progress 条，读 `blacklistTriggers[].relationDensity`——`mockData.js:270` 每事件写死 0.61/0.78 等）；图谱指标实时监测卡 `:240-248`（四卡之二，读 `blacklistGraphMetrics`——`mockData.js:285` value 0.62/threshold 0.55/status alert/desc「异常边 / 局部边集占比」）。另一挂载 `IndicatorDisplay.jsx:33`（融合指标卡场景复用）。三处读的全是 mock 常量。

### 1.2 为什么需要本指标

黑名单自动触发链路（监测→规则判别→入黑→联动）的第一环是**判定哪些关系是异常的**：异常关系密度把「图里可疑关联的浓度」压缩成一个 0-1 读数，配阈值（0.55）做实时告警开关——密度超阈即提示风控进入人工研判。需求把它与「节点异常度」并列为图谱计算指标的代表，说明设计意图是**图结构风险信号**（区别于规则引擎的业务规则信号）。对管理者的价值：图谱数据质量的持续监控位（边证据退化→密度上升→告警）。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**seq 408 只给功能行为（「利用图谱计算指标（如节点异常度、异常关系密度等）……实时监测，发现潜在风险链条」）——「异常」的判定标准（什么边算异常？低证据？时间冲突？外部风险标注？）一个字没有。UI mock 的 desc「异常边 / 局部边集占比」给了**分子分母形态**但没给「异常」判定维；「局部」的范围（全图？社区？N 跳邻域？）也未定义。两个口径空洞叠加，是本件判部分支持的第一根因。

### 1.4 类似指标权威方法可行性分析概要

图异常检测有三层方法谱系。其一，图异常检测综述（R1 Akoglu et al. 2015）：结构特征法（度、中心性、egonet 特征）与社区特征法两大族——「异常边/异常子图」的判定依赖特征偏离或标注，纯结构无监督判定只能给「可疑排序」不能给「异常真值」；其二，数据质量国标（R2 GB/T 36344-2018）：时效性维（0501 时间段正确性/0502 时间点及时性）与本件 TIME_CONFLICT 口径同族——把「边的时间属性自相矛盾」视为质量异常是有国标语义背书的操作化；其三，标注依赖的实践（R3 BOND 基准 2022）：节点级异常检测基准全部依赖 synthetic/organic **标注**——佐证「无标注即无真值」是领域共识。方法族对照：

| 方法族 | 判定轴 | 数据要求 | 与本库匹配 |
|---|---|---|---|
| 结构特征偏离（R1） | 度/中心性离群 | 图结构（有） | 可算代理（028 件承接） |
| 时间质量异常（R2 国标族） | 时间属性矛盾 | 边时间列（有） | **口径 B 已实现** |
| 标注真值（R3 基准族） | 风险标注 | 标注面 | **无（三源 0 命中）** |
| 证据等级代理（本件口径 A） | evidence_level=LOW | 边属性（有） | 已实现（操作化） |

结论：结构可算、语义待裁——典型需业务建模类的「方法可行、定义未闭合」。

## 四、数据缺失情况

### 4.1 异常标注面缺失（判定性缺口）

### 4.2 口径级待裁项（两层）

第一层「异常」判定维（A 低证据 / B 时间冲突 / 新设外部标注）；第二层「局部边集」范围（全图 / 社区内 / N 跳邻域）。两层叠加口径空间大，建议先裁第一层（决定告警语义）、第二层首期按全图（本件口径）。
