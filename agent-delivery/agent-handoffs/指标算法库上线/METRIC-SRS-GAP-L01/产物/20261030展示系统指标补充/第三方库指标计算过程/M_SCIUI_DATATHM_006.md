- 复现状态：脚本已跑通；三源词族排除 + 两处语义排除 + mock 聚合核全落产物。

### 1.2 为什么需要本指标

seq 345 的管理命题是「**资源被谁用得最值**」：价值占比列把调用次数（强度）升维成价值份额（结构），配合重点用户星标回答「哪些主体贡献了平台资源价值的大头」——需求原文「助力管理者识别资源价值分布及重点用户」。价值占比是这张清单的**价值结构读数**：没有它，清单只是调用次数排行；有了它，运营方可以按价值梯度做主体运营（重点用户维护/长尾激活）。「高价值」聚合读数（重点用户份额和）则是价值集中度的直接量角器——与 023 件（主体总数，覆盖面）互补构成应用状态的价值侧画像。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「高价值数据资源占比」「价值占比」字面三份真源 0 命中（附录 A.2）。需求明列的是功能（SRS 总体视窗.md seq 345 / 主需求 :2565 同文）：「支持统计和展示所有资源实际应用主体，包括科研机构、企业、项目团队，详细列出各主体调用资源的类型、次数和用途，助力管理者识别资源价值分布及重点用户」——「价值分布」是管理意图表述，无分级标准、无分摊算式、无「高价值」界定。三个口径黑洞：①价值怎么量（调用量折算？覆盖场景加权？经济估值？）；②「高价值」怎么界（分级线在哪/重点用户=高价值吗）；③占比分母是什么（全部资源价值/全部调用/全部主体数）。mock 的 isKeyUser 星标 + valueShare 列是前端作者的演示设计，不构成口径证据。核增需求与算法库 0 命中。

### 1.4 类似指标权威方法可行性分析概要

「高价值数据资源占比」的权威方法锚分三层。其一，数据资产估值（R1 DCAM/ISO 22432 系）：数据资产按成本法/收益法/市场法估值登记——「高价值」=估值分位线（如 P80 以上），占比=高价值资产数÷总资产数，前提是资产登记面带估值字段。其二，公共数据授权运营监测（R2 国家数据局监测评估指南）：授权运营产品目录+收入/调用分层——「高价值」按运营贡献度（收入/调用量）分位，官方口径以**登记+流水**为基础。其三，数据管理能力（R3 GB/T 36073-2018 DCMM）：数据资产目录化管理要求——资产目录含价值分级属性是成熟度 3 级特征，分级标准由组织自定。方法族对照：

| 方法族 | 「高价值」定义 | 数据要求 | 与三源匹配 |
|---|---|---|---|
| 估值分位（R1） | 估值 P80+ | 资产登记+估值字段 | **无（估值面缺位）** |
| 运营贡献分位（R2） | 收入/调用贡献度 | 运营流水+产品目录 | **无（价值流水缺位；调用侧见 014 族）** |
| 资产目录分级（R3） | 组织自定分级线 | 资产目录带分级属性 | **无（逻辑资产目录缺失，038 件同判）** |
| 前端演示 | mock valueShare | mockData.js | 结构披露（不作源） |

结论：三条权威路径的共同前提是**资产价值登记面**（估值字段或分级属性）——三源均无承载。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：

$$\text{HVShare} = \frac{\sum_{s \in S_{\text{HV}}} V(s)}{V_{\text{total}}} \times 100\%,\quad V(s) = \text{主体 } s \text{ 的资源价值分摊额}$$

## 四、数据缺失情况

### 4.1 资产价值分级面零承载（结构级，判定性缺口）

「资源×价值等级×评估依据」的分级登记面与「主体×资源」价值分摊面三源零承载（§3.3）——与 038 件（逻辑资产目录缺失）同根：**资产管理制度缺位**而非数据量不足。seq 345 的「价值分布」意图没有配套的价值度量基建：价值量纲未定（调用折算/收益估值/成本法）、「高价值」界定线未裁、分摊模型未建。**四缺失情形归属「表不存在」**：修复动作是分级标准立项（一纸裁定价值量纲与分位线）+ 分摊模型挂接调用日志（起步）；mock 的 valueShare-callCount 同序特征（§3.2）为调用折算起步提供了演示侧佐证。本缺口与 038 件共享资产目录基建：目录若立项，数量统计（038 直接受益）与分级属性（本件受益）一次落位。

### 4.2 mock 语义陷阱披露（方法级，防误用）

本件的语义陷阱在**派单名与 UI 列名的错位**：派单名「高价值数据资源占比」听起来像资产分级统计（资源维），但挂载点实况是主体清单的价值分摊列（主体维）——「高价值」在 UI 里的对应物是 isKeyUser 星标（重点用户），不是资源分级标记。若按派单名字面去三源找「高价值资源」分级面，方向就偏了；正确口径是主体侧聚合（重点用户份额和 33.4% 的演示形态）。本件在 §1.1/§3.2 双处披露这一错位并在 notes 写死语境核结论，后续族内件引用 valueShare 时以本件口径为准。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 资产价值分级标准立项（量纲+分位线） | 口径裁定 | 本件 + 038（目录共享） | 触发器①前置（一纸裁定） |
| 主体×资源价值分摊模型（调用折算起步） | 数据工程 | 本件 | 触发器①；mock 同序特征佐证可行性 |
| 资产登记面带估值/分级字段 | 数据工程立项 | 本件 + 038 | 触发器②（完全直接支持） |
| UI「—」占位 | 展示规范 | 本件 UI 列 | mock 份额值建议替换 |

档位后果：分级标准+分摊模型 → **完全转换支持**；登记面直查 → **完全直接支持**；现状 → 完全不支持。推荐顺序：口径裁定（即期一纸）→ 调用折算模型（v1，与 014 族调用日志共用）→ 资产目录立项（v2，与 038 共享）。
