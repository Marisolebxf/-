## 一、需求定义概述

### 1.1 所属功能模块

科技信息展示系统/科技知识图谱/**指标展示**（两处挂载）：其一，融合统计指标和模型特征 Tab——`FusionIndicatorsPanel.jsx` 消费 `mockData.js:376` 的 fusionIndicators 数组，`net_density`（网络密度）是五项融合指标的第一项：graphValue=0.32（图谱分析源）、ruleValue=0.35（传统统计源）、modelValue=0.31（模型特征源）、fusionValue=0.33（融合值）、weight=0.25（均衡场景权重，五项最高）；用户可切场景预设（risk/talent/project）改权重。其二，图查询资产深入分析抽屉——`QueryAssetDeepAnalysisDrawer.jsx` 消费 `queryAssetDeepAnalysis.js:24-30` 的 `buildDeepAnalysis`，KPI 第三格「网络密度」用公式 `density = +(edgeCount / Math.max(nodeCount*(nodeCount-1)/2, 1) * 100).toFixed(1)`（百分比形态）。两处挂载一个共同点：**公式（分子=实际边、分母=理论最大边）在前端写死，缺的是真图数据**。

### 1.2 为什么需要本指标

网络密度回答「这张图有多密」：它是图结构比较的基线读数——密度过高说明冗余关联多、过低说明覆盖不足，融合指标面板把它列为第一权重项（0.25），因为其余四项（聚类系数/平均路径/中心性方差/模块度）的「正常区间」都随密度变。查询资产抽屉用它做资产体检：用户检索到一张图资产后，密度 KPI 告诉他这张图是稀疏骨架还是密实网络，决定后续分析（路径搜索/社群发现）的适用性。对管理者的价值：图谱建设进度评估（边覆盖到什么程度了）与图谱间横向比较（技术图 vs 合作图 vs 政策图）。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**SRS《指标展示.md》seq 413-417（融合统计指标和模型特征族：指标整合/权重配置/指标关联分析/一致性检验/综合评分）只写「提供多源指标整合功能，支持将知识图谱分析指标、传统统计指标和机器学习模型特征进行统一管理和展示」——网络密度作为「知识图谱分析指标」的实例被点名在 UI 实现层（fusionIndicators 数组），公式由前端 `queryAssetDeepAnalysis.js:24-30` 给出（D=E/C(N,2)，百分比形态）。检索记录见附录 A.2。

### 1.4 类似指标权威方法可行性分析概要

网络密度是图论教科书第一课的标准量，权威锚三重齐备。其一，图论经典（R1 Harary 1969《Graph Theory》）：无向简单图密度 $D = 2E/(N(N-1))$——UI 前端原式 $E/\binom{N}{2}$ 与之数学同义（$2E/(N(N-1)) = E/(N(N-1)/2)$）；其二，NetworkX 标准库（R2 `nx.density`）：同一公式的工程实现形态，直接接受 nx.Graph 返回 0-1 比值；其三，社交网络分析经典教材（R3 Wasserman & Faust 1994）：密度作为「群结构凝聚度」第一指标的学科定位——融合指标面板把 net_density 权重设 0.25 居首，与学科惯例一致。方法族对照：

| 方法族 | 代表 | 本库承载 | 贴合度 |
|---|---|---|---|
| 图论定义（R1） | Harary 1969 | UI 原式逐行同义 | **锚** |
| 标准库（R2） | NetworkX density | 本件脚本同构复刻 | 高 |
| SNA 学科定位（R3） | Wasserman & Faust | 融合面板权重设计印证 | 高 |
| 前端演示 | mock 0.32 | 量级与真图巧合一致 | 算法可用、数据需换真图 |

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**定义（UI 公式为准，口径闭合度高——与 Harary 标准式同义）**：

$$D = \frac{E_{actual}}{\binom{N}{2}} = \frac{2E}{N(N-1)}$$

$N$=节点数，$E$=实际边数（无向简单图，重边计一次）。**两待裁项**：图的界定（久新技术图单域 or 多域混图——本件按久新技术层单域实算）；边去重口径（本件按 canonical (min,max) 去重——`jiuxin_tech_edge_endpoints` 核查 distinct_edge_id=587,252=总边数，无重复边列）。

**降档/升档触发器（B10 模板）**：①现状即可算（本件已验证）→ 维持完全转换支持；②预计算任务落表（夜批算全图密度存结果表）→ 升**完全直接支持**；③若久新技术图下线且仅剩 dev 空壳 → 降部分支持；④若需多域混图 → 需先建跨域边（现无），混图场景维持转换档但口径另裁。

### 2.1 图构建（确定性采样框，B5）

### 2.2 三口径密度实算

| 口径 | N | E | 密度 | 产物键 |
|---|---|---|---|---|
| 久新全图直查（量级参考） | 19,430 | 587,252 | **0.3111%** | `derived[0].density_pct` |

**B3 同基披露**：全图直查口径的分子（587,252 全边）与分母（C(19,430,2)）同池同基——它是合法读数，但与框内口径不可混用：框内 0.336331% 高于全图 0.3111%，因为 5,000 框是 node_id 前缀框、框内节点间连边密度略高于全图平均（前缀框偏向）。对外引用建议随行注明口径；融合面板回填建议用全图直查口径（面板语义是「整张图谱」的密度）。mock 值 0.32 与真图全图 0.3111% 量级巧合一致（0.32 若读作比值是 32%，若读作密度比值则真图为 0.0031——**mock 的 0.32 是「拍脑袋的经验值」，恰与真图 0.31% 的百分数值同字面**，前端接入时必须统一量纲，B9）。

### 2.3 读数解释

技术图密度 0.31-0.34% 属**稀疏大图**量级：19,430 节点的完全图有 1.89 亿条理论边，实际 58.7 万边占 0.31%——这与「技术关联图谱」的语义一致（一个技术与少数强相关技术连边，不可能全连通）。gkx 合作图 0.0084% 更稀疏（合作网天然稀疏）。读数用途：①图谱健康度监测（边覆盖进度）；②图谱间比较（技术图密度是合作图的 40 倍——技术关联比人际合作更聚集）；③融合指标基线（密度决定聚类/路径指标的正常区间）。

### 2.4 与 UI 演示形态的衔接

UI 现状：融合面板喂 mock 常量（0.32 等），查询资产抽屉喂 seededInt 随机图（18-86 节点）。接入真图路径：node/edge 两表直连（本件验证的结构）→ 前端 KPI 公式零改动（节点数边数直查即得）→ 融合面板三源值位（graphValue 用本件实算值；ruleValue/modelValue 语义见 §4.2 待裁项）。全图两计数 SQL 毫秒级——本件无需夜批预计算即可直查回填（密度是本族唯一「直查即得」的图指标）。

### 2.5 稳健性与口径敏感性

**（a）采样框边界**：框内读数（0.336331%）受前缀框偏向影响（node_id 序非随机）；全图直查读数（0.3111%）无此问题——本件全图口径分子分母均直查自全表，无采样，是更稳健的对外口径。**（b）边去重口径**：distinct_edge_id=587,252=总行数（`jiuxin_tech_edge_endpoints`），说明边表无重复行；但 (source,target) 与 (target,source) 是否成对存储未逐边核查——本件按 canonical (min,max) 去重后框内 38,383 边与 KGANALY_001 未去重读数 38,383 一致，证明边表无成对重复（若成对存储，去重后会减半）。**（c）有向/无向**：UI 公式按无向 C(N,2) 分母；边表有 direction_status 列（有向标注），本件按无向处理（与 UI 同构）——若甲方裁定为有向图密度（分母 N(N-1)），数值减半，属口径级待裁项。

## 四、数据缺失情况

### 4.1 现成结果面缺失（唯一结构缺口，非判定性）

三源无密度结果表（`absence_probe`）——「完全转换支持」而非「完全直接支持」的唯一原因。修复最轻量：密度只需两条 COUNT SQL（毫秒级），展示层直查即可，无需夜批——本件是族内唯一「直查即得」的图指标。

### 4.2 融合三源语义与量纲（口径级）

两个待裁项：其一，**融合值位的三源语义**——fusionIndicators 给 graphValue（图谱分析）/ruleValue（传统统计）/modelValue（模型特征）三位值，图谱源本件已实算，但传统统计源与模型特征源对「密度」取什么值（例如传统统计源=实体共现表密度？模型源=训练图密度？）SRS 未定义，需产品裁定；其二，**量纲裁定**——mock 0.32 与真图 0.3111% 的字面巧合（B9）：前端接入必须统一（建议 KPI 用 %形态、融合卡用 0-1 比值形态并在 UI 标注单位）。另：有向/无向口径（§2.5c）随量纲一并裁定。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 前端直连久新两表 COUNT | 前端工程（轻量） | 本件 + 全族 | 即期回填 graphValue/KPI |
| 融合三源语义定义 | 产品决策 | 本件 + 040/038/049 | rule/model 位取值待裁 |
| 量纲与有向口径裁定 | 口径裁定 | 本件 | % vs 比值、无向 vs 有向 |

档位后果：现状 → 完全转换支持（直查即得）；预计算落表 → 完全直接支持；久新图下线且 dev 仍空 → 部分支持。推荐：先直查回填图谱位与 KPI 位（零工程量），融合语义并行裁定。
