## 四、数据缺失情况

### 4.1 业务应用调用台账零承载（主口径·结构级，判定性缺口）

主口径（UI 挂载语境）的承载前提是业务应用×调用量台账（应用标识×调用×时间）——三源零承载（§3.3），与调用台账族（020/021/022/025/032/034/035）同根。**四缺失情形归属「表不存在」**：修复动作是 API 网关日志/调用台账接入（应用标识列必带），族级并项一次建设。

### 4.2 评估结论面零承载与成果维半稀疏（层2·结构级+数据级）

层2 口径（若甲方裁定）的判定性缺口是**评估结论面**：权威框架（R1）要求的任务书指标、结题材料、评审结论三源皆无——gkx 只有登记字段，久新画像稀疏且无结论维。次生缺口是**成果维半稀疏**（正向成果 14.71%）：项目-成果关联面在（join 覆盖好）但产出计数大量为 0/空——成果回填可先行提升代理质量。四缺失情形：评估面「表不存在」；成果维「表存在但数据稀疏」（补采可升）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 调用台账接入（应用标识列） | 监控工程立项（族级） | 本件主口径 + 032/034/035 + 020-022 | 触发器①（族级共用） |
| 评估结论面立项 / 成果代理口径裁定 | 口径裁定+数据工程 | 本件层2 | 触发器②③（F 形式甲方定） |
| gkx 成果维回填 | 数据治理 | 层2 成果代理质量 | 正向成果 8,601→提升 |
| 久新画像字段治理 | 数据治理 | 层2 时间/金额维 | 4.03%→提升 |
| UI 应用名披露 | 展示规范 | 本件 | mock 序列标注「演示示例应用」 |

档位后果：台账建成 → 主口径**完全直接支持**；成果代理裁定 → 层2 **完全转换支持**（存量+成果现在可算）；评估面立项 → 层2 升档；现状 → 完全不支持（主口径）。推荐顺序：台账族级并项（主线）、成果代理口径裁定（零成本即期）、成果回填与画像治理（轻路径）。
