### 1.4 类似指标权威方法可行性分析概要

「华人/海外人才」统计在官方体系有三条先例。其一，教育部序列统计：1978–2018 年出国留学 600 万人次、留学回国 370 万人次（R1）——官方以**留学经历**（出入境记录+学历学位认证）为判定轴，而不是姓名或族裔；其二，十部门《关于进一步做好留学人才回国服务工作的意见》（R2）把服务对象定义为"留学回国人才"，同样是经历口径；其三，OECD DIOC 以 **country of birth**（出生国）判定移民与族裔构成并推技能移徙率（R3）。三种权威口径都不依赖姓名代理。方法族对照：

| 方法族 | 判定轴 | 数据要求 | 与本库匹配 |
|---|---|---|---|
| 留学经历口径（教育部） | 出入境+学位认证记录 | 认证数据源 | **无（需新数据源）** |
| 出生国口径（OECD DIOC） | country of birth | 学者出生国字段 | **无字段** |
| 姓名代理（本项目可行近似） | 中文名含 CJK | name_zh | 有但**无区分度** |

## 二、计算过程

### 2.1 装载与规模校验

经 `_gkxdb.py` 连接 gkx 只读库（批次统一纪律）。主档 21,316 行与共享快照、`GKX_INVENTORY.json` 三方对账零漂移。姓名字段规模：`name_zh` 非空 20,420 行、`name_en` 非空 21,236 行——双语覆盖率高，为姓名代理提供了完整的试验面，但也正因覆盖率高，代理结果才暴露出池级失真（§2.3），这是"数据很全、结论不可用"的典型情形。

### 2.2 中文姓名判定

CJK 判定在 Python 侧完成：拉取全部 `name_zh` 非空值，用 Unicode 区间 `\u4e00-\u9fff` 正则逐一匹配。之所以不写在 SQL 里，是因为该 MySQL 实例（9.7.0-commercial）的 ICU regexp 不支持 `\x{4e00}` 转义写法、字面区间在部分 charset 下报 3697 错误，Python 侧判定是确定性等价且可复放的替代（实测 20,420 行拉取 <2 秒，无性能代价）。判定结果：20,420 行**全部**含 CJK（100%）——即"有中文名"与"中文名含汉字"在本库完全同义，name_zh 列不存在"拉丁字母填进中文名字段"的脏数据。

```python
# CJK 判定在 Python 侧（MySQL ICU regexp 不支持 \x{}，字面区间报 3697）
import re
CJK = re.compile(r"[\u4e00-\u9fff]")

cur.execute("SELECT name_zh FROM gkx.dwd_scholar "
            "WHERE name_zh IS NOT NULL AND name_zh != ''")
zh_names = [r[0] for r in cur.fetchall()]
chinese = sum(1 for n in zh_names if CJK.search(n))
# → nonnull=20420, with_cjk=20420（100%）
```

MySQL 侧等价写法（ICU regexp 支持字面区间）：`name_zh REGEXP '[一-龥]'`，机构统计 SQL 即用此形态；两种写法在同一 collation 下结果一致，主判定选 Python 侧只因需要对全列逐行断言且避免方言差异。

### 2.3 全库中名率：一个"正确但无意义"的读数

$\text{share}_{cn}^{all} = 20{,}420 / 21{,}316 = 95.7966\%$。按口径 A 的字面定义，这就是"华人占比"，且数字精确可复算；但它实际上度量的是**采集池的人员构成**：该学者库以中文学术圈为主（中文名几乎人人都有），所谓"非华人"只有 896 人。若把这个 95.80% 直接搬到 UI 堆叠柱上，用户会读出"全球 96% 的科技人才是华人"——一个荒谬的结论。这正是 B1 键名纪律的反面教材：数字能过闸、语义完全错。本件把这个读数改名为 `chinese_name_share_pct_global`（中名率），并在产物 notes 里写死"仅作池性质证据，不得作为华人占比对外展示"。

### 2.4 分区（国家）分布：需求语义的真实承载

在任履历（is_current=1）→ 机构英文名 → 大学表 `name_std` 精确等值 → `country`，得到可映射子盘 8,438 人（共享件口径），Top12 国家学者数：China 1,630 / United States 1,339 / United Kingdom 735 / Brazil 356 / Australia 286 / India 269 等（Top12 合计 5,798，占子盘 68.7%）。口径 B 的计算路径就是在这张国家分布表上对"country ≠ China"的子盘统计中名率——链路已通、SQL 已写好（产物 `top12_countries_scholars` 键），唯一缺口是子盘只覆盖全池 39.6%，分区读数会系统性偏向高校所在国。

```sql
SELECT u.country, COUNT(DISTINCT we.scholar_id) AS n
FROM gkx.dwd_scholar_work_experience we
JOIN gkx.dwd_forg_university_org_info u
  ON CONVERT(u.name_std USING utf8mb4) COLLATE utf8mb4_general_ci
     = CONVERT(we.org_name_en USING utf8mb4) COLLATE utf8mb4_general_ci
WHERE we.is_current = 1
  AND u.country IS NOT NULL AND u.country != ''
GROUP BY u.country
ORDER BY n DESC
LIMIT 12;
-- → China 1630 / United States 1339 / United Kingdom 735
--   Brazil 356 / Australia 286 / India 269 / …（Top12 合计 5798）
```

### 2.5 机构华人占比（需求第二分句）实测

对"在任学者数 ≥20"的机构按学者数 Top8 统计：中南大学 30 人（中名 30，100%）、浙江大学 29（100%）、武汉大学 28（100%）、西北工业大学 27（100%）、北京理工等——Top8 全部为中国高校，中名率无一例外 100%。这个结果一方面验证了机构筛选链路的可用性（分组、计数、占比一次跑通），另一方面把 §2.3 的池属性结论推到机构粒度：需求举例的"麻省理工学院华人教师统计"这类海外机构读数，在本子盘内有数（MIT 在可映射机构清单中），但权重被中国高校淹没。正式交付建议海外机构单独成榜。

```sql
SELECT u.name_std, u.country,
       COUNT(DISTINCT we.scholar_id) AS scholars,
       COUNT(DISTINCT CASE WHEN s.name_zh REGEXP '[一-龥]'
                           THEN s.scholar_id END) AS cn
FROM gkx.dwd_scholar_work_experience we
JOIN gkx.dwd_scholar s ON s.scholar_id = we.scholar_id
JOIN gkx.dwd_forg_university_org_info u
  ON CONVERT(u.name_std USING utf8mb4) COLLATE utf8mb4_general_ci
     = CONVERT(we.org_name_en USING utf8mb4) COLLATE utf8mb4_general_ci
WHERE we.is_current = 1
GROUP BY u.name_std, u.country
HAVING scholars >= 20
ORDER BY scholars DESC LIMIT 8;
-- → Top8 全为中国高校，cn_share_pct 全部 100.0
```

### 2.6 稳健性与口径敏感性

姓名代理的两向误差定性评估：**误纳**——有中文名的外籍学者（华裔外籍、汉学家、中国配偶随姓等）会被计入华人；**漏判**——无中文名的华人（早期移民、完全英文名化的华裔）会被排除。两向误差方向相反、量级无法从库内闭合（没有任何外部锚点可校），所以代理口径的绝对数不可信，只能用于相对比较（同一判定规则下的组间对比）。替代锚点的探测：教育部留学统计（R1）给的是全国总量（370 万回国人次），无法下钻到学者个体粒度做池内校准；OECD 出生国口径需要的数据本库无。结论：代理只能降级为"组内相对指标"，绝对占比对外展示必须换口径（B10 双口径并列已写死）。

### 3.2 D1 姓名代理：数据很全、结论不可用

`name_zh` 非空 20,420 行，非空率 95.80%，且实测非空行 100% 含 CJK 字符——这一行说明采集端把 name_zh 当"真中文名"字段维护，没有拉丁字母误填。但正是这种高覆盖，让姓名代理彻底失效：当 95.8% 的学者都有中文名时，"有中文名"不再携带任何族裔信息。换句话说，代理轴的失效不是缺数据造成的，而是数据太好造成的——池本身就是华人主导的学术圈。这是本件最反直觉的事实：按常理"数据缺失才降档"，本件却是"数据齐全且仍降档"。

### 3.3 D2 判定维的 absence_probe 全记录

否定性证据三件套：**查了什么**——`SHOW COLUMNS FROM gkx.dwd_scholar` 输出全部 27 列逐一核对（dwd_id, id, scholar_id, name_en, name_zh, avatar, scholar_org_name_en, scholar_org_name_zh, scholar_department_name_en, scholar_department_name_zh, scholar_org_id, orc_id, bio, bio_zh, paper_nums, citation_nums, h_index, status, created_time, updated_time, creater, updater, table_data_source, operator_remarks, is_deleted, insert_remark, reference_nums），另对 gkx 280 表名做 national/ethnic/birth/country 关键词扫描；**条件**——字段级存在性（非行数级）；**命中**——0。四种缺失情形的归属：**表存在但关键列不存在**，修复动作是加列或换源，不是补数据。

### 3.4 D3 国家链路：分区展示的骨架

在任履历→机构名→大学表 `country` 的链路给出可映射子盘 8,438 学者（全池 39.6%），Top12 国家分布：China 1,630 / United States 1,339 / United Kingdom 735 / Brazil 356 / Australia 286 / India 269 等，Top12 合计 5,798（子盘 68.7%）。这张分布表是口径 B（海外机构中名率）的计算骨架：对 country ≠ China 的子集统计中名率即可，SQL 与本件同链路。但子盘偏差必须随行披露：高校学者占比过高（大学表只覆盖高校），企业/院所华人学者缺席，区域读数会向高校所在国聚集。

### 3.5 机构粒度链路验证（需求第二分句）

对在任学者数 ≥20 的机构 Top8 统计：全部为中国高校（中南大学 30 人、浙江大学 29、武汉大学 28、西北工业大学 27 等），中名率全部 100%。这组读数一石二鸟：其一，验证了"机构筛选"的分组计数占比链路完整可用；其二，把 §3.2 的池属性结论下沉到机构粒度——连"顶尖机构"子集都是中国高校主导，海外机构（含需求原文点名的麻省理工学院）必须单独成榜才有可读性。MIT 在可映射机构清单中存在，子盘内可查。

## 四、数据缺失情况

### 4.1 判定维缺失（结构级，主因）

「华人」判定的权威轴——出生国（OECD DIOC 口径，R3）、国籍、族裔——在两库均无字段；absence_probe 全记录见 §3.3（27 列逐一核对 + 280 表关键词扫描，命中 0）。四缺失情形归属：**表存在但关键列不存在**。修复动作只有两个方向：加字段（工程大、回填难——出生国无法从履历推断，需学者本人申报或权威库对齐）或换判定轴（留学经历轴，走外部数据源，见 4.3）。

### 4.2 代理轴的可用性缺口（次因）

即便退到姓名代理，其绝对读数（95.80%）也因池属性失效（§2.3）；两向误差（误纳外籍中名者 / 漏判无中文名华人）没有任何库内锚点可校准。相对读数（口径 B 海外机构子盘）可用但受地理覆盖钳制——子盘 8,438 学者只占全池 39.6%，且高校集中。这条缺口的修复与 `M_TALENT_UI_GLOBAL_STOCK` §4.1 是同一个工程（非高校机构地理编码），不重复立项。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 口径 B 先行（海外机构中名率） | 产品决策 | 本件即期可交付 | 子盘覆盖度须随行披露 |
| 接留服中心认证数据 | 外部数据源 | 本件（升级判定轴） | R2 体系；"留学经历"判定最准 |
| 学者出生国字段回填 | 字段工程 | 本件 + OECD 口径对齐 | 工程大，不推荐先行 |

三条路径的档位后果：口径 B → 仍部分支持但语义闭合（子盘披露）；认证数据 → 可升完全转换支持；出生国字段 → 完全直接/转换支持。推荐组合：即期走口径 B，中期推动认证数据源立项。
