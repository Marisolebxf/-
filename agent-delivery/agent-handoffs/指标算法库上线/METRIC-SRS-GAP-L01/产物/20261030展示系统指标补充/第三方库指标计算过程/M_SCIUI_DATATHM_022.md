### 1.2 为什么需要本指标

累计调用与趋势分析的管理问题是「资源被用的走势如何」：单点同比（021）看年度动能，年度序列（本件）看**整段生命周期形态**——起步期/放量期/平台期的拐点识别，「判断资源应用热度和生命周期，优化资源运维策略」（:2571 原文）。序列读数比单点读数多一层时间维要求：不止本年/上年两期，而是基期至当年的**逐期跨年覆盖**——这对日志原料的时间跨度要求更严（R1 水平法要基期与末期、逐期环比要中间各期）。本库场景下，该读数要求调用动作被跨年记录（接口×时间戳×次数的日志），没有跨年调用日志，任何内容面数据都与「历年被用了多少次」无关。

### 1.3 需求文档是否给出定义方法

**三份需求说明书未出现「调用量年度增长趋势」指标名。**语义锚两处：主需求 :2563（资源接口状态跟踪）「通过API日志采集与接口调用分析，动态跟踪每个资源接口的连接活跃度、调用频率和失败率」；:2571（1.1.1.1.4.4.1.4.4 累计调用与趋势分析）「采用大数据统计技术，自动归集各类数据资源自上线以来的累计调用量，并按时间区段进行趋势分析」——功能在、且**需求自点名工程前提**（API 日志采集/归集累计调用量）；「年度增长趋势」的序列口径（时间区段取年度？列结构总量/新增/同比三列？基期如何定？）均无定义。核增需求与算法库 0 命中（附录 A.2）。

### 1.4 类似指标权威方法可行性分析概要

「年度增长趋势」的权威方法锚分三层。其一，国家统计局平均发展速度/平均增长速度口径（R1）：序列趋势的标准度量是水平法（几何平均法）——环比发展速度连乘开 n 次方，平均增长速度=平均发展速度−1；强调**序列各期与基期**的时间维要求。其二，政府数据开放的年度增长官方叙事（R2 开放数林指数）：地方平台有效数据集总数 2017 年 8 千多个 → 2025 年近 48 万个，八年近 57 倍、复合年均增长率 66%——**跨年序列聚合+复合增速披露**的标准形态（其度量对象是数据集开放量，调用量序列须由调用日志聚合，语义分界与 021 同）。其三，开放平台调用统计实践（R3 深圳平台）：接口调用量累计 373,575,274 次逐接口计数——调用日志聚合的官方形态，是本件序列读数的目标态原料。方法族对照：

| 方法族 | 代表 | 原料 | 度量对象 | 与三源匹配 |
|---|---|---|---|---|
| 统计序列增速（水平法） | R1（统计局） | 跨年序列面 | 任意统计量 | **无跨年调用面** |
| 开放数据年度增长叙事 | R2（开放数林） | 年度序列统计 | 数据集开放量 | 数据量面在（≠调用量，语义错位） |
| 开放平台调用统计 | R3（深圳） | 调用日志 | 接口调用次数 | **无调用日志** |
| 前端演示 | UI mock 序列 | mock 常量 | — | 结构披露（不作源） |

结论：权威口径的原料（跨年调用日志序列面）三源零承载；R2 的数据集增长序列与调用量是两个度量对象，不可混同（DATAOV_002 已按接入口径单独成件）。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：按 R1 水平法口径推测

$$\text{TrendSeries} = \left[(y, \text{Calls}_y, \Delta_y, \text{YoY}_y)\right]_{y=y_0}^{Y},\quad \Delta_y = \text{Calls}_y - \text{Calls}_{y-1},\quad \bar{g} = \sqrt[n]{\frac{\text{Calls}_Y}{\text{Calls}_{y_0}}} - 1$$

即年度调用量序列（年份×总量×新增×同比）+ 区间复合增速（水平法），按接口聚合可下钻。**前提是跨年调用日志面存在（接口×时间戳×次数、覆盖基期至当年），三源实测无（§3.3）**——公式列示仅作口径锚，不构成可执行计算（F4：本件 §二 从缺）。

## 四、数据缺失情况

### 4.1 调用日志跨年序列面零承载（结构级，判定性缺口）

年度序列的原料（基期至当年逐期调用次数）要求调用动作被**跨年**记录。三源实测零承载（§3.3）——**服务侧从未留痕**：数据资源的「被使用」发生在 API 网关/服务层，该层日志未落库；最近邻 sys_log 仅 3.5 个月且为管理操作语义，连时间维最低要求都不满足。需求 :2571 把「自动归集累计调用量」写进功能（前提自宣），工程未建。**四缺失情形归属「表不存在」**：修复动作是调用日志接入（网关日志/APM/访问计数），与 020（耗时维）/021（两期维）共用——一次接入，调用监控三件套全升档，且 seq 343-344 的服务可用性/接口响应/异常告警/调用分析族同时受益。**序列特有披露**：接入后序列只能自接入年度起累加，接入前历史无回溯源（除非网关留有存量日志可回补）——UI mock 展示的 2022-2026 五年在真实接入后需按实际覆盖年份截断。

### 4.2 代理路径不存在（方法级，与 DATAOV_002 的分界）

内容年份面代理在本件不成立（§〇 论证：产出时间≠使用时间）——这决定了本件判完全不支持而非部分支持。`:621` Card 与导出 sheet 的 mock `overviewAnnualAccessTrend` 本体是「资源接入」年度趋势，DATAOV_002 按该语义用内容年份面代理（部分支持）；本件按 UI 标签「调用量」语义核验——若强行用内容面年分布充当「调用量趋势」，会把「库内产出增长」冒充「服务使用增长」，语义完全失真——B10 禁止。同一 mock 两种语境、两种判档，是本批口径裁定的典型案例。唯一合法路径是触发器②（甲方裁定代理口径+先立项相应日志采集），库内无即期方案。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| API 网关/调用日志接入 | 监控工程立项 | 本件 + 020 + 021 + seq 343-344 族 | 触发器①（族级共用）；接入前历史标缺 |
| 导出 sheet 与 Card 置空规范 | 展示规范 | 本件即期 | mock 五年序列建议替换「暂无数据」 |
| 序列口径预定义 | 口径裁定 | 日志接入时同步 | 时间区段（年度）、列结构（总量/新增/同比）、基期规则 |

档位后果：日志接入 → **完全直接支持**（序列自接入年起）；现状 → 完全不支持（无中间档——代理路径不存在）。推荐：随族级监控工程立项，本件不单独处置。
