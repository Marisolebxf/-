- 复现状态：脚本已跑通；三源时间列分布全落产物（负证据）。
- 档位结论：**完全不支持**（negative_evidence，探针三件套在案）。
- 关键事实：即使最宽松的「日均增量」口径也不可得——久新单版本快照无第二版本可比；gkx 回填分布只能算 ETL 吞吐（07-24 单日 112 万条=94.5%）。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技知识图谱/服务展示/图分析集成/实时数据分析与动态监控（1.1.1.1.5.3.2.3；SRS seq 452、excel_row 455）。UI 实际挂载：`realtimeMonitor.js:5-10` 定义 MONITOR_METRICS 四读数（entityRate/relationRate/queryLatency/errorRate），本件是第二卡 `:7` relationRate（label=关系增量/分钟，unit=条，threshold=380，warnHigh=true）；`RealtimeMonitorPanel.jsx` 消费：`:26-36` useEffect setInterval 3,000ms 调 `tickMonitorSnapshot`（随机游走 ±9% jitter，下限 50），`:42-49` 趋势折线（实体增量/关系增量双线，保留 24 个历史点），`:64-87` 四 Statistic 卡+阈值进度条（超阈值橙色告警），`:90-105` detectMonitorAlerts 生成告警 Alert。语义：**分钟级吞吐率监控**——每分钟新入库的关系边条数。

### 1.2 为什么需要本指标

知识图谱是持续生长的数据资产：新论文入库带来新引用边、新专利带来新共现边。关系增量/分钟回答两个运营问题：其一，**接入健康度**——增量骤降说明上游 ETL 断流（正常应有稳定增量）；其二，**异常突增预警**——短时海量边入库（如批量回填或攻击性写入）可能压垮图计算任务，threshold=380 条/分钟的告警线就是这个用途。它是「动态监控」需求句（「实时展示波动趋势、预警异常情况」）最直接的读数落点。与静态图谱统计（总量类）不同，本件监控的是**变化率**——这要求数据侧有时间维，而时间维正是三源的共同缺口。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**seq 452 只给行为（「能够接收实时数据流，对重点业务指标及监控点进行快速分析，实时展示波动趋势、预警异常情况」），「关系增量/分钟」的字面定义（窗口=1 分钟的边入库计数）由 UI 常量闭合（threshold 380/单位 条/分钟）。定义本身无悬念——缺口全在数据侧：分钟窗口要求事件流或逐条时间戳，这在三源均不存在（§〇 absence_probe）。

### 1.4 类似指标权威方法可行性分析概要

流式接入监控在工业界有标准做法。其一，Metrics 体系标准（R1 Prometheus counter+rate()）：计数器差分除窗口——`rate(edge_ingested_total[1m])` 即本件语义的监控工业形；其二，数据工程流水线监控（R2 Apache Kafka Streams 指标文档）：吞吐率=单位时间处理消息数，配阈值告警；其三，中国官方统计语境（R3 国家统计局「规模以上工业增加值增长速度」方法）：增速=报告期增量/基期存量——年度口径的同构思想。方法族对照：

| 方法族 | 代表 | 本库承载 | 贴合度 |
|---|---|---|---|
| counter+rate 窗口差分（R1） | Prometheus | **无 counter 面**（三源无事件流） | 方法可行、数据无承载 |
| 流吞吐监控（R2） | Kafka | 无流接入层 | 同上 |
| 增量率统计（R3） | 统计局 | 久新快照总量有、无第二期 | 仅思想参考 |

结论：方法侧零悬念（窗口计数），数据侧三源连最低原料（时间戳序列）都没有——方法文献只是佐证「指标本身定义清晰」，不能改变无承载判定。

## 四、数据缺失情况

### 4.1 时间维全缺（结构级，主因）

分钟级事件流三源不存在（`absence_probe` 三件——D1/D3/D5 全为「表不存在」级缺失）。修复只有一条正路：**接入层事件流立项**（Kafka/Flink CDC 落边入库事件表，含 event_time 列）——这是新数据源工程，非现有库表转换可得。折中路径：久新图批处理保留历史版本（每批落快照表，data_version 区分）→ 可算快照间增量（天/周级），但**不满足 UI 的分钟级语义**——降级口径须产品侧确认。

### 4.2 UI 面板的连带影响

监控面板四卡（007 本件/022 实体增量/035 接入错误率/+queryLatency）同吃一份数据流——本件负证据对 022/035 直接适用（同结构同判）；queryLatency 未派件但同判可预期。面板整体在数据侧落空，UI 现状的 setInterval 模拟是唯一「数据源」。建议：面板先下线或明确标注「演示」，待事件流立项后逐卡点亮。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 接入层事件流立项（event_time 事件表） | **新数据源** | 本件 + 022/035 + 043 | 唯一满足分钟级语义的路径 |
| 久新图快照版本保留 | 数据工程 | 本件 + 022 | 升部分支持（天/周级） |
| UI 降级口径（日均增量） | 产品决策 | 本件 + 022 | 依赖快照版本 |
| 面板标注「演示」 | 前端 | 四卡 | 防误导 |

档位后果：事件流 → 完全转换支持（分钟级）；仅快照版本 → 部分支持（降级粒度）；现状 → 完全不支持。
