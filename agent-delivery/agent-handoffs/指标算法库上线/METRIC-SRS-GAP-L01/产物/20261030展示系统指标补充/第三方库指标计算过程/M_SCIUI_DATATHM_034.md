### 1.2 为什么需要本指标

资产应用总览（seq 376 所在功能组）的管理命题是「**哪些数据资产在实际业务中最具活跃度和价值**」（需求句原文）：排行榜是这一命题最直接的回答——位次即资源价值的序可视化。权威对应物是公共数据开放平台的接口调用 TOP 榜（R2 深圳「接口调用总量 TOP10 + 近七日调用 TOP10」双榜 / R3 北京「最热接口」排序页）——按调用量对数据服务做 Top N 排序是开放平台运营的标配形态。本库场景下，该榜要求资产级调用统计与资产登记双前提——缺一则榜无从排起。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**seq 376 功能句（SRS 应用视窗.md:3-18 / 主需求同文）：「自动统计并展示各数据资源被调用和使用的排行情况，支持按时间、应用主体或业务领域进行排序，帮助用户直观了解哪些数据资产在实际业务中最具活跃度和价值」——排行对象（数据资源/数据资产）与排序键（被调用和使用的次数）在需求句内；但算式（按时间窗怎么取？）、Top N 深度（Top 5/10/全量？）、并列位次规则（同调用量怎么排？）均无定义。核增需求与算法库 0 命中（附录 A.2）。UI 的 7 条 mock 与下标位次是前端演示约定，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

「调用量 Top 榜」的权威方法锚分三层。其一，国家数据资源统计面（R1 国家数据局 2025 调查报告）：政务数据共享枢纽调用次数按枢纽级汇总（5,500 亿次）——官方只做总量纲，榜级排序下放地方平台；头部平台企业数据流通规模均值是其他企业 140 余倍的表述说明「头部集中」是官方关注的分布形态。其二，地方开放平台 TOP 榜实践（R2 深圳 / R3 北京）：双时间窗（累计+近七日）Top10、按接口粒度排序——粒度与深度由平台定义，原料是接口级调用日志。其三，库内排名面：dev `enterprise_ranking`（企业排名，0 行）/ 久新 `ads_research_problem_competition_rank`（46,835 行，科研问题竞争主体排名）——排名结果面存在但对象轴均非「数据资产」。方法族对照：

| 方法族 | 代表 | 排序对象 | 排序键 | 原料 | 与三源匹配 |
|---|---|---|---|---|---|
| 开放平台 TOP 榜 | R2 深圳 / R3 北京 | 数据接口/数据集 | 调用量（双窗） | 接口级调用日志 | **无日志** |
| 官方总量纲 | R1（国家数据局） | 共享枢纽 | 调用次数总量 | 逐笔落账制度 | **无台账** |
| 企业/科研排名面 | dev enterprise_ranking / 久新 competition_rank | 企业 / 科研竞争主体 | 综合分/文献计量 | 已有结果面 | **语义排除**（非资产） |
| 前端演示 | UI assetRanking | mock 资产 | mock calls | mock 常量 | 结构披露（不作源） |

结论：榜单的对象轴（数据资产登记）与依据轴（资产级调用量）三源均无承载——双缺。完整版见附录 C。

## 四、数据缺失情况

### 4.1 资产×调用量台账零承载（结构级，判定性缺口·前提一）

Top 榜的排序依据是资产级调用量统计。三源实测零承载（§3.3）——调用监控工程缺位与调用台账族（020/021/022/025/032/035）共享同一根因。**四缺失情形归属「表不存在」**：修复动作是 API 网关日志/调用台账接入，一次建设族内七件升档。

### 4.2 资产登记轴零承载（结构级，判定性缺口·前提二）

「数据资产」的编目边界（哪些库/表/接口/主题库算一项资产）三源无登记面（DATAOV_001 资产目录缺口同根）。即便台账建成，没有资产白名单则聚合粒度无法闭合（mock 的 7 条「主题库/数据集」粒度本身即是编目产物）。双前提叠加是本件完全不支持的结构性根因——这也是本件与纯调用量件（032）的判据差异：032 缺一前提（台账），本件缺双前提（台账+登记轴）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| API 网关/调用台账接入 | 监控工程立项（族级） | 本件 + 020/021/022/025/032/035 | 前提一（依据轴） |
| 资产登记面立项 | 数据工程立项 | 本件 D2 + DATAOV_001 族 | 前提二（对象轴） |
| Top N 深度与并列规则裁定 | 口径裁定 | 本件 | 深度（5/10/全量）与同值位次规则须甲方定 |
| UI 暂无数据态 | 展示规范 | 本件 | mock 7 条建议替换为「暂无数据」 |

档位后果：双前提建成 → **完全直接支持**；第三方监测+白名单裁定 → **完全转换支持**；现状 → 完全不支持。推荐顺序：两线并行立项（台账工程族级共用、登记面与 DATAOV_001 并项），口径裁定即期（零成本）。
