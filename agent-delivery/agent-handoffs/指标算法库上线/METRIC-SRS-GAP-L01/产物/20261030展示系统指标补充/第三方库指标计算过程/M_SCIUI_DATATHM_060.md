### 1.2 为什么需要本指标

等级分布回答「归集资源的质量整体落位在哪几档」：管理者看优/良占比判断接入渠道的整体质量水位、看中/差占比定位问题资源规模——它是行级等级（058）向上汇成的**组级分布形态**。需求把它实现为明细表的分组视图（seq 351 来源分析的探索工具之一），与「按来源渠道」「按数据种类」两个分组维并列——质量作为第三条透视轴。权威对应物是 R2（Dataphin）质量分分布：表质量分按分数段/规则通过率做分布统计——分布是治理平台的标准读数形态。本库场景下，该读数要求「资源×等级」稽核面 + 枚举聚合两层——没有稽核面，任何等级分布都无从分组。

### 1.3 需求文档是否给出定义方法

**需求文档未给出分布的定义方法。**「质量等级分布/等级分布」字面三份说明书 0 命中——本读数仅见 UI 分组选项（GROUP_OPTIONS）。语义锚承 058：SRS 接入视窗 seq 352「数据质量等级」为行级属性项；主需求 :2629「智能数据质量评估算法」为工程前提。SRS seq 357「质量状况」为分区属性项（行级语义非分布聚合）。**分布口径三无**：枚举域（三档还是四档——UI 两套阈值形态在 058 已披露）、计数维（条数 count vs 体量 Σvolume——UI 双维并存）、占比否（绝对计数 vs 占比百分比——UI 用绝对值+降序）均无定义。UI 的分组聚合是前端作者的演示约定，不构成口径证据。

### 1.4 类似指标权威方法可行性分析概要

等级分布的权威方法分三层。其一，数据治理平台工程口径（R2 Dataphin 质量分）：表质量分按分数段分布、规则按通过率统计——**分布是质量运营的标准读数**（问题表占比/健康度分布）；其二，国标评价框架（R1 GB/T 36344-2018）：质量评价在维度层展开，对象级评分做频数分布——评价报告的分布形态；其三，汇交审核制度（R3 GB/T 39912-2021）：汇交批次按审核结论（通过/不通过）汇总——审核结论分布的制度形态。方法族对照：

| 方法族 | 原料 | 分布机制 | 与三源匹配 |
|---|---|---|---|
| 质量分分布（R2） | 资源级评分 | 分数段/等级频数 | **无资源级评分** |
| 六维评价（R1） | 评价表 | 对象评分频数分布 | **无评价表** |
| 汇交审核汇总（R3） | 审核台账 | 按结论频数 | **无审核台账** |
| 前端演示 | mock 常量 | 客户端 GROUP BY | 结构披露（不作源） |

结论：三条权威路径的第一层原料（资源级评分/评价表/审核台账）三源均无承载——本件是 058 同根的**离散聚合层缺口**：基座（资源×等级）未建，`GROUP BY qualityLevel` 无从执行。与 059（均分——连续聚合）、061（单资源分——行级）共享基建。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：按 R2→R1 路径推测，分布是资源级质量等级的枚举频数分布——

$$D(\ell) = \bigl|\{\, r : L(r) = \ell \,\}\bigr|, \quad \ell \in \{\text{优}, \text{良}, \text{中}, \text{差}\}; \qquad V(\ell) = \sum_{r:\, L(r)=\ell} \text{vol}(r)$$

其中 $L(r)$ 为资源 r 的质量等级（058 同源，评分阈值离散化），$D(\ell)$ 为等级 $\ell$ 的资源条数（count 维），$V(\ell)$ 为该等级资源体量（Σvolume 维）——UI 客户端聚合的双维形态。占比形态须同基：$D(\ell)/\sum_{\ell'} D(\ell')$（条数占比）或 $V(\ell)/\sum_{\ell'} V(\ell')$（体量占比）。**口径三未裁**：枚举域（三档 vs 四档）、计数主维（count vs volume vs 双维）、绝对值 vs 占比。**前提是资源级等级列存在，三源实测无（§3.3）**——公式列示仅作口径锚（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①质量稽核结果面立项（规则库+资源级跑批+评分登记+等级映射）→ `GROUP BY level` 直查（count/Σvolume）→ 升**完全直接支持**；②乙方自建稽核规则跑批（资源级核查+阈值映射）→ 升**完全转换支持**（枚举域与计数维须登记裁定）；③维持现状 → 完全不支持（UI 该分组维建议「暂无数据」）。

## 四、数据缺失情况

### 4.1 资源级质量等级列零承载（结构级，判定性缺口）

资源级等级列三源零承载（§3.3）——本件是 058 同根的**离散聚合层缺口**：基座（资源×等级）未建 → `GROUP BY qualityLevel` 无从执行。主需求 :2629 把「智能数据质量评估算法」写进功能描述（工程前提自宣），但三源无规则库、无校验流水、无评分登记——等级分布从未被真实算出。**四缺失情形归属「表不存在」**：修复动作是质量稽核结果面立项（规则库+资源级跑批+评分登记+等级映射）；R1 六维可直接作规则库底稿。本缺口与 058（等级）/059（均分）/061（单资源分）/069（问题数）/017（问题总数）共享同一基建：一次立项族内升档。

### 4.2 分布口径三未裁（口径级，即便建成也须先裁）

分布口径三无定义（§1.3/§1.6）：**枚举域**（三档 vs 四档——承 058 两套阈值形态）、**计数主维**（count 条数 vs Σvolume 体量 vs 双维并列——UI 双维并存且两维序不同）、**绝对值 vs 占比**（UI 用绝对值+降序）。正式版须一纸裁定——此裁定与稽核面立项解耦，可先行。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 质量稽核结果面（规则库+跑批+评分登记+等级映射） | 数据工程立项 | 本件 + 058/059/061/069/017 | 触发器①（质量组共享基建） |
| 分布口径裁定（枚举域/计数主维/占比否） | 口径裁定 | 本件 | UI 双维并存须裁定，可先行 |
| UI 暂无数据态 | 展示规范 | 本件 UI | 分组维 qualityLevel 建议保留选项+空态提示 |

档位后果：稽核面 → **完全直接支持**（GROUP BY 直查）；自建规则跑批 → **完全转换支持**；现状 → 完全不支持。推荐顺序：口径裁定先行（即期一纸）→ 稽核面立项（族级主线，六件受益）。
