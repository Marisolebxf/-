## 摘要

「技术趋势判断结论」是技术详情卡「发展趋势」段的一行自然语言（如「XX技术在当前时间范围内保持上升的增长趋势，需结合成熟度、产业化潜力和投资需求继续复核」），由前端 `buildTechnologyTrackingTrendJudgement` 三分支模板确定性生成——模板是结论的呈现形态，判断本体的承载在库侧。实测底座厚实：`hotspot_yearly.trend_status` 逐节点逐年五态枚举全序列 233,160 行（2015-2026），全表累计可判定 35,534 行（RISING 12,045/DECLINING 12,264/STABLE 11,225）、INSUFFICIENT_EVIDENCE 197,593 行；`hotspot_status` 状态机五态（v2：INSUFFICIENT 15,976/ESTABLISHED_GROWING 2,539/MATURE 766/WATCH 146/EARLY_EMERGING 3）。但可判定率随时间恶化：2015 年 0.17%（33/19,430 BASELINE）→ 2023 年 39.9% 峰值 → **2026 年 6.39%**（INSUFFICIENT 18,188/19,430，RISING 仅 2）——2026 为部分观测年（10 月截止）叠加证据门槛，趋势结论大面积退化为兜底句。口径 A 分向审计（2025→2026）：上行 6,849 / 下行 11,123 / 持平 1,458（全池 19,430），均分变化 −10.9538；口径 B 已用 UI 同构模板把库侧读数组装成示例结论（facts.generated_conclusion_ui_style），证明「结构化状态→自然语言」的生成链路可复刻。判**部分支持**：底座与生成链路双现成，可判定率是唯一的、但批量的 gap。

- 需求判定：需求未明列叶（三份说明书 0 命中；srs/04 的「辅助趋势判断」属其他板块）。
- 复现状态：脚本已跑通；逐年状态分布、全表累计、分向审计、可判定率派生、示例结论落产物。
- 档位结论：**部分支持**（结构化底座厚 + 可判定率 6.39% 批量薄）。
- 关键事实：2026 年 93.61% 节点 INSUFFICIENT_EVIDENCE——上线即兜底句刷屏，产品侧必须预置「证据不足」的正名化展示而非当作异常。
- 升档路径：观测窗补满（2026 全年）+ 证据门槛校准 → 可判定率回升；NL 结论列落库 → 完全直接支持候选。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/技术发展跟踪/**技术详情卡·发展趋势段**（页面六视图联动的前端组件族）。本件挂载点：

```text
function buildTechnologyTrackingTrendJudgement(target) {   // techDevelopmentTracking.js:1461
  const topicName = target.name ?? target.topic ?? '当前技术';
  const trendText = target.trend ?? target.growth ?? null;
  if (trendText) {
    return `${topicName}在当前时间范围内保持${trendText}的增长趋势，需结合成熟度、产业化潜力和投资需求继续复核。`;   // 分支①
  }
  if (target.selectedYear && Number.isFinite(target.heatmapValue)) {
    return `${topicName}在 ${target.selectedYear} 年${target.heatmapMetricLabel ?? '热力指标'}为 ${target.heatmapValue}，建议与相邻年份评估结果对比。`;   // 分支②
  }
  return `${topicName}需结合当前时间范围内的热度、成熟度、潜力和风险变化持续跟踪。`;   // 分支③ 兜底
}
// 消费位 :1548-1557「发展趋势」段：body: trendJudgement + trendChart + rows: [{ label: '趋势判断', value: trendJudgement }]
```

三分支的设计逻辑：优先消费 target.trend/growth 字段（上游若给趋势标签则出「保持X增长趋势」句）；次选热力切片语境（给了年份+值则出对比建议句）；两者皆无则兜底「持续跟踪」句。模板句尾的「需结合成熟度、产业化潜力和投资需求继续复核」是固定的谨慎性后缀——前端作者对趋势结论的**不确定性披露**意识，与库侧 INSUFFICIENT_EVIDENCE 状态的设计哲学同源。mock 演示值不参与支持度结论。

### 1.2 为什么需要本指标

趋势结论是详情卡的「最后一公里」：前序所有读数（热度/成熟度/潜力/风险）最终要压成一句人话交付给决策者——「这技术该追还是该放」。自然语言形态降低消费门槛，但也带来两个工程问题：其一，**生成责任**——结论从哪来（前端拼句 vs 库侧判定）决定了它的权威性，本件实测证明前端只负责「拼」、判定在库侧 trend_status；其二，**可判定性**——不是所有节点都配得上一句结论，93.61% 证据不足的节点强行给结论就是编造，兜底分支的存在正是对「不可判定」的诚实。这两个问题的答案决定了本件的产品形态：库侧给状态、前端给模板、可判定率给上限。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「趋势判断」作为指标名在三份指定说明书 0 命中（技术发展跟踪.md 无该词）。srs 全目录命中 1 处：`srs/04-科技专题服务系统/科技专题内容运营中心/可视化管理.md:64`「辅助趋势判断」——产业趋势可视化语境，属科技专题服务系统板块。需求侧最接近的文本是技术发展跟踪.md seq 55 的「结果变化趋势」（022 件承接的功能词，本件是其「结论化」延伸）。「技术趋势判断结论」作为指标名属 UI 组件语义命名。

### 1.4 类似指标权威方法可行性分析概要

趋势判定的权威方法三族。其一，**Mann-Kendall 趋势检验**：非参数单调性检验，对时间序列给上升/下降/无趋势的统计判定（附 S 统计量与 p 值），水文/环境监测的标准方法（R1）——库侧 trend_status 的 RISING/DECLINING 判定在方法学上与之同族（无参数方向判定）；其二，**Kleinberg 突发检测**：对事件流识别 burst 区间，输出「升温/降温」窗口（R2）——hotspot growth 轴的学术原型；其三，**技术成熟度曲线（Gartner Hype Cycle）**：把趋势判断语境化为「触发期→期望膨胀→幻灭期→复苏期→成熟期」的阶段叙事（R3）——与 hotspot_status 状态机（EARLY_EMERGING→ESTABLISHED_GROWING→MATURE）形态同构。方法族对照：

| 方法族 | 代表 | 判定形态 | 与本库匹配 |
|---|---|---|---|
| 单调趋势检验 | Mann-Kendall（R1） | 统计三态 | **有同构**（trend_status 三态+证据态） |
| 突发检测 | Kleinberg（R2） | burst 窗口 | 有（growth 轴） |
| 阶段叙事 | Gartner Hype Cycle（R3） | 五阶段 | **有同构**（hotspot_status 五态） |

结论：库侧双状态体系在方法学上有权威对应物，缺的不是方法而是**证据量**（可判定率）。INSUFFICIENT_EVIDENCE 的设计即 R1 式「检验功效不足时不下结论」的工程化——这是库侧设计的可取之处，也是本件不降档的原因。完整版见附录 C。

## 二、计算过程

### 2.1 方法选择（文献依据）

趋势结论的底座判定采用双轨：结构化状态轨直接消费库侧 trend_status（其 RISING/STABLE/DECLINING 三态对应 Mann-Kendall 的统计三态判定，INSUFFICIENT_EVIDENCE 对应检验功效不足不下结论——R1 范式的工程化）；分向审计轨用简单差分（delta 三值分类），不自行跑 M-K 检验的理由：hotspot 分是 0-100 百分位合成分非原始观测序列，对合成分跑统计检验会放大归一化噪声，差分方向与状态枚举的一致性（§2.4 互证）已足够支撑结论生成。R3 的阶段叙事在库侧有独立承载（hotspot_status 状态机），本件登记为结论的「阶段槽」数据源（模板句尾「结合成熟度…复核」的填充材料）。

### 2.2 结构化状态底座装载

直连久新 Doris（只读）。`ads_technology_hotspot_yearly` 233,160 行（19,430 节点×12 年，与 022 件对账零漂移），trend_status 列逐年分布（facts.jiuxin_trend_status_by_year）：2015 年几乎全 INSUFFICIENT（19,397）+BASELINE 33（首年基线态）；2016-2019 可判定率缓慢爬升（2017 年 RISING 166/STABLE 161/DECLINING 76）；2020-2023 进入黄金窗（2023 年峰值：INSUFFICIENT 11,689，可判定 7,741=39.9%）；2024 起回落（13,822 INSUFFICIENT）；**2025 年 15,976 INSUFFICIENT（可判定 3,454=17.8%）；2026 年 18,188 INSUFFICIENT（可判定 1,242=6.39%，RISING 仅 2）**。全表累计（facts.jiuxin_trend_status_total）：INSUFFICIENT_EVIDENCE 197,593（84.8%）/ DECLINING 12,264 / RISING 12,045 / STABLE 11,225 / BASELINE 33。snapshot 侧 v2 状态机（facts.jiuxin_hotspot_status_v2）：INSUFFICIENT 15,976 / ESTABLISHED_GROWING 2,539 / MATURE 766 / WATCH 146 / EARLY_EMERGING 3——注意 snapshot 的 INSUFFICIENT 15,976 与 yearly 2025 行同值（快照取自 2025 完整窗），双表互证（B11）。

### 2.3 可判定率派生（核心读数）

2026 年可判定率 = (RISING 2 + STABLE 277 + DECLINING 963) / 19,430 = 1,242 / 19,430 = **6.3922%**（derived.jiuxin_trend_decidable_share_2026_pct，分子分母同源同表 2026 行，B3 note 在案）。其镜像读数：INSUFFICIENT 占比 18,188/19,430 = 93.61%——本件最重要的批量 gap 证据。可判定率的时序形态（§2.2 数据）揭示其驱动因素组合：2023 峰值 39.9% 后连续三年下滑，2026 断崖——观测窗缩短（10 月截止 vs 完整年）叠加证据门槛（近期论文≥3 篇等规则，021 件 Top5 实证同源）。「RISING 仅 2」的极值还有一个技术解释：RISING 判定需要完整的上升证据链，部分年窗内上升尚未累积满判定窗——这 2 个 RISING 不是「只有 2 个技术在涨」，而是「只有 2 个的上涨已过判定门槛」，与分向审计（up 6,849）的差值正是「在涨但未过门槛」的中间带。

### 2.4 分向审计（口径 A）

2025→2026 逐节点 delta 分向（facts.jiuxin_hotspot_2025_to_2026_direction）：up 6,849（35.25%）/ down 11,123（57.24%）/ flat 1,458（7.50%）/ total 19,430；均分变化 −10.9538（facts.jiuxin_hotspot_2025_to_2026_avg_delta）。一致性互证：分向的下行主导（57.24%）与 trend_status 2026 的 DECLINING 963 + INSUFFICIENT 18,188 结构吻合——若 18,188 个证据不足节点里有相当部分实际下行（分向审计无门槛），则两轨读数方向一致、幅度差异由门槛解释。偏置披露（B9/B10）：down 为主的方向读数含 PARTIAL_YEAR 成分（2026 年分母窗短，年初高基线节点普遍读作回落），该读数不可直接对外发布为「57% 技术在衰退」。

### 2.5 结论生成链路复刻（口径 B）

用 UI 三分支模板同构的逻辑，把 §2.3/§2.4 读数灌入槽位（facts.generated_conclusion_ui_style）：「候选技术节点池在 2025→2026 观测窗整体呈下行（均分变化 -10.9538，上行 6849 / 下行 11123 / 持平 1458，共 19430 节点）；2026 为部分观测年，趋势读数须结合成熟度、产业化潜力和投资需求继续复核。」——句式与分支①同构（趋势句+谨慎后缀），后缀的三个语义槽在库侧各有承载：成熟度→stage_assessment 阶段档（015）、产业化潜力→potential 六维（016）、投资需求→bottleneck/行动建议文本。链路结论：**结构化读数→自然语言结论的生成管线可以完整复刻，前端模板可直接消费库侧状态列**（trend_status 填 trend 槽、heatmap 值填分支②槽），批内无技术障碍，唯可判定率限制批量输出质量。

### 2.6 稳健性与口径敏感性

三线敏感性：① 观测窗敏感性——2026 读数对 metrics_as_of_date（10-16）敏感，全年补满后可判定率会上修（幅度不可预估，但 2025 同口径 17.8% 是上界参照）；② 门槛敏感性——trend_status 的判定门槛（近期证据量）是上游规则，若门槛下调（如近期论文≥1），INSUFFICIENT 池会向 STABLE/DECLINING 大规模迁移，可判定率跳升但结论置信度下降——R1 范式下「功效不足不判定」优于「勉强判定」，门槛下调须慎重复核；③ 方向阈值敏感性——分向审计的 flat 阈值（delta=0）过严，delta∈(−ε,+ε) 的小幅波动被劈进 up/down，ε 的引入会重塑三向占比，本件取严格零差（与 trend_status 的 flat 语义对齐）。

## 四、数据缺失情况

### 4.1 可判定率缺口（主因）

2026 年 93.61% 节点证据不足（§3.3），趋势结论的批量生成被钳制在 6.39%。「缺失」的准确性质：不是数据没采（233,160 行全在），是**证据量没过判定门槛**——观测窗未满（自愈型）+ 长尾节点天然稀薄（池级天花板型）+ 门槛规则（可校准型）。三型缺口的修复路径各异：等时间/扩证据源/调门槛，任何单一动作都不足以独立把可判定率推到产品可用线（假设 50%+），须组合施策。

### 4.2 NL 结论面缺失（次因）

库侧无自然语言结论列，结论文本生产在前端模板（D5）。这未必是缺陷——模板方案天然保证文案一致性与多语言可控性，库侧只需给结构化状态（现状即如此）。若未来要求「结论可审计」（每个结论句可回溯到生成时间与规则版本），则须在库侧落结论快照表，属升档路径非补缺。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 兜底句正名化（「证据不足」态展示） | 产品决策 | 本件即期可交付 | 93.61% 不是异常是常态，UI 须设计该态 |
| 2026 全年后重算 | 时间自愈 | 本件+022 | 可判定率上修（上界参照 17.8%） |
| 证据门槛校准评审 | 上游规则 | 本件+021 | 门槛-置信度权衡，慎调 |
| 长尾节点证据源扩充 | 上游扩充 | 本件+017/021 | 池级天花板抬升 |
| 结论快照表（审计需求） | 上游建表 | 本件 | 结论可回溯（升档项） |

档位后果：兜底正名化+全年重算 → 部分支持语义闭合；门槛校准+证据扩充 → 可判定率质变（升完全转换支持候选）；结论快照落库 → 完全直接支持候选。推荐：即期兜底正名化 + 全年后自动重算，门槛校准挂中期评审。
