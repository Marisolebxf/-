### 1.6 推测原意与推测定义

**推测定义（活跃学者口径）**：

- 年度活跃学者数：$A_y = |\{s : \exists\, r \in \text{relation}(s),\ r.\text{year} = y \}|$，$y \in [1990, 2024]$（窗口外剔除）；
- 同比增长率：$g_y = (A_y - A_{y-1}) / A_{y-1} \times 100\%$；
- **KPI「平均同比增长」**：$\bar{g} = \mathrm{mean}(g_{2020}, g_{2021}, g_{2022}, g_{2023}, g_{2024})$——取**近五个完整年**均值，2025/2026 因论文收录滞后剔除（窗口写死，2027 年起滚动）。

## 二、计算过程

### 2.1 装载与规模校验

经 `_gkxdb.py` 连接 gkx 只读库。核心依赖 `dwd_scholar_paper_relation` 实测 `COUNT(*) = 1,065,385` 行（该表不在 20261021 轮高频清点内，本件为首建基数；字段 21 列含 `scholar_id/paper_id/year/citations/publish_time`）。首要发现：**该表自带 `year` 列**——年度聚合不需要 JOIN 论文主表（`dwd_scholar_papers` 无 scholar_id，关联本就必须走这张关系表），年度切面是"原生字段"而非"转换产物"，这是结构判定里最有利的事实。学者主档 21,316 行作分母参照（与同批四件共用基数，三级对账零漂移）。

### 2.2 年度序列与脏值治理

直接 `GROUP BY year` 探测发现脏年份：`0` 年 1,846 行、`1761`/`1775` 等 18–19 世纪年份散点——论文年份被误标（追溯年识别错误类）。治理规则：窗口限定 `year BETWEEN 1990 AND 2026`，窗口外行整行剔除（1989 年及以前 + 0 年合计占比小、且不在任何展示窗口）。治理后 $A_y$ 序列 1990–2026 共 37 点：1990 年 780 起步，2016 年 11,049 → 2020 年 13,736 → 2022 年 14,436 → 2023 年 14,482 → 2024 年 14,686，2025 年骤降至 8,464、2026 年 281。2025/2026 的塌陷不是人才流失而是**论文收录滞后**（当年论文尚未录全），这是文献计量学的标准现象，处理方式是不进入均值窗口、序列保留但标"不完整年"。

```sql
-- 活跃学者年度序列（relation 原生 year，窗口治理）
SELECT `year`, COUNT(DISTINCT scholar_id) AS n
FROM gkx.dwd_scholar_paper_relation
WHERE `year` BETWEEN 1990 AND 2026
GROUP BY `year`
ORDER BY `year`;
-- → 1990:780 … 2016:11049 … 2020:13736
--   2022:14436 / 2023:14482 / 2024:14686
--   2025:8464 / 2026:281（收录滞后，不完整年）
```

治理对照：不限窗口时 `year=0` 有 1,846 行、1761/1775/1800 等历史误标年散点，早期稀疏点会产生伪同比尖峰——窗口截断是序列可用性的前提，不是装饰性清洗。

### 2.3 同比增长率序列

对相邻年差分（$A_{y-1} > 0$ 恒成立）：$g_{2020} = +6.3569\%$、$g_{2021} = +3.6182\%$、$g_{2022} = +1.4263\%$、$g_{2023} = +0.3186\%$、$g_{2024} = +1.4086\%$。形态解读：2020 年高基数增长（疫情年线上科研放量）后逐年降温，2023 年几乎归零（+0.32%），2024 年回升至 +1.41%——"增速趋缓后企稳"是本池的真实形态。1990–2024 全序列 35 个同比点全部落产物（`yoy_*` 逐键），供时序图与回溯使用。

```python
series = {1990: 780, …, 2020: 13736, 2021: 14233, 2022: 14436,
          2023: 14482, 2024: 14686, 2025: 8464, 2026: 281}
years = sorted(series)
yoy = {b: round((series[b]-series[a])/series[a]*100, 4)
       for a, b in zip(years, years[1:]) if series[a] > 0}
# → g2020=+6.3569 g2021=+3.6182 g2022=+1.4263
#   g2023=+0.3186 g2024=+1.4086
```

### 2.4 KPI 均值口径

$\bar{g}_{2020\text{–}2024} = (6.3569 + 3.6182 + 1.4263 + 0.3186 + 1.4086)/5 = \mathbf{+2.6257\%}$。窗口选择的三条纪律：①只取完整年（2025/2026 收录滞后剔除，否则均值被拖成 -27%，完全失真——实测对照）；②窗口随年滚动（2027 年交付时窗口平移为 2021–2025），规则写死在产物 `avg_window` 键；③均值是算术平均（各年等权），不做产量加权——因为 UI 读数语义是"每年的平均变化"，不是"累计变化率"。与 mock 的对照：+12.5% 常量 vs 真实 +2.63%，正式版替换后读数下降是预期行为。

```python
recent = [yoy[y] for y in sorted(yoy) if 2020 <= y <= 2024]
avg5 = round(sum(recent)/len(recent), 4)
# → +2.6257   （窗口=2020–2024 完整年）

# 反事实：若误含 2025（-42.3669）
bad = [yoy[y] for y in sorted(yoy)[-5:]]
round(sum(bad)/len(bad), 4)
# → -27.1787（方向反转——窗口纪律是生命线）
```

### 2.5 稳健性与口径敏感性

三组敏感性。其一，口径语义：活跃学者年增（本件）vs 人头年增（不可建）——若池内学者平均产出年限稳定，两者增速同向但幅度不同，正文按"活跃口径"命名避免冒充人头口径。其二，脏年份敏感性：若不剔除 1990 前窗口（含 1761 等误标年），早期稀疏点会产生 >100% 的伪同比尖峰，治理规则（窗口截断）是必要的而非装饰性的。其三，均值窗口敏感性：若把 2025 年（-42.37%）误纳入五均，均值翻成 -6.2%——方向都会反转，可见"完整年窗口"是本指标的生命线，产物 `avg_window` 键与正文双写。年度序列对 citation 权重不敏感（本件只数人头不引权重），无 B9 量纲风险。

### 2.6 展示口径与联动建议

KPI 卡建议展示 +2.6%（1 位小数），角标方向"up"；同屏的全球人才总数卡若也配 trend 角标，必须引用本序列（+2.63%）而非各自写常量，消除同页两个增长率打架的隐患。区域抽屉同义位（分区域同比）需要"区域×年"的活跃学者矩阵——relation 表无机构字段，须 JOIN 履历地理链（四成覆盖），v1 建议只交付全库口径，区域同比随地理工程解锁。年度时间轴切片（UI 2020–2026）与之天然对齐，2025/2026 两个不完整年在时间轴上标注"收录不全"。

### 3.2 D1 关系表：年度切面的原生承载

`dwd_scholar_paper_relation` 1,065,385 行，21 列含 `scholar_id/paper_id/year/citations/publish_time`。本件最有利的结构事实是 **`year` 是原生列**：年度聚合不需要 JOIN 论文主表（`dwd_scholar_papers` 738,106 行反而无 scholar_id，学者关联只能走这张关系表），`GROUP BY year` 一步直出。该表不在 20261021 轮高频清点清单内，本件为其首建基数，后续批次复用前须重跑校验。citations 列的存在还预留了"加权活跃度"的扩展空间（本件未用，只数人头）。

### 3.3 D2 年份脏值与窗口治理

直接 `GROUP BY year` 探到脏年份：`year = 0` 有 1,846 行，另有 1761/1775/1800 等历史年份散点——论文年份的自动抽取在古籍与早期文献上会误判。治理规则：`year BETWEEN 1990 AND 2026`，窗口外整行剔除。治理的必要性用反事实验证：若不剔除，早期稀疏点（如 1761 年 1 名学者）会产生 +∞% 的伪同比尖峰，序列可用性归零；剔除后 1990–2024 序列连续光滑，35 个同比点全部可解释。这不是装饰性清洗，是本指标可用性的前提。

### 3.4 序列形态与收录滞后

治理后活跃学者序列：1990 年 780 → 2010 年 7,351 → 2016 年 11,049 → 2020 年 13,736 → 2022 年 14,436 → 2023 年 14,482 → 2024 年 14,686，随后 2025 年 8,464、2026 年 281 的塌陷。塌陷不是人才流失，是**论文收录滞后**（当年产出尚未录全）——文献计量学的标准现象。处理：2025/2026 保留在序列中但标"不完整年"，均值窗口写死剔除。若三年后回看 2025 年数据回补至 1.4 万量级，窗口滚动规则自动吸收，无需改代码。

### 3.5 D3 人头口径不可建的结构证据

主档 `dwd_scholar` 27 列逐一核对（absence_probe 同 `M_TALENT_UI_CHINESE_RATIO` §3.3 共用）：无 `first_seen_year`/`first_paper_year`/`enrolled_year` 类字段；`created_time` 是 ETL 装载时间（全表同一批次同秒级），无法充当人才产生时间。人头口径（"库内人才数的年增"）因此不可建——不是数据质量问题，是维度不存在。修复路径：主档加 `first_seen_year` 运营字段（每次批次装载回填新出现学者），轻量可行，届时人头口径与活跃口径可平行双轨交付。

## 四、数据缺失情况

### 4.1 人头年度入口缺失（结构级，决定口径）

主档 `dwd_scholar` 无 `first_seen_year` 类字段（27 列逐一核对，absence_probe 与 CHINESE_RATIO §3.3 共用）；`created_time` 是 ETL 装载时间（同批次同秒级），无法充当人才产生时间。人头口径（"库内人才数的年增"）因此不可建——本件改走活跃学者口径并在正文/产物双写披露。四缺失情形归属：**表存在但关键列不存在**。修复动作轻量：批次装载时回填新出现学者的 `first_seen_year`（一个 UPDATE 语句的运营纪律），下一批次即可双轨交付人头/活跃两口径。

### 4.2 论文收录滞后（数据源自然特性）

2025 年 8,464 / 2026 年 281 的塌陷是收录滞后而非人才流失：文献数据库对当年产出的收录通常滞后 6–18 个月，2026 年才过三分之一更是只有零星预印本入库。处理：两年标"不完整年"剔除均值窗口，序列保留供回看。风险在下游：若 UI 年度时间轴切片直接读 2026 年对比 2024 年，会得到"-98%"的假暴跌——产物 `avg_window` 键与正文 §2.5 反事实已写死纪律，前端须同步实现"不完整年禁比"逻辑。

### 4.3 脏年份与历史段（已治理）

`year = 0` 1,846 行与 1761–1989 年的稀疏历史点已按窗口规则剔除（§2.2）。治理不是损失：历史段学者数个位数、对序列形态无贡献，剔除反而消除伪尖峰。若未来数字化民国及以前文献，窗口规则需重议（当前写死 1990 起是务实选择，金样板同款纪律）。

### 4.4 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 主档回填 first_seen_year | 运营字段 | 本件（双轨人头口径） | 轻量，下一批次可生效 |
| 收录滞后曲线监控 | 数据源治理 | relation 表质量 | 月检 2025/2026 回补进度 |
| 区域同比矩阵 | 随地理工程 | 抽屉同义位 | 依赖履历地理链（四成覆盖） |

第 1 条性价比最高：一个字段的运营纪律换来人头/活跃双口径，直接消除 §1.6 的降档争议；第 2 条让"不完整年"的判定从写死规则变成数据驱动；第 3 条与 GLOBAL_STOCK 主数据工程同源。
