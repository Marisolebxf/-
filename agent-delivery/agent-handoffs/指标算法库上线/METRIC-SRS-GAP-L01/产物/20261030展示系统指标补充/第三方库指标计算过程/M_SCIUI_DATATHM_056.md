### 1.2 为什么需要本指标

覆盖资源数回答「平台的服务能力辐射到多少资源」：与累计调用量（深度）互补，它是调用行为的**广度**读数——285.6 万次调用铺在 30,398 个资源上（均值≈94 次/资源）还是集中在少数资源，直接决定「平台是基础设施还是精品店」的定位判断；热度/生命周期研判（卡片排的第四卡）也以覆盖面为分母语境。需求语义锚 seq 346「归集上线以来累计调用量，按时间区段分析热度与生命周期」——覆盖资源数是该语境的衍生卡（累计调用的去重维度）。权威对应物是 GB/T 33850-2017 信息技术服务监控：服务调用的覆盖面统计以调用记录为准——流量语义的国标锚。本库场景下，该读数要求调用流水（谁在何时调用了什么资源）存在——没有流水，「覆盖」无从界定。

### 1.3 需求文档是否给出定义方法

**需求文档未给出覆盖的定义方法。**「覆盖资源数/资源覆盖」字面三份说明书 0 命中——本读数仅见 UI 卡名。语义锚 SRS 应用视窗 seq 346「归集上线以来累计调用量，按时间区段分析热度与生命周期」——累计调用量是立项项，覆盖资源数是 UI 作者加的衍生卡。**覆盖口径三无**：覆盖判据（至少一次调用？达到阈值次数？）、时间窗（上线以来全量 vs 当期）、与总量的关系（覆盖率形态分母如何取）均无定义。**mock 口径混同实证**（§3.2）：`resourceCovered: 30398` 与 overviewKPIs「资源总量 30,398」同值——演示作者在无流水时直接抄了存量值，「覆盖」的流量语义在演示数据中从未真正行使。

### 1.4 类似指标权威方法可行性分析概要

覆盖资源数的权威方法分三层。其一，服务监控国标（R1 GB/T 33850-2017）：服务调用覆盖面统计**以调用记录为准**——流量语义的国标锚（覆盖=有记录者）；其二，数据资产管理口径（R2 DAMA-DMBOK 资产利用率）：资产利用率=被使用的资产/总资产——覆盖率的分子分母框架（覆盖数是分子）；其三，平台运营工程口径（R3 Prometheus/网关日志）：API 调用日志按 resource 维度去重——`COUNT(DISTINCT resource)` 的工程范式。方法族对照：

| 方法族 | 原料 | 覆盖机制 | 与三源匹配 |
|---|---|---|---|
| 调用记录统计（R1） | 调用流水 | 有记录即覆盖 | **无流水** |
| 资产利用率（R2） | 资产目录+使用登记 | 覆盖率分子 | **无使用登记**（目录近似有） |
| 网关日志去重（R3） | API 网关日志 | DISTINCT resource | **无网关日志** |
| 前端演示 | mock 常量 | 抄总量值 | 结构披露（不作源） |

结论：三条权威路径的第一层原料（调用流水/使用登记/网关日志）三源均无承载——流量口径不可交付；但存量侧（资产目录）有近似（036 件三源表计数先例）——「目录在、流水缺」构成本件部分支持的判定结构。与 DATAOV_002/DATAIN 族（接入/调用流水台账未立项）同根，与 057（资源调用频率——同缺流水）连坐。完整版见附录 C。

### 1.6 推测原意与推测定义（含降档/升档触发器，B10 模板）

**推测定义（须披露口径不闭合）**：按 R1→R3 路径推测，覆盖资源数是调用流水的资源去重计数——

$$N_{\text{cov}} = \bigl|\{\, r : \exists\, c \in L,\ c.\text{resource} = r \,\}\bigr| = \text{COUNT}(\text{DISTINCT resource\_id}) \; \text{FROM 调用流水}\; L$$

覆盖判据默认「至少一次调用」（R1 有记录即覆盖）；覆盖率形态 $N_{\text{cov}} / N_{\text{total}}$（分母=资源总量，R2 框架）。**存量近似**（若甲方裁定覆盖≈总量）：$N_{\text{total}} \approx$ 三源表计数（全口径 1,032 / 剔备份 930——036 件先例），但表数≠资源数（一资源可多表），须再乘资源-表映射。**口径三未裁**：覆盖判据（一次 vs 阈值）、时间窗（上线以来 vs 当期）、近似转正规则（表→资源映射）。**前提是调用流水存在，三源实测无（§3.3）**——公式列示仅作口径锚（F4：本件 §二 从缺）。

**降档/升档触发器（B10 模板）**：①调用流水台账立项（网关日志/调用登记）→ `COUNT(DISTINCT resource_id)` 直查 → 升**完全直接支持**；②甲方裁定「覆盖≈总量」+ 资源-表映射登记 → 存量近似转正（值=映射后资源数）→ 升**完全转换支持**；③维持现状 → 部分支持（UI 建议改挂存量口径或「暂无数据」）。

## 二、计算过程

### 2.1 口径裁定（B10 多口径并列）

本件读数「覆盖资源数」存在两个互不等价的口径，B10 并列登记、主判流量口径：**口径 A（正式口径，流量）**——被调用行为覆盖到的资源去重计数 $N_{\text{cov}} = \text{COUNT}(\text{DISTINCT resource\_id})$ FROM 调用流水（覆盖判据=至少一次调用）；三源无调用流水台账（§2.2/§3.3），**不可得**，指标键 `platform_covered_resource_count = null` 留空。**口径 B（存量近似）**——若甲方裁定「覆盖≈总量」，$N_{\text{cov}} \approx N_{\text{total}}$（登记在库全集），表级近似可交付但语义不等价（流量子集 vs 存量全集），仅登记不转正（§2.3）。两口径的选择是本件唯一的口径级降档因——mock 恰好演示了错选后果（§2.4）。

### 2.2 排除实测：调用流水词族三源逐一留证

判「无承载」前的三源探针（复用 L4 族探针 `_probe_s304_l4_collect_out.json` + lane7 快照，B8）：**dev** 542 表 registry/collect 词族命中 6 张（`facts.dev_registry_like_tables`）——`app_article_collect`（文章收藏）/`jimu_report_data_source`+`onl_drag_dataset_*`（BI 报表数据源配置）/`gen_datasource_conf`（代码生成器数据源配置），逐一语义排除（`facts.dev_registry_semantic_note`）；**gkx** 280 表 collect 词族唯一命中 `dwd_org_changerecord_info`（机构变更记录——要素明细，`facts.gkx_collect_like_tables`+note），语义排除；**久新** 调用流水词族 0 命中（`facts.jiuxin_status`——L4/L5 族先例：流水台账未立项）。三源结论：调用流水面 0（语义级），口径 A 无从计算——这是本件不写正式指标值的唯一原因。

### 2.3 存量近似读数落盘（036 件先例复用）

### 2.5 稳健性与口径敏感性

三点敏感性：其一，**流量/存量语义边界**——覆盖（被调用过的子集）与总量（登记在库的全集）在任何有闲置资源的真实系统中必不相等，近似转正会系统性高估覆盖；其二，**覆盖判据敏感性**——「至少一次调用」vs「次数阈值」两判据下的覆盖数单调差（阈值越高覆盖越小），判据无登记则口径 A 即便有流水也需先裁；其三，**表级近似的映射敏感性**——一资源多表映射规则无登记（063/064 共享缺口），930/1,032 两读数本身也随备份/配置剔除边界浮动。

## 四、数据缺失情况

### 4.1 调用流水面零承载（结构级，流量判定性缺口）

调用流水台账三源零承载（§3.3）——与 DATAOV_002/DATAIN 族（接入/调用流水未立项）同根。**本件的连坐面**：累计调用四卡排共享流水前提——覆盖资源数（本件）、日均调用（057）都卡在同一缺口上，流水立项则两件双升。**四缺失情形归属「表不存在」**：修复动作是调用流水立项（API 网关日志/调用登记表——谁/何时/调用了什么资源/成败）；GB/T 33850 服务监控的调用记录规范可直接作流水表设计底稿。

### 4.2 流量/存量语义边界未裁（口径级，近似转正的阻断件）

本件降档的口径层根因：**覆盖（流量子集）≠总量（存量全集）**——mock 口径混同自证（30398 抄总量）恰好演示了无流水时的常见错误。正式版须裁定：①覆盖判据（至少一次调用 vs 次数阈值）；②是否接受存量近似（覆盖≈总量——须同时登记资源-表映射，表数 930/1,032 才能换算为资源数）；③覆盖率形态是否需要（分母裁定）。此裁定与流水立项解耦，可先行。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 调用流水台账（网关日志/调用登记） | 数据工程立项 | 本件 + 057 + DATAOV/DATAIN 族 | 触发器①（四卡排流水前提，两件双升） |
| 覆盖口径裁定（判据/时间窗/近似规则） | 口径裁定 | 本件 | mock 混同实证在前，可先行 |
| 资源-表映射登记 | 数据工程配套 | 本件 + 063/064/066/067 | 存量近似转正的阻断件，资产目录立项附带交付 |
| UI 存量口径改挂或空态 | 展示规范 | 本件 UI | 30398 演示值建议撤下 |

档位后果：流水 → **完全直接支持**（DISTINCT 直查）；近似转正 → **完全转换支持**；现状 → 部分支持。推荐顺序：口径裁定先行（即期一纸）→ 资源-表映射（资产目录配套）→ 流水立项（运营监控主线）。
