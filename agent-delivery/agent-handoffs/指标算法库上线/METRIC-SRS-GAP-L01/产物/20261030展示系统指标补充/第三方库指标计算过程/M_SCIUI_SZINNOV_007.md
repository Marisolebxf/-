## 摘要

「基础设施增量指标」是深圳创新监测页科技发展指标树的二级叶：「基础设施」一级维（mock 1,260 个，yoy -19.1%）下与「基础设施核心指标」（mock 731）并列的「基础设施增量指标」（mock 302 个）。UI 的「增量」语义由兄弟维同构佐证——论文维 48,200 篇下分「论文核心指标 27,956 / 论文增量指标 11,568」，专家维 22,156 下分「核心 13,264 / 增量 9,168」——「增量指标」是年内新增计数。三源探针结论：**设施对象底册在三源结构级不存在**（gkx 八关键词表名+列名双级 0 命中、dev 137 表 0 命中、久新 203 表 0 命中），需求文书未定义计数口径，UI 自注官方源不在三源。最近代理久新 facility 序列（深圳 2000-2026 年 5→17 家，2025=16、年增量-1）与 UI 量级差 78.8 倍且语义是 OpenAlex 科研设施非城市基础设施，只作对照面。判**完全不支持**，五年趋势窗（2021-2025）无任何年份可取数。

- 需求判定：**需求明列维度**（seq 119 十一维枚举末位），但计数口径未定义。
- 复现状态：脚本已跑通；三源扫描 0 命中留证、代理序列与差分落产物。
- 档位结论：**完全不支持**（对象维/口径维/时间面三构件全缺）。
- 关键事实：唯一代理量级差 78.8 倍（1,260 mock vs 16 实测）——代理与 UI 语义不同物的实证。
- 升档路径：接入官方统计源（深圳统计年鉴基础设施投资额 / 科创委创新载体名录）——三源内无升档路径。

### 1.2 为什么需要本指标

基础设施是创新生态的硬件底座：大科学装置、共享仪器、创新载体（实验室/中试平台/孵化器）的存量与增量直接刻画一个城市创新体系的「重资产」投入强度。「增量指标」比总量更敏感——它回答「今年新建了多少」，是政策见效的最快读数。需求把它与论文/专利/专家并列为 11 个展示维度之一，说明业务叙事里「软产出」（论文专利）与「硬条件」（基础设施）要同屏对照。

数据侧本件是全批「对象维缺失」最彻底的一件：SZINNOV_011（区级地图）至少有机构底册可作区级聚合、SZINNOV_012（平台活跃度）至少有机构活跃度列可作 CITY 级代理，本件连「什么是基础设施」的对象表都无——三源没有设施清单、没有设施类型、没有设立时间。判档的举证重心因此落在「查过什么、怎么查的、命中几行」的探针三件套上（B4），而非任何数值读数。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**SRS《深圳创新监测.md》seq 119（excel_row 122）原文：「从论文、期刊、专利、专家学者、会议、组织机构、课题、项目、资金、政策、基础设施等多个维度展示科技发展指标，用户可选择查看不同维度的指标数据。」——「基础设施」是 11 维枚举的末位，**维度名命中但指标定义未给**：计数单位（个/家/台套/亿元？）、对象范围（大科学装置/创新载体/仪器设施/新型基础设施？）、增量算法（年内新设立数？净增？同比差分？）全部空白。主需求文档 :769/:779 为同段复述。另查科技全域态势 SRS（:42 地图平移）的要素枚举是「论文、期刊、专利、专家学者、会议、组织机构、课题、项目」九项——**不含基础设施**，本维仅深圳创新监测模块明文。

### 1.4 类似指标权威方法可行性分析概要

基础设施统计的权威口径有三层。我国科技统计体系（科技部《科技统计年鉴》）序列统计**研究与发展机构数**与**大型科研仪器**（价值 50 万元以上台套数），以机构登记与仪器入网为计数轴（R1）；深圳市官方创新载体口径（深圳市科创委）统计**重点实验室/工程中心/技术中心/孵化器/众创空间**等载体名录，按认定批次逐年滚动（R2，即 UI 自注数据源的口径族）；OECD Frascati 手册则把研究基础设施归入 R&D 资本形成（GFCF）的金额口径（R3）。方法族对照：

| 方法族 | 计数轴 | 单位 | 数据要求 | 与三源匹配 |
|---|---|---|---|---|
| 仪器台套口径（科技部，R1） | 50 万元以上仪器入网 | 台套 | 仪器共享平台底册 | **无（三源无仪器表）** |
| 创新载体口径（深圳科创委，R2） | 载体认定名录 | 家/个 | 载体底册+认定时间 | **无（三源无载体名录）** |
| 资本形成口径（OECD，R3） | 基础设施投资额 | 金额 | 统计年鉴经济表 | **无（gkx 经济码无基础设施投资项）** |
| OpenAlex facility 代理（久新在库） | 机构类型=facility | 家 | 已有 | 有但语义窄、量级差 78.8 倍（对照面） |

结论：三种权威口径的计数轴三源均无承载；久新 facility 是唯一在库代理但语义是「国家实验室/望远镜/加速器」非城市基础设施。完整版见附录 C。

否定性证据三件套：**查了什么**——gkx 侧 `information_schema.tables` 表名扫描（infra/facility/instrument/apparatus/equipment/platform/carrier/incubat 八关键词，280 表全库）+ `information_schema.columns` 列名扫描（infra/facility/instrument/apparatus/platform 五词）；dev 侧 137 表 instrument/facility/infra 三词；久新 203 表 SHOW TABLES 关键词过滤（instrument/facility/infra/equipment）。**条件**——表名/列名的子串匹配（结构级存在性，非行数级）。**命中**——三源合计 0 表 0 列（`facts.gkx_infra_tables=[]`、`facts.gkx_infra_columns=[]`、`facts.dev_infra_tables=[]`、`facts.jiuxin_infra_tables=[]`）。四种缺失情形的归属：**表不存在**（连候选表都没有），修复动作只能是引入新数据源，不是补数据。另：主需求文档 :3565 点名的「大型科学仪器共享」（9,262 台套/499 单位）说明需求侧明确期望仪器级底册——三源连表都没有，期望落空留证。

### 3.3 D4 代理序列：为什么不能作承载

久新 `ads_geo_yearly_institution_type_metrics` 中深圳 facility（科研设施）序列：2000 年 5 家 → 2015 年 16 → 2025 年 **16 家**、2026 年 17（`facts.jiuxin_sz_facility_series`，27 年全窗）。差分增量序列 `facts.jiuxin_sz_facility_yoy_delta`：2025 年 **-1**、2026 年 +1、历史多数年份在 -4~+4 间波动。两个不符：**量级不符**——UI mock 一级维 1,260 个，代理 16 家，比值 78.8（`derived.jiuxin_sz_facility_2025_vs_ui_mock_ratio`，分子为演示值不作数据证据、分母为实测）；**语义不符**——OpenAlex facility 类型是「国家实验室、望远镜、粒子加速器」类科研装置（深圳 16 家即鹏城实验室、深圳大学天文台等量级），而 UI 语境的城市基础设施（1,260 个量级）显然包含载体/仪器/新型基础设施的宽口径。量级与语义双不符的代理不能作承载，只登记为对照面读数。

### 3.4 「增量」语义佐证与兄弟维同构

UI 兄弟维的「核心/增量」拆分给了增量算法的语义锚：论文维 48,200 篇下「论文核心指标 27,956 / 论文增量指标 11,568」（增量/核心=41.3%）、专家维 22,156 下「核心 13,264 / 增量 9,168」（69.1%）、本维 1,260 下「核心 731 / 增量 302」（41.3%）。可见「增量指标」是**年内新增计数**而非数学差分（302≠1260-731）。要算它，底册必须有「设立年」列——三源无设施表，更无设施×时间面；即便未来接入名录，也须校验设立时间列的年份粒度（B9）。

## 四、数据缺失情况

### 4.1 对象维缺失（结构级，主因）

「基础设施」的对象表——无论哪种口径（仪器台套/载体名录/投资金额）——在三源均无：gkx 八关键词表名+列名双级扫描 0 命中、dev 137 表 0 命中、久新 203 表 0 命中（absence_probe 四条在案）。四缺失情形归属：**表不存在**。这是最彻底的一类缺失：字段工程（加列回填）都无从谈起，因为没有宿主表。修复动作只剩引入外部数据源。

### 4.2 口径维缺失（需求级）

需求文书只在 11 维枚举里给了「基础设施」四个字：计数单位、对象范围、增量算法全空白。四种候选口径（大科学装置数十亿级/创新载体数千级/仪器台套近万级/新型基础设施万亿投资级）的量级横跨数量级——即使三源有底册，口径不裁定也无法对齐 UI 的 1,260 量级。本件的口径缺失与对象维缺失互相锁死：没有底册就无法用数据分布反推口径，没有口径就无法定向找源。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 接入深圳统计年鉴/科创委载体名录 | 外部数据源 | 本件（唯一路径） | UI 自注源（科创委/统计局）；须含设立年列才能算增量 |
| OpenAlex facility 代理 | 不建议 | — | 语义窄+量级差 78.8 倍，仅对照面 |
| 需求侧补口径定义 | 产品决策 | 本件+SZINNOV_012 | 四种口径量级差数量级，先裁定再找源 |

三条路径的档位后果：官方源接入且含时间列 → 重评（升部分支持以上）；官方源仅存量无时间列 → 总量可算增量不可算（仍部分支持）；代理口径 → 不升档。本件与 SZINNOV_012 的「平台对象维」共用引入载体名录的工程——一份名录（含类型+设立年）可同时救两件。
