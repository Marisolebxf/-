## 摘要

「跨部门协同率」是政策分析评价·政策画像卡（DS-11）metrics 行的组成读数（mock 68%），export 自认计算方法需立项调研——「协同」语义在政务语境三义并存（发文侧联合署名/执行侧数据共享率/系统侧部门协作度），本件按唯一有三源原料的**联合发文学术口径**（R1/R2）实测：gkx ministry 列 19,989 行非空中，顿号联合署名仅 336 行且**单值坍缩**（全部为「北京市科委+中关村管委会」一市两部门形态），真正的多机关署名信息（如广东五机关连写）散落在 **title 层**（正则保守命中 225 行）——两层 UNION 去重得 560 行，融合代理率 2.802%。这个读数的语义是「联合发文占比」而非「协同率」：单值坍缩说明 ministry 列的联合署名维护几乎空白，title 连写需机关名切分工程才能完整计数，「应协同政策集」分母更是口径问题而非数据问题。dev `dept_distribution` 列在 0 行、久新命中面全语义排除（机构合作≠部门协同）。判**部分支持**——口径可裁剪、输入面有缺陷但有量，升档需机关名切分工程落地；若甲方裁定为执行侧口径则需政务平台对接（外部源单独立项）。

- 需求判定：三份需求真源无「跨部门协同率」；「跨部门协同」5 处均非政策域（导出便利功能语）。
- 复现状态：两个代理读数落产物（顿号口径 1.681% / 两层融合 2.802%）；结构化协同率登记键留空。
- 档位结论：**部分支持**（联合发文口径可算但形态缺陷 + 分母口径未定义 + 执行侧面零承载）。
- 关键事实：ministry 顿号联合 336 行 DISTINCT 单值——「列在、形态坍缩」，联合署名维护近乎空白的多机关信息实际在 title 层连写（225 行）。
- 升档路径：机关名切分与规范化工程 → 联合发文口径闭合升完全转换支持；执行侧口径 → 政务共享平台对接单独立项。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技政策跟踪/**政策分析评价**·政策画像（DS-11 政策/企业/人才三画像）·跨部门协同率。UI 容器是 `PortraitTrio.jsx`（三卡+Drawer 详情，`analysis/PortraitTrio.jsx:40` 消费 `policyPortraitSummaries`）：政策画像卡（`policyData.js:2175` 起）KPI 位是「综合力度指数 86 分」（046 件），点开 Drawer 后 detail.metrics 四行是画像的组成读数——发布密度 128 项/季、平均资助强度 3200 万元、**跨部门协同率 68%（本件，`:2185`）**、免申即享占比 24%。组件行为：纯展示 mock（metrics 数组渲染为标签行），无后端取数。这个挂载形态说明「跨部门协同率」在 UI 设计里是**政策画像的一个维度读数**——与发布密度（量）、资助强度（额）并列的「协同」维。

### 1.2 为什么需要本指标

政策工具的组合化是近年科技政策的显著趋势：一项产业政策往往需要科技、财政、税务、工信等多部门协同落地——联合发文既是协同的**制度痕迹**（会签才能联合署名），也是政策执行力的**前置信号**（多部门背书的政策资源配置更足）。画像卡把它列为四读数之一，业务意图是给政策对比提供「组织保障」维：两政策力度相近时，跨部门协同率高的执行确定性更强。学术上这正是政策文献量化研究的标准做法（R1 以联合行文观测环境治理跨部门协同的演进；R2 以联合发文数量测度区域创新政策的主体协同）。

### 1.3 需求文档是否给出定义方法

**需求文档未提及该指标定义方法。**「跨部门协同率」指标名在三份需求真源 0 命中；「跨部门协同」在主需求 5 处命中（:2435/:2625/:2879/:3267/:3465）全部是**非政策域**语境——引进成本数据导出「便于单位内部汇报或跨部门协同」、数据来源明细导出「方便业务汇报、策略研讨和跨部门协同」、日志导出、软科学成果筛查、创新载体协同治理——都是「便于跨部门协同（使用）」的导出功能语，不是政策域的协同度量。「协同率」字样 0 命中。export 行自认「对某方面能力或状态的量化评价（科技政策库场景）——计算方法需要立项调研后才能确定」。

### 1.4 类似指标权威方法可行性分析概要

「跨部门协同」的量化在官方/学术体系有三族先例：

| 方法族 | 代表 | 观测窗 | 数据要求 | 与本库匹配 |
|---|---|---|---|---|
| 联合发文分析（发文侧） | R1 环境治理 976 份联合行文；R2 京津冀/长三角联合发文数 | 政策文献的署名栏 | 政策库机关字段（结构化） | **部分**（列在但形态缺陷，§2.2） |

## 二、计算过程

### 2.1 方法选择（文献依据）

采用联合发文口径（口径①）的保守两层代理：R1/R2 的联合行文分析法为本件方法论锚——以政策文献署名栏的多部门共现为协同观测窗。工程上分两层：**ministry 顿号层**（结构化分隔符直接计数）与 **title 连写层**（机关名无分隔连写的正则识别，13 省份词表保守匹配），两层 UNION 去重后除以 ministry 非空行。选择理由：这是三源现状下唯一可复算的口径；两层融合部分修复了 ministry 层单值坍缩造成的信息缺失（§2.2）。分母用 ministry 非空行（19,989）而非全表（20,000）——11 行字面 'null' 无机关信息，不进分母（口径限制随行披露）。

### 2.2 gkx 联合署名面盘点（可算侧的形态缺陷与修复）

**ministry 顿号层**：非空 19,989 行中顿号联合署名 **336 行（1.681%）**——但 DISTINCT 值集只有 **1 个值**：「北京市科学技术委员会、中关村科技园区管理委员会」×336。这是「列在、形态坍缩」的典型缺口：ETL 只在单一来源（北京科委联合发文批次）保留了多机关分隔形态，其余联合发文都以单机关名或连写进了其他字段。**斜杠层**：118 行，样本判别是「国务院/中央人民政府」类发文主体别名，非联合署名。**部门词表共现**：16 个部门词（科学技术/财政/税务/发展改革/工业和信息化等）在 ministry 内共现 ≥2 词的行数为 **0**（分布：0 词 12,367 / 1 词 7,622）——ministry 层的多部门信息除顿号单值外完全缺失。**title 连写层**：正则（机关后缀「厅|委员会|局」紧跟省份词，13 省词表）保守命中 **225 行**，样本含「广东省科学技术厅广东省发展和改革委员会广东省工业和信息化厅广东省商务厅广东省市场监督管理局关于印发…」（五机关连写）、「上海市经济和信息化委员会上海市科学技术委员会上海市人力资源和社会保障局关于印发…」（三机关）——**多机关署名信息实际在标题层**。**两层融合**：UNION 去重（交集 1 行）得 **560 行，融合代理率 2.802%**（`joint_publish_proxy_combined_pct`）。**长度分档佐证**：ministry 长度 ≤10 字 16,309 行 / 11-20 字 3,344 行 / 21-40 字 336 行——21-40 字段恰是顿号联合值，≤20 字占 98.3%，坐实单机关短值为主。

### 2.3 dev 与久新的承载排除

## 四、数据缺失情况

### 4.1 部门协同关系面缺失（结构级，主因）

三源均无「部门 A×部门 B×政策/事项」协同关系承载（§3.3 三件留证）——联合发文的会签部门数、执行侧的共享接口，都是运行侧/治理侧数据，不在科技要素库、开发数据仓、久新分析仓的任何一张表里。这是与 POLCMP_008（参与事件）同型的「事件在别处」缺口：协同痕迹产生于政务办公流程（会签系统/共享平台），须经对接才能入库。但本件与 008 的差异在于：**发文侧口径可以从政策文献自身解析**——署名栏就是协同的制度痕迹，不需要运行时数据。这也是本件判部分支持而非完全不支持的原因。

### 4.2 ministry 形态缺陷与机关切分工程（数据级，次因）

§3.2 的形态坍缩意味着即便选定口径①，分子也需先做解析工程：机关名词表（部委/省厅/市局三级）+ 分隔符与连写双形态识别 + 别名归一。工程量中等（词表建设为主），不依赖新数据源——gkx 19,989 行原料全部在库。「应协同政策集」分母（口径级）建议随切分工程一并裁定（候选：全量政策/产业类政策/跨领域事项政策三选一，B10 登记待裁）。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 机关名切分与规范化工程 | 解析工程 | 本件（主）+ 政策画像全族 | 词表+双形态识别+title 回退，库内原料足量 |
| 分母口径裁定 | 口径立项 | 本件 | 三候选（全量/产业类/跨领域），随工程裁定 |
| `dept_distribution` 回填 | 数据工程 | 本件 + 发布密度类 | dev 落位列在 0 行，切分产物可直接回填 |
| 政务共享平台对接（口径②） | 外部立项 | 本件（执行侧口径） | R3 框架，单独立项不在三源 |

档位后果：切分工程落地 + 分母裁定 → 口径①**完全转换支持**（560 行下界 → 完整联合发文集）；仅口径② → 部分支持（外部源未接）；两不做 → 维持部分支持（代理读数 2.802% 随行披露口径限制）。推荐：切分工程先行（与政策画像族共用词表资产）。
