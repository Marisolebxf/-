## 摘要

「指标增长率」是全球创新监测页多维度排名模块的对比维度：载体详情抽屉用折线展示创新指数逐年增长率（`InnovationRanking.jsx:419` 用 `(s−s₁)/s₁×100` 对 scoreHistory 逐年计算），科技创新评估页用柱线组合图的红色增长率线（mock 10.6→8.4%）。该指标名在三份 SRS 与主文档均未出现，但"增长率"作为通用统计读数在数据侧是最有承载的：久新库有两张表带**现成 YoY 列**（emerging topic 的 paper_count_yoy 覆盖 95%+；research problem 的 paper_growth_rate 覆盖 37%），gkx 融资事件表按年聚合即得连续 7 年同比序列。本件实测产出三组读数：gkx 融资事件同比（2025 年 −32.75%）、久新技术节点论文总量同比（2025 年 −38.45%）、节点级上行占比（2024→2025 仅 16.31% 节点论文数上行）。判**完全直接支持**——增长率本体三源两源直查直算；唯一口径风险是 UI 的增长率先挂在"创新能力指数"上，若甲方要求指数增长率则该指数本身是需业务建模件（INNOV_014 同族），触发器已写死。

- 需求判定：**UI 推测叶**（SRS 未出现「指标增长率」；近似叶 seq 74 多维度排名展示无增长率分项定义）。
- 复现状态：脚本已跑通；gkx 七年同比 + 久新现成 YoY 列覆盖 + 节点上行占比三组读数落产物。
- 档位结论：**完全直接支持**（久新现成列 + gkx 自算序列，双源直接承载）。
- 关键事实：gkx 融资事件 2015 峰值 3,884 起后逐年下行，2025 年 618 起、同比 −32.75%——增长率为负是池衰减信号，UI 展示需带池口径注记。
- 升降档路径：若增长率必须挂"创新能力指数"→ 降部分支持（指数需建模）；若接受论文/专利/融资事件量增长率 → 维持本档直查。

## 一、需求定义概述

### 1.1 所属功能模块

智能服务集群/科技信息展示系统/科技发展态势/全球创新监测/创新载体排行榜/**多维度排名展示**（SRS seq 74；UI `InnovationRanking.jsx`）。本件挂载点有两处：其一是载体排行榜的详情抽屉——用户点击排行榜中的创新载体名称，抽屉内「创新能力指数变化趋势」图以柱（创新指数）+线（增长率）双轴展示 2020–2024 五年序列，`InnovationRanking.jsx:419` 的增长率线由前端就地计算：`scores.map((s, i) => i > 0 ? Math.round((s - scores[i-1]) / scores[i-1] * 100) : 0)`——这是 UI 代码里**明写的增长率公式**（同比、首年补 0），本件推测定义直接采信该式；其二是科技创新评估new 页的柱线组合图（`TechInnovationEvaluationNewPage.jsx:560`），红色平滑折线为增长率（mock 值 10.6/10.6/16.8/19.7/17.1/8.4%，2020–2025）。

mock 值是 UI 需求证据（演示值，不参与支持度结论）：前端作者选择的基期是"上一年同期"（逐年差分），展示形态是"折线/百分比"，量级在 ±20% 区间。这组 UI 证据把「增长率」的口径收窄为**年度同比**，排除了环比（MoM）与累计同比（YTD）两种变体。

### 1.2 为什么需要本指标

排名展示的是"谁在前"，增长率展示的是"谁在涨"——多维度排名模块若只有存量排名，用户无法区分"稳居榜首"与"即将跌出"的载体。载体详情抽屉把创新指数柱状图与增长率折线放在同一坐标系（双 y 轴），就是让"水位"与"流速"同屏可比；科技创新评估页的增长率线同理，服务"哪些维度在改善"的评估叙事。增长率的另一层价值是预警语义：连续负增长是载体创新衰减的最早信号，比排名下滑平均早 1–2 个报告期显现。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「指标增长率」全称在三份 SRS（`科技全域态势.md`/`技术发展跟踪.md`/`全球创新监测.md`）与《科技信息展示系统和科技专题服务系统.md》rg 检索均未命中。近似叶仅有两处：SRS 全球创新监测 seq 74「多维度排名展示」（原文"提供创新载体的多维度排名，包括总体排名、领域排名、地区排名，用户可切换查看不同维度的排名情况"——只列排名维度，无增长率分项）；主文档 7303–7307 行「总量与增长率展示」（原文"用户可查看产业总体规模及年增长率，系统以柱状图或折线图动态呈现，支持按区域、行业筛选"——属科技专题服务系统产业规模可视化叶，非本页语境，但**柱状图+年增长率的展示形态与本件 UI 完全同构**，可作口径旁证）。

### 1.4 类似指标权威方法可行性分析概要

增长率的权威定义高度收敛，无口径争议空间：OECD《Main Science and Technology Indicators》对科技指标增长率的官方口径是**复合年均增长率（CAGR）**，基于不变价序列计算：CAGR = [(I_t1/I_t0)^(1/(t1−t0)) − 1] × 100%，年度区间（t1−t0=1）时退化为普通同比（R1）；中国官方统计（国家统计局科技统计）对 R&D 经费等指标同样以"比上年增长%"作主口径。方法族对照：

| 方法族 | 公式 | 适用 | 与本件 UI 对齐 |
|---|---|---|---|
| 年度同比（OECD MSTI 年度区间退化式） | (X_y − X_{y−1})/X_{y−1} | 相邻两年 | **完全对齐**（InnovationRanking.jsx:419 就地计算式） |
| CAGR 复合（OECD MSTI 标准式） | (I_t1/I_t0)^{1/n} − 1 | 多年区间年均 | 对齐（多年窗口可选） |
| 环比 MoM | (X_m − X_{m−1})/X_{m−1} | 月度监测 | 不对齐（UI 为年序列） |

结论：年度同比为唯一主口径，CAGR 为多年窗口补充口径，两者同一数据面可并行直算。完整版见附录 C。

## 二、计算过程

### 2.1 装载与规模校验

gkx 侧经 `_gkxdb.py` 连接（批次统一纪律），`dwd_org_financing_info` 全表 25,654 行与共享快照 `code/_snapshots/_shared_probe_s3_01_out.json` fix2 键「机构融资事件行数=25654」**零漂移对账**。日期维 `completion_date` 100% 覆盖（无 NULL、无零日期，lane6 探针 `completion_date 覆盖` 键实测 25,654/25,654、零日期 0 行）。久新侧 `ads_technology_yearly_metrics` 年份分布与 lane1 探针一致（2025 年 12,278 行/12,278 节点，B11 批间对账）。

### 2.2 gkx 融资事件年度序列与同比

按年聚合（排除零日期协议 B9）：2015 年 2,602 → 2016 峰值 3,884 → 2017 2,909 → 2018 2,257 → 2019 1,666 → 2020 1,948 → 2021 2,019 → 2022 1,757 → 2023 1,266 → 2024 919 → 2025 618 → 2026 在途 238。同比序列（产物键 `gkx_financing_event_growth_by_year_pct`）：2019 −26.19% / 2020 +16.93% / 2021 +3.64% / 2022 −12.98% / 2023 −27.95% / 2024 −27.41% / 2025 −32.75%。序列呈"2016 见顶、2017 起趋势性下行、2020 疫情年反弹、2021 后加速萎缩"的形态——这是采集池的衰减信号（结合 INNOV_010 的省份证据，该池为广东企业融资池），增长率的负值语义是"样本池覆盖收缩"，UI 展示必须带池口径注记，否则会被误读为"广东创新融资崩塌"。

```sql
SELECT YEAR(completion_date) y, COUNT(*) c
FROM gkx.dwd_org_financing_info
WHERE completion_date IS NOT NULL AND completion_date > '1000-01-01'
GROUP BY y ORDER BY y;
-- → 2016 峰值 3884；2019–2025 连续 7 年可算同比（B9 零日期协议）
```

### 2.3 久新现成 YoY 列核验

久新库有两张表**内置同比增长率列**，无需自算：`ads_emerging_topic_yearly_metrics.paper_count_yoy`（2025 年 4,496 行中 4,275 行非空，95.1%；2021–2026 六个年份均 93%+）与 `ads_research_problem_yearly_metrics.paper_growth_rate`（4,177 行中 1,549 行非空，37.1%——该表按问题×年组织，基期年无增长率属正常语义）。另 `ads_research_problem_development_snapshot.latest_growth_rate`（812 行问题快照中 414 行非空，51.0%）承载"最近增长率"点读数。这组现成列证明：增长率在久新库是**一等公民指标**（建模时即物化进表），判"完全直接支持"的核心证据即此。

### 2.4 久新技术节点论文总量与上行占比

除现成列外，本件对 `ads_technology_yearly_metrics` 做了节点级自连接验证：2023→2024 对 10,284 节点中 2,540 上行（24.71%）；2024→2025 对 9,280 节点中 1,514 上行（16.31%）；2025→2026 对 2,898 节点中仅 5 上行（0.17%，在途年证据）。全库论文总量同比：2024→2025 = (5,513−8,952)/8,952 = **−38.45%**。上行占比（up-share）是增长率的分布版：总量同比只给均值方向，上行占比给出"多少节点在涨"——2025 年总量同比 −38% 但仍有 16.3% 节点上行，说明衰减是结构性的（观察池收缩）而非全面萎缩，这是增长率读数在 UI 排名场景（哪些载体在涨）里更贴需求的口径。

### 2.5 dev 侧缺席的证据与处理

开发库 `enterprise_invest` 46,967 行中 `event_date` 有效覆盖 **0 行**（absence_probe 留证：`SELECT COUNT(*), SUM(CASE WHEN event_date > '1000-01-01' ...)` → 0）——dev 侧无任何可按年聚合的投资事件面，增长率在 dev 侧不可算。按三源铁律，两源（gkx+久新）直接承载已满足"完全直接支持"，dev 缺席如实记录不构成降档；但需注意：dev 的缺席意味着若未来以开发库为唯一生产源，增长率将失去投资维承载（修复建议见 §四）。

### 2.6 稳健性与口径敏感性

同比口径的两个已知陷阱逐一规避：**基期为零**——本件要求分母 X_{y−1} > 0 才计算（久新 rp 表基期年不计算增长率属正常，不算缺数）；**在途年**——2026 年 gkx 仅 238 事件、久新节点面仅 3,450 行（vs 2025 年 12,278），在途年若参与会产出深度负增长的假读数，本件全部读数排除 2026（B9）。CAGR 口径对窗口起点敏感（2015 起算与 2016 峰值起算结果差异大），多年窗口读数必须随行披露窗口。
