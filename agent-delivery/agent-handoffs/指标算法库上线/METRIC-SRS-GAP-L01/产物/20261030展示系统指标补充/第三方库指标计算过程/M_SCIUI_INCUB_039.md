## 摘要

「热门仪器利用率排行」是服务统计窗的资源热度条形图（横向 Top5，单位「%」，点击条形联动选中仪器刷新统计详情）。UI 行为链：`buildUsageRanking` 对当前筛选集 instruments 按 `usageRate` 降序取前 5 → `buildHorizontalBarOption` 渲染 → `:1456` 点击联动。数据侧判定：**完全不支持**——排序键 usageRate（机时利用率派生字段）三源零承载（本批共享探针 dev 542/gkx 280/久新 218 表实数扫描 + S3-07 l2b 15 列断言），排行主体（共享仪器台账）三源亦无表（SOFTSCI_003 留证）。mock 排行实为 Top4（仅 4 台仪器 88/76/64/52，演示值）。INCUB_008（S3-07 根字段件）已证「运行态零承载」，本件排行面复判一致。升档路径：机时日志接入 → 单台利用率可算 → 排行即 sort 直出。

- 需求判定：**UI 挂载件**（SRS 无同名；上位叶 1.1.1.1.4.6.4.1.1）。
- 复现状态：负证据断言脚本已跑通（三源表数断言 + 词族复核）。
- 档位结论：**完全不支持**（排序键与排行主体双缺）。
- 关键事实：mock 排行 Top4 = 88/76/64/52——仪器池规模不足自证演示态。
- 升档路径：机时日志接入 → 完全转换支持；利用率结果面直供 → 完全直接支持。

## 一、需求定义概述

### 1.1 所属功能模块

科技信息展示系统 → 科技成果展示 → 大型科学仪器共享/**服务统计**。四宫格之三：「热门仪器利用率排行」卡（横向条形，含选中仪器统计详情联动）。数据链：mock instruments 数组（usageRate 字段）→ `buildUsageRanking`（`:212-221`：sort 降序 + slice(0,5) + map 三元组）→ `buildHorizontalBarOption(usageRanking, "%")`（`:1453`）→ ECharts 渲染；`:1456` onClick 按 params.name 匹配仪器刷新统计详情区（INCUB_057 件消费点：利用率/预约量/服务次数/状态/所属机构五读数）。

mock 值全部为演示常量（4 台 88/76/64/52），不参与支持度结论。

### 1.2 为什么需要本指标

排行回答「哪些仪器最抢手」：管理者看资源利用的头部集中与闲置尾部（扩容/调配依据），创业者按热门度与排队预期遴选。SRS 上位功能（使用评价与频次统计）要求「自动收集仪器的使用频率」——排行是使用频率的排序视图。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**「热门仪器利用率排行」指标名未出现；SRS 只有频次统计功能句，没有排行口径（Top 几、窗口期年度/累计、并列破平局规则）。

### 1.4 类似指标权威方法可行性分析概要

利用率排行的权威基准是科技部《大型科研仪器开放共享评价考核实施细则》「仪器运行机时」（权重 15 分）：年有效工作机时 ÷ 年可用机时。方法族对照：

| 方法族 | 数据轴 | 数据要求 | 与本库匹配 |
|---|---|---|---|
| 机时利用率降序（考核口径） | 单台年机时 | 机时日志 + 台账 | **无（外部设备系统）** |
| 预约量代理排序 | 单台预约单数 | 预约流水 | **无（INCUB_057 同证）** |
| 库内静态近似 | — | 需任何运行态字段 | **无** |

结论：排行 = 排序键 + 台账两层，三源两层皆缺；负结论件。完整版见附录 C。

## 四、数据缺失情况

### 4.1 机时日志零承载（结构级，主因）

利用率 = 年有效工作机时 ÷ 年可用机时，分子分母均来自设备运行系统（开机日志/维护计划），三源无镜像。四缺失情形归属：**表不存在**。修复动作是**设备管理系统对接**，库内无法构建。

### 4.2 台账连带缺失

排行的横轴是仪器（名称/分类/机构），依赖台账（SOFTSCI_003 §4.1 同案）。机时先到而台账后到期间，只能出匿名排行（设备 ID 序），出不了名称标签。

### 4.3 修复建议与影响面

| 建议 | 类型 | 影响指标 | 说明 |
|---|---|---|---|
| 对接设备机时接口 | 外部系统对接 | 本件 + INCUB_007/008/019 + P10_037 | 一源解一族 |
| 接入共享仪器台账 | 外部数据源 | 本件 + SOFTSCI_003/004 + INCUB_035/057/061 | 排行标签层 |
| 破平局规则裁定 | 产品裁定 | 本件 | 同率场景 |

档位后果：机时 + 台账双接入 → 完全转换支持；利用率结果面直供 → 完全直接支持；无动作 → 维持完全不支持。推荐：机时与台账合并推共享平台一揽子对接。
