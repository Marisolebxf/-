## 工作过程

1. 核对对接文档与纪要：深势三类接口均返回 `detailUrl`，跳转能力本身不缺。
2. 原方案 A（`window.open` 外跳）实现后，用户走查裁定「三个页面跳转链接都用弹框形式打开而不是跳转一个新的页签」。
3. 改为方案 B：抽 `DetailIframeModal` 公共组件，三页 `openDetail()` 统一 `detailVisible = true`。
4. 先实测深势详情页响应头，确认可被 iframe 内嵌；再落地组件（含无 url 时 `a-empty`、加载态）。
5. `pnpm type-check` + `pnpm build-only` 通过。

## 决策记录

| 决策 | 结论 | 依据 |
|---|---|---|
| 详情打开方式 | **iframe 弹窗**，不做外跳 | 用户 2026-10-30 走查明确要求；外跳丢当前页上下文 |
| 弹窗是否保留外链 | 保留，标题栏「在新窗口打开」 | 深势页面在 iframe 内偶发需要更大视口的场景，给用户退路 |
| 组件归属 | `views/service/components/` 跨三页共用 | 同一交互第 2 处出现即封装（仓级规约） |
| 门户入口是否展示深势不支持字段 | 不展示 | 前置任务 01 已固化：奖金、竞赛类型下拉、点赞排序均不呈现 |
