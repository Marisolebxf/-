## 工作过程

1. 首版误做成自创极简页 → 用户裁定「不能动原型样式结构，只能修改纪要明确改动的点」→ 整体回退，按原型 JSX 结构复刻。
2. 还原毛玻璃卡片与页壳单层（壳由 `DefaultLayout .content-shell-layout` 承担，页根 `transparent` + 无边框），去掉自建双层壳。
3. 地图无坐标 → 新增 `geo.ts` 按地址文字三级模糊匹配定位（`venueAddress` → 标题 → 深圳场馆 13 处 / 深圳 11 区 / 全国 15 城），确定性抖动防重叠（禁 `Math.random`）。
4. 红框问题逐条修：KPI 占位字符串 → 取真实 stats；`recommendation` 未剥 `data` 层 → 补齐；筛选框 `value=""` 假选项 → 用接口真实枚举 + 「全部」。
5. 「每个活动类型都有 247 条但地图只有 1 个点」→ 样本量 13 → 100，字典扩充，「科技园」泛词长词优先。
6. 「活动分类数量和比例不对」→ 查明深势四类 `stats` 完全相同，改为只取首份、饼图按当前列表真实统计。
7. 列表卡片高度不一 → `height:100%` + 标题固定两行 + `organizer` `margin-top:auto`。
8. 栅格宽度反复调整，最终定为每行 2 卡 + 页根 `overflow-x: hidden`（Arco `a-row` gutter 负 margin 会横向溢出）。

## 决策记录

| 决策 | 结论 | 依据 |
|---|---|---|
| 页面形态 | **完整复刻 demo 原型**，不做精简重写 | 用户裁定「不是让你重写这个页面，而是完全拿原型页面改成真实接口」 |
| 四类 stats 口径 | 只取首份，不跨类累加 | 深势返回四类 stats 完全相同（各 247/2243/79/107），累加会翻 4 倍 |
| 活动分类饼图 | 前端按当前列表真实计数 | 接口无按类聚合口径 |
| KPI 合作机构 / 专家讲者 | 316 / 428（各类 stats 真实累加） | 两项在四类下数值不同，可累加 |
| 地图定位 | 地址文字三级模糊匹配 + 确定性抖动 | 接口无 GIS 坐标 |
| 列表分页 | **前端分页**（6/12/24，默认 6） | 地图与图例需要全量，列表只切片 |
| 栅格 | 每行 2 卡 | 用户最终裁定（3 卡在常见宽度下第三张显示不全） |
| 横向滚动 | `overflow-x: hidden` | Arco gutter 负 margin 机制 |
