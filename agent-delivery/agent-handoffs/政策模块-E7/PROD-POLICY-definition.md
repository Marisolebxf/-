## 1. 产品定位

### 1.1 一句话定位

政策要素（E7）是 GKX 智树平台的"创新关键变量"维度，目标是让深圳市科技治理者从"被动响应政策"转向"主动塑造政策环境"：对内（专题分析层）服务深度研判与战略决策，对外（门户政策扶持层）服务面向产业的政策扶持全景展示。

### 1.2 两个系统中的定位与价值

| 系统 | 入口层 | 用户角色 | 定位 | 核心价值 |
|------|--------|----------|------|----------|
| **科技专题服务系统**（E7 政策分析，`/policy/*`） | 战略分析层 | 政策研究员 / 决策支撑 / 智库分析师 | 智能化政策感知与评估引擎，聚焦特定产业/技术领域的政策**演进、区域差异、本地实效** | 把握政策窗口期、借鉴先进经验、定位深圳政策短板（"支持力度—产业适配性—落地实效性"三维框架） |
| **智慧服务门户系统**（政策扶持，`/policy-portal/*`） | 门户展示层 | 产业研究决策者 / 公众 / 招商人员 | 面向产业的政策扶持情况全景呈现，"看得见、点得开、链得到源" | 一屏看清全国/省/市/深圳政策概况、密度、产业覆盖、力度排名与最新动态 |

### 1.3 与算法库 / 数据血缘的关系

- 政策维度的所有统计与评估能力由**算法库（Python）后台**统一提供（5 基础指标 + 实体图谱 + 6 深度模型 + 文本解析/匹配/推演），前端只通过 Java REST 消费聚合结果，不写算法、不直连 nGQL（架构铁律 1/2/7）。
- 界面上每个统计指标遵循 D9 数据血缘 8 件套，指标命名空间 `M_POLICY_*`，Wave 0 全 Mock 并加 🧪 角标。

### 1.4 本次原型边界（重要）

- **算法全集实现**（每个政策算法都要跑通，见 §4），但**前端展示仅覆盖 9 页**（专题 3 + 门户 6）。
- 展示系统科技政策跟踪的三个子功能（科创政策全景 DS-10 / 政策分析评价 DS-11 / 政策效果推演 DS-12）**本次不做前端页面**，相关后台算法能力仍随全集实现（用于支撑专题/门户页面与未来扩展）。

## 2. 页面清单（9 页）

> 路由、对应 P-XX、task_id 均引用 `catalog-topic-policy.yaml` coordinator 已回填字段。优先级：P0 = 评审主线必达；P1 = 增强体验/可演示但可降级。

### 2.1 专题分析层（3 页，`/policy/*`，对应 bid §1.1.1.2.4.2.6 政策分析）

#### 页 1 · `/policy/overview` — 政策时序分析（P-70，优先级 **P0**）

- **核心功能**：用户选定产业/技术领域后，系统自动关联聚合相关国家及地方政策，基于发布时间、效力层级、支持力度构建时序模型，生成**政策密度指数**与**支持强度趋势图**，识别政策演进关键节点与周期性规律、预判政策窗口期。
- **关键交互**：领域选择器 → 时序粒度切换（年/季/月）→ 趋势折线 + 密度热度条 + 关键节点标注（窗口期高亮）→ 节点点选联动政策明细 → 报告导出。
- **对应 bid 章节**：§1.1.1.2.4.2.6.1（政策数据自动关联 + 时序模型智能分析）。
- **对应 P-XX**：P-70（route=`/policy/overview`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_DENSITY_INDEX`、`M_POLICY_INTENSITY_TREND`、`M_POLICY_NEW_COUNT_M`。

#### 页 2 · `/policy/analysis` — 区域政策对比（P-72，优先级 **P0**）

- **核心功能**：自动采集长三角、粤港澳大湾区等核心经济区指定领域政策文本，NLP 提取补贴标准/准入条件等结构化条款，在统一评价框架下生成**区域对比矩阵 + 雷达图/热力图**，揭示区域政策差异与竞争优势。
- **关键交互**：多区域多选 → 评价维度配置 → 对比矩阵（行=区域，列=指标）→ 雷达图/热力图切换 → 差异自动标注与结论 → 对比历史保存/导出。
- **对应 bid 章节**：§1.1.1.2.4.2.6.2（跨区域政策采集 + 标准化对比分析）。
- **对应 P-XX**：P-72（route=`/policy/analysis`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_REGION_SCORE`、`M_POLICY_SUBSIDY_STD`、`M_POLICY_REGION_GAP`。

#### 页 3 · `/policy/recommendation` — 深圳政策现状分析（三维框架）（P-73，优先级 **P0**）

- **核心功能**：基于"**政策支持力度—产业适配性—落地实效性**"三维框架，用户自定义指标（政策数量、资金规模、创新激励等）与权重，系统自动计算深圳政策得分，仪表盘可视化优势与短板，输出针对性优化方案。
- **关键交互**：三维框架配置面板（指标勾选 + 权重滑杆）→ 实时算分 → 仪表盘 + 数字卡片 + 雷达图（优势/短板分色）→ 短板成因下钻 → 优化策略建议卡 → 评估报告导出。
- **对应 bid 章节**：§1.1.1.2.4.2.6.3（指标体系构建 + 深圳政策对标 + 结果可视化输出）。
- **对应 P-XX**：P-73（route=`/policy/recommendation`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_SUPPORT_SCORE`、`M_POLICY_INDUSTRY_FIT_SCORE`、`M_POLICY_EFFECT_SCORE`、`M_POLICY_SZ_COMPETITIVE_SCORE`。

### 2.2 门户政策扶持层（6 页，`/policy-portal/*`，对应 bid §1.1.1.1.1.1.2 政策扶持）

#### 页 4 · `/policy-portal/overview` — 政策概况统计（P-17，优先级 **P0**）

- **核心功能**：统计全国、省、市三级政策数量与发布时间连续性，支持多维筛选、导出、权限分级。
- **关键交互**：三级（全国/省/市）Tab 切换 → 数字卡片 + 数量对比柱状 + 连续性折线 → 多维筛选（领域/类型/时间）→ 导出。
- **对应 bid 章节**：§1.1.1.1.1.1.2.1（全国/省级/市级政策统计）。
- **对应 P-XX**：P-17（route=`/policy-portal/overview`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_NATIONAL_COUNT`、`M_POLICY_PROVINCE_COUNT`、`M_POLICY_CITY_COUNT`、`M_POLICY_CONTINUITY_INDEX`。

#### 页 5 · `/policy-portal/map` — 政策地图（P-18，优先级 **P0**）

- **核心功能**：地图层级切换（全国→省→市）+ 热力渲染展示政策密度分布，支持区域交互、规则配置、导出。
- **关键交互**：Leaflet 地图三级下钻 → 热力/分级填色 → 区域点选弹出政策概要 → 图例与渲染规则配置 → 导出图片。
- **对应 bid 章节**：§1.1.1.1.1.1.2.2（政策地图）。
- **对应 P-XX**：P-18（route=`/policy-portal/map`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_REGIONAL_DENSITY`。

#### 页 6 · `/policy-portal/industry-coverage` — 政策产业覆盖（P-19，优先级 **P1**）

- **核心功能**：结合产业链全景图呈现各节点政策覆盖状态、覆盖缺口与覆盖度统计。
- **关键交互**：产业链全景图（节点着色=覆盖度）→ 节点点选展开覆盖政策清单 → 覆盖缺口高亮 → 覆盖度统计面板。
- **对应 bid 章节**：§1.1.1.1.1.1.2.3（政策产业覆盖）。
- **对应 P-XX**：P-19（route=`/policy-portal/industry-coverage`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_CHAIN_COVERAGE_RATE`、`M_POLICY_COVERAGE_GAP_COUNT`。

#### 页 7 · `/policy-portal/intensity-rank` — 政策力度排名（P-20，优先级 **P1**）

- **核心功能**：基于补贴金额、税收优惠、政策数量、执行周期等指标，形成**省级**与**城市**两套政策力度排名。
- **关键交互**：省级/城市 Tab 切换 → 排行榜（条形 + 名次徽标）→ 指标权重说明 → 点选查看构成明细 → 导出。
- **对应 bid 章节**：§1.1.1.1.1.1.2.4（省级政策力度排名 + 城市政策力度排名）。
- **对应 P-XX**：P-20（route=`/policy-portal/intensity-rank`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_INTENSITY_INDEX`、`M_POLICY_PROVINCE_RANK`、`M_POLICY_CITY_RANK`。

#### 页 8 · `/policy-portal/latest` — 最新政策动态（P-21，优先级 **P0**）

- **核心功能**：时间线方式展示全国各地/深圳最新政策动态新闻，链接至源地址；支持筛选、搜索、收藏、分享。
- **关键交互**：时间线流 → 筛选（地区/领域/时间）+ 关键词搜索 → 卡片点击跳转源链接 → 收藏/分享。
- **对应 bid 章节**：§1.1.1.1.1.1.2.5（最新政策动态）。
- **对应 P-XX**：P-21（route=`/policy-portal/latest`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_LATEST_COUNT_D`（明细列表为主，统计型指标少）。

#### 页 9 · `/policy-portal/shenzhen` — 深圳政策对比（P-22，优先级 **P0**）

- **核心功能**：对深圳政策数量、区域分布、产业覆盖、最新政策时间线进行综合展示与联动。
- **关键交互**：四区块联动看板（数量趋势 + 各区分布地图/图表 + 产业覆盖 + 最新时间线）→ 任一区块筛选联动其余区块。
- **对应 bid 章节**：§1.1.1.1.1.1.2.6（深圳政策数量对比/区域分布/产业覆盖/最新政策）。
- **对应 P-XX**：P-22（route=`/policy-portal/shenzhen`，task_id=`E-E7-POLICY-M1-L05`）。
- **关键指标（示例）**：`M_POLICY_SZ_COUNT`、`M_POLICY_SZ_DISTRICT_DIST`、`M_POLICY_SZ_CHAIN_COVERAGE`。

## 4. 算法全集说明（"每个算法都跑"）

> 原则：**算法层全集实现**（Python，L01/L02/L03），是本原型的后台底座；**前端展示仅覆盖专题 3 页 + 门户 6 页**。未被 9 页直接消费的算法仍需跑通并通过 API 暴露，供血缘核验、未来 DS-10/11/12 与 Wave2 扩展复用。

### 4.1 政策基础指标模型（5 类，task L01，对应 P-01~P-07）

| # | 指标模型 | 内容 | 前端消费页 |
|---|----------|------|-----------|
| 1 | 政策级别指标 | 国/省/市/区四级政策数量与趋势 | P-17、P-22 |
| 2 | 政策类型指标 | 产业/人才/企业扶持等类型分布与趋势 | P-17、P-19 |
| 3 | 政策时序指标 | 各时期发布数量 + 增长率（密度/连续性） | P-70、P-17 |
| 4 | 全国政策分布指标 | 各省政策数量与区域分布趋势 | P-18、P-20、P-72 |
| 5 | 深圳政策分布指标 | 深圳各区政策分布与增长 | P-22、P-73 |

### 4.2 政策实体图谱（2 项，task L02，对应 P-08/P-09）

- **政策实体识别构建**：规则+词典+NER 抽取政策名称/级别/类型/发布地点/发布时间等实体与属性。→ 支撑 P-70 自动关联、P-72 条款提取。
- **政策实体关系抽取**：抽取政策↔主题/目标/实施主体/受益对象/监管机构，以及政策↔产业/技术/企业/人才/科研机构/服务机构的扶持/适用/监管关系。→ 支撑 P-19 产业覆盖、P-72 关联对比、未来关联网络。

### 4.3 政策深度分析 6 模型（task L03，对应 P-10~P-16）

| # | 模型 | 输出 | 前端消费页 |
|---|------|------|-----------|
| 1 | 政策焦点识别模型 | 焦点/堵点结构化结果 | P-73 短板成因、P-70 节点解读 |
| 2 | 政策力度评估模型 | 政策力度指数 + 排行榜 | **P-20 力度排名**、P-73 支持力度维 |
| 3 | 政策效果评估模型 | 政策效果评估指数 + 分维结果 | P-73 落地实效性维 |
| 4 | 政策短板识别模型 | 覆盖/有效性短板 + 成因 | P-73 短板、P-19 覆盖缺口 |
| 5 | 政策机遇识别模型 | 政策机遇标注（关注度/影响力/稳定性） | P-73 优化方向（增强） |
| 6 | 政策布局推荐模型 | 机遇+短板→布局/调整建议 | P-73 优化策略卡（增强） |

### 4.4 政策文本能力（随全集实现，9 页弱消费 / 主要供 Wave2 与 DS-10/11/12）

- 政策文本智能解析 / 结论自动生成 / **摘要生成** / 关键点高亮 / 应用建议（对应 P-52、P-63、P-68）。
- 政策实体属性**标注**（实体识别副产物，P-08）。

### 4.5 政策匹配推送（随全集实现，对应 P-38）

- 基于企业/用户特征做政策标签匹配、自动推送、效果统计。本次无独立前端页，算法跑通并暴露 API（与企业要素招引/培育推荐的"政策匹配度"复用同一能力族）。

### 4.6 政策效果推演仿真（随全集实现，对应 P-58~P-62）

- 政策出台前参数配置 + 模型选择 + 多方案对比仿真；相似政策匹配与效果预测；GDP/就业等经济指标空间模拟。**算法全集实现**，但**前端属展示系统 DS-12，本次排除**，不出页面。

> **结论**：政策算法 = 5 基础指标 + 2 实体图谱 + 6 深度模型 + 文本解析/摘要/标注 + 政策匹配推送 + 政策效果推演仿真，**全集跑通**；前端只在专题 3 页 + 门户 6 页消费其中可视化结果，其余以 API + 血缘登记形式就位。
