# 生产 TDSQL 磁盘估算（加工库 / 线上库）

- 日期：2026-10-19
- 用途：按总集已提供的约 20% 样例，估算生产 TDSQL 磁盘并申请资源
- 实测实例：zhipu-edu `10.50.11.76:3306`（样例已手工同步到该库）
- 口径：`information_schema.tables` 的 `data_length + index_length`。20% 按线性 ×5 外推到全量
- 备份不放在下面两块数据盘上

## 1. 实测（20% 样例）

| 库 | 占用 | 表 | 有数据的表 |
|---|---:|---:|---:|
| `demo_gkxlumenx_ods` | 40.4 GiB | — | — |
| `demo_gkxlumenx_dwd` | 7.2 GiB | 139 | 29 |
| `demo_gkxlumenx_ads` | 1.0 GiB | 101 | 44 |
| `demo_gkxlumenx_dim` | 2.6 MiB | 18 | 18 |
| 平台库、`gkxlumenx_cfg` 等 | 约 0.03 GiB | — | — |
| **合计** | **48.6 GiB** | | |

DWD 体积集中在明细原文，其中 `enterprise_recruit` 约 5.4 GiB。ADS 的 1.0 GiB 几乎全是约 18 万家企业的评分、排名和图谱结果。空着的 57 张 ADS 表主要是产业链全景、创新事件、政策图谱等结果表。

## 2. 估算约定

1. ODS 全量 = 当前 40.4 GiB × 5 = **202 GiB**。
2. DWD 开发未完成。完成后与 ODS 同量，全量 **202 GiB**，不按现在的 7.2 GiB × 5。
3. ADS 是结果表，不是明细原文。企业结果 ×5 约 5 GiB；未灌的产业链、政策、创新监测、服务机构按同量级估，ADS 全量约 **25 GiB**。不按 ODS 的 202 GiB 估。
4. DIM、CFG、平台库（用户权限、Nacos、任务、专题分析任务与检索记录）全量不到 **3 GiB**。

## 3. 两套库各放什么

加工库与线上库分开。依据 `architecture-baseline.md`：Java 只读 ADS；ODS → DWD → ADS 在数据工厂完成；明细检索走 Elasticsearch。

| | 加工库 | 线上库 |
|---|---|---|
| 放入 | 当批 ODS、换批时的上一批/在途 ODS、完成后的全量 DWD | ADS、DIM、CFG、平台库 |
| 不放入 | 线上事务库 | ODS；DWD 招聘/新闻/专利等原文 |
| 全量数据 | 202 + 202 + 202 = **606 GiB** | 约 **30 GiB** |
| 申请磁盘 | **1 TiB** | **200 GiB** |

加工库 1 TiB：606 GiB 业务数据，加上约 15% InnoDB 膨胀和 30% 空闲，换批时新旧 ODS 可以并存。

线上库 200 GiB：30 GiB 业务数据之外留结果表继续增加、binlog 和空闲。只按已有企业 ADS ×5 申请 100 GiB 偏紧。

现有 CMS、专题检索仍直接读 DWD 主数据（企业主档、产业链、政策主表）。这些主档现在约 1 GiB，全量约 5 GiB，放进线上库不改变 200 GiB。招聘、新闻、专利原文留在加工库。若把做完后的整库 DWD 再抄一份到线上，线上要另加约 200 GiB，与加工/线上分离重复。
