## 4. 整体流程

1. 用户看多方案对比。前端提交 `jobs`，种类为方案对照。element 读缺项表里的方案对照行。雷达和 KPI 的数就是这些行上的对照值。少于两行则对比空，不造第二个方案。
2. 用户选定一个方案并调整关键参数。前端再次提交 `jobs`，种类为参数模拟。element 按方案和参数档拣行，返回评估结果、趋势和已归档的那次模拟。对不上则该块空。切参数不自动起任务，也不调用推演函数。
3. 用户看实施路径。前端提交 `jobs`，种类为路径与风险。element 按方案读节点、时间进度和风险。无行则路径空。
4. 用户看意见。前端调 `shells`，种类为互动意见。element 按方案读意见行。页面上新打的字不进入这次请求的写库。
5. 用户导出方案报告。前端调 `shells`，种类为方案报告。element 读该范围的方案对照行和意见行。有行则从行生成导出内容。无行则导出空。不返回一份写死的文件。

某一次 `jobs` 或 `shells` 失败，不清空 `evaluation/counts` 已经返回的短板条数和机遇条数，也不清空其他种类已经返回的区块。
