## 功能点

| 功能点 | 谁在什么情况下做什么 | 界面上必须看见什么 |
|---|---|---|
| 211-1 列表 | 打开科创政策全景里这份报告所在的页 | 有成功行时，报告列表只出现这些行。每一行看见评估范围、生成时间，以及「查看报告」「下载」。不看见综合评分、评估维度得分、评估机构。没有成功行时，同页现有四张卡仍按现在的内容留着，报告列表不改成空白 |
| 211-2 查看 | 在成功行上点「查看报告」 | 弹窗打开。标题是「政策效果评估报告」。往下按固定顺序看见：评估范围、生成时间、达成度、社会影响、存在问题、改进建议、报告正文。问题和建议按条排列。不看见综合评分、评估维度得分、评估机构，也不看见图表 |
| 211-3 下载 | 在列表上点「下载」，或在已打开的同一份报告弹窗里点「导出 Word」「导出 PDF」 | 这三处是同一功能点，交出同一套段落，顺序与查看弹窗一致，标题同为「政策效果评估报告」。列表「下载」给出 Word 与 PDF 两档，弹窗两个导出按钮各对应一档。PDF 是真 pdf。Word 是与 PDF 同源的 html，存成 `.doc` |

列表「下载」与弹窗里的导出 Word、导出 PDF 不另写第二套文稿，也不把综合评分、维度得分、评估机构、结论摘要或图表补进文件。

## 段落顺序（查看与下载共用）

顺序固定，不多段、不少段、不调换：

1. 标题「政策效果评估报告」
2. 评估范围（该行 `scope_text`）
3. 生成时间（该行 `generated_at`）
4. 达成度
5. 社会影响
6. 存在问题
7. 改进建议
8. 报告正文

存在问题、改进建议：按中文分号「；」或换行拆成条，去掉空段，一条一个条目。整段没有可拆内容时不造条目。达成度、社会影响、报告正文保持整段，不按分号拆条。

## 状态

用户能看见的提示只用下面这几句。这些句子里不出现库表名、gapfill、mock、缺项演示。

| 状态 | 界面上必须看见什么 |
|---|---|
| 有成功行 | 报告列表只列出成功行（判定见现状，不展示判定用语）。每行是评估范围、生成时间、「查看报告」「下载」。同页另外三张卡保持原样 |
| 没有成功行 | 现有四张卡先留着，不清空：政策受众反馈收集、政策效果评估报告、政策实施效果跟踪、政策匹配与推送。报告卡继续显示这次打开时已经在显示的行。不提示切换失败，也不另写「没有生成成功」 |
| 列表加载失败 | 只在政策效果评估报告这张卡里显示「报告暂时读不到，可稍后重试」。另外三张卡不清空、不改成这句 |

| 正文某段为空 | 该段标题仍在，标题下显示「暂无」。不编一段补白，不把别的段抄过来 |

有成功行之后，不以「缺项演示」开头的规则未满足的行不再进报告列表。没有成功行时不加这句过滤说明。
