## 核过的事实

1. **有成功行时列表只显示成功行；没有成功行时现有行和四张卡还在。** 成功行仍是 `fill_method=llm`，且达成度、社会影响、存在问题、改进建议、报告正文都不以「缺项演示」开头。接口返回全部行，过滤在展示前端。种子那两句长范围对不上源表标题时插新行，不改种子；新行一旦成为成功行，列表只留这些行，种子不再进列表。一条成功行都没有，或抄入失败：不删旧行，报告卡继续显示表里现有行；政策受众反馈收集、政策效果评估报告、政策实施效果跟踪、政策匹配与推送四张卡不清空。

2. **查看与下载是同一八段；空段「暂无」；不出现评分。** 查看弹窗、列表下载、弹窗导出都沿用界面稿那一份 HTML：标题「政策效果评估报告」、评估范围、生成时间、达成度、社会影响、存在问题、改进建议、报告正文。空段留标题，正文写「暂无」。这份 HTML 没有综合评分、评估维度得分、评估机构、图表。插入多带的 `metric_id`、`gap_item`、`gapfill_batch_id` 不进这八段，也不另加评分列。Java 不拼正文。

3. **列表一个「下载」只下 PDF，弹窗两档是同一份文稿。** 列表不拆成两个按钮，点「下载」只出 PDF。查看弹窗仍是「导出 Word」和「导出 PDF」。两档都是第 2 条那一份 HTML，都走现有 `POST /display/v1/situation/report/generate`，`reportType=policy-assessment-report`。PDF 是真 pdf，Word 是与 PDF 同源的 html，存成 `.doc`。
