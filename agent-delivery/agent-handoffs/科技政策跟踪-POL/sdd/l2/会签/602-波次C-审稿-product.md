## 硬清单

1. 需规原文每个分句都有功能点编号。需规那一句拆成系统引用多源、采集接入、去重合并、格式标准化、噪声过滤、建立校验规则、准确性完整性一致性、高质量数据源，说明书功能点表分别是 602-1 至 602-8（约 240–249 行）。四单没有另起一套编号。
2. 602-1 至 602-6 写了界面上必须看见什么，能按说明书那张表截图：选择政策、国内海外分块、执行按钮、六条规则行、应合并、待标准化、停用仍在、没点执行时批次为空。602-7、602-8 有三处截图对不上，见 P-C1、P-C2、P-C3。
3. 状态清单覆盖了未选、未命中、停用、无数据、失败。说明书状态表（约 253–263 行）和 API 第 5 节九行一致：未选、未执行、执行中、贴源无数、ID 不在贴源、ID 未命中、规则停用、无加工事实、读取失败。未命中是「这次没搜到」，无数据是「这一源还没有贴源数据」和命中 null，失败是「读取失败」，三句没有收成同一个 0。结果三态「成功、部分、失败」另有缺口，见 P-C3。
4. 功能点落点：602-1 落到 `GET …/governance/clean-candidates`（入口、来源、搜索词、贴源 id）和两表列（国内 `title` / `publish_code` / `ministry` / `publish_date` / `id`，海外 `title` / `organ` / `publish_date` / `id`）。602-2 落到执行响应的批次头（批次名，条数等于这次勾选条数）。602-3、602-4 的判定文案落在页上固定句，能算的列在 DATA 第 4 节。602-5、一致性整条没有列，命中 null，和「没有加工事实」同一句。602-6 落在 ARCH 第 6 节，启停不落库。漏的点名见下面四条。
5. 影响清单没有清零。四单正文里的旧口径已经拿掉：不再用单值 `policyId`、不再用 `script_state.status` 六值、不再把 `policy_base_info` 当候选（API 第 29 行，DATA 第 22 行，ARCH 第 27 行，METRIC 第 18 行），文首改为「已按当日裁定重写」。说明书「需同步（影响清单）」（约 315–325 行）仍写四单本轮不改，总控、合规演示用例、PC-1 导语和第 4 节、第 11.2 节仍是「只读第 6 项」。说明书自己写了这三处留到后一波，本波任务也不许改说明书，所以不另开一条异议。后一波回写清单时，把四单改成已重写，其余仍标留后。

## 异议

[product-agent] P-C1 · 点过执行之后，完整性、一致性要看见的「一条脱敏失败样例」没有落到响应字段，也没有表列。一致性、噪声过滤现在没有列，样例会不会被写成一句假失败，设计没写。 · 依据：说明书 602-7、602-8（约 248–249 行）；读法方案 3.2 把「脱敏失败样例」列在点执行之后要看见的块；API 第 3 节响应表只有命中条数、状态、应合并、待标准化、命中 null，没有样例；DATA 第 4 节五条的列里也没有样例。 · 建议：执行响应为每条规则加「脱敏失败样例」。无加工事实时这项为 null，不造示例句。一致性、噪声过滤与缺列的作用范围同样为 null，并在 API 写明。

[product-agent] P-C2 · 准确性这一行要看见一个看得出是演示的数，数据稿四列里没有数字；选中的贴源 id 在演示表里没有行时，界面会落成空白。裁定选的是演示数，不是空白。 · 依据：裁定清单第 3 条；说明书 602-7；API 第 77 行写「数放进这一次响应」；DATA 第 5 节与 `ads.md`「准确性演示」只有来源、贴源 id、演示命中说明、写入批次标记，并写明本叶不连库灌数。无行时没有写成演示数、读取失败或无加工事实中的哪一句。 · 建议：请监管人定一种。加一列演示条数，或写明没有行时仍显示固定演示数并标明演示。不要收成无加工事实的空白，也不要写成已经按原文核过。

[product-agent] P-C3 · 「成功、部分、失败」只写了三选一，没有判定句。截图无法验收 602-8，也容易和「读取失败」混成同一句。 · 依据：说明书 602-8（约 249 行）；ARCH 第 108 行；API 第 74 行。状态清单里的失败只定义了读取失败。 · 建议：补三句，由监管人确认后再写进 API。读取失败、无加工事实不占用这三句。产品不代选哪一种算法。

[product-agent] P-C4 · 有可判定结果时，批次明细上的更新时间没有来源。用户在去重合并、格式标准化、完整性能够判定的时候，看不见一个允许使用的时间。 · 依据：说明书 602-8 要求看见更新时间；DATA 第 60 行只写没有事实时留空，并禁止用贴源 `updated_time` 和 `script_state.tried_at`；API 只在无加工事实那一行写更新时间留空。 · 建议：有可判定结果时，更新时间用这一次响应的时刻，并标明是这一次请求，不是贴源行的更新时间。没有事实时仍留空。

[product-agent] P-C5 · 智能搜索的词，接口稿和数据稿不是同一句。海外块按文号或发文部门去搜，会显示「这次没搜到」，说明书没有告诉用户海外不按这两项搜。 · 依据：说明书约 280 行「按标题、文号或发文部门」；API 第 43 行搜索词仍是这一句，没有分源；DATA 第 32 行海外只搜 `title`，文号和发文部门不参与。列的收法是先前审稿 D1，两稿没对齐。 · 建议：API 改成与 DATA 一致：海外搜索词只对标题。不要把没参与搜索说成该 ID 不存在。

[product-agent] P-C6 · `stores/README.md` 的 ADS 索引行仍只写 16 张，没有指向准确性草稿表。只按索引找表的人会漏掉 602-7 的演示数。 · 依据：README 第 21 行仍是「ADS 16 张」，日期停在 2026-11-09；`ads.md` 第 97 行已有「准确性演示」，并写明不计入那 16 张；`CHANGELOG.md` 2026-11-10 那一行和 `01-data-flow.md` 第 75 行已经记下 `policy_accuracy_demo`。 · 建议：索引行加半句，指向这张草稿表，并写明不计入 16 张。不要把草稿表算进 as-built 16 张。
