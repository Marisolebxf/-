# DS-11 viz 读面 BE 侦察笔记（2026-11-12）

- 来源：只读侦察（lumen-svc-platform dev @ b939d010 前后基线）；供 `POL-L2-DS11-VIZ-GAPFILL-L02-BE` 开工引用
- 结论一句话：**完全复刻既有 evaluation 读面模式，零新建类即可挂上 viz 七块**

## 1. 既有链路（三层，网关 StripPrefix=1：前端 `/display/v1/**` → display `/v1/**` → element `/v1/element/**`）

| 层 | 关键类 |
|---|---|
| display（7099，对外唯一面） | `gkxlumen-display/.../controller/PolicyEvaluationController.java`（`/v1/policy/evaluation`：GET counts/shells、POST jobs）；`service/PolicyEvaluationService.java`（kind 分发核心）；`feign/RemoteElementClient.java`（每方法 `@NoToken`） |
| element（7082，Controller 全量 `@Inner`，仅 display 可调） | `gkxlumen-element/.../controller/PolicyGapfillController.java`（`/evaluation/counts|shells|template|trend|partition|scheme` 等 20+ 端点）；`support/ElementDao.java`（JdbcTemplate 只读封装） |

**本链路无 Mapper / 无 DTO**：Controller 直接持有 SQL 常量 + `ElementDao.listOrEmpty(...)`，返回 `R<Map<String,Object>>`（`records` 键包 List<Map>，snake_case 由 DAO 统一转 camelCase）。

## 2. 可复用模式要点

- **数据源**：element 单 JdbcTemplate 直连 MySQL，全仓无 `@DS`。库切换靠 SQL 占位符 `{gapfill}` → `gkxlumenx_gapfill`（`ElementDao.qualify()` 替换；可经 `ELEMENT_GAPFILL_DB` 覆盖）。连接 `hikari read-only: true`。
- `listOrEmpty(sql, args)`：表未建/库不存在/查询失败 → `List.of()` + log.warn，**不建表不插入**（D16）。
- 端点写法惯例：列清单写死 SQL 常量（注明与灌数脚本/缺项任务一致，禁 `SELECT *`）；`row_kind` 等中文枚举闭集先验后查，闭集外不查表直接空 records；可选过滤读全量后 Java 内存筛（带 `ponytail:` 注释）。
- display `PolicyEvaluationService` kind 分发：`shells(kind,...)`（互动意见/方案报告/模板选用 → 各 element 端点；其他 → 空 records）；`jobs(body)`：`JOB_KINDS=Set.of("趋势","分区","方案对照","参数模拟","路径与风险")` 同步读；`sub_type` 白名单走异步。**viz 做同步读，不进异步白名单**（先例 219/220/227-230 均如此）。
- DS12 simulation 链路模板：`PolicySimulationController` → `PolicySimulationService.jobs()`（kind 闭集 + `ready()` 前置校验）→ `PolicySimulationReadController` 按 kind 分发到 `gapfill_policy_sim_forecast`（row_kind=请求种类）/ `gapfill_policy_sim_result`（映射）/ `_stakeholder` / `_sim_score` / `{ads}.policy_text_parse`。「未出台仿真」空行才调 Python LLM 兜底（表先行、LLM 兜底先例）。

## 3. viz 新读面建议落点

1. **element**（推荐主改点）：`PolicyGapfillController` 加 `@Inner @GetMapping("/evaluation/viz")`，SQL 常量 `SELECT ... FROM {gapfill}.<viz表> WHERE row_kind = ? ORDER BY id`；表名族与分表/单表以 DATA 单（`POL-L2-DS11-VIZ-GAPFILL-L02-DATA`）定稿为准。若七块参数差异大，可在同包新建 `PolicyEvalVizController`（同风格，零框架改动）。
2. **display**：`PolicyEvaluationController` 加 `GET /v1/policy/evaluation/viz`（`block` 参数收七块），`PolicyEvaluationService` 加 viz 分支；`RemoteElementClient` 加 `@NoToken @GetMapping("/v1/element/policy/evaluation/viz")`。对外即 `/display/v1/policy/evaluation/viz`。
3. **空态惯例**：element/display 一律 `R.ok(Map.of("records", List.of()))` 恒 200，不抛 501/404；闭集外/条件不齐/表未建/Feign 失败全落空 records。分值列缺失保持 NULL（不造 0），计数列经 `ElementDao.normalize()` 保证 JSON 数字 int（防 Long→字符串致 ECharts 画不出）。
4. **血缘列**：读面 SELECT 清单含 `is_mock, metric_id, gap_item, fill_method, gapfill_batch_id, generated_at`（与 DS12 缺项表惯例一致，以 DATA 定稿为准）。

## 4. 风险与红线（BE 单实现时逐条自检）

1. `@Inner` + `@NoToken` 必须配对：display 侧 Feign 方法漏 `@NoToken` → 缺 `from: Y` 内部头，下游 `@Inner` 切面拒绝，表现为 200 但空数据。
2. 路由避让：element `/v1/element/policy/**` 已有 `/evaluation/counts|shells|template|trend|partition|scheme`，新端点用 `/evaluation/viz`；display 同理。
3. 白名单闭集：`JOB_KINDS` / `JOB_SUB_TYPES` / `PolicyAnalysisTypes.WHITELIST`（与 Python `polan.job.JOB_SUB_TYPES` 对齐，禁乱改）。viz 同步读**不进**异步白名单。
4. display 是聚合 BFF 只读不连 MySQL（`gkxlumen-display-dev.yml` 职责边界），库访问只能落 element。
5. **命名区分**：专题侧 `gkxlumen-topic-policy` 已有 `PolicyVizServiceImpl`（读 `gapfill_policy_viz_events/terms/clusters/depth`，经 Python `/internal/policy/viz/*`）。DS-11 的 eval viz 是**另一族表、另一条链路（display→element 直读）**，勿混。
6. CI：改 display/element 触发 dev 自动部署；Java 仓不受前端人工确认推送闸门约束。
