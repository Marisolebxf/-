## 2. 生成逻辑

生成不走上面的 `kind` 同步读。同步读继续只读表。生成另走与 242 相同的执行口：`POST` 任务 → topic-async → Python `/internal/policy/jobs/execute`。`sub_type=policy_trend_cache`，`kind=深度分析报告`，带 `domain`。`force=true` 才重算。Java 只转发，不写正文，不调模型。

本阶段写入前先做 demo 库守卫（与灌数相同的 `assert_demo_mysql_targets`：ODS / DWD / ADS 必须以 `demo_` 开头）。读政策用连接上的 DWD，缺省 `demo_gkxlumenx_dwd.policy_base_info`（242 同表：`policy_id, title, abstract, content, keywords`）。写只写 demo 主机上的 `gkxlumenx_gapfill.gapfill_policy_trend_report`。不写正式 lumen 集群，不写 `gkxlumenx_ods` / `gkxlumenx_dwd` / `gkxlumenx_ads`。

一个领域一次只处理一行。热点那种「不传领域就三个一起写」不用于本稿。

### 2.1 取材

领域名整段当作关键词（🟡）。在 DWD 的标题、摘要、关键词里匹配，取最近 8 条，且 `content` 去空白后非空。不够 8 条时有几条用几条；一条都没有则不写缓存。材料只带这 8 条的标题、摘要、正文，不另查解析表或推演表（242 会拼解析和推演摘要，深度报告这一刀不拼）。

### 2.2 模型产出

一次调用只产出这一领域的一个标题、一段正文。JSON 两个键：`title`、`body`。不产出 242 的四段（政策背景 / 主要内容 / 预期效果 / 实施建议）。标题截到 256 字，正文截断后写入 `body`。空标题或空正文视为失败。材料里没有的机构、金额、日期、条文不编。材料不够时正文写明依据不足，不用「缺项演示」当开头。

### 2.3 命中规则

只看该 `domain_name` 的报告行：

- 命中：至少一行 `fill_method=llm`，且 `body` 去掉空白后不以「缺项演示」开头。命中则不调模型。`force=true` 时无视命中。
- 未命中：没有行，或 `fill_method=manual`，或正文以「缺项演示」开头。现在三行演示都是未命中。

不用 242 的「该政策已有解读段就短路」。那条会把演示行当成缓存，演示句就换不掉。

### 2.4 写回

只在标题和正文都非空之后写。先删该 `domain_name` 的旧行，再插入一行。插入字段：

- `title`、`domain_name`、`body`：模型结果
- `metric_id`：仍空，不新注册指标
- `gap_item`：仍是 `205 深度分析报告`
- `fill_method`：`llm`
- `gapfill_batch_id`：本任务批次，不复用种子批次 `POL-L2-DS10-TREND-GAPFILL-L01`，避免全景灌数按钮按 `BTN-panorama` 删行时把模型行清掉，也避免种子脚本把模型行当手工行覆盖
- `generated_at`：写入当时
- 不写 `is_mock` 列（表上没有）。D4 语义保持 mock，不把就绪度改绿

一个领域保持一行。不把文件字节写入本表。

### 2.5 失败

下列情况都不 `DELETE`，不 `INSERT`，不把正文改成新的「缺项演示」句：

- 没有模型密钥（242 这里返回 `degraded`，`generated=0`，不进写库）
- 一条政策正文都摘不到
- 模型失败、返回空、标题或正文为空
- 写库守卫拒绝（连到的不是 demo 库）

旧演示行原样留下。展示页下次同步读到的仍是旧标题和旧正文。

## 3. 中台菜单看见什么

另有「重新生成」，带 `force=true`，已缓存也能重算。重算失败时这一行仍是上一次成功的标题和正文。

失败时这一行文字不变，旁边一句失败原因（无密钥、没有可摘政策、模型失败）。不出现新的「缺项演示」正文。
