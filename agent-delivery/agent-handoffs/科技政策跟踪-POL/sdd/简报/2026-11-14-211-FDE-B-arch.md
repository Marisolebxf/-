## 读法

### 调用链

展示读与下载仍走现有两段，中间不插入生成：

```text
lumen-ui-science-pc
  → GET /display/v1/policy/panorama/assessment-report
  → Java 只读 gkxlumenx_gapfill.gapfill_policy_assessment_report
  → 接口返回全部行；成功行过滤在展示前端

查看 / 下载
  → 展示前端按同一份 HTML 拼段落
  → POST /display/v1/situation/report/generate
     reportType=policy-assessment-report
```

- 展示服务、展示前端都不连 demo 库（D12）。
- 中台生成写在 `demo_gkxlumenx_ads.gapfill_policy_assessment_report`。本波不把这条写放进展示请求里。
- Java 不拼正文，不新建下载接口。
- 列表仍是一个「下载」，只下 PDF。查看弹窗里保留「导出 Word」和「导出 PDF」。两档都是同一份 HTML。

### 成功行

源表里同时满足下面两条的行才是成功行：

- `fill_method=llm`
- 达成度、社会影响、存在问题、改进建议、报告正文五段都不以「缺项演示」开头

### 怎么抄

波次 D 用一次性脚本，只读 `demo_gkxlumenx_ads.gapfill_policy_assessment_report` 这张表，不读生成接口返回。成功行抄进 `gkxlumenx_gapfill.gapfill_policy_assessment_report`。不写 `gkxlumenx` 业务库；这次只抄入这张缺项表。

`scope_text` 原样带走，不截断，不改成展示种子那两句长范围。源表按 `id` 去重。

- 目标表没有相同 `scope_text`：插入新行。不要用政策标题去改那两行手工种子。
- 目标侧同一 `scope_text` 已经有多行：这一条停下来交给人拣，不自动收成一行。
- 同一 `scope_text` 只有一行：只更新五段正文、`generated_at`、`fill_method`，不改 `scope_text`。

插入列为 `scope_text`、五段、`generated_at`、`fill_method`、`is_mock`、`metric_id`、`gap_item`、`gapfill_batch_id`。不带 `policy_id`（展示表没有这列），不加评分列。`is_mock` 保持源行的 1。`gap_item` 与 `gapfill_batch_id` 从源行原样抄，不要留空。

五段正文列是 `achievement_text`、`social_impact`、`problem_text`、`suggestion_text`、`report_body`。

抄失败，或一条成功行都没有：不 DELETE 旧行。已经写上的留着，没写到的旧行原样。

### 前端过滤

过滤放在展示前端。接口仍返回全部行，不改 SQL 的 WHERE。

- 返回行里有成功行：列表只显示这些成功行。
- 一条成功行都没有：页面仍显示表里现有行。政策受众反馈收集、政策效果评估报告、政策实施效果跟踪、政策匹配与推送四张功能卡不清空。

查看与下载仍是前端拼段落，段落顺序沿用产品稿与界面稿的同一份 HTML。
