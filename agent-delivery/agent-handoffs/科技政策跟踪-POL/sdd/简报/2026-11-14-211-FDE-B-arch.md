## 读法

### 调用链

展示读与下载仍走现有两段，中间不插入生成：

```text
lumen-ui-science-pc
  → GET /display/v1/policy/panorama/assessment-report
  → Java 只读 gkxlumenx_gapfill.gapfill_policy_assessment_report
  → 接口返回全部行；成功行过滤在展示前端

查看 / 下载
  → 展示前端按同一份 HTML 拼段落
  → POST /display/v1/situation/report/generate
     reportType=policy-assessment-report
```

- 展示服务、展示前端都不连 demo 库（D12）。
- 中台生成写在 `demo_gkxlumenx_ads.gapfill_policy_assessment_report`。本波不把这条写放进展示请求里。
- Java 不拼正文，不新建下载接口。
- 列表仍是一个「下载」，只下 PDF。查看弹窗里保留「导出 Word」和「导出 PDF」。两档都是同一份 HTML。

### 成功行

源表里同时满足下面两条的行才是成功行：

- `fill_method=llm`
- 达成度、社会影响、存在问题、改进建议、报告正文五段都不以「缺项演示」开头

### 怎么抄

波次 D 用一次性脚本，把成功行按列抄进 `gkxlumenx_gapfill.gapfill_policy_assessment_report`。列名不变，不加评分列。`is_mock` 仍为 1。不写 `gkxlumenx` 业务库；这次只抄入这张缺项表。

按 `scope_text` 对齐：

- 目标已有同范围：更新这一行的五段正文和 `generated_at`，并把 `fill_method` 写成 `llm`，使抄入后的行仍满足上面的成功行判定。不改 `scope_text`，不插第二行。
- 目标没有同范围：插入一行，列与源表同名，五段正文、`generated_at`、`fill_method=llm`、`is_mock=1` 一并写入。不加评分列。

五段正文列是 `achievement_text`、`social_impact`、`problem_text`、`suggestion_text`、`report_body`。

抄失败，或一条成功行都没有：不 DELETE 旧行。已经写上的留着，没写到的旧行原样。

### 前端过滤

过滤放在展示前端。接口仍返回全部行，不改 SQL 的 WHERE。

- 返回行里有成功行：列表只显示这些成功行。
- 一条成功行都没有：页面仍显示表里现有行。政策受众反馈收集、政策效果评估报告、政策实施效果跟踪、政策匹配与推送四张功能卡不清空。

查看与下载仍是前端拼段落，段落顺序沿用产品稿与界面稿的同一份 HTML。
