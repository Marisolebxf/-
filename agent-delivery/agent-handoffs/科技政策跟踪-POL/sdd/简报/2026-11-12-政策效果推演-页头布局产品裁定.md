## 1. 问题（产品视角）

| 现象 | 产品判断 |
|---|---|
| 「利益攸关反馈」挂在整页最顶部 KPI 行 | **错位**。需规 236 是效果预估下的子叶（问卷/征集/专家评审 + 汇总意见），不是跨页总览指标；无独立 `metric_id`，页头条数会把「子叶过程量」抬成「整页结果」 |
| 「布局建议 0 节点」与推演同排 | **易误导**。会签/ARCH 已写：`M_POLICY_LAYOUT_REC_COUNT` 等布局推荐键**不进** 232–236；页头该卡是 FE 复刻壳，0 节点会被读成「推演算出来没建议」 |
| 64.8 / 99.5 两卡仍在页头 | **可保留作整页概览**，但是得分来自 `gapfill_policy_sim_score`（D4 mock），须保留 ⚠️/待确认语义，不能暗示真模型已上线 |
| 用户进「未出台政策仿真」仍先被页头四卡抢注意力 | **信息层级反了**：应先条件与仿真结果，页头只留极少数整页概览 |

不替甲方改 232–236 业务口径；本裁定只动**信息架构 / 呈现层级**。

## 2. 目标信息架构（推荐）

```
政策效果推演
├── 标题区（无业务 KPI，或仅 2 张整页概览卡，见选项）
├── 主 Tab：效果预估 | 科技政策推演
└── 效果预估子 Tab（需规序）：未出台 → 新出台 → 区域空间 → 多维评估 → 利益攸关方
    └── 利益攸关方子页内：
        1) 政策选择
        2) 评估活动识别（四卡）
        3) 信息反馈与互动 + 已汇总意见列表
        4) 本区「意见条数」作卡片副标题/角标，不上页头
```

默认进哪一子 Tab：维持现状「多维评估」亦可；若本轮验收主盯 232，可临时把默认改为「未出台」（不改需规，仅默认焦点）。

## 3. 决策卡（请人选）

### 卡 A · 页头 KPI 保留哪些？

1. **（推荐）页头只留 2 卡**：预估综合效果 + 落地成效维；去掉「利益攸关反馈」与「布局建议」  
   - 理由：与 EST 会签「布局键不进推演区」、236 是子叶过程量一致；页头干净，0 节点不再吓人  
2. 页头留 3 卡：综合效果 + 落地成效 + 布局建议（复刻壳）；**仅去掉利益攸关反馈**（当前草稿已按此改 FE，待确认）  
3. 页头 4 卡全留，只把利益攸关反馈挪到子页（布局建议仍顶栏）— **不推荐**  
4. 页头 KPI **整行去掉**，分数只出现在多维评估 / 仿真结果区内 — 改动面大，需 UE 再走一眼

### 卡 B · 「布局建议」去哪？

1. **（推荐，若选 A1）** 推演页不再展示；评价页 / 研报页若已有布局建议卡则继续用那边  
2. 仍留推演页头复刻壳，但 **值为 0 时改诚实空态**（「暂无布局建议」），禁止亮「0 节点」  
3. 保持现状出数（含 0）— **不推荐**

### 卡 C · 「利益攸关反馈」落点

1. **（推荐，唯一）** 只在「效果预估 → 利益攸关方参与评估」子页内展示条数与列表；页头禁止出现  
2. （否决）继续页头第 4 卡

## 4. 与线上「未出台无数据」的边界

- 页头布局 **不解决** 232 无数据：根因是 gapfill 缺列 `similar_items` + fallback LLM `generate_text` 导入失败（见 trace `99d3be61…`）。  
- 布局裁定与 232 修数/修代码可并行，但验收叙事要分开：布局 = 层级对；232 = 有仿真结果行。
