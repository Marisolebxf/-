## 1. 统一分法

报告相关能力只分四类。不要把图表、导出文件和另一条产品的研报算进同一种生成。

| 类 | 含义 | 数据从哪来 |
|---|---|---|
| 正文缓存 | 打开时先读缺项表。未缓存才派 Python，用政策正文生成，写回同一张表，再读 | 缺项表 + `policy_trend_cache` / 已有的 242 任务 |
| 实时生成 | 每次对比当场生成，不落缺项表 | 结果在任务回执里 |
| 只读已有行 | 解析、指标、统计已经有行，打开只读 | ADS 或已有缺项行 |
| 导出壳 | 不生产正文。有正文之后才拼 PDF / Word | `situation/report` |

Java 不写报告、不调模型。前端不直连 Python。D4 本波仍是 mock：`is_mock=1`，只表示正文来自模型补齐，不把就绪度改绿。

## 3. 205 本刀怎么走

和用户口径一致，并补上一条否则演示句永远下不掉的规则。

1. 先读对应缺项表。
2. 该领域已有 `fill_method=llm` 且正文不是「缺项演示」开头：直接显示，不生成。
3. 没有行，或仍是手工演示行：界面发起 `sub_type=policy_trend_cache`。Python 用领域名在政策标题、摘要、关键词里取最近 8 条有正文的政策，生成后覆盖该领域旧行。
4. 热点识别不带领域时，三个领域各写一批。
5. 「重新生成」带 `force=true`，无视缓存。
6. 摘不到政策或没有模型密钥：不删旧行，不另写演示句。

领域名当关键词是临时规则，标 🟡。三个名字不是库里的分类列。

## 4. 实现顺序

1. Python：`policy_trend_cache` 写回三张表现表。
2. Java：`panorama/jobs` 增加该 `sub_type`，走已有 topic-async。带 `kind` 的同步读表保持。
3. 前端：影响评估、深度分析报告、热点识别在未缓存时发起上述任务，完成后重读。进度跟任务状态。导出不动。
