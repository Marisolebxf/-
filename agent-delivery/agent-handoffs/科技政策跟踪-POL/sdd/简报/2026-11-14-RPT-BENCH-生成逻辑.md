## 2. 生成逻辑

一次生成只服务一对对象。四段都写进上面四列，不新增列。

1. 中台提交：范围（`国内先进地区` 或 `全球科创领先城市`）、恰好 2 个对象、1～3 个字段。对象或字段不在闭集里，直接拒绝，不读表、不写表。
2. 先按唯一键读现有行。该键已是 `fill_method=llm` 且四段都非空：菜单只显示，不调模型。点「重新生成」才无视这条。`manual` 行视为还没缓存，但在新正文写成功前继续显示。
3. Python 只读 demo 平面已有政策正文（地区名对上该对象），每侧最近 8 篇、单篇前 8000 字。任一侧摘不到正文：整次失败，不写。
4. 模型按「视角对象 × 字段」出四段。对方名称写进四段文字。读得到的力度或文种件数可以写进文字；读不到不造数，也不另存一列。
5. 四段都非空，才按唯一键覆盖或插入。写入列：四段正文、`is_mock=1`、`metric_id` 空、`gap_item` 不变、`fill_method=llm`、`gapfill_batch_id=RPT-BENCH-217`、`generated_at` 为写成功时间。同一对象和字段的键不变。
6. 一次点击的全部行放在一个事务里。任一段空、模型失败、没有密钥：整次回滚，旧行保持原句。不删行，不另写演示句。
7. 调用链：中台页面只调 Java；Java 只派任务；Python 调模型并写库。Java 不拼四段、不调模型。页面不直连 Python。
8. 只使用 demo 算法进程已有的 MySQL 连接，表名不变。不写 lumen 正式实例，不写 ODS、DWD、ADS、供应方库。D4 仍是 mock。

导出不在这条链路里。无行不产 PDF、Word。
