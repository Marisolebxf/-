## 1. 背景

企业总览已落地四个一级 Tab：态势概览 / 企业分布 / 重点对象 / 风险机会。当前页面中存在两个需要产品先确认的区域：

- 态势概览 Tab 下的“关键下钻入口”。
- 风险机会 Tab 下的“后续处置路径”。

这两个名称更像内部 IA 或设计实现术语。如果直接表现为几个跳转按钮，用户难以理解：

- 为什么此处需要继续点击。
- 点击动作对应哪个业务任务。
- 跳转后会得到什么结论或产物。
- 是否会继承当前产业、区域、时间和风险/机会上下文。

因此本任务不要求 UE/UI/FE 先包装交互，而是由 PM 回溯并确认两个位置的原始需求点。

## 3. 建议产品判定口径

PM 可按以下四类给出结论：

| 类型 | 判定说明 | 后续角色 |
|---|---|---|
| 保留为“继续分析建议” | 用户从当前态势结论继续看分布、对象、竞争力等分析。 | UE 定义结论到动作的表达，FE 实现上下文跳转。 |
| 保留为“处置动作” | 用户需要对风险/机会形成跟进、服务、报告或研判动作。 | PM 先定义业务动作，UE 再设计任务流。 |
| 改为“相关分析推荐” | 只是帮助用户快速去相关页面，不构成处置。 | UE 改名并弱化为辅助链接。 |
| 移除或暂缓 | 当前没有明确业务任务支撑。 | FE 移除模块或保留待确认提示，不进入本期验收。 |

## 4.1 PM 决策说明

| 决策点 | 结论 |
|---|---|
| D1 / D2 / D3 | “关键下钻入口”不是独立底部区域。下钻严格定义为用户点击 KPI 卡、趋势图、环形图/产业结构图、地图、对象卡等数据载体后，带当前上下文进入具体分析。态势概览底部按钮组应移除。 |
| D4 / D5 | “后续处置路径”不是业务办理闭环，也不是底部跳转按钮组。风险机会动作必须绑定具体风险/机会对象，内联在风险项或机会项卡片内。 |
| D6 / D7 | 态势概览下钻必须携带来源页、来源 Tab、产业、时间、区域以及 `sourceMetric` 或 `sourceChart`；风险机会动作必须携带风险/机会类型、影响对象或建议动作。 |
| D8 | 不允许使用无对象、无指标、无图表上下文的裸跳转按钮作为“下钻”或“处置路径”。 |

## 4.2 回溯依据

- `ENT-functional-design-v2.md` §9.1：企业总览 / 态势概览的用户问题是“这个产业的企业生态怎么样？我现在该关注什么？”，功能模块包括 JudgmentStrip、KPI、趋势、地图、TopN 和下钻入口。
- `ENT-functional-design-v2.md` §7.3：企业总览 / 风险机会 JudgmentStrip 链接应进入企业洞察 / 深圳现状或企业决策 / 招引培育，并携带 `industry`、`suggested_action`。
- `ENT-userflow.md` §3.1：领导/决策用户从企业总览查看态势/风险/机会后，按“看重点对象 / 看异常原因 / 形成动作”继续进入企业全景、企业洞察或企业决策。
- `ENT-UE-IA-L03-overview-integration.md` §11.2：态势概览承接 E-20/E-32 的总体态势判断，风险机会承接风险异常、机会建议和后续动作，但 L03 当前实现把它们落成底部按钮组，需要按本 PM 复议结论纠偏为数据载体下钻与卡片内动作。

## 4.3 PM 对 UE 7.8 待确认问题的处理结论

| 待确认问题 | PM 处理结论 | 后续执行口径 |

### 4.3.1 PM 对 UE 推导项的边界声明

| 类型 | 是否允许进入 FE 实施 | PM 边界 |
|---|---|---|
| 数据载体点击下钻 | 允许 | KPI、趋势图点位、结构图分组、地图区域、重点对象卡均可作为下钻入口，但必须带上下文。 |
| 趋势异常点 / 拐点动作 | 条件允许 | 需求支持“查看原因”，但默认承接应优先为趋势异常原因抽屉或趋势明细；只有当异常点已被归因为风险项，并具备 `riskType/riskDimension` 时，才可进入痛难点。 |
| 默认目标页和英文参数枚举 | 允许作为 Wave 0 临时契约 | 目标页、参数名、枚举 key 需要在评审态浮层标识为 UE 推导；后续接真实数据或后端 API 时再收敛。 |
| 生成名单 / 招引培育动作 | 条件允许 | 必须有候选企业集合、机会类型和建议动作；无对象时不展示强动作，不允许生成空名单。 |
| 「UE 推导 · 待讨论」页面浮层 | 允许但仅评审态 | 服务全员讨论，不作为正式用户界面；不得替代需求确认流程。 |
