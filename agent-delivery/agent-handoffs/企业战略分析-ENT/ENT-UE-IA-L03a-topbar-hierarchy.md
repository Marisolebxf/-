## 6. UE 交付回填

### 6.1 最终顶部信息层级

企业中心四个二级页面统一采用同一套顶部结构。顶部区域不再把标题、筛选、Tab、操作混排成一条“大工具条”，而是按语义拆成两层。四个二级页面默认不显示可见页面标题；左侧菜单选中态负责表达二级页面位置，页内一级 Tab 选中态负责表达当前视角。

企业中心不单独提供一个可承载“域级全局搜索”的首页或容器页；系统顶部是否需要全局搜索也未经过产品确认。因此在产品确认前，不设计常驻“企业中心全局搜索”入口，不把搜索入口放到四个二级页面顶部，也不放到系统 Header。企业检索能力保留，但入口按具体任务场景出现。

```text
EnterprisePageTop
├─ ContextBar（跨 Tab 保留的业务上下文）
│  └─ 产业 / 时间 / 区域 / 企业群等上下文筛选
├─ PrimaryWorkbenchTabs（当前二级页面内一级 Tab）
│  └─ 态势概览 / 企业分布 / 重点对象 / 风险机会 等
└─ TabContentHeader（当前 Tab 内容标题，可选）
   └─ 当前 Tab 的一句话结论 / JudgmentStrip / 局部说明
```

层级解释：

| 层级 | 表达什么 | 不表达什么 |
|---|---|---|
| `ContextBar` | 企业中心基础分析口径，例如产业、时间、区域、企业群 | 不表示当前 Tab；不承载页面/Tab 专属筛选；不承担全局企业检索完整页职责 |
| `PrimaryWorkbenchTabs` | 当前二级页面内的平级业务视角切换 | 不进入左侧菜单；不替代 ContextBar |
| `TabContentHeader` | 当前 Tab 内容区的业务说明、结论和状态提示 | 不重复左侧菜单标题，不再显示面包屑 |
| `SceneSearchEntry` | 内容区内与当前任务强相关的找企业入口，例如查找企业、选择企业、添加对比企业、打开高级检索 | 不是常驻全局入口；不放在页面顶部；不改变左侧菜单或页内一级 Tab |
| `DevStatusNotice` | 开发/验收阶段的 IA 说明、Mock、待维护、更新时间提示 | 不属于正式顶部结构；不展示 IA 文档来源；不常驻在 ContextBar 上方 |

明确结论：

- 四个二级页面默认不显示可见页面标题。`企业中心 · 企业总览 / 企业全景 / 企业洞察 / 企业决策` 可作为 route title、浏览器标题、埋点 page_name、无障碍 `aria-label` 或代码语义，但不作为顶部大标题重复展示。
- 深层横向能力页若显示面包屑，不再额外显示路径型标题。只有当页面有独立业务对象或结果主题时才显示内容标题，例如企业画像页显示企业名称，检索页可显示检索结果主题。
- 当前 Tab 不进入页面标题；由 `PrimaryWorkbenchTabs` 的选中态表达。
- 右上角不保留“当前 Tab”重复 Tag。若需要业务状态提示，放入 `TabContentHeader` 或 `JudgmentStrip`，文案必须是结论/状态，不是导航标签。
- `ContextBar` 放在页内一级 Tab 上方，具体位置是二级页面内容容器顶部、`PrimaryWorkbenchTabs` 上方。它只表达企业中心基础分析口径，例如产业、时间、区域、企业群；页面/Tab 专属筛选下沉到内容区局部 FilterBar。
- 产品确认前，不做常驻“企业中心全局搜索”。企业检索只作为内容区场景化任务入口出现，例如“查找企业 / 选择企业 / 添加对比企业 / 打开高级检索”。
- 是否建设系统级全局搜索、是否覆盖其它模块、是否放入系统 Header，转 `PM-ENT-global-search-scope-confirmation.md` 产品确认任务。
- Tab 内容区内不得再显示旧页面壳、旧面包屑或旧建设来源标题。
- 截图中类似“统一承接态势概览、企业分布、重点对象和风险机会，来源：企业中心 IA，更新时间，Wave 0 Mock / 待维护字段”的蓝底说明条，定性为开发/验收态 `DevStatusNotice`，不属于正式用户界面的顶部层级。

### 6.3 关键交互规则

#### URL 与 Tab

- 页内一级 Tab 切换必须同步 URL query，例如 `/enterprise-center/overview?tab=distribution`。
- 旧路由直达时，按 `enterpriseCenterRouteMap` 映射出二级页面和默认 Tab，再渲染同一顶部结构。
- URL 中的 `tab` 只表示当前二级页面内的一级 Tab，不表示左侧菜单，也不表示横向检索能力。
- 非法或废弃 Tab 参数不得新增临时 Tab；应回落到该二级页面默认 Tab。

#### ContextBar

- `ContextBar` 只承载企业中心基础分析口径：产业、时间、区域、企业群。是否纳入“企业群”仍以产品确认为准。
- 四个二级页面共用的是基础 ContextBar，不共用全部筛选条件。
- 每个 Tab 的专业筛选必须放在内容区局部 FilterBar、图表工具条或二级分段控件中，不要把所有筛选都塞进 ContextBar。

| 筛选层级 | 放置位置 | 字段范围 | 规则 |
|---|---|---|---|
| 基础 ContextBar | 页内一级 Tab 上方 | 产业、时间、区域、企业群 | 四个二级页面共享；用于表达当前分析口径；字段数量保持克制。 |
| 页面/Tab 局部 FilterBar | 当前 Tab 内容区顶部或图表/表格工具条 | 企业类型、企业规模、资质标签、供应链层级、风险等级、评分维度、招引条件、培育条件、名单策略等 | 只影响当前页面/Tab 或当前组件；不得伪装成跨页 ContextBar。 |
| 二级分段控件 | 当前 Tab 内容区内 | 技术力/商业力、招引/培育、单链/多链等 | 用于当前分析视角内部切换，不进入 ContextBar，不进入页内一级 Tab。 |

- ContextBar 改变后，当前 Tab 内容、指标、图表、列表均按新基础口径刷新。
- Tab 切换不得静默清空 ContextBar。
- 跨二级页面跳转若携带 ContextBar 条件，应显示一次可关闭的上下文继承提示，例如“已沿用 企业总览 的口径：产业=集成电路，区域=深圳，时间=近三年”。提示中应提供“调整口径 / 清除继承条件”入口。
- 上下文继承提示使用全局提示、通知提醒框或页内 Alert，必须可关闭；关闭后不影响已继承的筛选结果。
- 若某个页面或 Tab 不适用某个基础口径，应显示禁用/不适用态和原因，例如“该视图不按区域统计，区域条件不参与计算”，不能静默隐藏或静默忽略。
- Tab 内容区允许有局部筛选，但必须放在 `TabContentHeader` 或内容区 FilterBar 内，并与 ContextBar 做视觉区分。

#### 开发/验收态提示

- “统一承接...”“旧总览入口保留为兼容路由”这类 IA 解释只服务实施、验收和交接，不应作为正式 UI 常驻内容。
- `来源：企业中心 IA` 这类设计来源不展示给最终用户；如需展示来源，应展示真实业务数据来源、指标来源或更新时间。
- `Wave 0 Mock / 待维护字段 / 待确认` 可保留为状态提示，但应下沉到当前 Tab 内容区、指标卡、图表标题、表格工具条或具体字段旁，以 `MockBadge`、`PendingBadge`、Tooltip 等轻量形式表达。
- 只有当开发/演示环境明确需要验收说明时，才允许显示 `DevStatusNotice`；生产/正式演示口径默认隐藏。
- `DevStatusNotice` 不放在 `ContextBar` 上方，不占据页面顶部主视觉，不替代页面标题、ContextBar 或页内一级 Tab。

#### ContextBar 与企业检索能力关系

- 两者是协同关系，不是包含关系。
- `ContextBar` 是“看数据的口径”，负责限定当前页面和当前 Tab 的分析范围，例如产业、时间、区域、企业群。
- 企业检索能力是“找企业/找企业集合”的对象能力，负责进入检索、画像、名单、对比等对象工作流。
- 产品确认前，不使用“全局搜索”作为企业中心常驻入口名称，避免与系统级全局搜索混淆。
- 从企业总览进入搜索时，只能通过内容区明确的对象动作进入，例如“查找风险企业 / 添加重点对象 / 打开高级检索”。`source=/enterprise-center/overview` 只用于返回路径、面包屑和恢复现场，不改变搜索能力归属。
- 企业检索入口不得放入 `ContextBar`，避免用户误以为搜索只是当前 Tab 的局部筛选字段。
- 打开企业检索时，应把当前 ContextBar 作为默认检索上下文带入搜索页或搜索浮层，例如当前产业、区域、时间窗。
- 搜索结果返回企业中心时，应恢复原 `source + tab + ContextBar`；若用户在搜索页主动改了产业/区域/时间，可在返回前提示“应用到当前页面口径”或提供显式应用动作，不能静默覆盖原 ContextBar。
- 搜索选中企业对象后，可把企业对象或企业群作为局部对象上下文传给当前 Tab 或目标页，但不应把企业名称直接塞进 ContextBar，除非后续明确设计“企业群”字段。

#### 企业检索入口

- 企业检索入口采用场景化文案和场景化位置，例如“查找企业 / 选择企业 / 添加对比企业 / 筛选企业集合 / 打开高级检索”。
- 入口只在内容区具体任务需要时出现；不得放在四个二级页面顶部，不放入 ContextBar，也不作为固定页内一级 Tab。
- 从任一场景化入口进入 `/development/search` 时必须携带：
  - `source`：当前二级页面路径，例如 `/enterprise-center/overview`
  - `tab`：当前页内一级 Tab
  - `industry`、`region`、`time`：当前 ContextBar 可序列化上下文
- `/development/search` 保留为兼容/高级检索落地页。进入后左侧 active 由 `source` 决定；无 `source` 时默认回到企业总览上下文。
- 搜索返回时优先回到 `source + tab + ContextBar`，不得把企业检索加入左侧菜单、固定 Tab 或系统 Header。
- 是否升级为系统级全局搜索，等待产品确认任务结论。

#### 刷新

- 四个二级页面不默认放置刷新按钮。若当前页面使用的是静态 mock、前端本地数据或无实时接口，刷新没有明确业务价值，应删除。
- 只有在存在“后台计算 / 实时数据 / 长任务结果 / 异步指标更新时间”的页面，才允许出现刷新或重新计算入口。
- 若保留刷新，语义必须写清楚，不叫泛化的“刷新页面”，而是按业务命名：
  - `刷新数据`：重新拉取当前 ContextBar + 当前 Tab 的数据。
  - `重新计算`：重新触发当前口径下的模型/指标计算。
  - `同步最新`：同步后台最新维护结果或异步任务结果。
- 刷新不重置产业、时间、区域、企业群、当前 Tab、排序、分页和已选对象；如果需要重置，应另设“重置筛选”且放在筛选区。
- 刷新过程中保持容器尺寸稳定，使用 Arco `Button` loading / `Spin` / `Skeleton`，避免页面抖动。

#### 当前 Tab 标识

- 当前 Tab 只由 `PrimaryWorkbenchTabs` 的 selected/active 状态表达。
- 不在右上角重复显示当前 Tab Tag，避免形成第二套导航。
- 如业务确实需要强调当前结论，使用 `JudgmentStrip` 文案，例如“当前口径下，深圳集成电路企业新增放缓”，而不是“当前 Tab：态势概览”。

#### 面包屑

- 企业中心四个二级页面不显示面包屑，因为左侧菜单选中态已足够表达二级位置。
- 深层横向能力页显示面包屑，例如：
  - `企业中心 / 企业总览 / 企业检索`
  - `企业中心 / 企业全景 / 统一企业画像`
- 深层横向能力页显示面包屑后，不再显示路径型标题；只显示业务对象标题或结果主题。
- 旧路由兼容页如果被聚合页承载，不额外显示旧面包屑；如果是独立横向能力页，则按 `source` 显示新 IA 面包屑。
- 面包屑首节点从业务域根节点 `企业中心` 开始，不默认显示“首页”。

#### 1440px 以下适配

- 产品确认前，不在全局 Header 或企业中心域入口区新增常驻搜索入口；二级页面只处理自身 ContextBar 和页内一级 Tab 适配。
- `ContextBar` 可换行成两行或使用收纳按钮，但必须仍位于 `PrimaryWorkbenchTabs` 上方。
- 页内一级 Tab 不与 ContextBar 混成一行；空间不足时 Tab 横向滚动或使用 Arco Tabs overflow，不改成下拉菜单，除非项目已有同类规则。
