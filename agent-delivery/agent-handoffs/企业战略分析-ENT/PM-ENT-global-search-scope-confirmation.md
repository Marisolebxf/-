## 1. 背景

企业中心原讨论中出现“全局搜索”入口，但当前 IA 已明确：

- 企业中心左侧只有四个二级页面：企业总览 / 企业全景 / 企业洞察 / 企业决策。
- 不新增“企业检索”固定 Tab。
- 不把企业检索放回左侧菜单。
- 四个二级页面顶部不应放常驻“全局搜索”，否则会被误解为当前二级页面搜索。
- 系统顶部也不能直接放该入口，否则会被理解为“科技专题服务系统全局搜索”。

因此，是否存在系统级全局搜索需求，已经超出企业中心 UE 能单独决定的范围，需要 PM 确认。

## 3. 临时 UE 规则

在 PM 未确认前，执行以下临时规则：

- 不在系统 Header 新增全局搜索。
- 不在企业总览 / 企业全景 / 企业洞察 / 企业决策顶部放常驻全局搜索。
- 不新增“企业检索”左侧菜单或固定页内一级 Tab。
- 企业检索能力保留为场景化入口：
  - 查找企业
  - 选择企业
  - 添加对比企业
  - 筛选企业集合
  - 打开高级检索
- 场景化入口进入 `/development/search` 时携带 `source`、`tab`、`industry`、`region`、`time`，用于返回和恢复上下文。
- `ContextBar` 只承载分析口径，不放搜索输入框。

## 4. PM 决策选项

| 选项 | 决策 | 适用场景 | 后续动作 |
|---|---|---|---|
| A | 暂不做系统级全局搜索 | 只有企业中心有明确找企业需求，其它模块未确认 | 企业中心继续使用场景化企业检索入口；`/development/search` 保持企业高级检索兼容页。 |
| B | 做企业中心域级搜索，但不进系统 Header | 企业中心四个二级页面都需要找企业，但其它模块不需要统一搜索 | 需要先确定企业中心域级入口容器；若没有企业中心首页/域入口区，不建议本期落地。 |
| C | 做科技专题服务系统级全局搜索 | 多个模块都有对象检索需求，且产品允许系统 Header 放统一入口 | 新增 SearchHub 产品设计、结果页 IA、权限/脱敏/API/data 任务。 |

## 5. 建议默认值

UE Lead 当前建议采用 **选项 A**：

> 暂不做系统级全局搜索，也不做企业中心常驻全局搜索。企业检索保留为企业中心内的场景化任务入口。

理由：

- 当前没有证据证明其它模块存在统一搜索需求。
- 企业中心没有独立首页或域级承载页，常驻入口位置不稳定。
- 放在四个二级页面顶部会被误解为当前页搜索。
- 放在系统 Header 会扩大为全系统搜索承诺。
- 场景化入口能满足当前找企业、选企业、加入对比、打开高级检索等任务，不破坏 IA。

## 6.1 PM 确认结论

本期不建设科技专题服务系统级全局搜索，也不建设企业中心常驻域级搜索入口。企业检索仅作为企业中心内的横向对象能力，通过内容区场景化任务入口进入 `/development/search`。

`/development/search` 的本期定位是企业高级检索兼容/落地页，不是左侧第五个二级页面，不是系统 Header 搜索，不是未来跨要素 SearchHub 的承诺入口。页面可以承载关键字、智能、高级筛选、结果列表、结果内再筛选和企业画像抽屉，但必须保留企业中心来源上下文。

### PM 边界规则

- 不在系统 Header 增加“全局搜索”。
- 不在企业总览 / 企业全景 / 企业洞察 / 企业决策顶部增加常驻搜索。
- 不新增“企业检索”左侧菜单。
- 不新增“企业检索”固定一级 Tab。
- 不把 `/development/search` 包装成企业中心第五个二级页面。
- 不把其它要素对象域纳入本期搜索范围。
- 场景化入口进入 `/development/search` 时必须携带 `source`、`tab`、`industry`、`region`、`time`。
- 搜索页返回时优先恢复 `source + tab + ContextBar`，不得静默覆盖原企业中心分析口径。
- 搜索页左侧 active 由 `source` 决定；无 `source` 时默认归属企业总览上下文。
- 企业画像抽屉和整页画像需要保留来源上下文与返回能力。

### 对 `ENT-UE-IA-L07` 的执行要求

`ENT-UE-IA-L07` 应聚焦企业检索横向能力闭环：

1. `/development/search` 企业高级检索落地页的信息层级、面包屑、返回路径和左侧 active。
2. 场景化入口与 query 参数规范。
3. SearchHub 三模式：关键字、智能、高级筛选。
4. ResultToolbar / ResultList / 结果内再筛选。
5. 企业画像抽屉、整页画像、深度分析跳转。
6. 对比篮、名单、收藏、最近查看的上下文保留规则。
7. 来源、更新时间、Mock、待维护、待确认提示下沉到结果、指标、字段或模块旁。
8. E-36/E-37 继续归后台内容管理侧，企业中心前台只消费维护结果。

## 7. 决策后动作

若选择 A：

- `ENT-UE-IA-L03a` 顶部规则保持最终状态：四个二级页面顶部不放常驻搜索。
- `frontend-agent` 在当前顶部归位切片中只移除/避免常驻搜索入口，保留内容区场景化入口。
- `UE Lead` 先细化 `ENT-UE-IA-L07`：`/development/search` 信息层级、返回路径、结果区、画像抽屉和跨页上下文规则。
- `frontend-agent` 再按 L07 落地企业检索横向能力闭环。

若选择 B：

- 先补企业中心域级入口设计，不直接塞到四个二级页面顶部。
- 追加 UE/UI/FE 任务，明确入口容器、返回规则、权限和状态。

若选择 C：

- 新增系统级 SearchHub PRD。
- 追加 UE/UI/FE/API/data/permission 任务。
- 更新 `Design.md` 或系统级交互规范，定义系统 Header 搜索入口、对象类型、结果页、权限与脱敏。
