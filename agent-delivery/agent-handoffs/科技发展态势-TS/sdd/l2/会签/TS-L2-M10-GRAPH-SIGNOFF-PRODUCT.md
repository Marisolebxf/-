## 分节说明

### 1. 需规分句还原与「裁掉」项核对

- **关系属性编辑不做**：需规 34–40 只有 36「关系增加」在**创建弹窗**里设类型/强度/时间，37 只有删除，无「编辑关系」分句；「编辑关系」属 41–47（需规序 46 实体关系编辑）。故裁掉前端现存的 `updateGraphMaintainRelation`（`maintainModel.ts:427`）**不超需规**，支持。代价是用户填错强度只能删了重加，但需规未要求编辑，可接受。
- **节点拖拽不持久化**：需规 34 只要求新节点「出现在指定位置」，无「移动已有节点并保存」分句。裁定成立；但见 C14（不要留下会误导的假拖拽）。
- **关系类型三枚举**：需规 36 用「**如**『包含』『依赖』『促进』」，是举例而非封闭清单。稿封成三枚举（删「转化/关联」）属口径收窄，需监管人确认（P2）——这是产品口径而非纯实现细节，不能由架构单方定。
- **无漏句**：34–40 每个分句都能在 §6 找到对应行（见上表）。唯一的界面要素漏项是 **37 的确认对话框**（C2）。

### 2. 草稿 + 保存一次发布（卡 2A）下的用户体验

- **两个「保存」最易出事**：38-3 的弹窗「保存」若只进草稿，用户会以为已落库，关页即丢。必须按 C4 把弹窗按钮改为「确定」、工具栏改「保存图谱」，并常驻未保存计数，弹窗确定后提示「已加入待保存改动」。这是本次产品会签的核心诉求。
- **50 条上限**：硬顶会打断「保存一次」语义。按 C5 给常驻计数与「保存后继续」，并说明保存后撤销不跨版本。
- **409 冲突**：草稿不能静默丢。按 C6 写清「有效操作是否重放、失效项如何列、两个动作」。
- **离页/刷新**：按 C1 补 `beforeunload` 与切分区确认；39-4 的「刷新不丢」必须改成「已保存不丢」。
- **39-4 与可追溯**：卡 2A 选草稿模式即意味着未保存内容不会持久化，这与简报 39-4「刷新不丢」的界面承诺直接冲突；不是实现 bug，是产品定义需重新表述，故列拍板 P1。

### 3. 回滚与版本（40-3 / 40-4）

- 版本列表/详情已覆盖 40-4「操作人、时间、逐条改动」：列表有操作人/时间/类型/改动计数/可回滚；详情读 `change_log` 的 op/before/after/操作人/时间；operator 由 display 注入、before 回填（§1-6/§1-7）补齐了 as-built。可满足。
- 回滚连带 41–47：§3 预览按「技术点 / 技术点间关系 / 实体挂接 / 实体关系 / 实体属性」分组计数，方向对；但仅给计数不够「告知」，按 C11 增目标版本信息 + 一句中文风险说明 + 可再回滚提示。
- 无快照版本置灰：§3 `:92` 已有「回滚按钮置灰并提示『该版本无快照』」，满足；建议列表行也标「不可回滚」原因（C11）。
- 历史版本 operator：上线前 ENT 版本 operator 写死 `py`（`tech_graph_maintain_routes.py:844`），40-4 的「操作人员」对历史版本无意义，建议显示「系统（历史）」并在详情注明（C12）。

### 4. 全景页回显人工改动（卡 1B）

- **新点可搜**：方向对，但 200 上限与 `tm:` 前缀的选中映射未定义，可能「搜得到但点不开/被截断」——按 C10 收紧。
