### 4.1 签收条件（写代码之前就得满足）

架构或方案可以签收，只因按稿做得到。

- 真算、真查、真模型做得到：写清调用链、表、接口、`metric_id`。
- 做不到：只接受一种替代。新建 ADS 表，由 data-agent 的执行单让 Python 把 mock 行写入该表，Java 接口只读该表。
- 稿里写明表名、灌数方、读取接口，缺一不签。
- 这种表不进 ODS / DWD / 供应方库，也不用 `gapfill_` 前缀冒充 D16 缺项表。读到的数 D4 仍是 mock，界面保留 MockBadge。
- 接口直接返回写死 JSON、常量或内存 fixture 的稿，不签。
- 方向预警允许 501。501 也要写在架构稿里，并说明前端空态，不能用假规划正文填上。
- 真源：`architecture-baseline.md` 决策 D18。

编码类任务开工前，WBS 里必须已经有对应的架构或实现方案，且该方案已签收。缺了就先补方案，不先写代码。
