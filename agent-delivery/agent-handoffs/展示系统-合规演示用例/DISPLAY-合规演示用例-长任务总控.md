## 5. 用例编号与写法

- 编号：`{L2码}-CASE-<序2位>`，如 `TS-L2-DS01-CASE-01`、`SVC-L2-ZHIKU-CASE-02`、`TA-L2-DS13-CASE-01`。
- 每条必填：`界面 / 输入或选择 / 触发 / 接口 / 请求 / 期望输出 / 数据情况`。
- `期望输出` 必须可判定（图表出现、列表条数、字段值、空态文案、错误码），不用「正常展示」这类模糊描述。
- 每份用例顶部写「主路径一句话」，例：`深圳 × 最近3年 → 科技全域态势 → 11 要素图层可切换，科创事件双 Tab 可开`。
- 标题行标注状态：`覆盖已齐` / `部分可演` / `覆盖不到（缺资源）` / `待签收`。

## 6. 完成定义（门）

- **M1 完成**：该模块需规每条都有对应 CASE 行；七列齐全；输入列写的是界面**可选项全集**（不是单一示例值）。
- **M2 完成**：调研清单逐表有结论（行数/覆盖/批次/mock 比例或「调查受阻」+ 原因）；不得留空表。
- **M3 完成**：**前置是该页接口实测可调（200）+ 库中有数据**，不满足则整叶 `blocked`、写「待开发完成」，不填可演也不拿「覆盖不到」充数；满足后覆盖 M1 全部 CASE 编号，**零缺格**；`supported` 必带表名+行数证据；`gap` 必带缺口引用；`设计无资源` 必带设计依据。
- **M4 完成**：缺口数 = M3 的 gap 数；每条有修复建议（数据补 / 算法改 / 不演）与责任方。
- **M5 完成**：每轮有「用例集 / 前置数据 / 判定 / 退出」，gap 用例有降级路径，与 M4 交叉引用一致。
- **总控关单**：三模块索引行齐全；至少一条主路径可端到端演；所有不可演行均有明确口径。
- **LOOP 完成（human:李伟 2026-11-07 口头口径，对齐 §6.5.2/§6.5.7）**：`样本满足` = 按合规用例中**可演行**的条件，分析结果或界面查询的各项指标**都有数据且对得上期望输出** → 监管人才说「签收」；签收时**再校验一次**，校验通过 = LOOP 真正完成（验收单 `done`，操作人写监管人）。可演行对不上 → 进 DATA/QUERY/ALGO 分类建子任务，补完再验；覆盖不到行不判通过。
