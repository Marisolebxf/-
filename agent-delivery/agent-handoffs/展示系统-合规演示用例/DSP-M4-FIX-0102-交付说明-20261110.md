## 一、FIX-01 · 权利要求数（claim_count）口径与实测

- **规则**（版本 `v1-claims-2026-11-10`，王慧 V2.3「JSON 数组取长度，文本按编号项计数」）：
  `num_attr`（供应商 HTML `<div class="indep-clm|dep-clm" num="N">` 取 max N）> `json`（数组长度）> `numbered`（去标签行首编号项计数，带健全性闸门）。
- **实测**：20,026 行 / 20,000 distinct pn，解析成功 **19,991**（num_attr 19,567 / numbered 450 / none 9 行不出数不落库）；claim_count 1~1107，均值 19.08。1107 为 AU 专利源数据（供应商 num 属性），非解析伪影。
- **落库**：`demo_gkxlumenx_ai.patent_claim_count`（PK pn；claim_count + ipc4 + parse_path + rule_version + batch；upsert 幂等，回读 digest `7555b8a9b7405c1e` 一致）。
- **覆盖率**：19,991/2,420,895 = **0.83%**（冻结上限，如实标注）；其中可归因 ipc4 467 行（见 §〇.2）。
- **002 接线**：权利要求数维 = 领域内覆盖专利均值 → 覆盖领域（78/200）min-max 归一 → 5 维等权 0.2；未覆盖领域该维缺测按王慧重归一。payload 新增 `avg_claims` / `claims_covered_count` / `claims_source_note` / `claims_covered_domains`。

## 二、FIX-02 · 法律事件 4 类码值 + 转让交叉校验口径与实测

- **规则**（版本 `v1-legal-2026-11-10`，王慧 V2.3 语义，`legal_events` 事件文本 + `patent_legal` code 双源）：

  | 类 | 规则 | 全量实测 | 可归因 ipc4 |
  |---|---|---:|---:|
  | license 许可 | 含「许可」/licen* 且不含「开放许可」 | 50 | 2 |
  | litigation 诉讼 | 含「诉讼」「无效宣告」「无效」/invalidation/litigation | **0**（如实标注） | 0 |
  | pledge 质押 | 含「质押」/pledge | 104 | 7 |
  | open_license 开放许可 | 含「开放许可」 | 6 | 2 |
  | transfer 转让（交叉校验） | code ∈ {TA01,TR01,PC,PC1} 或事件含「转移」/transfer/assignment | 19,996 | 467 |

- **类间悬殊解释**：样本 = 转移事件专利集（§〇.1），故 transfer 绝对主导、诉讼 0 命中；许可 50 vs 探针 56 差异 = 探针行级粗查含 6 件开放许可（50+6=56），规则口径下完全可解释。
- **转让交叉校验**：legal 分类 19,996 ↔ transfer 表 20,000，交集 19,996（99.98%）✅。
- **落库**：`patent_legal_event_code`（PK pn+event_category，20,156 行，带命中证据列 ev_matched_events/codes）+ `patent_legal_ipc4_coverage`（106 个 ipc4 覆盖基线：covered/gkx_total/coverage_pct，后端比率分母真源，无需回连主表全扫）。回读 digest `0bd6bb37819feb1a` 一致。
- **004 接线**：市场维 = 5 类在可归因 ipc4 子集内占比 → min-max → 等权（诉讼 0 命中不参与）；market_score 0–100 出数，78/200 领域有覆盖；综合分权重 规模/质量/市场 = 1/3。payload 新增 `market_score` / `market_covered_count` / `market_categories` / `market_category_counts`（全量）/ `market_attributable_counts`（可归因）/ `market_zero_hit_note` / `market_sample_bias_note` / `market_source_note`。
