## 设计

1. 复用已有8张 `demo_gkxlumenx_ads.synth_elem_*`，不新建表、不写ODS/DWD。按区域×对比×时间范围×批号成套填充，1/3/5年分别使用 `mock_20261107_elem_delivery_{1y|3y|5y}`。只复制已命名且is_mock=1的seed，不覆盖原批或任何真实批。
2. 现有 `synth_elem_index.value_json` 扩展保存 `panorama` 和 `panoramaIsMock=true`，保持三透镜原字段。每城五类计数及每类5条明细。只有索引行is_mock=1且JSON显式标记时读此快照；真实批继续原源侧查询。所有数量/名称均为功能演示数据。
3. 同指数表补2020–2023年度mock行，基期2024。历史批号 `mock_20261107_elem_hist_{year}_{window}`，批次时间早于当前批。与活力共用年度历史读取器，按条件及EQUAL档读1/3/5个点，同比只用相邻年度且非零基数。
4. 全景分类为当前结果数组的本地筛选，支持所有已完成条件；切条件或快照重置为全部。不会再用任务ID查询跑批。新任务结果的snapshotId保留实际batch标识，source仍为task。
5. 旧成功任务若compositeIndex=null且无类型/指标结果，工作台改为展示同条件有效跑批（mode=instant、task=null），不篡改数据库冻结载荷；报告同样使用跑批结果，不向空父任务申请PDF。已有有效冻结任务保持原结果。
