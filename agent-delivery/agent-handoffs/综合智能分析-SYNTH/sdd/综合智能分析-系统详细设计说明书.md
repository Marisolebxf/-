### 11.2 公共列与批次语义

公共列（全部本模块新建表必备）：

| 列 | 说明 |
|---|---|
| `metric_id` | 指标结果表必填；分析产物/快照可空 |
| `region_code` / `region_name` | 目标区域 |
| `compare_scope` | 对比范围 |
| `window_label` | 最近1年/3年/5年（中文归一） |
| `year` / `period_key` | 可空 |
| `value_num` / `value_json` | 标量或结构化载荷 |
| `calc_batch_id` | 批次号；预填批用 `mock_` 前缀 |
| `calc_batch_created_at` | 批次时间；**「最新批」以此排序，禁止对 `calc_batch_id` 字符串比大小** |
| `calc_status` | `running` / `succeeded` / `failed`；**读取只认 `succeeded`** |
| `is_mock` | 预填/未实算为 1 |
| `method_version` | 与快照外壳一致 |
| `generated_at` | 写入时间 |

批次与幂等规则（每表的业务粒度/唯一键见对应 L2 册 DATA 表）：

| 规则 | 内容 |
|---|---|
| 业务唯一键 | `(region_code, compare_scope, window_label, 业务维度列…, calc_batch_id)`；**快照/图事实类表唯一键同样必须含完整条件上下文（region+compare+window）**，同一主体在不同区域/窗口是不同行，不得互相覆盖。DDL 以 `uk_` 落地 |
| 写入方式 | 按批整写：新批全部插入 `running` → 校验通过整批置 `succeeded`；失败批置 `failed` 隔离，不被读取 |
| 读取批次 | 同条件键下 `calc_status='succeeded'` 按 `calc_batch_created_at` 取最新批（先查最新批时间，再取该批全部行，两条 SQL，防半批）；**禁止**用 `calc_batch_id` 字符串/UUID 比较新旧 |
| 重跑 | 生成新批次，不覆盖旧批；保留最近 3 批，更早由清理任务删除（owner：data-agent） |
| 并发半批 | 只读 `succeeded` + 整批同 `calc_batch_id`，天然规避 |
| 原子性 | 批次状态翻转是提交点；禁止以单条 UPSERT 作为发布方式 |

DDL 列宽/索引会签后由 data-agent 出（demo+正式两份，结构一致）。
