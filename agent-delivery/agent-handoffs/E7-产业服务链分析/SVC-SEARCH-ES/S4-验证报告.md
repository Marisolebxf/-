## 2. 已知语义差异（ES vs MySQL，均已记录接口文档 §6）

| 场景 | MySQL | ES | 根因与立场 |

| `industry=研究和试验发展` | LIKE 子串跨值命中 11,693（含「工程和技术研究和试验发展」7,117 + 「自然科学…」2,134 + 「医学…」1,346 等） | IK 短语匹配 2,165 | MySQL LIKE 把「研究和试验发展」当子串跨行业大类命中；ES 按分词短语精确。**ES 更准确**；高筛侧走 filters `industry in [...]`（meta 字典值精确匹配）无此问题 |

## 3. 检索能力边界（如实）

- **拼音检索（shenzhen / sz）**：0 命中——集群未装 `analysis-pinyin` 插件，`pinyin_analyzer` 回落 standard 单字分词。**mapping 已预留子字段 `name_cn.pinyin`，装插件后重建索引即激活**（PLAYBOOK-svc-org-index-recreate §回退有记录）。属集群能力边界，非本次改造缺陷。
- **前缀检索**：`match_phrase_prefix`（华大基）0 命中——同因（无插件/未建 ngram 专用字段）；当前 keyword 检索走 `wildcard *华大*` 已覆盖子串场景（华大=22/22 对齐 MySQL）。
- **org_kind=高校/科研院所**：0 命中——诚实值。服务池 43,296 家按 `_org_kind` 物化全部为企业（上游 demo 灌数来源即企业池），前端智能解析 chip「高校」在 ES 命中 0 属数据事实，非过滤故障。

## 5. 验证结论

- **回退 DoD 达成**：默认引擎（mysql）下旧参数行为与改造前逐字一致；ES 引擎异常自动降级路径经 24 项单测与活体验证。
- **灰度就绪**：`SVC_SEARCH_ENGINE=es` 可按页灰度；`engine` 字段出参可观测（前端埋点待灰度上线时补，接口文档 §8 已标注）。
- **三 Tab 全链路**：前端 DSL（`46cda9f`）→ Java Map 透传 → Python 双引擎（`db68cf7`）→ ES 43k 索引（`f8602df`），端到端可用。
