# 服务机构检索 ES 化方案（gkx_svc_org 独立轻量索引）

> 任务：`LUMEN-SVC-SEARCH-ES-L01` ｜ Epic：E7-产业服务链分析 ｜ 状态：**方案稿，待用户评审**
> 决策链：2026-10-20 用户拍板「分开索引 + 服务链 ES 轻量化 + 企业信息二次查询企业 ES + MySQL 零改动」。
> 本文按用户要求组织：ES 结构（基于服务链现有字段全量调研）→ mapping 方案（参考企业 ES，每个字段标注来源）→ 后端接口（尽量复用，高筛复用不了则新契约）。

## 0. 背景与决策记录（为什么做）

| 事实 | 证据 |
|---|---|
| 三 tab（智能检索/查机构/高级筛选）现走 MySQL `svc_org_card` | `lumen-topic-py/gkx_svc_service/repo.py` pymysql 直查 |
| 表 43,296 行，**零二级索引**（仅 PK + `uk_svc_org_card_org`） | `demo-algo-ent-analysis/scripts/mysql/svc_ddl_demo_empty.sql:63-82` |
| `LIKE '%kw%'` 全表扫，实测 0.2~2.8s；等值条件（六类）也扫全表 | 2026-10-20 接口实测 |
| 机构源量级 5000 万（用户口径），口径放开后 MySQL 必然撑不住 | 用户 2026-10-20 |
| 团队已有企业检索 ES 范式：`gkx_enterprise`（81 字段）+ `lumen-etl-es-py`（模块化 ETL + 水位线 + 别名）+ `gkx_search_service`（ES DSL 查询） | 三仓代码调研 |

**已否决的替代方案**：
- ❌ tag 打在企业索引上（用户提出后经调研否决）：圈定池含高校/科研院所（`_org_kind` 按 uni/inst 集合打标），不保证是企业索引真子集；且 mapping 污染 5000 万文档、变更半径耦合企业主链路。
- ❌ MySQL 加索引续命：前导通配 LIKE 不吃 B+Tree，治标不治本（已与用户确认跳过此档）。

**轻量化原则（用户 2026-10-20 拍板）**：org_id 与企业同源（hang ODS/ENT 同一机构键，非随机 uuid），企业侧详细信息（注册资本/法人/上市/专利/高管/经营范围等 81 字段）**不冗余进服务链 ES**——需要时拿 org_id **二次查询企业 ES**（`gkx_search_service` 既有能力）。服务链索引只存「检索过滤 + 排序 + 卡面摘要」所需最小字段集。

## 2. ES Mapping 方案（参考企业 ES `conf/es/gkx_enterprise_mappings.json` 81 字段范式）

### 2.1 索引与别名

- 物理索引 `gkx_svc_org_v1`，别名 `gkx_svc_org`（全量重建走 v2 + 别名原子切换，回退=指回 v1；复用 `app/es.py` 现机制）。
- settings 复用 `build_index_settings()`（IK/pinyin 插件自动探测，缺失自动回退 standard——demo 单节点已验证此降级路径）。
- 分片：43k 文档 1 shard / 0 replica（企业默认同款；量级涨到百万再调）。

### 2.2 字段 mapping（每个字段标来源）

**A. 身份与路由（3）**

| 字段 | 类型 | 来源 |
|---|---|---|
| `org_id` | keyword | card.org_id（hang ODS/ENT 同键；**ES _id 同值**，二次查企业 ES 直接用） |
| `data_source` | keyword | ETL 常量 `svc_org_card` |
| `synced_at` / `es_updated_at` | date | ETL 时间戳（企业同款三兄弟） |

**B. 检索面（4，参考企业 name_cn 三件套）**

| 字段 | 类型/analyzer | 来源 |
|---|---|---|
| `name_cn` | text `ik_max_word_analyzer` + 子字段 `.keyword`（排序） | card.name_cn |
| `name_pinyin` | text pinyin tokenizer（缺插件回退 standard） | ETL 由 name_cn 生成 |
| `name_prefix` | text `edge_ngram_analyzer`（1~20，输入即搜） | ETL 由 name_cn 生成 |
| `industry` | text `ik_smart_analyzer` + `.keyword` | card.industry |

**C. 过滤面（8）**

| 字段 | 类型 | 来源 |
|---|---|---|
| `service_type` | keyword | circle.service_type_candidate（六类：IP/FINANCE/HR/MKT/CONSULT/INNOV） |
| `org_kind` | keyword | ETL 物化 `_org_kind()`（高校/科研院所/企业，uni/inst 集合判定，规则复用 svcseed.py） |
| `stage_codes` | keyword[] | ETL 物化 `stage_of()`（stage-research/ip/transfer/pilot/testing/market；与 svcmodels.py 同款规则） |
| `province` / `city` / `area` | keyword | card 三列原样 |
| `pending_client_confirm` | boolean | circle 同名列（圈定待核验标记，D9 诚实性用） |
| `fields_flat` | keyword[] | ETL 领域词规则（⚠️ Q2 待定） |

**D. 排序与评分面（4）**

| 字段 | 类型 | 来源 |
|---|---|---|
| `tech_score` | float | svc_tech_power_score.score（最新 calc_batch_id，六类取该机构最高分；**无分= null 不伪造**） |
| `dimension_scores` | object{5 float} | 同上 dimension_scores（Q060 五维，画像抽屉用） |
| `incorporation_year` | integer | 企业 ES 二跳回填（mget org_id→incorporation_year，一次性轻拷贝；⚠️ Q3 miss 则空） |
| `employees_number` | integer | card.employees_number（年报投影，规模排序备用） |

**E. 摘要卡面（3，二次查询前的最小展示信息）**

| 字段 | 类型 | 来源 |
|---|---|---|
| `ext` | object(flattened) | card.ext 原样透传（recommended 等零散标记） |
| `etl_batch_id` | keyword | card 同名（血缘追踪） |
| `rule_version` | keyword | circle 同名（圈定规则版本） |

**合计 22 字段 vs 企业 81 字段——轻量化达成**（不含专利/高管/上市/经营范围等企业专有信息，全部二次查询企业 ES）。

### 2.3 二次查询协议（企业信息怎么拿）

- 服务链检索结果 → 前端拿 `org_id` 列表 → 走既有 `gkx_search_service` 企业详情接口（`enterprise_detail_*` 系列已存在）。
- **后端聚合兜底（推荐做在 S2）**：`profile/get` 内部先查 `gkx_svc_org`，再 mget 企业 ES 补全企业字段，一次往返给前端画像抽屉。前端零改动。

## 3. 后端服务接口方案

### 3.1 总原则：契约能不动就不动，动则出正式接口文档

| 接口 | 现状 | ES 化后 | 前端影响 |
|---|---|---|---|
| `POST /svc/topic/v1/service/search/orgs` | MySQL 版 | **路径/出参契约不变**；内部双引擎；新增 3 个可选入参（见 3.2） | 零改动即受益 |
| `POST /svc/topic/v1/service/profile/get` | MySQL card+tech | 先查 svc 索引 + mget 企业 ES 补全 | 零改动（字段只多不少） |
| Java 门面 `ServiceFacadeController` | 透传 | **零改动**（Feign 契约不变） | — |

### 3.2 search/orgs 入参扩展（向后兼容，全部可选）

```jsonc
// 新增可选参数（旧参数 keyword/service_type/city/province/area/industry/page/size 原样保留）
{
  "sort": "tech_score" | "name_cn",        // 默认 name_cn（与现 MySQL 行为一致）；tech_score 缺分机构排后
  "org_kind": "高校|科研院所|企业",          // 高筛 type 条件
  "stage_code": "stage-testing",           // 高筛 segment 条件（单值；多值传数组）
  "tech_score_gte": 60,                    // 高筛 techScore 区间
  // 以下为高筛 DSL 直译模式（S3 前端切换用，见 3.4）
  "filters": [ {"field":"city","op":"in","value":["深圳","广州"]}, {"field":"tech_score","op":"gte","value":60} ]
}
```

### 3.3 出参扩展（旧字段逐字保留，新增字段只增不删）

```jsonc
{
  "code": 0, "data": {
    "items": [/* _card_item 形状原样 + tech_score + tech_scores[] + stage_codes + org_kind */],
    "recommended": [ /* 新增：tech_score Top6 卡面（修「技术力领先机构」空推荐位） */ ],
    "total": 43296, "page": 1, "size": 12, "empty": false,
    "data_source": "es:gkx_svc_org",       // 引擎标识（回退时为 demo_ads）
    "engine": "es" | "mysql"                // 新增：灰度观察用
  }
}
```

### 3.4 高筛（高级筛选 tab）复用决策——**复用不了，出新契约**

调研结论：`gkx_search_service` 的企业高筛 DSL 翻译层（`enterprise_search.py` 600+ 行：字段注册表 `_FIELD_REGISTRY`、操作符→ES 子句、nested 处理）**强耦合企业字段面**（`_NESTED_PATHS`、企业字段白名单、企业默认排序），服务链字段集不同（org_kind/stage_codes/tech_score 均为企业没有的），硬复用=双方都改=回归风险两倍。

**决策：`gkx_svc_service` 自建轻量 DSL 翻译器**（预计 ~150 行：8 个过滤字段 × 5 种操作符的直译表），复用企业侧的**翻译范式**（`_wrap/match_phrase/bool should` 写法照抄）而非代码本体。**上线后给前端下发新接口文档**（3.2 的 filters 数组协议 + 字段-操作符矩阵），前端 `dslToSearchBody` 从「透传 4 字段」切到 filters 直译——**根治七字段静默丢弃的诚实性问题**。

### 3.5 灰度与回退

- 环境变量 `SVC_SEARCH_ENGINE`（默认 `mysql`）→ `es` 按页灰度；
- ES 异常自动降级 mysql（单次请求级 try/except，日志打点）；
- 回退验证 DoD：切回 mysql 后三 tab 示例查询行为与改造前逐字一致。

## 4. ETL 方案（lumen-etl-es-py 新增 service_org job）

```
源（MySQL）                          物化计算（ETL 内，一次性算好）              → ES 文档
─────────────────────────────────────────────────────────────────────────────
svc_org_card (43k, 主骨架)
LEFT JOIN svc_org_circle        →   service_type / pending_client_confirm / rule_version
LEFT JOIN svc_tech_power_score  →   tech_score / dimension_scores（取最新 batch 最高分）
                                  + org_kind（uni/inst 集合判定，规则同 svcseed）
                                  + stage_codes（stage_of() 启发式，规则同 svcmodels）
                                  + name_pinyin / name_prefix（分词器侧生成，ETL 只传原文）
                                  + incorporation_year（企业 ES mget 回填，miss 留空 Q3）
```

- 模块范式：仿 `RegInfoSyncModule`（`creates_docs=True` 一对一），水位线模块名 `svc_org_card`（增量按 `update_time`，复用 `WatermarkManager`）；
- 全量 43k 文档：分钟级；重跑= v2 别名切换，不删旧索引；
- 触发：`POST /internal/etl/indexes/service-org`（仿企业侧 `indexes/enterprise` 端点）；
- **规则单一真源**：`stage_of/_org_kind` 逻辑从 `demo-algo-ent-analysis` 抽到共享（或复制时注明真源指针），禁止两边漂移。
