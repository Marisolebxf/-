## 企业总览定义

`企业总览` 是门户展示型入口，原始需求名称为“企业发展”。页内按原始顺序设置 `企业整体概况 / 重点企业概览 / 明星企业介绍 / 深圳企业介绍` 四个页内一级 Tab。

“企业发展”的产品语义确认为：以产业内企业群体为观察对象，通过企业规模、空间分布、重点企业、代表企业和深圳企业情况，判断当前科技专题所对应产业的发展态势。它不是单企业成长服务，也不是招商、培育、风险处置等企业业务工作台。

菜单继续使用 `企业总览`，产品定义保留“当前科技专题产业的企业发展态势总览”。页面提供趋势、结构和代表企业贡献等轻量解释，但不进入企业评估、风险诊断、推荐模型等专业研判。

### 原型模拟数据边界

八大未来产业的具体目录、编码、企业归属和产业链映射在本期先不等待真实数据。前端原型可使用合理的模拟数据完成展示开发，但模拟数据必须按真实数据替换接口设计，不能在文档、页面说明或验收中冒充已确认的官方产业目录。

| 模拟数据规则 | 要求 |
| --- | --- |
| 产业数量 | 固定构造 8 个未来产业展示对象，满足八大未来产业总览的页面结构；具体名称可用原型命名，不宣称为正式目录。 |
| 关联关系 | 每个未来产业配置一个或多个模拟产业链、重点企业、明星企业及深圳统计数据；同一标识在总览、重点企业、明星企业和深圳企业介绍中保持一致。 |
| 数值叙事 | 数量、趋势、区域分布、科研人数、规模分布和企业亮点应相互一致，能支撑多产业对比和单产业专题浏览。 |
| 可替换性 | 产业、产业链、企业、统计批次和推荐依据使用独立数据结构，不将名称、数值或链位写死在页面逻辑中。 |
| 真实数据接入 | 后续以专题目录、产业链映射和数据批次替换模拟数据；替换不应改变已确认的信息架构、范围提示和页面交互。 |

本规则只解除原型展示开发的数据依赖，不代表企业总览 UE 已完成确认，也不自动启动前端实现。

原始需求未要求把“所属未来产业”作为所有企业实体的必显字段，也未将其定义为企业类型。本文将“未来产业”首先作为企业总体数量和企业分布的统计分组口径；如后续在同一页面引入跨产业企业卡片或表格，才可将 `所属未来产业` 作为可选辅助标签，并明确这是产品增强而非原始需求直接要求。

`重点企业产业链全景` 归属 `企业总览 → 重点企业概览`，承接门户 `E-33` 重点企业全景图；不归入“重点企业分析”。企业总览负责看内容、识别代表企业和进入企业画像，不承担战略分析式的复杂筛选、统计下钻和城市对标。

### 门户展示深化边界

企业总览严格承接原始“企业发展”的四项内容；页面共享的是当前专题产业上下文，不新增企业查询式多字段筛选、条件组合、查询方案或导出入口。

这里的“当前专题”指科技专题服务中的八大未来产业范围；“当前产业”指用户从总览进入或选中的其中一个具体未来产业。科技专题战略分析中的“目标产业”属于独立的通用分析能力，不反向扩大企业总览门户范围。企业总览必须持续、明确展示当前科技专题；凡进入某一产业或产业链的具体内容，还必须明确当前未来产业与产业链名称。

页面级上下文至少应表达 `科技专题服务 / 八大未来产业或当前未来产业 / 数据时间或批次`。展示范围可以是八大未来产业的聚合或对比，也可以是其中一个具体未来产业；具体由各 Tab 原始功能决定。涉及产业链的区块必须显示具体未来产业和产业链名称，不能只使用脱离上下文的“全链重点企业”。若当前未来产业包含多条可展示产业链，区块一次只展示一条，并在当前未来产业范围内轻量切换；不得把多个产业或多条产业链的企业混成一条“全链”。

| 页内 Tab | 原始功能 | 本期门户深化设计 | 不承接内容 |
| --- | --- | --- | --- |
| 企业整体概况 | 企业总体数量、企业分布情况、科研人数 | 企业总体数量与企业分布按各未来产业聚合 / 对比；科研人数展示产业科研人数规模，不与企业从业者总人数混用；如后续展示跨产业企业对象，产业标签属于可选增强 | 企业类型交叉筛选、企业清单下钻、评估评分、图表导出 |
| 重点企业概览 | 重点企业全景、重点企业规模统计、重点企业领域统计 | 采用“当前未来产业 + 当前产业链”两层口径：先明确八大未来产业中的具体产业，再展示该产业链全景、重点企业基础信息、四类企业规模统计和领域分布 | 多产业混合链、供应商 / 客户关系、断链风险、推荐排名、独立导出 |
| 明星企业介绍 | 产品功能全景图、技术优势可视化、团队实力多维展示、产业生态图谱 | 以当前未来产业下按预设标准固定推荐的一家明星企业为对象；按产品、技术、团队、产业生态四个区块组织内容；生态节点可查看合作详情 | 用户自行选择企业、企业评估、风险诊断、招引 / 培育结论 |
| 深圳企业介绍 | 深圳企业数量、领域分布、规模分析、深圳重点企业 | 固定深圳地域，并按八大未来产业展示数量与历年趋势、领域分布、规模分布和深圳重点企业；领域分布结合各未来产业链全景图；原文“各产业”在本门户范围内归一解释为八大未来产业 | 全国 / 城市对标、产业链角色下钻、企业评估模型、供应链风险 |

`企业整体概况`、`明星企业介绍`、`深圳企业介绍`的原始需求均未提出企业查询式筛选或导出；“按产业”在企业总览门户中统一限定为八大未来产业及其中的单个未来产业。原型可使用轻量产业切换或从概况中的产业项进入具体未来产业，但不能复用企业查询或重点企业分析的复杂筛选体系。

深圳企业介绍的“按产业”同样是统计分组，不等于只显示单一当前产业。该 Tab 先回答“深圳在各未来产业中的企业发展状况”，再可在图表中聚焦某个产业；不将其改造成全国 / 城市横向对标或企业集合下钻页面。

### 明星企业固定推荐规则

明星企业不是用户从企业库中自由挑选的对象，而是当前产业下按预设标准固定推荐的代表企业。同一产业、同一标准版本下，候选企业共用一套入选标准；切换当前产业或标准版本后，同步切换对应的标准和明星企业。每家企业展示的不是另一套独立标准，而是其在共用标准下各自不同的 `入选理由`。当前不提供手动换一家、随机推荐或跨产业明星企业混排。推荐标准、阈值、候选池来源、更新频率及维护责任由后续数据 / 运营规则确认。

推荐标准必须向用户说明，但不等于暴露原始评分公式或敏感数据。页面采用三层透明规则：

| 层级 | 展示内容 | 规则 |
| --- | --- | --- |
| 首屏摘要 | `入选理由` 一句话、当前产业、适用标准版本或数据时间 | 始终可见，说明该企业在共用标准下为何作为当前产业代表企业出现 |
| 查看入选标准 | 适用产业、候选范围、标准名称 / 版本、已确认的评估维度和更新时间 | 点击 `查看入选标准` 后以浮层或抽屉展示；这是当前产业候选企业共用的标准。标准未定稿时如实显示“入选标准待配置”，不得伪造具体标准 |
| 企业入选理由 | 当前企业匹配的具体亮点和可展示证据摘要 | 与共用标准区分展示；不同企业可不同，不作为另一套独立标准 |
| 不公开内容 | 具体权重、内部阈值、排名、敏感原始证据、运营人工备注 | 不在门户页面公开；如后续存在内部审计需求，另按权限进入维护或审计能力 |

因此，用户既知道“当前产业按什么统一标准筛选”，也知道“这家企业为何在该标准下被选中”，但不会把明星企业页做成可调权重的推荐模型配置页。

### 重点企业概览：E-33 重点企业全景图

`E-33` 的原始三项功能为重点企业全景、重点企业规模统计、重点企业领域统计。当前“产业链全景”是重点企业全景的展示方式，必须同时保留规模统计与领域统计，不得只剩链位画布。

| 区块 | 展示与交互 |
| --- | --- |
| 重点企业全景 | 按当前产业及当前产业链展示全链重点企业及企业名称、所在地、企业类型等基础信息；区块标题或上下文必须明确具体产业链名称，链位节点只承担内容浏览，不进入供应链关系分析。 |
| 重点企业规模统计 | 按外企、高企、小微、上市四类，在国家 / 省 / 市三级展示数量或结构分布；不扩展为重点企业分析的七类类型筛选与地图下钻。 |
| 重点企业领域统计 | 结合产业链展示重点企业领域分布；企业论文、专利关键词可作为领域关联依据。 |

当前原型已有的固定高度链位画布、链位详情和代表企业展示可保留为“重点企业全景”的 UE 实现；其数据范围应跟随当前专题产业，不在门户页提供复杂筛选或独立导出。

## 重点企业分析结果定义

`重点企业分析` 是加入对比篮前的企业对象发现与筛选前置页：通过生态类分析帮助用户理解企业结构、发现可操作对象，并把对象带入对比篮、企业评估、风险洞察或引育推荐等后续模块。本页由旧“企业总览分析结果”更名而来，其中 `E-33` 重点企业产业链全景已迁出。

重点企业分析是专业分析入口，不是企业模块默认主入口，也不替代企业总览的门户展示职责。企业分析主路径为：`企业总览（内容认知） -> 企业查询 / 重点企业分析（主动找对象与看结构） -> 对比篮（暂存与分发） -> 企业评估 / 风险洞察 / 引育推荐`。重点企业分析中“加入对比篮、进入企业评估、进入风险洞察、加入招引 / 培育候选”等操作，只在图表或分析项下钻形成明确企业集合后的结果页态提供；对比篮不前置为分析默认数据来源。

### 页面定位

重点企业分析用于承接原需求中的企业生态类分析，包括企业类型与区域分布、重点企业领域覆盖、深圳企业产业链位置和城市横向对标。它负责“看结构、找对象、下钻到企业集合、装篮或带入后续模块”，不负责生成正式深度分析报告。

重点企业分析不做完整技术力 / 商业力 / 综合竞争力评估，不做供应链风险诊断，不做企业发展痛难点诊断，不做招引 / 培育名单生成，不做一企一策建议，不做 OPS 维护，不提供独立导出。

重点企业分析不依赖对比篮作为默认数据来源；对比篮只承接用户在分析页下钻结果页态主动选择的企业对象。重点企业分析也不设置统一对象货架、排行榜页或额外推荐模型。

### 原需求最小充分原则

重点企业分析只补齐原需求明确要求的生态分析和必要承接机制，不主动新增没有原文依据的分析形态。

| 承接内容 | 原需求来源 | 重点企业分析边界 |
| --- | --- | --- |
| 产业与企业类型筛选 | `REQ-ENT-001` | 作为全局口径和类型 / 区域分析条件 |
| 三级地理透视与可视化呈现 | `REQ-ENT-001` | 支持国家 / 省 / 市地图下钻；深圳场景可到区级 |
| 重点企业领域分布分析 | `REQ-ENT-002` | 展示领域覆盖矩阵和跨领域分布图谱 |
| 企业业务关联与领域覆盖计算 | `REQ-ENT-002` | 展示覆盖广度、参与深度和匹配企业集合 |
| 跨领域分布图谱展示 | `REQ-ENT-002` | 展示企业与产业领域之间的跨领域关系，不做无限图谱展开 |
| 深圳企业现状分析 | `REQ-ENT-005` | 展示深圳产业链位置和城市对标，不生成深圳现状报告 |
| 深圳企业产业链定位 | `REQ-ENT-005` | 按产业链、环节、链中角色下钻到深圳企业清单 |

重点企业分析明确不新增：企业排行榜页、正式分析报告、分析图表导出、统一重点对象货架、额外推荐模型、企业评估式评分 / 排名、风险洞察式风险诊断、引育推荐式名单生成。

### 首屏结构

重点企业分析采用一页纵向工作台结构，不恢复旧的 `态势概览 / 企业分布 / 重点对象` 强制页签。若页面内容较长，可使用页内锚点导航，锚点只用于定位，不改变页面结构。

首屏以生态格局判断为主，不以重点对象清单为主。

| 顺序 | 区块 | 内容 |
| --- | --- | --- |
| 1 | 当前筛选口径 | 产业 / 产业链、地域范围、企业类型、产业领域 / 技术标签、数据批次 / 时间口径 |
| 2 | 生态摘要 KPI | 当前口径下企业总量、企业类型覆盖、可下钻企业量、覆盖领域数等总览摘要；不引入综合竞争力均值 |
| 3 | 关键分布图 | 优先展示企业类型与区域分布的地图主视图，帮助理解区域集聚和类型结构 |
| 4 | 下钻对象入口 | 仅作为从图表下钻到企业集合的入口，不展示独立推荐名单 |

全局筛选区不挂 `TraceInfoIcon`，避免组合追溯过载。全局筛选只控制重点企业分析的当前分析口径，不替代企业查询的高级筛选字段库。

### 当前筛选口径

重点企业分析顶部只保留少量全局筛选，避免把分析工作台做成企业查询页。

| 字段 | 规则 |
| --- | --- |
| 产业 / 产业链 | 作为当前分析主口径；产业链可作为产业的细化条件 |
| 地域范围 | 默认深圳；支持全国 / 省份 / 城市切换；地图分析支持国家 -> 省 -> 市逐级下钻，深圳场景可到区级 |
| 企业类型 | 采用七类：外企 / 高企 / 小微 / 上市 / 专精特新 / 小巨人 / 链主龙头，不再区分原文四类和扩展标签 |
| 产业领域 / 技术标签 | 用于领域覆盖和技术方向分析 |
| 数据批次 / 时间口径 | 用于标识统计批次和时间范围，不作为复杂时序分析入口 |

全局口径控制整页 KPI、地图、类型结构、领域覆盖、深圳企业产业链位置和城市对标。产业链 / 链位环节是产业领域的细化条件；选择后相关分析区基于收窄后的企业集合重新计算，但不相关区块不重复展示链位控件。图表点击默认只在当前分析区内下钻、过滤或展开结果区，不改变全局筛选。

### 分析区总览

重点企业分析按四个分析区组织，分析区标题旁在演示 / 内部评审模式显示 `TraceInfoIcon`。普通业务模式隐藏追溯标识。

| 分析区 | traceId | 主视图 | 辅助视图 | 不承接内容 |
| --- | --- | --- | --- | --- |
| 企业类型与区域分布 | `REQ-ENT-001` | 可缩放地图下钻 | 类型结构图、类型 x 区域交叉矩阵 | 企业排行榜、区域竞争力排名 |
| 重点企业领域覆盖 | `REQ-ENT-002` | 领域覆盖矩阵 | 跨领域分布图谱 | 无限图谱展开、推荐模型 |
| 深圳企业产业链位置 | `REQ-ENT-005` | 产业链环节图 | 链位 / 角色分布图 | 供应链关系图谱、风险诊断 |
| 城市横向对标 | `REQ-ENT-005` | 多城市指标对比柱图 | 城市 x 指标对比表 | 城市排行榜、企业评估雷达图 |

图表、矩阵和重点企业分析内下钻结果页态继承所在分析区 `traceId`，不重复密集挂 icon。装篮、查看画像、进入企业评估、进入风险洞察、加入招引候选、加入培育候选等属于派生交互，不单独挂原需求编号。

### 企业类型与区域分布

`企业类型与区域分布` 承接 `REQ-ENT-001`，回答“当前产业和地域口径下，不同企业类型如何分布、在哪里集聚”。

| 项 | 规格 |
| --- | --- |
| 展示结果 | 外企、高企、小微、上市、专精特新、小巨人、链主龙头七类企业在不同区域的数量、规模、占比和类型结构 |
| 主视图 | 可缩放地图下钻；支持滚轮缩放、控件放大 / 缩小、点击区域进入下一级、面包屑返回 |
| 聚合态 | 国家、省、市层级展示区域聚合数据，包括企业数量、规模、占比、类型结构摘要 |
| 最小层级 | 深圳场景可到区级；到达最小展示层级后，地图展示企业点位 |
| 点位规则 | 企业点位可按企业类型着色；hover 展示企业名称、类型、产业领域；点击点位打开简要浮层或企业画像入口 |
| 辅助视图 | 类型结构图 + 类型 x 区域交叉矩阵；多标签企业允许重复计入，但必须提示统计口径 |
| 顶部企业类型筛选 | 为空时展示七类完整维度；筛选后所有 KPI、地图、类型结构图、交叉矩阵、领域覆盖、产业链位置、城市对标和下钻结果都基于已选企业类型集合 |
| 下钻规则 | 支持区域路径、企业类型路径和区域 x 类型交叉路径；点击类型进入该类型企业分布；点击交叉单元进入当前区域 + 当前类型企业清单 |

当前地图范围或最小区域支持地图 / 列表双视图。列表视图使用“重点企业分析内下钻结果页态”统一规则。

### 重点企业领域覆盖

`重点企业领域覆盖` 承接 `REQ-ENT-002`，回答“当前企业集合覆盖哪些产业领域、业务范围、产品线和技术标签”。

| 项 | 规格 |
| --- | --- |
| 展示结果 | 企业业务范围、产品线、技术标签到产业领域的映射关系；覆盖广度、参与深度和匹配企业集合 |
| 主视图 | 领域覆盖矩阵，用于表达覆盖广度和参与深度 |
| 辅助视图 | 跨领域分布图谱，用于表达企业与产业领域之间的跨领域关系 |
| 下钻层级 | 产业领域 -> 技术标签 / 产品方向 -> 企业清单 |
| 点击规则 | 支持点击领域节点、企业节点和领域-企业关系边；点击后在页内结果区展示匹配企业及覆盖深度 |

| 项 | 规格 |
| --- | --- |
| 展示结果 | 指定产业链或环节下的深圳相关企业、链中角色、环节覆盖情况 |
| 主视图 | 产业链环节图 |
| 辅助视图 | 链位 / 角色分布图 |

### 城市横向对标

`城市横向对标` 承接 `REQ-ENT-005`，回答“深圳企业群与北京、上海、苏州等城市相比，哪些指标有优势或短板”。

| 项 | 规格 |
| --- | --- |
| 展示结果 | 深圳与北京、上海、苏州等城市的平均技术力、商业力、企业密度等群体指标对比 |
| 主视图 | 多城市指标对比柱图 |
| 辅助视图 | 城市 x 指标对比表 |
| 下钻层级 | 对标城市组 -> 指标 -> 城市企业集合 |
| 点击规则 | 点击指标查看各城市该指标对比；点击城市 x 指标单元查看当前口径下支撑该指标的企业集合 |
| 边界 | 不生成城市排行榜，不进入企业评估模型详情；技术力 / 商业力仅作为城市企业群体均值指标引用，深度评估进入企业评估 |

城市横向对标不使用雷达图。雷达图属于企业技术力评估对比分析，不在重点企业分析复用。

### 重点企业分析内下钻结果页态

重点企业分析不设置统一对象货架。三个分析区通过模块内下钻结果页态展示对象清单；用户点击地图、类型、领域、深圳产业链环节或城市对标项后，主内容区切换为当前条件下的企业结果页，原分析区不在同屏追加展示，并通过顶部面包屑返回重点企业分析或来源分析区。

重点企业分析内下钻结果页态展示完整分页企业列表，不只是摘要列表。

| 项 | 规格 |
| --- | --- |
| 数据口径 | 当前全局筛选口径 + 当前分析区下钻条件 |
| 顶部筛选 | 只在重点企业分析首页展示；下钻结果页态隐藏顶部筛选，返回重点企业分析首页后恢复 |
| 页面形态 | 主内容区整页承载结果列表，不作为底部追加结果区，不加外层高亮边框或卡片 |
| 返回 | 通过面包屑返回重点企业分析或来源分析区，不提供独立返回按钮 |
| 列表模型 | 复用企业查询列表字段模型和对象操作 |
| 列表能力 | 分页、排序、勾选、轻量筛选、批量动作 |
| 轻量筛选 | 企业名称、企业类型、区域、产业领域 / 技术标签、数据更新时间等与当前下钻条件相关的字段 |
| 不承接能力 | 复杂筛选、高级字段库、AND / OR 条件构造、保存查询方案、导出 |
| 单行动作 | 企业名称进入详情页；`查看画像` 打开画像抽屉；支持加入对比篮 |
| 批量动作 | 加入对比篮、进入企业评估、进入风险洞察、加入招引候选、加入培育候选 |

进入企业评估、风险洞察或引育推荐前，必须形成明确企业对象集合，并完成数量、权限、对象状态、字段可用性和来源条件校验。未选择对象时不进入后续模块。跨模块动作必须记录来源分析区和下钻条件。

重点企业分析内下钻结果页态不提供导出按钮，也不设计导出跳转。原需求没有重点企业分析导出要求。

### 重点企业分析与企业查询边界

重点企业分析不设置跳转 `企业查询` 的专门入口，也不定义分析到查询的条件传递规则。

重点企业分析只处理当前分析口径下的图表查看、模块内下钻结果页态、完整分页列表、轻量筛选 / 排序 / 勾选、加入对比篮，以及带入企业评估、风险洞察或引育推荐等后续模块。

若用户需要主动检索、复杂筛选、高级筛选字段库、AND / OR 条件构造、保存查询方案或查询清单导出，应直接通过左侧二级菜单进入 `企业查询`。

### 不保留当前实现口径

| 当前实现内容 | 处理 |
| --- | --- |
| 企业全景类菜单命名 | 不保留，避免与企业总览语义过近 |
| 企业数量态势看板式布局 | 不作为目标结构，只可复用必要摘要指标 |
| 顶部智能搜索常驻压过分析内容 | 不作为重点企业分析主结构；查询能力回到企业查询页 |
| `态势概览 / 企业分布 / 重点对象` 旧 Tab | 不恢复为重点企业分析强制 Tab；如需快速定位，仅使用页内锚点导航 |
| 重点对象态势 / 推荐名单式表达 | 不作为重点企业分析独立模块；改为下钻企业清单、当前条件企业对象、匹配企业集合等中性表述 |

| 需求追溯 `i` icon | 仅在评审 / 演示模式显示，不跟业务角色绑定 |

## 个人资产中心本期口径

个人资产中心作为本期产品化能力纳入交付，不只作为后续预留。它是全系统个人能力，入口放在右上角用户菜单 / 个人中心中，不进入企业模块左侧二级菜单。本期先承接企业模块产生的可复用资产、暂存对象和导出记录，后续可扩展到产业链、政策、产业服务链、综合智能分析等模块。

### 最近查询与查询方案

最近查询和查询方案分开管理：

| 类型 | 产生方式 | 保留规则 | 恢复方式 |
| --- | --- | --- | --- |
| 最近查询 | 用户执行普通关键词查询、结构化查企业、高级筛选应用、热门场景查询后系统自动记录 | 只保留近 30 天，最多 20 条；重复条件合并更新时间和命中数量 | 按来源恢复普通查询页或高级筛选字段库 |

最近查询不记录空查询。VISIT 访客不记录最近查询。涉及敏感字段的查询，记录条件摘要时需要脱敏。

### 指标配置生效规则

普通用户的指标配置分为临时配置和个人模板：

| 配置形态 | 生效范围 | 本期处理 |
| --- | --- | --- |
| 临时分析配置 | 当前分析任务 | 用户选择指标、调整权重后，立即影响本次技术力、商业力、综合竞争力计算、对比图和报告草稿 |
| 保存为个人模板 | 当前用户个人资产 | 用户可将本次指标组合和权重保存为个人模板，后续在企业评估和评估报告导出中复用 |
| 全局指标模板 | 全系统默认模型 | 不给普通用户直接修改；由 OPS / SYS 按维护、审批和版本规则处理 |
| 团队共享模板 | 团队或机构范围 | 本期不作为企业模块必做，后续可在个人资产中心扩展 |

个人模板只影响当前用户后续使用，不直接改变全局默认模型。用户加载个人模板时，应基于当前数据版本重新计算，并在报告或浮层中标记模板名称、指标口径和数据更新时间。

### 企业评估任务历史

本期轻量保存企业评估任务历史，用于恢复最近评估任务、关联报告导出记录和避免重复生成报告，不做完整任务管理系统。

| 项 | 规则 |
| --- | --- |
| 产生时机 | 用户生成评估结果后自动生成评估任务记录 |
| 不保存场景 | 只配置但未生成评估结果的任务，不进入正式历史 |
| 与个人模板关系 | 保存个人模板只保存指标组合和权重，不等于保存评估任务 |
| 与报告导出关系 | 报告导出记录关联评估任务 ID；一个评估任务可关联多个报告导出记录 |
| 页面入口 | 企业评估页可提供 `最近评估任务`、`恢复上次评估`、`查看关联报告` |
| 不做能力 | 不做多任务项目管理、团队共享评估任务、复杂版本比较和任务协作审批 |

评估任务历史至少记录：评估任务 ID、评估任务指纹、评估模式、企业对象集合、指标模板、指标组合、权重配置、区域 / 产业 / 时间口径、数据批次、生成状态、最近更新时间和关联报告导出记录。

### 报告导出记录规则

报告导出记录支持查看和有效期内重新下载。

| 状态 | 行为 |
| --- | --- |
| 生成中 | 显示报告生成进度和当前阶段，可从个人资产中心进入查看 |
| 生成成功 | 在有效期内且权限未变化时可下载 |
| 生成失败 | 显示失败原因、失败时间和可重试入口，保留审计状态 |
| 可重试 | 用户可基于原评估任务指纹重新发起生成 |
| 有效期内且权限未变化 | 可查看记录并重新下载 |
| 超过有效期 | 只显示记录，不允许重新下载 |
| 权限变化或对象权限失效 | 只显示记录，不允许重新下载；提示权限变化 |
| 待支付 / 待审批 | 显示记录和状态，不提供正式下载 |
| 已支付 / 审批通过 | 按权限和有效期允许下载 |

报告导出记录至少展示导出类型、导出时间、对象数量、字段范围、水印信息、收费状态、审计状态、生成状态、失败原因、有效期、关联评估任务指纹和关联追溯编号。

- 追溯与来源：数据来源、更新时间、可信度、`REQ-*` 追溯编号。

### 字段分级规则

企业 schema 按 `必填 / 可选 / 预留` 分级。这里的必填不是数据库非空约束，而是产品交付和验收中的字段优先级。

| 分级 | 含义 | 前端和导出规则 |
| --- | --- | --- |
| 必填字段 | 支撑企业识别、查询、对比、评估、导出和追溯的核心字段 | 列表、画像、导出默认使用；缺失时显示 `暂无 / 待补充` 并进入数据质量提示 |
| 可选字段 | 增强详情、分析深度和报告解释力的字段 | 详情页和报告按可得性展示，可由模板或权限控制导出 |
| 预留字段 | 原始需求有方向或产品化有价值，但本期不强制完整落地 | schema 和对接说明中保留，页面不要求首批展示，不默认导出 |

| 字段组 | 必填 | 可选 | 预留 |
| --- | --- | --- | --- |

| 企业类型资质 | 企业类型、企业资质、高企/专精特新/上市标识 | 资质荣誉清单、企业规模 | 荣誉证书附件 |
| 技术能力 | 技术力分、有效专利数、核心技术标签 | 高价值专利、研发人员占比、专利引用 | 论文、标准、软著明细 |
| 商业能力 | 商业力分、营收规模或营收区间 | 营收增长率、利润率、市场份额、客户集中度 | 融资轮次、投资机构 |
| 综合竞争力 | 综合竞争力分、排名或分档、主要优势/短板 | 雷达图分项、差距分析 | 自定义评价版本对比 |
| 供应链关系 | 链位、供应链角色、断链风险等级 | 上游、下游、合作伙伴、核心供应商 | 多级供应链全量明细 |
| 风险痛点 | 风险等级、风险类型、痛点类型 | 舆情风险、经营风险、知识产权风险、改进建议 | 完整风险事件流水 |

| 追溯来源 | 数据来源、更新时间、数据版本、追溯编号 | 字段来源明细、可信度等级 | 原始采集批次明细 |

### 字段使用规则

1. 查询列表只使用必填字段和少量高价值可选字段。
2. 企业画像头部只展示必填字段和核心评分，不堆完整字段。
3. 详情页承接可选字段。
4. 预留字段不要求本期页面完整展示，但 schema、导出模板和对接说明中保留。
5. 字段缺失不能让页面空白，应显示缺失状态，并在 OPS 数据批次或来源状态中可追踪。
6. 导出报告按模板控制字段：必填字段默认导出，可选字段按模板或权限选择，预留字段不默认导出。

### 查询入口切换规则

`智能搜索`、`查企业`、`高级筛选` 是三个独立查询入口，可以复用结果列表模型，但不能共享同一个已提交结果态。用户从一个入口切换到另一个入口时，应进入目标入口的初始查询状态，而不是继续展示上一入口的结果。

| 切换动作 | 产品规则 |
| --- | --- |
| 智能搜索结果态 -> 查企业 | 清空智能搜索输入、识别条件和结果区，进入查企业初始态 |
| 智能搜索结果态 / 查企业结果态 -> 高级筛选 | 进入高级筛选字段库初始态；如来自热门场景则只带入预置条件，不展示旧结果 |
| 查企业结果态 -> 智能搜索 | 清空查企业关键词和结果区，进入智能搜索初始态 |
| 高级筛选结果态 -> 智能搜索 / 查企业 | 清空字段库结果态，进入对应普通查询初始态 |
| 最近查询 / 查询方案恢复 | 这是用户明确恢复历史资产的动作，可按记录来源恢复条件；查询方案默认先展示条件，由用户确认后执行 |

该规则用于避免用户误判结果来源。结果列表、排序、视图切换、对比篮等组件可以复用，但每次入口切换必须重置当前查询提交状态。

原需求中的智能检索更接近自然语言检索 / 语义理解能力；本期已弱化为传统关键词匹配 + 多字段条件匹配 + 高级筛选。`智能搜索` 名称可保留为入口名称，但 `智能解析` 等文案只能按多字段匹配触发理解，不承诺自然语言 / 大模型语义解析。

企业查询页面级 UE 规则单独维护在 `p2a-session/企业模块深化UE规格.md`，本产品规格不展开页面组织、状态反馈、对象流转和 frontend-agent 执行规则。

查询结果状态需区分主查询结果和结果内筛选结果：智能搜索、查企业或高级筛选的主查询命中 0 时才进入查询结果空态；结果空态不展示推荐企业或相近推荐，只保留修改关键词、清空条件、切换模式、编辑高级筛选等纠错动作。若主查询已有命中、仅结果列表内的二次筛选命中 0，应保留查询方案摘要、当前条件和结果列表操作区，只在列表内容区域展示“结果内筛选无匹配”的局部空态，并提供清除结果内筛选。

查询结果排序遵循“排序字段 = 结果可解释字段”：进入排序下拉的字段必须在卡片或表格结果项中常驻展示，不能只在排序控件中出现。当前企业查询排序字段为综合竞争力、有效专利数、最新营收和成立时间，均应在结果展示中可见；算法类字段需保留指标说明入口。

查询清单导出任务属于当前查询结果上下文。查询页内的导出任务状态只展示当前查询方式和当前查询条件产生的任务；切换到其它查询入口后不共享上一入口的导出状态。重新查询时不自动恢复历史已完成或已失败的导出进度面板；进行中任务可保留，刚完成 / 刚失败的任务只短暂反馈。完整导出历史统一进入个人资产中心查看。

## 企业评估规格

`企业评估` 用于对选定企业进行技术力、商业力和综合竞争力评估，支持指标配置、评分结果、企业对比、排名、差距分析和报告输出。企业评估不是对象暂存区，也不是企业查询页；对象可来自企业查询、企业总览、对比篮、画像详情等入口，进入企业评估后再选择评估模式和任务类型。

### 企业评估模式

| 评估模式 | 原需求依据 | 用途 |
| --- | --- | --- |
| 技术力评估 | 企业技术力评估对比分析 | 评估企业技术创新能力、专利、研发、核心技术覆盖和技术短板 |
| 商业力评估 | 企业商业力评估对比分析 | 评估企业市场表现、营收、盈利、客户、品牌和商业化能力 |
| 综合竞争力评估 | 企业竞争力分析 | 综合技术、商业、组织等维度，形成综合竞争力判断 |

三种评估模式在企业评估页内切换，不拆成左侧二级菜单。

### 企业评估对象数量规则

| 评估模式 | 1 家企业 | 2 家企业 | 3 家以上 |
| --- | --- | --- | --- |
| 技术力评估 | 不支持 | 支持，输出技术力得分、双企雷达、指标差异、差距报告 | 支持，输出排名表、柱状图、指标矩阵、差异列表，不使用雷达图 |
| 商业力评估 | 不支持 | 支持，输出商业能力横向对比、评分 / 排名、关键指标差异、商业短板 | 支持，输出排名表、柱状图、指标矩阵、差异列表，不使用雷达图 |
| 综合竞争力评估 | 支持，输出综合竞争力得分、维度雷达、短板提示、指标明细 | 支持，输出双企雷达、维度差异、竞争短板 | 支持，输出排名表、指标矩阵、差异分析，不使用雷达图 |

技术力评估和商业力评估不做单企业评估页，进入条件至少选择 2 家企业。综合竞争力评估支持单企业和多企业。雷达图只用于综合竞争力单企业、双企综合竞争力对比，以及技术力双企对比；3 家以上统一使用排名表、柱状图、指标矩阵或差异列表。

### 企业评估指标配置

| 配置项 | 规则 |
| --- | --- |
| 默认指标模板 | 每个评估模式提供默认指标模板 |
| 临时调整 | 普通用户可在当前评估任务中临时调整指标和权重 |
| 个人模板 | 普通用户可将指标组合和权重保存为个人指标模板 |
| 全局模板 | OPS / SYS 在维护管理中维护全局默认模板、版本和审批 |
| 生效范围 | 普通用户的临时配置只影响当前任务；个人模板只影响当前用户后续使用 |

系统必须向用户提供默认模板。默认模板来自维护管理中的全局模板；普通用户进入评估时默认加载对应评估模式和行业 / 产业口径下的全局默认模板。用户可直接使用，也可临时调整或另存为个人模板，但不能修改全局模板。OPS / SYS 在维护管理中维护全局模板，包括指标组合、默认权重、适用行业 / 产业、版本、生效状态和审批。

### 企业评估权限边界

企业评估权限按动作和字段双层控制：页面可见不等于字段可见，能生成评估不等于能导出全部数据，能导出报告不等于能导出底层明细。

| 动作 | 权限口径 |
| --- | --- |
| 进入企业评估页 | GOV / INNO / THINK 可进入；VISIT 不进入或只读；OPS / SYS 不作为常规业务评估用户 |
| 生成评估结果 | GOV / INNO / THINK 可生成；VISIT 不可生成 |
| 临时调整指标和权重 | GOV / INNO / THINK 可在当前任务中临时调整 |
| 保存个人模板 | GOV / INNO / THINK 可保存为个人模板；VISIT 不保存 |
| 修改全局模板 | 仅 OPS / SYS 在维护管理中维护 |
| 查看敏感指标 | 按字段权限控制，不随企业评估页面权限自动开放 |
| 生成企业评估报告 | GOV / INNO / THINK 可按权限生成 |
| 导出含敏感字段报告 | 受字段权限、导出模板、审批和脱敏规则控制 |
| 查看他人评估任务历史 | 本期不支持 |
| 团队共享评估任务 | 本期不支持 |

| 角色 | 企业评估处理 |
| --- | --- |
| GOV 政府驾驶舱 | 可生成评估、导出报告；敏感字段按权限和模板控制 |
| INNO 创新工作台 | 可生成评估、临时调权、保存个人模板、导出企业评估报告；敏感字段范围更收敛 |
| THINK 研判工作台 | 权限最完整，可生成全部企业评估产物；敏感字段仍按字段权限和导出模板控制 |
| VISIT 访客只读 | 不生成评估、不保存模板、不导出 |
| OPS 运营后台 | 维护全局模板、字段、模型参数、数据批次，不作为业务评估用户 |
| SYS 系统后台 | 系统配置、权限、审计，不作为常规业务评估用户 |

评估任务历史和个人模板默认仅本人可见。本期不做团队共享、任务协作审批或跨用户查看评估任务历史。敏感字段在结果页、报告和导出中都必须按字段权限控制。

### 企业评估模型与权重规则

| 模型 | 指标 / 权重对象 | 配置规则 | 生成约束 |
| --- | --- | --- | --- |
| 技术力模型 | 技术指标库中的指标 | 用户可从专利数量 / 引用、研发人员占比、核心技术覆盖度等技术指标库中灵活组合指标并赋权 | 权重合计必须等于 100%；正式技术力评估结果仍要求至少 2 家企业 |
| 商业力模型 | 商业指标库中的指标 | 用户可从年营收、利润率、客户集中度、品牌声量等商业指标中选择，并按行业特性调整默认指标组合和权重 | 权重合计必须等于 100%；正式商业力评估结果仍要求至少 2 家企业 |
| 综合竞争力模型 | 综合维度权重 + 维度内部指标权重 | 综合竞争力整合技术力、商业力等维度，采用两层权重：综合维度权重，以及各启用维度内部指标权重 | 综合层权重必须等于 100%；每个启用维度内部指标权重也必须等于 100%；支持单企业和多企业 |

技术力和商业力都有独立指标库，用户可选指标、赋权。商业力默认模板受行业 / 产业领域影响。综合竞争力不是简单再造一套独立指标，而是整合技术力、商业力等维度，并在综合层配置维度权重。普通用户调整只影响当前任务或个人模板；全局默认模板归维护管理。技术力 / 商业力配置过程中可以实时计算得分预览，但正式结果生成仍按企业数量规则校验。

### 企业评估指标选择与权重配置交互

评估任务配置页中的指标配置区域采用 `模板选择 -> 指标分组表格 -> 已选指标与权重 -> 得分预览` 的顺序组织，不使用字段树。指标配置服务于当前评估任务，不替代维护管理中的全局模板维护。

| 配置环节 | 交互规则 |
| --- | --- |
| 模板选择 | 默认加载系统默认模板；可切换个人模板或临时自定义。技术力按产业 / 技术方向优先匹配默认模板，商业力按行业 / 产业领域优先匹配默认模板，综合竞争力加载综合默认模板及维度权重 |
| 指标分组表格 | 表格字段包括勾选、指标名称、指标分组、数据状态、当前权重、数据来源、指标说明入口 |
| 指标选择 | 至少选择 1 个指标；未勾选指标权重置空或禁用；已勾选指标可编辑权重 |
| 权重编辑 | 使用数字输入框，不使用滑杆；本期只支持整数权重；输入范围 0-100 |
| 总权重提示 | 显示总权重进度，例如 `当前 85% / 100%` 或 `当前 112% / 100%`；低于 100% 提示补齐，高于 100% 提示降低，等于 100% 才允许生成 |
| 快捷操作 | 支持 `一键均分`，将已选指标平均分配到 100%；不做自动归一化，不在用户修改单个权重时自动改动其它指标 |
| 缺失指标 | 缺失指标可勾选，但必须展示缺失 / 部分缺失状态，并提示会影响评分可信度 |
| 得分预览 | 技术力 / 商业力显示已选企业预估得分列表；综合竞争力显示综合得分和维度得分预览。预览仅用于配置校验，最终结果以生成后的评估结果为准 |

综合竞争力采用两层配置：第一层为综合维度权重，第二层为维度内指标权重。综合维度可包括技术力、商业力、组织与成长、产业链位置、风险稳健性等；点击某个启用维度后，通过折叠面板配置该维度内部指标。页面不同时铺开所有维度内部指标。未启用维度不参与综合层权重；启用维度的内部指标权重必须等于 100%。

生成按钮只有在企业数量满足当前评估模式、至少选择 1 个指标、综合层及启用维度内部所有权重均等于 100%、数据缺失未触发禁止生成规则时可用。

### 企业评估任务流程

| 步骤 | 规则 |
| --- | --- |
| 进入评估 | 来源包括企业查询、企业总览、对比篮、企业画像；进入时携带企业对象。没有企业对象时，也允许在企业评估页内添加企业 |
| 选择评估模式 | 在 `技术力评估 / 商业力评估 / 综合竞争力评估` 三种模式中选择 |
| 确认企业对象 | 展示已选企业，支持增删，并按当前评估模式校验企业数量 |
| 选择指标模板 | 支持默认模板、个人模板和临时自定义 |
| 调整指标权重 | 普通用户只影响当前任务或个人模板，不修改全局模板 |
| 生成评估结果 | 校验企业数量、指标完整性和权重配置后生成结果 |

企业评估页默认不直接出结果，先进入评估任务配置。对比篮、企业查询、企业总览和企业画像只负责带入企业对象，不替企业评估生成任务结果。

评估结果生成后自动形成轻量评估任务记录。评估任务历史用于恢复最近任务、关联报告导出记录和支撑同指纹报告生成判断；配置未生成结果不进入正式历史。个人模板、评估任务历史和报告导出记录分开管理，但通过评估任务 ID、评估任务指纹和报告导出记录互相关联。

### 企业评估原需求子功能归属

| 评估模式 | 原需求一级能力 | 子功能归属 |
| --- | --- | --- |
| 技术力评估 | 企业技术力评估对比分析 | `技术力模型构建与参数自定义` 负责指标库、指标组合和权重；`多企业技术力对比分析` 负责技术力得分、双企雷达、排名表和差距分析报告 |
| 商业力评估 | 企业商业力评估对比分析 | `商业力模型配置与指标选择` 负责商业指标选择、行业特性调整和权重；`商业竞争力对标分析` 负责商业力评分、排名和可视化对比图 |
| 综合竞争力评估 | 企业竞争力分析 | `综合评估框架与指标库` 负责多维度、多指标框架；`个性化竞争力评价与输出` 负责综合竞争力得分、雷达图、排名和短板提示 |

`商业竞争力对标分析` 是 `企业商业力评估对比分析` 的结果分析子功能，不作为第四种评估模式或独立二级菜单。

原需求功能到结果模块的映射必须在企业原型中落位展示，并以当前模块 TRACE 的验收叶子与 `md_ref` 作为来源锚点。页面对应模块标题或结果区标题旁可使用统一 `TraceInfoIcon` 浮层展示源文档位置、原始标题、原文摘要、本轮解释和状态；不再新建页面私有需求编号。企业模块在本轮解释中额外说明该结果模块承接的原需求一级能力、子功能和当前页面结果模块。浮层只在演示模式 / 内部评审模式显示，不在页面主体展示解释性大段文案。该规则适用于企业评估，也适用于后续风险洞察、引育推荐等企业分析页面。

### 企业评估输出结果

| 评估模式 | 结果输出 |

### 企业评估结果页结构

| 区域 | 内容 |

| 技术力对比报告 / 技术力差距分析报告 | 技术力得分、技术排名、双企雷达、指标差异、技术短板、差距分析 | 不做单企业技术力报告 |

| 综合竞争力评估报告 | 综合竞争力得分、维度雷达、排名、短板提示、指标明细 | 不输出招引 / 培育推荐结论 |

导出规则：本期默认导出 PDF，Word 作为后续增强；导出记录进入个人资产中心；导出必须带水印、审计和追溯编号。企业评估报告不混入风险洞察结论和引育推荐结论；如涉及综合建议，只能是评估短板提示，不输出招商 / 培育推荐结论。

报告生成可能涉及后台评分计算、图表渲染和报告文件生成，耗时可能较长。前端必须提供报告生成进度反馈，不能让页面卡住或只显示静态 loading。进度条可采用前端模拟步骤 + 后台状态轮询组合，向用户展示系统正在做什么。

| 生成阶段 | 前端提示 |
| --- | --- |
| 任务提交 | 已提交报告生成任务，正在校验企业对象、指标模板和权限 |
| 数据准备 | 正在读取企业指标、数据批次、追溯信息和字段权限 |
| 评分计算 | 正在计算评分、排名、差距、短板和评分可信度 |
| 图表生成 | 正在生成雷达图、排名表、指标矩阵和可视化对比图 |
| 报告装配 | 正在装配报告目录、数据质量说明、审计信息和水印 |
| 生成完成 | 报告已生成，可下载；同步写入个人资产中心报告导出记录 |

如果生成时间超过预期，应提示用户任务仍在后台执行，可稍后在个人资产中心查看导出记录和下载状态。失败时展示失败原因、可重试入口和审计记录状态。

报告生成以后台任务记录和评估任务指纹为准，不依赖前端本地缓存。评估任务指纹至少包含企业对象集合、企业对象顺序（当排序影响结果时）、评估模式、指标模板 ID / 模板版本、指标组合、权重配置、区域 / 产业 / 时间口径、数据批次、数据权限视角 / 当前角色和结果版本。只要指纹不变，视为同一个评估报告任务。

用户离开页面后再次进入，若评估配置未变化，点击 `生成报告` 时先查询后台是否存在同指纹报告任务：

| 同指纹任务状态 | 再次点击生成报告的处理 |
| --- | --- |
| 正在生成 | 不重新生成；展示 `查看生成进度`，并提供进入个人资产中心查看任务的入口 |
| 已生成且未过期 | 不默认重新生成；主按钮为 `下载已有报告`，次按钮为 `重新生成`，辅助入口为 `查看导出记录` |
| 生成失败 | 主按钮为 `重试生成`，次按钮为 `查看失败原因` |
| 已过期 | 提示已有报告已过期，默认建议重新生成 |
| 不存在 | 创建新的报告生成任务 |

分析结果页和报告文件需要区分：分析结果页可基于当前评估配置恢复或重新展示；PDF / Word 报告文件是后台生成任务。用户可手动选择重新生成，但系统默认避免重复生成。

### 企业评估状态规则

| 状态 | 处理 |
| --- | --- |
| 企业数量不足 | 当前评估模式置灰，或生成按钮置灰并提示所需企业数量 |
| 数据缺失 / 低可信 | 指标显示数据状态；缺失指标不记 0 分，不参与该企业该项得分计算，按剩余可用指标重算，并降低评分可信度 |
| 权重不等于 100% | 不允许生成评估结果；低于 100% 提示补齐权重，高于 100% 提示降低权重 |
| 使用默认模板 | 可直接生成 |
| 临时调整指标 | 生成前提示仅本次评估任务有效 |

### 企业评估数据缺失与评分可信度规则

| 指标数据状态 | 含义 | 处理 |
| --- | --- | --- |
| 正常 | 当前评估对象均有可用数据 | 正常参与计算 |
| 部分缺失 | 多企业评估中，部分企业缺该指标 | 可选并参与有数据企业计算；提示会影响企业间可比性 |
| 缺失 | 当前评估对象均无可用数据 | 默认不建议选择；如强制选择，生成前二次确认；关键指标全部缺失时禁止生成 |
| 过期 | 有数据，但超过数据有效期 | 可选，但结果页和报告必须标注 |
| 低可信 | 数据来源可信度不足或口径不稳定 | 可选，但结果页和报告必须标注 |

缺失指标不记 0 分，避免把“没有数据”误判为“表现差”。缺失指标不参与该企业该项得分计算，系统按剩余可用指标重算，同时降低评分可信度。报告中必须列出被剔除的缺失指标和影响范围。

评分可信度按可用指标权重覆盖率和关键指标缺失情况分级：

| 可信度 | 规则 |
| --- | --- |
| 高 | 可用指标权重覆盖率 >= 90%，且无关键指标缺失 |
| 中 | 可用指标权重覆盖率 70%-89%，或存在少量关键指标缺失 |
| 低 | 可用指标权重覆盖率 50%-69%，或存在多个关键指标缺失 |
| 不可生成 | 可用指标权重覆盖率 < 50%，或关键指标全部缺失 |

多企业对比时，每家企业独立计算评分可信度。排名表必须在得分旁展示可信度标签；如果企业之间指标覆盖差异过大，排名旁提示 `可比性受限`。双企雷达中，某企业缺失的维度点标记为缺失，不用 0 填充。差距分析只分析双方都有数据的指标；一方缺失的指标进入 `数据缺口` 说明，不作为能力短板判断。

结果页展示要求：核心结论区在得分旁显示可信度标签；指标明细展示每个指标的数据状态；差距 / 短板分析区分 `能力短板` 和 `数据缺口`；报告输出必须包含数据缺失清单、重算规则和可信度说明。

生成按钮规则：权重不等于 100%、企业数量不足、未选择指标、可用指标权重覆盖率 < 50%、关键指标全部缺失时禁止生成。存在低可信、过期或部分缺失指标时允许生成，但结果页和报告必须标注。

企业评估不承担对象暂存，不嵌入对比篮，不输出招商 / 培育推荐结论，不输出风险洞察结论；风险相关指标可以作为评估因子引用，但风险分析归 `风险洞察`。

### 企业评估与对比篮关系

对比篮只传递企业对象和上下文，不做评估条件校验。企业评估接收对象后，由企业评估校验具体任务条件：只选择 1 家企业时，只能进入综合竞争力评估，技术力评估和商业力评估置灰或提示“至少选择 2 家企业”；选择 2 家企业时，三种评估模式均可进入；选择 3 家以上时，技术力 / 商业力 / 综合竞争力均使用排名表、指标矩阵和差异列表，不展示雷达图。对象数量不满足时，在企业评估页提示用户调整对象选择。

## 对比篮规格

`对比篮` 定位为企业分析对象暂存区，不承载任何对比分析或轻量对比。UI 菜单和页面标题仍显示为 `对比篮`，页面主体不放解释性文案；真实定位写入产品文档、需求说明或标题旁 `i` 浮层。

`i` 浮层建议文案：用于暂存企业对象，并将选中企业带入企业评估、风险洞察，或加入招引 / 培育候选名单。对比篮本身不展示对比分析结果。

对比篮不做雷达图、排名表、指标矩阵、技术力 / 商业力 / 竞争力展示、企业差距分析或轻量对比。两家企业雷达图、多企业排名、指标矩阵和差距分析均归入 `企业评估` 或其它目标分析模块；目标模块负责校验所需企业数量和分析条件。

### 对比篮容量与恢复

| 规则 | 口径 |
| --- | --- |
| 暂存容量 | 默认最多暂存 50 家企业 |
| 超限处理 | 单个加入超限时提示 `对比篮已满，请移除部分企业后再加入` |
| 批量加入超限 | 按当前列表顺序加入剩余容量内的前 N 个企业，并提示未加入数量 |
| 保存范围 | 本期支持单用户单篮可恢复 |
| 恢复规则 | 用户刷新页面或重新进入模块时，可恢复最近一次对比篮对象集合 |
| 不做能力 | 不做多套命名篮、团队共享篮、收藏夹 |

### 对比篮字段最小集

加入对比篮时，企业对象至少携带；页面只展示对象识别、筛选、来源和管理字段，不展示评估结果：

| 字段 | 用途 |
| --- | --- |
| 选择框 | 批量选择进入后续分析模块 |
| 企业 ID / 统一社会信用代码 | 对象唯一识别 |
| 企业名称 | 展示 |
| 地区 | 对象筛选和带入后续分析 |
| 产业领域 | 对象筛选和带入后续分析 |
| 企业类型 | 类型筛选 |
| 风险等级 | 对象筛选和带入风险洞察 |
| 引育标签 | 对象筛选和带入引育推荐 |
| 加入来源 | 标记来自企业查询、企业总览、企业画像、引育推荐等入口 |
| 最近操作时间 | 排序、恢复和审计 |
| 数据更新时间 | 结果可信度 |
| 操作 | 查看画像 / 详情、移除 |

对比篮操作包括：查看画像 / 详情、勾选、移除、清空、带选中企业进入 `企业评估`、`风险洞察`，以及将选中企业批量加入 `招引候选` 或 `培育候选`。跳转类动作只传递企业对象和上下文；加入名单类动作只写入候选名单，不在对比篮内生成分析结果。

### 对比篮与引育名单边界

对比篮可作为企业对象分发入口，支持将选中企业批量加入招引候选或培育候选名单，但不在对比篮内进行引育推荐分析。

| 能力 | 对比篮处理 |
| --- | --- |
| 加入招引候选 | 保留；将选中企业加入招引候选名单，已在名单中的企业不重复加入 |
| 加入培育候选 | 保留；将选中企业加入培育候选名单，已在名单中的企业不重复加入 |
| 查看引育名单 | 可提供入口，跳转 `引育推荐` 下的候选名单视图 |
| 推荐理由 / 价值分析 | 不在对比篮生成，归 `引育推荐` |
| 一企一策建议 | 不在对比篮生成，归 `引育推荐` |
| 引育名单导出 | 不在对比篮导出；如启用可选导出，也只在 `引育推荐` 结果页处理 |

未选择企业时点击 `加入招引候选` 或 `加入培育候选`，提示 `请先选择企业`。批量加入后不自动跳转，提示 `已加入 X 家，Y 家已在名单中`，并可提供 `查看引育名单` 的轻提示入口。

### 对比篮页面交互规则

| 交互项 | 确认口径 |
| --- | --- |
| 批量工具栏 | 顺序为 `已选 X 家 / 进入企业评估 / 进入风险洞察 / 加入招引候选 / 加入培育候选 / 清空选择` |
| 引育名单入口 | `查看引育名单` 放在页面右上角固定入口，不放入批量工具栏 |
| 引育加入提示 | 批量加入招引 / 培育候选后提示 `已加入 X 家，Y 家已在名单中`，并提供 `查看引育名单` 轻提示动作 |
| 默认排序 | 按最近操作时间倒序，最新加入或更新的企业在前 |
| 本期筛选 / 搜索 | 仅提供企业名称 / 统一社会信用代码搜索、加入来源筛选、企业类型筛选、清空筛选 |
| 不做筛选 | 地区、产业领域、风险等级、引育标签等复杂筛选回到企业查询或目标模块处理 |
| 清空对比篮 | 需要二次确认 |
| 单个移除 | 不需要二次确认；可给撤销提示作为增强 |

### 对比篮去重与全局状态

对比篮是企业对象的全局暂存状态。企业一旦加入对比篮，在企业查询、企业总览、企业画像、引育推荐等所有出现该企业的入口中，都必须同步显示已加入状态。

| 规则 | 口径 |
| --- | --- |
| 唯一键 | 以 `企业 ID / 统一社会信用代码` 去重 |
| 未加入状态 | 按钮显示 `加入对比篮` |
| 已加入状态 | 按钮显示 `已加入` |
| 再次点击 | 点击 `已加入` 执行取消加入，从对比篮移除 |
| 重复加入 | 不新增重复记录；来自新入口时可追加加入来源并更新最近操作时间 |
| 来源记录 | 支持记录多个来源，例如企业查询、企业总览、企业画像、引育推荐 |
| 单企业提示 | 加入成功提示 `已加入对比篮`；取消成功提示 `已从对比篮移除` |
| 批量加入 | 只加入未加入企业；已加入企业不重复加入；提示 `已加入 X 家，Y 家已在对比篮` |

批量取消只在对比篮页面内提供，不在查询结果或总览列表中提供批量取消，避免跨页面误删暂存对象。

## 风险洞察规格

`风险洞察` 承接 `REQ-ENT-008 企业供应链关系分析` 和 `REQ-ENT-009 企业发展痛难点分析`。它不是无对象风险态势看板，不做高风险企业推荐列表，不做企业评估式评分 / 排名，不做完整一企一策，也不生成供应链报告。

风险洞察以企业对象为主语。供应链是围绕企业展开的关系网络，不作为一级分析对象；产业 / 行业只作为痛难点诊断上下文、行业数据基准和最佳实践匹配依据。

### 页面结构与对象来源

风险洞察采用 `对象选择 / 对象确认 -> 分析切换` 结构。分析区内可切换 `供应链关系分析` 和 `发展痛难点分析`，但切换必须基于同一对象上下文。

无对象进入风险洞察时，只展示对象选择空状态：

| 入口 | 规则 |
| --- | --- |
| 搜索企业 | 选择单个企业后进入对象确认 |
| 从对比篮选择 | 读取当前用户对比篮对象 |
| 最近分析对象 | 恢复最近使用过的企业对象 |
| 历史诊断任务恢复 | 恢复个人历史诊断任务对象和结果 |

无对象状态不展示风险总览、高风险排行、风险趋势、系统推荐对象、待诊断企业推荐或风险关注企业榜。

外部带入对象时进入对象确认状态，不重复做风险总览：

| 来源 | 带入对象 | 规则 |
| --- | --- | --- |
| 企业画像 / 企业详情 | 1 家企业 | 可直接进入单企业供应链图谱或单企业痛难点诊断 |
| 对比篮 | 选中的企业集合 | 供应链最多选择 1-2 家；痛难点可进入集合共性诊断 |
| 重点企业分析内下钻结果页态 | 用户勾选的企业集合 | 记录来源分析区和下钻条件 |
| 企业查询结果 | 用户勾选的企业集合 | 记录对象集合来源 |
| 最近分析对象 | 最近使用企业或企业集合 | 用于快速恢复分析上下文 |

### 分析对象口径

| 场景 | 口径 |
| --- | --- |
| 单企业供应链 | 默认模式，进入完整供应链图谱、多级下钻、关键节点识别和断链风险识别 |
| 两企业供应链 | 轻量对比模式，仅查看共同供应商、共同客户、合作伙伴重叠、关键节点差异和断链风险线索 |
| 3 家及以上集合 | 不生成供应链图谱；必须先缩小到 1-2 家 |
| 单企业痛难点 | 输出完整问题诊断和改进建议 |
| 企业集合痛难点 | 输出共性痛点聚合，不逐家生成完整诊断报告 |

供应链图谱不得设计 3 家及以上多企业对比。企业集合在供应链分析中只是候选池；在痛难点诊断中可作为共性诊断对象。

### 供应链关系分析

供应链关系分析承接 `REQ-ENT-008`，围绕目标企业展示供应商、客户和合作伙伴关系，支持多级下钻、关键节点识别和断链风险识别。

| 项 | 规格 |
| --- | --- |
| 图谱模式 | 单企业使用中心辐射图谱；两企业使用双中心对比图谱 |
| 关系类型 | 只保留供应商、客户、合作伙伴 |
| 下钻深度 | 默认展示 1 级关系，最多支持 3 级下钻 |
| 关键节点 | 核心供应商为必做；关键客户 / 关键合作伙伴作为辅助标注 |
| 断链风险 | 仅包含单点依赖、节点异常、路径脆弱三类 |
| 结果结构 | 供应链图谱、关键节点列表、断链风险列表 |
| 备份方案 | 仅在关键节点风险或断链风险处提示 `建议制定备份方案` |

供应链关系分析不做供应链总评分、供应链排行榜、替代供应商推荐、备选名单、替代路径、备份方案生成或供应链报告导出。

#### 单企业图谱

单企业图谱以目标企业为中心：

- 供应商作为上游关系；
- 客户作为下游关系；
- 合作伙伴作为横向协作关系；
- 默认展示一级关系，节点可逐层展开到二级、三级；
- 图谱可参考外部 `企业分析 - 企业图谱` 的画布、节点详情面板、层级控制、路径发现和候选对象加入图谱交互，参考链接：http://111.198.38.90:50100/#/entan。

外部图谱只作为交互参考，不复用其 `企业 -> 产业 / 科研机构 / 人才 / 服务机构 / 企业` 关系类型、全局概览、模拟新增企业入库、大规模多企业入图谱或技术能力评估上下文。

#### 两企业对比图谱

两企业对比图谱采用双中心布局：

- 企业 A / 企业 B 分别作为两个中心节点；
- 共同节点居中展示并高亮标识，分别连接两家中心企业；
- 差异节点按 `A 独有 / B 独有` 分区展示；
- 图谱边使用不同中心企业颜色区分来源；
- 节点仍按供应商、客户、合作伙伴标识类型；
- 列表侧提供共同节点、A 独有节点、B 独有节点筛选与定位。

不做两企业混合大图，不支持 3 家及以上图谱对比。

#### 节点与边信息

| 元素 | 展示内容 |
| --- | --- |
| 节点摘要 | 企业名称、节点类型、风险 / 关键标记 |
| 节点浮层 | 统一社会信用代码、地区、企业类型 / 产业领域、关系类型、层级、数据来源、查看画像、展开下一级、加入对比篮 |
| 边信息 | 关系类型、关系层级、数据来源 |

边不展示强 / 中 / 弱、关系分数、交易金额强度、依赖度评分、合作紧密度或自定义权重。

#### 关键节点与断链风险联动

关键节点列表字段包括企业名称、节点类型、关系类型、层级、中心性说明、风险标记、数据来源和操作。列表与图谱双向联动：

- 点击列表行，高亮对应图谱节点；
- 点击 `定位图谱`，视图移动到节点；
- 点击图谱关键节点，右侧列表定位到对应行；
- 支持查看画像和展开关系。

断链风险列表字段包括风险类型、涉及节点、涉及路径、风险说明、数据来源和 `建议制定备份方案` 提示。列表与图谱联动：

- 单点依赖风险高亮核心依赖节点；
- 节点异常风险高亮异常节点；
- 路径脆弱风险高亮相关路径；
- 不提供风险处置流转、替代供应商推荐或备份方案入口。

#### 图谱控制

图谱只提供轻量筛选和层级控制：

- 关系类型筛选：供应商 / 客户 / 合作伙伴；
- 层级筛选：1 级 / 2 级 / 3 级；
- 只看风险节点；
- 只看关键节点；
- 重置视图；
- 数据来源和更新时间说明。

不做高级图谱查询语言、算法权重配置、关系强度配置或复杂图谱分析模型。

### 企业发展痛难点分析

企业发展痛难点分析承接 `REQ-ENT-009`。它基于专家知识库、行业数据和企业特征进行多维问题匹配，不是企业评估评分模型，也不输出综合竞争力排名。

`专家知识库` 指问题分类、诊断规则、成因解释、行业最佳实践、解决方案模板和典型案例等结构化知识资产，不是专家列表，也不作为前台主界面暴露。

`智能痛难点诊断模型` 指基于企业特征、行业数据和专家知识库的多维问题匹配模型。模型围绕技术研发、市场拓展、融资、管理四类维度，自动匹配企业特征识别发展障碍，并支撑问题描述、成因分析、行业最佳实践和解决方案生成。

| 项 | 规格 |
| --- | --- |
| 主语 | 企业 / 企业集合 |
| 产业 / 行业 | 只作为诊断上下文、行业数据基准和最佳实践匹配依据 |
| 诊断维度 | 技术研发、市场拓展、融资、管理 |
| 诊断依据 | 专家知识库、行业数据、企业特征 |
| 展示规则 | 展示命中依据和来源摘要，不暴露完整模型规则 |
| 结果结构 | 维度 -> 问题 -> 成因 -> 行业最佳实践 -> 解决方案 |
| 建议边界 | 输出解决方向和服务建议；不生成完整一企一策、不做政策匹配、不做服务派单 |
| 数据不足 | 提示即可，不设置复杂可信度评分 |

痛难点诊断不得以目标产业为主入口，不做产业痛点统计页，不使用 `深圳企业与行业最佳` 雷达图，不输出综合评分或排名。

#### 单企业诊断

单企业痛难点诊断页面按 `对象摘要 -> 诊断维度总览 -> 分维度问题清单 -> 问题详情展开 -> 报告入口` 组织。

| 区块 | 规格 |
| --- | --- |
| 对象摘要 | 企业名称、统一社会信用代码、所属产业 / 行业、企业类型 / 规模、所在地区、诊断时间、数据来源摘要 |
| 诊断维度总览 | 四个维度卡片；展示命中问题数、`高 / 中 / 低` 严重度标签和数据状态 |
| 分维度问题清单 | 按技术研发、市场拓展、融资、管理分组展示问题标题、问题描述摘要、命中依据摘要、严重度标签和数据来源 |
| 问题详情 | 问题描述、命中依据、成因分析、行业最佳实践、解决方案 / 改进建议、数据来源说明 |
| 报告入口 | 诊断结果生成后显示 `生成企业发展痛难点分析建议报告`；已生成时显示下载 / 重新生成状态 |

维度总览不展示维度分数、雷达图、综合得分、排名或行业最佳对比图。

#### 企业集合共性诊断

企业集合共性诊断页面按 `集合摘要 -> 共性痛点分布 -> 共性问题清单 -> 典型企业入口 -> 集合报告入口` 组织，不逐家展开完整诊断。

| 区块 | 规格 |
| --- | --- |
| 集合摘要 | 企业数量、对象来源、来源条件、所属产业 / 行业分布摘要、数据批次 |
| 共性痛点分布 | 按四个维度展示命中企业数、占比和主要问题 |
| 共性问题清单 | 问题标题、涉及企业数量 / 占比、典型企业、共性成因、行业最佳实践、共性解决方向 |
| 典型企业入口 | 点击典型企业进入单企业诊断或企业画像 |
| 集合报告入口 | 生成集合共性 `企业发展痛难点分析建议报告`，不逐家生成完整报告 |

严重度采用 `高 / 中 / 低` 轻量标签，仅用于阅读优先级和排序，不作为企业评分、不参与综合排名。数据不足提示放在维度卡片和问题详情中；维度卡片可显示 `数据不足，暂不判断`，问题详情说明缺失数据。

### 报告口径

风险洞察中只有 `企业发展痛难点分析建议报告` 这个正式报告产物。供应链关系分析不提供报告导出，也不作为关联背景摘要附入痛难点报告。

| 项 | 规格 |
| --- | --- |
| 报告对象 | 单企业报告、企业集合共性报告 |
| 集合报告边界 | 不逐家生成完整诊断 |
| 报告结构 | 基本信息、核心诊断结论、分维度问题诊断、问题描述、命中依据、成因分析、行业最佳实践、解决方案、追溯与数据说明 |
| 生成方式 | 后台任务生成，进入个人资产中心报告记录 |
| 任务阶段 | 任务提交、数据准备、诊断结果装配、报告生成、生成完成 |
| 任务指纹 | 分析对象或对象集合、诊断维度、数据批次、诊断结果版本、报告模板版本 |
| 格式 | 默认 PDF，Word 作为后续增强 |
| 权限 | 受报告导出权限、字段分级、脱敏、水印、审计控制 |

报告不包含供应链图谱、关键节点列表、断链风险摘要、备份方案提示、替代供应商名单、企业评估分数、一企一策、政策匹配、服务派单或报告编辑器能力。

同指纹报告未过期时优先下载已有报告；生成失败可重试；过期或诊断结果变更后重新生成。

供应链图谱可见不等于节点详情和风险证据全量可见。节点详情、舆情 / 异常证据、敏感关系来源按字段权限和脱敏控制。

本期轻量保存个人历史诊断任务和最近分析对象，用于恢复对象、查看最近分析和关联报告；不做团队共享、协作审批或多版本详细对比。

页面必须处理以下状态：

| 状态 | 提示 |
| --- | --- |

| 派生交互 | 不单独挂编号 | 对象选择、装篮、查看画像、图谱筛选、层级控制、定位图谱、两企业切换 / 对比模式、最近分析对象、历史任务恢复、报告下载 / 重新生成、个人资产中心入口 |

追溯标识普通业务模式隐藏，演示 / 内部评审模式显示。报告只挂 `REQ-ENT-009`，不混入供应链追溯。

## 企业未细化页面追溯映射基线

以下映射用于补齐已确认 IA 中尚未深入细化的企业页面，作为后续继续讨论和 UE / frontend-agent 派单的追溯基线；具体模块布局、图表形态和交互细节仍需在对应页面深化时确认。

### 引育推荐

`引育推荐` 承接 `REQ-ENT-006 招引企业推荐分析` 和 `REQ-ENT-007 培育企业推荐分析`，用于智能生成招商育商名单，并为产业链招商、梯度培育和一企一策服务提供数据支撑。

`引育推荐` 下拆为 `招引推荐` 和 `培育推荐` 两个独立视图。两者共享候选管理、生成任务和追溯浮层框架，但不共用对象池、不混用推荐结论。

#### 原需求溯源

| 原需求编号 | 原始能力 | 子功能 | 本轮承接 |
| --- | --- | --- | --- |
| `REQ-ENT-006` | 招引企业推荐分析 | 高潜力企业智能挖掘、招引名单与价值分析 | 面向全国企业库，基于深圳产业发展方向筛选高成长性、关键技术型、隐形冠军或专精特新目标企业，生成招引推荐名单及依据 |
| `REQ-ENT-007` | 培育企业推荐分析 | 本地潜力企业识别模型、培育建议清单生成 | 面向深圳市内企业，识别具备潜力但面临发展瓶颈的优质企业，生成建议培育名单、所需支持和一企一策建议摘要 |

#### 招引推荐

`招引推荐` 面向全国企业库，服务于深圳招商引入。它不写死排除深圳企业，但核心是发现适合深圳招引、落地、补链强链的目标企业。

`招引推荐` 不是静态名单页，应提供业务规则型推荐模型配置。本期不做复杂算法建模平台，不支持普通用户任意新增指标公式。

招引推荐生成链路：

1. 选择深圳重点产业方向、技术领域或产业链环节。
2. 配置目标企业所在地 / 来源区域、企业特征、最低匹配度和指标权重。
3. 系统从全国企业库筛选并形成 `招引候选名单`。
4. 经过推荐规则分析后生成 `招引推荐名单`。
5. 展示推荐依据、核心优势、关键指标和合作价值，支撑招商对接。

招引推荐主维度固定为：

| 主维度 | 说明 |
| --- | --- |
| 技术匹配度 | 判断企业关键技术、技术标签、专利能力、产业链环节与深圳重点产业方向的匹配程度 |
| 成长性 | 判断企业营收增长、融资、规模扩张、市场表现等成长潜力 |
| 区域适配性 | 判断企业与深圳产业布局、招商方向、链主企业需求和落地条件的适配程度 |

`高成长性`、`关键技术型`、`隐形冠军`、`专精特新` 作为筛选标签或加分因子进入推荐依据，不只作为普通企业类型下拉项。

#### 培育推荐

`培育推荐` 面向深圳本地企业库，服务于本地企业梯度培育和精准扶持。它识别具备潜力但面临发展瓶颈、需要政策或服务支持的本地企业。

`培育推荐` 同样不是手工名单维护页，应提供业务规则型本地潜力企业识别配置。本期不做复杂算法建模平台，不支持普通用户任意新增指标公式。

培育推荐生成链路：

1. 选择深圳产业方向、深圳辖区 / 园区 / 企业范围、企业阶段或企业类型。
2. 配置潜力识别条件、最低潜力阈值、支持类型和指标权重。
3. 系统扫描深圳本地企业库并形成 `培育候选名单`。
4. 经过潜力识别和支持需求分析后生成 `建议培育名单`。
5. 展示所需支持和一企一策建议摘要，辅助工作人员后续制定具体扶持方案。

培育推荐主维度固定为：

| 主维度 | 说明 |
| --- | --- |
| 技术壁垒 | 判断企业技术门槛、知识产权、研发能力和产品差异化 |
| 市场增速 | 判断企业市场增长、订单 / 营收趋势、融资或扩张表现 |
| 团队背景 | 判断核心团队、人才结构、管理能力和成长支撑条件 |
| 所需支持识别 | 识别企业在技术研发、市场拓展、融资、管理提升、政策匹配、资源对接等方面的支持需求 |

`一企一策` 在本需求中来自 `培育建议清单生成`，不是独立大功能，也不是自动生成完整方案。`一企` 指具体到单个深圳本地培育企业；`一策` 指针对该企业的差异化培育支持建议。本模块只提供制定一企一策的依据和建议摘要，不生成完整政策包、服务派单或正式一企一策报告，也不替代 `风险洞察` 的痛难点诊断报告。

#### 候选名单与结果名单边界

`候选名单` 是对象池，`结果名单` 是分析结果。页面不使用一个泛化的 `推荐名单` 概念，而按业务视图区分：

| 视图 | 候选对象 | 分析后结果 |
| --- | --- | --- |
| 招引推荐 | 招引候选名单 | 招引推荐名单 |
| 培育推荐 | 培育候选名单 | 建议培育名单 |

候选来源包括系统模型扫描和跨模块带入。企业查询、企业总览、企业画像、对比篮等外部入口只能把企业加入候选名单，不能直接生成招引推荐名单或建议培育名单。风险洞察可将企业带入 `培育候选名单`，但仅作为需进一步培育分析的来源，不因存在风险或痛点自动成为建议培育对象。

#### 视图内筛选与模型配置

`引育推荐` 不设置跨 `招引推荐 / 培育推荐` 的顶部通用筛选。筛选和模型配置全部下沉到各视图内部，由两个视图分别定义对象范围、时间周期、产业方向、区域口径和指标权重。

模块顶部只保留公共操作，例如 `招引推荐 / 培育推荐` 视图切换、生成任务记录 / 历史生成和必要的追溯入口，不放置会影响名单生成的通用筛选项。

| 视图 | 内部筛选 / 配置 |
| --- | --- |
| 招引推荐 | 深圳重点产业方向、技术领域 / 产业链环节、目标企业所在地 / 来源区域、企业特征、技术匹配度 / 成长性 / 区域适配性权重、最低匹配度 |
| 培育推荐 | 深圳产业方向、深圳辖区 / 园区 / 企业范围、企业阶段 / 企业类型、潜力识别条件、技术壁垒 / 市场增速 / 团队背景权重、所需支持类型 |

指标配置自由度控制为：固定主维度、主维度权重可调、二级指标可勾选、支持推荐场景模板；普通用户不支持完全自定义指标公式。`自定义指标` 如保留，只作为后续增强或管理员配置能力。

#### 推荐依据展示

推荐依据分三层展示：

| 视图 | 列表层 | 详情层 | 追溯层 |
| --- | --- | --- | --- |
| 招引推荐 | 匹配度、推荐理由、核心优势标签、关键指标 | 技术匹配度 / 成长性 / 区域适配性拆解，核心优势、合作价值、招商对接建议 | `REQ-ENT-006`、模型配置、全国企业库筛选条件、权重配置、生成时间 |
| 培育推荐 | 潜力评分、所需支持、建议理由、企业阶段 | 技术壁垒 / 市场增速 / 团队背景拆解，发展瓶颈、所需支持、一企一策建议摘要 | `REQ-ENT-007`、模型配置、深圳本地企业库筛选条件、权重配置、生成时间；可附引用的风险洞察 / 痛难点依据 |

列表层只展示快速筛名单所需的核心依据。详情层解释为什么推荐。追溯层用于内部评审 / 审计，不在页面主体放置大段需求解释。

#### 名单生成进度

`招引推荐名单` 和 `建议培育名单` 都按异步生成任务处理，不假设点击后立即返回完整结果。名单生成复用系统已有通用进度展示规则，不为 `引育推荐` 单独发明一套。

生成流程：

`提交模型配置 -> 创建生成任务 -> 展示进度 -> 分阶段更新状态 -> 生成结果名单 -> 可查看任务记录`

任务阶段包括：

- 任务创建
- 企业库筛选
- 指标计算
- 推荐依据生成
- 名单生成完成

任务状态包括：

- 待开始
- 计算中
- 生成依据中
- 已完成
- 失败
- 已取消

前端展示应支持按钮 loading、页面进度条 / 任务卡片 / 抽屉、后台运行、取消任务、失败重试。失败后保留配置并允许重新生成。完成后进入 `招引推荐名单` 或 `建议培育名单`。历史生成记录可查看当时配置、生成时间、结果数量和状态。

#### 名单输出与导出口径

`REQ-ENT-006 / REQ-ENT-007` 明确要求的是生成 / 输出名单及依据，不等同于文件导出。本轮必做口径是页面结果展示和名单管理。

文件导出不作为两条原需求的必备能力。如系统已有通用导出机制，可作为可选增强承接；不恢复独立 `分析导出` 菜单。

#### 追溯浮层

`引育推荐` 复用统一 `REQ-ENT-xxx` 追溯浮层机制，不单独设计一套。浮层用于解释需求来源、承接子功能、本轮解释、结果落位和生成条件摘要，不承担模型配置或算法解释页面职责。

| 位置 | 追溯编号 | 浮层说明重点 |
| --- | --- | --- |
| 招引推荐视图标题 | `REQ-ENT-006` | 招引企业推荐分析，承接高潜力企业智能挖掘、招引名单与价值分析 |
| 招引推荐名单结果区 | `REQ-ENT-006` | 全国企业库筛选、技术匹配度 / 成长性 / 区域适配性、招引推荐名单及依据 |
| 推荐依据 / 合作价值区块 | `REQ-ENT-006` | 核心优势、关键指标、合作价值，支撑招商对接 |
| 培育推荐视图标题 | `REQ-ENT-007` | 培育企业推荐分析，承接本地潜力企业识别模型、培育建议清单生成 |
| 建议培育名单结果区 | `REQ-ENT-007` | 深圳本地企业识别、技术壁垒 / 市场增速 / 团队背景、建议培育名单 |
| 所需支持 / 一企一策建议摘要区块 | `REQ-ENT-007` | 标注所需支持，辅助用户定制一企一策 |

浮层内容包含追溯编号、原始需求标题、原文摘要、承接子功能、本轮解释、当前结果区落位、对象池、筛选条件、指标维度、权重配置、生成时间和状态。若引用风险洞察 / 痛难点作为培育辅助依据，可在浮层中标注辅助引用，但主追溯仍为 `REQ-ENT-007`。

| 全量导出 | 本期不提供普通业务用户全量导出；即使具备较高权限，也应通过导出模板、审批或额度规则限制范围 |
| 报告类导出 | 企业评估报告、画像摘要、企业发展痛难点分析建议报告以摘要和分析结论为主，不导出底层全量明细数据 |
| 名单类导出 | 引育名单导出仅作为可选增强；如启用，可导出候选或结果企业及推荐理由、建议动作等必要字段，敏感跟进字段需按权限或审批控制 |
| 字段模板 | 导出字段由模板控制，必填字段默认导出，可选字段按权限和模板选择，预留字段不默认导出 |
| 超限处理 | 超出数量上限或敏感字段权限时，导出前提示裁剪范围、脱敏或申请审批，不静默导出 |

### 导出审计与水印

所有正式导出都必须留审计记录并带水印。

| 审计字段 | 说明 |
| --- | --- |
| 导出人 | 当前用户 |
| 角色 | 当前角色/权限视角 |
| 导出时间 | 时间戳 |
| 导出类型 | 查询清单、画像摘要、企业评估报告、企业发展痛难点分析建议报告；如启用引育名单可选导出，则记录招引推荐名单或建议培育名单 |
| 对象数量 | 导出企业数量 |
| 筛选条件 | 当前查询/筛选条件 |
| 字段范围 | 导出的字段模板 |
| 是否含敏感字段 | 如联系方式、财务、风险等 |
| 水印信息 | 用户名、时间、系统标识 |
| 追溯编号 | 关联 `REQ-*` 或导出模板编号 |

### 导出额度与收费

存在产品化需求：可能只可免费导出 1-2 份报告，后续再导出收费。

该能力纳入本期产品化范围，至少需要支撑额度提示、导出记录、收费状态和审计留痕。若项目当前不接入真实支付通道，也应保留订单/支付状态字段，支持后续与完整系统计费能力对接。

| 能力 | 本期处理 |
| --- | --- |
| 免费额度规则 | 支持按用户或机构配置免费导出份数，例如 1-2 份 |
| 超额提示 | 用户超出免费额度时，在导出前提示需付费或需审批 |
| 收费状态 | 导出记录中保留免费、待支付、已支付、审批通过、失败等状态 |
| 审计记录 | 记录导出人、角色、时间、对象范围、字段范围、水印和收费状态 |
| 订单/支付字段 | 本期保留对接字段；真实支付闭环按完整系统能力接入 |
| 发票/财务 | 不作为企业模块页面必做，可在完整系统商业化能力中承接 |

导出记录进入个人资产中心，与查询历史、对比暂存和指标模板统一查看。

## 维护管理

`维护管理` 是企业模块的后台支撑能力，只面向 OPS / SYS 或具备维护权限的用户。它不是业务分析页，也不是普通用户工具页，不进入普通用户主流程。

维护管理负责维护企业分析所需的全局配置、模板、数据批次、权限、脱敏和审计；业务页负责使用配置生成分析结果；个人资产中心负责个人模板、个人任务和个人报告 / 导出记录。

### 职责边界

| 能力 | 业务页 | 个人资产中心 | 维护管理 |
| --- | --- | --- | --- |
| 本次查询 / 分析筛选条件 | 配置并生效 | 可恢复个人方案 | 不负责 |
| 本次生成任务权重调整 | 配置并生效 | 可保存为个人模板 | 不污染全局配置 |
| 推荐 / 评估场景模板选择 | 使用模板 | 可保存个人模板 | 维护全局默认模板 |
| 字段字典 / 指标字典 | 按配置展示 | 不负责 | 维护字段、指标、分级、敏感级别和默认权重 |
| 模型版本 / 规则版本 | 展示当前使用版本 | 记录个人任务使用版本 | 维护全局模板、版本启停和生效范围 |
| 数据批次 | 展示当前批次和质量提示 | 记录个人任务使用批次 | 维护企业模块可用数据批次 |
| 字段权限 / 脱敏规则 | 按权限生效 | 记录个人可见产物 | 维护字段级权限、脱敏和角色规则 |
| 报告 / 导出模板 | 在结果页触发生成或导出 | 查看个人报告 / 导出记录 | 维护模板、字段范围、水印和审计配置 |
| 任务 / 导出审计 | 查看个人状态 | 查看个人记录 | 查看全局审计、异常任务和敏感操作日志 |

### 可见性规则

| 场景 | 维护管理菜单状态 |
| --- | --- |
| OPS / SYS / 有维护权限用户 | 可见且可进入 |
| GOV / INNO / THINK 等普通业务角色 | 正式权限下不可见 |
| VISIT 访客只读 | 不可见 |
| 内部评审 / 演示模式 | 可显示锁态，用于演示权限边界，不开放访问 |

维护管理页面按 6 个内部页签 / 分区组织：

1. `字段指标`
2. `模型规则`
3. `数据批次`
4. `报告导出模板`
5. `权限脱敏`
6. `审计监控`

### 字段指标

`字段指标` 维护企业分析可用字段、字段分级、敏感级别、指标启停和默认权重。它不允许 OPS 随意改变业务口径，不允许在前台直接新增无法映射数据源的字段，不允许删除已被模型、报告或追溯引用的字段；此类字段只能停用或下线，并记录版本和影响范围。

| 对象 | 维护内容 |
| --- | --- |
| 企业字段字典 | 字段名称、字段编码、所属分组、字段分级、敏感级别、使用位置 |
| 指标字典 | 指标名称、指标编码、所属模型、启用 / 停用、默认权重、适用角色 / 适用场景 |

字段分组包括基础识别、产业归属、技术能力、商业能力、供应链、风险痛点、引育推荐等。字段分级沿用 `必填 / 可选 / 预留`；敏感级别至少包含公开、内部、敏感；使用位置覆盖企业查询、企业画像、对比篮、企业评估、风险洞察、引育推荐和导出模板。

### 模型规则

`模型规则` 维护全局默认模型模板和规则版本。业务页中的配置是本次任务参数，普通用户只能选择模板、调整本次任务权重或保存个人模板，不能修改全局模板。

| 模板类型 | 维护内容 |
| --- | --- |
| 企业评估模型模板 | 技术力评估模板、商业力评估模板、综合竞争力模板、默认指标权重、适用企业类型 / 产业方向、模型版本 |
| 引育推荐规则模板 | 招引推荐模板、培育推荐模板、固定主维度、默认权重、默认阈值、推荐场景模板、版本启停 |
| 风险洞察诊断规则版本 | 供应链关系分析规则版本、痛难点诊断规则版本、诊断维度配置、专家知识库版本、规则生效状态 |

已用于历史任务或报告的模板版本不能覆盖修改，只能新建版本。模型版本变更必须记录影响范围，并让业务页展示当前使用的模型 / 规则版本。

### 数据批次

`数据批次` 不负责数据生产本身，只负责让业务页知道当前分析使用哪批企业数据、来源是什么、更新时间是什么、质量状态如何。

| 能力 | 内容 |
| --- | --- |
| 企业库数据批次 | 批次编号、数据来源、覆盖范围、更新时间、生效状态、数据质量状态 |
| 业务页使用批次 | 企业查询、企业总览、企业评估、风险洞察、引育推荐分别使用的批次 |
| 数据质量提示 | 字段缺失率、最近更新时间、不可用字段、数据不足提示、批次异常状态 |

维护管理只记录和切换企业模块可用数据批次，不做完整 ETL 调度平台，不做数据清洗工作台。普通业务用户不能切换全局数据批次。历史分析任务和报告必须保留当时使用的数据批次编号。数据批次过期或异常时，业务页只提示，不自动改变分析口径。

### 报告导出模板

`报告导出模板` 只维护模板，不直接生成业务报告。业务页结果页触发报告或导出，个人资产中心查看个人报告 / 导出记录。模板变更不能影响已生成报告。

| 类型 | 内容 |
| --- | --- |
| 报告模板 | 企业评估报告模板、企业发展痛难点分析建议报告模板、画像摘要模板、模板版本、模板启停、水印规则、适用角色 / 场景 |
| 导出模板 | 查询清单导出模板、可选引育名单导出模板、字段范围、字段顺序、脱敏策略、数量上限、格式 |

不恢复独立 `分析导出` 二级菜单。引育名单导出模板只在启用通用导出增强时出现，不作为 `REQ-ENT-006 / REQ-ENT-007` 的必备能力。

### 权限脱敏

`权限脱敏` 控制谁能看、谁能执行分析、谁能生成报告、谁能导出，以及哪些字段需要脱敏。

| 类型 | 内容 |
| --- | --- |
| 角色可见模块 | GOV / INNO / THINK / VISIT / OPS / SYS 对企业二级菜单的可见性，演示 / 内部评审模式锁态规则 |
| 分析权限 | 是否可执行企业评估、风险洞察、引育推荐生成，是否可查看历史任务 |
| 报告 / 导出权限 | 是否可生成 / 下载报告，是否可导出查询清单，是否可使用可选引育名单导出，数量上限和额度规则 |
| 字段级权限与脱敏 | 联系方式、财务数据、风险证据、供应链敏感关系、对接进度 / 项目跟踪；隐藏、部分遮罩、汇总展示等脱敏方式 |

维护管理不替代完整统一身份认证系统。权限规则由维护管理配置，业务页只按规则生效，不在业务页临时写死角色判断。普通用户不能绕过字段权限查看脱敏字段。报告 / 导出必须继承字段级权限、水印和审计规则。VISIT 只读，不生成正式任务。

### 审计监控

`审计监控` 是 OPS / SYS 查看企业模块运行情况、异常任务和敏感操作的后台能力，不是普通业务用户的个人历史记录。维护管理看全局审计；个人资产中心只看个人任务和个人报告记录。

| 类型 | 内容 |
| --- | --- |
| 分析任务记录 | 企业评估、风险洞察、引育推荐生成任务；任务状态、创建人、创建时间、使用对象 / 对象数量、模型版本、数据批次 |
| 报告 / 导出记录 | 报告生成 / 下载、查询清单导出、可选引育名单导出；水印编号、导出字段范围、对象数量 |
| 异常与失败任务 | 生成失败、数据不足、权限不足、批次异常、模板失效、可重试 / 不可重试原因 |
| 敏感操作日志 | 模板启停、指标权重变更、字段敏感级别变更、权限规则变更、数据批次切换、导出模板变更 |

审计记录不可由普通用户删除。审计只记录关键操作和结果，不展示完整敏感数据内容。本期不做复杂工单审批流，最多保留异常处理备注 / 重试操作。
