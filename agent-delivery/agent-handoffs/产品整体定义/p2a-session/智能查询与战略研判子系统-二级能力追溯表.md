# 科技专题服务系统 · 智能查询与战略研判子系统-二级能力追溯表

## 版本

Draft v0.1

## 追溯基准

源文档：

- `p2a-session/科技专题数据查询与科技专题战略分析-实施方案摘录.md`

已确认产品口径：

- 当前对象是 `科技专题服务系统 · 智能查询与战略研判子系统`，不是完整六大模块的科技专题服务系统。
- 默认主导航采用：专题工作台、智能查询、态势全景、专题研判、决策支持、成果沉淀。
- 专业模式保留：技术链、产业链、企业、科研机构、人才、政策、产业服务链、综合智能分析。
- 企业中心、门户-产业服务、门户-政策扶持不作为一级导航，拆入用户路径并保留追溯来源。
- 对比篮是全系统常驻复层模块，首版企业对象优先接入。
- 企业查询 MVP 首批范围已确认。

实现侧样本：

- `repos/demo-ui-topic`

## 覆盖状态说明

| 状态 | 含义 |
| --- | --- |
| 已覆盖 | 当前路由或页面能明确承接该能力，且功能语义基本一致 |
| 部分覆盖 | 当前有入口、页面或局部能力，但粒度、交互闭环、算法口径或统一规范不足 |
| 规划中 | 已确认为产品口径或首批范围，但当前实现仍需调整或补齐 |
| 缺口 | 当前未见明确承接页面或通用能力 |
| 待确认 | 需要进一步确认数据、算法、业务口径或归属 |

## 五、主要缺口汇总

| 优先级 | 缺口 | 影响 | 建议归属 |
| --- | --- | --- | --- |
| P0 | 缺少统一“智能查询”一级入口和规范 | 数据查询仍分散在企业、产业链、政策等对象域，难以证明完整数据查询底座 | product-agent + UE |
| P0 | 对比篮仍偏企业中心内页 | 已确认应为全系统常驻复层模块，当前实现需要调整系统层级 | UE + frontend-agent |
| P1 | 企业查询 MVP 需按已确认范围固化 | 当前已有企业检索页，但需按“找企业 + 筛候选 + 初步判断信号”重新归位 | product-agent + UE + frontend-agent |
| P1 | 查询结果到推荐图表/自定义图表/图表面板链路缺失 | 文档侧数据智能分析要求尚未满足 | product-agent + UE |
| P1 | 聚合页面需要二级能力说明 | 企业、科研机构、人才、产业服务链等被聚合后，容易误判覆盖 | product-agent |
| P2 | 门户来源需要持续标注 | 门户-产业服务、门户-政策扶持不再作为一级导航，但仍需保留来源追溯 | product-agent |
| P2 | 术语解释和主体详情标准未统一 | 当前画像存在，但术语、字段、详情层级不统一 | UE |

## 六、后续建议

1. 基于本追溯表补一份 `科技专题数据查询统一规范`：
   - 查询入口形态。
   - 对象类型。
   - 结果 schema。
   - 画像/详情标准。
   - 对比篮接入规范。
   - 导出和图表面板链路。

   - 首版查询场景。
   - 列表字段。
   - 高级筛选字段。
   - 对比篮接入。
   - 企业画像与企业对比跳转。
3. 后续再决定是否同步改写 `gap-analysis.md` 和 product-agent 派单。
