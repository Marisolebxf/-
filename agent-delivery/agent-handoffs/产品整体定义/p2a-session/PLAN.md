## Goal

基于《科技专题数据查询与科技专题战略分析-实施方案摘录.md》进行当前阶段产品需求核对，把“科技专题数据查询 + 科技专题战略分析”从完整实施方案中独立出来，并按本轮新边界重拆：本次只交付专业模式下的 `产业链`、`企业`、`政策`、`产业服务链`、`综合智能分析` 五个模块。

`技术链`、`科研机构`、`人才` 不属于本次工作范围，由其它厂商负责；在本轮文档中只保留为排除项和外部对接边界，不进入后续 UE / frontend-agent 派单。

完整《科技专题服务系统-实施方案摘录.md》仍作为上游来源和完整系统差距参照；当前核对、派单和下一步产品确认优先以提取文档为直接依据。

## Non-goals

- 不直接修改科技专题服务系统前端代码。
- 不先做 UI 视觉改版。
- 不把所有原文子功能机械拆成开发任务。
- 不在未确认边界前输出最终 PRD。
- 不把科技专题服务系统与科技信息展示系统混在一个需求口径里。
- 不在本轮直接展开科技信息展示系统需求梳理。
- 不在差距分析阶段修改当前前端实现。
- 不再把项目管理、信息发布、内容运营、系统支撑作为当前核对主范围；这些只保留为完整系统差距背景。
- 不把技术链、科研机构、人才纳入本次交付能力包。
- 不把由其它厂商负责的模块拆成 UE 或 frontend-agent 任务。

## Core Mechanism

采用 Ask_Why 的产品梳理流程：

1. 以提取文档作为当前直接需求基准。
2. 核对“数据查询 + 战略分析”是否足以解释 `demo-ui-topic` 当前前台实现。
3. 将完整实施方案中的其它模块保留为差距背景，不混入当前前台验收范围。
4. 输出 product-agent 后续确认边界。
7. 将确认事项记录到 `DECISIONS.md`，将未决问题记录到 `OPEN_QUESTIONS.md`。
8. 在 P0 和主要 P1 问题收敛后输出 `FINAL_PLAN.md`。

63. 顶部筛选口径确认：`引育推荐` 不设置跨 `招引推荐 / 培育推荐` 的顶部通用筛选；筛选和模型配置全部下沉到各视图内部。模块顶部只保留视图切换、生成任务记录 / 历史生成和必要追溯入口，不放置影响名单生成的通用筛选项。
64. 候选与结果边界确认：候选名单是对象池，结果名单是分析结果。企业查询、企业总览、企业画像、对比篮等外部入口只能加入候选名单，不能直接生成招引推荐名单或建议培育名单；风险洞察只能带入培育候选，不因存在风险或痛点自动成为建议培育对象。
65. 推荐依据展示确认：分为列表层、详情层和追溯层。列表层快速筛名单；详情层展示指标拆解和业务价值；追溯层用于内部评审 / 审计，展示需求编号、模型配置、输入条件、权重配置和生成时间。
66. 导出口径修正：`REQ-ENT-006 / REQ-ENT-007` 明确要求生成 / 输出名单及依据，不等同于文件导出。页面结果展示和名单管理为必做；文件导出仅作为系统通用导出机制下的可选增强，不作为两条原需求必备能力，不恢复独立 `分析导出` 菜单。
67. 一企一策边界确认：`一企一策` 来自培育建议清单生成，不是独立大功能，也不是系统自动生成完整方案。培育推荐只提供制定一企一策的依据和建议摘要，不生成完整政策包、服务派单或正式一企一策报告。
68. 名单生成进度确认：`招引推荐名单` 和 `建议培育名单` 都按异步生成任务处理，复用系统通用进度展示规则。任务阶段为任务创建、企业库筛选、指标计算、推荐依据生成、名单生成完成；支持后台运行、取消、失败重试和历史生成记录。
69. 引育推荐追溯浮层确认：复用统一 `REQ-ENT-xxx` 追溯浮层机制；`招引推荐` 主追溯为 `REQ-ENT-006`，`培育推荐` 主追溯为 `REQ-ENT-007`。浮层展示原需求、承接子功能、本轮解释、结果落位和生成条件摘要，不承担模型配置或算法解释页面职责。
70. 维护管理职责边界确认：业务页负责筛选、调本次参数、生成分析和查看结果；个人资产中心负责个人模板、个人任务和个人报告 / 导出记录；维护管理负责字段、指标、默认模板、模型版本、数据批次、权限、脱敏、报告 / 导出模板和审计等全局支撑。
71. 维护管理范围确认：不做大而全后台，只保留企业模块分析需要的 6 组能力，即字段与指标维护、模型与规则模板、数据批次管理、报告 / 导出模板、权限与脱敏规则、审计与任务监控。页面按 `字段指标 / 模型规则 / 数据批次 / 报告导出模板 / 权限脱敏 / 审计监控` 6 个内部页签或分区组织。
72. 字段指标确认：维护企业字段字典和指标字典，包含字段名称、编码、分组、必填 / 可选 / 预留、敏感级别、使用位置，以及指标名称、编码、所属模型、启用 / 停用、默认权重、适用角色 / 场景。不允许前台新增无法映射数据源的字段，不允许删除已被模型、报告或追溯引用的字段，只能停用或下线，并记录版本和影响范围。
73. 模型规则确认：维护管理中的模型模板是全局默认规则，业务页配置是本次任务参数。企业评估模型模板、引育推荐规则模板、风险洞察诊断规则版本均在维护管理中维护；普通用户不能改全局模板，已用于历史任务 / 报告的模板版本不能覆盖修改，只能新建版本，业务页应显示当前使用版本。
74. 数据批次确认：数据批次管理不负责数据生产，只记录和切换企业模块可用数据批次，展示批次编号、来源、覆盖范围、更新时间、生效状态和质量状态。普通业务用户不能切换全局数据批次；历史分析任务和报告必须保留当时使用的数据批次编号；批次过期或异常时业务页只提示，不自动改口径。
75. 报告导出模板确认：维护管理只管模板，不直接生成业务报告；业务页结果页触发报告或导出，个人资产中心查看个人报告 / 导出记录。报告模板包含企业评估报告、企业发展痛难点分析建议报告、画像摘要等；导出模板包含查询清单和可选引育名单导出模板。引育名单导出模板只在启用通用导出增强时出现。
76. 权限脱敏确认：维护管理配置角色可见模块、分析权限、报告 / 导出权限、字段级权限与脱敏规则；不替代完整统一身份认证系统。业务页只按规则生效，不临时写死角色判断；普通用户不能绕过字段权限查看脱敏字段；报告 / 导出必须继承字段级权限、水印和审计规则。
77. 审计监控确认：维护管理看全局审计，个人资产中心只看个人任务和个人报告记录。审计监控包含分析任务记录、报告 / 导出记录、异常与失败任务、敏感操作日志；审计记录不可由普通用户删除，只记录关键操作和结果，不展示完整敏感数据内容。本期不做复杂工单审批流，最多保留异常处理备注 / 重试操作。
78. 维护管理可见性确认：只面向 OPS / SYS 或具备维护权限的用户；GOV / INNO / THINK 等普通业务角色正式权限下不可见；VISIT 不可见；内部评审 / 演示模式可显示锁态用于说明权限边界，但不开放访问。
79. 一级菜单命名确认：当前实现中的 `技术链分析`、`科研机构`、`人才分析` 保留现状，不进入本轮改造；`企业中心` 在本轮规范化为 `企业分析`；`产业链` 规范化为 `产业链分析`；`门户-产业服务` 归位到 `产业服务链分析`，不再作为本轮一级菜单；`门户-政策扶持` 归位到 `政策分析`，不再作为本轮一级菜单。整理后的一级菜单展示口径为：`技术链分析 / 产业链分析 / 企业分析 / 科研机构 / 人才分析 / 政策分析 / 产业服务链分析 / 综合智能分析`。
80. 企业 IA 重新归位：二级菜单顺序调整为 `企业总览 / 企业查询 / 重点企业分析 / 对比篮 / 企业评估 / 风险洞察 / 引育推荐 / 维护管理`。企业总览承接门户“企业发展”四组需求，页内顺序为 `企业整体概况 / 重点企业概览 / 明星企业介绍 / 深圳企业介绍`；旧混合型企业总览改名为“重点企业分析”，只保留类型与区域、领域覆盖、深圳企业现状三组分析；`E-33` 重点企业产业链全景迁回 `企业总览 → 重点企业概览`。本条覆盖 PLAN 中所有“企业总览五个分析区”的旧口径。
81. 企业任务流补充确认：重点企业分析是专业分析入口，不是企业模块默认主入口；企业总览负责门户内容认知。保持 `企业总览 / 企业查询 / 重点企业分析 / 对比篮` 的既定菜单顺序不变。重点企业分析下钻形成明确企业集合后的结果页，才提供加入对比篮、进入企业评估、进入风险洞察和加入招引 / 培育候选等操作；对比篮负责跨菜单暂存与分发，不前置为重点企业分析默认数据来源。
