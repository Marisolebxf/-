## 一、产品定位

“科技专题服务系统 · 智能查询与战略研判子系统”是完整科技专题服务系统下的一个子系统，负责完成从科技数据发现、结构化理解、智能分析到专题战略研判的核心链路。

它不是完整“科技专题服务系统”本体。完整系统还包含项目管理、信息发布管理、内容运营中心、系统管理中心等模块；这些不进入本文件主范围。

## 二、产品主线

基于提取文档，本子系统的产品主线是：

```text
探查 -> 展示 -> 分析 -> 沉淀/导出 -> 战略研判
```

含义：

| 阶段 | 产品含义 | 对应能力 |
| --- | --- | --- |
| 探查 | 用户通过关键词、语义、结构化条件、图谱关系发现对象 | 综合智能查询 |
| 展示 | 系统把结果组织成列表、图谱、主体详情、术语解释 | 统一结构化结果展示 |
| 分析 | 系统基于结果推荐图表，用户可自定义维度和图表 | 数据智能分析 |
| 沉淀/导出 | 用户将图表组合为面板，保存、复用、导出 | 图表面板管理、查询结果导出 |
| 战略研判 | 围绕技术、产业、企业、机构、人才、政策、服务、协同形成决策判断 | 科技专题战略分析 |

## 四、科技专题数据查询能力结构

### 4.1 数据智能呈现

数据智能呈现负责把多源异构科技数据转化为可理解、可交互、可导出的结构化视图。

| 二级能力 | 三级能力 | 产品要求 |
| --- | --- | --- |
| 综合智能查询 | 关键词与语义融合探查 | 支持自然语言/关键词输入，自动识别实体和上下文，返回跨对象结果 |
| 综合智能查询 | 结构化条件与图谱联动探查 | 支持字段组合、结构化筛选和图谱关系探索 |
| 统一结构化结果展示 | 多模态结果展示与交互 | 支持结构化列表、图谱展示、排序、筛选、批量操作、图谱探索 |
| 统一结构化结果展示 | 专业术语与主体详情呈现 | 支持术语解释，以及产业、技术、企业等主体详情页 |
| 统一结构化结果展示 | 查询结果智能导出 | 支持 Excel/JSON 导出、自定义字段、按类型分表、批量下载 |

### 4.2 数据智能分析

数据智能分析负责把查询结果继续转化为图表、面板和业务洞察。

| 二级能力 | 三级能力 | 产品要求 |
| --- | --- | --- |
| 推荐图表分析 | 人才与科研产出分析视图 | 基于人才结构、科研机构绩效等数据自动推荐饼图、柱状图等视图 |
| 推荐图表分析 | 技术、服务与资讯热度视图 | 基于技术演进、服务机构、资讯内容生成热力图、词云等视图 |
| 自定义图表创建 | 多维数据筛选与组合 | 支持用户从查询结果中选择字段、设置过滤条件、组合分析维度 |
| 自定义图表创建 | 图表类型与坐标配置 | 支持选择图表类型、自定义字段、标签、刻度范围等参数 |
| 图表面板管理 | 多图表集成与模板应用 | 支持把推荐图表和自定义图表组合成分析面板，应用预设模板 |
| 图表面板管理 | 可视化布局与对齐控制 | 支持调整图表位置、大小，提供网格参考线 |
| 图表面板管理 | 面板保存与多格式导出 | 支持面板命名、保存至个人/团队空间，并支持多格式导出 |

### 4.3 数据查询产品判断

数据查询是独立基础能力，但实现时可以嵌入各战略分析子域。

不能把它降级为“搜索框”。它至少包含：

1. 多模式探查。
2. 统一结果展示。
3. 主体详情和术语解释。
4. 查询结果导出。
5. 查询结果上的推荐图表。
6. 自定义图表。
7. 多图表面板沉淀。

## 五、科技专题战略分析能力结构

战略分析是按科技创新对象和决策问题展开的研判矩阵。八个子域全部保留为需求边界；页面实现允许聚合，但必须能追溯到每个子域。

### 5.1 技术链分析

核心问题：技术从哪里来、处于什么阶段、是否具备产业化潜力、转化堵点在哪里。

| 二级能力 | 三级能力 |
| --- | --- |
| 技术链全景图谱 | 技术网络可视化；技术节点深度下钻 |
| 新技术热点发现 | 智能语义热点提取；热点趋势量化分析 |
| 技术产业化潜力识别 | 潜力评估模型计算；多技术潜力对比分析 |
| 技术阶段研判 | 技术阶段自动判定；用户参数自定义研判 |
| 深圳技术发展分析 | 深圳区域数据专项提取；深圳潜力与阶段综合评估 |
| 技术转化瓶颈堵点原因识别 | 技术转化流程可视化；瓶颈自动识别与归因 |

### 5.2 产业链分析

| --- | --- |
| 产业链全景图谱 | 产业链结构可视化；节点深度下钻与动态演进 |
| 产业周期分析 | 周期模型自定义与报告生成；周期趋势模拟预测 |
| 区域产业指数评价 | 评价体系构建与指标配置；多区域多产业对比与结果呈现 |
| 产业关键环节识别 | 全链路环节结构化展示；关键环节智能标注与分析 |
| 产业瓶颈堵点识别 | 多维度瓶颈综合分析；瓶颈智能识别与归因建议 |
| 深圳产业情况分析对比 | 深圳数据专项提取与多维对标；深圳产业化潜力与发展阶段综合判断 |
| 深圳产业发展分析 | 智能建议推荐与发展路径规划 |
| 区域产业竞争力评价 | 多维竞争力指标体系构建；综合竞争力计算与横向排名 |

## 六、文档侧验收口径

在不看当前实现的情况下，本子系统的需求结构应满足：

1. 有一个明确的“科技专题数据查询”底座能力。
2. 数据查询不仅包含搜索，还包含展示、导出、推荐图表、自定义图表和面板沉淀。
3. 战略分析八个子域全量保留。
4. 页面或实现可以聚合，但需求追溯必须能回到八个子域。
5. 不把项目管理、信息发布管理、内容运营中心、系统管理中心纳入当前子系统主范围。

## 七、后续实现对照入口

完成本文件确认后，再进入实现对照。对照时应检查：

1. 当前实现是否承载了数据查询底座能力，还是只有分散搜索框。
2. 当前实现是否覆盖八个战略分析子域。
3. 聚合页面是否能追溯到每个子域和二级能力。
4. 当前系统命名是否误导为完整科技专题服务系统。
5. 需要补的是“子系统能力缺口”，还是“完整系统其它模块缺口”。
