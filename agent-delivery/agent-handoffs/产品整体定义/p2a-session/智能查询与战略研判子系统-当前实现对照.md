# 科技专题服务系统 · 智能查询与战略研判子系统-当前实现对照

## 版本

Draft v0.1

## 对照基准

文档侧基准：

- `p2a-session/智能查询与战略研判子系统-文档侧产品结构.md`

实现侧样本：

- `repos/demo-ui-topic`

本文件只做“文档侧产品结构 vs 当前实现”的对照，不把当前实现反向当作需求源。

## 一、总体判断

当前 `demo-ui-topic` 更接近“科技专题服务系统 · 智能查询与战略研判子系统”的前台分析工作台原型，不应继续被表述为完整“科技专题服务系统”。

| 对照项 | 当前实现判断 | 结论 |
| --- | --- | --- |
| 产品命名 | 左侧品牌仍显示“科技专题服务系统” | 容易误导为完整系统，应改为子系统口径或在产品说明中标注隶属关系 |
| 一级能力 | 侧边栏以专题分析域组织，没有“科技专题数据查询”一级入口 | 战略分析可见，数据查询底座未一级化 |
| 数据查询 | 有通用 SearchScaffold 范式，并落在企业、产业链、政策等检索页 | 有能力雏形，但不是完整“数据智能呈现 + 数据智能分析” |
| 战略分析 | 技术链、产业链、企业、科研机构、人才、政策、产业服务链、综合智能分析均有入口 | 八个子域基本覆盖，但颗粒度和命名与文档侧不完全一致 |
| 图表面板 | 多页面有图表、导出、对比篮、局部自定义指标 | 缺少跨查询结果的推荐图表、自定义图表创建、图表面板保存与模板管理 |

## 二、数据查询能力对照

### 2.1 当前实现证据

当前实现具备通用检索范式：

- `SearchScaffold` 注释明确为通用要素检索装配器，包含检索中枢、高级筛选、结果区、画像抽屉、对比篮。
- `SearchHub` 支持关键字、智能搜索、高级筛选三种模式。
- `ResultToolbar` 支持命中数、视图切换、排序、结果内再筛、对比篮、导出。
- `ResultList` 支持卡片/表格结果、分页、画像查看、对比、收藏、名单、深度分析等行级动作。

已落地的检索页：

| 对象域 | 路由 | 页面文件 | 覆盖情况 |
| --- | --- | --- | --- |
| 企业 | `/development/search` | `src/app/pages/development/SearchPage.tsx` | 三模式检索、结果列表、企业画像、对比篮、导出 |
| 产业链 | `/industry/search` | `src/app/pages/industry/ChainSearchPage.tsx` | 三模式检索、产业链画像跳转、上下文过滤 |
| 政策 | `/policy-portal/search` | `src/app/pages/policy-portal/PolicySearchPage.tsx` | 三模式检索、政策画像、收藏/导出/深度分析 |
| 产业服务门户 | `/industry-portal/search` | `src/app/pages/industry-portal/IndustryPortalSearch.tsx` | 有入口，但未纳入通用 SearchScaffold 证据链 |

### 2.2 文档侧能力覆盖表

| 文档侧能力 | 当前实现状态 | 判断 |
| --- | --- | --- |
| 关键词与语义融合探查 | 企业、产业链、政策已支持关键字/智能模式 | 部分覆盖 |
| 结构化条件与图谱联动探查 | 企业、产业链、政策有高级筛选；图谱联动只在局部分析页体现 | 部分覆盖 |
| 多模态结果展示与交互 | 检索结果支持卡片/表格、排序、再筛、分页；图谱结果未成为统一检索结果形态 | 部分覆盖 |
| 专业术语与主体详情呈现 | 企业画像、产业链画像、政策画像已有；术语解释未见统一能力 | 部分覆盖 |
| 查询结果智能导出 | 有导出按钮和 Mock 任务提示 | 雏形覆盖 |
| 推荐图表分析 | 各分析页有图表，但不是“基于查询结果自动推荐图表” | 缺口 |
| 自定义图表创建 | 局部页面有自定义指标/权重，不是通用图表创建器 | 缺口 |
| 图表面板管理 | 未见多图表面板组合、保存、模板、个人/团队空间 | 缺口 |

### 2.3 数据查询结论

当前实现不能说已经完整实现“科技专题数据查询”。

更准确的口径是：

> 当前实现已经沉淀出可复用的“要素检索工作台范式”，并在企业、产业链、政策等对象域部分落地；但尚未形成文档要求的统一“科技专题数据查询”底座，尤其缺少查询结果驱动的推荐图表、自定义图表创建和图表面板管理。

## 四、当前实现的主要偏差

### 4.1 命名偏差

当前系统品牌仍显示“科技专题服务系统”，但当前实现未覆盖项目管理、信息发布管理、内容运营中心、系统管理中心。

建议产品口径改为：

> 科技专题服务系统 · 智能查询与战略研判子系统

如果 UI 暂不改名，也应在产品文档和验收说明中明确“当前实现为子系统/前台分析工作台，不代表完整系统”。

### 4.2 数据查询偏差

当前实现把查询分散在对象域内：

- 企业检索。
- 产业链检索。
- 政策检索。
- 产业链门户检索。

这符合“入口可分散”的阶段性口径，但还缺一个统一规范层：

- 统一对象类型清单。
- 统一查询结果 schema。
- 统一画像/详情标准。
- 统一导出字段与格式标准。
- 统一检索到图表/面板的流转。

### 4.3 图表面板偏差

文档侧把“图表面板管理”放在数据智能分析下，要求多图表集成、模板、布局、保存、个人/团队空间、多格式导出。

当前实现更多是：

- 分析页内置图表。
- 局部自定义指标。
- 局部导出按钮。
- 对比篮。

因此不能等同于图表面板管理。

### 4.4 IA 偏差

当前左侧导航混合了三类东西：

1. 文档侧战略分析子域：技术链、产业链、科研机构、人才、政策、产业服务链、综合智能分析。
2. 当前实现重组域：企业中心。
3. 门户前台入口：门户-产业服务、门户-政策扶持。

这个 IA 可以作为前台工作台组织方式，但不能直接当作文档侧产品结构。

## 五、优先级差距清单

| 优先级 | 差距 | 说明 | 建议归属 |
| --- | --- | --- | --- |
| P0 | 系统口径误导 | 当前实现以“科技专题服务系统”呈现，但实际是子系统/前台分析工作台 | product-agent |
| P0 | 数据查询一级底座缺失 | 没有独立“科技专题数据查询”结构和统一规范，只是对象域检索分散存在 | product-agent + UE |
| P1 | 查询到图表/面板链路缺失 | 推荐图表、自定义图表、面板保存/模板/导出未形成通用能力 | product-agent + UE |
| P1 | 企业中心与企业分析映射不清 | 当前 IA 重组合理但需要追溯表，否则会偏离文档侧“企业分析” | product-agent |
| P1 | 科研/人才/服务链能力聚合后追溯不足 | 导航层聚合后，二级能力是否覆盖不清 | product-agent |
| P2 | 门户层归属需说明 | 门户-产业服务、门户-政策扶持是前台入口还是战略分析下的扩展 IA，需要标注 | product-agent |
| P2 | 术语解释未统一 | 画像和说明有局部能力，但未见统一术语解释服务 | UE 后续细化 |

## 六、下一步建议

1. 先确认当前实现口径：
   - 按“智能查询与战略研判子系统/前台分析工作台”验收。
   - 不按完整“科技专题服务系统”验收。
2. 生成二级能力追溯表：
   - 文档侧每个二级能力对应到当前路由、页面、聚合模块或缺口。
3. 单独补一份“科技专题数据查询统一规范”：
   - 不一定先做统一入口，但要统一对象、结果、画像、导出、图表面板链路。
4. 再决定是否更新旧的 `gap-analysis.md` 和 `product-agent-handoff.md`。
