## 产品定位

科技专题服务系统以“数据查询 -> 专题分析 -> 项目管理 -> 信息发布 -> 内容运营 -> 系统支撑”为主线，面向科技治理和产业研究场景，提供从数据发现、专题研判、项目过程管理到成果发布和运营支撑的一体化服务。

从源文档看，系统不是单一分析看板，而是一个覆盖前台分析工作台、成果分发、后台内容维护、用户协同和系统管理的综合产品。当前实现 `demo-ui-topic` 更偏前台专题分析和门户展示，后台与项目管理闭环覆盖不足。

## 业务闭环

1. 数据查询：用户从关键词、语义、条件筛选或图谱关系进入，定位产业、技术、企业、人才、政策等对象。
2. 专题分析：系统围绕对象进入技术链、产业链、企业、科研机构、人才、政策、服务链和区域创新分析。
3. 项目管理：将研判结果转入具体科技专题项目，跟踪项目进展、资源和风险。
4. 信息发布：将分析结果沉淀为图表、面板、报告、资讯或推送内容。
5. 内容运营：运营侧维护数据、知识、图谱、可视化模板和门户内容。
6. 系统支撑：平台提供账户、权限、消息、工单、任务和历史关注等协同能力。

## 当前实现概况

当前 `repos/demo-ui-topic` 的前台导航和路由主要覆盖：

| 当前导航/路由域 | 对应能力域 | 说明 |
| --- | --- | --- |
| 技术链分析 | 专题分析 | 技术链全景、热点、潜力、阶段、深圳、瓶颈 |
| 产业链 / 门户-产业服务 | 专题分析 + 数据查询 | 产业图谱、周期、评价、检索、门户展示 |
| 企业中心 | 专题分析 + 数据查询 | 企业总览、检索、画像、洞察、决策、引育 |
| 科研机构 | 专题分析 | 科研机构概况、能力、合作、支持、引育 |
| 人才分析 | 专题分析 | 空间布局、综合评价、关系链、供需、引育 |
| 政策分析 / 门户-政策扶持 | 专题分析 + 数据查询 + 信息发布局部 | 政策时序、对比、深圳现状、政策门户、检索 |
| 产业服务链分析 | 专题分析 | 服务链分析、机构研判、引培决策 |
| 综合智能分析 | 专题分析 | 区域创新活力、要素、协同 |

当前未形成独立前台入口或完整闭环的能力：

| 能力 | 当前判断 |
| --- | --- |
| 科技专题数据查询总入口 | 分散在企业检索、产业链检索、政策检索等局部入口中，缺统一查询入口 |
| 项目驾驶舱 / 项目跟踪 / 项目内容 / 项目资源 | 未在主导航和路由中发现明确实现 |
| 编辑工具 / 推送配置 | 未在主导航和路由中发现明确实现 |
| 内容运营中心 | 仅在企业 IA 文档中作为后台侧被提及，前台不承载 |
| 系统管理中心 | 权限/用户等级有前端模拟，但账户、消息、工单、任务、历史关注未形成完整系统管理模块 |

## 下一步产品判断

product-agent 需要优先确认：

1. `demo-ui-topic` 是否仅作为前台专题分析沙箱，还是要代表科技专题服务系统完整产品。
2. “数据查询”是否需要统一总入口，还是允许按企业/产业/政策等专题分散承载。
3. “信息发布管理”应补成独立前台闭环，还是先用导出/分享/报告按钮弱覆盖。
4. “项目管理”是否属于当前科技专题服务前台 P1 能力，还是另起项目管理子系统。
5. “内容运营中心”和“系统管理中心”是否只作为后台支撑域进入后续产品任务。
