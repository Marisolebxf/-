# 需求追溯标号规范

## 版本

Draft v0.1

## 适用范围

本规范只服务于本轮五模块 IA/追溯标注和原型演示核对。

源文档基准：

- `p2a-session/科技专题数据查询与科技专题战略分析-实施方案摘录-去除技术链科研机构人才.md`
- 门户·企业发展来源的既有验收编号 `E-31~E-37` 作为补充追溯来源；其中 `E-33` 重点企业全景图在企业总览继续承接，不重新编号为 `REQ-ENT-xxx`

## 标号规则

| 前缀 | 模块/能力域 | 示例 |
| --- | --- | --- |
| `REQ-DQ` | 科技专题数据查询通用能力 | `REQ-DQ-001` |
| `REQ-IC` | 产业链 | `REQ-IC-001` |
| `REQ-ENT` | 企业 | `REQ-ENT-001` |
| `REQ-POL` | 政策 | `REQ-POL-001` |
| `REQ-SVC` | 产业服务链 | `REQ-SVC-001` |
| `REQ-CIA` | 综合智能分析 | `REQ-CIA-001` |
| `E` | 门户·企业发展既有验收编号 | `E-33` |

编号一旦进入原型或任务派单，不因菜单重命名而变化。`E-31~E-37` 与 `REQ-ENT-xxx` 属于不同来源，不做互相替换；同一页面可按分析区分别挂接来源编号。若需求被摘出或改由其它厂商负责，编号保留，但状态改为 `外部负责` 或 `本期不实现`。

## 原型展示方式

建议在原型中把追溯标号渲染为能力标题旁的 `i` icon。该能力只在演示模式 / 内部评审模式显示，不作为业务角色，不改变任何业务权限。

`i` icon 浮层建议展示：

| 字段 | 说明 |
| --- | --- |
| 追溯编号 | 如 `REQ-ENT-006` 或 `E-33` |
| 源文档位置 | 文件名 + 行号范围 |
| 原始标题 | 源文档中的章节标题 |
| 原文摘要 | 默认展示，用于汇报快速核对 |
| 完整原文 | 二级展开或查看入口，不默认铺开 |
| 本轮解释 | 是否完整落地、只做 IA/追溯、数据支持、外部负责 |
| 状态 | `本期深化`、`本期标注`、`通用保留`、`本期不实现`、`外部负责` |

后期正式开发时可统一去除：

- UI 层：隐藏 `TraceInfoIcon` 或关闭 `showRequirementTrace` / `reviewMode` 开关。
- 数据层：保留 `traceId` 字段用于 QA 和验收，也可以在生产构建中剔除浮层原文。
- 文档层：继续保留追溯编号，便于变更评审和验收回溯。

## 后续开发移除策略

| 层级 | 建议处理 |
| --- | --- |
| 原型演示 | 默认显示 `i` icon，可点击/悬停查看追溯原文 |
| 开发联调 | 保留 `traceId` 和 `sourceLine`，便于验收核对 |
| 正式上线 | 通过配置关闭浮层；如需瘦身，可在构建阶段剔除 `sourceExcerpt` |
| 需求变更 | 新增需求追加新编号；废弃需求不复用编号，只改状态 |
