# 科技专题服务系统 · 智能查询与战略研判子系统-实验口径确认

## 版本

Draft v0.2

## 一、实验口径定义

本轮实验口径用于判断 `repos/demo-ui-topic` 作为原型/样机，是否能够验证“科技专题服务系统 · 智能查询与战略研判子系统”的核心产品方向。

它不是正式项目验收口径，也不是完整科技专题服务系统验收口径。

实验口径只回答三个问题：

1. 当前实现是否能证明“智能查询 + 战略研判”这条产品主线成立。
2. 当前实现是否能作为后续产品、UE、前端继续深化的基础。
3. 当前实现还缺哪些关键能力，不能被误判为已经完整实现。

## 二、实验对象

实验对象：

- `repos/demo-ui-topic`

实验边界：

- 只验证“科技专题数据查询”和“科技专题战略分析”相关能力。
- 不验证项目管理、信息发布管理、内容运营中心、系统管理中心。
- 不把当前左侧导航当作文档侧产品结构。
- 不把 Mock 数据、占位页面、局部按钮等同于正式能力完成。

## 三、实验名称口径

### 3.1 页面原型展示名称

页面原型中的可见系统名称保持：

> 科技专题服务系统

该名称不要求在当前页面原型中修改。原因是原型已按该名称设计、展示和演示，直接修改页面名称可能影响既有演示语境。

### 3.2 文档和验收说明名称

文档、汇报材料、实验结论、差距分析、product-agent 派单中应注明：

> 科技专题服务系统 · 智能查询与战略研判子系统原型实验

可接受简称：

> 智能查询与战略研判子系统原型

### 3.3 标注规则

当必须引用页面原型中的名称时，可以写：

> 页面原型展示名为“科技专题服务系统”，但本轮实验实际验证对象为“科技专题服务系统 · 智能查询与战略研判子系统原型实验”。

不应写成：

> 当前原型已完成科技专题服务系统。

原因：

当前实验样机不覆盖完整科技专题服务系统六大模块。页面展示名称可以保留完整系统名，但文档口径必须注明真实实验边界，否则后续差距判断会失真。

## 四、实验目标

| 实验目标 | 判断问题 | 当前状态 |
| --- | --- | --- |
| 验证前台分析工作台是否成立 | 用户是否能围绕专题对象进行查询、浏览、分析和研判 | 可验证 |
| 验证战略分析八个子域是否可组织成产品前台 | 八个子域是否都有入口或聚合入口 | 可验证 |
| 验证通用要素检索范式是否可复用 | 企业、产业链、政策是否可复用同一检索壳 | 可验证 |
| 验证“查询 -> 画像 -> 分析”链路 | 检索结果是否能进入主体画像或分析动作 | 部分可验证 |
| 验证“查询 -> 图表 -> 面板沉淀”链路 | 查询结果是否能生成推荐图表、自定义图表和面板 | 不可验证 |

## 五、实验通过标准

### 5.1 可判定为实验通过的内容

以下内容可以按“实验已验证”记录：

| 能力 | 通过标准 | 当前依据 |
| --- | --- | --- |
| 子系统定位 | 能证明当前样机是完整系统下的查询与研判子系统 | 已形成子系统命名和产品结构 |
| 战略分析入口 | 八个战略分析子域均有导航入口或聚合入口 | 当前实现已有技术链、产业链、企业中心、科研机构、人才、政策、产业服务链、综合智能分析 |
| 技术链分析 | 文档侧 6 项能力均有显式页面入口 | `/techchain/*` |
| 产业链分析 | 全景、周期、区域评价、关键环节、瓶颈、深圳分析等核心入口已存在 | `/industry/*` |
| 综合智能分析 | 区域创新活力、要素、协同三项与文档侧一致 | `/intelligence/*` |
| 通用检索范式 | 至少两个以上对象域复用检索壳 | 企业、产业链、政策已复用或对标 `SearchScaffold` |
| 结果交互 | 支持结果列表、排序、再筛、画像、对比、导出等实验动作 | `SearchScaffold`、`ResultToolbar`、`ResultList` |

### 5.2 只能判定为部分通过的内容

以下内容不能算完整实现，只能算“实验方向成立”：

| 能力 | 当前表现 | 实验结论 |
| --- | --- | --- |
| 科技专题数据查询 | 企业、产业链、政策等对象域存在分散检索页 | 验证了范式，不代表统一查询底座完成 |
| 企业分析 | 被重组为企业中心 | 验证了前台 IA，但需回映到文档侧企业分析能力 |
| 科研机构分析 | 多项能力被聚合成概况、全景、合作、支持、引育 | 验证了页面组织方向，需补二级追溯 |
| 人才分析 | 文档侧 11 项能力聚合为 5 个页面 | 验证了聚合方向，覆盖深度待确认 |
| 产业服务链分析 | 3 个分析页 + 门户入口承载 | 验证了聚合方向，二级能力待追溯 |
| 政策分析 | 分为专题分析层和政策扶持门户层 | 验证了前台入口，但需标注 IA 扩展 |

### 5.3 不能判定为通过的内容

以下内容不能在实验结论中写成“已实现”：

| 能力 | 原因 |
| --- | --- |
| 完整科技专题服务系统 | 当前不覆盖六大模块，只覆盖子系统范围 |
| 科技专题数据查询一级模块 | 当前没有统一一级入口和统一查询规范 |
| 推荐图表分析 | 当前主要是分析页内置图表，不是查询结果自动推荐图表 |
| 自定义图表创建 | 当前局部有自定义指标/权重，不是通用图表创建器 |
| 图表面板管理 | 未见多图表组合、布局、模板、保存、个人/团队空间 |
| 统一术语解释能力 | 当前没有统一术语解释/知识解释服务 |
| 正式数据接入与算法准确性 | 当前多处仍是 Mock 或原型数据，不能证明真实数据和算法闭环 |

## 六、实验结论模板

建议后续对外或对内汇报时使用以下口径：

> 页面原型展示名为“科技专题服务系统”。本轮实验实际验证对象为“科技专题服务系统 · 智能查询与战略研判子系统原型实验”。当前样机已验证该子系统的前台工作台方向：战略分析八个子域具备入口级覆盖，企业、产业链、政策等对象域已沉淀通用检索工作台范式，可支持从检索、结果、画像到分析动作的基本链路。当前样机尚不能作为完整科技专题服务系统验收，也不能证明“科技专题数据查询”底座已经完整实现；推荐图表、自定义图表、图表面板管理、统一查询规范和二级能力追溯仍需后续补齐。
