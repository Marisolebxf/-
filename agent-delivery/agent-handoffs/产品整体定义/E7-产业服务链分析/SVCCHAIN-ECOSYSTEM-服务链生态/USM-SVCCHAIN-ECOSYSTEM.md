# USM-SVCCHAIN-ECOSYSTEM｜服务链生态（产业服务链 · 链路维度）

> **版本**：v1.0-r2
> **状态**：与 IA、Wireframe、UX-SPEC、TRACE 同步（AI 起草，待体验 Owner 确认）
> **原始需求**：展示 Bid `1.1.1.2.4.2.7.4`（服务链短板分析）、`.7.5`（服务链图谱分析）、`.7.8`（深圳服务链现状分析），共 6 个三级项
> **registry**：TOPIC-SVCCHAIN-R2  
> **本轮决策（Q068 · P7）**：产业上下文 = 15 个产业集群，与门户/政策同一份。任务 `CHAIN-INDUSTRY-CLUSTER-SUPP-L01`。分析侧 `field-*` 不换。

## 1. 模块结果

围绕一个产业领域上下文，完成"看清链条结构（全链路可视化）→ 定位断链弱链（瓶颈堵点识别）→ 洞察生态网络（图谱构建与探索统计）→ 评估深圳能级（统一框架横向对比）"的链路维度认知闭环。不做单机构集合的覆盖/趋势/评估（7.1-7.3，R1 机构维度叶子），不做招引/培育名单生成（7.6/7.7，招引培育域叶子）。

### US-SVC-ECO-01｜全链路可视化呈现

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | `REQ-SVC-ECO-CHAIN-VIS`（7.4.1） |
| 产品角色 | `ROLE-SVC-GOV` |
| 依赖 | 无 |
| Frames | `F-SVC-ECO-01`、`F-SVC-ECO-02`、`F-SVC-ECO-05` |
| 业务结果 | 选定产业从研发到市场推广的全周期服务链路图稳定呈现，各环节显示依赖服务类型与在库机构供给，环节可下钻 |

作为政府科技主管人员，我想看到特定产业从研发、中试到产业化的全周期服务链路图，以便理解各环节依赖的服务类型与当前供给格局。

主路径：

1. 进入服务链生态页，上下文条显示当前产业领域（与 R1 叶子共用 field 字典；默认取持久化值）。
2. 链路视图按 6 个环节（研发支持 → 技术转移与知识产权 → 中试与检测 → 孵化育成 → 产业化推广 → 投融资与人才）横向渲染链路卡（专家知识库演示态，🧪）。
3. 每个环节卡显示：环节名、依赖服务类型清单、该产业下在库服务机构数（ⓘ `M_SVC_CHAIN_SEGMENT_ORG_COUNT`）、平均服务深度。
4. click 环节卡打开环节详情面板（Drawer）：服务类型说明 + 环节内机构列表（可开机构画像、可加入对比篮）。
5. 切换产业领域后链路图与所有环节数据重算，环节详情面板若开启则同步刷新。

| 异常 | 系统行为 | 恢复 |
| --- | --- | --- |
| 某环节该产业无在库机构 | 环节卡保留并显示"暂无供给机构"（同时触发 US-02 空白标注），不渲染 0 假数据 | 查看其他环节或切换产业 |
| `segment` URL 参数无法解析 | 不打开详情面板，Message"环节不存在"，清除该参数 | 从链路图重新点击 |
| 图渲染失败 | 链路区局部错误 + 重试，页面壳与上下文保留 | 点击重试 |

验收：

- `AC-US-SVC-ECO-01-01`：链路图 6 环节顺序、名称与专家知识库演示配置一致，每环节显示依赖服务类型 ≥2 项。
- `AC-US-SVC-ECO-01-02`：环节机构数与该产业下按环节归属统计的在库机构严格一致（与环节详情列表数一致）。
- `AC-US-SVC-ECO-01-03`：环节卡可 click/Enter 下钻详情面板，URL 同步 `segment` 参数，直达链接可恢复面板。
- `AC-US-SVC-ECO-01-04`：切换产业领域后链路数据全部重算，不残留上一产业数值；领域选择持久化且与 URL `field` 同步。
- `AC-US-SVC-ECO-01-05`：环节机构数数字旁必有 ⓘ（`M_SVC_CHAIN_SEGMENT_ORG_COUNT`）与 🧪；链路图区带"专家知识库演示态"声明。

不包含：链路知识库的维护编辑；跨产业链路结构对比；服务类型字典管理。

| 属性 | 内容 |

| `requirement_refs` | `REQ-SVC-ECO-BOTTLENECK`（7.4.2） |

| 产品角色 | `ROLE-SVC-GOV` |

| 业务结果 | 链路图上薄弱环节、服务空白、资源瓶颈以高亮/警示标签标注，识别依据逐条可核对；识别算法未定前保持诚实演示态 |

作为政府科技主管人员，我想让系统自动标出链条中的薄弱环节、服务空白区和资源瓶颈，以便制定靶向补链强链措施，同时清楚知道当前判定是演示规则。

主路径：

1. 链路图上按演示态规则标注三类问题：服务空白（该环节无在库机构，红色警示）、薄弱环节（机构数 ≤1，橙色）、资源瓶颈（平均服务深度 < 55 分，橙色）。
2. 识别面板列出每条判定：环节名、问题类型、判定依据（引用具体机构数/深度值，可与链路图核对）。
3. 面板整体带 🧪 与红问号（`M_SVC_CHAIN_BOTTLENECK` D1 missing，⚠️ Q-SVCCHAIN-03）；业务模式保留"演示规则判定"用户可读声明。
4. click 判定行定位/高亮对应环节卡，并可直接打开该环节详情。

| 异常 | 系统行为 | 恢复 |
| --- | --- | --- |
| 当前产业无任何问题环节 | 识别面板显示"当前演示规则下未发现明显短板"，不硬造问题 | 切换产业 |
| 全部环节均无机构（极端） | 面板提示"该产业服务供给数据不足，暂无法判定"，链路图保留结构 | 切换产业 |

验收：

- `AC-US-SVC-ECO-02-01`：三类判定（空白/薄弱/瓶颈）触发条件与演示规则一致，链路图标注色与识别面板行一一对应。
- `AC-US-SVC-ECO-02-02`：每条判定含依据行且引用数值与链路图当前数据一致。
- `AC-US-SVC-ECO-02-03`：瓶颈判定旁必有红问号（`M_SVC_CHAIN_BOTTLENECK` D1 missing，评审模式点开只显 Q-SVCCHAIN-03 治理引用，不显伪 8 件套）。
- `AC-US-SVC-ECO-02-04`：click 判定行后对应环节卡进入高亮态且滚动入视口。
- `AC-US-SVC-ECO-02-05`：业务模式下不出现 metric_id/Q 编号，保留"演示规则"可读声明。

不包含：专家规则库配置界面；瓶颈成因归因分析；补链措施自动生成。

### US-SVC-ECO-03｜关系网络构建

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | `REQ-SVC-ECO-GRAPH-BUILD`（7.5.1） |
| 产品角色 | `ROLE-SVC-PARK` |
| 依赖 | 无 |
| Frame | `F-SVC-ECO-03` |
| 业务结果 | 以重点服务机构为核心的多元关系网络图稳定呈现，关系类型/节点类型过滤持久化 |

作为园区服务生态运营人员，我想看到以重点服务机构为核心、含企业/高校/资本主体的投资、合作、竞争、人才流动关系网络，以便发现生态结构。

主路径：

1. 图谱视图渲染关系网络：节点 = 服务机构（主体）+ 企业/高校/资本（关联主体），边 = 投资/合作/竞争/人才流动四类关系（确定性演示数据，🧪）。
2. 过滤器支持关系类型多选、节点类型多选；过滤选择持久化，刷新后保留。
3. 节点大小按连接数（度）映射；不同节点类型/关系类型用图例区分（不只靠颜色，图例带文字）。
4. 支持聚焦机构：选定后仅显示其 1 度邻域；清除聚焦恢复全网。

| 异常 | 系统行为 | 恢复 |
| --- | --- | --- |
| 过滤后无任何边 | 图区显示"当前过滤条件下无关系数据"，过滤器保留 | 重置过滤 |
| 图渲染失败 | 图容器局部错误 + 重试 | 点击重试 |
| 持久化过滤数据损坏 | 静默回落默认全选，Message 提示 | 重新过滤 |

验收：

- `AC-US-SVC-ECO-03-01`：四类关系与三类关联主体均在图例中列出且可独立过滤；过滤立即生效。
- `AC-US-SVC-ECO-03-02`：过滤选择刷新后保留（localStorage）；重置按钮恢复全选。
- `AC-US-SVC-ECO-03-03`：聚焦机构后仅渲染其 1 度邻域；清除聚焦恢复全网且过滤器不变。
- `AC-US-SVC-ECO-03-04`：图谱区带 🧪 演示数据声明；关系数据为确定性数据集（刷新后布局种子一致，节点/边数量不变）。

不包含：图谱编辑；二度及以上邻域展开；与 NebulaGraph 真源联通（demo 阶段前端确定性数据，正式实现走 Java REST，见 IA §6）。

### US-SVC-ECO-04｜图谱探索与统计

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | `REQ-SVC-ECO-GRAPH-EXPLORE`（7.5.2） |
| `decision_refs` | `Q-SVCCHAIN-03` |
| 产品角色 | `ROLE-SVC-PARK` |
| 依赖 | US-03 |
| Frames | `F-SVC-ECO-03`、`F-SVC-05`（复用 R1 画像抽屉） |
| 业务结果 | 任意节点可下钻详情；网络密度、中心性统计可解释；影响力评分算法未定前保持诚实态 |

作为园区运营人员，我想在图谱上钻取任意机构节点的详细信息，并量化网络密度、中心性与影响力，以便识别关键枢纽。

主路径：

1. click 服务机构节点：打开机构画像抽屉（复用 R1 `OrgProfileDrawer`，URL `org` 参数同步，CT-SVC-ORG-02）；抽屉内可加入对比篮。
2. click 企业/高校/资本节点：打开侧栏摘要（名称/类型/关联关系清单），明示"非服务机构主体，画像详情不在本模块范围"。
3. 统计面板展示：网络密度（ⓘ `M_SVC_GRAPH_DENSITY`，标准公式）、度中心性 TOP5 机构（ⓘ `M_SVC_GRAPH_CENTRALITY`）、生态影响力评分（红问号 `M_SVC_GRAPH_INFLUENCE` D1 missing）。
4. 统计随过滤条件重算，面板注明"统计范围 = 当前过滤后的可见子网"。

| 异常 | 系统行为 | 恢复 |
| --- | --- | --- |
| `org` 参数指向不存在机构 | 不打开抽屉，Message + 清参数 | 从图谱重选 |
| 过滤后节点 <2 | 密度/中心性显示"子网过小，不计算统计值"，不输出 NaN | 放宽过滤 |

验收：

- `AC-US-SVC-ECO-04-01`：服务机构节点下钻与 R1 各视图打开的是同一抽屉组件、同一 org_id 语义；URL 带 `org` 可直达恢复。
- `AC-US-SVC-ECO-04-02`：网络密度值 = 2E/(N(N-1))（无向去重口径）且与当前可见子网节点/边数一致；hover 显示 N、E 取值。
- `AC-US-SVC-ECO-04-03`：度中心性 TOP5 与图中节点度数一致，机构名可下钻。
- `AC-US-SVC-ECO-04-04`：影响力评分位置显示红问号（D1 missing，只显 Q-SVCCHAIN-03 治理引用），不输出伪评分数值。
- `AC-US-SVC-ECO-04-05`：过滤变化后统计面板同步重算并注明统计范围。

不包含：介数/接近中心性等高阶指标；社区发现；跨模块实体互认跳转。
