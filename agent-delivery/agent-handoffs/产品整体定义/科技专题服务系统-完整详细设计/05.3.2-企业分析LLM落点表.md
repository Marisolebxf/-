判定口径（三档）：

- **规则**：现有模板拼接已满足五件套合同，无需 LLM；或字段是结构化数据（分数/排名/标签），LLM 无增益。
- **LLM**：文案承载「归纳 + 连接」劳动（多条事实 → 一段话），规则写不全或写死即僵硬；按 §05.3.1 §5 契约落地（只改 text、事实包、数字白名单、失败退回草稿不打 failed）。
- **暂缓**：技术上可润色，但被甲方口径（Q0xx）、数据源（K-O7）或产品合同（诚实空态/禁止扩写）卡住；先登记，闭合后再升 LLM。

### 1.2 落点密度说明（为什么「不多」是对的）

全表扫描 20+ 面向用户的文案点位，真落 LLM 收敛为 **2 个收尾函数 + 1 个 P3 复用模式，覆盖 8 个页面位置**：

| 收尾函数 | 覆盖位置 | 梯度 |
| --- | --- | --- |
| `narrate_eval`（一个函数三种事实包） | 技术力诊断尾列（结果页+报告关键发现）、商业力诊断尾列（结果页+报告）、竞争力报告两块 | P0/P1 |
| `narrate_pain` | 痛点共性问题四格 | P2 推荐 |
| 同模式复用 | 招引/培育依据行、培育建议 | P3 可选 |

密度低是**结构性结果**，四个原因：

1. **金样契约本身收敛**：05.6.1 模式 =「规则定卡，模型只改 text」——润色是文案层增强不是能力层新增，天然只落在"归纳性结论文案"位。政策域同样只有 3 个收尾（时序/区域/深圳），体系一致，**少而准是设计哲学**。
2. **企业域数据形态偏结构化**：分数、排名、标签、计数、图谱占绝大多数 UI 位，LLM 无增益；企业域是"算得出数"的域，不像政策域有大片"读文本"的位。
3. **口径锁死密度高**：断链风险（Q017 已闭合 + 8 件套 ⓘ）、风险与信用（白名单短语合同）是「**不能落**」而非「没扫到」——这两处恰恰是口径闭合工作做扎实的结果。
4. **未闭合口径先暂缓**：Q014/Q015/Q016/K-O7 卡着权重、份额、对标、趋势；闭合后 P3/暂缓项自然解锁，落点数量会增长。

扩展路径（按成本排序）：① P3 项随 P0 验收观感升级（同函数复用，最低成本）；② 暂缓项随口径/数据闭合解锁；③ 新增能力类 AI（智能问答、报告自动撰写）**不是润色落点**，须走范围变更（`product_enhancement`，先例：US-ENT-EVAL-ENTITLEMENT）且有甲方需求锚点——不为「AI 感」硬加，塞了违反诚实性铁律。
