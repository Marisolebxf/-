## 1. 这条链路做什么

对企业集合做**综合竞争力三维**评估：创新能力（技术域）、经营能力（商业域）、成长能力（技术×商业合成）。同时给出该企业集合的 `set_average`（集合均值）与 `set_leader`（集合龙头）作为对照系。输入输出与技术力同构；`sub_type=competitiveness`，同一异步六节点 Job。

产品语义（E-30「整合技术力、商业力等维度」「技术+市场+组织」）在现网落为：创新=技术域单维，经营=商业域单维，成长=技术转化与产业链覆盖合成——**as-built 映射，本文只记录**。

## 2. 完整逻辑（共享骨架，本叶差异点标注）

六节点骨架与 05.3.1 §2 逐字相同。本叶差异：

| 节点 | 本叶行为 |
| --- | --- |
| `compute` | **双跑**：`tech_power.run` + `biz_power.run` 各自落 ADS（竞争力不新算指标，只消费两表） |

其余节点与 05.3.1 完全一致。

## 3. 取数与合成（as-built 公式，不改不改判）

`_compute_eval_result` competitiveness 分支，对每家企业取 `tech_power` 行 `t` 与 `biz_power` 行 `b`：

| 合成项 | as-built 公式 |
| --- | --- |
| `innovation_score` 创新能力 | = `t.innovation_score`（技术域直取） |
| `operating_score` 经营能力 | = `b.market_score`（商业域市场维直取） |
| `growth_score` 成长能力 | = round((`t.transfer_score` + `b.chain_coverage_score`) / 2, 2)（技术转化与产业链覆盖率等权平均） |
| `comp_index` 综合分 | = round((创新 + 经营 + 成长) / 3, 2)（三维算术平均） |
| `set_average` | 集合内各维算术平均（每维一行） |
| `set_leader` | 集合内各维最大值 |

数据源：ADS `tech_power` + `biz_power` 双表 `IN` 查询；缺行按空 dict 参与（维度分取 0）。

## 4. 结果组装

信封外层与 05.3.1 同构。`result` 本叶形状：

| 字段 | 内容 | 润色触碰 |
| --- | --- | --- |
| `radar_axes` | `["创新能力","经营能力","成长能力"]` | 否 |
| `radar_series[]` | 每企业一行三维 `values` | 否 |
| `set_average` / `set_leader` | 集合级对照（见 §3） | 否 |
| `ranking[]` | 按 `comp_index` 降序 | 否 |
| `dimension_rows[]` | **每企业 3 行**（每维度一行）：name/code/`total_score`(=comp_index)/`dimension`/`score`/`set_mean`/`set_leader`/`gap_text`（该企业 weaknesses 规则稿，三行共用同一稿） | **是，只改 `gap_text`，按 `(enterprise, code, dimension)` 逐行** |
| `data_quality[]` | `compute_data_quality(codes,"competitiveness")` | 否 |

`summary`：`max_score` / `enterprise_count` / `avg_score` / `high_confidence_count`（按 `comp_index`）。

单企业任务：`set_average` 退化为该企业自身分、`set_leader`=自身分（对照系退化为基线，as-built 行为，前端按 1 家时弱化集合对照展示）。

## 5. 解读润色（as-built：复用 `narrate_eval`，本叶契约 = 05.3.1 §5 换粒度）

### 5.1 位置与边界（本叶）

同 05.3.1 §5.1；本叶只改 `dimension_rows[].gap_text`，**粒度=企业×维度**（三模式中唯一按维度出卡的叶）。

| 不动 | 理由 |
| --- | --- |
| `set_average` / `set_leader` / 雷达 / `ranking` / `comp_index` / `confidence` / `data_quality` | 结构化真源 |
| 结果页两列数字展示 | FE 数字拼接（05.3.2 §1.1 判定保持规则，不消费后端稿） |

### 5.2 事实包（competitiveness 形状）

顶层同 05.3.1 §5.2。本叶差异：

- `drafts[]` 每行带 `dimension` 键（与 `enterprises[]` 的 `dimension/set_mean/set_leader` 对应），卡定位键为 **`(enterprise, code, dimension)` 三元组**——同企业 3 行同名靠 dimension 区分（该设计经审查修正落地）；
- `enterprises[]` 每行含 `dimension` / `set_mean` / `set_leader`（对照系数字进白名单，允许「低于均值 55.5」类表述）；
- 无 `dimension_scores` 雷达明细（三维即行字段，已在 enterprises 行内）。

### 5.3 校验规则与三态

与 05.3.1 §5.3 完全一致（100 字上限 / 数字白名单 / 禁因果 / 三态 / 20s·0 重试·0.1）；差异仅卡协议：cards 必须回填 `dimension`，未命中三元组的卡按 `card{i}` 计拒、漏行按 `missing:N` 如实上报 fallback。

### 5.4 允许写成什么（示例）

规则稿「经营能力(50.0)：对照集合均值补短板」润色后允许：*「经营能力 50 分低于集合均值 55.5，与龙头 85.0 差距明显；优先补市场侧短板。」*——数字全部来自事实包（score/set_mean/set_leader/thresholds），无因果，不越 100 字。

### 5.5 同函数覆盖面与报告接线（as-built）

- 结果页：两列数字为 FE 拼接，**保持规则不消费后端稿**（05.3.2 判定）；
- 报告 v2：✅「维度差距诊断」尾列 +「关键发现」weakLines **已接** `dimensionRows[].gapText`——润色稿落快照即同源，**零 FE 改动**（三模式中唯一）；
- 服务端 ARTIFACT「决策摘要」：暂不另开润色（ENT-NARRATE-04）。
