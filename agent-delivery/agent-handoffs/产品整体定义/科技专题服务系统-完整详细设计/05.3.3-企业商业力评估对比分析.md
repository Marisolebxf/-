## 1. 这条链路做什么

对企业集合（1~50 家）做**商业力六维**评估：市场、产品、品牌、技术合作、产业链覆盖率、产业关键环节参与度。输入企业码集合与可选 `weights`，输出六维指标对比、`biz_power_index` 排名、逐企业诊断（含润色短评）与数据质量快照。

菜单入口「企业商业力评估对比分析」；发起后进入与技术力**同一个**异步六节点 Job（`analysis_type=enterprise_eval`，`sub_type=business`），过程页/结果页/报告与 05.3.1 同构。

## 2. 完整逻辑（共享骨架，本叶差异点标注）

六节点骨架、重叠异步回传、有限重试、取消/超时语义与 05.3.1 §2 **逐字相同，不重复**。本叶差异仅一处：

| 节点 | 本叶行为 |
| --- | --- |
| `compute` | 调 `biz_power.run(enterprise_codes)`：读 ADS `biz_power`，六维 minmax 归一 → `weighted(biz_power_index)` → `diagnose`（≥70 优势 / <45 短板挂 `ADVICE` 固定建议）。ADVICE 是规则模板（Q014 口径绑定，**不在润色范围**，见 §5.1） |

其余节点（submit / validate / data_gather / confidence / assemble）行为与 05.3.1 完全一致。

## 3. 取数与计算

| 项 | as-built |
| --- | --- |
| ADS 表 | `biz_power`（`org_id` 主键，行含六维分、`biz_power_index`、`rank_overall`、advantages/weaknesses/suggestions JSON 文本） |
| 六维 | `market` 市场 / `product` 产品 / `brand` 品牌 / `cooperation` 技术合作 / `chain_coverage` 产业链覆盖率 / `chain_keynode` 产业关键环节参与度 |
| 归一 | minmax 0-100（`evaluation/_util.py`） |
| 综合分 | `biz_power_index`（ADS 行值；`weights` 参数作为展示层权重随信封回显） |
| 诊断 | `diagnose`：维度分 ≥70 记优势、<45 记短板并挂 `ADVICE` 固定建议（六条固定话术，见 `biz_power.py ADVICE`） |
| 缺数 | 指标缺源时该维归一分取 50（中性），ADVICE 如实提示「当前 DWD 无市场份额和营收字段」等（as-built 文案） |

## 4. 结果组装

`_compute_eval_result` business 分支，信封外层与 05.3.1 同构（`task_id` / `analysis_type` / `sub_type` / `meta` / `enterprises` / `summary` / `result` / `weights` / `data_source`）。`result` 本叶形状：

| 字段 | 内容 | 润色触碰 |
| --- | --- | --- |
| `operating_indicators[]` | 每企业一行六维 `indicators{市场,产品,品牌,技术合作,产业链覆盖,关键环节参与}` | 否（结构化） |
| `ranking[]` | 按 `biz_power_index` 降序（name/code/score/rank） | 否 |
| `tabs` | `["operation_diagnosis","revenue_trend","industry_benchmark"]`（标识符） | 否 |
| `diagnosis_rows[]` | 每企业一行：name/code/`total_score`/`confidence`/`diagnosis_text`（= `_join_diagnosis(weaknesses, suggestions)` 规则拼接稿） | **是，只改 `diagnosis_text`** |
| `revenue_trend_available/hint` | `False` /「当前无营收时序数据」（恒定，as-built） | 否 |
| `industry_benchmark_available/hint` | `False` /「暂无对标库数据」（恒定，as-built） | 否 |
| `data_quality[]` | 与 05.3.1 同源（`compute_data_quality(codes,"business")`） | 否 |

`summary`：`max_score` / `enterprise_count` / `avg_score` / `benchmark_avg_score=None` / `benchmark_available=False` / `high_confidence_count`。

## 5. 解读润色（as-built：复用 `narrate_eval`，本叶契约 = 05.3.1 §5 换字段）

**状态：已上线**（`LUMEN-ENT-EVAL-NARRATE-L01`，technology 模式已线上验证 ok；business 分支同函数同批上线，本叶线上抽样待 QA，见 §5.7）。

### 5.1 位置与边界（本叶）

`_compute_eval_result` 之后、`finish_success` 之前，worker 同一执行流内；与 05.3.1 §5.1 逐条相同，本叶只改 `diagnosis_rows[].diagnosis_text`。

| 不动 | 理由 |
| --- | --- |
| `suggestions` / ADVICE 固定话术 | 与 Q014 口径绑定（ENT-NARRATE-02 暂缓，同 05.3.1） |
| 六维 `indicators`、`ranking`、`tabs`、`confidence`、`data_quality`、`benchmark_*`、`revenue_trend_*` | 结构化真源 |
| 营收趋势 / 行业对标空态提示 | 恒定空态，禁 LLM 趋势解读（对齐 05.3.1 趋势暂缓） |

### 5.2 事实包（business 形状）

顶层同 05.3.1 §5.2（`sub_type="business"` / `enterprise_count` / `weights` / `summary` / `drafts` / `thresholds` / `enterprises`）。本叶差异：

- `enterprises[]` 无 `dimension_scores`（技术力五维雷达不适用）——经营六维明细**未进事实包**，模型只见 `score`（综合分）与规则稿（ENT-EVAL-13，见 §8 开放项）；
- `drafts[].gap_text` 键名在 business 语义下承载的是 `diagnosis_text` 规则稿（同函数复用的字段名）；
- `confidence` / `missing_metric_ids` 同源 `data_quality`。

### 5.3 校验规则与三态

与 05.3.1 §5.3 **完全一致**：JSON `cards[{enterprise, code, text}]`、企业名必须在包内、单条 ≤100 字（`TEXT_LIMIT=100`，2026-10-27 放宽）、数字白名单（浮点相等，`missing_metric_ids` 不进白名单）、禁因果句（因为/由于/导致/受…影响）、`narration={ok|fallback|skipped}` 三态、失败退规则稿任务仍 success、`timeout_sec=20 / max_retries=0 / temperature=0.1`、卡定位键 `(enterprise, code)`（无维度键）。

### 5.4 允许写成什么（示例）

规则稿「品牌(40.0)：加强品牌建设与市场影响力，推动资本化提升品牌价值。」润色后允许：*「品牌 40.0 分低于 45 分线，为六维中最弱项；建议沿资本化方向提升品牌影响力，另存在营收数据缺口。」*——数字全部来自事实包，无因果推断，不越 100 字。不允许：*「由于市场份额流失导致品牌下滑」*（因果 + 事实包外归因）。

### 5.5 同函数覆盖面与报告接线（as-built）

- 结果页「诊断结论」：✅ 已消费后端 `diagnosis_text`（`EvalResultWorkspace`）；
- 报告 v2「关键发现」：✅ **已接**（`evalReportDocument.ts` `22e1d57`，ENT-NARRATE-05 路径 A）——`diagnosisKey='diagnosisText'`，`diagnosisByCode` 算法稿进关键发现 bullets，稿缺位（skipped/无键）自然退 FE 规则两句，不伪造文案；
- 服务端 ARTIFACT「决策摘要」：暂不另开润色（ENT-NARRATE-04，同 05.3.1）。
