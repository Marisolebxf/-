# 企业中心规范权威与生命周期

> **生效日期**：2026-07-12
> **目的**：明确企业中心 / 企业整体概况相关文档的使用边界，避免把已完成派单、历史讨论稿或旧路由兼容层当作当前产品规范。

## 1. 当前权威链

| 层级 | 当前权威 | 使用方式 |
| --- | --- | --- |
| 产品范围与业务边界 | `bid-reference/` 原始需求；本轮已跑通模块以 `E-31-企业发展/USM-E-31-企业发展.md` 与 `E-31-企业发展/IA-E31-企业发展.md` 为准 | 定义模块职责、产品角色与验收边界；当前只把 E-32 作为完整样例。 |
| 交互通则 | `UX-UE 通用交互组件规范.md` | 定义导航、Tab、ContextBar、面包屑、状态、键盘和无障碍通则；不固化企业业务口径。 |
| 视觉通则 | `../../Design.md` | 唯一视觉 token、栅格、间距和 Arco / 可视化内核边界来源。 |
| 现行演示 IA 与实现映射 | `repos/demo-ui-topic/docs/ia/enterprise/`、`src/app/pages/enterprise/enterpriseCenterRouteMap.ts`、`src/app/routes.tsx` | 用于核对当前演示入口、一级 Tab、兼容路由和已落地行为；不是原始业务需求的替代品。 |

## 2. 企业中心当前入口口径

| 左侧入口 | 当前主路由 | 说明 |
| --- | --- | --- |
| 企业总览 | `/enterprise-center/overview` | 页内四个一级 Tab：企业整体概况（E-32）、重点企业概览（E-33）、明星企业介绍（E-34）、深圳企业介绍（E-35）。 |
| 企业查询 | `/development/search` | 独立的横向查询能力；不应再回填为企业总览顶部常驻检索。 |
| 重点企业分析 | `/enterprise-center/key-enterprise-analysis` | 当前演示主入口；旧 `type-distribution`、`domain-distribution`、`status-analysis` 仅作兼容映射。 |
| 对比篮 / 企业评估 / 风险洞察 / 引育推荐 / 维护管理 | 对应 `/enterprise-center/*` 路由 | 由各模块需求逐项补齐，不因旧 E-20~E-30 文档而推定其业务边界已确认。 |

> 权限代码的最小级别以 `src/app/perms/matrix.ts` 为实现校验依据；若路由 handle 的展示级别与 matrix 不一致，应登记为待确认，不由文档自行裁决。

## 3. 文档生命周期

| 文件 | 状态 | 处理规则 |
| --- | --- | --- |
| `UX-UE 通用交互组件规范.md` | **现行通则** | 持续维护；企业业务例外须回指产品 IA。 |
| `UI-通用交互组件视觉规范.md` | **现行辅助映射** | 仅解释组件视觉如何落实 `Design.md`；与 `Design.md` 冲突时不自行扩张 token。 |
| `UX-权限交互规范-企业维度.md` | **历史权限讨论基线** | 保留 L0-L4、锁态、血缘等历史证据；其旧 IA、角色、路由和 E-20~E-30 全页断言不作为当前产品结论。 |
| `UI-权限视觉规范-企业维度.md` | **历史权限视觉基线** | 保留已实现权限组件和 token 参考；现行页面归位与产品角色回指本文件 §1。 |
| `UI-通用交互组件视觉规范-派单.md` | **已完成历史派单** | 不再作为规范输入或再次派发；其产出已沉淀至 `Design.md`。 |

## 4. 对齐原则

1. 不删除旧路由、旧任务或旧交接记录；明确它们是兼容 / 历史证据。
2. 不把权限 persona（`VISIT / INNO / GOV`）或 L0-L4 直接当作产品角色；产品角色以 USM 为准。
3. E-32 不承接企业查询、高级筛选、企业集合下钻、评估、风险诊断、推荐或导出。
4. 业务页面是否使用 ContextBar 由其跨 Tab / 跨页面共享口径决定；没有共享口径时可不渲染，不能为满足通则而硬加筛选条。
