# USM-内部评审模式

> **模块**：内部评审模式（跨模块评审辅助能力）
> **状态**：产品定义初稿
> **体验 Owner / 起草**：高颖
> **产品规则确认**：郭万迎（PM/合规）
> **语义状态确认**：何老师
> **治理依据**：`产品定义评审规程.md` §5.7 D-10、§6 SIG-04/SIG-05；非 bid 业务叶子

## 模块：内部评审模式

该能力帮助内部团队在远端演示中逐模块核对“需求—实现—数据—问题—修订”的关系；它不承接业务查询、权限授权或飞书任务写入。

## 覆盖范围与统一挂载

- “内部评审模式”开关是**全局壳层能力**：固定在右上角**用户 / 角色切换**下拉面板内；`系统后台 SYS` 仅是其中一种角色，不是开关入口名称。业务页面标题区或页面内部不重复设置入口。
- 每个业务模块在跑产品定义文档和 Demo 时，都必须按本 USM 的统一规则交付评审层内容：来源与验收解释、Mock / 待接入 / 开放项标识，以及本模块特有的评审辅助说明。
- 全局开关控制当前评审会话中所有业务模块的评审层显隐：开启后显示全角色与锁态菜单及当前页面的评审信息；关闭后只保留当前正式视角，不改变业务权限或业务数据；非内部用户不显示入口。
- 每份页面级 Wireframe 必须引用本 USM，并说明该页面在全局开关**开启后**的评审内容与落位；不再画出或另造页面级开关。只有页面特有的评审内容才在该 Wireframe 中另行说明。
- 评审模式是跨模块辅助层，不增加业务导航节点、业务数据或业务权限。

## 目标用户角色（≥2）

| 产品角色 | 角色依据 | 需要完成的工作任务 |
| --- | --- | --- |
| 体验评审者 | PDR 规定高颖主持 Track-MS walkthrough | 在页面内核对组件的需求解释、交互与验收点，确认修订结果。 |
| 语义/数据评审者 | PDR 要求何老师核对 metric、Mock 与 Pending | 判断指标口径、数据接入状态与开放项是否被正确标识。 |
| 合规/交付评审者 | PDR 规定郭万迎审核 TRACE、开放项和门禁 | 核查模块未漏需求，确认问题进入纪要与后续会签。 |

> 以上是评审流程角色，不替代系统的业务产品角色或权限 persona。

## 用户故事（As / Want / So that）

### US-REV-01 逐模块核对

作为体验评审者，我想在当前卡片旁查看对应的原始需求子项、当前解释和验收点，以便不离开页面完成组件级走查。

### US-REV-02 区分演示与正式能力

作为语义/数据评审者，我想识别当前指标或图表是否为 Mock、待接入或存在未决口径，以便不把演示效果误判为正式数据能力。

### US-REV-03 完成修订复核

作为合规/交付评审者，我想查看模块处于待核对、有问题、待复核还是已通过，以便把页面走查与纪要、飞书任务和正式会签串成闭环。

## 场景 walkthrough（主路径 + 异常路径）

### 主路径

1. 内部用户打开远端演示，默认看到已开启的评审模式。
2. 用户确认当前版本、页面和角色模拟上下文。
3. 用户在一个小模块标题附近点击 `ⓘ`，核对该模块的来源号、原文子项、当前解释和验收点。
4. 用户读取 `🧪`、`⚠️` 与模块复核状态，必要时在评审纪要和飞书手工登记问题。
5. 修订完成后，用户回到同一模块复核并更新模块状态；正式会签仍在页面外完成。

### 异常与降级路径

| 场景 | 页面行为 | 用户下一步 |
| --- | --- | --- |
| 模块没有可用原始来源 | 显示 `⚠️` 与“追溯待补”说明，不伪造来源号。 | 记录开放项并退回补 TRACE。 |
| 指标无正式口径或数据源 | 已登记 `Q-*` 的口径待定显示 `⚠️`；Mock 数据显示 `🧪`；无源指标显示无源/降级说明。 | 由语义/数据 Owner 确认，或按 DEMO / 不实现规则处理。 |
| 用户关闭评审模式 | 隐藏全部评审信息，保留正式业务视图。 | 可再次开启继续走查。 |
| 非内部用户访问 | 不显示评审模式入口和任何评审信息。 | 按正式业务权限浏览。 |

## 验收场景（可测试、用户语言）

| 编号 | 可验证结果 |
| --- | --- |
| REV-USM-01 | 内部用户在当前模块只看到该模块的来源子项、解释、验收点、关联指标和开放项，不会看到整页需求原文。 |
| REV-USM-02 | 关闭评审模式后，`ⓘ / 🧪 / ⚠️`、模块复核状态与评审抽屉均不可见，业务权限和业务数据不改变。 |
| REV-USM-03 | Mock、待接入和开放项能在对应模块被区分，且每个开放项可指向已有 `Q-*` 或明确“待登记”。 |
| REV-USM-04 | 修订后模块可从“有问题”进入“待复核”；只有验收点复核通过才可标“已通过”，且该状态不替代正式会签。 |
