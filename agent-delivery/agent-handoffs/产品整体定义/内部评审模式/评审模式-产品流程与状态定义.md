# 内部评审模式：产品流程与状态定义

> **状态**：产品定义初稿，尚未进入门 1 正式评审
> **性质**：跨模块评审辅助能力，不是新的 bid 业务叶子；需求来源以 TRACE 中的验收叶子与原文位置为准
> **适用对象**：科技专题服务系统的内部评审者与交付协作人员
> **规则 Owner**：郭万迎（PM/合规；评审流程、归档与正式结论）
> **体验起草**：高颖（UE/UI；页面交互、信息层级与状态呈现）
> **协作确认**：何老师（语义/数据状态）
> **治理依据**：`产品定义评审规程.md` §3.2、§5.7 D-10、§6 SIG-04/SIG-05；`data-lineage-policy.md`

## 1. 目标与边界

### 1.1 目标

让内部评审者在同一远端演示环境中完成一次可回溯的走查：识别当前评审范围、按模块核对需求和实现、理解数据状态、记录外部问题、在修订后完成复核。

### 1.2 不做什么

- 不改变任何业务权限、数据权限或正式菜单权限。
- 不替代正式 PDR、V1/V2 会签或 DG 结论；页面“已通过”仅表示当前模块复核通过。
- 不在页面内创建、修改或关闭飞书任务；问题仍由评审纪要和飞书人工归档。
- 不向访客或正式业务视图暴露需求原文、Mock、开放项和评审进度。

## 2. 评审对象与默认规则

| 项 | 定义 |
| --- | --- |
| 可用人群 | 所有内部用户；访客及正式业务展示不显示评审信息。 |
| 默认 | 内部用户默认开启评审模式。关闭仅影响当前界面的评审信息可见性，不改变业务权限。 |
| 演示链接 | 用远端部署链接开展评审；链接默认展示评审信息，不以 localhost/LAN 地址作为正式记录。 |
| 评审范围 | 当前系统版本 → 当前页面 → 当前小模块；例如 `E-32` 页面中的“未来产业企业数量排名”。 |
| 角色模拟 | 仅模拟产品角色的默认视图与数据可见范围；不授予真实操作权限。 |
| 关闭后入口 | 页面内不保留评审标签或提示；仅从顶部用户菜单重新开启。 |

## 3. 评审流程

```text
进入远端演示（评审模式默认开启）
  → 确认当前版本、页面和模拟角色
  → 逐个小模块查看需求、解释、验收点与数据状态
  → 标记模块复核状态并在评审纪要/飞书手工记录问题
  → 文档和 Demo 修订
  → 回到同一模块复核
  → 模块复核通过；再由正式门禁完成会签与归档
```

| 阶段 | 评审者动作 | 系统提供的信息 | 页面外记录 |
| --- | --- | --- | --- |
| 进入 | 确认版本、页面、角色模拟 | 评审模式已开启、当前评审范围 | 无 |
| 走查 | 逐卡片查看证据与交互 | 局部追溯、验收点、指标、Mock、开放项 | 无 |
| 提问 | 发现偏差或口径未定 | `⚠️` 与关联开放项 | 评审纪要、飞书任务人工登记 |
| 修订 | 文档或 Demo 依据问题修订 | 模块状态变为“待复核” | 修订链接、版本/提交证据 |
| 复核 | 重新执行该模块验收点 | 当前版本与历史问题引用 | 纪要更新结论 |
| 归档 | 完成正式门禁 | 全局门禁摘要 | PDR/V1/V2/门 2 会签单 |

## 4. 页面信息架构

### 4.1 模块内联信息（只显示本模块）

每个可评审小模块在标题附近提供轻量状态条和 `IconFile` 需求追溯入口，只展示以下内容：

1. **原始需求子项**：使用既有来源号加原文标题，例如 `E-32 · 企业总体数量`；不新造 `E-32.1`。
2. **当前解释**：本轮 IA/评审如何把该子项落到当前组件。
3. **验收点**：与当前卡片直接相关、可现场核对的 2–4 条。
4. **关联指标**：只列当前卡片的 `M_*`；没有正式口径时标明待确认。
5. **数据与开放项状态**：仅列当前卡片相关的 `🧪`、`⚠️` 与对应编号。
6. **模块复核状态**：`待核对 / 有问题 / 待复核 / 已通过`。

不在卡片内展示整页原文、其它卡片的需求、完整 USM、完整 PDR 清单或会签历史。

### 4.2 全局评审抽屉

页面级入口汇总以下信息：当前版本、页面范围、角色模拟、模块复核清单、完整 USM、TRACE、PDR/V1/V2/门 2 门禁情况、评审纪要和远端演示证据链接。

### 4.3 评审辅助说明与业务交付内容的边界

评审辅助说明用于解释“需求为什么这样落位、交互规则为何如此”，不属于业务交付功能、正式业务文案或独立验收产物。关闭评审模式后必须隐藏；业务功能本身及其真实结果不得因关闭而消失。

| 分类 | 关闭评审模式后的处理 | 通用内容类型 |
| --- | --- | --- |
| 需求与原型说明 | 隐藏 | 整体需求摘要、当前原型性质、正式口径/真源提示。 |
| 交互规则说明 | 隐藏 | 默认值、最小数据条件、地域/层级范围、聚合方式、选择上限等解释性文案。 |
| 联动边界说明 | 隐藏 | “仅作用于本卡片”“不影响其它统计”等实现边界提示。 |
| 评审证据与状态 | 隐藏 | `IconFile / ⓘ / 🧪 / ⚠️`、模块复核状态、版本与会签信息。 |
| 业务内容与可操作控件 | 保留 | 指标、图表、地图、筛选器、切换控件、复位和业务动作。 |
| 用户完成操作所需反馈 | 保留，但改写为业务语言 | 已选数量、超出选择上限的即时反馈、无法形成结果时的空态；不得展示实现阈值或评审措辞。 |

**交互说明挂载原则**：当某个规则不能仅通过控件状态、即时反馈或空态让评审者判断时，才在评审模式下以局部说明挂载；不得为了展示评审信息而新增业务区块、业务按钮或正式交付内容。

**页面级容器规则**：承载整体需求、原型状态、业务范围标签和评审入口的顶部评审容器，仅在评审模式开启时展示；关闭后整块隐藏，不保留任何评审标签。重新开启入口仅位于顶部用户菜单。

**复用契约**：任何业务模块接入评审模式时，先把页面内容按上表归为“评审辅助说明 / 业务交付内容 / 用户操作反馈”三类；只允许前一类受 `reviewMode` 隐藏。模块只在自身 IA 或 Wireframe 中登记具体文案和位置，不得新增模块私有的显隐规则。

## 5. 编号与状态字典

### 5.1 编号分层

| 类别 | 格式 | 说明 | 页面位置 |
| --- | --- | --- | --- |
| 原始需求来源 | TRACE `leaf_id` + `md_ref` | 验收目录叶子与 bid 原文位置共同构成来源锚点；不在本文件另立编号体系。 | 模块内联 |
| 用户故事 | `US-{模块}-01` | 用户目标与验收的文档锚点。 | 全局抽屉 |
| 指标 | `M_{DOMAIN}_*` | 指标定义与数据口径锚点。 | 指标旁 / 模块内联 |
| 开放项 | `Q-{模块}-*` | 待业务、语义或数据确认的事项。 | 模块内联；详情在抽屉 |
| 门禁检查 | `PDR-*`、`H-*`、`D-*`、`SIG-*` | 评审检查项，不是业务需求编号。 | 全局抽屉 |

### 5.2 证据状态（全部由评审模式控制）

> **打标真源引用（必须优先遵循）**：本节不重新定义指标数据状态，只定义它们在评审模式下的显示边界。修改 `ⓘ / 🧪 / ⚠️` 的触发条件、Tooltip 文案或数据字段时，须先按下表的原规则执行；规则本身发生变更时，更新原规则文件而非只改本文件。

| 标识 / 范围 | 原规则真源 | 本文只补充的规则 |
| --- | --- | --- |
| 模块标题旁 `IconFile`（需求追溯） | [PDR · TRACE 最低要求](../../../产品定义评审规程.md#32-追溯矩阵最低要求trace)；当前模块的 `TRACE-{模块}.yaml` | 仅在评审模式显示；只展示当前小模块对应的来源子项。 |
| 统计数字旁 `ⓘ`（MetricSpecCard） | [数据血缘规范 · §5 指标组件](../../../data-lineage-policy.md#5-ui-层组件定义)；[企业 D9 · §4.1](../UX-权限交互规范-企业维度.md#41-三类角标交互行为对照-data-lineage-policymd-5) | 仅在评审模式显示；不改变 `metric_id`、口径或血缘内容。 |
| `🧪` MockBadge | [数据血缘规范 · §5.1.3 MockBadge](../../../data-lineage-policy.md#513-mockbadgeMock-数据标识)；[企业 D9 · §4.1](../UX-权限交互规范-企业维度.md#41-三类角标交互行为对照-data-lineage-policymd-5) | 仅在评审模式显示；继续以 `is_mock`、来源和替换计划为准。 |
| `⚠️` PendingBadge | [企业 D9 · §4.1](../UX-权限交互规范-企业维度.md#41-三类角标交互行为对照-data-lineage-policymd-5)；[PDR · SIG-05](../../../产品定义评审规程.md#62-过关标准10-条) | 仅在评审模式显示；必须关联未闭合 `Q-*` 或 `mapping_status='⚠️'`。 |
| 无源 / DEMO 降级 | [PDR · §2.2 C 数据不足降级](../../../产品定义评审规程.md#22-四种典型情形的统一处理)；[PDR · §3.3 指标语义卡](../../../产品定义评审规程.md#33-指标语义卡最低要求北明) | 仅规定评审可见性；无源指标不得伪造正式数值。 |

| 标识 | 含义 | 何时出现 | 隐藏规则 |
| --- | --- | --- | --- |
| `IconFile` | 需求追溯入口 | 模块标题存在来源锚点 | 关闭评审模式即隐藏 |
| `ⓘ` | 指标说明入口（MetricSpecCard） | 统计/聚合字段存在 `metric_id` | 关闭评审模式即隐藏 |
| `🧪` | Mock 数据标识 | 指标元数据 `is_mock=true`；或当前为 Wave 0 / DEMO 占位数据 | 关闭评审模式即隐藏；Tooltip 必须说明 `source_systems` 与 `mock_until` / 替换计划 |
| `⚠️` | 已登记的口径/数据开放项 | 指标 `pending_ref` 指向未闭合 `Q-*`，或 `mapping_status='⚠️'` | 关闭评审模式即隐藏；Tooltip 必须带 Q 编号和临时默认说明 |

> `IconFile` 只用于模块标题旁的需求追溯；`ⓘ` 只用于统计数字旁的 MetricSpecCard。`有问题 / 待复核` 是模块复核状态，不使用 `⚠️` 代替。`mapping_status='❌'` 的无源指标不伪造数值，应显示无源/降级说明；其具体视觉样式待 V1 确认。

### 5.3 模块追溯浮层与交付处理（保留定义）

模块标题旁的 `IconFile` 仅在演示 / 内部评审模式显示，不作为业务角色，也不改变任何业务权限。浮层字段由当前模块 TRACE 提供：

| 字段 | 说明 |
| --- | --- |
| 来源锚点 | TRACE 中的验收叶子与原文子项标题；不创建页面私有需求编号。 |
| 源文档位置 | bid 文件名、章节或可定位位置。 |
| 原始标题 / 摘要 | 当前模块对应的原文标题与用于快速核对的摘要。 |
| 完整原文 | 二级展开或查看入口，不在页面主体默认铺开。 |
| 本轮解释 | 当前实现是完整落地、DEMO、数据支持、外部负责或其它已确认范围。 |
| 当前状态 | 本期处理状态；与 `🧪 / ⚠️` 的数据状态、模块复核状态分别表达。 |

| 阶段 | 处理策略 |
| --- | --- |
| 演示 / 内部评审 | 默认显示 `IconFile`，可点击或悬停查看上述局部信息。 |
| 开发联调 | 保留来源引用和源文位置，供 QA、验收和变更核对；不依赖自定义编号规则。 |
| 正式上线 | 通过配置关闭评审浮层；如需瘦身，可在构建阶段剔除原文摘要。 |
| 需求变更 | 更新 TRACE 的来源锚点、解释和状态；验收叶子变更按 acceptance-catalog 与 PDR 流程处理。 |

### 5.4 模块复核状态（全部由评审模式控制）

| 状态 | 进入条件 | 退出条件 | 说明 |
| --- | --- | --- | --- |
| 待核对 | 新模块或新版本尚未走查 | 评审开始或登记问题 | 默认状态 |
| 有问题 | 已发现需求、交互、数据或视觉偏差 | 修订完成，提交复核 | 问题细节在纪要/飞书，不在页面直接编辑 |
| 待复核 | 修订已提交，等待评审者复查 | 复核通过或发现新问题 | 应关联修订版本证据 |
| 已通过 | 当前模块验收点复核通过 | 出现新的需求、版本或问题时回到待核对/有问题 | 不等同 PDR、V1/V2 或门 2 正式通过 |

## 6. 关闭评审模式后的行为

关闭后隐藏页面级评审容器、`IconFile / ⓘ / 🧪 / ⚠️`、模块复核状态、追溯文本、评审抽屉和角色模拟辅助信息；页面内不保留评审标签。保留当前真实业务视图与原有权限结果；仅可从顶部用户菜单再次开启，不自动改变业务数据或菜单。
