> **版本**：v1.0-pack1 · 2026-08-10  
> **状态**：Pack1 交互五件套（未宣告门 1 闭合）

## 1. 模块结果

围绕用户确认的「目标区域 + 对比范围 + 时间窗」，构建企业—机构—人才合作关系图谱，**显性展示指标、计算方法和计算结果**：完整度、中心度、密度、区域创新协同指数、关系输入构成、横向对比、纵向趋势、高效集群、孤立主体、优势不足及协同—创新产出关联。默认条件深圳 × 全国重点城市 × 最近 3 年读取后台跑批快照秒开；修改任一条件后由用户点击「开始分析」，进入协同场景后台五阶段并可跨页面恢复。

源需求未给出三指标正式分母、聚合方式、权重、历史校准窗口及相关性方法；本包保持 D1 missing/draft + `Q-SYNTH-C-*`，演示公式只作可复现临时默认，不冒充已定算法。

### US-COLLAB-02｜指标体系与计算方法显性展示

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 算法库 §10.10；系统方案 §8.3.1–8.3.2 |
| 产品角色 | `ROLE-SYN-RESEARCH` |
| Frames | `F-COLLAB-01`、`F-COLLAB-03` |
| 业务结果 | 用户能看见用什么指标、输入什么关系、如何计算、哪些参数仍待确认 |

作为科研机构 / 研究分析用户，我想看清协同指数由哪些网络指标和合作关系构成、如何计算，以便判断结果是否适用于研判。

主路径：

1. 结果面「协同指标」固定展示：
   - 完整度：网络连接的全面性 / 覆盖水平；
   - 中心度：关键节点的辐射影响力；
   - 密度：整体合作紧密度；
   - 协同指数：三指标综合加权并经历史数据校准。
2. 「关系输入构成」展示联合专利、合作项目、人才流动等有效事件/边统计。
3. 打开 F-COLLAB-03，展示输入校验 → 建图 → 三指标计算 → 标准化/加权/历史校准 → 指数与诊断输出。
4. 正式算法未定处显示 `Q-SYNTH-C-01/02/03`；V1 若展示演示公式，必须标「团队临时默认 / 🧪」：
   - 完整度示例：有有效合作关系的主体数 / 有效主体总数；
   - 中心度示例：节点度中心性 `degree/(N-1)`，区域摘要取 TOP 与均值；
   - 密度示例：无向简单图 `2E/[N×(N-1)]`；
   - 协同指数示例：三指标归一化后等权合成。
5. 页面明确说明上述演示公式不等于甲方确认的正式算法。

验收：

- `AC-US-COLLAB-02-01`：完整度、中心度、密度均可在主结果面和方法抽屉定位；不得遗漏完整度。
- `AC-US-COLLAB-02-02`：用户不离开页面即可获得「指标 + 方法 + 结果」三者。
- `AC-US-COLLAB-02-03`：联合专利 / 合作项目 / 人才流动输入统计与图谱边图例同源。
- `AC-US-COLLAB-02-04`：正式未定项挂 D1 missing/draft + Q；不把演示公式标为正式。
- `AC-US-COLLAB-02-05`：筛选子图计算与全网快照计算的适用范围有明确文字，不混用分母。

不包含：用户修改并发布正式算法权重。

### US-COLLAB-05｜默认秒开与改条件可视化分析过程

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `product_interpretation` |
| `requirement_refs` | §10.10 支持按区域/时间范围在线分析；`CT-SYN-JOBS` |
| 产品角色 | `ROLE-SYN-GOV` |
| Frames | `F-COLLAB-01`、`F-COLLAB-02` |
| 业务结果 | 默认三元组秒开；非默认进入可恢复的协同五阶段后台任务 |

作为政府科技战略决策用户，我想在默认深圳、全国重点城市、最近 3 年时立即看到结果；修改条件后能看到后台分析真实推进，而不是无反馈等待。

主路径 A — 默认秒开：

1. 上下文等于默认三元组且存在对应 `CollabBatchSnapshot`。
2. F-COLLAB-01 直接渲染指标、方法和结果，不创建 `CollabTask`、不进过程页。
3. 元信息显示「预计算结果 · 跑批时间 · 方法版本」；评审态显示来源说明。

主路径 B — 改条件后台分析：

1. 用户修改任一条件，结果进入待分析态，显示与默认条件的差异。
2. 点击唯一主按钮「开始分析」，冻结上下文与方法版本；同用户同 `task_type` 已有非终态任务时恢复原任务。
3. F-COLLAB-02 展示协同场景五阶段：
   1. 任务提交与分析条件冻结；
   2. 装载创新主体与合作关系快照，构建区域协同网络；
   3. 计算完整度、中心度与密度三项网络指标；
   4. 合成协同指数，识别高效集群、孤立主体与优势不足；
   5. 校验横向对比与趋势结果，组装协同效率报告快照。
4. 用户可离开，任务后台继续；通过系统任务浮层、原路由或重新登录恢复同一 `taskId`。
5. 成功后不强制自动跳转；点击「查看分析结果」进入绑定任务快照的结果面。

异常与恢复：

| 场景 | 系统行为 | 恢复 |
| --- | --- | --- |
| 执行槽满 | 排队并显示队列位置，不承诺预计等待时间 | 等待；排队态可撤回 |
| 队列满 | 不建任务，保留配置并提示繁忙 | 稍后提交 |
| 网络断开 | 标「状态连接中断」，后台任务不判失败 | 重连后服务端恢复 |
| 任务失败 | 显示失败阶段、错误编号、冻结条件 | 新 `taskId` 重试 |
| 同类任务重复提交 | 恢复原任务，不创建第二个 | 查看原任务 |

验收：

- `AC-US-COLLAB-05-01`：默认三元组 + 有跑批时首屏结果秒开，无过程页跳转和用户任务。
- `AC-US-COLLAB-05-02`：修改任一条件后必须点击开始分析；过程文案为协同网络场景，不出现产业链「四力」或活力「四维」文案。
- `AC-US-COLLAB-05-03`：过程页仅显示完成/进行中/等待/失败及真实已用时间，不显示伪百分比。
- `AC-US-COLLAB-05-04`：刷新、跨页、重新登录可恢复同一服务端任务。
- `AC-US-COLLAB-05-05`：完成结果的上下文、方法版本与任务冻结快照一致。

### US-COLLAB-06｜协同效果评估与报告

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | §8.3.3；算法库 §10.10 结构化报告/优势不足/趋势 |
| 产品角色 | `ROLE-SYN-RESEARCH` |
| Frames | `F-COLLAB-01`、`F-COLLAB-03` |
| 业务结果 | 关联方法、样本与结果可解释，报告绑定不可变快照 |

作为科研机构 / 研究分析用户，我想查看协同网络与联合发明专利等创新产出的关联，并生成协同效率报告，以便形成可追溯研判材料。

主路径：

1. 效果评估区显示产出指标、样本范围、关联方法状态、关联结果与结论。
2. Pearson / Spearman、样本粒度、最小样本数未定时挂 `Q-SYNTH-C-03`；不得把相关性写成因果性。
3. 样本不足时显示「样本不足，暂无法给出关联结论」，不画伪相关线。
4. 报告包含经审核的优化合作路径策略建议；生成/审核规则未定时挂 `Q-SYNTH-C-04`。
5. 「生成协同效率报告」通过 `CT-SYN-03` 绑定当前 `resultSnapshotId`；报告任务只读快照，不重新计算指标。

验收：

- `AC-US-COLLAB-06-01`：关联结果旁有 `M_SYNTH_COLLAB_OUTPUT_CORR` 红问号 + 🧪，并显示样本与方法状态。
- `AC-US-COLLAB-06-02`：结论只描述关联，不声称因果。
- `AC-US-COLLAB-06-03`：无有效结果快照时报告入口禁用并说明。
- `AC-US-COLLAB-06-04`：报告任务绑定当前快照，重复生成按统一报告指纹复用。

## 5. 门 1 Walkthrough

1. 用户打开协同分析，看到深圳 / 全国重点城市 / 最近 3 年与跑批时间，秒开协同指数、完整度、中心度、密度、图谱、对比趋势和诊断。

3. 用户筛选人工智能产业，查看当前子图、中心主体、高效集群和孤立主体。
4. 用户把时间改为最近 5 年，结果进入待分析态；点击「开始分析」，查看协同五阶段，离开后从系统任务浮层恢复，完成后查看任务快照。
5. 用户查看协同—产出关联；样本有效时查看结果，样本不足时看到诚实空态；从当前快照生成报告。
