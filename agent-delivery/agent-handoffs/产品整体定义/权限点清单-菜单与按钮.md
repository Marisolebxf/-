## 1. 权限点编码规范

统一权限码格式：`{type}:{domain}:{key}`

| type | 含义 | 校验位置 |
|---|---|---|
| `menu` | 菜单/路由可见 | 前端路由守卫 + 后端菜单接口 |
| `btn` | 页面内按钮/操作点 | 前端指令 `v-perm` + 后端接口鉴权 |
| `data` | 数据密级/敏感字段 | 数据服务（行列级） |
| `view` | 视图模式（驾驶舱/工作台） | 前端按身份切换 |

- `domain`：`ds`（展示系统）/ `ent`（企业主题）/ `sys`（后台）/ `common`（通用）。
- 每个权限点声明 **minLevel（最低级别）** 与 **roles（可选限定身份/子角色）**。
- 前端原则：**非阻断**——无权时按钮 `disabled + 🔒 + 升级/登录/申请引导`，不直接隐藏关键入口（沿用 demo RoleLevelGate）。后端：**强校验**，越权直接 403。

## 2.5 屏幕类型功能形态模型（大 / 中 / 小）★

> **⚠️ 适用范围（重要）**：屏幕类型（大/中/小）**仅适用于科技信息展示系统**（§2.1）。
> **专题系统（门户垂直主题，含企业 §2.2/§2.3）仅 PC 端 = 中屏（MEDIUM）单形态**，无大屏/小屏适配；故企业等专题页面不设屏幕列，按"中屏全功能"处理。

> 屏幕类型是**独立于用户级别的第二维**：用户级别决定"能做多深、看多敏感"，屏幕类型决定"以什么形态呈现、开放哪几类功能"。同一账号在不同屏看到的功能集不同。对应招标"超大屏 / 中屏 / 小屏"三形态。

### 2.5.1 三种屏幕定位

| 屏幕 | 代号 | 定位 | 功能取向 | 个人定义 | 酷炫展示 |
|---|---|---|---|:--:|:--:|
| 大屏（超大屏） | `LARGE` | **展示为主**（指挥中心/接待/会商） | 只读巡览、概览、轮播 | ✕ 无 | ✅ 有 |
| 中屏（PC 工作台） | `MEDIUM` | **功能最全**（业务分析终端） | 全功能：分析/下钻/推演/配置/维护 | ✅ 有 | ✕ 无 |
| 小屏（移动/平板） | `SMALL` | **中屏裁剪**（随身查看） | 中屏核心功能子集 | ◑ 部分 | ✕ 无 |

### 2.5.2 功能分类 × 屏幕开放规则（核心）

> 每个按钮/操作归入一个 `feature_class`；屏幕是否开放由类别决定（无需逐按钮重复定义）。

| feature_class | 含义 | 典型操作 | 大 LARGE | 中 MEDIUM | 小 SMALL |
|---|---|---|:--:|:--:|:--:|
| `display` | 基础展示 | 查看图表/地图/概览 | ✅ | ✅ | ✅ |
| `showcase` | **酷炫展示**（大屏专属） | 自动轮播、全屏特效、3D 炫动、讲解动效、多屏联动 | ✅ | ✕ | ✕ |
| `interact` | 交互分析 | 下钻、筛选、对比、视图切换 | ◑ 只读巡览 | ✅ | ◑ 裁剪 |
| `deep` | 深度功能 | 推演、权重/口径配置、自助分析、高级筛选 | ✕ | ✅ | ✕ |
| `personal` | **个人定义** | 收藏、订阅、告警配置、自定义布局、导出、分享 | ✕ | ✅ | ◑ 部分 |
| `manage` | 维护管理 | 编辑、审核、发布、回滚、用户/角色 | ✕ | ✅（后台） | ✕ |

**落地为你提的三条规则**：
- **大屏 = `display` + `showcase`**，**不含** `personal`（订阅/收藏/配置等个人定义）、不含 `deep`/`manage`；交互仅"只读巡览"（预设路线、点击高亮，不做自助配置）。
- **中屏 = `display`+`interact`+`deep`+`personal`+`manage` 全开**，**唯独不含** `showcase`（不堆酷炫展示效果）。
- **小屏 = 中屏核心裁剪**：保 `display`+`interact`(裁剪)+`personal`(部分，如收藏/分享)，**去掉** `deep`/`showcase`/`manage`。

### 2.5.3 最终可用 = 三重交集

```
可用(按钮) = 用户级别命中 minLevel
           ∧ 屏幕类型允许该 feature_class
           ∧ （如有）数据密级/子角色命中
```

> 例：`btn:common:simulate`（推演，deep，minLevel L3）→ 仅 **中屏 + L3+** 可用；大屏/小屏即便 L3 也不出现。
> 例：`btn:common:fav`（收藏，personal，L1）→ 中屏 L1+ 可用、小屏 L1+ 可用、**大屏永不出现**。

## 6. 前端实现建议（含 demo 改造）

### 6.1 路由 meta + 守卫

```ts
// 每个路由声明
meta: { minLevel: 'L2', perms: ['menu:ent:type'], persona?: ['GOV'] }
// 守卫：level < minLevel → 不进入(关键页) 或 进入降级态(入门页)
```

### 6.2 按钮指令 `v-perm`（非阻断）

```html
<a-button v-perm="'btn:common:export'">导出</a-button>
<!-- 无权：自动 disabled + 锁标 + tooltip 升级/登录/申请引导，并埋点 user_level -->
```

实现要点：
- 指令读取当前 `userLevel + perms 集合`，命中则正常，否则 `disabled` + `🔒` + `Tooltip`。
- 关键转化入口（登录/升级/申请）即使无权也**保留可见**，引导转化。
- 所有 Gate 命中埋点（沿用 `observability.ts`），记录 `user_level / perm_code`。

### 6.3 Wave 0 mock 鉴权 → Wave 1 接 SSO

- **Wave 0**：前端 mock 一个 `currentUser = { level, persona, perms[] }`，顶栏提供**级别切换器 + 身份标识**用于评审演示；perms 由级别 + 身份本地推导（按本清单生成一张 `level→perms` 映射表）。
- **Wave 1**：`perms[]` 改由网关/统一权限服务下发（D6），前端逻辑不变。

### 6.4 demo 收敛改造点（demo 现状 → 目标）

| demo 现状 | 问题 | 改造目标 |
|---|---|---|
| 顶栏 "驾/析/研/政/运/数" 角色切换 | 与 U/S 级别并存=两套 | 折叠为**身份场景标识**（驾=GOV…），不再独立控权 |
| U1/U2/S1/S2/U3 标签 | 第三套口径 | 收敛为 **L0–L4 级别切换器**（§全系统设计 §12.2 映射） |
| 各页散落的 if-role 判断 | 不可维护 | 统一走 `v-perm` 指令 + 路由 meta |
| 无 D9 数据血缘角标 ⓘ/🧪/⚠️ | 违反 P0 铁律（实测缺失） | 与权限改造同批补齐（与本任务并行提给 frontend） |

### 6.5 后端（api/architect）

- 接口按本清单 `btn:*` / `menu:*` 声明所需权限点，网关统一校验（D6）。
- 数据密级/敏感字段在数据服务做**列级脱敏**，前端不做"假脱敏"。
- `btn:common:export-list` / `view-sensitive` / `simulate` 等敏感操作**全程审计留痕**。
