## 11.6 契约生成（A13 裁决）

前端契约由 **`openapi-typescript`** 从后端 OpenAPI **自动生成**，**只生成类型、不接管请求层**；**废止前端手写类型**，消除契约三处漂移。

## 11.7 订阅与推送（A15 裁决 · 关联 A9 / R8）

**归属**：订阅**复用 `gkxlumen-topic-async-service` 的异步执行能力**（展示侧不自造任务体系），**订阅关系与触发规则落展示侧**。

**推送三通道**：站内通知 + **邮件** + **短信**。推送能力**接 `upms` 的 `RemoteMessageService`**（`MessageSmsDTO` / `MessageEmailDTO` / `MessageHookDTO`），**不在 `topic-async-service` 内**；短信须在 `SmsBizCodeEnum` **注册业务码**。

> ⚠️ 依据 PM 郭万迎 2026-10-26《科技信息展示系统-短信与邮件功能需求分析》：共 **25 个推送功能点**（明确型 6 + 推断型 19），散落 **8 个模块**（订阅监测 / 订阅管理 / 城市订阅 / 载体订阅 / 预约订阅 / 人才订阅更新等）；其中 **19 个推断型的渠道归属待产品确认**。

**⚠️ 阻塞（A9）**：订阅关系 / 收藏 / 标签 / 导出配置的**写库落点未定**——`app_user` 是平台自有 **App 端**用户表，与 `upms` 的 `sys_user`（管理后台）**并列两套**；**待确认 PC 与 App 是否同一用户池**（方案侧建议复用 `sys_user`，详见 `ARCH-DISPLAY-01.md` §10.9.1）。**此项未定则订阅无法实装。**

**⚠️ 依赖（R8）**：异步任务依赖 **XXL-Job**，该模块存在但 **Helm 未部署**，需确认部署计划，否则订阅定时触发不可用。
