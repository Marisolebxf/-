## 0. 一句话

选择器上选到哪一层，后台就按那一层的**覆盖范围**查，禁止把集群编码当成产业编码去打 ADS。

- 只选集群 → 查该集群映射下的**全部**产业（及这些产业下的链数据）。  
- 选到产业（L0）→ 只查该产业。  
- 高级筛选还可以继续选到产业链更深层 → 只查该节点及其子孙。

## 3. 规则 1｜高级筛选要能选到最后一层

产业查询、企业查询的高级筛选里，产业相关选择必须是**同一棵树**：

```text
产业集群（15，CL-*）
  └─ 映射 L0（INB*，industry_chain.chain_tier='L0'）
       └─ 该 L0 下 L1
            └─ L1 下 L2 …
                 └─ 该分支实际最深一层（没有更深就停）
```

1. 树的根是 15 个集群，不是旧八大、不是国标 NIC。  
2. L0 只来自 `industry_cluster_map`；未映射的集群仍出现，子级为空。  
3. L1 / L2… 只来自 `industry_chain`（及节点表）里该 L0 的真实子级，**不造假环节**。  
4. 「最后一层」= 该分支**实际存在的最深一层**，不是固定写死 L2。有的链只有 L0，有的到 L1，有的到 L2。  
5. 用户**不必**选到最后一层；控件必须**允许**选到。  
6. 企业「所属产业」与产业查询「产业分类」共用这棵树，禁止各写一份旧 cascade（如现在企业 mock 的「集成电路/设计」）。

## 4. 规则 2｜产业查询高级筛选只留「产业分类」

产业查询高级筛选里，下列三个字段：

| 字段 | 本规则 |
|---|---|
| 所属产业领域 | **删** |
| 产业分类 | **留**，控件改成规则 1 的级联 |
| 产业标签 | **删** |

其它字段（对象类型、重点发展方向、更新时间、产业/链专属字段等）本规则不裁。推荐条件 / 结果内再筛若还挂着「领域 / 标签」，一并拿掉，避免删了字段库还留快捷入口。

企业查询高级筛选不套这条：企业侧对应字段仍叫「所属产业」，只改成规则 1 的级联。

## 5. 规则 3｜分析对象 = 集群 + 可选产业

适用于：深圳产业情况、分析对比，以及同类「分析对象」单选（周期、区域、诊断等）。

| 用户操作 | 查询语义 |
|---|---|
| 只选集群 | 查该集群下**全部**已映射 L0 的数据（聚合 / 并集，按该页指标口径） |
| 选了集群，再选一个产业 | 只查该 L0 产业的数据 |
| 集群无映射 | 空态「无相关产业数据」，**禁止**请求 ADS / Python 装有数 |
| 未选集群 | 未选分析对象，不发起分析 |

约束：

1. 必须是**两个控件**，禁止一个下拉把 `CL-*` 和 `INB*` 平铺混选。  
2. 第二框选项 = 当前集群映射的 L0；换集群则清空已选产业。  
3. **禁止**再自动带上「该集群第一个 L0」。只选集群必须在 URL / 请求里能看出来。  
4. 分析对象第二框停在 L0。要看 L1 结构用全景下钻，不把 L1 塞进「分析对象 · 产业」。  
5. 诊断页「所属产业链」仍是链对象确认，不是本规则的第二框。

## 6. 规则 4｜页面 → Java → Python → 库必须同一粒度

### 6.1 请求里必须带的范围

前端新写入只允许：

| 字段 | 含义 |
|---|---|
| `cluster_id` | 集群，`CL-SEI-*` / `CL-FUT-*` |
| `industry_id` | **仅** L0，`INB*`；只选集群时**不传或显式空** |
| `chain_node_id`（仅高级筛选选到 L1+ 时） | 链上节点；未选深层则不传 |

禁止：

- 把 `CL-SEI-01` 放进 `industry_id` / `industryCode` / `object_ids[]` 当产业去查。  
- 前端自己猜一个 L0 再假装用户选了产业。  
- Java 把 `cluster_id` 原样转给 Python / ADS 的产业主键。  
- Python 把集群编码当 `industry_chain.industry_id` 去扫 DWD / ADS。

### 6.2 展开发生在 Java（出数前）

Java 读 dim，产出**查询范围**，再打现有分析 / 企业 / ADS 接口：

| 粒度 `grain` | 展开结果 | 下游入参 |
|---|---|---|
| `cluster` | `industry_cluster_map` 该集群全部有效 L0 | 现有接口吃 `industry_id[]`（可多个） |
| `industry` | 数组里只有这一个 L0 | `industry_id[]` 长度为 1 |
| `chain_node` | 该节点 + 其子孙节点（高级筛选停在中间层） | 节点条件；没有节点条件的指标回退到所属 L0，并在响应里标明回退 |

空数组（pending 集群）→ Java **直接空态**，不调 Python、不打 ADS。

建议契约（实现时再落，本文件先锁语义）：

```text
POST /topic/v1/meta/industry-clusters/resolve-scope
{ cluster_id, industry_id?, chain_node_id? }
→ { grain, cluster_id, industry_ids[], node_ids[] }
```

现有 `GET .../{cluster_id}/l0` 继续给下拉用。分析 / 检索主路径必须先走 scope，再查数。

### 6.3 各层职责

| 层 | 做什么 | 不做什么 |
|---|---|---|
| 页面 | 如实传用户停在哪一层；空产业框就空着 | 不默认补 L0；不把集群 id 写成产业 id |
| Java | 读 dim 展开；校验 `industry_id` 属于该 `cluster_id` | 不算指标；不扫国标 NIC；不改 DWD |
| Python `/internal/*` | 只收展开后的 `industry_id[]` / `node_ids[]` | 不认 `CL-*` 当产业主键 |
| 库 | ADS 仍按产业 / 节点键；dim 只提供映射 | 不在 ADS 里另造一套集群主键冒充产业 |

可观测：请求和 trace 必须能看出 `grain` + 展开后的 id 列表，方便对账「只选了集群却只出了一条 L0」。
