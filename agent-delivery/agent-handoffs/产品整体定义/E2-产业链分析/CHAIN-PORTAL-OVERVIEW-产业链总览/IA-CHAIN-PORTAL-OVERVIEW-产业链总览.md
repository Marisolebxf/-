## 1. 模块边界

- **解决的问题**：用户选择一个 **产业层级 L0** 产业后，在同一 `industry_id` 上下文中查看该产业的产业链全景（默认 L1 子链）、整体概况、资讯事件、发展历程及深圳现状，并可把当前 L0 产业加入后续分析对象集合。
- **对象规则**：页面主对象为 **L0 产业**（与企业查询「所属产业」同口径，例：`集成电路`）；全景 Tab 默认展示其下 **L1 子链**（例：`半导体设备`、`晶圆制造`），更细结构经逐级下钻进入。标题使用“`{L0产业名称}产业链全景`”，例如“集成电路产业链全景”。
- **路由规则**：新链接写入 `industry_id`；旧 `chain_id` 只做兼容解析，不再作为五个 Tab 的主状态。下钻路径为页内状态，不要求独立一级路由。
- **篮规则**：写入 `industry` 共享对象域（L0），不写入 `industry_chain`。
- **承接内容**：
  - IC-38：八大未来产业的上下游、基础概况、动态资讯、发展历程和深圳产业现状综合介绍。
  - IC-39（门户全景叶子）：上下游、细分产业、节点基础信息、主流工艺/环节/依赖关系图谱；点击细分产业查看**简介 + 企业列表**（`智慧服务门户系统-要素相关.md` §1.1.1.1.1.1.1.1）。
  - IC-40：产业资讯事件线及逐条原始报道溯源。
  - IC-41：产业介绍、企业机构数量、全球/全国区域布局。
- **不承接内容**：
  - **IC-30 专题全景能力**：动态演进、主流技术路线、市场规模、科研/服务机构详情 Tab（归 `CHAIN-TOPIC-PANORAMA`）。
  - 产业查询的智能搜索、关键词搜索、高级筛选和结果列表。
  - 趋势诊断、区域评价、深圳决策的任务配置、计算、结果和报告。
  - 产业链图谱、发展内容和深圳现状的编辑、审核、发布后台。
  - 产业周期、关键环节、瓶颈、竞争力等模型的运行配置；总览只消费已发布标注。
  - “关注产业链 / 收藏产业链”。该能力无 Bid 来源，旧 Demo 不构成需求。

## 3. 信息架构

```text
产业链分析
└─ 产业链总览 /industry-center/overview
   ├─ 当前 L0 产业上下文
   │  ├─ 可检索 L0 产业下拉框（唯一 industry_id 控制器；与企业查询所属产业一致）
   │  └─ 加入 / 移出 industry 共享对比篮
   └─ 当前产业内容 Tabs
      ├─ 产业链全景（默认；仅门户 IC-39）
      │  ├─ 默认：当前 L0 下的 L1 子链（上 / 中 / 下游分区 + 工艺/环节/依赖关系）
      │  ├─ 逐级下钻：L1 → L2+ 更细子链结构（面包屑返回；结构浏览，非专题演进）
      │  ├─ 有方向、有业务语义的关系
      │  ├─ 关键 / 瓶颈等已发布分析标注（只读消费）
      │  ├─ 常驻 60% 图谱 + 40% 对象详情（Bid「弹窗」的交互解释）
      │  └─ 右侧对象详情面板
      │     ├─ 空态操作引导
      │     ├─ 节点基础信息 + 简介 + 企业列表
      │     ├─ 可下钻节点的「下钻内部结构」动作
      │     └─ 关系语义摘要（可选）
      ├─ 产业整体概况
      │  ├─ 产业介绍
      │  ├─ 企业数 / 机构数
      │  └─ 区域分布
      │     ├─ 完整四级可搜索地域控件
      │     ├─ 地图视图（默认）
      │     └─ 同层级列表视图
      ├─ 产业资讯
      │  └─ 事件线 → 事件详情 → 原始报道
      ├─ 产业发展历程
      │  └─ 发展阶段 → 里程碑 → 影响 → 证据
      └─ 深圳产业现状
         ├─ 深圳关键指标
         ├─ 深圳各区地图 / 列表
         └─ 特色优势 / 集群效应 / 竞争地位
```

### 4.1 唯一对象上下文与产业层级

1. 页面任何时刻只存在一个当前 `industry_id`（产业层级 L0）；全景不得混合多个 L0。
2. 从其他入口携带有效 `industry_id` 时直接使用；无对象上下文时使用后台配置的默认推荐 **L0 产业**。旧 `chain_id` 只读兼容。
3. 顶部可检索 L0 产业下拉框是唯一切换入口；选项口径与企业查询「所属产业」一致；Tab 内不得再次出现产业或子链选择器。
4. 全景默认渲染该 L0 下的 **L1 子链** 图；用户可对具备子结构的节点逐级下钻；面包屑返回上级；不得默认把 L2+ 工艺叶子当作首屏节点。
5. 切换 L0 产业保留当前 Tab，清除下钻栈、旧节点 / 关系和其他局部筛选；右栏回到操作引导空态。
6. 对比篮和已经提交的分析任务使用自己的对象快照，不随顶部切换而改变。
7. 门户全景**不提供**产业链演进控件；演进与节点技术路线/市场规模归专题全景。

### 4.2 Tab 顺序与默认值

固定顺序为：`产业链全景 → 产业整体概况 → 产业资讯 → 产业发展历程 → 深圳产业现状`。默认进入产业链全景。顺序不是按旧 Demo 继承，而是本轮人工逐条确认的产品解释。

## 5. 跨模块边界

| 来源或去向 | 可携带内容 | 不可携带 / 不可承担内容 |
| --- | --- | --- |
| 产业查询 → 总览 | 有效 `industry_id`（L0）、来源查询摘要 | 企业查询字段、搜索结果分页和高级筛选状态不得进入总览 |
| 总览 → 产业查询 | 当前 `industry_id` 可作为查询定位条件 | 总览不得内嵌三种完整检索模式 |
| 总览 ↔ 系统共享对比篮 | 总览只通过共享状态传递 `industry_id`、名称、对象类型 `industry`（L0）和来源 route；用户从系统悬浮入口自行打开全局浮层 | 总览不得提供打开浮层按钮或写入打开信号，不得实现局部对比篮、第二个篮或浮层内部对象管理；不得把“关注”当作篮状态 |
| 对比篮 → 趋势诊断 / 区域评价 / 深圳决策 | 用户确认的对象快照（产业级分析用 L0；需链级确认的分析由目标模块再解析） | 总览不运行模型、不生成分析报告 |
| 图谱 / 指标服务 → 总览 | 已发布的图谱结构、节点基础信息、企业列表与指标元数据 | 前端不得直连 Python、Nebula、ODS/DWD；不得在门户全景拉专题演进/技术路线契约 |
| 专题全景 → 总览 | 无强制跳转；能力边界分离 | 门户不得复刻 IC-30 演进与节点深度详情分组 |
| 门户 CMS → 总览 | 已发布的介绍、阶段、里程碑、特色优势、集群效应、竞争地位内容 | 总览不得提供编辑、审核、发布操作 |
| 内部评审模式 | 每个 Frame 对应位置的需求追溯、指标、Mock、Pending 挂载 | 业务模式中不得显示需求编号、评审文案或统一悬浮评审面板 |
