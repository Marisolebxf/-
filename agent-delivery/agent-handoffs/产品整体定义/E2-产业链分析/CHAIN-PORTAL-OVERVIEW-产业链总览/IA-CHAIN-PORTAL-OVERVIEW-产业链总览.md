## 1. 模块边界

- **解决的问题**：用户选择一个产业后，在同一 `industry_id` 上下文中查看该产业的产业链全景、整体概况、资讯事件、发展历程及深圳现状，并可把当前产业加入后续分析对象集合。
- **对象规则**：页面主对象为产业；产业链只作为全景 Tab 的结构数据。标题使用“`{产业名称}产业链全景`”，例如“集成电路产业链全景”。
- **路由规则**：新链接写入 `industry_id`；旧 `chain_id` 只做兼容解析，不再作为五个 Tab 的主状态。
- **篮规则**：写入 `industry` 共享对象域，不写入 `industry_chain`。
- **承接内容**：
  - IC-38：八大未来产业的上下游、基础概况、动态资讯、发展历程和深圳产业现状综合介绍。
  - IC-39：上下游、细分产业、节点基础信息、工艺、环节、依赖关系，以及细分产业简介和企业列表。
  - IC-40：产业资讯事件线及逐条原始报道溯源。
  - IC-41：产业介绍、企业机构数量、全球/全国区域布局。
  - IC-30：产业链结构可视化、节点深度下钻、动态演进。
- **不承接内容**：
  - 产业查询的智能搜索、关键词搜索、高级筛选和结果列表。
  - 趋势诊断、区域评价、深圳决策的任务配置、计算、结果和报告。
  - 产业链图谱、发展内容和深圳现状的编辑、审核、发布后台。
  - 产业周期、关键环节、瓶颈、竞争力等模型的运行配置；总览只消费已发布标注。
  - “关注产业链 / 收藏产业链”。该能力无 Bid 来源，旧 Demo 不构成需求。

## 3. 信息架构

```text
产业链分析
└─ 产业链总览 /industry-center/overview
   ├─ 当前产业链上下文
   │  ├─ 可检索产业链下拉框（唯一 chain_id 控制器）
   │  └─ 加入 / 移出共享对比篮
   └─ 当前产业链内容 Tabs
      ├─ 产业链全景（默认）
      │  ├─ 单产业链上游 / 中游 / 下游及全部链位环节
      │  ├─ 有方向、有业务语义的关系
      │  ├─ 关键 / 瓶颈等已发布分析标注
      │  ├─ 常驻 60% 图谱 + 40% 对象详情双栏工作台
      │  ├─ 产业链演进时间状态与变化标记
      │  └─ 右侧对象详情面板
      │     ├─ 空态操作引导
      │     ├─ 节点固定概览 + 关联企业 / 核心技术 / 科研与服务机构
      │     └─ 关系详情 + 变化证据
      ├─ 产业整体概况
      │  ├─ 产业介绍
      │  ├─ 企业数 / 机构数
      │  └─ 区域分布
      │     ├─ 完整四级可搜索地域控件
      │     ├─ 地图视图（默认）
      │     └─ 同层级列表视图
      ├─ 产业资讯
      │  └─ 事件线 → 事件详情 → 原始报道
      ├─ 产业发展历程
      │  └─ 发展阶段 → 里程碑 → 影响 → 证据
      └─ 深圳产业现状
         ├─ 深圳关键指标
         ├─ 深圳各区地图 / 列表
         └─ 特色优势 / 集群效应 / 竞争地位
```

## 4. 页面 / Tab 职责

| 节点 | 页面职责 | 路由 / 状态 | 原始需求 / TRACE |
| --- | --- | --- | --- |
| 当前产业链上下文 | 确定整个页面唯一对象并连接系统对比篮 | `chain_id`; `basket_state` | PI-CHAIN-OV-01/02；US-CHAIN-OV-01/10 |
| 产业链全景 | 首屏回答“这条产业链由哪些环节组成、如何依赖、当前结构与演进是什么”，常驻 60% 图谱 + 40% 对象详情 | `tab=panorama`; `evolution_time`; `node_id`; `relation_id`; `detail_mode`; `detail_tab` | IC-39、IC-30；US-CHAIN-OV-02/03/04 |
| 右侧对象详情面板 | 未选择时给出操作引导；选中节点时展示固定概览和三类详情；选中关系时展示语义与证据 | `node_id` 或 `relation_id`; `detail_mode=node|relation`; `detail_tab` | IC-39、IC-30；US-CHAIN-OV-03 |
| 产业整体概况 | 回答整条产业链的基础介绍、主体规模和空间布局 | `tab=profile`; `region_path`; `distribution_view` | IC-41；US-CHAIN-OV-06/07 |
| 产业资讯 | 按事件线浏览经整合确认的资讯并追到原始报道 | `tab=news`; `news_type`; `date_range`; `event_id` | IC-40；US-CHAIN-OV-05 |
| 产业发展历程 | 展示经过整理确认的发展阶段、里程碑及影响 | `tab=history`; `phase_id`; `milestone_id` | IC-38；算法依赖 IC-18；US-CHAIN-OV-08 |
| 深圳产业现状 | 展示当前产业链在深圳的本地指标、区级分布和区域特色研判 | `tab=shenzhen`; `district_path`; `distribution_view` | IC-38；算法依赖 IC-17；US-CHAIN-OV-09 |
| 共享对比篮状态交接 | 将当前产业链加入或移出 `industry_chain` 对象域；浮层打开、对象管理和后续动作由系统悬浮入口及系统组件承接 | `basket_state`; `elementKey=industry_chain`; 外部系统状态 | PI-CHAIN-OV-12；US-CHAIN-OV-10 |

### 4.1 唯一对象上下文

1. 页面任何时刻只存在一个当前 `chain_id`，全景不得混合多条产业链。
2. 从其他入口携带有效 `chain_id` 时直接使用；无对象上下文时使用后台配置的默认推荐产业链。
3. 顶部可检索下拉框是唯一切换入口；Tab 内不得再次出现产业链选择器。
4. 切换产业链保留当前 Tab，清除旧链的节点、关系、产业链演进时间、详情 Tab 和其他局部筛选；右栏回到操作引导空态。
5. 对比篮和已经提交的分析任务使用自己的对象快照，不随顶部切换而改变。

### 4.2 Tab 顺序与默认值

固定顺序为：`产业链全景 → 产业整体概况 → 产业资讯 → 产业发展历程 → 深圳产业现状`。默认进入产业链全景。顺序不是按旧 Demo 继承，而是本轮人工逐条确认的产品解释。

## 5. 跨模块边界

| 来源或去向 | 可携带内容 | 不可携带 / 不可承担内容 |
| --- | --- | --- |
| 产业查询 → 总览 | 有效 `chain_id`、来源查询摘要 | 企业查询字段、搜索结果分页和高级筛选状态不得进入总览 |
| 总览 → 产业查询 | 当前 `chain_id` 可作为查询定位条件 | 总览不得内嵌三种完整检索模式 |
| 总览 ↔ 系统共享对比篮 | 总览只通过共享状态传递 `chain_id`、名称、对象类型 `industry_chain` 和来源 route；用户从系统悬浮入口自行打开全局浮层 | 总览不得提供打开浮层按钮或写入打开信号，不得实现局部对比篮、第二个篮或浮层内部对象管理；不得把“关注”当作篮状态 |
| 对比篮 → 趋势诊断 / 区域评价 / 深圳决策 | 用户确认的产业链对象快照 | 总览不运行模型、不生成分析报告 |
| 图谱 / 指标服务 → 总览 | 已发布的图谱演进状态、主体清单、指标元数据和数据证据 | 前端不得直连 Python、Nebula、ODS/DWD 或硬编码算法说明 |
| 门户 CMS → 总览 | 已发布的介绍、阶段、里程碑、特色优势、集群效应、竞争地位内容 | 总览不得提供编辑、审核、发布操作 |
| 内部评审模式 | 每个 Frame 对应位置的需求追溯、指标、Mock、Pending 挂载 | 业务模式中不得显示需求编号、评审文案或统一悬浮评审面板 |
