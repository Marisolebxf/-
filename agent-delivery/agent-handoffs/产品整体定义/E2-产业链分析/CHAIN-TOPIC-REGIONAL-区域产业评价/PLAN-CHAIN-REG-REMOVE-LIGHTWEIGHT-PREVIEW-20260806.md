## 1. 问题

1. Demo / 五件套现有独立 **「轻量预览」** 按钮 +「预览不建任务、不入历史」合同。  
2. Bid `.2.3.1` 原文仅为：  
   > 系统实时计算综合指数，支持「所见即所得」调整。  
   **未**要求独立预览按钮，也**未**要求「预览任务」语义。  
3. 技术现实：拿产业链对象时**没有**综合指数；指数依赖 ADS 底分 / 模型查询；前端不能在无底分时「判定正式综合得分」。

结论：当前「轻量预览」= 过度产品推导，应撤掉；用更贴 Bid 的**配置区内联所见即所得**替代。

---

## 2. 目标语义（批准后成为合同）

### 2.1 Bid 直接落实（`direct_requirement`）

| 能力 | 合同 |
| --- | --- |
| 所见即所得 | 用户在配置区调整「计入指标 / 权重」时，**综合指数（及可选分维）随配置即时刷新** |
| 实时计算 | 指对**已就绪底分**按当前权重做重加权汇总，而非前端凭产业链 JSON 现算模型 |
| 正式结果 | 仍须点「生成分析」创建任务 → 过程壳 → 显式查看不可变结果 |

### 2.2 数据依赖（产品解释，须写进 TRACE）

```text
进入配置 / 对象组合合法
  → Java 按「产业 × 区域」拉取指标底分快照（ADS 批次或轻量查询；V1 Demo 可用固定 Mock 底分）
  → 配置区展示：工作集指标 + 权重 + 【即时汇总区】
  → 改权重 / 勾选计入 → 仅重算加权综合（及分维）；不建 task、不入分析记录
  → 「生成分析」→ 固化对象+模板+权重+底分/模型版本 → 正式不可变结果
```

| 禁止 | 原因 |
| --- | --- |
| 前端在无底分时显示「正式综合指数」 | 无数据源，属伪造 |
| 将「即时汇总」写成已完成正式分析 | 与任务/快照合同冲突 |
| 拿产业链主数据接口当作指数来源 | 对象身份 ≠ 区域指数模型输出 |

### 2.3 删除项

- 独立按钮「轻量预览」  
- 点击后才出现的「轻量预览」结果表区块  
- `previewing` 作为用户主动预览态（可保留内部 debounce 计算中态，不暴露为预览）  
- 评审挂点 `CHAIN-REG-F02-PREVIEW` / `PI-CHAIN-REG-LIGHTWEIGHT-PREVIEW`（废止或标 ⚪ 撤销）  
- AC / 文案中「预览不建任务」作为独立验收项（并入「即时汇总不建任务」）

### 2.4 替代 UI（F-REG-02 配置区）

建议在权重表下方 / 工具栏上方增加常驻 **「配置即时汇总」**（名称可定稿）：

| 元素 | 规则 |
| --- | --- |
| 综合指数（随权重变化） | 有底分且权重=100% 时显示数值；否则灰显原因 |
| 四维贡献（可选） | 商业力/技术力/学术力/支撑力（⚠️ QC11）随计入指标变化 |
| 多区域时 | 小表或条形：各区域综合指数随配置刷新 |
| 旁注 | 「基于当前底分快照的配置反馈，非正式分析结果」；评审 ⓘ → Bid「所见即所得」 |
| 底分未就绪 | 明示缺口 / Mock（评审态 🧪），禁用伪装正式分 |

工具栏仅保留：`[保存为个人模板]`（若已批）+ `[重置参数]` + `[生成分析]`。
