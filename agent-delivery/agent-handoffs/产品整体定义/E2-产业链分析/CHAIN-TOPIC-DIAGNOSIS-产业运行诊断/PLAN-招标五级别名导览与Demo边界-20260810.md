# PLAN · 产业运行诊断：招标五级别名导览 + Demo 边界说明

> **For agentic workers:** 可按下方任务清单顺序实现；默认强度 **ponytail full**。  
> **Goal:** 评审按招标五/六级名查找时能落到正确 Tab；同时一眼看清「Demo UI+Mock ≠ 正式算法」。  
> **触发：** 对方将「关键环节 / 瓶颈堵点」四叶子判为「原型无对应实现」（假阴性）。  
> **仓：** `demo-ui-topic`（UI）+ 本目录（评审话术/验收卡）  
> **Owner 建议：** frontend 改 UI；PM/产品补评审一页纸；不改 lumen 正式仓。

---

## 0. 现状（先对齐事实）

| 层 | 现状 | 问题 |
|---|---|---|
| 侧栏 L2 | 仅「产业运行诊断」 | 无「产业关键环节识别 / 产业瓶颈堵点识别」字样 |
| 页内 Tab | 「关键环节」「瓶颈堵点」（短名） | 与招标五级名不完全一致 |
| 页内 h1 | 已是招标五级名（`TAB_TITLES`） | 须先点进诊断页才看见 |
| 结果区标题 | 已用招标六级原文 | 须生成任务进结果才看见 |
| Demo 边界 Alert | 主要在**过程页** + `ReviewOnly` | 关评审模式 / 跳过过程页则看不见 |
| 产品定义 | E2 DIAGNOSIS 四件套已映射 Bid `.4`/`.5` | 评审入口未做「找得到」保障 |

**结论：** 能力在，发现路径弱；边界说明挂得太深。

---

## 1. 方案原则（铁律）

1. **不拆侧栏成四个平行 L2**（避免与「诊断工作台」产品归并决策冲突；DEC-CHAIN-DIAG-PACKAGE-SPLIT 已定拆包到诊断）。
2. **别名 = 导览，不是第二套页面**；深链仍指向现有 `?tab=key-link|bottleneck`。
3. **业务面少字、评审面写清**：导览可常显；技术/Mock/算法边界优先 `ReviewOnly` + MockBadge。
4. **六级叶子不另开菜单**；在导览表里列出「六级 → 所在 Tab / 结果区标题」。
5. **技术链「技术转化瓶颈堵点」禁止混挂**到本导览（防再次串模块）。

---

## 2. 推荐落地（两刀，半日级）

### 2.1 刀 A · 页内「招标能力导览」条（主刀）

**位置：** `IndustryDiagnosisPage` 工作台顶部，一级 Tab **下方**、当前 h1 **上方或紧贴下方**。  
**可见性：**

- **默认（业务/甲方演示）：** 折叠一行摘要，可展开  
  - 文案例：`本页承接招标「产业关键环节识别」「产业瓶颈堵点识别」；点 Tab 切换。`
- **评审模式（`ReviewOnly`）：** 默认展开完整对照表

**对照表字段（固定 4 行叶子 + 周期可选）：**

| 招标五级 | 招标六级 | 页内入口 | 深链 | 结果区应对标题 |
|---|---|---|---|---|
| 产业关键环节识别 | 全链路环节结构化展示 | Tab「关键环节」 | `?tab=key-link` | 全链路环节结构化展示 |
| 产业关键环节识别 | 关键环节智能标注与分析 | 同上 | 同上 | 同结果页「智能标注」区块 |
| 产业瓶颈堵点识别 | 多维度瓶颈综合分析 | Tab「瓶颈堵点」 | `?tab=bottleneck` | 多维度瓶颈综合分析 |
| 产业瓶颈堵点识别 | 瓶颈智能识别与归因建议 | 同上 | 同上 | 节点详情「瓶颈归因」 |

**交互：**

- 每行「打开」→ `changeTab` + 保留当前 `object_ids[]`（有对象则直达配置；无对象则空态引导对比篮，沿用现逻辑）。
- 可选第二按钮「看结果 Demo」→ 仅评审模式：带固定 demo `result_id` 进结果（避免评审还要手搓任务）。

**实现落点（建议）：**

| 文件 | 改动 |
|---|---|
| `industryDiagnosisModel.ts` | 新增 `DIAGNOSIS_BID_LEAF_GUIDE: { l5, l6, tab, resultTitle, note? }[]` 常量 |
| `IndustryDiagnosisPage.tsx` | 渲染 `DiagnosisBidGuide`（可同文件小组件，勿新仓） |
| `industryDiagnosis.css` | 导览条样式：左对齐、次级描边、不抢主按钮；遵循 Design.md 次级表面 |
| `tests/*diagnosis*` | 断言导览含四条六级原文 + `tab=key-link` / `bottleneck` |

**不做：** 改侧栏树结构（留给可选增强 2.3）。

### 2.2 刀 B · Demo 边界「三处同文案」（辅刀）

统一一条短文案（可拆 key_link / bottleneck 两句），挂到：

| 视图 | 挂载方式 | 文案要点 |
|---|---|---|
| 配置 draft | `ReviewOnly` Alert（info） | UI 承接 Bid 叶子；数据/标注为固定可回放 Mock；正式算法与口径待闭合 |
| 过程 process | 保留现有 Alert，措辞与上条对齐（去重复长句） | 已有，收敛文案 |
| 结果 result | `ReviewOnly` Alert + 现有 MockBadge | 结果为演示快照；「智能识别」≠ 线上推理 |

**建议定稿文案（可直接贴）：**

**关键环节：**  
> Demo 边界：本 Tab 承接招标「全链路环节结构化展示 / 关键环节智能标注与分析」。图谱与标注为固定可回放样例；高端化指数等因子权重正式口径待闭合。不以实时全网检索或生产算法完成态对外宣称。

**瓶颈堵点：**  
> Demo 边界：本 Tab 承接招标「多维度瓶颈综合分析 / 瓶颈智能识别与归因建议」。健康度与归因清单为固定可回放样例；五维阈值正式口径待闭合。不以生产时序计算或自动推理完成态对外宣称。

**实现落点：**

- `IndustryDiagnosisPage.tsx`：抽 `demoBoundaryCopy(analysisKey)`，draft / process / result 三处复用。
- 业务面（关评审模式）**不强制**常显长 Alert（防脏）；若 PM 要求甲方也看见，可改为一行 `Tag`：「演示数据」+ Tooltip 全文（仍短）。

### 2.3 可选增强（评审仍漏找时再做）

## 5. 对外回函模板（PM 可用）

> 四项叶子原型入口如下（Demo）：  
> 1）侧栏 **产业链分析 → 产业运行诊断**；  
> 2）页内 Tab **关键环节 / 瓶颈堵点**（页标题即为招标五级名）；  
> 3）结果区标题分别为「全链路环节结构化展示」「多维度瓶颈综合分析」等招标六级原文。  
>  
> Demo 边界：当前为可回放 UI + 固定样例数据，「智能标注 / 智能识别」非生产算法；正式因子与阈值口径闭合前不做完成态宣称。  
> 上线后将在诊断页增加「招标能力导览」对照表，避免按五级菜单名查找产生假阴性。

---

## 6. 明确不做

- 不为四叶子各开独立路由页/复制一套配置壳。  
- 不把 Mock 结果改成「像真算法」的假百分比进度。  
- 不在业务面堆砌 Bid/REQ/QC 编号（评审模式专用）。  
- 不改技术链瓶颈菜单文案挂到产业诊断。

---

## 7. 成功标准

1. 不熟悉系统的人只拿招标表，能在 **≤2 次点击** 从侧栏进到对应叶子结果区标题。  
2. 开评审模式时，配置/过程/结果任一视图可见 Demo 边界说明。  
3. 关评审模式时，无 `REQ-` / `Q05` / `Bid` 字样泄漏；MockBadge 仍可提示演示数据。  
4. 复评时「无对应实现」类假阴性可被导览表当场证伪。
