---

## 1. 决策（一句话）

**主方案 = S4 双轨（对外表现为发布快照）；V1 先按 S1a（不可变整图 JSON 包）落地。**

- 状态对比只比较同一 `chain_id` 下两个 **已发布** 历史状态（业务文案：基准时间 / 对比时间）。
- DWD 继续作为关系变更真源；**不**用「任意日历日 as-of 切整图」作为产品主路径。
- 不是 Analysis Job；同步读模型；前端不算 diff。

---

## 2. 为什么选它（摘要）

1. 贴 v5：快照 / diff 在 ADS，边 / 主体关系真源在 DWD，禁止 ADS 另建永久边真源。
2. 贴产品：要比的是「固定历史状态」，不是任意日切库；V1 允许 Pending、不宣称实时。
3. 贴现状：链 / 节点 SCD1，做不了可靠整图 as-of；发布包可立刻闭环。
4. 可演进：V1=S1a 整图 JSON → 生产仍保持「发布快照」语义，内容形态可升级为引用包，不换产品话术。

**明确不选作主方案**

| 方案 | 结论 |
| --- | --- |
| S2 纯 as-of | 节点无历史；改 SCD2 成本高；能力与产品下拉不完全同构 |
| S3 仅事件溯源 | 事件不全即黑洞；可作 diff/证据层，不替代快照目录 |
| 长期只 S1、永不双轨 | ADS 易沦为第二边真源，违 v5 |

---

## 3. 分层职责（钉死）

```text
日常变更 → DWD（链/节点 SCD1 当前版；边/主体 valid_from~valid_to）
     ↓ 显式「发布数据截至」
ADS 发布快照（对外唯一历史入口；不可编辑）
     ↓
状态对比 / 演进时间轴 /（默认）当前状态 只读 snapshot
```

| 层 | 存什么 | 不存什么 |
| --- | --- | --- |
| DWD 链 / 节点 | 当前属性 | 多版历史整图 |
| DWD 边 / `entity_rel` | 带有效期的关系账本 | 布局坐标、五类 diff 结论 |
| ADS 快照目录 + 内容 | `snapshot_id`、业务截至、nodes/edges/layout、可选主体集合 | 可写的「第二真源」边表 |
| ADS diff 事件 | 两快照间五类变化 + 证据状态 | 前端本地伪造的变化 KPI |

调用链：**FE → Java（只读 ADS；diff 可 Java 聚合或经 Java 调 Python）→ 禁止 FE 直连 Python / 禁止 FE 自算正式 diff。**

## 4. 防坑条文（本 DEC 强制）

### R1 · 当前状态与发布包一致

**默认**：业务态「当前状态」= 该链 **最新 `published` 快照**，与对比下拉同源。  
若 OPS / 评审需要看直播 DWD，必须单独入口或角标「含未发布变更」，**不得**默认同名「当前状态」无提示。

### R2 · V1 快照形态与节点历史

V1（S1a）：快照内容 = **不可变整图 JSON**（含节点属性、边、**布局坐标**、`layout_baseline_id`）。  
**禁止**用「只存 ID、回查当前 `industry_chain_node`」还原历史节点属性（SCD1 会穿帮）。  
生产若升级引用包：节点属性仍必须以包内物化为准，边可回查 DWD 当时有效行。

### R3 · 时点语义

发布作业的 **as-of 裁切时刻 ≡ 写入包内的 `effective_at`（业务截至）**。  
禁止「下拉显示 2024-06、实际按发布当日夜里裁切」。包内须自描述：`effective_at`、`generated_at`、`source_release_id`。

### R4 · 五类变化 V1 范围

| 类型 | V1 |
| --- | --- |
| 新增 / 退出 | **做**（结构键对称差） |
| 关系变化 | **做**（同边键属性变更） |
| 主体变化 | **可选**（仅当包内含企业集合或发布时 as-of 切 `entity_rel`） |
| 技术替代 | **正式不做**（无结构字段前禁止假归类） |
| 名称微调 / 排序 | **不进五类**；仅详情展示 |

无 `evidence_refs` → `confirm_status=pending`（待补证），不得进入「已确认变化」染色集。V1 允许全部 pending。

### R5 · Diff 配对与快照治理

- Diff **默认预计算 / 推荐比较「相邻已发布」**；用户选非相邻：可现场算，或提示建议选相邻版本（避免 O(N²) 与「大跃进」误解）。
- 快照 **只读**：禁止改包救火；变更只能 **新发一版** 或将旧版标 `deprecated`。
- 同一业务 `effective_at` 再发：默认 **新 `snapshot_id` + 旧版 deprecated**（或禁止重复；二选一在实现前由数据 Lead 钉死，推荐前者）。

### R6 · 布局基线

参与对比的两快照必须共享可对齐的 `layout_baseline_id`（或明确的继承规则）。  
不兼容 → **禁止对比**，保留最近有效单状态并提示重选。  
重算全图布局 = 新基线，旧包不与新基线混比。

### R7 · 对象范围

V1 状态对比 **禁止跨 `chain_id`**。  
产业全链路视图：按链分别发布 / 分别对比，或另定「视图级快照」（本 DEC 不冻结视图级；未定前全链路模式降级为单链或禁用状态对比）。

### R8 · 文案与评审

业务面禁用「快照」产品文案；用「数据截至 / 当前状态 / 状态对比 / 基准时间 / 对比时间」。  
`snapshot_id`、schema 版本、GAP 浮层仅 ReviewMode（与现 IA 一致）。

## 5. 对外读接口（契约方向，细节另稿）

| 接口 | 作用 |
| --- | --- |
| `GET .../snapshots?chain_id=` | 仅 `published`；按下拉「数据截至」 |
| `GET .../graphs/{snapshot_id}` | 整图（V1=包内 JSON） |
| `GET .../diffs?base=&compare=` | 五类事件；含 `confirm_status` |

缺口跟踪：`GAP-CHAIN-PANORAMA-SNAPSHOT-API`（OpenAPI 字段级另开任务）。

## 6. 阶段切分

| 阶段 | 做什么 |
| --- | --- |
| **V1** | 演示链 2～N 个 S1a 包；三只读接口；双图画布 + 五色图例；diff 全 pending；R1–R8 生效 |
| **生产** | 发布作业自动化；可选引用边回 DWD；相邻 diff 预计算；证据规则闭合后允许 confirmed；仍禁止 ADS 永久边真源 |

---

## 7. 非目标

- 不把状态对比做成 Job Runtime / `analysis-jobs`。
- 不把 Job Input/Result Snapshot 与图谱发布快照混表。
- 不要求本 DEC 解决节点改 SCD2。
- 不在本 DEC 冻结 CMS 发布按钮交互稿（体验另补；数据语义以本文为准）。
- 不宣称实时推送或任意日 as-of 整图。
