## 1. 模块目标与产品边界

围绕一个明确的 `industry_chain`，让政府、园区和企业用户即时完成：

1. 看清从原材料、生产、流通到终端市场的完整上下游结构；
2. 从宏观链条下钻某一环节，查看与该环节绑定的关联企业、主流技术路线和市场规模；
3. 以固定快照核对新增、退出、主体变化、关系变化和技术替代；
4. 通过标准服务合同消费图谱、主体清单和属性统计结果。

### 1.1 承接内容

- 产业链阶段、正式环节和正式上下游关系；
- 节点绑定的关联企业、主流技术路线和市场规模详情；人才、科研机构、服务机构和供应链是算法模型的多源输入，在没有独立展示需求前不扩成本页主分组；
- 按上下游环节或主体类型查询关系、主体清单和属性信息；
- 单点、双快照和时间轴三种阅读模式；
- 可解释的加载、空、错、无权和数据缺口状态。

### 1.2 不承接

- 产业周期、关键环节、瓶颈堵点、区域评价和深圳产业决策等七项独立分析；
- 门户“产业总览”及门户 `产业链全景` 页面改造；
- 图谱模板设计、人工录入、文件导入、关系维护、模型训练和后台发布；
- 算法 Bid 提到的 SDK、数据导出服务对应的前台按钮；未有独立产品定义前不新增导出；
- 企业画像复制、技术分析入口、报告生成、收藏、任务过程或任务撤回；
- 用前端 Mock、当前时间或本地 persona 推断正式数据、快照或权限。

## 2. 产品角色与权限解释

| 产品角色 | 原始依据 | 实现映射 | 数据与操作边界 |
| --- | --- | --- | --- |
| 政府科技主管部门决策人员 | 算法 Bid 明确政府部门用于布局和政策制定；IC-30 | `GOV × L3` | 在授权范围查看内部或敏感详情；不在业务页维护图谱 |
| 产业园区招商与促进人员 | 展示 Bid 明确产业链招商；IC-30 明确园区 | `INNO × L3` | 在园区授权范围定位环节、主体与技术路径 |
| 企业战略与业务人员 | 算法 Bid明确企业战略研判与协同发展；IC-30 | 企业认证后 `INNO × L2` | 只看公开、已授权或服务端脱敏内容 |

产品角色不等于 L0–L4 权限 persona。实现方式沿用企业分析：

- 产品文档先说明“谁、为什么使用”，权限服务再返回账号可见范围；
- 页面不从 Mock 用户、前端 persona 或 URL 自行推断权限和敏感字段；
- 无权动作保留位置并禁用说明，未授权敏感值不渲染；服务端失败关闭；
- L4 `OPS/SYS` 负责结构、字段、快照、权限与审计维护，不作为日常业务用户；
- 专题系统只做 PC 中屏，按钮能力遵循 `btn:common:view/filter/drill`；全景图谱不因算法 Bid 自动获得导出或维护按钮。

| 对象 | 稳定身份 | 职责 | 禁止解释 |

| `industry_chain` | `chain_id` + `parent_industry_id` | 所属产业链栏（level 1）；工作区主对象 | 不与第二对象同时进入工作区 |

| `enterprise` | 企业域稳定 ID / 统一社会信用代码 | 由关联企业卡打开共享企业画像抽屉，并复用同一企业主记录 | 不生成页面临时 ID，不复制或伪造企业画像 |
| `evidence` | `evidence_id` + `source_ref` | 解释关系、属性与变化 | 不以 UI 文案冒充来源 |

### 3.1 对象选择合同

1. 直接点击左侧“产业链全景图谱”且 URL 无有效对象时，系统补默认推荐产业 + 第一条可用 1 级链 + 最新数据截至并直入（`source=default`，秒开，不创建任务）；`F-PAN-01` 为页内「本次工作上下文」，**不**打开对比篮或 Modal。
2. 分析对象为可搜索单选 Select，placeholder「请选择产业」，选项仅 level 0；未选红校验「尚未选择分析对象」。所属产业链为可搜索 Select，选项为该产业下 level 1 链。数据截至为 Select，选项同源工作区「查看时间」。
3. 选择产业后**必须再选 1 级链**才能加载图谱；默认入口可自动带入第一条可用链以秒开。
4. 选择 `industry_chain`（查询/篮）时预填父产业并秒开该单链全景。
5. 对比篮或产业查询分发：链秒开；产业仅 1 条链时自动选链秒开；多条链只填产业，选链后点「开始分析」。篮分发不是本页换对象主路径。
6. 用户清空产业后保持空态（`source=cleared`），不静默写回默认。本页顶栏不出现「去产业查询」「打开对比篮」。
7. 未确认产业+链前，不加载图谱业务数据。改条件后图谱保持上次已应用结果，直到「开始分析」任务成功并点「查看分析结果」。
8. 改条件出现「开始分析」→ 系统任务 `chain:panorama:graph` → 分析过程壳 → 「查看分析结果」刷新图谱。本页无「查看报告」。

### 5.1 工作区硬规则

- 主画布绘制产业链阶段、正式环节和正式关系；断点作为关系完整性缺口，使用红色虚线、“断点”文本和可点击关系详情呈现，不得与“瓶颈关注”节点状态混用。节点下钻通过“环节详情三类直接要求 → 微观实体/属性”完成。
- 完整链不得因性能策略静默折叠、聚合或分页；超长链使用视口平移、适配和结构列表。
- 默认稳定左到右；单点、双快照、时间轴复用同一空间基线。
- 点击/Enter 环节节点必须进入与 `chain_id + node_id + snapshot_id` 绑定的深度详情，同时保留完整链、节点高亮、时间状态和视口；缩放、平移、适配、复位、全屏只改变视口。
- 复合环节若服务返回 `child_nodes/child_edges`，显示“下钻内部结构”并进入子链/工艺链；叶子环节直接进入三类详情。不要求所有环节都有子链，也不得用右侧 Tab 切换冒充子结构下钻。
- 返回上一级时恢复刚才进入的复合节点选中、高亮和详情，不回到未选状态。
- 图谱工具栏复用系统通用组件并固定在图谱左上角，页面不得自定义工具项或样式；演进图例固定在图谱左下角，五类变化同时使用不同语义色与中文文本，不只依赖颜色；证据未闭合统一使用可点击的系统 `IconExclamationCircle` +“待补证”，浮层回链 Q062 并说明缺口、当前处理、责任人和关闭条件。
- 时间轴仅在时间轴模式显示且位于图谱下方，与图谱保持 16px 间距；图谱区必须让出时间轴高度，使两者共同位于首屏可用空间内。顶部只保留模式和时间控制。页面工作区四周保留 16px 内边距。
- 业务界面不得使用“快照”作为产品文案：统一使用“数据截至 / 当前状态 / 状态对比 / 查看时间 / 基准时间 / 对比时间 / 演进时间轴”；`snapshot_id` 仅保留为服务字段或内部评审术语。
- 双状态比较在图谱可用宽度不足 1100px 时自动由横向切换为纵向；图谱区填满首屏剩余高度，状态标识位于左上工具栏下方 16px，图例为左下单列。
- `schema v1.0`、Q062“待补证”及其浮层均属于 ReviewMode，BusinessMode 必须 absent。
- 结构列表只提供当前发布状态的结构等价阅读，不支持动态演进；进入时停止播放、回到当前状态并隐藏状态对比、演进时间轴、变化图例及详情变化标识。
- 变化状态 Tag 与图例共享唯一颜色映射：新增绿、退出红、关系变化蓝、主体变化紫、技术替代橙。
- F-PAN-03 的职责概要与分组明细不得重复：主要投入/主要产出只在概要出现；主流技术路线必须显示为由前置投入、技术/工艺步骤与产出/应用组成的有向路径，不得把技术实体标签列表改名冒充路线。
- 左侧工作区外层只承担图谱/结构列表、下钻路径和时间轴的布局，不绘制额外卡片背景、边框或圆角；实际图谱/结构列表保留唯一内容容器，禁止多层容器嵌套。
- 右侧演进状态条位于下钻面包屑之后、概要与分组列表之前；演进类型只在该状态条显示一次，不得在概要重复。列表增长不得把状态条推到首屏之外。
- 状态颜色须可区分：演进“新增”为绿色，企业“在营”为深青色，环节“稳健环节”为青色；结构列表状态 Tag 按内容自适应宽度，不横向撑满卡片。
- 1920/1680 保留“控制—主视图—分析”三段关系；1440 将右侧详情转为宽度不小于 480px 的 Drawer，打开不重排图谱坐标。
- 导航 `selectedKey` 由 `/industry-center/panorama` 稳定决定，query 变化不得丢失菜单选中或转到技术链菜单。

## 6. 数据与服务边界

```text
页面 → 网关统一鉴权 → Java 聚合服务 /topic/v1/{element}/graph|metrics|analysis
     → ADS / 已登记模型服务 → Python 算法与 NebulaGraph/ES/数据层
```

- 前端不得直连 Python、数据库或 NebulaGraph，也不得在前端推断关系、统计和差异。
- 图谱服务至少返回稳定身份、阶段/环节、关系方向、主体引用、快照身份和证据引用；主体查询支持按环节与主体类别读取。
- 复合环节的内部结构合同使用 `child_nodes/child_edges`；未返回时视为叶子环节，前端不推断或生成子链。
- 图谱、主体清单和属性统计属于算法 Bid 的服务输出合同；具体 OpenAPI 字段尚未冻结时，V1 使用固定可回放响应并标明 Pending，不冒充生产接口。
- “属性统计与分析报告”是算法输出类型，不自动变成本页 KPI 卡或报告生成入口。

## 7. 指标与数据缺口

| 可见字段 | metric_id / 身份 | V1 处理 |
| --- | --- | --- |
| 市场规模 | `M_CHAIN_MARKET_SIZE` | 语义已登记但无正式数据源；按 Q056 值为空，显示“暂无正式数据源”，不以 Mock 数值替代 |
| 关联企业 | 企业稳定 ID 列表 | 卡片、企业画像抽屉和企业对比篮必须解析到同一企业主记录；无法解析的引用不渲染为可查看企业。若展示“企业数”必须引用 `M_CHAIN_ENTERPRISE_COUNT` 并等待本专题 readiness |
| 节点 / 关系 | `node_id` / `edge_id` 明细 | 不显示节点数、关系数 KPI；`M_CHAIN_NODE_COUNT`、`M_CHAIN_EDGE_COUNT` 仅登记为后续候选 |
| 动态变化 | 快照差异事件 ID | 按 Q062 固定双快照展示枚举和证据；不显示无 readiness 的变化数量 KPI |

指标语义已存在，不得再写“指标真源未建立”。当前缺口是：本专题缺少适用的 D1–D4 readiness 行、图谱与快照 API 未冻结、正式市场数据源缺失。
