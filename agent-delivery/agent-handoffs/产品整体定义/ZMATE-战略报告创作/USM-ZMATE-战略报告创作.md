## 模块：ZMATE 战略报告创作

在 **Zmate（AaaS）壳**上交付「战略咨询报告」的**生成与审阅工作台**：外壳跟德金交付节奏（项目轨 / Query / 专家·Skill / 任务时间线 / 报告阅读），研究内核跟乐之域辩论范式（澄清 → 正反辩论 → 辩论知识卷宗只读），数据经「专题切片 / 研判卡」接指标需求与（后续）三系统 MCP；报告按四层十组件装配，**禁止黑盒一步成文**；多 Agent 协作过程必须对用户可见。

**承接**：  
- 创作壳（项目轨、Query、报告类型、专家/Skill 安装≠本次使用）  
- 人在回路澄清确认（禁 autoRun）  
- Graph 协作可见过程（澄清 → Planner → 辩论∥切片 → Seeker → Writer/Assembler → 合规 Judge）  
- 指标需求四态与数据诚实（无假 live）  
- 报告装配与溯源；合规 Judge Default-FAIL  
- 内部评审模式页特有差异说明  

**不承接（非目标 · 本阶段）**：  
- 门户「研究报告 / 洞察报告 / 战略咨询报告」分类浏览、定向推送、成果库运营（另轨消费本工作台产出）  
- 从零自研 Agent 运行时 / 替代 Zmate  
- V1 强制完整辩论主舞台或指标进化闭环作为 11-30 阻断门禁（方案默认：辩论/切片进化为扩展点；Demo 仍须可点验协作过程）  
- Agent 静默改绿 D1–D4 或绕过人闸冒充 live  
- 把「辩论知识卷宗」与「专题切片 / 研判卡」混成同一产品对象  
- Demo 直连 lumen 正式后端或写入 `lumen-*`（D12）  
- 专题八域分析工作区共性页（`05-功能-战略分析`）≠ 本工作台  

**本轮决策（相对源需求的产品落位）**：  
- 父包挂靠推荐：**高端智库「战略咨询报告生成 / 智能写作」能力** + **专题切片数据轴交叉引用**（FDE 一屏计划 §6.2；门 1 前可再确认）  
- 旧 `ZMATE-FE-INTEGRATED-DEMO-L01` + L02–L08 Graph 脚手架：定义签收前视为**预研废稿候选**；签收后按 Wireframe 重做（默认废稿，局部复用仅在会签允许时）  
- 术语强制：`专题切片/研判卡` ≠ `辩论知识卷宗`；合规 Judge ≠ 战略胜负裁判

## 用户故事（As / Want / So that）

### US-ZMATE-RPT-01 在创作壳发起战略报告任务

作为政府科技主管部门、产业园区、投资机构或研究团队，我想在战略报告创作首页通过 **Query（自然语言命题）**、选择报告类型、选择项目文件夹（可选），并看到 **专家入口与 Skill 列表**，以便创建一条可跟踪的报告任务并进入工作区，而无需先理解 Graph 子站路由。

> 源需求对齐：SRS `战略咨询报告` · level5「战略咨询报告生成」—「生成战略报告」启动配置/新流程；核增「自然语言写作输入」。  
> 建设方案：§5① 创作入口；§9.1① 交付壳。

### US-ZMATE-RPT-02 区分「已安装 Skill」与「本次任务使用」

作为业务用户，我想在任务配置中明确看到哪些 Skill **已安装到 Harness**、哪些被勾选为 **本次任务启用**，以便复用专家能力包而不误以为「装了就会自动写进本报告」。

> 建设方案 §6.2.4；三方对照 §4 Skill「安装 ≠ 本次使用」。  
> **可测**：安装态芯片与「本次使用」芯片文案/状态分离；取消本次使用后时间线不得静默调用该 Skill。

### US-ZMATE-RPT-03 人在回路澄清确认（禁 autoRun）

作为研究团队或政府科技主管部门，我想在澄清阶段看到结构化澄清卡（对象 / 行业 / 范围 / 时间 / 受众 / 深度 / 决策等），逐步确认或修改，并在 **显式「确认需求」之前**看到右侧报告区处于「等待需求确认」、系统 **禁止 autoRun 自动跑完后续 Graph**，以便避免无效长跑与黑盒成文。

> 源需求：核增「用户意图确认与大纲澄清」— 输出大纲/细节供用户修改。  
> 建设方案 §9.1② 人在回路必验。

### US-ZMATE-RPT-04 绑定或生成研判卡（专题切片）

作为业务用户，我想在澄清确认后选定或生成一张 **研判卡（ScopeCard）**，对应一个 **专题切片（ThematicSlice / slice_id）**，并看到方面域摘要，以便后续指标需求与取数都挂在该切片上，而不是让 Agent 直接拿指标库当规划入口。

> 建设方案 §4 术语、§5③、§6.3；Agent 模式文 §5。  
> **本轮决策**：V2 起强制澄清落到 `slice_id`；Demo 至少一张研判卡可点验（可 Mock）。

作为业务用户，我想在任务协作枢纽（Graph Hub）看到当前阶段与下一站解锁条件，并按序进入：**澄清 → Planner →（辩论 ∥ 切片）→ Seeker → Writer/Assembler → 合规 Judge**，以便理解「谁在做什么、交接了什么制品」，而不是一条假进度条假装跑完。

## 场景 walkthrough（主路径 + 异常路径）

### 主路径 A · 创作壳 → 人闸澄清 →（最小）报告可读（V1 可独立走完）

1. 进入创作首页；输入 Query；选报告类型；可选项目文件夹；查看专家网格。  
2. 确认「已安装 Skill」列表与「本次使用」勾选分离（US-02）。  
3. 创建任务 → 进入工作区 / Graph Hub；左侧可见阶段。  
4. 进入澄清站：填写/调整澄清卡；右侧报告区显示「等待需求确认」；**确认前不得 autoRun**。  
5. 「确认需求」→ 绑定/生成研判卡（至少一张 Mock 卡可见）。  
6. （V1 最短）可跳过完整辩论，经 Planner 示意后进入 Writer 装配占位 → 完成后右侧出报告与基础溯源角标。  
7. 合规 Judge 最小规则：缺 id / 假 live 示例可触发 FAIL 提示。

### 主路径 B · 完整协作可见（Demo 必做可点验）

1. 同主路径 A 至确认需求 + 研判卡。  
2. Planner 站：看到任务树 / 组件开关摘要（不露思维链）。  
3. **并行入口**：辩论站 ∥ 切片站。  
   - 辩论：人控新一轮 / 引导轮 / 结束；卷宗三层可读写 → 结束后只读；文案标明无胜负裁判。  
   - 切片：方面域 + 指标需求四态 Mock；术语不得把卷宗叫成切片。  
4. Seeker：取数摘要写入证据包（串行模拟亦可）。  
5. Writer：须辩论结束（若启用）+ 取数齐备（或显式缺口）才生成；生成中右侧 **不出未完成正文**。  
6. Assembler：组件结构可见；关键数字旁 `slice_id`/`metric_id` 或缺口。  
7. Judge：Default-FAIL 用例可点验；PASS 后可读终稿。  
8. （V3 降级）对抗审查可为抽屉壳 + 静态问题清单，可注入反方卷宗论点示意。

### 主路径 C · 项目轨恢复

1. 从项目轨打开既有任务。  
2. 进入 Hub，停在上次未完成阶段（如澄清未确认）。  
3. 不得静默跳过已锁定人闸。

### 异常与降级路径

| 场景 | 页面行为 | 用户下一步 |
| --- | --- | --- |
| 未确认需求就期望出报告 | 右侧保持「等待需求确认」；无正文；无 autoRun | 完成澄清并确认 |
| 未结束辩论却要求成文（启用辩论时） | Writer 入口锁定或说明条件未满足 | 结束辩论或显式跳过（若产品允许且标记缺口） |
| 指标四态均为缺口仍要「live」数字 | Judge FAIL；禁止假绿 | 接受 `known_gaps` 交付或补数 |
| 把辩论知识卷宗与专题切片混称 | 文案走查不通过；评审模式可挂术语对照 | 修正文案 |
| 研究区出现「胜负 / 采信方」Judge | 不符合合同 | 仅合规闸 +（V3）对抗审查 |
| 安装 Skill 被当成已启用 | 阻断或明显警示 | 显式勾选本次使用 |
| 单页一键跑完全链假进度 | 禁止 | 分站 + 人闸 |
| Mock 关闭却用 fixture 填数 | 禁止（`USE_MOCK=false` 零 fixture） | 保持空态/错误态 |
| 加载 / 接口失败（真链阶段） | 错误条 + 重试；不伪造成功报告 | 重试或带着缺口交付 |
| 无导出权限（真链阶段） | 下载失败关闭；报告仍可读 | 申请权限 |
| 门户入口期望在本工作台完成推送 | 不承接；引导门户另轨 | — |
