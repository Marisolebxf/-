## 1. 模块边界

- **解决的问题**：帮助政府、园区和投资机构从全国企业库发现深圳招引对象，从深圳本地企业库发现梯度培育对象，并基于可追溯的规则配置生成两类结果名单及推荐依据。
- **承接内容**：招引/培育候选管理、视图内规则配置、异步生成任务、结果名单、推荐依据、详情拆解、历史生成与内部评审追溯。
- **不承接内容**：企业全库搜索、对比篮暂存、企业评估、供应链/痛难点诊断、全局模型模板维护、自动生成完整一企一策、服务派单、独立分析导出菜单。
- **对象边界**：候选名单是待分析对象池；招引推荐名单和建议培育名单是任务快照下的分析结果，两者不得混称或互相覆盖。

## 2. 产品角色与入口

| 产品角色 | 需求证据 | 入口 | 核心目标 |
| --- | --- | --- | --- |
| 政府招商与产业管理人员 | 企业分析面向政府；E-26 服务精准招商 | 企业分析 → 引育推荐；企业总览/查询/画像/对比篮带入 | 形成可解释的招引推荐名单，支撑招商落地和补链强链 |
| 产业园区运营或企业服务人员 | 企业分析面向园区；培育模型服务园区管理机构 | 企业分析 → 引育推荐；风险洞察带入培育候选 | 识别本地潜力企业、所需支持与差异化培育建议摘要 |
| 投资机构产业研究人员 | 企业分析面向投资机构；培育模型服务投资平台 | 企业分析 → 引育推荐；查询/画像带入 | 复核推荐依据、成长潜力与合作价值，辅助资源配置 |

> 行业协会在算法库中是适用对象，但当前企业分析产品总述未将其列为直接使用角色；本包不将其扩写为第四类主角色，也不影响算法能力后续适用。

## 5. 两类视图的业务边界

| 规则 | 招引推荐 | 培育推荐 |
| --- | --- | --- |
| 对象池 | 全国企业库；不硬排除深圳企业 | 深圳本地企业库 |
| 候选名称 | 招引候选名单 | 培育候选名单 |
| 结果名称 | 招引推荐名单 | 建议培育名单 |
| 业务目标 | 招商引入、落地、补链强链 | 梯度培育、精准扶持 |
| 固定主维度 | 技术匹配度、成长性、区域适配性 | 技术壁垒、市场增速、团队背景；补充所需支持识别 |
| 详情价值 | 核心优势、合作价值、招商对接建议 | 发展瓶颈、所需支持、一企一策建议摘要 |
| 禁止 | 普通用户自建公式；把候选直接当结果 | 风险排行榜；完整政策包、正式一企一策报告或服务派单 |

## 6. 任务与状态模型

```text
配置草稿
  └─ 提交 → 待开始 → 企业库筛选 → 指标计算 → 推荐依据生成 → 已完成
                                      ├─ 失败 → 保留配置 → 重试 / 按此新建
                                      └─ 已取消 → 保留任务摘要
```

- 每次生成创建不可变任务快照，记录对象池、筛选条件、模板版本、二级指标、权重、阈值、数据批次和提交人权限上下文。
- 离开页面不取消后台任务；历史生成和个人资产中心读取同一任务源。
- 结果只属于该任务快照；修改配置必须创建新任务，不覆盖历史结果。
- `Q015` 未闭合前，指数、阈值和权重均显示“待语义确认 / DEMO”，不得表现为正式口径。

| 来源或去向 | 可携带内容 | 不可携带 / 不可承担内容 |

| 企业评估 | 可作为详情证据引用的已授权评估摘要 | 不把评估评分直接改写为推荐指数 |
| 企业画像 | 从结果名单打开对象详情并保留返回上下文 | 画像不承接任务状态或全量推荐依据 |

| 个人资产中心 | 任务 ID、结果状态、可选共享导出资产 | 不重新计算、编辑或删除审计要求保留的任务 |
| 通用导出 | 可选输出当前结果名单摘要并继承权限、脱敏、水印和审计 | 不恢复独立“分析导出”菜单；不作为 E-26/E-27 页面验收前置 |

## 8. 路由与上下文契约

- 权威业务路由：`/enterprise-center/attraction`。
- 旧路由 `/enterprise/recommendation` 仅作为兼容入口，重定向后保留 `tab`、候选类型和来源上下文。
- 候选带入最小参数：`enterprise_codes[]`、`candidate_type=attraction|cultivation`、`source`、`return_context_id`。
- 任务恢复最小参数：`task_id`；详情另带 `enterprise_code`。
- 同一 `return_context_id` 往返时恢复候选筛选、当前选择和滚动位置；新进入只恢复持久候选名单，不恢复旧临时选择。

## 9. 指标、数据与架构

- 指标：`M_ENT_ATTRACTION_INDEX`、`M_ENT_CULTIVATION_INDEX`、`M_ENT_GROWTH_POTENTIAL`、`M_ENT_INDUSTRY_MATCH_SCORE`、`M_ENT_POLICY_MATCH_SCORE`、`M_ENT_RECOMMEND_COUNT`。
- 上述推荐相关指标除已登记状态外均受 `Q015` 阈值/权重影响；UI 必须展示语义状态，不得前端自行计算正式指数。
- 前端经网关与 Java 聚合服务调用内部推荐能力，不直连 Python、数据库或 ADS。
- 全局规则模板由维护管理发布并版本化；历史任务保留当时模板和数据批次。
- 敏感名单、来源与联系方式遵循字段级权限、脱敏、水印和审计；权限不足不等于真实空数据。

## 10. 与范围真源的差异

| 原始功能 | 当前归位 / 重组 | 范围处理 |
| --- | --- | --- |
| E-26、E-27 共用旧 `/enterprise/recommendation` | 一个二级菜单内拆为两个独立视图，当前路由 `/enterprise-center/attraction` | 两叶子均保留并分别追溯，不静默合并 |
| 原文“名单/优选清单” | 区分候选对象池与任务结果名单 | 防止外部加入动作冒充推荐分析 |
| 算法库支持报告与数据导出 | 页面结果与名单管理为核心；报告/文件导出交给通用结果输出能力按需增强 | TRACE 保留算法来源差异，不恢复独立菜单 |
| 培育建议 / 一企一策 | 只输出依据和建议摘要 | 不扩展为完整政策包、工单或正式报告 |
| 动态模型训练与更新 | 业务页只调本次参数；全局模板版本与训练归维护/算法能力 | 不把业务页做成算法建模平台 |
