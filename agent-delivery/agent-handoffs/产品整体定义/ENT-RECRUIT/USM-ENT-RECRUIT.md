# USM-ENT-RECRUIT.md

> **模块**：引育推荐（E-26 / E-27）
> **版本**：v1.0 · 核心产品包待评审
> **体验 Owner**：高颖
> **交付层级**：medium · Track-MS
> **范围真源**：`REQ-ENT-006`、`REQ-ENT-007`、`catalog-topic-enterprise.yaml#E-26/#E-27`、企业招引/培育推荐算法模型

## 模块定位

引育推荐把“发现候选企业”和“形成可解释的推荐结果”连成一条任务流。招引推荐面向全国企业库，为深圳招商引入形成招引推荐名单；培育推荐面向深圳本地企业库，为梯度培育形成建议培育名单、所需支持和一企一策建议摘要。候选不是结果，风险、评估或外部标签也不能自动替代推荐任务。

## 目标用户角色

| 产品角色 | 角色依据 | 需要完成的业务任务 |
| --- | --- | --- |
| 政府招商与产业管理人员 | 企业分析原文面向政府；E-26 服务深圳招商引入 | 配置招引条件、生成并复核推荐名单、查看合作价值与招商建议 |
| 产业园区运营或企业服务人员 | 企业分析原文面向园区；培育模型服务园区管理机构 | 识别园区或辖区潜力企业、确认所需支持、形成培育建议摘要 |
| 投资机构产业研究人员 | 企业分析原文面向投资机构 | 查看推荐依据、成长潜力和风险/评估辅助证据，支持资源配置 |

> GOV / INNO / THINK、L0–L4 和 Mock 用户只用于后续权限映射，不替代上述产品角色。行业协会是算法库明确的适用对象，但不是本轮企业分析主使用角色。

## 用户故事

### US-ENT-RECRUIT-CANDIDATE 管理候选对象

作为政府或园区企业服务人员，我想把查询、画像、重点企业分析、对比篮或风险洞察中的企业加入明确的招引/培育候选名单，以便在正确对象池中继续推荐分析。

- 加入动作必须选择 `招引候选` 或 `培育候选`，不使用泛化“推荐名单”。
- 重复对象不重复写入，反馈新增、重复和不符合对象范围的数量。
- 培育候选只接受深圳本地企业；招引候选面向全国且不硬排除深圳企业。
- 加入完成后不自动生成推荐指数、理由或结果，也不强制跳转。

### US-ENT-RECRUIT-ATTRACTION-CONFIG 配置招引推荐

作为政府招商与产业管理人员，我想围绕深圳产业方向配置招引规则，以便从全国企业库筛选适合落地、补链强链的企业。

- 选择重点产业方向、技术领域/产业链环节、来源区域和企业特征。
- 固定主维度为技术匹配度、成长性、区域适配性；支持主维度调权重、二级指标勾选和场景模板。
- 高成长性、关键技术型、隐形冠军、专精特新作为筛选标签或加分因子进入依据。
- 普通用户不能创建公式或修改全局模板；`Q015` 未闭合时权重和阈值显示待确认。

### US-ENT-RECRUIT-CULTIVATION-CONFIG 配置培育推荐

作为园区运营或企业服务人员，我想按深圳辖区、园区和企业阶段配置培育规则，以便识别值得梯度培育且需要精准支持的本地企业。

- 选择深圳产业方向、辖区/园区/企业范围、企业阶段/类型和潜力识别条件。
- 固定主维度为技术壁垒、市场增速、团队背景，并补充所需支持识别。
- 支持最低潜力阈值、主维度权重、二级指标和场景模板，不支持普通用户自建公式。
- 可引用痛难点诊断作为辅助依据，但不得把风险或痛点自动转成建议培育结论。

### US-ENT-RECRUIT-PROCESS 跟踪生成任务

作为提交任务的用户，我想在离开页面后仍能跟踪生成进度并处理失败，以便不因长时计算丢失工作。

- 提交时冻结候选对象、规则参数、模板版本、数据批次与权限上下文。
- 过程阶段为任务创建、企业库筛选、指标计算、推荐依据生成、名单生成完成。
- 页面只展示服务端证明的阶段和状态，不使用假百分比或前端计时冒充算法进度。
- 支持后台运行、取消、失败重试和“按此配置新建”；历史任务不被覆盖。

### US-ENT-RECRUIT-ATTRACTION-RESULT 复核招引名单

作为政府招商与产业管理人员，我想快速筛选招引推荐名单并查看企业推荐依据，以便确定需要进一步招商对接的目标。

- 列表展示招引推荐指数、匹配度、推荐理由、核心优势标签和关键指标。
- 详情展示技术匹配度、成长性、区域适配性拆解、合作价值与招商对接建议。
- 追溯层记录 `REQ-ENT-006`、对象池、配置、权重、数据批次和生成时间，仅在评审/审计模式显示。
- 指标缺失、低可信或待确认时明确说明，不把缺失值当成零或正式结论。

### US-ENT-RECRUIT-CULTIVATION-RESULT 复核培育名单

作为园区运营或企业服务人员，我想查看建议培育名单、所需支持和建议摘要，以便确定后续精准扶持方向。

- 列表展示培育推荐指数、潜力、所需支持、建议理由和企业阶段。
- 详情展示技术壁垒、市场增速、团队背景、发展瓶颈、所需支持与一企一策建议摘要。
- 一企一策只提供制定依据和摘要，不自动生成完整政策包、正式报告或服务派单。
- 风险洞察只可作为辅助证据，主追溯保持 `REQ-ENT-007`。

### US-ENT-RECRUIT-HISTORY 恢复历史任务

作为重复开展招商育商分析的用户，我想找回历史配置和结果，以便复核当时结论或基于旧配置创建新任务。

- 历史记录展示推荐类型、配置摘要、模板版本、数据批次、时间、状态和结果数。
- 已完成任务打开不可变结果；调整任何条件都创建新任务。
- 无权限、对象失效或批次不可用时保留任务摘要并说明原因。
- 模块历史与个人资产中心读取同一任务源，不复制或重新计算结果。

## 主路径 walkthrough

### A. 从企业查询加入招引候选并生成名单

1. 用户在企业查询结果中选择企业，执行“加入招引候选”。
2. 系统按企业标识去重写入，提示新增与重复数量，不自动生成结果。
3. 用户进入 `/enterprise-center/attraction?tab=attraction&view=config`，看到已加入候选和来源摘要。
4. 用户选择深圳重点产业方向、技术领域/链位、来源区域、企业特征和规则模板。
5. 用户调整固定主维度权重；若 `Q015` 未闭合，页面显示“待语义确认 / DEMO”。
6. 用户提交后进入生成过程；任务在后台依次更新可证明阶段。
7. 任务完成后进入招引推荐名单，用户按匹配度和优势筛选对象并打开详情。
8. 用户查看合作价值、招商对接建议和内部追溯信息，再返回名单继续复核。

### B. 从风险洞察加入培育候选并生成建议培育名单

1. 用户在痛难点结果中主动选择企业并执行“加入培育候选”。
2. 系统只将企业作为候选来源，不因痛点自动判断其应被培育。
3. 用户进入培育推荐配置，系统校验深圳本地对象范围；不符合对象逐项说明。
4. 用户选择产业方向、辖区/园区、企业阶段、支持类型和潜力规则。
5. 用户提交并等待异步任务完成。
6. 建议培育名单展示潜力、所需支持和建议理由；用户打开企业详情查看维度拆解。
7. 页面将痛难点标为辅助证据，并输出一企一策建议摘要，不生成完整方案或工单。

### C. 恢复失败或历史任务

1. 用户从历史生成打开失败任务，看到失败阶段、错误编号和保留配置。
2. 用户选择“重试”或“按此配置新建”；系统不覆盖原任务。
3. 新任务创建后，用户可离开页面并从历史或个人资产中心恢复。
4. 已完成历史任务始终展示当时的规则模板、权重和数据批次，不跟随当前全局模板变化。

## 异常与降级路径

| 场景 | 页面行为 | 用户下一步 |
| --- | --- | --- |
| 候选为空 | 保留配置框架，提示从企业查询/总览/画像/对比篮加入，或使用合法的模型扫描对象池 | 前往来源页或选择规则扫描 |
| 培育候选含非深圳企业 | 逐项标记“不在深圳本地对象池”，不静默删除也不纳入提交 | 移除或改加入招引候选 |
| 重复加入 | 提示新增与重复数量，保留原候选和来源集合 | 继续配置或查看候选 |
| 权重不满足校验 | 阻止提交并指出需补齐或降低的维度 | 调整权重；不自动偷偷归一化 |
| Q015 未闭合 | 指标与默认值显示待语义确认/DEMO，禁止宣称正式口径 | 可用于内部 V1 评审，不可作为门 1 完整闭合证据 |
| 数据不足/低可信 | 对具体指标标记缺失、低可信或无源，不显示为 0 | 查看可用依据、调整对象或等待数据 |
| 任务运行中离开 | 后台继续；历史入口显示运行状态 | 返回恢复或取消 |
| 任务失败 | 保留失败阶段、错误编号和配置 | 重试或按此配置新建 |
| 任务取消 | 保留任务摘要和审计记录，不生成结果名单 | 按此配置新建 |
| 无执行权限 | 配置可按权限展示只读/锁态，提交禁用并说明所缺能力 | 申请权限或返回 |
| 无敏感字段权限 | 名单仍可见授权摘要，敏感字段脱敏且说明 | 按授权继续复核 |
| 历史对象失效 | 保留任务与对象占位，说明对象不可用 | 查看其余对象或按可用对象新建 |
| 通用导出未启用 | 不显示文件导出，不影响页面名单与依据验收 | 使用页面结果或等待能力启用 |

## 与范围真源的差异说明

| 原始功能 / 章节 | 当前 IA / 页面归位 | 是否影响范围 | TRACE 动作 |
