## 2. 模块边界

### 2.1 解决的问题

企业评估把一个或多个企业对象、评估模式、指标模板、权重和可用数据组合成可复现的评估任务，生成有数据覆盖度和可信度说明的技术力、商业力或综合竞争力结果，并支持历史恢复与评估报告。

### 2.2 承接内容

- 仅从对比篮新增企业对象；评估页可移除本次对象，但不承担企业搜索或新增。
- 技术力、商业力、综合竞争力三种评估模式。
- 系统模板、个人模板、当次自定义配置；指标选择与权重校验。
- 数据覆盖、关键指标缺失和可信度预检。
- 正式结果、差距 / 短板、排名或矩阵等适量可视化。
- 独立评估生成过程、评估历史、由既有配置再建任务、个人中心同源任务投影与后台报告任务。
- 指标说明业务抽屉；内部评审模式在同一抽屉追加指标元数据。
- 内部评审模式的需求追溯展示。

### 2.3 明确排除

- 不把对比篮嵌入评估页，不反向改写或清空对比篮。
- 不在评估页提供企业搜索、固定候选池或本地新增；本页移除仅影响当前配置、不回写对比篮，补充对象须返回对比篮。
- 不承接供应链关系、风险洞察、企业发展痛难点结果。
- 不承接招引 / 培育结论、一企一策或候选名单管理。
- 普通评估用户不维护全局模板、默认权重、模型参数或数据批次。
- 配置页、企业总览和对比篮不生成评估报告。
- 不新增第四种业务模式，不用复杂雷达图承载三家及以上企业。

## 6. 核心任务流

1. 接收对比篮对象，记录 `source` 与 `return_context_id`；无对比篮对象时引导用户先进入对比篮选择，并按当前 `mode` 预选对比篮的 `analysis_type`。
2. 选择模式；技术力 / 商业力至少 2 家，综合竞争力至少 1 家。
3. 从分组模板选择器加载系统模板、当前模式下已保存的个人历史模板或当次自定义配置；个人模板可在个人中心查看并带回复用。
4. 校验指标、整数权重、对象权限、字段可见性、数据覆盖和模型条件。
5. 用户明确触发“生成评估”；系统按“模式 + 企业数量 + 生成时间”生成只读 `task_display_name`，并固化对象、模式、`template_id` / 版本、已选指标、整数权重、可信度、算法版本与权限范围，创建任务并进入独立生成过程页；当前 DEMO 的数据批次未接入，快照不得写入或展示伪造批次值。
6. 生成过程页按任务提交、权限与配置校验、企业数据汇聚、指标计算、可信度与可比性校验、结果图表组装六阶段展示；只显示真实阶段和已用时间，不伪造百分比，允许离开后从最近评估或个人中心恢复。
7. 完成后查看结果；结果页可切换单企诊断或从任务对象集中选择企业 A / B，观察视角变化不修改任务快照、综合得分或报告指纹。
8. 返回配置派生新任务或提交后台报告任务；报告完成后可下载与当前不可变任务快照绑定的当前报告。

## 8. 指标、数据与可信度

### 8.1 指标集合

- 技术力：`M_ENT_TECH_POWER_SCORE`、`M_ENT_TECH_RANK`、`M_ENT_PATENT_GRANT_COUNT`、`M_ENT_RD_INVESTMENT_RATIO`。
- 商业力：`M_ENT_BUSINESS_POWER_SCORE`、`M_ENT_REVENUE_LATEST`、`M_ENT_REVENUE_GROWTH_RATE`、`M_ENT_PROFIT_MARGIN`、`M_ENT_MARKET_SHARE`。
- 综合竞争力：`M_ENT_COMPETITIVENESS_SCORE`、`M_ENT_COMPETITIVENESS_RANK`、`M_ENT_SHORTBOARD_COUNT`、`M_ENT_INNOVATION_INDEX`。

13 项均已有指标种子卡；当前仅专利授权量、最新营业收入具备可直接使用的数据源，10 项待算法 / `Q014` 闭合，市场份额受 `Q019` 阻塞。`M_ENT_BUSINESS_POWER_SCORE` 的种子卡当前误指向 E-23 / 需求 3.3，应由指标与合规 Owner 校正到 E-24 / 需求 3.4，产品包只登记差异，不静默改口径。

### 8.2 数据与可信度规则

- 缺失数据不得按 0 计算；只按可用指标重算，并降低可信度。
- 高：覆盖度 ≥ 90% 且无关键指标缺失；中：70%～89% 或少量关键指标缺失；低：50%～69% 或多个关键指标缺失。
- 覆盖度 < 50% 或全部关键指标缺失时不可生成正式结果。
- 多企业比较逐企业给出可信度；覆盖结构不同需提示可比性风险。
- 雷达图缺失点显示缺失，不落到 0；差距分析只比较共同可用数据。
- 正式链路固定为 `前端 → 网关 → Java 聚合 → 已登记算法 / ADS`，前端不得直连 Python、数据库或自行计算官方分数。
- `data_batch` 是 FULL 任务快照字段；当前 DEMO 数据批次未接入，只能在内部评审模式显示“数据批次未接入”，业务模式不展示该缺口，不得生成、保存或写入报告指纹 `mock_20260618` 等伪造批次值。

### 8.3 指标说明契约

- 配置页点击指标说明“查看”打开业务抽屉，不跳离当前评估配置。
- 业务模式展示指标名称、衡量目的、所属维度、业务口径、单位、指标方向、适用范围、数据状态与缺失影响。
- 内部评审模式在同一抽屉追加 `metric_id`、公式、源表、源系统、更新频率、版本和 `Q014 / Q019`；这些内部字段在业务模式不渲染。
- 指标说明只解释指标，不修改选择、权重、对象集或任务快照。

## 9. 模式与可视化归位

任务名称与个人模板没有继承关系：个人模板名称只标识可复用的指标 / 权重配置；任务展示名只在生成评估时由系统创建。结果页统一为“任务 KPI → 左侧解释型分析 + 右侧全对象综合排名 → 整行诊断 → 报告”。右侧排名只读取任务快照中的模式综合得分，不得使用第一个已选指标代替综合得分。三家及以上仍全部进入排名，但任何雷达最多同时呈现两家企业曲线。

| 模式 | 左侧解释型分析 | 右侧全对象 | 下方诊断 | 对象切换 |
| --- | --- | --- | --- | --- |
| 技术力 | 0～100 归一化技术维度雷达；不混入原始专利数、百分比或排名 | 技术力加权排名 | 专利、研发投入等原始指标、集合均值、差距、技术优势与短板 | 2 家直接对比；≥3 家默认前两名并可从对象集重选 A / B |
| 商业力 | 营业收入、收入增长率、利润率分指标对比，各自保留单位；不使用无来源雷达或营收 / 专利双轴混图 | 商业力综合排名仅在主排名图展示一次 | “商业诊断与明细”合并经营指标、综合得分、数据可信度和诊断结论；有连续数据时提供营收趋势 | 全部对象进入主排名与诊断明细；不再另设重复排行表 |
| 综合竞争力 | 单企诊断为当前企业 vs 对象集均值 / 领先值；双企对比只显示 A / B 两条竞争力曲线 | 综合竞争力排名 | 技术力、商业力、成长性、创新度、抗风险等维度差异、优势与短板 | 1 家单企诊断；2 家直接对比；≥3 家支持单企诊断 / 双企对比切换 |

技术雷达的正式维度序列、归一化规则与每轴 `metric_id` 受 `Q014` 约束；未登记前只能作为明确标注的 DEMO 展示，不能成为官方评分依据。商业营收趋势仅在任务快照含连续年度数据时出现；当前无连续数据时显示缺失状态，不补造趋势。市场份额继续受 `Q019` 阻塞，不进入得分、图表或短板计算。

## 10. 评审模式需求展示

- 顶部“企业评估”评审标题及其 `TraceInfoIcon / traceId` 只在内部评审模式出现，业务模式整组隐藏；左侧菜单和三种模式标签仍承担业务定位。
- 评审标题聚合 `REQ-ENT-003 / 004 / 010`；配置区按当前模式绑定对应 REQ。
- 数据覆盖区和各结果子模块标题绑定具体来源、原文摘要、当前落位及“直接承接 / 产品化展开”关系；报告沿用当前模式 REQ。
- 弹层字段：trace id、来源 `md_ref` 与叶子、原始标题 / 摘要、当前解释、能力 → 子功能 → 当前区块、状态 / 层级 / 开放问题、Story / IA / Frame。
- 只在页面标题、模式配置标题、数据覆盖标题、结果子模块标题和报告标题挂载；不在 KPI 卡、按钮、表格行、指标明细或分页器上重复挂载。
- 最近评估、对比篮带入、后台报告任务是派生流程，只追溯 Decision / Story，不伪造需求叶子。
- 指标口径使用独立 `MetricSpecCard`，不与需求追溯图标混用。
- 评审模式不绕过权限，不暴露未授权敏感值。

## 11. 报告与历史

- 只有结果页可创建评估报告；按当前模式生成技术力、商业力或综合竞争力报告。
- 默认 PDF；Word 为后续能力。任务状态：提交、数据准备、评分计算、图表生成、报告组装、完成 / 失败。
- 同对象、模式、模板版本、权重、数据批次与权限范围形成报告指纹；同指纹的处理中或有效报告复用后台任务。
- 报告完成态提供“下载当前报告”；下载内容必须来自当前结果任务快照并关联当前 `task_id`，不得下载其他任务或未完成报告。
- 资产中心保存状态和下载记录；报告受角色、字段分级、对象上限、脱敏 / 审批和审计控制。
- 最近评估收录用户明确提交后的处理中、已完成和失败任务；仅保存配置不产生任务。任务状态改变仍更新同一记录，不扩展为团队协作、审批流、复杂版本比较或通用任务管理。
- 最近评估与个人中心“评估任务”读取同一任务源；个人中心只是跨场景资产入口，不复制第二份任务、状态或报告计数。

## 12. 与既有材料的差异

| 既有口径 | 本次归位 |
| --- | --- |
| `/enterprise/capability` 与 `/enterprise/competitiveness` 分散路由 | 统一到 `/enterprise-center/evaluation` 路由族，以 `mode` 保留三个独立需求叶子 |
| 旧权限矩阵将 L2 权重设为只读 | 以 Decision 101 为准：L2 可当次调权并保存个人模板，但不得改全局模板 |
| 旧设计偏横向分栏 | 中屏采用纵向分区工作台；对象、模板、指标、数据预检顺序向下展开 |
| 仅政府 / 园区 / 投资机构 | 补入原需求明确的行业协会和企业自身，并绑定用途与权限边界 |

| 三家以上统一改成总分条形图并在下方重复企业排名 | 保留全对象综合排名；左侧改为最多两家曲线的解释型分析，下方只承担指标诊断，不重复企业排行 |
| 结果页按第一个已选指标排序 | 综合排名必须读取任务快照中的模式综合得分；指标、权重与模板快照随任务固化 |
| 旧商业力将营收与专利混画，并用多企业趋势替代排名 | 专利归技术力；商业力使用带原单位的经营指标对比、全对象综合排名及有数据才出现的营收趋势 |
| 生成过程仅由按钮等待或弹窗表达 | 进入独立 `view=processing` 过程页，展示六阶段、已用时间及离开恢复 |
| 指标说明只显示技术元数据或无查看落位 | 业务抽屉先解释业务语义，评审模式追加内部元数据，二者严格隔离 |
| 最近评估与个人中心各自保存任务 | 两处读取同一任务源，个人中心不复制任务状态 |
| Demo 使用不存在的数据批次 | 当前仅标记“数据批次未接入”，禁止生成 `mock_20260618` 等伪造值 |
