## 2. 模块边界

### 2.1 解决的问题

企业评估把一个或多个企业对象、评估模式、指标模板、权重和可用数据组合成可复现的评估任务，以可追溯方式承接 Bid 中技术力、商业力和综合竞争力的指标、维度、评分、排名、对比、差距/短板、趋势与报告要求。已定义项进入产品落位，未定义项保留显式 GAP，不以“已映射”冒充“已满足”。

### 2.2 承接内容

- 仅从对比篮新增企业对象；评估页可移除本次对象，但不承担企业搜索或新增。
- 技术力、商业力、综合竞争力三种评估模式。
- 系统模板、个人模板、当次自定义配置；指标选择与权重校验。
- 商业力模式的评价行业上下文、行业预览配置与自定义配置冲突确认；当前 DEMO 可用确定性模拟配置预览交互，但不把模拟映射声明为正式行业标准。
- 数据覆盖、关键指标缺失和可信度预检。
- 正式结果、差距 / 短板、排名、趋势、行业对标或矩阵等适量可视化；缺少正式数据或算法的直接要求保留入口与 GAP，不以产品化图表替代。
- 独立评估生成过程、评估历史、由既有配置再建任务、个人中心同源任务投影与后台报告任务。
- 指标说明业务抽屉；内部评审模式在同一抽屉追加指标元数据。
- 企业名称以中文为主并预留英文名称字段；涉及 K-O7 外部采购数据时必须展示合规可用状态，不得使用未授权样例冒充正式数据。
- 内部评审模式的需求追溯展示。
- 待批准：技术力、商业力、综合竞争力三类独立日额度的提前预检、简单超限弹窗与共享权益服务接入。

### 2.3 明确排除

- 不把对比篮嵌入评估页，不反向改写或清空对比篮。
- 不在评估页提供企业搜索、固定候选池或本地新增；本页移除仅影响当前配置、不回写对比篮，补充对象通过系统浮层完成。
- 不承接供应链关系、风险洞察、企业发展痛难点结果。
- 不承接招引 / 培育结论、一企一策或候选名单管理。
- 普通评估用户不维护全局模板、默认权重、模型参数或数据批次。
- 配置页、企业总览和对比篮不生成评估报告。
- 不新增第四种业务模式，不用复杂雷达图承载三家及以上企业。
- 不在本模块定义具体权益等级、日额度、套餐价格、订单、支付、发票或完整商业化中心。
- 不把 GOV / INNO / THINK 等权限 persona 当作收费等级，不把评估发起额度与报告导出额度合并。

## 3. 产品角色与权限映射

| 产品角色 | 使用目的 | 实现角色 × 等级 | 数据与操作边界 |
| --- | --- | --- | --- |
| 政府科技管理与产业决策人员 | 识别区域 / 产业企业能力结构、重点对象和政策服务方向 | `GOV × L3` | 按授权查看内部 / 敏感字段，创建评估、调整当次配置、生成结果与受控报告 |
| 产业园区运营 / 企业服务人员 | 评估园区企业能力与短板，形成分层服务依据 | `INNO × L3` | 按园区授权范围执行完整评估；不改全局模板 |
| 投资机构产业研究 / 尽调人员 | 对授权企业做能力比较、尽调辅助和候选筛选 | `THINK × L2` | 仅授权 / 脱敏字段；有限对象和报告模板；可保存个人模板 |
| 行业协会研究 / 服务人员 | 形成会员企业行业对标、共性短板和服务议题 | `THINK × L2` | 仅会员 / 授权及脱敏数据；不得据此查看未授权企业敏感经营数据 |
| 企业经营管理 / 战略人员 | 对本企业自评、与授权或脱敏同行对标，识别短板并支持战略决策 | `INNO × L2`（完成企业认证） | 本企业明细 + 授权 / 脱敏同行数据；不得反查同行敏感明细 |

权限规则：L2 / L3 都可选指标、临时调权、保存个人模板和生成结果；两者的临时配置均不修改全局模板。L4 `OPS / SYS` 只维护全局模板、默认权重、字段、模型参数、数据批次、权限和审计，不作为日常评估用户。

## 6. 核心任务流

1. 接收对比篮对象，记录 `source` 与 `return_context_id`；无对象或需调整时原位打开系统对比篮，并按当前 `mode` 预选 `analysis_type`。`source=compare-basket` 时本次 `analysis_type` 优先于残留 `mode`，配置态每次 `enterprise_codes[]` 更新均覆盖对象草稿；任务过程、结果和报告态保持任务快照。
2. 选择模式；技术力 / 商业力至少 2 家，综合竞争力至少 1 家。
3. 从分组模板选择器加载系统模板、当前模式下已保存的个人历史模板或当次自定义配置；个人模板可在个人中心查看并带回复用。商业力模式同时选择评价行业：未改动配置时加载该行业适用维度与默认权重；已改动时必须选择“应用行业配置 / 保留自定义配置 / 取消”，不得静默覆盖。
4. 当前 DEMO 的行业配置使用确定性模拟预览并在业务模式以自然语言披露；正式行业映射、默认权重和算法仍受 `Q014 / GAP-INTERACTION-BID-01` 阻断。业务与评审模式共享相同配置结果，评审模式只追加正式规则未闭合说明。
5. 校验指标、整数权重、对象权限、字段可见性、数据覆盖和模型条件。数据覆盖与可信度对全部对象执行；首屏每页展示 9 家，支持按企业名称定位和可信度筛选，搜索、筛选与分页不改变预检结论或生成条件。
6. 限额开关开启时，用户在上游“下一步”或本页“生成评估”触发日权益体验预检；技术、商业、综合分别映射独立分类。超限或权益服务异常时不创建任务并保留当前上下文。
7. 用户明确触发“生成评估”；创建接口再次校验日权益，成功创建 `task_id` 时原子扣减一次对应分类额度。系统按“模式 + 企业数量 + 生成时间”生成只读 `task_display_name`，并固化对象、模式、`template_id` / 版本、已选指标、整数权重、可信度、算法版本与权限范围，创建任务并进入独立生成过程页；当前 DEMO 的数据批次未接入，快照不得写入或展示伪造批次值。
8. 生成过程页按任务提交、权限与配置校验、企业数据汇聚、指标计算、可信度与可比性校验、结果图表组装六阶段展示；只显示真实阶段和已用时间，不伪造百分比，允许离开后从最近评估或个人中心恢复。
9. 完成后查看结果；1–5 家显示全部对象名，6–50 家只显示任务快照顺序中的前三家与“等 N 家”，通过“查看全部对象”打开可搜索、筛选、分页的只读对象抽屉。结果页可切换单企诊断或从任务对象集中搜索选择企业 A / B，观察视角变化不修改任务快照、综合得分或报告指纹。
10. 返回配置派生新任务或提交后台报告任务。后台从当前不可变结果快照生成结构化报告模型，并用同一 `report_revision` 产出 HTML 阅读内容和 A4 PDF；任务完成后进入只读报告页，可下载与当前 `task_id` 绑定的同源 PDF。报告不提供章节配置或正文编辑。

上述 13 项是当前注册集合，不等于 Bid 指标全集。以下直接要求尚无已核验 `metric_id`，必须保留为阻断 GAP：专利引用 `GAP-METRIC-BID-01`、研发人员占比 `GAP-METRIC-BID-02`、核心技术覆盖度 `GAP-METRIC-BID-03`、客户集中度 `GAP-METRIC-BID-04`、品牌声量 `GAP-METRIC-BID-05`、组织能力维度 `GAP-METRIC-BID-06`。算法 Bid 中技术五维、商业六维及综合竞争力规模/财务/人力资源/市场表现维度还需逐项登记 `metric_id`，统一受 `Q014` 阻断。

13 项均已有指标种子卡；当前仅专利授权量、最新营业收入具备可直接使用的数据源，10 项待算法 / `Q014` 闭合。市场份额、品牌声量、客户集中度受 `K-O7` 阻断；项目决策清单中的市场份额 `Q019` 仅作为当前决策记录引用，须先闭合 `GAP-SOURCE-01` 编号冲突。`M_ENT_BUSINESS_POWER_SCORE` 的种子卡当前误指向 E-23 / 需求 3.3，应由指标与合规 Owner校正到 E-24 / 需求 3.4，产品包只登记差异，不静默改口径。

### 8.2 数据与可信度规则

- 缺失数据不得按 0 计算；只按可用指标重算，并降低可信度。
- 高：覆盖度 ≥ 90% 且无关键指标缺失；中：70%～89% 或少量关键指标缺失；低：50%～69% 或多个关键指标缺失。
- 覆盖度 < 50% 或全部关键指标缺失时不可生成正式结果。
- 多企业比较逐企业给出可信度；覆盖结构不同需提示可比性风险。
- 雷达图缺失点显示缺失，不落到 0；差距分析只比较共同可用数据。
- 正式链路固定为 `前端 → 网关 → Java 聚合 → 已登记算法 / ADS`，前端不得直连 Python、数据库或自行计算官方分数。
- 数据覆盖与可信度的正式预检由 Java 聚合后端负责；前端仅对对象数量、指标选择和权重合计做目标 ≤100ms 的本地校验。对象、评估模式或已选指标变化时，前端防抖 300～500ms 后触发后端预检；仅权重变化时只做前端本地校验，不触发后端预检。
- 正式预检常规响应参考区间为 1～3 秒、普通请求目标 ≤3 秒，P95 ≤5 秒。后端响应时延从预检请求发出起算，到前端收到可渲染的预检结果止，不包含触发前的 300～500ms 防抖；请求发出后等待超过 300ms 时展示稳定 loading，超过 5 秒时展示“仍在预检”并提供重试。预检未返回通过结论前不得静默放开“生成评估”。该时序与责任边界属于 `product_interpretation`，不改变当前交付阶段。
- `Q014` 临时默认值用于试点时，业务界面必须显示“待甲方确认”，不得只在内部评审元数据中提示。
- 企业名称展示以中文为主，数据契约预留英文名称；K-O7 外部数据未完成授权与合规确认前不得进入正式评分、图表或报告。
- `data_batch` 是 FULL 任务快照字段；当前 DEMO 数据批次未接入，只能在内部评审模式显示“数据批次未接入”，业务模式不展示该缺口，不得生成、保存或写入报告指纹 `mock_20260618` 等伪造批次值。

### 8.3 指标说明契约

- 配置页点击指标说明“查看”打开业务抽屉，不跳离当前评估配置。
- 业务模式展示指标名称、衡量目的、所属维度、业务口径、单位、指标方向、适用范围、数据状态与缺失影响。
- 内部评审模式在同一抽屉追加 `metric_id`、公式、源表、源系统、更新频率、版本和 `Q014 / K-O7 / GAP-SOURCE-01`；这些内部字段在业务模式不渲染。
- 指标说明只解释指标，不修改选择、权重、对象集或任务快照。

### 8.4 日权益接入契约（待范围批准）

- 权益规则由共享权益服务拥有，系统任务层拥有预检、最终校验、原子扣减与幂等返还协议；ENT-EVAL 只拥有三模式分类映射、触发位置和弹窗。
- 认证身份、专业用户类型和付费套餐分别维护，后端返回稳定 `entitlement_tier`；页面不按权限 persona 推导。
- `technology / business / comprehensive` 三类按 `Asia/Shanghai` 自然日独立计数；综合类不同时扣技术和商业额度。
- 上游“发起分析 → 下一步：前往配置”已明确模式时先做体验预检；直接入口、历史复用或个人中心进入配置时，在“生成评估”前预检。
- 体验预检不扣减。任务创建接口再次校验，并原子完成 `task_id` 创建与一次额度扣减。
- 平台故障、算法系统错误和排队阶段用户撤回时幂等返还；正常完成与有效“数据不足”结果不返还。

## 11. 报告与历史

- 只有结果页可创建评估报告；按当前模式生成技术力、商业力或综合竞争力报告。
- HTML 是系统内只读阅读形态，PDF 是本期正式下载格式，二者来自同一结构化报告模型与 `report_revision`；HTML 不作为独立文件格式开放下载，Word 为后续能力。
- 任务状态：提交、数据准备、评分计算、图表生成、报告组装、完成 / 失败。完成时 HTML 阅读内容和 PDF 同时可用，不要求用户再次提交 PDF 生成。
- 同对象、模式、模板版本、权重、数据批次与权限范围形成报告指纹；同指纹的处理中或有效报告复用后台任务。
- 报告完成态提供“下载当前报告”；下载内容必须来自当前结果任务快照并关联当前 `task_id`，不得下载其他任务或未完成报告。
- 报告采用固定核心章节与自动扩展章节；用户不能配置章节、隐藏缺失状态或编辑系统正文。扩展章节只按模式、对象数量、指标、数据可用性与权限自动装配。
- 固定核心章节为：封面与报告身份、决策摘要（含关键差距与改进方向）、评估范围与方法、综合结果、优势短板与差距、改进方向、数据质量与限制、附录与追溯。模式专属分析、趋势与对标按数据条件自动出现；不满足条件时保留简短不可用说明，不留空白图表、不补造数据。
- 单企业报告使用“当前企业 vs 对象集均值 / 领先值”诊断；双企业报告使用 A/B 差距对比；多企业报告保留全量对象参与，正文聚焦排名分布、Top / Bottom 与分组诊断，完整排名进入附录。
- 决策摘要控制在前 2–3 页，完整分析与证据随后展开。系统文字只归纳综合得分、排名、维度差距、优势、短板、可信度和已登记改进方向，并提供指标依据；不生成未经任务结果支持的外部成因、行业事实或策略推断。
- 资产中心保存状态和下载记录；报告受角色、字段分级、对象上限、脱敏 / 审批和审计控制。
- 最近评估收录用户明确提交后的处理中、已完成和失败任务；仅保存配置不产生任务。任务状态改变仍更新同一记录，不扩展为团队协作、审批流、复杂版本比较或通用任务管理。
- 最近评估与个人中心“评估任务”读取同一任务源；个人中心只是跨场景资产入口，不复制第二份任务、状态或报告计数。
