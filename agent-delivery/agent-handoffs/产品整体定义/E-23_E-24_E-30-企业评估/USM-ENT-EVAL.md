## 3. 用户故事

### US-ENT-EVAL-OBJ｜接收和确认评估对象

**作为**任一有权评估的产品角色，**我想要**从对比篮自动带入企业并在评估页确认或剔除本次不参与对象，**以便**新增来源唯一、无需重复选择且能恢复原工作现场。

- 接收 `enterprise_codes[]`、`source=compare-basket`、`analysis_type`、`return_context_id`。
- 显示“来自对比篮 · X 家”和企业名称；有效对象自动成为本次对象。
- 评估对象作为三种模式的共享上下文，在配置视图中只于模式选择器上方渲染一次；切换模式保留同一对象集合，并按目标模式重新校验最少对象数。
- 评估页不提供企业搜索、候选池或新增；可移除本次对象且不回写对比篮，补充对象返回对比篮，同一上下文恢复篮内筛选、勾选和滚动位置。
- 无权 / 失效对象剔除后明确提示；仍需按模式重新校验最少对象数。
- 对象区空态只显示居中的蓝色主按钮“前往对比篮选择企业”，标题右侧不渲染重复入口；存在对象时才显示“返回对比篮调整对象”。
- 配置对象 1–5 家时完整显示可移除标签；6–50 家时默认显示前 3 家并提供“管理全部对象（N 家）”。管理抽屉支持中英文名称定位、每页 10 家和当次移除，不允许新增对象、不回写对比篮。
- 结果页 1–5 家显示全部对象名；6–50 家只显示任务快照顺序中的前三家与“等 N 家”，完整对象通过可搜索、筛选、分页的只读抽屉查看。摘要收纳不得改变任务对象集。
- 结果摘要中的“查看全部对象”位于对象文字下方并与文字左边缘对齐，避免长对象摘要与操作挤在同一行。

### US-ENT-EVAL-TECH｜配置技术力评估

**作为**政府、园区、投资研究、行业协会或企业自身用户，**我想要**用至少两家企业的技术指标和可调整权重创建技术力评估，**以便**比较技术能力、排名和差异。

- 可加载系统 / 个人模板，选择技术力指标并当次调权。
- 关联 `M_ENT_TECH_POWER_SCORE`、`M_ENT_TECH_RANK`、`M_ENT_PATENT_GRANT_COUNT`、`M_ENT_RD_INVESTMENT_RATIO`。
- Bid 明确的专利数量/引用、研发人员占比、核心技术覆盖度必须出现在指标库；未登记前分别显示 `GAP-METRIC-BID-01/02/03`，不得以专利授权量或研发投入强度替代后声称完整覆盖。
- 技术人才、技术创新、技术转化、技术合作、技术投入五个算法 Bid 维度必须保留；逐轴 `metric_id` 和归一化规则受 `Q014` 阻断。
- 结果使用归一化技术维度解释能力结构，不把专利数量、研发投入比例或排名直接混在同一雷达量纲中。
- 两家直接进行双企业技术维度对比；三家及以上保留全对象技术力加权排名，并允许从任务对象集中任取两家进入双企雷达。A/B 仅控制雷达解释视角，不裁剪下方全对象技术诊断明细。
- 结果输出包含技术力指数、分维分析、优势短板、趋势变化与改进建议；无连续数据或正式建议模型时显示 GAP，不生成替代结论。
- 技术力结果下方只使用一个覆盖任务全部对象的“技术指标与差距诊断”，每页显示 10 家，并在同一企业行展示技术力综合得分、原始技术指标、数据可信度、领先差距、优势与短板；趋势 / 改进建议缺失作为区块内状态，不再追加第二张“指标明细与综合差距”企业表。

### US-ENT-EVAL-BIZ｜配置商业力评估

**作为**上述产品角色，**我想要**用至少两家企业的经营指标和可调整权重创建商业力评估，**以便**识别经营竞争力和短板。

- 关联 `M_ENT_BUSINESS_POWER_SCORE`、`M_ENT_REVENUE_LATEST`、`M_ENT_REVENUE_GROWTH_RATE`、`M_ENT_PROFIT_MARGIN`、`M_ENT_MARKET_SHARE`。
- Bid 明确的客户集中度和品牌声量必须保留在指标库，并支持根据行业特性调整评价维度；未登记前显示 `GAP-METRIC-BID-04/05` 与 `GAP-INTERACTION-BID-01`。
- 业务模式选择评价行业后加载该行业的适用指标与默认权重；当前 DEMO 使用确定性模拟预览并以自然语言说明不是正式行业标准。用户未改动时可直接切换；已有改动时必须选择应用行业配置、保留自定义配置或取消，不能静默覆盖。
- 业务与评审模式必须产生相同的行业、指标和权重结果；评审模式仅在 `ENT-EVAL-F01-INDUSTRY-PREVIEW-NOTE` 追加正式行业映射、权重和闭环条件，业务模式不渲染内部说明。
- 市场、产品、品牌、技术合作、产业链覆盖率、关键环节参与度六个算法 Bid 维度必须保留；逐维 `metric_id`、阈值和数据源受 `Q014 / K-O7` 阻断。
- 全部对象对比营业收入、收入增长率和利润率；关键经营指标卡支持名称定位并每页显示 6 家。全对象商业力综合排名只在主排名图表达一次，下方“商业诊断与明细”覆盖全部对象、每页显示 10 家，但不提供独立排名序号、排序入口或第二套排行结论。
- 商业指标各自保留亿元 / % 等原单位，不以雷达或营收 / 专利双轴图混合量纲；营收趋势只在任务快照具有连续年度数据时出现。
- 市场份额、品牌声量、客户集中度在 `K-O7` 未闭合前标为不可用，不以样例数据替代正式口径；当前决策清单 `Q019` 与 SRS 第 6 章同号异义，须持续显示 `GAP-SOURCE-01`，不得把两者混写。
- 结果输出包含商业力指数、分维分析、趋势变化、行业对标与报告；无正式数据时保留缺失状态。

### US-ENT-EVAL-COMP｜配置综合竞争力评估

**作为**上述产品角色，**我想要**从至少一家企业出发配置维度权重和维度内指标权重，**以便**获得综合竞争力画像与短板。

- 关联 `M_ENT_COMPETITIVENESS_SCORE`、`M_ENT_COMPETITIVENESS_RANK`、`M_ENT_SHORTBOARD_COUNT`、`M_ENT_INNOVATION_INDEX`。
- 综合框架必须首先覆盖 Bid 的技术、市场、组织三类维度；组织能力未登记前显示 `GAP-METRIC-BID-06`。成长性、创新度、抗风险只能作为产品化解释追加，不能替代三类直接要求。
- 算法 Bid 的企业规模、财务状况、人力资源、市场表现必须映射到技术/市场/组织框架或显式 GAP，不得静默删除。
- 一家进入单企诊断，对比对象集均值和对象集领先值；两家展示双企业竞争力雷达与差距。
- 三家及以上仍保留全对象综合排名结果；≤10 家首屏完整展示，>10 家首屏显示 Top 5 + Bottom 5 并提供完整排名二级视图。同时允许在“单企诊断 / 双企对比”间切换，双企雷达最多两条企业曲线。
- 维度权重与维度内权重分层配置，默认折叠展开，避免单表混淆。
- 结果下方只使用一个“综合竞争力与差距诊断”：单企态显式展示当前企业综合得分与数据可信度，并在同一区块展示技术 / 市场 / 组织等维度得分、对象集均值 / 领先值、差距和优势 / 短板；双企态展示 A / B 综合得分、可信度、维度差值与差异结论。右侧综合竞争力排名是唯一排名表达，不再追加“指标明细与综合差距”企业表。

### US-ENT-EVAL-QUALITY｜校验模板、权重和数据质量

**作为**评估发起人，**我想要**在生成前看清指标有效性、权重错误、数据覆盖和可信度，**以便**避免把不可比或缺数据的结果当成正式结论。

- 权重用 0～100 的整数输入；支持一键平均分配，不静默自动归一化。
- 所需权重层级都必须合计 100；错误定位到具体维度 / 指标。
- 缺失不记 0；覆盖度 <50% 或关键指标全部缺失时阻止生成。
- 每家企业分别给出高 / 中 / 低可信度；数据结构不同提示可比性风险。
- 全部对象始终参与预检；覆盖与可信度卡支持企业名称定位、可信度筛选并每页显示 9 家，搜索、筛选和分页只改变可见范围，不改变生成条件或整体风险提示。
- 正式数据覆盖与可信度预检由 Java 聚合后端负责；前端对对象数量、指标选择和权重合计的本地校验目标 ≤100ms。对象、模式或已选指标变化时防抖 300～500ms 后触发后端预检，仅权重变化时只做本地校验。
- 后端预检常规响应参考区间为 1～3 秒、普通请求目标 ≤3 秒，P95 ≤5 秒；时延从预检请求发出起算，到前端收到可渲染结果止，不包含触发前防抖。请求发出后等待超过 300ms 展示稳定 loading，超过 5 秒展示“仍在预检”并提供重试，且在预检通过前不得静默放开生成。
- 点击指标说明“查看”打开业务抽屉，展示目的、维度、业务口径、单位、方向、范围、状态和缺失影响；内部评审模式追加 `metric_id`、公式、源表、源系统、更新频率、版本和开放问题，业务模式不渲染内部字段。
- 使用 `Q014` 临时默认权重时，业务模式显示“待甲方确认”；企业名称以中文为主并预留英文名称；K-O7 外部数据未完成授权合规确认前不得进入正式评分或报告。

### US-ENT-EVAL-RESULT｜生成并理解正式结果

**作为**评估发起人，**我想要**生成有任务快照、指标依据和可信度说明的正式结果，**以便**复核结论并采取后续行动。

- 只有用户明确触发生成，才创建 `evaluationTaskId` 和任务记录并进入处理中；仅保存配置不产生任务。后台成功后同一任务转为已完成并开放结果，失败则保留失败阶段供恢复或重试。
- 用户触发生成后先进入独立过程页，按任务提交、权限与配置校验、企业数据汇聚、指标计算、可信度与可比性校验、结果图表组装展示；不伪造后台百分比，允许离开并从最近评估或个人中心恢复。
- 结果固定关联系统生成的只读 `task_display_name`、对象、模式、`template_id` / 模板版本、已选指标、每项整数权重、可信度、数据批次、算法版本、权限范围和生成时间；任务展示名不来自个人模板名称。
- `data_batch` 是正式快照字段，但当前 DEMO 未接入数据批次；评审态只说明“数据批次未接入”，业务态不显示该内部缺口，任务与报告不得写入 `mock_20260618` 等伪造值。
- 页面先给 4 个以内 KPI 和一个结论条，再展示模式适配图表、明细及短板。
- 技术力保留趋势变化与改进建议落位；商业力保留趋势和行业对标落位；综合竞争力保留趋势与分析报告落位。缺正式结果时显示不可用原因，不用通用结论条冒充。
- 所有模式的全对象排名只按任务快照中的模式综合得分排序，不得以第一个已选指标值替代；刷新和历史恢复保持同一结果。
- 排名超过 10 家时，Top 5 使用主蓝、Bottom 5 使用中性灰，两组之间保留一个类别间隔并显示同色图例；颜色只表达分组，不改变得分语义。
- 结果页切换当前诊断企业或企业 A / B 只改变观察视角，不修改任务快照、综合得分或报告指纹。
- 内部评审模式展示顶部“企业评估”评审标题及页面 / 配置 / 关键结果 REQ 追溯；业务模式隐藏该评审标题与追溯信息。
- 内部评审模式下，数据覆盖及每个结果子模块标题可查看原需求摘要、来源位置、当前落位和“直接承接 / 产品化展开”分类；业务模式不渲染这些评审信息。
- “当前展示 Top 5 与 Bottom 5；按本次评估综合得分排序”“排名固定为任务快照结果；名称定位、可信度与数据状态筛选仅缩小可见范围，不触发重排。”“对象列表只读，顺序固定为任务创建时的对象快照；搜索与筛选不改变任务。”三段实现机制说明只在内部评审模式展示；业务模式保留业务数据、图例和操作。

### US-ENT-EVAL-REPORT｜生成受控评估报告

**作为**有报告权限的评估发起人，**我想要**从结果页提交后台报告任务，并在完成后阅读与 PDF 同源的完整报告，**以便**先快速掌握决策结论，再复核分析依据并获得可审计、可下载的评估材料。

- 仅结果页提供创建报告；完成后通过 `F-EVAL-10`（`/enterprise-center/evaluation?view=report&task_id={evaluationTaskId}&report_id={reportId}`）阅读只读 HTML 报告，并下载同一 `report_revision` 的 A4 PDF。HTML 是系统内阅读形态，不是独立下载格式；Word 后续开放。
- 状态为提交、数据准备、评分计算、图表生成、报告组装、完成 / 失败。
- 同指纹的处理中或有效报告复用，不由前端缓存冒充后台事实。
- 后台先从不可变评估快照生成结构化报告模型，再由 HTML 阅读模板和 A4 PDF 模板分别渲染；两种形态共用章节、字段、结论、证据锚点和图表资产，仅屏幕阅读与分页表现不同。
- 用户不配置章节、不编辑正文。报告固定包含封面与报告身份、决策摘要（含关键差距与改进方向）、评估范围与方法、综合结果、优势短板与差距、改进方向、数据质量与限制、附录与追溯；模式专属分析、趋势与对标按模式、对象数量、指标、数据可用性和权限自动装配。
- 报告前 2–3 页形成决策摘要，正文保留完整分析与证据。单企业使用当前企业对对象集均值 / 领先值诊断，双企业使用 A/B 差距对比，多企业正文聚焦排名分布、Top / Bottom 和分组诊断，完整排名进入附录；任何收纳都不裁剪任务对象。
- 系统文字只归纳任务快照中的综合得分、排名、维度差距、优势、短板、可信度及已登记改进方向，并为结论关联指标依据；不得扩写任务结果未支持的成因、行业事实或策略推断。
- 数据不足、无连续时序、无合规基准、字段无权或指标未登记时，不渲染空图表、不补造数据、不允许用户隐藏，改为显示缺少内容、对结论的影响和是否进入评分。
- 下载受字段分级、脱敏 / 审批、对象数量、报告模板和审计约束。
- 报告完成态提供“下载当前报告”，下载文件必须关联当前 `task_id` 并由当前不可变结果快照生成；未完成、无权限或任务不一致时不可下载。

### US-ENT-EVAL-HISTORY｜找回和复用评估任务

**作为**评估发起人，**我想要**查看最近已提交的评估任务并恢复过程、结果或基于旧配置创建新任务，**以便**持续研判而不覆盖历史事实。

- 展示任务 ID、模式、企业摘要、模板 / 版本、数据批次、时间、可信度和报告数。
- 支持恢复结果、按此配置新建评估、查看关联报告。
- “按此配置新建评估”复制配置形成新草稿，不覆盖旧任务；历史不扩展为团队协作或复杂版本管理。
- 最近评估与个人中心“评估任务”读取同一任务集合和状态；个人中心只提供跨场景继续查看入口，不复制第二份任务、报告数或状态。
- 工作台一级导航顺序固定为“技术力评估 / 商业力评估 / 综合竞争力评估 / 最近评估”，最近评估作为第四个导航 Tab；进入 `view=history` 时第四项保持选中。
- 不得在页头保留“最近评估”入口；从历史视图点击前三个 Tab 时退出 `view=history` 并回到所选模式配置，避免同一能力形成重复入口。

## 4. 主路径

### 4.1 从对比篮发起

1. 用户在对比篮选择企业和评估类型，确认“下一步：前往配置”。
2. 企业评估解析对象并显示来源；用户可移除本次不参与对象，并处理无权 / 失效对象提示。
3. 页面按 `analysis_type` 打开对应模式，用户加载模板并调整指标 / 权重。
4. 预检展示每家企业的数据覆盖和可信度，阻止不满足条件的生成。
5. 限额开关开启时执行日权益体验预检；超限显示简单弹窗，服务异常显示可重试错误，二者均不创建任务。
6. 用户触发生成，创建接口再次校验并原子完成任务创建和额度扣减；随后进入独立生成过程页，展示六个业务阶段、已用时间和可离开提示。
7. 生成完成后进入结果页，展示结论、模式解释型分析、排名摘要、指标诊断、短板和报告入口；全对象排名通过首屏阈值与完整排名二级视图共同承载，用户可在任务对象集中搜索切换当前诊断企业或双企 A / B。
8. 用户创建报告后可离开，后台完成结构化内容与图表组装；完成后进入只读 HTML 报告，先阅读决策摘要，再浏览完整分析与附录，并下载同一版本 PDF。
9. 用户可返回对比篮恢复现场，或从最近评估、个人中心找回同一评估任务和关联报告。

### 4.2 直接进入

1. 用户从企业中心进入企业评估，选择模式。
2. 页面不预填演示企业，显示空对象状态和“前往对比篮选择企业”。
3. 对比篮按当前评估模式预选分析类型；用户完成对象选择后进入主路径第 2～7 步。

## 5. 异常与权限路径

| 场景 | 系统行为 | 用户可行动作 |
| --- | --- | --- |
| 无对象 | 展示空态，不加载空图表 | 前往对比篮选择企业 |
| 对象数量不足 | 技术力 / 商业力少于 2 家时说明原因 | 返回对比篮调整或切换综合竞争力 |
| 对象无权或失效 | 剔除无效对象并逐类汇总提示 | 使用有效交集或返回对比篮 |
| 权重不等于 100 | 阻止生成并定位层级，不自动归一化 | 修改或一键平均分配 |
| 部分指标缺失 | 不记 0，重算可用指标并降低可信度 | 查看缺失说明后继续或换对象 / 指标 |
| 覆盖度 <50% / 关键指标全缺 | 禁止正式生成 | 更换对象、指标或等待数据 |
| 低可信度 | 允许生成但显著警示；报告同步带入 | 确认继续或返回调整 |
| 生成中 | 保留任务进度，防止重复提交 | 离开后从最近评估查看 |
| 生成失败 | 保留失败阶段与可审计错误编号 | 重试或按此配置新建评估 |
| 无报告权限 | 保留入口位置并说明权限原因 | 查看在线结果 |
| 同指纹报告已存在 | 复用处理中 / 有效任务 | 查看状态或下载 |
| 当日分类额度已用完 | 不进入配置或不创建任务，显示类别、已用/总额、重置时间 | 联系开通或关闭后保留上下文 |
| 权益服务异常 / 配置无效 | 失败关闭并保留配置，显示可重试错误 | 稍后重试 |
| 最终创建校验超限 | 即使体验预检曾通过，仍不创建任务并显示同一超限弹窗 | 联系开通或次日重试 |
| 平台故障 / 算法系统错误 / 排队撤回 | 保留终态并幂等返还已扣额度 | 按原配置重新发起 |
