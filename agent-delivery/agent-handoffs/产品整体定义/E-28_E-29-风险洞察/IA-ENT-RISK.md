## 2. 模块边界

### 2.1 解决的问题

风险洞察以已选企业对象为主语，帮助政府、园区和投资机构看清企业供应链结构、关键节点和断链风险，或识别企业发展中的技术研发、市场拓展、融资和管理问题，并把结果沉淀为可追溯报告。

### 2.2 承接内容

- 从对比篮带入企业对象，完成当次对象确认与数量校验。
- `供应链关系`、`发展痛难点`两个分析 Tab 加 `最近分析` 第三个页面级 Tab；前两个分析 Tab 共用对象上下文，第三个 Tab 读取同一任务体系。
- 单企业供应链图谱；两企业供应链轻量对比；用户不配置展开层级，结果初始只展示一级，点击可展开节点逐层加载下一层，由系统以最大三级保护。
- 核心供应商、关键节点、单点依赖、节点异常和路径脆弱风险识别。
- 图谱顶部以轻量状态行说明当前层级、节点数和共同节点数；关系类型图例独立位于画布右下角；关键节点与断链风险区在评审模式承载精确原需求追溯。
- 关键节点风险或断链风险项明确提示“建议提前制定备份方案”，供应链报告同步保留该提示，帮助用户基于风险线索开展线下研判。
- 单企业痛难点诊断；最多 50 家企业集合共性诊断；技术研发、市场拓展、融资、管理四个页面维度。
- 分析生成过程、不可变结果快照、最近分析、按此配置新建、报告生成与下载。
- 供应链关系分析报告和企业发展痛难点分析建议报告；两类报告都进入个人资产中心。
- 内部评审模式的需求追溯、metric_id、Q 项和 DEMO / 数据缺口说明。
- 痛难点“四维诊断”和“问题清单 / 共性问题”标题分别承载原需求追溯；四个维度卡片的指标说明分别挂在各自实际数值旁，不在标题堆叠评审图标。

### 2.3 明确排除

- 不在风险洞察页内搜索、新增或维护企业；补充对象原位打开系统对比篮。
- 不生成无对象风险态势、高风险企业榜、供应链总评分、企业综合排名或推荐企业清单。
- 不做替代供应商推荐、替代路径计算、备选名单、备份方案编辑器或自动生成备份方案；“建议提前制定备份方案”仅是原需求对应的业务提示，不构成方案生成能力。
- 不做企业评估的技术力、商业力、综合竞争力评分，也不把严重度转成企业排名。
- 不生成完整一企一策，不做政策匹配、服务派单或招引 / 培育候选管理。
- 普通业务用户不维护图谱关系、算法参数、阈值、专家知识库、报告模板或数据批次。

## 6. 核心任务流

1. 从对比篮接收 `enterprise_codes[]`、`source=compare-basket`、`analysis_type` 和 `return_context_id`；风险洞察页不提供企业搜索。
2. 在分析 Tab 上方确认共享对象上下文：1–5 家完整显示，6–50 家仅显示快照顺序前三家与“管理全部对象”。管理抽屉支持按名称定位、每页 10 家和当次移除；移除同步影响两个 Tab 的共享对象集合，但不回写对比篮。抽屉不承担新增对象，补充对象原位打开系统对比篮。`source=compare-basket` 时有效 `analysis_type` 优先于残留 `tab`，配置态再次分发同步覆盖对象草稿，任务态保持任务快照。
3. 选择供应链关系或发展痛难点 Tab 开展分析；第三个“最近分析”Tab 进入 F-RISK-05。两个分析 Tab 之间切换不改变来源与对象，只恢复该 Tab 的关系范围或诊断维度草稿；切换到供应链且对象超过 2 家时保留对象上下文，但要求缩减后才能分析，不静默截断。
4. 配置关系类型，或痛难点诊断维度；执行权限、数据覆盖和模型条件预检。供应链展开深度由系统控制，不作为用户配置；预检区只显示状态和问题，不承载页面级提交按钮。
5. 用户在页面底部操作栏右侧明确触发“开始分析”，系统固化对象、Tab、配置、数据 / 算法 / 权限版本，创建 `riskTaskId` 并进入独立过程页。对象为空、对象超限、预检未通过或无权限时按钮禁用，并在预检区说明原因。
6. 过程页按企业评估同构为任务摘要卡与“可视化分析过程”卡：摘要卡展示任务 ID、分析类型、企业数量、已用时间和状态；过程卡以纵向阶段标签展示已完成 / 进行中 / 等待中 / 失败，并用成功 / 信息 / 错误 Alert 说明当前结果。所有过程动作固定在 Alert 下方右侧，不占用标题栏。分析完成后仍停留过程页，用户可点击“查看分析结果”主动进入相应结果，或查看最近分析；失败时保留失败阶段、错误编号和“重新尝试 / 按此配置新建分析”。
7. 结果页顶部展示不可变任务摘要，并只提供“按此配置新建分析”。痛难点结果 1–5 家显示全部对象名，6–50 家显示快照顺序前三家与“等 N 家”；“查看全部对象”位于对象摘要文字下方并左对齐，进入只读抽屉。抽屉中的“对象列表只读，顺序固定为任务创建时的对象快照；搜索与筛选不改变任务。”仅在评审模式显示，业务模式不存在。集合首屏展示四维影响分布与影响企业数最高的 5 个共性问题，每项最多展示 3 家典型企业，完整问题或受影响企业进入可检索二级视图；查看某企业时只显示其在当前任务中的问题命中摘要，不创建第二份单企任务。供应链图谱初始展示一级，顶部以轻量文本显示当前层级、节点数和共同节点数，右下角显示中心企业 / 供应商 / 客户 / 合作伙伴静态图例。用户点击带“可展开”标识的节点加载下一层，可折叠并查看当前路径 / 深度；“系统最多 3 级”仅在展开动作提示中说明。所有观察操作不得修改任务快照。
8. 仅结果页可以创建对应报告；报告入口独立置于业务结果之后，按当前状态显示“创建报告 / 生成中 / 查看或下载报告”，报告异步生成，完成后下载当前任务报告或前往个人资产中心。
9. 最近分析与个人中心读取同一任务源，可恢复结果或“按此配置新建分析”，不覆盖旧任务。

## 7. 与企业评估一致的共享交互

| 交互 | 一致规则 | 风险洞察差异 |
| --- | --- | --- |
| 企业选择 | 对比篮负责新增 / 暂存；业务页负责确认和当次移除 | 供应链上限 2 家；痛难点支持集合共性诊断 |
| 对象与 Tab 层级 | 对象是多种分析模式共享的工作上下文，位于模式 Tab 上方 | 两个 Tab 共享对象，但分别保留关系范围和诊断维度草稿 |
| 对象区布局与空态 | 同一对象区结构、来源标签、企业标签、不可用对象提示；空态使用紧凑状态行与“打开对比篮” | 标题为“分析对象”；有对象时显示“打开对比篮调整对象”，原位展开系统浮层 |
| 配置态多对象披露 | 1–5 家完整显示；6–50 家显示前三家与“管理全部对象”，管理抽屉支持名称搜索、每页 10 家和当次移除 | 供应链仍以 2 家为可提交上限；超限时保留共享对象但阻断分析，不静默截断 |
| 来源与返回 | 记录来源、数量、`return_context_id`；返回恢复对比篮现场 | 按当前 Tab 预选风险洞察分析类型 |
| 生成过程 | 独立过程页由任务摘要卡与“可视化分析过程”卡组成；阶段采用纵向状态说明，状态反馈使用语义 Alert，操作统一位于 Alert 下方右侧；完成后停留并由用户主动查看结果 | 仅阶段名称按图谱 / 诊断计算变化，保持五阶段且不自动跳转 |
| 配置提交动作 | 页面级最终提交动作统一置于页面底部操作栏右侧；数据预检区只展示校验状态和问题 | 风险洞察只保留“开始分析”主按钮，不提供“保存为个人模板” |
| 结果页动作 | 顶部任务摘要只提供“按此配置新建”，不改写旧任务；报告位于业务结果后的独立区块 | 文案为“按此配置新建分析”，业务结果结构不同 |
| 多对象结果披露 | 1–5 家全显；6–50 家前三家 + 等 N 家，完整对象只读可检索；二级视图不改变任务范围 | 仅发展痛难点适用；集合首屏为共性问题 Top 5 与典型企业，供应链仍限制 1–2 家 |
| 报告生成 | 仅结果页独立报告区块创建；后台任务；重复指纹复用；按状态区分创建、生成中、查看 / 下载 | 供应链报告与痛难点建议报告使用不同标题和模板 |
| 历史 / 资产 | 最近任务与个人资产中心同源，不复制状态 | 以 `analysis_type` 区分两类任务和报告 |
| 最近分析入口 | 作为模式区第三个页面级 Tab，位于发展痛难点之后 | 进入历史态后第三个 Tab 独占选中；标题区不再重复提供同名按钮 |

## 8. 跨模块边界

| 来源或去向 | 可携带内容 | 不可携带 / 不可承担内容 |
| --- | --- | --- |
| 对比篮 → 风险洞察 | 企业对象、分析类型、来源、返回上下文 | 对比篮不生成风险结果或报告 |
| 企业画像 / 查询 / 重点企业分析 → 对比篮 | 候选企业和来源条件，再由对比篮分发 | 不绕过对比篮直接在风险洞察新增对象 |
| 风险洞察 → 企业画像 | 图谱节点或典型企业标识 | 企业画像不承接风险任务状态 |
| 风险洞察 → 个人资产中心 | 任务 ID、报告 ID、状态、下载权限 | 资产中心不复制任务、重新计算或改写报告 |
| 风险洞察 → 引育推荐 / 企业评估 | 只允许用户重新选择对象并发起独立任务 | 不把风险结论直接变成评分、推荐或名单 |
| 维护管理 → 风险洞察 | 已发布关系、模型、阈值、知识库和报告模板版本 | 业务用户不在风险洞察页修改全局配置 |

## 9. 指标、数据与架构

- 供应链：`M_ENT_SUPPLIER_COUNT`、`M_ENT_CORE_SUPPLIER_COUNT`、`M_ENT_NODE_CENTRALITY`、`M_ENT_SUPPLY_CHAIN_RISK`、`M_ENT_RELATION_STRENGTH`。
- 痛难点当前可见：`M_ENT_PAINPOINT_COUNT`、`M_ENT_PAINPOINT_SEVERITY`；`M_ENT_PAINPOINT_GAP` 仅保留指标登记，Bid 要求的“行业最佳实践”按文本内容承载，在未定义并展示量化差距字段前不得激活该指标挂点。
- `Q017 / Q018` 未闭合时，上述阈值、评级和诊断结果只能按已登记 DEMO / 待语义核对状态展示；不得伪造正式公式或批准结论。
- 正式链路固定为前端 → 网关 → Java 聚合 → Python 算法 / ADS；前端不计算官方风险或诊断指标。
- 供应链图谱正式图数据来自 NebulaGraph；不得新建 Neo4j 或由前端拼接权威关系。
