## 2. 设计原则

1. **统一身份（One Identity）**：一个自然人 = 一个 SSO 账号，跨展示系统 + 专题门户 + 所有垂直主题；不为每个系统单独建号。
2. **双维度授权**：
   - **级别（Level）**＝能力档位 / 数据可见深度（L0→L4 单调递增），决定"**能不能**做某动作、能看多敏感的数据"。
   - **身份场景（Persona/Scenario）**＝业务归属 + 默认视图，决定"**看哪个范围**、默认呈现成驾驶舱还是工作台"。
3. **按级别逐级开通**：高级别**包含**低级别全部能力（叠加式），入门级功能对低级别开放，深度分析对高级别开放。
4. **最小可见 + 非阻断引导**：越权功能不直接 403 整页，而是弱化 + 锁标 + "登录/升级/申请"引导（沿用 demo 的 RoleLevelGate 思路）。
5. **数据权限独立于页面权限**：能进页面 ≠ 能看全部数据；数据按**密级 + 范围（区域/领域/机构）**二次过滤。
6. **口径不外包给 AI / 不替甲方拍板**：级别划分、敏感字段、密级口径均为业务口径，最终甲方确认（§13）。
7. **对齐 D6**：鉴权、SSO、权限校验在**网关 + 统一权限服务**层实现，各业务服务只声明所需权限点，不各自造轮子。

## 3. 统一用户级别模型（L0–L4）★核心

> 级别是"能力阶梯"，**高包含低**。这是"按用户级别开通"的主轴。

| 级别 | 代号 | 名称 | 典型用户 | 能力边界（累加） |
|---|---|---|---|---|
| **L0** | `GUEST` | 公众访客 | 未登录、接待现场、大屏观众 | 只读**公开**展示与概览；无下钻敏感、无导出、无个性化 |
| **L1** | `REGISTERED` | 注册用户 | 注册公众 / 企业 / 高校师生 | L0 + **入门级功能**：检索（三模式）、统一画像（脱敏）、收藏、配额内导出 |
| **L2** | `PRO` | 专业用户 | 实名认证的科研 / 企业 / 智库分析人员 | L1 + **完整分析工作台**：多页深度分析、对比、自助配置（口径只读）、按配额导出 |
| **L3** | `INTERNAL` | 内部业务用户 | 政府 / 管委会内部经办与分析 | L2 + **敏感下钻 + 推演 + 无脱敏 + 名单导出 + 自定义口径权重** |
| **L4** | `ADMIN` | 管理 / 运营 | 系统管理、内容运营、审核发布、设备运维 | L3 + **后台维护、内容/数据/图谱维护、上屏审核发布、设备控制、用户与权限管理** |

> **说明**：L4 是管理面，建议进一步用**功能子角色**细分（§5.3 运营子角色），避免"超管一人通吃"。

## 4. 身份场景模型（横向维度）

> 招标四大场景（第 15/17/49 行原文）+ 运营/系统两类后台身份。身份决定**可见范围 + 默认视图**，与级别正交。

| 身份场景 | 代号 | 对应招标场景 | 服务对象 | 默认视图 | 数据范围倾向 |
|---|---|---|---|---|---|
| 政府决策 | `GOV` | 决策场景 | 政府 / 管委会 | **驾驶舱**（先结论） | 全域、风险、推演、政策效果 |
| 创新主体 | `INNO` | 创新场景 | 高校 / 科研机构 / 企业 | 工作台 | 技术、人才、机构、成果、供需对接 |
| 智库研究 | `THINK` | 智库场景 | 智库 | 工作台 | 前沿洞见、城市评价、人才竞争力 |
| 接待访客 | `VISIT` | 接待场景 | 参观 / 访问人员 | 展示专题（只读概览） | 仅接待专题、成果展示，**不下钻敏感** |
| 内容运营 | `OPS` | （后台） | 平台运营 | 后台 | 内容、专题、图谱、发布 |
| 系统/设备 | `SYS` | （后台） | 系统管理 / 现场运维 | 后台 | 用户、角色、设备、日志、资源 |

> **关键澄清**：demo 的"领导驾驶舱 vs 业务分析师"不是两个级别，而是**同为 L3 内部级、身份不同（GOV 驾驶舱视图 vs INNO/内部分析工作台视图）**。这解决了"领导权限高却看得少"的悖论——领导是 L3 且默认驾驶舱视图（看结论），明细配置按需展开。

**账号 = 1 个级别 + 1 个主身份（可挂多身份）**。例：某政府领导 = `L3 + GOV`；某高校研究员 = `L2 + INNO`；接待讲解 = `L4(子角色:讲解) ` 或现场 `L0 + VISIT` 的大屏。

## 5. 角色 = 级别 × 身份 的命名与清单

### 5.1 对外（公众面）角色

| 角色名 | 级别 | 身份 | 说明 |
|---|---|---|---|
| 公众访客 | L0 | VISIT/— | 未登录浏览公开展示 |
| 接待访客（大屏） | L0 | VISIT | 接待现场只读专题 |
| 注册公众 | L1 | INNO | 注册后入门级功能 |
| 生态企业用户 | L1/L2 | INNO | 企业实名，入门级 +（认证后）部分分析 |

### 5.2 对内（业务面）角色

| 角色名 | 级别 | 身份 | 说明 |
|---|---|---|---|
| 政府决策用户 | L3 | GOV | 驾驶舱、推演、风险、政策效果 |
| 创新业务分析用户 | L2/L3 | INNO | 完整分析工作台 |
| 智库研究用户 | L2/L3 | THINK | 前沿洞见、评价、竞争力 |
| 展示讲解员 | L4(子) | OPS | 控展示/切大屏/播放，**不改数据** |

### 5.3 管理/运营（L4 功能子角色，避免超管通吃）

| 子角色 | 职责 | 不可做 |
|---|---|---|
| 系统超级管理员 | 用户/角色/资源/接口/日志全量 | —（最高，操作留痕 + 审计） |
| 系统管理员 | 专题/页面菜单/场景权限/播放策略配置 | 不碰用户敏感数据 |
| 数据维护 | 数据源/图层/指标/接入状态 | 不改图谱/不发布上屏 |
| 图谱维护 | 节点/关系/实体/版本 | 须经审核才生效 |
| 内容运营 | 文案/成果/服务全景/讲解材料 | 不改数据/不直接上屏 |
| 审核发布 | 审核专题/图谱变更/数据上屏/对外版本 | 不直接编辑内容（职责分离） |
| 设备/现场运维 | 超大屏/中屏/小屏/直播间/播放设备 | 不改展示数据 |

> 职责分离铁律：**编辑** 与 **审核发布** 不可同一人同时拥有（防止自编自发上屏）。

## 7. 门户垂直主题通用授权模型

门户专题含 7 个垂直要素主题：**企业 / 产业链 / 技术 / 人才 / 机构 / 政策 / 服务**。每个主题统一拆为**两层**，授权规则可复制（企业是样板，见 §8）：

| 层 | 内容 | 主开放级别 | 设计意图 |
|---|---|---|---|
| **入门级（门户层）** | 概况、检索工作台、重点/明星/区域榜单、统一画像（脱敏） | **L1 起**（L0 看概览） | 公众/企业自助查询、对外服务 |
| **分析级（分析层）** | 多页深度分析、评估对比、推荐、诊断、图谱 | **L2 起**（深度 L3） | 专业/内部决策分析 |
| **后台层** | 内容/数据/图谱维护、口径配置、发布 | **L4** | 运营维护 |

> 通用规则："**入门级 = L1 解锁、分析级 = L2 解锁、敏感与口径配置 = L3/L4 解锁**"。其余 6 个要素主题套用本规则即可，仅"敏感字段清单"按要素各自定义（§9.2）。

## 8.5 屏幕类型维度（大 / 中 / 小，独立于级别）

权限有**第三个独立维度——屏幕形态**（招标"超大屏/中屏/小屏"）。级别决定"看多深"，屏幕决定"以什么形态呈现、开放哪几类功能"。
> **⚠️ 适用范围**：屏幕三形态**仅展示系统**；**专题系统（门户垂直主题，含企业）仅 PC 端 = 中屏单形态**，无大屏/小屏适配。
> **线上原型**：展示系统 `demo-ui-science` → https://skxrules.unicomcn.tech:30999/ ；专题系统 `demo-ui-topic`（含企业）→ https://skxdemo.unicomcn.tech:30999/ 。

| 屏幕 | 定位 | 开放功能类 | 不含 |
|---|---|---|---|
| **大屏 LARGE** | 展示为主（指挥/接待/会商） | 基础展示 + **酷炫展示**（轮播/特效/3D/多屏联动）+ 只读巡览 | **无个人定义**（订阅/收藏/配置/导出）、无深度分析、无维护 |
| **中屏 MEDIUM** | 业务工作台（功能最全） | 展示 + 交互 + **深度（推演/配置/自助）+ 个人定义 + 维护** | **不含酷炫展示** |
| **小屏 SMALL** | 移动随身（中屏裁剪） | 展示 + 交互(裁剪) + 个人定义(部分：收藏/分享) | 无深度、无酷炫、无维护 |

> **最终可用 = 用户级别 ∧ 屏幕功能类 ∧ 数据密级/子角色** 三重交集。
> 展示系统已细化到二级页面（DS-01~30）× 级别 × 屏幕，按钮按 6 类功能（display/showcase/interact/deep/personal/manage）映射屏幕；详见配套 `权限点清单-菜单与按钮.md` §2.1 / §2.5 与 `level-perms-matrix.yaml`。

## 9. 数据权限与密级（独立于页面权限）

### 9.1 密级分层（4 级，🟡 待甲方确认）

| 密级 | 代号 | 含义 | 最低可见级别 |
|---|---|---|---|
| 公开 | `PUBLIC` | 可对外展示、可上大屏 | L0 |
| 内部 | `INTERNAL` | 注册/专业用户可见 | L1/L2 |
| 敏感 | `SENSITIVE` | 联系方式、尽调、个体明细 | L3 |
| 涉密 | `RESTRICTED` | 风险预警、推演底稿、特定名单 | L3（+审计）/ 限定身份 |

### 9.2 敏感字段清单（样板，🟡 待甲方）

| 主题 | 敏感字段（SENSITIVE+） | 脱敏规则 |
|---|---|---|
| 企业 | 联系方式、法人、股权、财务明细、痛难点底稿、招引/培育名单 | L2 以下打码/隐藏，L3 完整 |
| 人才 | 联系方式、个人画像明细、尽调报告 | 招标 1.1.1.1.4.3.3.1.4 原文要求"敏感信息仅授权展示" |
| 政策 | 推演参数底稿、效果评估底稿 | L3 可配置，L2 仅看结果 |

### 9.3 数据范围过滤（按身份）
- 按**区域 / 领域 / 机构 / 项目**维度限定可见数据子集（如某区用户仅看本区企业）。
- 范围由身份场景 + 账号属性（所属单位/区域）决定，与级别叠加生效。

## 13. 权限技术模型（对齐架构基线 D6）

```
统一账号(SSO) → 网关统一鉴权 → 统一权限服务（RBAC）
  权限点 = {系统, 场景, 页面, 功能, 数据密级, 资源, 设备}
  授权 = 账号 →(多)角色 → 级别(L) + 身份(Persona) + 数据范围 + 子角色(L4)
```

| 权限类型 | 控制对象 | 校验位置 |
|---|---|---|
| 系统权限 | 能否进入展示/专题系统 | 网关 |
| 场景权限 | 决策/创新/智库/接待 | 网关 + 前端路由守卫 |
| 页面权限 | 一/二/三级页面 | 前端路由 + 后端接口 |
| 功能权限 | 查看/下钻/导出/推演/播放/维护/审核/发布 | 后端接口 + 前端 Gate |
| 数据权限 | 区域/领域/机构/密级 | 数据服务（行级/列级） |
| 资源权限 | 数据/图谱/指标/报告/设备资源 | 资源服务 |
| 设备权限 | 超大屏/中屏/小屏/直播间 | 设备/播控服务 |

- 业务服务**只声明所需权限点**，不自行实现鉴权（D6）。
- 前端沿用"非阻断 Gate"：越权弱化 + 锁标 + 升级引导，埋点记录 `user_level`。
- 敏感数据列级脱敏在数据服务层完成，前端不做"假脱敏"。

## 16. 与范围铁律的关系

- 角色权限是**横切能力（D6）**，不计入 58 功能点 ±10% 基线；新增角色/级别不触发范围变更，但**界面行为（脱敏/导出/推演开关）**须在对应 DS/E 功能点内实现，不另立功能点。
- 涉及"接待场景大屏""政策推演""敏感人才详情"等均有招标原文依据（§参见关联文档行号），非超范围。
