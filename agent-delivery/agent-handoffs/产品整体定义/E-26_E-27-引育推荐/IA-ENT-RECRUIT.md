## 1. 模块边界

- **解决的问题**：在企业分析中，为招商引资和本地企业培育提供可筛选、可排序、可解释、可报告和可导出的企业推荐结果；同时承接从企业查询或对比篮进入的人工线索，以“指定对象复核分析”产生可供人工决策的引育证据。
- **承接内容**：
  - E-26：从全国企业范围筛选高成长性、关键技术型、“隐形冠军”或“专精特新”招引对象，形成招引推荐指数、优选企业清单、行业领域排名、推荐依据、核心优势、关键指标、合作价值和分析报告。
  - E-27：从深圳市内企业识别具备潜力但面临发展瓶颈的高培育价值对象，形成培育推荐指数、优选企业排名、行业分布、发展瓶颈、培育建议、所需支持、详细分析报告和数据导出。
  - 模型交付：两类模型均承接 Bid 中的多源数据输入、阈值 / 权重、历史样本训练与优化、动态监测更新、RESTful API、SDK 及在线平台调用能力；未确定的路径、触发阈值和 SDK 形态作为阻断项，不在产品包中臆造。
- **页面形态**：一个“引育推荐”二级页面，包含“招引推荐”和“培育推荐”两个独立视图；每个视图内含“条件筛选推荐 / 候选工作台”两种工作入口。
- **不承接内容**：企业全库搜索、异步任务中心、通用历史资产中心、模型公式编辑、全局权重维护、企业评估与风险洞察的计算过程、完整一企一策生成或服务派单。
- **闭环边界**：候选工作台由引育推荐拥有；对比篮只暂存和分发对象；企业评估 / 风险洞察只生成专业证据；是否保留、待定或排除始终由用户在引育候选工作台手工确认。
- **视图隔离**：两视图可以共享页面壳层和系统状态规则，但不得混用对象范围、筛选条件、模型维度、名单、详情字段或推荐结论。

## 5. 核心任务流

### 5.1 招引推荐

1. 用户进入“引育推荐”，选择“招引推荐”。
2. 用户按企业标签、行业领域或地域来源设置条件。
3. 用户显式执行推荐分析；页面展示处理中状态，不预置虚构名单。
4. 系统返回招引推荐指数、完整优选企业清单和企业行业领域排名；结果区显示总数、当前筛选数与已选数，默认每页 20 家。
5. 用户可在结果内局部筛选、稳定翻页和跨页选择；局部筛选只改变当前展示集合，不重新运行模型或重编号原始排名。
6. 用户在名单中选择企业，联动查看目标特征与识别依据、三类综合维度、高潜挖掘依据、核心优势、关键指标和合作价值。
7. 用户查看模型版本、数据版本、生成时间与更新状态；有新政策或新数据时，结果明确标记待重新计算或计算中。
8. 用户生成数据分析报告或导出数据；超过暂定阈值时转为后台生成，但不扩展为通用异步任务中心。

### 5.2 培育推荐

1. 用户进入“引育推荐”，选择“培育推荐”。
2. 用户按产业类别、政策导向或企业规模设置条件；对象范围固定为深圳市内企业。
3. 用户显式执行推荐分析；页面展示处理中状态。
4. 系统返回培育推荐指数和完整优选企业排名；结果区显示总数、当前筛选数与已选数，默认每页 20 家，用户可切换查看行业分布。
5. 用户可在结果内局部筛选、稳定翻页和跨页选择；点击行业分布只筛选当前名单视图，不重新运行模型或重编号原始排名。
6. 用户在名单中选择企业，联动查看三类综合维度、本地潜力识别依据，并按“发展瓶颈 → 培育建议 → 所需支持”查看对应关系。
7. 用户查看模型版本、数据版本、生成时间与更新状态；有新政策、市场或企业数据时，结果明确标记待重新计算或计算中。
8. 用户生成详细分析报告或导出数据；超过暂定阈值时转为后台生成，但不扩展为通用异步任务中心。

### 5.3 人工线索复核与研判闭环

1. 用户在企业查询或对比篮中把企业加入招引 / 培育候选；记录来源为“人工线索”，不产生模型推荐结论。
2. 引育推荐对应视图的候选工作台展示线索来源、加入人、加入时间和当前状态；培育线索须先校验是否为深圳市内企业。
3. 用户选择一家或多家待分析企业，以与当前招引 / 培育视图相同的模型、维度、权重和数据版本执行“指定对象复核分析”。
4. 结果标记为“人工线索复核结果”；如有排名，只表示本次指定企业集合内的相对顺序，不得冒充全国 / 深圳全量排名。
5. 用户可将“已分析·待确认”企业加入对比篮，再从对比篮发起企业评估或风险洞察。
6. 目标分析页通过 `return_context_id` 返回引育候选工作台，回传任务引用和证据摘要，不直接改写推荐指数或候选状态。
7. 用户结合引育复核结果、评估和风险证据，手工选择“已确认候选 / 待定 / 已排除”。

## 8. 数据与指标边界

- 数值主层：推荐指数和三类综合推荐维度；必须使用已注册且与 bid 对齐的 `metric_id`。
- 证据层：技术匹配度、成长性、区域适配性、技术壁垒、市场增速、团队背景先作为解释证据；只有显示数值时才要求独立 `metric_id`。
- “关键指标”不是单一统计指标；实际展示的每个指标必须携带自身 `metric_id`。
- 现有指标语义不得覆盖 bid：`生态连接度 ≠ 深圳连接度`、旧培育四维公式不得继续冒充 bid 三维公式。
- 正式语义未闭合时显示 `GAP / pending_data_lead`，缺失值显示“暂无数据”，不得显示为 0。
- 招引输入必须追溯企业信用信息、行业协会、专利 / 知识产权、政府开放、财务和业务领域等 Bid 数据类别；培育输入必须追溯企业、政策、市场调研和行业动态。
- 每次分析结果必须绑定 `model_version`、`data_version`、`generated_at` 和数据覆盖 / 缺失摘要；模型训练、数据标准化与阈值管理由算法 / 数据契约承担。
- 新政策或新数据命中正式更新规则时，结果进入 `update_available / recalculating`；在新版结果完成前保留旧结果与版本标识，不静默替换。
- 大结果集必须保留完整结果语义：默认每页 20 家，可切换 20 / 50 / 100；采用服务端稳定分页，不以无限滚动或默认 Top N 替代完整名单。
- 结果内筛选只缩小展示集合；列表仍展示完整分析结果中的原始排名，不重新运行模型、不重编号，也不改变结果版本。
- 底部批量操作栏显示“已选 Z 家 / 取消选择 / 全选当前筛选结果 Y 家 / 加入对比篮”；选择跨页保留，超出对比篮剩余容量时整批阻断并提示缩小范围，禁止静默截断。
- 暂定单次指定对象复核不超过 50 家；导出不超过 1,000 家时直接生成，超过 1,000 家转为后台生成。上述阈值以 `GAP-RECRUIT-BATCH-01` 跟踪，需在 V1 会签前完成性能验证，不作为 Bid 原始要求。
