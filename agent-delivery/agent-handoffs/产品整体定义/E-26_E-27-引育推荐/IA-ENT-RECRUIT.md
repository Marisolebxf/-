## 1. 模块边界

- **解决的问题**：在企业分析中，为招商引资和本地企业培育提供可筛选、可排序、可解释、可报告和可导出的企业推荐结果；同时承接从企业查询或对比篮进入的人工线索，以“指定对象复核分析”产生可供人工决策的引育证据。
- **承接内容**：
  - E-26：从全国企业范围筛选高成长性、关键技术型、“隐形冠军”或“专精特新”招引对象，形成招引推荐指数、优选企业清单、行业领域排名、推荐依据、核心优势、关键指标、合作价值和分析报告。
  - E-27：从深圳市内企业识别具备潜力但面临发展瓶颈的高培育价值对象，形成培育推荐指数、优选企业排名、行业分布、发展瓶颈、培育建议、所需支持、详细分析报告和数据导出。
  - 模型交付：两类模型均承接 Bid 中的多源数据输入、阈值 / 权重、历史样本训练与优化、动态监测更新、RESTful API、SDK 及在线平台调用能力；未确定的路径、触发阈值和 SDK 形态作为阻断项，不在产品包中臆造。
- **页面形态**：一个“引育推荐”二级页面，包含“招引推荐”和“培育推荐”两个独立视图；每个视图内含“条件筛选推荐 / 候选工作台”两种工作入口。
- **不承接内容**：企业全库搜索、引育页自建的异步任务中心或历史资产中心、模型公式编辑、全局权重维护、企业评估与风险洞察的计算过程、完整一企一策生成或服务派单。
- **异步过程增强**：招引推荐与培育推荐均接入共享 `SYS-ANALYSIS-JOBS` 任务层，以“任务提交 → 权限与配置校验 → 数据汇聚 → 算法计算 → 结果组装”展示过程；用户可离开页面并从系统任务浮层或个人中心恢复。两类任务使用独立 `task_type`，不共享输入快照或结果。
- **闭环边界**：候选工作台由引育推荐拥有；对比篮只暂存和分发对象；企业评估 / 风险洞察只生成专业证据；是否保留、待定或排除始终由用户在引育候选工作台手工确认。
- **指定对象复核边界**：用户在候选工作台点击“执行指定对象复核”后，必须保持当前“候选工作台”Tab，在当前 Tab 内完成模型参数配置、任务提交、五阶段过程与结果输出；不得跳转或切换到“条件筛选推荐”Tab。参数配置只投影当前模型契约已提供的参数项，未闭合的阈值 / 权重不得由页面补造默认值。
- **入口状态隔离**：同一招引 / 培育视图内，“条件筛选推荐”和“候选工作台”分别保存分析状态、任务 ID、输入与参数快照、五阶段过程、结果引用、结果内筛选、分页和选择集合。切换入口只恢复目标 Tab 自身上下文，不得把另一 Tab 的处理中、成功、失败或结果列表投影过来；系统任务恢复也必须回到任务所属入口。
- **风险复核增强**：招引与培育企业详情均增加“企业风险与信用”复核区，摘要呈现司法涉诉、失信被执行、经营异常、行政处罚四类公开风险线索，并可查看明细；该区属于 `product_enhancement`，不计入推荐指数、不自动改排名或排除企业，也不替代专业法律意见。
- **视图隔离**：两视图可以共享页面壳层和系统状态规则，但不得混用对象范围、筛选条件、模型维度、名单、详情字段或推荐结论。
- **报告消费者边界**：招引分析报告与培育分析报告分别作为 `ENT-EXPORT` 的 `attraction_recommendation_analysis_report`、`cultivation_recommendation_analysis_report` 两个报告类型，复用七个固定核心章节、只读 HTML Reader 与同修订 PDF；引育推荐仍拥有业务内容、指标语义、来源快照、权限上下文和安全返回路由，`ENT-EXPORT` 不推导推荐结论。
- **数据导出边界**：“导出数据”是当前推荐结果的表格 / 数据导出，携带当前视图、筛选、排序、列、对象范围、数据版本和权限上下文；它不是报告 Reader 的格式选项，不得复用报告章节冒充推荐数据文件。

## 5. 核心任务流

### 5.1 招引推荐

1. 用户进入“引育推荐”，选择“招引推荐”。
2. 用户按企业标签、行业领域或地域来源设置条件。
3. 用户显式执行推荐分析；页面展示五阶段可视化过程，不预置虚构名单；可离开页面并从系统任务浮层或个人中心恢复。
4. 系统返回招引推荐指数、完整优选企业清单和企业行业领域排名；结果区显示总数、当前筛选数与已选数，默认每页 20 家。
5. 用户可在结果内局部筛选、稳定翻页和跨页选择；局部筛选只改变当前展示集合，不重新运行模型或重编号原始排名。
6. 用户在名单中选择企业，联动查看目标特征与识别依据、三类综合维度、高潜挖掘依据、核心优势、关键指标和合作价值；同时查看独立的企业风险与信用摘要，必要时打开明细抽屉复核公开风险线索。
7. 用户查看模型版本、数据版本、生成时间与更新状态；有新政策或新数据时，结果明确标记待重新计算或计算中。
8. 用户生成招引分析报告时，系统冻结当前来源任务与结果快照，经引育适配器提交给 `ENT-EXPORT`；可用后进入共享只读 Reader，并可下载与 HTML 同一 `report_revision_id` 的 PDF。用户也可独立导出当前推荐数据；超过暂定阈值时转为后台生成。

### 5.2 培育推荐

1. 用户进入“引育推荐”，选择“培育推荐”。
2. 用户按产业类别、政策导向或企业规模设置条件；对象范围固定为深圳市内企业。
3. 用户显式执行推荐分析；页面展示五阶段可视化过程；可离开页面并从系统任务浮层或个人中心恢复。
4. 系统返回培育推荐指数和完整优选企业排名；结果区显示总数、当前筛选数与已选数，默认每页 20 家，用户可切换查看行业分布。
5. 用户可在结果内局部筛选、稳定翻页和跨页选择；点击行业分布只筛选当前名单视图，不重新运行模型或重编号原始排名。
6. 用户在名单中选择企业，联动查看三类综合维度、本地潜力识别依据，并按“发展瓶颈 → 培育建议 → 所需支持”查看对应关系；同时查看独立的企业风险与信用摘要，必要时打开明细抽屉复核公开风险线索。
7. 用户查看模型版本、数据版本、生成时间与更新状态；有新政策、市场或企业数据时，结果明确标记待重新计算或计算中。
8. 用户生成培育分析报告时，系统冻结当前来源任务与结果快照，经引育适配器提交给 `ENT-EXPORT`；可用后进入共享只读 Reader，并可下载与 HTML 同一 `report_revision_id` 的 PDF。用户也可独立导出当前推荐数据；超过暂定阈值时转为后台生成。

### 5.3 人工线索复核与研判闭环

1. 用户在企业查询或对比篮中把企业加入招引 / 培育候选；记录来源为“人工线索”，不产生模型推荐结论。
2. 引育推荐对应视图的候选工作台展示线索来源、加入人、加入时间和当前状态；培育线索须先校验是否为深圳市内企业。
3. 用户选择一家或多家待分析企业，点击“执行指定对象复核”；页面保持当前“候选工作台”Tab，并在当前 Tab 内打开指定对象模型参数配置，显示对象摘要及模型契约实际提供的参数项。
4. 用户确认配置后提交任务；页面仍停留在候选工作台，以当前 Tab 内阶段承接五阶段过程，完成后输出“人工线索复核结果”。如有排名，只表示本次指定企业集合内的相对顺序，不得冒充全国 / 深圳全量排名。
   - 指定对象任务的过程与结果只属于候选工作台；此时主动切到条件筛选推荐，只显示该入口原有状态，不得继续显示本任务的五阶段过程或人工线索复核结果。切回候选工作台后恢复该任务进度或结果。
5. 用户可从复核结果返回候选列表；返回后恢复复核前的视图类型、候选筛选、分页和未失效的选择上下文。
6. 用户可将“已分析·待确认”企业加入对比篮，再从对比篮发起企业评估或风险洞察。
7. 目标分析页通过 `return_context_id` 返回引育候选工作台，回传任务引用和证据摘要，不直接改写推荐指数或候选状态。
8. 用户结合引育复核结果、评估和风险证据，手工选择“已确认候选 / 待定 / 已排除”。

## 8. 数据与指标边界

- 数值主层：推荐指数和三类综合推荐维度；必须使用已注册且与 bid 对齐的 `metric_id`。
- 证据层：技术匹配度、成长性、区域适配性、技术壁垒、市场增速、团队背景先作为解释证据；只有显示数值时才要求独立 `metric_id`。
- “关键指标”不是单一统计指标；实际展示的每个指标必须携带自身 `metric_id`。
- 现有指标语义不得覆盖 bid：`生态连接度 ≠ 深圳连接度`、旧培育四维公式不得继续冒充 bid 三维公式。
- 正式语义未闭合时显示 `GAP / pending_data_lead`，缺失值显示“暂无数据”，不得显示为 0。
- 招引输入必须追溯企业信用信息、行业协会、专利 / 知识产权、政府开放、财务和业务领域等 Bid 数据类别；培育输入必须追溯企业、政策、市场调研和行业动态。
- “企业风险与信用”复核区展示司法涉诉、失信被执行、经营异常、行政处罚四类记录摘要；类别映射、记录去重、状态值、来源覆盖与更新时间由 `GAP-RECRUIT-RISK-CREDIT-01` 闭合，四件套不预设真实覆盖率或权威结论。
- 风险摘要只允许表达“存在 N 项需关注 / 当前公开数据未检出 / 风险数据待核验”；禁止使用“无风险”，禁止把记录数量聚合成未批准的风险评分或等级。
- 每次分析结果必须绑定 `model_version`、`data_version`、`generated_at` 和数据覆盖 / 缺失摘要；模型训练、数据标准化与阈值管理由算法 / 数据契约承担。
- 新政策或新数据命中正式更新规则时，结果进入 `update_available / recalculating`；在新版结果完成前保留旧结果与版本标识，不静默替换。
- 大结果集必须保留完整结果语义：默认每页 20 家，可切换 20 / 50 / 100；采用服务端稳定分页，不以无限滚动或默认 Top N 替代完整名单。
- 结果内筛选只缩小展示集合；列表仍展示完整分析结果中的原始排名，不重新运行模型、不重编号，也不改变结果版本。
- 底部批量操作栏显示“已选 Z 家 / 取消选择 / 全选当前筛选结果 Y 家 / 加入对比篮”；选择跨页保留，超出对比篮剩余容量时整批阻断并提示缩小范围，禁止静默截断。
- 暂定单次指定对象复核不超过 50 家；导出不超过 1,000 家时直接生成，超过 1,000 家转为后台生成。上述阈值以 `GAP-RECRUIT-BATCH-01` 跟踪，需在 V1 会签前完成性能验证，不作为 Bid 原始要求。
