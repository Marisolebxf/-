## 模块：引育推荐

引育推荐通过一个二级页面中的两个独立视图完成两类任务：从全国企业中识别招引目标，从深圳市内企业中识别培育对象。每个视图同时支持“条件筛选推荐”和“指定对象复核”：前者由模型从对象池中优选，后者只评估从企业查询或对比篮加入的人工线索。两类分析接入共享系统任务层，以一致的五阶段过程运行并支持跨页面恢复，但任务类型、输入快照和结果保持隔离。企业详情提供独立的“企业风险与信用”复核证据，但不将风险线索写入推荐指数或自动决策。本模块拥有候选工作台，但不自建通用历史资产、模型公式编辑、专业法律意见或完整一企一策生成。

## 1. 目标用户角色

| 产品角色 | bid-reference 角色依据 | 需要完成的业务任务 |
| --- | --- | --- |
| 政府招商与产业管理人员 | 企业分析面向政府；招引模型面向政府招商部门；培育模型面向政府部门 | 形成招引优选名单或本地培育名单，为招商、政策和资源配置提供依据 |
| 园区运营与企业服务人员 | 企业分析面向园区；两类模型分别面向园区运营方 / 管理机构 | 识别园区招引目标与需重点培育的本地企业 |
| 投资机构 / 投资平台产业研究人员 | 企业分析、招引模型和培育模型均明确投资机构 / 平台 | 复核企业推荐指数、价值与潜力，辅助投资和合作匹配 |
| 行业协会产业服务人员 | 培育模型明确面向行业协会 | 查看培育排名、行业分布和所需支持，辅助行业服务 |

> 权限等级、persona、Mock 用户和既有深化材料不替代以上角色来源。行业协会仅进入培育推荐故事。

```text

│  ├─ US-ENT-RECRUIT-A1 设置条件并执行招引分析

│  └─ US-ENT-RECRUIT-A3 生成招引报告并导出数据
└─ 培育推荐 E-27

   ├─ US-ENT-RECRUIT-C2 查看培育排名、行业分布与所需支持
   └─ US-ENT-RECRUIT-C3 生成培育报告并导出数据

跨视图候选与研判闭环
├─ US-ENT-RECRUIT-L1 管理人工线索与候选状态
├─ US-ENT-RECRUIT-L2 对指定企业执行引育复核分析
├─ US-ENT-RECRUIT-L3 送入对比篮研判并返回人工确认

└─ US-ENT-RECRUIT-R3 查看并恢复异步分析过程
```

### US-ENT-RECRUIT-L1 管理人工线索与候选状态

作为招商或企业服务人员，我想在引育推荐页查看从企业查询或对比篮加入的人工线索，以便继续分析而不是让线索停留在只读记录中。

**验收：**

- 候选工作台按招引 / 培育隔离，展示企业、线索来源、加入人、加入时间和状态。
- 来自企业查询或对比篮的对象默认为“人工线索 / 待分析”，不显示为已推荐。
- 培育线索必须通过深圳市内企业范围预检；不通过时不能执行培育分析，可明确转为招引线索。
- 状态集合为“待分析 / 分析中 / 已分析·待确认 / 研判中 / 已确认候选 / 待定 / 已排除”。

### US-ENT-RECRUIT-L2 对指定企业执行引育复核分析

作为招商或企业培育人员，我想选择人工线索执行与当前引育视图一致的模型复核，以便判断指定企业是否具备引育价值。

**验收：**

- 支持选择一家或多家“待分析”企业执行指定对象复核。
- 复核使用当前招引 / 培育模型相同的维度、权重、数据版本和结果字段，不创建第三套模型。
- 结果标题明确为“人工线索复核结果”，并保留本次指定对象集合、分析模式和数据版本。
- 指定对象排名只在本次集合内有效，不得表述为全国企业或深圳市内企业的全量排名。

### US-ENT-RECRUIT-L3 送入对比篮研判并返回人工确认

作为需要审慎判断候选企业的用户，我想把拿不准的引育对象送入对比篮，再通过企业评估或风险洞察获取补充证据，以便返回引育工作台做最终人工确认。

**验收：**

- 引育结果和候选工作台可将选中企业加入对比篮，并保留引育任务上下文与 `return_context_id`。
- 对比篮只负责对象暂存和分发；企业评估 / 风险洞察按各自契约生成专业结果。
- 返回时在原候选记录上挂载任务引用、结果版本、证据摘要和查看入口，不拷贝或改写引育指数。
- 评估 / 风险结果不自动更改候选状态；只有用户可选择“已确认候选 / 待定 / 已排除”。

### US-ENT-RECRUIT-R1 浏览和批量处理大结果集

作为需要从大量推荐企业中持续研判的用户，我想在不丢失完整排名语境的前提下筛选、翻页和跨页选择，以便高效缩小名单并执行后续操作。

**验收：**

- 结果区显示“共分析 X 家 / 当前筛选 Y 家 / 已选 Z 家”，完整名单不被默认 Top N 截断。
- 采用服务端稳定分页，默认每页 20 家，可切换 20 / 50 / 100；列表保留完整分析结果中的原始排名。
- 结果内局部筛选只缩小展示集合，不重新运行模型、不改变结果版本、不将原始排名重编号。
- 表头全选仅选择当前页；底部操作栏依次提供“已选 Z 家 / 取消选择 / 全选当前筛选结果 Y 家 / 加入对比篮”，选择跨页保留。
- 超出对比篮剩余容量时整批阻断并提示缩小范围，不静默加入前若干家。
- 单次指定对象复核暂定不超过 50 家；导出不超过 1,000 家直接生成，超过后后台生成。阈值由 `GAP-RECRUIT-BATCH-01` 跟踪性能验证。
- 如提供“重点关注 Top 20”，它只能是带排序依据的快捷筛选，并同时保留“查看完整结果”。

### US-ENT-RECRUIT-R2 复核企业风险与信用线索

作为需要审慎判断引育对象的用户，我想在企业推荐详情中看到法律与信用风险摘要并查看公开记录明细，以便在招商或培育决策前完成基本风险复核。

**验收：**

- 招引与培育企业详情均在标题旁显示风险摘要状态，并在“关键指标”之后提供独立的“企业风险与信用”区。
- 风险区覆盖司法涉诉、失信被执行、经营异常、行政处罚四类公开风险线索；每类展示记录数量、最近事件时间和简短摘要。
- 风险摘要只使用“存在 N 项需关注 / 当前公开数据未检出 / 风险数据待核验”，不得使用“无风险”。
- 点击“查看风险明细”打开当前企业的明细抽屉，逐条展示风险类型、事件摘要、发生日期、当前状态、信息来源和数据更新时间。
- 风险记录缺失、来源未覆盖或查询失败时显示“风险数据待核验”，不得把缺失记录显示为 0 条或“无风险”。
- 风险数据范围、来源覆盖、企业关联、去重和状态语义由 `GAP-RECRUIT-RISK-CREDIT-01` 跟踪，闭合前不生成正式计数或法律结论。
- 风险与信用线索不进入招引 / 培育推荐指数，不自动改排名、确认、待定或排除企业，也不构成专业法律意见。

### US-ENT-RECRUIT-R3 查看并恢复异步分析过程

作为发起招引或培育分析的用户，我想看到一致的分析阶段并在离开页面后继续运行，以便不必停留等待，也能准确恢复当前任务。

**验收：**

- 招引与培育均展示“任务提交 / 权限与配置校验 / 数据汇聚 / 算法计算 / 结果组装”五阶段及已完成、进行中、等待中状态。
- 当前阶段使用信息提示条说明，处理中可选择“稍后查看”离开页面。
- 任务离开页面后继续，可从系统任务浮层或个人中心恢复。
- 招引与培育使用独立任务类型；同一视图重复提交恢复已有未完成任务，不混用另一视图的条件或结果。
- 过程不伪造百分比，不展示上一次结果冒充本次结果。

### US-ENT-RECRUIT-A1 设置条件并执行招引推荐分析

作为政府招商、园区运营或投资机构研究人员，我想按企业标签、行业领域和地域来源筛选全国企业并执行招引推荐分析，以便从全国范围锁定与深圳产业方向契合的目标企业。

**验收：**

- 招引视图明确显示对象范围为全国企业。
- 支持按企业标签、行业领域或地域来源设置条件。
- 目标特征覆盖高成长性、关键技术型、隐形冠军和专精特新；来自权威数据 / 模型契约，不由前端自定认定规则。
- 页面说明综合模型使用产业相关度、政策匹配度和深圳连接度，但不提供无依据的公式或权重编辑器。
- 用户显式点击执行分析后才进入处理中状态；未执行时不显示默认名单或 DEMO 分数。
- 分析条件不会联动或覆盖培育推荐视图的条件。

### US-ENT-RECRUIT-A2 查看招引名单与企业价值

作为招商或产业研究人员，我想从招引名单中选择企业并查看推荐依据和合作价值，以便判断优先对接对象。

**验收：**

- 招引名单以排名为主，展示企业名称、行业领域、地域来源和招引推荐指数。
- 企业行业领域排名在语义闭合后可展示；未闭合时标记 GAP，不展示伪排名。
- 选择名单行后，企业详情与名单联动，不跳离筛选现场。
- 详情呈现产业相关度、政策匹配度、深圳连接度三类综合推荐维度。
- 技术匹配度、成长性、区域适配性作为高潜挖掘证据；若没有独立 `metric_id`，只作解释字段，不显示伪分数。
- 核心优势、关键指标和合作价值均有落点；关键指标中的每个统计项携带自身 `metric_id`。
- 名单或详情显示命中的目标特征与识别依据；“企业标签”不能冒充隐形冠军或专精特新认定。
- 结果显示模型版本、数据版本、生成时间、数据覆盖摘要和动态更新状态。

### US-ENT-RECRUIT-A3 生成招引分析报告并导出数据

作为招商或产业研究人员，我想从当前招引结果生成分析报告并导出数据，以便开展招商对接、内部研判和后续协作。

**验收：**

- 当前招引结果页提供“生成分析报告”和“导出数据”入口。
- 生成中、可用和失败状态在当前页面反馈；失败不清空当前名单。
- bid 未定义文件格式、报告模板和字段范围时，页面不预先宣称具体格式。
- 不新增历史任务中心、个人资产中心或独立导出菜单。

### US-ENT-RECRUIT-C1 设置条件并执行培育推荐分析

作为政府、园区、投资平台或行业协会人员，我想按产业类别、政策导向和企业规模筛选深圳市内企业并执行培育推荐分析，以便发现具有培育价值的本地企业。

**验收：**

- 培育视图明确显示对象范围为深圳市内企业。
- 支持按产业类别、政策导向或企业规模设置条件。
- 页面说明综合模型使用产业相关度、政策匹配度和企业潜力，但不提供无依据的公式或权重编辑器。
- 用户显式点击执行分析后才进入处理中状态。
- 全国招引企业、招引筛选和招引结论不会混入培育视图。

### US-ENT-RECRUIT-C2 查看培育排名、行业分布与所需支持

作为企业培育或产业服务人员，我想从培育排名中查看企业潜力、行业分布和所需支持，以便制定精准扶持政策和“一企一策”。

**验收：**

- 企业排名为主工作区，展示排名、企业名称、产业类别、企业规模和培育推荐指数。
- 行业分布作为补充结果视图，不遮挡或取代企业排名。
- 选择名单行后联动展示产业相关度、政策匹配度和企业潜力。
- 技术壁垒、市场增速、团队背景作为本地潜力识别证据；无独立 `metric_id` 时不显示伪分数。
- 详情明确展示所需支持，并说明其可作为定制“一企一策”的依据；不在本模块直接生成完整政策方案或服务工单。
- 详情明确展示发展瓶颈、瓶颈证据、培育建议和所需支持的对应关系；不把风险洞察结果替代培育模型的瓶颈识别。
- 结果显示模型版本、数据版本、生成时间、数据覆盖摘要和动态更新状态。

### US-ENT-RECRUIT-C3 生成培育分析报告并导出数据

作为企业培育或产业服务人员，我想从当前培育结果生成详细分析报告并导出数据，以便开展政策制定、投资决策和合作匹配。

**验收：**

- 当前培育结果页提供“生成分析报告”和“导出数据”入口。
- 报告保留培育排名、行业分布、推荐维度和所需支持的业务语境。
- 报告或导出失败时保留当前结果和筛选条件，并允许重试。
- 不把培育报告扩展为风险洞察报告、企业评估报告或完整一企一策。

## 3. 主路径 walkthrough

### 3.1 招引推荐

1. 用户从企业分析进入“引育推荐”，默认或主动选择“招引推荐”。
2. 页面显示全国企业范围，以及企业标签、行业领域和地域来源筛选。
3. 用户设置条件并执行推荐分析；页面保留条件并显示五阶段可视化过程，可稍后从系统任务浮层或个人中心恢复。
4. 分析完成后展示完整优选企业清单、招引推荐指数和可用的行业领域排名；默认每页 20 家。
5. 用户在结果内局部筛选、稳定翻页并跨页选择；页面保留原始排名，底部明确已选数和全选当前筛选结果的作用范围。
6. 用户选择企业，右侧详情联动展示目标特征与识别依据、综合维度、高潜挖掘依据、核心优势、关键指标和合作价值；标题显示风险摘要，用户可在“企业风险与信用”区打开明细抽屉复核公开记录。
7. 页面展示模型 / 数据版本与动态更新状态；新政策或新数据触发更新时，保留旧结果直至新版本完成。
8. 用户生成分析报告或导出数据。

### 3.2 培育推荐

1. 用户选择“培育推荐”，页面切换为深圳市内企业范围。
2. 页面显示产业类别、政策导向和企业规模筛选。
3. 用户设置条件并执行推荐分析；页面保留条件并显示五阶段可视化过程，可稍后从系统任务浮层或个人中心恢复。
4. 分析完成后展示完整企业排名并默认每页 20 家；用户可切换查看行业分布。
5. 用户在结果内局部筛选、点击行业分布筛选名单、稳定翻页并跨页选择；页面保留原始排名和结果版本。
6. 用户选择企业，右侧详情联动展示综合维度、识别证据和“发展瓶颈 → 培育建议 → 所需支持”；标题显示风险摘要，用户可在“企业风险与信用”区打开明细抽屉复核公开记录。
7. 页面展示模型 / 数据版本与动态更新状态；新政策、市场或企业数据触发更新时，保留旧结果直至新版本完成。
8. 用户生成详细分析报告或导出数据。

### 3.3 人工线索复核与研判闭环

1. 用户在企业查询或对比篮中选择“加入招引候选 / 加入培育候选”。
2. 用户进入引育推荐的对应候选工作台；线索以“人工线索 / 待分析”展示。
3. 培育线索先做深圳市内范围预检；用户选定对象并执行“指定对象复核分析”。
4. 结果标记为“人工线索复核结果”，用户将拿不准的企业加入对比篮。
5. 用户从对比篮发起企业评估或风险洞察，完成后通过 `return_context_id` 返回原候选工作台。
6. 用户结合引育分析与补充证据，手工确认、待定或排除。

## 4. 异常与降级路径

| 场景 | 页面行为 | 用户下一步 |
| --- | --- | --- |
| 初始未分析 | 展示当前视图条件，不展示默认名单或虚构分数 | 设置条件并执行分析 |
| 分析中 | 保留条件，展示五阶段与当前阶段，防止重复提交，不用旧结果冒充本次结果 | 等待结果或稍后从系统任务浮层 / 个人中心恢复 |
| 空结果 | 明确“分析成功但无匹配企业”，保留全部条件 | 调整条件后重新分析 |
| 部分数据缺失 | 保留可用名单；缺失字段显示“暂无数据”，报告披露缺失项 | 查看可用结果或调整条件 |
| 有新政策 / 新数据 | 标记“有可用更新”，展示当前模型 / 数据版本；重新计算时保留旧结果 | 等待自动更新或按契约重试 |
| 模型 / 数据版本不一致 | 禁止无标识地混用排名和指数，保留上一版可追溯结果 | 等待版本对齐或重新分析 |
| 指标语义待确认 | 在具体字段旁显示 `GAP / pending_data_lead` | 等待 Data / 算法 / 何老师闭合 |
| 分析失败 | 保留条件并说明失败，不表现为空结果 | 按原条件重试 |
| 无权限 | 不显示结果数量、排名、详情或导出内容 | 返回或申请授权 |
| 报告 / 导出失败 | 保留当前结果，显示当前操作失败 | 重试或继续查看结果 |
| 结果数量过多 | 保留完整结果与总数，按默认 20 家稳定分页，并提示使用结果内筛选 | 筛选、翻页或调整每页数量 |
| 局部筛选后已选企业不可见 | 保留跨页 / 跨筛选选择并持续显示已选数 | 查看已选对象或取消选择 |
| 加入对比篮超出剩余容量 | 整批阻断并显示剩余容量，不截取部分企业 | 缩小选择范围后重试 |
| 指定对象复核超过暂定 50 家 | 阻止提交并提示分批或缩小范围 | 调整至允许范围；等待性能阈值验证 |
| 导出超过暂定 1,000 家 | 转为后台生成并在当前页面反馈状态 | 继续浏览结果或等待生成完成 |
| 培育线索非深圳市内企业 | 预检不通过，禁止培育复核 | 转为招引线索或移除 |
| 部分线索重复 | 保留原记录，返回新增 / 重复数量 | 继续处理未分析线索 |
| 外部研判返回上下文失效 | 保留候选记录，提示任务证据需重新关联 | 从评估 / 风险历史结果手工关联或重新研判 |
| 风险记录未覆盖或查询失败 | 风险摘要与四类记录均显示“风险数据待核验”，保留其他推荐详情 | 稍后重试或转由线下尽调；不阻断查看推荐结果 |
| 当前公开数据未检出记录 | 显示“当前公开数据未检出”并同时展示数据更新时间与覆盖说明 | 继续复核；不得理解为企业“无风险” |

## 7. 非页面系统协作验收

> RESTful API 与 SDK 是 Bid 的模型调用形态，但 Bid 未定义新的人类产品角色，因此不虚构“系统集成员”用户故事，以直接需求契约验收。

| 需求 | 可测试结果 |
| --- | --- |
| `DR-ENT-RECRUIT-A-09` | 招引模型登记 RESTful API、SDK 和在线平台三种形态；可按企业标签、行业领域、地域来源查询，并获取分析、报告和导出。 |
| `DR-ENT-RECRUIT-C-09` | 培育模型登记 RESTful API、SDK 和在线平台三种形态；可按产业类别、政策导向、企业规模查询，并获取分析、报告和导出。 |
| 架构边界 | 对外契约经网关 / Java 聚合服务提供，不直接暴露 Python 内部接口；输入输出携带模型 / 数据版本。 |
| 待闭合项 | URL、认证、版本、错误码、SDK 语言与发布形态保持 `GAP-RECRUIT-API-01`，未确认前不得自行声称。 |

## 8. 评审追溯验收

- A1 / A2 / A3 在评审模式引用 `ENT-RECRUIT-F01-CONFIG-TITLE`、`ENT-RECRUIT-F02-RESULT-TITLE`、`ENT-RECRUIT-F02-METRIC-DETAIL`、`ENT-RECRUIT-F02-MODEL-STATUS`。
- C1 / C2 / C3 在评审模式引用 `ENT-RECRUIT-F03-CONFIG-TITLE`、`ENT-RECRUIT-F04-RESULT-TITLE`、`ENT-RECRUIT-F04-METRIC-DETAIL`、`ENT-RECRUIT-F04-MODEL-STATUS`。
- RESTful API / SDK 契约在评审模式引用 `ENT-RECRUIT-F06-SERVICE-CONTRACT`。
- 大结果集产品解释在评审模式引用 `ENT-RECRUIT-F02-LARGE-RESULT`、`ENT-RECRUIT-F04-LARGE-RESULT`。
- 企业风险与信用增强在评审模式引用 `ENT-RECRUIT-F02-RISK-CREDIT`、`ENT-RECRUIT-F04-RISK-CREDIT`。
- 异步分析过程引用系统任务包的 `SYS-JOBS-F03-PROCESS-TITLE`，由共享组件自门控。
- 业务模式必须移除所有评审标记，且不得改变业务字段、权限、结果或服务契约。
