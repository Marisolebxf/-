# 科技信息展示系统角色权限体系

## 1. 系统定位

科技信息展示系统不是后台管理系统，也不是专题分析工作台，核心定位是面向不同业务场景的科技信息可视化展示与交互决策系统。

系统包含线上和线下两种服务方式：

- 线上服务：基于算力、信息分析模型、知识图谱和智能分析能力，提供人机互动、感知交互、科技信息智能分析、决策模拟和可视化展示。
- 线下服务：依托展示与服务中心的超大屏、音频灯光、直播间等设备设施，提供现场展示、接待演示、研讨汇报和成果呈现。

因此，科技信息展示系统的权限设计重点不是单纯的后台菜单控制，而是围绕以下问题展开：

- 谁能看哪些展示场景？
- 谁能进入哪些专题页面？
- 谁能进行地图、图层、图谱、指标下钻？
- 谁能控制大屏播放和现场演示？
- 谁能维护展示内容、图谱关系和数据资源？
- 谁能审核并发布上屏内容？

## 2. 主要业务场景

| 场景 | 面向对象 | 权限重点 |
|---|---|---|
| 决策场景 | 政府用户 | 看全局、看风险、看推演、看政策效果 |
| 创新场景 | 高校、科研机构、企业 | 看技术、人才、机构、成果、供需对接 |
| 智库场景 | 智库用户 | 看前沿洞见、城市评价、人才竞争力、辅助决策 |
| 接待场景 | 访问人员 | 看演示专题、成果展示、服务全景，不允许编辑 |

## 3. 建议角色体系

| 角色 | 核心权限 |
|---|---|
| 展示系统超级管理员 | 管理全部展示页面、专题、用户、角色、设备、数据资源、图谱资源、接口和日志 |
| 展示系统管理员 | 配置展示专题、页面菜单、场景权限、展示资源、屏幕播放策略 |
| 政府决策用户 | 查看科技发展态势、政策跟踪、政策效果推演、风险预警、科技指数、规划服务 |
| 创新主体用户 | 查看技术发展、人才态势、机构画像、科技成果、产业服务、供需对接类展示内容 |
| 智库研究用户 | 查看前沿洞见、创新评价、人才竞争力评价、专家协同、辅助决策结果 |
| 展示讲解员 | 打开展示专题、切换大屏页面、播放讲解路线、切换中屏/小屏内容、控制演示状态 |
| 接待访客用户 | 只读访问指定接待专题、成果展示、科技服务全景，不可下钻敏感数据 |
| 数据维护用户 | 维护展示数据源、图层数据、指标数据、科技数据资源、数据接入状态 |
| 图谱维护用户 | 维护技术图谱、关键实体、实体关系、图谱版本、修改历史 |
| 内容运营用户 | 维护专题文案、成果展示内容、服务全景内容、展示讲解材料 |
| 审核发布用户 | 审核展示专题、图谱变更、内容发布、数据上屏、对外展示版本 |
| 设备/现场运维用户 | 管理超大屏、中屏、小屏、直播间、播放设备、展示状态和故障处理 |

## 4. 页面模块权限

科技信息展示系统包含 7 个大功能模块：

- 科技发展态势
- 科技政策跟踪
- 科技人才态势
- 科技数据资源
- 科技知识图谱
- 科技成果展示
- 科技服务全景

各模块建议按查看权限和高级权限分别控制。

| 模块 | 查看权限 | 高级权限 |
|---|---|---|
| 科技发展态势 | 查看全域态势、全球/湾区/深圳监测、科技指数 | 配置指标、切换图层、导出、配置展示卡片 |
| 科技政策跟踪 | 查看政策全景、政策分析、政策效果推演 | 配置推演参数、维护政策口径、发布政策专题 |
| 科技人才态势 | 查看人才分布、人才画像、引进推荐评估 | 查看敏感人才详情、导出尽调报告、调整推荐条件 |
| 科技数据资源 | 查看总体视窗、接入视窗、主题视窗、应用视窗 | 管理数据源、接口、资源状态、数据质量 |
| 科技知识图谱 | 查看分析展示、指标展示、算法展示、服务展示 | 编辑图谱节点、关系、版本、关键实体 |
| 科技成果展示 | 查看软科学成果、生态展示、时空演进、仪器共享等 | 维护成果内容、配置展示顺序、发布展示专题 |
| 科技服务全景 | 查看创新生态、智库服务、科技交流、竞赛、传播 | 维护服务内容、配置服务入口、管理展示材料 |

## 5. 操作权限分层

| 权限层 | 说明 |
|---|---|
| 只读查看 | 看页面、看图表、看大屏、看专题 |
| 交互下钻 | 地图缩放、图层开关、节点点击、详情查看、时间筛选 |
| 分析推演 | 输入决策参数、查看推演结果、方案对比 |
| 展示控制 | 大屏播放、页面切换、演示模式、讲解路线、全屏控制 |
| 内容维护 | 维护专题内容、图谱节点、关键实体、展示文案、成果材料 |
| 发布审核 | 审核后上屏、对外发布、版本回滚、操作留痕 |

## 6. 关键权限边界

| 边界 | 原因 |
|---|---|
| 接待用户不能看敏感下钻 | 接待场景只适合展示成果和概览，不适合暴露企业、人才、政策细节 |
| 讲解员能控制展示但不能改数据 | 防止现场演示时误改图谱、指标或展示内容 |
| 政府用户可看推演结果，但参数配置应分级 | 政策效果推演涉及口径和模型输入，不能所有人都能改 |
| 图谱维护必须有版本和审核 | 图谱支持节点、关系、实体维护，必须可追溯 |
| 数据资源权限要按来源、主题、密级控制 | 科技数据资源涉及接入、主题、应用视窗，不能只做页面级权限 |
| 大屏展示要有上屏审核 | 避免未确认数据或草稿内容直接进入线下展示 |

## 7. 权限模型建议

建议采用“统一账号 + 多角色授权 + 场景权限 + 页面权限 + 功能权限 + 数据权限 + 资源权限”的权限模型。

| 权限类型 | 控制对象 |
|---|---|
| 系统权限 | 能否进入科技信息展示系统 |
| 场景权限 | 能否访问决策场景、创新场景、智库场景、接待场景 |
| 页面权限 | 能否访问某个一级/二级/三级展示页面 |
| 功能权限 | 能否查看、下钻、导出、推演、播放、维护、审核、发布 |
| 数据权限 | 能看哪些区域、领域、机构、企业、人才、政策、项目和成果 |
| 资源权限 | 能否访问数据资源、图谱资源、指标资源、报告资源、设备资源 |
| 设备权限 | 能否控制超大屏、中屏、小屏、直播间和现场播放设备 |

## 8. 总结

科技信息展示系统的角色权限体系，应以“场景访问 + 展示控制 + 数据下钻 + 图谱维护 + 内容发布 + 设备运维”为主，而不是单纯后台的用户、角色、页面权限。

该系统更像一个可视化展示与决策演示中心，权限设计要重点保护：

- 上屏内容
- 敏感下钻数据
- 决策推演参数
- 图谱维护动作
- 展示专题发布
- 现场设备控制
