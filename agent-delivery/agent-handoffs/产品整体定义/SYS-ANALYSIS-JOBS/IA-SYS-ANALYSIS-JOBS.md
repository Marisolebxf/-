## 1. 模块边界

### 1.1 解决的问题

科技专题服务系统中的大模型、复杂算法分析和报告生成可能持续较长时间。用户不应被迫停留在发起页面，也不应因页面切换、刷新、关闭浏览器或重新登录而丢失任务状态。本模块建立跨业务域共享的任务体验与接入协议，使用户能够：

1. 同时运行不同类型的长耗时分析任务。
2. 防止当前用户重复提交同一类型的非终态任务。
3. 在系统容量满载时进入有界队列，而不是反复提交。
4. 从系统级浮层查看自己的任务，并跳回来源模块。
5. 在来源模块恢复完整任务过程页。
6. 让所有创建报告文件的位置统一进入报告生成队列。
7. 在任务完成、失败或管理员异常终止后得到一致反馈和历史留痕。

### 1.2 承接内容

- 服务端任务真源及统一状态语义。
- `发起用户 + task_type` 的分析任务互斥。
- 分析队列与报告生成队列的独立容量和排队规则。
- 应用 Shell 层的系统任务浮层。
- 来源模块内的完整分析过程页恢复。
- 来源业务页内的报告任务弹层恢复。
- 页面、标签页、设备和重新登录后的同源状态恢复。
- 报告指纹复用、来源快照绑定、文件生成与个人资产投影。
- 普通用户不可取消运行中任务；管理员异常终止的运维边界。

### 1.3 不承接内容

- 不定义技术力、商业力、产业链等业务模型、指标、权重或结果内容。
- 不把名称含“分析”的同步查询、统计聚合或确定性映射能力自动改造成后台任务。
- 不把重点企业领域分布分析纳入长耗时大模型任务。
- 不展示或影射其他用户的任务、对象、参数、身份或资源占用详情。
- 不把系统任务浮层扩展为通用审批、协作或完整历史任务中心。
- 不在产品定义中硬编码分析并发数、报告并发数、队列长度或保留时长。
- 不允许普通用户取消已经进入运行中的分析或报告任务。
- 不在报告阶段重新执行来源分析、评分或排名。
- 不为报告任务新建脱离来源业务结果的独立过程页。
- 不替代个人资产中心的完整文件记录和下载历史。

## 2. 来源与范围分类

### 2.1 原始能力上下文

Bid 中存在多类深度分析、模型计算、分析报告、报告生成与导出能力，也明确服务政府、高校、科研机构、智库和企业等对象；但 Bid 没有直接定义系统级任务浮层、跨模块任务队列、个人互斥键、跨登录恢复或统一报告队列。

因此：

- 各业务分析与报告能力仍由各自 Bid 叶子和模块四件套负责。
- 本模块的系统浮层、任务调度体验和报告任务协议不计入 `direct_requirement`。
- 本模块全部活跃故事均分类为经用户批准的 `product_enhancement`。
- `coverage_summary.leaves_required = 0`，不得用 0/0 反向宣称覆盖了业务模块 Bid 叶子。

## 6. 任务分类与接入判定

### 6.1 分析生成任务

一个能力只有同时满足以下条件，才接入 `analysis_generation`：

1. 由用户明确提交。
2. 后端需要长耗时异步运行。
3. 用户离开页面后仍需继续。
4. 状态必须跨页面、标签页、设备或重新登录恢复。
5. 成功后产生独立、不可变的结果快照。

仅同步查询、统计聚合、关系浏览、确定性映射或读取既有结果，不因名称含“分析”而接入。

### 6.2 报告生成任务

所有“创建报告文件”的入口统一接入 `report_generation`，包括企业、产业链及后续其他业务域。以下情形不创建报告任务：

- 下载已经存在且仍有效的报告文件。
- 查看在线结果。
- 不生成报告文件的普通表格查询。

报告任务必须绑定来源快照和来源路由，不得脱离来源事实重新评分或分析。

### 6.3 业务模块接入登记

| 字段 | 分析任务 | 报告任务 |
| --- | --- | --- |
| `task_class` | `analysis_generation` | `report_generation` |
| `task_type` | 稳定的业务分析类型 | 稳定的报告类型 |
| 唯一规则 | `user_id + task_type` 的排队/运行唯一 | `report_fingerprint` 复用 |
| 来源 | 配置快照 | 已完成结果 / 查询上下文快照 |
| 恢复 | 完整过程页 | 来源业务页 + 报告弹层 |
| 完成产物 | 不可变业务结果快照 | PDF / Word 等报告文件 |
| 历史去向 | 来源模块最近记录 / 个人资产投影 | 个人资产中心报告记录 |

## 7. 核心任务规则

### 7.1 个人互斥

- 同一用户、同一 `task_type` 最多一个排队中或运行中分析任务。
- 当前用户已有非终态任务时，再次进入该分析类型恢复原任务，不创建第二个任务。
- 不同 `task_type` 可以同时提交。
- 其他用户的同类任务不形成业务互斥，也不在产品界面暴露。

### 7.2 系统容量

- 分析队列和报告队列使用独立并发上限。
- 并发数和队列最大长度由环境管理员配置，不写死在产品规则。
- 首期每个分析任务占一个槽位；协议预留未来按 `task_type` 配置权重。
- 执行槽满载时进入有界队列；队列满载后才拒绝。
- 产品界面可显示队列位置，不承诺预计等待时间。

### 7.3 取消、失败与重试

- 排队中的任务允许发起人撤回。
- 已进入运行中的任务不提供普通用户取消。
- 失败释放互斥键与执行槽，保留失败阶段和错误编号。
- 用户重试时基于原配置创建新任务，使用新 `task_id`，并登记 `retry_from_task_id`。
- 管理员只在故障或资源异常时强制终止，并必须记录操作者、原因、时间和审计编号。

### 7.4 完成与浮层保留

- 刚完成或刚失败任务在浮层保留到用户确认，或由可配置的短暂通知周期移除。
- 完整历史不长期堆积在浮层。
- 完成分析跳到来源结果页；完成报告允许下载并进入个人资产中心。

## 8. 主流程

### 8.1 分析任务

1. 用户在已接入模块完成配置并提交。
2. 来源模块权限和配置预检通过。
3. 系统检查 `user_id + task_type` 是否已有非终态任务。
4. 系统检查分析执行槽和队列容量。
5. 任务进入排队或运行；来源模块显示完整过程页。
6. 用户离开后，任务继续执行，系统浮层持续显示。
7. 用户从浮层、原路由或重新登录后恢复同一任务。
8. 成功后开放结果；失败后释放资源并允许基于原配置创建新任务。

### 8.2 报告任务

1. 用户在来源业务页点击生成报告。
2. 系统冻结来源结果或查询上下文快照并校验报告权限。
3. 生成 `report_fingerprint`。
4. 同指纹处理中任务直接恢复；有效成品直接下载；失败、过期或来源快照变化才创建新任务。
5. 新任务进入独立报告队列，弹层可关闭并后台继续。
6. 系统浮层显示报告任务；点击返回来源页并自动打开报告弹层。
7. 完成后进入个人资产中心并开放下载。
