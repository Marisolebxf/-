## 1. 知识图谱是什么（以及不是什么）

**是**：一批**点**（实体）和**边**（关系）放在一起，既能按名字找到点，也能问「这个企业和哪些机构合作」。画出来是网，存起来是图数据。

**不是**：

- 不是普通报表。报表问的是「今年专利多少件」；图问的是「这些专利的权利人如何连到这条产业链」。
- 不是搜索引擎全文。搜索可以先帮你定位到一个点，再从图上扩出去。
- 不是大模型本身。大模型可以**读**图上的结果写报告；**建图**靠清洗、对齐、规则和脚本。

本项目招标里的「产业全要素图谱」= 把产业、技术、企业、机构、人才、政策、服务机构连成一张可查询的网，并提供检索、关系、可视化、相似度、网络指标等 API。

## 2. 本体、Schema、实例图：三个层次

| 词 | 含义 | 本项目落点 |
| --- | --- | --- |
| **本体 Ontology** | 允许有哪些**种类**的点和边（企业可以、论文默认不可以单独成类） | 01 的七要素 + 五链边族 |
| **Schema** | 引擎里具体 Tag/Edge 名称、属性字段 | 亿集 Schema；由 GDF 变更窗管理 |
| **实例图** | 真实的「华为–某环节–某政策」一条条数据 | DWD 账本 + 亿集当前投影 + 已发布切面 |

「禁止第二套本体」= 不要为展示模块再发明一套点种类。可以增加**场景行**（这个页读哪些点边），不能增加**平行宇宙**。

主键必须是 **项目自己的企业 ID / 环节 ID**。合作方引擎内部还有 vid，那是发动机零件号，不能当对外合同字段。

## 3. 图上三类活：查、算、打分

| 类型 | 直觉 | 本项目标签 | 耗时 |
| --- | --- | --- | --- |
| 查子图 | 「把这个人两跳以内的合作画出来」 | G1 | 同步 HTTP，秒级 |
| 图算法 | 「谁是结构上的枢纽」「有没有一条路径」 | G2 | 视规模；没有现成模型就 501 |
| 子图打分 / 生成分析 | 「这条链的瓶颈在哪、该招谁」 | G3 | 常要排队，用 Job，离开页面不能丢 |

**中心性**：大致是「谁连得很多 / 谁在路上」。  
**社群**：大致是「谁和谁抱团」。  
**相似度**：两个名字或两个实体有多像，往往要深度学习模型，没有模型不能编一个分数。

**指标（M）**：专利数量、GDP、指数。它们住在 **ADS 表**里，经指标目录展示。把「区域产业指数」说成图算法，验收时会对不上公式和血缘。

## 4. 为什么「任意一天的整图」做不到（时间）

理想说法：「给我 2024-06-30 当天完整产业链」。那需要每个点和每条边都有历史版本。

本项目数据设计（DWD v5）实际是：

- **链、环节节点**：只保留**当前**属性（SCD1：新值覆盖旧值）。昨天的环节名称可能已经找不到。
- **关系**：带有效期，半开区间 `[valid_from, valid_to)` —— 像合同：从哪天生效，到哪天结束（结束当天不算）。

所以：

- **边**可以问「截至 T 哪些关系还活着」。
- **整图（含节点上写着的话、布局坐标）**不能靠「任意 T 现算」，除非当时做了一次 **发布**：把那天活着的边裁出来，配上当时的节点和坐标，**冻成一包**。这就是 B 面切面。

时间轴 = 翻这些冻包的目录，不是播放直播回放。

节点属性标注「以发布时刻为准」，**不要**对用户说「你看到的企业简介也是截至 T 的官方历史」。这是 CUT-D3。

## 5. 三套「快照」为什么必须分家

工程里很多东西都叫 snapshot，业务文案尽量避开「快照」这个词，但库表仍可能用 `snapshot_id`。

| 名字 | 冻的是什么 | 给谁用 |
| --- | --- | --- |
| 图谱发布包 `graph_snapshot` | 某条链某个截至日的**结构图** | 全景当前/对比/时间轴 |
| Job Input/Result Snapshot | 一次「生成分析」的原料和成品 | 诊断、推荐、报告 |
| CMS 发展历程 | 编辑写的阶段故事 | 门户介绍，不是图 |

混进一张表的后果：分析结论污染结构对比；时间轴出现「化验单」；无法回答「这张图是谁发布的」。

## 6. 数据分层：ODS / DWD / ADS（为什么 Java 只读 ADS）

| 层 | 像什么 | 谁写谁读 |
| --- | --- | --- |
| 供应方库 `gkx` | 别人家的原始账本 | 只读，GDF 贴源 |
| **ODS** | 原样复印件 | 项目贴源，不改结构 |
| **DWD** | 我们自己的明细标准（企业、环节、带有效期的边） | 数据产线写；建图从这里读 |
| **ADS** | 给页面用的宽表、指标、发布包 | Python 写；**Java 只读** |

Java 不扫 ODS/DWD 拼业务 API，是为了：契约稳定、权限清晰、算法和 API 分工。图的历史入口在 ADS 发布包，不在 Java 里现场跑 nGQL。

**ES**：全文检索（资讯、政策文本）。和「图上的边」互补：文本找不到关系，图不擅长长文章。

## 7. 调用链：为什么前端不能直连 Python 或图库

约定：

```text
浏览器  →  网关  →  Java（鉴权、聚合、只读 ADS）  →  Python /internal（算法、查图、写 ADS）
```

原因很实际：鉴权与租户在网关/Java 统一；算法与图驱动只维护一套；出了问题用一条 `traceparent` 从按钮追到脚本。

**D12**：正式前端 `lumen-ui-*` 不许打到任何 `demo-*` 服务（包括「暂时用 demo 顶一下」的代理）。对照 demo 允许**看代码再重写**，禁止 merge、禁止运行时依赖。

Java **禁止**做 NLP / 图算法 / 模型推理，也禁止内嵌 nGQL。抽取脚本在亿集里跑（对方也是 Python），本仓 Python 做适配和切面。

## 8. Nebula、Neo4j、亿集：三个容易混的名字

| 名字 | 是什么 | 本项目 |
| --- | --- | --- |
| **Neo4j** | 另一种图数据库 | **禁止**当生产引擎 |
| **NebulaGraph** | 团队基线里的图数据库，dev 已有实例 | 可能是亿集底下的物理库，也可能不是（**Q5 未决**） |
| **亿集** | 合作方的「建图 + 查图」平台（Schema、融合、任务、API） | 能力面；应用只调查图/任务 API |

你写页面时：只当「后面有一个查图服务」。不要在 React/Vue 里写图数据库地址。

亿集管理界面是给建模工程师的，**不嵌**进展示/专题给领导用。

对方若提供「用自然语言直接查库」（NL2SQL）：禁用。不安全，也和本体治理冲突。

## 9. HTTP 状态：200 空、404、501

| 码 | 含义 | 本项目图接口 |
| --- | --- | --- |
| 200 且有点边 | 查到了 | 正常 |
| 200 且空数组 | 查过了，就是没有 | 页面「暂无结构」 |
| 401/403 | 没登录 / 没权限 | 不把邻居数据藏在错误信息里泄露 |
| 404 | 路径或资源 ID 不存在 | 例如包 ID 写错 |
| **501 Not Implemented** | 这条能力还没接上 | 相似度无模型、社群未注册 |

501 是**诚实的合同履行方式**：招标写了相似度，模型没上线，就声明未实现。用 200 返回伪造分数，是验收事故。

Mock 数据在评审模式里用实验标记；正式用户路径不能靠假网撑场面。

## 10. 同步 API 和 Job

点一下立刻回来的是 **同步 REST**（检索、取已发布的图）。

要跑模型、可能几分钟、用户可能离开页面的，是 **Job**：创建任务 → 报阶段 → 结果冻住 → 用户点「查看」。这和「再发一版产业链相册」不是同一条流水线。

开放式智能体（自己决定调用哪些工具、无限循环）**不是**本项目生成分析的默认形态。默认是**预先声明的步骤图**（固定菜谱），好审计。

## 11. RAG、Agent、MCP：为什么写进「不当建图前提」

| 词 | 通常指 | 和建图的关系 |
| --- | --- | --- |
| RAG | 检索一段文本再让模型写答案 | 可以检索**已经建好的**图或指标，不能替代实体对齐 |
| Agent | 模型自己规划工具调用 | 本项目深度分析用固定 Job 图，不用开放 Agent 建图 |
| MCP | 给 IDE/模型接工具的协议 | 团队内部编排用，不是甲方图谱产品 |

建图依赖：稳定的 DWD、亿集任务、主键对齐。这些没就绪时，上 RAG 只会生成**听起来像那么回事的假关联**。

## 12. FDE 一句话（避免误读成前端岗）

行业里的 **Forward Deployed Engineer** 是「带着平台到现场，接到真实数据和已有 API，做成能用的系统，再把重复模式收回平台」。本 SAD 只借用它的**纪律**：从真实模块扫需求、不另造本体、生产可用、501 合法。

**不是**前端编制，也不新增岗位名称。中文「前端落地工程师」是误译，忽略即可。

## 13. 招标三层怎么叠在一起

| 层 | 文档 | 图谱相关 |
| --- | --- | --- |
| 展示系统 | 功能点 DS-01～30 | 多数是窗口；DS-21～24 是用图主入口 |
| 专题系统 | 战略分析、全景、诊断 | 全景用 B 面；诊断/推荐用 Job |
| 算法库 | `.1` 指标 `.2` 建图与 API `.3`～`.10` 模型 | `.2.1`～`.2.14` 是抽取，不在页面里做 |

读 SAD 时看到 `.2.15`：那是五类 **API 能力**，不是五个页面。

## 14. 指标血缘（D9）为什么出现在图谱文档里

领导在图旁边看到的数字，仍必须能回答：这是什么指标、公式、来自哪张表、多旧、是不是 Mock。图谱 JSON 里塞一个没有登记的 `bottleneck_score`，等于绕开指标治理。

所以：结构变化用切面的 diff；**分数**走指标目录或 Job 结果里带 honesty 的字段。

内部评审模式打开时，才显示 ⓘ / 缺口。关掉后，用户不应看到内部编号。
