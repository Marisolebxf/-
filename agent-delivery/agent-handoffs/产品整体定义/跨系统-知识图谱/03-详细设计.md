## 1. 建图详细

建图要回答的不是「页面上有一张网」，而是：

1. 允许哪些**点种类**、哪些**边家族**（本体，01 已定，本节落实现键）。
2. 点的对外主键必须是**项目归一键**，不能把亿集内部 vid 写成 `entity_id`。
3. 事实边从项目 DWD 来；推理边成功后**必须先回写 DWD**（CUT-D7），下一次发布才进 B 面相册。
4. 禁止绕过亿集（Demo 里是 yiji-sim）直写图存储。

生活类比见导读 L2 §2：A = 监控直播（当前图），B = 已冲洗的相册（发布切面），Job = 送检化验单。详细设计里这三套**不能混表**。

### 1.1 点类型（分析名 → 实现键）

主键 = **项目归一键**（DWD / 权威域），禁止用亿集内部 vid 当对外 `entity_id`。

| 分析名 | `entity_type` / 结构键 | 权威域（逻辑） |
| --- | --- | --- |
| 企业 | `enterprise` | 企业 DWD |
| 科研机构 | `institution` | 机构 DWD |
| 产业环节 | `chain_node` + `chain_id` | `industry_chain` / `node` |
| 技术 | `technology` | 技术权威域 【算法补字段】 |
| 人才 | `talent` | 人才权威域 |
| 政策 | `policy` | 政策权威域 |
| 服务机构 | `service_institution` | 服务机构权威域 |

区域是属性或 GIS，不单列点类型。载体在 01 §6 未升格前：挂企业 / 机构 / 服务机构，不新增 `carrier` 扩散。

**论文 / 专利不是点。** 页面上可以有文献列表、专利号、论文量（ADS/ES），图上只允许七要素。招标 `.2.3` / `.2.4` 是「从论文、专利里抽出**技术点**和关系」，不是把每一篇 PDF 入库成节点。Demo 对 `DOC-PAPER` 的处理就是这条纪律的现网样例（§1.4.3.7）。长文与「技术链 ≠ 论文引用网」见导读 L2 §6，**未删减**。

### 1.2 边类型

| 边族 | 存储 | 进 B 面？ |
| --- | --- | --- |
| 产业链上下游 / 供给 / 断点 | DWD `node_rel` `[valid_from, valid_to)` | 是 |
| 要素挂环节 | DWD `entity_rel` 同期账本 | 企业必裁；其余可空（CUT-D5） |
| 技术/人才/政策/服务跨类型 | 亿集当前图 + 可选 DWD 事实边 | **否**（CUT-D6）；只走 A |
| 推理边 | 亿集产出后 **必须回写 DWD** 新 `valid_from`（CUT-D7） | 回写后下一次发布才进 B |
| 股权 / 社交 | 仅 A | 否 |

半开区间 `[valid_from, valid_to)`：生效日算、结束日不算。链/节点属性按 SCD1 覆盖，所以**不能**靠「任意一天现算整图」；历史只能翻当时发布冻住的包（B 面）。这是 CUT-D3 的根：节点 as-of 不宣称。

Demo 企业维没有 CHAIN 全套 `node_rel` / `entity_rel` 时，用最小账本 `enterprise_graph_rel` 表达同一纪律（`origin=fact|infer`，带 `valid_from` / `batch_id`）。不因此发明第二套本体。

### 1.3 五大流程落点（算法 `.2`）

| 流程 | 落点 | 本仓实现叶 | Demo 对照（企业维） |
| --- | --- | --- | --- |
| （1）环节与上下游 | DWD 链/节点/`node_rel` | 数据 + 切面 | `facts.iter_located_in` 等；Tag `chain_node` |
| （2）要素与属性 | 权威域 + `entity_rel` | 数据；全景只读挂接 | `ent_upsert`；企业挂环节 |
| （3）实体构建与消歧 | GDF 触发 → 亿集实体脚本 | **不在**展示页 | yiji-sim `entities.*`；对齐目录 `build_catalog` |
| （4）知识推理 | 亿集推理脚本 → 回写 DWD | 可空 | `infer.py` 正则 / `infer_llm.py`；CUT-D7 |
| （5）图谱入库 | 亿集当前投影 + ADS 发布切面 | 切面 = 历史入口 | `persist_graph` → Nebula；B 面发布作业 **未做** |

`.2.1`～`.2.14` 对应（2）（3），脚本在亿集，GDF 只触发与观测。Demo 用 `entan/yiji_sim` 模拟这三类脚本，**禁止**在 GraphView 里做 NER。

### 1.4 GDF 触发序（推荐）

```text
Wave A 贴源 ODS
  → Wave B Mapping DWD
    → DAG：ADS/ES 作业（Python 仓执行）
    → DAG：亿集 Schema 校验（破坏性变更人工门禁 Q8）
    → DAG：事实关系任务（先）
    → DAG：实体/属性更新
    → DAG：推理任务（后；成功才回写 DWD rel）
    → （独立发布作业）裁切 ADS graph_snapshot
```

禁止绕过亿集直写图存储。管理凭证 ≠ 查询凭证（Q9）。建图输入强制项目 DWD，禁直连供应方 `gkx`（Q1）。

Demo 把「事实 → 实体 → 推理 → 回写 → persist」收成一条本地流水线（`scripts/run_yiji_sim.py`），**没有**独立发布作业，所以预览推理后 `GET /v1/graph` 仍是 A 面当前投影，不会突然出现 B 面时间轴。

### 1.4.1 ETL 跑批 vs 同步灌数 vs G3（实施）

对应概要 **02 §3.1 / §3.2**。本节把 Job 拆成 **写图批** 与 **分析批**，避免和 Job Runtime 混表。

| job_kind（逻辑名） | 写什么 | 不写什么 | 同步重灌 | 按钮 |
| --- | --- | --- | --- | --- |
| `graph_hang` | 已有点上的事实边（FETCH 成功才写） | 新 VID、B 面包、分析 Result | **禁止调用** | `limit=1` 可等同 Demo persist |
| `graph_infer` | 抽边 → CUT-D7；`persist=true` 才投影 A | Paper/Patent 点；假三元组 | **禁止** | Demo `POST /v1/graph/infer` |
| `graph_publish` | ADS `graph_snapshot`（无坐标拒发） | Job Result；A 面 live 冒充历史 | **禁止** | 运营发布，非分析按钮 |
| `analysis_*` | Result Snapshot only | 图存储、切面表 | 无关 | 「生成分析」 |

**Hang 扫描与游标（草稿）**

```text
WHERE entity 已有项目归一键
  AND （缺目标边 OR hang_status IN pending, failed）
  AND （force=false 时已有边则 skip）
ORDER BY entity_id
LIMIT batch_size
```

每条：`industry_link_code` / 稳定码 → FETCH → 写边。`no_stable_id` 计入 `skipped`，任务仍可 **partial success**（不要整批 500）。引擎不可用：job `failed` + honesty，禁止 200「已上图 0 条」充成功。

**续跑**：`cursor` = 上一批最后 `entity_id`；全量单飞键 `job_kind + domain(policy|enterprise|…) + index_or_graph_epoch`。

**与向量跑批的衔接**：无产业码的政策 Hang 会大量 skip。夜班顺序以 02 §3.2 为准：Job A 补槽 → Hang。本卷 **不** 在 Hang 内调 Milvus。

**路径草稿（非正式）**：Java `/topic/v1/industry/graph-jobs/{hang|infer|publish}` → Python `/internal/v1/graph/jobs/*`。创建返回 `job_id`；轮询进度字段建议：`processed / hung / skipped_no_stable_id / failed / cursor`。

Demo：`run_yiji_sim.py --apply --persist` 视为 **本机一次性 Hang+推理**，不是调度器；lumen 不得把这条同步脚本当生产重灌钩子。

#### 1.4.3.4 页面怎么拆：浏览图谱 ≠ 推理入库

顶栏只做 **A 面浏览**：选企业、邻域跳数、「在图谱上显示」、关联路径、模拟新增企业入库。这些走 `GET /v1/graph`、`GET /v1/graph/path`，**不抽三元组**。

卡片「从行业分析文档推理入库」才是流程（4）：

1. 选一篇 `industry_analysis_documents`（点「详情」新窗口看六表字段和行）。
2. 抽边方式：正则（默认）或 LLM。
3. **预览推理** = `persist=false`：读 DWD → 抽 → 对齐 → **不写账本、不灌 Nebula**。
4. **写入图谱** = `persist=true`：CUT-D7 回写 + persist；新关系边闪烁约 60 秒。

抽出明细（语料、规则扫描、三元组、丢弃原因）只出现在 **POST `/v1/graph/infer` 的响应和这块面板**。`GET /v1/graph` 只投影当前图上的点边，不会把 `extracts=0` 的原因画进图里。这是故意的：A 面不是推理工作台。

#### 1.4.3.5 抽出结果区要看什么（含 0 条）

面板始终展示（抽出 0 条也不得用 `v-if` 藏表）：

| 块 | 含义 | 对应 SAD |
| --- | --- | --- |
| 语料 | `document_id` / 标题 / 摘要 / 正文摘录 | 建图输入 = 项目 DWD，不是页面上现编的句子 |
| 处理步骤 | 读 DWD → 抽三元组 → 对齐已有点 → CUT-D7 → 投影当前图 | §1.3（4）（5） |
| 规则扫描 `attempts` | 每篇 × 三条正则：是否命中、span、捕获组 | 诚实：没命中也要看见扫过什么 |
| 抽出并可对齐的三元组 `extracts` | 能挂到已有点上的 `{src,rel,dst}` | 流程（4）成功态 |
| 未入图 / 丢弃 `drops` | `reason` + `reason_zh` + 原文片段 | 对不齐就 drop，不新建 Paper 点 |
| 将对齐写入的关系边 | 预览或已入库的 infer 边 | persist 后才出现在 `GET /v1/graph` |

#### 1.4.3.7 诚实空：`DOC-PAPER`（不要当成接口坏了）

正文含「论文 / 专利号」，三条正则都不命中。`run_infer` 走 paper 分支后 drop `unresolved_no_paper_vertex`。

预期面板：

```text
1. 读 DWD     读到《文献动态》（DOC-PAPER）
2. 抽三元组   规则扫描 3 次、命中 0；抽出可对齐三元组 0 条
3. 对齐已有点 入图候选 0，丢弃 1（unresolved_no_paper_vertex）
4. CUT-D7     预览模式：未写账本
5. 投影当前图 预览完成。要点「写入图谱」才会入库
```

丢弃原因中文：正文含论文/专利表述，且三条规则都未抽出可对齐边；禁止新建 Paper/Patent 点。原文片段为正文前约 80 字。

这不是抽边失败。旧 UI 在 `extracts.length===0` 时把表藏掉，只剩「请刷新 GET /v1/graph」，会误导成「刷新图就能看见抽出结果」。图 API 没有这些明细。

#### 1.4.3.8 抽出成功：`DOC-HW-PKG`

正文类似「华为已在先进封装环节实现量产」。本机 `persist=false` 预期 `extracts=2`（`located_in` + `produces`）。写入后：账本 `origin=infer`；Nebula 有新边；图上闪烁约 1 分钟。对齐不上「华为」时会 drop `unresolved`（主体对不齐已有点），同样要在丢弃表里看见 span，而不是静默 0 边。

#### 1.4.3.9 Demo API（非正式 OpenAPI；仅 demo-*）

| 用途 | 方法 | 路径 |

| A 面当前图 | GET | `/v1/graph`（`source=nebula\|pg\|error`） |
| 关联路径 | GET | `/v1/graph/path`（find_path=200；社群/相似专家 **501**） |

## 4. 失败态与可观测

| 情况 | HTTP / 行为 | Demo 现网怎么验 |
| --- | --- | --- |
| 无图 / 无包 | 200 诚实空；文案「暂无结构」 | 选不到企业或条件无点时 `GET /v1/graph` 空数组 |
| 能力未建 | **501** + honesty.reason | LLM 无 Key；社群/相似专家 |
| 薄包（无坐标） | `honesty.payload_thin=true`；演进禁用 | Demo 无 B 面，不要测时间轴 |
| 无权 | 4xx；不泄露邻居 | 沿用现网鉴权 |
| 图库错误 | 200/5xx 策略与现网一致；`source=error` | Nebula 不可用可回退 PG，`source` 必带 |
| Q5 切换 | 仅 `source` 变化，路径不变 | Demo `source=nebula\|pg` |
| 抽出 0 条可对齐边 | **200** + extracts=[] + drops 有原因 | `DOC-PAPER`；不是 500 |
| Hang 无稳定码 | 单条 skip；批任务可 partial | 进度 `skipped_no_stable_id`；禁止编 VID |
| Hang/发布引擎未就绪 | job failed 或 **501** | 禁止 200 假「已上图」 |
| 重灌请求里调用 Hang | **禁止**（设计违规） | 验收：reload 路径 grep 无 hang/persist |

全链路 `traceparent`。包内 `snapshot_id`。图接口响应必含 `source`。OTel：Python instrument + Java Agent；前端 `observability.ts`。Demo 推理走 `request.ts` 拦截器，501/失败带 `__traceId`。

指标数字遵守 D9，不在图 JSON 内发明无 `metric_id` 的 KPI。
