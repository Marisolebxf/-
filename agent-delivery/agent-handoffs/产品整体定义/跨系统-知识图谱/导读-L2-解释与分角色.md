## 1. 这套设计在解决什么问题

招标有两套系统：**科技信息展示**（领导看态势、政策、人才、成果）和 **科技专题服务**（产业链全景、深度分析、推荐）。两边都在说「图谱」「全要素」「关联关系」。

如果展示自己造「科创要素图」、专题再造「产业链图」，半年后会出现：同一个企业两个 ID、政策挂不上环节、全景时间轴和驾驶舱对不上。

所以拍板一句话：

> **只建一张图。** 展示六大模块和专题都是这张图的**不同窗口**，不是不同的图。

「窗口」的意思：驾驶舱嵌一小块子图；知识图谱页是查图工作台；专题全景是「某一条产业链、某个已发布截至日」的结构照片；深度分析是拿照片（或当前子图）去做打分，写出报告。

## 2. 用生活类比理解 A / B / Job

| 面 | 类比 | 业务上你看到什么 | 工程上读什么 |
| --- | --- | --- | --- |
| **A 当前图** | 监控直播：现在谁和谁连着 | 检索实体、点开关系、知识图谱页 | 亿集查图 API + 当前仍有效的关系 |
| **B 发布切面** | 已经冲洗好的相册：每张照片有拍摄日期 | 全景「当前状态 / 对比 / 时间轴」 | ADS 里冻住的整图包 |
| **Job** | 送检化验：下单、排队、出不可改的化验单 | 「生成分析」按钮、阶段文案、查看结果 | Job 的 Input/Result 快照 |

三件套最容易混的坑：

- 拿 **直播** 去播「去年六月的产业链」→ 不行（节点很多没有历史版）。
- 拿 **相册** 去当「现在搜一下某个人的股权」→ 不行（切面里根本没股权）。
- 拿 **化验单** 当成「又一张产业链照片」存进相册表 → 不行（混表后无法审计）。

时间轴只翻 **已发布的相册**，不在前端自己算「今天减昨天」。

## 3. 七要素和五链：别被数字绕进去

口头上领导说「打通五链」。报价和算法库按 **七要素** 拆。它们不是两套世界观。

- **点（谁）**：企业、科研机构、产业环节、技术、人才、政策、服务机构。
- **边（怎么连）**：技术链、产业链、人才链、政策链、服务链 —— 五种**关系家族**。
- **底图**：产业链的上下游环节。全景页主要拍的是这张底图，企业必须能挂上去（没有企业就挂一个空数组，诚实）。

另有一个 **瓶颈五维**：技术 / 人才 / 市场 / 资金 / 政策。那是诊断模型的五个**打分维度**，不是五种节点，也不是五张图。在一条产业链上切一刀，再打五个分。

展示还有 **七大模块**（态势、政策、人才、数据资源、知识图谱、成果、服务）。那是菜单，不是本体。其中 **数据资源 DS-17～20 默认不用图扫全**（运营视窗）。

## 4. 为什么很多页面标 M 或 501 仍算「覆盖了」

覆盖矩阵的要求是：**每个招标叶子有一行交代怎么用图**。不是「每个叶子都上图算法」。

| 标签 | 人话 | 例子 |
| --- | --- | --- |
| G1 | 把已有的点边查出来给页面画 | 政策挂企业、人才合作网、全景结构 |
| G2 | 在图上算路径、中心性、社群、相似度 | 知识图谱「算法展示」；没模型就 501 |
| G3 | 长时间计算 + 可恢复任务 | 瓶颈识别、招引推荐、政策推演 |
| M | 数字来自表格/搜索/地图，不跑图 | GDP、区域指数、仪器对接、论文量 |

**501**：这个能力合同里有，但模型或引擎还没接上。正确行为是告诉调用方「没实现」，附原因。用 200 返回 0.87 的假相似度，比 501 更糟。

**200 空**：图通了，这个条件下就是没有点。页面写「暂无结构」，不是报错。

## 6. 论文、专利、载体：为什么不新开点类型

先分清两件完全不同的事：

| | 页面上能不能出现 | 图谱里是不是一种「点」 |
| --- | --- | --- |
| 问的是 | 列表、卡片、GIS 上有没有这篇论文 | 图数据库里有没有一类叫 `Paper` 的节点 |
| 本 SAD 的答案 | **可以有**（检索、详情、地图点位） | **默认没有**（不进七要素） |

「不新开点类型」**不是**说系统不许展示论文。是说：论文不要变成和「企业、人才、政策」并列的第八种图节点。人才画像里照样可以列出论文；数字走 ADS/ES；图上只画 **人 / 机构 / 企业** 这些七要素之间的边。

### 6.1 「点类型」是什么

七要素 = 这张图**允许存在的角色种类**（谁可以当圆点）：

企业、产业环节、科研机构、**技术**、人才、政策、服务机构。

注意：**「技术」已经是七要素里的一种点。** 下面说「论文不是点」，不是说技术不是点。

每多一种点类型，就要规定：主键是什么、和另外六种怎么连、历史怎么裁、全景切面带不带、展示每一页会不会再要一套图例。种类一多，两套系统就不再是「同一张图」，而是「很多张各画各的图」。

所以原则只有一句：

> 口语里出现的东西，先问它是不是七要素里的某一种。  
> **是** → 在图上做成点，或挂到已有点上。  
> **不是** → 当文档/指标/地图图层存，**通过作者、权利人、承担单位**连回七要素。

「挂上去」= 例如论文存在 ES 里，记录 `author_id = 某人才`，以及（若抽得出）`technology_id = 某技术点`。点开人才能看见论文列表；点开技术点能看见「相关论文/专利」清单。图上的圆点是 **人才、技术、机构**，没有「这一篇 PDF」那种点。

### 6.2 技术、论文/专利、技术链：三者怎么叠

一句话：

| 词 | 在图里是什么 | 不是什么 |
| --- | --- | --- |
| **技术** | **点**。一个可对齐的技术主题/技术点，如「GaN HEMT」「Chiplet 封装」 | 不是某一篇论文的标题 |
| **技术链** | **边的家族**。谁研发/掌握/应用这项技术，技术如何前后演进、如何落到产业环节 | 不是「论文引用链」，也不是单独一张图 |
| **论文 / 专利** | **证据和清单**。用来识别「存在这项技术」、给技术点计数、给人才/企业挂成果 | 不是第七要素之外的新点类 |

招标算法库 `.2.3` / `.2.4` 是「从论文、专利、报告里**抽出技术实体和关系**」，不是「把每篇论文入库成节点」。抽出的结果写入 **技术点** + **技术链边上的端点**（人才掌握、机构产出、企业应用、环节产业化）。

```text
材料层（ES/ADS，不是图点）
  论文《…GaN…》  作者=张三   单位=某高校
  专利CNxxxx     权利人=华为  技术主题≈GaN HEMT

        抽取 / 对齐（建图脚本，不在展示页做）
                    ↓
图上的点
  张三(人才)    某高校(机构)    GaN HEMT(技术)    封装测试(产业环节)    华为(企业)

图上的边 = 技术链（边族，不是第三种点）
  某高校 --产出--> GaN HEMT
  张三   --掌握--> GaN HEMT
  华为   --应用--> GaN HEMT
  GaN HEMT --产业化--> 封装测试
  （可选）技术A --演进/依赖--> 技术B     ← DS-02「技术点图谱 / 关键路径」画的是这个
```

页面怎么体现：

| 页面想表现 | 读什么 |
| --- | --- |
| 科学技术全景、技术点连成路径（DS-02 / `.4.1`） | **技术点 + 技术链边**（G1/G2） |
| 「该技术全球论文量 / 深圳专利量」 | **M**：ADS 指标，按技术点或区域聚合论文/专利 **计数**，不把每篇画成点 |
| 点开技术点看文献列表 | ES/ADS 列表，`technology_id` 过滤；点作者跳到人才点（弱 G1） |
| 人才画像里的论文 | 列表挂人才；合作网络仍是人才—人才 / 人才—机构（人才链） |
| 瓶颈「技术维」 | 五维打分用到技术供给是否缺，**维度不是点类型** |

因此：

- 问「论文是不是实体点」→ **默认不是。**
- 问「技术是不是实体点」→ **是。**
- 问「技术链在哪」→ 在 **连到技术点的那些边上**（加技术点之间的演进/依赖），不在论文引用网上。

若某条专利/论文 **无法对齐到任何技术点**（主题太散、消歧失败）：仍可在成果页当文档展示，**不编造**一个技术点，也不为此新开 `Paper` 类。

### 6.3 用一个例子：张三的论文和华为的专利

页面要做的事：人才张三详情里列出 12 篇论文；企业华为详情里列出专利数量和清单。

**做法 A（本 SAD 要的）**

```text
图上的点：  张三(人才) ——任职—— 某高校(科研机构)
            张三 ——掌握—— GaN HEMT(技术)     ← 技术链边
            华为(企业) ——应用—— GaN HEMT ——产业化—— 某环节

论文 12 篇：  ES/文献库，author=张三，并对齐到技术点 GaN HEMT（抽得出才对齐）
专利清单：    ADS/专利表，assignee=华为，技术主题对齐同一技术点
论文量/专利量： ADS 指标，挂在技术点或企业上（M）
```

用户看到论文、专利；图上多出来的圆点是 **技术**，不是每一篇文献。查「张三和谁合作」走人才链；查「这项技术谁在做」走技术链；查「这篇题目」走搜索。

**做法 B（不要）**

再开两种点：`论文`、`专利`，然后必然还要期刊、发明人、申请人、引文……

```text
张三 ──撰写── 论文A ──发表于── 期刊X
华为 ──申请── 专利B ──引用── 专利C ──发明人── 李四
```

这是另一张「文献/知识产权图」。它和「七要素产业图」平行：同一人两个体系、同一机构两套 ID。展示再加会议、课题、仪器，每种再开点，种类会一直涨。招标验收的是七要素产业图，不是再造一套学术知识图谱。

弱 G1 是什么：从一篇论文跳到作者（人才点）或跳到已对齐的技术点。跳的是**七要素里已有的点**，不是把 PDF 本身画成点。

### 6.4 创新载体：业务上像「一种东西」，图上先不要第八类

Catalog（DS-26 / DS-29）说：孵化器、园区等 **创新载体 ≠ 企业本身**。这句话是对的——「深圳湾园区」不是「华为公司」。

但若立刻在图里新增第八种点 `carrier`（载体），就会和七要素并列扩散：每个展示页都要问「载体怎么和人才、政策连」。在甲方/算法还没规定「载体算机构、算服务机构、还是单独一类」之前，铺开 `carrier` = 第三套本体。

V1 先只表达页面真正要的三种关系（都不需要新点类）：

| 页面上要表达的 | 图上怎么做（升格前） |
| --- | --- |
| 这个园区谁在运营 | 边：某企业或某科研机构 →（运营）→ 先落到已有点上，或只在 ADS 里记运营主体 ID |
| 谁入驻了 | 边：入驻企业 →（入驻）→ 同上 |
| 适用哪些政策 | 边：政策 →（适用）→ 运营主体或入驻企业 |

「深圳湾园区」在列表和 GIS 上可以单独成卡片（那是展示对象，走 ADS/GIS）。**图引擎里**暂时不要出现第四种圆点叫载体。算法会签时必须圈定一格：

- 多数园区运营方是企业或事业单位 → 落到 **企业** 或 **科研机构**；或  
- 看成孵化/服务中介 → 落到 **服务机构**；或  
- 甲方书面确认必须单独一类 → 登记客户决策表，**再**升格，而不是开发先发明 `carrier`。

未圈定前：载体页用表格+地图+上述三种挂接；不要先写一套 Carrier Schema。

### 6.5 对照口诀

| 口语 | 图上的点？ | 用户仍然能看到？ |
| --- | --- | --- |
| 华为、某高校、张三、某项政策 | 是（七要素） | 是 |
| **GaN HEMT 等技术点** | **是（要素「技术」）** | 是；DS-02 画的就是这些点 |
| **技术链** | 不是点，是**连到技术的边** | 是（路径、掌握/应用关系） |
| 某篇论文、某件专利、某课题 | 否 | 是（列表/检索）；可对齐到技术点后当证据 |
| 该技术的论文量、专利量 | 否 | 是（ADS 指标 M） |
| 论文作者、专利权利人 | 是（人才/企业/机构） | 是 |
| 某园区/孵化器（升格前） | 先不单独成类 | 是（卡片+GIS）；关系挂运营方/入驻企业/政策 |
| GDP、指数 | 否 | 是（ADS 数字） |

还是混：记住——**少的是「图里允许的角色种类」，不是「界面允许出现的名词」。**

### 6.6 招标「专题 · 技术链分析」怎么做

条款：系统方案 `1.1.1.2.4.2.1`；算法库 `.4.1`～`.4.11`。出口：`lumen-ui-topic`，不是展示驾驶舱另造一张图。

它和「产业链全景」不是同一页：

| | 产业链分析里的全景 | 技术链分析里的全景 |
| --- | --- | --- |
| 圆点 | 产业环节（底图） | **技术点** |
| 边 | 上下游 / 供给 | **技术链**：演进、依赖、掌握、应用、产业化映射 |
| 历史播放 | B 面已发布切面 | V1 走 **A 面当前图**；不宣称技术点 as-of |
| 论文专利 | 可挂企业/环节指标 | **抽出技术点** + 下钻清单 + 论文量/专利量指标 |

招标写「技术节点及其引用、演进与关联」：这里的「引用」收口为 **技术点之间的演进/依赖**（从文献里抽），**不是**把论文互引网画成产品图。

六项功能对照（人话 → 工程）：

| 招标叶子 | 用户看见 | 图上做什么 | 论文/专利扮演什么 | 标签 |
| --- | --- | --- | --- | --- |
| 技术链全景图谱 | 技术网络 + 点开下钻 | A 面：技术点 + 技术链边；下钻出定义、关联企业 | 下钻区 **列表**：代表论文、核心专利（ES/ADS，`technology_id`） | G1 |
| 新技术热点发现 | 热点名、热度曲线 | 抽出来的概念 **对齐/新建技术点**；图上可高亮 | 材料：顶会顶刊 NLP；输出是技术点+热度指数，不是论文点 | M / G3 |
| 技术产业化潜力 | 评分、雷达对比 | 对象是 **技术点** | **计数与案例**进模型特征（论文规模、专利规模等），不是图结构 | G3 |
| 技术阶段研判 | 处在研发/应用哪一段 | 仍挂在技术点上 | 文献与资讯当 Job 输入；招标写了 LLM，走 Job，未注册 **501**，禁止假阶段 | M / G3 |
| 深圳技术发展分析 | 本地潜力与阶段 | 同一张 G，主体过滤深圳企业/机构 | 同上，地域切片 | M / G3 |
| 技术转化瓶颈识别 | 实验室到市场的堵点 | 转化阶段是 **流程/指标**，可映射到产业环节；不是新点类「论文」 | 专利、论文、转化案例当证据 | G3 |

闭环口令（招标原文）：**看全局（全景 G1）— 识趋势（热点 M/G3）— 评价值（潜力 G3）— 判阶段（G3）— 定本地（深圳切片）— 破堵点（转化瓶颈 G3）**。全程只有一种技术点。

实现顺序（与建图一致）：

1. `.2.3` / `.2.4` 从论文、专利抽出技术实体和关系 → 写入技术点 + 技术链边（亿集，GDF 触发）。  
2. 专题页全景只 **读 A 面** 子图（可与展示 DS-02 同源，禁止第二套技术本体）。  
3. 下钻拼装：图给关联企业/人才/环节；文献库给论文专利清单；ADS 给量。  
4. 热点/潜力/阶段/瓶颈 = Job 或指标，对象 ID = `technology_id`。  
5. 运营台「技术链内容管理」（`1.1.1.2.4.5.1.1`）是 **维护技术本体**，不是分析页，也不嵌进领导专题画布。

不要：用论文引用网络冒充技术链全景；为「转化环节」再开一套与七要素平行的点；把产业链 B 面时间轴套到技术链页上（技术历程 `.4.3` 走事件时间线 / CMS，≠ 图谱演进）。

### 6.7 「颠覆性技术」怎么识别（以及先别写上产品）

招标里**没有**「颠覆性技术」这一叶子。专题技术链写的是：前沿热点、产业化潜力、阶段研判、转化瓶颈。学术上的「颠覆」（替代主流技术轨道）和「论文突然变多」也不是一回事。**叫不叫颠覆、阈值多少，只能甲方拍板**（已登记 `Q068`）。

在口径未绿之前：

- **对外文案**只用招标词：热点 / 高潜力 / 阶段 / 替代。不要做「颠覆指数」给领导看。
- **图上不新开点类**。候选仍是普通**技术点**；顶多多一个待确认的标签或 Job 结果字段。
- 模型未进 `cfg_model_registry` → **501**，禁止 200 假分。

若甲方确认要识别，工程上仍挂在同一张 G 上，用**已有能力组合**当代理（算法出公式草案，不替甲方定义「颠覆」）：

| 信号 | 来自哪 | 直觉 | 单独够不够叫颠覆 |
| --- | --- | --- | --- |
| 前沿热点 | `.4.5` / 专题热点发现 | 论文、专利、资讯里新概念增速高 | 不够。热点可能是跟风 |
| 产业化潜力 | `.4.6` | 科研储备 × 转化 × 市场 | 不够。高潜力可以是渐进改进 |
| 技术阶段偏早 | `.4.8` | 还在实验室/样品 | 不够。早期≠颠覆 |
| **技术替代边** | 技术链：技术 A `substitutes` 技术 B | 图上出现「可能替换谁」 | 最接近「颠覆」的图结构，仍要证据，V1 可标 pending |
| 跨多产业环节 | 技术点挂到多条产业链 | 一种技术打穿多个环节 | 辅助信号 |

推荐 Job 形态（确认后）：输入 `technology_id` → 读 A 面子图 + ADS 论文/专利时序 → 输出 honesty 字段（命中了哪些信号、缺哪类证据），**不要**先发明不可解释的黑盒「颠覆分」。全景切面里的「技术替代」色是产业链结构变化，和「这项技术是否颠覆」不是自动同一句话。
