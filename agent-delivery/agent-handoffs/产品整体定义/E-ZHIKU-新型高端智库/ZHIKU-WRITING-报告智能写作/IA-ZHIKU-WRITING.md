## 1. 模块目标与产品边界

让智库用户在一个连续工作流中完成：发起（模板或自然语言）→ 大纲定制 → 后台 AI 写作 → 编辑与溯源 → 导出/发布沉淀。

### 1.1 承接内容

- 模板库（系统/个人）、模板预览、复制、编辑、分享、删除；
- 创作配置（模板式 + 自然语言式两入口）、意图确认追问；
- 大纲确认工作区（章节自由组合 + 分析思路注入）；
- 后台写作任务的状态机、进度模拟与创作历史；
- 报告编辑器：正文、脚注角标、来源抽屉、原文预览、AI 改写对照、图表卡样式切换、溯源附录；
- 我的素材库：上传、解析状态、任务关联、素材溯源；
- 导出 Word/PDF 真实文件；发布审核状态流转与成果侧出口。

### 1.2 不承接

- 战略咨询报告的选题管理、洞察报告发布运营、热点分析（归 ZHIKU-STRATEGY-REPORT，R5）；
- 智能问数的问答式取数工作台（归 ZHIKU-SMART-QUERY，R5；本包图表卡只消费写作上下文内的演示数据）；
- 案例广场（成果展示形态，归 ZHIKU-STRATEGY-REPORT）；
- 真实大模型接入、语音输入、OCR、外部研报库外链的可用性验收；
- 多账号协同、组织级模板治理与权限体系（正式阶段能力）。

## 3. 对象与稳定身份

| 对象 | 稳定身份 | 职责 | 禁止解释 |
| --- | --- | --- | --- |
| `report_task` | `task_id` | 写作全流程的唯一主对象，状态机载体 | 不跨任务共享正文 |
| `template` | `template_id` + `origin`(system/mine/shared) | 创作骨架资产 | 系统模板不可写；副本必须新 id |
| `outline_node` | `node_id`（任务内唯一） | 大纲结构与分析思路挂点 | 不脱离任务存在 |
| `citation` | `citation_id` + `source_type` | 脚注/来源抽屉/附录的同一数据源 | 附录不得独立于 citation 生成 |
| `material` | `material_id` + `parse_status` | 用户素材资产 | 未就绪素材不可被任务关联 |
| `chart_block` | `block_id` + `chart_style` | 正文内图表卡 | 样式切换只改 `chart_style` 不改数据 |
| `achievement` | `achievement_id` ← `task_id` | 发布后的成果侧投影（跨叶子契约） | 成果页只读，不反向改任务 |

## 6. 数据与服务边界

- demo 全 mock：领域 store 收敛在 `src/mock/writing/`（任务/模板/素材/成果出口），页面不得硬编码业务数据。
- store 均带 localStorage 持久化（key 前缀 `zhiku-wr-`），reducer 型 action 承载全部状态变更。
- 目标态（正式接入）：前端 → Java REST（gkxlumen-topic 域）→ Python `/internal/*`（写作/溯源算法），本包 UI 合同按此预留（store action 与未来 API 一一对应）。
- 导出：demo 由前端生成真实 `.doc`/`.pdf` 文件下载（内容含标题/正文/附录），不做版式还原承诺。
