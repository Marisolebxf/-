### US-ZHIKU-TM-01｜区域人才分布研判与双向联动

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 75（地域分布地图、机构排名列表、领域热点、流动趋势、统计指标卡、筛选对比） |
| 产品角色 | `ROLE-TM-PLANNER` |
| 依赖 | 无（模块入口故事） |
| Frame | `F-TM-01` |
| 业务结果 | 地图点位与右侧机构排名/点位列表双向联动选中，筛选与选中状态刷新可恢复 |

作为区域人才规划人员，我想在地图上查看人才/机构分布并与排名列表联动选中，以便直观定位重点区域与机构。

主路径：

1. 用户进入"人才地图"页"人才地图"页签，顶部统计卡显示分布点总数（ⓘ `ZHIKU-TM-DIST-TOTAL`）。
2. 地图展示分布点位（类别配色），右侧为机构排名列表与人才流动趋势图。
3. 用户点击地图点位，右侧列表对应行高亮滚动定位；点击列表行，地图对应点位放大标记（双向联动）。
4. 用户按类别（专家学者/科研机构/企业/服务机构）筛选点位，切换热力图模式。
5. 刷新页面后类别筛选、热力开关、选中点位保持。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 类别全部取消 | 地图空点位 + 提示"至少保留一个类别"或空态引导 | 重新勾选 |
| 选中点位被筛选条件过滤掉 | 自动清除选中态，不残留幽灵高亮 | 重新选择 |

验收：

- `AC-US-ZHIKU-TM-01-01`：地图点位与右侧列表双向联动选中（地图→列表高亮定位、列表→地图标记放大）。
- `AC-US-ZHIKU-TM-01-02`：类别筛选与热力切换实时生效且刷新保留（localStorage `zhiku-tm-` 前缀）。
- `AC-US-ZHIKU-TM-01-03`：分布总数统计卡带 ⓘ（`ZHIKU-TM-DIST-TOTAL`）与 🧪，数值随类别筛选联动。
- `AC-US-ZHIKU-TM-01-04`：流动趋势图与流向数据展示完整；选中点位被过滤后选中态自动清除。
- `AC-US-ZHIKU-TM-01-05`：选中点位刷新后恢复（含地图标记与列表高亮）。

不包含：真实 GIS 服务与行政区划边界（Leaflet 底图 + 种子坐标）；点位数据编辑。

### US-ZHIKU-TM-02｜定制人才指数权重并对比区域（演示态）

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 76（五维量化评估：数量/科研产出/学术影响力/产业贡献度/流动活跃度；柱状/折线/雷达/热力；权重定制化） |
| 产品角色 | `ROLE-TM-PLANNER` |
| 依赖 | 无 |
| Frame | `F-TM-02` |
| 业务结果 | 权重滑杆定制实时反算综合指数并跨会话保留；指数为 D1 缺失演示态，全程红问号+声明 |

作为区域人才规划人员，我想调整五维权重并对比各区域人才指数，以便按本地产业侧重形成区域支撑能力研判——同时我需要清楚该指数算法尚未定稿。

主路径：

1. 用户进入"人才指数"页签，综合得分卡为 D1 缺失红问号态（`ZHIKU-TM-INDEX-SCORE`，点开显示 GAP 治理引用）。
2. 用户拖动五维权重滑杆，综合得分与图表实时重算；权重刷新后保留。
3. 用户切换区域（深圳/广州/上海/北京/杭州），雷达图与五维明细联动。
4. 用户切换柱状/雷达视图对比多区域。
5. "恢复默认权重"一键复位。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 权重全部拖为 0 | 得分显示"—"并提示"权重和须大于 0" | 调整权重 |
| 区域无数据 | 空态（种子数据齐全，防御性处理） | 换区域 |

验收：

- `AC-US-ZHIKU-TM-02-01`：五维权重滑杆实时反算综合得分与图表，刷新后权重保留。
- `AC-US-ZHIKU-TM-02-02`：`ZHIKU-TM-INDEX-SCORE` 为 D1 missing 红问号态（IconQuestionCircle 红），点开显示 GAP-ZHIKU-TM-INDEX 治理引用而非伪 8 件套。
- `AC-US-ZHIKU-TM-02-03`：区域切换联动雷达与明细；柱状/雷达视图可切换。
- `AC-US-ZHIKU-TM-02-04`：权重和为 0 时得分显示"—"并禁止伪造数值。
- `AC-US-ZHIKU-TM-02-05`：页签带"权重算法定义卡未落地（Q-ZHIKU-04），当前为前端演示态计算"常驻声明。

不包含：真实指数算法（挂算法定义卡）；权重方案的多套保存。

### US-ZHIKU-TM-03｜精准检索人才并下钻画像

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 77（语义/关键词/全局筛选多模式检索；智能推荐相关专家；人才详情页） |
| 产品角色 | `ROLE-TM-SCOUT` |
| 依赖 | POOL US-01（画像页承接详情） |
| Frame | `F-TM-03` |
| 业务结果 | 双模式检索命中结果并可下钻 POOL 画像页；检索历史保留可复搜 |

作为高端人才寻访人员，我想用自然语句或关键词检索人才并顺着推荐专家扩展候选，以便快速锁定目标并查看完整画像。

主路径：

1. 用户进入"人才检索"页签，选择检索模式（语义 🧪 / 关键词）。
2. 输入检索词提交，结果列表展示匹配度、机构、方向；语义模式附"意图解析"说明条（🧪 演示态）。
3. 结果区下方"智能推荐相关专家 🧪"展示推荐条目。
4. 用户点击结果或推荐条目"查看画像"，跳转 `/talent/profile?scholar=<id>`（跨叶子回链 POOL）。
5. 检索历史记录最近 5 条，点击可复搜；刷新后历史保留。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 检索无命中 | 结果区 Empty："未命中人才，试试更换关键词"+ 推荐区保留 | 换词或走推荐 |
| 空检索词提交 | 输入校验提示，不发起检索 | 输入内容 |
| 非入库人才推荐 | 条目置灰"未入库，暂无画像" | 选择其他 |

验收：

- `AC-US-ZHIKU-TM-03-01`：语义/关键词双模式可切换，语义模式带 🧪 意图解析说明条。
- `AC-US-ZHIKU-TM-03-02`：结果条目与推荐专家均可下钻画像页且携带 scholar 参数（跨叶子 URL 契约）。
- `AC-US-ZHIKU-TM-03-03`：检索历史最近 5 条持久化，点击复搜。
- `AC-US-ZHIKU-TM-03-04`：无命中出现 Empty 且不清空检索词；空词提交被校验拦截。
- `AC-US-ZHIKU-TM-03-05`：匹配度得分带"演示态相似度，非真实语义检索"标注。

不包含：真实语义检索/向量召回；全局筛选面板（demo 双模式已覆盖检索语义，筛选归 POOL 列表筛选）。
