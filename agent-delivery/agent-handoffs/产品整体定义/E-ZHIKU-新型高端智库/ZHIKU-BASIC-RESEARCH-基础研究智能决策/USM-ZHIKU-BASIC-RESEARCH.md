## 1. 模块结果

围绕"深圳应该在哪些基础研究问题上投入、投给谁、效果如何"这一决策链，让科研管理用户完成"问题识别与订阅 → 趋势回溯与监控 → 三层次竞争格局研判 → 深圳部署清单联动 → 组织实施资源配置 → 成果评估回看"的完整闭环，并在竞争格局/成果评估节点直接引出"生成报告"跨叶子出口（进入 ZHIKU-WRITING 预填任务）。不承接报告写作本体（归 ZHIKU-WRITING），不承接技术预见/技术路线图（归 ROADMAP 相关叶子），不做真实挖掘模型与量化算法——demo 阶段"智能识别"与两项算法得分均为标注 🧪 的演示态，禁止伪闭合。

## 4. 用户故事

### US-ZHIKU-BR-01｜检索、筛选并订阅基础研究问题

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 82（清单生成、维护、在线发布；定向查询与订阅） |
| 产品角色 | `ROLE-BR-MANAGER` |
| 依赖 | 无（模块入口故事） |
| Frame | `F-BR-01` |
| 业务结果 | 用户能从问题清单中快速定位关注的问题并建立订阅关系，订阅关系跨会话保留 |

作为科技管理部门决策支撑人员，我想按关键词、权威来源与发布状态定向查询基础研究问题，并订阅重点问题，以便持续跟踪它们的动态而不必每次重新翻找。

主路径：

1. 用户进入"问题清单与趋势"页，默认停在"问题清单"标签。
2. 顶部统计卡显示问题总数（ⓘ `ZHIKU-BR-ISSUE-TOTAL`）与我的订阅数。
3. 用户输入关键词或点选权威来源目录（基金指南/院士建议/政策文件/研讨纪要）过滤清单，可再按状态（已在线发布/识别中）过滤。
4. 用户对任一问题点"订阅"，行内订阅标记点亮，"我的订阅"区即时出现该问题。
5. 用户对已订阅问题点"退订"，订阅关系解除；刷新页面后订阅集合与筛选条件保持不变。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 筛选组合无结果 | 表格区局部 Empty，提示"无匹配问题"并提供"清空筛选"按钮，筛选条保留 | 一键清空或调整条件 |
| 订阅列表为空 | "我的订阅"区 Empty 态引导"从下方清单订阅重点问题" | 回清单订阅 |
| 重复订阅同一问题 | 订阅动作幂等，不产生重复条目 | 无需处理 |

验收：

- `AC-US-ZHIKU-BR-01-01`：关键词、来源、状态三类筛选可叠加使用，结果实时更新，"清空筛选"一键恢复全量。
- `AC-US-ZHIKU-BR-01-02`：任一问题可订阅/退订，订阅态在行内与"我的订阅"区双处同步呈现。
- `AC-US-ZHIKU-BR-01-03`：刷新页面后订阅集合保持不变（localStorage `zhiku-br-` 前缀持久化）。
- `AC-US-ZHIKU-BR-01-04`：筛选无结果时出现局部 Empty 与"清空筛选"按钮，点击后恢复全量清单。
- `AC-US-ZHIKU-BR-01-05`：问题总数统计卡带 ⓘ（`ZHIKU-BR-ISSUE-TOTAL`）与 🧪 MockBadge，弹卡含 8 件套与就绪度四行。
- `AC-US-ZHIKU-BR-01-06`：订阅/退订不改变清单本体数据（问题总数不因订阅变化）。

不包含：订阅消息的真实推送通道（demo 只维护订阅关系与界面提示）；多用户订阅隔离。

### US-ZHIKU-BR-02｜智能识别新问题并入库发布

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 82（权威来源目录+大数据挖掘构建识别模型；清单生成、维护） |
| 产品角色 | `ROLE-BR-MANAGER` |
| 依赖 | US-01（同一清单视图） |
| Frame | `F-BR-01` |
| 业务结果 | "识别模型"产出的候选问题真实进入清单并可维护状态（识别中 → 在线发布），演示态全程 🧪 标注 |

作为科技管理部门决策支撑人员，我想一键触发智能识别并看到新问题真实进入清单，再人工确认后在线发布，以便体验"识别模型 → 清单维护 → 在线发布"的完整管理链路。

主路径：

1. 用户在问题清单卡片点"智能识别（挖掘模型）🧪"。
2. 按钮进入 loading（模拟挖掘耗时），完成后弹出成功提示：识别到 1 个新问题。
3. 新问题置顶出现在清单中，带"新识别 🧪"标记，状态为"识别中"。
4. 用户对"识别中"的问题执行"在线发布"，状态流转为"已在线发布"，问题总数统计卡同步 +1。
5. 刷新页面后新识别问题与其状态保持不变。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 演示候选池耗尽 | 提示"演示数据池已用尽，暂无新问题可识别"，按钮恢复可点但不再入库 | 可用"恢复演示数据"重置 |
| 识别进行中重复点击 | 按钮 loading 期间禁用，不产生并发识别 | 等待完成 |
| 误识别问题 | "识别中"问题可"移除"（仅限新识别且未发布的），清单回滚 | 移除后可再次识别 |

验收：

- `AC-US-ZHIKU-BR-02-01`：触发识别后有可见 loading 态，完成后新问题真实出现在清单顶部（非仅 toast），带"新识别"标记与 🧪 标注。
- `AC-US-ZHIKU-BR-02-02`：新识别问题状态为"识别中"，执行"在线发布"后状态变为"已在线发布"，`ZHIKU-BR-ISSUE-TOTAL` 统计卡数值 +1（口径=已发布）。
- `AC-US-ZHIKU-BR-02-03`：刷新页面后新识别问题、其状态与清单顺序保持不变。
- `AC-US-ZHIKU-BR-02-04`：候选池耗尽后再次识别出现明确空态提示，不产生重复/伪造问题。
- `AC-US-ZHIKU-BR-02-05`：未发布的新识别问题可移除，移除后不出现在清单与订阅区。
- `AC-US-ZHIKU-BR-02-06`：识别功能全程带"演示态：预置候选池+固定延时，非真实挖掘模型"的诚实性标注。

不包含：真实 NLP/文本挖掘模型接入；权威来源目录的后台配置管理。

### US-ZHIKU-BR-03｜回溯问题发展趋势并处理监控预警

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 83（发展轨迹、增长速度、研究热度、潜力评估；动态监控、预测报告、智能推荐） |
| 产品角色 | `ROLE-BR-ANALYST` |
| 依赖 | US-01（从清单下钻进入） |
| Frame | `F-BR-02` |
| 业务结果 | 单个问题的来源回溯、趋势轨迹、量化得分、预警与推荐形成一屏研判视图，且下钻上下文可分享、可刷新恢复 |

作为智库研究分析人员，我想从清单点击某个问题直接进入它的发展趋势视图，回看轨迹、处理预警、顺着推荐跳到相关问题，以便对单个问题形成完整研判。

主路径：

1. 用户在问题清单点"查看趋势"，页面切换到"问题发展趋势"标签且目标问题已选中（URL 同步 `tab` 与 `issue` 参数）。
2. 视图展示：问题来源回溯条（来源目录+识别时间）、发展轨迹图（近 5 年产出）、增长速度/研究热度/潜力评估统计卡（ⓘ `ZHIKU-BR-ISSUE-HEAT-SCORE`，演示态）。
3. 用户查看"动态监控预警"，对已处理的预警点"标记已处理"，预警条目变灰移到已处理分组。
4. 用户点"智能推荐"中的相关问题，视图切换为该问题（URL 同步）；点相关文献打开摘要抽屉。
5. 刷新页面后当前问题、预警处理状态保持不变。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 新识别问题暂无趋势数据 | 轨迹图区局部 Empty："该问题为新识别，趋势数据积累中"，统计卡显示"—" | 回清单选择成熟问题 |
| 当前问题无预警 | 预警卡 Empty："当前问题暂无预警" | 无需处理 |
| URL 携带不存在的 issue id | 回退到默认问题并提示"目标问题不存在，已展示默认问题" | 重新选择 |

验收：

- `AC-US-ZHIKU-BR-03-01`：从清单"查看趋势"进入后目标问题已选中，URL 含 `tab=trend&issue=<id>`，复制该 URL 新开或刷新后上下文完整恢复。
- `AC-US-ZHIKU-BR-03-02`：趋势视图含来源回溯、发展轨迹图、三张量化得分统计卡；得分卡带 ⓘ（`ZHIKU-BR-ISSUE-HEAT-SCORE`）与演示态说明。
- `AC-US-ZHIKU-BR-03-03`：预警可"标记已处理"，处理后从未处理分组移出，刷新后处理状态保留。
- `AC-US-ZHIKU-BR-03-04`：智能推荐的"相关问题"点击后切换当前问题且 URL 同步；"相关文献"点击后打开摘要抽屉。
- `AC-US-ZHIKU-BR-03-05`：新识别问题（无趋势数据）进入趋势视图时出现明确 Empty 态，不伪造轨迹数据。
- `AC-US-ZHIKU-BR-03-06`：潜力评估处带"演示态打分，非真实时序+文献引用+成果综合模型"的诚实性标注。

不包含：预测报告文档的自动生成（"预测报告"语义由趋势视图+生成报告出口承接，正式版挂算法侧）；预警规则配置。

### US-ZHIKU-BR-04｜三层次竞争格局对比并生成报告

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 84（国际/国家/深圳市三层次竞争态势；研究热度/前沿引领性/投资力度/研究主体总量统计与可视化；区域对比、趋势追踪） |
| 产品角色 | `ROLE-BR-ANALYST` |
| 依赖 | US-03（同页下钻语境）；跨叶子依赖 ZHIKU-WRITING US-02（预填任务的大纲确认） |
| Frame | `F-BR-03` |

作为智库研究分析人员，我想在国际、国家、深圳市三个层次间切换对比竞争态势，并把当前研判直接转成一份竞争格局报告任务，以便分析结果不停留在图表而是进入报告生产线。

主路径：

1. 用户切到"竞争格局报告"标签，三层次 Tab（国际/国家/深圳市）默认停在上次选择。
2. 当前层次的研究热度/前沿引领性/投资力度/研究主体总量四张统计卡刷新（ⓘ `ZHIKU-BR-COMPETITION-INDEX`，D1 缺失红问号态）。
3. 用户在"区域对比"卡切换柱状图/雷达图两种可视化。
4. 用户查看"趋势追踪"三层次逐年曲线。
5. 用户点"生成竞争格局报告"，系统在写作模块创建预填任务（标题含当前层次、大纲含竞争态势章节、分析思路注入当前层次统计数据），并跳转到写作模块大纲确认步骤。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 生成报告前二次确认取消 | 不创建任务、不跳转，停留当前视图 | 继续分析 |
| 重复点击生成 | 每次生成独立新任务（demo 语义），确认弹窗明示"将创建新的写作任务" | 可到写作模块删除多余任务 |
| 层次数据缺失 | 该层次统计卡显示"—"并保留 ⓘ 追溯入口 | 切换其他层次 |

验收：

- `AC-US-ZHIKU-BR-04-01`：三层次 Tab 切换后四张统计卡与两张图表同步刷新，且当前层次选择刷新页面后保留。
- `AC-US-ZHIKU-BR-04-02`：区域对比图支持柱状图/雷达图切换，切换不丢当前层次上下文。
- `AC-US-ZHIKU-BR-04-03`：竞争格局综合指数指标为 D1 缺失态（红问号 `IconQuestionCircle`，点开显示 GAP 治理引用而非伪 8 件套），页面带 Q-ZHIKU-04 待确认标注。
- `AC-US-ZHIKU-BR-04-04`：点"生成竞争格局报告"确认后，写作模块任务列表真实新增一条任务，其标题含当前层次名，大纲 ≥4 章且至少一章的分析思路含当前层次统计数值。
- `AC-US-ZHIKU-BR-04-05`：生成后自动跳转到写作模块大纲确认步骤（URL 含 `step=outline&task=<新任务 id>`），用户可继续走 ZHIKU-WRITING US-02/03 完成写作闭环。
- `AC-US-ZHIKU-BR-04-06`：取消确认弹窗后写作模块任务数不变。

不包含：报告正文的生成与编辑（归 ZHIKU-WRITING）；竞争格局指数正式权重算法（挂 `GAP-ZHIKU-BR-COMPETITION-INDEX-权重算法定义卡未落地`）。

### US-ZHIKU-BR-05｜深圳市部署清单筛选与地图联动

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 85（动态生成更新部署清单；可视化清单、趋势分析、热点问题识别） |
| 产品角色 | `ROLE-BR-MANAGER` |
| 依赖 | US-01（热点问题回链到问题清单） |
| Frame | `F-BR-04` |
| 业务结果 | 部署清单的表格视图与地图视图保持同一筛选上下文并双向联动，热点问题可回链到问题清单继续下钻 |

作为科技管理部门决策支撑人员，我想按领域/优先级/进展状态筛选部署清单，并在地图和表格之间来回定位同一条目，以便同时掌握"部署了什么"与"部署在哪里"。

主路径：

1. 用户进入"深圳市部署清单"页，顶部统计卡显示清单总数（ⓘ `ZHIKU-BR-DEPLOY-TOTAL`）与高优先级条目数。

3. 用户点击表格某行，地图上对应点位放大高亮（选中态），行呈选中底色。
4. 用户点击地图点位，表格滚动定位到对应行并高亮，详情侧条显示该条目的领域/机构/优先级/状态/更新时间。
5. 用户查看趋势分析（清单规模与高优先级逐年）与"热点问题识别"标签，点热点问题跳转到问题清单页并定位该问题趋势。

| 异常 | 系统行为 | 用户下一步 |
