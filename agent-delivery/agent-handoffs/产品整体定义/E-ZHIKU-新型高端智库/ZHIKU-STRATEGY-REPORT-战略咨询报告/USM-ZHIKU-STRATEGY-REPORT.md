## 4. 用户故事

### US-ZHIKU-SP-01｜管理研究报告全生命周期

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 50（报告创建、编辑、上传、查询、删除、版本管理；自动摘要、关键词提取、智能标签、质量检测；导出、分类归档） |
| 产品角色 | `ROLE-SP-RESEARCHER` |
| 依赖 | 无（模块入口故事） |
| Frame | `F-SP-01` |
| 业务结果 | 研究报告可上传（🧪 自动摘要/关键词/标签/质检）、编辑元信息、重传生成新版本、归档进研报库、删除有校验，检索筛选与全部变更刷新后保持 |

作为研究报告管理者，我想上传报告后自动获得摘要、关键词与质量评分，并能编辑、管版本、归档和删除，以便报告资产有序沉淀而不靠手工整理。

主路径：

1. 用户进入"战略咨询报告"页，默认停在"研究报告"标签：关键词/行业筛选 + 报告列表（标题/行业/版本号/质量分/发布时间）。
2. 用户点"上传报告"，选择演示文件并填标题/行业，确认后条目以"解析中"入列，约 2 秒后 🧪 自动生成摘要、关键词、智能标签与质量检测分，状态转"已就绪"。
3. 用户点开报告详情抽屉：摘要/目录/全文预览/脚注溯源附录/版本历史。
4. 用户"编辑"元信息（标题/行业/摘要）保存即生效；"上传新版本"后版本号 +1，版本历史追加，旧版本可回看。
5. 用户"归档"报告，条目进入"研报库"分组并打归档标；"删除"弹确认，若该报告已被战略报告生成引用则拦截提示。
6. 用户"导出"报告（文本演示导出）。
7. 刷新后筛选、列表、版本、归档态全部保持。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 上传未选文件/标题为空 | 校验拦截，弹窗不关闭 | 修正后重试 |
| 检索无结果 | 局部 Empty + "清空筛选" | 一键清空 |
| 删除被引用的报告 | 拦截并列出引用它的生成记录 | 先解除引用或放弃 |
| 解析中报告被点开 | 详情抽屉显示"解析中"骨架态 | 等待完成 |

验收：

- `AC-US-ZHIKU-SP-01-01`：上传经校验入列并经历"解析中→已就绪"流转，🧪 自动摘要/关键词/标签/质量分真实出现在详情中（规则式演示，带 🧪 标注）。
- `AC-US-ZHIKU-SP-01-02`：关键词+行业筛选叠加实时生效、刷新保持；无结果局部 Empty+清空。
- `AC-US-ZHIKU-SP-01-03`：编辑元信息保存即生效；上传新版本后版本号 +1 且版本历史可回看旧版摘要。
- `AC-US-ZHIKU-SP-01-04`：归档报告进入研报库分组（带归档时间），研报库回链可打开原报告详情。
- `AC-US-ZHIKU-SP-01-05`：删除有确认弹窗；被生成记录引用的报告删除被拦截并列明引用方。
- `AC-US-ZHIKU-SP-01-06`：研究报告总数统计卡带 ⓘ（`ZHIKU-SP-RESEARCH-TOTAL`）与 🧪。
- `AC-US-ZHIKU-SP-01-07`：全部状态（列表/版本/归档/筛选）刷新后保持（localStorage `zhiku-sp-` 前缀）。

不包含：真实文档解析与 NLP 摘要（🧪 规则式）；跨平台调用 API（正式阶段 Java REST）；可视化报告编辑器（归 ZHIKU-WRITING）。
