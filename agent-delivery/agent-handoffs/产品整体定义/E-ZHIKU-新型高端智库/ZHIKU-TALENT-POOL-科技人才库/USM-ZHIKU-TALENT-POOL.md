## 1. 模块结果

围绕"要找谁、这个人怎么样、值不值得持续跟踪"这一人才服务链，让用户完成"分类/检索定位人才 → 全景画像研判（基础/关联/行为/心理四维）→ 收藏关注与专属人才池沉淀 → 动态资讯与个性化推送持续跟踪"的完整闭环，并在人才池节点提供"生成人才池分析报告"跨叶子出口（进入 ZHIKU-WRITING 预填任务）。不承接地图可视化与区域人才指数（归 ZHIKU-TALENT-MAP），不承接报告写作本体（归 ZHIKU-WRITING）。心理信息（序号 62）为高敏感维度，采集与展示边界挂 `Q-ZHIKU-05`，demo 阶段仅演示态呈现且全程 ⚠️ 标注；影响力/贡献度/成长指数等打分为演示态简化公式，禁止伪闭合。

## 4. 用户故事

### US-ZHIKU-TP-01｜检索学者并查看全景画像

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |
| `requirement_refs` | 序号 59（基础信息结构化视图）、60（关联信息：头衔/成果/主题/合作团队/网络关系/相似学者；影响力与贡献度计算；雷达图/河流图/关系网络图）、61（行为信息：迁徙路径/成长轨迹/合作倾向；时间轴/热力图/趋势图） |
| 产品角色 | `ROLE-TP-ANALYST` |
| 依赖 | 无（模块入口故事） |
| Frame | `F-TP-01` |
| 业务结果 | 单个学者的基础/关联/行为三维画像形成一屏研判视图，且学者与页签上下文 URL 可分享、刷新可恢复 |

作为人才评估研判人员，我想按姓名检索学者并在基础/关联/行为页签间切换查看其结构化画像，以便快速形成对该学者的整体判断，并把当前视图链接直接发给同事。

主路径：

1. 用户进入"人才画像"页，默认展示默认学者的"基础信息"页签（URL 同步 `scholar` 与 `tab` 参数）。
2. 基础信息页签展示照片位、职称、机构、领域、研究方向、荣誉称号、联系方式与教育/工作经历时间轴（序号 59 全字段）。
3. 用户切换"关联信息"页签：成果影响力雷达图与作者贡献度得分（ⓘ `ZHIKU-TP-INFLUENCE-SCORE`，演示态）、研究主题河流图、合作网络关系图、相似学者列表。
4. 用户切换"行为信息"页签：迁徙路径图、成长轨迹趋势图与成长指数（ⓘ `ZHIKU-TP-GROWTH-INDEX`，演示态）、合作活跃度热力图。
5. 用户点相似学者中的条目，画像切换为该学者（URL 同步）；用户搜索另一学者姓名，命中后画像切换。
6. 刷新页面或复制 URL 新开，当前学者与页签完整恢复。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 搜索无命中学者 | 画像区局部 Empty："未找到该学者，请检查姓名或更换检索词"，保留搜索词 | 修改检索词或从下拉选择 |
| URL 携带不存在的 scholar id | 回退默认学者并提示"目标学者不存在，已展示默认学者" | 重新选择 |
| 相似学者为非入库学者 | 条目置灰并提示"该学者未入库，暂无画像" | 选择其他条目 |

验收：

- `AC-US-ZHIKU-TP-01-01`：画像页 URL 含 `scholar=<id>&tab=<key>`，复制新开或刷新后学者与页签完整恢复。
- `AC-US-ZHIKU-TP-01-02`：基础信息页签含序号 59 要求的结构化字段（职称/机构/领域/研究方向/荣誉/主页占位）与教育、工作双时间轴。
- `AC-US-ZHIKU-TP-01-03`：关联信息页签含雷达图、河流图、合作网络图、相似学者四块；贡献度得分卡带 ⓘ（`ZHIKU-TP-INFLUENCE-SCORE`）与演示态标注。
- `AC-US-ZHIKU-TP-01-04`：行为信息页签含迁徙路径、成长趋势（ⓘ `ZHIKU-TP-GROWTH-INDEX`）、合作活跃度热力三块。
- `AC-US-ZHIKU-TP-01-05`：点击相似学者后画像切换且 URL 同步；搜索无命中时出现 Empty 态且不清空搜索词。
- `AC-US-ZHIKU-TP-01-06`：影响力/成长指数处带"演示态简化公式，非正式算法"的诚实性标注。

不包含：学者数据的新增/编辑（画像为只读消费）；真实成果库/文献库对接。

| 属性 | 内容 |
| --- | --- |
| `source_relation` | `direct_requirement` |

| 产品角色 | `ROLE-TP-ANALYST` |
| 依赖 | US-01（画像页第四页签） |

4. 用户点击诚信记录中"关注"状态条目可查看说明（demo 数据均为"正常"，关注态由种子数据演示）。
5. 刷新页面后页签上下文保持（URL `tab=psych`）。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 学者无诚信记录 | 记录表 Empty："暂无核验记录" | 无需处理 |

- `AC-US-ZHIKU-TP-02-02`：诚信记录、意识形态指标、舆情主题三块完整呈现，数据全部来自 mock 种子（无前端硬编码结论文案）。
- `AC-US-ZHIKU-TP-02-03`：所有打分/倾向数值带"演示态，非真实情感分析/主题聚类输出"标注。
- `AC-US-ZHIKU-TP-02-04`：`tab=psych` 可经 URL 直达且刷新保持。
- `AC-US-ZHIKU-TP-02-05`：该页签不出现任何"风险等级判定/建议不引进"等结论性文案（诚实性约束：demo 不代算法/甲方下结论）。

不包含：真实撤稿库/舆情源接入；风险评级模型；心理信息的导出（高敏感数据 demo 不提供导出）。

### US-ZHIKU-TP-04｜构建并管理专属人才池（TOP100）

| 属性 | 内容 |

| 依赖 | US-01（画像下钻）、US-06（收藏联动） |
| Frame | `F-TP-03` |
| 业务结果 | 从条件筛选到专属池沉淀的完整管理闭环：池可保存、重命名、更新成员、共享（链接复制）、导出，且跨会话保留；并可从池直接生成分析报告（跨叶子出口） |

作为人才寻访人员，我想按领域/机构等条件筛选 TOP100 榜单并把目标人选保存为专属人才池，以便围绕科研项目持续维护候选集合，并一键生成人才池分析报告。

主路径：

1. 用户进入"人才库"页"TOP100 榜单"页签，顶部统计卡显示收录数（ⓘ `ZHIKU-TP-TOP100-TOTAL`）。
2. 用户设置筛选条件（领域/机构），榜单实时过滤；筛选条件刷新后保留。
3. 用户勾选若干人才行，点"保存为专属人才池"，命名后池出现在"我的人才池"区。
4. 用户对已有池执行：重命名；"更新成员"（在当前筛选结果中增删勾选）；"共享"（复制池摘要到剪贴板并提示）；"导出"（真实下载池成员 CSV）。
5. 用户点池成员姓名下钻画像页（URL 契约同 US-01）。
6. 用户对池点"生成人才池分析报告"，确认后在「报告创作」模块真实创建预填任务并跳转大纲确认（跨叶子契约）。
7. 刷新页面后池列表、成员、筛选条件全部保留。

| 异常 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 未勾选人才就保存池 | 保存按钮禁用并提示"先勾选目标人才" | 勾选后重试 |
| 池名称为空或重名 | 表单校验错误提示，不落库 | 修改名称 |
| 删除池 | 二次确认 Modal，确认后移除并可撤销提示（5 秒内） | 撤销或确认 |
| 筛选组合无结果 | 榜单区局部 Empty + "清空筛选" | 一键清空 |

验收：

- `AC-US-ZHIKU-TP-04-01`：筛选条件可组合叠加、实时过滤、刷新保留；无结果时出现 Empty 与"清空筛选"。
- `AC-US-ZHIKU-TP-04-02`：勾选人才可保存为命名池，池在"我的人才池"区展示成员数与创建时间，刷新后保留（localStorage `zhiku-tp-` 前缀）。

- `AC-US-ZHIKU-TP-04-04`：池"共享"复制摘要文本成功并提示；"导出"产生真实 CSV 下载，内容为池成员明细。
- `AC-US-ZHIKU-TP-04-05`：池成员姓名可下钻画像页且 URL 携带 scholar 参数。
- `AC-US-ZHIKU-TP-04-06`：`ZHIKU-TP-TOP100-TOTAL` 与"我的人才池数"（ⓘ `ZHIKU-TP-POOL-TOTAL`）两张统计卡带 ⓘ 与 🧪。

不包含：真实 TOP100 指标加权算法（榜单为静态种子排序）；池的多用户共享权限（共享=复制摘要演示）。
