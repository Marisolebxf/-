## 为什么要单独一本，而不是写进知识图谱 SAD

图谱回答「点和边在不在」。政策时序空板的根因是：**点在图上，政策明细对不上点**——`theme` 被当成产业。向量回答的是「这段话像哪个已有点」，不新建第二套产业。

知识图谱 SAD 写「RAG 不是建图开工条件」仍然对：没有图，向量没有合法 VID 可检索。先有图，再有产业向量。

---

## 为什么不直接上政策全文 RAG

4.7 万篇正文 × 切片会得到文档知识库，适合问答「这条申报条件是什么」，**不适合**给上图提供 `chain:INB1303`。产业点只有约千个，用锚点向量更便宜、更好定码。招标里的「向量检索」在政策对比/报告场景可以后接**文档 collection**，不要和产业 collection 混。

## 分角色别踩坑

### 产品 / UE

- 详情页 `ext5` 叫 **政策主题标签**，不要叫目标产业。
- 时序板空 = 无产业码，不是前端没画图。全局 47051 是 metrics 回落，不是本任务切片。

### 数据 / 重灌操作员

- **灌链**：映射 + 上图完成后，才跑索引 rebuild；链没稳定不要建库。
- **灌政策 / 企业**：清业务 DWD 再映射，**默认不调 LLM、不重建向量索引、不调 Milvus**。
- 不要指望政策重灌把「监督管理」变成集成电路；也不要把「重灌」理解成刷新产业向量。

### 算法

- 复用 hang 的锚点匹配；LLM 只准出中文名。
- 检索 API 与 hang 定码共用；禁止第二套 VID 规则。
- 连现网 Milvus 时 **新建** `gkxlumen_industry_*`（下划线；连字符名建不出）；不要把产业名 embed 进 `amcpdp-*`（那是图/视频帧，模型维度不同）。

### Java / 前端

- 只 Feign / 只调 REST。超时不要本地编一个产业码重试。不要直连 `192.168.88.43:19530`。

### QA

- 用例：有链名标题应能对码；纯主题标签不得对码；假 VID 必须丢掉。

### PM / 架构

- 采购向量云前先确认：**已经有 Milvus**。先做 P0 纠正映射；P1 只加产业 collection。覆盖矩阵（01 §6）用来挡「只给政策做 RAG」和「把产业链塞进 amcpdp」两种膨胀。
