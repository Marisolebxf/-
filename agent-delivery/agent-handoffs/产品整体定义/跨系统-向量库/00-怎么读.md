## 一分钟版（全员先看完这 9 句）

1. 我们要的是 **产业坐标系的向量**，不是再给每篇政策做一个聊天知识库。
2. 词表就是知识图谱上的 **产业链 / 链环**（`chain:` / `segment:`），和跨系统知识图谱 **同一套点**。
3. 向量只负责 **召回像哪个产业**；写库、上图仍要稳定码，**禁止用中文名或相似度当 VID**。
4. **建库挂在产业链灌数末段**：链表/图点 VID 稳定后一次 `embed/rebuild`；不是灌每一条链当场打向量。
5. 政策 ODS 的 `theme` 是 **政策主题标签**（监督管理、产业发展），不是目标产业；政策重灌不得把它写进 `related_entities.industry`。
6. 政策/企业等 **业务灌数**只做结构映射 + 字面对码（L0+L1），**默认不调 Milvus、不调 LLM**；语义抽槽是独立任务。
7. 对不上图的名称可以留在 DWD 里当 `{name}`，上图诚实 skip，不造 `chain:INB*`。
8. 前端 → Java → Python `/internal/*`；Java 不做 embedding。未就绪检索可降级字面匹配，禁止假码。
9. 现网已有 **Milvus 2.4**（`192.168.88.43:19530`）。产业锚点 **共用实例、另开 collection**（前缀 **`gkxlumen_industry_`**，不得用连字符）；`amcpdp-*` 是图搜/多模态，**不要往里写产业链**。会签前，三卷 **不是** 生产 OpenAPI。原记 `88.48` **作废**。
