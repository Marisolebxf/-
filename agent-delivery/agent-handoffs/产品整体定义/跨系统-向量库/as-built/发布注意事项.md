## 2. 空集合不够用

`gkxlumen_industry_anchor` 只是货架。政策页「开始跑批」先对它做一次检索探测：集合不存在时 Milvus 返回非 0，Python 回 503，Java 收成 501，文案是「产业锚点索引不可用或正在重建，未写假码」。

集合存在但没有向量时，检索可以是 `code=0` 且 `items=[]`。探测不再判失败，跑批仍对不上任何产业链 / 环节码。要出码，必须先把链表名字写进这个集合。

## 3. 产业链内容要不要灌进这个集合

要。写入的是图上已经稳定的 **链（chain）和环节（segment）名字**，不是政策正文，也不是 ADS 指标。一条锚点 = 一个图上 VID（如 `chain:INB1303`）+ 名字 + 别名拼成的 `text` + 768 维向量。锚点侧 embed **不加**检索指令前缀；查询侧才加。

这条写入挂在 **产业链上图的末段**，不挂在政策「灌数据」或「开始跑批」上。

```text
产业链灌数（MySQL）
  llm_ods → demo ODS → DWD industry_chain / industry_chain_node → ADS
        │
        │  这一步只写关系库，不写 Milvus
        ▼
上图 POST /internal/v1/chain/graph/project
  project_graph：DWD 链表 → Nebula demo_gkx_chain
        │
        │  chain/segment 点数写稳之后，同一次调用的末尾
        ▼
_hook_industry_index → industry_embed.rebuild
  TEI POST http://gkxlumen-embed-tei:8080/v1/embeddings
  Milvus：drop + create + insert  gkxlumen_industry_anchor
```

代码位置：`lumen-algo-py` 的 `lumen_common/algorithms/chain/graph_project.py`（`_hook_industry_index`，全库只有这一处调用 `rebuild`）和 `lumen_common/algorithms/industry_embed.py`（`load_anchors` / `rebuild`）。对外也可以单独打 `POST /internal/industry/embed/rebuild`，但它是同一条整库重建，不是第二条业务入口。

点没写稳、词表为空、TEI 或 Milvus 失败时，**跳过或失败并保留上一版索引**，不回滚已经写好的 DWD 和图。

## 4. 现网 demo 谁负责把名字写进集合

`demo-ui-system-test` 产业链分析算法库下的 **「产业链入向量库」** 才写这个集合。

| 按钮 | 路径 | 是否写向量库 |
|---|---|---|
| 基础指标 · 灌数据 | `POST /innov/v1/industry/internal/run-chain-pipeline` | 否。只做 `llm_ods → ODS → DWD → ADS` |
| 产业链入向量库 · 写入向量库 | `POST /innov/v1/industry/internal/embed-load` → entan-py `POST /internal/industry/embed/load` | 是。读 DWD `industry_chain` / `industry_chain_node` 的名字，TEI embed 后整库替换 `gkxlumen_industry_anchor` |
| 政策 · 开始跑批 | `POST /policy/v1/industry/jobs/enrich` | 否。只检索，索引空或不可用就停 |

使用顺序：先在「基础指标」灌完关系库，再打开「产业链入向量库」点「写入向量库」。空词表不会 drop 已有集合。政策「灌数据」不写本集合。

正式仓 `lumen-algo-py` 的上图末段 `project_graph` → `rebuild` 仍是另一条写入点，和这个 demo 菜单不是同一个进程。
