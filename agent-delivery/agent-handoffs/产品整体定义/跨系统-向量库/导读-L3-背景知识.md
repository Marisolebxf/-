## 图谱 vs 向量（直觉）

- **图谱**：户口本。`chain:INB1303` 叫「集成电路」，政策点 `pol:21259587` 可以有一条 `apply_to` 边连过去。
- **向量**：长相相似的检索。把「芯片产量增长」和「集成电路」放进同一空间，找出最近的户口，**再去户口本核对名字是不是真的那一户**。

没有户口本，向量只能给出「长得像」的字符串，不能上图（上图禁止用名称当 VID）。

## 整条链路怎么算（TEI + Milvus）

**TEI** = **Text Embeddings Inference**（Hugging Face 的文本向量推理服务）。K8s 里那台 `gkxlumen-embed-tei:8080` 就是它，模型是 `bge-base-zh-v1.5`。

整条链路就两步：**把字变成一组数，再在这组数里找最像的产业名。**

**1. 编码（TEI）**  
模型已经训好。一句话进去，出来 **768 个小数**（一个向量）。意思接近的句子，这 768 个数在空间里靠得近；字面碰巧像、意思不像的，反而离得远。  
查询侧会先加一句指令前缀（「为这个句子生成表示以用于检索相关文章：」），锚点名不加——检索是「长政策句对短产业名」，两边编码方式本来就不对称。

**2. 入库 / 检索（Milvus）**  
灌链成功后，把图上约 1516 个产业名（链 + 环节）各算一次向量，放进 `gkxlumen_industry_anchor`（仍在 `10.50.69.111:19530`，**没进 K8s**）。  
以后搜「集成电路产量增长 23.1%」，只对**这一句**再算一次向量，在库里按夹角（COSINE）取 top-k 个最像的名字和 VID。

**3. 定码不在向量里**  
分数只表示「像不像」，**不是** `chain:INB*`。还要过 `match_industry_anchors`，对上图上已有的点才写槽。对不上就只留 `{name}`。

之前用 blake2b 哈希，本质是数笔画像不像，所以「集成电路产量增长」会撞上「矿产勘探」。换成 bge 之后，同一句里集成电路约 0.50、矿产勘探约 0.16——这就是语义检索比字面匹配多出来的那一层。

两个地址不要混：TEI 只负责算；Milvus 只负责存和搜。

## L0 / L1 / L2（政策映射）

- **L0**：字段搬家。主题进 ext5，不进产业槽。
- **L1**：标题等字面是否包含图上链名。同步，可进重灌。
- **L2**：大模型读摘要/要点/正文截断，抽出产业**中文名**，再走 L1 对码。异步，不进重灌。

产业向量插在 L1 与 L2 之间：先找出「像哪些链」，L1/L2 只在这个短名单里干活。

**什么时候写入 Milvus**：只在 **产业链灌完、图上已有稳定 VID** 之后整表重建。政策灌进去的是「谁像哪条链」的查询，不是把政策正文变成词表。

## 同一台 Milvus，不同货架

机房里已经有一台 **Milvus**（`10.50.11.76`），上面同实例住着别人的库（`aip_kb_*` 等）。产业链名字是另一类货：文本、短、要对应户口本 VID。放进**同一仓库的新货架**（前缀必须下划线 `gkxlumen_industry_*`，连字符名建不出），不能写进别人的 collection，也不能写进多媒体帧货架——尺子（embedding 维度）都不一样。原记 `88.48` **作废**。
