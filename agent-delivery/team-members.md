## 2.6 展示系统三屏分工（bid-reference 要求）

科技信息展示系统须具备 **大 / 中 / 小** 三种 UE/UI 形态（见 `bid-reference` §展示层）。本项目按**双轨交付**：

| 屏幕 | 场景定位 | 视觉风格 | 负责团队 | 负责人 |
|------|----------|----------|----------|--------|
| **大屏** | 接待、汇报、展厅超大屏 | 传统展示大屏（**蓝色背景**）；**不适用** `Design.md` 浅蓝白工作台 | **联通数智**（约 5 人，含设计师+前端） | **王亚东** |
| **中屏** | 政府决策、智库分析、主工作台 | `Design.md` 浅蓝白 + Arco（D8） | 现有团队 | 高颖（UE）+ 孔东（前端） |
| **小屏** | 裁剪版、移动/窄屏适配 | 中屏信息架构裁剪，Arco 响应式 | 现有团队 | 高颖 + 孔东 |

### 大屏轨（Track-L）· 联通数智全链路

王亚东团队**端到端负责**：

```text
大屏 UE → 大屏 UI（高保真）→ 大屏前端实现 → 大屏后台接口对接
```

| 事项 | 负责人 |
|------|--------|
| 大屏 UE/IA/wireframe | 王亚东团队 |
| 大屏高保真与视觉冻结 | 王亚东团队 |
| 大屏前端开发与联调 | 王亚东团队 |
| 大屏所需后台 API | 王亚东团队对接；契约与 **侯佳伟** 对齐 |
| 指标语义 / metric_id | **何老师**（北明）核对 |
| 数据贴源 / ADS | **辜少彬**（GDF）+ 徐滕强 |
| 合规 TRACE / ±10% | **郭万迎** 审核 |

### 中/小屏轨（Track-MS）· 现有团队

```text
wireframe → V1 高保真（UI + ui-agent）→ demo 逼近（孔东团队）→ 门2 → lumen 复刻
```

详见 `产品定义评审规程.md` §5.5–§5.7。

### 跨轨协作纪律

| 纪律 | 说明 |
|------|------|
| 视觉规范分轨 | 大屏用联通数智大屏规范；中/小屏用 `Design.md`，**禁止混搭** |
| 产品合规统一 | 两轨均须映射 `TRACE-{模块}.yaml` 与 bid 叶子 |
| API 统一入口 | 大屏/中屏均走 Java 聚合层（方案 A），禁止前端直连 Python |
| 评审分轨签字 | 大屏走 **V-L 大屏交付会签**；中/小走 **V1 + V2** |

## 6.5 数据平台 · GDF（通用数据处理工厂）

| 真名 | 角色 | 本项目职责 |
|------|------|------------|
| **辜少彬** | **GDF 团队负责人** | 带领 GDF 团队完成本项目**数据中台建设** |

### 核心目标（三项）

#### 目标 1 · 贴源与要素标准表落库

在 **GDF 平台**上完成：

- 总集采购的**原始数据贴源**（ODS 层）
- 按架构师设计的各维度**要素数据标准表**做 **Mapping**，落库 **MySQL** 与 **ES**
- 相关**调度任务**管理、**错误告警**与运行监控

**协作接口**：徐滕强（要素表/ADS 契约设计）· 何老师（指标语义与字段口径）· `数据库设计.md` §12

#### 目标 2 · 加工过程调度与编排

对以下加工过程，由 GDF 统一调度、监控与告警：

| 加工类型 | GDF 实现方式 | 说明 |
|----------|--------------|------|
| **简单指标计算** | GDF 内直接实现 | 标准 SQL + 数据库用户自定义函数（UDF） |
| **复杂指标 / 图实体识别 / 专题核心算法** | GDF 调用 K8s 微服务 API | 高算力实现以微服务发布在 K8s；GDF 用 Java/Python 代码编排调度 |
| **图数据实体识别与构建** | 微服务 + GDF 调度 | 与算法团队、图谱引擎（NebulaGraph）协同 |
| **专题核心算法执行** | 微服务 + GDF 调度 | 对接唐绍祖团队 Python `/internal/*` 服务 |

**协作接口**：唐绍祖（算法微服务）· 侯佳伟/徐滕强（K8s 服务注册与 API 契约）· `data-lineage-policy.md`（metric_id 回写 ADS）

#### 目标 3 · 大模型相关任务调度（探索）

在与大模型相关的任务调度场景上，探索 **GDF + LLM 工作流**的结合路径（如同步抽取、批处理推理、Agent 流水线触发等）；与唐绍祖（LLM/Agent）、徐滕强（数据聚合）联合试点。

### 本项目分工

| 事项 | 负责人 |
|------|--------|
| GDF 平台贴源 / Mapping / 调度总体 | **辜少彬** |
| 要素标准表 DDL / ADS 契约定义 | 徐滕强（架构）+ GDF 落地 |
| 指标语义与 Mapping 字段口径 | 何老师（北明） |
| 复杂算法微服务（K8s） | 唐绍祖 |
| 简单指标 SQL/UDF | GDF（辜少彬团队） |
| 门 1 PDR（涉数据贴源/调度模块） | 辜少彬列席 |

### 数据链路位置（简图）

```text
总集采购原始数据
    ↓  GDF 贴源（ODS）
    ↓  GDF Mapping
MySQL 要素标准表 + ES
    ↓
├─ 简单指标：GDF SQL/UDF
├─ 复杂指标 / 图构建 / 专题算法：GDF → K8s 微服务 API
└─ LLM 任务（探索）：GDF 编排
    ↓
Java 聚合层（只读 ADS）→ 前端
```
