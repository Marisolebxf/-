## 1. 概述

### 1.1 内测上线目标

将**科技专题服务系统**（前端 `lumen-ui-topic` / `lumen-ui-topic-mobile` + Java 聚合 `gkxlumen-topic*` / `gkxlumen-metrics` / gateway + 依赖的专题侧 Python `/internal/*`）发布到**云环境**，与现网联调集群（`10.50.69.111` 等）**隔离**，满足总集内测上线验收材料要求。

本方案**不**覆盖科技信息展示系统完整内测上线包（另册）；算法库专项见 `2-专题算法库/`。

### 1.2 影响范围（产品补充 · 草稿）

| 范围 | 说明 |
|---|---|
| 用户可见 | 专题五维分析（企业 / 产业链 / 政策 / 服务机构 / 综合）PC + 小屏 |
| 服务面 | 网关 → `gkxlumen-topic` 及 enterprise/chain/policy/async 等门面；指标 `gkxlumen-metrics` |
| 下游 | Python `lumen-algo-py` / `lumen-etl-es-py`（云环境侧调用，不直连 demo） |
| 数据 | ADS MySQL、ES（企业/政策）、对象存储 `gkx-lumen/*`、TRSGraph、Redis（token/首页） |
| 不在本单 | 展示系统全量页、门户 CMS 独立交付包、GDF 贴源作业细则（仅登记依赖） |

## 3. 实施部署验证

### 3.1 架构与配置

#### 3.1.1 部署架构（文字版）

```
用户 →（入口/ Ingress · TBD）→ gkxlumen-gateway
  → gkxlumen-topic* / metrics / async
  → Python /internal/*（lumen-algo-py 等）
  → ADS MySQL / ES / Redis / TRSGraph / S3(obs.cc.cs)
```

前端静态资源：`lumen-ui-topic`、`lumen-ui-topic-mobile` 独立 Deployment（云环境端口/域名 **TBD**）。

#### 3.1.2 逻辑分层

前端 → Java REST → Python `/internal/*`（不可越层）；图谱走 TRSGraph/Nebula 协议，Java 不写算法。

#### 3.1.3 基础设施版本（infra）

| 组件 | 云环境备注 |
|---|---|
| K8s / 容器化管理平台 | 版本以控制台为准 · **TBD 填版本号** |
| Harbor | `192.168.152.88:32001` |
| ES / Redis / Milvus / S3 | 见 §2.2.2 |

#### 3.1.4 应用框架版本

以各仓 `dev`/`tag` 发布说明为准：Vue3+Arco（前端）、PigX/Spring Cloud（Java）、Python 3.11 系（算法）。具体镜像 digest 发布时回填。

#### 3.1.6 网络与安全原则

- 云环境与现网网络隔离；管理面优先内网 / VPN
- 密钥进 Secret / 容器化管理平台凭据，不进镜像与 git
- 公网仅暴露必要入口（绑定 `111.198.38.90` 的映射 · **TBD 清单**）

### 3.2 部署流程

#### 3.2.1 发布验证

1. 代码进入云环境侧 GitLab 代码库（或经审批的镜像同步策略 · **TBD**）
2. **容器化管理平台**触发构建 → 推 Harbor 镜像仓库
3. 容器化管理平台/ Helm 发布到云环境 业务工作区
4. 健康检查 + 专题冒烟

#### 3.2.2 部署操作规范

- 禁止在云环境节点手搓 `docker run` 代替流水线
- 禁止用现网 GitLab Runner 打云环境镜像
- 变更留 tag / release note；双人确认高风险配置（Nacos、密钥）

### 3.3 运行服务清单（专题相关 · 草稿）

| 服务 / 工作负载 | 仓 | 备注 |
|---|---|---|
| `gkxlumen-gateway` | lumen-svc-platform | 入口 |
| `gkxlumen-topic` 及 enterprise/chain/policy/async 等 | lumen-svc-platform | 聚合核心 |
| `gkxlumen-metrics` | lumen-svc-platform | 指标 |
| `lumen-ui-topic` / topic-mobile | 对应前端仓 | 静态站 |
| `lumen-platform-algo-py` 等 | lumen-algo-py | 按专题依赖子集 |
| `lumen-etl-es-py` | lumen-etl-es-py | 按需 |

完整副本数 / HPA：**TBD** 内测上线前填。

### 3.4 工程模块与镜像（构建侧）

镜像仓库前缀：`192.168.152.88:32001/<业务组>/...`（示例）。构建定义在**容器化管理平台**流水线，不在 gitlab-runner。

### 3.5 发布策略

#### 3.5.1 部署顺序（建议）

1. 中间件就绪（Redis / ES / MySQL ADS / S3 / 可观测）
2. 配置与 Secret
3. Python 算法依赖
4. Java 网关与 topic/metrics/async
5. 前端
6. 冒烟与总集抽检

#### 3.5.2 版本与变更

云环境以**不可变 tag / digest**为准；`latest` 仅允许在联调环境。变更单关联 task-id。

### 3.6 结果验证

| 阶段 | 内容 |
|---|---|
| 基础设施 | Pod Ready、探针、证书 |
| 接口 | 网关健康、专题主 API 抽样 |
| 前端 | 登录/入口、五维各 1 条主路径 |
| 数据 | 关键指标非空或诚实空态；无串现网库 |

### 3.7 回滚策略

- 应用：回滚至上一 Harbor digest + 容器化管理平台历史版本
- 配置：Nacos 历史版本（按 dataId，禁整批误覆盖）
- 数据：内测上线窗口禁止不可逆 DDL；必要备份提前完成

## 4. 风险防控与应急预案

### 4.1 常见风险

| 风险 | 应对 |
|---|---|
| 误连现网集群/库 | 发布前核对 kubeconfig 与 JDBC/ES endpoint；清单双签 |
| CI 仍走 gitlab-runner | 流水线门禁：云环境仅容器化管理平台；文档与培训强调 |
| 对象存储桶未建 / 权限不足 | 内测上线前桶探测；失败阻断发布 |
| 密钥进仓 | Code review + pre-commit；Secret 轮换 |

### 4.2 应急响应

发现云环境故障 → 止血（回滚/切流）→ 定位（Grafana/日志/trace）→ 复盘写入 handoff。应急小组：运维 + 后端 + 前端值班 · 名单 **TBD**。
