## 4. 部署前准备

### 4.1 容器平台准备

1. 登录灵雀云业务工作区：`…/zhipu~region-gkx~zhipu-tts/overview`
2. 确认命名空间/项目与现网集群**不是**同一 API Server
3. 配置镜像拉取密钥指向生产 Harbor `zp-tts`
4. 账号：见飞书凭证表（示例用户名 `zp-mice`，**口令不写本文**）

### 4.2 中间件镜像 / 实例准备

- 确认 Redis / ES / MySQL / S3 / Milvus 连通（从生产集群内测）
- 桶 `gkx-lumen` 及 D14 目录已建；`milvus` 桶业务只读/禁用写

### 4.3 源码与 GitLab（生产侧）

- 生产 GitLab：`http://192.168.152.88:30010/zp-tts`（VPN：`183.62.232.62:30010`）
- 与现网 `aminer-edu-gitlab…/gkx-lumen` **分离**；同步策略（mirror / 发版打 tag）**TBD**
- 人员账号走生产 GitLab 自有账号体系（飞书表列有多人账号 · **口令不入库**）

### 4.4 业务镜像准备（灵雀云 CI）

1. 打开灵雀云 Pipeline：`…/zhipu-devops-busy/pipeline/pipelines`
2. 为专题相关仓配置流水线（前端 `lumen-ui-topic`、Java `lumen-svc-platform` 专题模块、依赖 Python）
3. 产物推送：`192.168.152.88:32001/zp-tts/<image>:<tag>`
4. **检查点**：流水线执行器显示为灵雀云构建节点；若仍绑定 gitlab-runner → **阻断发布**

## 6. 业务组件部署（专题）

建议顺序：

1. **密钥 / 配置**：生产 Nacos dataId、K8s Secret（LLM、OSS、DB、SSO 等）— 遵循 Nacos 变更规约，**禁** `FORCE_NACOS_REPUBLISH` 误伤
2. **算法依赖**：确认专题调用的 Python Deployment Ready（详见算法库手册）
3. **后端**：gateway → metrics → topic 及 enterprise/chain/policy/async
4. **前端**：topic PC / mobile；配置生产 API 基址（勿指向现网 `10.50.69.111`）
5. **Service / Ingress**：按生产端口规划暴露
6. **数据初始化**：字典、权限、专题演示样本（按合规演示用例）

每步保留：镜像 digest、流水线 run URL、操作人、时间。

## 8. 常见部署问题（草稿）

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 拉取镜像失败 | 仍指向 `harbor.test.com` | 改生产 Harbor 与 pull secret |
| 前端白屏 / SSO | 生产 `systemCode` / Nacos sso 块缺失 | 按 Nacos 规约单 dataId 修复 |
| 接口连到现网 | 配置未切环境 | 全量检索 `10.50.69`、aminer GitLab 域名 |
| Pipeline 在 runner 虚机执行 | 误用 gitlab-runner | 改绑灵雀云；更新本手册检查点 |
| ES 磁盘 | 500G 数据盘未挂 | 找基础设施补挂载 |
