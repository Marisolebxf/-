## 1. 文档目的

说明专题算法库在云环境侧的构建、镜像、中间件接入与发布步骤，供运维/算法执行与总集查阅。

## 2. 名词解释

| 名词 | 含义 |
|---|---|
| 算法库 | `lumen-algo-py` 等正式 Python 服务，仅 `/internal/*` |
| 容器化管理平台 | 云环境唯一 CI/CD |
| Harbor 镜像仓库 | 算法镜像落地项目 |
| 现网 | `10.50.69.111` + aminer GitLab CI · 仅对照 |

## 3. 环境说明

### 3.1 部署架构

Java → Python `/internal/*` → ADS / ES / Milvus / S3 / TRSGraph。详见《专题算法库·内测上线部署方案》。

### 3.2 服务器资源

与专题方案共用云环境池：容器化管理平台 业务工作区、ES 三台、Milvus、GDF 虚机、`192.168.202.172`（**仅 GDF PG**）。算法库额外关注：worker 并发、向量磁盘、LLM 配额。

### 3.3 中间件

| 组件 | 云环境接入 |
|---|---|
| Milvus | `milvus-proxy.infra.svc.cluster.local:19530` · 控制台 `192.168.202.164:30301` |
| ES | `192.168.202.139`–`141` |
| 对象存储 | `http://obs.cc.cs` · 分析结果目录；禁写 `milvus` 桶 |
| Redis | 按模块需要（缓存/队列）· **TBD** |
| LLM | K8s Secret · 不进镜像 |

### 3.4 端口

集群内 Service 端口以 Helm/清单为准；对外一般**不**直接暴露算法端口（只经 Java）。运维调试入口 **TBD**。

## 4. 部署前准备

### 4.1 容器平台

登录容器化管理平台 业务工作区；确认与现网 API Server 隔离；配置 Harbor pull secret。

### 4.2 中间件

- Milvus 账号连通（凭证见飞书表 · 不入库）
- ES index 模板/权限与专题检索约定一致
- S3 可写 `gkx-analysis-results`（及模块需要的目录）

### 4.3 源码

云环境 GitLab 代码库 组下算法仓；或审批后的镜像晋升流程 **TBD**。

### 4.4 业务镜像

1. Pipeline 工作区：`…/devops` → pipelines  
2. 构建 `lumen-algo-py`（api/worker 及开通子制品）  
3. 推送 `192.168.152.88:32001/<业务组>/<name>:<tag>`  
4. **验收**：构建日志宿主 ≠ gitlab-runner 业务 CI

## 6. 业务组件部署

1. 创建/更新 Secret（LLM、DB、OSS、Milvus）  
2. 部署 api Deployment + Service  
3. 部署 worker（若异步）  
4. 按需 innov/entan/etl  
5. Java 配置指向云环境 Service DNS  
6. 冒烟：经专题前端或 Java 触发一条真实调用  
7. （可选）部署 `lumen-ui-algo-apiview` 供算法验收  

**不要**部署 demo-algo-* 供 lumen 调用（D12）。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| Java 仍打现网算法 | 查 Feign/`python-base-url`、环境变量 |
| 503 / 超时 | worker 扩容、LLM 限流、查 trace |
| Milvus 鉴权失败 | 换云环境账号；禁把现网密码拷进云环境 Secret 文档 |
| 流水线走 runner 虚机 | 改容器化管理平台；更新检查表 |
