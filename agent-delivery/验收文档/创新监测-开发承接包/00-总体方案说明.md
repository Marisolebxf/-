## 1. 业务范围（五个功能模块）

| 模块 | 需规功能 | 交付形态 |
|---|---|---|
| M1 科创事件 | GIS 落点/热力图/时间筛选/重要性分级/详情关联 | `ads.innovation_event` + 事件 API + 地图页 |
| M2 创新点落图与赋分 | 创新点映射图谱节点、实体影响分与排名 | 图谱 + `ads.node_influence` + 图谱 API + 落图页 |
| M3 创新载体排行 | 创新能力指数、总体/领域/地区排行、趋势 | `ads.carrier_index` + 排行 API + 排行页 |
| M4 城市创新能力 | 城市排名、对标、要素分析、政策建议 | `ads.city_index` + 评估 API + 对标页 |
| M5 创新影响预测 | 贡献度、趋势预测（含置信区间）、突变检测 | `ads.impact_prediction` 等 + 预测 API + 趋势页 |

## 2. 总体架构与职责边界

```
┌─ 前端仓 ───────────────────────────────────────────┐
│  GIS地图 · 排行榜 · 对标雷达 · 趋势曲线 · 订阅管理      │
└──────────────── 只调 Java REST API ────────────────┘
┌─ Java 仓 ──────────────────────────────────────────┐
│  REST API（只读 ADS 表） + 用户态（订阅/推送/导出）      │
│  不做任何算法计算                                      │
└──────────────── 只读 ADS / 读写用户库 ───────────────┘
┌─ Python 仓 ────────────────────────────────────────┐
│  ODS抽取清洗 → 机构ID贯通 → 事件流水线 → 图谱构建/赋分    │
│  → 指数计算 → 预测；批处理产出，全部写 DWD/DWM/ADS       │
│  不对外提供业务 API（仅暴露内部模型推理服务）             │
└──────────────── 读 ODS（只读）/ 写自建库 ─────────────┘
        ODS 贴源层 = 三方要素库 186 张表（只读，不改造）
```

**铁律**：
1. ADS 表结构（01 文档）是三仓唯一契约面，任何变更走评审，Python/Java 双方会签；
2. Java 不写 ADS（用户态数据存独立 schema `app_user`）；前端不直连数据库；
3. 所有算法产出带 `model_version` + `confidence`，支持 A/B 双引擎回归对比。

## 3. 双轨算法策略（算力适配）

| | 方案 A（算力充足） | 方案 B（算力受限，默认起步） |
|---|---|---|
| 资讯 NLP | 私有化 GLM 一体化抽取 | BERT 分类 + UIE 抽取 + LightGBM 分级 |
| 大模型用途 | 在线全量加工 | 离线蒸馏标注 / 低置信复核 / 月度报告（API） |
| 硬件 | 4–8 卡推理 | 1–2 张 T4/4090 |

工程上通过统一引擎接口 `classify / extract / link / generate` 插拔（见 02 文档 §3），**双轨切换不影响 ADS 表结构与 API**。指标/图算法/预测层与算力无关，两方案完全一致。

关键事实（来自数据缺口分析）：**约 70% 事件类型可由 ODS 结构化表规则直转**，NLP 仅覆盖资讯类——事件底盘不受算力路线影响，可最先上线。

## 4. 阶段计划（与 06-WBS 对应）

| 阶段 | 周期建议 | 内容 | 出口标准 |
|---|---|---|---|
| S1 | 2 周 | 三仓脚手架就绪；01 表结构建库；机构ID贯通流水线 V1；维表（城市/区划）落库；向数据供方发缺口需求函 | ADS 建库完成，Mock API 可联调 |
| S2 | 3 周 | 结构化事件直转 7 类上线；事件 API + 地图页联调 | 事件地图端到端可演示 |
| S3 | 3 周 | 资讯 NLP 流水线（方案 B 起步）；重要性分级；订阅推送 | 全事件类型上线，分级达验收线 |
| S4 | 4 周 | 图谱构建+赋分；载体/城市指数 V1；排行/对标页 | M2/M3/M4 端到端 |
| S5 | 3 周 | 预测与突变检测；报告生成；性能与算力档位切换演练 | 全模块验收 |

## 5. 风险与决策记录

| # | 风险/决策 | 处置 |
|---|---|---|
| 1 | 数据缺口 G-1~G-25（详见缺口清单文档） | 全部降级方案做成**配置开关**（01 文档 `gkx_cfg.degrade_switch` 表），补数后切换不改代码 |
| 2 | 算力到位时间不确定 | 默认按方案 B 开发，引擎接口预留 A；S5 安排切换演练 |
| 3 | 亿级图谱平台接口未定（G-11） | 自建领域层先行，预留 `domain_source` 字段标记来源 |
| 4 | 全球城市数据不可得（G-19/20） | 一期榜单范围=国内城市+标杆城市人工补录包 |
| 5 | ODS 回溯年限未确认（G-25） | S1 必须拿到供方答复，决定 M5 出"趋势预测"还是"动量分析" |
