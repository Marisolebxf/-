# 02 · 算法实现说明（Python 仓）

> **读者**：Python 算法/数据工程团队
> **职责**：ODS 只读抽取 → 加工 → 写入 `innov_dim/dwd/dwm/ads/cfg`（表结构见 01 文档）。不对外提供业务 API。
> **双轨策略**：默认按方案 B（BERT 主导）开发，所有 NLP 能力经统一引擎接口实现，方案 A（大模型）为同接口的另一实现，后期切换只改配置。

## 2. 流水线规格（输入→步骤→输出）

### P1 机构ID贯通（master_data，S1 最先交付）

| 项 | 内容 |
|---|---|
| 输入 | ODS：`dwd_org_reg_info`、`dwd_company_base`+`dwd_company_history_name`、`dwd_forg_base_info`、`dwd_org_hels_info` |
| 步骤 | ①信用代码精确合并 → ②名称归一规则（去括号/全半角/公司后缀）→ ③embedding(bge-small) 相似度聚类 → ④低置信(<0.85)样本送 LLM API 批量裁决/人工队列 |
| 输出 | `dim_org_master`、`dim_org_alias` |
| 增量 | 日批，按 ODS updated_time 增量 |
| 验收 | 抽样 1000 对合并结果，准确率 ≥98% |

### P2 结构化事件直转（event/rule_converters，S2）

每个 converter 一个类，注册到统一 registry。共 7 类直转源（融资/投资/并购/政策/项目/工商变更与荣誉/招投标），字段映射严格按《数据缺口清单》文档第二章表格执行。统一处理：

- 时间缺失 → 读 `cfg_degrade_switch`（如 `ma_event_time=updated_time`），写 `time_quality`；
- 主体 → `dim_org_master` 反查地理坐标；
- 输出 `dwd_event_std`（produce_mode='rule'）。

### P3 资讯 NLP 流水线（event/nlp_pipeline，S3）

```
ODS资讯表 → 去重(SimHash+向量) → engine.classify(事件类型,9类)
→ engine.extract(按 event_schema 抽槽位) → NER+实体链接(orgs/persons)
→ 地理编码 → 组装 dwd_event_std (produce_mode='nlp', confidence)
→ confidence<0.7 → 复核队列(engine_llm 二判, 结果回流训练集)
```

输入表：`dwd_org_important_news_info`、`dwd_industry_chain_news_info`、`dwd_information`、`dwd_liang_zi_yan_fa_jin_zhan`；G-7 全球资讯流到位后新增 connector 即可。

### P4 重要性分级（event/importance，S3）

- 特征：主体影响分（P6 输出）、source_count（热度降级特征，开关 `heat_source`）、来源权威度、事件类型先验（`dim_event_type.importance_prior`）、金额对数；
- 模型：LightGBM 回归 → 分位数标定三级（Top10%/40%）；输出 `importance_score/level/detail`（分项贡献写 JSON，保证可解释）；
- 调度：日批全量重算近 90 天事件（热度滑窗），写 `ads_innovation_event`。

### P5 图谱构建与落图（graph，S4）

- 节点/边来源映射见《数据缺口清单》第三章表格；图库运行时主存 + `dwm_graph_node/edge` 快照；
- 落图（实体链接）：候选召回（别名表+向量）→ 排序（bert_engine: cross-encoder / llm_engine: 上下文裁决）→ `ads_innovation_point_map`；
- 领域层：`dim_tech_domain` 由产业链表 + IPC 前缀映射 + 学科代码初始化（脚本 `scripts/init_tech_domain.py`），G-11 图谱平台接入后 domain_source 增加 'kgp'。

### P6 实体赋分（graph/scoring，S4）

```
influence = α·PersonalizedPageRank(重启源=近90天创新点节点)
          + β·度中心性 + γ·中介中心性(近似算法,大图采样)
          + δ·成果产出分(时间衰减 half-life=2年)
```
按 domain 子图分别计算，月度快照写 `ads_node_influence`（score_detail 必填）。初始分利用现成字段：`dwd_scholar.h_index/citation_nums`、`dwd_patent_cited.cited_by_nums`。

### P7 指数计算（index，S4）

- 先产 `dwm_org_achievement_year`（论文按 cover_year_start、专利按申请年聚合——**不要用** `dwd_org_rd_achiev_info` 做趋势，它是无年度的累计快照）；
- 载体：经 `dim_carrier_org_rel.attribution_coef` 折算聚合 → 归一化（min-max+log）→ AHP×熵权合成 → `ads_carrier_index`；
- 城市：四子指数（resource/institution/output/environment）取数按缺口清单第五章矩阵 → `ads_city_index`；范围由开关 `city_scope` 控制（domestic_only / with_benchmark）；
- 权重文件入 `cfg_index_weight`，**代码不得硬编码权重**。

### P8 预测与突变（forecast，S5）

- 领域趋势：年度序列（≥8 年用 Prophet 出置信区间；不足走"动量分析"分支，由开关 `forecast_mode` 控制，对应缺口 G-25）；
- 贡献度：创新点在领域子图上截断 PPR 传播占比，explain_path 记 Top3 路径；
- 突变：Kleinberg burst（关键词频次）+ BERTopic 主题聚类（bert 引擎用 small embedding，llm 引擎补主题命名）→ `ads_topic_burst`。

### P9 报告生成（report，S5）

模板引擎（Jinja2，短板规则→建议条目库）生成初稿 → `generate_mode='template'`；LLM 可用时走 RAG 润色 `generate_mode='llm'` → `ads_report(review_status=0)` 待人工审核。

## 3. 引擎抽象（双轨核心接口）

```python
class NlpEngine(ABC):
    def classify(self, text: str, taxonomy: str) -> ClassifyResult: ...      # label, confidence
    def extract(self, text: str, schema: dict) -> ExtractResult: ...         # slots, confidence
    def link(self, mention: str, context: str, candidates: list) -> LinkResult: ...
    def generate(self, context: dict, template_id: str) -> str: ...

# conf/settings.yaml:  engine: bert   # bert | llm | hybrid(低置信回退llm)
```

- `bert_engine`：classify=RoBERTa-wwm 微调；extract=UIE；link=bge-reranker；generate=Jinja2 模板；
- `llm_engine`：四个方法统一走 GLM（私有化 endpoint 或 API），prompt 与 JSON Schema 放 `conf/event_schema/`；
- `hybrid`：bert 为主，confidence 低于阈值的样本回退 llm（阈值入配置）。
- 所有结果写库时带 `model_version`（从 `cfg_model_registry` 取 active 版本）。

## 4. 调度 DAG（依赖关系）

```
日批:  P1机构贯通 ─→ P2直转 ─→ P4重要性(近90天) ─→ ads事件
              └────→ P3资讯NLP ──┘
月批:  P5图谱重建 ─→ P6赋分 ─→ P7指数 ─→ P8预测/突变 ─→ P9报告
小时批: P3 增量(新资讯) → P4 增量
```
失败重试 3 次；每个任务写运行水位表（last_watermark）支持断点续跑。
