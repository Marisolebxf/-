## 4. `repos/demo-ui-system-test` 本批实际改了什么

本批只改前端指标证据展示，没有新增或修改 `demo-ui-system-test` 中的 Python 算法脚本。

实际变更文件：

```text
src/views/components/metricReadinessEvidence.ts
```

主要改动结果：

1. `src/views/components/metricReadinessEvidence.ts` 集中补充了 SVC 域全部 29 个指标的 D1/D2/D3/D4 就绪度和综合阻塞说明。
2. 每个指标条目包含：`metric_id`、`metric_name`、`domain`、`d1_def_status`、`d2_schema_status`、`d3_source_mapping`、`d4_ingestion`、`summary`（综合阻塞说明）、`blocking_points`（具体阻塞点数组）。
3. D1 missing 的指标（如 `M_SVC_ORG_MARKET_HEAT`、`M_SVC_CHAIN_BOTTLENECK`、`M_SVC_GRAPH_INFLUENCE`）以 missing_def 状态呈现，summary 明确标注"王惠尚未定义口径"。
4. 所有有数据库支撑的指标都写清了具体表名、行数、字段名和非空率。

需要重点向 `demo-ui-topic` 迁移的 UI 证据要点是：

- 指标是否被王惠定义口径；
- 指标是否被王惠定义计算过程；
- 数据库表是否存在、表是否有数据、关键字段是否非空；
- 哪些字段已映射、哪些字段未映射；
- 当前页面读的是 mock/预计算还是真实表；
- 每个 `partial` 状态具体支持哪部分、不支持哪部分。

## 5. 算法脚本与 API 的真实位置

`demo-ui-system-test` 只是 UI 仓库，算法脚本不在该仓库内。产业服务链分析算法的实际位置：

```text
repos/demo-algo-ent-analysis/（尚无 SVC 专属算法模块）
repos/lumen-algo-py/（公共算法库，尚无 SVC 专属算法模块）
```

本批没有新增或修改算法脚本。产业服务链分析的算法模块尚未独立开发，当前 UI 中展示的数据来源全部为 mock 数据或从已有 SVC 数据库表直接取数（如 `svc_org_circle`、`svc_org_card`、`svc_metric_fact` 等）。

API 服务入口：

```text
repos/demo-algo-ent-analysis/api/main.py
```

该入口当前已有企业分析（ENT）域的接口，但尚无 SVC 域的独立接口。后续如果需要为 SVC 域新增真实数据接口，应在 `api/main.py` 中新增 SVC 域路由组，并在 `repos/demo-algo-ent-analysis` 或 `repos/lumen-algo-py` 中开发对应算法模块。

## 10. SVC 算法 API 接口使用说明

> 本节为侯佳伟提供：`repos/lumen-algo-py` 中已实现的 29 个 SVC（产业服务链分析）指标计算 API 的完整使用文档。
> 所有接口已在 `lumen-algo-py` 项目中实现并通过 33 项测试（29 个指标端点 + health + shortboard + 通用路由 + 未知指标）。

### 10.1 服务架构概览

**服务框架**：FastAPI（Python 3.10+）
**服务入口**：`lumen_algo_service/main.py`，通过 `views/svcan.py` 注册 SVC 路由
**路由前缀**：`/internal/v1/svcan`
**统一响应包装**：`{code: 0, msg: null, data: {...}}`（`code=0` 为成功，非 0 为异常）
**数据库连接**：读取 `conf/settings.yaml` 中 `svcan` 配置段，连接 `demo_gkxlumenx_ads` 和 `demo_gkxlumenx_dwd`
**降级策略**：DB 可达时返回 `data_source="real"`（真实数据）；DB 不可达或表无数据时返回 `data_source="mock"`（mock 数据，源自 `demo-ui-topic` 的 `servicePortalData.ts`）
**CI/CD**：`.gitlab-ci.yml` 构建 Docker 镜像，部署到 k8s 集群

### 10.2 响应结构说明

每个指标计算接口返回统一结构：

```json
{
  "code": 0,
  "msg": null,
  "data": {
    "metric_id": "M_SVC_ORG_TOTAL",
    "value": 3525,
    "data_source": "real",
    "confidence": "high",
    "calc_process": {
      "formula": "SELECT value FROM svc_metric_fact WHERE metric_id=M_SVC_ORG_CNT",
      "source_tables": ["demo_gkxlumenx_ads.svc_metric_fact"],
      "model_version": "svcan-v1.0"
    }
  }
}
```

| 字段                                | 类型         | 说明                                                                                                                       |
| ----------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `code`                            | int          | 0=成功，非 0=异常                                                                                                          |
| `msg`                             | string/null  | 异常信息，成功时为 null                                                                                                    |
| `data.metric_id`                  | string       | 指标 ID（如`M_SVC_ORG_TOTAL`）                                                                                           |
| `data.value`                      | any          | 指标计算值（int、float、list、dict 等）                                                                                    |
| `data.data_source`                | string       | `"real"` = 真实数据库查询；`"mock"` = mock 数据降级；`"unknown"` = 未知指标                                          |
| `data.confidence`                 | string       | `"high"` = 高置信度（有真实数据）；`"medium"` = 中等（部分依赖真实数据）；`"low"` = 低（mock）；`"blocked"` = 阻塞 |
| `data.calc_process.formula`       | string       | 计算公式或 SQL 查询语句                                                                                                    |
| `data.calc_process.source_tables` | list[string] | 依赖的数据表清单                                                                                                           |
| `data.calc_process.model_version` | string       | 算法版本号（`svcan-v1.0` 为真实数据，`svcan-mock-v1.0` 为 mock）                                                       |

async function fetchMetric(metricId: string) {
  const res = await fetch(`${API_BASE}/metric/${metricId}`);
  const body = await res.json();
  if (body.code !== 0) throw new Error(body.msg);
  return body.data;  // { metric_id, value, data_source, confidence, calc_process }
}

async function fetchOrgTotal() {
  const res = await fetch(`${API_BASE}/org/total`);

  return body.data.value;  // 3525
}

// 判断数据源是否为真实数据
async function isRealData(metricId: string): Promise<boolean> {
  const data = await fetchMetric(metricId);
  return data.data_source === 'real';
}

### 10.5 降级策略说明

| 场景                              | 行为             | `data_source` | `confidence`             |
| --------------------------------- | ---------------- | --------------- | -------------------------- |
| DB 可达，表有数据                 | 查询真实数据返回 | `"real"`      | `"high"` 或 `"medium"` |
| DB 可达，表为空表（有结构无数据） | 降级返回 mock    | `"mock"`      | `"low"`                  |
| DB 不可达（网络/权限问题）        | 降级返回 mock    | `"mock"`      | `"low"` 或 `"blocked"` |
| 未知指标 ID                       | 返回空值         | `"unknown"`   | `"blocked"`              |
| 计算异常                          | 返回错误信息     | `"mock"`      | `"blocked"`              |

**设计要点**：每个 DB-backed 函数内部调用 `connect_svcan_readonly()` 尝试连接数据库；连接失败时 `db=None`，`_q()` 函数返回空列表，函数自动降级到 mock。这确保所有端点在任何环境下都能返回有效响应，不会因数据库不可达而 500。

### 10.7 迁移到 demo-ui-topic 的任务拆解

#### 任务 1：配置 API 网关代理

在 `demo-ui-topic` 的开发环境配置中，将 `/internal/v1/svcan/*` 路径代理到 `lumen-algo-py` 服务地址。
执行步骤：

1. 确认 `lumen-algo-py` 服务部署后的访问地址（内网 k8s Service 或公网 Ingress）。
2. 在 `demo-ui-topic` 的 vite/nginx 代理配置中添加 `/internal/v1/svcan` 转发规则。
3. 测试 `curl <demo-ui-topic-host>/internal/v1/svcan/health` 能返回 200。

#### 任务 2：替换前端 mock 数据为 API 调用

`demo-ui-topic` 现有 mock 数据在 `src/app/mock/service-center/servicePortalData.ts`。
执行步骤：

1. 逐个找到前端组件中使用 mock 数据的位置（搜索 `servicePortalData` 引用）。
2. 将有真实数据支撑的指标（如 `M_SVC_ORG_TOTAL` 可从 `svc_metric_fact` 取 3525、`M_SVC_PT_SZ_REGION_ORG` 可从 `svc_region_dist` 取各区数据）逐步替换为真实 API 调用。
3. 对无数据支撑的指标，保留 mock 值但明确标注"mock 阶段虚构数据，等待数据接入"。
4. `servicePortalData.ts` 中定义的 KPI `metricIds` 需确保全部在 29 个 SVC 指标清单中。

#### 任务 3：前端指标显示适配

每个 API 返回的 `value` 字段格式不同（int、list、dict），前端需要按指标类型适配渲染逻辑。
执行步骤：

1. 对照 10.3 节的接口清单，确认每个指标的 `value` 数据类型。
2. 数值型指标（如 `M_SVC_ORG_TOTAL` 返回 int 3525）直接显示。
3. 分布型指标（如 `M_SVC_PT_SZ_REGION_ORG` 返回 `[{name, count}]`）渲染为分布图/表格。
4. 评分型指标（如 `M_SVC_REC_ATTRACT_SCORE` 返回 dict）渲染为评分卡片。

#### 任务 4：数据源标注

前端需要根据 `data_source` 字段显示数据来源标识。
执行步骤：

1. `data_source === "real"` 时，显示"真实数据"标识（绿色）。
2. `data_source === "mock"` 时，显示"mock 数据"标识（橙色），附带提示"等待数据接入"。
3. 在指标详情面板展示 `calc_process.formula` 和 `calc_process.source_tables`，让用户了解计算过程。
