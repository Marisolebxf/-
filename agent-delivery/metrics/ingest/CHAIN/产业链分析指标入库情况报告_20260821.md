### 4.1 服务为什么能在 CICD 中启动

`repos/lumen-algo-py` 的 `.gitlab-ci.yml` 中：

```text
image:innov
  -> docker build -f docker/Dockerfile.innov .
  -> harbor 镜像：gkxlumen-innov-py

deploy:innov
  -> 热更新 Deployment: gkxlumen-platform-innov-py
```

`docker/Dockerfile.innov` 的启动入口：

```dockerfile
ENTRYPOINT ["opentelemetry-instrument"]
CMD ["uvicorn", "api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

即部署后 Kubernetes 监听 `8000` 端口，应用对象为 `vendor/innov-py/api.main:app`。`/healthz` 为 K8s 健康检查，`/internal/status` 可查看产业链灌数和表行数状态。

侯佳伟的 SVC 服务走的是同仓库另一个镜像：

```text
image:api -> docker/Dockerfile.api -> gkx-lumen-algo-py-api
deploy:api -> Deployment: lumen-platform-algo-py
启动对象：lumen_algo_service.main:app，路由前缀 /internal/v1/svcan
```

两者互不影响，可以独立部署。

### 4.2 请求统一约定

所有 `/v1/chain/**` 接口都返回统一包络：

```json
{
  "code": 0,
  "msg": null,
  "data": {}
}
```

其中 `code == 0` 表示正常。数据面由请求头控制：

```http
X-GKX-PLANE-CHAIN: demo
```

默认值为 `demo`；传 `live` 时进入正式库数据面。mock fallback 只作用于 demo 数据面，live 数据面永远不启用 mock，也不会把 mock 写回正式库。

兜底开关：

```text
CHAIN_DEMO_MOCK_FALLBACK=1     # 默认开启
CHAIN_DEMO_MOCK_FALLBACK=0     # 关闭，恢复原空值语义
```

建议李伟联调时不要关闭该开关。mock 语义沿用 `demo-ui-topic` 当前页面可展示的数据形状；当真实表缺数、查询为空或连接异常时，接口仍返回非空 `data`，避免前端因空数组或 `null` 崩页。

**数据库连接**：`vendor/innov-py/chainan/llm_ods/dbconn.py`，按数据面连接 demo/正式库
**降级策略**：demo 数据面真实结果为空或查询异常时自动降级到 mock；live 数据面永不降级
**CI/CD**：`.gitlab-ci.yml` 构建 `gkxlumen-innov-py` 镜像，部署到 `gkxlumen-platform-innov-py`

### 7.2 响应结构说明

每个接口返回统一结构：

```json
{
  "code": 0,
  "msg": null,
  "data": {}
}
```

`data` 的具体结构由接口决定：统计类接口返回 `list<dict>`，全景/周期/瓶颈等复合接口返回 `dict`，关键环节/区域指数/竞争力返回 `list<dict>`，深圳专题返回包含 `panorama`、`advantage`、`problem`、`opportunity` 的 `dict`。

### 7.5 降级策略说明

| 场景 | 行为 | 说明 |
|---|---|---|
| demo 表有数据 | 返回真实库结果 | 优先真实数据 |
| demo 表为空 | 返回 mock 可展示结果 | `data` 非空，避免前端崩页 |

| `X-GKX-PLANE-CHAIN: live` | 永远走正式库，不降级 | 不写正式库、不伪造结果 |
