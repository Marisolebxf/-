### 1. M_CHAIN_GLOBAL_REGION_COUNT（全球分布区域数）

**建议口径（改前→改后）**：
- 改前：老 DWD `industry_chain_enterprise` 总部国家计数，Mock ✅。
- 改后：**目标口径锁定 = 指定产业链的链上主体（企业+机构）总部所在国家/地区去重数**；计算链 `industry_chain`（或 industry_code 字典）→ 上链桥（`enterprise_industry_chain` 灌数后 / 过渡期 `dwd_org_industry_tags`）→ `dwd_org_base_info` 区域轴。**现网无 country 字段且海外名录 0 行 → 照 SVC GLOBAL 模式处置：格子先写国内可执行真数（现网=1，仅中国），UI 强制「目前只有国内数据，全球待接入」提醒 + ⚠️ 挂 Q-SVCCHAIN-07**；不造海外区域假数、不把港澳台单独拆档。

```sql
-- 过渡期可执行版（国内真数；全球档挂 Q-SVCCHAIN-07）
SELECT COUNT(DISTINCT b.province) AS national_region_cnt   -- 主档无 country，先以 province 代理国家粒度（现网全=中国 → 计 1）
FROM demo_gkxlumenx_dwd.enterprise_industry_chain e        -- 灌数后启用；现 0 行 → 真数 0，UI 如实呈现

-- 过渡桥：e 换 dwd_org_industry_tags t（t.industry_code=:code）JOIN b ON b.external_id=t.credit_code
```

**风险点与待拍**：① 语义二选一（见三兄弟共同判定）：**建议 A「某链的链上主体覆盖区域数」**（链维 KPI，随链切换）——与 NATIONAL/SZ 同族自洽，且 SVC 先例同构；B「有链企业的区域数」（区域轴优先）需另建区域×链交叉口径，不建议本轮锁；② country 粒度字段缺失，需供方补列或长期以 province 代理——**待拍**；③ 上链桥 0 行/104 行两档都不可发表，D3 建议 `none`（桥）+ 全球档挂 Q-SVCCHAIN-07；④ D1 建议 `draft`（语义建议 A 待拍后升 aligned）、D4 建议 `mock`。

### 3. M_CHAIN_SZ_REGION_COUNT（深圳产业分布区域数）

**现稿画像**（seed L207-214）：definition=「深圳下辖区/县去重数」；formula=`COUNT(DISTINCT headquarters_district) WHERE headquarters_city='深圳'`；source_tables 挂 `dwd_company_location_tags`（未在现网清单确认）；calc-logic 旧版指向 `gkxlumenx_ads.chain_sz_dist`（48 行，老 mock ADS，F9）。v0.1.0 / Mock ✅ / NO-MX。

- 改后：**对齐 M_SVC_PT_SZ_REGION_ORG v0.2.1 先例——不再做裸计数**：区轴=标准十区字典（福田/罗湖/南山/盐田/宝安/龙岗/龙华/坪山/光明/大鹏新区）全集常显、无值区显 0；空 area 单列「未分配」桶常显；主档 `dwd_org_base_info.area` 为唯一区级真源。本指标取值=**有链上主体的非零区数**（或十区全覆盖恒 10——两种读法见待拍②）。

```sql

SELECT d.area_name, COUNT(DISTINCT b.org_id) AS org_cnt
FROM dim_sz_10districts d                                   -- 十区字典（复用 SVC 同一字典，勿另造）
LEFT JOIN (
  SELECT b.org_id, COALESCE(NULLIF(b.area,''),'未分配') AS area_name
  FROM demo_gkxlumenx_dwd.enterprise_industry_chain e       -- 过渡桥：dwd_org_industry_tags

) b ON b.area_name = d.area_name
GROUP BY d.area_name;
-- 指标值 = org_cnt>0 的区数（读法A）或含未分配桶口径见待拍
```

**风险点与待拍**：① 区级字段唯一真源=主档 area（老 source 的 location_tags 弃用）——**待拍确认**；② 指标语义两读：A=「链上主体覆盖的非零区数」（真 KPI，随链变）/ B=「深圳恒 10」（十区字典全集常显，KPI 无信息量）——**建议 A，B 作 UI 常识层不带指标卡**；③ 桥空 → D3 `none` + D1 `draft` + D4 `mock`；④ NO-MX 建议补行。

### 7. M_CHAIN_REG_POLICY_COVERAGE（政策覆盖率）

- **建议口径（改前→改后）**：
  - 改前：pending_ods + 「映射表待建」。
  - 改后：**对齐 REG_COMP_SUPPORT：指定区域内、指定产业链相关政策命中的链环节数 / 该链全部环节数**（政策区域=policy_base.city；环节命中=title/keywords/keypoints/theme 文本匹配 industry_link_name，匹配规则沿用兄弟条目；status 有效态）。

```sql
-- 分子：命中环节数（文本匹配，规则同 REG_COMP_SUPPORT）
SELECT COUNT(DISTINCT hit.link_code) AS covered_links,
       (SELECT COUNT(DISTINCT link_code) FROM demo_gkxlumenx_ods.dwd_industry_chain_info WHERE industry_code=:chain_code) AS total_links
FROM (
  SELECT l.industry_link_code AS link_code
  FROM demo_gkxlumenx_ods.dwd_industry_chain_info l
  JOIN demo_gkxlumenx_ods.dwd_policy_base pb
    ON pb.city = :region_city AND pb.status='有效'
   AND (pb.title LIKE CONCAT('%',l.industry_link_name,'%')
     OR pb.keywords LIKE CONCAT('%',l.industry_link_name,'%')
     OR pb.keypoints LIKE CONCAT('%',l.industry_link_name,'%')
     OR pb.theme    LIKE CONCAT('%',l.industry_link_name,'%'))
  WHERE l.industry_code = :chain_code
) hit;
-- 覆盖率 = covered_links / total_links
```

- **风险点与待拍**：① `dwd_policy_base` demo 存在性两处矛盾（ENT 缺失 vs 兄弟条目引用）——**必须先核，核前 D3 不得离开 pending_ods**；② 文本匹配召回/精度无量化——沿用先例但需 demo 实测回填匹配率；③ 分母 L0=43 vs L1=28 环节深度（F5）——**待拍**；④ 「覆盖率」输出比例还是分档（如 ≥60% 高覆盖）——建议纯比例，分档交 UI，**待拍**。

### 9. M_CHAIN_REG_REVENUE（营收）

### 11. M_CHAIN_REG_TALENT_STRUCTURE（人才结构）

- **现稿画像**（seed L1454-1470，TOPIC-REG-017）：T0-X 占位；旧 calc-logic：「未发现人才结构表，分档加权待建」。矩阵 D3=pending_ods。

- **建议口径（改前→改后）**：
  - 改前：pending_ods + 「人才结构分档加权」无源稿。
  - 改后：**两案**：**建议 A（可执行、先例多）：区域+链上企业研发人员占比**=SUM(最新年 development_employee)/SUM(同年 employees_number)，输出比例（结构分档交 UI，不做分档加权模型）；B（学者口径）：链上高校/院所学者去重人数。A 数据面宽、B 与学术生态重复——**建议 A 为主，B 并入 PAPERS/RESEARCH_ORG 册页，待拍**。

```sql

       SUM(CASE WHEN f.year=latest.y THEN f.employees_number     END) AS total_headcount,
       ROUND(SUM(f.development_employee)/NULLIF(SUM(f.employees_number),0),4) AS rd_ratio

JOIN (SELECT org_id, MAX(year) y FROM demo_gkxlumenx_ods.dwd_org_annual_financial_info GROUP BY org_id) latest ON latest.org_id=f.org_id AND latest.y=f.year
```
