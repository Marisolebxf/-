### 0.3 本指标套用（一句话）

封面号的第一条纪律是「不出数」：它登记的是「服务机构基础指标模型」这一族指标的构建任务，本身不是可展示的数值。因此若按「有没有对应结果面」去判档，会得到「完全不支持」这种看似严谨、实则答错问题的结论。本件的做法是把封面号展开成它登记的六大体系，逐个体系判「今天能不能算出数」，再按体系聚合出档位。

## 摘要

「服务机构基础指标模型构建」是产业服务链分析的底座：它不直接产出某个可展示数值，而是登记了六个体系（产业布局、全球分布、投融资资讯、新增动态、深圳规模、深圳分布），后续所有 SVC 指标都从这六个体系取数。旧稿按演示库口径给过一版体系盘点（圈定池 43,296 家、六类分桶、境外表 0 行），但演示库的圈定池是人工圈选名单，换源后必须重新回答「谁来当分母」。

本件在 gkx 上重建口径：以 45,011 行经营范围记录去重得到 44,153 家机构作为池（可回查率为 99.95%，即 44,153 家中能与底册 189,116 行对上的比例），六类服务桶按词表多命中（一家可同时命中多类，主类按 INNOV > IP > FINANCE > HR > MKT > CONSULT 归并）。成立年序列覆盖 64 个年份，投融资事件 25,654 件、池内 5,910 家，深圳机构 25,597 家（占池 57.97%%），区分布非空 25,587 家。

档位落在 **部分支持**：四体系可现转，全球分布体系的海外/港澳台轴在 gkx 境外表里只有 GB/US/CA 三个国别值、country 列 100% 为空，无法支撑「全球」语义；深圳规模体系的「服务能力」在库内没有任何量化字段。两处缺口都写进 §四 并给了修复路径，未以「体系多」为由抬档。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是科技专题服务系统的产业服务链分析底座。需求把服务机构的「面」拆成六个体系：全球服务机构产业布局、全球服务机构分布、投融资动态资讯、新增服务机构动态、深圳服务机构规模、深圳服务机构分布。六个体系各自有展示形态（分布图、时序图、规模档、区域热力），但它们共用一个机构域，这个域就是本封面号要定义的底座。

因此本件的产出形态与其他九件不同：不是一个数值，而是一张「体系 × 支撑度」的矩阵，加上每个体系的可复算口径说明。下游指标要引用池规模、类型分布、成立年序列时，应引用本件产物而不是各自重算。

### 1.2 为什么需要这个指标

没有统一的机构域，十个 SVC 指标会各自圈池：链环节计数圈 44,153 家、技术力评价圈 3,211 家、关系链圈 12,905 家——分母不同，跨指标对比就会失真。封面号的价值在于把「谁是服务机构」这件事定一次，并把这六个体系的口径钉在同一份快照上。

这也解释了为什么它必须「不出数」：一旦封面号自己给一个「服务机构总数」的展示值，下游就会把它当权威分母，而不再检查池的定义是否适配自己的口径。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 封面号在需规里只有体系清单与展示要求，没有计算式；旧稿的体系拆解来自王惠调研稿，且其数据口径全部落在演示库（`demo_*`，主机 111.198.38.90，本件不再引用）。

本件把「方法」定义为：每个体系先找 gkx 里能承载它的表，再判该表能否支撑体系的语义；能支撑就写口径，不能支撑就写缺口，不用邻近字段硬凑。

### 1.4 指标口径与维度拆解

六体系与本件的字段映射：产业布局 → `dwd_org_org_product_info.main_activities` 的六类词表；全球分布 → 底册 `province/city` + `dwd_forg_base_info`；投融资 → `dwd_org_financing_info`；新增 → 底册 `incorporation_year`；深圳规模 → `city='深圳市'` × `registered_capital` × 规模档（`size`）；深圳分布 → 底册 `area`。

每一体系都在 §2 给出「分子/分母/缺失处理」，并在产物里保留原始计数字段，便于甲方按自己的口径重算。

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 池/机构域 | `dwd_org_org_product_info.org_id` | 按 org_id 去重，不做行数计数 |
| 行业/类型 | `main_activities` 词表 | 未命中归 UNCLASSIFIED，不丢弃 |
| 财务截面 | `dwd_org_annual_financial_info` 最近有值年 | 缺年不补 0，取最近有值年 |
| 风险事件 | `dwd_org_risk_shixin` / `dwd_org_company_punish` | 无记录记 0 件（事件型字段，0 是真实语义） |
| 资讯量 | `dwd_org_important_news_info` 标题条数 | 无资讯记 0，仅作代理 |
| 资本关系 | `dwd_org_invest_info` / `dwd_org_shareholder_info` | 对端解析不了的行丢弃并计数 |

### 1.5 与同域姊妹指标的分工

与 `M_SVC_CHAIN_SEGMENT_ORG_COUNT`（环节机构数）的分工：后者按六环节切池，回答「每个环节有多少供给」；本件按六类型切池，回答「服务机构整体长什么样」。两者共用同一份池快照（`svc21_facts_20261022.json`），所以环节计数之和（60,673 含重复）与本件的类型多命中计数（同一条机构可命中多类）可以互相校验。

与四件技术力模型（174—177）的分工：技术力模型各自圈定单一类型子池（FINANCE 3,211 / IP 108 / HR 582 / MKT 1,146），子池之和小于本件池规模，差额是主类为 INNOV 与 UNCLASSIFIED 的机构——这不是矛盾，而是「主类归并」的必然结果。

### 1.6 本件的边界与不做什么

本件不做三件事：不产出封面单值（避免被当权威分母）、不建 ADS 结果表（封面号三禁）、不把「体系可算」等同于「指标已达标」（体系可算只说明有数，阈值与展示口径另议）。

另外，本件不引用旧稿的演示库结果面（三张 ADS 表 0 行的自证），因为那证明的是「演示库里没有」，与 gkx 是否有源无关；换源后应重新回答「源侧有没有这张结果表」，答案同样是没有，但理由不同。

## 二、计算过程

### 2.1 数据源与快照

全部数字来自 `code/_snapshots21/svc21_facts_20261022.json` 与 `base_20261021.json`，均为 gkx 只读快照；快照的 `source` 字段记录库名、主机与拉取时间。脚本不连库，单次运行在 2 秒内完成。

| 快照 | 承载内容 | 行数 |
|---|---|---|
| `svc21_facts_20261022.json` | 池、六环节、类型、财务、风险、资讯、资本边、底册字段 | 44,153 机构 |
| `base_20261021.json` | org_id / 信用码 / 名称 / 省 / 市 / 成立年 | 189,116 行 |
| `svc21_kw_20261022.json` | 47 个单词在经营范围里的命中量 | 45,011 行口径 |

快照与库的对应关系写在 `sources` 里，任何一个数字都可以顺着「字段 → 快照键 → 源表」回查到 gkx 表名。

### 2.2 池的定义（分母）

池 = `gkx.dwd_org_org_product_info` 中 `is_deleted=0` 且 `main_activities` 非空的机构，按 `org_id` 去重。原始 45,011 行去重后 44,153 家，其中 99.95% 能在底册 189,116 行里找到同名主体。

这个定义有两个已知偏差：一是「经营范围里写了服务」不等于「主营是服务」（例如房地产公司写了「金融咨询」也会入池）；二是经营范围文本长短差异极大（中位 213 字），文本越长命中越多。两处偏差都写进 §四，未做加权修正——因为任何加权都会引入新的不可复核参数。

### 2.3 体系一：产业布局（六类桶）

六类词表：INNOV（研发/技术开发/检测/中试）、IP（专利/商标/知识产权）、FINANCE（融资/担保/基金/保理）、HR（人力资源/劳务派遣/招聘）、MKT（市场/广告/营销/品牌）、CONSULT（咨询/管理顾问）。一条机构可命中多类，产物同时给「多命中」与「主类」两列。

| 类型 | 多命中家数 | 主类家数 | 主类占池 |
|---|---:|---:|---:|
| 创新/技术服务 | 32,294 | 3,447 | 7.81% |
| 金融服务 | 10,177 | 9,812 | 22.22% |
| 咨询服务 | 35,343 | 12,579 | 28.49% |
| 市场营销服务 | 18,059 | 11,125 | 25.20% |
| 人力资源服务 | 4,686 | 2,734 | 6.19% |
| 知识产权服务 | 776 | 776 | 1.76% |
| 未分类 | 0 | 3,680 | 8.33% |

主类归并顺序 INNOV > IP > FINANCE > HR > MKT > CONSULT 是本件的工程选择：INNOV 是 umbrella 语义，若让它排最后，凡写过「技术咨询」的机构都会掉进 CONSULT，导致创新类失真。顺序改变会改变主类分布，故在主类列旁保留多命中列，供甲方按自己的优先级重算。

### 2.4 体系二：全球分布（国内轴 / 海外轴）

国内轴用底册省/市字段，覆盖 31 个省级区划；广东占绝对多数，这是「深圳项目、机构域以粤港澳为主」的直接结果，不是全国分布。产物同时给省轴与市轴 TOP10，避免只报「广东第一」这种无信息量的结论。

海外轴在 gkx 上不成立：`dwd_forg_base_info` 20,000 行里 `country_code` 只有 GB（19,832）、US（159）、CA（9）三值，`country` 列 100% 为空。这不是「海外机构少」，而是「这张表不是全球机构名录」——它更像某个单国别来源的导入残留。因此本体系判部分支持，海外/港澳台展示位应先留空而不是塞 GB 数据。

### 2.5 体系三：投融资动态资讯

事件明细 25,654 件，池内 5,910 家；时间分布峰值在 2016 年（3,704 件），2017 年后逐年回落——这与「融资事件减少」不能直接划等号，因为该表的采集截止时间与覆盖机构都在变。

金额列大面积缺失：能取到金额的事件占比很低，故本件只报「事件数」与「有金额事件数」，不出「融资总额」，避免用一个覆盖率不明的金额列去乘出总量。

### 2.6 体系四：新增服务机构动态

按底册成立年计数，覆盖 64 个年份。2018 年是峰值（1,969 家），此后逐年下降：2021 年 921、2022 年 483、2023 年 218、2024 年 66、2025 年 12。

这条曲线不能用来说明「新增机构在萎缩」。真实原因是底册的成立年登记滞后：越近的年份，越可能还没被采集入库。因此本件把 2023 年之后标为「登记不全」，只展示不断言；若要做真实的新增趋势，必须换成工商登记全量快照（见 §四 修复路径）。

### 2.7 体系五：深圳规模 / 体系六：深圳分布

深圳 25,597 家，占池 57.97%%；规模档分布：小型 22,750、中型 8,545、微型 6,632、未知 4,299、大型 1,906。注册资本非空 44,083 家（全池口径），深圳子池内非空率同样接近满格。

区分布非空 25,587 家，TOP3 是南山区 7,067、宝安区 5,350、龙岗区 3,342——与深圳科技服务业的实际集聚一致，可作为口径合理性的一次外部校验。

但「规模」在需求里包含「服务能力」，而 gkx 没有任何服务能力量化字段（无资质等级、无服务收入科目、无客户数）。本体系只能给「注册资本 + 规模档」这一半，服务能力子维记为缺口。

### 2.9 结果解读

六体系里最稳的是「深圳分布」与「新增动态」：字段单一、覆盖率高、口径无歧义。最不稳的是「全球分布」：表面上有一张 2 万行的境外表，实际只有三个国别值，任何「全球 TOP N」都会是伪结论。

对下游的直接影响：做「服务机构产业布局」看板时，六类桶可以直接上，但要在角标注明「多命中、可重复计数」；做「全球分布」时必须先隐藏海外轴，否则会展示出 99% 集中在英国的荒诞图。

计算链在本目录闭合：脚本只读 `code/_snapshots21/` 下的四份快照（机构池、底册、词表命中、专利代理样本），不连任何数据库，也不 import 本目录之外的模块。快照自身带 `source` 字段（库名 gkx、主机、拉取时间），因此「文档 → 产物 → 脚本 → 快照 → 源表」这条链上每一跳都能单独打开核对，不存在只在某台机器上偶发能跑通的环节。

### 3.2 字段级核验

字段级核验做了三件事：一是 `SUM(col IS NOT NULL)` 自检，确认规模档、区、注册资本三列不是空壳（规模档非空 25,597/25,597、区非空 25,587/25,597、注册资本非空 44,083/44,132）；二是对 `dwd_forg_base_info` 做值域分布，发现国别只有三值；三是对成立年做尾部检查，发现 2024/2025 骤降。

三件事都不是「跑一条 SQL 看有没有数」，而是「看数的形状对不对」。空壳列与退化列在 SQL 层不会报错，只会安静地返回 0 或常数——这是本批十件共同的核验纪律。

### 3.3 口径陷阱与规避

| 陷阱 | 本件如何处理 |
|---|---|
| 整列为空（DATA_FACTS §3.10） | 先 `SUM(IS NOT NULL)` 自检，不用未自检的列做分母 |
| 不许接 `| tail`（§3.12） | 脚本直跑并保留退出码，失败即失败 |
| 基期分母（§3.16） | 成立年序列只对真实存在年份计数，不补 0；2026 单独标残年 |
| 专利年份（§3.13） | 本件不引用专利年份，避免 2021 前零行被当 0 |
| 重跑丢字段（§3.25） | 脚本自带 base_years 三字段；重跑用 `rebuild_metric.py` 复核 |

另有一条本件特有的陷阱：`dwd_org_org_product_info` 的一行不等于一家机构（45,011 行 / 44,153 家），若直接用行数当分母，会把 858 家重复计数，池规模虚高 1.9%。本件全程以 `org_id` 去重后再计数。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 全球分布-海外轴 | 全球/港澳台机构名录及国别字段 | 「全球分布」只能展示国内轴 | 采购或对接境外机构名录；或明确降级为「国内分布」并改展示名 |
| 深圳规模-服务能力 | 服务能力量化口径（资质等级/服务收入/客户数） | 规模体系只有资本与人数代理 | 与甲方确认服务能力定义，再决定用资质等级还是服务收入科目 |
| 投融资金额 | 事件金额的完整覆盖 | 不出融资总额，只报事件数 | 补金额字段来源，或标注「金额仅覆盖有值事件」后单独发布 |
| 新增动态近三年 | 工商登记全量快照 | 2023 年后成立年明显低估 | 接入市场监管全量登记库，按季度刷新 |
| 池的业务纯度 | 主营服务业务的判定字段 | 经营范围命中≠主营（地产/制造混入） | 引入行业代码主表与营收结构，做二次过滤 |

### 4.2 修复路径与优先级

优先级按「补齐成本 ÷ 解锁维度数」排：成本最低、能一次解锁多个维度缺口的排前面。本批十件的共同短板是「服务过程类数据」（合同、验收、评价、投诉）在 gkx 完全没有承载表，这类缺口不是换字段能解决的，必须等甲方开放业务系统或采购第三方评分。

短期（可在一周内做）优先补「已有表但没接」的部分：把 dwd_org_recruit_info 的 hiring_number、dwd_org_annual_financial_info 的更多科目、dwd_org_org_product_info 的结构化产品字段接进快照。中期（需要建表）补 svc_quality_score / svc_csat_score / svc_success_case_count / svc_coop_edge 四张结果面。长期（需要外部数据）补牌照清单、服务合同、客户评价。

### 4.3 降档论证（为什么不是更高一档）

封面号的档位是「六体系聚合」，聚合规则是：任一体系完全不可用则整体不得高于部分支持。本件海外轴完全不可用（不是量少，而是语义不成立），故整体封顶在部分支持。

若只看「能算的几个体系」，很容易写成完全转换支持；但那样会让「全球分布」这一体系在验收时无法交付，属于用体系数量掩盖单体系缺口，本件不做这种聚合。

### 4.4 缺口对下游的影响

缺口的第一层影响是「指标语义不完整」：缺一维时综合值仍能算，但它回答的问题已经变了。例如技术力指数若缺「融资成本」，高分机构可能只是「资本多、风险低」，而不是「融资便宜」。

第二层影响是「跨指标不可比」：两件指标若缺的维度不同，排序差异无法归因到机构本身，只能归因到口径差异。本批十件因此统一了池规则、标准化与缺维处理三条，尽量把差异压到维度选择上。

第三层影响是「展示必须带限定语」：凡缺维的指标，前端角标要写明「本指标不含 X 维」，否则用户会默认它是全维度评价。这一点写进 §附录 C 的交付清单。

|---|---|---|
| 服务质量评分 | 无（无评价/评分/投诉闭环表） | 待建 svc_quality_score，先用资讯量弱代理并标注 |
| 客户满意度 | 无（无问卷/评分表） | 待建 svc_csat_score |

## 五、王惠方法对照与选用建议

王惠稿把封面号拆成六体系、并为每个体系指定了「优先表 + 代理表」，这是本件能落地的前提。本件沿用其拆法，但把「代理表」全部换到 gkx：旧稿的圈定池、六类分桶列、境外表都来自演示库口径，换源后需要重新验证每个代理是否还成立。

验证结果分三类：直接成立（新增、深圳分布）、需要重建口径（产业布局的多命中/主类）、不成立（海外轴）。第三类是换源暴露出来的真问题：旧稿写「境外表 0 行」，本件写「境外表 2 万行但只有一个国家」——结论同向（海外不可用），但原因完全不同，修复路径也不同。

因此本件对王惠口径的态度是「结构采纳、代理重验」，而不是「照抄结论」。

### 5.4 替代路径对比

| 路径 | 优点 | 缺点 | 本件取舍 |
|---|---|---|---|
| 纯硬指标排序（专利/研发） | 客观、可复算 | 把服务能力窄化为创新能力，咨询/营销/人力类失效 | 不采用，仅作旁证 |
| 纯专家打分 | 可解释、贴合行业 | 不可复算，无法审计 | 不采用 |
| 本件：代理 + 显式缺口 | 可复算、缺口可追责 | 代理存在语义降级 | 采用 |

**选用建议**：采纳王惠的六体系拆法；代理表全部换成 gkx 并用值域分布重验，海外轴由「0 行」改判为「单国别残留」。

## 附录 G 常见误读与纠正

**问：为什么分母是 44,153 而不是底册 189,116？**

底册是全量法人库（189,116 行），其中绝大多数不是服务机构。本批统一以「经营范围里出现服务类表述」作为服务机构的可操作定义，故分母是 44,153。若甲方有正式的服务机构认定名单，应替换分母并重跑全部十件。

**问：为什么同一家机构会出现在多个环节/类型里？**

因为代理口径是「经营范围命中」，不是「唯一归属」。经营范围是一段自由文本，一家机构可以同时写研发、检测、销售。产物同时给多命中与主类两列，就是为了让下游按需选择，而不是让本件替甲方决定归属。

**问：数字能不能直接和旧稿比？**

不能比绝对数，只能比结构与排序。旧稿的分母是人工圈选名单（43,296），本件是经营范围实体（44,153），两者不是同一个总体；此外旧稿的分类器列与词表口径也不同。

**问：缺维为什么不补 0？**

补 0 等于断言「该机构在这一维得分为 0」，而事实是「我们不知道」。这会把「无数据」伪装成「表现最差」，系统性压低数据稀疏机构的排名。本件的做法是缺维不进平均，并同步缩小权重分母。

**问：为什么阈值不直接用行业均值？**

gkx 没有行业均值口径（无行业代码主表与行业统计口径对齐）。用本池分位数是退而求其次，但它至少可复算；写一个来源不明的「行业均值」会让整条链无法审计。

**问：代理指标会不会方向相反？**

会。典型是「资讯条数代理服务质量」：负面新闻也计入条数。凡是存在方向性风险的代理，本件都在 §四 标注，并限制其只作排序参考、不作结论依据。

**问：重跑后数字变了怎么办？**

先看是不是快照变了（`generated_at` 与 `built_at`），再看是不是上游表补数。文档与产物必须同步更新：本批要求 MD 的 mtime 晚于 `_out.json`，且改脚本后必须重跑渲染器，避免正文停在旧数字。

**问：这套口径能不能直接上生产？**

能上「有供给/相对排序」这类展示，不能上「绝对水平/政策结论」这类判断。上生产前至少要补：正式机构名单、机构×环节成员表、服务质量与满意度结果面三件。
