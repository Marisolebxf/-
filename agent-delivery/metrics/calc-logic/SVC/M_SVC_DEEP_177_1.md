## 摘要

「市场营销服务机构技术力评价模型」从调研能力、策划能力、成功项目案例三维评价市场调研、营销策划、公关传播类机构。MKT 类是六类里最依赖「效果与过程数据」的类型，而这类数据恰恰最商业敏感、最难公开获取。

本件在 gkx 上实测：MKT 主类池 1,146 家；调研能力 0 家、策划能力 0 家、成功项目案例（资讯代理）682 家，资讯合计 20,063 条、中位 1.0 条、最高 2,426 条。因两维无源，**综合指数暂缓**，只提交分维可得性、单维代理分（仅在 682 家有资讯的机构内可比）与 TOP10 描述性清单。

档位 **部分支持**。本件结论落在「为什么不该算」上：把资讯条数当成功案例，会把品牌方算成营销服务机构、把被报道当成案例多——这是口径错误，不是数据不足。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是技术力评估下的 MKT 专项：对营销服务机构做三维打分，输出指数与排名。

### 1.2 为什么需要这个指标

营销服务机构的价值在于「帮客户把东西卖出去、把品牌立起来」，衡量它需要调研方法、方案质量与项目结果三类过程数据。这类数据几乎全部沉淀在机构自己的项目档案里，公开层面能观察到的只有「机构自己被报道了多少」——两者的错位是本件最大的方法论风险。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规给了三维名称与「层次分析/主成分/机器学习」的候选方法，但没有公式、阈值或源表。旧稿采用王惠三项口径。

### 1.4 指标口径与维度拆解

三维口径：调研能力 = 调研报告份数/样本量/方法说明（无表）；策划能力 = 方案数/比稿中标/执行验收（无表）；成功项目案例 = 项目数/行业分布/客户复购（无表），现用资讯条数做单维 min-max ×100 的弱代理。按原设计应等权 1/3，但因两维全空，本件**不合成**。

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 池/机构域 | `dwd_org_org_product_info.org_id` | 按 org_id 去重，不做行数计数 |
| 行业/类型 | `main_activities` 词表 | 未命中归 UNCLASSIFIED，不丢弃 |
| 财务截面 | `dwd_org_annual_financial_info` 最近有值年 | 缺年不补 0，取最近有值年 |
| 风险事件 | `dwd_org_risk_shixin` / `dwd_org_company_punish` | 无记录记 0 件（事件型字段，0 是真实语义） |
| 资讯量 | `dwd_org_important_news_info` 标题条数 | 无资讯记 0，仅作代理 |
| 资本关系 | `dwd_org_invest_info` / `dwd_org_shareholder_info` | 对端解析不了的行丢弃并计数 |

### 1.5 与同域姊妹指标的分工

与 174/175/176 同骨架，但本件是四件里唯一「三维中两维全空」的：另外三件至少有两维可算。「宁可不出数，也不出错数」是 v6 铁律的直接应用。

### 1.6 本件的边界与不做什么

本件不做：不用资讯情感当项目结果、不用粉丝/流量代理（无数据）、不对调研与策划维插补、不发布综合排名。

## 二、计算过程

### 2.1 数据源与池

池 = 主类为 MKT 的 1,146 家。池的纯度问题与 174/176 同源：经营范围写「市场营销策划」的既有广告/公关公司，也有大量消费品牌与地产商的营销部门表述。TOP10 里出现多家非营销服务机构即为此故。

本件因此把 TOP10 定位为「描述性清单」而非「榜单」——不排名次、不给星级，只列资讯条数与标签数，供业务方判断池纯度。

### 2.2 维度一｜调研能力（无源）

需要调研报告份数、样本量、方法说明（定量/定性、抽样框）、数据采集广度。gkx 无任何调研项目表，也没有可代理的字段（没有「报告」「样本」类结构化列）。本维 0 覆盖。

试过的替代：用资讯里的「发布报告」关键词命中（文本匹配），实测命中极少且无法区分「发布报告」与「被引用报告」，不构成可复核的口径，故放弃。

### 2.3 维度二｜策划能力（无源）

需要方案数、比稿中标记录、执行落地与资源整合情况。gkx 无投标/比稿/验收类表，本维 0 覆盖。

这是营销机构最核心的能力维（比稿胜率），缺失后三维只剩「曝光」一条腿，模型无法闭合。

### 2.4 维度三｜成功项目案例（资讯代理）

正式口径是项目数、行业分布、客户复购。现用 `dwd_org_important_news_info` 标题条数做单维 min-max ×100，覆盖 682 家（59.5%），资讯合计 20,063 条、中位 1.0 条、最高 2,426 条。

这个代理对营销机构的方向性偏差最严重：公关/传播类机构天然高曝光（制造报道就是它们的业务），调研类、投放类机构天然低曝光。用一个偏向公关的指标评价全行业，结论必然偏向公关。 故该分只称「单维代理分」，不称指数。

### 2.5 标准化、赋权与阈值

本件**不合成指数**：产物 `index_withheld.reason` 写明「3 维中 2 维无源」，`what_would_unblock` 列出 svc_research_score / svc_planning_score / svc_success_case_count 三张待建结果面。

为什么不像 175 那样对子集出指数？175 的缺口是「覆盖薄」（方法对、样本少），本件的缺口是「两维根本没有」加「第三维口径错」（资讯 ≠ 项目案例）。覆盖薄可以限额发布，缺两维且代理失真不能。

为便于业务方判断，产物仍给出单维代理分与资讯分位（中位 1.0、最高 2,426），但不给综合分、不给名次。

### 2.7 结果解读

单维代理分的 TOP1 是洲明科技（资讯 2,426 条，LED 显示企业），TOP2 天虹数科、TOP3 香雪制药——全是品牌方而非营销服务机构。这不是排序 bug，是池定义问题：它们的经营范围里含「市场营销策划」。

资讯中位数只有 1.0 条，说明长尾极重：682 家里大多数只有 1—2 条报道，头部几家占了绝大部分条数。在这种分布下做 min-max，头部会拿满分、绝大多数挤在低位，区分度其实来自「有没有被报道」而非「报道多少」。

使用建议：本件只用于「MKT 池摸底」，不进入任何对外榜单；若要出榜，必须先有调研/策划两类过程数据。

### 2.9 参数与常量清单

| 参数 | 取值 | 来源/说明 |
|---|---|---|
| 池规则 | org_id 去重 + 经营范围非空 | 避免 45,011 行 / 44,153 家的重复计数 |

| 缺维处理 | 空维不进平均、不补 0 | 缺维时按非空维等权，权重分母同步缩小 |
| 最少维度 | ≥2 维非空才出综合值 | 单维噪声不得冒充综合分 |
| 阈值 | 见各件 §2 合成小节 | 需规未给数值，本件按分位或经验值并标注 |
| 年份 | 见产物 `base_years_used/_missing/_note` | 缺失年不摊 0，残年单独标注 |

把「不出数」写成正式结论，需要比「出数」更硬的证据链：本件的证据是两维零覆盖（连弱代理字段都没有）、第三维语义偏移（资讯 ≠ 案例）、TOP10 行业构成错位（池不纯）。三条合起来才支撑弃算。

如果只写「数据不足所以不算」，业务方会认为是偷懒；写清「为什么算了会错」，才是可交付的结论。

### 3.1 逐维支撑矩阵

| 维度 | gkx 源表 / 字段 | 覆盖 | 支撑判定 |

### 3.2 字段级核验

核验一：三维覆盖逐维计数（0 / 0 / 682），确认不是「有表无值」；核验二：资讯分布检查（合计 20,063、中位 1.0、最高 2,426），确认长尾不是脏数据造成；核验三：TOP10 逐家看行业，确认非营销机构占比高，据此判定池纯度不足、指数不宜合成。

### 3.3 口径陷阱与规避

| 陷阱 | 本件如何处理 |

### 4.2 修复路径与优先级

优先级按「补齐成本 ÷ 解锁维度数」排：成本最低、能一次解锁多个维度缺口的排前面。本批十件的共同短板是「服务过程类数据」（合同、验收、评价、投诉）在 gkx 完全没有承载表，这类缺口不是换字段能解决的，必须等甲方开放业务系统或采购第三方评分。

短期（可在一周内做）优先补「已有表但没接」的部分：把 dwd_org_recruit_info 的 hiring_number、dwd_org_annual_financial_info 的更多科目、dwd_org_org_product_info 的结构化产品字段接进快照。中期（需要建表）补 svc_quality_score / svc_csat_score / svc_success_case_count / svc_coop_edge 四张结果面。长期（需要外部数据）补牌照清单、服务合同、客户评价。

### 4.3 降档论证（为什么不是更高一档）

不抬档的第一条理由：抬档的门槛是「所有必需维度现在都能算出足够数据」，而本件至少有一维是结构性无源——不是「样本少」，而是「库里没有这张表、也没有可替代的字段」。这类缺口换写法、加 SQL 都补不出来。

不抬档的第二条理由：本件的代理关系是「语义降级」而非「同义转换」。例如用资讯条数代理服务质量，代理量测的是曝光度，方向可能相反（负面新闻也会推高条数）。只要存在这种方向性风险，就不能称「完全转换支持」。

不降档的理由：主体维度确有量、能算、能复核，且排序结果与行业常识不冲突（见 §2.8 的极值回查），不属于「完全不支持」。故最终判 **部分支持**。

### 4.4 缺口对下游的影响

本件最大的方法论风险是「用一个偏向公关的指标评价全行业」。如果勉强出分，公关公司会系统性占优，调研型与投放型机构被系统性低估——这不是精度问题，是方向性错误。

弃算的代价是「这个指标暂时不可用」，出错的代价是「业务方拿错数做决策」。v6 要求后者绝不允许。

对下游：如果产品侧必须要一个 MKT 分数，建议改用「分维标签」而非「综合分」——例如标注「有资讯记录/调研未知/策划未知」，把不确定性显式暴露给使用者，而不是压缩成一个 0—100 的数。

## 五、王惠方法对照与选用建议

王惠调研稿（20260829 批次规范化迁移）给出的口径，是本批十件里唯一有「维度名 + 可执行代理规则」的版本：它把需求原文的定性描述翻译成「哪张表、哪个字段、缺了用什么代理、缺维怎么处理」，并显式登记了待建项。本件沿用其维度划分与合成骨架，只把数据来源从旧库口径整体换到 gkx，并把代理规则逐条落进脚本。

与官方口径对照：需求原文本身不给公式（见 §1.3），故不存在「官方公式 vs 王惠公式」的正面冲突；可比的只有维度语义。国家统计局《国家科技服务业统计分类（2018）》提供的是行业边界而非评分方法，OECD/JRC 复合指标手册提供的是「标准化—赋权—聚合—敏感性」的通用流程，二者与王惠口径不矛盾。

与替代路径对照：一条常见替代是「用专利/研发等硬指标直接排序」，优点是客观，缺点是把服务能力窄化为创新能力，对咨询、营销、人力类机构几乎失效；另一条是「纯专家打分」，可解释但不能复算。王惠口径走的是「可复算的代理 + 显式披露缺口」中间路线，与本项目「数字必须能指到落盘文件」的交付要求一致。

### 5.4 替代路径对比

| 路径 | 优点 | 缺点 | 本件取舍 |
|---|---|---|---|
| 照旧稿合成三维 | 有数 | 两维全空 + 弱代理维污染结论 | 不采用 |
| 用资讯单维 ×100 当指数 | 有数、可复算 | 把曝光度当技术力 | 不采用（仅保留为代理分） |
| 本件：弃算 + 分维披露 | 不出错数 | 指标暂不可用 | 采用 |

**选用建议**：不采纳旧稿的三维合成：两维结构性无源、第三维为方向性失真的弱代理，改为「分维可得性 + 单维代理分」，指数弃算。

## 附录 G 常见误读与纠正

**问：为什么这件不出指数？**

三维里两维在 gkx 完全没有承载表，剩下的一维（资讯条数）是弱代理——它衡量曝光而非项目成果。把单维代理 ×100 当指数，等于把曝光度改名成技术力。

**问：175 也只有部分维可算，为什么它出指数？**

175 的可算维（agency 件数、资本边）语义都对，只是覆盖薄，可以限额发布；177 的两维是「根本没有」，第三维语义还错，任何合成都会失真。

**问：池为什么有 1,146 家？**

主类归并后 MKT 是第四大类，因为「市场营销策划」是极常见的经营范围表述，几乎所有消费类企业都会写。

**问：TOP10 为什么这么多品牌方？**

池纯度问题。资讯多的往往是品牌方（它们本身就是新闻主体），不是服务机构。

**问：单维代理分还能用吗？**
