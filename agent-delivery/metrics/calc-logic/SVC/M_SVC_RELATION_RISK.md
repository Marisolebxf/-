## 摘要

本件把风险拆成三层：主体层（谁有记录）、边层（风险主体连了谁）、暴露层（干净机构被连到多少）。三层各有自己的分母，混在一起就会得出「一半机构有风险」这种吓人的结论。

| 读数 | 值 |
|---|---|
| 服务机构池 | 44,153 家 |
| 风险机构（处罚或失信） | 22,719 家（51.4552%） |
| 失信被执行机构 | 9,869 家（22.3518%） |
| 行政处罚机构 | 16,197 家（36.6838%） |
| 两类均有 | 3,347 家（占风险机构 14.7322%） |
| 仅失信 / 仅处罚 | 6,522 / 12,850 家 |
| 失信记录 / 处罚记录 | 60,364 / 51,672 条 |
| 单家最多记录 | 1,239 条 |
| 股权边 | 13,141 条 |
| 风险—风险边 | 3,183 条（24.2219%） |
| 混合边（一端风险） | 5,118 条（38.9468%） |
| 干净—干净边 | 4,840 条（36.8313%） |
| 有边的风险机构 | 5,877 家（占风险机构 25.8682%） |
| 有边的干净机构 | 7,028 家（占干净机构 32.789%） |
| 一跳暴露的干净机构 | 3,184 家（占活跃干净 45.3045%） |
| 二跳新增暴露 | 1,893 家（为一跳的 0.5945 倍） |
| 判档 | 部分支持 |

第一个必须说清的事实是**风险率的分母**。51.4552% 是「池内至少有一条处罚或失信记录」的比例，不是「严重违法比例」。行政处罚涵盖税务、工商、环保、消防等大量轻微事项，一家机构十年内被罚一次很常见；把它读成「一半服务机构有问题」，是把合规记录当成了信用污点。产物里因此把失信（22.3518%）单列，因为失信被执行才是真正影响履约能力的口径。

第二个事实是**传导覆盖率低**。22,719 家风险机构里只有 5,877 家有股权边（25.8682%），其余 16,842 家是孤立点——它们有风险记录，但在股权图上连不到任何人。这意味着「风险传导」在这张图上只覆盖四分之一的体量，剩下四分之三的风险主体无法通过图影响别人。

第三个事实是**暴露的不对称**。活跃干净机构里 45.3045% 至少连着一个风险主体，这个比例远高于活跃风险机构的 25.8682%。原因不是干净机构更爱冒险，而是干净机构数量多（21,434 家）、有边的比例也高（32.789%），而风险机构里有大量孤立点。二跳只新增 1,893 家，是一跳的 0.5945 倍，说明传导在两步内基本收敛——这既是好消息（波及面不扩散），也是坏消息（股权图的连通性本来就弱，二跳算不出更多）。

### 1.2 为什么需要「服务关系风险」

服务机构的风险有两个来源。一个是自身：被处罚、被列为失信被执行人，直接影响它能不能继续履约。另一个是关系：它的股东、被投方、母公司出事，会通过控制权、资金链、声誉三条渠道传导过来。第二类风险单看机构自己是看不见的——一家干净的代理机构，如果其控股股东被列为失信被执行人，它的持续经营能力就已经受损，但它的处罚记录仍然是零。

本件的作用就是把第二类风险显性化：不是给机构打分，而是回答「这家机构离风险有多远」。一跳邻居有风险，是第一层；二跳才有，是第二层。层数越远，传导强度越弱，但预警价值仍在。

### 1.3 口径定义

风险主体集合 $R$：在 `dwd_org_company_punish` 或 `dwd_org_risk_shixin` 中至少有一条记录、且 `org_id` 落在服务机构池内的机构。

$$R = \{v \in V : \text{punish}(v) \ge 1 \ \lor\ \text{shixin}(v) \ge 1\}$$

一跳暴露集合 $X_1$：非风险机构中，至少有一个邻居属于 $R$ 的机构。

$$X_1 = \{v \in V \setminus R : \exists u \in R,\ (u,v) \in E\}$$

二跳新增 $X_2$：$X_1$ 的邻居中既不属于 $R$ 也不属于 $X_1$ 的机构。三条补充约定写进产物：

第一，**分母分层**。风险率的分母是池 44,153；一跳暴露率给两个分母——活跃干净机构 7,028（能连到人的）与全部干净机构 21,434（含孤立点）。两个读数差三倍，必须并报。

第二，**风险类型不合并**。失信与处罚分开统计，`both_n` 单列。原因见摘要：两者严重性差一个量级，合在一起会掩盖失信口径。

第三，**边只走股权**。传导只用投资/股东边，合作与供应链边无表。这不是选择，是约束，必须在正文与 UI 同时声明。

### 1.4 计算公式与本批实现式

```python
def risk_rate(risky, pool):
    return risky / pool * 100 if pool else None

def exposed_rate(exposed, active_clean):
    return exposed / active_clean * 100 if active_clean else None

# 一跳
X1 = {b for a, b in edges if a in R and b not in R} | \
     {a for a, b in edges if b in R and a not in R}

# 二跳（排除风险主体与一跳暴露）
X2 = {m for n in X1 for m in adj[n] if m not in R and m not in X1}
```

实现上有一个容易写错的地方：二跳集合必须显式排除 $R$ 与 $X_1$，否则会把「一跳暴露节点的风险邻居」重新算进二跳，导致二跳数虚高。本件在产物里落 `two_hop_clean_n` 与 `exposed_clean_n` 两个字段，并用「二跳 ≤ 一跳」做合理性检查——若二跳大于一跳，说明排除条件写漏了。

## 二、计算过程

### 2.1 风险主体的构造

先从共享快照 `svc21_facts_20261022.json` 的 `risk` 段按 `org_id` 聚合记录数（该快照由 gkx 只读实测构建，含池、风险、投资边、股东边四段），得到池内 16,197 家有处罚记录、共 51,672 条；再从 `dwd_org_risk_shixin` 聚合，得到 9,869 家有失信记录、共 60,364 条。两表按 `org_id` 取并集，得到风险主体 22,719 家。

并集里三类要分开：仅处罚 12,850 家、仅失信 6,522 家、两类均有 3,347 家。两类均有的占风险机构 14.7322%，这部分是「已经被罚且已经失信」的机构，风险等级最高。产物里 `population` 段把五个数（总数、失信、处罚、两类、仅失信、仅处罚）全部落盘，任何一个缺失都会让读者无法还原并集关系。

### 2.2 记录密度与异常值

失信机构平均 6.1165 条记录、受处罚机构平均 3.1902 条记录。单家最多 1,239 条，这个数需要谨慎：一家机构有上千条处罚记录，要么是超大型集团（各分支机构分别被罚），要么是表内存在重复导入。本件不做去重，因为表里没有可靠的「处罚决定书编号」字段可以判定重复；但把这个最大值写进产物（`max_records_single_org`），让读者知道分布尾部有多重。

记录数不等于风险数。一家被罚 1,239 次的机构和一家被罚 1 次的机构，在「是否有风险」这个二值口径里是一样的。本件主口径用二值，记录数只作分布描述，不参与传导计算——否则一条边会被重复计数上千次。

### 2.3 边的构造与分类

边集与密度件共用同一套构造：投资边 + 股东边，无向去重，13,141 条。按两端是否属于 $R$ 分成三类：风险—风险 3,183 条（24.2219%）、混合 5,118 条（38.9468%）、干净—干净 4,840 条（36.8313%）。

这个三分结构很能说明问题。风险—风险边占近四分之一，意味着风险在图上不是随机分布的，而是**成团出现**：出事的机构往往互相持股，或者被同一个出险集团控制。混合边占 38.9468%，是传导的通道：一端风险、一端干净，干净那端就是一跳暴露。干净—干净边 4,840 条构成图的「安全区」，但安全区也可能被二跳穿透。

### 2.4 一跳暴露

混合边两端取出干净的那一端，去重后得到 3,184 家一跳暴露机构。这个数的分母有两个：活跃干净机构 7,028 家（有边的），暴露率 45.3045%；全部干净机构 21,434 家，暴露率 14.8549%。

两个读数差三倍，含义完全不同。45.3045% 说的是「在股权图上连得上人的干净机构里，近一半直接连着风险主体」——这个比例高得惊人，说明服务机构的股权网络与风险主体高度重叠。14.8549% 说的是「全部干净机构里，七分之一被直接波及」——这个口径更适合对外发布，因为它不排除孤立点。

### 2.5 二跳与收敛

一跳暴露节点再向外一跳，排除风险主体与一跳集合，得到 1,893 家二跳新增。二跳是一跳的 0.5945 倍，占全部干净机构的 8.8318%。二跳小于一跳，说明传导在两步内收敛，没有出现「指数扩散」。

这个收敛性有两个解释，必须同时给出。第一种是结构性的：股权图的连通分量本来就碎（密度件测得 2,270 个分量），二跳能走到的新节点有限。第二种是口径性的：二跳只算「新增」，已经在一跳里的不重复计，所以数字天然小于一跳。两种解释都成立，不能只取一个。

### 2.6 暴露类型拆分

3,184 家一跳暴露机构里，只通过处罚主体暴露的 1,924 家（60.4271%）、只通过失信主体暴露的 554 家（17.3995%）、同时通过两类暴露的 706 家（22.1734%）。

这个拆分对业务很重要：只连到处罚主体的机构，风险等级低（处罚多为轻微违规）；连到失信主体的 554 家与 706 家（两者合计即失信暴露），才是真正需要预警的对象。产物里把三类都落盘，UI 上应当用不同颜色区分，而不是统一标红。

### 2.7 城市切片

四市的风险率差异明显：深圳 43.7043%、广州 61.0078%、东莞 62.4884%、惠州 71.079%。深圳最低，但这个「低」不能直接读成「深圳服务生态最健康」。

原因有三层。第一，分母不同：深圳池 25,597 家，广州 12,641 家，东莞 4,300 家，惠州 1,594 家，小池子的率更容易被个别机构拉动。第二，执法强度不同：处罚记录的多少与当地市场监管力度直接相关，严格执法的地区记录更多，不代表问题更多。第三，注册地与经营地可能分离：按注册地归集，会把在深圳经营、注册在惠州的机构算进惠州。

一跳暴露的城市分布同样不均衡：深圳 2,088 家（占全部暴露 65.5779%）、广州 852 家、东莞 172 家、惠州 70 家。深圳绝对数最大，与它的池规模一致；比例上则要看各市活跃干净机构数，不宜直接用绝对数排名。

## 四、数据缺失情况

### 4.1 合作边传导：结构性无源（拒拟维）

gkx 无 `enterprise_cooperation`（`information_schema.TABLES WHERE TABLE_SCHEMA='gkx'` 命中 0 行），开发库 `gkxlumenx_dwd` 有结构但 0 行；演示库同名表为全量装载，铁律禁引，不构成支持。

**拒拟理由**：没有合作边，无法算「合作方出事 → 我方被波及」。
**替代口径**：投资/股东边一跳暴露。
**与原文差别**：股权传导只覆盖控制/参股链，漏掉客户、供应商、联合体伙伴。服务机构的业务风险大量来自「大客户流失」与「合作方违约」，这两类在股权图上完全不可见。替代口径会**系统性低估**服务关系的风险暴露。

### 4.2 供应链传导：结构性无源（拒拟维）

`enterprise_supply_chain` 在 gkx 不存在（0 行），供应商/客户关系无承载。

**拒拟理由**：无供应链边，上下游停摆风险无法计算。
**替代口径**：本维在本件内拒拟（不做代理）。
**与原文差别**：不是「代理得不准」，而是「完全无法代理」——股权关系与供应关系没有稳定的映射。

### 4.3 风险事件时间序列与处置进度：结构性无源（拒拟维）

处罚表与失信表没有可靠的事件日期与结案状态列，`svc_metric_series` 亦不存在。

**拒拟理由**：无时间字段，无法区分「历史已修复」与「当前仍在」。
**替代口径**：存量计数。
**与原文差别**：只能回答「有没有记录」，不能回答「何时发生、是否已履行」。一条 2018 年已结案的失信记录，与一条 2026 年新立的记录，在存量口径里权重相同。

### 4.4 孤立风险主体

22,719 家风险机构里 16,842 家没有股权边（74.1318%）。这些机构有风险记录，但在图上连不到任何人，传导计算对它们完全无效。这不是计算错误，是图的覆盖问题——它们在别的图（合作图、供应链图）上可能有边，但那两张图不存在。

### 4.5 记录去重不可行

单家最多 1,239 条记录，但表里没有处罚决定书编号，无法判定同一事件是否被重复导入。本件不做去重，只把最大值披露。若甲方后续补上编号，应重算记录分布，但二值口径（是否有风险）不受影响。

### 4.6 不得外推的三件事

1. **不得把 51.4552% 读成「一半机构严重违法」**：处罚含大量轻微事项，失信才是硬口径。
2. **不得用城市风险率排名**：执法强度、注册地与经营地分离都会干扰。
3. **不得把股权暴露当业务暴露**：两条传导路径缺位，暴露率必然低估。

### 4.7 停用与重估条件

出现以下任一情况应重估：① 合作边或供应链边入湖（可算业务传导）；② 风险表补事件日期与结案状态（可做时序与在险口径）；③ 股权边两端解析率提升（本件只吃两端可解析的池内边，图覆盖不完整，解析率见 `M_SVC_RELATION_DENSITY` 件）；④ 服务机构池边界变更（分母换，全部读数重算）。

## 五、结论与发布建议

### 5.1 可用结论

第一，风险主体 22,719 家占池 51.4552%，失信 9,869 家占 22.3518%。第二，股权边 13,141 条中风险—风险占 24.2219%，风险成团。第三，一跳暴露 3,184 家，占活跃干净机构 45.3045%、占全部干净机构 14.8549%。第四，二跳新增 1,893 家，传导两步内收敛。第五，业务传导两维结构性无源，判部分支持。

### 5.2 发布口径（逐条写死）

| 项 | 必须写明的口径 |
|---|---|
| 风险口径 | 处罚与失信分开，失信单列 |
| 传导边 | 投资 + 股东，无向，不含合作/供应链 |
| 暴露分母 | 活跃干净 7,028 与全部干净 21,434 双报 |
| 城市 | 同时给池规模，率不作排名 |
| 时间 | 存量累计，不按年切片 |
| 记录数 | 只作分布，不参与传导 |

### 5.3 与旧稿的取舍

旧稿（镜像面）用演示关系图给出暴露率，本版不再引用。本版的风险主体来自 gkx 真实处罚/失信表，暴露率建立在 13,141 条真实股权边上；档位仍判「部分支持」，但缺口从「数据不可信」换成「业务传导路径缺失 + 无时序」。

### 5.4 后续

三条路径：① 合作边入湖；② 供应链边入湖；③ 风险表补事件时间。三者任一落地都要重跑暴露计算，并重写「一跳/二跳」章节——尤其是二跳，业务边一旦接入，收敛性结论可能反转。

## 附录 D　「51%」这个数字该怎么读

51.4552% 是本件最容易被误读的数，所以单独拆一层。

第一层，它的分子是「至少一条处罚或失信记录」，不是「重大违法」。行政处罚的法定种类包括警告、罚款、没收、责令停产停业等，其中警告与小额罚款占多数。一家机构因为「未按期公示年报」被罚，也会进这个分子。

第二层，它的分母是服务机构池 44,153 家，不是全部企业。服务机构（代理、检测、咨询、孵化等）本身是监管密集型行业，被检查频次高于一般企业，记录率天然更高。

第三层，它与失信口径差一倍以上：失信 22.3518%，处罚 36.6838%。如果只看失信，结论是「约五分之一的服务机构有履约风险」；如果只看处罚，结论是「超过三分之一被罚过」。两个数都对，问的问题不同。

结论：对外发布时应当以失信为主口径，处罚作辅助披露；两者都不宜单独作为「机构质量」的判据，必须与业务规模、存续年限一起看。
