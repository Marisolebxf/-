## 摘要

「全球服务机构分布」在需求里是地图型 KPI：按国家给出机构家数，再下钻到省份/城市。旧稿之所以能画出多个国家，是因为演示库的 `svc_org_circle` 里人工塞了京/浙几家与少量海外样本；换到 gkx 后必须重新回答一个更基础的问题——gkx 到底有没有「国别」这个字段。

实测答案是：底册 `dwd_org_base_info` 没有 country/nation 类列，只有省/市；机构池 44,153 家里 44,132 家可回联底册，全部落在广东省（深圳 25,597、广州 12,641、东莞 4,300、惠州 1,594），另 21 家悬空。国家轴因此只有「中国 44,132 + 未判定 21」两行，覆盖国家数 1。`dwd_forg_*` 近源虽然存在，但它是英国偏企业名录与全球科研机构名录，与「六类服务机构」口径不闭合，不能拿来填海外格。

判档 **部分支持**：国内格与省级下钻可以完整对账（省合计 44,132、市合计 44,132），但海外格在任何构建路径下都无源。发布时必须把「全球」降级为「国内（广东）+ 海外待补」，否则地图会把「无源」渲染成「该国没有机构」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是产业服务链分析页面的「全球服务机构分布」地图与国家/省份下钻。算法侧对应服务机构基础指标模型六大体系中的「全球服务机构分布」；展示侧要求国家色阶、国家 tooltip、省级下钻三层。这个指标不是独立的分析结论，而是「服务机构库」的空间索引：用户点某个国家，看到的是该国机构列表；点某个省，看到的是省内城市分布。

### 1.2 为什么需要这个指标

分布类指标的价值在「比较」：深圳与北京比、中国与新加坡比、都市圈与全国比。比较成立的前提是国家/省份的归属规则一致。旧稿的多国分布实际上不可比较——样本里海外机构只有个位数，任何「新加坡有 3 家、中国有 43,292 家」的对比都只是在比样本量，不是在比产业。换源后本件宁可只给一格，也不把不可比的海外样本画进地图。

另一个原因是下游依赖：`M_SVC_ORG_TOTAL` 给出总数，本件给出空间拆解；`M_SVC_ORG_COVERAGE_BREADTH/DEPTH` 的所有城市切片都引用本件的归并规则。如果本件偷偷把 21 家悬空并进深圳，下游所有城市占比都会带着这个错误传播。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规只写「全球服务机构分布」，没有定义国家如何认定（注册地/办公地/服务对象所在地）、港澳台是否单列、分支机构算总公司所在国还是本地。旧稿用 calc-logic 补了「按池表 country 字段分组 COUNT」这一层，但旧库的 country 字段本身是人工填的，换到 gkx 后该字段不存在，口径必须重新落地。

### 1.4 指标口径与维度拆解

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 国家 | 无 country 列；由 `province` 归并为「中国」 | 悬空 21 家归「未判定」，不猜国别 |
| 省份 | `dwd_org_base_info.province` | 空值归「未回联底册」 |
| 城市 | `dwd_org_base_info.city` | 空值归「未回联底册」 |
| 港澳台 | 无字段 | 不单列，等甲方裁决 |
| 海外机构 | `dwd_forg_*` 语义不闭合 | 留空集，不填 0 |

口径边界：国家格的分母是机构池 44,153，不是底册 189,116；省份格只覆盖广东省，因为池内没有第二省；「未判定」21 家是一个独立格，既不算中国也不算海外。

### 1.5 与同域姊妹指标的分工

与 `M_SVC_ORG_TOTAL` 的分工：本件引用它的池定义，不重算总数；本件所有国家格相加必须等于 44,153。

与 `M_SVC_ORG_NEW_COUNT` 的分工：本件是存量空间分布，NEW_COUNT 是时间分布；两者交叉可做「某市某年新增」，但交叉表的每个格子都必须能回到池。

与 `M_SVC_CHAIN_SEGMENT_ORG_COUNT` 的关系：该件用同一池 44,153，并给出「六环节多命中合计 60,673、环节去重 34,578」。这两个数是环节维派生量，**不是**另一个机构池；本件数的是机构池 44,153，与环节去重 34,578 相差 9,575 家（有机构无任何环节命中）。正文必须点明这一点，防止下游把 34,578 当国家分布分母。

### 1.6 本件的边界与不做什么

不做海外补数（无闭合源）；不做国家名称归一（没有国家字段）；不做「机构注册地 vs 服务地」的双口径（底册只有注册地）；不把港澳台从中国拆出（需求未裁决）；不把 21 家悬空按城市猜测归并。

## 二、计算过程

### 2.1 方法选择：先归并到省级，再映射国家，而不是直接猜国别

方法选择的约束是字段：gkx 底册只有 `province`/`city`，没有 `country`。因此唯一可审计的路径是「省 → 国家」的确定性映射：广东省 → 中国，其余省 → 中国，空省 → 未判定。这条路径的优点是每一步都能对账：省合计 = 市合计 = 回联数 = 44,132；缺点是它只能产出「中国」一个真实国家格。

放弃的方案是「用机构名称里的地名猜国别」。名称含「深圳」「广州」可以猜中国，但含「亚太」「国际」的机构无法判定，且会把「深圳市××贸易有限公司」与「××国际控股有限公司」混为一谈。另一个放弃的方案是「用 `dwd_forg_*` 补海外格」：该表是英国偏企业名录，行业与六类服务机构不闭合，补进去会让海外格变成「名录里有谁」而不是「服务机构有谁」。

### 2.2 步骤 1｜池与回联（D1）

池取 `svc21_facts.pool`，44,153 家（定义见 `M_SVC_ORG_TOTAL` §2.2）。以 org_id 回联底册，命中 44,132 家，回联率 99.95%；21 家悬空。悬空的 21 家不丢弃：它们进入「未判定」国家格与「未回联底册」省份格，保证总数仍为 44,153。

### 2.3 步骤 2｜省级归并与国家映射（D2）

省级分布实测只有两行：广东省 44,132、未回联底册 21。没有第二省，是因为 gkx 底册 189,116 行里深圳都市圈四市占 99.82%，省外样本合计仅 342 家，而这 342 家里没有一家进入服务机构池（池的 org_id 全部来自经营范围表，经营范围表本身以都市圈企业为主）。

国家映射规则：广东省 → 中国；未回联 → 未判定。映射后 `country_dist` 为「中国 44,132、未判定 21」，`country_covered=1`。这里的 1 不是「全球只有一个国家有服务机构」，而是「本池只覆盖一个国家」。

### 2.4 步骤 3｜城市下钻与对账（D3）

城市分布为深圳 25,597、广州 12,641、东莞 4,300、惠州 1,594、未回联 21，五档合计 44,153。省级两档合计同样是 44,153。两条对账链都写进产物：`province_dist` 与 `city_dist` 各自求和相等，且都等于池数。

与 `M_SVC_CHAIN_SEGMENT_ORG_COUNT` 的同池对账：该件 `population.distinct_org_id=44,153`，与本件逐位相等；其 `stage_union_orgs=34,578`、`stage_multiplicity_sum=60,673`。本件明确声明：ORG_CNT 的分母是 44,153，不是 34,578；差值 9,575 是「无任何环节命中」的机构数。

### 2.5 步骤 4｜海外格探测（D4）

海外格做了三条探测：①底册列清单里搜 country/nation/region 类字段，结果为空；②`dwd_forg_*` 近源存在，但表注释与样本显示为英国偏企业名录、全球科研机构名录，行业字段与六类服务机构不闭合；③旧稿的海外样本只有个位数，且来自演示库人工圈定。三条探测的结论一致：海外格无闭合源，返回空集。

产物里 `overseas_source_probe` 记录了这三条判断，`decision` 写明「海外格留空、返回空集而非 0」。这是本件最重要的工程约定：空集与 0 在 UI 上是两种语义，前者是「没有数据」，后者是「确认为零」。

### 2.6 步骤 5｜产物与复现（D5）

产物 `code/M_SVC_ORG_CNT_out.json` 含 `support_judgment`、`base_years_used/_missing/_note`、`sources`、`population`、`country_dist`、`province_dist`、`city_dist`、`country_covered`、`overseas_source_probe`、`pool_reconciliation`、`difference_vs_old_draft`、`gaps`。脚本自包含、零 DB、只读快照，运行约 0.7 秒。

### 3.6 国家轴与省轴的口径关系

国家轴是省轴的函数：`country = f(province)`，不是独立字段。这个设计的好处是「国家格 = 省格之和」永远成立；坏处是当省字段缺失时，国家也只能是「未判定」。工程上建议在下游 API 里同时返回 `province_dist` 与 `country_dist`，让前端能校验两者之和相等；若不等，说明有机构在映射中被丢弃。

### 3.7 与同池件的对账表

| 件 | 池/派生量 | 取值 | 与本件关系 |
|---|---|---:|---|
| M_SVC_ORG_TOTAL | 机构池 | 44,153 | 本件分母 |
| M_SVC_CHAIN_SEGMENT_ORG_COUNT | 环节去重 | 34,578 | 池的子集，不是分母 |
| M_SVC_CHAIN_SEGMENT_ORG_COUNT | 环节多命中合计 | 60,673 | 环节维派生，非机构数 |
| M_SVC_ORG_CNT | 国家格合计 | 44,153 | 本件自身 |

### 3.8 城市占比的读法

| 城市 | 占池 | 读法 |
|---|---:|---|
| 深圳市 | 57.97% | 池内主体，不是全国主体 |
| 广州市 | 28.63% | 省会，第二极 |
| 东莞市 | 9.74% | 制造配套型服务 |
| 惠州市 | 3.61% | 池内长尾 |
| 未回联底册 | 0.05% | 未知，不并市 |

占比的分母是 44,153，不是广东省的 44,132，也不是全国企业数。三个分母会给出三个不同的深圳占比（57.97% / 58.01% / 极小），发布时必须锁定一个。本件统一用池分母，理由是与 `M_SVC_ORG_TOTAL` 一致；若甲方要「深圳占广东」，应明确写 25,597/44,132（约 58.0%），不能与 57.97% 混用。

### 3.9 空集与 0 的工程约定

本件在产物里用 `overseas_source_probe.decision` 明确「返回空集而非 0」。这个约定必须传到 API：`null` 表示无源，`0` 表示确认无机构，前端对两者的渲染必须不同（灰色「无数据」 vs 色阶最小值）。如果没有这条约定，地图会把整个海外涂成「0 家」，用户会读成「这些国家没有服务机构」，这是比缺数更严重的误导。工程上建议在接口层就把 `null` 与 `0` 分开序列化，不要依赖前端判断。

这一条同样适用于「未回联」：`null` 表示没有归属，`0` 表示确认没有机构；两者在 JSON 里必须是不同的值。


## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 海外机构 | 与六类口径闭合的海外名录 | 「全球」只剩一国 | 指定海外名录供方，或确认「中国机构出海布局」代理口径 |
| 国家字段 | 底册无 country/nation 列 | 国家只能靠省映射 | 底册补国别列，或接入海关/登记海外主体数据 |
| 港澳台 | 无单列字段 | 无法按甲方口径拆分 | 需求裁决后由底册补 region_code |
| 省外样本 | 池内无第二省 | 省际比较不可用 | 扩池到全国经营范围企业 |
| 海外退出 | 无注销/吊销 | 海外格即使补源也无净变化 | 随海外名录一起补事件流 |

### 4.2 修复路径与优先级

短期（一周内）：把「全球」在 UI 上改为「国内（广东）+ 海外待补」，并把空集与 0 的语义写进接口文档；同时给 21 家悬空机构逐家核对 org_id，确认是底册缺行还是键不一致。

中期（需要建表）：底册补 `country_code` 与 `region_code`（港澳台），并建立「注册地/服务地」双字段；扩池到全国经营范围企业，否则省际比较永远只有广东一格。

长期（需要外部数据）：接入与六类服务机构口径闭合的海外名录（可按 NACE 72/73/74 或 ISIC 69-75 对齐），并补海外注销事件流。没有这三步，「全球分布」只能是一个国内分布。

### 4.3 降档论证（为什么不是更高/更低一档）

不抬到「完全转换支持」：海外格在任何路径下都无源，国家轴只有一格，指标名里的「全球」无法兑现。

不降到「完全不支持」：国内格与省/市下钻完全可算、可对账，44,132 家全部有省有市，21 家悬空也单列可查。按四档定义，这是典型的「部分维度拿不到足够数据」，落部分支持。

### 4.4 缺口对下游的影响

第一层是地图：海外国家全部显示「无数据」，若前端把空集渲染成 0，会误导为「该国没有服务机构」。第二层是排名：只有中国一格时，「全球国家排名」没有意义，应关闭该视图。第三层是占比：海外份额无法计算，`M_SVC_ORG_CNT` 只能给国内城市占比，不能给「深圳占全球」这类结论。

### 4.5 字段级缺口表

| 期望字段 | gkx 是否有等价列 | 处置 |
|---|---|---|
| `country_code` | 无 | 省映射，只有中国 |
| `region_code`（港澳台） | 无 | 不单列 |
| `overseas_flag` | 无 | 空集 |
| `service_country`（服务地） | 无 | 不做双口径 |
| `branch_flag` | 无 | 不做集团合并 |

## 五、结论与发布建议

本件可以发布「国内分布」版本，不能发布「全球分布」版本。发布口径三句话：第一，国家轴只有中国一格，覆盖国家数 1，海外格是无源空集而非 0；第二，国内分布为广东一省，深圳 25,597、广州 12,641、东莞 4,300、惠州 1,594，21 家未回联单列；第三，本件与 `M_SVC_CHAIN_SEGMENT_ORG_COUNT` 同池 44,153，环节去重 34,578 不是本件分母。

建议 API 返回 `country_dist` 时同时返回 `country_covered=1` 与 `overseas_status="no_source"`，让前端能区分「没有数据」与「确认为零」。若甲方坚持要「全球」，必须先给海外名录，否则任何海外数字都是样本量展览。

## 附录 G　常见误读与纠正

**问：为什么只有中国一个国家？** 因为底册没有国别列，机构池只覆盖广东一省；这不是「全球只有中国有服务机构」，而是「本池只覆盖中国」。

**问：海外格为什么不是 0？** 0 表示「确认该国没有服务机构」，空集表示「没有数据」。本件无海外源，只能用空集。

**问：为什么不能拿 `dwd_forg_*` 补？** 它是以英国企业为主的名录与全球科研机构名录，行业口径与六类服务机构不闭合，补进去会得到「名录里有谁」而不是「服务机构有谁」。

**问：34,578 能不能当国家分布分母？** 不能。它是六环节去重机构数，是 44,153 的子集；用它当分母会把 9,575 家无环节命中的机构漏掉。

**问：21 家未回联能不能并进深圳？** 不能。没有证据表明它们在深圳；猜测会把未知伪装成已知。

**问：旧稿的京/浙机构去哪了？** 不在本池。本池 org_id 全部来自经营范围表，旧稿那几家来自演示库人工名单，两者不是同一总体。

**问：为什么城市占比加起来不是 100.00%？** 四舍五入。25,597/44,153 与 12,641/44,153 等五档占比逐项四舍五入后合计 100.00%，但中间值有 0.01 级误差；展示时应由前端按最大余数法配平，不要在文档里手工调数。

**问：为什么国家格与省格相加都等于 44,153，还要两条链？** 因为一条是「国家→省」的映射校验，一条是「省→市」的下钻校验；两条都过，才能确认映射函数没有在半路吞掉机构。只留一条，映射 bug 会躲在下钻里。

**问：海外格能不能先用 `dwd_forg_*` 顶着上线？** 不能。它的行业口径与六类服务机构不闭合，顶上去会让「海外服务机构」变成「英国企业名录里的公司」，后续所有跨国比较都建立在错误总体上。宁可空着，也不要错着。
