## 摘要

「市场热度」不是直接观测值，而是把新增序列压成一个标签：斜率告诉你方向，CV 告诉你稳不稳。王惠方法给出的规则是「相对斜率 + 变异系数」四象限；本件沿用其阈值（上行 +50%、下行 −10%、高波动 30%），只把输入序列换成 gkx 的 2013—2022 成立年计数。

实测：均值 2,087.7 家/年、标准差 961.78、OLS 斜率 **−305.34 家/年**、相对斜率 **−14.63%**、CV **46.07%**。相对斜率低于 −10% 阈值，评级为 **下行期**；CV 高于 30% 只影响「平稳期」内部的高低波动细分，不改变下行结论。与旧稿相比，斜率从 −294.9 变为 −305.34、CV 从 44.0% 变为 46.07%，评级仍是「下行期」——结论稳健，幅度有差。

判档 **部分支持** 的原因不在算法，而在窗口：2023—2025 的成立年只有 218/66/12 家，若把它们纳入回归，斜率会被放大到 −351.04、CV 升到 84.96%，评级虽仍是下行，但幅度严重失真。本件因此锁定 2013—2022，并把「当前热度」限定为「截至 2022」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是「新增服务机构动态」卡片上的热度标签（上升期/平稳/下行期）与颜色。算法侧属服务机构基础指标模型的派生评级；展示侧是一个标签 + 一句解释（「近十年新增年均下行 14.63%」）。它不是独立图表，而是对 NEW_CNT 序列的二次压缩。

### 1.2 为什么需要这个指标

政策使用者不擅长读斜率，但能读懂「下行期」。把序列压成标签，是为了让非技术读者在 3 秒内判断趋势方向。代价是信息损失：标签丢掉了幅度、拐点与波动结构，所以必须同时保留斜率、CV 与窗口，供追问时展开。

另一个作用是跨区域可比：如果每个城市都用同一套阈值，就可以把「深圳下行、广州平稳」放在一张表里比较。没有统一阈值，各城市各说各话，标签就退化成修辞。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规只写「市场热度」与「趋势分析」，没有给阈值、窗口与波动率定义。方法来自王惠（见 §五），本件按 v6 要求逐条对照并沿用其阈值，只替换数据源与窗口。

### 1.4 指标口径与维度拆解

| 维度/口径 | 计算 | 缺失时的处理 |
|---|---|---|
| 输入序列 | 年度新增（成立年计数） | 缺失年不进回归 |
| 窗口 | 2013—2022 | 固定，不滚动 |
| 斜率 | OLS 对年份回归 | 需 ≥3 个点 |
| 相对斜率 | 斜率 / 均值 | 均值 0 时不出比率 |
| CV | 标准差 / 均值 | 同上 |
| 评级 | 阈值四象限 | 边界值归入较保守档 |

口径边界：窗口内每年权重相同；不做对数变换；不做季节调整；不剔除峰值年；阈值不随样本调整。

### 1.5 与同域姊妹指标的分工

与 `M_SVC_ORG_NEW_COUNT`：本件消费其 `series_2013_2022`，不重算计数；序列是唯一真源。

与 `M_SVC_NEW_CNT`：本件是其叙事层的进一步压缩；NEW_CNT 给同比，本件给标签。

与 `M_SVC_ORG_TOTAL`：本件不改变池，只改变「怎么读池的时间结构」。

### 1.6 本件的边界与不做什么

不做预测（标签不是 forecast）；不做因果（下行不等于政策失效）；不做城市排名（除非每个城市都有同窗口序列）；不把 2023—2025 纳入；不做月度热度；不把 CV 当风险值（它只是波动率）。

## 二、计算过程

### 2.1 方法选择：相对斜率 + CV，而不是绝对斜率

用绝对斜率（−305.34 家/年）单独评级的问题是量纲：一个大城市每年减少 300 家可能只是 5%，一个小城市减少 300 家可能是 50%。相对斜率（斜率/均值）把量纲去掉，才能跨城市比较。CV 则回答「这条趋势线稳不稳」：同样是下行，CV 高说明年际波动大，政策不能按单年数据反应。

放弃的方案是「首末年差值 / 首年」（−81.4%）。这个数只用了两个端点，对端点异常极敏感：若 2013 年恰好是低谷，下降幅度会被夸大。OLS 用全部 10 个点，稳健性更好。

### 2.2 步骤 1｜序列与描述统计（D1）

输入 2013—2022 十个点：2,593、3,108、3,342、3,089、2,656、1,969、1,499、1,217、921、483。均值 2,087.7，标准差 961.78（总体标准差），首年 2,593、末年 483、年均变化 −211.0。十年合计 20,877，与 NEW_COUNT 逐位相等。

描述统计先于回归：均值与标准差是相对斜率与 CV 的分母，必须先锁定。若分母用样本标准差（n−1），CV 会略微上升，评级不变但数字不同；本件统一用总体标准差，并在产物 `window_main.std` 固化。

### 2.3 步骤 2｜OLS 斜率（D2）

以年份为 x、年度计数为 y 做一元线性回归，得斜率 −305.34 家/年。含义是「窗口内平均每年少 305 家」，不是「2022 比 2021 少 305 家」（实际少 438 家）。斜率的绝对值大于年均变化 −211.0，是因为 OLS 对两端点赋予更大杠杆：2013 年高于趋势线、2022 年低于趋势线，回归线被拉陡。

相对斜率 = −305.34 / 2,087.7 = −0.1463，即 −14.63%。这个数才是评级输入，绝对斜率只用于解释幅度。

### 2.4 步骤 3｜CV 与评级（D3）

CV = 961.78 / 2,087.7 = 0.4607，即 46.07%。评级规则：相对斜率 ≥ +50% → 上升期；相对斜率 ≤ −10% → 下行期；其余按 CV 分「平稳（低波动）」与「平稳（高波动）」，CV 阈值 30%。本件相对斜率 −14.63% ≤ −10%，直接落 **下行期**，CV 不参与该分支。

边界处理：若相对斜率恰为 −10%，归入下行期（保守）；若恰为 +50%，归入上升期；CV 恰为 30% 归入高波动。边界规则写进代码，避免不同实现给出不同标签。

### 2.5 步骤 4｜右截断敏感性（D4）

把 2016—2025 十个点（含右截断）做同样回归：斜率 −351.04、相对斜率 −28.94%、CV 84.96%，评级仍是下行期。这个对照不是备选口径，而是反例：它证明「纳入缺登年」会明显放大斜率的绝对值与 CV，让「下行」看起来比实际更陡、更不稳。

因此本件把主窗口锁在 2013—2022，把 2016—2025 只放进 `window_alt_truncated` 作证据，不进评级。

| 趋势分析 | 斜率 + CV | 不能预测 |
| 跨区域可比 | 相对斜率 | 需各城市同窗口 |
| 当前状态 | 截至 2022 | 2023 后不可用 |

### 3.6 城市子集热度的可行性

理论上可以对每个城市各跑一次回归，得到「深圳下行、广州平稳」等标签。但本件没有把城市热度写进产物，原因是样本量：惠州 1,594 家分到 10 年，年均约 159 家，单年波动很容易把 CV 推到 60% 以上，标签会随窗口轻微移动而翻转。城市热度若要上线，必须先做最小样本量门槛（例如年均 ≥500 家），否则标签不可信。

### 3.7 阈值敏感性的定性说明

相对斜率 −14.63% 距离 −10% 阈值只有 4.63 个百分点。若把窗口改成 2014—2022（去掉 2013），斜率会略缓；若改成 2012—2022（多加一年），斜率会略陡。无论哪种，只要不纳入 2023—2025，评级仍会是下行期。真正的翻转风险来自「纳入截断年」：那会把相对斜率推到 −28.94%，虽然仍是下行，但幅度失真。阈值本身不敏感，窗口才敏感。

### 3.8 两条时间轴的区分

| 时间轴 | 来源 | 用途 | 本件是否使用 |
|---|---|---|---|
| 成立年 | 底册成立年 | 新增/热度 | 是 |
| 事件年 | 专利/融资/新闻 | 活跃度 | 否 |
| 入库年 | 无 | 平台运营 | 否 |
| 注册年 | 无独立列 | 工商口径 | 近似成立年 |

热度必须用「成立年」，不能用「事件年」。事件年衡量的是「某年有没有动作」，一家 2005 年成立的老企业 2024 年申请专利，会推高 2024 年的事件年计数，但它不是新机构。把事件年当新增，会把成熟企业的日常动作误读为市场进入。

## 五、王惠方法对照

### 5.1 王惠方法的原始表述（转述）

王惠把「市场热度」定义为新增序列的方向与稳定性：先对年度计数做线性回归取斜率，再除以均值得到相对斜率；同时用变异系数衡量年际波动。评级规则为四档：相对斜率高于 +50% 为上升期；低于 −10% 为下行期；中间区间按 CV 30% 分为「平稳（低波动）」与「平稳（高波动）」。其核心主张是「先看方向、再看稳定」，反对只用首末差值。

### 5.2 本件与王惠的逐项对照

| 对照项 | 王惠方法 | 本件实现 | 是否一致 |
|---|---|---|---|
| 方向度量 | OLS 斜率 | OLS 斜率 | 一致 |
| 归一化 | 斜率/均值 | 斜率/均值 | 一致 |
| 波动度量 | CV | CV（总体标准差） | 一致 |
| 上行阈值 | +50% | +50% | 一致 |
| 下行阈值 | −10% | −10% | 一致 |
| 高波动阈值 | 30% | 30% | 一致 |
| 窗口 | 近十年 | 2013—2022 | 形式一致、端点不同 |
| 数据源 | 演示库 | gkx | 按 v6 换源 |

### 5.3 阈值为何原样保留

阈值是评级语义的一部分，换源不应顺手改阈值，否则新旧两版无法对话。本件原样保留 +50%/−10%/30%，只改窗口与源；这样「下行期」三个字在两版里是同一个含义，差异只来自数据。若未来要调阈值，必须单独出变更说明，不能夹在换源里。

### 5.4 窗口选择的分歧与处理

王惠原文用「近十年」，旧稿实现为 2017—2026（含进行年 2026）。本件改为 2013—2022，理由是 gkx 底册 2023 年后右截断，含当年会把缺登当下跌。这一改动与王惠的「近十年」形式一致（都是十个完整年），只是端点后移。若甲方坚持「含当年」，本件可提供 `window_alt_truncated` 的结果，但必须标注「受右截断影响，不作评级」。

### 5.5 选用建议

**建议采纳本件实现，理由有三。** 其一，阈值与王惠完全一致，评级语义不变；其二，窗口用十个完整年，避免了「含进行年」的右截断偏差；其三，所有中间量（均值、std、斜率、CV）都落盘，可比可复核。

不建议直接采用旧稿的 2017—2026 窗口：它把 2026 年这个几乎没有数据的年份放进回归，斜率会被缺登拉陡，且每年重跑都会变。也不建议改用「首末差值」：它对端点异常过于敏感，且丢掉了中间八年的信息。

若甲方要求「当前热度」，建议在本件标签旁加一句「截至 2022，2023 年后待补」，而不是把 2023—2025 硬塞进回归。后者会让标签看起来更「新」，但数字更假。

### 5.6 与旧稿的结论对照

| 项 | 旧稿 | 本件 | 结论 |
|---|---|---|---|
| 斜率 | −294.9 | −305.34 | 同向，幅度略陡 |
| CV | 44.0% | 46.07% | 同向，波动略高 |
| 评级 | 下行期 | 下行期 | 不变 |
| 窗口 | 2017—2026 | 2013—2022 | 不可直接比 |

结论：换源不改变「下行期」判断，改变的是幅度与可信窗口。旧稿的「含 2026」不可复用，本件的「截至 2022」必须写进 UI。

## 附录 G　常见误读与纠正

**问：下行期是不是说市场在萎缩？** 严格说，是「新增机构数在窗口内年均下行 14.63%」。它不等于「存量萎缩」，也不等于「需求萎缩」；存量可能仍在增长，只是增速放缓。

**问：为什么不用 2023—2025？** 因为这三年成立年右截断（218/66/12），纳入会把缺登当下跌，斜率与 CV 都会失真。

**问：标签能不能按月更新？** 不能。底册只有年，且右截断未解决；按月更新只会让标签更不稳定。

**问：CV 46.07% 算高吗？** 高于 30% 的高波动阈值，但本件已判下行，CV 不改变分支。它只说明年际波动大，单年数据不宜过度解读。

**问：深圳与其他城市能直接比标签吗？** 只有在同窗口、同阈值、样本量足够时才可比。惠州年均样本小，标签容易翻转，不建议直接比。
