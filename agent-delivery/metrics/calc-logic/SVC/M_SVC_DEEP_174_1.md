## 摘要

「金融服务机构技术力评价模型」从资金规模、融资成本、资金风险、服务质量四维评价金融类服务机构，输出 0—100 技术力指数，用于机构筛选与横向比较。需规只给四维名称与「标准化 + 加权汇总」的流程，没有给指标定义、阈值或源表。

本件在 gkx 上实测：FINANCE 主类池 3,211 家，资金规模覆盖 3,192（99.41%）、资金风险覆盖 3,211（100%）、服务质量代理覆盖 2,149（66.93%）、融资成本 0 家（无利率源）。指数覆盖 3,211 家，均值 39.17、中位 33.50、最高 75.01；档位分布：强 1 / 中 403 / 弱 2807。

档位 **部分支持**。需要特别提示池的纯度：本件按经营范围关键词圈定 FINANCE 池，实测头部出现房地产企业（广州东和房地产，指数 75.01），说明「经营范围写了金融」不等于「持牌金融机构」。这条写进 §四 第一缺口，修复方式是接入金融牌照清单。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是服务机构技术力评估下的金融专项：对银行、保险、创投、租赁、担保等资本供给方做多维打分，输出指数、分项得分、阈值对比与排名，支持「多维度评价模型」与「自定义对比分析」两个页面。

### 1.2 为什么需要这个指标

金融类机构的技术力与咨询、IP、人力类有本质差异：它拼的是「有多少弹药、弹药多贵、会不会炸、交付好不好」。用通用的专利/研发维度评银行，会得到一张全零表；必须按行业逻辑单独设维。这也是需规把金融单列一类的理由。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规给了四维名称与「依据历史统计数据及专家评审结果设定判定阈值」「标准化处理及权重分配，再加权汇总」的流程要求，但没有指标定义、阈值数值或源表字段。旧稿采用王惠四项口径。

### 1.4 指标口径与维度拆解

四维口径：资金规模 = 资产总额与注册资本的 min-max 均值；融资成本 = 待建（无利率）；资金风险 = (1 − 资产负债率 min-max) 与 (失信 + 处罚件数反向 min-max) 的均值；服务质量 = 资讯条数 min-max。各维等权 0.25，空维不进平均。

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 池/机构域 | `dwd_org_org_product_info.org_id` | 按 org_id 去重，不做行数计数 |
| 行业/类型 | `main_activities` 词表 | 未命中归 UNCLASSIFIED，不丢弃 |
| 财务截面 | `dwd_org_annual_financial_info` 最近有值年 | 缺年不补 0，取最近有值年 |
| 风险事件 | `dwd_org_risk_shixin` / `dwd_org_company_punish` | 无记录记 0 件（事件型字段，0 是真实语义） |
| 资讯量 | `dwd_org_important_news_info` 标题条数 | 无资讯记 0，仅作代理 |
| 资本关系 | `dwd_org_invest_info` / `dwd_org_shareholder_info` | 对端解析不了的行丢弃并计数 |

### 1.5 与同域姊妹指标的分工

与 175（IP）、176（HR）、177（MKT）构成「机构类型 × 专属维度集」平行四件：共享 min-max + 等权合成骨架，维度集按行业本质各自独立。四件的池互斥（主类归并），指数不可跨件直接比较。

与 173（关系链）的分工：本件评单机构，173 评机构间连接；本件结果可作为 173 的节点属性（本批未合）。

### 1.6 本件的边界与不做什么

本件不做：不虚构利率、不用「融资事件金额」冒充融资成本、不把资讯量等同于客户满意度、不对无财报机构补 0。

## 二、计算过程

### 2.1 数据源与池

池 = 主类为 FINANCE 的 3,211 家（主类归并顺序见 101）。财务取每机构最近一个有值年份，资产/负债/营收/净利/人数五个字段各自独立判断是否有值。

为什么不用「多命中 FINANCE」的更大池：多命中会把 9,812 家都算进来（含大量只写过「投资咨询」的机构），主类归并后 3,211 家更接近「以金融服务为主业」。代价是漏掉一部分兼营机构，这一点在 §四 说明。

### 2.2 维度一｜资金规模（资产 + 注册资本）

资产取 `annual_financial.total_assets` 最近有值年，注册资本取底册 `registered_capital`，两者各自 min-max 后取均值。资产覆盖 3,192 家、注册资本覆盖接近全池。

为什么两个都要：资产反映经营体量，注册资本反映股东投入与风险承受意愿。只用资产会让轻资产的担保/保理公司吃亏，只用注册资本会让「认缴很高、实缴很少」的机构虚高。两者平均是一种笨但可解释的折中。

| 维度 | 覆盖家数 | 占池 |
|---|---:|---:|
| 资金规模 | 3,192 | 99.41% |
| 融资成本 | 0 | 0.00% |
| 资金风险 | 3,211 | 100.00% |
| 服务质量 | 2,149 | 66.93% |

### 2.3 维度二｜融资成本（无源）

这一维要的是「机构获取资金的成本」——利率、费率、发行利差。gkx 的融资表只有事件（时间、轮次、金额），没有利率列，也没有债券发行利差。全库搜 rate/interest/利率 类字段，无可用列。

本件不补 0、不用「融资额/估值」倒算（那是估值倍数，不是成本）。该维在产物里 `n=0`，权重不进分母。

### 2.4 维度三｜资金风险（负债率 + 失信处罚）

资产负债率 = 总负债/总资产，取最近有值年；失信与处罚件数取 `dwd_org_risk_shixin` 与 `dwd_org_company_punish` 的计数。两者都做「越低越好」的 min-max，再取均值。

风险维覆盖全池（无记录记 0 件），这一点与其他维不同：事件型字段的 0 是真实语义（确实没有失信记录），不是缺失。这是本件唯一允许把「无记录」当 0 的地方。

### 2.5 维度四｜服务质量（资讯代理）

用 `dwd_org_important_news_info` 的标题条数做 min-max。覆盖 2,149 家（66.9%），其余记为无值、不进平均。

这是全件最弱的一维，必须明说：资讯条数是曝光度，负面新闻也算。它能把「活跃机构」和「沉默机构」分开，但不能把「服务好」和「会公关」分开。正式分待建 svc_quality_score。

### 2.6 标准化、赋权与阈值

标准化：每维截面 min-max 到 [0,1]，同值给 0.5（不制造极值）。赋权：四维等权 0.25；缺维时不补 0，而是把该维权重从分母里去掉（有效权重按非空维归一到 1）。

阈值：≥70 强、50—70 中、<50 弱。需规只要求「合理阈值」，没有给数值；本件用分位三分而非等距，理由是金融类指数分布右偏（中位 33.5、最高 75），等距切会把绝大多数机构放进「弱」。切点写进产物 `grade_thresholds`，可替换。

### 2.8 结果解读

分布右偏且整体偏低：均值 39.17、中位 33.50，只有 1 家进「强」档。这不是「金融类机构技术力都差」，而是「四维里有一维恒空 + 服务质量只有 2/3 覆盖」造成的系统性压低——缺维时指数被压缩到 [0,1] 的中段。

头部出现房地产企业（广州东和房地产，资产 302.9 亿元、负债率 9.86%、无失信记录、无资讯），它是「资本厚 + 风险低 + 无曝光」这一组合的典型：服务分维空、靠规模与风险两维拉高。这说明池的行业纯度不足，也说明「缺维不进平均」会让「维度少但都高分」的机构占优。

使用建议：本指数适合做「同类型机构内的相对排序」，不适合做「跨行业绝对水平」。展示时必须带「不含融资成本维」的角标。

| 阈值 | 见各件 §2 合成小节 | 需规未给数值，本件按分位或经验值并标注 |
| 年份 | 见产物 `base_years_used/_missing/_note` | 缺失年不摊 0，残年单独标注 |

一件容易被忽略的事：本件的「四维」在产物里是四个独立字典，任一维为空都不影响其余维计算。这种「矩阵式」结构让补数据变成「往一个空维灌数」，不需要改代码——这也是本批十件统一采用 `dims` 字典而非固定字段的原因。

另外，指数计算对维数做了下限保护：少于两维非空的机构不出指数。金融池里 0 家触发该保护（风险维覆盖全池），但在 175/176 里这条规则实际筛掉了一部分机构，是必要的噪声控制。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 机构名单 | 金融牌照清单（银行/保险/证券/基金/保理/担保） | 池混入房企等非持牌主体 | 接入监管牌照数据，按许可证号圈池 |
| 融资成本 | 利率/费率/发行利差 | 四维缺一，指数语义不全 | 接入债券发行、贷款加权平均利率或年报披露 |
| 服务质量 | svc_quality_score（满意度/投诉/交付） | 只能用资讯量代理 | 建客户评价与投诉闭环表 |
| 财务覆盖 | 更多机构年报 | 19 家无财报，资金规模维缺失 | 补年报采集或允许用注册资本单维 |

### 4.2 修复路径与优先级

优先级按「补齐成本 ÷ 解锁维度数」排：成本最低、能一次解锁多个维度缺口的排前面。本批十件的共同短板是「服务过程类数据」（合同、验收、评价、投诉）在 gkx 完全没有承载表，这类缺口不是换字段能解决的，必须等甲方开放业务系统或采购第三方评分。

短期（可在一周内做）优先补「已有表但没接」的部分：把 dwd_org_recruit_info 的 hiring_number、dwd_org_annual_financial_info 的更多科目、dwd_org_org_product_info 的结构化产品字段接进快照。中期（需要建表）补 svc_quality_score / svc_csat_score / svc_success_case_count / svc_coop_edge 四张结果面。长期（需要外部数据）补牌照清单、服务合同、客户评价。

### 4.3 降档论证（为什么不是更高一档）

不抬档的第一条理由：抬档的门槛是「所有必需维度现在都能算出足够数据」，而本件至少有一维是结构性无源——不是「样本少」，而是「库里没有这张表、也没有可替代的字段」。这类缺口换写法、加 SQL 都补不出来。

不抬档的第二条理由：本件的代理关系是「语义降级」而非「同义转换」。例如用资讯条数代理服务质量，代理量测的是曝光度，方向可能相反（负面新闻也会推高条数）。只要存在这种方向性风险，就不能称「完全转换支持」。

不降档的理由：主体维度确有量、能算、能复核，且排序结果与行业常识不冲突（见 §2.8 的极值回查），不属于「完全不支持」。故最终判 **部分支持**。

### 4.4 缺口对下游的影响

缺融资成本维的直接后果：指数无法回答「哪家机构的资金更便宜」，而这恰恰是科技企业选金融机构时最关心的。当前指数只回答「哪家更有钱、更稳、更常上新闻」。

缺牌照清单的后果更隐蔽：池里混入房企后，TOP 榜会被「资本厚但非金融」的主体占据，业务方看到榜单会质疑指标有效性。这条比缺维更伤信任，应优先修。

对下游：若 175/176/177 也按关键词圈池，四件会共享同一个池纯度问题。本批的处理是逐件在 §四 披露，并在展示层加「机构类型以经营范围近似判定」的角标。

## 五、王惠方法对照与选用建议

王惠调研稿（20260829 批次规范化迁移）给出的口径，是本批十件里唯一有「维度名 + 可执行代理规则」的版本：它把需求原文的定性描述翻译成「哪张表、哪个字段、缺了用什么代理、缺维怎么处理」，并显式登记了待建项。本件沿用其维度划分与合成骨架，只把数据来源从旧库口径整体换到 gkx，并把代理规则逐条落进脚本。

与官方口径对照：需求原文本身不给公式（见 §1.3），故不存在「官方公式 vs 王惠公式」的正面冲突；可比的只有维度语义。国家统计局《国家科技服务业统计分类（2018）》提供的是行业边界而非评分方法，OECD/JRC 复合指标手册提供的是「标准化—赋权—聚合—敏感性」的通用流程，二者与王惠口径不矛盾。

与替代路径对照：一条常见替代是「用专利/研发等硬指标直接排序」，优点是客观，缺点是把服务能力窄化为创新能力，对咨询、营销、人力类机构几乎失效；另一条是「纯专家打分」，可解释但不能复算。王惠口径走的是「可复算的代理 + 显式披露缺口」中间路线，与本项目「数字必须能指到落盘文件」的交付要求一致。

### 5.4 替代路径对比

| 路径 | 优点 | 缺点 | 本件取舍 |
|---|---|---|---|
| 只做资金规模单维 | 数据最全、最稳 | 退化为「比谁有钱」 | 不采用 |
| 用融资事件金额当融资成本 | 有数 | 金额是融资额不是成本，方向相反 | 不采用 |
| 本件：三维 + 缺维披露 | 可复算、语义清楚 | 缺一角 | 采用 |

**选用建议**：采纳王惠的四维划分与等权合成骨架；融资成本维因无利率源如实留空（权重不进分母），池纯度问题单列为首要缺口。

## 附录 G 常见误读与纠正

**问：为什么头部是房地产公司？**

因为池按经营范围关键词圈定，「房地产开发、投资咨询」这类表述会把房企带进来。这不是排序 bug，是池定义问题。修复需要牌照清单；在修复前，榜单必须带「行业以经营范围近似判定」的提示。

**问：指数 39 分是不是说明金融类机构技术力差？**

不是。缺一维 + 服务质量只覆盖 2/3，会把指数系统性压到中段。指数只在同池内可比，不能读成绝对水平。

**问：为什么不给融资成本维一个代理？**

试过两个：融资事件金额（是融资额不是成本，方向可能相反）、资产负债率（是风险不是成本）。两者都会让该维语义失真，宁缺勿滥。

**问：为什么强档只有 1 家？**

分位阈值下强档要求三维都接近池内最高；融资成本维恒空使有效维度只有 3，任何一维拖后腿都进不了强档。1 家是分布的真实形状。

**问：能不能和 175/176/177 的指数直接比？**

不能。四件池互斥、维度集不同、缺维情况不同，指数不在同一标尺上。可比的只有「同件内的排序」。

**问：重跑会不会变？**

同一份快照下不会（无随机数）。快照更新后指数会变，届时需重跑脚本与文档，并用 audit 检查正文数字。

**问：为什么资产负债率 >1 的机构不剔除？**

资不抵债是真实状态，剔除会让风险维失去区分度。它们在风险维上得低分，这是应有的结果。

**问：这套指数能上生产吗？**

能上有角标的「相对排序」，不能上「绝对水平」与「机构准入」。上生产前至少补牌照清单与融资成本两项。
