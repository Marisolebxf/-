## 摘要

「投融资动态」在需求里是一条年度柱线：每年多少笔、合计多少钱、投早投晚各多少。旧稿用演示库的 `svc_org_finance_event` 把 INVEST（9,120）与 FINANCING（6,635）两类事件相加，得到 15,755 件；换到 gkx 后，能用的只有 `dwd_org_financing_info`，它没有事件类型列，也没有金额，只有融资事件的日期与主体。

实测：表内 25,654 行，池内 24,391 件（占 95.08%），覆盖 5,910 家机构（占池 13.39%），日期从 1980-01-03 到 2026-07-17，日期覆盖率 100%，无未定日期事件。年度峰值 2016 年 3,704 件，2025 年 587 件；三个区间 2015—2018 合计 11,025、2019—2022 合计 7,052、2023—2025 合计 2,681。

判档 **部分支持**：数量轴可算、可对账，金额轴与投资侧完全缺失。需求原文若坚持「投融资金额」，本件只能给「融资金额不可用」的空轴，不能用 0 填充——0 会被读成「融资金额为零」，而事实是「金额列没有值」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是产业服务链分析页面的「投融资动态」：年度融资事件柱图、融资事件列表、机构融资次数排名，以及（需求要求的）金额与轮次分布。算法侧对应服务机构基础指标模型的「投融资动态资讯」；展示侧是页面中部的折柱混合图。

### 1.2 为什么需要这个指标

融资事件是服务机构「被资本认可」的直接信号。新增机构数回答「有多少人进来」，融资事件回答「资本愿不愿意为它们付费」。两者结合，才能看出「进入多但融资少」的结构性问题——本件实测覆盖 5,910 家，占池 13.39%，说明绝大多数服务机构从未发生可观测融资。

另一个原因是时间锚：融资事件有精确日期，可以做年度甚至月度序列，不受「成立年右截断」影响。2026 年虽然只有 233 件，但它是「采集时点未过完」的残年，不是缺登，处理方式与成立年完全不同。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规只写「投融资动态资讯」，没有定义「投融资」是否含 IPO/并购/债权、金额是披露值还是估算值、同一轮多投资方算一笔还是多笔。旧稿用 calc-logic 钉了「事件表按 metric_id 过滤后计数」，本件只能钉「融资表按日期分组计数」，投资侧无表可钉。

### 1.4 指标口径与维度拆解

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 事件日期 | `dwd_org_financing_info` 日期列 | 无日期不入序列（实测 0 件） |
| 事件主体 | `org_id` | 池外事件不计入池内口径（1,263 件） |
| 年度计数 | 日期按年分组 | 2026 残年不进趋势 |
| 金额 | 金额列 | 整列空，金额轴禁用 |
| 轮次 | 无轮次列 | 不可用 |
| 事件类型 | 无 INVEST/FINANCING 列 | 不可复刻双口径 |
| 投资侧 | 无独立表 | 不可用 |

口径边界：一件事件只归一年；同一机构同年多轮各计一件；池外事件不计入主口径但单独披露；金额缺失不补 0。

### 1.5 与同域姊妹指标的分工

与 `M_SVC_ORG_NEW_CNT`：本件是事件年，后者是成立年；两条时间轴不能混。2024 年成立的机构可能在 2025 年融资，事件年与成立年天然错位。

与 `M_SVC_ORG_TECH_SCORE`：本件不计入技术分（技术分用专利/研发/案例），融资只作独立展示。

与 `M_SVC_ORG_TOTAL`：本件分母仍是 44,153，覆盖 5,910 家；不改变池。

### 1.6 本件的边界与不做什么

不做金额（列空）；不做轮次（无列）；不做投资侧（无表）；不做 IPO/并购拆分（无类型）；不把 2026 残年画进趋势；不把池外 1,263 件并进主口径；不估算未披露金额。

## 二、计算过程

### 2.1 方法选择：事件表按日期分组，而不是「机构首次融资年」

方法选择的约束是表结构：gkx 只有融资事件表，没有「机构融资状态」宽表。因此唯一可复算的口径是「事件级计数」：一条融资记录算一件，按事件日期归年。这个口径能回答「每年发生多少笔」，不能回答「多少家机构首次获得融资」——后者需要按机构取 min(日期)，是另一个指标。

放弃的方案是「按机构去重计数」。若按机构去重，2016 年的 3,704 件会变成「当年有融资的机构数」（远小于件数），序列的含义从「事件数」变成「机构数」，与需求里的「投融资动态」（事件流）不符。本件保留事件级，机构覆盖数只作辅助指标披露。

### 2.2 步骤 1｜事件抽取与池内过滤（D1）

融资表 25,654 行，按 org_id 与池（44,153）求交，得池内 24,391 件、池外 1,263 件。池外事件不丢弃，单独记入 `population.events_outside_pool`，原因是它们可能属于「尚未入池但已融资」的机构，未来扩池后应自动纳入。

池内 24,391 件覆盖 5,910 家机构，机构覆盖率 13.39%。这个比例说明融资是少数机构的事件，不能把「平均每家融资 4.13 件」当成普遍事实——分母里 86.61% 的机构是 0 件。

### 2.3 步骤 2｜日期锚与年度序列（D2）

日期锚：最早 1980-01-03，最晚 2026-07-17，24,391 件全部有日期，覆盖率 100%，无未定日期事件。这在本批十件里是最好的时间锚——成立年有 21 家缺失，融资日期一件不缺。

按年分组得 43 个有值年份。2000—2025 序列从 36 件增至 2016 年峰值 3,704 件，再降至 2025 年 587 件。1980—1999 年段事件极少（个位数到十几件），只进全量序列、不作趋势。

### 2.4 步骤 3｜峰值、区间与同比（D3）

峰值 2016 年 3,704 件；2015 年 2,490、2017 年 2,724，形成一个三年平台。区间累计：2015—2018 合计 11,025、2019—2022 合计 7,052、2023—2025 合计 2,681，三段递减。

同比：2014 年 +115.62%、2015 年 +140.58%、2016 年 +48.76% 为上升段；2017 年 −26.46%、2018 年 −22.65%、2019 年 −24.49% 为回落段；2020 年 +16.22%、2021 年 +4.54% 小幅反弹；2022 年 −13.14%、2023 年 −27.58%、2024 年 −27.8%、2025 年 −33.14% 再次下行。

### 2.5 步骤 4｜金额轴与投资侧的处置（D4）

金额列 `amount_nonnull=0`，整列为空。这不是「金额都很小」，而是「一列都没有值」。处置方式是禁用金额轴：产物里 `amount_nonnull=0`、`amount_note` 写明「金额列整列为空，金额轴禁用」，UI 上金额 tab 显示「数据未接入」而不是「0 元」。

投资侧：gkx 无独立投资事件表，也没有 INVEST/FINANCING 类型列。旧稿的 9,120 件 INVEST 事件在 gkx 无对应，不能把融资表复制一份当投资侧。产物 `gaps.invest_side` 明确写「投融资合成口径只能覆盖融资侧」。

### 2.6 步骤 5｜产物与复现（D5）

### 3.2 字段级核验

核验一：池内 24,391 + 池外 1,263 = 表内 25,654，行数与源表相等。核验二：24,391 件全部有日期，`undated_events=0`。核验三：年度序列 1980—2026 全部相加等于 24,391。核验四：三个区间 11,025+7,052+2,681 = 20,758，加上 2014 年及以前的 3,633 件等于 24,391。核验五：覆盖机构 5,910 / 池 44,153 = 13.39%。

第四条核验需要解释：三个区间接续但不覆盖全序列，2015 年之前的事件不在任何区间内。这是有意设计——区间用于「近十年平台期」的读法，全序列另存 `series_all`。

| 残年（2026） | 不进趋势，`base_years_missing` 标注 |
| 池外事件 | 单独披露，不并主口径 |
| 多轮融资 | 一件一轮各计，不按机构去重 |
| 旧稿双口径 | 不复制融资表冒充投资侧 |

### 3.6 覆盖率的两种读法

13.39% 是「有融资事件的机构占池」的比例，不是「获得融资的机构占全体服务机构」的比例。前者分母是本池（经营范围口径），后者分母应是官方认定的服务机构；本池含制造企业与高校，会把覆盖率拉低。发布时应写「本池内 13.39% 的机构有可观测融资事件」，不能写「深圳只有 13.39% 的服务机构融过资」。

### 3.7 事件年与成立年的交叉

| 组合 | 含义 | 是否可用 |
|---|---|---|
| 2020 成立 + 2023 融资 | 新机构三年内融资 | 可算，但样本小 |
| 2005 成立 + 2023 融资 | 老机构晚期融资 | 可算 |
| 无成立年 + 有融资 | 21 家缺失年机构 | 只进融资侧 |
| 有成立年 + 无融资 | 86.61% 的机构 | 只进存量侧 |

交叉表的价值在于识别「新机构融资率」，但本件不展开：右截断会让近年成立的机构被低估，交叉后会得到「越新的机构融资率越低」的假象。要做这个分析，必须先补成立年。

### 3.8 2015 年前事件的读法

| 区间 | 事件数 | 用途 |
|---|---:|---|
| 1980—2014 | 3,633 | 只作历史背景 |
| 2015—2025 | 20,758 | 主平台期 |
| 2015—2018 | 11,025 | 高峰段 |
| 2019—2022 | 7,052 | 回落段 |
| 2023—2025 | 2,681 | 近期段 |

2015 年前的事件数少，不代表当年没有融资，而是「当年有融资的机构大多已注销或未被底册收录」。这与成立年的左截断是同一个机制：当前快照只能看到「活到今天」的主体。因此 2015 年前的序列只作背景，不作趋势。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 金额 | 金额列整列空 | 金额轴、轮次金额不可用 | 接融资披露数据源 |
| 投资侧 | 无独立投资事件表 | 投融资合成口径只剩融资 | 接投资事件表 |
| 轮次 | 无轮次列 | 无法分早期/后期 | 接轮次字段 |
| 事件类型 | 无 INVEST/FINANCING | 无法复刻旧稿双口径 | 接类型列 |
| 池外机构 | 1,263 件主体不在池 | 覆盖被低估 | 扩池或补机构 |
| 2026 | 残年 | 不能作年度结论 | 等年末重跑 |

### 4.2 修复路径与优先级

P0：UI 金额 tab 显示「未接入」，不显示 0；P1：接轮次与金额字段，恢复「数量+金额」双轴；P2：接投资事件表，恢复投融资合成口径；P3：扩池纳入池外 1,263 件的主体。

### 4.3 降档论证（为什么不是更高/更低一档）

不抬档：金额与投资侧两项核心依赖都缺，需求里的「投融资」只能兑现一半。不降档：融资事件数量轴完整、日期锚 100%、可复现、可对账，且峰值与旧稿一致。落部分支持。

### 4.4 缺口对下游的影响

金额缺失让「融资总额」「平均单笔」两个常用指标不可用；投资侧缺失让「投融资合计」不可复刻旧稿；轮次缺失让「早期/后期占比」不可用。三者都不影响事件计数，但会让「投融资动态」在汇报里显得单薄——只有柱、没有额。

### 4.5 字段级缺口表

| 期望字段 | gkx 是否有 | 处置 |
|---|---|---|
| 金额 | 有列但全空 | 禁用 |
| 币种 | 无 | 不可用 |
| 轮次 | 无 | 不可用 |
| 投资方 | 无 | 不可用 |
| 事件类型 | 无 | 不可用 |
| 退出方式 | 无 | 不可用 |

## 五、结论与发布建议

本件可发布「融资事件年度计数」，不可发布「投融资金额」与「投资侧」。发布口径三句话：第一，24,391 是池内融资事件，不是投融资合计；第二，金额列整列为空，金额轴禁用，不得以 0 代替；第三，2026 年 233 件是残年，不进趋势。

建议 API 返回 `series_2000_2025`、`peak`、`time_anchor`，并在响应头写 `amount=unavailable`、`invest_side=unavailable`，让前端按能力渲染，而不是按 0 渲染。

## 附录 G　常见误读与纠正

**问：24,391 是不是投融资总数？** 不是。它只是融资侧事件；投资侧在 gkx 没有表。

**问：金额为什么是 0？** 不是 0 元，是整列没有值。产物里 `amount_nonnull=0`，UI 必须显示「未接入」。

**问：2026 年 233 件能不能算年度数？** 不能，采集时点未过完，是残年。它只用于「本年至今」的临时展示，不进趋势。

**问：池外 1,263 件为什么不并进来？** 它们的主体不在 44,153 池内，并进来会破坏「同池」约定；单独披露，等扩池后再纳入。

**问：覆盖 13.39% 是不是太低？** 分母含制造企业与高校，融资事件只覆盖市场化服务机构，比例低是结构性的，不是数据缺失。
