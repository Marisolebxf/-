## 摘要

密度是一个「先有点集、再有边集、最后才有一个数」的指标。点集换一次、边集换一次，同一个业务问题会给出相差一个数量级的答案，所以本件把三层口径全部写死并逐层披露。

| 读数 | 值 |
|---|---|
| 服务机构池 $P_0$ | 44,153 家 |
| 去孤立点 $P_1$ | 12,905 家（29.2279%） |
| 池内无向边 $E$ | 13,141 条 |
| 全池密度（每万对） | 0.1348 |
| 去孤立点密度（每万对） | 1.5783 |
| 两点集密度倍率 | 11.7065 |
| 最大连通分量 | 7,040 家（占 $P_1$ 54.5525%） |
| 连通分量数 | 2,270 个，第二大为 33 家 |
| 平均度（$P_0$ / $P_1$） | 0.5952 / 2.0366 |
| 最大度 | 329 |
| 孤立点 | 31,248 家（70.7721%） |
| 投资边占内部边 | 43.1246% |
| 股东边新增边 | 56.8754% |
| 深圳域内边占比 | 59.204% |
| 判档 | 部分支持 |

第一件要说清的事是**点集敏感性**。全池 44,153 家里有 31,248 家一条边都没有，占 70.7721%；把它们放进分母，密度被摊薄到 0.1348/万对；剔掉之后只剩 12,905 家，密度立刻变成 1.5783/万对，差 11.7065 倍。两个数都「对」，因为它们回答的不是同一个问题：前者是「整个服务生态有多疏」，后者是「已经在网里的机构之间有多密」。发布时必须二选一写明，不能只给一个数让读者自己猜口径。

第二件是**边集语义**。13,141 条边里 5,667 条只由投资边构成（43.1246%），股东边在投资边之外又新增 7,474 条（56.8754%）。两类边都是股权关系：投资是「A 出资给 B」，股东是「A 是 B 的股东」。它们与「A 为 B 提供知识产权/检测/技术转移服务」不是一回事。把股权密度读成服务密度，会系统性低估服务关系——因为大量服务交易根本不产生股权。

第三件是**连通结构**。图不是一张大网，而是 2,270 个碎块，最大一块 7,040 家（占去孤立点后的 54.5525%），第二块只有 33 家，其余全是长尾小分量。这说明服务机构之间的关系高度依赖少数集团型主体（最大度 329），一旦把这些主体从图里拿掉，整个网络会散成大量孤岛。密度的「平均」在这里几乎没有解释力，必须同时给分量结构。

### 1.2 为什么需要「关系链密度」

服务机构的价值不在单家机构的规模，而在它能把多少企业连起来。一家知识产权代理机构如果只服务 1 家企业，它是「一个供应商」；如果服务 300 家，它是「一个节点」。密度就是把这种「节点性」从个体层面抬到生态层面的量：它衡量的是整个服务网络里，任意两家机构之间存在关系通道的概率。

这个量在业务上有两个直接用途。第一，招商与培育：密度低的城市，说明服务机构之间缺少协作，引入一家头部机构可能带来整片连接；密度高的城市，增量机构的边际价值低，重点应转向「补短板环节」。第二，风险传导：关系越密，单点失效的波及面越大——这一点在姊妹件 `M_SVC_RELATION_RISK` 里展开。

### 1.3 口径定义

图 $G=(V,E)$ 为无向简单图，$V$ 为服务机构池，$E$ 为池内两端都可解析的关系边（投资边与股东边合并去重，方向忽略）。密度按标准定义：

$$\text{Density}(G)=\frac{2|E|}{|V|(|V|-1)}=\frac{|E|}{\binom{|V|}{2}}$$

平均度与归一化平均度：

$$\bar{k}=\frac{2|E|}{|V|},\qquad \bar{k}_{\text{norm}}=\frac{\bar{k}}{|V|-1}=\text{Density}(G)$$

三条补充约定写进产物 `point_sets` 与 `density`：

第一，**点集三档**。$P_0$ 为全池 44,153 家（含孤立点，孤立点记度 0 并计入分母）；$P_1$ 为度 $\ge 1$ 的 12,905 家；$P_2$ 为最大连通分量 7,040 家。本件主口径报 $P_0$ 与 $P_1$ 两档，$P_2$ 只作结构描述，不替代主口径——巨片内部密度天然高于全图，用它当主口径会系统性抬高读数。

第二，**归一化分母**。平均度归一化一律用 $n-1$（不是 $n$），$P_0$ 为 44,152、$P_1$ 为 12,904。这与 §3.60 对图类指标的归一化要求一致。

第三，**孤立点不猜**。31,248 家孤立点不补边、不按均值插补、不剔除出分母后静默改口径，而是显式记 `degree_buckets["0"]` 并在正文披露。

### 1.4 计算公式与本批实现式

```python
def density(n, m):                  # n 节点数，m 无向边数
    return m / (n * (n - 1) / 2) if n > 1 else None

def mean_degree(n, m):
    return 2 * m / n if n else None

def norm_mean_degree(n, m):
    return (2 * m / n) / (n - 1) if n > 1 else None   # 分母 n-1，不是 n
```

实现上最容易写错的是 `2m/n` 与 `m/n` 的混淆：无向图每条边贡献 2 个度，漏乘 2 会让平均度整体减半，而密度公式恰好不受影响（密度的分子是边数不是度数和），于是「密度对、平均度错」这种组合极难被肉眼发现。本件在产物里同时落 `mean_degree` 与 `density`，并用恒等式 `norm_mean_degree == density` 做自检，两者在 $P_0$、$P_1$ 上都吻合。

## 二、计算过程

### 2.1 池的构造与去重

脚本先连 gkx，拉 `dwd_org_org_product_info` 的机构 id 与名称，按 `org_id` 去重得到 44,153 家。这一步看似平凡，但决定了后面所有分母：如果按「机构—产品」行数当池规模，同一家机构有多个产品会被重复计数，密度会被系统性压低。产物里 `point_sets.P0.n` 明确写的是 `org_id` 去重后的家数，不是行数。

池里还有一层地理信息。按注册地切分，深圳 25,597 家、广州 12,641 家、东莞 4,300 家、惠州 1,594 家，四市合计 44,132 家，剩余 21 家注册地不在四市或为空，只进全池分母、不进城市切片。这个差额很小，但必须在表里对上，否则「分城市加总 ≠ 全池」会被读成计算错误。

### 2.2 边的构造与合并

投资边从 `dwd_org_invest_info` 取 `org_id` 与 `inv_org_id` 两端，股东边从 `dwd_org_shareholder_info` 取 `org_id` 与 `shareholder_org_id`。两条边表都先过滤「至少一端在池内」，得到触碰池的投资边 41,888 行、股东边 372,205 行；再过滤「两端都在池内」，得到 5,682 行与 16,217 行。

两端解析率是本件最刺眼的质量指标：投资边只有 13.5647% 的原始行两端都能落到池内，股东边只有 4.357%。原因不是池太小，而是股权边的另一端大量是企业而非服务机构——服务机构池只是全底册 189,116 家企业的一个子集，投资方与被投方多数落在池外。这不是错误，但意味着**这张图是「服务机构之间的股权子图」，不是「服务机构的全部对外关系」**。

合并时按无向对去重：`(min(a,b), max(a,b))`，同一对既有投资边又有股东边只留一条，且不计重数。去重后 13,141 条边，其中仅由投资边构成的 5,667 条（43.1246%），股东边新增 7,474 条（56.8754%）。这个拆分很重要：它说明股东边不是投资边的子集，两类边提供的是互补信息，任何只取其一的实现都会丢掉一半以上的边。

### 2.3 度分布与孤立点

$P_0$ 的度分布：度 0 共 31,248 家（70.7721%）、度 1 共 8,149 家、度 2—4 共 3,905 家、度 5—9 共 605 家、度 10 及以上 246 家（占 $P_1$ 的 1.9062%）。$P_1$ 里度恰为 1 的占 63.1461%，也就是说**即使只看「有边的机构」，近三分之二也只有一条边**。

这是一张典型的「核心—边缘」图：少数机构连了很多，绝大多数只连一条。最大度 329，即单家机构与其他 329 家池内机构各有一条边；它的存在让平均度 2.0366 变得没有代表性——中位数其实是 1。产物里因此同时给 `degree_buckets` 与 `max_degree`，而不只给均值。

### 2.4 连通分量

用并查集扫一遍边集，得到 2,270 个连通分量。最大分量 7,040 家，占 $P_1$ 的 54.5525%、占 $P_0$ 的 15.9446%；第二分量只有 33 家；其余 2,268 个分量平均不到 2.6 家。这个结构说明网络没有「中层」——要么在巨片里，要么在几个人的小圈子里。

巨片占比同时暴露了密度指标的脆弱性：如果只报巨片密度，读数会比 $P_1$ 更高；如果报全池，又被 70.7721% 的孤立点摊薄。本件选择两档并报，并明确 $P_2$ 不作为主口径。

### 2.5 城市切片

按机构注册地把边切成域内边（两端同城），得到深圳 7,780 条、广州 3,102 条、东莞 294 条、惠州 129 条。四市的密度差异不是线性的：惠州每万对 1.0161，看着最高，但它的池只有 1,594 家、域内边只有 129 条；深圳每万对 0.2375、广州 0.3883、东莞 0.3181。

这里必须提醒：小池子的密度极不稳定。惠州的 1.0161 只由 129 条边支撑，任何一条边的进出都会明显改变读数；把它读成「惠州服务关系最密」是过度解读。产物里同时给 `nodes` / `internal_edges` / `active_nodes`，就是为了让读者能看到分母有多小。

活跃率（有边机构占本市池）反而更可比：深圳 29.7457%、广州 25.5122%、东莞 9.3023%、惠州 11.0414%。深圳的活跃率最高，但密度低于广州，原因是深圳池大（25,597 家），分母摊薄效应更强。这两个读数放在一起，才构成完整的判断。

### 2.6 自检与恒等式

三条自检全部通过。第一，`norm_mean_degree == density` 在 $P_0$ 与 $P_1$ 上都成立（$P_0$ 为 1.348e-05、$P_1$ 为 0.000158，四舍五入后与密度一致）。第二，度分布各桶之和等于 44,153。第三，城市切片域内边之和 11,305 条小于全池 13,141 条，差额 1,836 条为跨城边，方向合理。

另外做了一次「仅投资边」的敏感性：只用投资边时 $E=5,667$、$P_1$ 会缩小到更少的活跃机构，密度随之下降；把股东边加回来，密度上升。两套结果都留在产物里（`edges.from_invest_only` 与 `edges.undirected_internal_edges`），供甲方判断「只算投资」还是「投资+股东」。

## 四、数据缺失情况

### 4.1 服务合作边：结构性无源（拒拟维）

gkx 的 280 张表里没有 `enterprise_cooperation`，`information_schema.TABLES WHERE TABLE_SCHEMA='gkx'` 逐字命中 0 行，模糊词 `%cooperat%` / `%supply%` / `%svc%` 的表名命中同样为 0。开发库 `gkxlumenx_dwd` 有同名结构但实测 0 行（结构与数据是两种事实，不能写成「无表」）。演示库有同名表且为全量装载，但按 20261021 铁律禁引，不构成支持。

**拒拟理由**：没有合作边，「服务合作关系密度」这一维无法计算。
**替代口径**：投资/股东边密度。
**与原文差别**：股权关系不等于业务合作。服务机构与企业之间最常见的关系是「购买服务」，这种关系通常不产生股权，因此替代口径会**系统性低估**服务关系密度；同时它会**高估**集团内部的紧密度（母子公司天然有股权边）。两个方向的偏差不对称，不能用一个系数校正。

### 4.2 密度时间序列：结构性无源（拒拟维）

`svc_metric_series` 在 gkx 不存在（0 行），投资/股东边也没有可靠的年份字段（只有 `create_time` / `update_time` 这类系统时间，不是业务发生时间）。因此不能出「2024 年密度 vs 2025 年密度」这样的序列。

**拒拟理由**：无时序承载表，边无业务时间。
**替代口径**：快照截面密度。
**与原文差别**：只能给单日截面，不能给趋势、环比、拐点；任何「密度在上升」的判断都无据。

### 4.3 服务类型分层密度：结构性无源（拒拟维）

`svc_org_card` / `svc_org_circle` 均不存在，服务机构的「服务类型」标签无承载表。因此无法回答「知识产权类服务机构的密度是否高于检测类」。

**拒拟理由**：无服务类型标签表。
**替代口径**：按城市切片。
**与原文差别**：城市切片替代服务类型切片，能回答「哪里密」，不能回答「哪类服务更密」。

### 4.4 两端解析率偏低

投资边两端解析率 13.5647%、股东边 4.357%。这意味着大量股权边的一端落在服务机构池之外，图中「池内边」只是全部股权关系的一个子集。这个缺口不是表缺失，而是**池定义与服务生态不重合**：服务机构的股东/被投方很多是普通企业。

后果：密度读数对池定义高度敏感。若把池扩到全底册 189,116 家，边数会大幅上升，但那时算的就不是「服务机构密度」而是「企业股权密度」。本件坚持服务机构池，并把解析率写进正文。

### 4.5 边无权重

两类边表都有金额字段，但金额单位未在表结构中标注（同族问题见 `M_ENT_RELATION_STRENGTH` 的单位争议）。本件因此只计边数、不用金额，密度是「二值边密度」，不是「加权密度」。这是一条主动放弃：加权密度需要可信的单位，否则权重会把结论带偏。

### 4.6 不得外推的三件事

1. **不得读作服务合作密度**：股权边与服务边是两种关系。
2. **不得用小池城市排名**：惠州 129 条边、东莞 294 条边，密度不稳定。
3. **不得把 $P_1$ 密度当全生态密度**：$P_1$ 已剔除 70.7721% 的孤立点。

### 4.7 停用与重估条件

出现以下任一情况应重估：① 合作边表入湖（可算真正的服务关系密度）；② `svc_metric_series` 入湖（可出时序）；③ 服务机构池定义变更（分母换了，全部读数重算）；④ 边表补上业务时间戳（可做增量密度）。

## 五、结论与发布建议

### 5.1 可用结论

第一，$P_0$ 44,153 家、$P_1$ 12,905 家、边 13,141 条，两档密度分别为 0.1348 与 1.5783（每万对）。第二，孤立点 31,248 家占 70.7721%，密度对点集极敏感，倍率 11.7065。第三，图碎成 2,270 个分量，巨片 7,040 家占 $P_1$ 的 54.5525%。第四，边全部来自投资/股东，服务合作维结构性无源，判部分支持。

### 5.2 发布口径（逐条写死）

| 项 | 必须写明的口径 |
|---|---|
| 点集 | $P_0$ 与 $P_1$ 双报，$P_2$ 只作结构描述 |
| 边集 | 投资 + 股东，无向去重，不含合作/供应链 |
| 归一化 | 平均度分母 $n-1$ |
| 孤立点 | 31,248 家，$P_0$ 计 0 并进分母 |
| 城市 | 同时给池规模与活跃率，密度不单独排序 |
| 权重 | 无权重，二值边 |

### 5.3 与旧稿的取舍

旧稿（镜像面）曾用演示关系图给出密度读数，本版不再引用。本版的两档密度都建立在 gkx 真实股权边上，档位仍判「部分支持」，但缺口从「数据不可信」换成「语义不匹配 + 时序缺失」——同一个档位、不同的理由，返工时不能照抄。

### 5.4 后续

三条路径：① 合作边入湖；② `svc_metric_series` 入湖；③ 服务机构池与服务类型标签定稿。三者任一落地都要重跑本件并重写两档密度——不是调参，是换口径。

## 附录 D　口径敏感性的量化过程

口径敏感性不是一句「很敏感」，而是可以算出来的。本件用三步量化：

第一步，固定边集 13,141 条，只改点集。$P_0$ 的 44,153 家给出 0.1348/万对，$P_1$ 的 12,905 家给出 1.5783/万对，倍率 11.7065。这个倍率完全来自分母：分母从 44,153 缩到 12,905（缩到 29.2279%），密度按 $1/n^2$ 放大，理论倍率约 11.7，与实测吻合，说明计算本身没有额外扭曲。

第二步，固定点集，只改边集。只用投资边时 5,667 条，用投资+股东时 13,141 条，边数涨 2.3189 倍；密度同比例涨，因为分母不变。这一步说明「边来源」对读数的影响是线性的，比点集影响小得多——但语义影响更大，因为股东边与投资边是两种关系。

第三步，固定全池，只改城市切片。深圳 7,780 条边、25,597 家，密度 0.2375；惠州 129 条边、1,594 家，密度 1.0161。惠州的密度是深圳的 4.2783 倍，但它的边只有深圳的 1.6581%。这个反例说明：小样本城市的密度不能参与排名，必须与池规模一起看。

三步合起来给出的结论是：**点集是第一敏感源，边集语义是第二敏感源，城市规模是第三**。发布口径必须先锁点集，再锁边集，最后才谈城市比较。
