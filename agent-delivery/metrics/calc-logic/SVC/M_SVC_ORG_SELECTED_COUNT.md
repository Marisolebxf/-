## 摘要

这不是一个「算不出来」的指标，而是一个「不应该算」的指标。页面上的「当前分析 N 家」来自前端内存里的勾选集合：用户勾了 12 家，N 就是 12；刷新页面，N 归零；换个用户，N 是另一个数。它既没有统计总体，也没有参考期，更没有跨用户可比性。

旧稿把它当成结果面的一条记录，试图从 `svc_*` 表里按 `metric_id` 查出 N。实测该 ID 在结果面恒 0 行，而且这个 0 是设计态、不是数据缺失——系统从来没打算为会话语义落库。gkx 侧同样没有承载表，280 张表中 `svc_*` 表族为 0。

本件的产物不做任何计算，只固化三条事实：①指标身份检验五项全否（无总体/无参考期/无去重/不持久/不可比）；②gkx 无承载表；③三个反事实候选（44,153 存量、25,597 深圳子池、埋点日均勾选）都不能冒充 N。判档 **完全不支持**，且这不是缺陷，是正确处置。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

原本挂在产业服务链分析页面的服务机构库列表：用户勾选若干机构后，右上角显示「当前分析 N 家」，点击进入对比/批量分析。它服务的是「当前这一屏」的交互，不是跨用户、跨时间的统计。

### 1.2 为什么需要这个指标

严格说，页面需要的是「当前选中了几家」这个交互反馈，不是「指标」。用户勾选时需要一个即时计数，避免重复勾选或漏选；这个需求是真实的，但它属于前端状态管理，不属于数据仓库。

把它误当指标的原因通常是「它在页面上有一个数字」。页面上的数字不都是指标：页码、进度条、选中数都是 UI 状态。判断标准是「换一个用户/换一天，这个数是否仍有同样含义」——N 不满足。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规只描述「当前分析机构数」的展示位置，没有定义总体、参考期、去重规则。旧稿把它塞进结果面，是工程上的「顺手」，不是需求要求；2026-10-13 的废止决定正是把这层顺手纠正过来。

### 1.4 指标口径与维度拆解

| 口径要素 | 本件实际情况 |
|---|---|
| 总体 | 无（会话集合不是总体） |
| 参考期 | 无（随会话生灭） |
| 去重规则 | 无（前端数组，可能重复） |
| 持久化 | 无（刷新即失） |
| 跨用户可比 | 无（每人勾选不同） |
| 承载表 | 无 |

### 1.5 与同域姊妹指标的分工

与 `M_SVC_ORG_TOTAL`：那是「池里有多少家」，本件是「用户选了几家」。前者是统计，后者是交互；前者可跨用户比较，后者不可。

与 `M_SVC_ORG_CNT`、`M_SVC_ORG_COVERAGE_*`：它们都以池为总体，本件没有总体，不能与它们并列。

与「机构关注度」类埋点指标：如果甲方真正想要的是「哪些机构被看得多」，那是一个新指标，需要前端埋点、按机构聚合、定义时间窗，不能沿用本 ID。

### 1.6 本件的边界与不做什么

不计算 N；不落库；不做存量替代；不做「按勾选数排行」；不把 44,153 或 25,597 当 N；不复活已废止的 ID；如要「关注度」，另立条目。

## 二、计算过程

### 2.1 方法选择：不做计算，只做身份检验

本件没有公式。所谓「计算过程」只有一步：对候选对象做指标身份检验，五项（总体、参考期、去重、持久化、可比性）全部为否，则判定「不是指标」，停止后续加工。这个检验比任何公式都重要——它防止团队把 UI 状态当统计对象，进而为它建表、灌数、做口径，浪费且误导。

### 2.2 步骤 1｜身份检验（D1）

五项检验：①是否有明确总体？否，会话集合随用户变；②是否有参考期？否，随会话生灭；③是否有去重规则？否，前端数组；④是否持久化？否，刷新即失；⑤是否跨用户可比？否。五项全否，对象不合法。

### 2.3 步骤 2｜承载表探测（D2）

gkx 280 张表中检索 `svc_*`，结果 0 张；旧库结果面按 `metric_id` 过滤，恒 0 行。0 行是设计态：系统从未为会话语义建表。把 0 行当「数据缺失」去补，是方向性错误。

### 2.4 步骤 3｜反事实候选评估（D3）

三个候选：存量 44,153（与勾选无关，方差 0）、深圳子池 25,597（同上，只换分母）、埋点日均勾选（需前端埋点，属产品行为指标）。三者都不能冒充 N：前两个是恒定值，第三个是另一个指标。

### 2.5 步骤 4｜废止与归档（D4）

2026-10-13 徐滕强拍板废止，理由「前端会话勾选计数非指标；无总体、无参考期、无跨用户可比性」。本件按废止态归档：产物 `status=retired`，`support_judgment=完全不支持`，不做数、不补数。

### 2.6 步骤 5｜产物与复现（D5）

### 3.7 UI 状态与统计指标的边界

| 对象 | 类型 | 是否进数仓 |
|---|---|---|
| 页码 / 总数 | UI 状态 | 否 |
| 当前筛选结果数 | UI 状态 | 否 |
| 当前分析 N 家 | UI 状态 | 否 |
| 机构存量总数 | 统计指标 | 是 |
| 机构新增数 | 统计指标 | 是 |
| 机构关注度 | 埋点指标 | 另立 |

边界的判断标准只有一条：换一个用户、换一天，这个数是否仍有同样含义。页码换了用户仍是页码，但「N 家」换了用户就是另一个集合。

### 3.8 指标身份检验的执行方式

| 步骤 | 动作 | 判据 |
|---|---|---|
| 1 | 问总体是什么 | 能说出集合边界 |
| 2 | 问参考期是什么 | 能说出起止 |
| 3 | 问怎么去重 | 能说出唯一键 |
| 4 | 问存在哪里 | 能说出表名 |
| 5 | 问换人是否同义 | 能给出肯定答案 |

五步全过才算指标。本件在第 1 步就失败：会话集合没有边界，用户勾选多少它就是多少。后面的步骤不必再问，直接归档。

### 3.9 会话语义的三个反例

| 反例 | 说明 | 为什么不能统计 |
|---|---|---|
| 同一用户两次勾选 | 12 家 → 8 家 | 分母随操作变 |
| 两个用户同时在线 | 一个 12、一个 30 | 无跨用户口径 |
| 刷新页面 | N 归零 | 无持久化 |

三个反例覆盖了「时间、用户、会话」三个维度：任何一个维度上 N 都没有稳定值。统计指标至少要在一个维度上稳定，本件三个都不稳定。

本件不需要补数。唯一可能的后续是「机构关注度」：如果甲方真正想要「哪些机构被看得多」，应另立一个埋点类产品指标，定义总体（被查看的机构）、参考期（日/周/月）、去重规则（按 session 或 user）、持久化（埋点表），并重新走一遍指标评审。该新指标不能沿用 `M_SVC_ORG_SELECTED_COUNT` 这个 ID，否则历史口径会混。

### 4.3 降档论证（为什么是完全不支持）

四档定义里，「完全不支持」指「指标及关键依赖维度均无法构建」。本件比这更彻底：**对象不合法**。不是表没有、字段没有，而是「会话集合」根本不构成统计总体。任何补表、补数、补口径的努力，都是在为一个非指标建基础设施，因此判完全不支持，并标记 retired。

### 4.4 缺口对下游的影响

正面影响：废止后，前端不再等待一个永远为 0 的结果面字段，页面角标直接读本地状态，响应更快、语义更准。负面影响：如果有下游报表曾引用这个 ID，需要改为「不展示」或改用存量指标，并在报表说明里写清「原当前分析机构数已废止」。

### 4.5 字段级缺口表

| 期望字段 | gkx 是否有 | 处置 |
|---|---|---|
| `selection` | 无 | 前端内存 |
| `selection.length` | 无 | 前端计算 |
| `session_id` | 无 | 不落库 |
| `user_id` | 无 | 不落库 |
| 时间戳 | 无 | 不落库 |

### 4.6 与其它 UI 状态的区分

| 候选 | 为什么不是指标 | 正确处理 |
|---|---|---|
| 当前页码 | 随浏览变化 | 前端状态 |
| 当前筛选结果数 | 随筛选条件变化 | 前端状态 |
| 当前分析 N 家 | 随勾选变化 | 前端状态 |
| 最近访问机构 | 随会话变化 | 埋点另立 |
| 机构收藏数 | 需账号体系 | 产品功能 |

这张表用于需求评审：当甲方说「页面上这个数字能不能统计」时，先对照它属于哪一类。UI 状态不需要数仓支持，埋点指标需要另立条目，只有统计指标才进本批交付。

### 4.7 废止的决策链

| 时间 | 事件 | 产出 |
|---|---|---|
| 2026-09 | 需求评审提出「当前分析 N 家」 | 进入候选清单 |

| 2026-10-22 | gkx 口径归档 | 本件 |
| 待定 | 关注度需求另立 | 未启动 |

决策链的意义是留痕：本件不是写手自行删除，而是业务方拍板、工程归档。后续如有人问「为什么没有这个指标」，可指向这条链与 `retired_reason`。

### 4.8 废止后的报表影响面

| 报表/页面 | 是否引用本 ID | 处置 |
|---|---|---|
| 服务机构库角标 | 是（前端） | 保留，改读本地状态 |
| 产业服务链分析总览 | 否 | 无影响 |
| 服务机构月报 | 否 | 无影响 |
| 数据字典 | 是 | 标 retired |
| API 文档 | 是 | 移除字段或标废弃 |

影响面很小，因为本件从来不是报表口径。真正需要改的是数据字典与 API 文档：把字段标成废弃，避免新接入方误用。

## 五、废止结论与替代方案

本件的结论是「不做」：`M_SVC_ORG_SELECTED_COUNT` 自 2026-10-13 起废止，判档完全不支持，不补数、不建表、不替代。页面角标继续由前端 `selection.length` 提供，属于 UI 状态，不进数仓。

如果甲方需要「机构关注度」，建议另立 `M_SVC_ORG_ATTENTION`（暂名），定义为「按日/周聚合的机构详情页浏览次数（按 session 去重）」，数据来自前端埋点，落独立埋点表，不与本 ID 混用。该新指标需要重新评审总体、参考期、去重与隐私合规，不能直接复用本件的任何产物。

对下游的三条交代：第一，报表中如出现「当前分析机构数」，应删除或改为「当前筛选结果数（前端）」；第二，任何以本 ID 为分母的比率都不成立，需改用 44,153 存量；第三，废止不影响同批九件，九件均以 44,153 为池，与本件无口径依赖。

## 附录 G　常见误读与纠正

**问：为什么不给一个数？** 因为它不是指标。会话勾选数没有总体、没有参考期、跨用户不可比，给数只会制造假指标。

**问：为什么不用 44,153 替代？** 44,153 是池的总数，与用户勾选无关，方差为 0；用它替代等于把「选中 12 家」显示成「44,153 家」。

**问：结果面为什么是 0 行？** 设计态。系统从未为会话语义建表，0 行不是缺失。

**问：废止后页面角标怎么办？** 前端继续读本地 `selection.length`，属于 UI 状态，不进数仓。

**问：废止会不会让页面少一个功能？** 不会。角标仍由前端计算，只是不再从数仓取数；功能不变，链路更短。

**问：本件为什么还要交付脚本与产物？** 为了留痕：脚本可证明「没有可计算值」，产物可证明「判档与废止状态」，不是空口说「不支持」。

**问：如果甲方一定要「关注度」怎么办？** 另立埋点指标，重新评审总体/参考期/去重/隐私，不能复用本 ID。
