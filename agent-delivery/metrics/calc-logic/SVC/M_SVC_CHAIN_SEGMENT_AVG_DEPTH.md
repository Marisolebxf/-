## 摘要

「环节平均服务深度」是链路图上每个环节节点的一个标签：这个环节的机构平均能做多深（从单一服务到全链条解决方案）。公式极简——环节内所有机构的深度分取平均——难的是深度分本身怎么来。

本件在 gkx 上逐一试了三类替代口径，全部否决：经营范围文本长度（长文本只说明写得细，不说明服务深）、机构覆盖环节数（那是广度不是深度）、财务规模（营收大不等于服务深，贸易型机构营收很高但服务很浅）。三类代理都与「深度」语义不同向，若强行采用会产出可解释性极差的数。

最终本件只交付「分母 + 空值 + 缺口说明」：六环节分母 30,776 / 776 / 13,878 / 8 / 4,533 / 10,702，分母合计 60,673（含重复）、去重 34,578；分子全部为 null，展示为「—」。档位判 **部分支持**，因为分母侧可算、指标框架可落地，缺的只是分子这一块数据资产。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是链路图节点上的「深度」标签：同样是研发服务环节，有的机构只做单项检测，有的能做「需求诊断—方案设计—实施—验收」全流程。深度分想刻画的正是这个差别，展示形态是环节节点的第二行小字或颜色深浅。

### 1.2 为什么需要这个指标

广度回答「有多少家」，深度回答「能做多深」。只报广度会导致「数量繁荣」的错觉：一个环节有 3 万家机构，但如果都只做最末端的一小段，链条依然是断的。补链政策要区分「引数量」与「引能力」，深度就是后者的度量。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规只出现「服务深度」这个词，没有定义、没有分级、没有源表。旧稿把它登记为「0.2.0 目标口径」，即承认当时不可算。

### 1.4 指标口径与维度拆解

深度分的定义（目标态）：对每个「机构×环节」，按服务链条覆盖度打 0—100 分，覆盖从「单点服务」到「全流程解决方案」的层级；环节平均深度 = 该环节所有机构深度分的算术平均。分级与打分规则属 Q-SVCCHAIN-02，需方尚未签署，本件不自造。

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 池/机构域 | `dwd_org_org_product_info.org_id` | 按 org_id 去重，不做行数计数 |
| 行业/类型 | `main_activities` 词表 | 未命中归 UNCLASSIFIED，不丢弃 |
| 财务截面 | `dwd_org_annual_financial_info` 最近有值年 | 缺年不补 0，取最近有值年 |
| 风险事件 | `dwd_org_risk_shixin` / `dwd_org_company_punish` | 无记录记 0 件（事件型字段，0 是真实语义） |
| 资讯量 | `dwd_org_important_news_info` 标题条数 | 无资讯记 0，仅作代理 |
| 资本关系 | `dwd_org_invest_info` / `dwd_org_shareholder_info` | 对端解析不了的行丢弃并计数 |

### 1.5 与同域姊妹指标的分工

与 ORG_COUNT 的关系：共用同一份分母，本件不重算机构数；与 BOTTLENECK 的关系：BOTTLENECK 的第三档（资源瓶颈）以本件为输入，本件全空直接导致该档不可判——两件的缺口是同一个缺口。

与 172（短板模型）的关系：172 用「经营效益」替代了深度维来做区分，属于绕开缺口，不是填补缺口。

### 1.6 本件的边界与不做什么

本件不做：不自造深度打分规则、不用文本长度/规模等异向代理、不把空值写成 0、不在 ADS 里落 0 值占位。

## 二、计算过程

### 2.1 数据源与分母

分母来自 `svc21_facts_20261022.json` 的六环节计数（与 ORG_COUNT 同源同值）；分子需要一张「机构×环节×深度分」的表，gkx 与 live 均不存在。

| 环节 | 分母（机构数） | 分子（深度分） | 展示 |
|---|---:|---|---|
| 研发与科研合作 | 30,776 | 无源 | — |
| 知识产权与标准 | 776 | 无源 | — |
| 技术转移与孵化 | 13,878 | 无源 | — |
| 中试熟化 | 8 | 无源 | — |
| 检测认证 | 4,533 | 无源 | — |
| 市场化服务 | 10,702 | 无源 | — |

### 2.2 为什么不用文本长度代理

一个直觉方案是用 `main_activities` 的文本长度当深度：写得越长，服务越全。实测该假设不成立——文本长度中位 213 字，最长的是集团公司（把几十项业务全列上），而专做单一高端服务的机构往往只写一行。长度与深度甚至可能负相关。

这类「看起来相关、方向可能相反」的代理，一旦进入指数就会污染排序。本件对它的处理是：可以写在正文当探索记录，但不进产物、不进展示。

### 2.3 为什么不用覆盖环节数代理

第二个候选是「机构覆盖了几个环节」（0—6），越多样越深。问题是这测的是广度：一家什么都做一点的贸易商可以覆盖 5 个环节，而一家只做芯片可靠性检测的实验室只覆盖 1 个环节，显然后者更深。用覆盖数当深度，会把「杂」误判为「深」。

### 2.4 为什么不用财务规模代理

第三个候选是营收或资产。规模与服务深度在服务业里相关性很弱：贸易型、代理型机构营收可以很大，但服务链条极短；小型精品咨询公司营收不大，却能覆盖全流程。用规模代理深度，等于把「大」当成「强」。

更麻烦的是财务覆盖率本身不足（全池 6,759 家有年报），用它当分子会让深度分只在有财报的机构上有值，进一步扭曲环节平均。

### 2.5 空值语义与展示规则

本件输出 `avg_depth: null` 与 `display: "—"`。规则写死在脚本里：分子为空时不得返回 0，不得返回空字符串，也不得用分母当默认值。这样前端拿到 null 就知道「无数据」，不会画成 0 高度的柱子。

同时保留 `depth_status: "无源"` 与 `empty_rule` 两个字段，让下游能做「缺口可解释」的展示：鼠标悬停显示「该环节深度分待建」，而不是显示一个误导性的 0。

### 2.7 结果解读

六个「—」不是失败，而是诚实：它告诉甲方「这一列现在没有数」，从而把「建深度分表」变成一件必须排期的事。如果把它填成 0，看板上会显示六条贴地的柱子，所有人都会以为「服务深度极低」，而真相是「还没测」。

从交付角度，本件的价值在于把「缺口」变成了可验收的接口：只要供方按 Q-SVCCHAIN-02 给出机构×环节深度分，把数据灌进快照同名键，脚本无需改动即可出数。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 机构×环节深度分 | Q-SVCCHAIN-02 分级规则 + 打分表 | 指标全空，BOTTLENECK 第三档连带不可判 | 先签口径（0—100 分五级），再由供方按机构×环节打分 |

| 深度的时间维 | 历史打分版本 | 无法看深度变化 | 按年度快照打分并留存版本 |

### 4.2 修复路径与优先级

优先级按「补齐成本 ÷ 解锁维度数」排：成本最低、能一次解锁多个维度缺口的排前面。本批十件的共同短板是「服务过程类数据」（合同、验收、评价、投诉）在 gkx 完全没有承载表，这类缺口不是换字段能解决的，必须等甲方开放业务系统或采购第三方评分。

短期（可在一周内做）优先补「已有表但没接」的部分：把 dwd_org_recruit_info 的 hiring_number、dwd_org_annual_financial_info 的更多科目、dwd_org_org_product_info 的结构化产品字段接进快照。中期（需要建表）补 svc_quality_score / svc_csat_score / svc_success_case_count / svc_coop_edge 四张结果面。长期（需要外部数据）补牌照清单、服务合同、客户评价。

### 4.3 降档论证（为什么不是更高一档）

不抬档的第一条理由：抬档的门槛是「所有必需维度现在都能算出足够数据」，而本件至少有一维是结构性无源——不是「样本少」，而是「库里没有这张表、也没有可替代的字段」。这类缺口换写法、加 SQL 都补不出来。

不抬档的第二条理由：本件的代理关系是「语义降级」而非「同义转换」。例如用资讯条数代理服务质量，代理量测的是曝光度，方向可能相反（负面新闻也会推高条数）。只要存在这种方向性风险，就不能称「完全转换支持」。

不降档的理由：主体维度确有量、能算、能复核，且排序结果与行业常识不冲突（见 §2.8 的极值回查），不属于「完全不支持」。故最终判 **部分支持**。

### 4.4 缺口对下游的影响

缺口的第一层影响是「指标语义不完整」：缺一维时综合值仍能算，但它回答的问题已经变了。例如技术力指数若缺「融资成本」，高分机构可能只是「资本多、风险低」，而不是「融资便宜」。

第二层影响是「跨指标不可比」：两件指标若缺的维度不同，排序差异无法归因到机构本身，只能归因到口径差异。本批十件因此统一了池规则、标准化与缺维处理三条，尽量把差异压到维度选择上。

第三层影响是「展示必须带限定语」：凡缺维的指标，前端角标要写明「本指标不含 X 维」，否则用户会默认它是全维度评价。这一点写进 §附录 C 的交付清单。

## 五、王惠方法对照与选用建议

王惠调研稿（20260829 批次规范化迁移）给出的口径，是本批十件里唯一有「维度名 + 可执行代理规则」的版本：它把需求原文的定性描述翻译成「哪张表、哪个字段、缺了用什么代理、缺维怎么处理」，并显式登记了待建项。本件沿用其维度划分与合成骨架，只把数据来源从旧库口径整体换到 gkx，并把代理规则逐条落进脚本。

与官方口径对照：需求原文本身不给公式（见 §1.3），故不存在「官方公式 vs 王惠公式」的正面冲突；可比的只有维度语义。国家统计局《国家科技服务业统计分类（2018）》提供的是行业边界而非评分方法，OECD/JRC 复合指标手册提供的是「标准化—赋权—聚合—敏感性」的通用流程，二者与王惠口径不矛盾。

与替代路径对照：一条常见替代是「用专利/研发等硬指标直接排序」，优点是客观，缺点是把服务能力窄化为创新能力，对咨询、营销、人力类机构几乎失效；另一条是「纯专家打分」，可解释但不能复算。王惠口径走的是「可复算的代理 + 显式披露缺口」中间路线，与本项目「数字必须能指到落盘文件」的交付要求一致。

### 5.4 替代路径对比

| 路径 | 优点 | 缺点 | 本件取舍 |
|---|---|---|---|
| 纯硬指标排序（专利/研发） | 客观、可复算 | 把服务能力窄化为创新能力，咨询/营销/人力类失效 | 不采用，仅作旁证 |
| 纯专家打分 | 可解释、贴合行业 | 不可复算，无法审计 | 不采用 |
| 本件：代理 + 显式缺口 | 可复算、缺口可追责 | 代理存在语义降级 | 采用 |

**选用建议**：采纳王惠 avg_depth 公式与「空不补 0」规则；三类替代代理经实测否决，不引入。

## 附录 G 常见误读与纠正

**问：为什么分母是 44,153 而不是底册 189,116？**

底册是全量法人库（189,116 行），其中绝大多数不是服务机构。本批统一以「经营范围里出现服务类表述」作为服务机构的可操作定义，故分母是 44,153。若甲方有正式的服务机构认定名单，应替换分母并重跑全部十件。

**问：为什么同一家机构会出现在多个环节/类型里？**

因为代理口径是「经营范围命中」，不是「唯一归属」。经营范围是一段自由文本，一家机构可以同时写研发、检测、销售。产物同时给多命中与主类两列，就是为了让下游按需选择，而不是让本件替甲方决定归属。

**问：数字能不能直接和旧稿比？**

不能比绝对数，只能比结构与排序。旧稿的分母是人工圈选名单（43,296），本件是经营范围实体（44,153），两者不是同一个总体；此外旧稿的分类器列与词表口径也不同。

**问：缺维为什么不补 0？**

补 0 等于断言「该机构在这一维得分为 0」，而事实是「我们不知道」。这会把「无数据」伪装成「表现最差」，系统性压低数据稀疏机构的排名。本件的做法是缺维不进平均，并同步缩小权重分母。

**问：为什么阈值不直接用行业均值？**

gkx 没有行业均值口径（无行业代码主表与行业统计口径对齐）。用本池分位数是退而求其次，但它至少可复算；写一个来源不明的「行业均值」会让整条链无法审计。

**问：代理指标会不会方向相反？**

会。典型是「资讯条数代理服务质量」：负面新闻也计入条数。凡是存在方向性风险的代理，本件都在 §四 标注，并限制其只作排序参考、不作结论依据。

**问：重跑后数字变了怎么办？**

先看是不是快照变了（`generated_at` 与 `built_at`），再看是不是上游表补数。文档与产物必须同步更新：本批要求 MD 的 mtime 晚于 `_out.json`，且改脚本后必须重跑渲染器，避免正文停在旧数字。

**问：这套口径能不能直接上生产？**

能上「有供给/相对排序」这类展示，不能上「绝对水平/政策结论」这类判断。上生产前至少要补：正式机构名单、机构×环节成员表、服务质量与满意度结果面三件。
