## 摘要

「深圳服务机构分布」是服务机构族里唯一一个纯地理切片：它不发明新口径，只把机构池按行政区切开，回答「深圳的服务机构长在哪些区、是不是过度集中」。需求原文把「深圳服务机构规模及深圳服务机构分布」并列写入六大体系，但两级都没有给区级公式，本件的口径是工程口径——按底册 `area` 字段等值匹配，空白单列、不猜归属。

换源后的实测是：深圳切片 **25,597 家**，其中 9 个行政区有机构、合计 **25,587 家（99.96%）**，`area` 空白的 **10 家（0.04%）** 单列。区级梯度为南山 7,067（27.62%）、宝安 5,350（20.91%）、龙岗 3,342（13.06%）、福田 3,097（12.10%）、龙华 2,893（11.31%）、光明 1,513（5.91%）、罗湖 1,233（4.82%）、坪山 838（3.28%）、盐田 254（0.99%），大鹏新区 0 家。HHI 为 0.171486，对应等效区数 5.83；前三区合计 15,759 家占 61.59%，前五区占 85.00%。

判档为 **完全转换支持**：不需要建结果面，区级计数可当日现转且逐位闭合，每个数都能在 `code/M_SVC_SZ_DISTRICT.py` 重跑复现。需要如实披露的是三点：其一，池是经营范围代理口径而不是官方服务机构名录，区级分布继承了这个偏差；其二，大鹏新区的 0 家是真实 0 行而不是缺值，展示层不能画成「数据加载中」；其三，南山与福田的类型结构相反（南山以金融服务为首、福田金融占比 43.11%），区级总量接近不等于区级功能相同。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是产业服务链分析 → 深圳对比 → 区级分布。展示形态是深圳地图上的十个行政区着色 + 区级排行榜；算法侧挂在服务机构基础指标模型的人口底座族，与「深圳服务机构规模」「深圳梯队位置」「城市对比指标值」共用同一份深圳切片。这个分布同时是补链政策的落点依据：如果某个区服务机构密度极低，政策资源就要向该区倾斜，因此区级数字必须能与总量对账，不能是另一套人口。

### 1.2 为什么需要这个指标

总量回答「深圳有多少家服务机构」，分布回答「这些家在哪里」。两者不能互相替代：总量相同的两个城市，服务机构全落在一个区与均匀分布，产业服务能力的空间可达性完全不同。对深圳而言这个问题尤其现实——南山区一区就占 27.62%，而盐田区只有 0.99%，前者是后者的 27.8 倍；如果只看总量 25,597，会误以为全市服务供给均衡。

分布类指标的风险不在算术，而在归属。行政区不是机构的自有属性，而是登记地址的派生属性：地址写法不统一、前海与南山的功能区叠压、深汕合作区不在深圳十区之内，任何一个处理不当都会让区级数字在批次之间跳变。本件因此把「归属规则」写进正文（§2.2），并明确三条不做：不按注册地址文本解析、不做「功能区→行政区」的映射、不把空白并进任何一个区。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法，calc-logic 也没有同 ID 正本。** 需规只写「深圳服务机构规模及深圳服务机构分布」这十个字，没有给区级划分、没有给归属规则、没有给「分布」是计数还是密度。`REM_QUEUE_20261023.json` 中本件的 `calc_logic` 与 `wanghui` 两个字段均为 `null`，说明项目内既没有算法正本、也没有王惠侧的历史定义。

因此本件的公式是工程口径，且必须自我约束：区级分布只能定义成「机构池按 `area` 等值分组的计数」，因为这是唯一不需要引入外部假设的定义。任何更「聪明」的定义（按地址解析、按经纬度落区、按功能区归并）都需要一份本件拿不到的参照表，一旦引入就会变成不可复算的黑箱。这条自我约束也解释了为什么本件判「完全转换支持」而不是更高档：不是因为有现成结果，而是因为定义足够窄、窄到现有字段能完整承载。

### 1.4 指标口径与维度拆解

核心口径是「深圳切片按行政区计数」，维度拆解如下。所有维度都不是必需维——分布本身是一维的（区），其余维度只用于交叉展示。

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 机构唯一键 | `dwd_org_org_product_info.org_id` | 无 org_id 的行不入池（实测 0 行） |
| 城市过滤 | `dwd_org_base_info.city = '深圳市'` | 等值匹配，不做 LIKE、不做「深圳→深圳市」模糊归一 |
| 行政区 | `dwd_org_base_info.area` | 空白单列「未分配」，不并区、不猜 |
| 机构类型 | 经营范围词表派生六类 | 未命中归「未分类」，不丢行 |
| 规模档 | `dwd_org_base_info` 规模档 | 空值归「未知」，不参与区级排序 |
| 服务环节 | 经营范围词表派生六站 | 仅披露，不参与区级计数 |

口径边界有四条：其一，**一机构一行**，同一 org_id 的多条经营范围记录只计一次；其二，**区级合计必须等于切片**，25,587 + 10 = 25,597 是本件的硬对账；其三，**大鹏新区保留 0 行**，十区一个不少，不许因为 0 就从轴上删掉；其四，**不做密度**，区级密度需要区的面积与服务机构从业人数，两者本件都没有，硬算会把「面积小」误读成「密度高」。

### 1.5 与同域姊妹指标的分工

与 `M_SVC_PT_SZ_TOTAL` 的分工：后者只回答深圳一共多少家（25,597），本件回答这些家怎么分。两件共用同一份 `pool ∩ city=深圳市`，本件的区级合计必须与后者的总数逐位相等，这条对账已写进 §3.7。

与 `M_SVC_PT_SZ_REGION_ORG` 的分工：两件同池、同字段、同数字，差别只在验收单元——后者挂在 PORTAL 深圳专题的区级机构件上，本件挂在产业服务链分析的深圳对比页。**同数不同件不是重复建设**，而是两个页面各自需要独立可验收的产物；一旦池规则变更，两件必须同批重跑，不能只改一件。

与 `M_SVC_SZ_SCALE` 的分工：本件给区级总量，SCALE 给规模档结构。本件的 `by_size` 只是交叉披露，规模档的定义与对账以 SCALE 为准，本件不回写。

### 1.6 本件的边界与不做什么

本件不做五件事：不做区级密度（缺面积与从业人数）；不做区级时间序列（池快照是截面，没有历史分区快照）；不做「功能区」口径（前海/河套/深汕都没有稳定映射表）；不做区级排名打分（排名需要跨城市可比，而池 100% 落广东）；不把 25,597 与旧稿的深圳数相减（旧稿分母是人工圈定名单，总体不同）。

## 二、计算过程

### 2.1 方法选择：等值分组，而不是地址解析

选择「按 `area` 等值分组」而不是「按注册地址文本解析行政区」，理由有三。第一是可复算：等值分组只依赖一个字段，任何人拿同一份快照都能得到同一组整数；地址解析依赖分词规则与地名库版本，换一版地名词典区级数字就会变，无法审计。第二是可对账：`area` 是底册的结构化字段，空值就是空值，能明确数出 10 家；地址解析的失败是隐性的，解析不出来会被静默归到「其他」，看起来没有缺口实际全是缺口。第三是与同族一致：深圳切片的总量件、规模件、类型件都以底册字段为准，本件若改用地址解析，区级合计就对不上 25,597。

放弃的方案是「按经纬度落区」。gkx 底册没有经纬度列，外部地理编码服务需要逐家调用、有配额与费用，且同一个地址在不同服务商那里可能落到不同区。另一个放弃的方案是「按邮政编码落区」，深圳的邮编与行政区不是一一对应（同一邮编跨区的情况普遍存在），用它落区会产生系统性错配。

### 2.2 步骤 1｜机构池与深圳切片（D1）

池的纳入规则沿用 `M_SVC_ORG_TOTAL` §2.2：`gkx.dwd_org_org_product_info` 中 `main_activities` 非空的行，按 `org_id` 去重，得 44,153 家。再以 `org_id` 回联 `dwd_org_base_info`（189,116 行），命中 44,132 家（99.95%），取 `city = '深圳市'` 得深圳切片 **25,597 家**，占池 57.97%。池外 18,556 家分布在广州、东莞、惠州与 21 家未回联，本件不涉及（`code/_snapshots21/svc21_facts_20261022.json`）。

深圳切片是「服务机构池里的深圳机构」，不是「深圳全部企业」。底册里深圳企业远多于 25,597，差额是制造业、批发零售、房地产等没有技术服务经营范围的登记主体。这个区别决定了本件的分母语义：区级占比的分母是 25,597，不是深圳法人单位总数。

### 2.3 步骤 2｜行政区归属与未分配（D2）

`dwd_org_base_info.area` 在深圳切片上的取值为十个行政区名（南山区、福田区、罗湖区、盐田区、宝安区、龙岗区、龙华区、坪山区、光明区、大鹏新区），实测 25,587 家有值、10 家为空。有值的部分直接等值分组，不做任何字符串清洗；空白的 10 家单列「未分配（area 空）」，不并入任何一个区，也不按名称猜测。

为什么不用名称或地址兜底这 10 家？因为兜底无法验证。一家名字里带「南山」的机构可能注册在宝安，地址里出现「前海」的机构在行政区上可能属南山也可能属宝安（前海是功能区不是行政区）。10 家占 0.04%，把它们猜进某个区不会改变任何排序，却会让「区级合计 = 切片」这条对账从严格相等退化成「大致相等」——为了 0.04% 牺牲对账的严格性不划算。

### 2.4 步骤 3｜计数与集中度（D3）

区级计数公式为：

$$\text{DISTRICT}_{a} = \text{COUNT}\big(\text{org\_id} \mid \text{city}=\text{深圳市},\ \text{area}=a\big)$$

集中度用赫芬达尔指数（HHI），按区级份额的平方和计算：

$$\text{HHI} = \sum_{a=1}^{10}\left(\frac{\text{DISTRICT}_a}{25{,}597}\right)^2 = 0.171486$$

HHI 的取值区间是 0 到 1：10 个区完全均分时 HHI = 0.1，全部集中在一区时 HHI = 1。本件实测 0.171486，对应等效区数 $1/\text{HHI} = 5.8314$——意思是「深圳的服务机构分布，等效于把机构摊在 5.83 个等大的区上」。这个数与「有机构的区有 9 个」不矛盾：9 个区有机构，但规模差异很大，等效区数必然小于 9。

同时给出两个更直观的集中度读数：前三区（南山、宝安、龙岗）合计 15,759 家、占 61.59%；前五区（再加福田、龙华）合计 21,749 家、占 85.00%。这两个比例的分母是**有区级归属的 25,587 家**（不是含未分配的 25,597），分子是产物里的 `concentration.top3_orgs` 与各区计数相加。

### 2.5 步骤 4｜交叉分面（D4，仅披露）

区级 × 类型：类型由经营范围词表派生六类（IP/FINANCE/HR/MKT/CONSULT/INNOV），未命中归「未分类」。南山的首位类型是金融服务 2,355 家（33.32%），宝安的首位是综合咨询 2,639 家（49.33%），福田金融 1,335 家（43.11%），罗湖金融 540 家（43.80%），光明综合咨询 635 家（41.97%）。这一组交叉说明区级总量接近不代表功能相同：福田 3,097 家与龙岗 3,342 家总量只差 245 家，但福田的金融占比 43.11%、龙岗只有 22.68%，龙岗的研发创新占比 9.01% 反而是福田 1.91% 的四倍多。

区级 × 规模：南山区大型 322 家（4.56%）、中型 1,432 家（20.26%）、小型 4,001 家（56.62%）、微型 1,306 家（18.48%）；盐田区大型 20 家但占比 7.87%，是十区里大型占比最高的区。这个反差值得注意：盐田总量只有 254 家，大型占比却最高，说明「总量小」不等于「能级低」，用总量排名替代能级排名会误判盐田。

区级 × 环节：只作披露，不参与区级计数。南山的研发环节命中 5,359 家（75.83%）、市场与金融 2,571 家（36.38%）；宝安研发 4,222 家（78.92%）、但市场与金融只有 774 家（14.47%）。中试熟化环节在十区里只有南山 1 家、福田 1 家，其余八区为 0——这个 0 是词表口径下的真实 0，反映的是「经营范围里写中试的机构极少」，不是「这些区没有中试能力」。

### 2.8 与旧稿的差异

旧稿的深圳分布来自演示库的人工圈定名单，总量与区级数都不是本件的可比对象：旧稿分母是「会签名单」，本件分母是「有经营范围文本的机构」，纳入规则不同。旧稿的区级结构以福田与南山双中心为主，本件南山一区就占 27.62%、宝安第二 20.91%，重心明显西移。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 官方服务机构名录 | 甲方认定的服务机构名单 | 区级分布继承经营范围代理的偏差 | 由甲方提供名录，替换池后全族重跑 |
| 未分配 10 家 | `area` 空白 | 占 0.04%，不改变排序 | 底册补 `area` 或提供注册地址解析结果 |
| 区级面积 | 各区面积（平方公里） | 不能算密度，只能算总量与占比 | 接入统计年鉴区级面积 |
| 区级从业人数 | 区级服务业从业人数 | 不能算人均服务供给 | 接入社保/统计年鉴区级就业 |
| 功能区映射 | 前海/河套/深汕的行政区归属 | 功能区口径不可用 | 甲方提供功能区—行政区对照表 |
| 历史分区快照 | 往年区级分布 | 不能出区级趋势 | 按年落盘快照后另件处理 |

### 4.2 修复路径与优先级

短期（一周内）优先做两件成本最低的事：其一，把 10 家未分配机构逐家核对，确认是 `area` 漏填还是机构不在深圳十区；其二，从统计年鉴补十区面积，让「区级密度」这个下游需求有分母。中期（需要建表）补区级从业人数与功能区映射。长期（需要外部数据）补官方服务机构名录与历史分区快照。

### 4.3 降档论证（为什么不是更高/更低一档）

不抬到「完全直接支持」的理由：两库都没有区级分布结果面，`svc_*` 在 gkx 是 0 张、在 live 是 13 张全空，没有任何一处能直接读出「南山区 7,067」。

不降的理由：区级归属字段覆盖 99.96%、空白可单列、区级合计与切片严格闭合、交叉分面逐行闭合，缺的只有面积与从业人数这两个「本件不做」的维。按四档定义，结构完整、数据量足、当日可现转，正是「完全转换支持」。面积与从业人数缺失影响的是密度，不是分布本身——本件不做密度已在 §1.6 声明。

### 4.4 缺口对下游的影响

第一层影响是「密度类下游」：`M_SVC_SZ_DENSITY` 一类件若要落地，必须先拿到区级面积与从业人数，本件的区级计数只能当分子。第二层影响是「政策落点」：区级分布是补链资源分配的依据，池口径变更会让落点整体平移，因此池版本号必须随结果面一起发布。第三层影响是「展示限定语」：地图着色必须标注「经营范围口径」，否则用户会把它当成官方认定名单的分布。

## 五、结论与发布建议

本件可以发布，但发布口径必须写清三句话：第一，25,597 是「gkx 经营范围口径」的深圳服务机构切片，不是官方认定名单；第二，区级分布是登记行政区的分布，不是实际办公地的分布，两者可能不一致；第三，大鹏新区的 0 家是真实 0 行，展示层按「暂无供给机构」呈现，不能画成加载态。

建议首发命名为「深圳服务机构分布（经营范围口径）」，地图同时给出两个读数：绝对数（区级计数）与相对数（占深圳切片比例），并在图例注明 HHI = 0.171486、等效区数 5.83，让用户一眼看出「深圳服务机构是单核集中而不是均衡分布」。

## 附录 H　常见误读与纠正

**问：南山 7,067 家，是不是深圳四分之一的服务机构都在南山？** 是 27.62%，但这是经营范围口径下的登记分布，不是实际办公地分布。大量机构注册在南山、实际服务全市。

**问：大鹏新区 0 家，是不是数据没加载？** 不是。池内确实没有 `area = 大鹏新区` 的机构，是真实 0 行。展示层应写「暂无供给机构」，不写加载态。

**问：为什么不做区级密度？** 密度需要面积与从业人数两个分母，两库都没有。用机构数除以「感觉上的区面积」会把盐田（面积小）算成高密度，结论会反向。

**问：10 家未分配能不能按比例摊到各区？** 不能。摊分会制造不存在的归属，且会让「区级合计 = 切片」这条对账失去严格性。0.04% 的缺口如实单列，比编一个归属更可信。

**问：HHI 0.171486 算高还是低？** 10 区完全均分是 0.1，全部集中一区是 1。0.17 对应等效区数 5.83，属于「中度集中、单核明显」。这个判读要随口径变，剔制造业后 HHI 会上升。

**问：这张图和官方公布的各区企业数为什么不一样？** 分母不同。官方公布的是全部登记主体，本件只数「有技术服务经营范围」的机构，且已经按 `org_id` 去重。
