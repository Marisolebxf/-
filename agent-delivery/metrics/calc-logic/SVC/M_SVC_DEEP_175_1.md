## 摘要

「知识产权服务机构技术力评价模型」从专业能力、业务范围、成功案例、合作伙伴四维评价代理所与 IP 服务机构。IP 类是六大类里唯一能把「能力」落到官方登记数据上的类型——专利申请书上的代理机构字段就是专业能力的直接证据。

本件在 gkx 上跑通：IP 主类池 108 家；`dwd_patent.agency` 按 dwd_id 区间顺序扫描 1,678,411 件（覆盖 57.0%），与池内机构名精确对齐命中 3 家、合计 43,260 件；成功案例代理覆盖 62 家、合作伙伴 40 家、业务范围 0 家。指数覆盖 32 家，均值 10.57、中位 2.05、最高 59.76。

档位 **部分支持**。三个限制必须一起说：①池只有 108 家（关键词口径把大量「经营范围含专利」的科技企业也算了进来）；②agency 是自由文本，精确名对齐会漏掉简称与分支所；③业务范围维无表。因此本件的指数只能作「可命中子集内的相对排序」，不能当 IP 行业排名发布。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是技术力评估下的 IP 专项：对专利/商标代理所、IP 法律与运营机构做四维打分，用于企业选代理所、政府培育 IP 服务生态。

### 1.2 为什么需要这个指标

IP 机构的「技术力」不像金融机构那样看资本，而是看代理质量与业态覆盖。国家知识产权局等十七部门《关于加快推动知识产权服务业高质量发展的意见》把「专业化、市场化、国际化」与「代理、法律、运营、信息、咨询」业态结构列为发展坐标，这正好对应本件的四维：能力（代理量）、范围（业态覆盖）、案例（品牌）、伙伴（协同网络）。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规只给四维名称与「结合历史行业均值及专家建议设定阈值」「采集—清洗—单项得分—加权合成」的流程，没有公式、阈值或源表。旧稿采用王惠四项口径。

### 1.4 指标口径与维度拆解

四维口径：专业能力 = agency 对齐后的代理件数（不做发明占比，因为样本内无授权/类型字段可比）；业务范围 = 已挂产业数（无表，空）；成功案例 = 资讯条数代理；合作伙伴 = 资本边去重对端数。等权 0.25。

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 池/机构域 | `dwd_org_org_product_info.org_id` | 按 org_id 去重，不做行数计数 |
| 行业/类型 | `main_activities` 词表 | 未命中归 UNCLASSIFIED，不丢弃 |
| 财务截面 | `dwd_org_annual_financial_info` 最近有值年 | 缺年不补 0，取最近有值年 |
| 风险事件 | `dwd_org_risk_shixin` / `dwd_org_company_punish` | 无记录记 0 件（事件型字段，0 是真实语义） |
| 资讯量 | `dwd_org_important_news_info` 标题条数 | 无资讯记 0，仅作代理 |
| 资本关系 | `dwd_org_invest_info` / `dwd_org_shareholder_info` | 对端解析不了的行丢弃并计数 |

### 1.5 与同域姊妹指标的分工

与 174/176/177 同骨架不同维度：本件的「专业能力」是四件里唯一有官方登记数据支撑的维度，但也是覆盖最薄的维度（3/108）。这个反差本身就是结论：数据最硬的维度，往往是最难对齐的维度。

与 173 的分工：173 的关系图包含 IP 机构，但只统计资本边；本件的合作伙伴维与之同源，不另算。

### 1.6 本件的边界与不做什么

本件不做：不用申请人专利数冒充代理量、不把「经营范围含专利」等同于「代理机构」、不对未命中的 105 家插补专业能力分。

## 二、计算过程

### 2.1 数据源与池

池 = 主类为 IP 的 108 家。这个池明显偏大：真正的专利代理机构需要国知局备案，全国约 5 千家、深圳数百家；本池 108 家里只有 3 家能在专利 agency 字段上对上。

因此本件把池分成两层：`ip_primary`（108 家，用于覆盖率统计）与 `agency_matched`（3 家，用于能力维打分）。指数只在能凑够两维的 32 家上计算。这种「分层」是为了不把「没对上 agency」误判为「没有代理能力」。

### 2.2 维度一｜专业能力（agency 代理件数）

取 `dwd_patent.agency` 与机构全名精确匹配。为避免全表扫描（294 万件、agency 为自由文本），按 `dwd_id` 区间每 30 万条分页扫描，已扫 1,678,411 件（57.0%），命中 3 家、43,260 件。

覆盖率 57.0%（76 页冻结副本）必须披露：这是顺序扫描不是随机抽样，若某代理所的专利集中在未扫区间，件数会被低估。因此产物里给的是「样本内件数」，不按覆盖率外推。

| 维度 | 覆盖家数 | 占池 |
|---|---:|---:|
| 专业能力 | 3 | 2.78% |
| 业务范围 | 0 | 0.00% |
| 成功案例数 | 62 | 57.41% |
| 合作伙伴 | 40 | 37.04% |

### 2.3 维度二｜业务范围（无源）

需要「机构 × 产业」多对多表。gkx 没有 `dwd_org_industry_tags`；旧库有同名表但只有 104 行且 credit_code 与底册失配，等于没有。本维 0 覆盖。

替代方案试过两个：用 `main_activities` 里的行业词做粗分类（粒度太粗，且与池定义同源，会循环论证）；用客户专利的 IPC 分布反推机构业务范围（需要代理所—客户映射，agency 字段只到所不到客户）。两者都不可行。

### 2.4 维度三｜成功案例数（资讯代理）

正式口径应是「代理/服务过的项目数、行业分布、客户复购」。gkx 无此表，只能用资讯条数代理，覆盖 62 家（57.4%）。

这个代理对 IP 机构尤其弱：代理所很少上新闻，上了多半是获奖或诉讼，不是案例。在本件 TOP10 里，第一名（广百股份，资讯 887 条）根本不是代理所——这正是代理失效的直接证据。

### 2.5 维度四｜合作伙伴（资本边）

投资边 + 机构股东边去重对端数，覆盖 40 家（37.0%）。对 IP 机构来说，资本边能反映「是否属于某集团」，但反映不了「与哪些企业有代理合作关系」——后者才是 IP 机构的核心关系。

### 2.6 标准化、赋权与阈值

标准化 min-max、等权 0.25、空维不进平均、<2 维不出指数。阈值同样用分位三分，但因为分布极度偏斜（中位 2.05、最高 59.76），分位切点实际退化为「有没有分」。

必须说明：本件的指数分布没有解读价值（32 家里中位只有 2.05、均值 10.57），真正有价值的是分维覆盖与 agency 命中。这也是为什么产物里把 `index_coverage_note` 写成了一句警告而不是脚注。

`cd code && python3 M_SVC_DEEP_175_1.py`，读机构快照与 agency 扫描快照，输出分维覆盖、指数覆盖与 TOP10，覆盖写 `_out.json`。

### 2.8 结果解读

三个命中机构都是真实代理所（名称能与底册全名逐字对上），件数合计 43,260 件，占样本内全部 agency 命中件数 80,259 的 53.9%，量级与 57.0% 的样本覆盖率大致吻合。这说明「名称精确对齐」这条路是通的，问题在于池里只有 3 家真代理所。

TOP10 里排第一的广百股份（资讯 887 条、伙伴 9 家、代理 0 件）暴露了代理组合的失效：当能力维为空时，案例维（资讯）会主导排序，把零售企业顶到 IP 榜首。这条不能靠调权重解决，只能靠「能力维非空才出指数」的硬规则。

使用建议：本件暂不发布排名，只发布「agency 命中清单 + 分维覆盖」；若要发布，先把池换成国知局备案代理机构名单。

### 2.9 与旧稿的差异

| 项 | 旧稿（演示库口径） | 本件（gkx） |
|---|---|---|
| IP 池 | 96 | 108 |
| agency 命中 | 5 家 / 171,459 件 | 3 家 / 43,260 件（样本 57.0%） |
| 业务范围 | `industry_tags` 104 行失配 | 无表 |

### 2.10 参数与常量清单

| 参数 | 取值 | 来源/说明 |
|---|---|---|
| 池规则 | org_id 去重 + 经营范围非空 | 避免 45,011 行 / 44,153 家的重复计数 |
| 标准化 | 截面 min-max 到 [0,1] | 同值给 0.5，不制造极值 |

本件的价值不在指数，而在把「agency 可对齐」这件事验证通了：只要有备案名单与索引，「代理件数」就能从自由文本变成稳定指标，这是 IP 类技术力唯一可能做到「官方数据级客观」的路径。

相反，如果继续用资讯量代理成功案例，IP 类永远算不准——代理所不上新闻，这是行业属性，不是数据采集问题。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 代理机构备案名单 | 国知局备案代理机构（名称 + 机构代码） | 池 108 家里仅 3 家真代理所 | 接入备案库，按机构代码而非名称对齐 |

| 成功案例 | svc_success_case_count | 只能用资讯代理，且对代理所失效 | 接入代理委托书/申请量数据 |
| agency 全量 | 完整 agency 扫描 | 样本 57.0%，件数可能低估 | 按 agency 建索引后全量 GROUP BY |

### 4.2 修复路径与优先级

优先级按「补齐成本 ÷ 解锁维度数」排：成本最低、能一次解锁多个维度缺口的排前面。本批十件的共同短板是「服务过程类数据」（合同、验收、评价、投诉）在 gkx 完全没有承载表，这类缺口不是换字段能解决的，必须等甲方开放业务系统或采购第三方评分。

短期（可在一周内做）优先补「已有表但没接」的部分：把 dwd_org_recruit_info 的 hiring_number、dwd_org_annual_financial_info 的更多科目、dwd_org_org_product_info 的结构化产品字段接进快照。中期（需要建表）补 svc_quality_score / svc_csat_score / svc_success_case_count / svc_coop_edge 四张结果面。长期（需要外部数据）补牌照清单、服务合同、客户评价。

### 4.3 降档论证（为什么不是更高一档）

不抬档的第一条理由：抬档的门槛是「所有必需维度现在都能算出足够数据」，而本件至少有一维是结构性无源——不是「样本少」，而是「库里没有这张表、也没有可替代的字段」。这类缺口换写法、加 SQL 都补不出来。

不抬档的第二条理由：本件的代理关系是「语义降级」而非「同义转换」。例如用资讯条数代理服务质量，代理量测的是曝光度，方向可能相反（负面新闻也会推高条数）。只要存在这种方向性风险，就不能称「完全转换支持」。

不降档的理由：主体维度确有量、能算、能复核，且排序结果与行业常识不冲突（见 §2.8 的极值回查），不属于「完全不支持」。故最终判 **部分支持**。

### 4.4 缺口对下游的影响

池纯度问题在本件最严重：101 的 IP 主类池 108 家是「经营范围含专利/商标/知识产权」的机构，其中大量是科技企业的知识产权部门表述，不是代理机构。用一个 3/108 命中的池算指数，统计意义很弱。

业务范围维缺失让「业态覆盖」这个政策最关心的维度完全落空——而它恰好是十七部门意见的核心（代理/法律/运营/信息/咨询五业态）。

对下游：本件不应进入「机构排名」页面，只适合做「IP 服务能力摸底」的内部参考。这一点必须与产品确认，否则会被当成权威榜单。

## 五、王惠方法对照与选用建议

王惠调研稿（20260829 批次规范化迁移）给出的口径，是本批十件里唯一有「维度名 + 可执行代理规则」的版本：它把需求原文的定性描述翻译成「哪张表、哪个字段、缺了用什么代理、缺维怎么处理」，并显式登记了待建项。本件沿用其维度划分与合成骨架，只把数据来源从旧库口径整体换到 gkx，并把代理规则逐条落进脚本。

与官方口径对照：需求原文本身不给公式（见 §1.3），故不存在「官方公式 vs 王惠公式」的正面冲突；可比的只有维度语义。国家统计局《国家科技服务业统计分类（2018）》提供的是行业边界而非评分方法，OECD/JRC 复合指标手册提供的是「标准化—赋权—聚合—敏感性」的通用流程，二者与王惠口径不矛盾。

与替代路径对照：一条常见替代是「用专利/研发等硬指标直接排序」，优点是客观，缺点是把服务能力窄化为创新能力，对咨询、营销、人力类机构几乎失效；另一条是「纯专家打分」，可解释但不能复算。王惠口径走的是「可复算的代理 + 显式披露缺口」中间路线，与本项目「数字必须能指到落盘文件」的交付要求一致。

### 5.4 替代路径对比

| 路径 | 优点 | 缺点 | 本件取舍 |
|---|---|---|---|
| 用申请人专利数当能力 | 覆盖高 | 申请人是企业不是代理所，语义完全错 | 不采用 |
| 模糊匹配 agency 名称 | 命中更多 | 误配风险高，无法复核 | 不采用 |
| 本件：精确对齐 + 分维披露 | 可复核 | 覆盖薄 | 采用（仅内部参考） |

**选用建议**：采纳王惠的四维划分；业务范围维无源、成功案例仅有资讯弱代理，指数只作「可命中子集内的相对排序」，不对外发布 IP 榜单。

## 附录 G 常见误读与纠正

**问：为什么 IP 池只有 108 家，而市场上有数千家代理所？**

因为池是按经营范围关键词从 4.4 万家服务机构里筛的，不是按备案名单。真正的代理所大多不写「知识产权服务」而是写「专利代理」，词表覆盖不全；反过来，科技企业写「专利技术研发」也会入池。这是池定义的系统性偏差。

**问：agency 命中只有 3 家，指数还有意义吗？**

作为行业排名没有意义；作为「这 3 家的代理量级参考」有意义（10,767 / 5,499 / 3,404 件，与样本覆盖率吻合）。产物里已写明「指数只对可命中子集成立」。

**问：为什么不用模糊匹配提高命中？**

agency 是自由文本，模糊匹配会把「中一联合」配到其他所，且无法逐条复核。精确匹配虽然漏，但每一条都能验证。

**问：TOP1 为什么是零售企业？**

因为能力维为空时，案例维（资讯 887 条）主导排序。这不是权重问题，是「能力维覆盖太薄」的结构问题；修复方式是「能力维非空才出指数」，本件已在产物里标注。

**问：业务范围维能不能用 IPC 反推？**

不能。agency 字段只到「所」，不到「客户」，没有代理所—客户映射就无法把客户的 IPC 归到所上。

**问：样本 57.0% 会不会严重低估？**

会低估，但方向一致（不会虚高）。若需精确值，应按 agency 建索引后全量 GROUP BY，成本约 40 分钟。

**问：能不能和 174 的指数比？**

不能。池不同（金融 3,211 / IP 108）、维度不同、覆盖差异极大，指数不在同一标尺。
