## 摘要

「入库服务机构总数」是服务机构库的人口底座：六大核心指标体系全部以这个人口为分母或圈定对象。需求原文要求服务机构基础指标模型「分析全球及深圳本地的服务机构运行状态和发展趋势」，但没有给出字段级公式；口径由项目内 calc-logic 钉在「池表唯一键 COUNT」上，本件只把池表从演示库口径换到 gkx。

换源后的实测是：`gkx.dwd_org_org_product_info` 45,011 行，按 `org_id` 去重 **44,153 家**；与底册 189,116 行回联命中 **44,132 家（99.95%）**，仅 21 家悬空。城市切片为深圳 25,597、广州 12,641、东莞 4,300、惠州 1,594，深圳占 57.97%。旧稿的 43,296 家来自演示库的人工圈定名单，与 gkx 经营范围机构不是同一个总体，绝对数不可直接相减比较。

判档为 **完全转换支持**：不需要新建结果面就能从 gkx 现转出唯一键计数，且每个数都能在 `code/M_SVC_ORG_TOTAL.py` 重跑复现。需要如实披露的是：gkx 没有人工认定的服务机构名录，本件人口是「有经营范围文本的机构」这一代理定义，池内包含大型制造企业与高校，不能等同于「科技服务业法人单位」的官方口径。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的是科技专题服务系统 → 科技专题战略分析 → 产业服务链分析 → 服务机构库底座。算法侧对应《科技专题服务算法库》§1.1.1.1.1.1.1.1.4「服务机构基础指标模型构建」（SRS 序号 101）的六大体系；展示侧是产业服务链分析页面的机构总量角标与下钻入口。这个总数同时是「全球分布」「新增动态」「市场热度」「技术力」等下游件的共同分母——分母一变，下游所有占比与排名都要重算。

### 1.2 为什么需要这个指标

总数类指标的风险从来不在算术，而在真源。同一个「服务机构数」可以从机构池、机构卡面、结果面、ODS 全量四个地方数出四个不同的数：池表 44,153、卡面投影、事实面 value、底册 189,116。允许多真源并存，对账矩阵立即失去意义。项目内钉版把本指标钉在池表唯一键上，正是官方统计「一个数字一个责任项目」纪律的项目化：市场监管总局的登记在册主体数只从全国登记簿导出，五经普的法人单位数只从普查框导出，从不允许「按卡面再数一遍」作为第二官方数。

对甲方而言，这个数是「服务机构家底」的唯一入口。它决定了补链政策的分母：如果分母把大型制造企业也算进来，那么「深圳有 2.5 万家服务机构」这句话就会把产业服务能力夸大约一个量级。因此本件把「口径定义」与「数字」一起交付，并在 §三 逐条写明池的纳入/排除规则。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需规只要求「分析全球及深圳本地的服务机构运行状态和发展趋势，生成各项指标及趋势分析结果」，没有给出服务机构的认定标准、唯一键、是否含待确认主体、是否含分支机构。旧稿用 calc-logic 钉版补上了这层：池表一行一家、待确认也算入库、`COUNT(*)` 不加 DISTINCT、不数卡面/事实面/ODS 全量。本件沿用这四条纪律，只把池表换成 gkx 上可复算的 `dwd_org_org_product_info`。

### 1.4 指标口径与维度拆解

本件的核心口径是「机构池按 org_id 去重计数」，维度拆解如下。所有维度都不是必需维——总数本身是一维的，维度只用于切片展示。

| 维度/口径 | gkx 字段 | 缺失时的处理 |
|---|---|---|
| 机构唯一键 | `dwd_org_org_product_info.org_id` | 无 org_id 的行不入池（实测 0 行） |
| 经营范围文本 | `main_activities` | 空文本不入池（实测 2 行，已排除） |
| 工商属性 | `dwd_org_base_info`（省/市/成立年/注册资本） | 回联不上的 21 家单独列「未回联」，不丢弃、不并市 |
| 城市 | `dwd_org_base_info.city` | 空值单列，不做「深圳→深圳市」模糊归一 |
| 成立年 | `dwd_org_base_info` 成立年列 | 缺失 21 家，见 `M_SVC_NEW_CNT`，本件不摊年 |
| 机构规模 | `dwd_org_base_info` 规模档 | 空值归「未知」，不参与总数 |

口径边界有三条：其一，**一机构一行**，同一 org_id 的多条经营范围记录只计一次；其二，**不按名称去重**，底册有 47 个重名，按名称去重会误伤不同法人；其三，**不把底册 189,116 当总数**，底册是全国企业主档，服务机构只是其中按经营范围圈出的子集。

### 1.5 与同域姊妹指标的分工

与 `M_SVC_ORG_CNT` 的分工：本件只回答「一共多少家」，ORG_CNT 回答「这些家分布在哪些国家/省份」。两者共用同一份 `population.distinct_org_id`，ORG_CNT 不再重算池。

与 `M_SVC_NEW_CNT`、`M_SVC_ORG_NEW_COUNT` 的分工：本件是存量截面，后两者是成立年序列（流量）。存量回答「现在有多少」，流量回答「每年新增多少」，两者不能互相替代：把存量差分当新增，会把注销与迁入混进来。

与 `M_SVC_ORG_COVERAGE_BREADTH`、`M_SVC_ORG_COVERAGE_DEPTH` 的分工：本件是分母，广度/深度是分子侧的机构级刻画。广度/深度只在池内做相对比较，不改变池的边界。

### 1.6 本件的边界与不做什么

本件不做四件事：不做年度序列（成立年序列另件）；不做城市/行业加权（加权需要可信的规模与行业口径，本件只给原始计数）；不做「服务机构」的官方认定（gkx 无此名录）；不把 44,153 与旧稿 43,296 做差值归因（两者总体不同，差值没有解释力）。

## 二、计算过程

### 2.1 方法选择：唯一键计数，而不是多源对账后的「最大数」

选择唯一键计数而非「多源取最大」的理由有三。其一，官方统计纪律：登记在册主体数、法人单位数都是「一个总体一个责任项目」，多源取最大会让口径随数据供应方变化而漂移。其二，可复算性：唯一键计数只依赖 `org_id`，任何人在任何机器上用同一份快照都能得到同一个整数；多源对账则需要一套未定义的仲裁规则，无法审计。其三，下游一致性：本件是 SVC 域所有占比指标的分母，分母必须稳定；若分母随「哪个源行数多」而变，所有下游占比都会在批次之间跳变。

放弃的方案是「用底册 189,116 当服务机构总数」。这是最常见的误用：底册是全国企业主档，包含制造业、批发零售、房地产等全部行业，把它当服务机构总数会把分母放大四倍以上。另一个放弃的方案是「用机构卡面行数」——卡面是池表的展示投影，从投影反数人口等于让下游定义上游。

### 2.2 步骤 1｜机构池定义与去重（D1）

池的纳入规则是：`gkx.dwd_org_org_product_info` 中 `main_activities` 非空的行，按 `org_id` 去重。实测 45,011 行、44,153 个不同 org_id，行/家比为 1.019，说明绝大多数机构只有一条经营范围记录，少量机构有多条。`main_activities` 空文本仅 2 行，已排除；文本长度中位 212 字、P90 511 字、最大 1,504 字，足够承载关键词命中。

去重必须用 `org_id` 而不是名称：底册 189,116 行只有 189,069 个不同 `name_cn`，有 47 个重名；按名称去重会把不同法人合并，按名称 JOIN 会把同一法人的专利/新闻重复计数。本件只数 org_id，不做名称聚合。

### 2.3 步骤 2｜与底册回联（D2）

以 org_id 回联 `dwd_org_base_info`（189,116 行），命中 44,132 家，回联率 99.95%；21 家悬空。悬空的原因不是池表脏数据，而是这 21 家在底册快照生成时尚未入册或 org_id 不一致；本件把它们单列「未回联」，既不丢弃也不猜测城市。

回联后的省份分布只有广东省 44,132 家，城市分布为深圳 25,597、广州 12,641、东莞 4,300、惠州 1,594。这个分布不是「全国服务机构分布」，而是「广东都市圈服务机构分布」：底册 189,116 行中深圳都市圈四市占 99.82%，全国其他城市合计仅 342 家。任何「全国排名」类读出都必须先披露这个结构性偏斜。

### 2.4 步骤 3｜计数与对账链（D3）

计数公式为：

$$\text{ORG\_TOTAL} = \text{COUNT}^{*}\big(\text{distinct org\_id} \mid \text{main\_activities} \neq \emptyset\big) = 44{,}153$$

对账链有三条：其一，池内 org_id 去重数 44,153 与 `population.distinct_org_id` 逐位相等；其二，城市切片合计 25,597+12,641+4,300+1,594+21 = 44,153，与池数相等；其三，与底册回联 44,132 加悬空 21 等于 44,153。三条对账都落在 `_out.json` 的 `population` 与 `city_dist` 里，甲方可逐项复算。

### 2.5 步骤 4｜规模与行业切片（D4，仅披露）

规模切片来自底册：小型 22,750、中型 8,545、微型 6,632、未知 4,320、大型 1,906。行业切片前五为制造业 13,129、科学研究和技术服务业 7,396、批发和零售业 7,036、信息传输/软件和信息技术服务业 6,696、租赁和商务服务业 3,426。这两组数只作披露，不参与总数，也不作为「服务机构类型」的正式分类——底册行业是登记行业，不是实际服务领域。

### 2.8 与旧稿的差异

旧稿的 43,296 家来自演示库 `svc_org_circle`（人工圈定名单），本件的 44,153 家来自 gkx 经营范围机构。两者差 857 家，但这个差值没有归因意义：旧稿分母是「会签名单」，本件分母是「有经营范围文本的机构」，纳入规则不同。旧稿的深圳 14,033 家（32.41%）与本件的 25,597 家（57.97%）差距更大，原因同样是分母不同——本件池里深圳占比更高，因为 gkx 经营范围表以深圳都市圈企业为主。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 缺什么 | 影响 | 修复路径 |
|---|---|---|---|
| 官方服务机构名录 | 甲方认定的服务机构名单 | 池含制造企业与高校，总数偏高 | 由甲方提供服务机构名录，替换池定义后重跑 |
| 海外机构 | 与六类口径闭合的海外名录 | 「全球」名实不符 | 指定海外名录供方，或确认「全球布局的中国机构」代理口径 |
| 出清侧 | 注销/吊销事件流 | 只有存量，没有净新增 | 接入市场监管注销数据 |
| 分支机构 | 分支机构标识 | 可能把分公司与总公司各计一次 | 底册补分支标识后按集团口径重算 |
| 行业口径 | 实际服务领域标签 | 行业切片只是登记行业 | 接入机构×产业映射表 |

### 4.2 修复路径与优先级

短期（一周内）优先做两件成本最低的事：其一，把池内「制造业/批发零售/房地产」等明显非服务业的行业单独打标，给甲方一个「窄口径总数」与「宽口径总数」两个数；其二，把 21 家未回联机构逐家核对，确认是 org_id 不一致还是底册缺行。中期（需要建表）补机构×产业映射与分支机构标识。长期（需要外部数据）补官方服务机构名录与海外名录。

### 4.3 降档论证（为什么不是更高/更低一档）

不抬到「完全直接支持」的理由：gkx 没有现成的 `svc_org_circle` 结果表，本件的数是从经营范围表现转出来的，不是直接读数。

不降的理由：池结构完整、唯一键可核、当前数据量足（44,153 家、回联 99.95%），现在就能经转换得到稳定计数，且计数不依赖任何缺失维度。按四档定义，这正是「完全转换支持」。

### 4.4 缺口对下游的影响

第一层影响是「分母语义」：下游所有占比都以 44,153 为分母，若甲方要的是「科技服务业法人单位」，分母应更小，占比会整体上移。第二层影响是「跨批次可比」：池定义一旦变更（例如剔除制造业），所有下游件的占比与排名都要重算，不能只改本件。第三层影响是「展示限定语」：前端角标必须写「经营范围口径」，否则用户会默认它是官方认定名单。

### 4.5 字段级缺口表

| 期望字段 | gkx 是否有等价列 | 处置 |
|---|---|---|
| 服务机构认定标识 | 无 | 待甲方名录 |
| 分支机构标识 | 无 | 待底册补列 |
| 实际服务领域 | 无稳定映射 | 用六类服务类型代理，见 BREADTH |
| 注销/吊销日期 | 无 | 待市场监管数据 |
| 国别 | 无 | 见 ORG_CNT，海外格留空 |

### 4.6 口径变更的影响矩阵

| 若口径改为 | 分母变化 | 下游需要重算的件 |
|---|---|---|
| 剔除制造业 | 44,153 → 约 31,024 | CNT/BREADTH/DEPTH/TECH_SCORE 全部 |
| 只保留「科学研究和技术服务业」 | 44,153 → 7,396 | 同上，且深圳占比会明显下降 |
| 并入底册全部企业 | 44,153 → 189,116 | 全部，且「服务机构」语义失效 |
| 按集团合并分支机构 | 略降（无标识，暂不可算） | 全部 |
| 加入海外机构 | 上升（无源，暂不可算） | 全部 |

这张表是给甲方做口径决策用的：任何一次分母变更都不是本件单独的事，而是 SVC 域十件一起重算。工程上建议把「池版本号」写进结果面，让下游能判断自己消费的是哪一版分母。


## 五、结论与发布建议

本件可以发布，但发布口径必须写清三句话：第一，44,153 是「gkx 经营范围口径」的服务机构池，不是官方认定名单；第二，深圳 25,597 家占 57.97%，这是池的结构，不是全国服务机构的真实分布；第三，21 家未回联底册的机构单列，不并入任何城市。

建议首发命名为「入库服务机构总数（经营范围口径）」，并在 API 响应体同时返回 `wide_total=44153` 与「窄口径（剔除制造业等非服务业）」两个数，让甲方按用途选择。窄口径需要一次额外的行业过滤，不改池的唯一键规则。

## 附录 G　常见误读与纠正

**问：为什么不是 189,116？** 底册是全量企业主档，包含制造业、批发零售、房地产等全部行业；服务机构只是其中按经营范围圈出的子集。把 189,116 当服务机构总数，分母会放大四倍以上。

**问：为什么深圳占 57.97%，是不是深圳真的占全国一半以上？** 不是。gkx 底册本身以深圳都市圈为主（四市占 99.82%），这个占比是样本框结构，不是全国分布。任何全国排名都必须先扩样本框。

**问：21 家未回联为什么不并进深圳？** 没有证据表明它们在深圳。按城市归并的前提是底册有值；缺失就是缺失，猜测会把「未知」伪装成「已知」。

**问：池里为什么有华为、比亚迪和高校？** 因为池的定义是「有经营范围文本的机构」，不是「科技服务业认定名单」。它们有技术服务经营范围，按代理口径应入池；这也正是本件反复提示「窄口径」的原因。

**问：能不能把 44,153 与旧稿 43,296 相减，说增加了 857 家？** 不能。两个分母的纳入规则不同，差值没有归因意义。换源后只能比结构，不能比绝对数。

**问：这个数能不能直接上生产？** 能上「总量与结构」展示，不能上「官方认定服务机构数」的政策结论。上生产前至少要补甲方名录与分支机构标识。
