## 摘要

服务网络密度衡量「这张网有多密」：实际存在的边占可能边的比例。公式是 $D = 2|E|/(|N|(|N|-1))$，无向图标准式。本件实测：N = 44,153、E = 13,141，可能边 974,721,628 条，实际 13,141 条，实现率 **0.00134818%**，密度 **1.348180e-05**；若把分母换成活跃子网（N_act = 12,905），密度升到 **1.578251e-04**，仍是一个万分之一点六的极稀网络。

三项实测结论必须分开讲。第一，**这个网络的稀疏度是数量级的稀疏**：可能边近 9.75 亿条，实际 1.3 万条，密度 1.3e-05。任何「服务网络高度互联」的叙事在这组数字面前都不成立。稀疏的原因不是机构之间没有关系，而是三种切割叠加：池只装广东 4 市的 44,153 家、边只算资本纽带、对端不在池的边全部剔除。第二，**口径敏感度极高**：若两表相加不去重，E 变 21,879、密度变 2.2446e-05（虚高 66.5%）；若只算投资边，E = 0、密度 = 0（因为 5,667 个投资对 100% 包含在股东对里）；若只算股东边，E = 7,474、密度 7.6678e-06。四种口径给出四个量级相近但语义不同的数，必须锁定一种并写死。第三，**会签裁决把这条路堵死了**：Q-SVCCHAIN-03 明确「服务网络密度的边不算投资/股东」，理由是资本纽带不等于服务关系——两家机构有股权关系，不代表一家给另一家提供服务。裁决意味着本件的 1.348e-05 **在正式口径下不可用**，只能作为代理量披露。

这三条合起来决定了本件的档位。密度公式可算、边集可算、敏感度可算，计算链没有任何断点；但正式语义（服务关系网络）的边不存在，而会签又明确禁止用资本边顶替。所以本件不是「算不出」，而是「算出来的不是那个东西」。判 **部分支持**。

文档结构上，§二 给计算过程与四种口径的敏感度、§三 给数据支撑与陷阱、§四 给降档论证与会签裁决的完整引用、附录 B 给可复核数字、附录 G 专门解释「为什么 1.3e-05 不是错误」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能是：**科技专题服务系统 → 科技专题战略分析 → 产业服务链分析 → 服务网络概览**。算法侧对应算法库 §1.1.1.1.1.1.1.11「服务网络分析」的密度项：计算服务图谱的全局密度，用于刻画网络的整体连接强度，并可对比不同区域/类型子网的密度差异。展示侧对应 SRS seq 133/134 的网络概览页：一个数值（密度）+ 一个趋势/对比图（分区域、分类型）。

产品任务有三件：**定边**（哪些关系算服务网络的边）、**算密度**（E 与 N 的比值）、**对比**（子网密度、跨期变化）。本件只做全局密度的主口径与敏感度，不做子网密度（需按区域/类型切图，属扩展需求），不做节点级指标（见 CENTRALITY/INFLUENCE）。

### 1.2 为什么需要「服务网络密度」这个指标

密度是网络的**宏观体温**。单看某家机构的度数，只能知道它连了几家；看整体密度，才知道这张网是「稠密小世界」还是「稀疏星型」。这个区别对政策判断很关键：稠密网络的资源传导快、政策一竿子能到底；稀疏网络必须靠枢纽节点做二次传导，政策要「抓大户」。服务业的实际形态通常是后者——大量小微机构各自连着少数平台型机构，密度极低但枢纽度极高，本件实测的 1.3e-05 与 329 的最大度正是这个形态的量化。

密度的第二个用途是**横向对比**。同一套口径下，深圳子网与广州子网的密度差异，能反映两地服务机构生态的成熟度差异；跨期比较能反映网络是在变密还是变疏。这类对比的前提是口径稳定——密度对边集与节点域都极度敏感（本件实测四种口径差 3 倍以上），口径一变，跨期与跨区对比全部失效。这也是为什么本件把口径敏感度单列一节（§2.4），而不是放在附录里。

密度的第三个用途是**作为其他指标的分母**。社群发现、聚类系数、平均路径长度等指标都以密度为基准做归一；如果密度算错，这些指标的归一也全错。本件因此把「口径写死 + 敏感度全披露」作为交付的最低要求。

### 1.3 需求文档是否给出定义方法

**需求文档给了指标名称，没给边集口径。** 算法库只写「计算服务网络的密度」，没有定义：边是什么、节点域是什么、有向还是无向、是否去重、是否含孤立点。王惠稿补了公式（无向图标准式）与「边为服务关系」的语义，但同样没有解决「服务关系数据从哪来」。

真正把口径定死的是**会签裁决 Q-SVCCHAIN-03**：服务网络密度的边不算投资/股东。这条裁决是对王惠口径的**收紧**——王惠在度中心性里允许「服务关系 ∪ 资本关系」，但在密度这里，会签认为资本关系不能代表服务关系，因为两者的语义距离太大（有股权关系 ≠ 有服务往来）。本件完全接受这条裁决，并把它的后果（本件数值只能作代理）写在最显眼的位置。

## 二、计算过程

### 2.1 公式与两个输入的来源

无向图密度标准式：

$$D = \frac{2|E|}{|N|(|N|-1)}$$

分子乘 2 是因为每条无向边被两个端点各计一次；分母是 N 个节点的可能无向边总数 $C(N,2) = N(N-1)/2$，乘 2 后与分子对齐。这个式子的取值范围是 [0,1]：完全图 D=1，无边 D=0。

两个输入：E = 13,141（来自 113 件的边集：投资 ∪ 机构股东，双端在池、无向去重、去自环）；N = 44,153（来自 112 件的节点域）。代入：分子 2×13,141 = 26,282；分母 44,153×44,152 = 1,949,443,256；D = 26,282/1,949,443,256 = **1.348180e-05**。

可能边数 = 44,153×44,152/2 = **974,721,628** 条。实际 13,141 条，实现率 = 13,141/974,721,628 = **0.00134818%**。这个百分数比密度更直观：一万条可能的关系里，实际存在 0.135 条——换句话说，每 10 万对机构里只有 1.35 对有资本纽带。

### 2.2 活跃口径：分母该不该含孤立点

全池口径把 31,248 个零度节点算进分母，密度被压到 1.3e-05；活跃口径只算 12,905 个有度节点，密度变成 $2×13,141/(12,905×12,904) = 26,282/166,526,120 =$ **1.578251e-04**，是前者的 11.7 倍。

哪个对？取决于问题。问「整个服务生态的资本连接有多密」，用全池（含孤立点）——因为孤立点也是生态的一部分，它们没连接这件事本身就是密度信息。问「有资本关系的机构之间有多密」，用活跃口径——这是条件密度。本件的正式口径取全池（与 CENTRALITY 的分母一致），活跃口径作为对照值一并出。

这里有个容易犯的错：用活跃口径算出的 1.578e-04 去和别人的全池口径比较，会得出「我们的网络密 12 倍」的错误结论。本件在产物里把两个值分别命名（`density_pool` / `density_active`），并在文档里反复标注，就是为了防止这种跨口径误比。

### 2.3 稀疏度的三重成因

1.348e-05 这个数看起来极端，但它不是数据缺陷，是三重切割的必然结果。

**切割一：池域**。池只装广东 4 市的 44,153 家服务机构（深圳 57.97%、广州 28.63%、东莞 9.74%、惠州 3.61%）。机构与省外主体的资本关系全部被剔除——投资表触池 41,888 行里，双端都在池的只有 5,677 行（13.55%），其余 86.45% 的对端在池外。若把池扩到全国，E 会大幅增加，但 N 增加得更快（全国服务机构数十万家），密度未必上升。

**切割二：关系类型**。只算资本纽带。服务、合作、客户三类关系（如果存在）全部未计。这三类在实际业务中比资本关系频繁得多——一家机构一年可能服务上百家客户，但十年只发生一次股权变更。所以「真实服务网络」的密度应该远高于 1.3e-05，只是本库测不到。

**切割三：去重与去自环**。两表重叠 5,667 对必须合并（否则 E 虚增 66.5%），自环 20 条必须剔除（无向图里自环无意义）。这两步让 E 从 21,899（相加去自环）降到 13,141。

三重切割叠起来，1.3e-05 就有了完整解释。任何拿这个数去论证「广东服务机构之间缺乏合作」的说法都是错的——它只能论证「池内资本纽带极稀疏」。

### 2.4 口径敏感度：四种边集给四个数

| 口径 | E | D（全池） | 相对主口径 |
|---|---:|---:|---:|

四行里最值得讲的是第二行：**只算投资边，密度直接归零**。原因是投资表的 5,667 个节点对 **100% 包含**在股东表的 13,141 对里——同一笔资本关系，投资表记「A 投 B」，股东表记「B 的股东是 A」，两表是同一事实的两个视角。因此「投资边的独立贡献 = 0 条」不是取数 bug，而是这批数据的结构特征（详见 113 件 §2.2）。

第三行说明股东边是边集的主体（7,474 对独占），第四行说明不去重的代价（虚高 66.5%）。这四行合起来构成本件的「口径敏感度带」：任何引用本件数值的人，必须同时说明用的是哪一行，否则数字不可比。

### 2.5 会签裁决 Q-SVCCHAIN-03 的完整后果

裁决原文：**「服务网络密度的边不算投资/股东」**。这条裁决的适用范围是本指标（密度），不是度中心性或影响力（那两件仍在资本边上计算，并各自标注语义）。

后果有三层。**第一层，本件无正式边**：既然不许用投资/股东边，而服务关系边又不存在，正式口径下本件的 E 是「不可得」而不是「0」——「不可得」意味着不能报一个数，「0」意味着报 0（会误导为「网络完全无连接」）。本件的处置是：正式口径报 null，代理口径报 1.348e-05，两者在产物里分开命名（`caliber_ruling` 与 `main.density_pool`）。

**第二层，展示层必须带限定语**。前端若只显示「服务网络密度 0.0013%」，用户会以为是服务网络的真实密度。正确展示是「资本纽带密度（代理）0.0013%；正式服务网络密度暂不可得（服务关系数据未入湖）」。

**第三层，下游不可引用为服务密度**。任何以「服务网络密度」为主语的分析（例如「深圳服务网络密度是广州的 X 倍」）都不能引用本件数值。本件的数值只能用于「资本纽带密度」这一语义。

### 2.6 密度与度数的关系：为什么密度低但枢纽度高

一个常见的困惑是：密度只有 1.3e-05，为什么会有度 329 的机构？答案在分布形态。密度是**全局平均**，度数是**局部极值**。13,141 条边集中在 12,905 个节点上（其中 8,149 个只有 1 条边），6 个枢纽吃掉了约 900 条边（深创投 329、中信 227、高新投 219、深投控 116、中小担 100、力合 51，合计 1,042 条边次、约 521 条边）。换句话说，**边的高度集中**与**全局的低密度**完全可以并存——这正是枢纽驱动网络的标志。

用公式表达：全局平均度 $\bar{k} = 2E/N = 26,282/44,153 = 0.595$，而最大度 329 是平均度的 553 倍。密度与平均度是同一件事的两种写法（$D = \bar{k}/(N-1)$），所以「密度低」等价于「平均度低」，与「存在高度节点」不矛盾。

## 五、王惠方法对照与选用建议

王惠稿对密度的口径是：无向图标准式、边为「服务关系与资本关系的并集」、N 取服务池规模。会签 Q-SVCCHAIN-03 对第二条做了收紧：密度不许用投资/股东边。

**（1）公式沿用**。$D = 2|E|/(|N|(|N|-1))$ 是标准式，本件一字不改。

**（2）边集口径被会签改写**。这是本件与王惠唯一的实质差异：王惠允许资本边，会签不允许。本件以会签为准（会签晚于王惠稿，且是针对本指标的专项裁决），并把后果写进产物。

**（3）N 的取值补了裁决**。王惠写「服务池规模」，本件用 44,153（全池），与 CENTRALITY 一致；活跃口径作对照。

**选用建议**：公式用王惠的，边集与会签对齐（即正式口径暂无可用边），N 用全池。对外披露时统一表述为「资本纽带密度（代理）1.348e-05；正式服务网络密度待服务关系数据入湖后重算」。这条建议同时约束前端文案与分析报告主语。
