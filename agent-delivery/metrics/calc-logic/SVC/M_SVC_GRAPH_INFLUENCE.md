## 摘要

生态影响力评分把三个中心性压成一个 0—100 的分数，回答「这家机构在整个生态网络里有多重要」。公式照抄王惠：$Influence = 100/3 × (\hat{DC} + \hat{BC} + \hat{CC})$，三个分量各自 min-max 到 [0,1] 后等权相加。本件在 13,141 条资本边、12,905 个有度节点上实测：最高分 **96.30**（深圳市创新投资集团，度 329）、次高 **89.04**（中信证券，度 227）、第三 **59.35**（深圳市高新投创业投资，度 219）；分布中位 13.13、p90 21.00、p99 26.22、均值 9.87。

三项结构性发现值得单列。第一，**头部断层明显**：96.30 → 89.04 → 59.35，第三名比第二名低 29.69 分，说明真正意义上的「生态枢纽」只有两家，第三名开始进入第二梯队。第二，**度与介数不同步**：深创投度 329（第一）、介数 0.007690（第二），中信证券度 227（第二）、介数 0.008650（第一）——中信的介数更高说明它更多处在「桥」的位置（连接不同子群），深创投更多是「星心」（连接大量叶子）。这正是三中心性合成的价值：单看度会认为深创投压倒性第一，合成后两者差距为 7.26 分。第三，**接近中心性区分度最低**：全部 12,905 个有分节点的 CC 落在 0.034—0.048 的窄带内（因为巨型分量占 7,040 个节点、绝大多数节点到其他节点的距离都在 3—5 跳），min-max 后这一维只贡献很小的方差，实际主导排名的是 DC 与 BC。

方法上本件做过一次重要修正，必须写出来。**首版按「分量内归一」**（BC 除以 $(m-1)(m-2)/2$、CC 除以 $m-1$，m 为所属分量规模），结果榜单被小分量占据：3 节点小链的中点 BC 归一后等于 1.0，与巨型分量的枢纽并列，Top10 全是度 5—9 的小分量节点（广东华农大资产经营 67.48、深圳麦格米特 67.38…），深创投反而排不进去。根因是 2,270 个分量里有 2,200 多个是 2—33 节点的小碎片，分量内归一等于给碎片发「满分券」。修正为**全局归一**（BC 除以全池 $(N-1)(N-2)/2$、CC 除以 $N-1$）后，榜单恢复正确：深创投 96.30、中信 89.04。这个坑写在 §2.4，是本文档最值得读的一节。

结论：公式、归一化、计算链、复现全部成立，唯一且实质的缺口是**边集语义**——库内没有服务关系边，本件在资本纽带上代理。按四档定义判 **部分支持**；语义边界（评的是资本纽带网络位置，不是服务网络位置）在 §2.6、§4.3 与附录 G 明确。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能是：**科技专题服务系统 → 科技专题战略分析 → 产业服务链分析 → 生态影响力榜单**。算法侧对应算法库 §1.1.1.1.1.1.1.11 的「综合影响力评估」：把度中心性、介数中心性、接近中心性合成为一个综合分，用于识别生态中的关键枢纽与桥接机构。展示侧对应 SRS seq 133/135：榜单页按综合分排序，详情页展示三个分项得分与雷达图。

产品任务有四件：**算三维**（度、介数、接近）、**归一**（各维 min-max 到 [0,1]）、**合成**（等权平均 ×100）、**出榜**（排序 + 分档 + 分项解释）。本件不做密度（DENSITY）、不做单维度榜单（CENTRALITY）、不做边抽取（113）。

### 1.2 为什么需要「生态影响力评分」这个指标

单维度指标都有盲区。度中心性只看「连了多少家」，会把「连了很多叶子但不在任何桥位置」的机构高估；介数中心性只看「处在多少条最短路径上」，会把「连接大量叶子」的星心低估（叶子之间的路径不经过星心以外的节点，介数反而不高）；接近中心性只看「到所有点多近」，在巨型分量内部区分度极低。三个盲区互不重叠，合成起来才能给出一个相对完整的「结构重要性」画像。

业务上，这个分数用于三类决策：**选链主**（谁是生态里最能带动的机构）、**选桥接方**（谁能在两个子群之间牵线）、**选合作对象**（谁的网络位置最有利于资源传导）。三类决策对三维的偏好不同——选链主看度、选桥接方看介数、选合作对象看接近——所以本件不只输出合成分，也在产物里保留三个分项，供使用方按场景切换权重。等权只是默认值。

方法上，合成指标有一个通病：**归一化方式决定榜单**。本件在首版踩过这个坑（见 §2.4），修正后的做法是全局归一 + 固定种子抽样，保证同一份快照重跑得到完全相同的榜单。这一点比公式本身更重要——一个不可复现的影响力榜单，业务方用一次就不会再用第二次。

### 1.3 需求文档是否给出定义方法

**需求文档给了三个中心性的名称与合成要求，没给归一化与抽样口径。** 算法库只写「综合度中心性、介数中心性、接近中心性评估节点影响力」，没有写：三维是否等权、归一化在全局还是分量内做、介数在大图上是否抽样、孤立节点是否计 0、同分如何排序。SRS 只描述展示（雷达图、分项得分）。

本件的公式来自王惠稿（三中心性 + 等权），归一化与抽样口径是本件补的。补的理由是：王惠写「各维归一后等权」，但没写归一的范围；而「分量内 vs 全局」这个选择在本数据上会**彻底改变榜单**（首版实测 Top10 全部错误），这是必须显式裁决的口径分岔。

## 二、计算过程

### 2.1 图结构与三个分量的定义

图：44,153 个节点、13,141 条无向边（与 113/CENTRALITY/DENSITY 完全同源）。有度节点 12,905 个，连通分量 2,270 个，最大分量 7,040 个节点（占池 15.94%），其余分量规模 33、20、18、17、15、14、14……快速衰减。

三个中心性的定义：

- **度中心性**：$DC(v) = \deg(v)/(N-1)$，N = 44,153。衡量局部触达面。
- **介数中心性**：$BC(v) = \frac{2}{(N-1)(N-2)} \sum_{s \ne v \ne t} \frac{\sigma_{st}(v)}{\sigma_{st}}$，其中 $\sigma_{st}$ 是 s 到 t 的最短路径数、$\sigma_{st}(v)$ 是经过 v 的条数。衡量「桥」的位置。
- **接近中心性**（调和式）：$CC(v) = \frac{1}{N-1}\sum_{u \ne v} \frac{1}{d(v,u)}$，d 为最短距离，不可达记 0。调和式的好处是不要求图连通（经典式在非连通图上无定义）。

三者都归一化到「除以全池规模」，保证不同分量的节点可比——这是本件修正后的核心口径，详见 §2.4。

### 2.2 介数计算：7,040 节点的抽样策略

Brandes 算法的复杂度是 $O(nm)$，7,040 节点、9,383 条边的巨型分量做全源 BFS 约需 $7,040 × 9,383 ≈ 6.6×10^7$ 次邻居遍历，Python 实现约 70 秒——超过单件 90 秒的红线。因此本件对巨型分量抽样：取 **k = 1,000 个种子节点**（固定随机种子 20261022，可复现），做 Brandes 后按 $n/k$ 放大（n = 7,040，放大 7.04 倍）。

抽样误差的量级：介数估计的标准误约为 $1/\sqrt{k}$，k=1,000 时约 3.2%；对本件的影响是排名相邻的机构可能互换，但头部（深创投 0.007690 vs 中信 0.008650，差 11.1%）不会因抽样翻转。其余分量规模 ≤33，全部**精确计算**（无抽样），产物 `betweenness_approx` 字段逐分量记录「节点数 / 种子数 / 是否精确」，审计时可查。

一个容易忽略的细节：抽样放大用的是 $n/k$ 而不是 $(n-1)/(k-1)$，两者在 k=1,000、n=7,040 时差 0.01%，不影响结论。本件用 $n/k$，写进脚本注释。

### 2.3 接近中心性：scipy 最短路分块

7,040 个节点的 All-Pairs Shortest Path 若用纯 Python BFS，约 $7,040 × 9,383$ 次遍历，同样超时。本件的做法是用 scipy 的 `shortest_path(method='D', unweighted=True)` 按 1,000 行一块分块求解，得到 7,040×7,040 的距离矩阵块，再按行求 $\sum 1/d$。实测巨型分量耗时约 4 秒，全图（含 2,269 个小分量）总计约 10 秒，全件 11.1 秒完成。

调和式在不可达时记 0（而非无穷），这保证了非连通图上每个节点的 CC 都有定义。巨型分量内部绝大多数节点对可达（分量内连通），所以 CC 的值域集中在 0.034—0.048 的窄带；小分量的节点 CC 极低（只能到达分量内的少数节点，除以 N−1 = 44,152 后接近 0）。

### 2.4 归一化：首版为什么错了，怎么改的

这是本文档最重要的一节。首版实现用的是**分量内归一**：BC 除以 $(m-1)(m-2)/2$、CC 除以 $m-1$（m 为节点所属分量的规模）。理由是「不同分量规模差异大，分量内归一更公平」。实测结果（首版 Top10）：

| 排名 | 机构 | 度 | 分数 | DĈ | BĈ | CĈ |
|---|---|---:|---:|---:|---:|---:|
| 1 | 广东华农大资产经营有限公司 | 9 | 67.48 | 0.000204 | 1.000 | 1.000 |
| 2 | 深圳麦格米特电气股份有限公司 | 8 | 67.38 | 0.000181 | 1.000 | 1.000 |
| 3 | 金蝶软件（中国）有限公司 | 7 | 67.28 | 0.000159 | 1.000 | 1.000 |

一眼就能看出问题：第一名度只有 9，BĈ 与 CĈ 都是 1.0（满分），而深创投（度 329）根本不在榜上。根因是**分量内归一对小分量极度有利**：一个 3 节点的链 A—B—C，中点 B 的介数在分量内是「1 条最短路径经过它 / 分量内可能路径数 1」= 1.0，归一后拿满分；而深创投在 7,040 节点的巨型分量里，介数虽大但分母是 $(7039×7038)/2 ≈ 2.48×10^7$，归一后只有 0.0074（按分量内归一），反而低于小分量中点的 1.0。结果是 2,270 个分量里的 2,200 多个小碎片批量产出「满分节点」，把榜单彻底带偏。

修正为**全局归一**：BC 除以 $(N-1)(N-2)/2$（N = 44,153）、CC 除以 $N-1$。这样做之后，小分量节点的 BĈ 与 CĈ 都变得极小（它们能参与的路径数本来就少），巨型分量的枢纽自然浮上来。修正后 Top3：深创投 96.30、中信 89.04、高新投创投 59.35，与业务直觉一致。

这个修正的教训是通用性的：**多分量图上的中心性，归一化必须在全局做，否则等于给碎片发满分券**。本件把它写进文档，是因为同类错误在下游任何图指标里都可能重犯（社群影响力、区域网络对比等）。

### 2.5 合成与分布

三维 min-max 后等权平均 ×100：$Influence = 100/3 × (\hat{DC}+\hat{BC}+\hat{CC})$。实测分布：n = 12,905、mean 9.87、median 13.13、p90 21.00、p99 26.22、max 96.30、min 0.00。

分布形态是「长尾 + 两个极端点」：绝大多数机构落在 5—25 分，96.30 与 89.04 孤立在右端。中位 13.13 高于均值 9.87 说明左尾（低分）更长——大量度 1 的叶子机构 DĈ ≈ 0、BĈ = 0、CĈ 低，分数被压到 5—10；而少数中度机构（度 5—20）三维都有值，分数在 20—40。这个形态对分档有直接影响：若按「≥70 领先 / 55—70 稳健 / 40—55 关注 / <40 薄弱」分档，本批只有 2 家领先（深创投、中信）、1 家稳健（高新投创投）、约 30 家关注，其余 12,870 家薄弱——分档阈值需要按实际分布重设，不能照搬旧稿的 70/55/40。

### 2.6 语义边界：评的是资本网络位置

本件分数衡量的是节点在**资本纽带网络**中的结构位置，不是服务网络。这一点必须反复讲清，因为它与 DENSITY 的处境不同：DENSITY 被会签 Q-SVCCHAIN-03 明确禁止用资本边，本件**没有被禁止**——会签只约束密度。理由是：密度是「网络整体有多密」的断言，用资本边冒充服务边会让整体结论失真；而影响力是「节点在这个网络里多重要」的排序，只要明确「这个网络是资本网络」，排序本身是成立的、有业务价值的（选资本枢纽、选桥接方）。

因此本件判 **部分支持**：公式与排序全部成立、可交付，但边集是代理（服务关系边缺失，见 §4.1 G1），不是需求主语的完整实现。所有对外表述必须带主语：**「资本纽带网络影响力」**，不能简写成「生态影响力」而不加限定。附录 G 给了标准表述模板。

### 4.3 为什么判「部分支持」而不是「完全转换支持」（本件曾误判，此处留痕）

初稿判的是「完全转换支持」，理由是：结构齐备、数据量足够、会签只约束密度不约束影响力，且「资本纽带网络影响力」本身是一个有业务价值的成立命题。这个理由在**技术层面**成立，按四档定义**站不住**，故改判。三条理由：

**第一，四档定义看的是需求语义能否交付，不是公式能否跑通。** 需求要的是「服务机构在服务生态中的影响力」，边集只有资本纽带（投资 + 机构股东），服务关系边库内无承载表（G1）。四档里「部分支持」的定义正是「主体可算，但至少一个必需维度缺失或只能用代理变量」——本件精确落在这一格。

**第二，同批同边集的件必须同档。** `M_SVC_GRAPH_CENTRALITY` 用的是同一份 13,141 条边、同样的 12,905 个有度节点，判的是「部分支持」，理由就是「正式服务关系边无承载表」。度中心性在资本网络里的语义合法性并不比影响力弱，若影响力可判完全支持，中心性没有理由降档。两份文档对同一件事给出不同结论，是最容易被甲方抓住的那类矛盾。

**第三，介数是抽样估计。** 巨型分量 7,040 节点取 1,000 个固定种子，标准误约 3.2%。「完全转换支持」要求「经确定的转换规则可算出」，抽样估计不是确定规则下的精确量；虽不改变头部排序，但边界名次（p90 附近）会互换。这一条单独不足以降档，与第一条叠加则清楚。

**反向考虑过并否决的处理**：把三件图指标统一升到「完全转换支持」，理由是「网络已被正确命名」。否决原因：需求文档的主语是**服务**机构生态，不是资本网络；升档等于把「我们没拿到服务关系边」这件事从文档里抹掉，正是「无据抬档」。

**这条留痕本身就是交付物的一部分**：四档的价值在于同一件事在不同文档里有同一个结论。判档口径若可随作者论证灵活移动，闸门就只能检查格式，检查不了诚实。

## 五、王惠方法对照与选用建议

王惠稿对影响力的口径是：三中心性（度、介数、接近）各自归一后等权合成 ×100，权重可由专家调整。本件的对照结论：

**（1）公式沿用**。三中心性 + 等权合成，本件一字不改。

**（2）归一化补裁决**。王惠写「各自归一」，未写归一范围。本件补了「全局归一」的裁决，并用首版错误（§2.4）证明这条裁决不是可选项——分量内归一会让榜单失效。

**（3）抽样补口径**。王惠未提大图抽样。本件补了「巨型分量 1,000 种子、其余精确、种子 20261022」，保证可复现。

**（4）权重保持等权**。王惠允许专家调权，本件默认等权、保留分项，把调权留给使用方在展示层做（不写死在后端）。理由是：本批没有专家权重输入，写死任何非等权权重都是编造。

**选用建议**：采用王惠的三中心性与等权合成，补全局归一与固定种子抽样；对外统一表述为「资本纽带网络生态影响力」，权重暂用等权，待甲方给出专家权重后按 `model_version` 重算。

## 附录 C 可行性完整版（可交付形态）

### C.1 计算流程（伪代码）

```
# M_SVC_GRAPH_INFLUENCE 伪代码
nodes = 44153; E = 13141
deg   = count_degree(E)
dc    = {v: deg[v]/(nodes-1)}
for comp in components(E):
    if len(comp) <= 1500: src = all;  exact = True
    else:                 src = sample(1000, seed=20261022); exact = False
    bc_local = brandes(comp, src) * (len(comp)/len(src)) / 2
    cc_local = harmonic_closeness(comp)          # scipy 无权最短路
    bc[v] = bc_local[v] / ((nodes-1)*(nodes-2)/2)   # 全局归一
    cc[v] = cc_local[v] / (nodes-1)                 # 全局归一
score = 100/3 * (mm(dc) + mm(bc) + mm(cc))
emit top10(score), distribution(score), graph_meta
```

## 附录 G 常见误读与纠正

| 误读 | 纠正 |
|---|---|
| 「96.30 说明深创投服务能力最强」 | 是资本纽带网络位置，不是服务能力 |
| 「分数可以跨版本比」 | 归一化或权重一变，分数全变，不可混比 |
| 「小分量节点也能拿 1.0」 | 那是分量内归一的错误结果，本件用全局归一 |
| 「介数是抽样，所以结果不靠谱」 | 3.2% 标准误，头部差距 18.7%，不影响结论 |
| 「孤立点应该给 0 分」 | 给 null；给 0 会造出 31,248 个假观测 |

**标准表述模板**：「在资本纽带的机构网络中，XX 的综合影响力得分为 96.30（度中心性 0.0075、介数 0.0077、接近 0.048），位列第一；该分数衡量资本网络结构位置，不代表服务能力或经营绩效。」
