## 摘要

「中心度」在需求原文里出现两次，语义都是「节点重要性」：一次在技术知识图谱的「关键节点识别与标记」——「根据节点的重要性指标（如中心度、影响力等）自动识别关键节点，并在图谱中以特殊样式进行标记」；一次在算法库的「网络指标计算 API」——「支持计算指定图谱网络中的网络密度、中心度等网络指标」。需求给了指标名与用途，**没有给出中心度的具体定义**（哪种中心性、什么网络、节点是什么）。

本报告采用的 AI-20261016 口径把中心度实现为**学者合作网络的度中心性**：以 `dwd_zh_author` 中同一 `paper_id` 的作者两两成边，构建无向合作网络，取 $C_D(v)=\deg(v)/(n-1)$，同时输出加权合作强度（合作论文计数的加权度）作为辅助排序。产物由 `metrics/repro/M_INNOV_DS_02_PATH_001.py` 在 `gkx.dwd_zh_author` 全量直算（20261021 改源，不再从 BUNDLE 抽取）。

实测网络规模可观（45,766 节点、107,528 边、13,878 篇多作者论文，全量无抽样），但质量有两处硬伤。其一，**ID 体系断裂**：`zh_author` 与 `zh_paper` 的 JOIN 只命中 799 条，说明两张表的论文 ID 不是同一套编码，网络只能在 author 表内部按 `paper_id` 聚类，无法与论文题录、期刊、机构、年份联动。其二，**姓名未消歧**：Top20 全部是「王伟、张磊、张伟、张丽」这类通名，度值是把所有同名作者合并后的结果，一个「王伟」可能对应几十位不同学者。再叠加网络极稀疏（p90 度 = 2，度中心性量级 $10^{-4}$）与「SRS 的节点是技术、本实现的节点是学者」这一对象平移，判定**部分支持**：算法可跑、可复算，但不能作为发布级中心度。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

本指标有两个需求锚点，均属图谱分析能力：

**锚点一（主）**：科技信息展示系统 → 技术知识图谱 → **展示关键路径和关键节点** → 关键节点识别与标记（SRS §1.1.1.1.4.1.2.3.2）。功能描述为「系统能够接收后端分析得出的关键路径数据……根据节点的重要性指标（如中心度、影响力等）自动识别关键节点，并在图谱中以特殊样式进行标记，如放大节点、改变颜色或添加特殊图标」。这是**前端消费**侧：中心度决定哪些节点被放大/变色。

**锚点二（辅）**：科技专题服务算法库 → 产业全要素图谱 API 服务 → **网络指标计算 API**（「支持计算指定图谱网络中的网络密度、中心度等网络指标」），以及「区域创新协同分析模型」把中心度列为三大网络指标之一（「中心度（评估关键节点的辐射影响力）」）。这是**服务供给**侧：中心度是一个可被 API 调用的通用网络指标。

两个锚点都没有限定「网络是什么网络、节点是什么节点」。本实现选择**学者合作网络**（人物节点、合著关系边），属于把通用的「节点重要性」落到科研关系场景，需在 §1.3、§四 明确这一对象平移。

### 1.2 为什么需要「中心度」这个指标

图谱可视化的根本矛盾是节点太多、边太密，用户看不出重点。需求给出的解法是「按重要性指标自动识别关键节点并视觉强化」——把有限的视觉变量（大小、颜色、图标）分配给最重要的少数节点，其余保持默认样式。中心度就是「重要性」的第一候选度量：它只依赖网络拓扑，不需要额外属性数据，且含义直观——连接越多，节点越处于网络中心。

对科研关系场景，中心度的业务含义是「谁是合作网络里的枢纽」：一位学者与多少位不同学者合著过论文，决定其在合作网络中的辐射面。这对人才画像、团队识别、引才引智都有直接用途：枢纽学者往往是跨机构合作的桥梁，也是团队带头人的候选。相比「论文数」「被引数」等产出型指标，中心度刻画的是**关系位置**而非**产出规模**，二者互补——一位高产但独作的学者中心度可能很低。

## 二、计算过程

> **口径说明**：本节按 AI-20261016 口径撰写（**非王惠定义**，故无 §五 对照）；已由 `metrics/repro/M_INNOV_DS_02_PATH_001.py` 在**三方库 `gkx`**（`183.240.141.251:3318`，只读）**实测跑通**，62,002 行作者全量入网、全量算中心度，产物为 `M_INNOV_DS_02_PATH_001_out.json`。本版不再读 BUNDLE，也不再抽样。文内引用为 SCI 叙述式；完整题录见文末「参考文献」。

### 2.1 方法选择：为什么是度中心性而不是中介或接近中心性

中心性是一族指标，选哪一种取决于想回答的问题。度中心性回答「谁直接连的人最多」，中介中心性回答「谁处在别人的最短路径上（桥）」，接近中心性回答「谁离所有人都近」，特征向量/PageRank 回答「谁连的人本身也重要」。本指标的业务语境是「图谱里哪些节点该被放大」——需要的是**一眼可解释、可增量、可批量**的重要性分数，而不是精细的结构洞分析。

度中心性的优势正在这三点：公式只有一步除法（$\deg/(n-1)$），任何非技术用户都能理解「他合作过 37 位学者」；新增一篇论文只需给相关作者度数 +1，无需重算全图；计算复杂度 $O(|E|)$，45,766 节点的图在秒级完成。这与 Freeman 对中心性三分类的原始论述一致：度中心性衡量「活动量/直接联系」，是局部指标，不依赖全图结构 (Freeman, 1978)。Newman 对科学合作网络的实证也表明，度分布本身就是刻画合作结构的核心统计量，且合作网络的度分布通常呈重尾，高度节点天然是「关键节点」候选 (Newman, 2001)。

反观另外两族：中介中心性语义上更贴近「关键节点」（它刻画的正是 SRS 所说的「核心脉络」上的必经之处），但标准算法需对每个节点做单源最短路，复杂度 $O(|V||E|)$，45,766 节点、107,528 边的图全量计算约需数十分钟到数小时，且结果对边的增删极敏感，不适合「实时更新」；Brandes 的快速算法把常数降下来，但没有改变量级 (Brandes, 2001)。接近中心性在**非连通图**上甚至没有定义（不连通节点间距离为无穷），而本网络因 ID 断裂与稀疏性必然是非连通的（p90 度仅 2），直接不可用。因此度中心性是当前数据条件下唯一「语义说得通、算得动、更新得起」的选择；中介中心性列为二期增强（附录 C.5）。

### 2.2 步骤 1｜数据源与 ID 体系：一张表自洽，两张表断裂

网络构建的第一步是确定「作者—论文」关系从哪里来。库内相关表有两张：`gkx.dwd_zh_author`（62,002 行，作者维度，含姓名与 `paper_id`）与 `gkx.dwd_zh_paper`（100,900 行，论文维度，含题录；主键是 `id` 而非 `paper_id`）。直觉做法是用 `paper_id` 把两表 JOIN，从 `zh_paper` 取年份、期刊、机构，再在 `zh_author` 内两两成边。实测 JOIN 只命中 **799** 条——相对于 62,002 行的作者表，命中率约 1.3%。

这说明两张表的论文 ID 不是同一套编码：可能一张是内部自增 ID、另一张是外部来源 ID（DOI/知网 ID），也可能采集批次不同导致 ID 空间错位。后果是严重的：网络只能在 `dwd_zh_author` **表内部**按 `paper_id` 自洽构建，无法挂接论文的年份、期刊、机构、学科属性。这意味着本实现无法做「分年度合作网络」「分机构合作网络」「分学科中心度」——而这些恰恰是科研关系分析最常用的切片（Newman 在实证中也是分领域、分年份考察合作网络演化的）(Newman, 2001)。

工程上，脚本采取「先自洽、后补挂」策略：用 author 表内部的 `paper_id` 分组，同组作者两两成边；论文属性暂不挂接，留待 ID 打通后增量补。这一取舍保证了网络可建、指标可算，但把「属性切片」能力推迟到二期。§四 把 ID 对齐列为第一优先缺口，因为它的修复成本（一次映射表构建）远低于收益（解锁全部分层分析）。

### 2.3 步骤 2｜网络构建：13,878 篇多作者论文长出 107,528 条边

建边规则是「同一 `paper_id` 下的任意两位作者之间连一条无向边」。一篇 $k$ 位作者的论文产生 $\binom{k}{2}=k(k-1)/2$ 条边：2 人 1 条、3 人 3 条、5 人 10 条、10 人 45 条。实测有 **13,878** 篇多作者论文（其余论文为单作者或无作者记录，不产生边），共产出 **107,528** 条边、涉及 **45,766** 个节点。平均每篇多作者论文贡献约 7.7 条边，反推平均作者数约 4—5 人，与中文论文的合著规模相符。

这里必须交代与旧版的差异来源。20261020 版脚本对作者表用了无序 `LIMIT 60000` 抽样（`author_links_sample=60000`），只覆盖 62,002 行中的 6 万行；20261021 版改为全量 62,002 行，因此节点与边分别增加 1,258 和 3,194。为排除「换库导致数据缩水」的可能，本版用同一全量结果截取前 60,000 行复算，得到 44,508 节点 / 104,334 边 / 13,431 篇，与旧 out.json 三项完全一致——说明 gkx 镜像无损，旧值只是抽样值，新值才是全量真值。

网络规模的健康度要用密度与度分布判断，不能只看节点数。密度 $\rho=\dfrac{2|E|}{|V|(|V|-1)}=\dfrac{215{,}056}{45{,}766\times45{,}765}\approx1.03\times10^{-4}|}{|V|(|V|-1)}=\dfrac{208{,}668}{44{,}508\times44{,}507}\approx1.05\times10^{-4}$，即十万分之一量级——这是一个**极稀疏**的网络。更直观的是度分布：实测 **p90 度 = 2**（全量与旧 6 万子样本相同），意味着 90% 的学者只与 1—2 位不同学者合作过。这与「合作网络应呈重尾」的经典结论方向一致（多数节点度很低、少数节点度很高），但本网络的低度端过于极端：大量学者只出现在一篇论文里，形成大量「孤立的星形小组」，组与组之间没有桥 (Newman, 2001)。

稀疏性带来两个直接后果。其一，中心度的区分度低：Top1 度 37、Top20 度 18，而中位数接近 1，绝大多数节点挤在 0—2 之间，分数几乎无法区分「普通合作者」与「完全不合作者」。其二，网络大概率是非连通的（多个独立小组），这使得接近中心性不可用、中介中心性大量为 0（因为没有跨组最短路径可经过）。这两点在 §2.4、§2.6 进一步量化。

### 2.4 步骤 3｜度中心性计算：$10^{-4}$ 量级的分数为什么不能直接展示

度中心性 $C_D(v)=\deg(v)/(n-1)$，分母取 $n-1=45{,}765$（标准归一化，使完全图中心节点的值为 1）。实测 Top1「张磊」「王伟」并列度 37，$C_D=37/45{,}765=0.000808$；Top20「刘斌」度 18，$C_D=18/45{,}765=0.000393$。也就是说，全库最高中心度不到千分之一。

这个量级是「大而稀疏网络」的必然结果：分母是 4.4 万，分子只有几十。它带来三个工程影响。第一，**不能直接展示**：前端若把 0.000808 显示为「中心度」，用户无法理解；必须做缩放（如乘以 $10^4$ 或以 Top1 为 100 做相对化）。第二，**阈值难以设定**：若要「自动识别关键节点」，需要回答「度 ≥ 多少算关键」，而度分布是连续衰减的（37、37、30、26、26、24……），没有自然断点，只能用 Top-N 或分位数（如 P99.9）。第三，**归一化方式影响可比性**：若改用「度 / 最大度」的相对中心度，Top1 恒为 1、其余按比例缩放，展示更友好但失去跨网络可比性；若保留 $n-1$ 归一，则跨网络可比但数值极小。SRS 未规定，需产品侧选定（§四 列为待定项）。

另一个细节是「加权合作强度」：脚本同时输出 `weighted_collab`，即该学者所有合著论文的 `(k-1)` 之和——度数只数「合作过多少位不同学者」，加权度还数「合作了多少次」。两者排序并不一致：Top20 中「张敏」度 20、加权 74，而「刘涛」度 20、加权 86，说明刘涛与同一批人合作更频繁。这一差异有业务价值（「广度」vs「频次」），但当前脚本只用度排序，加权度仅作参考列，未参与 Top20 排序，需在方法页说明。

### 2.5 步骤 4｜姓名消歧：Top20 全是通名，度值其实是「同名合并度」

本实现最严重的问题不在算法而在实体身份。`dwd_zh_author` 只有姓名（`author_name`），没有 ORCID、没有作者内部 ID、没有机构+学科的稳定组合键。因此「王伟」这个字符串在表中出现的所有记录被当作**同一个人**，其度数 37 实际上是「所有叫王伟的作者的合作关系并集」。

后果在 Top20 上一目了然：张磊（37）、王伟（37）、张伟（30）、张丽（26）、张健（26）、王敏（24）、王磊（24）、李强（23）……全部是中文高重名率姓名。据公安部姓名报告口径，王伟、张伟、李伟等长期位居重名榜首，单名对应的真实人数可达数十万。在一个 4.4 万节点的学者网络里，一个通名背后可能对应几十位不同学者，度值是把他们的合作者全部合并后的结果——这不是「某位学者是枢纽」，而是「这个名字很常见」。

这一缺陷无法用算法修补，只能靠数据治理：接入 ORCID/Scopus Author ID、用「姓名 + 机构 + 学科」三元组做规则消歧、或用合著者集合相似度做聚类消歧（同一人的不同记录往往共享多位合著者）。在消歧完成前，中心度只能作为「姓名级」指标使用，不能作为「学者级」指标发布。这也是本指标判「部分支持」而非「完全转换支持」的核心原因：网络能建、分数能算，但节点的身份不唯一，指标的主体就不成立。

### 2.6 步骤 5｜排序、Top-N 与「关键节点」的业务解释

按 $C_D$ 降序取 Top20（脚本输出），得到的就是 SRS 所说的「关键节点」候选。但把这份榜单交给业务方前，必须回答三个解释性问题。

第一，**Top-N 还是阈值**？SRS 说「自动识别关键节点」，没有说识别几个。当前实现取 Top20，是一个任意但可用的约定；生产环境应按图谱规模动态取（如 $N=\max(20,\lceil0.1\%|V|\rceil)$），并允许前端配置。

第二，**度中心性能否代表「核心脉络」**？SRS 的语境是「技术发展的核心脉络和关键节点」，其中「脉络」暗示路径结构，而度中心性只数直接连接、不看路径。一位与 37 人各合作一次的学者，与一位处在两个大学科群之间、只有 5 个合作者但都是各组桥梁的学者，后者更符合「关键节点」的直觉，但前者度更高。这说明度中心性与需求语义存在系统性偏差，中介中心性才更贴近「脉络」（Freeman, 1979）。当前选择是成本与语义的折中，需在方法页披露。

第三，**同名污染如何影响榜单**？由于 Top20 全是通名，榜单的稳定性极差：新增一篇由 5 位「王伟」合著的论文，会让「王伟」的度跳增 4，可能直接改变排名。更严重的是，同一批数据在不同采集批次下，「王伟」的记录集合不同，度值就会漂移。因此当前榜单只能用于「内部探索」，不能用于对外发布或人才评价——后者需要消歧后的稳定 ID。

#### 2.7.3 结果解读

1. **网络可建、规模可信**：45,766 节点、107,528 边、13,878 篇多作者论文，与 62,002 行作者表、100,900 行论文表量级自洽，说明 author 表内部的 `paper_id` 是可用的分组键。

5. **并列排序只有工程解**：Top10 中「张磊」「王伟」同度 37，本版用姓名做确定性二级键，保证多次运行顺序一致；但姓名次序无业务含义，仍需按加权度或稳定哈希定义业务二级键。
6. **量级需缩放**：$10^{-4}$ 的分数不能直接展示，需相对化（Top1=100）或乘以 $10^4$。

## 四、数据缺失情况

主指标可构建（度中心性可算）；残余缺口按优先级：

1. **作者身份消歧**（第一优先）：无 ORCID/内部 person id，节点身份不唯一，Top20 全是通名。需接入 ORCID/Scopus Author ID，或构建「姓名+机构+学科」规则消歧与合著者集合聚类消歧；这是从「姓名级」升到「学者级」的唯一路径。
2. **双 ID 体系断裂**：`zh_author.paper_id` 与 `zh_paper` 主键仅 799 命中。需建 ID 映射表（DOI/题名+年份指纹匹配），打通后才能做分年、分机构、分学科网络。
3. **网络极稀疏**：p90 度 = 2，90% 节点只有 1—2 个合作者，中心度区分度低。根因是作者表仅覆盖部分论文（62,002 行 vs 论文表 100,900 行）且单作者论文多；需扩大作者覆盖、补全多作者论文的作者列表。
4. **并列排序只有工程解**：同分者当前按姓名排序，顺序稳定但无业务含义。需把二级键改为「度 → 加权合作强度 → 稳定哈希」，并在结果表存 `sort_key`，避免前端各自排序。
5. **中心性类型单一**：仅度中心性，未实现中介、接近、特征向量/PageRank。SRS 的「核心脉络」语义更接近中介中心性，需二期补齐。
6. **节点类型与 SRS 不一致**：SRS 的图谱节点是技术实体，本实现是学者；需建立「学者—技术」映射（作者论文的关键词/IPC）才能对齐需求。
7. **无时效切片**：缺年份挂接，无法做「近 5 年合作网络」，早年合作关系与近期混算。
8. **无物化结果面**：需落 ADS（节点 id、姓名、度、中心度、加权度、网络版本、计算时间），否则前端每次都要全量重算。

**甲方侧建议**：本指标一期只能作为「合作广度探索榜」内部使用，不可对外称「关键节点」；二期优先做作者消歧与 ID 打通（两项都是一次性数据治理，收益覆盖全部科研关系类指标），再补中介中心性并完成与技术图谱节点的对齐。

## 附录 C　中心度类指标权威构建方法可行性报告（完整版）

### C.1 报告目的与范围

回答三问：(1) 权威文献如何定义与选择中心性指标？(2) 本项目库表能落地哪一种？(3) 支持度几何？范围限定为「合作网络节点中心性」，不含整体网络密度（另有 `M_SVC_GRAPH_DENSITY` 等）与区域协同指数（归算法库模型层）。

### C.2 需求语义锚定

SRS 要求「依据重要性指标识别关键节点并视觉强化」，算法库要求「可计算图谱网络的中心度」。三条约束：①能对每个节点给分；②分数可比较、可排序；③能随图谱更新重算。未限定中心性类型与网络类型，故方法选择需同时考虑语义贴合与工程可行。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：度中心性（采用）

Freeman 把中心性概念化为「点度」「中介」「接近」三类，其中度中心性衡量节点的直接联系数量，是最基础、最局部的度量 (Freeman, 1978)。优势：$O(|E|)$ 计算、可增量、语义直观。劣势：不看全图结构，无法区分「广泛合作」与「桥接位置」。

#### C.3.2 方法族 B：中介中心性

中介中心性统计经过节点的最短路径比例，刻画「桥」或「把关人」角色；Freeman 的实验研究显示它与度中心性并不高度相关，二者捕捉不同维度 (Freeman, 1979)。Brandes 给出 $O(|V||E|)$ 的快速算法 (Brandes, 2001)。可迁移性：高（语义最贴近「核心脉络」），但当前图规模下全量计算成本较高，且非连通图上大量节点为 0。

#### C.3.3 方法族 C：接近/特征向量中心性

接近中心性要求图连通（否则距离无穷），本网络不满足；特征向量/PageRank 需全图迭代，对稀疏、非连通图收敛慢且结果受悬挂节点影响。可迁移性：中低（当前不可用）。

#### C.3.4 方法族 D：科学合作网络实证范式

Newman 对科学合作网络的实证给出度分布、连通分量、平均距离、聚类系数的分析框架，并指出合作网络普遍呈重尾度分布、高度节点对应高产/跨机构学者 (Newman, 2001)。可迁移性：高（提供分布基线与榜单解释框架，但不能直接给出「关键节点」判定）。
