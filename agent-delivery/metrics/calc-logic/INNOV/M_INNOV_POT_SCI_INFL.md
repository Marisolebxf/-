## 摘要

「产业科学影响力」要回答的是「这个产业的论文被引得多不多、国际合作多不多」，对象是**产业**，不是机构也不是区域。需求原文（产业发展潜力评估 §7.3.4）明确给出两个分量：「论文被引次数、国际合作论文比例」，王惠 calc-logic 把它落成二维加权平均、取值 0—100。本文严格按这两个分量取值，没有引入影响因子、期刊分区或下载量，因为 `dwd_zh_journal.impact_score` 与 `dwd_zh_paper.download_num` 在 `gkx` 里整列为空（陷阱 §3.10），任何用它们加权的做法都是造数。

论文级数据是好的：`dwd_zh_paper_citation` 20,031 行、`citation_num` 全部非空、合计 **144,020** 次，中位 3、P90 16、P99 60、最高 670；`dwd_zh_author` 62,002 行覆盖 20,048 篇，与上表按 `paper_id` 交集 **20,031** 篇，两表同域，可以直接算「每篇被引 + 每篇作者单位」。

问题出在产业归属。两表的 `paper_id` 与 `dwd_zh_paper.id` 只有 **782/100,900（0.78%）** 能对上，拿不到发表年与期刊；机构串到 `star_base_rows_gkx.json` 底册的匹配率是 **4.88%**（3,027/60,970 行），再要求机构有 `industry_l1` 时只剩 **0.36%**（223 行）——可归属论文 **127 篇（0.63%）**，最高的产业（科学研究和技术服务业）也只有 33 篇。按 100 篇的入榜门槛，**没有一个产业达标**，所以本文不产出产业排名。

国际合作维同样薄：按 affiliation 命中外国国别词，20,031 篇里只有 **58 篇（0.29%）**，合计被引 925 次，篇均 15.95 次（国内篇均约 7.15 次）。方向是对的（国际合作论文被引更高），但 58 篇的样本量、且方差近 0，不能用来给产业排序。

因此本文交付两件事：一是**论文级**的完整统计（20,031 篇、144,020 次被引、58 篇国际合作），二是**机构级 D1 排行**（≥20 篇的 9 家机构，中山大学 104 篇 910 次、华南理工 29 篇 726 次、南方医科 55 篇 543 次）。产业级结果只写进 `_out.json` 的 `industry_level`，标注「覆盖 <1%，不可对外发布」。按 §〇 判**部分支持**。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技发展态势 → 科技创新评估 → 产业发展潜力评估 → 科学影响力评估**。

需求对该模块的定位是「通过收集和分析国内企业产业投入、技术或产品的成熟度、形成的产值等产业发展潜力指标，以及科学影响力、技术影响力等科技影响力指标，构建产业发展潜力评估体系」。这句话里，「科学影响力」与「技术影响力」并列，前者看论文，后者看专利；两者都以**产业**为单位。

「科学影响力评估」一节的具体任务是：

> 基于论文引用、国际合作等数据，评估特定产业的科学影响力，用户可查看科学影响力指标（如论文被引次数、国际合作论文比例等）的分布情况和排名，了解产业的科学影响力水平。

页面任务可以拆成四条：

| 页面任务 | 对指标的要求 |
|---|---|
| 产业科学影响力排名 | 每个产业一个 0—100 分，可排序 |
| 分量分布图 | 被引次数、国际合作比例分别可见 |
| 产业档案 | 能下钻到支撑论文/机构 |
| 与产业技术影响力并列 | 两个指标的量纲要一致（都是 0—100） |

第三条是本文保留机构级与论文级结果的原因：即使产业级排名做不出来，产业档案页仍需要「这个产业有哪些机构在发论文、被引多少」的下钻能力。

### 1.2 为什么需要「产业科学影响力」这个指标

产业发展潜力评估如果只看投入（R&D、项目经费）与产出（产值、专利），会漏掉「这个产业的知识底座有多厚」。一个产业如果论文被引高、国际合作多，说明它连接了外部知识网络，技术追赶的起点更高；反之，如果只有专利数量没有论文支撑，可能是代工型扩张。

被引与国际合作这两个分量回答的是不同问题：被引回答「工作被谁用」，国际合作回答「知识从哪来」。一个产业可能被引很高但全是大团队内部自引，也可能被引一般但国际合作广泛。两者并列，才能把「内向型高产」与「外向型连接」区分开。

需求把这两个分量写成「如……等」，说明它们是示例而不是封闭列表；但本文不擅自加第三个分量（例如影响因子），因为库内没有可用字段，加了就是造数。

### 1.3 需求文档是否给出定义方法

**需求文档给了分量，没给公式。**

原文只列了两个示例分量（论文被引次数、国际合作论文比例），没有给出：

- 两个分量的权重；
- 被引是总量、篇均还是归一化；
- 国际合作是「作者国籍≥2」还是「机构国别≥2」；
- 产业如何界定（国民经济行业门类 / 产业链 / 自定义产业标签）；
- 产业内多机构多论文如何汇总（求和 / 均值 / 份额）；
- 0—100 的归一方式与分档阈值。

王惠 calc-logic 补了「二维加权平均」与「国际合作＝作者地址国别≥2」，但**没有给权重**，也没有说明产业归属用哪张表。本文的产业归属选择（`star_base_rows_gkx.json` 的 `industry_l1_name`）与等权假设都是工程决策，必须标注。

### 1.6 推测原意与推测定义

**推测原意**：产品要的不是「学术评价」，而是「产业知识底座体检」——给产业政策制定者看「这个产业的研究有多强、跟国际接不接轨」。

**推测定义（本文采用，产业级）**：

> 对产业 $k$，记 $C_k$ = 该产业可归属论文的被引合计，$I_k$ = 国际合作论文数 / 该产业可归属论文数；则
> $$
> \text{score}_k = 50 \cdot \text{rank}(C_k) + 50 \cdot \text{rank}(I_k)
>
$$
> 仅对「可归属论文 ≥100 篇」的产业计算。本文实测无产业达标，故 `ranked=[]`。

**论文级定义（本文实际交付）**：$\text{cited\_per\_paper} = \sum citation\_num / N$，国际合作占比 $= I/N$，按机构聚合并给 D1 百分位分。

**为什么产业门槛设 100 篇**：33 篇的产业算出来的国际合作比例，分母太小，一篇之差就能让比例翻倍；100 篇是「能谈比例」的最低样本量，也是本文对「不把噪声当排名」的自我保护。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是王惠 calc-logic 的二维加权平均。本文没有改维度，但把「产业级合成」降级为「论文级 + 机构级」，原因是产业归属覆盖率只有 0.63%。这不是公式问题，是对象连接问题：公式要的是「产业内的论文集合」，而库内没有「论文→产业」的稳定键。

降级的具体做法是：先算每篇论文的被引与国际合作标记，再按作者单位聚合到机构，最后用底册的 `industry_l1_name` 尝试把机构映射到产业。前两步覆盖率足够（20,031 篇全有被引，3,027 行作者可匹配机构），第三步只有 223 行可落产业。本文把前两步作为交付，第三步作为诊断。

### 2.2 口径拆解：对象、集合、归一

**对象**：论文（`paper_id`）→ 机构（底册名）→ 产业（`industry_l1_name`）。三层对象逐层收窄，每层都记录覆盖率。

**集合**：以 `dwd_zh_paper_citation` 的 20,031 个 `paper_id` 为基集，与 `dwd_zh_author` 的 20,048 篇求交，得 20,031 篇。这个基集不是全库 100,900 篇，而是「有被引记录」的子集；两者 id 交集只有 782，说明被引表覆盖的是另一批论文（很可能是供应方按主题抽取的样本）。本文在 §三明确这一点，不把它当全库。

**归一**：论文级不归一（保留原始被引次数与比例）；机构级对「被引合计」做池内百分位（≥20 篇的 9 家机构）；产业级本应做二维百分位，但因无产业达标而未执行。

**合作分摊**：一篇论文命中多个机构时，机构级各记一次（因为是机构视角）；产业级按 $1/n$ 分摊被引（因为产业视角不能重复计数）。两种口径在 `_out.json` 里分别写明。

### 2.3 依赖分解（两跳停）

| 跳 | 依赖 | 承载 | 状态 |
|---|---|---|---|
| 1 | 论文 → 被引 | `dwd_zh_paper_citation(id, citation_num)` | 20,031 行，100% 非空 |
| 1 | 论文 → 作者单位 | `dwd_zh_author(paper_id, institution, affiliation)` | 62,002 行 / 20,048 篇，60,970 行有 institution |
| 2 | 机构 → 产业 | `dwd_org_base_info.industry_l1_name`（底册快照） | 186,804/189,116 行有 l1，但论文机构命中率 0.36% |
| 2 | 论文 → 年份/期刊 | `dwd_zh_paper.id` | 仅 782 个 id 交集，**本批不用** |

「两跳停」：走到机构就停，不再往「论文明细/期刊/学科」走。原因是 id 域不通（782 交集），继续走只会引入更多假设。

### 2.4 算路 / SQL

本指标**零新增 SQL**，全部读 `_probe_a26.py` 已落盘的快照（该探针 4 条 SQL，均 ≤10 万行）：

```sql
-- 探针已执行（code/_probe_a26.py），本指标只读结果
SELECT id, citation_num FROM gkx.dwd_zh_paper_citation;          -- 20,031 行
SELECT paper_id, institution, affiliation FROM gkx.dwd_zh_author; -- 62,002 行
SELECT id, doi FROM gkx.dwd_zh_paper;                             -- 100,900 行（仅取 id 域）
```

算路：

1. 取 `cites = {id: citation_num}`（20,031）；
2. 取 `auths = {paper_id: [(institution, affiliation)]}`（20,048 篇）；
3. 交集 20,031 篇；
4. 每篇：拆分 institution（按 `; ； , ， 、 / |`）→ 逐 token 匹配底册名（精确 → 最长前缀 4—30 字）→ 去重得机构集合；
5. 机构集合 → `industry_l1_name` 集合；
6. 国际合作：任一 affiliation 命中外国国别词（58 个中文词 + 55 个英文词，港澳台不计）；
7. 论文级统计 → 机构聚合 → 产业聚合（1/n 分摊）→ 门槛筛选。

### 2.5 清洗规则

| 规则 | 处理 | 影响 |
|---|---|---|
| `citation_num` 为空 | 不剔除，按 0 计（实测 0 行） | 0 |
| `citation_num=0` | 保留（实测 0 行，最小值 1） | 0 |
| 作者 institution 为空 | 跳过该行，不影响论文被引 | 1,032 行 |
| 机构 token 含多个单位 | 按分隔符拆开，逐 token 匹配 | — |
| 机构匹配到底册但无 l1 | 计入机构级，不计入产业级 | 2,804 行 |
| 港澳台机构 | 不算「国际合作」 | — |
| 外国国别词误命中（如「美国」出现在中文机构名） | 无法排除，计入误差 | 估计 <5 篇 |

清洗原则是「宁可少算，不可错算」：机构匹配不到就不进产业级，不用模糊匹配硬凑；国际合作识别不到的就不标记，不用「英文机构名」这种弱特征。

### 2.6 结果解读

论文级：20,031 篇、144,020 次被引、篇均 7.19、中位 3、P90 16、P99 60、最高 670。分布是典型的重尾：一半论文被引 ≤3 次，前 1% 拿走 60 次以上。这符合中文论文被引的一般形态，也说明「用篇均会被少数高被引拉高」——所以机构级用「被引合计」而不是篇均做 D1，避免小样本机构因一篇高被引冲上榜首。

机构级：9 家机构 ≥20 篇。中山大学 104 篇 910 次（篇均 8.75）、华南理工 29 篇 726 次（篇均 25.03）、南方医科 55 篇 543 次（9.87）、华南农业 31 篇 477 次（15.39）、暨南 44 篇 424 次（9.64）、广州医科 39 篇 333 次（8.54）、广州大学 23 篇 270 次（11.74）、中山一院 35 篇 175 次（5.00）、孙逸仙纪念医院 21 篇 108 次（5.14）。华南理工篇均最高（25.03），但只有 29 篇；中山大学总量最高，篇均中等。这正是「总量 vs 篇均」需要同时展示的理由。

国际合作：58 篇（0.29%），合计被引 925 次，篇均 15.95 次，是国内的 2.2 倍。方向与文献一致（国际合作论文被引更高），但 58 篇的分母太小，且 9 家机构里有 8 家的国际合作篇数为 0——这个分量在当前数据上无法区分机构，更无法区分产业。

产业级：17 个产业有可归属论文，最高的是科学研究和技术服务业 33 篇（141.5 次分摊被引）、教育 22 篇（111.0）、电力热力 14 篇（108.0）、制造业 13 篇（79.0）、建筑业 13 篇（46.5）。全部低于 100 篇门槛，`ranked=[]`。国际合作在 17 个产业里**全部为 0**，进一步说明 D2 在当前数据上不可用于排序。

## 四、数据缺失情况

### 4.1 缺失清单

| 缺失项 | 现状 | 影响 | 修复建议 |
|---|---|---|---|
| 论文→产业稳定键 | 机构串匹配 4.88%，有 l1 的仅 0.36% | 产业级排名不可交付 | 建「机构名→统一社会信用代码→行业码」映射表 |

### 4.2 对结论的影响边界

上述缺失**不改变论文级与机构级结论**：20,031 篇被引、3,027 行机构匹配都是实测，机构排行可复核。它们改变的是**产业级结论**：127 篇、17 个产业、最高 33 篇，任何排名都会被单篇论文扰动。

### 4.3 不可外推的三件事

第一，不能把这 20,031 篇当成「全库中文论文」：它与 `dwd_zh_paper` 的 id 交集只有 782，覆盖的是另一批论文（很可能是供应方样本）。第二，不能把「国际合作占比 0.29%」当成中国论文的国际化水平：这是中文期刊作者单位的文本命中率，英文合著大多不写在中文机构的 affiliation 里。第三，不能把机构级 D1 当成「机构科研实力」：它只反映这 20,031 篇样本里的被引，不含项目、专利、人才。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

| 二级 | 口径 | 计算逻辑 | 源字段 |
|---|---|---|---|
| 论文被引次数 | 产业相关论文被引合计 | `SUM(citation_num)` | `dwd_zh_paper_citation`、`dwd_scholar.citation_nums` |
| 国际合作论文比例 | 作者地址跨≥2 国的论文占比 | 国际合作论文数 / 论文数 | `dwd_zh_author`、`dwd_en_author` |

并写明「采用加权平均，二维」「选定产业入集」。

### 5.2 新方法概述

保留二维，补三件事：产业归属用 `industry_l1_name` 底册、机构匹配用「精确 + 最长前缀」、产业级设 100 篇门槛。因无产业达标，实际交付降为论文级 + 机构级，并把产业级结果留在 `_out.json` 里作诊断。

### 5.3 逐维对照表

| 维度 | 王惠原法 | 本文实现 | 差异与理由 |
|---|---|---|---|
| 论文被引 | 产业内 `SUM(citation_num)` | 论文级全量 + 机构级聚合；产业级 1/n 分摊 | 产业归属不足，降级到机构 |
| 国际合作 | 作者地址国别≥2 | affiliation 文本命中外国国别词 | 无国别字段，只能文本推断 |
| 学者被引 | `dwd_scholar.citation_nums` 可选 | **不用** | 学者级被引无法拆到单篇，会与论文被引重复计数 |
| 权重 | 加权平均，未给值 | 产业级本应等权；实际未执行 | 无产业达标 |
| 对象 | 产业 | 论文 → 机构 → 产业（逐层收窄） | 受数据约束 |

### 5.4 选用建议与理由

**建议采纳论文级 + 机构级交付，暂不发布产业排名。** 理由：论文级数据完整（20,031 篇、144,020 次），机构级有 9 家可排行；产业级只有 127 篇，发布排名会误导。

**建议甲方优先补三样**：论文主键统一（让被引表能挂年份）、机构统一社会信用代码（让机构能挂行业码）、作者国别字段（让国际合作可判定）。这三样补齐后，本指标可以从「部分支持」升到「完全转换支持」，且不需要改公式。

## 附录 C　产业科学影响力类似指标权威构建方法可行性报告（完整版）

### C.1 报告目的与范围

回答「在只有论文被引与作者单位两张表的前提下，能否构建产业级科学影响力」。范围限定在中文论文，不含英文论文、专利、项目。

### C.2 需求语义锚定

需求写「评估特定产业的科学影响力」，关键词是「产业」。如果只做机构排行，交付的是「机构科学影响力」，不是本指标。本文因此把产业级不可交付作为核心结论，而不是用机构级结果冒充。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：产业论文计量

OECD Scoreboard 与 NSF Indicators 都按产业/学科统计论文数、被引、国际合作占比。它们的共同前提是「论文有产业标签」——通常来自期刊学科分类或作者单位行业码。本项目缺的正是这个标签。

#### C.3.2 方法族 B：归一化引用影响力

FWCI/CNCI 用「同学科、同年、同文献类型的期望被引」做分母。它需要学科码与年度基线，本项目两者都缺，且被引表无年份。

#### C.3.3 方法族 C：国际合作网络

CWTS 用合著国别对构建网络。本项目无国别字段，只能从 affiliation 文本推断，58 篇命中，不足以建网络。

#### C.3.4 方法族 D：产业技术复杂度

Hidalgo-Hausmann 的经济复杂度用出口结构推产业能力，对象是技术复杂度而非科学影响力，不适用。

### C.4 数据可行性详细分析

#### C.4.1 被引维

20,031 行、100% 非空、合计 144,020。单看这一维，数据质量好；问题是它覆盖的不是全库论文（id 交集 782）。

#### C.4.2 国际合作维

62,002 行作者、60,970 行有单位，但无国别字段。文本推断命中 58 篇（0.29%），且 9 家机构里 8 家为 0。该维在当前数据上不可用于排序。

#### C.4.3 产业归属

底册 186,804 行有 l1，但论文机构串命中底册仅 3,027 行（4.88%），其中 223 行（0.36%）的机构有 l1。产业归属是瓶颈。

#### C.4.4 方法—数据对照矩阵

| 方法 | 需要的输入 | 库内状态 | 可行性 |
|---|---|---|---|
| A 产业论文计量 | 论文 + 被引 + 产业标签 | 缺产业标签 | 论文级可行，产业级不可行 |
| B FWCI/CNCI | 学科码 + 年份 + 被引 | 缺学科码、缺年份 | 不可行 |
| C 国际合作网络 | 国别字段 | 无 | 不可行 |
| D 技术复杂度 | 出口/专利结构 | 对象不符 | 不适用 |

### C.5 推荐构建方案（工程可执行）

1. 以 20,031 篇为基集，算被引与国际合作标记；
2. 机构匹配用「精确 + 最长前缀」，输出 3,027 行匹配明细；
3. 机构 → 产业只在有 l1 时落，输出 223 行；
4. 产业级设 100 篇门槛，未达标不排名；
5. 机构级出 D1 百分位（≥20 篇），作为可交付替代。

### C.6 风险与残余不确定性

- 20,031 篇不是全库，机构排行有样本偏差；
- 国际合作文本推断会漏掉英文合著（中文期刊不写英文单位）；
- 机构名前缀匹配可能把「中山大学附属第一医院」并到「中山大学」（本文按最长前缀， actual 会分开，但仍有误并）；
- 产业 l1 是门类级，粒度粗。

### C.7 可行性总判（完整版结论）

论文级与机构级可行，产业级不可行。判「部分支持」，与 `_out.json` 的 `support_judgment` 一致。
