## 摘要

「科学论文数量」回答的是一个纯计数问题：在选定领域、选定时间粒度、选定机构或地域下，有多少篇论文。它不做影响力、不做加权、不做质量分层——那是 `M_INNOV_PAPER_INFLUENCE` 与 `M_INNOV_SCHOLAR_INFLUENCE` 的事，本条只数篇数，且必须能按年、季、月三种粒度切换。

实测数据面是本文档 8 个指标里最干净的一个：`gkx.dwd_zh_paper` 100,900 行、100,900 个互异 `id`，`cover_year_start` 100% 可解析，作者串 JSON 解析零失败，机构名 84,320 个、署名实例 436,086 个，城市归属 93,817 篇（92.98%）。按年看，1980—2013 是长尾（每年 2—717 篇），2014 年起进入千篇级，2017 年达到 6,903 篇的平台期，2018—2023 稳定在 6,067—6,758 篇之间，**2024 年突然跳到 32,379 篇**，2025 年回落到 6,548 篇、2026 年只有 2,989 篇（截至 8 月）。

2024 年这个尖峰是本文最重要的披露项。它占全库 32.09%，是 2023 年的 4.87 倍，而前后两年都在 6,500 量级；季度序列进一步显示 2024Q1—Q4 分别为 7,272、8,729、7,762、8,616 篇，四个季度同时抬高，不是某一个月的数据事故，而是**整批采集一次性补录**的形态。剔除 2024 年后，2022—2023 两年均值 6,491 篇对 2019—2021 三年均值 6,422.7 篇只有 +1.06%，与「+135.42%」的含尖峰读数相差两个数量级。因此本文同时给出两个数，并把 `base_years_used` / `base_years_missing` 写进 `_out.json`，任何对外图表都必须在 2024 处断点标注。

机构维与地域维可用但口径不同：城市是「篇」口径（93,817 篇可归属，其中 21,217 篇有多个城市，按署名全部计入时各城之和会大于篇数），机构是「署名实例」口径（436,086 个实例，高校占 327,891 个、企业 49,282 个、院所 27,360 个、医院 13,626 个、其他 17,778 个）。这两个口径不能混在一张表里相加，本文在 §2.2 单独说明。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技发展态势 → 科技创新评估 → 科学创造力评估 → 科学论文数量分析**（需求原文 1.1.1.1.4.1.7.1.1）。

需求对该页的定位是「通过收集和分析科学论文创造的数量、科学网络的中心性、科学研究的前沿性等关键指标，构建科学创造力评估体系」。在这个体系里，论文数量是**唯一的规模底座**：中心性要在论文—作者网络上算，前沿性要在引文网络上算，两者的分母都来自论文池。因此本条不是一张可有可无的统计卡，而是另外两条指标的前置条件。

| 页面任务 | 对指标的要求 |
|---|---|
| 论文数量柱状图 | 按年出数，且 1980—2026 全序列可画 |
| 季度/月度折线 | 时间粒度可下钻到季、月，不需要重新入湖 |
| 研究机构排行 | 按机构名聚合，机构名需可读、可去重 |
| 地域分布 | 按城市聚合，需给出覆盖率而不是静默丢弃 |
| 领域筛选 | 按题名/关键词过滤后重算，不改变分母定义 |

### 1.2 为什么需要「科学论文数量」这个指标

专利与论文是创新链的两端：专利计量偏应用与商业化，论文计量偏基础研究。需求把「科学创造力」单独立成一节，正是为了不让基础研究被专利口径吃掉。如果只给专利数，一个以基础研究为主的机构会在所有评估里失分；如果只给论文数，一个以工程化为主的机构同样会失真。两者并列，才有「创新链前端与后端」的完整视图。

单看总数也不够用，因为论文产出有极强的年度节律与机构差异。本文实测：2017 年 6,903 篇是 2018—2023 平台期的最高点，2024 年是异常年，2025 年回落到 6,548 篇；机构侧广州中医药大学第一附属医院一家就有 1,552 个署名实例，而 84,320 个机构名里绝大多数只有个位数。若只给一个「全库 100,900 篇」，页面既看不出年际波动，也看不出机构集中度。因此本条必须同时交付三个切片（时间、机构、地域），这也是需求原文明确列出的三个维度。

第三个理由是口径纪律。论文数是最容易被「顺手加权」的指标：一旦把被引、影响因子、下载量揉进来，它就不再是「数量」，而会与 `M_INNOV_PAPER_INFLUENCE` 撞车。本文把「只计数」写成铁律，并在 §2.5 明确列出所有被拒绝的加工（不加权、不按被引加权、不用 `impact_score`、不用 `download_num`），保证这条指标在跨指标对比时是可解释的。

### 1.3 需求文档是否给出定义方法

**需求给了维度，没给公式。**

原文（第 877 行）是：「收集并统计特定领域内科学论文的发表数量，用户可按时间范围（年、季度、月）、研究机构、地域等维度查看论文数量分布情况，提供柱状图、折线图等可视化形式展示论文数量的变化趋势。」这段话明确了三件事：统计对象是「发表数量」、时间粒度有三级、切片维有机构与地域。没有明确的是：

- 「特定领域」如何入集（题名关键词、期刊分类、还是人工标定）；
- 一篇论文有多个机构署名时，机构维算一次还是多次；
- 一篇论文有多个城市时，地域维如何分摊；
- 会议论文、预印本、学位论文是否计入；
- 同一论文的中英文版本是否去重；
- 年份取发表年、收录年还是在线年。

`cfg_metric-INNOV-seed.yaml` 补了两条约束：一是「只消费 05 seq 96 论文项（1）–（4）；专利/交易额/资讯不进」，二是「本条『趋势』=已落库计数的历史图表，不是 seq 139 预测」，并禁止 reuse `M_INNOV_PAPER_INFLUENCE` / `M_CHAIN_REG_PAPERS` / `M_TECH_PAPER_PATENT_CNT`。也就是说，seed 只划边界，同样没有给公式。

本文的选择是：领域入集用题名/关键词二次过滤（不预筛分母），机构与城市按署名全计入并单独披露多归属篇数，年份取 `cover_year_start`，类型只统计库内已有的期刊论文。这四条都是工程决策，已在 §2.5 逐条写明，不能伪装成需求原文。

### 1.6 推测原意与推测定义

**推测原意**：产品要的不是「学术产出评价」，而是「一张能按时间、机构、地域三个方向切片的论文计数表」，用来看基础研究的规模与分布。它更接近「统计报表」而不是「评价指数」。

**推测定义（本文采用）**：

> 设论文集合 $P$、领域过滤条件 $F$（题名/关键词二次过滤，默认空），则对任意时间粒度 $g \in \{\text{年},\text{季},\text{月}\}$、任意切片 $d \in \{\text{机构},\text{城市}\}$：
> $$
> N(g,d\mid F)=\#\{p \in P : F(p),\ \text{year}(p)\in g,\ d \in \text{attr}(p)\}
>
$$
> 其中 $\text{attr}(p)$ 是论文 $p$ 的署名机构集合或城市集合；按篇计数时 $N$ 用 `COUNT(DISTINCT p.id)`，按切片计数时用「署名实例数」。

**为什么机构/城市用「署名实例」而不是「篇」**：一篇论文有 3 个单位，机构维若只算一次就得选一个「第一单位」，会系统性偏向第一作者单位；算三次则各机构之和大于篇数。本文选择后者（全计入），并在每个机构/城市结果旁标注该切片的口径是「署名实例」，同时把「多城市论文 21,217 篇」写进 `_out.json`，让使用者知道各城之和会比总篇数大。

**为什么不做归一化**：这是计数指标，归一化（除以机构人数、除以经费）需要分母表，而 `dwd_org_base_info` 无 R&D 人员/经费字段。任何「篇/人」「篇/万元」的强度口径都缺分母，本文不做，也不把它伪装成「标准化后的人数」。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是需求原文的三维（时间、机构、地域）与 seed 的「只计数」约束。本文没有改动维度，只补了四件原文未写的事：领域入集方式、多归属分摊、年份取值、类型边界。之所以必须补，是因为原文的「统计发表数量」在工程上有四种互不相容的实现，选哪一种会直接改变页面上的数字。

本文没有做的降级：没有把「篇」降成「署名实例」混报，没有把 2024 尖峰抹平，没有把 7.02% 未归属城市的论文摊到省会，也没有用英文库 1,387 篇去补中文库。所有降级项都在 §2.5 与 §四列明，且都保留了原始口径的对照数字。

### 2.2 口径拆解：对象、集合、归一

**对象**：论文实体 `dwd_zh_paper.id`。100,900 行、100,900 个互异 ID，一篇一行，无重复，因此「篇数」与「行数」在本文完全等价。这一点必须先确认，否则后面所有计数都不可信。

**集合**：全库 100,900 篇，不做机构/地域/年份预筛，也不做领域预筛（领域过滤在结果层按题名/关键词二次过滤）。理由是预筛会改变分母，而分母一旦改变，同一张图在不同筛选条件下的总数就不可比。

**归一**：不做。计数指标的分母是「1 篇」，不是 min-max，也不是百分位。本文唯一做过的归一化处理是把城市名统一到「市」级全称（例如把「深圳」与「深圳市」合并），这属于字符串规范化，不是数值归一。

**双计规则（必须单独说）**：机构维与城市维按署名全计入，因此两张切片表的合计都不等于 100,900。机构侧合计 436,086 个署名实例；城市侧可归属 93,817 篇，其中 21,217 篇有 ≥2 个城市。本文在 `_out.json` 的 `coverage` 里把三个数（篇数、署名实例数、多归属篇数）并列写出，避免使用者把切片合计误当总数。

### 2.3 依赖分解（两跳停）

| 跳 | 依赖 | 承载 | 状态 |
|---|---|---|---|
| 1 | 论文主档：ID、题名、发表年、作者串、类型、下载量 | `gkx.dwd_zh_paper` | 100,900 行，年份 100% 可解析 |
| 1 | 英文对照 | `gkx.dwd_en_paper` | 1,387 行，仅对照 |
| 2 | 论文 → 作者明细 | `dwd_zh_author` 62,002 行 | **本批不使用**：主表 `author_info_list` 已含机构名，再 JOIN 会引入一套不同的机构名写法 |
| 2 | 论文 → 引文明细 | `dwd_zh_paper_citation` 20,031 行 | 不使用：仅 782 行可对齐（0.775%），属 `M_INNOV_SCI_FRONTIER` 的口径 |
| 2 | 论文 → 关键词 | `dwd_zh_paper_classification` 20,048 行 | 不使用：仅 799 行可对齐，领域过滤改用题名匹配 |

「两跳停」的意思是：本指标只走第 1 跳，不再往作者明细或引文明细走。原因是计数指标只需要「谁署名了哪篇」，主表的作者串已经足够；一旦 JOIN `dwd_zh_author`，同一篇论文会出现两套机构名（主表是采集方拼的串，作者表是逐条记录），机构聚合会翻倍。

### 2.4 算路 / SQL

全流程 1 条 SQL，落在 10 万行窄列表上：

```sql
-- Q1 论文主档（100,900 行，5 列，54.6 秒）
SELECT id, cover_year_start, cover_date_start, open_access, author_info_list
FROM gkx.dwd_zh_paper;
```

100,900 行一次性拉到本地后，所有统计在内存完成：年份解析、季度/月度派生、作者串 JSON 解析、机构性质判定（高校/院所/医院/企业/其他）、城市识别、分组计数。**没有对 `dwd_zh_paper` 做任何 GROUP BY 大列**，也没有 JOIN 作者表、引文表、关键词表。

为什么把 `open_access` 也取回来：它是需求未要求但页面常用的一个旁证字段（开放获取 33,262 篇，32.97%）。本文只用它做描述性统计，不进入任何计数口径；把它写进 `_out.json` 是为了让后续做「开放科学」类指标的人不必再查一次库。

### 2.5 清洗规则

| 规则 | 处理 | 影响行数 |
|---|---|---|
| `id` 重复 | 不去重（实测 0 重复） | 0 |
| `cover_year_start` 为空/非年份 | 剔除出年序列，但仍计入总数 | 0（实测全可解析） |
| `author_info_list` JSON 解析失败 | 该篇不计入机构/城市切片，仍计入总数 | 0 |
| 一篇多机构 | 全计入，机构维为署名实例口径 | 436,086 实例 / 100,900 篇 |
| 一篇多城市 | 全计入，并单独报多归属篇数 | 21,217 篇 |
| 城市名写法不一 | 统一到「市」级全称后匹配 | 93,817 篇命中 |
| 机构名为空或纯符号 | 归「其他」，不剔除 | 149 个署名实例 |
| `paper_type` 非期刊论文 | 不剔除（实测全为期刊论文） | 0 |
| `download_num = 0` | 不使用该列 | 100,900（整列） |
| 2024 年尖峰 | **保留原值**，在年序列与图表上断点标注 | 32,379 |
| 2025/2026 不完整年 | 保留在序列里，但禁止参与同比与增速分母 | 6,548 + 2,989 |

清洗原则是「能打标就不删行」。删行会改变分母，而分母是这张表的全部意义；对计数指标来说，悄悄删掉 7.02% 未归属城市的论文，等于把「地域分布」变成「有地址的论文分布」，两者不是一件事。

### 2.6 结果解读

年序列（1980—2026）：1980—2000 每年 2—21 篇，属长尾；2001—2013 从 46 篇爬到 717 篇；2014 年跳到 1,926 篇，2015 年 3,082 篇，2016 年 4,710 篇，2017 年 6,903 篇；2018—2023 稳定在 6,067—6,758 篇；2024 年 32,379 篇；2025 年 6,548 篇；2026 年 2,989 篇（截至 8 月）。

2024 年的形态值得单独描述：四个季度分别为 7,272、8,729、7,762、8,616 篇，而 2025 年四个季度只有 1,537、1,534、1,439、2,038 篇。也就是说，2024 不是「某季度爆发」，而是**全年均匀抬高约 4.7 倍**，2025 又整体回落到 1,500 量级。这种「整整一年同比例抬高、次年同比例回落」的形态，最合理的解释是采集批次在 2024 年一次性补录了一批历史文献并把发表年记成了 2024，而不是真实产出翻倍。

剔除 2024 后的稳态：2022—2023 均值 6,491 篇，2019—2021 均值 6,422.7 篇，增幅 +1.06%。这个数与含尖峰的 +135.42% 并列写在 `_out.json` 的 `growth` 与 `anomaly` 两个块里，前者是「真实增速的可用读数」，后者是「必须披露的异常」。

机构维：84,320 个机构名，Top 5 是广州中医药大学第一附属医院（1,552 个署名实例）、深圳供电局有限公司（821）、中国能源建设集团广东省电力设计研究院有限公司（773）、中山大学附属第一医院（739）、深圳市中医院（668）。这个榜单明显偏医药与电力，说明库内中文论文的采集面偏应用学科，不能当作「全国科研机构排名」。

地域维：93,817 篇可归属，Top 5 是广州市 23,445 篇、北京市 17,061 篇、深圳市 9,976 篇、上海市 6,233 篇、南京市 5,689 篇。广州与深圳合计 33,421 篇，占可归属篇数的 35.6%，这与库的采集范围（大湾区为主）一致，不能读成「广州论文产出是北京的 1.37 倍」。

| 下载量 | 100,900 行全为 0 | 不能做热度旁证 | 供应方回填或确认废弃 |
| 2024 尖峰 | 32,379 篇，占 32.09% | 含尖峰的增速不可用 | 供应方给批次号，按批次剔除后重算 |
| 2025/2026 完整性 | 6,548 / 2,989 篇 | 不能参与同比 | 待年度补全 |

### 4.2 对结论的影响边界

上述缺失**不改变计数本体**：100,900 篇的年份、机构、城市三个切片现在都能出，且三处对账闭合。它们改变的是**解释边界**：地域分布只覆盖 92.98%，机构排行是署名实例口径而非机构份额，年趋势必须在 2024 断点，2025/2026 不能与 2021—2024 直接同比。

### 4.3 不可外推的三件事

第一，不能把 100,900 篇当成「全国中文论文总量」。库的采集面以粤港澳机构为主（广州 23,445、深圳 9,976 合计占可归属篇数 35.6%），机构榜单前五里三家是广东医疗/电力单位，明显是区域采集而非全国普查。

第二，不能把 2024 年的 32,379 篇当成「产出爆发」。四个季度同时抬高 4.7 倍、次年同比例回落，这是批次补录的形态；把它写进政策材料会直接误导判断。

第三，不能把机构署名实例数当成「机构论文数」。一篇多机构的论文在每个机构都计一次，436,086 个实例对应 100,900 篇，平均每篇 4.32 个署名；直接把实例数当篇数会放大 4.32 倍。

**建议采纳本文实现，作为本指标的当前交付版。** 理由有三：其一，主表 100,900 行、年份 100% 可解析、机构与城市均可切片，三条序列一次跑通，满足「完全转换支持」的档位定义；其二，三处对账（总数、署名实例、城市覆盖）全部闭合，数字可复核；其三，尖峰与覆盖率这两个最容易误导的点都写进了 `_out.json`，页面只需读字段即可正确标注，不必再人工判断。

## 附录 C　科学论文数量类似指标权威构建方法可行性报告（完整版）

### C.1 报告目的与范围

本附录回答一个问题：在不引入外部数据库、只靠 `gkx` 的前提下，「按时间 × 机构 × 地域统计论文篇数」这件事能做到什么程度，以及哪些权威口径因为缺字段而无法照搬。范围限定在中文期刊论文的计数面，不扩展到被引、影响因子、学科归一。

### C.2 需求语义锚定

需求用的词是「发表数量」，不是「产出质量」也不是「影响力」。在文献计量语境里，篇数属于「产出侧」，被引属于「影响侧」，两者不能混。需求同时给了年、季、月三级粒度，说明它要的是一张可以下钻的统计表，而不是一个综合分。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：文献数据库计数

Web of Science、Scopus、CNKI 的核心产品都是「按收录年 × 机构 × 学科」的计数表。它们的共同前提是：一篇文献一行、有唯一 ID、有机构规范化字段、有收录年。本文的 `dwd_zh_paper` 满足前三条（ID 唯一、年份可解析、机构串可解析），第四条（机构规范化）只做到 92.98% 的城市级匹配，机构名本身未规范化。这就是「方法族 A 可落地但有折扣」的具体含义。

#### C.3.2 方法族 B：科技统计年鉴口径

《中国科技统计年鉴》与 OECD Frascati 手册统计的是「论文产出强度」，分母是 R&D 人员全时当量或 R&D 经费。本项目库内没有 R&D 分母表（`dwd_rd` 为空表），因此只能出「篇数」，不能出「篇/人」「篇/万元」。这不是本文的取舍，是分母不存在。

#### C.3.3 方法族 C：学科归一化计量

软科、QS、ESI 的学科阈值需要学科分类码。库内 `dwd_zh_paper_classification` 只有 20,048 行、799 篇可对齐，且内容是关键词串而非码表，占比 0.799%。用它做学科归一，等于用 0.8% 的样本推断全体，不可接受。

#### C.3.4 方法族 D：跨库去重

OpenAlex、Dimensions 用 DOI 或标题指纹做跨库去重。库内无 DOI 字段，只能用题名精确匹配，而中英文版本、标点差异、副标题都会导致漏配。本文不做跨库去重，只在中文库内部按 `id` 去重（100,900 个 ID 无重复）。

### C.4 数据可行性详细分析

#### C.4.1 论文本体

100,900 行、100,900 个 ID，一篇一行。这是最强的一块：计数指标最怕的「同篇多行」在这里不存在。

#### C.4.2 时间维

`cover_year_start` 100% 可解析，跨度 1980—2026。季度与月度由 `cover_date_start` 派生，2023Q4—2026Q3 与 2025-03—2026-08 两段粒度完整。2024 年的批次尖峰是时间维唯一的解释性风险。

#### C.4.3 机构维

436,086 个署名实例、84,320 个机构名，平均每篇 4.32 个署名。机构名未规范化，同一机构的不同院系是不同字符串（「广州中医药大学」618 与「广州中医药大学第一附属医院」1,552 是两条），所以机构排行只能看单体，不能自动合并成「大学」口径。

#### C.4.4 地域维

93,817 篇可识别城市（92.98%），其中 21,217 篇有多个城市。识别依据是机构名中的地名与地址文本，未接 `dwd_org_base_info`（该表 189,116 行以企业为主，高校/医院覆盖不足）。这决定了地域维只能做「城市分布」，不能做「跨省迁移」。

#### C.4.5 方法—数据对照矩阵

| 方法 | 需要的输入 | 库内状态 | 可行性 |
|---|---|---|---|
| A 数据库计数 | 唯一 ID、年份、机构串 | 全部具备 | **可行** |
| B 产出强度 | R&D 人员/经费 | `dwd_rd` 空表 | 不可行 |
| C 学科归一 | 学科码表 | 仅关键词 0.799% | 不可行 |
| D 跨库去重 | DOI | 无 | 不可行 |

### C.5 推荐构建方案（工程可执行）

1. 以 `dwd_zh_paper` 为唯一事实表，一条 SQL 拉窄列；
2. 年份/季度/月度在内存派生，不做 SQL 侧 date 函数；
3. 作者串 JSON 内存解析，机构性质按关键词表判定，城市按地名表匹配；
4. 三套切片（时间、机构、城市）与覆盖率、尖峰标记一并落 `_out.json`。

### C.6 风险与残余不确定性

- 2024 年批次尖峰会污染任何含该年的趋势读数，必须断点；
- 机构名未规范化，机构排行不能自动合并院系；
- 城市识别 92.98%，剩余 7.02% 不能按比例摊派；
- 库内只有期刊论文，类型结构不可交付。

### C.7 可行性总判（完整版结论）

方法族 A 在本库**结构与数据都足够**，三条切片现在就能出，判「完全转换支持」。B/C/D 的缺口属于「扩展能力」，不是本指标必需，不影响档位。
