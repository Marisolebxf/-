## 摘要

「湾区创新能力因素统计」是湾区创新能力页的**明细层**：上层的四个子指数（资源/机构/机制/环境）各自给一个 0–100 分值，本指标则把每个子指数拆到可核验的原始量，供用户回答「这个分是怎么来的」。它与四个子指数的关系是「明细 ↔ 汇总」，不是竞争关系。

本报告在 `gkx` 上落成一张 4 城 × 10 子项的矩阵：资源维（专利 2021–2024 共 2,126,758 件、上市公司研发 2019–2024 共 7,488.97 亿元）、机构维（载体 190,848 家、高企 27,634 家、科研院所 2,074 家）、环境维（有效政策 1,212 条、高企密度 10.63%–16.02%）、机制维（三项全空）。十个子项里 **7 个有数、3 个结构性不可算**。

三条必须先立的判断：其一，本指标**不合成总分**——需求要的是「因素统计」，合成会把 3/10 的空缺藏进一个漂亮数字里，反而不如把空缺摆在表上；其二，所有占比的分母是**四城合计**，不是湾区 11 城，深圳 50.62% 的机构份额是「四城内」份额；其三，机制维的不可算是**表结构问题**（缺列、整列空），不是「数据还没采」，任何 SQL 都补不出来。按 §〇 判**部分支持**。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块是**粤港澳大湾区创新能力**（需求编号 1.1.1.1.4.1.5.2）。产品形态上，这是一个「因素构成」面板：左侧列出四类因素（创新资源、创新机构、创新机制、创新环境），每个因素下挂若干可量化子项，右侧是该子项在四城之间的对比条形图与占比。

它在体系中的位置是**证据层**。需求原文要求「用户可查看各子指标的数值和贡献度」，而子指数只给分值、不给原始量；没有本指标，用户看到「深圳机构指数 100」时无法知道这是 96,614 家机构、16,490 家科技型机构、1,118,312 件专利算出来的，也无法判断这个 100 是「真的强」还是「因为只有四个城在比」。

### 1.2 为什么需要「因素统计」而不是再做一个指数

指数是压缩，统计是展开。压缩必然丢信息：四个子指数把 10 个子项压成 4 个数，用户无法定位短板来自哪个子项。需求原文特意把「因素统计」与「指标体系」并列，说明产品设计上已意识到需要一层可下钻的明细。

第二个理由是可审计。指数一旦被质疑（例如「为什么深圳 100」），唯一能自证的方式就是摊开原始量。本指标承担这个自证职责，因此它的字段设计必须满足：每一个数都能指回一张表、一个过滤条件、一个时间窗。

第三个理由是缺口可视化。机制维三项全不可算这件事，如果只在机制指数里体现为一个 0，会被误读为「机制弱」；摊在因素统计表上，用户看到的是「三个格子写着不可算 + 原因」，这才是诚实的表达。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**

招标正文在 §1.1.1.1.4.1.5.2 只给四因素的名字与「综合分析」的总要求，在 §1.1.1.1.4.1.5.2.3 只给「分解为多个子指标」的功能描述，没有任何子项清单、单位、时间窗或取数表。检索「因素统计」「创新资源」「创新环境」在正文中均无与公式绑定的定义句。

可复现的框架来自王惠 V1.5-20260830 的四因素划分（资源/机构/机制/环境），本报告**沿用框架、重定呈现**：框架（哪四类、每类挂哪些子项）照王惠；呈现（原始值 + 四城占比 + 不合成）为本批定义，因为王惠原文对「因素统计」只给了框架没有给输出形态。

### 1.6 推测原意与推测定义（仿王惠口径写法）

框架不需要推测（王惠给了四因素与子项名），但**输出形态**需要裁定，因为王惠原文只写「输出因素级明细」而没有规定是原始值、指数还是占比。本报告的裁定是「原始值 + 四城占比」，理由与三处细则如下：

1. **不做加权合成**。若合成，机制维空缺必须补 0 或删维；补 0 会把「不知道」说成「最差」，删维会让四因素变三因素、与需求原文的四因素表述冲突。输出原始值可以同时保住「四因素齐全」与「缺口显式」，这是唯一不自相矛盾的形态。
2. **占比的分母写死为四城合计**。王惠原文对指数写「11 城极值归一」，对统计没写分母。本报告用四城合计并在每个表头标注，避免深圳 50.62% 被读成「占湾区一半」。
3. **机制维保留空行**。三行照常出现在表里，值列写「不可算」，原因列写具体证据（缺列/整列空/抽样率）。这不是「留白」，是把缺口做成一等公民。

## 二、计算过程

### 2.1 方法选择：为什么是「矩阵」而不是「合成分」

第一，需求词是「统计」不是「指数」。需求原文把「因素统计」与「四个子指数」并列在同一功能模块下，说明产品上已分工：子指数负责给分，统计负责给数。若统计也合成，两者就重复了。

第二，空缺处理决定了不能合成。机制维 0/3，任何合成方案都要对空缺做假设（补 0 / 删维 / 插补），三种假设都会引入需求未授权的判断。矩阵形态不需要假设——空着就是空着，并附原因。

第三，可审计性。矩阵的每一格都能指回「表 + 过滤 + 窗口」，甲方可以逐格复核；合成分值只能复核公式，不能复核每一格。

代价也要说清：矩阵不能排序。用户看四城对比时要自己读 10 行，而不是读一个数。这是有意的取舍——在 30% 子项缺失的情况下，给一个「综合排名」比不给更危险。

### 2.2 步骤 1｜资源维：专利资源与研发投入

**专利资源**：2021–2024 四个完整申请年，深圳 1,118,312、广州 550,169、东莞 365,186、惠州 93,091，四城合计 **2,126,758** 件（占主表 2,939,895 件的 72.34%）。数据走 `_snapshots21/patent_panel_innov_20261021.json` 的 `app_year` × 底册 `name_cn → city` 映射，**零 SQL**；每个申请人按 1/k 计权（k = 该名称在底册中对应的机构数，共 47 个重名），以保证「四城专利合计 = 逐城相加」在任意切片下都成立。

**研发投入**：`gkx.dwd_org_stock_finance_info.research_development_amount`，2019–2024，深圳 5,618.29 亿、广州 1,077.89 亿、东莞 311.36 亿、惠州 481.43 亿，四城合计 **7,488.97 亿元**，覆盖 856 家上市公司（占四城底册 190,848 家的 0.45%）。

这里有一个必须写死的口径陷阱：`research_development_amount` 是**年内累计值**，同一 `org_id` 同一年有 03/06/09/12 四个 `occur_period`。若把四季相加，四城合计会变成 **18,231.47 亿元**，虚增 **2.4344 倍**。本报告只取 `occur_period` 以 `'12'` 结尾的全年累计值，并在 `probes.rd_wrong_caliber_yi` 保留错误口径的数以备对账。

另一个陷阱是 `dwd_org_annual_financial_info.arch_development_am` 与 `development_employee` 两列**100% 为 NULL**（整列空），不能作为研发投入或研发人员的备用源。本报告只用上市公司年报口径，因此资源维的「研发投入」实质上只覆盖**上市企业**，不是全口径 R&D。

**专利归属的 12.24% 缺口**：面板 2,939,895 件中，窗口内有 296,792 件（12.24%）的申请人名称在底册中找不到对应机构，因而无法归城。这部分不进任何城市的分子，也不进分母（占比分母是已归城四城之和），所以占比表**内部自洽**、但**不覆盖全量**。296,792 件相当于东莞全年的 3.2 倍，不能忽略；它们的来源是底册未收录的企业（新注册、注销、外资代表处）与申请人名书写差异。修法是做「申请人名 → 统一社会信用代码」的模糊对齐，属独立工程，本报告不擅自补全（补全会把猜测写进数字）。

### 2.3 步骤 2｜机构维：载体、高企、科研院所

**载体数量** = 企业底册 `org_id` 去重 + 科研院所 `org_id` 去重。两表 `org_id` 实测**零交集**，可直接相加：深圳 96,614、广州 50,427、东莞 33,717、惠州 10,090，合计 **190,848**。

**科技型机构** = 高企去重数（`org_tag ∈ {高新技术企业, 国家级高新技术企业}`）：深圳 15,476、广州 7,499、东莞 3,584、惠州 1,075，合计 **27,634**。注意此处与机构指数的「科技型机构 16,490/8,321/3,711/1,186」不同——差异正是科研院所（+1,014/+822/+127/+111），因为指数口径把院所并入科技型机构，而因素统计把院所单列为第三子项。两处口径差异是**有意设计**（因素统计要避免同一批院所被数两次），已在附录 B 登记。

**科研院所**：`gkx.dwd_research_institute_base_info` 2,074 行，深圳 1,014（48.89%）、广州 822（39.63%）、东莞 127（6.12%）、惠州 111（5.35%）。穗深合计 88.52%，是四因素中**集中度最低**的一组数据之一——对比研发投入的穗深合计 89.41%，院所分布几乎同构。

机构维是本次唯一 3/3 全通的维度，也是唯一能支撑「结构分析」的维度：载体多但高企少 = 注册量大而创新主体少（东莞高企密度 10.63%），院所占比高 = 公共研发资源集中（广州院所占载体 1.63%，深圳 1.05%）。

### 2.4 步骤 3｜机制维：三项全不可算的逐项证据

这一维必须逐项写，因为「不可算」的三种原因是完全不同的工程问题，混淆会导致错误的修复预期。

**联合专利（不可算）**。`gkx.dwd_patent` 主表**没有 `applicants` 列**（只有 `applicant` 单值列，且为规范化后的主申请人）。协同专利需要「同一 pn 有 ≥2 个申请人」，必须走 `dwd_patent_applicants`；该表实测仅 **28,964 行 / 20,000 个 pn**，占主表 2,939,895 件的 **0.68%**，且共申请人名与底册 `name_cn` 的精确对齐率仅 **1.51%**。这不是「抽样」，是一张**封闭的 2 万条演示样本**，任何基于它的协同率都不能外推到全量。修法：需要主表补 `applicants` 或全量申请人关联表，属**结构变更**，不是 SQL 能解决。

**合作项目（不可算）**。`gkx.dwd_zh_project` 58,453 行，`funded_institution` 列 **58,453/58,453 全为 NULL**。`participating_institution` 为单机构名，含分隔符（可拆出多机构）的仅 **29 行 = 0.05%**，「≥2 机构参与」在结构上不成立——不是数据稀疏，是该字段设计为单值。修法：需要项目—机构多对多关联表。

**成果转化（不可算）**。`gkx.dwd_patent_transfer` 22,809 行 / 20,000 个 pn（同样是 0.68% 封闭抽样），转移前后权利人名称与底册精确对齐率 **2.07%**。修法：需要全量转移登记 + 权利人实体对齐。

三项的共同点是：**都是「关联结构缺失」而不是「数据量不足」**。这意味着即使库里再灌十倍数据，只要不补列/补关联表，这一维仍然是 0/3。这个判断比「暂时没数据」严重得多，必须写进结论。

### 2.5 步骤 4｜环境维：政策供给与高企密度

**政策供给**：`gkx.dwd_policy_base` 20,000 行，全表 `status` 均为「有效」（没有失效样本，因此「有效政策数」等于「政策数」）。城市归属靠标题/正文中的城市名匹配，命中率仅 **6.06%**（1,212 条），其中 9,706 条为占位行（标题含「示例」「测试」类模板）。逐城：深圳 879、广州 325、东莞 8、惠州 **0**。

这条数据的可信度必须打折：6.06% 的归属率意味着 93.94% 的政策没有被计入任何城市，而「惠州 0」极可能是归属失败而不是「惠州无政策」。本报告保留该子项但标注「归属率 6.06%」，并在 §四 把它列为**可修缺口**（需要政策表补 `city` 列或做正文地名解析）。

**高企密度** = 高企去重数 / 机构总数：深圳 16.02%、广州 14.87%、惠州 10.65%、东莞 10.63%。这是环境维里唯一**不需要外部归属**的子项（分子分母都来自同一批机构），因此可信度最高。它同时是机构维与资源维的交叉诊断量：密度高说明「机构中创新主体的比例高」，与机构总量无关。

读这张表要注意三处「不一致」，它们才是分析价值所在：

其一，**研发投入的集中度远高于专利**（深圳 75.02% vs 52.58%）。深圳以 52.58% 的专利占了 75.02% 的研发投入，说明其单位专利的研发成本最高；惠州相反——只有 4.38% 的专利却占 6.43% 的研发投入。这不必然是「效率低」，因为研发投入是**上市公司年报口径**，惠州有 TCL、亿纬锂能、德赛等大市值公司，其研发费用中很大一部分投向不在惠州申请专利的业务线。

其二，**科研院所是唯一「广州接近深圳」的子项**（39.63% vs 48.89%，而载体是 26.42% vs 50.62%）。广州的公共研发资源密度显著高于其企业密度，这是广州「高校院所型」创新结构的直接证据。

其三，**政策占比不可用于城际比较**。深圳 72.52%、惠州 0，差距 72 个百分点，但这个差距主要来自归属成功率（6.06%）而不是政策数量本身。

## 四、数据缺失情况

### 4.1 可构建但存在缺口

**缺口一：机制维整维缺失（0/3）。** 三项分别是「缺列」「整列空」「0.68% 封闭抽样」，都属于结构问题。这是本指标最重的缺口，占 10 子项的 30%。

**缺口二：研发投入只覆盖上市公司。** 856 家 / 190,848 家 = 0.45%。非上市企业（含绝大多数高企）的研发费用在本库无源：`dwd_org_annual_financial_info` 的研发两列 100% NULL。因此「研发投入」实际是「上市公司研发投入」，用它代表城市 R&D 会系统性低估以中小企业为主的城市（东莞、惠州的高企研发几乎不可见）。

**缺口三：政策城市归属率 6.06%。** 20,000 条政策只有 1,212 条能归城，惠州归到 0 条。该子项目的占比表不可用于城际比较。

**缺口四：七城无机构底册、港澳为 0。** 珠海 0、佛山 1、中山 1、江门 0、肇庆 0、香港 0、澳门 0。`dwd_forg_base_info` 是英国样本（`country_code` GB 19,832），不能补港澳。

**缺口五：政策表无失效样本。** 20,000 行 `status` 全为「有效」，导致「有效政策数」退化为「政策数」，无法做政策强度的时间序列。

**缺口六：专利窗口只到 2024。** 2025 年 440,401 件（不完整）、2026 年 74,810 件（残年）不入算，序列在页面上须标注「2021–2024」。

### 4.2 缺口的后果归因（往哪偏、偏多少、能否交叉验证）

**往哪偏。** 机制维缺失使「机制」因素在四因素对比中必然显示为「无数据」，若前端用颜色深浅表示强弱，机制维会看起来最弱——这是把「不知道」渲染成「差」的典型错误，必须用灰色 + 文字标注。研发投入的上市公司口径会把东莞、惠州的企业研发系统性低估，使「资源」因素偏向深穗。政策归属率低会把环境因素偏向深圳（72.52%）。

**偏多少。** 可定量的是覆盖率：子项 70%、因素 75%、城市 36.36%、研发口径 0.45%、政策归属 6.06%。不可定量的是「若机制维可算，四城排序会不会变」——没有机制数据，无法构造反事实。但可以做上界推断：机制维三项（联合专利率、合作项目数、转化件数）在任何城市的绝对值都很小（万级以下），即使补齐也不会改变资源/机构维的十亿级、十万级量级对比，因此**机制维补齐不会改变四因素的整体强弱格局**，只会补上「协同质量」这一维度的细节。

**能否交叉验证。** 三条。其一，专利对账（四城差异 0）。其二，机构对账（190,848 逐位相等）。其三，研发投入与 `M_INNOV_GBA_INVEST` 同源同值（7,488.97 亿），且错误口径 18,231.47 亿与 2.4344 倍在两个脚本中一致，说明口径实现没有漂移。

### 5.1 王惠原方法还原

出处：四因素框架见 `王惠口径正本（GitLab 外本地归档）`；本指标同ID正本在全仓不存在（注册表 `pending_cosign`），10 项拆分口径为本批定义。

- **因素划分**：创新资源（研发投入、专利资源）、创新机构（载体数量、科技型机构、科研院所）、创新机制（联合专利、合作项目、成果转化）、创新环境（政策供给、高企密度）。
- **城际宇宙**：湾区 11 城，与四个子指数同宇宙。
- **输出**：「因素级明细」，即按因素×子项×城市给出统计值；王惠未规定是否合成、是否给占比。
- **源表**：`dwd_org_stock_finance_info`、`dwd_patent`、`dwd_org_base_info`、`dwd_research_institute_base_info`、`dwd_org_tech_tag`、`dwd_patent_applicants`、`dwd_zh_project`、`dwd_patent_transfer`、`dwd_policy_base`。

王惠口径的特征是**框架完整但输出形态开放**：四因素十子项的划分是明确的，但「明细」到底长什么样（原始值/指数/占比/矩阵）没有定义。这给了实现层裁量空间，也意味着必须在文档里把裁定写清，否则同一份框架会产出四种不同的表。

### 5.2 新方法概述（§二 重建路径要点）

框架照搬（四因素十子项一名不改），呈现层做三处定义：

1. **输出形态**：城市 × 子项矩阵，每格给原始值 + 四城占比；不合成、不归一、不打分。
2. **缺口表达**：不可算子项保留行位，值列写「不可算」，原因列写结构证据（缺列/整列空/抽样率），占比列留空。
3. **派生比率**：额外给三个比率（研发/专利、研发/机构、专利/机构），并明确标注「仅限同城跨年比较」的适用边界。

换言之，5.2 与 5.1 的关系是「框架继承、呈现新定义」，不是「换了一套方法」。

### 5.3 逐维对照表

| 维度 | 王惠口径 | 本报告口径 | 数据支撑差异 | 可复现性差异 |
|---|---|---|---|---|
| 因素框架 | 四因素十子项 | 同左，一名不改 | 无 | 完全可复现 |
| 城际宇宙 | 11 城 | 11 城定义、4 城实测 | 七城底册 0–1 家、港澳 0 | 王惠未披露覆盖；本报告写 4/11 |
| 资源·研发 | 研发投入 | 上市公司年报 12 月累计 | 王惠未限定口径；本库全口径无源 | 错误口径（2.4344 倍）已登记 |
| 资源·专利 | 专利资源 | 2021–2024 去重件数，1/k 计权 | 无（面板全量） | 与城市簇派生零差异 |
| 机构·三项 | 载体/高企/院所 | 同左；院所单列不并入高企 | 本报告避免院所重复计数 | 与机构指数口径差异已登记 |
| 机制·三项 | 联合专利/合作项目/转化 | 三项全标不可算 | 缺列、整列空、0.68% 抽样 | 王惠假设可算；本库结构不支持 |
| 环境·政策 | 政策供给 | 有效政策数，归属率 6.06% | 政策表无 `city` 列 | 惠州 0 是归属失败 |
| 环境·高企密度 | 高企密度 | 同左（高企/机构） | 无 | 完全可复现 |
| 输出形态 | 「因素级明细」（未定义） | 矩阵 + 原始值 + 占比，不合成 | 无 | 本报告新增裁定，须甲方确认 |

### 5.4 选用建议与理由

**建议采用王惠的四因素十子项框架，并采用本报告的「矩阵 + 占比 + 不合成」呈现。** 理由有三：其一，框架与需求原文的四因素表述逐字对应，不存在语义偏离；其二，矩阵形态在 30% 子项缺失时是唯一不自相矛盾的输出（合成必须对空缺做假设）；其三，每一格可审计，满足「用户可查看子指标数值和贡献度」的需求原文。

三处需要甲方确认的裁定：第一，**不合成**是否符合产品预期（若产品坚持要一个「因素综合分」，需要先决定机制维空缺如何处理）；第二，**研发投入的上市公司口径**是否可接受，或是否需要先补全口径 R&D 源；第三，**政策归属率 6.06%** 下的政策子项是否上线，或先隐藏待修。

**建议把「机制维不可算」做成产品语言而不是技术语言。** 用户不需要知道「`funded_institution` 整列为空」，只需要知道「协同与转化类数据暂未接入」。技术证据留在文档与 tooltip 里，主界面用一句人话，否则界面会被工程细节淹没。

### C.5 推荐构建方案（工程可执行）

1. 以四因素十子项为固定骨架，输出城市 × 子项矩阵，不合成。
2. 资源维：专利走面板快照（零 SQL），研发走上市公司 12 月累计。
3. 机构维：底册 + 院所（org_id 零交集，直接相加），高企只算标签不并院所。
4. 机制维：三行保留，值列「不可算」，原因列写结构证据；不补 0、不插补。
5. 环境维：高企密度可直接用；政策子项标注归属率 6.06%，惠州 0 标注为归属失败。
6. 前端表头必须写「样本城数 4/11、机制维不可算、研发仅上市公司」。

### C.6 风险与残余不确定性

- **空项被误读为差**：机制维若用色阶，会显示为最弱。
- **口径混用**：科技型机构 15,476 与 16,490 并存。
- **研发口径偏差**：0.45% 覆盖率，偏向深穗。
- **政策归属偏差**：6.06%，惠州 0。
- **占比误读**：四城分母被读成湾区分母。

### C.7 可行性总判（完整版结论）

七个子项在结构 + 数据上**现在就能算出**，且三处对账（专利、机构、研发）全部通过；但机制维三项属**结构缺失**（补数据无用，须补列/补关联表），研发与政策两子项属**口径受限**，七城底册缺失使「湾区」不完整。因此判**部分支持**。升级路径明确：补申请人全量表 → 联合专利可算；补项目—机构关联表 → 合作项目可算；补转移全量 → 成果转化可算；三条补齐后本指标可升「完全转换支持」。
