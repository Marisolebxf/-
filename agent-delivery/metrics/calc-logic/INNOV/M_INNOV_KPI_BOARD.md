## 摘要

本件是只读聚合件，不含任何自建公式。构造方式是把看板拆成 16 个格，每格写死一个「来源件 ID + `_out.json` 键路径」，脚本只做取值与空值检查，不做单位换算、不做加总、不跨池相除。这样任何一格被质疑时，都能在两跳内追到源表。

| 读数 | 值 |
|---|---|
| 看板格总数 | 16 |
| 有值格 | 14（87.5%） |
| 空值格 | 2（事件条数、事件关注度） |
| 专利类 | 5 格 |
| 论文类 | 4 格 |
| 投资/经费类 | 3 格 |
| 主体类 | 2 格 |
| 事件类 | 2 格（全空） |
| 来源件数 | 7 |
| 判档 | 部分支持 |

第一个事实是**主干四类都能落地**。专利公开总量 2,939,895 件、2021—2024 合计 2,424,684 件（占全库 82.4752%）；中文论文 100,900 篇、2023 年 6,651 篇（占全库 6.5917%）；深圳上市主体 2024 年研发费用 1,545.04 亿元，2021 至 2024 增幅 97.01%；高新技术企业 27,936 家，占企业底册 189,116 家的 14.7719%。这四类构成了看板的主视觉，且每一格都来自已归档件。

第二个事实是**事件两格必须留白**。同批的 `M_TNIE_EVENT_COUNT` 交的是「活动型标题条数」代理读数（18,884 / 1,668,414，即约 1.13%），`M_INNOV_EVENT_ATTENTION` 交的是负证据与「完全不支持」判定——两者都不是**事件发生数**。事件表本身只有 20 行、覆盖两天、全是国药励展系展会，不构成事件面。看板格要的是事件发生数，拿代理填格等于把另一种口径混进同源看板，所以两格一律 `null`，并在 `missing_reason` 里写明这层理由。

第三个事实是**看板不能承担「新口径」职能**。看板的格子是展示位，不是计算位。任何在看板里现算的比例都会绕开兄弟件的验收链，所以本件只允许两种运算：取标量、取已归档比率。派生段里的 8 个比值全部由两格读数相除得到，且逐个写明分子分母，便于甲方复核。

### 1.2 为什么需要看板

创新分析有十几条互不相通的计算链：专利在专利件里、论文在论文件里、研发费用在经费件里、高企在主体件里。单看任何一件都只能回答一个侧面，而决策场景需要的是一屏之内的横向对照：专利在涨还是跌、论文影响在什么水平、研发投入够不够、创新主体盘子有多大。

看板的价值就在于把这些侧面按固定位置摆好，让读者在第一屏建立量级感。它不产生新知识，但决定了读者先看到什么、后看到什么。也正因为它承担「第一印象」，任何一格口径漂移都会被放大成整体误判，所以本件对来源的要求比普通指标更严：宁可少一格，不可错一格。

### 1.3 口径定义

设看板格集合 $C=\{c_1,\dots,c_{16}\}$，每格绑定三元组：

$$\beta(c_i)=(m_i,\ p_i,\ o_i)$$

其中 $m_i$ 是来源件 ID，$p_i$ 是该件 `_out.json` 里的键路径，$o_i$ 是该件是否已归档在正式区。取值规则只有三条：

第一，**只读已归档件**。$o_i$ 为真才允许取值；暂存区、草稿区、他人未验收产物一律不读。第二，**只取标量**。键路径必须终止于数值或字符串，不允许在看板里做数组聚合。第三，**缺失即 null**。$m_i$ 不存在，或 $p_i$ 解析不到，该格写 `null` 并把原因落到 `missing_reason`，不插补、不用邻格推算。

### 1.4 计算公式与本批实现式

```python
def bind(cell, official_dir):
    src = os.path.join(official_dir, cell["source_metric_id"] + ".md")
    if not os.path.exists(src):
        return None, "正式区无来源件"
    out = json.load(open(f'code/{cell["source_metric_id"]}_out.json'))
    node = out
    for key in cell["source_key"].split("."):
        if not isinstance(node, dict) or key not in node:
            return None, f"键路径 {cell['source_key']} 解析不到"
        node = node[key]
    return node, None
```

三个实现要点。第一，`bind` 先检查 `.md` 是否存在，再读 `_out.json`；只查产物不查文档，会把没有验收的脚本产物放进来。第二，键路径逐段下钻且每段都判 `dict`，避免把列表下标误当键名。第三，返回二元组而不是抛异常，让单格失败不影响其余 15 格，缺格原因统一进 `missing_reason`。

## 二、计算过程

### 2.1 来源件筛选规则

候选来源只有一类：已经归档在 `第三方库指标计算过程/` 的正式件。筛选分三步。第一步列正式区目录下的 `.md`，排除以 `_` 开头的说明文件。第二步对每个候选检查 `code/<ID>_out.json` 是否存在且可解析，缺产物即淘汰。第三步人工确认该件的口径与本格语义一致，例如「专利公开总量」只能绑 `counts.patent_rows`，不能绑某个年度切片。

这条规则看似保守，实际是看板件唯一可行的纪律。看板的读者不会逐格翻来源，他们默认整屏同源同窗。若允许一格来自正式件、一格来自本批暂存区，两格的基期与去重口径可能不同，拼在一起就是错误对照。本件的事件两格即便同批事件类指标件已进正式区也照样不填——排除它们的理由不是「文件还没归档」，而是「读数不是事件发生数」，口径不匹配不会因为归档动作而改变。

### 2.2 十六格的落位

16 格按四类主干加一类缺口组织：专利 5 格、论文 4 格、投资/经费 3 格、主体 2 格、事件 2 格。前四类共 14 格全部有值，事件两格全空。这个分布不是设计出来的均衡，而是来源件实际覆盖的结果：专利与论文件本身读数最全，经费件覆盖研发与投融资两侧，主体件只交高企与基金两个截面。

格的顺序按「先规模、后质量、再投入、末主体」排列。专利先给全库总量，再给近四年合计，再给深圳切片与合格域数，最后给热度中位数；论文先给总量，再给年度截面，再给篇均被引与覆盖率。这个顺序让读者从「有多少」走到「好不好」，最后落到「投了多少、谁在创新」。

### 2.3 专利五格

专利公开总量 2,939,895 件，来自 `M_TECH_PAPER_PATENT_CNT` 的 `counts.patent_rows`。2021—2024 合计 2,424,684 件，占全库 82.4752%，来自 `M_INNOV_POT_OUTPUT` 的 `total.patent_2021_2024`。这两个数一起看才有意义：全库含 2025 与 2026 的采集残年，单看总量会被残年拉低解释力，所以补一格近四年合计。

这里有一个**必须点破的坑**：兄弟件 `M_TECH_PAPER_PATENT_CNT`（以及 130/131/132/135）共用的「基期专利总量」是 **2,009,365**，那是 **IPC 非空行**的四年合计（634 域口径），不是全表四年合计。若把它当分子、却用全表 2,939,895 当分母，会得 68.3482%，**比真实的 82.4752% 低 14.1 个百分点**——分子少算了 41.5 万行 IPC 缺失件，分母一行没少。本件早期版本正是这么算的，已改为全表对全表；IPC 子集口径保留为对照键 `patent_2021_2024_ipc_share_pct`（68.3482），只用于说明这个陷阱，不作为近四年占比发布。

深圳 2024 年专利 214,810 件，占全国 2024 年 494,655 件的 43.4262%。这个比例高得需要解释：它统计的是「深圳申请人在 2024 年公开的专利」对「全国同年公开专利」，分子分母同窗，比例本身成立；但它反映的是公开量份额，不是存量份额，不能读成「深圳拥有全国四成专利」。

合格技术域 238 个，口径是 2024 年该 IPC4 在深圳有 100 件及以上。这个门槛是兄弟件定的，本件原样引用，不改阈值。热度中位数 39.1374，是 238 个技术域热度分的中间值，说明半数技术域低于 40 分（0—100 标度），可作为「整体热度偏中低」的一行注脚。

### 2.4 论文四格

中文论文总量 100,900 篇，来自 `counts.paper_rows`；2023 年 6,651 篇，占全库 6.5917%。2023 是兄弟件选定的展示截面，不是峰值年：2024 年有 32,379 篇，是入库批次峰，兄弟件明确不把它当趋势。本件遵守这个判断，看板只展示 2023，避免读者把批次峰误读成产出暴增。

篇均被引 7.19 次，分母是「有引文记录的 20,031 篇」，不是全库 100,900 篇。引文覆盖率 0.198523，即 19.8523% 的论文能匹配到引文记录。这两格必须成组读：7.19 是高引用子集的均值，若把它当成全库篇均，会系统性高估论文影响。看板上两格相邻摆放，就是为了让读者同时看到「均值」和「这个均值只覆盖两成」。

### 2.5 投资与经费三格

深圳上市主体 2024 年研发费用 1,545.04 亿元，2021 至 2024 增幅 97.01%（由 784.24 亿元增至 1,545.04 亿元，增量 760.8 亿元）。增幅接近翻倍，与专利产出的温和增长形成对照：投入增速远高于公开量增速，说明单位投入的产出在下降，或投入滞后于产出，两种解释都需要更长序列才能分辨，看板不做因果判断。

投融资事件金额 2024 年为 3,441,816.16 万元，口径是「仅已挂链、有金额」的事件。这个口径比研发费用窄得多，两者不可相加、不可相除。看板把研发费用与投融资金额分格摆放，并在单位上明确区分亿元与万元，就是为了防止读者把两个不同母体的金额拼成一个「总投入」。

### 2.6 主体两格

高新技术企业 27,936 家，来自标签表截面，占企业底册 189,116 家的 14.7719%。这个比例是「高企标签覆盖率」，不是「高企占全部企业比例」——底册本身是代理名单，不是工商全量。看板使用时必须带这句限定，否则 14.7719% 会被读成深圳高企占比。

深圳产业基金 576 支，四城（北京、上海、深圳、广州）合计 1,881 支，深圳占 30.622%。基金数是截面计数，不带时间窗；兄弟件的口径是「注册地落城」，因此跨城母基金只计一次，不会重复。看板把这一格放在主体类末尾，作为「政府侧资金工具」的一个侧写。

### 2.7 事件两格置空

事件条数与事件关注度两格无**可用来源**。这里要分清两件事：同批确实有 `M_TNIE_EVENT_COUNT` 与 `M_INNOV_EVENT_ATTENTION` 两件，但它们的前者只交「活动型标题条数」代理、后者交负证据判完全不支持；在此基础上，`dwd_event` 仅 20 行单一展会系列、`innovation_event`/`dwd_innovation_event` 在 gkx 逐字 0。缺的不是文件，是**事件面**。

置空的写法也要讲究：`value` 为 `null`，`status` 为 `null`，`missing_reason` 写明「事件面缺源、代理读数不填真计数格」并点名涉及的件。不写 0，因为 0 是一个读数，会被前端画成「事件为零」；不写空字符串，因为空串在数值格式化时会变成 0。`null` 是唯一能被前端识别为「无数据」的形态。

## 四、数据缺失情况

### 4.1 事件条数：事件面缺源，代理读数不填真计数格（缺格）

同类指标件 `M_TNIE_EVENT_COUNT` 只交代理读数（活动型标题 18,884 条 / 1,668,414 条，约 1.13%），事件表本身只有 20 行、只覆盖两天、全部是国药励展系展会，不构成通用事件计数。看板不拿代理口径填格。

**缺格理由**：事件面缺源（`dwd_event` 20 行单一展会系列、事件表逐字 0），代理读数不是事件发生数。
**替代口径**：无。事件维整体留白；**即使 `M_TNIE_EVENT_COUNT` 已归档也不绑定**，除非改用真事件表重算。
**与原文差别**：看板暂时只能覆盖创新投入与产出，不能覆盖「事件活跃度」。

### 4.2 事件关注度：负证据不构成分数（缺格）

同类指标件 `M_INNOV_EVENT_ATTENTION` 判完全不支持：事件面缺失，且正本依赖的 `dwd_policy_base` 里 theme/quote_policy 各 19,998 / 20,000 行是字符串 'NULL'。看板不拿专利被引或媒体条数冒充事件关注度。

**缺格理由**：事件关注度在 gkx 不可构建（负证据），不是「文件尚未归档」。
**替代口径**：无。若甲方坚持要一格「关注度」，只能改用媒体关注并显式改名，不能沿用「事件」二字。
**与原文差别**：看板缺事件热度这一整个象限。

### 4.3 无看板结果面

`dwd_kpi` 与 `dwd_indicator` 逐字命中均为 0 张表。gkx 280 张表里没有任何一张以看板格为行、以读数为列。这意味着看板永远是「绑出来的」，不是「查出来的」；来源件的任何口径变更都会直接传导到看板，没有中间缓冲层。

### 4.4 不得外推的四件事

1. **不得把 null 当 0**：事件两格是「无数据」，不是「事件为零」。
2. **不得跨格相加**：研发费用（亿元）与投融资金额（万元）母体不同，不可相加成「总投入」。
3. **不得把覆盖率当占比**：高企 14.7719% 的分母是代理底册，不是工商全量。
4. **不得把篇均被引当全库均值**：7.19 只覆盖 19.8523% 的论文。

### 4.5 停用与重估条件

出现以下任一情况应重估：① 事件计数件与事件关注度件正式归档；② 兄弟件重跑导致键路径变更；③ 底册从代理名单换成工商全量；④ 甲方要求看板增加「趋势线」而非截面格——届时需要新增时间序列格，本件不支持。

## 五、结论与发布建议

### 5.1 可用结论

第一，16 格中 14 格有值，覆盖率 87.5%，主干四类齐全。第二，专利 2,939,895 件，近四年 2,424,684 件占 82.4752%（IPC 子集口径 2,009,365 件对应 68.3482%，仅作对照，不作结论）。第三，论文 100,900 篇，2023 年 6,651 篇占 6.5917%，篇均被引 7.19 仅覆盖 19.8523%。第四，深圳研发费用 1,545.04 亿元，2021 至 2024 增幅 97.01%。第五，高企 27,936 家占底册 14.7719%，深圳基金 576 支占四城 30.622%。第六，事件两格无来源件，置 null。第七，判部分支持。

### 5.2 发布口径（逐条写死）

| 项 | 必须写明的口径 |
|---|---|
| 事件两格 | 显示「无数据」，不得显示 0 |
| 篇均被引 | 标注覆盖 19.8523%，不是全库均值 |
| 高企 | 标注占代理底册 14.7719% |
| 研发费用 | 亿元；投融资金额万元；两者不相加 |
| 专利份额 | 公开量份额，不是存量份额 |
| 来源 | 每格带「件 ID + 键路径」角标 |

### 5.3 与旧稿的取舍

本件不引用任何旧看板稿的拼装结果。旧稿常见做法是先画 16 个格子再倒填数字，本版反过来：先锁定 7 份已归档来源件，再按实际可取的键路径决定格子。这样做的代价是事件两格必须留白，收益是每一格都能被独立复核。

### 5.4 后续

三条路径：① 等事件两件正式归档后补绑；② 若甲方要「趋势」，需要兄弟件提供年度序列而不是截面；③ 底册换全量后重算高企占比。第一条最直接，但事件面本身不足，即便归档也只能补「代理口径」格，需甲方先裁定是否接受。

## 附录 C 可行性完整版

### C.1 为什么不做「看板层加总」

看板的天然诱惑是把四类读数合成一个「创新总指数」。本件明确不做，原因有三：单位不可通约（件、篇、亿元、家）；母体不可通约（全库、近四年、深圳切片、代理底册）；权重没有官方来源。任何合成都会引入一个自建权重，而自建权重在看板这种高曝光位置最容易被误读为官方结论。

### C.2 键路径为什么写死在脚本里

键路径是来源件与看板之间的契约。若改成「按标签模糊匹配」，来源件改名或新增同义键时，看板会静默绑到错误的数。写死键路径的代价是来源件升级时要改脚本，收益是任何绑定错误都会以「键路径解析不到」的形式显式暴露，而不是悄悄取到一个看起来合理的值。

### C.3 事件维的最小可行补法

若甲方要求事件维必须有一格，最小可行方案是：正式归档一件「媒体报道中的活动型标题条数」代理件，看板格改名为「活动报道条数（媒体代理）」，并在格内标注「媒体≠事件」。这需要甲方先确认代理口径可接受，本件不擅自改格名。
