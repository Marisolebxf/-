## 摘要

「专家科研活跃度」在需求文档中有两处落点：其一是**专家活跃度可视化**（「通过活动热力图、时间轴等形式展示专家的科研活跃度，包括发表论文数量、参与项目情况、学术活动参与度等指标」），其二是**个人科研活跃度与合作网络分析**（「对学者在国际学术合作网络中的活跃度、影响力及网络扩展能力进行评估」）。需求给了三个子项，但未给公式。

王惠未定义本指标（`B5_INNOV.json`：`formula_source_1019=AI-20261016`, `wanghui=false`）。本文按需求原句重建四维口径：近窗论文产出（2024–2026，权重 0.35）、近窗篇均被引（0.25）、合著加权度（0.20）、参与国家/省部级项目数（0.20），各维 `log1p` 后 min-max，×100。

实测在 **1,842 位可展示学者**上产出 3.88–78.42 的连续分，中位 31.10、均值 31.93、≥50 分 145 人、≥70 分 2 人（宁光 78.42、王玮 70.08）。脚本 `code/M_INNOV_EXPERT_ACTIVITY.py` 已跑通并产出 `code/M_INNOV_EXPERT_ACTIVITY_out.json`。

档位结论：**部分支持**。核心约束是学者域著名的 **ID 断裂**：主档 21,316 人与关系表 20,015 人只有 1,842 人同 ID（8.65%），有属性标签的另一套人才库与主档重合率也仅 8.72%（`DATA_FACTS_gkx.md` §十一）。这意味着本指标能算、能排序，但覆盖面只有主档的 8.65%。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块：**科技信息展示系统 → 指数可视化展示 → 专家活跃度可视化**（§1.1.1.1.4.1.8.2.4），以及**人才服务 → 学者引进难度预测 → 个人科研活跃度与合作网络分析**（§1.1.1.1.4.3.4.2.6）。

前者是**群体视图**（热力图、时间轴、群体趋势），后者是**个体视图**（单个学者的活跃度与合作网络）。两者共用同一批子项，但聚合粒度不同：群体视图需要「按机构/地域/领域分组的活跃度分布」，个体视图需要「单人的分项解释」。

### 1.2 为什么需要「专家科研活跃度」这个指标

需求把专家活跃度列在「指数可视化」这一层，与「专家 H 指数排行」「科技影响力趋势」并列。这说明产品要回答的不是「谁最厉害」（H 指数已承担），而是「**谁最近在干活**」。

这个区分很重要：H 指数是终身累计量，一位资深院士可能近三年没有新论文，H 指数依然很高；一位青年学者刚发表 10 篇高被引论文，H 指数还很低。人才引进、项目评审、科研资源分配都需要后者——**当期活跃度**，而不是历史地位。

第二层价值是**合作网络**。需求原文明确要求评估「网络扩展能力」，这意味着活跃度不能只数论文，还要看合作广度与强度。本文因此把合著加权度作为独立一维。

### 1.3 需求文档是否给出定义方法

**需求给了三个子项名，未给公式**：

> 「包括发表论文数量、参与项目情况、学术活动参与度等指标」（§1.1.1.1.4.1.8.2.4）

三个子项中，前两项有源表（论文关系、项目表），第三项「学术活动参与度」（会议/讲座/交流）在开发库**没有任何表**——已全库检索 `%confer%`、`%meeting%`、`%lecture%`、`%活动%`，返回 0 张表。这一项无法纳入。

王惠口径文档目录中无 `M_INNOV_EXPERT_ACTIVITY.md`（同目录有 100+ 个指标口径文件，唯独缺此件），`B5_INNOV.json` 亦标注 `formula_source_1019=AI-20261016`。因此本指标是**无原始口径、需重建**的一类，重建依据只能是需求原句 + 学术计量惯例。

### 1.6 推测原意与推测定义（无王惠口径，按需求原句重建）

**推测原意**：产品要一个「谁最近在科研一线活跃」的排序与分布，用于人才引进、专家推荐、科研资源分配；它必须与 h 指数（终身成就）区分开，并体现合作网络的扩展能力。

**推测定义（本文口径）**：

> 专家科研活跃度 = 在 2024–2026 近窗内，综合学者的**论文产出量**（0.35）、**篇均被引**（0.25）、**合著加权度**（0.20）、**参与国家/省部级项目数**（0.20），各维 `log1p` 后在本批学者内 min-max 归一，加权 ×100。

$$
S(s)=100\times\Big(0.35\,n(\log(1+P_s))+0.25\,n(\log(1+\bar{C}_s))+0.20\,n(\log(1+W_s))+0.20\,n(\log(1+G_s))\Big)
$$

其中 $P_s$ 为近窗论文数、$\bar{C}_s$ 为近窗篇均被引、$W_s$ 为合著加权度（$\sum$ 合作篇数）、$G_s$ 为匹配到的项目数。

**四个设计取舍**：① 用「近窗」而非「全量」，是为了让活跃度区别于终身成就；② 用「篇均被引」而非「总被引」，是为了不让高产者垄断影响维；③ 用「加权度」而非「度」，因为度会奖励「广撒网、每段弱」的合作模式（`DATA_FACTS` §十已证：度 64 者加权度 57,992，度 109 者加权度仅 151）；④ 项目维用「姓名 + 单位」双条件，抑制同名膨胀。

## 二、计算过程

### 2.1 依赖分解（两跳止步）与 ID 域现实

| 层级 | D1 产出 | D2 影响 | D3 合作 | D4 项目 |
|---|---|---|---|---|
| 第 0 跳（指标） | 近窗论文数 | 近窗篇均被引 | 合著加权度 | 参与项目数 |
| 第 1 跳（源表） | `dwd_scholar_paper_relation` | 同表 `citations` | `dwd_scholar_coauthor` | `dwd_zh_project` |
| 第 2 跳（对齐键） | `scholar_id` | `scholar_id` | `scholar_id` + `co_scholar_id` | 姓名 + 单位 |
| 止步点 | 不再追期刊分区、影响因子 | 不再追他引/自引拆分 | 不再追 PageRank/介数 | 不再追项目金额、结题状态 |
| 止步理由 | 无分区表 | 无自引标记 | 无需构图（加权度已足够） | 金额字段大量为空 |

这条链在纸面上只需两跳，实际执行时撞到一个**结构性障碍**：第 1 跳的 `scholar_id` 与第 0 跳的学者主档 `dwd_scholar.scholar_id` **不是同一套 ID**。

实测四个数字（`coverage.id_space`）：

| 检查 | 数值 |
|---|---|
| 主档 `dwd_scholar` 去重 `scholar_id` | 21,316 |
| 论文关系表去重 `scholar_id` | 20,015 |
| 合著表去重 `scholar_id` | 20,011 |
| 主档 ∩ 关系表 | **1,843**（占主档 8.65%） |
| 主档 ∩ 合著表 | **1,839** |

`DATA_FACTS_gkx.md` §十一 已把这一现象命名为「身份宇宙 ↔ 属性宇宙 ID 断裂」，并记录：`dwd_scholar_talent_flag` 20,030 人与主档交集仅 1,858 人（8.72%），教育背景/工作经历表的 `scholar_id` 集合（20,025 / 20,028）与人才称号表高度一致，说明这三张表同源于**另一套人才库**。

**这对本指标的含义**：活跃度可以在 20,015 个 ID 上算，但只有 1,842 个 ID 能挂上姓名、机构、h 指数（即「可展示」）。本文选择**只对可展示的 1,842 人打分**，理由是：无法展示的分对产品无价值，且这 1.9 万人无法与项目表按姓名对齐（无姓名），四维中会缺一维，混合打分会产生「维度缺失导致的系统性低分」。

### 2.2 步骤 1｜近窗论文产出与影响

关系表按 `scholar_id` 聚合，取 `year ∈ [2024, 2026]` 的子集：

| 口径 | 数值 |
|---|---|
| 关系总行数 | 1,065,385 |
| 近窗论文行数（1,842 人） | 23,057 |
| 有近窗被引的学者 | 1,069 / 1,842（58.0%） |
| 单人近窗最高产出 | 291 篇（陈钱） |
| 单人近窗最高篇均被引 | 35.62（宁光，69 篇 / 2,458 次） |

篇均被引 $\bar{C}=$ 近窗总被引 / 近窗论文数。对 773 位近窗被引为 0 的学者，该项取 0，不做插补——插补会把「未被引用」误判为「中等影响」。

### 2.3 步骤 2｜合著加权度

合著表 1,187,606 行，按 `scholar_id` 聚合 `co_paper_count` 求和得加权度 $W_s$，同时保留去重合作者数 `deg`、最大单合作篇数 `max_co`、合作机构数 `co_orgs`。

**必须披露的三条网络事实**（`DATA_FACTS_gkx.md` §十）：

1. **30.5% 的边缺对端 ID**（361,951 行 `co_scholar_id` 为空或 0），已剔除；这意味着加权度是**下界**，学者的真实合作强度被系统性低估约三成。
2. **对端出现 899,662 个不同 ID，远超主档 21,316 人**，说明对端多为**库外学者**（无主档、无机构背书）；按对端机构做聚合时覆盖率受限。
3. **医疗类机构占 36.6%**（按 `co_scholar_org_name_zh` 统计），合著网明显偏向生物医学领域；工科与人文社科的合著密度被结构性低估。

建图结果（交叉校验用）：去重无向边 **822,018**、节点 **620,839**、连通块 1,199、最大块 611,039（**98.42%**）。这一形态（巨型连通块 + 长尾小团）是真实合作网的典型特征，与 demo 企业合作网（28,456 个碎块、最大块 220）形成对照——后者是随机撒边产物，不可用于本指标。

### 2.4 步骤 3｜项目匹配（姓名 + 单位双条件）

`dwd_zh_project` 共 **58,453** 条项目，字段含 `project_host`（主持人）、`participants`（参与人 JSON）、`institution`（依托单位）、`year`、`level`、`amount`、`title`。

匹配规则：学者姓名 == 主持人姓名（或出现在参与人列表），**且**学者机构与项目依托单位互相包含（去空格后子串判定）。双条件的目的是抑制同名：单靠姓名匹配会命中 **32,335** 条项目行（大量同名误配），加单位条件后收敛到 **845** 位学者（占 1,842 人的 45.87%），人均匹配 1–17 项。

为什么严格要求单位：中文姓名的重名率极高（「王伟」「李静」类姓名在 2 万人主档中可能出现数十次），若只按姓名匹配，一位地方院校学者可能被匹配到清华同名人主持的国家重点项目，产生严重高估。双条件会漏掉「学者调岗后项目仍挂原单位」的情况，但漏配比错配更可接受。

### 2.5 步骤 4｜归一、加权与分布

四维均做 `log1p` 后 min-max（`log1p` 用于压缩陈钱 291 篇、宁光 3,647 加权度这类极端值），权重 0.35 / 0.25 / 0.20 / 0.20，×100。

结果分布：min 3.88、中位 31.10、均值 31.93、P90 47.92、P99 61.14、max 78.42；≥50 分 145 人（7.87%）、≥70 分 2 人（0.11%）、0 分 0 人（因 min-max 后仍保留底分）。

权重设计的理由：产出是活跃度最直接的证据（0.35）；影响是产出的质量修正（0.25）；合作与项目各 0.20，前者体现网络扩展能力（需求明确要求），后者体现资源获取能力。项目维没有给更高权重，是因为它只覆盖 45.87% 的人，权重过高会让「无项目者」被系统性压低。

### 2.6 步骤 5｜效度校验（活跃度 ≠ 终身成就）

三项相关性（`validity_check`）：

| 校验 | 相关系数 | 解读 |
|---|---|---|
| 活跃度分 vs 存量论文数 | 0.5380 | 中度相关，未退化为「存量排名」 |
| 活跃度分 vs h 指数 | 0.5434 | 中度相关，与终身成就可区分 |
| 近窗论文数 vs 存量论文数 | 0.6262 | 近窗与存量相关但不等同 |

若活跃度分与 h 指数的相关超过 0.8，说明口径退化为「资深程度排名」；实测 0.5434，符合「活跃度 ≠ 终身成就」的设计意图。

两类极端样本进一步验证了区分能力：

**上升期**（近窗产出高、存量少）：史志远（天津大学，存量 17 篇 / 近窗 9 篇 / 加权度 84 / 31.42 分）、张泽宇（华中农业大学，25 / 14 / 34.39 分）、于茜（北京航空航天大学，14 / 6 / 26.19 分）。这类学者在 h 指数榜上不可见，但在活跃度榜上进入中上游。

**存量型**（存量高、近窗为 0）：陈宇综（深圳湾实验室，259 篇 / 总被引 101,859 / h=136 / 近窗 0 → 16.07 分）、刘忠范（北京大学，582 篇 / h=151 → 28.11 分）、方精云（北京大学，345 篇 / h=121 → 23.17 分）。这类学者在 h 指数榜前列，但活跃度被压到中下游，正是本指标的设计目的。

## 五、王惠方法对照

### 5.1 王惠是否定义过本指标

**没有。** 三项证据：① 王惠口径文档目录（`20260904_创新技术/指标计算逻辑/`，100+ 文件）中不存在 `M_INNOV_EXPERT_ACTIVITY.md`；② `_work_full/B5_INNOV.json` 标注 `formula_source_1019=AI-20261016`、`wanghui=false`；③ 需求文档只有子项名，无公式。

因此本节的「对照」不是两版公式对比，而是**与王惠体系内相邻指标的口径对齐检查**——特别是 `M_INNOV_SCHOLAR_INFLUENCE`（学者影响力）与 `M_INNOV_CONFERENCE_INFLUENCE`（会议影响力），避免两指标重复计量同一信号。

### 5.2 与相邻指标的边界

| 指标 | 语义 | 主信号 | 与本指标的关系 |
|---|---|---|---|
| `M_INNOV_SCHOLAR_INFLUENCE` | 学者影响力（存量地位） | h 指数、总被引 | 本指标用近窗量，二者中度相关（0.5434） |
| `M_INNOV_CONFERENCE_INFLUENCE` | 会议影响力 | 会议层级/规模 | 本指标缺「学术活动」维，本应与之衔接，但无会议表 |
| `M_INNOV_ORG_INFLUENCE` | 机构影响力 | 机构论文/专利 | 本指标是个人级，可上卷到机构 |
| `M_INNOV_PATENT_INFLUENCE` | 专利影响力 | 专利被引 | 本指标未纳入专利维（学者-专利无关联表） |

边界结论：本指标与「学者影响力」的分工是**近窗 vs 存量**，与「会议影响力」的分工本应是**个人参与 vs 会议本身**，但因无会议数据，这条边界暂无法建立。

### 5.3 选用建议

**建议采纳本文四维口径作为专家科研活跃度的基线，但须同步三项治理**：

1. **ID 映射是前置条件**。在甲方提供主档与关系表的 ID 映射前，本指标只能覆盖 1,842 人（8.65%），不适合做「全库专家活跃度排行」；若产品必须全量，应改为「两套宇宙分别出榜 + 明确标注来源」。
2. **会议数据缺失须在产品侧说明**。需求句明确要求「学术活动参与度」，当前口径无法交付；建议 UI 上把活跃度拆成「论文活跃度 / 项目活跃度 / 合作活跃度」三个可见子项，避免用户以为已包含会议。
3. **权重须业务确认**。0.35/0.25/0.20/0.20 是方法学默认值，未经 AHP 或业务校准；特别是项目维（0.20）只覆盖 45.87% 的人，对「项目型学者」有加成，是否合理需需求方裁定。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：近窗产出计数

以近 2–3 年论文数、项目数为代理。优点是直接、可解释；缺点是不区分质量。本文用于 D1、D4。

#### C.3.2 方法族 B：近窗影响计量

#### C.3.3 方法族 C：合作网络计量

#### C.3.4 方法族 D：学术活动计量

#### C.3.5 方法族 E：终身成就计量

以 h 指数、总被引计量。优点是稳定、可跨库比较；缺点是语义不符（存量≠活跃）。本文仅用于效度校验。
