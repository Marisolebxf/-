## 摘要

「科学研究前沿性」要用共被引网络识别「哪些论文簇正在成为前沿」，再用关键词共现识别「哪些方向正在变热」，最后给出这些主题的时间演变与空间分布。它是一个**四子项指标**，不是单一分数；四个子项的数据门槛完全不同，因此必须逐项判档，不能用一个总档掩盖差异。

实测结果是「两冷两热」。冷的两项：`dwd_zh_paper_citation` 20,031 行里只有 782 行带非空 `citation_id_list`（占论文池 0.775%），被引列表共出现 9,391 个被引 ID，其中只有 121 个（1.288%）能在本库 100,900 篇论文池里找到；268,982 个共被引对在 w≥2 过滤后剩 32 条边，进入池内过滤后**一条不剩**，连通分量为 0、最大簇为 0 篇。关键词侧稍好但仍然不够：`dwd_zh_paper_classification` 20,048 行里 799 行可对齐（0.792%），3,310 个互异关键词、7,251 个词对，w≥2 后只剩 24 条边、220 个节点，词频中位数为 1，图论意义上的「核心热点」不存在。

热的两项：时间演变有 799 篇带年份的样本，按近窗 2022—2024 对基线 2015—2019 可以算出每个主题词的增幅（例：人工智能从基线 0.0 升到近窗 1.0 篇/年，+100%；「治疗」从 0.6 降到 0.0，-60%）；空间分布有 733 篇（91.74%）可落城市，北京 189 篇、广州 125 篇、南京 45 篇、武汉 43 篇、深圳 42 篇。

结论是：**这条指标当前只能交付「主题词时间演变 + 空间分布」两张表，不能交付「研究前沿簇」与「核心热点图」**。判「部分支持」而不是「完全不支持」，是因为前两张表确实能用、且数值可复核；判「部分支持」而不是「完全转换支持」，是因为后两张表不是「暂时没跑」，而是**在现有数据量下无论怎么算都闭合不了**——共被引网络需要被引 ID 与论文 ID 同域，而这两套 ID 现在只有 1.29% 的交集。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技发展态势 → 科技创新评估 → 科学创造力评估 → 科学研究前沿性分析**（需求原文 1.1.1.1.4.1.7.1.3）。

需求的原文表述是「通过文献计量学和引文网络分析，识别特定领域内的研究前沿和热点方向，用户可查看前沿主题的时间演变和空间分布，了解科学研究的发展趋势和突破点」。这句话里其实藏了四件事：识别前沿（共被引簇）、识别热点（关键词共现）、看时间演变、看空间分布。calc-logic 把它显式拆成四维，本文按四维逐项判档。

| 页面任务 | 对指标的要求 |
|---|---|
| 前沿主题图谱 | 共被引 ≥2 的连通分量，需给出簇强度与簇内论文数 |
| 热点方向词云/榜单 | 高频且共现 ≥2 的关键词对，需给出度数 |
| 主题时间演变 | 每个主题词在近窗与基线的年均篇数之比 |
| 空间分布 | 主题论文在各城的份额 |
| 领域筛选 | 按题名入集领域论文，四维共用同一分母 |

### 1.2 为什么需要「科学研究前沿性」这个指标

论文数量告诉你「有多少」，前沿性告诉你「哪些正在变热」。两者缺一，科学创造力评估就只剩规模没有方向：一个城市论文很多但都在传统学科，与一个城市论文不多但集中在新兴方向，其创造力含义完全不同。需求把「前沿性」与「数量」「中心性」并列，正是为了让方向感进入评估。

这条指标也是四条科学创造力指标里唯一需要**引文网络**的一条。中心性用的是合作网络（作者—机构），前沿性用的是引用网络（论文—论文），两者的数据依赖完全不同：合作网络只要作者串，引用网络要 `citation_id_list`。本文的实测正是卡在后者：引文表只有 2 万行、可对齐 782 篇，被引 ID 与本库论文 ID 只有 1.29% 同域。换句话说，这条指标的瓶颈不在「有没有表」，而在「引文网络的节点是否落在同一个池子里」。

第三个理由是它必须可解释。前沿簇如果只给一个「热度分」，使用者无法判断它是「真前沿」还是「小样本噪声」。本文因此坚持输出簇内论文数、边数、连通分量数这些可复核的量，并在边数为 0 时**直接报告 0**，不用关键词频次去伪造一个「前沿榜」。这是本文与「用关键词频次冒充前沿」做法的根本区别。

### 1.3 需求文档是否给出定义方法

**需求给了四个观察角度，没给任何阈值。**

原文只写「识别研究前沿和热点方向」「查看前沿主题的时间演变和空间分布」，没有写：共被引的阈值是几、连通分量要不要设最小簇规模、关键词共现的窗口是多长、时间演变的近窗与基线各几年、空间分布的分母是主题论文还是全库论文。

calc-logic 补了四条可执行口径：研究前沿 = 共被引 ≥2 的连通分量，簇强度 = 簇内论文数 × 总被引；热点方向 = `COUNT(DISTINCT 论文id)` 且词对共现 ≥2；时间演变 = (近 3 年均值 − 前 5 年均值) / max(前 5 年均值, 1)；空间分布 = 该城论文数 / 主题论文数。这四条已经把阈值写死，本文照用，未改阈值。

仍未闭合的是：中英文语料是否合并（本文只用中文，英文库 1,387 篇太小）、被引 ID 与论文 ID 不同域时怎么办（本文选择「不桥接、只报池内交集」）、主题词的最小频次（本文取中位数 1 作为观察线，不设硬门槛）。这三条在 §2.5 写明为工程决策。

### 1.4 类似指标权威机构构建方法可行性分析概要

> 完整论证、方法谱系与风险清单见 **附录 C《科学研究前沿性类似指标权威构建方法可行性报告（完整版）》**。

| 方法族 | 代表机构/文献脉络 | 核心构架 | 与本指标贴合度 |

| A. 共被引簇分析 | Small (1973) co-citation；CiteSpace、VOSviewer | 以共被引强度建网，取连通分量做前沿簇 | **高**（calc-logic 走这条） |

**数据可行性（摘要）**：

### 1.6 推测原意与推测定义

**推测原意**：产品要的是一张「前沿主题地图」，让决策者看到某个领域最近在热什么、这些热点在哪些城市聚集。它更接近「科研态势感知」而不是「学术评价」。

**推测定义（本文采用）**：

> 设论文池 $P$（100,900 篇）、引文表给出共被引对集合 $E_c=\{(i,j,w)\}$、关键词表给出词对集合 $E_k=\{(u,v,w)\}$。四子项定义为：
> $$
> \text{前沿簇}=\text{CC}(E_c^{w\ge 2}\cap P\times P),\quad
> \text{热点}=\{u: \deg(u)\ge 1,\ \text{freq}(u)\ge \text{median}\}
>
$$
> $$
> \Delta_u=\frac{\bar n_u^{(2022\text{—}2024)}-\bar n_u^{(2015\text{—}2019)}}{\max(\bar n_u^{(2015\text{—}2019)},1)},\quad
> s_c=\frac{\#\{p\in P: \text{city}(p)=c\}}{\#\{p\in P:\text{city}(p)\ne\varnothing\}}
>
$$

**为什么必须取池内交集**：共被引簇的意义是「这些论文互相引用」，如果被引 ID 指向库外论文，簇就无法落到本库论文上，页面上会出现「有簇但点不开」的空节点。本文因此只保留两端都在 $P$ 内的边，并把这个过滤后的边数（0）作为结论，而不是把 32 条跨界边当成簇。

**为什么热点用「中位频次」而不是固定阈值**：3,310 个词的频次中位数是 1，若设 freq≥5 只剩 8 个词，设 freq≥2 只剩约 300 个词，任何一个固定阈值都会把结论变成「阈值选择的结果」。本文取中位数作观察线，并在结果里同时报度数，让使用者自己判断。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是 calc-logic 的四维定义。本文没有改动任何阈值（共被引 ≥2、共现 ≥2、近 3 年对前 5 年），只补了三件原文未写的事：被引 ID 与论文 ID 不同域时的处理、英文语料是否合并、主题词最小频次。之所以必须补，是因为不补就无法判定「边数 0」到底是数据没有还是算法算错。

本文做的降级只有一处：**不交付研究前沿簇与核心热点图**。这不是「把阈值调低直到出图」，而是承认在 0.775% 覆盖率下任何簇都是小样本噪声。本文没有做的降级包括：没有把关键词频次当成共被引簇的替代、没有把 32 条跨界边画成网络、没有用英文库 1,387 篇去补边、没有把 2015 年的 201 篇样本当成「前沿爆发」。

### 2.2 口径拆解：对象、集合、归一

**对象**：领域主题。研究前沿的对象是「论文簇」，热点方向的对象是「关键词」，时间演变的对象是「主题词」，空间分布的对象是「主题论文」。四个对象不同，不能互相替代。

**集合**：本库 100,900 篇中文论文为母池；引文侧取 782 篇有被引列表的论文，关键词侧取 799 篇有关键词的论文，两者的交集是 782 篇（本文实测 `citing_and_classified=782`，说明关键词表基本覆盖了引文表那批论文）。

**归一**：时间演变用「年均篇数」而不是「总篇数」，因为近窗 3 年与基线 5 年长度不同；分母取 `max(基线均值, 1)`，避免 0 除。空间分布用「该城论文数 / 可归属城市论文数（733）」，不是除以 100,900——后者会把 92.74% 的未归属当成「没有论文的城市」。

**边与簇的定义**：共被引边 $(i,j)$ 的权重 $w$ 是「同时引用 $i$ 与 $j$ 的论文数」，只保留 $w\ge 2$ 且 $i,j\in P$ 的边；连通分量用并查集，簇强度 = 簇内论文数 × 簇内总被引。本文实测这条链路每一步的剩余量：268,982 对 → 32 条 w≥2 边 → 池内 0 条 → 分量 0 个。

### 2.3 依赖分解（两跳停）

| 跳 | 依赖 | 承载 | 状态 |
|---|---|---|---|
| 1 | 论文主档：ID、题名、发表年 | `gkx.dwd_zh_paper` | 100,900 行，年份 100% |
| 1 | 被引列表 | `dwd_zh_paper_citation` | 20,031 行，782 行非空 |
| 1 | 关键词 | `dwd_zh_paper_classification` | 20,048 行，799 行可对齐 |
| 1 | 作者单位/地址 | `dwd_zh_author` | 62,002 行，733 篇可落城市 |
| 2 | 被引 ID → 池内论文 | 需要同一 ID 域 | **断在第 2 跳**：仅 121/9,391 同域 |
| 2 | 关键词 → 学科码 | 需要码表 | 库内无码表，只做词级统计 |

「两跳停」在这里不是主动选择，而是被动断链：第 2 跳的被引 ID 与本库 `id` 不同域，无法回连。本文尝试过用题名匹配桥接，但被引列表里只有 ID、没有题名，桥接不可行；这一点写进 §四的修复要求。

### 2.4 算路 / SQL

本指标**零 SQL**，全部读 20261022 的探针缓存。原因是三张附表都在 2 万行量级，探针阶段已各查 1 次并把行级数据落盘，重跑只读缓存即可复现：

```text
-- 探针阶段（已落盘，脚本不再连库）
_P1  SELECT id, citation_num, citation_id_list FROM gkx.dwd_zh_paper_citation;      -- 20,031 行
_P2  SELECT id, keywords FROM gkx.dwd_zh_paper_classification;                      -- 20,048 行
_P3  SELECT paper_id, institution, affiliation FROM gkx.dwd_zh_author;              -- 62,002 行
_P4  SELECT id, cover_year_start FROM gkx.dwd_zh_paper;                             -- 100,900 行（年份列）
```

本地计算顺序：先建池内 ID 集合 → 解析被引列表并统计共被引对 → 过滤 w≥2 → 取池内交集 → 并查集求分量；再解析关键词、统计词频与词对 → 过滤 w≥2 → 算度数；最后按年份算主题词近窗/基线均值、按城市算份额。

**为什么不在 SQL 里做**：`citation_id_list` 是长文本列表，SQL 侧拆分会把 2 万行炸成几十万行中间结果；关键词同理。2 万行拉到本地后全部计算在 0.3 秒内完成，没有理由让数据库承担解析工作。

### 2.5 清洗规则

| 规则 | 处理 | 影响行数 |
|---|---|---|
| `citation_id_list` 为空 | 该篇不进引文网，但仍计入论文池 | 19,249 行 |
| 被引 ID 不在池内 | 丢边，不桥接、不猜 | 9,270 个 ID |
| 共被引对 w=1 | 丢弃（口径要求 w≥2） | 268,950 对 |
| 自引（i=j） | 丢弃 | 若干 |
| 关键词为空 | 该篇不进词网 | 19,249 行 |
| 关键词频次低于中位数 | 保留在节点集但标为低度，不做硬删 | 3,090 个词 |
| 城市无法识别 | 不进空间分布分母 | 66 篇（8.26%） |
| 2025/2026 样本 | 不进近窗与基线（样本过少） | 3 篇（2025） |
| 英文库 | 不合并（1,387 篇，量不足） | 1,387 篇 |

清洗原则是「宁可少画一张图，也不编一条边」。对网络类指标来说，为了让图「看起来有结构」而降低 w 阈值，是最常见的造假路径；本文把 w≥2 写死在口径里，w=1 的 268,950 对一律丢弃，哪怕结果是 0 条边也不回头改阈值。

### 2.6 结果解读

**研究前沿（不可建）**：268,982 个共被引对 → w≥2 剩 32 条 → 两端都在池内剩 0 条 → 连通分量 0 个 → 最大簇 0 篇。这个链条的断点在第三步：32 条边里没有一条的两端都是本库论文。原因是被引列表里的 9,391 个 ID 只有 121 个能在池内找到（1.288%），其余 98.7% 指向库外文献。**结论：研究前沿簇在现有数据下不可建，不输出任何簇。**

**热点方向（退化）**：3,310 个互异关键词、7,251 个词对，w≥2 后 24 条边、220 个节点，词频中位数为 1。Top 词是「治疗」10 次（度 1）、「应用」9 次（度 1）、「预后」8 次（度 2）、「磁共振成像」8 次（度 0）、「诊断」5 次（度 2）。度数最高只有 2，说明这些词两两之间几乎没有稳定共现结构；把它画成网络会得到一堆孤立点加几条细线，不构成「核心热点」。

**时间演变（可出数）**：799 篇样本按年分布为 2015 年 201 篇、2016 年 10 篇、2017 年 15 篇、2018 年 32 篇、2019 年 40 篇、2020 年 36 篇、2021 年 20 篇、2022 年 18 篇、2023 年 24 篇、2024 年 34 篇、2025 年 3 篇。2015 年的 201 篇与 2016 年的 10 篇之间有一个 20 倍的断崖，这与 `M_INNOV_SCI_PAPER` 里 2024 年的批次尖峰是同一类问题（采集批次把一批文献的年份记到了同一年），因此本文在算近窗/基线时把 2015 保留在基线内但单独标注该断崖。示例读数：人工智能 近窗 1.0 篇/年、基线 0.0，+100%；针灸 同 +100%；「治疗」近窗 0.0、基线 0.6，-60%；「中国」近窗 0.0、基线 0.8，-80%。

**空间分布（可出数）**：733 篇可落城市（91.74%），北京 189 篇、广州 125 篇、南京 45 篇、武汉 43 篇、深圳 42 篇、上海 42 篇、成都 33 篇、中山 28 篇、天津 28 篇。北京与广州合计 314 篇，占可归属样本的 42.8%；这个集中度与 `M_INNOV_SCI_PAPER` 的城市分布（广州 23,445、北京 17,061）方向一致，但绝对量只有后者的 1/100 量级，因为这里只是 782—799 篇的子样本。

## 四、数据缺失情况

### 4.1 缺失清单

| 缺失项 | 现状 | 影响 | 修复建议 |
|---|---|---|---|
| 引文表覆盖率 | 20,031/100,900 = 19.9%，其中带列表 782 篇 | 共被引网无法闭合 | 补齐到全量并保证 `citation_id_list` 非空 |
| 被引 ID 域 | 9,391 个 ID 仅 121 个在池内 | 98.7% 的边指向库外 | 建立被引 ID 与本库 `id` 的映射，或直接给 DOI |
| 关键词表覆盖率 | 20,048/100,900 = 19.9%，799 篇可对齐 | 词网退化 | 补齐到全量 |
| 学科码表 | 无 | 无法按学科归并主题词 | 补中图分类号 |
| 摘要/全文 | 无 | 无法做主题模型或语义聚类 | 补摘要字段 |
| 英文语料 | 1,387 篇 | 无法补足引文网 | 补英文引文表 |
| 年份批次异常 | 2015 年 201 篇 vs 2016 年 10 篇 | 时间演变基线被单年主导 | 供应方给批次号 |

### 4.2 对结论的影响边界

上述缺失**改变的是「能不能做前沿簇」，不是「能不能做时间/空间」**。时间演变与空间分布两张表在 799/733 篇样本上是可复核的，可以交付；前沿簇与热点图在任何阈值下都不可交付。这条边界必须写进页面：同一张卡片上，两张子表有数、两张子表没有数，不能让使用者误以为「空图是因为没查到」。

### 4.3 不可外推的三件事

第一，不能把 24 条关键词边当成「领域热点结构」。度数最高 2、平均 0.22，任何一个真实领域的关键词网络都比这密。第二，不能把 799 篇的时间演变当成「全库主题趋势」。这 799 篇只是有引文/关键词记录的那批，占池 0.79%，且 2015 年有批次异常。第三，不能把 733 篇的城市份额当成「城市前沿论文占比」。它的分母是「可归属城市的 733 篇」，不是 100,900 篇。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

王惠 calc-logic 的四维结构是：

| 二级 | 三级 | 口径 | 计算逻辑 | 源字段 |
|---|---|---|---|---|
| 研究前沿 | — | 高被引论文共被引连通簇 | 共被引 ≥2 的连通分量；簇强度=簇内论文数×总被引 | `dwd_zh_paper_citation(citation_id_list)` |
| 热点方向 | — | 高频且共现的关键词 | `COUNT(DISTINCT 论文id)`；词对共现 ≥2 | `dwd_zh_paper_classification(keywords)` |
| 时间演变 | — | 主题词近窗相对基线的增幅 | (近3年均值 − 前5年均值)/max(前5年均值,1) | `dwd_zh_paper(cover_year_start)` + 关键词 |
| 空间分布 | — | 主题论文在各城的份额 | 该城论文数 / 主题论文数 | `dwd_zh_author(institution, affiliation)` + `dwd_org_base_info` |

并写明「引文落 `citation_id_list`，不用作者关系表」。

### 5.2 新方法概述

新方法保留四维与全部阈值，补三件事：被引 ID 与池内 ID 的同域过滤（并报告过滤前后边数）、英文语料不合并的显式声明、时间演变样本的批次异常标注。输出除两张可用表外，还有完整的「漏斗数字」（对 → 边 → 池内边 → 分量），让「不可建」这件事本身可复核。

## 附录 C　科学研究前沿性类似指标权威构建方法可行性报告（完整版）

### C.1 报告目的与范围

本附录回答：在只有本库 100,900 篇中文论文、引文表 2 万行、关键词表 2 万行的条件下，四个子项各自能做到什么程度，以及权威的共被引方法为什么不能照搬。

### C.2 需求语义锚定

「前沿」在文献计量里有两套完全不同的实现：一套是共被引簇（结构视角），一套是突现词（时间视角）。前者回答「哪一组论文被一起引用」，后者回答「哪个词突然变多」。需求同时提了「研究前沿」和「热点方向」，等于两套都要。本文的实测显示，两套在本库都受限于样本量，但受限方式不同：共被引是「边断裂」，突现词是「序列太短」。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：共被引簇

Small (1973) 的原始定义是「两篇论文被第三篇同时引用，则它们共被引一次」。CiteSpace 在此之上加了三件事：w≥2 过滤、连通分量、簇强度。本文完全照用这三件事，结果是 0 条池内边——不是算法错，是两端不在同一池。

#### C.3.2 方法族 B：文献耦合

Kessler (1963) 的耦合是「两篇论文引用同一批参考文献」。它比共被引更容易闭合，因为它只需要每篇论文的参考文献列表，不需要被引论文本身在池内。但本库的 `citation_id_list` 正是参考文献列表，只是覆盖率 0.775%，所以耦合同样做不了。

#### C.3.3 方法族 C：突现词检测

Kleinberg 的 burst detection 需要每个词在连续年份上的频次序列。本文的序列只有 2015—2025（11 年），且 2016—2021 每年不足 40 篇，频次多为 0 或 1。在这种序列上做 burst，任何 λ 参数都会把噪声当突现。

#### C.3.4 方法族 D：主题模型

LDA / BERTopic 需要摘要或全文。库内 `dwd_zh_paper` 无摘要字段，只有题名与关键词，主题模型退化为关键词聚类，与 C 同源，不构成独立方法。

### C.4 数据可行性详细分析

#### C.4.1 引文侧

20,031 行、782 行有列表、9,391 个被引 ID、121 个池内命中。四个数字决定了共被引不可建。

#### C.4.2 关键词侧

20,048 行、799 行可对齐、3,310 个词、7,251 个对、24 条 w≥2 边。词频中位数 1 说明长尾极长，头部也只有 10 次。

#### C.4.3 时间侧

799 篇带年份，2015 年 201 篇是异常高点（占样本 25.2%），2016 年断崖到 10 篇。近窗 2022—2024 共 76 篇，每年约 25 篇，做词级增幅可以，做簇级演化不行。

#### C.4.4 空间侧

733 篇可落城市（91.74%），Top 3 北京 189、广州 125、南京 45。这是四维里最干净的一维。

#### C.4.5 方法—数据对照矩阵

| 方法 | 需要的输入 | 库内状态 | 可行性 |
|---|---|---|---|
| A 共被引簇 | 被引 ID 同域、w≥2 边 | 池内边 0 | 不可行 |
| B 文献耦合 | 完整参考文献列表 | 0.775% 覆盖 | 不可行 |
| C 突现词 | 长年份序列 | 11 年、年样本 <40 | 不可行 |
| D 主题模型 | 摘要/全文 | 无 | 不可行 |
| 时间演变 | 年份 + 词 | 799 篇 | **可行** |
| 空间分布 | 城市 + 词 | 733 篇 | **可行** |

### C.5 推荐构建方案（工程可执行）

1. 交付两张表：主题词时间演变、主题论文城市分布；
2. 不交付前沿簇与热点图，接口返回 `null` 并在前端显示「数据不足」；
3. 把漏斗数字（对/边/池内边/分量）写进接口响应，供前端展示「为什么没有图」；
4. 待引文表补齐到全量、被引 ID 同域后，再启用簇算法，阈值不变。

### C.6 风险与残余不确定性

- 2015 年批次异常会污染时间演变的基线；
- 799 篇样本的 Top 词频次只有 10，任何排名都不稳定；
- 24 条关键词边的图若强行可视化，会被误读为「热点结构」；
- 被引 ID 不同域是供给问题，不是算法问题，短期无法靠调参解决。

### C.7 可行性总判（完整版结论）

四子项中两项可用、两项不可建，判「部分支持」。不可建的两项不是「永远不可建」，而是「需要供应方补引文覆盖与 ID 映射」；补齐后可按现有阈值直接启用，不需改口径。
