### 0.2 本件判定：部分支持

**判定结论：部分支持。** 落点在于「三个宇宙的名次都能产出，但名次的可比性被上游指数与底册构成双重削弱」。

## 摘要

多维度排名展示（M_INNOV_DS_04_CARRIER_RANK_002）把创新载体的创新能力指数转换为名次，并按总体、地区、领域三个宇宙分别呈现，对应需求原文「提供创新载体的多维度排名，包括总体排名、领域排名、地区排名等，用户可切换查看不同维度的排名情况」。本件不新造排序算法，沿用王惠 V1.5 的 `RANK(index_score)` 口径：以同批 3,000 家载体的指数分为唯一排序键，同分同名次、名次跳号，再按城市与 IPC4 主分类切出切片，切片内独立重排。实测总体宇宙 3,000 家全部有名次，地区宇宙 12 个城市切片（深圳 1,122 家、广州 583 家、东莞 238 家、惠州 57 家及 8 个英国城市），领域宇宙 4 个 IPC4 切片（`B23K26` 15 家、`A61M1` 5 家、`H01R13` 30 家、`A61M16` 2 家）。头部十家名次与上游指数完全一致，第一名深圳市科曼医疗设备有限公司 100.0 分、名次百分位 0.033%，第十名广东沃德精密科技股份有限公司 28.22 分、名次百分位 0.333%。但 2,082 家（69.4%）指数为 0 并形成零分带，且广东四市占入集 66.7%、资源维覆盖率不足 0.5%，据此判定为**部分支持**：名次可复现、可展示，但跨城市与跨领域的名次不可直接比较。

## 一、需求定义概述

### 1.1 需求原文溯源

需求原文在「全球创新监测」下设置「创新载体排行榜」一级功能，开篇即给出功能定位与价值主张：「将各领域科技创新与基础研究监测及汇总的创新成果数据，按照数据模型计算创新能力指数，进行排名展示。该功能通过可视化方式呈现创新载体的创新活力程度，帮助用户了解不同创新载体的创新能力和表现，为创新资源分配和合作决策提供参考依据。」（§1.1.1.1.4.1.4.4）

其下四个子功能与本件直接相关。**多维度排名展示**：「提供创新载体的多维度排名，包括总体排名、领域排名、地区排名等，用户可切换查看不同维度的排名情况。」（§1.1.1.1.4.1.4.4.2）**排名筛选功能**：「用户可按领域、地区、时间范围等条件筛选创新载体，查看特定条件下的排名情况。」（§1.1.1.1.4.1.4.4.3）**详情查看**：「用户点击排行榜中的创新载体名称，可查看该载体的详细信息，包括创新成果、创新能力指数变化趋势等。」（§1.1.1.1.4.1.4.4.4）**指数计算**：「基于数据模型对各创新载体的创新成果数据进行计算，生成创新能力指数，用户可查看指数计算方法和权重设置。」（§1.1.1.1.4.1.4.4.1）

需要特别指出，原文用了「多维度排名」而非「多维加权排名」：其含义是**同一指数在多个分组宇宙中分别排名**，而非为每个维度单独赋权再合成。这一区分决定了本件的实现路径——指数只算一次，排名做三次。

### 1.2 UI 呈现形态

前端以「三页签 + 一切换 + 一筛选」承载本件。三页签对应总体、地区、领域三个宇宙，页签标题旁标注该宇宙的载体计数；切换指地区与领域页签内的下拉选择器，用于在 12 个城市与 4 个 IPC4 之间切换；筛选器按载体类型、创新领域、时间范围过滤后再排名，筛选条件变化时名次实时重算而非仅在当前页内重排。

列表每行展示六列：名次、载体名称、所属城市、所属领域（主 IPC4）、创新能力指数、名次百分位。名次列在零分带内以灰色并列样式展示（如「919」重复出现），百分位列显示「前 X%」而非裸数字，避免用户把 0.033 误读为 33%。详情抽屉复用载体域指标，展示指数三维分项、专利与论文计数、高企资质标记，并在底部提示「名次仅在当前宇宙内可比」。

### 1.5 与相邻指标的边界

与 **M_INNOV_CARRIER_RANK_001** 的边界是「指数」与「名次」：前者输出 0–100 的能力分及其三维分项，后者只在分值之上做序关系变换，不改变分值。两者若出现不一致，一律以指数为准，排名侧只允许出现「同分同名次」造成的并列，不允许出现「同分不同名次」或「低分高名次」。

与 **M_INNOV_CITY_RANK_GLOBAL** 的边界是「载体排名」与「城市排名」：后者以城市为对象、聚合市域内全部载体后排名，本件以载体为对象、在市内排名；城市排名回答「哪个城市强」，本件回答「这个城市里谁强」，二者不可互换，也不可把本件的组内名次直接聚合成城市名次（聚合会放大底册厚的城市）。

与 **M_INNOV_DS_06_CARRIER_003** 的边界是「榜单」与「画像」：详情抽屉中的三维分项、专利/论文计数、资质标记由载体画像指标提供，本件只负责名次与百分位，避免两处各自计算导致数字打架。

### 1.6 计量单位与统计期

名次是无量纲的序数，取值 1 至 `total_in_group`，其大小只在同一 `group_key` 内有意义；`pct_position` 是无量纲百分比，含义是「位于前百分之几」，数值越小越靠前。指数分为 0–100 的无量纲分值，沿用上游定义。

统计期取 2024 自然年（上游 `stat_year = 2024`），即载体在该年的成果与资质快照。时间范围筛选改变的是入集载体集合而非历史名次序列；本件不存储时序名次，若需「指数变化趋势」须由上游指数表按年落库后另行提供，当前仅有点位快照。

## 二、计算过程

### 2.1 总体框架：一次算分、三次排名

本件把「算分」与「排名」彻底解耦：指数由上游 `M_INNOV_CARRIER_INDEX_GLOBAL` 一次算出并冻结，本件只做序关系变换。这样做的好处是三个宇宙共享同一分值与同一入集口径，用户在页签间切换时看到的是「同一批载体在不同分组中的位置」，而不是「三套不同算法给出的三套分数」。若每个宇宙各自重算指数，则跨页签的分数不可比，页签切换会变成口径切换，违背原文「切换查看不同维度的排名情况」的本意。

解耦的代价是分组内极值不再重算。举例而言，深圳切片内第一名 100.0 分是全局第一，而惠州切片内第一名 29.51 分在全局仅列第七；若按组内极值重算，惠州第一名也会变成 100.0，用户会误以为惠州头部与深圳头部等强。本件选择保留全局分值、只在组内排名次，正是为了避免这种「组内第一即满分」的错觉。

### 2.2 入集与上游指数口径

入集规则由上游确定：以载体主档为底，按名称做跨源对齐（境内机构、科研院所、境外机构三源），对齐成功且至少有一个成果或资质信号的载体进入 3,000 家候选集。指数三维为产出维（专利数、论文数）、资质维（高企标记、研发机构标记）、资源维（研发人员数、营业收入），各维批内极值归一后等权合成乘 100，缺测维按有效维重归一。

实测三维覆盖极不均衡：产出维覆盖 731 家、授权子项 675 家、高企资质 350 家，而资源维的 `annual_dev_or_emp` 仅 2 家、`revenue` 仅 12 家。覆盖率差异直接决定了指数分布形态——三维齐备的载体极少，多数载体只有产出维与资质维两维，个别载体仅一维，故 3,000 家中 918 家得正分、2,082 家得 0 分。零分并非「能力为零」，而是「三维全缺测」，这一点必须在页面上写清楚，否则会误导资源分配决策。

### 2.3 三个宇宙的定义

**总体宇宙**以全部 3,000 家为组，`group_key = ALL`，名次 1–3,000，用于回答「全局最强是谁」。**地区宇宙**以载体主档的 `city` 为分组键，同一城市内独立排名；上游共 437 个城市有载体，本件演示仅保留载体数最多的 12 个切片（深圳、广州、东莞、LONDON、惠州、MANCHESTER、BIRMINGHAM、GLASGOW、LEEDS、BRISTOL、LEICESTER、PRESTON），其余城市按需展开。**领域宇宙**以 `dwd_org_tech_tag` 中出现频次最高的 IPC4 为主领域，按主领域分组，演示 4 个切片（`B23K26` 激光加工、`A61M1` 医疗器械、`H01R13` 电连接器、`A61M16` 呼吸器具）。

三个宇宙的入集并不互斥：一家载体既在总体榜上，也在其所属城市的地区榜上，还可能出现在某个领域榜上。因此前端必须显式标注当前宇宙，且详情页要同时给出「全局第 r1」与「本市第 r2」两个名次，避免用户把组内名次当成全局名次。

### 2.4 名次计算与并列规则

设某宇宙 `u` 的组 `g` 内有 `n` 家载体，第 `j` 家的指数分为 `s_j`，则名次定义为：

```
rank_j = 1 + |{ k : s_k > s_j }|          （同分同名次，后续跳号）
total_in_group = n
```

该定义即竞赛排名（competition ranking，又称 1224 式）：若前两名同分，则两家均为第 1 名，第三家为第 3 名。选择跳号而非密集名次（dense rank，1123 式），原因是跳号名次保留了「有多少家排在我前面」这一信息，与 `pct_position` 的语义一致；密集名次会压缩尾部，使「第 919 名」看起来像「第 3 名」，在零分带占七成的情况下尤其危险。

并列内部的展示顺序由稳定三键决定：`score` 降序、`name` 字典序升序、`org_id` 升序。第三键的存在保证任意两次运行、任意两个节点上的输出完全一致，便于对账；同时避免「同分载体在页面上随机换位」造成的用户困惑。需要强调，稳定三键只决定**展示顺序**，不改变名次数值——同分载体的 `rank` 必须相等，若实现中把展示序号写进 `rank`，即属口径违规。

### 2.5 名次百分位与展示换算

百分位定义为 `pct_position = rank / n × 100`，单位是百分比，含义是「位于前百分之几」。实测第一名 `1 / 3000 × 100 = 0.033`，第二名 `0.067`，第十名 `0.333`，与该公式完全吻合。前端展示时统一加「前」字并保留两位小数（前 0.03%、前 0.33%），不使用裸小数，原因是 0.033 极易被误读为「3.3%」或「第 33 名」。

组内百分位与全局百分位必须分开计算。以惠州切片为例，组内第一名 29.51 分对应 `1 / 57 × 100 = 1.75%`（组内前 1.75%），但在全局 3,000 家中该分对应的名次约为第 7 名（全局前 0.23%）。两个数字都对，但回答的问题不同；页面应同时给出「组内前 1.75%」与「全局第 7」，否则用户无法判断这个「第一」的含金量。

### 2.6 零分带与跨宇宙一致性

零分带是本件最重要的结构特征：2,082 家指数为 0，占 69.4%，在总体宇宙中全部并列于第 919 名（因为恰有 918 家为正分）。这意味着总体榜的第 919 至第 3,000 名在数值上毫无区别，任何「第 1,500 名比第 2,000 名强」的解读都是错误的。本件在输出中显式给出 `zero_band = true` 标记与 `zero_band_pct = 69.4`，前端据此把该段折叠为一条「并列 919 名（共 2,082 家）」的聚合行。

跨宇宙一致性用于校验名次链路是否自洽：全局前十中有五家同时是其所在城市或领域的组内第一（科曼、大族激光、麦格米特、铁头科技、新威尔电子），说明头部载体在各宇宙中稳定领先；反之，若某载体全局第一却在组内屈居第五，则必然是分组键错配或名称对齐失败。本件把这一组「跨宇宙头部」写入输出（`cross_universe_heads`），作为回归测试的黄金样本。

## 三、数据支撑情况

### 3.1 真源表与规模

本件依赖五张 gkx 表，规模从 2,074 行到 202,424 行，均在可直接精确计数的量级。载体主档 189,116 行是入集的底册，科研机构 2,074 行用于补充院所类载体，境外机构 20,000 行提供英国城市载体，技术标签 202,424 行为领域宇宙提供分组键，年度财务 90,926 行本应提供资源维但 `dev` 字段全空。

所有校验查询均在 30 秒内返回。由于载体主档不足 20 万行，本件允许直接 `COUNT(*)` 与 `GROUP BY city`，无需借助 `information_schema` 估算；这也是本件与专利域指标在查询策略上的主要差别。

### 3.2 名称对齐是主键

本件的分组键（城市）与展示键（名称）都来自名称对齐，而非稳定的机构 ID。上游把境内主档、科研院所、境外机构三源按名称归一后合并，对齐失败的载体要么被排除在 3,000 家之外，要么以 `null` 或原名残留的形式出现在切片中（BRISTOL 的 `null` 即为一例）。名称对齐的质量直接决定地区宇宙的可靠性：若两家同名机构被合并，其指数会被叠加；若同一机构两种写法未合并，其指数会被拆散并在两个城市各占一个名次。

当前 3,000 家入集相对 189,116 行主档仅占 1.59%，说明绝大多数机构因缺少成果或资质信号而未入集。这是合理的筛选（无信号则无法评分），但也意味着「未上榜」不等于「不存在」，页面不宜把榜单呈现为「全部载体名录」。

### 3.3 覆盖与偏置

底册构成须强制披露三点。其一，**地域偏粤**：广东四市合计 2,000 家，占入集 66.7%（深圳 37.4%、广州 19.4%、东莞 7.9%、惠州 1.9%），任何跨城市的名次比较都会把「底册多」误读为「创新强」。其二，**境外切片集中于英国**：地区宇宙的后八位全部为英国城市，且其组内第一指数全为 0，说明境外载体的成果信号尚未打通，其名次不可与境内城市并列解读。其三，**领域切片样本过薄**：4 个 IPC4 中 3 个不足 30 家，`A61M16` 仅 2 家。

因此在页面上必须做到：跨城市比较须加注「底册偏粤（广东 66.7%）」；境外城市单独分区展示，不与境内城市同表排序；样本不足 30 家的领域切片加注「样本过少」。

### 3.4 计算成本与可复现性

本件不重算指数、不重跑排名，仅做内存重组与六条计数校验，运行时间 2 秒内。可复现性由三重保障：上游两份 out.json 随代码归档、脚本内置与上游 `support_judgment` 的一致性断言、所有校验查询以 SQL 常量写入附录 B。由于排名是纯序关系变换，只要上游分值与入集不变，名次在任何节点上都应逐位一致。

## 四、数据缺失情况

### 4.1 资源维全空导致指数语义削弱

`gkx.dwd_org_annual_financial_info` 90,926 行中 `dev` 字段 100% 为 NULL，`revenue` 仅 12 条非空，`annual_dev_or_emp` 仅 2 条。资源维在三维中名义上占三分之一权重，实际几乎不参与合成，指数退化为「产出 + 资质」两维。这不会让名次算不出来，但会让名次回答的问题从「综合创新能力」偏移为「成果数量与资质」，须在页面口径说明中如实标注。

### 4.2 零分带占七成

2,082 家（69.4%）指数为 0，形成长达 2,082 位的并列名次段。零分带内部没有任何序信息，任何在此段内做的「名次提升」展示都是伪信号。当前处置是标记 `zero_band` 并在前端折叠；根治办法是补齐资源维或降低入集门槛，让这些载体至少有一维可得正分。

### 4.3 领域宇宙样本过薄

`A61M1` 5 家、`A61M16` 2 家，组内名次的取值空间分别只有 5 与 2，几乎不具区分度。当前处置是照常输出但建议前端加注；根治办法是扩大领域切片的载体池（放宽主领域判定为「任一 IPC4 命中」而非「主领域」），或把领域宇宙改为「按 IPC 部（A/B/C…）分组」以增大组内样本。

### 4.4 地区宇宙的命名与对齐缺陷

地区切片中出现 `null` 名称（BRISTOL 组内第一）、英文城市名与中文城市名混排（LONDON 与 深圳 同表）、以及明显非创新主体的机构名（`LITTLE SCALLYWAGS DAY NURSERY LIMITED` 为幼儿园类机构）。这些缺陷说明境外载体的行业过滤尚未生效，名称对齐也缺少人工复核环节。当前处置是在地区宇宙中把境外城市单列并标注「信号未打通」；根治办法是补行业分类过滤与名称对齐的人工校验队列。

## 五、王惠方法对照与选用建议

### 5.1 王惠口径要点

王惠 V1.5 对本件的定义是：以创新能力指数为唯一排序键，做 `RANK(index_score)`；设总体、地区（城市）、领域（IPC4）三个宇宙，各宇宙内独立排名；同分同名次且名次跳号；指数分与入集口径在三个宇宙间共享，不因分组而重算。该口径的核心主张是「一次算分、多次排名」，即排名只做序关系变换，不引入新信息。

### 5.2 三种备选口径的对照

| 口径 | 名次定义 | 同分处理 | 跨组可比性 | 与本件差异 |
| --- | --- | --- | --- | --- |
| 王惠 V1.5（本件采用） | 组内竞赛排名 | 同名次跳号 | 组内可比、跨组不可比 | 基准 |
| 密集名次（dense rank） | 组内密集排名 | 同名次不跳号 | 同上，但尾部被压缩 | 零分带会从「并列 919」变成「并列 3」 |
| 组内重归一后再排名 | 组内极值归一 | 同名次跳号 | 组内可比性增强、跨组更不可比 | 惠州第一会变成 100 分，误导性强 |
| 只展示指数不排名 | 无 | — | 完全可比 | 不满足原文「排名展示」要求 |

### 5.3 实测对照结论

在总体宇宙上，王惠口径与密集名次的头部完全一致（前 918 名逐位相同），差异全部集中在零分带：王惠口径下 2,082 家并列第 919 名，密集名次下并列第 919 名但后续名次不再跳号，末位显示为第 919 名而非第 3,000 名。两种都能自洽，但密集名次会让用户误以为「榜单只有 919 家」，与 `total_in_group = 3,000` 冲突，故不采用。

在地区宇宙上，若改用「组内重归一后再排名」，惠州第一名会从 29.51 分变成 100.0 分，与深圳第一名同分。实测惠州与深圳的组内分数分布差异显著（深圳 1,122 家中 918 家为正分，惠州 57 家中正分不足 10 家），重归一会彻底抹平这一差异，故明确排除。

在领域宇宙上，王惠口径的结论是「算得出但样本不足」，`A61M16` 仅 2 家时名次只有 1 与 2 两种取值；这不是口径问题，而是分组粒度问题，应通过设最小样本门槛解决，而非改排名算法。

### 5.4 选用建议

**建议采纳王惠 V1.5 作为基线口径**，理由有三：其一，「一次算分、多次排名」保证了三个宇宙的分数可比，页签切换不会变成口径切换；其二，竞赛排名（跳号）与 `pct_position` 的语义严格一致，「第 r 名 / 共 n 家」可直接换算为「前 r/n」，无需额外解释；其三，同分同名次如实暴露了零分带的存在，而不是用密集名次把它包装成「尾部仍有区分」。

在此基线之上建议做三点增强：一是**并行输出 dense rank 字段**供前端折叠展示使用，但 `rank` 主字段仍用竞赛排名；二是**设最小样本门槛**（建议 `n ≥ 30`），低于门槛的领域与地区切片标注「样本过少」或隐藏；三是**分离境内外分区**，境外城市因资源维与行业过滤未打通，暂不与境内城市同表排序。不建议改用「组内重归一」，因为它会把「底册薄」伪装成「头部强」，与本项目「先实测后定档」的纪律直接冲突。

## 附录 C 多维度排名展示类似指标权威构建方法可行性报告（完整版）

### C.1 报告目的与边界

本附录回答三个问题：权威机构与文献对「分组排名 / 多榜单展示」有哪些规范做法；本项目能否在现有数据上落地；综合方法与数据后应给何种支持度判定。范围限定为创新载体的**相对名次**展示，不另定义指数（指数见 `M_INNOV_DS_04_CARRIER_RANK_001`），也不涉及城际排名（见 `M_INNOV_CITY_*`）。

### C.2 需求语义锚定

需求只写「支持按不同维度对创新载体进行排名展示」，未定义维度集合、并列规则与最小样本量。结合同节「按载体类型、创新领域、创新价值等条件筛选」，可推定维度至少含地区（城市隐含于展示）、领域（创新领域）与类型（载体类型）。本件落地地区与领域两维；类型维因仅在 `enterprise_innovation_carrier` 中有字段且其分布呈等分造数特征，暂不启用。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：分组内排名与并列规则

商务部《国家级经济技术开发区综合发展水平考核评价办法（2021年版）》按分类分组、组内排序并公布名次，是国内「分组考核 + 组内排名」最直接的官方实践 (商务部, 2021)；工信部中小企业发展促进中心的《中小企业发展环境评估报告》同样采用分城市分组、组内排名的做法，并明确披露样本与口径 (工业和信息化部、中国中小企业发展促进中心, 2026)。工程实现上对应 SQL 标准三种并列语义（`ROW_NUMBER` / `RANK` / `DENSE_RANK`）。构架要点是先定比较池、再定并列规则；名次必须与池子绑定。可迁移性**高**：本件的三宇宙 + 竞赛排名 + 百分位即该族落地。

#### C.3.2 方法族 B：排名聚合的适用边界

Dwork 等系统讨论 Web 排名聚合，指出 Kemeny 最优聚合为 NP-hard，实践中用 Borda 或似然比近似，并警告聚合结果对噪声与策略性操纵敏感 (Dwork et al., 2001)。构架要点是多榜单合成会放大噪声，除非有强理由应保留分榜单。可迁移性**中高（作为「不合成」的反向依据）**：本件据此拒绝输出「综合名次」，只给分宇宙名次。

#### C.3.3 方法族 C：秩相关与榜单一致性

Kendall 的秩相关系数用于度量两套排序的一致性 (Kendall, 1938)。构架要点是一致性高说明切片是「同榜不同池」，一致性低说明切片改变了评价实质。可迁移性**高**：本件以头部重叠（总体 Top5 与深圳切片 5/5）与百分位分布做一致性校验。

#### C.3.4 方法族 D：评价披露与标准化

《专利导航指南 第1部分：总则》（GB/T 39551.1-2020）要求分析结论注明数据来源、范围与局限 (全国知识管理标准化技术委员会, 2020)；商务部考核办法亦要求公布评价口径与分组依据 (商务部, 2021)。构架要点是排名必须配套样本量、并列情况与数据局限说明。可迁移性**高（合规层）**：本件的三层披露（并列家数、零分带、样本不足）即其落地。

### C.4 数据可行性详细分析

| 依赖 | 候选表 | 规模 | 状态 | 判定 |
|---|---|---:|---|---|
| 指数输入 | RANK_001 派生 | 3,000 | 918 为正、2,082 为零 | 可用但零膨胀 |
| 地区分组（国内） | `dwd_org_base_info.city/province` | 189,116 | 12 个切片 | 可用 |
| 地区分组（海外） | `dwd_forg_base_info.country/city` | 20,000 | LONDON 192 家头部 0.00 | **不可用** |
| 领域分组 | `dwd_patent.main_classification_ipcr` | 2,939,895 | 4 个演示切片 2–30 家 | 部分 |
| 现成结果面 | `demo.enterprise_ranking` | 1,134,500 | `model_version=demo_rank_v0.1`，`rank_no` 组内连续无并列 | **禁用（造数）** |

现成结果面之所以禁用，是因为其 `rank_no` 在每个 `rank_dim` 组内严格 1..N 连排、无并列无跳号，而 `overall` 维仅有 4,045 个不同分值——名次连续性与分值分辨率互相矛盾，只能是合成造数；真实零膨胀分布下，2,082 家同分必然并列。

### C.5 推荐构建方案（工程可执行）

1. **指数输入**：取 RANK_001 的 `index_score` 与该批有效维数。
2. **宇宙切分**：总体（默认）、地区（city/country）、领域（IPC4）。
3. **排名**：`RANK()` 竞赛名次（同分跳号）+ 百分位，零分带单列。
4. **门槛**：$n_U<30$ 不出榜，只显示样本数；海外未对齐前不出榜。
5. **披露**：并列家数、零分带规模、样本量、有效维数四项随榜单输出。

增强方案：海外表与主表建立关联后恢复全球宇宙；载体类型维在分布修正后启用；引入月度快照支持「名次变化趋势」。放弃方案：直接读 `enterprise_ranking`（造数）；输出跨宇宙「综合名次」（聚合放大噪声，且违背「按不同维度看名次」的需求语义）。

### C.6 风险与残余不确定性

| 风险 | 影响 | 缓解 |
|---|---|---|
| 零分带 69.4% 并列 | 名次区分力只覆盖前 918 家 | 单列 + 并列家数披露 |
| 海外切片全零 | 0 分载体被评为「全球第一」 | 暂停出榜，标「数据接入中」 |
| 领域样本 2–30 家 | 名次由噪声决定 | 最小样本量 30 门槛 |
| 指数资源维 100% 空 | 名次内核被削弱 | 标注有效维数 |
| 造数排名表误用 | 结果失真且不可追溯 | 禁用 + 血缘标记 |
| 名次被过度解读 | 对中小载体不公 | 页面提示「排名仅反映成果记录」 |

### C.7 可行性总判（完整版结论）

| 维度 | 结论 |
|---|---|
| 方法可行性 | **高**。分组排名是标准能力，聚合与否有文献依据。 |
| 结构可行性 | **高**。地区、领域切分字段齐备。 |
| 当前数据量 | **部分**。零分带 69.4%、海外未对齐、领域样本少。 |
| 现在能否经转换得到 | **是（总体 + 深圳地区宇宙）**。 |
| 是否「完全不可能」 | **否**。 |
| 建议数据支持度标签 | **部分支持**（海外对齐 + 指数补维后可升「完全转换支持」）。 |

**一句话**：名次算得出、切得动、可解释，但零分带与海外全零使榜单只有头部有效——按 §〇 落 **部分支持**。

```python
# code/M_INNOV_DS_04_CARRIER_RANK_002.py（骨架，实际脚本已执行并产出 _out.json）
import json

RANK = json.load(open("code/M_INNOV_CARRIER_RANK_GLOBAL_out.json", encoding="utf-8"))

def pct(rank, n):
    return round(rank / n * 100, 3)

def build_view(rc, n_ranked):
    top10 = [dict(name=t["name"], src=t["src"], score=t["score"], rank=t["rank"],
                  pct_position=pct(t["rank"], n_ranked))
             for t in rc["top10_global"]]
    regions = rc.get("region_rank") or []
    fields = rc.get("field_rank_demo") or []
    positive = IDX["stats"]["positive"]
    return {
        "n_carriers": IDX["n_carriers"],
        "n_ranked": n_ranked,
        "positive_index": positive,
        "zero_band": IDX["n_carriers"] - positive,
        "universes": {"global_n": n_ranked, "region_slices": len(regions),
                      "field_slices": len(fields)},
        "top10_with_pct_position": top10,
    }

# 断言：名次与指数必须来自同一批入集
assert IDX["n_carriers"] == RANK["n_carriers"], "入集数不一致"
```
