## 摘要

「专家学者影响力」要回答的是「这位学者在本平台学者池里有多强」，而不是「这位学者在全国有多强」。需求清单序号 11 只写「支持要素影响力分析，通过算法模型评估各要素的重要性和影响力」，没有给公式；王惠 calc-logic 把它落成三维加权平均：H 指数、被引数量、论文数量，院士标签仅展示、不进分。本文严格按这三列取值，不重算 h 指数，也不引入任何外部学者库。

实测数据面很干净：`gkx.dwd_scholar` 21,316 行、21,316 个互异 `scholar_id`，`h_index` 100% 非空（中位 18、最大 286、均值 21.00），`citation_nums` 中位 1,047.5、最大 328,858，`paper_nums` 中位 51、最大 3,379。三列量纲相差三个数量级，因此本版把每列先做 `log1p` 再在池内 min-max 到 0—100，等权平均；把同一公式换成池内百分位重跑，Spearman 相关 0.998、Top 50 重合 45 人，排序对归一方式不敏感。

结果分布为：中位 51.66、P90 64.90、P99 78.95、最高 98.74（南开大学陈军，h=286、被引 328,858、发文 2,487）。按 80/60/40/20 切五档，T1 领军 168 人（0.79%）、T2 骨干 4,285 人（20.10%）、T3 中坚 12,902 人（60.53%）、T4 成长 3,137 人（14.72%）、T5 起步 824 人（3.87%）。院士名单 112 人中有 80 人能在学者主表找到，这 80 人的中位分为 77.83，位于全池第 98.8 百分位，说明院士标签与三维分方向一致，可作外部效度旁证。

本文同时披露两类不能静默处理的问题：一是 719 行 `h_index > paper_nums`（3.37%），违反 Hirsch 定义，只能打标不能修正；二是 21,316 人是**库内学者池**，不等于全国学者总体，跨库比较必须先统一学者 ID。这两点不改变「现在就能算」的判断，但会改变分数的解释边界，故在 §三、§四逐条写明。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技发展态势 → 科技全域态势 → 要素影响力分析**，并与「指数可视化展示 → 专家 H 指数排行可视化」共用同一批学者数据。

需求对全域态势的定位是「从论文、期刊、专利、专家学者、会议、组织机构、课题、项目多个主体切入进行全景把握、态势智能感知」。在这个列表里，专家学者是**主体**而不是附属属性：页面既要能按学者看他的 h、被引、发文，也要能在要素影响力卡片里给出一个可横向比较的综合刻度。前者是档案，后者是指标。

「专家学者影响力」承担的正是后者。它在页面上的任务包括：

| 页面任务 | 对指标的要求 |
|---|---|
| 要素影响力卡片 | 单一 0—100 分值，可跨学者排序 |
| 专家 H 指数排行 | 分值与 h 值同向，且能解释「为什么他的分高」 |
| 机构/学科聚合视图 | 分值可按机构名聚合，机构均值稳定 |
| 院士标记 | 只做展示徽标，不能反向影响分值 |

第三点决定本文必须输出机构维聚合（2,108 个机构名、292 个 ≥10 人的机构），否则页面只能做单人卡片，做不了机构对比。第四点决定院士标签只作为 `academician` 布尔字段输出，不进入任何权重。

### 1.2 为什么需要「专家学者影响力」这个指标

只有 h 指数，会把「高被引但发文少」和「高产但影响一般」混在一起。以本文实测为例：池内 h 中位数 18，但被引中位数 1,047.5、发文中位数 51，三者的尾部形态完全不同——h 的 P99 是 92，被引的 P99 是 36,488.9，发文的 P99 是 524。如果页面只按 h 排序，一位 h=60、被引 2 万、发文 200 的学者，会和一位 h=60、被引 8 千、发文 600 的学者并列，但两者的影响力结构完全不同。

只有被引，会奖励综述型、方法型的高被引单篇，忽略持续产出。只有发文量，会奖励灌水。三维合成的意义不是「更科学」，而是**让三种不同的强都可见**：h 高说明持续高质量产出，被引高说明工作被用得多，发文多说明产能稳定。三者等权是一种口径缺省，不是数据结论，因此本文把权重写进 `_out.json` 的 `method.weights`，并在 §五给出替换权重的接口。

此外，需求原文把「要素影响力」列为全域态势的必备分析能力，学者是要素之一。缺了它，要素影响力卡片只剩机构、专利、论文，学者这一主体无法进入同一张对比表。

### 1.3 需求文档是否给出定义方法

**需求文档没给出公式，只给了分析目标与展示要求。**

需求清单序号 11 的原文是「支持要素影响力分析，通过算法模型评估各要素的重要性和影响力」；「专家 H 指数排行可视化」一节则要求「以柱状图、雷达图等形式展示专家 H 指数排行情况，用户可按学科领域、机构类型、地域范围等条件筛选查看」。这两处都没有给出：

- 三维各自的权重；
- 被引数量取总量还是近五年；
- 论文数量是否去重、是否含会议；
- h 指数由谁计算、按什么语料计算；
- 分值的归一方式与分档阈值；
- 学科/机构/地域筛选维如何落到字段。

王惠 calc-logic 补出了三维与「加权平均」，但**同样没有给权重**，并明确「院士标签仅展示，不进分」。本文的等权、`log1p` 归一、五档切分都是在这处未闭合上做的工程决策，必须在文中标注为报告假设，不能伪装成需求原文。

### 1.6 推测原意与推测定义

**推测原意**：产品要的不是「学术评价」，而是「在一个统一 0—100 刻度下，把学者放进要素影响力卡片里，与其他要素横向比较」。因此它更接近「相对位置分」而不是「绝对学术水平分」。

**推测定义（本文采用）**：

> 对学者 $s$，记 $h_s$ = `h_index`、$c_s$ = `citation_nums`、$p_s$ = `paper_nums`；三列各自做 $\log(1+x)$ 后在 21,316 人池内 min-max 到 0—100，得 $\tilde h_s, \tilde c_s, \tilde p_s$；则
> $$
> \text{score}_s = \frac{1}{3}\tilde h_s + \frac{1}{3}\tilde c_s + \frac{1}{3}\tilde p_s \in [0,100]
>
$$
> 院士标签 $a_s$ 只作为展示字段输出，不进入上式。

**为什么用 `log1p` 而不是直接 min-max**：三列都是重尾分布（被引 P99 是 36,488.9，最大值 328,858，是 P99 的 9 倍）。直接 min-max 会把 99% 的人压到 0—10 分，只剩头部几个人有区分度；`log1p` 压缩尾部后，中段才展开。本文把百分位版本作为敏感性对照，两者 Spearman 0.998，说明排序结论不依赖这个选择。

**为什么等权**：calc-logic 写「加权平均」但没给权重。等权是最小假设；任何非等权都需要甲方签字，本文不替甲方做价值判断。`_out.json` 的 `method.weights` 已把三个 1/3 写死，替换权重只需改一处。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是王惠 calc-logic 的三维加权平均，本文没有改动维度，只补了三件原文未写的事：归一方式、权重缺省、分档阈值。之所以必须补，是因为三维原始值不可直接相加：h 的量级是 10，被引的量级是 10³—10⁵，发文的量级是 10²。直接相加等于把权重几乎全部给了被引，而这不是 calc-logic 的本意（它写的是「加权平均」，三维并列）。

本文没有做的降级：没有把 h 换成「近五年 h」、没有把被引换成「近五年被引」、没有剔除综述、没有按学科标准化。原因是库内没有年度引用明细，也没有学科码表；任何这类处理都会引入无法复核的假设。本文选择「只做量纲统一，不动语义」。

### 2.2 口径拆解：对象、集合、归一

**对象**：学者实体（`scholar_id`）。21,316 行、21,316 个互异 ID，无重复。`status=1` 的 21,308 人、`status=2` 的 8 人，本文全部保留（口径未要求剔除离职/退休），并在 `_out.json` 的 `coverage` 里给出状态分布。

**集合**：全库学者池，不做机构/学科/地域预筛。理由是筛选会改变分母，从而改变百分位；页面若需要「某机构内排名」，应在结果层对同一分值重新排序，而不是重算分值。

**归一**：对每列 $x$，先 $\log(1+x)$，再 $100 \cdot \frac{\log(1+x)-\min}{\max-\min}$。三列各自归一，互不影响。归一后的分数是「相对位置」，不是「绝对水平」；这也是为什么全池中位数落在 51.66 而不是某个绝对分数线。

**分档**：80/60/40/20 四刀切五档（T1—T5）。切点是展示约定，不是统计分位；因此各档人数不等（T1 仅 168 人），这是重尾分布的正常形态，不应为了「每档 20%」而改成强制分位。

### 2.3 依赖分解（两跳停）

| 跳 | 依赖 | 承载 | 状态 |
|---|---|---|---|
| 1 | 学者主档：ID、姓名、机构名、h、被引、发文 | `gkx.dwd_scholar` | 21,316 行，三列 100% 非空 |
| 1 | 院士标签 | `gkx.dwd_scholar_talent_flag` | 20,030 行，112 人为院士 |
| 2 | 学者 → 论文明细（用于复算 h/被引） | `dwd_scholar_paper_relation` 1,065,385 行 / `dwd_scholar_papers` 738,106 行 | **本批不使用**：口径明示 h 为外采只读，禁止重算 |
| 2 | 学者 → 学科 | `dwd_scholar_research_direction` 20,030 行 | 关键词串，非学科码表；本批只作展示 |

「两跳停」的意思是：本指标只走到第 1 跳，不再往论文明细走。原因是口径禁止重算 h；一旦用库内 10 万篇中文论文复算，得到的 h 会系统性低于供应方基于更大语料的值，两套量纲混排会直接毁掉排行。

### 2.4 算路 / SQL

全流程 2 条 SQL，均落在 ≤2.2 万行的小表：

```sql
-- Q1 学者主档（21,316 行，窄列，9.89 秒）
SELECT scholar_id, name_zh, scholar_org_name_zh, paper_nums, citation_nums,
       h_index, status, is_deleted, reference_nums
FROM gkx.dwd_scholar;

-- Q2 院士名单（112 行，仅展示）
SELECT scholar_id FROM gkx.dwd_scholar_talent_flag WHERE academician = 1;
```

Q1 的 21,316 行一次性拉到本地后，所有统计在内存完成：三列各自 `log1p` → min-max → 等权 → 排序 → 分档 → 机构聚合。**没有对 `dwd_scholar` 做任何 GROUP BY 大列**，也没有 join 论文表。

为什么 `reference_nums` 也取回来：为了验证它是不是可用列。实测 21,316 行 `notnull=0`，即整列为空，故本文不使用；把它写进 §1.3 与 §四，避免后续误用。

### 2.5 清洗规则

| 规则 | 处理 | 影响行数 |
|---|---|---|
| `scholar_id` 重复 | 不去重（实测 0 重复） | 0 |
| `is_deleted=1` | 不剔除（实测 0 行） | 0 |
| `status=2` | 保留 | 8 |
| `paper_nums=0` | 保留，`log1p(0)=0` 得该维最低分 | 15 |
| `citation_nums=0` | 保留，同上 | 402 |
| `h_index > paper_nums` | **保留原值并打标**，不修正 | 719 |
| 机构名为空 | 保留在总分里，机构聚合时跳过 | 487 |
| 院士 ID 不在主表 | 只影响展示，不影响分值 | 32 |

清洗原则是「能打标就不删行」。删行会改变分母，从而改变所有人的百分位；对一个相对位置分来说，这是不可接受的副作用。

### 2.6 结果解读

主结果：21,316 人，中位 51.66，P90 64.90，P99 78.95，最高 98.74。直方图（10 分一档）为 0—10: 294、10—20: 530、20—30: 998、30—40: 2,139、40—50: 5,456、50—60: 7,446、60—70: 3,485、70—80: 800、80—90: 157、90—100: 11。分布右偏但主体在 40—70，符合「多数人接近中位、少数人拉开」的预期。

Top 3 是南开大学陈军（100.00，h=286、被引 328,858、发文 2,487）、香港中文大学（深圳）唐本忠（99.99，h=219、被引 257,865、发文 2,411）、中国科学院江雷（99.98，h=237、被引 263,507、发文 1,438）。三人的强项结构不同：陈军三项都极高，江雷 h 更高但发文少，唐本忠被引高而 h 略低——这正是三维合成想保留的信息。

机构维：2,108 个机构名，292 个机构有 ≥10 人。均值最高的是西湖大学（15 人，62.93）、中国科学院长春应用化学研究所（16 人，62.66）、中国科学院化学研究所（17 人，62.36）。注意这是「机构内学者分值的均值」，不是机构影响力；小学校如果只引进了少量高被引学者，均值会很高，样本量必须一起看。

类型维：高校 19,877 人（93.2%，均值 50.61）、院所 312 人（48.75）、医院 242 人（45.31）、企业 81 人（42.64）、其他 804 人（36.83）。企业学者只有 81 人，说明这个学者池基本是学术机构池，用它评价产业界专家会严重欠采样。

#### 2.7.3 结果解读与评审

排序稳健性：主口径（`log1p` + min-max）与敏感性口径（池内百分位）的 Spearman 是 0.998，Top 50 重合 45 人。差异集中在被引 1 万—3 万这一段：百分位口径对这一段不敏感，min-max 口径会因为 `log1p` 压缩而把差距拉平。两种口径给出的「谁在前 50」几乎一致，说明结论不依赖归一方式。

院士效度：112 名院士中 80 人能在主表找到，这 80 人的中位分 77.83，位于全池第 98.8 百分位。这是外部效度的正面证据；同时 32 人找不到，说明两份表不是同一批学者（`dwd_scholar_talent_flag` 20,030 行 < `dwd_scholar` 21,316 行），院士标记只能「有则显示」，不能反推「没有就不是院士」。

完整性风险：719 行 `h_index > paper_nums`，占 3.37%。按 Hirsch 定义，h 不可能大于发文量；这说明供应方的 h 与 paper_nums 不是同一语料算出来的。本文保留原值（改任何一边都会破坏与供应方的一致性），但在 `integrity` 字段打标，页面可用小徽标提示「字段待供应方校准」。

## 四、数据缺失情况

### 4.1 缺失清单

| 缺失项 | 现状 | 影响 | 修复建议 |
|---|---|---|---|
| `reference_nums` | 21,316 行全 0 | 无法用「参考文献量」做第四维 | 供应方回填，或确认该列废弃 |
| `scholar_org_id` | 21,316 行全空 | 机构只能按名称字符串聚合，缩写/更名会分裂 | 补机构 ID 或建名称规范化表 |

| 地域 | 需机构名 → 底册匹配，4.97% | 无法做地域筛选 | 补机构 ID 后由底册带出城市 |

| 院士名单覆盖 | 112 人中 32 人不在学者主表 | 院士徽标漏显 | 统一两表学者 ID |
| 年度引用明细 | 库内无 | 无法做「近五年被引」或趋势 | 补 `dwd_scholar_citation_by_year` 类表 |

### 4.2 对结论的影响边界

上述缺失**不改变分值本体**：三维三列都是 100% 非空，分值现在就能算。它们改变的是**解释边界**：分值不能跨库比较（学者池不同）、不能按学科解释（无码表）、不能按地域切片（匹配率 4.97%）、不能把院士徽标的缺失当成「不是院士」。

### 4.3 不可外推的三件事

第一，不能把本文分值当成「全国学者影响力排名」。学者池 21,316 人，机构名以中国科学院、上海交大、北大、清华等为主，明显偏向高被引学术机构；企业学者只有 81 人。第二，不能把机构均值当成机构排名，小学校少量高被引学者会把均值拉高（西湖大学 15 人 62.93 是典型）。第三，不能把 `h_index` 与 `paper_nums` 的矛盾行用于个体争议场景，这 719 行需要供应方先解释。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

王惠 calc-logic 的原文结构是：

| 二级 | 三级 | 口径 | 计算逻辑 | 源字段 |
|---|---|---|---|---|
| H 指数 | — | 学者 H 指数 | 学者 H 指数 | `dwd_scholar(scholar_id, h_index)` |
| 被引数量 | — | 学者论文总被引 | 学者论文总被引 | `dwd_scholar(scholar_id, citation_nums)` |
| 论文数量 | — | 学者发文量 | 学者已发表论文数 | `dwd_scholar(scholar_id, paper_nums)` |

并写明「采用加权平均」「院士标签仅展示，不进分」「禁止用 M_CHAIN_ACADEMIC_POWER 顶替」。

### 5.2 新方法概述

新方法保留三维与「不进院士标签」，补三件事：每列 `log1p` 后池内 min-max、等权、80/60/40/20 五档。输出除分值外，还有机构聚合、类型聚合、院士效度、完整性打标、敏感性对照。

### 5.3 逐维对照表

| 维度 | 王惠原法 | 本文实现 | 差异与理由 |
|---|---|---|---|
| H 指数 | 直接取 `h_index` | 同，只做 `log1p` 归一 | 不重算（口径禁令） |
| 被引数量 | 直接取 `citation_nums` | 同，只做 `log1p` 归一 | 不拆年度（库内无年度明细） |
| 论文数量 | 直接取 `paper_nums` | 同，只做 `log1p` 归一 | 不去重（无 DOI 级明细） |
| 权重 | 「加权平均」，未给值 | 等权 1/3 | 口径缺省，已在 `method.weights` 写明 |
| 院士标签 | 仅展示 | `academician` 布尔输出 | 一致 |
| 分档 | 未给 | 80/60/40/20 五档 | 展示约定，非统计分位 |
| 学科/地域筛选 | 未在本指标要求 | 不做 | 属 HINDEX 子功能，非本 ID 公式 |

### 5.4 选用建议与理由

**建议采纳本文实现，作为本指标的当前交付版。** 理由有三：其一，三维字段 100% 非空，现在就能出分，满足「完全转换支持」的档位定义；其二，归一与权重都写在 `_out.json` 里，甲方若要改权重（例如 0.5/0.3/0.2），只需改 `W` 一处并重跑 0.8 秒；其三，敏感性对照（Spearman 0.998）证明排序不依赖归一技巧，结论可复核。

**不建议**在没有学科码表的情况下对外发布「分学科影响力榜」，也不建议把机构均值直接当机构排名。前者会误导，后者样本量太小。

## 附录 C　专家学者影响力类似指标权威构建方法可行性报告（完整版）

### C.1 报告目的与范围

本附录要回答一个问题：在王惠 calc-logic 已给出三维的前提下，库内数据能否支撑「方法族 A（文献计量三件套）」的完整落地，以及若换用方法族 B/C 会缺什么。范围限定在学者实体，不扩展到机构排名或学科排名。

### C.2 需求语义锚定

需求用的词是「影响力」，不是「学术水平」也不是「 productivity」。在文献计量语境里，「影响力」通常由引用侧指标承载（citation count、h-index、FWCI），而「产出」由发文量承载。王惠把两者并列，等于把「被用得多」与「写得多」都算进影响力，这是一种产品口径而不是学术口径。本文沿用，不纠正。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：文献计量三件套

Hirsch (2005) 定义 h 为「有 h 篇论文各被引至少 h 次」的最大 h。它的优点是对极端高被引不敏感、对持续产出敏感；缺点是不可跨学科比较、对青年学者不友好。Scopus/SciVal、Web of Science、OpenAlex 都提供学者级 h 与 citation count，且都明确「基于自有语料」。这与本项目的「外采只读」定位一致。

#### C.3.2 方法族 B：标准化复合引用指标

Ioannidis 团队的 standardized citation metrics 对被引、h、合著、自引做领域内标准化后合成，解决跨学科不可比问题。它需要学科分类与合著网络，本项目库内只有 `fields` 关键词串（8.69% 可挂）与 `dwd_scholar_coauthor` 1,187,606 行。合著网络有，学科码表没有，故 B 只能做一半。

#### C.3.3 方法族 C：Altmetric 社会影响力

Altmetric Attention Score 统计新闻、政策文件、社交媒体提及。本项目库内无对应表，方法族 C 不可行。

#### C.3.4 方法族 D：机构/学科聚合排行

软科、QS 以机构为单位聚合学者指标并做学科归一。本项目可做机构聚合（2,108 个名称、292 个 ≥10 人），但无学科归一，故只能做「机构均值」而不能做「学科排行」。

### C.4 数据可行性详细分析

#### C.4.1 学者本体

21,316 行、21,316 个 ID，三列 100% 非空。这是最强的一块：不需要任何插补，也没有缺失维。

#### C.4.2 引用侧

`citation_nums` 是学者级总被引，不是年度序列。它能支撑「总量」，不能支撑「近五年」或「趋势」。若甲方要趋势，需补年度引用表。

#### C.4.3 产出侧

`paper_nums` 是学者级总发文，不去重、不分类型。它与 `dwd_scholar_paper_relation`（1,065,385 行）可以对账，但本批没有做逐篇复算，原因是口径禁止重算 h，而复算发文量会引出「哪一边为准」的新问题。

#### C.4.4 方法—数据对照矩阵

| 方法 | 需要的输入 | 库内状态 | 可行性 |
|---|---|---|---|
| A 三件套 | h、被引、发文 | 三列全有 | **可行** |
| B 标准化复合 | 学科码、合著、被引 | 缺学科码 | 部分可行 |
| C Altmetric | 新闻/社媒 | 无 | 不可行 |
| D 机构排行 | 机构 ID、学科码 | 缺机构 ID、学科码 | 部分可行 |

### C.5 推荐构建方案（工程可执行）

1. 以 `dwd_scholar` 为唯一事实表，三列只读；
2. 每列 `log1p` 后池内 min-max，等权合成；
3. 分值落 `_out.json`，同时输出机构/类型/院士三个切片；
4. 完整性打标（719 行）与院士未命中（32 人）单独字段输出，不混入分值。

### C.6 风险与残余不确定性

- 学者池不是全国总体，跨库比较无效；
- h 与发文的语料不一致（719 行冲突），个体争议场景不可用；
- 等权是缺省，不是甲方签字权重；
- 机构名未规范化，缩写/更名会分裂聚合。

### C.7 可行性总判（完整版结论）

方法族 A 在本库**结构与数据都足够**，现在就能出分，判「完全转换支持」。B/C/D 的缺口属于「扩展能力」而不是「本指标必需」，不影响本 ID 的档位。
