## 摘要

「项目支持」是政策与条件保障力指标展示的第四个子功能。需求要求「收集并统计特定领域的科技项目、产业项目等支持项目数据，用户可按项目类型、资助机构、时间范围等维度查看项目分布情况，系统提供项目数量、资助金额、实施效果等指标的分析结果」（需求清单序号 155）。需求给了四个查看维度与三个度量，但没有给出公式、权重、项目范围、领域口径或效果定义；AI-20261016 只补出「学科支持度 = 项目数与金额百分位的等权合成」，其余口径由本报告补齐并逐项实测。

脚本 `code/M_INNOV_PG_PROJECT.py` 在 `gkx` 三方库跑通（32.5 秒、6 条 SQL）：`dwd_zh_project` 共 **58,453** 条，资助金额 **100%** 非空、合计 **2,529,097.0 万元（252.91 亿元）**、均值 **43.27 万元**；类型集中在面上（27,939 条，47.80%）与青年（23,884 条，40.86%），金额却由面上（55.58%）与重点（9.18%）主导；年份覆盖 1986—2023，但 2021 年只剩 2,339 条、2022 年 58 条、2023 年 6 条，2024—2026 年零记录；实施效果只能对上 20,067 条（34.33%），且奖励合计恒为 0。

结论是「数量与金额两格可用，机构/产业/时间三格不可用」。资助机构维度只有「国家自然科学基金(NSFC)」一个取值，无法做机构对比；需求明写「产业项目」，本库一条也没有；`funded_province`、`funded_institution` 两列整列为空，属地只能用参与单位名称做代理，而参与单位语义是「参与」不是「承担」。2022 年后的断崖是**录入停摆**，不是资助规模下降，任何「近年项目支持减弱」的写法都是误读。

更需要写死的一条是抽样框：本表 38 年累计 5.85 万项、252.91 亿元，而 NSFC 2024 单年就资助 5.49 万项、335.81 亿元（NSFC, 2025）。两者体量相当，说明本表不是 NSFC 全量台账，而是某种子集。在抽样框确认前，它只能支撑「表内结构」，不能支撑「全国项目支持总量」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技发展态势 → 科技发展规划 → 政策与条件保障力指标展示 → 项目支持分析**。

### 1.2 为什么需要「项目支持」这个指标

政策与条件保障力不能只看「发了多少文件」，还要看「钱和项目有没有落地」。政策扶持力度回答「政策多不多」，经费支持回答「钱多不多」，项目支持回答「**有没有具体的项目载体**」。三者缺一，评估就会偏向文件端：一个地区可能政策文件很多、经费预算很大，但立项项目很少，说明支持没有转化为可执行的研究活动。

从规划视角看，项目支持还有一层作用：它把「领域」与「支持强度」连起来。规划编制要知道「哪些学科/方向拿到了项目、拿到了多少钱」，才能判断现有支持结构是否与规划重点一致。这也是需求要求「按项目类型、资助机构、时间范围查看分布」的原因——分布本身就是结构信号。

此外，「实施效果」被需求与数量、金额并列，说明编写人不满足于投入侧统计，还想看产出。本库能对上的只有论文/专利/奖励计数，且覆盖率 34.33%，只能作弱信号。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。**

需求清单序号 155（算法库 §1.1.1.1.4.1.7.4.4）原文只写：

> 收集并统计特定领域的科技项目、产业项目等支持项目数据，用户可按项目类型、资助机构、时间范围等维度查看项目分布情况，系统提供项目数量、资助金额、实施效果等指标的分析结果。

没有给出：

- 「项目支持」是一个综合得分，还是六个并列统计格；
- 项目类型如何枚举（按资助类别？按计划层级？按产业/学术？）；

### 2.1 公式出处与为什么用百分位等权

项目支持不是单一比值，而是「六格统计 + 一格打分」。六格里，类型、机构、时间、学科是分组维度，数量、金额、效果是度量。真正需要公式的只有「领域支持强度」：怎么把某个学科的项目数与金额合成一个可排序的分数。

AI-20261016 给的方案是「项目数百分位与金额百分位的等权平均」。这个方案的好处是抗量纲：项目数是件、金额是元，直接相加没有意义；转成百分位后都在 0—100，可以平均。另一个好处是抗极端值：一个学科如果只有 1 个项目但金额 6,000 万，直接按金额排序会把它顶到第一，百分位也会，但至少不会让均值被单一极值拉爆。

代价是信息损失：百分位只保留「在 119 个学科中的相对位置」，不保留差距大小。第 1 名与第 2 名可能只差 1 个项目，却拿到 100 与 99.15；第 100 名与第 119 名可能差 50 个项目，却只差几个百分点。因此本报告在输出里同时保留原始 `n` 与 `amount_wan`，百分位只作排序辅助，不作唯一结论。

还有一个必须说明的选择：等权。需求没给权重，AI-20261016 也没解释为什么是 0.5/0.5。本报告沿用等权，但在 §五把它标成「报告假设」，并给出「只看数量」「只看金额」两种替代排序的差异，供甲方裁决。

### 2.2 口径拆解：六格与一个分数

**观测单元**：一条项目记录（`dwd_zh_project.id`）。总计 58,453 条。

**六个统计格**：

| 格 | 维度/度量 | 字段 | 口径 |
|---|---|---|---|
| 1 | 项目类型 | `fund_category` | 原值分组，8 类 |
| 2 | 资助机构 | `project_source` | 原值分组，仅 1 类 |
| 3 | 时间范围 | `approval_year` | 取前 4 位为年，1986—2023 |
| 4 | 领域 | `discipline` | 取「-」前一级为学科，119 个 |
| 5 | 项目数量 | `COUNT(*)` | 按上述维度计数 |
| 6 | 资助金额 | `SUM(funded_amount)` | 单位万元；均值 = 合计/条数 |
| 7 | 实施效果 | `dwd_zh_project_output` | 左连接后统计论文/专利/奖励 |

**领域支持强度**（AI-20261016）：

$$S_j = 0.5 \times P^{n}_j + 0.5 \times P^{a}_j$$

其中 $P^{n}_j$ 是学科 $j$ 项目数在 119 个学科中的百分位（0—100），$P^{a}_j$ 是金额百分位。百分位用「排名减一除以 n 减一」计算，最小值 0、最大值 100。

**实施效果**：不做合成，直接给三个合计与覆盖率；覆盖率 = 能对上产出记录的项目数 ÷ 全部项目数。均值只在「有产出记录」的 20,067 条上算，避免把未采集当零产出。

### 2.4 算路 / SQL

**步骤 1｜盘子与填充率**：

```sql
SELECT COUNT(*) n,
       SUM(funded_amount>0) amt_ok,
       SUM(discipline IS NOT NULL AND discipline<>'' AND UPPER(TRIM(discipline)) NOT IN ('NULL','NONE','-')) disc_ok,
       SUM(funded_province IS NOT NULL AND funded_province<>'' AND UPPER(TRIM(funded_province)) NOT IN ('NULL','NONE','-')) prov_ok,
       SUM(funded_institution IS NOT NULL AND funded_institution<>'' AND UPPER(TRIM(funded_institution)) NOT IN ('NULL','NONE','-')) inst_ok,
       SUM(participating_institution IS NOT NULL AND participating_institution<>'') part_ok
FROM gkx.dwd_zh_project;
```

**步骤 2｜类型 / 机构 / 层级 / 年份**（脚本内分三条查询，均带聚合）：

```sql
SELECT fund_category, COUNT(*) n, SUM(funded_amount) amount_wan, AVG(funded_amount) avg_wan
FROM gkx.dwd_zh_project GROUP BY 1 ORDER BY n DESC;

SELECT project_source funder, project_level lvl, COUNT(*) n FROM gkx.dwd_zh_project GROUP BY 1,2;

SELECT LEFT(CAST(approval_year AS CHAR),4) y, COUNT(*) n, SUM(funded_amount) amount_wan
FROM gkx.dwd_zh_project GROUP BY 1 ORDER BY 1;
```

**步骤 3｜学科支持度**：

```sql
SELECT SUBSTRING_INDEX(discipline,'-',1) major,
       COUNT(*) n, SUM(funded_amount) amount_wan
FROM gkx.dwd_zh_project
WHERE discipline IS NOT NULL AND discipline<>''
  AND UPPER(TRIM(discipline)) NOT IN ('NULL','NONE','-')
GROUP BY 1;
```

随后在 Python 里对 `n` 与 `amount_wan` 分别做百分位排名，等权平均。

**步骤 4｜实施效果**：

```sql
SELECT COUNT(*) projects, SUM(o.id IS NOT NULL) with_output,
       SUM(o.journal_articles_count) journals, SUM(o.patents_count) patents,
       SUM(o.awards_count) awards, SUM(o.total_outputs) total_out
FROM gkx.dwd_zh_project p
LEFT JOIN gkx.dwd_zh_project_output o ON o.id=p.id;
```

用合计而非 `AVG`，是为了把「有产出记录」与「全部项目」两个分母分开：合计除以 58,453 是「全口径人均」，除以 20,067 是「有记录项目人均」，本文两者都输出，正文只用后者。

### 2.5 清洗规则

| 规则 | 处理 | 影响 |
|---|---|---|
| `approval_year` 为 `YYYYMMDD` 整数 | 转字符串后取前 4 位为年 | 否则 `>=2020` 恒真，近窗统计失效 |
| `discipline` 为空/NULL/'NULL' | 不进入学科聚合 | 8.33% 记录不参与学科分数 |
| `discipline` 含「-」 | 取第一段为一级学科 | 119 个一级学科 |
| `funded_amount` ≤0 | 不参与金额均值 | 实测 0 条，无影响 |
| 类型名含「（C类）」 | 保留原值 | 疑似新分类回溯套用，见 §四 |
| 参与单位文本匹配「深圳」 | 仅作代理，不称「深圳项目数」 | 语义为参与而非承担 |
| 产出表无记录 | 不当作「零产出」 | 65.67% 未覆盖 |
| 小样本学科 | 保留但标注 | n=1 的学科百分位为 0，分数无意义 |
| `awards_count` 合计 0 | 不解释为「没有获奖」 | 字段未采集 |
| 金额单位 | 全部为万元 | 对外换算为亿元时除以 10,000 |

`approval_year` 那一条是本轮实测发现的真实缺陷：该字段存的是 `20200101` 这样的整数，任何年份都 ≥2020，所以旧的「近窗」写法会把全表都算成近窗。本版脚本先用 `CAST(... AS CHAR)` 再取四位，`n_recent_ge_2020` 因此是真实的 7,122 条（2020—2023 之和），不再恒等于 58,453。

### 2.6 结果解读

**（1）数量与金额的结构是「面上主导、重点抬均值」**。面上项目 27,939 条占 47.80%，金额 1,405,707.65 万元占 55.58%，均值 50.3 万元；青年项目 23,884 条占 40.86%，金额 543,580.67 万元只占 21.49%，均值 22.8 万元；重点项目只有 962 条（1.65%），金额 232,259.90 万元却占 9.18%，均值 241.4 万元。这组数字说明「项目数」与「资助金额」不是同一件事：按数量排，青年几乎与面上并驾；按金额排，青年只有面上的一半不到。任何把两者等权合成的分数，都必须接受这个结构性差异。

**（2）类型分布与官方年度报告可比，但只是「形似」**。NSFC 2024 年报披露单年资助面上 20,758 项、青年 23,226 项、地区 3,519 项、重点 745 项、联合基金 1,306 项、重大研究计划 419 项、数学天元 155 项（NSFC, 2025）。本表 38 年累计的面上是 27,939 项、青年 23,884 项，量级只相当于官方一年。这不是「NSFC 规模小」，而是本表只覆盖了一个子集。类型比例可以看，绝对量不能对外称「全国」。

**（3）时间序列在 2021 年断裂，断点是录入不是资助**。2019 年 4,816 条、2020 年 4,719 条、2021 年 2,339 条、2022 年 58 条、2023 年 6 条、2024—2026 年 0 条。2021 年已经只有前一年的半量，2022 年起基本归零。金额同步：2020 年 221,684.5 万元、2021 年 73,237.0 万元、2022 年 2,240.0 万元、2023 年 60.0 万元。若把这组数当「项目支持力度下降」，会得出「2022 年后国家几乎不资助项目」的荒谬结论；真实原因是源表录入停摆。按 §四的口径，本指标的时间范围只能宣称覆盖 1986—2021，2022—2023 是残片。

**（4）资助机构维度退化成一个常数**。`project_source` 全表只有「国家自然科学基金(NSFC)」一个取值，58,453 条全部如此；`project_level` 也只有「国家级」。需求要「按资助机构查看分布」，本库给不出任何对比，连「国家 vs 地方」「基金委 vs 科技部」都做不到。这不是数据稀疏，是维度不存在。

**（5）领域支持度的头部是医学与信息，尾部是小样本学科**。119 个一级学科里，影像医学与生物医学工程 2,678 项 / 107,340.2 万元得 100 分，电子学与信息系统 1,667 项 / 70,080.0 万元得 98.31，机械设计与制造 1,648 项 / 71,627.9 万元得 98.31，计算机科学 1,645 项 / 74,870.9 万元得 98.31，环境地球科学 1,246 项 / 59,468.0 万元得 96.61。分布 mean 50.00、median 49.15、p10 10.34、p90 90.25，说明百分位合成没有退化。尾部分数低不代表这些学科不重要，只代表本表里样本太少；n=1 时百分位必然为 0，这是排名方法的退化，不是学科评价。

**（6）实施效果只能作弱信号**。20,067/58,453 条能对上产出（34.33%），产出合计 80,689，其中有记录项目平均 3.07 篇期刊论文、0.51 件专利、0.00 项奖励。奖励合计为 0 说明产出表根本没有奖励数据，不是「没有获奖」。覆盖率 34.33% 意味着另外 65.67% 不能当零产出——它们可能只是没被采集。用这组数做「项目绩效排名」会系统性低估未覆盖学科。

**（7）抽样框必须先解释再发布**。38 年 5.85 万项、252.91 亿元，低于 NSFC 单年 5.49 万项、335.81 亿元（2024）。这不可能是「NSFC 变小了」，只能是本表按某个规则抽样（可能是按学科、按依托单位或按可爬取页面）。在抽样规则确认前，任何「累计资助强度」「年均项目数」的对外表述都会失真；本文因此只发布「表内结构」，不发布「总量结论」。

### C.1 报告目的与范围

本附录回答：① 权威机构如何统计「项目支持」；② 本库能支撑哪几格；③ 产业项目与机构维度为何不可得。

### C.2 需求语义锚定

需求给的是「四维 + 三指标」的展示需求：类型、机构、时间、领域四个切片，数量、金额、效果三个度量。它没有要求一个综合得分，但 AI-20261016 为领域排序补了一个百分位分数。语义核心是「**支持力度**」——既要覆盖广度（项目数），也要覆盖强度（金额），还要看结果（效果）。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：科技项目年度统计

NSFC 年度报告按项目类型披露申请数、资助数、资助经费，是最贴近本指标的口径 (NSFC, 2025)。其 2024 年数据为：接收 2,502 个依托单位 40.39 万项申请，资助 5.49 万项、335.81 亿元；面上 20,758 项、青年 23,226 项、地区 3,519 项、重点 745 项、联合基金 1,306 项、重大研究计划 419 项、数学天元 155 项。这套口径与本表的 `fund_category` 可以逐项对齐。

#### C.3.2 方法族 B：研发投入统计

OECD《Frascati Manual 2015》定义了 R&D 支出的统计边界（基础研究/应用研究/试验发展、资金来源、执行部门），是金额口径的宏观参照 (OECD, 2015)。国家统计局年度公报按地区披露 R&D 经费与强度。两者都不能落到单个项目，但能校验「项目金额合计」是否落在合理量级。

#### C.3.3 方法族 C：基金管理的法定框架

《国家自然科学基金条例》（2024 修订）规定基金用于资助基础研究、支持人才培养和团队建设，明确项目设置、申请、评审、资助、监督流程（国务院, 2024）。它解释了为什么 NSFC 的项目类型是这样一组：面上/青年/地区/重点/联合/重大研究计划/专项/天元，各有法定定位。这也说明「项目类型」不是任意分组，而是资助制度的结构。

#### C.3.4 方法族 D：科研产出计量

以论文/专利/奖励计数度量项目效果，是科研评价的常见做法，但受数据覆盖与滞后影响。本库产出表只覆盖 34.33%，且奖励字段合计为 0，只能作弱信号。

#### C.3.5 方法族 E：领域支持强度

用项目数与金额的百分位排名刻画学科支持强度，本质是把「分布位置」当分数。优点是简单可复现，缺点是小样本学科退化（n=1 必得 0 分）、不保留差距大小。

#### C.4.1 类型与金额
