## 摘要

本件是一个「六维反向百分位」模型：每一维先在对数化后取百分位秩，再用 $100\times(1-\text{秩})$ 转成痛难度，最后按可用维加权平均。分越高越痛。

| 读数 | 值 |
|---|---|
| 深圳机构 $P_0$ | 1,014 家 |
| 可识别 $P_1$（任一方有值） | 128 家（12.6233%） |
| 打分集 $P_2$（≥3 维有值） | 25 家（占 $P_1$ 19.5312%） |
| 不可识别 | 886 家（87.3767%） |
| 可识别但不打分 | 103 家（占 $P_1$ 80.4688%） |
| 分数区间 | 7.2917 — 71.9697 |
| 中位 / 均值 | 45.3301 / 42.8603 |
| p25 / p75 / p90 | 30.4592 / 55.8726 / 63.6353 |
| 高 / 中 / 低 | 2 / 4 / 19 |
| 高痛点占打分集 | 8.0% |
| 等权秩相关 | 0.9785 |
| 替代权秩相关 | 0.9808 |
| 逐维剔除最差秩相关 | 0.8246（剔项目维） |
| 判档 | 部分支持 |

第一个事实是**点集收缩得极快**。1,014 家机构，只有 128 家在一维以上有值，只有 25 家达到三维门槛。也就是说，模型真正能评价的只有 25 家，占深圳机构的 2.4655%。任何「深圳科研机构痛难点全景」的说法，都必须先声明这一点。

第二个事实是**分级极不均衡**。25 家里高痛点 2 家（8.0%）、中 4 家（16.0%）、低 19 家（76.0%）。这个分布是按 P90/P75 切出来的，天然就是「少数高、多数低」，不代表真实世界如此——它只是把打分集内部的名次外化成三档。

第三个事实是**权重不敏感、维度敏感**。等权与替代权的秩相关 0.9785 / 0.9808，说明换权重几乎不改排序；但逐维剔除时，剔项目维降到 0.8246、剔论文维降到 0.8454，说明「有没有项目维」比「项目维权重多少」重要得多。这是小样本模型的典型特征：结构比参数重要。

### 1.2 为什么要「打分」而不是只给读数

读数（项目 212 笔、论文 558 篇）是城市级的，回答不了「先培育谁」。要排序就必须把多维压成一维，而压的过程必然引入主观选择：哪些维、各占多少权重、多少维才够格打分。把这些选择显性化、可复现，就是模型的价值——不是给一个「客观分数」，而是给一个「口径完全公开、可以被推翻重算」的分数。

本件因此不做「绝对分」，只做「打分集内部的相对分」。分数 45.3301 没有绝对含义，只有「在这 25 家里处于中位」的含义。

### 1.3 口径定义

六维原始计数 $x_{i,k}$，$k\in\{\text{project},\text{transfer},\text{paper},\text{patent},\text{talent},\text{policy}\}$。对每维在 $P_2$ 的正值分布上取百分位秩 $q_{i,k}\in[0,1]$，痛难度：

$$s_{i,k}=100\times(1-q_{i,k})$$

合成分（按可用维重归一）：

$$S_i=\frac{\sum_{k\in A_i} w_k\, s_{i,k}}{\sum_{k\in A_i} w_k},\qquad A_i=\{k: x_{i,k}>0\}$$

权重 $w$：项目 0.25、转让 0.2、论文 0.2、专利 0.15、人才 0.1、政策 0.1。

三条补充约定：

第一，**打分门槛 3 维**。$|A_i|\ge 3$ 才进 $P_2$。少于 3 维时，任一维的百分位都会主导合成分，分数不可解释。1—2 维的 103 家记「可识别但不打分」，不补 0、不按均值插补。

第二，**百分位只在 $P_2$ 内取**。这意味着 $s_{i,k}$ 是「在 25 家里的相对位置」，不是「在全国机构里的位置」。换一个打分集，所有分数都会变。

第三，**分级在 $P_2$ 内切**。高 = 分数 ≥ P90、中 = ≥ P75、低 = 其余。P90 = 63.6353、P75 = 55.8726，因此高 2 家、中 4 家、低 19 家。

### 1.4 计算公式与本批实现式

```python
def pct_rank(v, dist):                  # dist 为该维在 P2 的正值升序列表
    lo = bisect_left(dist, v)
    hi = bisect_right(dist, v)
    return (lo + hi) / 2 / len(dist)     # 并列取中点秩

def pain(v, dist):
    return 100 * (1 - pct_rank(v, dist))

def composite(raw, avail, w):
    num = sum(w[k] * pain(raw[k], dist[k]) for k in avail)
    den = sum(w[k] for k in avail)
    return num / den if den else None
```

三个实现细节决定了结果可不可复现。第一，并列值取中点秩（`(lo+hi)/2`），不是「第一个位置」，否则同一取值会因排序稳定性得到不同分数。第二，分母是**可用维权重之和**，不是固定 1，否则缺维的机构分数会被系统性压低。第三，`dist` 只含正值，零值不参与秩计算——零值机构本来就不在 $A_i$ 里。

## 二、计算过程

### 2.1 点集三层收缩

第一层 $P_0$：深圳 1,014 家，含六维全零。第二层 $P_1$：六维任一有值，128 家（12.6233%）。第三层 $P_2$：至少 3 维有值，25 家（占 $P_1$ 的 19.5312%）。

三层之间各砍掉一大块。$P_0\to P_1$ 砍掉 886 家（87.3767%），这是「底册口径」问题——大量民非机构本来就不产科研。$P_1\to P_2$ 砍掉 103 家（占 $P_1$ 80.4688%），这是「维度太少不能打分」问题——它们有值，但只有 1—2 维，打分会被单一维度主导。

产物里把三层都写成 `point_sets`，并明确 `isolated_handling`：全零机构记「不可识别」，1—2 维记「可识别但不打分」，都不补 0、不并入低痛点。这一条很关键：如果把 886 家按 0 分并入，模型会得出「深圳九成机构零痛点」的荒谬结论。

### 2.2 维度覆盖与缺失结构

每维有值机构数：项目 20、转让 5、论文 80、专利 87、人才 17、政策 29。$P_2$ 内正值数：项目 12、转让 3、论文 24、专利 23、人才 12、政策 12。

这里有两个明显短板。第一，转让维全池只有 5 家有值，$P_2$ 内只有 3 家，任何含转让的权重都会让这 3 家决定转让维的秩；0.2 的权重意味着「有没有转让记录」几乎决定了 20% 的分数。第二，人才维来自姓名桥接，`scholars_matched` 只有 147（对应 21,316 行作者记录），桥接率极低，17 家有值可能只是「桥上了的」。

维度覆盖的分布（$P_1$ 内）：1 维 54 家、2 维 49 家、3 维 17 家、4 维 5 家、5 维 3 家、6 维 0 家。**没有一家六维齐全**，五维只有 3 家（其中两家出现在 top15：深圳华大生命科学研究院、深圳市疾病预防控制中心）。这意味着没有任何一家机构的分数是「六维完整」的，全部带缺维重归一。

### 2.3 百分位与合成分

每一维的秩在该维 $P_2$ 正值分布上取。以项目维为例，12 个正值，最高者（102 笔）秩为 1，痛难度 0；最低者秩为 1/12，痛难度接近 100。这个转换把所有维度拉到同一尺度，避免「专利 943 件」与「政策 45 次」直接相加。

合成分按可用维重归一。一家只有 3 维（项目、论文、政策）的机构，分母是 0.25+0.2+0.1=0.55，不是 1。这个设计让缺维机构不至于因为「少了几维」而被系统性压低，但也带来一个副作用：**维度少的机构，分数更容易被单维拉到极值**。这正是 top1 出现的原因（见 2.6）。

### 2.4 分布与分级

25 家打分集的分布：最小 7.2917、p25 30.4592、中位 45.3301、均值 42.8603、p75 55.8726、p90 63.6353、最大 71.9697。分布略右偏（均值低于中位），说明低分尾部更长——多数机构在 30—55 之间，少数拉到 70 以上。

分级用 P90/P75：高 2 家（8.0%）、中 4 家（16.0%）、低 19 家（76.0%）。三档的分界值分别是 63.6353 与 55.8726。这不是「自然断点」，是人为分位，换分位（如 P80/P60）会改变每档家数，但不会改变排序。

### 2.5 稳定性检验

三项检验，全部落盘在 `stability`。第一，等权（六维各 1/6）与主口径的 Spearman 秩相关 0.9785；第二，替代权（项目 0.3、论文 0.25、专利 0.2、转让 0.1、人才 0.1、政策 0.05）与主口径 0.9808。两者都高于 0.97，说明排序对权重不敏感。

第三，逐维剔除。剔项目维 ρ=0.8246、剔论文维 0.8454、剔专利维 0.8986、剔转让维 0.9838、剔政策维 0.9815、剔人才维 0.9908。最大降幅出现在项目维，说明项目维承载了最多的排序信息；人才维几乎不影响排序（0.9908），与它的低覆盖率一致。

同时看 top20 重叠：剔任一维后，top20 名单仍保留 18—19 家。这说明**分级名单稳、单家名次不稳**——一家机构可能从第 5 掉到第 8，但不会从「高痛点」掉到「低痛点」。发布时应当用分级（高/中/低），不要用名次（第 1/第 2）。

### 2.6 头部名单与它的解释边界

top15 的分数从 71.9697 递减到 40.5998。前四家是：深圳市龙岗区耳鼻咽喉医院 71.9697（3 维）、中国农业科学院农业基因组研究所 64.4022（3 维）、中国医学科学院肿瘤医院深圳医院 63.124（3 维）、深圳市妇幼保健院 60.999（4 维）。

这里必须直说一个模型缺陷：**排名靠前的多是「维度少、绝对产出低」的机构**。top1 只有 3 维有值（项目 2、论文 1、政策 1），它之所以高分，是因为在这三维上都处于 $P_2$ 的低位；而这样的绝对产出对一家专科医院而言并不异常。模型没有规模归一（人数缺失），所以「产出少」会被读成「痛」——而产出少可能只是因为机构规模小、或产出不在这六张表里。

这不是可以靠调权重解决的——权重再怎么调，只要百分位是在 $P_2$ 内取的，「有值但值小」的机构就会得高分。正确的修法是引入规模分母（人均产出），而人数整列为空。这条缺陷必须写进发布说明，否则名单会被误读为「最需要帮助的机构」。

### 2.7 与 154_1 的关系

`M_ORG_DEEP_154_1` 是「外部机构引入推荐」：候选池是非深圳 1,060 家，能力分越高越好。本件是「本市机构痛点识别」：母体是深圳 1,014 家，痛难度越高越靠前。两件共用同一份机构面板，但母体、方向、权重、输出全不同，不构成重复计算。

共同的脆弱点是专利桥接：两件都依赖申请人名称匹配，`patent_matched_orgs` 只有 219/2,074。桥接缺口会同时压低两件的专利维，引用时不得把两件的专利数相加。

## 四、数据缺失情况

### 4.1 协同（合作）维：结构性无源（拒拟维）

gkx 无 `enterprise_cooperation` 与 `enterprise_supply_chain`（`information_schema.TABLES WHERE TABLE_SCHEMA='gkx'` 命中 0 行）；开发库 `gkxlumenx_dwd` 有结构但 0 行；演示库同名表为全量装载，铁律禁引，不构成支持。

**拒拟理由**：无机构—企业合作边，六维里缺最关键的「协同」维。
**替代口径**：以专利转让与纵向项目间接代理协同能力。
**与原文差别**：代理只能看到「已经发生的转让/立项」，看不到在谈、失败、非专利形式的合作；「协同弱」与「无合作记录」不可区分。

### 4.2 经费强度维：无分母（拒拟维）

`employees_number` 整列为空（§3.71），机构人数缺失；`project_fund` 单位未标注。没有人数就没有人均经费，没有单位就不能跨机构相加。

**拒拟理由**：缺分母与单位。
**替代口径**：六维中不含经费强度，只保留项目笔数。
**与原文差别**：无法区分「项目多而小」与「项目少而大」，模型对经费规模不敏感。

### 4.3 时间演化：不可用（拒拟维）

项目只有起始年、无结题年；论文年列受采集批次峰污染（2024 年占 32.09%，§3.74）；`svc_metric_series` 不存在。

**拒拟理由**：无可靠时间轴。
**替代口径**：快照截面分级。
**与原文差别**：只出「当前是不是痛点」，不出「趋势」，不能做政策效果评估。

### 4.4 打分集过小

$P_2$ 只有 25 家。百分位秩建立在 12—24 个正值上（转让维只有 3 个），单家机构的进出会明显改变秩。这决定了模型只能给分级，不能给稳定名次。

### 4.5 无规模归一

人数缺失导致无法做人均产出。当前模型对「小机构」有系统性高估（详见 2.6）。这不是可调参数，而是缺分母。

### 4.6 不得外推的三件事

1. **不得把 886 家读成「无痛点」**：它们不可识别。
2. **不得用名次发布**：top20 重叠只有 18—19 家，名次不稳。
3. **不得跨集比较分数**：分数是 $P_2$ 内相对值，换集即失效。

### 4.7 停用与重估条件

出现以下任一情况应重估：① 合作边入湖（补协同维）；② 人数补齐（可做规模归一）；③ 转让数据补全（当前只有 5 家，权重 0.2 已过高）；④ 官方权重表下发（主口径整体重算）。

## 五、结论与发布建议

### 5.1 可用结论

第一，$P_0$ 1,014 → $P_1$ 128 → $P_2$ 25，模型只覆盖 25 家。第二，高/中/低 = 2/4/19，阈值 63.6353 与 55.8726。第三，权重不敏感（ρ 0.9785 / 0.9808），维度敏感（剔除最差 0.8246）。第四，头部名单偏小机构，因无规模归一。第五，协同维无表，判部分支持。

### 5.2 发布口径（逐条写死）

| 项 | 必须写明的口径 |
|---|---|
| 点集 | $P_2$ = 25 家，非全深圳 |
| 分数 | 相对分，只在 $P_2$ 内可比 |
| 分级 | P90/P75 人为切分，非自然断点 |
| 权重 | 自拟，未经甲方签字 |
| 缺维 | 按可用维重归一，不补 0 |
| 名单 | 只用档位，不用名次 |

### 5.3 与旧稿的取舍

旧稿（镜像面）用演示合作维打分，本版剔除合作维、改用六维，并把权重与稳定性全部落盘。档位仍判「部分支持」，但缺口从「数据不可信」换成「协同维缺失 + 打分集过小 + 无规模归一」。

### 5.4 后续

三条路径：① 合作边入湖；② 人数补齐；③ 官方权重下发。其中人数最紧要——没有规模归一，名单可能把「体量小」当成「痛」，这是当前模型最大的解释风险。

## 附录 D　「分数高就是痛」这句话的边界

模型把「产出少」等同于「痛」，这个等价关系在三个地方不成立，必须逐条写清。

第一，产出少可能是「不需要」而不是「做不到」。一家专科医院只发 1 篇中文论文，可能因为它主攻临床而非科研，这不是痛点。模型无法区分「不想做」与「做不了」。

第二，产出少可能是「不在这张表里」。英文论文、横向课题、技术服务合同都不在六维里，港校深圳研究院的产出大量落在这些口径。它们的分数因此偏高，但真实能力不弱。

第三，产出少可能是「机构规模小」。没有人数分母，规模效应无法剥离。top1 只有 3 维有值，它的高分很可能主要来自「体量小」，而不是「痛」——这一点因缺人数无法证实，只能作为待验假设。

结论：分数只能用于「在同一档内挑选候选」，不能用于「判定某家机构经营困难」。发布时必须带这三条限定。
