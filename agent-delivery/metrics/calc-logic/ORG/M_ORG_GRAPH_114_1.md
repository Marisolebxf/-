## 摘要

本件以 2,074 家科研机构为实体主表，建了 2,241 条别名词典（规范名 + 去尾括号写法），对 100,900 篇论文的 435,937 条署名机构串做匹配。词典命中 1,566 个不同字符串、9,671 条实例、235 家机构；对「机构类」字符串（含研究院/研究所/研究中心/实验室，且不含大学/学院/医院/公司）的召回是 2.38%（字符串）与 2.63%（实例）；再收窄到「纯科研院所」口径（排除大学/医院/企业），召回升到 6.99% 与 8.51%。

召回低的主因不是匹配算法，而是**分母错位**：底册只收广东省 2,074 家科研机构，论文语料却是全国乃至全球的署名串（84,320 个不同字符串）。窄口径里未命中的头部是「中国食品药品检定研究院」446 次、「中国石油勘探开发研究院」156 次、「中国城市规划设计研究院深圳分院」82 次、「中国水利水电科学研究院」77 次——前两个是国家级院所，本就不在广东底册；后两个一个在深圳、一个在广州，属于「在粤但未收录」的真缺口。这两类必须分开说，否则 2.38% 会被误读成「识别算法很差」。

精度侧的问题比召回更值得注意。命中实例里最大的一条是「广州中医药大学第一附属医院」→「广州中医药大学」，1,552 次，占全部命中的 16.05%；前 10 条样例合计 3,503 次，占 36.23%。这说明「命中」里有相当一部分是「附属医院/学院 → 母体大学」的隶属映射，不是同名实体。如果业务方要的是「医院」这个实体，这 1,552 次就是误匹配；如果业务方要的是「大学及其附属机构」的合并口径，它就是正确的归并。本件没有做隶属关系判定，只做了名称匹配，因此把这类样例单独列出供人工确认。

属性提取的覆盖率是四个数字：论文 11.38%（236 家）、专利 10.56%（219 家）、项目 2.56%（53 家）、学者 1.40%（29 家）。人员规模是 0.00%，不是稀疏而是无字段——`dwd_research_institute_base_info` 没有 `employees`/`org_size` 列，`dwd_org_base_info.org_size` 只覆盖企业库且与本底册零交集。这一项必须在页面上写「不可计算」，不能用 0 代替。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

本件挂在「产业全要素图谱 → 科研机构实体识别构建」下，页面形态是「实体主表 + 别名管理 + 识别评测报告」。主表展示每家机构的名称、类型、地区、地址、经纬度、登记信息；别名管理展示每个实体的规范名与别名（含去括号写法）；评测报告展示词典/规则的召回率、精度样例、候选新实体。

需求给的输入是「学术论文数据库、专利数据库、科研机构官方网站等多源权威数据」，输出是「机构名称、类型、学科领域、地理位置，以及人员规模、论文产出量、专利数量、地址」。本件用到论文（署名串）、专利（按名匹配）、项目（按名匹配）、学者（按名匹配）四源，官方网站没有接入。

### 1.2 为什么需要这个指标

实体识别是所有机构类指标的地基。如果「中国科学院深圳先进技术研究院」在论文里写成「深圳先进院」、在专利里写成「中国科学院深圳先进技术研究院」、在底册里写成「中国科学院深圳先进技术研究院（深圳市先进技术研究院）」，三个来源对不上，后面所有的产出统计、合作网络、布局分析都会失真。实体识别的价值不是「多一张表」，而是「让同一家机构在不同来源里能对上」。

第二个用途是发现「漏收」的机构。论文署名串里出现「中国城市规划设计研究院深圳分院」82 次、「南方电网科学研究院」67 次，这两家都在广东，但不在 2,074 家底册里。它们可能是「企业性质的研究院」被底册排除，也可能是「事业单位但未登记」。无论哪种，都是底册的覆盖缺口，识别评测能把它们捞出来。

第三个用途是给「属性提取」定基线。需求要论文产出量、专利数量、人员规模三项属性，本件给出的覆盖率是 11.38%、10.56%、0.00%。这三个数字告诉业务方：前两项能用但只覆盖头部，第三项完全不可用。没有这个基线，产品会以为「属性提取」已经做完，实际上只做了十分之一。

### 1.3 需求文档是否给出定义方法

给了方法框架，没给规则。原文是「结合基于规则的正则匹配与关键字抽取，以及基于词典的分词、词性标注与命名实体识别（NER）算法，精准提取机构名称、类型、学科领域及地理位置，并进行去重与异常清理」。规则长什么样、词典怎么建、NER 用什么模型，需求没有说。

本件做了三个选择：词典用「规范名 + 去尾括号」两种写法，共 2,241 条；规则用机构后缀正则（研究院/研究所/研究中心/实验室/大学/学院/医院/基金会/学会/协会/委员会/检验中心/技术中心/设计院），并用「有限公司/集团/厂/银行/支行/分公司」做负向排除；匹配用前缀桶 + 包含匹配，不做编辑距离与向量相似度。三个选择都是为了「可复现」——编辑距离与向量模型会引入阈值参数，阈值一变结果就变，无法逐条复核。

`wanghui=false`，`calc-logic` 库中无对应条目。本件的识别规则没有经过标注集评测，召回率的分母是「规则判为机构类的串」，不是「人工标注的机构串」。这一点必须披露：2.38% 是「对规则口径的召回」，不是「对真实机构的召回」。

### 1.4 类似指标权威机构构建方法可行性分析概要

机构实体主数据在国际上有成熟范式。ROR（Research Organization Registry）给每个研究机构一个持久 ID，记录名称、别名、国家、类型、上级关系，并开放批量下载；ISNI 用 16 位号码标识个人与机构；Wikidata 用 QID 加多语言标签与别名。三者的共同点是「持久 ID + 别名集 + 关系」，这正是本件缺的两样：持久 ID 有（统一社会信用代码），别名集只有「去括号」一种，关系（上级/下属/合并）完全没有。

NER 方面，学术界主流是 BERT 类模型 + 标注集（如 CoNLL、MSRA），机构名识别通常作为嵌套 NER 处理。本件没有用模型，原因有三：没有标注集、模型输出不可逐条解释、以及署名串的形态高度规整（绝大多数以「研究院/研究所/大学」结尾），规则足以覆盖。代价是召回上限受规则限制，收益是可复现性。

可行性结论：**主数据可建、别名与关系不足、NER 不可评测**。主表的 2,074 行可以直接作为实体库；别名只有 2,241 条（平均每家 1.08 条），远少于 ROR 的「每家 3—10 条别名」；上下级关系（大学—附属医院、中科院—研究所）完全没有，导致隶属映射只能靠字符串包含，产生 §摘要 里的精度问题。

### 1.6 推测原意与推测定义

推测原意：业务方要的是一张「机构字典」——给定一个名字（论文署名、专利申请人、政策提及），能查到它是哪家机构、什么类型、在哪、有什么属性。因此本件的核心产出是**主表 + 别名 + 识别评测**，不是「一个 NER 模型」。

形式化定义。实体主表 $E=\{e_1,\dots,e_{2074}\}$，每个实体有属性集 $A(e)$（名称、类型、地区、地址、经纬度、登记信息）。别名函数 $\text{alias}(e)=\{\text{name}(e)\}\cup\{\text{strip\_paren}(\text{name}(e))\}$

识别：给定署名串 $s$，若存在 $e$ 使 $\text{alias}(e)$ 是 $s$ 的前缀或 $s$ 包含 $\text{alias}(e)$，则记 $s\to e$。规则判定：若 $s$ 命中机构后缀正则且不含负向词，则记 $s$ 为「机构类串」。

召回率：$\text{recall}_{str}=|\{s: s \text{ 机构类}, s\to e\}| / |\{s: s \text{ 机构类}\}|$；实例召回 $\text{recall}_{inst}=\sum_{s\to e}\text{cnt}(s) / \sum_{s \text{ 机构类}}\text{cnt}(s)$。

属性提取率：$\text{fill}(a)=|\{e: a(e)\neq\emptyset\}| / 2074$。

维护：变更日志来自 `dwd_org_changerecord_info`，与底册按 `org_id`/`external_id` 关联，命中 0 行，因此维护机制只有 ETL 的 `updated_time`，没有字段级变更记录。

## 二、计算过程

### 2.1 方法选择与总体流程

四步：先装实体主表并做去重与类型补全，再建别名词典与前缀桶，然后对 435,937 条署名串做词典 + 规则双路识别，最后回填论文/专利/项目/学者四类属性并算覆盖率。全程零 SQL，只读面板与本批探针，运行约 2.05 秒。

选择「词典 + 规则」而不是「NER 模型」，核心原因是标注集缺失。NER 模型的召回率必须用人工标注的测试集评测，而本件没有标注集；用规则自己圈定的「机构类串」当分母，评测的是「规则对规则的召回」，只能内部比较，不能对外声称「识别准确率 95%」。这一点在页面上必须写清楚，否则「2.38%」会被当成模型的糟糕表现，而它其实只是「词典覆盖率」。

选择「前缀桶」而不是「全表扫描」，是性能考虑。2,241 条别名对 435,937 条串做全量包含匹配是 9.8 亿次比较，Python 里要几分钟；按别名前 2 字建桶（1,015 个桶）后，每条串只需比对同桶的别名，实测 2.05 秒跑完。前缀桶的代价是「别名首字不同但实为同一机构」的写法会漏（如「中科院深圳先进院」与「中国科学院深圳先进技术研究院」），本件没有处理这类缩写。

### 2.2 步骤 1：主表装配、去重与类型补全

主表 2,074 行、27 列，`org_id` 2,074 个不同值、`external_id` 2,074 个不同值，没有重复主键。名称有 2,070 个不同值，4 组重名（8 行）：广州市从化区规划编制研究中心、国家药品监督管理局南方医药经济研究所、广州市从化区经济社会发展研究中心、深圳市深圳医学科学院教育基金会。这 4 组重名不是数据错误——它们是同一名称在两个区/两个登记批次下的两条记录，`org_id` 不同。页面如果用名称做主键，这 8 行会互相覆盖。

类型分布：民办非企业单位 1,480、事业单位 575、司法鉴定机构 5、基金会 5、社会团体 4、空 3、编办管理其他机构 1、机关 1。空值的 3 家可以用 `external_id` 前 2 位补全——前缀 `12` 对应事业单位，这 3 家全部落在 `12` 下，补全后类型覆盖 2,074/2,074。前缀分布是 `52` 1,480、`12` 578、`34` 5、`53` 5、`51` 4、`11` 1、`19` 1，与类型分布一一对应，说明 `external_id` 的编码规则可以作为类型校验规则。

城市分布：深圳 1,014、广州 822、东莞 127、惠州 111。四市合计 2,074，没有省外机构——这是底册的收录范围，不是「广东只有这些机构」。这一点在识别评测里会变成「分母错位」：论文语料是全国性的，底册是广东的，两者本来就不在一个范围。

### 2.3 步骤 2：别名词典与前缀桶

别名 = 规范名 + 去尾括号写法。例如「广州中医药大学（广州中医药研究院）」的别名是它自己与「广州中医药大学」；「深圳市龙岗中心医院（深圳市龙岗中心医院集团、深圳市第九人民医院、…）」的别名是它自己与「深圳市龙岗中心医院」。2,074 个规范名去掉重复后得到 2,241 条别名（平均每家 1.08 条）。

冲突检查：同一别名指向多个实体的情况为 0 条。这是因为底册的名称在去掉括号后仍然唯一；如果两家机构去掉括号后同名（如两个「规划编制研究中心」），它们的全名不同、去括号后也不同（一个带「从化区」、一个带「增城区」），因此没有冲突。

前缀桶按别名前 2 字切分，得到 1,015 个桶。最大的桶是「中国」（大量中科院与国家级院所）、「广东」（省属院所）、「深圳」「广州」（市属）。桶的作用是加速匹配，不是语义分类；桶内仍然要做包含匹配。

### 2.4 步骤 3：论文署名串的词典匹配

语料是 100,900 篇论文的署名机构串，共 435,937 条实例、84,320 个不同字符串。匹配规则是「别名是串的前缀，或串包含别名」，命中后记 `(串, 实体, 次数)`。

实测命中 1,566 个不同字符串、9,671 条实例、235 家机构。整体命中率（对全部 84,320 个串）是 1.86%（字符串）与 2.22%（实例）。这两个数看起来很低，但分母包含大量非机构串（人名、实验室名、企业名、外文名），不是「该命中却没命中」的比例。

精度样例里最突出的是隶属映射。前 10 条命中合计 3,503 条实例，占全部命中的 36.23%，其中「广州中医药大学第一附属医院」1,552 次、「广州中医药大学」618 次、「第一临床医学院」477 次、「第四临床医学院」240 次、「中药学院」136 次、「针灸康复临床医学院」106 次，全部指向「广州中医药大学（广州中医药研究院）」；「广东省中医院」90 次指向「广东省中医院（广州中医药大学第二附属医院…）」。唯一精确匹配的样例是「中国科学院深圳先进技术研究院」99 次。

这说明本件的匹配在「大学 + 附属医院 + 学院」这一族上做了过度归并。对「大学」这个实体，把附属医院的论文算进来是合理的（附属医院是大学的一部分）；对「医院」这个实体，就不合理（医院有自己的科研产出）。本件没有实体层级，无法区分这两种语义，因此把这 6 条样例单独列在 `precision_samples` 里，供业务方决定归并口径。

### 2.5 步骤 4：规则识别与召回

规则用机构后缀正则判定「是不是机构串」：含研究院/研究所/研究中心/实验室/大学/学院/医院/防治中心/基金会/学会/协会/委员会/检验中心/技术中心/设计院，且不含有限公司/有限责任公司/股份有限公司/集团/厂/银行/支行/分公司。命中规则的串记为「机构类串」。

实测机构类串 61,595 个、353,993 条实例。其中被词典命中的 1,463 个串（实例命中数见产物），字符串召回 2.38%、实例召回 2.63%。这两个数比整体命中率（1.86%/2.22%）高一点，因为分母去掉了非机构串，但幅度不大——说明「机构类串」里绝大多数仍不在广东底册。

再收窄口径：只保留含「研究院/研究所/研究中心/实验室」且不含「大学/学院/医院/公司/集团」的串，得到 3,604 个串、14,503 条实例；词典命中 252 个串、1,234 条实例，字符串召回 6.99%、实例召回 8.51%。这个口径最接近「科研院所」，召回也最高。

窄口径的未命中头部很说明问题：中国食品药品检定研究院 446、中国石油勘探开发研究院 156、中国城市规划设计研究院深圳分院 82、中国水利水电科学研究院 77、南方电网科学研究院 67、中国工程物理研究院流体物理研究所 59、中国林业科学研究院林业科技信息研究所 57、核工业西南物理研究院 56、中国地震局地球物理研究所 55、中国核动力研究设计院…54、中国工程物理研究院激光聚变研究中心 54、中国环境科学研究院…53、河南省疾病预防控制中心性病艾滋病防治研究所 51、国家粮食和物资储备局科学研究院 51。

这 14 条里，大部分是国家级或省外院所（食品药品检定、石油勘探、水利水电、工程物理、核工业、地震局、环境科学、河南疾控、粮食储备），本就不该在广东底册；但「中国城市规划设计研究院深圳分院」与「南方电网科学研究院」在广东，属于真缺口。前者是央企分院（可能未在广东登记为独立法人），后者是企业研究院（底册只收事业单位/民办非企业）。这两类缺口不是算法问题，是收录范围问题。

### 2.6 步骤 5：属性提取与人员规模缺口

四类产出的提取率：论文 236 家（11.38%）、专利 219 家（10.56%）、专利 IPC 小类 194 家（9.35%）、项目 53 家（2.56%）、学者 29 家（1.40%）、政策提及 72 家（3.47%）、专利受让 10 家（0.48%）。基础属性方面：地址 2,074（100%）、经纬度 2,056（99.13%）、注册资本 2,044（98.55%）、成立日期 1,996（96.24%）。

人员规模是 0.00%，原因不是「没匹配上」，而是「没有字段」。`dwd_research_institute_base_info` 的 27 列里没有 `employees`/`org_size`/`staff_num`；`dwd_org_base_info.org_size` 只覆盖企业库，且该库与本底册按 `org_id`/`external_id` 都是零交集（工商库只覆盖企业）。`dwd_org_annual_financial_info.development_employee` 整列为空（90,926 行非空数 0）。三条路都断了，所以这一项只能标「不可计算」。

属性提取的覆盖率低，根因与识别召回相同：底册是广东的，产出是全库的；而且论文/专利的署名写法与底册名称不一致，匹配不上。论文 11.38% 已经是四类里最高的，因为它用了面板的匹配结果（面板对论文做了更宽的匹配）；专利 10.56% 用的是 `patent_ipc4_by_name` 的匹配；项目 2.56% 与学者 1.40% 最低，因为项目承担单位名、学者单位名的写法最不规范。

真正值得补的是「在粤但未收录」的机构：中国城市规划设计研究院深圳分院（82 次）、南方电网科学研究院（67 次）。前者是央企分院，后者是企业研究院，两者都不符合底册的「事业单位/民办非企业」登记类型，但对「产业全要素图谱」来说是重要节点。建议单建一张「企业/央企研究机构」表，不要硬塞进科研机构底册。

### 3.2 召回率的分母问题

本件最重要的方法论提醒是：**召回率的分母决定了召回率的含义**。同一个匹配结果，在「全部署名串」口径下是 1.86%，在「机构类串」口径下是 2.38%，在「科研院所」口径下是 6.99%，按实体算是 11.33%。四个数都对，但含义完全不同。

如果对外只报一个数，应该报哪个？本件建议报「窄口径 8.51%（实例）」，并注明「分母是 3,604 个含研究院/研究所/中心/实验室且不含大学/医院/公司的署名串」。这个口径最接近「科研院所识别」的业务语义，也最少受「底册只收广东」的干扰。但即便是这个口径，分母里仍有大量省外院所（中国食品药品检定研究院等），所以 8.51% 仍然是「对全国科研院所署名串」的召回，不是「对广东科研院所」的召回。

要算「对广东科研院所」的召回，需要先判定每个署名串是否属于广东，这本身就是一个地址识别问题，本件没有做。这是一个明确的方法缺口，写在这里供后续版本补。

### 3.3 逐维缺口与修复路径

别名的缺口最直接：2,241 条别名平均每家 1.08 条，而 ROR 的机构平均有 3—10 条别名（含缩写、英文名、旧名、下属机构名）。修复路径是接入机构官网、百度百科、ROR 的别名集，预计能把别名扩到 8,000—10,000 条，召回提升 2—4 倍。

层级的缺口同样关键：主表没有 `parent_org_id`，大学与附属医院、中科院与研究所、省科学院与下属所的关系只能靠字符串包含推断，导致 §2.10 的隶属误匹配。修复路径是建一张「机构关系表」（parent_id, child_id, relation_type, source），先从名称里的括号注（「广东省中医院（广州中医药大学第二附属医院…）」）抽，再人工补。

人员规模的缺口无法用 ETL 解决：主表没有列、年报表整列为空、企业库零交集。修复路径只有一条——由数据方新增「机构人员规模」字段，来源可以是事业单位年度报告、机构官网、或编办数据。

实体维护的缺口是结构性的：`dwd_org_changerecord_info` 是工商变更库，与事业单位底册零交集。修复路径是建「机构实体变更日志」（org_id, field, old, new, changed_at, source），由 ETL 在每次更新时写入；当前只能靠 `updated_time` 判断批次，不能判断字段级变化。

### 4.2 后果归因：哪些话不能说

第一，不能说「识别准确率 2.38%」或「召回率只有 2.38%」。2.38% 是「对规则圈定的机构类串」的字符串召回，分母里包含大量省外机构；按实体算是 11.33%，按窄口径实例算是 8.51%。三个数含义不同，必须说清分母。第二，不能说「本件做了 NER」。本件没有用任何模型，只有词典与正则；说 NER 会让用户以为有语义泛化能力，实际上「深圳先进院」这种缩写是识别不出来的。

第三，不能说「广州中医药大学第一附属医院的论文属于广州中医药大学」。这是本件的匹配结果，不是事实判断；附属医院是独立法人，论文归属要看署名规则。第四，不能说「人员规模为 0」。0.00% 是「无字段」，不是「所有机构都是 0 人」；这两个说法在页面上必须区分。

第五，不能说「候选新实体都是漏识别」。候选里 739 次的中山一院、668 次的深圳市中医院都是医院，本就不在科研机构底册的收录范围；真正的漏识别是「在粤但未收录」的央企分院与企业研究院，数量远小于候选总数。

### 4.3 判档说明

本件判「部分支持」：实体主表 2,074 行、27 列、无重复主键、基础属性填充率 96%—100%，这部分是可交付的；词典与规则识别都跑通并给出了四套口径的召回率；属性提取的四类产出覆盖 11.38% / 10.56% / 2.56% / 1.40%。但人员规模 0%、变更日志 0 条、别名只有 1.08 条/家、隶属关系无字段。按 §0.1 的定义，这属于「主数据可交付 + 识别与属性覆盖不足」，是部分支持。

没有降到「完全不支持」，是因为主表本身是完整可用的，识别评测也有真实数字与可复核的样例。没有升到「完全转换支持」，是因为需求点名的「人员规模」完全不可得、「实体维护更新」没有可审计的日志、「NER」没有标注集无法评测。

### 4.4 补齐关键字段后的规模预估

若别名从 2,241 条扩到 9,000 条（每家 4—5 条），按当前「别名数 → 命中串数」的比例（1,566/2,241 ≈ 0.70）估算，命中串可从 1,566 增到约 6,300，实例从 9,671 增到约 3.9 万，实例召回从 2.22% 升到约 9%。

若加上 `parent_org_id` 与隶属关系表，附属医院/学院的命中可以正确归到子机构，大学实体的论文数会下降、医院实体的论文数会上升。这会改变合作链、布局、扶持三件的输入，因此隶属关系表应当优先于别名扩充。

若人员规模字段能补上，属性提取的完整度会从「四类产出 11%」升到「五类属性 60%+」，扶持推荐的 T 维也能从「学者库代理」升级为「真实人员结构」。这是本件对下游影响最大的一项。

## 五、结论与发布建议

### 5.1 结论

可发布：2,074 行实体主表（名称/类型/地区/地址/经纬度/登记信息）、2,241 条别名词典、四套口径的识别召回率、精度样例（隶属映射）、候选新实体清单、属性提取率表。

必须加限定语：召回率的分母是「规则圈定的机构类串」，不是人工标注集；命中里 36.23% 是子机构并入母体；人员规模不可计算；变更日志为 0；底册只收广东四市，省外机构不在收录范围。

### 5.2 发布建议

第一，主表页面用 `org_id` 做主键，不要用名称（4 组重名会互相覆盖）。第二，别名管理页面显示「规范名 + 别名 + 来源」，并标注哪些别名是规则生成的（去括号）、哪些是人工补的。第三，识别评测页面必须同时显示四套口径的召回率与分母定义，不能只给一个数。第四，精度样例单独一个面板，把「隶属映射」与「精确匹配」分开，让用户决定归并口径。

第五，人员规模字段显示「暂无数据」而不是「0」，并附一行说明「底册无此字段、年报表整列为空」。这一条看似小事，但它是本件最容易被误读的地方——一个 0 会被当成「这家机构没有人员」。

## 附录 D　构建方法可行性报告（完整版）

一、方法谱系。实体识别有三条路径：词典匹配（规则/别名）、统计模型（CRF/BERT-NER）、混合（词典 + 模型）。词典匹配精度高、召回受别名覆盖限制；统计模型泛化好、需要标注集；混合需要两者都有。本件走纯词典 + 规则，因为没有标注集，且署名串形态规整（以机构后缀结尾）。

二、为什么不做编辑距离与向量相似度。编辑距离（Levenshtein）对「中国科学院深圳先进技术研究院」与「深圳先进院」这类缩写无效，对「广州中医药大学」与「广州中医药大学第一附属医院」这类包含关系会产生假阳性；向量相似度需要预训练模型与阈值，阈值一变结果就变，无法逐条复核。本件选择「前缀桶 + 包含匹配」，牺牲缩写召回，换取可解释性。

三、精度的处理。本件不做自动消歧，只把精度样例列出。原因是没有实体层级（parent_org_id），无法判断「附属医院」应该归到大学还是单独成实体。这个判断是业务决策，不是算法能替代的。建议在实体库里加 `entity_level`（大学/学院/医院/研究所）与 `parent_org_id`，由业务方定归并规则。

四、召回的分母。本件给了四套口径（全部串、机构类串、窄口径、按实体），因为分母选择直接决定召回率的数值。对外沟通时应当明确「8.51% 的分母是 3,604 个科研院所类署名串」，而不是笼统说「召回率 8.51%」。

五、结论。本件在当前数据条件下已把主表与识别评测做到可交付（2,074 行主表、2,241 条别名、四套口径召回、精度样例、候选清单），可作为「机构字典 + 识别基线」使用。要升级为需求所描述的「实体识别系统」，必须补三样东西：别名集（ROR/官网/百科）、实体层级（parent_org_id）、标注集（500—1,000 条人工标注）。三样都不具备时，任何「准确率」的说法都缺乏依据。

六、一句话结论。本件可以上线为「科研机构主数据 + 识别覆盖率评测」，但不能上线为「高精度实体识别服务」；前者是字典与基线，后者需要别名、层级、标注三样补齐后才成立。

七、遗留事项。4 组重名机构（8 行）需要业务方确认是否合并；「中国城市规划设计研究院深圳分院」「南方电网科学研究院」这类在粤但未收录的机构，建议单建「企业/央企研究机构」表；NER 模型若要上线，需先有 500 条以上的标注集，否则无法评测。
