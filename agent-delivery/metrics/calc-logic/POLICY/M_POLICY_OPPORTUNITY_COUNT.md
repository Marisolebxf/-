## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

本指标挂接《科技专题服务算法库》**政策深度分析模型构建 → 政策机遇识别模型**（§1.1.1.1.1.1.1.8.5）在 **DS-11-POLICY-EVAL（政策分析评价报告页）** 的机遇清单区块。需求原文对该页件的任务定义为：机遇模型输出「政策机遇清单」，报告页展示清单条数并支持按政策标签、时间区间及分析维度查询——即本指标是清单的**聚合计数面**，为报告页的「本周期识别出 N 条政策机遇」摘要数字与清单钻取入口供数。

### 1.2 为什么需要本指标

政策分析评价报告页的信息架构遵循「摘要数字→清单→单条详情」三层钻取，机遇清单条数是最顶层的摘要数字之一。没有它，报告页无法回答「这期政策监测到底识别出多少条机遇」的基线问题，用户只能翻看无总数的明细列表；有了它，条数的时序变化（本期 vs 上期）即「政策机遇趋势」的最简可读形式，直接服务需求输出物「政策机遇趋势分析报告」。同时，清单条数作为模型产出的体量指标，是甲方验收机遇模型「有没有在干活」的第一眼证据——空清单与满清单对应完全不同的运营动作（补数 vs 排序运营）。

### 1.3 需求文档是否给出定义方法

**需求文档没提及指标定义方法。** 需求原文（§1.1.1.1.1.1.1.8.5）给出机遇模型的输出物含「政策机遇清单」，但**未给清单的入选规则、阈值或条数口径**；DS-11-POLICY-EVAL 页面需求中也只有「展示机遇清单」级别的功能描述。三份需求说明书均未出现「政策机遇清单条数」作为独立指标名。入选规则（综合分 ≥60）全部来自王惠对 170 的口径定义。

#### 1.4.1 族 A｜复合指标判定族：计数是判定之后的一步，不能独立成法

**谁在用。** OECD/JRC 的复合指标手册（Handbook on Constructing Composite Indicators）是欧盟与多数国际组织构建指数的方法基准，其流程把「选取—变换—归一—加权—聚合—判定—呈现」分成明确的步骤；判定步（阈值或分位）之后才是归类与计数。Saisana 等在 *JRSS-A* 上给出的不确定性与敏感性分析框架，进一步要求对权重、归一方法、阈值三条同时做扰动，并报告排名的稳定性。

**怎么定义与口径边界。** 这一族的边界是「判定必须消费同一份综合分」：清单条数 = Σ I(Opp ≥ τ)，其中 Opp 必须与模型件（170）逐位一致。若页件另算一套分，就会出现「模型说 0 条、页面说 2 条」的对账事故——这正是本批 v2 要修的问题。敏感性框架的边界则是「阈值不是天然给定的」：τ 变动 10 分就可能让清单从 0 变 2，因此 τ 必须参数化并留痕。

**在本库能否落地。** 可落地，且已落地：v2 脚本与 170 共享同一段五子指标计算逻辑（'NULL' 清洗、theme 分组、min-max、三维等权），实测 2 条可评分政策均为 50.00 分，过线 0 条。**实测可得率**：判定链路 100%（可跑通），有效判定对象 2/20,000（0.01%）。**差在哪**：20,000 条里只有 2 条能被全维评分，其余 19,998 条缺 theme/keywords/quote，无法进入判定——这不是方法问题，是输入问题。

**为何选。** 它是唯一能保证「页件与模型件同源」的方法，也是甲方复核时能逐位对账的方法；同时它提供了阈值敏感性的规范语言，使「0 条」可以被解释为「阈值 + 输入」的函数，而不是一句空结论。

#### 1.4.2 族 B｜官方统计计数纪律族：入集规则先行、计数必须可对账

**谁在用。** 国家统计局的统计分组与统计标准体系（统计用区划代码、城乡划分代码、国民经济行业分类等）确立了一条工程纪律：先定义入集规则（去重、有效域、统计期），再做分组计数，最后必须能与总量对账。普查与年报的每一张分组表都满足「各组之和 = 总计」。

**怎么定义与口径边界。** 边界有三条：其一，入集与去重规则必须先于计数写下（本件的入集=170 的入集：`id` 去重、`status` 有效）；其二，代理指标必须与正式指标显式区分（关键词近似轨必须标「非机遇判定」）；其三，分组计数要能对账（清单条数 + 未过线条数 = 可评分政策数 = 2，本件满足）。

**在本库能否落地。** 可落地：入集规则已固定，`publish_year` 满量 19,997 可用于统计期切分，`ministry` 19,989 可用于分组。**实测可得率**：对账链路 100%（2 = 0 + 2）。**差在哪**：官方统计的对账是「分组之和=总量」，本件的总量（20,000）里有 19,998 条不可评分，属于「未入集」而不是「未过线」，两者必须在报表上分列，否则 0 条会被误读为「全库无机遇」。

**为何选。** 它给的是**呈现纪律**而不是算法：把「不可评分」「未过线」「过线」三态分开，是本件不误导甲方的关键。v2 的 `_out.json` 正是按这三态分区的。

#### 1.4.3 族 C｜政策科学族：机遇是「目标—工具错配」，但错配需要可读的文本

**谁在用。** Howlett 与 Rayner 的政策组合研究把政策设计拆成 consistency（目标与工具一致）、coherence（工具之间协调）、congruence（与情境匹配）三条判据；政策试验研究（Heilmann）则强调候选方向必须有可信的验证信号才进入推广。国内制度侧，《重大行政决策程序暂行条例》第三十六条确立了「决策后评估」：实施后明显未达预期、公众意见较多或决策机关认为必要时应当组织评估，评估结果作为调整决策的依据。

**怎么定义与口径边界。** 这一族的「机遇」不是「政策文本里出现了积极动词」，而是「目标面已强、工具面尚弱」的错配方向。要识别错配，至少需要三样东西：政策目标文本、政策工具分类、执行效果或短板证据。三者缺一，所谓的「机遇」就退化为文本风格判断。

**在本库能否落地。** 不能落地为判定方法：库内 theme 真实值 2 行（分组键）、keywords 0 行（工具/主题词）、quote_policy 2 行（引用/依据），无法做工具分类与目标—工具匹配；`content` 19,203 行虽有全文，但全文只能支撑「关键词近似」，支撑不了结构化错配判定。**实测可得率**：文本 96.0%（19,203/20,000）、结构化主题 0.01%（2/20,000）、工具分类 0%。**差在哪**：缺的是**标注**，不是文本。

**为何不选。** 并非方法不好，而是它的最小输入（主题 + 工具 + 短板）本库只有文本一项。用它做判定会退化成「读标题猜机遇」，这正是本批 v2 要废弃的旧轨。保留它的方式是把它写进「机遇」的语义定义（§1.6），而不是写进算法。

#### 1.4.4 族 D｜商业政策数据商族：政策文本全，但口径不可审计

**谁在用。** 北大法宝、政策通、各类「政策大数据」平台提供政策全文检索、主题标签、政策力度评分；部分平台还给出「政策机遇」类榜单。

**怎么定义与口径边界。** 这类产品的标签体系（主题、效力级别、发文机关）通常可用，但「机遇」评分多为模型推断且不公开特征与权重；同一政策在不同平台的「力度分」可以相差很大。边界问题是：标签可审计、评分不可审计。

**在本库能否落地。** 不可落地：无授权、无接口、无对齐主键（本库政策以 `id` 为主，外部平台以标题/文号为主，标题变体多）。**实测可得率 0%**。其评分口径**未取证，不得假设**。

**为何不选。** 与 A 族冲突：A 族要求「判定消费同一份综合分」，引入外部评分等于引入第二套不可复现的口径。若甲方需要外部标签，正确用法是只用其**标签**（可审计）扩 theme，而不是用其**评分**替代 170。

## 二、计算过程

> **口径说明**：本件采用王惠 170 第四步口径（v2 升级：既有 20261020 版脚本为标题关键词近似判据，本批已重写为全维王惠口径），复现脚本 `code/M_POLICY_OPPORTUNITY_COUNT.py`，结果见 `M_POLICY_OPPORTUNITY_COUNT_out.json`。文内 (Author) 与文末参考文献一一对应。

### 2.1 方法选择：全维王惠口径替代标题关键词近似

清单计数的正确位置在复合指标流水线的**判定步之后**：先有逐政策综合分，再过阈值，再计数——这是复合指标手册「聚合—判定—呈现」次序在页件层的体现 (OECD & JRC, 2008)。既有脚本（20261020 版）因当时 theme 通道尚未探明，退而用标题关键词做机遇近似：标题含「新出台/首次/创新示范」计新增类、含「修订/补充通知/实施细则」计细化修订类，两数作为「机会面」展示。该近似的优点是零依赖、当日可跑；缺点是把「机遇」窄化为「文本动词」，与 170 的三维语义（关注度/影响力/稳定性）脱钩，且无法复用阈值判定。本批 v2 升级的判断依据是：既然 170 全维脚本已在 gkx 真源跑通王惠四步，页件应消费同一份综合分而非平行口径——否则模型件与页件会出现「两个机遇数」，违反单一口径纪律。升级后实测：可全维评分政策 2 条（均 50.00 分）、**清单条数 0**；关键词近似轨的参考数（新增类 11、细化修订类若干）保留在 out.json 作对照，不再作为主口径。

### 2.2 步骤 1｜输入对齐（消费 170 综合分）

本件的第一步不是取数而是**口径对齐**：清单的入选判定必须与 170 的综合分同源。工程实现上，v2 脚本与 170 脚本共享同一段五子指标计算逻辑（'NULL' 占位清洗、theme 分组、min-max 归一、三维等权），确保逐政策综合分逐位一致。这一步的业务含义是：报告页的「N 条机遇」与模型件的「机遇判定」是同一件事的两个呈现，任何一侧单独改口径都会造成对账事故。实测对齐结果：可评分政策 2 条、综合分均 50.00、过线 0 条——与 170 报告 §2.7 数字完全一致。

### 2.3 步骤 2｜阈值判定与计数

$$N_{\text{list}}=\sum_{p\in P} I\bigl(Opp(p)\ge 60\bigr)$$

阈值 60 沿用王惠 170 原稿（「政策机遇综合得分 ≥60 分的政策识别为政策机遇」），本件不改判。实测 $N_{\text{list}}=0$：两条可评分政策（湖北科技创业十条意见 2015、湖北科技特派员专项资金办法 2010）综合分均为 50.00，距 60 线差 10 分——差距来自三维中多数子指标在 2 行样本内无区分度（min-max 常数规则取 50）。需要向产品侧明确：**0 不是「没有机遇」的断言，而是「当前数据不足以判定任何政策为机遇」的诚实表达**；两语义在报告页的呈现方式应有别（前者可结案、后者须挂「数据补齐中」状态标）。

### 2.4 步骤 3｜清单主体与钻取字段

清单条数只是页件的聚合面，钻取面需要清单主体字段。v2 输出的清单主体结构为：政策 id、标题、发布年份、主题数组（theme 摊平）、综合分、三维分（关注度/影响力/稳定性各多少）、过线与否。当前可入清单主体（含未过线者）仅 2 条，即 170 报告的具名样例；两件的年份（2015/2010）与主题（科技创新/财政支持等）字段齐全，可验证钻取链路的字段闭环。这一步验证的结论是：**清单的 schema 已就绪，缺的是行**——一旦 theme 标注铺设，同一 schema 可承载全库 20,000 条的评分与过线标记，无需改结构。

### 2.5 步骤 4｜趋势面对照（关键词近似轨的参考定位）

需求输出物含「政策机遇趋势分析报告」。在综合分轨断供期，v2 保留关键词近似轨作趋势面的参考视图：新增类（新出台/首次/创新示范）与细化修订类（修订/补充通知/实施细则）标题命中的年度分布，可展示「政策供给动词结构」的时序——但它度量的是发文行为类型而非机遇本身，页面呈现必须标注「供给结构参考，非机遇判定」。该处理方式与官方统计实践中「代理指标须与正式指标显式区分」的口径纪律一致 (国家统计局, 2021)。待 theme/keywords 补齐后，趋势面切换为逐期清单条数对比（本期 N vs 上期 N），近似轨退役。

### 2.6 步骤 5｜服务化口径（查询参数映射）

需求要求清单「可按政策标签、时间区间及分析维度进行查询」。v2 脚本的参数化预留与查询维度一一映射：时间区间 → `publish_year` 过滤（通道满量 19,997/20,000，当日即可用）；政策标签 → theme 过滤（断供，待补）；分析维度 → 三维分展示列（随综合分产出）。三个维度中仅时间维当日可用，与 170 报告 §2.6 残维视图的结论一致——页件的可用性上限完全由模型件的数据通道决定，页件本身无独立瓶颈。

### 4.1 缺口后果归因：0 条是「判不出」，不是「没有」

本件的所有缺口都指向同一个后果：清单条数 0。但这个 0 有三种可能的成因——「确实无机遇」「数据不足无法判定」「阈值设得太高」——三者的产品处置完全不同。本节的归因就是把 0 拆开，并给出每一层可量化的偏移。

| 缺口 | 偏移方向 | 偏移量级 | 交叉验证 |
|---|---|---|---|
| theme 2/20,000（0.01%） | **假阴性**：绝大多数政策无法分组，只能落到常数规则 | 可评分 2 条 / 有效 20,000 条 = 0.01% | 能：分组覆盖率可直接算 |
| keywords 0 | 关键词通道整列为空 → 该子指标对所有人同分 | 0/20,000 | 能：通道非空计数 |
| quote_policy 2 | 引用通道近乎空 → 子指标无区分度 | 2/20,000 | 能：同上 |
| min-max 常数规则 | 单值/零方差时取 50 → 所有可评分政策同分 | 2 条均 50.00；距阈值 60 差 10 分 | 能：分数分布可直接看 |
| 阈值 60 未校准 | 阈值下调即**由 0 变 2** | τ=60 → 0 条；τ≤50 → 2 条（全部可评分政策过线） | 能：阈值扫描 |
| 旧近似轨并存 | 页面若回灌近似数，会显示「有 11 条」 | 近似轨新增类 11 条（非机遇判定） | 能：取数点核对 |

**第一层：可评分对象的覆盖率决定了 0 的语义。** 20,000 条政策里只有 2 条能进入全维评分，覆盖率 0.01%。这意味着「0 条」的置信基础只有 2 个样本，而不是 20,000 个。把它读成「全库没有机遇」是**样本外推**，本报告明确拒绝；正确读法是「在可判定的 2 条里，没有一条过线」。

**第二层：常数规则把所有可评分政策压到同一点。** 由于 theme 只有 2 行、keywords 为 0，多数子指标在样本内无方差，min-max 归一按常数规则取 50，三维等权后综合分仍是 50.00。这不是「两条政策恰好都 50 分」，而是「在当前输入下，任何可评分政策都会得 50 分」。因此分差信息为零，排序无意义——本件只输出计数，不输出排名。

**第三层：阈值弹性极大，10 分之差使清单从 0 变 2。** 若甲方把阈值定为 50，两条政策全部过线，清单条数变为 2；若定 60，则为 0。这说明在本数据状态下，**清单条数几乎完全由阈值决定，而不是由政策内容决定**。因此阈值必须参数化、必须留痕、必须在页面上标注当前取值，否则同一个「N 条」在不同批次间不可比。

**可交叉验证的部分与不可验证的部分要分开。** 覆盖率、通道非空数、分数分布、阈值扫描四项都可直接从 `_out.json` 复算，属于可验证；「补齐 theme 后清单会变成多少」则**未取证，不得假设**——没有标注就没有真值，任何预估都只是情景假设。这也是本报告不写「补数后预计 N 条」的原因。

### C.9 补齐动作与可验证边界

| 动作 | 前置 | 可验证的产出 | 不能声称的 |
|---|---|---|---|
| theme 标注铺设 | 政策主题体系 + 人工/模型标注 | 分组覆盖率、可评分对象数 | 「补完就有 N 条机遇」 |
| keywords 抽取 | 分词/词典 + 质量抽检 | 通道非空率 | 抽取质量等于人工标注 |
| quote_policy 回填 | 引用字段结构化 | 通道非空率 | 引用多即政策强 |
| 阈值参数化 | 配置表 + 版本号 | 不同 τ 下的清单数 | 某个 τ 是「正确」的 |
| 近似轨下线 | 取数点切换 | 双口径零并存 | 近似轨可作历史对比基准 |

最后一列是**禁止声称项**，与 §4.1 的「未取证不得假设」同源：补数能提高覆盖率，但不能预先承诺补数后的清单条数；阈值可以参数化，但不能声称某个取值是唯一正确的。

验收时建议用三个数而不是一个数：**可评分对象数（2）**、**过线数（0）**、**未入集数（19,998）**。只报「0 条」会把「判不出」误传成「没有」；三个数并列时，甲方一眼能看出 0 的来源在入集侧。这也是本件与 170 报告在呈现上唯一需要保持同步的地方——两件的三态数字必须逐项相等，否则页件与模型件又会分裂。

最后一条边界：**清单 schema 与条数是两件事**。清单的字段契约（政策 id、综合分、各子指标分、阈值、批次）已经就绪且可复现，这部分不依赖上游补数；条数则完全依赖 theme/keywords 的铺设。因此本件的交付状态应表述为「契约就绪、条数为 0（判不出）」，而不是「清单未开发」——前者是数据问题，后者是工程问题，两者的工单归属完全不同。
