## 口径定义

政策分析评价报告页上，对选定政策集自动生成可编辑摘要与结论并具备推送就绪状态的综合结果，从信息覆盖度、结论条数、推送就绪三维度评定。本条是报告 NLP 摘要能力，不是焦点/力度/效果/布局模型的文本复述。

## 计算逻辑说明

建议采用**“结构化信息抽取 + 生成式摘要生成”双轨并行的混合架构**。整体计算流程分为四个阶段：

### 第一阶段：数据预处理与文本组装

**输入**：`dwd_policy_base`表中单条政策记录

**处理步骤**：

1. **主文本组装**：将`content`（政策正文）作为摘要生成的主要数据源。若`content`为空或长度不足，则以`abstract`（政策摘要）作为兜底。
2. **元数据关联**：将`title`（政策标题）、`publish_code`（文号）、`ministry`（发文部门）、`publish_date`（发文日期）、`keywords`（关键词）、`theme`（政策主题）、`keypoints`（政策要点）等结构化字段作为摘要生成的**上下文增强信息**，用于引导模型关注重点。
3. **长文本分块**：若`content`超过模型上下文窗口（如超过4096 token），采用**层次化分块策略**（hierarchical chunking），按段落或语义边界切分，保留跨块重叠以维持上下文连贯性。

### 第二阶段：关键信息抽取与结构化增强

此阶段为整个流程的核心，旨在解决通用大模型处理长文本政策时存在的**实体遗漏**和**逻辑断层**问题。

**2.1 实体抽取模块**

从政策全文中抽取以下关键要素：

| 抽取目标             | 对应字段/用途                                      | 技术手段              |
| :------------------- | :------------------------------------------------- | :-------------------- |
| 政策主体（发文部门） | 与`ministry`交叉验证                               | 命名实体识别（NER）   |
| 政策客体（适用对象） | 从`policy_support`中提取`support_object`           | 规则匹配 + NER        |
| 时间要素             | 发文日期、实施日期、失效日期                       | 规则匹配 + 语义解析   |
| 政策主题             | 与`theme`字段交叉验证                              | 主题模型 + 关键词抽取 |
| 扶持目标             | 从`policy_support`中提取支持对象、行为、方式、条件 | JSON解析 + 结构化提取 |

**2.2 关系建模模块**

构建政策文本内部的**语义关联**，梳理公文内在逻辑：

- **句法依存分析**：提取政策文本的依存句法树及依存句法特征，识别核心谓语、宾语结构，定位政策动作（如“支持”“申报”“认定”）与动作对象的关系。
- **引用关系识别**：解析`quote_policy`字段，识别政策间的引用与继承关系。
- **逻辑结构识别**：基于章节标题（如“一、试点示范内容”“二、报送流程”）识别政策的**问题定义→政策目标→具体措施→申报流程**的逻辑链条。

**2.3 关键语句抽取**

集成无监督算法，基于句向量改进的政策文本关键句子抽取策略，对政策全文进行句子重要性排序：

- 计算句子与政策标题的语义相似度
- 计算句子与`keywords`/`theme`的语义相关性
- 基于TextRank算法进行句子图排序
- 融合依存句法特征增强句子表示效果

### 第三阶段：摘要生成

**3.1 生成式摘要（主路径）**

采用**大语言模型（LLM）提示生成**方案，将第二阶段抽取的结构化信息作为**思维链（Chain-of-Thought）引导**注入提示词：

**提示词模板结构**：

text

```
【任务】根据以下政策全文和政策要素，生成一份精炼、可读性强的政策摘要。

【政策标题】{title}
【发文部门】{ministry}
【发文日期】{publish_date}
【关键词】{keywords}
【政策主题】{theme}
【政策要点】{keypoints}
【扶持目标】{policy_support}

【政策全文】
{content}

【生成要求】
1. 摘要控制在300-500字
2. 必须包含：政策背景与目的、主要内容与措施、适用对象与条件、时间节点与流程
3. 语言通俗易懂，便于管理层快速理解
4. 保留原文关键数据、金额、日期等具体信息
```



**模型选型建议**：

- 可选择Qwen2.5-7B等开源大模型进行微调，或直接调用GPT-4/DeepSeek等商用API
- 已有政务实践表明，基于DeepSeek大模型的政策摘要生成可有效“将复杂的政策语言转化为通俗易懂的表述”

**3.2 抽取式摘要（兜底/辅助）**

当生成式模型不可用或需要快速响应时，启用抽取式摘要作为兜底方案：

- 基于第二阶段的关键语句排序结果，选取Top-N句子按原文顺序拼接
- 输出长度控制在200-500字

**3.3 结论生成**

在摘要基础上，额外生成**管理层结论**，包含：

- **政策核心价值**：该政策解决什么问题
- **适用建议**：哪些对象应重点关注
- **行动建议**：申报/应对的关键时间节点和步骤

### 第四阶段：高亮标记与推送

**4.1 关键信息高亮**

基于第二阶段的结构化抽取结果，在生成的摘要和结论中对以下内容进行**自动高亮**：

- **时间节点**（发文日期、申报截止日期等）→ 高亮为橙色
- **金额/数字**（资助金额、比例等）→ 高亮为蓝色
- **适用对象**（企业、高校、研究机构等）→ 高亮为绿色
- **关键动作**（申报、认定、备案等）→ 高亮为红色

**4.2 可编辑结论推送**

- 生成的摘要与结论以**富文本格式**呈现，支持用户在线编辑修改
- 修改记录自动保存，支持版本追溯
- 推送至管理层的报告页或移动端
