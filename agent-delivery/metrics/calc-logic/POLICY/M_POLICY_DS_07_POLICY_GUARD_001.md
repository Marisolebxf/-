## 摘要

「发展战略引导力评估」是《科技信息展示系统》科技创新评估→政策与条件保障力指标展示下的第一个三级指标（§1.1.1.1.4.1.7.4.1），任务是对特定领域的发展战略规划、产业政策文件给出**前瞻性、系统性、针对性**三维评价，让决策者看到「战略规划本身写得清不清楚、接不接得上既有政策、有没有可落地的扶持措施」。需求原文点明了三个维度名，但没有给词表、公式、阈值与字段映射。

本报告采用王惠三维闭集口径，在 `gkx.dwd_policy_base` 20,000 条有效政策上零 SQL 复现：前瞻维标题层命中 **1,085 条（5.42%）**；把正文纳入后命中 **5,783 条（28.91%）**，其中 4,698 条只在正文命中；承接维 `quote_policy` 真实值 **2 条（0.01%）**；扶持维 `policy_support` **0 条**。按「缺维不进平均」合成，得 **2.72 分**（前瞻与承接两维参与）。

这个 2.72 必须谨慎解读。它衡量的是「三个文本标记在一个 2 万条政策库里的平均覆盖率」，不是「政策写得好不好」；而且三维里两维的分子只有个位数，等权平均实际上被前瞻维单独决定。更关键的是，5.42% 是**标题层**命中率，不是「政策是否具备规划属性」的判定——标题写了「规划」不等于规划落地，标题没写也不等于没有规划。能匹配不等于能评价，这是本件最重要的一句限定。结论：**部分支持**。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

本指标挂接《科技信息展示系统和科技专题服务系统》**科技创新评估 → 政策与条件保障力指标展示 → 发展战略引导力评估**（§1.1.1.1.4.1.7.4.1）。其上位模块「政策与条件保障力指标展示」的建设目标是：「通过收集和分析发展战略的引导力、政策扶持力度以及经费与项目支持力度等关键指标，构建政策与条件保障力评估体系」，并与专利—发明人—学者—地域—产业知识图谱结合，形成「不同产业领域的政策环境和支持力度」评估结果。

产品形态是一个**可按领域筛选的三维评分卡**：用户在页面上选定产业领域（如半导体、新能源）后，系统给出该领域战略规划文件在前瞻性、系统性、针对性三个维度上的得分与关键内容摘录，并可下钻查看具体命中的规划名称、引用的上位政策、列明的扶持方式。它是后续「政策与条件保障力综合评估」（`M_POLICY_DS_07_POLICY_GUARD_008`）五维中的第一维输入。

### 1.2 为什么需要本指标

政策保障力评估最容易滑向「数文件」：统计某个领域发了多少条政策、多少件规划。但文件数量回答不了「这些文件是否指向未来、是否互相衔接、是否有可执行的抓手」——而这三点恰是战略规划质量的实质。需求原文把「前瞻性、系统性和针对性」并列为三个评价轴，正是要避免「数量繁荣、质量空心」的评估假象。

从下游看，本指标是综合评估的锚：`M_POLICY_DS_07_POLICY_GUARD_008` 的五维中，引导力维直接读本指标结果。若本指标算不出来，综合评估就只剩「政策数量 × 级别覆盖 × 链接可见度」这类结构性计数，无法回答「保障得够不够好」。从页面看，它也是「政策优化建议」的事实基础：只有指出某领域「缺顶层规划（前瞻弱）」「不引上位文件（系统弱）」「只喊口号无扶持方式（针对弱）」，优化建议才有落点。

## 二、计算过程

### 2.1 方法选择：文本标记率而非专家评分

本件的第一性问题是如何在「没有专家标注、没有质量标签」的条件下给出可复核的三维评价。可选的路径有两条：一条是请专家逐份打分（德尔菲），优点是贴近「质量」构念，缺点是不可批量、不可复现、无法随政策新增而自动更新；另一条是用闭集词表做文本标记，优点是批量、可复核、每个命中都能指到具体字段，缺点是只能测「写了什么」，不能测「做成了什么」。本件选后者，不是因为它更好，而是因为前者在本项目的数据条件下无法落地。

标记法的核心纪律是**口径必须窄且可解释**。前瞻性只认四个词（规划、纲要、远景、行动计划），不扩展到「战略」「布局」「行动」这类高频词，因为后者几乎每份政策都会出现，命中率会趋近 100%，失去判别力。系统性只认 `quote_policy` 非空，不用正文里的「根据《X》」正则，因为正文引用无法区分「引用上位政策」与「提到某个文件名称」。针对性只认 `policy_support.support_way` 的结构化字段，不用正文里的「补贴」「奖励」关键词，因为后者会把「禁止补贴」也算成扶持措施。

### 2.2 步骤 1｜总体、去重与占位符

统计总体是 `gkx.dwd_policy_base` 全表 20,000 行，去重键为 `id`，20,000 个不同值。`status` 全表单一值「有效」，因此不做状态过滤；`is_deleted` 全 0，同样不过滤。占位符按 `UPPER(TRIM(col)) NOT IN ('NULL','','NONE','-')` 清洗，重点是小写 `'null'`——`policy_support` 全表 20,000 行都是这个四字符占位串，若只判 `IS NOT NULL`，会得到一个「20,000 行有值、覆盖率 100%」的假针对性维。

清洗后的真实值：`title` 20,000、`theme` 2、`keywords` 0、`keypoints` 0、`quote_policy` 2、`policy_support` 0。这组数字决定了三维里只有前瞻维的标题字段满量，另两维的分子都是个位数或零。

### 2.3 步骤 2｜前瞻性：四字段退化为单字段

王惠原设计是 `title`/`keywords`/`keypoints`/`theme` 四字段任一命中即计数。本库 `keywords` 与 `keypoints` 都是 0 行，`theme` 只有 2 行且两条都不含四个词，因此实际参与匹配的只有 `title`。标题层命中 1,085 条，占 5.425%。

这个 1,085 必须标明是标题层。为了量化「标题层与全文层的差」，本件把匹配面扩到 `title + content + abstract`，命中升至 5,783 条（28.915%），其中 4,698 条只在正文命中。两层的差值说明：如果只看标题，会漏掉 81% 的正文命中；如果看全文，又会把「正文提到规划」当成「这份政策是规划」。两种口径回答的是不同问题，不能混用。主口径仍按王惠用标题/标签字段，全文层只作敏感性披露。

### 2.4 步骤 3｜系统性：2 条引用与一处截断

系统性取 `quote_policy` 非空率。全表只有 2 条政策有引用：id=18352858 与 id=18394903，都是湖北省科学技术厅的政策。命中率 2/20,000 = 0.01%。

这里有一处数据质量事实必须登记：id=18352858 的 `quote_policy` JSON 数组在库内已截断（末尾缺右括号与后续元素），只能按「有引用」计数，不能按引用条数统计。若把它当完整数组解析，会抛异常并把该政策误判为「无引用」，把 2 条打成 1 条。本件用「非空即命中」的判定，规避了截断问题，但也因此无法给出「平均引用条数」这种更细的指标。

### 2.5 步骤 4｜针对性：整列为空

针对性取 `policy_support` 中 `support_way` 非空的条数。全表 20,000 行 `policy_support` 都是字面 `'null'`，清洗后为 0；即便不清洗，`json.loads('null')` 也返回 `None`，`support_way` 仍为空。因此该维对全部政策返回 0，整维不可算。

这一维不能用正文关键词顶替。「补贴」「奖励」「补助」这类词在政策正文里高频出现，但它们既可能是「给予补贴」也可能是「不得给予补贴」「补贴政策废止」，关键词命中无法区分肯定与否定、现行与废止。更重要的是，需求要的是「精准扶持措施」，即结构化的措施类型与对象，而不是「正文出现过扶持词」。用关键词顶替会把「提到」当成「有措施」，正是本件要避免的「能匹配不等于能评价」。

### 2.6 步骤 5｜合成与缺维处理

三维比率分别为 0.05425、0.0001、0（不可算）。按王惠「缺维不进平均」，只取前两维：

$$G=\frac{0.05425+0.0001}{2}\times 100=2.7175\approx 2.72$$

若把 D3 按 0 纳入分母，得分会变成 1.81，等于用一个「整列没有数据」的维度去惩罚政策体系；这正是缺失值处理里最典型的错误。本件明确不这么做，并在 `out.json` 的 `dims_available` 写 `2/3`，让复核者一眼看到分母。

### 2.7 复现代码与结果展示

执行 `cd code && python3 M_POLICY_DS_07_POLICY_GUARD_001.py`，零 SQL、0.51 秒，读取政策快照、正文快照与补充探针，覆盖写出 `code/M_POLICY_DS_07_POLICY_GUARD_001_out.json`。脚本不连数据库、不 import 任何本地 helper。

|---|---|---|

| `dims[D1].hit` | 1,085 | 标题层前瞻命中 |
| `dims[D1].rate_pct` | 5.425 | 前瞻率 |
| `dims[D2].hit` | 2 | 引用命中 |
| `dims[D2].rate_pct` | 0.01 | 承接率 |

### 2.8 结果解读：2.72 分不是质量分

2.72 的构成是 5.42% 与 0.01% 的等权平均。前者是标题里出现四个规划词之一的比例，后者是库内有引用记录的比例。两个比率都不是「质量」：标题写「规划」可能是一份转发通知，有引用记录可能只是复制了文件名。把它们平均成一个 0—100 的分数，会制造一种「政策前瞻性只有 2.72 分」的错觉。

正确的读法是分维读：前瞻维 5.42%（标题层）、承接维 0.01%、扶持维不可判。三个数放在一起，能回答的是「这份语料在文本层几乎没有规划语汇与引用记录」，不能回答「政策体系好不好」。页面上如果只能放一个数，应放「三维完备度 2/3」而不是 2.72 分。

### 2.9 边界条件与异常值

第一，标题长度极短的公示公告可能天然不含规划词，会被判为「前瞻弱」，这是标记法的系统性偏差，不是政策问题。第二，正文层命中 4,698 条只在正文出现，说明「标题不含规划词」不等于「正文没有规划内容」；若甲方要求「政策是否具备规划属性」，必须用全文层并配合人工抽样校验。第三，`quote_policy` 截断记录只能按「有/无」计数，不能算条数。第四，`theme` 2 条政策的主题都不含四个词，前瞻维实际上完全由标题决定，主题字段对本件没有贡献。

### 2.10 权重与口径的敏感性

本件采用「可算维等权」，这是缺省，不是共识。把权重或口径改动一点，分数就会大幅漂移：

| 口径 | 计算式 | 分数 | 说明 |
|---|---|---:|---|
| 本件（标题层，等权） | (5.425 + 0.01) / 2 | 2.72 | 2/3 维 |
| 全文层替代标题层 | (28.915 + 0.01) / 2 | 14.46 | 前瞻维换算法 |
| 前瞻维权重 2 : 承接维 1 | (2×5.425 + 0.01) / 3 | 3.62 | 主观加权 |
| 只保留前瞻维 | 5.425 | 5.43 | 单维 |
| 三维全算（针对性记 0） | (5.425 + 0.01 + 0) / 3 | 1.81 | 用缺数惩罚 |

这张表说明：2.72 不是「政策引导力」的唯一度量，它是「标题层前瞻率与引用率等权平均」这一特定口径的结果。换一个同样合理的口径，分数可以在 1.81 到 14.46 之间变动，相差 8 倍。发布时若只给 2.72 而不给口径，读者无法判断这个数是「政策弱」还是「口径严」。

本件选标题层而非全文层，理由是标题是政策的正式名称，代表发文者的自我定位；正文含规划词可能只是引用了他省规划。这个选择有道理，但不是唯一正确；若甲方更关心「文本里有没有规划内容」，应改用全文层，并在页面上同时披露两个数。

### 2.11 与 169 / 170 的口径衔接

本件与 169（政策力度）、170（政策机遇）共用 `dwd_policy_base` 20,000 条分母，但三者的前瞻性口径不同：169 用多字段加权，170 用五子指标，本件用标题单词标记。三种口径产出的「前瞻率」不可直接比较，也不可在同一张图上画三条线。

衔接方式是：页面上把本件的 5.42% 标注为「标题规划词命中率」，把 170 的机遇分标注为「综合机遇分」，两者各自带口径注脚；若要做趋势对比，必须先统一到同一字段集，否则对比的是口径差异而不是政策差异。

### 3.4 「文本标记率」与「专家评分」的距离

需求把「引导力」写得像一个可评的质量属性，本件给的是一个文本标记率。两者之间隔着三层：

第一层是**语义**。标题含「规划」不等于这份政策有战略视野，可能只是转发上级规划；标题不含规划词不等于没有战略内容，正文可能有。标记法只能测字面，不能测意图。

第二层是**主体**。政策引导力取决于发文机关层级、政策工具强度、执行资源，这些在文本里可能提到，也可能完全不提。本件只统计「有没有出现规划词」，没有区分国务院文件与县级通知。

第三层是**后果**。引导力最终要看政策是否改变了主体行为，这需要执行数据与对照，本库没有。文本标记率与政策效果之间没有可验证的映射。

因此本件的 5.42% 只能叫「标题规划词命中率」。若甲方要的是「专家对政策引导力的评分」，必须另建标注集、另定评分量表，不能用本件的数替代。这一点在 §4.2 已列为「不能说的话」，在此再强调一次，因为它是本件最容易被抬档的地方。

### 3.5 三个字段的「字面 null」问题

`policy_support` 的 20,000 行不是空字符串，而是字面字符串 `'null'`。这两种情况在工程上必须分开处理：空字符串可以直接 `TRIM(x)=''` 判空，字面 `'null'` 会被 `IS NOT NULL` 判为「有值」，从而在统计里被误计为覆盖。本件在快照清洗阶段对 `'null'`、`'NULL'`、`'None'` 三种大小写形态统一剔除，剔除后 `support_way` 有效值为 0。

同样的坑存在于 `theme` 与 `quote_policy`：若只按 `IS NOT NULL` 统计，两列都会显示 20,000 行覆盖，实际有效值分别只有 2 行。§3.2 的「非占位符行数」一列就是按剔除占位符后的口径统计的，读者不应拿它和「非空行数」混用。这也是本件把 `data_support_level` 判为「部分支持」而非「完全支持」的技术依据之一：字段在，但值是占位符，语义上等于没有。

这一点还影响下游：171 复用本件的 `quote_policy` 计数时，若不清洗会把 20,000 当成引用总数，进而把「系统性」维算成 100%。本件在快照层就完成清洗，下游直接读有效值，避免同类错误扩散。

## 四、数据缺失情况

### 4.1 缺口清单

| # | 缺口 | 影响维度 | 后果 | 修复路径 | 优先级 |
|---|---|---|---|---|---|
| 1 | `policy_support` 全表 0 行 | 针对性 | 整维不可算 | 结构化抽取扶持方式 / 接政策工具标签 | 高 |
| 2 | `quote_policy` 2 行且 1 行截断 | 系统性 | 引用网络不可构建 | 补采政策间引用关系 / 修 JSON | 高 |
| 3 | `keywords`/`keypoints` 0 行 | 前瞻性 | 四字段退化为单字段 | 关键词抽取或第三方标签 | 中 |
| 4 | `theme` 2 行 | 前瞻性 / 领域筛选 | 无法按主题或领域切分 | 主题标注 | 高 |
| 5 | 无领域字段 | 领域筛选 | 无法出「分领域评分卡」 | 建政策—产业领域映射 | 中 |

### 4.2 后果归因：哪些话不能说

第一，不能说「政策前瞻性只有 5.42%」。5.42% 是标题命中率，不是政策属性；全文层是 28.91%，两者差 5 倍。第二，不能说「政策体系不承接上位政策」。`quote_policy` 只有 2 行，0.01% 是采集缺口，不是承接水平。第三，不能说「政策没有扶持措施」。`policy_support` 整列为空，是字段未铺数据，不是政策没写。第四，不能说「2.72 分说明引导力弱」。分数被两维近零值拖平，且分母只有两维，不能当质量分。

第五，不能把「能匹配」当成「能评价」。标题含「规划」只证明文本里出现了这个词，不证明这份政策真的在做规划；正文含「补贴」只证明出现了这个词，不证明有补贴措施。标记法的产出是「文本特征覆盖率」，不是「政策效果」。第六，不能把「未命中」当成「不存在」。标题没写规划词的政策，正文可能有大段规划内容（实测 4,698 条），把它判为「无规划」会系统性低估。第七，不能把「三维等权」当成「三维同等重要」。需求没有给权重，等权是缺省，不是共识；若甲方认为针对性更重要，权重必须重新裁决。

### 4.3 判档说明

本件判「部分支持」而不是「完全转换支持」，核心证据是针对性维整列为空：`policy_support` 20,000 行全是字面 `null`，`support_way` 一条都取不到。按 §〇 的定义，「完全转换支持」要求「现在就能经转换得到」，而这一维不是转换能补出来的，是要补采或做结构化抽取的数据。

若强行判「完全直接支持」，甲方按 §三 核验时会发现针对性维永远为 0、系统性维只有 2 条，反而损害可信度。降档并写清「哪一维能算、哪一维不能算」，比给一个看起来完整的三维评分更诚实。

### 4.4 缺口对结果的量化影响

若 `policy_support` 从 0 补到可用规模，针对性维会从「不可算」变成真值，三维得分才第一次有完整分母；若 `quote_policy` 从 2 条补到可用规模，系统性维才会从 0.01% 变成有意义的比率；若 `keywords`/`keypoints` 补齐，前瞻维才会从单字段恢复为四字段，命中率可能上升也可能下降（取决于标签质量）。

这三项修复会改变 2.72 这个分数，而不是只增加新维度。因此当前分数只能作「占位」，不能作「基线」；任何「今年 2.72、明年 5.0」的同比叙事都不成立。页面在此之前应显示「三维完备度 2/3」，并把不可算维标成灰色，而不是给一个完整的三维雷达图。

### 4.5 领域筛选缺口对页面形态的连带影响

需求原文的第四个维度是「领域筛选」：按产业领域分别评估政策引导力。本库没有「政策—产业领域」映射字段，`theme` 只有 2 行，无法切分领域。这个缺口不是少一张图，而是改变了页面形态：

| 需求形态 | 当前可行形态 | 差异 |
|---|---|---|
| 分领域评分卡 | 单一总体评分 | 无法比较领域间差异 |
| 领域排名 | 无排名 | 无分母，排名无意义 |
| 领域趋势 | 无趋势 | `publish_year` 2022 后为残片 |
| 领域下钻 | 无下钻 | 无映射表 |

因此本件只能给「全库总体」的 2.72 分（或分维的 5.42% / 0.01%），不能给「某领域引导力」。若甲方坚持要分领域，必须先建映射表：一条政策可能对应多个领域，映射表需要「政策 id × 领域 id」的多对多结构，而不是在政策表上加一列。这是本件在上线前 TODO 里把「建政策—产业领域映射」列为中优先级的理由。

在映射表落地前，页面上的领域选择器应置灰并给出提示「领域口径待建」，不能默认返回全库数据却显示成某个领域的结果。后者是最常见的误导：用户选了「新能源」，页面仍显示全库 2.72 分，用户会以为这是新能源的引导力。置灰虽然不好看，但不会造假。

同样，分领域导出功能也应一并关闭。导出的 CSV 若只有全库一行、却在文件名里写「新能源领域」，流到管理层手里就是一份错误证据。关闭导出比事后解释便宜得多。

等映射表建成、领域覆盖率达到可解释水平后，再逐项打开选择器与导出；打开的先后顺序应按「映射覆盖率」而不是按页面排期，否则会重复出现「有按钮、无数据」的假功能。

映射覆盖率本身也应成为发布门禁：低于 60% 时只开「全库」视图，60%—90% 时开选择器但标注「部分领域未覆盖」，90% 以上才允许导出分领域报表。没有这条门禁，领域功能会随补数进度反复回退。

门禁阈值可由业务方调整，但「有门槛」这件事不能省；否则页面能力会先于数据成熟度上线。

## 五、结论与发布建议

### 5.1 结论

本件方法可复现、脚本可在本目录直接跑通、每个命中可追溯，但**不具备发布三维评分的业务条件**。可发布的内容是：前瞻维标题层与全文层两个命中率、承接维 2 条引用明细、扶持维不可算的说明、三维完备度 2/3。不可发布的内容是：单一「引导力得分」、跨领域排名、任何「政策质量」结论。

### 5.2 发布建议

第一，页面用「三维分列」而不是「一个总分」：前瞻 5.42%（标题）/ 28.91%（全文）、承接 0.01%、针对性不可判。第二，总分位置显示「2.72（2/3 维）」并加注「缺维不进平均，分数不可跨库比较」。第三，前瞻维必须同时给标题层与全文层两个数，并标注匹配面；只给一个数会让用户误读。第四，与 `M_POLICY_DS_07_POLICY_GUARD_008` 联动时，综合评估必须同时读「完备度 2/3」，否则会把一个缺维分数当完整输入。

## 附录 C　构建方法可行性报告（完整版）

**一、可复制的方法路径。** 战略规划质量评估有三条可复制路线：官方衔接审查（看规划是否与既有政策衔接）、战略导向评估（看规划是否明确指导方针与目标）、文本标记计量（看文本是否出现特定语汇）。前两条是制度要求，第三条是可操作化手段。本件把三条串起来：用文本标记测「写了什么」，用制度要求解释「为什么这三类标记重要」，但不声称标记率等于质量。

**二、为什么不做专家评分。** 德尔菲法能测质量，但要求专家逐份阅读、独立打分、多轮收敛，成本高且不可复现；本库 20,000 条政策，任何专家团队都无法全量评分。更关键的是，专家评分没有留痕，复核者无法判断某个分数是怎么来的。标记法虽然粗，但每个命中都能指到标题或字段，复核成本低。

**三、阈值与匹配面的取值依据。** 本件不设阈值，三维直接合成；匹配面按王惠用标题/标签字段，另做全文层敏感性。词表只取四个低歧义词，是为了避免高频词把命中率推到 100%。若甲方要求「政策是否具备规划属性」，应改用全文层并配合人工抽样，不能用标题层直接代替。

**四、结论。** 本件方法在本库条件下可行且可复算，能支撑「前瞻维标题/全文两率 + 承接维明细 + 三维完备度」，不能支撑「单一引导力得分 / 跨领域排名 / 政策质量结论」。若甲方需要后者，需先补 `policy_support` 与 `quote_policy`，届时三维可直接全量复算。
