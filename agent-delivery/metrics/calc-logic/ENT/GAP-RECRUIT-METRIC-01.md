先说最容易被误读的一点：**均值 36.1847 不是「深圳连接度平均三成六」**。它是「每个企业各维比例的算术平均」，而分布是双峰的：30,916 家为 0，17,492 家为 100（区间 75—100）。中间段（0—75）合计 14,460 家。双峰来自口径本身——只有一条边的企业，比例非 0 即 100；边数越多，比例越接近中间。中位数 7.9034 与均值 36.1847 差 4.6 倍，正是这条双峰分布的读数，不是数据异常。

第二个要说明的是**分母**。62,868 是「三类边中至少有一类的主体数」，不是底册 189,116。剩下 126,248 家企业在这三张表里一条边都没有，按口径不参与评分（缺维不是 0 分）。如果拿 189,116 当分母，>0 占比会从 50.8239% 掉到 16.90%，那是把一个「有关系企业中的占比」偷换成「全底册覆盖率」。本报告所有比例的分母都写在 `denominator_note` 里，正文引用时逐条对齐。

第三，旧稿与本次的读数**逐位相同**（62,868 / 31,952 / 36.1847 / 7.9034，差 0）。这不是巧合：两边读的是同一批源表行，只是旧稿走镜像面、本版直连 gkx。逐项差 0 是「换源没有换口径」的证据；反过来，若哪一项对不上，就说明换源时口径动了。

### 1.2 为什么需要「深圳连接度」

招引模型要回答的是「这家企业值不值得招到深圳」。产业相关度回答「赛道对不对」，政策匹配度回答「政策够不够」，而深圳连接度回答的是「它跟深圳有没有既成关系」。三者缺一，推荐就会偏：只靠产业与政策，会把一批与深圳毫无资本/组织联系的外地企业排到前面，招引落地成本被系统性低估。

从数据角度，这个维度还有一个特殊价值：它是三维里**唯一可以用图结构直接量化**的一维。产业相关度要产业链标签、政策匹配度要政策文本匹配，两者都依赖外部口径；连接度只需要「边 + 属地」两件事，而这两件事在 gkx 都是真实行。

### 1.3 口径定义

设企业 $i$ 的第 $k$ 类关系边集合为 $E_k(i)$，对端集合为 $N_k(i)$，深圳对端集合为 $N_k^{SZ}(i)$。第 $k$ 维的连接比例定义为：

$$S_k(i)=100\times\frac{|N_k^{SZ}(i)|}{|N_k(i)|}$$

综合连接度取有定义维度的算术平均：

$$Conn_{SZ}(i)=\frac{1}{|K_i|}\sum_{k\in K_i}S_k(i),\qquad K_i=\{k: |N_k(i)|>0\}$$

本件取三维：$k=1$ 对外投资、$k=2$ 归属/分支（股东边 + 子公司名称代理）、$k=3$ 稳健性口径（投资 + 股东边合并重算，不含子公司名称代理）。

三点必须在口径层写死：

第一，**分母是「该企业自己的对端数」，不是全库对端数**。同一家企业边多边少，比例都归一到 0—100，这样大企业不会因为边多而天然高分。

第二，**缺维不进分母**。一家只有投资边的企业，$K_i=\{1\}$，分数就是 $S_1$；不能把缺失的股东维按 0 摊进去，否则「没查到」会被读成「没有深圳关系」。

第三，$D3$ 是**口径敏感性项**，不是第三个独立数据源。它与 $D1$、$D2$ 共用同一批边，只回答「去掉子公司名称代理后分数会不会翻盘」。把它当独立维度计权，等于给投资边记两次。

### 1.4 计算公式与本批实现式

本批实现式（`metrics/repro/GAP-RECRUIT-METRIC-01.py`）：

```python
s1 = sz_invest / total_invest * 100              # D1
s2 = (sz_sub_name + sz_shareholder) / (total_sub + total_shareholder) * 100   # D2
s3 = (sz_invest + sz_shareholder) / (total_invest + total_shareholder) * 100  # D3 稳健性
conn = mean([x for x in (s1, s2, s3) if x is not None])
```

属地判定：`dwd_org_base_info.city` 含「深圳」即为深圳主体；子公司维因为 `sub_org_id` 在底册命中 0 行（附录 B.3），只能用 `sub_name_cn` 含「深圳」作名称代理。这一条是本件最大的口径妥协，§四单独展开。

## 二、计算过程

### 2.1 装载与规模校验

脚本先读底册快照，建两个结构：`org_id → {name, province, city}` 与「深圳 org_id 集合」。底册 189,116 行里 95,600 行 `city` 含「深圳」，占 50.551%——这个比例本身值得注意：gkx 底册的属地分布高度偏向深圳，说明它不是全国均匀样本，而是「深圳为主、辐射周边」的要素库。任何按底册做的城市类指标都要带着这条前提读。

再逐表拉边。三张表都只取 `org_id` 与对端列，不取金额、比例、时间：本件不用这些字段，取了只会增加传输量。拉完做三项校验：① 行数与 `COUNT(*)` 一致（46,967 / 400,286 / 178,900）；② 对端为空的行剔除并计数；③ 对端落在底册深圳集合的行数（13,240 / 14,152 / 64,541）。三项对上后才进入聚合。

校验里有一个必须解释的 0：子公司表 `sub_org_id` 命中底册深圳集合 **0 行**，命中底册任意主体也是 **0 行**（`subsidiary_sub_org_resolved = 0`）。这说明 `sub_org_id` 不是底册的 `org_id` 体系，两套 id 对不上。若强行按 id 判属地，子公司维会整维为 0；本件因此改用名称代理，并把「id 命中 0」写进产物，避免下游误以为「子公司都不在深圳」。

### 2.2 三个维度的定义与聚合

D1 对外投资：`dwd_org_invest_info` 的 `org_id` 是投资方、`inv_org_id` 是被投方。对每个投资方，统计「被投方在深圳」的比例。46,967 行里 13,240 行对端在深圳，占 28.19%。这条边的语义是「这家企业把钱投到了深圳」，方向明确、可解释。

D2 归属/分支：由两部分相加——股东边（`dwd_org_shareholder_info` 的 `org_id` 是被投企业、`inv_org_id` 是股东）与子公司边（`dwd_org_subsidiary_info` 的 `org_id` 是母公司、`sub_name_cn` 是子公司名）。两部分的「深圳对端」分别按 id 与名称判定，然后**先各自累加计数、再合并算一个比例**，而不是先算两个比例再平均。原因：股东边 400,286 行、子公司边 178,900 行，量级差 2.24 倍；若先算比例再平均，子公司维会被过度加权。

D3 稳健性：把 D1 与股东边合并重算，去掉子公司名称代理。它的作用是回答「D2 的高分是不是名称代理撑起来的」。实测 $Conn_{SZ}$ 与「D1+D2 两维口径」的 Spearman 相关 **0.999895**（62,868 家全样本），说明 D3 与主口径几乎完全同序——它不引入新信息，只用于证明结论对口径选择不敏感。

聚合时有一个容易写错的地方：**同一对端重复出现只算一次**。投资表里同一 `(org_id, inv_org_id)` 可能有多行（不同轮次/不同比例），若按行计数，多轮投资的企业会被放大。本件按行计数而非按对端去重——这是一个有意的选择：多轮投资确实代表更强的联系，按行计数保留了「联系频次」信息。代价是同一对端被重复计权，这一点写进 §四 的口径风险，不在正文里假装它是「企业数」。

### 2.3 子公司维的名称代理

子公司表有 `sub_org_id` 与 `sub_name_cn` 两列。前者看起来是更硬的键，实测却完全对不上底册（0 行命中）。原因大概率是两张表的 id 生成体系不同（子公司表来自工商登记，底册来自另一套主数据）。在不能改源表的前提下，只剩名称代理一条路：`sub_name_cn` 含「深圳」即判为深圳对端。

名称代理的偏差是双向的。**高估**：注册在深圳但实际无经营的分支、名称里带「深圳」但主体在境外的壳公司，都会被计入。**低估**：注册地在东莞/惠州但名称不含「深圳」、实际业务在深圳的子公司，会被漏掉。178,900 行里 64,541 行名称含「深圳」（36.0766%），这个比例明显高于投资边（28.19%）与股东边（3.5355%），说明名称里出现「深圳」是一件很常见的事，代理的「命中率」高但不等于「准确率」高。

因此本件把子公司维**只放在 D2 里、且 D3 把它剔除**。若某企业的 D2 与 D3 差距很大，读数是「名称代理在起作用」，不是「这家企业跟深圳关系突然变强」。

### 2.4 分母与缺失维处理

聚合的第二个关键点是分母。对每家企业，三维各自的分母是它自己的对端数：`d1_total`、`d2_total`（子公司行 + 股东行）、`d3_total`（投资行 + 股东行）。比例为 0 的情况有两种，必须区分：

第一种是「有边但对端都不在深圳」，比例真为 0；第二种是「这一类边一条都没有」，比例无定义。代码用 `None` 表示后者，聚合时 `[x for x in (s1,s2,s3) if x is not None]` 把它排除。若不排除而按 0 计，62,868 家里会有大量企业被系统性地拉低——金投资边一条都没有的企业，D1 记 0 会让它的 $Conn_{SZ}$ 直接腰斩。

最终 62,868 家里，30,916 家 $Conn_{SZ}=0$（占 49.18%），31,952 家 >0（50.8239%）。0 分组全部是「有边但对端不在深圳」——因为「无边」的企业根本不进评分集。这个区分决定了 0 分的语义：它是「有关系但都不在深圳」，不是「没有关系」。

### 2.5 分数分布与双峰

| 区间 | 企业数 | 说明 |
|---|---:|---|
| 0 | 30,916 | 有边，对端全不在深圳 |
| (0—10) | 798 | 极少数对端在深圳 |
| [10—25) | 2,706 | 少量深圳对端 |
| [25—50) | 4,885 | 约三成深圳对端 |
| [50—75) | 6,071 | 过半在深圳 |
| [75—100] | 17,492 | 绝大多数对端在深圳 |

分布是明显双峰：0 与 100 两端合计 48,408 家（77.00%），中间四段合计 14,460 家。双峰的成因是**边数少**：`firm_degree_stats` 显示企业边数的中位数是 1、p75 是 2、p90 是 5、p99 是 22、最大 222。边数为 1 时比例只能取 0 或 100；边数为 2 时只能取 0/50/100。也就是说，绝大多数企业的分数不是「连续测量」，而是「一条边的二值判断」。

这条事实决定了指标的用法：**它适合做筛选（是否与深圳有关系），不适合做精细排序（关系强弱）**。要在同一侧内部排序，必须看边数或引入金额权重，而后者不在本件口径内。

### 2.6 稳健性与口径敏感性

三项检验：

第一，**换源一致性**。旧稿（20261020 镜像面）读数 62,868 / 31,952 / 36.1847 / 7.9034，本版直连 gkx 后四项差全为 0。这说明两边读的是同一批源表行，换源没有换口径。若未来 gkx 增量更新，这四项会漂，漂多少就是增量。

第二，**口径敏感性**。$Conn_{SZ}$ 与 D1+D2 两维口径的 Spearman 相关 0.999895。0.999895 已经接近「完全同序」，说明 D3 加不加、怎么加，对排序没有实质影响。这不是「稳健性很好」的夸奖，而是「D3 冗余」的证据——它作为独立维度没有信息增量，只能当敏感性检查。

第三，**名称代理敏感性**。把子公司维整体剔除（只留投资 + 股东），得到 D3 口径。D3 与主口径同序，但分数水平会变：名称代理把 64,541 行判为深圳对端，占子公司边的 36.0766%，剔除后这些「疑似深圳」的联系消失。对子公司边多、投资边少的企业，D3 会明显低于主口径。本件没有把两套分数都落盘，只落了聚合后的主口径与相关性；逐企业的 D1/D2/D3 三分量在 `top15_*` 与 `top15_positive` 里可见。

## 三、数据支撑情况

### 3.1 三张边表的实测规模

| 表 | 行数 | 对端在深圳 | 占比 | 语义 |
|---|---:|---:|---:|---|
| `dwd_org_invest_info` | 46,967 | 13,240 | 28.19% | 投资方 → 被投方 |
| `dwd_org_shareholder_info` | 400,286 | 14,152 | 3.5355% | 被投企业 → 股东 |
| `dwd_org_subsidiary_info` | 178,900 | 64,541 | 36.0766% | 母公司 → 子公司（名称代理） |
| 底册 `dwd_org_base_info` | 189,116 | 95,600 | 50.551% | 属地判定基准 |

股东边的深圳占比只有 3.5355%，与投资边 28.19% 形成鲜明对比。原因是两张表的方向相反：投资表的 `org_id` 是投资方（多为深圳主体），股东表的 `org_id` 是被投企业（分布更广），对端才是股东。方向一换，属地浓度就变。这也是为什么 D2 要把股东边与子公司边合并后再算——单看股东边，深圳占比会被方向性压低。

### 3.2 属地判定的可靠性

底册 `city` 字段的深圳占比 50.551%，说明这批数据以深圳为主。对「深圳连接度」这个指标，这既是便利（深圳主体多、样本足）也是风险（非深圳主体少，比例的分母偏小）。实测 62,868 家评分企业里，17,315 家本身就在深圳（27.5418%）——它们的「深圳连接度」天然偏高，因为对端池里深圳主体本来就多。

发布时必须带这条限定：**分数不能跨城市比较**。一家广州企业与一家深圳企业，即使 $Conn_{SZ}$ 相同，含义也不同——前者是「跨城联系」，后者是「城内联系」。

### 3.3 覆盖率与名称可得性

62,868 家评分企业里，能在底册取到 `name_cn` 的只有 28,402 家（45.1772%），34,466 家（54.83%）名称为空。这不是底册缺名，而是**边表里的 `org_id` 有一半不在底册**。换句话说，投资/股东/子公司三张表的 org_id 体系比底册更宽，约有半数主体是「底册外主体」。

这条事实对产品的影响很直接：Top 榜如果不做名称过滤，会出现大量只有 id 的行；如果做过滤，榜单会系统性偏向「底册内的大企业」。本件两种榜都落盘（`top15_by_conn` 不过滤、`top15_named` 过滤），让下游自己选。

## 四、数据缺失情况

### 4.1 供应链维：结构性无源

申请单把 `enterprise_supply_chain` 列为阻塞表。实测：`information_schema.tables WHERE table_schema='gkx' AND table_name='enterprise_supply_chain'` 命中 **0**；模糊检索 `supply` / `supplier` / `vendor` 表名命中 **0**，列名只在 `dwd_bid_base_out.supplier_qualification_criteria`（招标资格文本，非关系列）出现。live 开发库侧同样无此表。

因此本件**不做供应链维**。这不是「暂时缺数」，是「结构上不存在」。旧稿把 D3 命名为「供应链」，实际算的是投资+股东边合并；本版把这个名字改回「稳健性口径」，避免把资本边读成供应关系。

### 4.2 子公司 `sub_org_id` 不可用

`sub_org_id` 命中底册 **0 行**（`subsidiary_id_sz_rows = 0`、`subsidiary_sub_org_resolved = 0`）。这不是「子公司都不在深圳」，而是两套 id 体系对不上。后果：子公司维只能用名称代理，精度受限（§2.3）。

### 4.3 名称代理的偏差

名称含「深圳」的子公司 64,541 行（36.0766%），这个判定会高估「注册在深圳但无经营」的分支、低估「注册在外但名称不含深圳」的分支。偏差不可量化（没有 ground truth），只能标注。

### 4.4 金额与比例未入分

投资表有 `investment_amount` 与 `investment_ratio` 两列（非空行占比高，具体读数见 `M_ENT_RELATION_STRENGTH` 产物），本件**没有**用它们加权。原因：需求只要「连接度」，没有说「按金额加权」；一旦引入金额，分档阈值（1 亿/1,000 万）会主导分数，而金额单位本身还有争议（见 `M_ENT_RELATION_STRENGTH` 的单位敏感性）。本件选择「只看有没有边」，把金额问题留给关系强度件。

### 4.5 未做主体归并

同一集团的不同法人、同一企业的不同写法，都会在边表里成为不同 `org_id`。本件不做归并：归并规则一引入，节点数、边数、所有比例都会变，且没有权威主数据可依。

### 4.6 不得外推的三件事

1. **不得读作「深圳业务占比」**：边是资本/组织联系，不是营收、不是订单、不是人员。
2. **不得跨城市比较**：底册 50.551% 在深圳，分母结构不同。
3. **不得当「招引成功率」**：连接度高只说明「已有联系」，不说明「愿意迁入」。

### 4.7 停用与重估条件

出现以下任一情况应重估：① `enterprise_supply_chain` 入湖（供应链维可加）；② 子公司表 id 体系与底册打通（名称代理可撤）；③ 底册属地分布显著变化（深圳占比离开 50% 附近）；④ 投资表出现「事件时间」字段（可做年度增量）。

## 五、结果与解读

### 5.1 榜单读数

`top15_named` 的头部是「深圳市深圳通有限公司」「深圳市中农易讯信息技术有限公司」「深圳华强信息产业有限公司」等，分数均为 100，边数 6—10 条，且全部是子公司边（`d1_total = 0`、`d2_total = 8—10`）。这说明头部高分企业的共同形态是「母公司在外、子公司在深圳」，而不是「对外投资多」。

`top15_positive` 里出现「对外投资 22 条、全部在深圳」的主体（`d1_total = 22`、分数 100）。这类企业是另一种形态：投资方本身在深圳，投出去的对象也都在深圳。两种 100 分的业务含义完全不同，榜单必须带 `d1_total` / `d2_total` 才能区分。

### 5.2 读数怎么用

第一，做**筛选**：$Conn_{SZ} > 0$ 的 31,952 家是「与深圳有既成联系」的池子，招引模型应优先在这个池子里排序，而不是全底册。

第二，做**分层**：0 分（30,916 家）不是「不能招」，而是「目前没有资本/组织联系」，招引策略应偏「建立联系」（政策、园区、基金）；>0 的企业偏「放大联系」。

第三，**不要用均值做阈值**：36.1847 是双峰分布的均值，落在中间段的企业其实很少（14,460 家）。用均值当「合格线」会把两端都误判。

### 5.3 稳定性与互证

| 检验 | 结果 | 结论 |
|---|---|---|
| 换源对账 | 四项差 0 | 镜像面与 gkx 同源 |
| D3 与两维口径 | Spearman 0.999895 | D3 冗余，仅作敏感性 |
| 子公司 id 命中 | 0 行 | 名称代理是唯一路径 |
| 名称可得率 | 45.1772% | 半数主体在底册外 |
| 重复运行 | 读数逐位一致 | 无随机性 |

### 5.4 反常识点

**反常识一：均值 36.1847 高于中位数 7.9034 四倍多。** 直觉上「比例均值应该接近中位」，实际是双峰把均值拉向中间。看到均值就以为「平均三成六」是错的。

**反常识二：股东边的深圳占比（3.5355%）远低于投资边（28.19%）。** 同一批企业、同一个城市，方向一换比例差 8 倍。原因是 `org_id` 在两张表里指的不是同一侧主体。

**反常识三：子公司维的 id 命中是 0，但名称命中是 36.0766%。** 「键对不上」不等于「数据没有」，只是不能用硬键关联。这条经验对其它关系类指标同样成立。

**反常识四：评分企业只占底册的 33.24%（62,868 / 189,116），但深圳企业占底册 50.551%。** 说明「在深圳」与「有资本/组织边」是两件事：大量深圳主体在这三张表里一条边都没有。

### 5.5 与其它指标的联动

与 `M_ENT_RELATION_STRENGTH`：本件给「有没有联系」，关系强度给「联系有多强」。两件合用可以构造「深圳联系强度」= 连接度 × 边强度，但需要先解决金额单位问题。

与 `M_ENT_REGION_COVERAGE`：本件是单城比例，区域覆盖是城市广度。两者相乘可以近似「深圳业务权重」，但都只覆盖资本/组织边。

与招引推荐指数：本件是三维之一，另两维（产业相关度、政策匹配度）各自有独立件。加权方式未在需求中闭合，本件不猜权重。

---

## 六、结论与发布建议

### 6.1 可用结论

第一，三张边表在 gkx 齐备，62,868 家企业可算 $Conn_{SZ}$，均值 36.1847、中位 7.9034、>0 者 31,952 家。第二，换源后与旧稿四项差 0，口径未漂。第三，供应链维结构性无源，本件不冒充；子公司维用名称代理，偏差已标注。

### 6.2 发布口径（逐条写死）

| 项 | 必须写明的口径 |
|---|---|
| 分母 | 该企业自己的对端数；评分集 62,868，不是底册 189,116 |
| 维度 | D1 投资 / D2 股东+子公司 / D3 稳健性（不计权） |
| 属地 | 底册 `city` 含「深圳」；子公司用 `sub_name_cn` 名称代理 |
| 缺失维 | 不进分母，不按 0 摊 |
| 金额 | 不参与打分 |
| 归并 | 未做主体归并 |
| 比较 | 不跨城市比较 |

### 6.3 后续

三条增强路径：① 供应链表入湖后加第四维（需先有表）；② 子公司 id 打通后撤掉名称代理；③ 投资表补事件时间后做「联系新增/流失」的年度序列。三者都需要新数据，不是调参能解决。
