## 摘要

「历年新增企业数」数的是每一年新登记了多少家企业。判定锚是注册日期，不是入库时间，也不是首次经营时间——注册日期是主档的原生 DATE 字段，语义与市场监管部门的「统计期内完成登记注册」同构。

实测国内主档 189,116 行，注册日有效 188,762（99.81%），空日期 354 行不进分组；国外主档 20,000 行，注册日有效 16,037（80.19%），空日期 3,963 行同样不进分组。两侧并集后 1980—2026 共 47 年，累计 201,807 家。

序列的形态很清楚：1980 年代每年两位数到百位数，1992 年跳到 415 家，2000 年过千，2014 年过万，2016 年见顶 14,069 家，之后逐年回落，2025 年 3,062 家。峰值年与回落节奏与全国新设企业的大势同向，但量级不可比——本库是登记全集的子集，只能做形态对表。

一个必须写在最前面的坑：国外样本在 2007—2011 有一个 1,345—2,823 的高台，2012 年骤降到 104，这是样本灌入口径造成的断层，不是真实的新设波动。这条断裂已在 §四 单列，使用时不能把 2007—2011 的国外数当趋势。

结论是**完全转换支持**：结构与数据都够、47 年序列已现转落盘，缺的只是目标结果表；国外 `country` 全空只影响「按国家拆分」，不影响「按年计数」这一主口径。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业分析 → 企业总览 → 历年新增企业数**。页面形态是一条年度柱状图加一条累计曲线，鼠标悬停显示当年家数与同比；另有一个「近五年」小卡，显示最近五个完整年的合计。

它是存量指标的流量对偶：企业总数是存量切片，本件是流入流量。产品上「盘子多大」看总数，「盘子长多快」看本件。两者不能互相替代——一家企业注销后仍计入历史新增，但不再计入当前存量。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业分析 → 企业总览 → 新增趋势 |
| 页面载体 | 年度柱状图 + 累计曲线 |
| 输出形态 | 年 → 国内 / 国外 / 合计 / 累计 / 同比 |
| 更新频率 | 建议季度（年度序列，季度刷新足够） |
| 粒度 | 年（注册日派生） |

### 1.2 为什么需要这个指标

第一，它是营商环境的第一流量信号。存量数字变化太慢，一年只动几个百分点；新登记数直接响应政策与市场温度，是「今年比去年热还是冷」的最短答案。

第二，它是领域热度读数的底座。需求原文写的是「历年涉足某领域企业的新增数量」，领域过滤在 API 层做，本件提供的是全量底表；没有这张底表，任何领域切片都要从主档重扫。

第三，它是累计叙事的素材。「企业库从多少家长到多少家」这类展示需要累计序列，而累计序列就是一阶求和，必须先有年度序列。

### 1.3 需求文档是否给出定义方法

**给了判定锚与去重要求，没给年份切窗与国内外边界。** 需求原文明确「根据提取的企业注册时间等指标」判定新增、要求「对重复注册的企业进行去重」、建议「选择过去五年或者十年的数据」；未给的是：年份分组粒度（语义上是「历年」，即按年）、国外是否并算、累计值是否输出。

本件的处置：按年分组；国内与国外并算但分列（`domestic` / `foreign` / `total` 三列都给）；累计值输出（`cumulative`）。三条都在产物 `result.series` 里逐行落地，读的人不需要猜。

另一个未闭合项是「重复注册」。本件用 `org_id` 去重，因为主档 `org_id` 全表唯一；若同一法人多块牌照注册为多个 `org_id`，本件会重复计数。这一层库内无法识别，属已知边界。

### 1.4 类似指标权威机构构建方法可行性

年度新设企业统计在官方与学界有三套常见做法：登记注册流量统计、法人单位增量统计、商业库新增收录统计。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 登记注册流量 | 市场监管总局经营主体统计 | 统计期内完成登记注册的主体计数 | 高（本件采用，锚一致） |
| B 法人单位增量 | 国家统计局法人单位统计 | 期末单位数减期初数 + 退出数 | 中（需存量与退出两侧） |
| C 商业库新增 | 企业信息服务机构 | 首次收录时间当新增 | 低（收录时间≠注册时间） |

**A 族是本件采用的方法。** 判定锚是「登记完成时点」，与 `incorporation_date` 语义一致；统计对象是登记主体，本件取其中的企业主档；统计期是自然年，本件按 `YEAR()` 取整。三条对齐，方法同构。

**B 族**需要存量与退出两侧的完整流水，本库没有退出表（只有 `reg_status` 状态位），算不出「期末减期初」的分解，故不采用。

**C 族**用「首次收录时间」当新增，会系统性后移——一家 2016 年注册的企业若 2024 年才被收录，C 族记 2024 年新增。本件不用收录时间，正是为了避开这个后移。

## 二、计算过程

### 2.1 总体思路与数据流

两张主档各做一次 `GROUP BY YEAR(incorporation_date)`，得到两份「年 → 家数」字典；再按 1980—2026 逐年对齐相加，得到合计序列与累计序列。空日期在 SQL 层就被排除，不进任何年份桶。

对齐用完整年份轴而不是取两张表的年份并集，是为了让缺失年显式为 0 而不是缺行。图表读的是完整轴，缺行会让折线断开，0 会让折线落地——后者才是真相（那一年确实没有新登记）。

| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 国内分组 | `dwd_org_base_info` | `GROUP BY YEAR()` | 69 个年份桶 |
| 国外分组 | `dwd_forg_base_info` | 同上 | 168 个年份桶 |
| 裁剪 | 两份字典 | 丢弃 < 1980 的脏年 | 2,992 行不计 |
| 对齐 | 两份字典 | 1980—2026 完整轴 | 47 行 |
| 累计 | 合计序列 | 逐行累加 | 47 个累计值 |

### 2.2 口径定义与公式

年度计数与累计是同一个序列的两种读法：

$$N_{Y}=D_{Y}+F_{Y},\qquad C_{Y}=\sum_{y=1980}^{Y} N_{y}$$

其中 $D_Y$ 是国内当年注册数，$F_Y$ 是国外当年注册数，$C_Y$ 是截至 Y 年的累计。同比按相邻两年计算，第一年无前值：

$$g_{Y}=\frac{N_{Y}}{N_{Y-1}}-1$$

去重键用 `org_id`。主档 189,116 行对应 189,116 个不同 `org_id`，所以 $\sum 1$ 与 `COUNT(DISTINCT org_id)` 等价；这条等价性是本件敢用行计数的前提，也写进了产物 `probes.n_distinct_org`。

| 量 | 取值 | 含义 |
|---|---|---|
| $D$ 合计 | 188,762 | 国内有效注册日行数 |
| $F$ 合计 | 16,037 | 国外有效注册日行数 |
| 序列年数 | 47 | 1980—2026 |
| 累计 | 201,807 | 47 年合计 |
| 峰值年 | 2016 | 14,069 家 |

### 2.3 累计口径与年度切分的区别

本件同时给年度与累计，两者不能混用。年度回答「今年新增多少」，累计回答「到今年为止一共多少」。页面上如果只显示累计，会把「增长放缓」读成「还在增长」——累计永远上升，除非某年为负（不可能）。

另一个容易混的是「存量」。累计不是存量：累计含已注销企业，存量只含存续。本库存续 168,830 行（89.27%），与累计 201,807 的差额主要是注销与历史样本口径差，两者不可互相替代。

| 口径 | 含义 | 本件是否采用 |
|---|---|---|
| 年度新增 | 当年注册数 | 是（`total`） |
| 累计新增 | 1980 年起累加 | 是（`cumulative`） |
| 存量 | 当前存续企业数 | 否（另有指标） |
| 净增 | 新增减注销 | 否（无注销年字段） |

### 2.4 计算步骤（脚本逐步实现）

1）读两份按年快照（未命中则现查并落盘）；2）把 `year = None` 的桶摘出来记为「空日期」，不进序列；3）丢弃 1980 年前的脏年，记录丢弃量；4）按 1980—2026 完整轴对齐相加；5）算累计与同比；6）标记 2026 为残年。

第 6 步是防误读的关键。2026 年只有 122 家，不是「断崖式下跌」，是「年度还没过完」。产物里 `current_year.partial = true`，正文也把它排除在「近五年」之外——近五年取 2021—2025 五个完整年。

| 步骤 | 实现 | 校验 |
|---|---|---|

## 三、数据支撑情况

### 3.1 依赖表与可得性

本件只依赖两张主档的同一个字段。字段是 DATE 类型，没有字符串解析成本；空值比例国内 0.19%、国外 19.81%，都在可接受范围。

成本在扫描：`GROUP BY YEAR(incorporation_date)` 用不到索引，国内全表扫约 40 秒。处置是落快照复用，重跑不再打库。

| 依赖维度 | 实测状态 | 关键证据 | 缺口与修复路径 |
|---|---|---|---|
| 国内注册日 | 可用 | 188,762 / 189,116 | 354 行缺失，可忽略 |
| 国外注册日 | 可用 | 16,037 / 20,000 | 3,963 行缺失，占 19.81% |
| 国外国别 | 不可用 | `country` 全空 | 需甲方提供 |
| 注销年 | 不可用 | 无字段 | 需新增退出流水 |
| 领域标签 | 可用 | 关联表在 | 本件不做过滤 |

### 3.2 四判定落表

结构过、数据过，唯二不过的是「国外国别」与「注销年」。两者都不影响年度新增主口径，所以不拉低档位，但在 §四 单列。

| 判定项 | 结论 | 证据 |
|---|---|---|
| 表结构直接支持（开发库+三方库） | 否 | 无年度结果表 |
| 表数据直接支持（开发库+三方库） | 否 | 同上 |
| 依赖表结构支持（开发库/三方库） | 是 | DATE 字段 + 主档 |
| 依赖表数据支持（开发库/三方库） | 是 | 双侧有效率 99.81% / 80.19% |
| 聚合结论 | 完全转换支持 | 47 年已落盘 |

### 3.3 数据量、覆盖与代表性

覆盖上，国内 99.81% 的行进入序列，国外 80.19% 进入。国外缺失的 19.81% 不是随机——早期样本的注册日录入不全，越早的年份缺失越多，所以国外的早期年份偏低，这是已知偏差。

代表性上，国内侧是广东为主的登记子集（广东占 99.82%），所以「全国新设企业」的量级不可对标；能做的是形态对表：峰值年、平台期、回落节奏三项与全国大势同向。

国外侧有一个必须点名的断层：2007—2011 年每年 1,345—2,823 家，2012 年骤降到 104。这不是真实波动，是 2 万行样本的灌入分布造成的。序列里保留这些数字（它们是真实的行），但正文标注不可当趋势使用。

### 3.4 结构支持判定

结构侧够用：字段是 DATE、语义明确、无解析歧义。`incorporation_date` 与 `incorporation_year` 两列并存，本件用前者派生，后者只做交叉校验（两者一致率极高，不一致的行以 DATE 为准）。

局限在「新增」的语义：注册是「出生」，不是「开业」，也不是「首次被收录」。一家企业注册后立即注销，仍计入当年新增；这是登记口径的定义，不是缺陷。

### 3.5 与开发库 live 的差异

开发库的国外主档是 0 行空壳，gkx 有 20,000 行。这是本件与旧稿最大的环境差异：同一个脚本，在开发库跑出来的国外侧全 0，在 gkx 跑出来有数。

上线需把 47 年序列表物化（`year, domestic, foreign, total, cumulative`），并保留 `partial` 标记，让前端知道 2026 不能画成整年。

## 四、数据缺失情况

### 4.1 缺口清单

五个缺口，按影响排序。前两个影响可解释性，后三个影响扩展用法，但都不影响 47 年主序列的成立。

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| 国外国别全空 | 不能按国家拆新增 | 只给国外合计 | 甲方补 `country` |
| 国外 2007—2011 断层 | 该段不可当趋势 | 正文标注 | 需全量国外主档 |
| 注销年缺失 | 不能算净增 | 只算毛新增 | 新建退出流水 |
| 重复注册不可识别 | 一法人多照会重复计 | 用 `org_id` 去重 | 需法人主键 |
| 2026 残年 | 不能与整年比 | 标 `partial` 并排除 | 年底自然补齐 |

### 4.2 逐条影响

**国外国别全空**影响的是拆解维度，不是总量。20,000 行国外主档的年度分布是可用的（除断层段），但「美国多少家、日本多少家」这一层完全不可得。

**2007—2011 断层**是本件最容易被误用的一段。数字本身是真的（那些行确实注册在那些年），但分布是被样本灌入口径塑造的，不是自然分布。把它当「外资进入高峰」会得出错误结论。

**注销年缺失**让本件只能算毛新增。要算净增（新增减注销），必须有注销日期字段，库内只有 `reg_status` 状态位，没有日期。

### 4.3 明确不做什么（禁止的替代）

- 不用 `created_time` 当注册时间——那是入库时间，会整体后移。
- 不把 2026 残年当整年——122 家不是断崖，是年度未完。
- 不用国外 2007—2011 段做趋势外推——样本断层，不是真实波动。
- 不用累计值代替存量——累计含注销，存量只含存续。
- 不把本库量级与全国新设企业数对标——本库是子集，比例无意义。

五条禁令的共同点是「不要把能算的东西说成想说的东西」。能算的是「登记子集的年度分布」，想说的可能是「全国新设趋势」，两者形态同向但量级不可比。

### 4.4 若甲方补齐后的口径升级路径

补齐分两条：一条补国别（扩拆解维度），一条补退出流水（从毛新增升级为净增）。前者不改主序列，后者会改序列的尾部形态。

只补国别，档位不变，可交付范围从「国内外两列」扩到「国别明细」。补了退出流水，才能回答「净增是正是负」，那是另一个指标（企业净增数），不是本件的扩项。

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 补国别字段 | 可按国家拆新增 | 已是完全转换支持，范围扩大 |
| 补全量国外主档 | 断层消失 | 同上 |
| 补注销日期 | 可算净增 | 另立指标 |
| 补法人主键 | 可识别重复注册 | 同上 |

**基期声明**：`base_years_used` = 1980—2025 共 46 个年份；`base_years_missing` = []；`base_years_note` 说明 2026 为残年不进基期、1980 年前 2,992 行为脏年已裁。2026 年不进 `used` 也不进 `missing`，因为它是「主动排除的残年」，不是「库内缺失的年」。

## 五、王惠方法对照

王惠 20260816 底稿的起点是「按注册年分组」，2026-08-27 按架构师口头扩为「国内 ∪ 国外」。本件完整沿用这两步，差异只在数据源：底稿假定两侧都有主档，本件实测国外 `country` 全空、注册日缺失 19.81%。

第二处差异是窗口。底稿建议「过去五年或十年」，本件给全序列 47 年，近五年单列。给全序列的理由是累计叙事需要长序列；单列近五年的理由是短窗口更适合做同比读数。

**选用建议**：判定锚（注册日）、分组（按年）、去重（`org_id`）、国内 ∪ 国外四项沿用王惠；窗口从「五或十年」改为「全序列 + 近五年单列」；国外 2007—2011 段标注不可外推。若甲方只要近五年，直接取 `recent_5y` 即可，不必重算。

## 附录 M 开发交接说明

**问：页面怎么画？**

答：年度柱状图只画完整年（1980—2025），2026 单列为「进行中」，不画柱。

**问：能按领域筛吗？**

答：能，领域标签在关联表，API 层过滤后复用本序列。

**问：数字会变吗？**

答：会。主档增量驱动，季度刷新；历史年基本不动，最近两年会随补录上修。

**问：能对外称「全国新设企业数」吗？**

答：不能。本库是登记子集，只能称「库内企业年度新增」。
