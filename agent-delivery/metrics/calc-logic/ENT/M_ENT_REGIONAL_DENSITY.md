## 摘要

区域企业密度是「区域企业数 ÷ 区域面积」，用来回答「同样一块地上，企业有多密」。本件在 gkx 上的实测结论很干脆：**分子齐、分母无**。189,116 家企业可按省（29）、市（65）、县（146）三级聚合出 240 个格子，每个格子的企业数都是真值；但全库找不到任何可以相除的面积数值——15 个 area/面积 相关列全是编码或名称，区划维表 `dwd_dim_admin_area` 的 20,000 行里没有面积字段，宏观指标表 287 个指标代码里名称含「面积」的 0 个。

按口径「area 空或 ≤0 时该区空，不写 0」，交付态是 **0 行**、240 个格子全部置空。0 行不是脚本失败，是正确结果：若强行输出 0，等于告诉前端「这些地方每平方公里 0 家企业」，比空白更误导。产物里用 `denominator_available=false` 与 `blocked_cells` 两个字段把这件事写死。

为了证明分子与链路无误，本件另给一条不含面积的降级读数：省均 6,521.2414 家、市均 2,909.4769 家、县均 1,295.3151 家。这三个数的单位是「家/行政区」，不是「家/km²」，语义已经改变，只能用于同层级内部排序，不能用于跨层级或跨面积比较，本件把它标为 `non_deliverable`。

因此定档 **部分支持**：有分子、有层级、有可执行的相除链路，缺的只是分母这一列数据。判「完全不支持」会掩盖「分子已就绪」这个事实，判「完全转换支持」则会掩盖「分母根本不在库」这个事实。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业分析 → 区域分布 → 集聚效应**。页面形态是一张密度图层：省界着色，越深表示每平方公里企业越多；点省下钻到市，点市下钻到区县。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业分析 → 区域分布 → 集聚效应 |
| 页面载体 | 密度图层（省/市/县三级） |
| 输出形态 | 区域键 + 层级 + 企业数 + 面积 + 密度 |
| 更新频率 | 日（口径）/ 年（面积） |
| 粒度 | 行政区 × 层级 |
| 关联Q | Q012 |

它与同族三件的分工：`M_ENT_REGION_COVERAGE` 数「点亮多少格」，`M_ENT_REGIONAL_COUNT` 数「每格多少家」，本件算「每平方公里多少家」。三件共享同一份分子聚合，只有本件需要分母。

### 1.2 为什么需要这个指标

家数回答「哪里多」，密度回答「哪里挤」。两者在跨区域比较时给出完全不同的排序：一个面积大的城市家数多但密度低，一个面积小的城市家数少但密度高。招商与选址场景关心的是后者——企业可选址的空间是有限的。

第二个用途是识别「统计假象」。某省企业数排第一，可能只是因为它面积大；密度能把面积因素除掉，让「集聚」与「铺开」区分开。这也是需求文档用「集聚效应」而不是「企业数量」来描述这一块的原因。

第三个用途是政策评估的分母。产业园区、扶持政策的覆盖强度常按「每万家企业」或「每平方公里」计量，密度是这类分母的直接来源。

### 1.3 需求文档是否给出定义方法

需求文档没有给公式，只给了「集聚效应」的语义与「从全国到城市逐级下钻」的呈现要求。口径由算法 2026-09 的 COVER-STAT-L01 补齐：

> 国内省 / 市 / 县：该区 REGIONAL_COUNT / 该区 `code_region.area`，单位 家/km²；`area` 空或 ≤0 该区空（不写 0）；全国行不算；国外不算；产业不是分组维。

这段话把分子、分母、单位、置空规则、排除项五项都写死了，唯一没有写死的是「分母从哪来」——原文假定 `code_region` 是一张可用的区划维表。gkx 侧的现实是这张表不存在，于是整条口径卡在分母上。

### 1.4 类似指标权威机构构建方法可行性

密度类指标的方法分歧几乎全在分母上。分子（企业数）各家一致，分母有四种选法，选哪一种直接决定读数含义。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 行政面积 | Ciccone & Hall (1996) | 家数 / 法定行政边界面积 | **高（口径主路径）** |
| B 建成区面积 | Combes et al. (2012) | 家数 / 实际建设空间 | 中（更贴选址，但边界每年变） |
| C 人口 | 城市经济学人均口径 | 家数 / 常住人口 | 低（度量人均承载） |
| D 区位商 | 产业集聚研究 | 区域份额 / 全国份额 | 低（度量相对集中） |
| E 就业密度 | Duranton & Puga (2004) | 就业人数 / 面积 | 中（需就业数据） |

**A 族是口径指定的主路径**，也是唯一「法定、稳定、可核验」的分母：行政边界由民政部公布，面积不随月度数据波动。Ciccone 与 Hall 强调面积口径必须与被测现象的空间范围一致，这条纪律在本项目尤其尖锐——深圳全市面积与建成区面积差一倍，换分母密度就翻倍。

**B 族更贴「企业可选址空间」的语义**，但建成区边界每年更新、无库内字段，且各市口径不一（有的含深汕合作区、有的不含）。Combes 等在法国案例里同时报告行政区与就业区两套密度、用排序一致性证明结论稳健，这是本件想采纳的做法；但没有一套可核验的建成区面积数据，第二步做不了。

**C/D 族语义不同**：人口分母度量「人均承载」，区位商度量「相对集中」，都不是「单位面积家数」。把任一个换上来，指标名字就得改。

**E 族需要就业数据**，gkx 的从业人数只有 3,170 行正值（3.4864%），不足以支撑。

### 1.6 推测原意与推测定义

推测原意是：**在任意行政层级上，给出「每平方公里有多少家企业」**，用于跨区强度比较与集聚判断。可执行定义：

$$ density_{r} = \frac{count_{r}}{area_{r}},\quad area_{r} > 0 $$

其中 $count_{r}$ 是区域 $r$ 的企业数（省/市/县三级各自聚合），$area_{r}$ 是该区域的行政面积（km²）。置空规则：$area_{r}$ 为空或 ≤0 时，$density_{r}$ 为空，不写 0、不拿上级面积顶替。

依赖维度如下表。D1–D4 全部就绪，D5 完全缺失，D6 是分母的元数据缺口。

| 代号 | 依赖维度 | 类型 | 本件实测 |
|---|---|---|---|
| D1 | 企业数（分子） | 聚合 | 有，240 个格子 / 189,116 家 |
| D2 | 省级键 | 字段 | 有，29 个值 |
| D3 | 市级键 | 字段 | 有，65 个值 |
| D4 | 县级键 | 字段 | 有，146 格（下界） |
| D5 | 行政面积（分母） | 字段 | **无，0 个数值型面积列** |
| D6 | 面积单位 | 元数据 | 无（旧稿记录列注释只写「面积」） |

D6 值得单列：即便将来灌入面积，单位仍需确认是 km² 还是亩/公顷。旧稿记录过「列注释只写面积，未标 km²，误判会差 100—1,500 倍」，这个风险在 gkx 侧同样存在。

## 二、计算过程

### 2.1 总体思路与数据流

链路分三段：分子聚合、分母探测、相除与置空。前两段互不依赖，可以并行；第三段在分母不可用时直接短路成 0 行，不进入除法。

| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 分子聚合 | `dwd_org_base_info` | 三列 GROUP BY | 152 个组合格 |
| 分母探测 | `information_schema` + 两张候选表 | 逐列/逐表检索 | 0 个可用面积 |
| 相除 | 分子 × 分母 | 键对齐后相除 | 0 行（分母空） |
| 置空 | 240 个格子 | `area` 空则该区空 | `blocked_cells` |
| 降级读数 | 分子 | 家/行政区 | 3 个均值（非交付） |

这条链路的设计意图是「先把能算的算完，再证明不能算的那一步为什么不能算」。如果一上来就判「算不了」，没人能复核到底是分子错还是分母缺；现在的产物里分子、分母、置空三块证据各自独立，任何一块被质疑都能单独查。

### 2.2 步骤 1｜分子聚合

分子来自 `dwd_org_base_info`，`is_deleted=0`，按 `province,city,area` 分组。结果 152 个组合格，聚合出 29 个省级、65 个市级、146 个县级单位，合计 189,116 家。

$$ count_{prov} = \sum_{city,area} n_{prov,city,area} $$

三级的格子数分别是 29、65、146，相加得 240——这是产物里 `blocked_cells.total` 的来源。注意三者是嵌套关系，240 不是「240 个互斥区域」，而是「240 个待填面积的格子」，其中同一个县同时贡献省、市、县三个格子。

### 2.3 步骤 2｜分母探测（三路并查）

分母不是「查一下有没有」，而是三路并查，任一路命中都算有分母。三路全部落空，才判「分母不在库」。

**第一路：列级扫描。** 在 `information_schema.columns` 里找列名或列注释含 area/面积/km²/square 的列，命中 15 个。逐个看类型：全部是 `varchar`（编码或名称）或与研究无关的数值列（`tpsa` 是分子极性表面积，不是行政区面积；`area_code_type` 是区划代码类型）。真正可用于相除的数值型面积列 **0 个**。

**第二路：表级扫描。** 找表名含 `code_region`、`region_scope`、`density`、`admin_area` 的表，只命中 `dwd_dim_admin_area`。这张表 20,000 行，字段是 `cur_code`/`cur_name`/`parent_code`/`province_name`/`city_name`/`area_name`/`cur_level` 一类，**没有任何面积列**；而且它只覆盖 120 个区县、29 个省，是全量区划的抽样表，连当分母的资格都不完整。

**第三路：宏观指标扫描。** `dwd_macro_index_data` 有 20,000 行、287 个指标代码，理论上可能藏着「行政区面积」这类宏观口径。用 `index_code LIKE '%面积%'` 查，命中 **0 行**。该表的指标代码是 `gmjj_jjzl_01`、`a77460` 这类不透明编码，且库内没有「代码→指标名」的字典表，即便有面积口径也无法定位。

$$ denominator\_available = \left( n_{numeric\_area} > 0 \right) \lor \left( n_{area\_table} > 0 \right) \lor \left( n_{macro\_area} > 0 \right) = false $$

三个子条件全为假，结论是硬结论：不是「值空」，是「没有这一列」。

### 2.4 步骤 3｜相除与置空

按口径，`area` 空或 ≤0 时该区空。既然分母整体不存在，240 个格子全部置空，交付 0 行。

$$ delivered\_rows = \left| \left\{ r : area_{r} > 0 \right\} \right| = 0 $$

这里必须区分两种「空」：一种是「这个区域确实没有企业」（count=0），另一种是「这个区域有企业但不知道面积」（area 缺失）。前者可以写 0，后者不能。本件的 240 个格子全部是后者，所以全部置空而不是填 0。

### 2.5 步骤 4｜降级读数（非交付值）

为了证明「分母一旦到位，结果量级合理」，产物另给一组不含面积的均值。它们的单位是「家/行政区」，不是「家/km²」。

$$ \bar{n}_{prov} = \frac{189116}{29} = 6521.2414,\quad \bar{n}_{city} = \frac{189116}{65} = 2909.4769,\quad \bar{n}_{county} = \frac{189116}{146} = 1295.3151 $$

这三（四）个数的用途只有一个：证明分子聚合没有算错。它们不能当密度用——「每省 6,521 家」与「每平方公里多少家」是两个构念，前者把「省的面积差异」完全忽略了。产物里这组数放在 `compute.fallback_no_area`，标签直接写「降级读数，非 家/km²，不交付」。

### 2.6 步骤 5｜结果解读与链条自证

0 行的解读必须写清楚，否则评审时容易被读成「脚本没跑通」。产物用三个字段自证：`denominator_available=false`（分母不存在）、`blocked_cells.total=240`（被置空的格子数）、`numerator_cells`（分子侧的真实格子数）。三者一起看，结论是「分子有 240 格、分母为 0、故交付 0 行」。

分子侧的分布也一并落盘：广东 188,776 家占 99.8202%，深圳 95,600、广州 49,605、东莞 33,590、惠州 9,979。这组数字的作用不是密度，而是证明分子与 `M_ENT_REGION_COVERAGE` 同源——同一个底册、同一条分组 SQL、同一组数字。

### 2.7 复现代码与结果展示

脚本先读已验证快照 `code/_snapshots21/ent_region_agg_20261022.json`（缺失时回落 live 分组查询），再现场跑三条分母探针。产物落在 `metrics/repro/out/M_ENT_REGIONAL_DENSITY_out.json`，含 `compute.denominator_available`、`compute.blocked_cells`、`compute.numerator`、`compute.fallback_no_area`、`probes.denominator` 五块。

| 命令 | 期望 | 备注 |
|---|---|---|
| `cd code && python3 M_ENT_REGIONAL_DENSITY.py` | 交付 0 行 + 240 置空格 | 实测 1.89 秒（分子读快照） |
| `rebuild_metric.py M_ENT_REGIONAL_DENSITY --check` | 语义一致 | 重跑对账 |
| `audit_md_vs_out.py --only M_ENT_REGIONAL_DENSITY` | 无漂移 | 正文数字逐项对产物 |

### 2.8 与旧稿的差异

旧稿在开发库口径下判的是「部分支持」，理由与本稿相同（缺分母），但缺口的性质变了：旧稿是「有表有列、area 全 0（0/3,349）」，本稿是「表不在、列不在、值不在」。

| 项 | 旧稿（开发库口径） | 本稿（gkx 口径） | 差异原因 |
|---|---|---|---|
| 分母载体 | 区划维表 `code_region`（3,349 行） | gkx 无此表 | 源表不存在 |
| 分母状态 | 有 `area` 列，0/3,349 有值 | 无任何数值型面积列 | 从「值空」变「列无」 |
| 分子 | 189,116 家 / 29 省 / 65 市 / 146 格 | 同 | 无变化 |
| 交付态 | 0 行 | 0 行 | 一致 |
| 修复动作 | 灌数 | 建维表 + 灌数 + 定单位 | 升级 |
| 档位 | 部分支持 | 部分支持 | 结论未变，理由更硬 |

这条差异是本批五件里最典型的一次「口径换轨」：同一句公式，换个库就从「数据工程未完成」变成「结构缺口」。如果只照抄旧稿的「有表有列」，会得出「gkx 里也有 code_region」的错误结论。

## 三、数据支撑情况

### 3.1 依赖表与可得性

| 依赖维度 | 实测状态 | 关键证据 | 缺口与修复路径 |

| 企业数（分子） | 可用 | 189,116 家 / 240 格 | 无 |
| 省级键 | 可用 | 29 个值 | 无 |
| 市级键 | 可用 | 65 个值 | 无 |
| 县级键 | 可用（下界） | 146 格 | 区县填充 82.1951% |
| 行政面积（分母） | 不可用 | 0 个数值型面积列 | 建维表 + 灌数 |
| 面积单位 | 不可用 | 无字段说明 | 灌数时同步定单位 |

前四行支撑分子，后两行是分母缺口。这张表就是「部分支持」的完整证据链：五行可用、两行不可用，且不可用的两行恰好是公式的分母。

### 3.2 四判定落表

| 判定项 | 结论 | 证据 |
|---|---|---|
| 表结构直接支持（开发库+三方库） | 否 | 无面积列 |
| 表数据直接支持（开发库+三方库） | 否 | 0 行面积值 |
| 依赖表结构支持（开发库/三方库） | 是（分子侧） | 底册四列齐全 |
| 依赖表数据支持（开发库/三方库） | 是（分子侧） | 189,116 行 |
| 聚合结论 | 部分支持 | 缺分母 |

### 3.3 数据量、覆盖与代表性

分子相对全国企业法人是一个很小的子集，且高度偏粤（99.8202%）。这带来一个连锁后果：即便明天灌入面积，跨省密度也不可比——省外合计 340 家，除北京 163 家外，其余 27 个省级单位合计仅 177 家、平均 6.56 家，其中 22 个单位不足 10 家，任何密度值都会被小样本噪声主导。

代表性上，本件的分子可以支撑「深圳市内部各区县的密度排序」（深圳 95,600 家、9 个有名称的区，单区最多 25,192 家，宝安区），但不支撑「深圳 vs 广州」的密度比较：广州 49,605 家分布在 11 个区，单区最多 8,282 家（白云区与天河区并列），采集强度明显低于深圳，密度差异里混着采集差异。

### 3.4 结构支持判定

结构侧的唯一问题是缺面积字段。这不是「表设计不好」，而是「这个库的定位里没有地理面积」——gkx 是产业数据集成库，不是统计地理库，行政区划只保留编码与名称用于关联，不保留面积用于计算。

因此本件不建议在 gkx 内硬造面积（比如用经纬度外接矩形估算），那会引入一个无法核验的分母。正确做法是从民政部/统计年鉴引入一张独立的区划面积维表，按区划代码关联。

### 3.5 与开发库 live 的差异

旧稿的 live 侧有 `code_region`（3,349 行），gkx 侧没有。除此之外两侧分子完全一致：同一张 `dwd_org_base_info`、同一批 189,116 行、同样的 29/65/146。

这个差异决定了上线方案：如果最终交付仍在开发库体系内，只需灌 `area`；如果迁到 gkx，必须先建维表。两条路径的工作量差一个数量级，必须在排期时讲清。

## 四、数据缺失情况

### 4.1 缺口清单

本件的缺口集中在一处（分母），但它派生出六个具体问题，每个都要单独处置。

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| 行政面积字段 | 密度完全不可算 | 交付 0 行 | 建区划面积维表 |
| 面积单位未定义 | 即便灌数也可能差 100—1,500 倍 | 不灌数 | 灌数时同步定 km² |
| 面积口径未裁决 | 行政面积 vs 建成区，深圳差约一倍 | 按口径取行政面积 | 甲方裁决 |
| 区县填充 82.1951% | 县级密度只覆盖已知区县 | 县级标注下界 | 补采注册地区县 |
| 底册偏粤 99.8202% | 跨省密度不可比 | 披露 | 扩采省外名录 |
| 无区划版本字段 | 面积与区划可能错配 | 只做截面 | ETL 加版本 |

六条里前三条是分母自身的缺口，后三条是分母到位后仍会存在的问题。这个区分很重要：**灌入面积只解决第一条，另外五条依然在**。

### 4.2 逐条影响

「面积单位未定义」是最隐蔽的一条。旧稿记录过：列注释只写「面积」，未标 km²；如果实际是亩（1 亩 ≈ 0.000667 km²），密度会差 1,500 倍；如果是公顷，差 100 倍。这种错误不会让脚本报错，只会让结果量级全错，而且看起来完全正常。

「面积口径未裁决」决定读数的语义。行政面积包含山体、水域、农田，建成区只含实际建设空间；对深圳这类「全域面积大、可建设空间占比低」的城市，同一批企业用两个分母算出的密度可以差约一倍。口径细稿选行政面积，本件遵从，但把建成区口径列为待确认项。

「底册偏粤」让跨省比较失去意义。省外 340 家分布在 28 个省级单位（另有 1 家省份为空），除北京 163 家外，其余 27 个单位合计 177 家、平均 6.56 家；用这样的分子算密度，得到的是「采集强度图」而不是「企业密度图」。这一条在分母到位后依然成立，必须在页面上标注。

### 4.3 明确不做什么（禁止的替代）

- 不拿上级面积顶下级——市缺面积就用省面积除，会让市的密度凭空变小。
- 不拿人口或 GDP 顶面积——语义从「空间密度」变成「人均承载」或「经济密度」。
- 不拿经纬度外接矩形估算面积——引入无法核验的分母。
- 不把 0 行显示成 0 值——空白是「不知道」，0 是「确实没有」。
- 不用「家/行政区」冒充「家/km²」——单位语义已变，只能内部排序。

五条禁令的共同点是「不要把缺的东西用近似值填上」。密度这个指标对分母极其敏感，任何近似都会让排序失真，而失真的排序比空白更有害。

### 4.4 若甲方补齐后的口径升级路径

补齐分三步，每一步对应一个档位状态。只补面积字段，可以从「0 行」变成「有数」，但因为单位与口径未定、跨省不可比，仍是部分支持；补面积 + 定单位 + 裁决口径，可以升到完全转换支持；再补省外名录，才能对外称「全国密度」。

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 灌入面积（km² 明确） | 可出密度值 | 部分支持 → 可讨论完全转换 |
| 裁决行政 vs 建成区 | 读数语义确定 | 完全转换支持 |
| 补省外名录 | 跨省可比 | 可对外发布 |
| 补区县填充 | 县级密度可用 | 仍为完全转换 |
| 加区划版本 | 可做跨期 | 仍为完全转换 |

**基期声明**：`base_years_used` = []；`base_years_missing` = []。本件是截面件：分子取当前底册快照，分母不存在，故无年度序列与基期年份。面积本身是年度更新数据（行政区划每年调整），一旦灌入，基期应记为「面积数据年份」而不是企业数年份。

## 五、王惠方法对照

本件不在王惠 20260816 底稿内，口径来自算法 2026-09 的 COVER-STAT-L01。它借用的是王惠族的「区域四件套」结构：`M_ENT_REGIONAL_COUNT` 出分子、`code_region` 出分母、本条做相除。

与王惠族的边界有三条。其一，王惠底稿里的区域类指标都是计数或占比，没有「除以面积」的比率型指标，本件是新增构念；其二，本件的分母依赖一张区划维表，而王惠族的指标全部只依赖底册，所以本件的支持度天然低于同族其它三件；其三，本件的置空规则（area 空该区空）是 COVER-STAT-L01 专有的，不能套到计数件上。

**选用建议**：公式照 COVER-STAT-L01 原式执行，不改；分母缺口按 §四 的六条清单处置，不自行降级；若甲方最终决定不做密度、只做家数热力图，则本件可整体下线，由 `M_ENT_REGIONAL_COUNT` 承接展示需求。这条建议的现实意义是：在分母补齐前，家数热力图是唯一不会误导的替代品。

## 附录 I 口径问答

**问：为什么 0 行不是脚本失败？**

答：分母不存在，按口径该区空。脚本正常退出、产物完整、`blocked_cells` 记录 240 个被置空的格子。若输出 0 值，才是口径错误。

**问：能不能用经纬度估面积？**

答：不能。外接矩形与真实行政边界差异极大（尤其沿海与山区），会引入一个无法核验的分母。

**问：为什么不用人口当分母？**

答：语义变了。「家/万人」度量人均承载，「家/km²」度量空间密度，两者排序不同，不能互相替代。

**问：分子既然齐了，为什么不做个家数热力图先上线？**

答：可以，而且建议这么做。家数热力图不依赖分母，是当前唯一不会误导的替代品。
