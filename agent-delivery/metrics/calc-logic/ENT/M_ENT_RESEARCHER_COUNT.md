## 摘要

企业科研人数要回答「这批企业一共有多少人在做研发」。本件在 gkx 上的实测结论是一个干净的零：**三个来源、618,011 行、非空值 0 个**。国内财务年表 `development_employee` 90,926 行全 NULL，海外表 `rd_staff` 51 行全 NULL，工商年报资产表 `yfrysl` 527,034 行全为空字符串（不是 NULL，是空串——说明字段被写入过，但上游没有可写的内容）。

这不是覆盖率问题。覆盖率问题长这样：10 万行里有 3 万行有值，缺 70%，可以插补、可以标注覆盖。本件的形态是 10 万行里 0 行有值，插补无从下手——没有任何一个真实的科研人数可用于校准插补系数。产物里 `n_scored=0`、`sum_researcher=null`，且按口径不输出 0：合计 0 会被读成「这些企业没有科研人员」，而事实是「我们不知道」。

本件同时否决了四条代理路径。从业人数 `employees_number` 只有 3,170/90,926 行正值（3.4864%），且 calc-logic 明令禁止顶替；研发投入金额（`arch_development_am` 全 NULL、海外 `research_development_amount` 51/51 有值但无人数可除）；专利发明人反推会系统性偏向专利密集行业；工商年报从业人数 `cyrs` 在本库不可用。四条都写进了 `proxy_deviation`，一条也没采用。

因此定档 **完全不支持**，并把产物定性为 `negative_evidence`：它证明的不是「结果是多少」，而是「为什么算不出来、以及试过哪些路都不通」。这类产物必须可复核——脚本每次重跑都会重新扫列、重新计数、重新确认 0 值，任何一天上游灌了数，`n_scored` 会立刻从 0 变成正数，档位也就必须重判。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业分析 → 创新能力 → 投入侧**。页面形态是一张卡片：一个总数 + 覆盖企业家数 + 数据年份，点开可看企业明细（按人数倒序）。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业分析 → 创新能力 → 投入侧 |
| 页面载体 | 创新能力卡片 + 企业明细弹层 |
| 输出形态 | 企业科研人数合计 + 计入企业家数 + 最新年份 |
| 更新频率 | 年（年报口径） |
| 粒度 | 企业 × 年 → 汇总 |
| 关联Q | Q-E32-01（未闭合） |

与本域其它件的边界：`M_ENT_RD_INVESTMENT_RATIO` 算研发投入占营收比（分子是钱），`M_ENT_PATENT_VALID_COUNT` 算有效专利数（产出侧），本件算人（投入侧的人数口径）。三者常被并列展示，但只有本件依赖「人数」这一列——也正因为如此，它单独卡住了。

### 1.2 为什么需要这个指标

科研人数是创新能力的**投入侧**度量。专利、论文度量产出侧，营收、利润度量经营侧，人数度量「有多少人在做研发」，是解释产出差异最直接的自变量。

对政府用户，它支撑「产业人才密度」判断与人才政策投放：一个地区研发人员总量是人才公寓、落户指标、研发补助的分配依据。对企业用户，它支撑「同行研发规模」对标：我的研发团队是 50 人还是 500 人，在同行里处于什么位置。对园区用户，它支撑「研发人员集聚度」与配套商业、通勤的规划。

还有一层隐性用途：它是研发强度的分母之一。「研发人员占从业人数比」这个常被引用的强度指标，分子就来自本件。本件算不出来，那个派生指标也一并不可用。

### 1.3 需求文档是否给出定义方法

需求原句写的是「通过汇总统计企业人数，展示在产业中从业者的总体人数」——落点是**企业总人数**，不是研发人员。而 calc-logic 的口径是：

> 每企取最新一个有年报的自然年的科研人员数加总；国内取 `development_employee`，国外取 `rd_staff`；无值/NULL/占位 0 不进合计；禁止用从业人数、禁止用研发投入金额冒充。

两句话直接冲突：需求说「就用企业人数」，calc-logic 说「禁止用从业人数」。这不是实现方可以自行调和的分歧，必须由甲方裁决。本报告的处理是：**按 calc-logic 的研发人员口径定档**（因为它是指标注册口径），同时把需求原句口径的可用量一并测出，供裁决时参考。

两条口径的实测结论相同——都不可构建，但原因不同：研发人员口径是「列全空」，总人数口径是「覆盖率仅 3.4864%」。这个区别在裁决时很重要：如果甲方坚持要总人数，至少还有一个 3.49% 的样本可以谈覆盖；如果坚持研发人员，则必须换源。

### 1.4 类似指标权威机构构建方法可行性

「科研人数」看似最不需要方法——数人而已。但真正编过这个数的人都知道，它至少有五个互不等价的定义：**人数（headcount）／全时当量（FTE）／科技人员（高企口径）／研发人员（R&D 口径）／从业人数（需求原句）**。五者之间不是精度差异，而是构念差异。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A R&D 人员（HC） | OECD Frascati Manual | 企业内从事 R&D 的人员数 | **高（口径主路径）** |
| B R&D 人员（FTE） | OECD / UNESCO UIS | 按工时折算的全时当量 | 中（需工时，本库无） |
| C 科技人员 | 高企认定口径 | 大专以上或 183 天以上技术人员 | 中（口径更宽，需学历字段） |
| D 从业人数 | 工商年报 | 企业在岗职工总数 | 低（口径被明令禁止） |
| E 发明人反推 | 专利计量文献 | 专利发明人去重计数 | 低（系统性偏向专利密集行业） |

**A 族是口径指定的主路径**，也是国际上最通用的定义：Frascati Manual 把 R&D 人员定义为「直接从事 R&D 活动的人员」，并要求按 HC 与 FTE 双口径报告。本库没有工时字段，只能做 HC。

**B 族更精确**，但需要工时台账，国内企业年报不采集，本库更没有。用 HC 冒充 FTE 会让研发强度系统性偏高（一个人投三成工时被记成一个人）。

**C 族的「科技人员」比「研发人员」宽**：高企认定要求科技人员占职工总数 10% 以上，其中「科技人员」含技术管理、直接技术服务人员。用 C 族口径数出来的人数会大于 A 族，两者不可比。

**D 族是需求原句的口径**，被 calc-logic 明令禁止，理由是「从业人数不等于研发人员」——一个人在企业上班，不代表他在做研发。

**E 族是代理路径**，专利发明人去重可以估「有多少人参与过发明」，但会漏掉不做专利的研发人员、重复计算跨企业发明人，且系统性偏向专利密集行业。本件不采用。

### 1.6 推测原意与推测定义

推测原意是：**给出一批企业的科研人员总量，用于判断产业创新投入的人力规模**。可执行定义：

$$ researcher\_total = \sum_{e} latest\_year\_dev\_employee_{e} + \sum_{e} latest\_year\_rd\_staff_{e} $$

其中 $latest\_year\_dev\_employee_{e}$ 是企业 $e$ 最新一个有年报年度的研发人员数，无值、NULL、占位 0 都不进合计。三个边界：取最新年（避免重复计数）、无值不进合计（不把缺失当 0）、不跨口径混加（不能国内用研发人员、国外用总人数，也不能用研发投入除以人均薪酬反推）。

依赖维度如下。D1–D5 是「结构在、数据空」，D6 是「口径未裁决」，D7 是「无替代源」。

| 代号 | 依赖维度 | 类型 | 本件实测 |
|---|---|---|---|
| D1 | 国内研发人员字段 | 字段 | 在（`double`），90,926 行非空 0 |
| D2 | 海外研发人员字段 | 字段 | 在（`double`），51 行非空 0 |
| D3 | 工商年报研发人员 | 字段 | 在（`varchar`），527,034 行非空 0 |
| D4 | 企业标识（关联键） | 字段 | 在（`org_id` / `jgid`） |
| D5 | 年份字段 | 字段 | 在，2007—2025 |
| D6 | 口径裁决 | 定义 | 缺（需求 vs calc-logic 冲突） |
| D7 | 替代源 | 数据 | 无（四条代理全部否决） |

D4/D5 齐全这件事值得强调：本件的失败不是「关联不上」或「年份对不齐」，而是纯粹「没有值」。如果连键都缺，失败原因会变成数据结构问题；现在键全、年份全、列全，唯独值全空。

## 二、计算过程

### 2.1 为什么本件没有计算过程

按口径，计算过程应当是「取每企最新年值 → 国内与海外相加 → 得总数」。这条链路在本件的第一跳就断了：`development_employee` 非空 0 行，取不到任何一个 $latest\_year$ 值；`rd_staff` 同样。没有输入，后续的相加、去重、年份对齐全部无从谈起。

因此本件按 F4 从缺处理：不写「先分组再求和」的伪流程，也不把探测步骤包装成计算步骤。真正的取数与计数证据全部放在 §三，那里逐表给出 SQL、行数、非空计数与对照列，可逐条复核。把探针塞进 §二 会让读者误以为「有过程、只是结果为空」，而事实是「过程无法开始」。

### 2.2 空集求和的处置

唯一需要写死的口径是空集如何处理：

$$ researcher\_total = \begin{cases} \sum_{i \in scored} v_i & \left| scored \right| > 0 \\ \text{null} & \left| scored \right| = 0 \end{cases} $$

本件 $\left| scored \right| = 0$，故输出 null。这不只是格式选择：0 是一个结论（「没有科研人员」），null 是一个状态（「不知道」）。按 calc-logic「无值不进合计」，空集不能写成 0。

### 2.3 复现入口与产物

脚本不读快照，每次现场扫列、现场计数，因为否定性证据的价值在于「此刻仍然为空」。入口是 `metrics/repro/M_ENT_RESEARCHER_COUNT.py`，产物是 `metrics/repro/out/M_ENT_RESEARCHER_COUNT_out.json`；后者含 `compute.domestic`、`compute.foreign`、`compute.annual_report_asset`、`compute.stock_finance_rd_staff_columns`、`compute.requirement_headcount_alternative`、`probes.empty_columns` 六块，另有 `verdict_kind="negative_evidence"` 标明产物性质。

| 命令 | 期望 | 备注 |
|---|---|---|
| `cd code && python3 M_ENT_RESEARCHER_COUNT.py` | `n_scored=0`、`sum=null` | 实测 21.66 秒 |
| `rebuild_metric.py M_ENT_RESEARCHER_COUNT --check` | 语义一致 | 重跑对账 |
| `audit_md_vs_out.py --only M_ENT_RESEARCHER_COUNT` | 无漂移 | 正文数字逐项对产物 |

重跑一致性的判定要看语义指纹而非耗时：`elapsed_sec` 每次不同（21.66 秒是本次值），但 `n_scored`、三个源的计数、候选列清单必须逐字一致。任何一项变了，说明库里的数据变了，档位需要重判。

## 三、数据支撑情况

### 3.1 探针一｜国内财务年表

表 `dwd_org_annual_financial_info`，90,926 行、8,127 家企业、年份覆盖 2007—2025。

$$ dev\_non\_null = \sum_i \mathbb{1}\left[ development\_employee_i \neq \text{NULL} \right] = 0,\quad dev\_pos = 0 $$

非空 0、正值 0、填充率 0.0000%。同表的从业人数 `employees_number` 有 3,170 行正值（3.4864%），说明这张表**并非整体没数**——营收、资产等列都有值，唯独研发人员列整列为空。这个对照很关键：它排除了「表没灌数」的解释，把问题精确锁定在「这一列没灌数」。

列类型是 `double`、注释是「研发人员数量」，说明建模时预留了这个字段；8,127 家企业、19 个年份的样本框也是完整的。缺的只有值。

### 3.2 探针二｜海外财务年表

表 `dwd_foreign_org_annual_financial_info`，51 行、12 家企业。

51 行全 NULL，填充率 0.0000%。同表的研发投入金额 `research_development_amount` 却是 51/51 有值——再次证明「表有数、这列没数」。海外侧样本量本身也只有 12 家，即便有值也不足以支撑「全球研发人员」口径，这一条属于局部缺口而非全局缺口。

### 3.3 探针三｜工商年报资产表

表 `dwd_org_annual_report_asset`，527,034 行、49,997 家企业。

$$ yfr\_ok = \sum_i \mathbb{1}\left[ yfrysl_i \neq \text{NULL} \land TRIM(yfrysl_i) \neq '' \right] = 0 $$

这里要特别注意：`yfrysl` 是 `varchar`，空值形态是**空字符串而不是 NULL**。如果只查 `IS NOT NULL`，会得到 527,034 个「非空」的假象。本件用 `TRIM(...) <> ''` 双重判定，真实非空 0。同表研发投入 `yftrje` 同样 0。空串这个形态说明字段被写入过（管线跑通），但上游没有可写的内容（治理缺口）。

### 3.5 代理路径逐条否决

四条代理路径全部测过，全部否决，理由写进 `proxy_deviation`：

| 代理 | 可用量 | 否决理由 |
|---|---|---|
| 从业人数 `employees_number` | 3,170/90,926 行正值（3.4864%） | calc-logic 明令禁止；覆盖率过低 |
| 研发投入金额 `arch_development_am` | 90,926 行非空 0 | 本身也是空列 |
| 海外研发投入 `research_development_amount` | 51/51 有值 | 无人数可除，缺人均研发经费系数 |
| 专利发明人反推 | 未测（无必要） | 系统性偏向专利密集行业，系数不可校正 |
| 工商年报从业人数 `cyrs` | 本库不可用 | 表不在 gkx |

这里最需要解释的是「为什么不能用从业人数」。表面上看，从业人数除以一个行业平均研发人员占比就能估出科研人数；但那个占比在 gkx 内无从获得——没有任何一张表同时有「从业人数」和「研发人员数」两列有值的样本。没有校准样本，占比只能外借，外借的系数无法核验。

第二个要解释的是「为什么不用研发投入除人均薪酬」。这个做法的隐含假设是「人均研发经费 = 人均薪酬」，实际研发经费里设备、材料、委外占大头，人员薪酬通常只占一半左右；用总投入除薪酬会系统性高估人数，且不同行业差异极大。

gkx 侧不存在 `enterprise_finance_history` 与 `enterprise_base` 两张表（`information_schema.tables` 按名检索返回空）。这两张表是旧稿的两条重要证据：前者提供「第四源全 0」（80,531 行），后者提供「生成列鉴别」案例。少了这两条，本件的证据链从「五源全空 + 一列假数」缩为「三源全空 + 全库无第四源」。结论没变，但论证方式变了：以前靠「多源交叉否定」，现在靠「全库扫描否定」。后者其实更强——它排除的不是「这五个来源不行」，而是「gkx 里没有第六个来源」。

## 四、数据缺失情况

### 4.1 缺口性质判定

本件的缺口属于「治理型空列」，不是「采集型缺失」。区分标准是看空值的形态：

| 形态 | 含义 | 本件是否存在 |
|---|---|---|
| 整列 NULL | 字段从未被写入 | 是（`development_employee`、`rd_staff`） |
| 整列空串 | 字段被写入过但无内容 | 是（`yfrysl`） |
| 部分 NULL | 采集不全，可插补 | 否 |
| 全 0 | 占位值，非真值 | 否（本库这三列是 NULL/空串，不是 0） |

「整列 NULL」与「整列空串」都指向同一个结论：上游没有产生过这个数。前者是 ETL 没写，后者是 ETL 写了空。两种形态都无法通过清洗修复，只能推动上游回填。

### 4.2 逐条影响

「国内研发人员值」缺失直接导致主体口径不可算。国内 8,127 家企业是全部样本，占底册 189,116 家的 4.2972%；这 8,127 家里一家都没有研发人员数。

「海外研发人员值」缺失让全球口径不可算，但影响有限——海外只有 12 家企业，即便有值也只是点缀。这一条属于局部缺口。

「工商年报研发人员值」缺失浪费了最大的样本框。49,997 家企业有年报资产记录（覆盖底册 26.4377%），是三个源里覆盖最广的；如果这一列有值，本件立刻可以从「完全不支持」跳到「部分支持」。它是性价比最高的修复点。

「上市财务研发人员列」缺失让本件失去交叉验证能力。上市公司年报附注里通常有完整的研发人员数，是质量最高的来源；gkx 的上市财务表 27 列里没有这一列，等于放弃了最可靠的第三方校验。

「口径裁决」缺失是一个定义层面的阻塞。在裁决前，任何实现都在替甲方做定义决策；本报告按 calc-logic 定档，但把需求原句的可用量一并测出（3.4864%），供裁决时参考。

「工时/FTE」缺失限制的是精度而非可用性。HC 口径可以回答「有多少人」，不能回答「相当于多少个全时人力」；后者在算研发强度时更准确。

### 4.3 明确不做什么（禁止的替代）

- 不用从业人数顶替——calc-logic 明令禁止，且覆盖率只有 3.4864%。
- 不用研发投入除以人均薪酬反推——假设不成立，行业差异极大。
- 不用专利发明人反推——系统性偏向专利密集行业，系数不可校正。
- 不把 NULL 当 0 求和——会把「不知道」写成「没有」。
- 不引用演示库的生成列——那是造数，不是证据。

五条禁令的共同点是「不要用一个不可核验的近似值填补空白」。人数这个指标对口径极敏感，任何代理都会让结果失去可比性，而不可比的数比空白更有害——空白至少诚实。

### 4.4 若甲方补齐后的口径升级路径

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 回填 `yfrysl`（49,997 家） | 可出年报口径人数 | 完全不支持 → 部分支持 |
| 回填 `development_employee` | 可出财务年表口径 | 部分支持 → 可讨论完全转换 |
| 补上市财务研发人员列 | 可交叉验证 | 完全转换支持 |
| 裁决研发人员 vs 总人数 | 定义确定 | 仍为完全转换 |
| 补工时字段 | 可出 FTE | 精度提升，非档位变化 |

**基期声明**：`base_years_used` = []；`base_years_missing` = []。本件无基期：口径要求「每企取最新一个有值自然年」，但没有一个有值年份，故不声明基期。国内表实测年份区间 2007—2025，仅作字段存在性证据，不构成可用序列。

## 五、王惠方法对照

本件不在王惠 20260816 底稿内，口径来自算法 2026-09 的 calc-logic（Q-E32-01 未闭合）。王惠族的创新类指标以「专利数」「研发投入」为主，没有「研发人数」这一构念——这不是遗漏，而是数据可得性决定的：王惠底稿编制时，研发人数列已经是空的。

与王惠族的边界有三条。其一，本件与 `M_ENT_RD_INVESTMENT_RATIO` 同属投入侧，但一个数人、一个数钱，不可互相替代；其二，本件与 `M_ENT_PATENT_VALID_COUNT` 分属投入侧与产出侧，常被并列展示但不能互相推导；其三，本件的口径冲突（研发人员 vs 从业人数）是王惠族没有的问题，因为王惠族的指标定义全部来自需求原文，没有二次改写。

**选用建议**：在裁决与回填完成前，本件应整体下线，页面上用「研发投入强度」与「有效专利数」替代呈现创新能力；不要用从业人数做一个「近似科研人数」上线，那会在第一次对外解释时被问倒。若甲方坚持要有一个人数口径，建议改名为「企业从业人数」并另立指标 ID，与 calc-logic 的科研人数彻底分开。

## 附录 H 口径问答

**问：为什么不能输出 0？**

答：0 是一个结论（「没有科研人员」），null 是一个状态（「不知道」）。本件是后者。按「无值不进合计」，空集求和为 null。

**问：三张表 61 万行都没数，会不会是查询写错了？**

答：三条 SQL 都用了 `IS NOT NULL` 与 `>0` 双判定，年报表额外加了 `TRIM(...)<>''`；同表的对照列（`employees_number`、`research_development_amount`）都查出了非零值，证明查询本身没问题。

**问：能不能等工商年报回填后再做？**

答：可以，而且这是最短路径。年报表覆盖 49,997 家企业，是三个源里覆盖最广的；一旦 `yfrysl` 有值，本件可从「完全不支持」升到「部分支持」。

**问：为什么旧稿说有不支持的证据，本稿还要重做？**

答：旧稿有两张表在 gkx 里不存在。本稿必须用 gkx 现有表重建证据链，否则结论无法在 gkx 上复核。
