## 摘要

「企业行业领域排名」是《科技专题服务算法库》**招引企业综合推荐模型（§5.7，seq 147）**的四个输出项之一，指在给定「行业领域」内按招引推荐指数对候选企业进行排名，供招商部门按行业筛选优选目标。需求文档**只列输出、未给排名的字段、范围与并列规则**（handoff 已登记缺口 ER-B10：排名范围/排序字段/并列规则无独立 ID，禁止发明 `M_ENT_DOMAIN_RANK`）。本文在引用原句的基础上给出「推测定义」：行业维度采用《国民经济行业分类》（GB/T 4754—2017）大类，排序键为招引推荐指数 $Rec(e)$，排名方法为行业内 dense rank。脚本 `metrics/repro/GAP-RECRUIT-METRIC-03.py` 已在三方库 `gkx` 换源重跑（读数与旧 demo 镜像逐项一致）：**186,135** 家可评分企业、覆盖 **108** 个行业（二级行业桶 94 个），Rec 代理分取值 606 种、有区分度。按 §〇，结构+当前数据量均足且现转结果合理 → **完全转换支持**（正式 Rec 公式与阈值待甲方闭合后替换代理排序键）。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**企业深度分析 → 招引企业综合推荐模型**（§1.1.1.1.1.1.1.5.7，seq 147），以及展示系统侧的**招引企业推荐分析**页面（E-26，《科技信息展示系统和科技专题服务系统》§1.1.1.2.4.2.3.6）。

该模型的产品任务是：为深圳打造招商引资评估和企业招引优选机制，基于产业相关度、政策匹配度、深圳连接度三维加权生成招引推荐指数，输出招引推荐指数、优选企业清单、**企业行业领域排名**与数据分析报告。

### 1.2 为什么需要「企业行业领域排名」这个指标

在招引推荐的输出体系中：

| 输出项 | 在模块中的任务（据需求原文归纳） |
|---|---|
| 企业招引推荐指数 | 量化企业与深圳产业/政策/经济联系的契合程度 |
| 优选企业清单 | 跨行业的优选企业名单 |
| **企业行业领域排名** | **按行业领域分组的企业排名**——支撑「按企业标签、行业领域和地域来源进行筛选与分析」的招引查询 |
| 数据分析报告 | 综合分析输出 |

没有「企业行业领域排名」，招商部门无法回答「新一代信息技术行业里最值得招的前 20 家是谁」这类行业场景问题——推荐指数只给全局分数，行业排名给**行业内相对位置**，两者互补。

> **本节写法说明**：本文件是 GAP 单（补数据需求单），不是普通指标报告；因此本节不写「方法谱系」，而写「方法口径 → 数据要求 → 本 GAP 缺在哪」。判断标准不变：每一族都要回答「它算出来的东西与本指标差在哪」。

**（1）四族方法与本 GAP 的对应关系**

| 方法族 | 代表出处 | 口径要点 | 该族实际产出物 | 本 GAP 的缺口类型 |
|---|---|---|---|---|
| A 标准行业分类 + 组内排序 | GB/T 4754—2017 (国家统计局, 2017a)；《统计上大中小微型企业划分办法（2017）》(国家统计局, 2017b) | 先按同质性分类归组，再在组内比较 | 行业桶 + 组内统计量 | **无缺口**（分类字段 18.68 万非空、94 个二级桶） |
| B 产业导向分组 | 《战略性新兴产业分类（2018）》(国家统计局, 2018)；深府〔2022〕1 号 (深圳市人民政府, 2022) | 以战新产业/城市集群替代行政行业分类 | 产业集群视图 | **数据缺口**：库内无「GB/T 小类 → 集群」对照表（`dwd_org_industry_tags` 是企业级链环节标签，非集群映射） |
| C 综合评价 → 组内排名 | OECD & JRC 复合指标手册 (OECD & JRC, 2008)；AHP 权重 (Saaty, 1990) | 归一→加权→聚合→敏感性，再排序 | 综合指数 + 名次 | **口径缺口**：Rec 三维权重与阈值未闭合 |
| D 招商引资评价实践 | 商务部/地方招商评估与 FDI 区位评分实践 | 多维加权评分后排名 | 招引评分与名单 | **口径缺口**：权重依赖历史样本训练，样本未提供 |

**族 A：它算出来的东西与本指标差在哪。** 族 A 产出的是**分组与组内统计量**（企业家数、均值、份额），它保证「同一桶里的企业可比」，但不生产排名键——分组维是排名的前提，不是排名本身。《统计上大中小微型企业划分办法（2017）》进一步提供了规模档的官方判据（从业人员、营业收入、资产总额，大/中/小须同时满足下限、微型满足一项即可）(国家统计局, 2017b)，这正好为代理排序键中的「规模档」信号提供了官方口径。族 A 在本 GAP 中**没有数据缺口**：`industry_l1..l4` 四级字段齐备，这是本单判「完全转换支持」的主要依据。

**族 B：它算出来的东西与本指标差在哪。** 族 B 产出的是**产业集群视图**（深圳「20+8」口径），它与 GB/T 行业分类不是一一对应：一个集群可能横跨多个大类，一个大类也可能拆进多个集群。因此族 B 需要一张「GB/T 小类 → 集群」对照表，而本库**没有这张表**：`dwd_org_industry_tags` 的 2,283,762 行（2,283,715 家去重企业、53,911 组 `industry_code`×`industry_link_code` 组合）是「企业 → (GB/T 行业, 产业链环节)」的明细，产业链环节并不等于「20+8」集群码，不能当对照表用。这构成本 GAP 中**唯一的数据缺口**。注意：这个缺口不影响「行业领域排名」本体（族 A 口径已可算），只影响「产业集群视图」这一增强形态——两类视图不能互相替代，也不能因为集群映射缺失就否定行业排名可算。

**族 C：它算出来的东西与本指标差在哪。** 族 C 产出的是**带权重与不确定性的综合指数**，它的排序结论只在「权重可辩护、敏感性已检验」时成立；手册明确要求报告权重来源与不确定性，而本 GAP 的代理键是四信号等权、未做敏感性检验。AHP 提供的是「专家两两比较→一致性检验→权重」的路径 (Saaty, 1990)，本库没有专家比较矩阵，也没有历史样本，因此**权重无法从数据或专家侧推出**——这是口径缺口，不是数据缺口。族 C 在本 GAP 中缺的是「$w$ 的来源」，不是「$x$ 的行数」。

**族 D：它算出来的东西与本指标差在哪。** 招商引资评价实践产出的是**场景化的招引分**（产业相关度 + 政策匹配度 + 本地连接度），与本指标需求原文的三维同名，但各地权重依本地产业政策而变、不公开、不可移植。它证明「三维加权」在业务上成立，但不能提供本项目的权重数值；照搬外地权重会把外地产业偏好带进深圳的招引口径。这是口径缺口，且必须由甲方而非数据侧闭合。

| A 国标分组 | 分组维口径（零缺口） | 无需请求，直接采用 |

| C 综合评价 | 权重来源与敏感性检验 | 甲方闭合 ER-B10 + 提供历史样本/专家矩阵 |
| D 招商实践 | 三维业务形态与展示口径 | 甲方确认三维命名与页面披露语 |

**（5）本节立场**：方法上四族都不需要「再研究」，需要的是三张表加一个口径——集群映射表（业务给）、历史样本或专家矩阵（甲方给）、排名结果面（工程给）、ER-B10（甲方签字）。因此本单不申请「方法可行性再评估」，只申请这四项。这也是 GAP 单与指标报告在写法上的根本区别：报告证明「能不能算」，GAP 单只说「缺什么、谁来给、什么时候给」。

## 二、计算过程

> **口径说明**：需求未给公式，以下为推测计算过程；已由脚本
> `metrics/repro/GAP-RECRUIT-METRIC-03.py` 在 `gkx`（183.240.141.251:3318，schema `gkx`）实测跑通，结果见同目录 `GAP-RECRUIT-METRIC-03_out.json`。

### 2.1 方法选择：国标行业分类为分组维、推荐指数为排序键

行业分组维度的权威口径是《国民经济行业分类》（GB/T 4754—2017）：该标准按经济活动同质性原则将全社会经济活动分为门类、大类、中类、小类四级（20 门类、97 大类、473 中类、1,382 小类），是国家统计工作中使用范围最广的分类基准 (国家统计局, 2017a)。招商语境的行业分组还应向国家战略性新兴产业与城市产业集群对齐：国家统计局令第 23 号《战略性新兴产业分类（2018）》以 GB/T 4754—2017 为基础对 9 大领域再分类 (国家统计局, 2018)；深圳市政府《关于发展壮大战略性新兴产业集群和培育发展未来产业的意见》（深府〔2022〕1 号）明确 20 个战略性新兴产业集群与 8 个未来产业 (深圳市人民政府, 2022)。本项目库内 `industry_l1..l4` 四级字段正是 GB/T 层级结构，可直接作分组维。

排名（ranking as derived order）本身是评价体系的标准产出形态：构建综合评价分数后在组内排序，是统计评价与招商引资企业评估的通行做法（商务部及各地招商评估实践均以多维加权评分→排名呈现）。

### 2.2 步骤 1｜行业归属判定（D1）

取 `dwd_org_base_info.industry_l2_name`（GB/T 大类名）为默认分组键；缺失时回退 `industry` 字段。

**实测（2026-10-20）**：`base_info` 189,116 行；行业非空 186,809（98.8%）；二级大类非空 185,907，distinct 二级桶 **94** 个、四级小类桶 1,139 个——与 GB/T 4754 层级吻合，结构量双足。

### 2.3 步骤 2｜排序键 Rec 代理（D2）

正式口径下排序键为招引推荐指数：

$$Rec(e)=\alpha\cdot Ind(e)+\beta\cdot Pol(e)+\gamma\cdot Conn_{SZ}(e)$$

三维分项与权重未闭合（需求要求历史样本训练，未给数值）。本实测采用**代理排序键**（可用信号的等权标准化合成）：

$$
Rec_{\text{proxy}}(e)=\frac{1}{|K|}\sum_{k\in K}\sigma_k(e),\quad
K\subseteq\{\text{注册年限},\ \log_{10}\text{注册资本},\ \text{上市状态},\ \text{规模档}\}
$$

每项映射到 [0,1]（年限 25 年封顶；资本 log10 满 5 位数量级封顶；上市=1；规模档大/中/小/微=1/0.66/0.33/0.1）。信号不足 2 项的企业不参与评分。

### 2.4 步骤 3｜行业内排名（D3）

对每个行业桶 $I$，按 $Rec_{\text{proxy}}$ 降序给出 dense rank：

$$Rank(e\,|\,I)=1+\left|\{e'\in I: Rec(e')>Rec(e)\}\right|$$

（并列同分同名次；`n_in_industry` 一并输出供相对位置计算。）

### 2.5 步骤 4｜输出形态

每行 = `org_id, name_cn, city, industry_l1/l2, Rec_proxy, industry_key, rank, n_in_industry`——即需求「按行业领域筛选 + 排名」的可交付数据集；正式版将 `Rec_proxy` 列替换为闭合后的 $Rec(e)$，排名逻辑不变。

### 2.6 与「20+8」产业集群的映射接口（可选增强）

`dwd_org_industry_tags`（`gkx` 三方库，2,283,762 行）把每家企业同时挂到一组 `industry_code`（GB/T 行业）与 `industry_link_code/name`（产业链环节，如「集成电路设计」），去重后有 53,911 组「行业码 × 链环节码」组合，可作「GB/T → 产业链环节」的可用对照底料。但它**不是**「GB/T 小类 → 20+8 集群」对照表：链环节是技术/业务分工口径，一个集群（如「新一代信息技术」）会横跨多个链环节，而一个链环节也可能落在多个集群下，两者不能直接等同。正式版的集群视图仍需官方《战略性新兴产业分类（2018）》对照表或业务侧提供的「20+8」映射表；在此之前本文不将其计入支持度判定。

## 四、数据缺失情况

主指标可构建；残余缺口如下：

1. **正式排序键未闭合**：招引推荐指数三维权重与阈值待甲方历史样本训练（ER-B10）；当前为代理键。
2. **行业→产业集群对照表缺位**：`gkx` 全库无「GB/T 小类 → 20+8 集群」对照表；`dwd_org_industry_tags` 的 228.4 万行是「企业→(行业码, 链环节码)」明细（53,911 组组合），链环节 ≠ 集群，不能替代对照表，「20+8」集群视图需业务侧补表。
3. **live 无结果面**：`enterprise_recruit` / `enterprise_industry_summary` 0 行，上线前需灌数/镜像。
4. **并列规则未定义**：dense rank 为工程默认，甲方可能要求竞争排名（1224 型）或分页唯一序——ER-B10 一并闭合。
5. **无物化结果表**：需落 ADS 排名结果面。

**甲方侧建议**：本指标属「口径闭合即可上线」——优先闭合 ER-B10（排序字段/范围/并列规则）与 Rec 权重；行业维用 GB/T 大类起步，集群映射后叠加「20+8」视图。

### 4.1 缺口的后果归因（往哪偏、偏多少、能否交叉验证）

**往哪偏。** 本 GAP 的缺口不是数据行数，而是排序键口径，因此偏差方向由代理键的构成决定：四信号等权（注册年限、`log10` 注册资本、上市状态、规模档）且两项封顶（年限 25 年、资本满 5 个数量级），结果是**系统性偏向「老、大、上市、有资本」的企业，压低「年轻、小而高成长」的科技企业**。机制很直接——封顶让成熟企业拿满分、上市是二值硬加分、规模档把「大」映射为 1.0。招引场景真正想要的高成长中小企业，恰好被这套键排在后面：**方向性偏差与业务目标相反**。

**偏多少（可定量）。** `out.json` 的 Rec 代理分 min 0.11 / max 1.00 / mean 0.6004 / median 0.59，取值 606 种；但满分并列严重：样例 4 个行业的 Top5 共 **20/20 条全部为 1.0**，整体 Top10 也 **10/10 全部为 1.0**，dense rank 因此在头部大量退化为 `rank=1`。覆盖率方面，可评分 186,135 / 行业非空 186,809 = **99.639%**；但行业桶 **108 个 > 二级大类桶 94 个**，说明分组键混用了 `industry_l2_name` 与 `industry` 回退值，同一层级的桶并不统一。因此偏差量级不能只报「606 种取值」，必须同时报「头部满分并列占比」——后者在抽样中为 **100%**，这是代理键最刺眼的问题。

**能否交叉验证。** 有三条路径：① **换分组键**：只用 `industry_l2_name`（94 桶）重算，预期桶数从 108 降到 94，部分企业迁移到不同桶，Top-N 名单随之变化；② **换排序键做稳定性检验**：分别只用注册资本、只用年限、只用规模档各排一次，比较 Top-100 重合率，预期重合率低（四信号等权 + 双封顶），重合率本身就是「代理键不可靠」的度量；③ 与 `enterprise_ranking`（demo 1,134,500 行）对账——该表 `model_version='demo_rank_v0.1'`、`rank_dim` 恒 overall，属造数，**不参与结论**，只能用来检查输出格式，不能用来验证名次。

**归因小结。** 偏差方向与业务目标相反（偏成熟大企业、压高成长中小企业），偏差量级集中在头部（抽样 Top 名单 100% 满分并列），而这两个问题都**不能靠调阈值修正**：前者要换信号或改权重，后者要改并列规则或让排序键连续化。因此在 ER-B10 闭合前，本指标只能承诺「可复现的名次」，不能承诺「可辩护的名次」；把这句话写进页面披露，比在文档里补一段方法说明更能保护甲方。

## 附录 C　「企业行业领域排名」类似指标权威构建方法可行性报告（完整版）

### C.1 报告目的与范围

回答三个问题：(1) 权威机构对「行业内企业排名」类指标用什么构建方法？(2) 本项目库表是否具备落地条件？(3) 能否构建、应判何档支持度？

范围限定：招引场景下「给定行业领域内的企业排名」，不是跨行业总榜，也不是企业信用评级本身。

### C.2 需求语义锚定

招标原文 §5.7 输出「企业行业领域排名」，调用语境「按企业标签、行业领域或地域来源进行招引推荐查询」。可行性筛选标准：方法须同时给出 **①标准行业分组维 + ②组内排序键**，缺一不可。

### C.3 权威与学术构建方法谱系（完整版）

> 本节按「方法族 → 数据要求 → 计算步骤 → 局限 → 与本 GAP 的距离」五段式展开。判断纪律：**不写「可借鉴」，只写清它算出来的东西与本指标差在哪**。

#### C.3.1 族 A：标准行业分类 + 组内排序（分组维主路径）

**代表**：国家统计局《国民经济行业分类》GB/T 4754—2017（20 门类 / 97 大类 / 473 中类 / 1,382 小类，同质性原则）(国家统计局, 2017a)；《统计上大中小微型企业划分办法（2017）》（按从业人员、营业收入、资产总额分档，大型/中型/小型须同时满足下限，微型满足一项即可）(国家统计局, 2017b)。

**数据要求**：每个经济单位一个主行业归属（四层代码）+ 规模判据所需的从业人数/营收/资产三项。

**计算步骤**：① 按主要活动归入最细层；② 向上卷到目标层级（门类/大类/中类/小类）；③ 组内比较（排序、均值、份额）；④ 组间不做比较（这正是「行业内排名」与「总榜」的分界）。

**局限**：分类只保证「同桶可比」，**不生产排序键**；一个企业只有主行业，多元化企业会被压成单桶；规模划分办法的营收/资产阈值需按行业分别取值，本库只有规模档、无原始三项，无法复核档位是否正确。

**与本 GAP 的距离**：分组维**零缺口**（`industry_l1..l4_name/code` 齐备、非空 186,809、二级桶 94、四级桶 1,139）；规模档提供了代理键中的一个信号，但档位来源不可复核，属「可用但需披露」。

#### C.3.2 族 B：产业（链）导向分组（招引语境增强）

**代表**：《战略性新兴产业分类（2018）》（9 大领域，建立与 GB/T 4754 的代码对应，部分活动加 \* 标识）(国家统计局, 2018)；深府〔2022〕1 号「20+8」产业集群（20 个战略性新兴产业集群 + 8 个未来产业）(深圳市人民政府, 2022)。

**数据要求**：一张「GB/T 小类（或中类）→ 集群」的多对多对照表，且需覆盖全部小类，不能只覆盖热点产业。

**计算步骤**：① 企业归属到 GB/T 小类；② 经对照表映射到集群（可能一对多，需定主集群规则）；③ 集群内排序；④ 与行业视图并列展示而非互相替代。

**局限**：对照表是多对多，映射规则本身就是一个口径决策；战新分类只覆盖战略性新兴产业，传统产业会落空；「20+8」是深圳政策口径，跨市不可直接套用。

**与本 GAP 的距离**：这是**本单唯一的数据缺口**——`gkx` 全库无「GB/T 小类 → 20+8 集群」对照表（0 行），无法支撑集群视图；但它不影响族 A 口径的行业排名本体。缺口性质是「对照表待灌」，不是「行业字段缺失」。

#### C.3.3 族 C：综合评价 → 组内排名（排序键来源）

**代表**：OECD & JRC《Handbook on Constructing Composite Indicators》(OECD & JRC, 2008)；AHP 权重法 (Saaty, 1990)；本项目同文档的招引推荐三维指数 $Rec(e)=\alpha Ind+\beta Pol+\gamma Conn_{SZ}$。

**数据要求**：① 每个维度可观测的指标；② 归一化规则；③ **权重来源**（专家比较矩阵或历史样本）；④ 敏感性分析所需的参数扰动范围。

**计算步骤**：① 指标选取与缺失处理；② 归一化（min-max / z-score / 距离法）；③ 加权聚合；④ 敏感性/不确定性检验；⑤ 排序并报告并列规则。

**局限**：手册明确要求披露权重来源与不确定性，否则排名不可辩护；AHP 需要专家两两比较矩阵与一致性比率检验（CR<0.1），本库没有；等权不是「中性选择」，而是隐含「四信号同等重要」的强假设，会直接决定头部名单。

**与本 GAP 的距离**：**口径缺口**——缺的是 $w$ 的来源与敏感性检验，不是 $x$ 的行数。代理键用等权 + 双封顶替代，能算出名次，但名次的可辩护性低于族 C 的规范要求；这正是「正式版待 ER-B10 闭合」的实质。

#### C.3.4 族 D：招商引资评价实践（业务形态参照）

**代表**：商务部/地方招商评估实践与 FDI 区位选址评分文献脉络；各地「招商靶向企业清单」的通行做法（产业相关度 + 政策匹配 + 本地连接三维加权后排序）。

**数据要求**：本地产业政策文本、目标企业池、历史落地样本（用于定权与回测）。

**计算步骤**：① 圈定目标产业；② 构建三维评分；③ 用历史落地/接触记录回测权重；④ 输出靶向名单并人工复核。

**局限**：权重依本地政策而变、通常不公开、不可跨市移植；缺少历史落地样本时无法回测；人工复核环节不可省略，意味着它不是纯算法指标。

**与本 GAP 的距离**：证明「三维加权 + 组内排序」在业务上成立，但不提供本项目的权重数值；照搬外地权重会把外地产业偏好带进深圳口径。属**口径缺口**，且必须由甲方闭合。

#### C.3.5 为什么不能直接照搬任何一族

族 A 只给分组不给键；族 B 的集群对照表在库内缺位；族 C 缺权重来源与敏感性检验；族 D 的权重不可移植、且无历史样本可回测。四族拼起来才等于本指标：**A 定分组、B 定产业视图、C 定排序键的规范形式、D 定业务形态**。任何单族照搬都会得到偏差明确的替代品——只照 A 得到「行业统计表」，只照 C 得到「无权重来源的自造指数」，只照 D 得到「外地口径的招引清单」。本 GAP 单因此把结论写成「分组维可现转、排序键须甲方闭合」，而不是笼统的「方法可行」。

#### C.4.2 覆盖率的读法

三个分母必须分开报：**① 底册分母**——行业非空 186,809/189,116=**98.78%**；**② 可评分分母**——代理信号有效 186,135/189,116=**98.42%**，即 674 家企业因行业或信号缺失未入榜；**③ 映射分母**——集群对照表 0 行 / 四级小类 1,139 个 = **0%**，这意味着「20+8」集群视图当前一点也覆盖不了，不能宣称「已支持集群视图」。

① **分组维数据充足**：98.78% 行业非空、94 个二级桶、1,139 个四级桶，族 A 口径可现转，这是「完全转换支持」的硬依据。
② **排序键是口径缺口而非数据缺口**：四项信号均可算（98.42%），缺的是权重来源与并列规则（ER-B10），不能用「补数据」解决。

### C.8 对甲方四问的逐条回答

**第一问：这个指标现在能不能出数？** 能，但是代理口径。行业非空 186,809 家，可评分 186,135 家（98.42%），已按行业桶现转出名次；`out.json` 里 Rec 代理分 606 种取值、中位 0.59，排名机制跑通。**「能出数」不等于「能按甲方要的口径出数」**，区别见第二问。

**第二问：出的是不是甲方要的那个东西？** 分组维是，排序键不是。分组维用 GB/T 二级大类，符合国家标准口径；排序键是「年限 + 注册资本 + 上市 + 规模档」四信号等权代理，**不是**招引推荐指数 $Rec=\alpha Ind+\beta Pol+\gamma Conn_{SZ}$——缺 $Pol$、$Conn$ 两维，且 $\alpha,\beta,\gamma$ 未定。因此当前产出应命名为「行业领域内企业规模-资质综合排序」，不宜直接叫「招引推荐排名」。

**第三问：要补齐还差什么、谁能给？** 差三样，都不大：① ER-B10 口径（排序字段、排名范围、并列规则）——甲方定；② Rec 三维权重——需甲方提供历史落地/接触样本训练，或直接用 AHP 专家矩阵替代 (Saaty, 1990)；③ 全量「GB/T 小类→20+8 集群」对照表（当前库内缺位，0 行）——业务侧给。另需工程侧把分组键统一到 `industry_l2_name`，并在 live 镜像灌数。

**第四问：补不齐时替代口径是什么、还叫不叫这个名字？** 替代口径就是当前的代理键排序，必须同时披露三件事：四信号等权、两项封顶（年限 25 年 / 资本 5 个数量级）、头部满分并列严重（抽样 Top 名单 100% 为 1.0）。名称建议保留「企业行业领域排名」，但页面须标注「代理排序键（非招引推荐指数）」；若甲方要求对外口径一致，则应改名为「行业领域企业综合排序（代理版）」，避免把代理键当成招引推荐结论使用。
