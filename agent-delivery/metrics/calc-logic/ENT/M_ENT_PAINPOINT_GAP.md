## 摘要

痛难点改进差距回答「这家企业的某项经营指标，与同行业典型水平差多少」。它不是打分，也不是分档，只输出原始差值：企业值减同组 P25、企业值减同组 P75。

本件在 gkx 上能跑通，但跑得不利索。六项原料里四项可用（净利润率 1,100 家、净资产收益率 1,031 家、主营业务收入 1,031 家、人均产值 550 家），两项废掉：研发人员占比整列为空（`development_employee` 非空 0/90,926），营收增长率只能配对 17 家（年报表跨年同企交集太小）。行业门类里样本 ≥30 的组 8 个，指标-组配对 28 个，合计 1,131 家企业可打分。

最要紧的一条不是缺维，是**金额单位疑不一致**。产物 `unit_check` 显示：营收最大值 29,800,924,733.43、中位数 16,554.99、P90 80,058,401.21；人均产值中位数 85.33。真实劳动生产率不可能低到两位数（元/人），中位数 1.66 万的营收也不像年营收。这说明同一列里混着「元」与「万元」，或分子分母量纲不齐。任何基于这列算出的差值，方向可能对、绝对值不可信。

因此定档 **部分支持**，并把产物定位成「组内排序提示」：用它可以判断「这家企业的净利润率低于同行业中位数」，但不能说「低了 3.2 个百分点」。凡是引用绝对差额的地方，都必须先解决单位问题。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业服务 → 企业诊断 → 改进差距**。页面形态是一个雷达图加一张明细表：六个维度各一条轴，轴上标出企业的位置与同组 P25/P75 区间；明细表逐项列出「指标值 / P25 / P75 / 差 P25 / 差 P75」。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业服务 → 企业诊断 → 改进差距 |
| 页面载体 | 差距雷达 + 明细表 |
| 输出形态 | 六维原始差值（不合成、不分档） |
| 更新频率 | 年（年报口径） |
| 粒度 | 企业 × 年 × 指标 |
| 关联Q | Q018（分组键未闭合） |

**与同域三件的边界（重要）**：`M_ENT_PAINPOINT_COUNT` 数的是风险事件条数（六张风险表，699,003 条），单位是「条」；`M_ENT_PAINPOINT_TOPIC` 做的是痛点主题归类，单位是「标签」，输出主题分布；`M_ENT_PAINPOINT_SEVERITY` 把多项偏离度加权合成一个严重度分并分轻/中/重三档，单位是「档」。本件与它们三者都不同：**本件不做加权、不分档、不数事件、不打标签**，只输出「企业财务指标 − 同组分位」的原始差值，单位跟随输入指标（个百分点、元、元/人）。三者不能互相顶替，也不能把本件的差值当成 SEVERITY 的分数用。

### 1.2 为什么需要这个指标

企业诊断最容易犯的错是「绝对值评判」：净利润率 3% 是好是坏？在高毛利软件业是差，在薄利批发业是正常。差距指标把评判标准换成「同组比较」，让读数自带参照系。

第二个用途是定位改进空间。企业知道自己「利润率低」，但不知道低在哪一段：是低于同组下四分位（已经掉队），还是在 P25 与 P75 之间（正常波动）？本件把 P25/P75 两条线画出来，企业能直接看到自己处在哪一段。

第三个用途是给严重度模型提供原料。`M_ENT_PAINPOINT_SEVERITY` 的加权合成需要各项偏离度，本件就是它的上游之一。两者分工明确：本件出「差多少」，SEVERITY 出「有多严重」。

### 1.3 需求文档是否给出定义方法

需求给的是语义（「识别企业痛难点并给出改进方向」）与呈现要求（雷达图 + 明细），没有给公式。calc-logic 补齐为：

> 对每家企业、每项指标，计算其值与同组 P25、P75 的差：$Gap_{k}(e) = x_{k}(e) - Baseline_{k}$，其中基线取分组 P25 与 P75 两条；不设硬阈值、不做加权、不分档；缺维不补 0，输出 null。

这段话写死了三件事：用分位数不用均值、输出两条差、缺维不补 0。没有写死两件事：分组键用什么、组内最小样本多少。两件都由本件补充定义，并标注为「本件自定义、待甲方确认」。

### 1.4 类似指标权威机构构建方法可行性

「与同组比」是诊断类指标的通用做法，分歧在分组键与基线统计量。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 行业中位数/P25/P75 | 统计局、行业协会 | 按行业分组取分位 | **高（口径主路径）** |
| B 产业链环节分组 | 产业链诊断 | 按产品/环节分组 | 中（Q018 未闭合） |
| C 规模分组 | 中小企业划型 | 按营收/人数分档 | 中（更贴可比性） |
| D 区域分组 | 区域对标 | 按省市分组 | 低（混入区域差异） |
| E 全样本分位 | 通用基准 | 不分组的全库分位 | 低（跨行业不可比） |

**A 族是口径主路径**，也是唯一在库内可执行的：`dwd_org_base_info.industry_l1_name` 提供行业门类，20 个门类里 8 个样本 ≥30。统计局与行业协会的分位发布都用这个粒度，可比性最好。

**B 族更贴「痛难点」语义**——同一条产业链上的企业才真正可比——但 Q018 未闭合，库内没有产业链分组字段，只能用行业门类代理。代理的代价是组内异质性上升：同一个「制造业」门类里横跨上游材料与下游整机，P25/P75 区间被拉宽，差距的绝对值被压小。

**C 族（规模分组）在实际诊断中常与行业分组叠加使用**：同一行业里，营收 1 亿与营收 100 亿的企业利润率不可比。本件没有叠加规模维，这是可以改进的方向，但会进一步稀释每组的样本量（现在 8 组已经是 ≥30 的下限）。

**D 族（区域分组）会混入区域经济差异**，不适合做「经营能力」诊断；**E 族（全样本分位）跨行业不可比**，会把行业差异误读成企业差异。

### 1.6 推测原意与推测定义

推测原意是：**用同组比较替代绝对阈值，指出企业在哪些经营维度上落后于同行、落后多少**。可执行定义：

$$ Gap_{k,P25}(e) = x_k(e) - q_{0.25}\left( x_k \mid g(e) \right),\quad Gap_{k,P75}(e) = x_k(e) - q_{0.75}\left( x_k \mid g(e) \right) $$

其中 $x_k(e)$ 是企业 $e$ 在指标 $k$ 上的值，$g(e)$ 是其所属分组（本件用行业门类代理），$q_{0.25}$、$q_{0.75}$ 是组内分位。差值为正表示高于该分位，为负表示低于。

六项原料与两个自定义参数：

| 代号 | 依赖维度 | 类型 | 本件实测 |
|---|---|---|---|
| D1 | 营业收入增长率 | 派生 | 17 家（不足） |
| D2 | 主营业务收入 | 字段 | 1,031 家 |
| D3 | 净利润率 | 派生 | 1,100 家 |
| D4 | 净资产收益率 | 派生 | 1,031 家 |
| D5 | 人均产值 | 派生 | 550 家（薄） |
| D6 | 研发人员占比 | 派生 | **0 家（整维缺）** |
| D7 | 分组键 | 字段 | 代理（行业门类），Q018 未闭合 |
| D8 | 基线配置表 | 表 | **0 张（在线计算替代）** |

两个自定义参数：组内最小样本 30 家、基线取 P25/P75。两者都是**本件自定义、待甲方确认**，不是官方口径。

## 二、计算过程

### 2.1 总体思路与数据流

链路分五段：取最新年财务、算四项比率、按行业分组算分位、相减得差、缺维置空。

| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 取数 | 年报表 + 底册 | 每企最新有营收年 + 行业门类 | 1,301 家（有金额） |
| 比率 | 营收/净利/权益/人数 | 四项派生 | 550—1,100 家 |
| 分组 | 行业门类 | 组内 n≥30 | 8 组 |
| 分位 | 组内指标值 | P25/P50/P75 | 28 配对 |
| 差值 | 企业值 − 分位 | 逐项相减 | 1,131 家可打分 |
| 置空 | 研发人员占比 | 整维 null | 不输出 0 差距 |

设计意图是「先把能算的算到最细，再把不能算的显式置空」。研发人员占比如果强行输出 0 差距，前端会显示「该企业与同行持平」——这是彻头彻尾的错读，因为根本没有值。

### 2.2 步骤 1｜取数与分组

从 `dwd_org_annual_financial_info` 取每企最新一个「营收>0」的年份，字段含 `operating_revenue`、`main_business_revenue`、`pure_profit`、`owners_equity`、`employees_number`；左连 `dwd_org_base_info`（`is_deleted=0`）取 `industry_l1_name` 作分组键。

$$ latest(e) = \arg\max_{t} \left\{ t : operating\_revenue_{e,t} > 0 \right\} $$

年报表 90,926 行里营收>0 的只有 2,191 行，取最新年后剩 1,301 家有金额。这个收缩幅度（2,191 → 1,301）说明「同一企业多个年度、只有一个年度有营收」的情况很普遍。

### 2.3 步骤 2｜四项比率

$$ net\_margin = \frac{pure\_profit}{operating\_revenue},\quad roe = \frac{pure\_profit}{owners\_equity} $$

$$ rev\_per\_cap = \frac{operating\_revenue}{employees\_number} $$

主营业务收入作为水平值直接入表（不做比率）。四项的可算家数分别是 1,100、1,031、550、1,031，差异来自分母：净利润与营收几乎总是同时有值；权益缺失的少一些；从业人数缺失最多，导致人均产值只剩 550 家。

### 2.4 步骤 3｜分组与在线分位

分组键用行业门类。全库门类里样本 ≥30 的有 8 个：制造业、科学研究和技术服务业、批发和零售业、信息传输/软件和信息技术服务业、租赁和商务服务业、房地产业、交通运输/仓储和邮政业、金融业。

$$ q_p(k, g) = \text{quantile}_p\left( \left\{ x_k(e) : g(e) = g \right\} \right),\quad p \in \{0.25, 0.5, 0.75\} $$

每个「指标 × 组」组合要求有效样本 ≥30，否则该组该指标不出基线。8 组 × 4 指标理论上 32 个配对，实际 28 个——金融业只有净利润率与 ROE 两项达标（人均产值与主营业务收入的样本不足 30），房地产业与交通运输业各缺一项（人均产值）。

基线全部在线计算，因为库内没有配置表：按 `%baseline%`、`%p25%`、`%p75%`、`%quantile%`、`%percentile%`、`%diagnosis%` 六组模式扫 `information_schema.tables`，命中 **0 张**。

### 2.5 步骤 4｜相减得差

$$ Gap_{k,P25}(e) = x_k(e) - q_{0.25}(k, g(e)),\quad Gap_{k,P75}(e) = x_k(e) - q_{0.75}(k, g(e)) $$

两项差值都落盘，不合成、不加权、不分档。产物 `compute.gaps.sample` 保留 8 家完整样本供逐项复核，`compute.gaps.by_metric` 给每项的可算家数。

以制造业为例，净利润率的 P25 = 0.0065、中位数 = 0.0387、P75 = 0.1019：一家净利润率 0.0126 的企业，差 P25 为 +0.0061、差 P75 为 −0.0893，读法是「高于下四分位、未到上四分位」。

### 2.6 步骤 5｜单位体检（本件最关键的一步）

在出数之前先做了一次分布体检，结果发现金额列量纲可疑：

| 统计量 | 值 | 说明 |
|---|---|---|
| 营收样本 | 1,301 | 有金额的企业 |
| 营收最大值 | 29,800,924,733.43 | 约 298 亿 |
| 营收中位数 | 16,554.99 | 约 1.66 万 |
| 营收 P90 | 80,058,401.21 | 约 8,006 万 |
| 人均产值中位数 | 85.33 | 元/人 |
| 人均产值 P90 | 456,553.13 | 元/人 |

最大值与中位数差六个数量级，且人均产值中位数落在两位数——真实企业劳动生产率不可能这么低。合理推断是「元」与「万元」混用：若中位数实为万元，则 1.66 亿营收、人均 85.33 万元，就都合理了。

产物因此加了 `unit_check.flag`，明确写「金额单位疑不一致（元与万元混用）」，并把用途限定为「组内排序提示」。这是本件与一般指标文档最大的不同：**先承认数不可全信，再说明哪一部分仍可用**。

### 2.7 复现代码与结果展示

脚本一次查三张表，全部在线计算分位，不读快照。产物落在 `code/M_ENT_PAINPOINT_GAP_out.json`，含 `compute.group_key`、`compute.dims`、`compute.baseline_online`、`compute.gaps`、`compute.unit_check`、`compute.extension_track` 六块。

| 命令 | 期望 | 备注 |
|---|---|---|
| `python3 M_ENT_PAINPOINT_GAP.py` | 8 组 / 28 配对 / 1,131 家 | 秒级（窗口函数 + 8 组分位） |
| `rebuild_metric.py M_ENT_PAINPOINT_GAP --check` | 语义一致 | 重跑对账 |
| `audit_md_vs_out.py --only M_ENT_PAINPOINT_GAP` | 无漂移 | 正文数字逐项对产物 |

耗时主要花在「取最新年」的窗口函数与 8 组分位计算上（具体秒数不写进产物，见 DATA_FACTS §3.44）。生产上分位应按季度预计算落表——这也正是配置表应该承担的角色。

### 2.8 与旧稿的差异

旧稿在开发库口径下同样判「部分支持」，但缺口结构不同：旧稿的基线来自一张演示库的诊断配置表（有阈值、有档位），本稿只能用在线分位，且新增了「单位疑混用」这条旧稿没有的发现。

|---|---|---|---|
| 基线来源 | 配置表（含阈值） | 在线 P25/P75 | 配置表不存在 |
| 分组键 | 产业链分组 | 行业门类代理 | Q018 未闭合 |
| 研发人员占比 | 有列无值 | 整维缺（0/90,926） | 一致但更硬 |
| 单位问题 | 未发现 | 疑元/万元混用 | 新增体检 |
| 可打分家数 | 未逐项核 | 1,131 家 | 新增核算 |
| 档位 | 部分支持 | 部分支持 | 一致 |

### 3.4 结构支持判定

结构侧的问题是「两缺一疑」：缺基线配置表、缺研发人员值、金额单位疑。前两个是硬缺，第三个是质量问题。

值得注意的是，缺基线表反而让本件更透明：在线分位是每次现算的，公式与阈值都写在脚本里，谁都能复核；配置表如果存在但内容不透明，反而更难验证。当然，长期看仍应建表——现算的成本与一致性风险都高于读表。

### 3.5 与 live 及同域件的差异

与同域三件的差异已在 §1.1 写明，这里补充数据层面的对照：

| 件 | 来源 | 单位 | 输出 |
|---|---|---|---|
| `M_ENT_PAINPOINT_COUNT` | 六张风险表 | 条 | 事件计数 |
| `M_ENT_PAINPOINT_TOPIC` | 风险事件文本 | 标签 | 主题分布 |
| `M_ENT_PAINPOINT_SEVERITY` | 多项偏离度加权 | 档 | 轻/中/重 |
| 本件 | 年报财务 + 利润表 | 差值 | 原始差额 |

四件共用「痛难点」这个词，但对象完全不同：前三件看的是「出了什么事」，本件看的是「经营指标差多少」。把本件的差值塞进 SEVERITY 的分数里，会重复计算；把 COUNT 的事件条数当成本件的样本量，会张冠李戴。

## 四、数据缺失情况

### 4.1 缺口性质判定

| 形态 | 本件表现 | 可否修复 |
|---|---|---|
| 缺表（从未建） | 基线/分位配置表 0 张 | 可（建表） |
| 整列空值 | `development_employee` 0/90,926 | 可（回填） |
| 配对不足 | 营收增长率 17 家 | 可（换源） |
| 键未闭合 | Q018 产业链分组 | 需甲方 |
| 量纲不齐 | 金额元/万元混用 | 可（校单位） |

五种形态里只有「键未闭合」需要外部决策，其余都能在数据侧解决。这也是判「部分支持」而非「不支持」的底气：路径清楚，只是还没走。

### 4.2 逐条影响（含代理偏差量化）

**① 分组键代理偏差。** 用行业门类代理产业链分组，组内异质性上升，P25/P75 区间被拉宽。量化的一个侧面：制造业净利润率的 P25 = 0.0065、P75 = 0.1019，区间宽度 0.0954；信息传输/软件业的 P25 = −0.1033、P75 = 0.1523，宽度 0.2556——后者是前者的 2.7 倍，说明同一门类内部的离散度差异极大。区间越宽，差值绝对值越被压小，这是「代理导致差距偏小」的直接证据。偏差幅度无法在库内量化，须 Q018 闭合后重算。

**② 研发人员占比整维缺。** `development_employee` 非空 0/90,926，人才维度没有任何输入。本件输出 null 而不是 0 差距——0 差距意味着「与同行持平」，是错误结论。

**③ 营收增长率配对不足。** 年报表 2023→2024 同企两年营收交集只有 17 家，无法建组内分位。扩源轨：利润表 `yysr` 跨年可配对 3,162 家，但 calc-logic 指定源是年报表，换源须先闭合口径，故本件未纳入，只把 3,162 这个数记进 `extension_track`。

**④ 金额单位疑混用（最严重）。** 营收最大值 29,800,924,733.43 与中位数 16,554.99 并存，人均产值中位数 85.33。若按「元」理解，中位数企业年营收 1.66 万元、人均产值 85 元，均不合常理；若按「万元」理解则合理。混用的后果是：同一组内既有按元填报的样本、也有按万元填报的样本，分位数被强行拉平，差值失去物理意义。方向不可定，幅度不可量化，只能声明。

**⑤ 期别偏早。** 营收>0 的行集中在 2014—2017，最新年实际取到早年。差值反映的是历史截面，与「当前经营状况」有时滞。这个偏差方向明确（结论偏旧），但无法用库内数据校正。

### 4.3 明确不做什么（禁止的替代）

- 不给缺维补 0 差距——会把「无数据」写成「与同行持平」。
- 不把差值合成一个总分——那是 SEVERITY 的职责，本件只出原料。
- 不设「劣势/优势」硬阈值——阈值属主观，口径明确要求不设。
- 不用全样本分位替代组内分位——跨行业不可比。
- 不把绝对金额当对外读数——单位未校前只能排序。

### 4.4 若甲方补齐后的口径升级路径

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 校金额单位 | 差值绝对值可信 | 部分支持 → 可讨论完全转换 |
| 建基线配置表 | 口径可审计、可版本化 | 完全转换支持 |
| 回填研发人员数 | 人才维可用 | 六维齐 |
| 换利润表扩营收增长 | 成长维 3,162 家 | 五维可用 |
| Q018 闭合 | 分组更贴语义 | 精度提升 |

**基期声明**：`base_years_used` = [2014, 2015, 2016, 2017, 2025]；`base_years_missing` = [2018, 2019, 2020, 2021, 2022, 2023, 2024]。每企取「最新一个有营收的年」，取到的年份集中在 2014—2017，故 used 只列实际承载主体的年份；2018—2024 虽在表内存在，但承载主体极少，单列 missing 以免被读成可用基期。增长率维用 2023→2024 两年配对（17 家），与本截面基期不同源。

## 五、王惠方法对照

本件不在王惠 20260816 底稿内，口径来自算法 2026-09。但同域的 `M_ENT_PAINPOINT_SEVERITY` 是王惠定义过的（ALGO-ENT-DEEP-143，偏离度加权汇总 + 轻/中/重三档），两者关系必须讲清。

王惠的 SEVERITY 做的是「合成」：把多项偏离度按权重加成一个严重度分，再切三档。本件做的是「拆解」：只给单项偏离的原始差额，不合成、不加权、不分档。顺序上本件在上游——先有差额，才谈加权。因此本件不能替代 SEVERITY，SEVERITY 也不应绕过本件自己算差额（否则两套差额口径会打架）。

与 `M_ENT_PAINPOINT_COUNT`、`M_ENT_PAINPOINT_TOPIC` 的边界：那两件是王惠口径（COUNT 数风险事件、TOPIC 做主题归类），对象是「事件」，本件对象是「财务指标」。三者的输出不能相加，也不能互相校验——事件多不代表指标差，指标差不代表有事件。

**选用建议**：雷达图上线时把研发人员占比那条轴显式置灰并标「无数据」，不要留空让人误读为 0；营收增长率那条轴标注「样本 17 家，仅供参考」；金额类指标只显示相对位置（高于/低于 P25/P75），不显示绝对差额，直到单位问题解决。

## 附录 I 口径问答

**问：为什么不给一个「痛难点总分」？**

答：那是 `M_ENT_PAINPOINT_SEVERITY` 的职责（王惠口径，加权 + 三档）。本件只出原料，合成会让两套口径打架。

**问：研发人员占比为什么显示空而不是 0？**

答：`development_employee` 整列为空，0 差距会读成「与同行持平」。空表示「无数据」，是唯一诚实的呈现。

**问：为什么用 P25/P75 而不是均值？**

答：财务指标分布右偏严重（营收最大值与中位数差六个数量级），均值被极值主导。分位数对极值稳健，也便于划出「下四分位/中间段/上四分位」三段。

**问：差值能对外发布吗？**

答：目前不能。金额单位疑混用，绝对差额不可信；相对位置（高于/低于哪条线）可用。单位校完后才谈发布。
