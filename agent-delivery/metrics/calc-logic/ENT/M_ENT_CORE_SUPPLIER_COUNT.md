## 摘要

「核心供应商数」要回答的是：一家企业最要紧的几个供应商有几个。正本把它定义成「供应集合 S 里，与本企有出资关系的那部分，按出资额取前五，数个数」。这个定义有一个隐含前提——S 是供应商，出资额是本企对供应商的投资。

前提不成立。第一，S 不存在：gkx 无供应边表，旧机开发库的同名表 0 行。第二，`dwd_org_invest_info` 里的出资额是「投资方 → 被投企业」的资本投入，不是「本企 → 供应商」的采购或投资。第三，全库没有 `is_core_supplier`、`purchase_amount`、`purchase_ratio`、`supplier_rank` 任何一个同义列。

代理面试算的结果很有说服力，也很有讽刺意味。若把投资边直接当供应边，S 就变成了「本企的被投企业集合」，再与本企的投资记录求交，交集还是它自己，最后按出资额取 TOP5，得到的数就是 `min(5, 出度)`。实测 19,611 家投资方里，1,952 家出度 ≥5，全部得 5；3,548 家出度 2—4；14,111 家出度恰好 1。指标退化成「有没有投满 5 家」，与供应商无关。

更能说明问题的是出度榜首：香港中央结算有限公司，369 个「被投企业」。这是沪深港通的持股结算机构，它出现在这张表里，说明 `dwd_org_invest_info` 混入了二级市场持股记录，连「产业投资」都不是。

金额列也不能用。列注释写「投资金额(元)」，但全资边的中位数是 1,000、最小 0.1、最大 19,999,999，跨九个数量级；按元读，大量全资子公司资本不足千元；按万元读，最大边达 2,000 亿元级。两种读法都不自洽，任何「按金额排序」都不可复现。

结论：完全不支持。四组否定性探针齐备，代理面不仅语义不符，连数值稳定性都不成立。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业分析 → 企业供应链关系分析 → 核心供应商**。页面形态是画像卡上的一个 0—5 的数，点开显示「你最依赖的几家供应商」。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业分析 → 供应链关系分析 |
| 页面载体 | 画像卡 |
| 输出形态 | 企业 → 核心供应商数（0—5） |
| 更新频率 | 周 |
| 粒度 | 企业（org_id） |

### 1.2 为什么需要这个指标

供应商数量告诉你「有几个」，核心供应商数告诉你「最要紧的几个是谁」。后者是集中度分析的基础：核心供应商占采购额的比例越高，单点断供的风险越大。

第二个用途是排序依据。同样有 200 个供应商，核心 5 家与核心 1 家的风险结构不同。这个数能把「广而不深」与「窄而深」分开。

第三个用途是风险传导的起点。断链风险要沿最关键的边传播，核心供应商就是那几条边。

### 1.3 需求文档是否给出定义方法

**给了，而且把「不要什么」写得更细。** 正本的依赖表列了三行：

| 顺序 | 表 | 用途 |
|---|---|---|
| 1 | `enterprise_supply_chain` | 直接一级供应商（`relation_type='supplier'`） |
| 2 | `enterprise_invest` | 本企 → 该供应商的 `invest_amount` |
| 3 | 本条 | TOP5 后 COUNT |

口径四句：

> 供应集合 S = DISTINCT related_org_id FROM enterprise_supply_chain WHERE org_id=:id AND relation_type='supplier'
> 核心 = S 中与 enterprise_invest 配上的行（投资方 = :id，被投 = 该供应商），ORDER BY invest_amount DESC 取 TOP5
> 不足 5 个有金额：有几个算几个（0～5；并列可能 >5）
> 禁止 risk_level、is_core_supplier、chain_score、股东表

最后一句很重要：正本明确禁止读 `is_core_supplier`——那一列是上游某条 MODEL 的产出，不是本件的输入。这解释了为什么本件不能简单「找一列叫 core 的字段数一数」。

本件的实测结论是：第 1 张表 0 行，第 2 张表（对应 gkx 的投资边）方向不符，第 3 步无从执行。

### 1.4 类似指标权威机构构建方法可行性

「核心供应商」在业界的构建方法有四种：

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 采购额 TOP-N | 企业采购管理实践 | 按年度采购额排序取前五 | 高：但需采购额 |
| B 年报前五名供应商 | 上市公司年报 | 文本披露前五名 | 中：只覆盖上市，且是占比不是名单 |
| C 供应集中度指数 | 供应链管理文献（HHI） | 采购份额平方和 | 高：需份额 |
| D 关系强度打分 | 商业图谱 | 多信号加权 | 低：权重不公开 |

A、C 两族都需要「采购额或采购份额」，本库没有。B 族需要年报文本，本库的财务表只有汇总数，没有前五名供应商附注。D 族是黑箱。

正本选的路径接近 A 族，但用「出资额」代替「采购额」。这个替换在语义上不成立——出资是资本投入，采购是货物交易。实测数据也印证了这一点：出资比例 100% 的边（全资子公司）有 15,907 条，它们显然不是「核心供应商」，而是「子公司」。

## 二、计算过程（为什么不成立）

正本的三步是串行的：S → 交集 → TOP5。第一步就要 `enterprise_supply_chain`，这张表在 gkx 0 张、开发库 0 行。S 为空集，交集为空集，TOP5 为空集，`COUNT` 得 0。

若强行用投资边代替 S，三步会变成：S' = 本企的被投企业集合；交集 = S' ∩ {本企投资的对象} = S'；TOP5 = 按出资额取前五。结果等于 `min(5, 出度)`——一个只与「投了几家」有关的数，与供应完全无关。

这个退化不是理论推演，是实测结果：19,611 家投资方里 1,952 家出度 ≥5，按代理口径全部得 5；14,111 家出度恰好 1，全部得 1。指标失去区分度，也失去语义。

金额列同样不可用：全资边金额跨九个数量级，单位读法不自洽（详见 §3.4）。即便接受「用投资边代理」，TOP5 的排序也不可复现。

| `relation_type` | 0 | 边类型 |

活库复核：`information_schema.columns` 按 `column_name LIKE '%is_core%' OR '%core_supplier%' OR '%purchase_amount%' OR '%purchase_ratio%'` 查，返回 0 行。表名含 `supply` 的表 0 张。

这一条比母集合缺失更致命：即便有供应边，没有「核心」的判定依据（出资额、采购额、排名），也筛不出核心子集。正本用「出资额」当依据，但出资额在投资表里，方向是反的。

### 3.4 探针三：代理面试算与它的三处塌陷

代理口径：S' = 本企的被投企业；核心 = 按出资额取前五；核心数 = `min(5, 出度)`。

**塌陷一：方向反了。** 列注释写得很清楚：

| 列 | 注释 | 读义 |
|---|---|---|
| `name_cn` | 机构名称 | 投资方 |
| `inv_name` | 被投资企业名称 | 被投方 |
| `investment_amount` | 投资金额(元) | 出资额 |
| `investment_ratio` | 股权占比(%) | 持股比例 |

方向自证用华为系做了一次：`华为投资控股有限公司 → 华为技术有限公司`，出资比例 1.0。若把这条边读成「华为技术的核心供应商是华为投资控股」，任何人都能看出荒谬。

最大出资边（`top_edges_returned` 前 5）：

| 投资方 | 被投方 | 出资额（原始值） | 出资比例 |
|---|---|---:|---:|
| 广州市城市建设投资集团有限公司 | 广发银行股份有限公司 | 744,013,552 | 0.03 |
| 广东粤财资产管理有限公司 | 广发银行股份有限公司 | 212,099,341 | — |
| 广东宏禧瑞投资合伙企业（有限合伙） | 广东宏科建设股份有限公司 | 122,641,550 | — |
| 深圳市成祥投资发展有限公司 | 深圳市木雅建设科技股份有限公司 | 19,999,999 | — |
| 深圳市财政局 | 深圳市引导基金投资有限公司 | 10,000,000 | — |

这五条全是资本关系：城投投银行、财政局设引导基金。把它们写成「核心供应商」，语义完全错位。

**塌陷二：出度截断。** 代理口径的数值分布：

| 出度 | 投资方数 | 代理口径的核心数 |
|---|---:|---:|
| ≥5 | 1,952 | 恒为 5 |
| 2—4 | 3,548 | 等于出度 |
| =1 | 14,111 | 恒为 1 |
| 合计 | 19,611 | — |

19,611 家里 1,952 家（9.95%）恒得 5，指标对这批企业完全没有区分度。

出度榜首更能说明数据性质：

| 投资方 | 被投数 |
|---|---:|
| 香港中央结算有限公司 | 369 |
| 深圳市创新投资集团有限公司 | 249 |
| 深圳市引导基金投资有限公司 | 172 |
| 深圳市高新投创业投资有限公司 | 170 |

香港中央结算有限公司是沪深港通的持股结算机构，它「投资」369 家，实际是代持境外投资者持股。这张表混入了二级市场持股记录，连「产业投资」都不是，更不可能是「供应关系」。

**塌陷三：金额单位不自洽。** 全资边（出资比例 ≥99.99%）的金额分布：

| 区间 | 条数 |
|---|---:|
| 行数 | 15,881 |
| 最小 | 0.1 |
| 中位数 | 1,000 |
| 最大 | 19,999,999 |
| <10 | 141 |
| 10—1,000 | 6,768 |
| 1,000—100,000 | 8,289 |
| ≥100,000 | 683 |

列注释写「元」，但按元读，6,768 家全资子公司的出资额不足 1,000 元；按万元读，最大的那条是 2,000 亿元级。两种读法都不能自洽。任何「按金额排 TOP5」在这张表上都不可复现。

顺带一个相关的口径瑕疵：`investment_ratio` 的注释写「股权占比(%)」，实测取值全在 0—1 之间（最大值 1.0，>1 的行 0 条），实际按小数存。用它做阈值判断时必须 ×100，否则「≥99.99%」这个条件一条都命中不了。

### 3.5 探针四：替代面清单

| 面 | 规模 | 能否定义核心 |
|---|---|---|
| 投资边 | 46,967 行 | 否：方向反、无采购额、金额单位乱 |
| 股权边 | 400,286 行 / 70,034 对 | 否：股东构成，不是采购 |
| 母子公司边 | 178,900 行 / 21,909 母公司 | 否：控制关系，不是采购 |
| 中标候选 | 39,520 行 / 12,528 中标方 | 否：缺采购方 org_id |
| 招投标公告 | 39,962 条 | 否：招标方只有名称字符串 |

五个面都试过，没有一个能同时满足「对象是供应商」与「有排序依据」两个条件。母子公司边尤其容易误用：它确实有明确的「父子」结构，看上去像供应链上下游，但它是合并报表范围，不是货物流动。

## 四、数据缺失情况

### 4.1 缺口清单

| 编号 | 缺口 | 性质 | 可否补 |
|---|---|---|---|
| G1 | 供应边表 0 行 | 数据性 | 需 ETL 灌数 |
| G2 | 无核心标记列 | 结构性 | 随 G1 建 |
| G3 | 无采购额/份额列 | 结构性 | 需交易数据 |
| G4 | 投资边方向不符 | 语义性 | 不可改，只能换源 |
| G5 | 投资金额单位不自洽 | 数据性 | 需清洗 |
| G6 | 无 `enterprise_supply_summary` 结果表 | 工程性 | 可建 |

### 4.2 逐条影响

G1 决定 S 是否为空。G2、G3 决定「核心」能否判定。三者是串联的：缺一个，`COUNT` 就是 0 或不可复现。

G4 是本件与 `M_ENT_SUPPLIER_COUNT` 最大的不同：那边只是「没有边」，本件还多一层「有边但方向反」。方向问题不可通过清洗解决，只能换数据源。

G5 影响排序稳定性。即便接受代理，金额排序也不可复现，因为同一张表里混着两种单位。

G6 是落表缺口，可在口径打通后一次性补。

### 4.3 明确不做什么（禁止的替代）

- **不用投资边当供应边。** 方向反、字段缺、单位乱。
- **不用股权边当供应边。** 股东构成与采购关系无关。
- **不用中标记录当核心供应。** 缺采购方主键。
- **不读 `is_core_supplier` 造核心。** 正本明令禁止，且该列只在空表里。
- **不用「出度 ≥5 恒为 5」的结果充数。** 那是退化值，不是指标。

### 4.4 若甲方补齐后的口径升级路径

第一步，灌供应边（`org_id, related_org_id, relation_type`），S 成立。

第二步，补采购额或采购占比（`purchase_amount` / `purchase_ratio`），TOP5 才有排序依据。

第三步，把「本企对该供应商的出资额」单独建表，与投资边解耦——不能用二级市场持股表当产业投资表。

三步完成后，本件可从「完全不支持」升到「完全转换支持」；落 `enterprise_supply_summary` 后到「完全直接支持」。

## 五、王惠方法对照

王惠侧本件无正本，本节只做同族对照。

| 对照项 | 同族做法 | 本件做法 | 差异与选用建议 |
|---|---|---|---|
| 核心定义 | 部分件用 `is_core_supplier` | 正本禁止，本件不用 | 建议同族统一禁用该列 |
| 排序依据 | 部分件用投资额 | 本件实测不可用 | 建议改用采购额 |
| 代理处置 | 部分件默认可用 | 本件实测退化 | 建议同族引用本件 §3.4 |

**选用建议**：同族若需「核心」概念，应等采购额到位后重建，不要沿用「投资额 TOP5」这一版口径。
