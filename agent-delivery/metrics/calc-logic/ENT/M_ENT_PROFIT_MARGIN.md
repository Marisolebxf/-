## 摘要

「企业净利率」是最基础的一行财务比率：净利润除以营业收入。它不需要模型、不需要权重，唯一的技术问题在数据侧——分子分母是否同时可得、单位是否一致、分母是否为正。

实测两个来源。`dwd_org_annual_financial_info` 90,926 行里有 2,095 行同时具备正营收与非空净利，涉及 1,257 家企业；`dwd_org_annual_report_asset` 527,034 行里只有 11,970 行能解析出数值（其余 515,064 行不可算：其中 514,140 行是 `xsze` 严格等于「企业选择不公示」的法定占位串，144 行 `xsze` 为空，另 780 行为其它非数值文本），涉及 7,452 家。两源按「企业 × 年」合并去重后，6,526 家企业各取最新可得年，得到 6,526 个净利率值。

分布的重心很低：中位数 0.72%，10 分位 −54.31%，90 分位 14.67%，亏损面 30.37%，落在 ±10% 区间的占 67.05%。这不是「企业普遍不赚钱」的证据，而是小分母效应的必然结果——大量小微企业营收几十万、净利几万，比值天然抖动。

一个必须点名的坑：两源存在单位不一致。财务表里招商银行 2022 年营收记为 44,933,800 元（约 4,493 万元），与公开口径差两个数量级；资产表里还有营收 5.0 元、净利 −1,017 元的行，算出 −20,344,584% 的净利率。这类行共 586 个（8.98%），本件把它们留在分布里（它们是真实行）、剔除出名次榜（否则榜首永远是异常值）。

结论是**部分支持**：公式与字段都成立、6,526 家已现转，但覆盖率 3.45%、单位不一致、研发两列全为 0，三项都不支持「完全转换」这个档。

## 一、需求定义概述

### 1.1 所属功能模块

该指标挂在**企业分析 → 企业画像 → 财务健康**。页面形态是企业详情页上的一个百分比，配一行「净利润 / 营业收入」的小字；另有一个行业分位条，显示该企业在同行业中的位置。

它是财务画像里最容易读、也最容易被误读的一个数。容易读是因为比值直观；容易误读是因为小分母——营收 10 万、净利 −5 万的企业，净利率 −50%，但它的经营含义与营收 10 亿、净利 −5 亿的企业完全不同。

| 项目 | 内容 |
|---|---|
| 功能路径 | 企业分析 → 企业画像 → 财务健康 |
| 页面载体 | 详情页百分比 + 行业分位条 |
| 输出形态 | 企业 → 净利率（%）+ 营收 + 净利 + 年 |
| 更新频率 | 年度（随年报披露） |
| 粒度 | 企业 × 年，取最新可得年 |

### 1.2 为什么需要这个指标

第一，它是盈利质量的最短判据。毛利率看产品、净利率看整体——费用、税、非经常损益全在净利里，一个数就能把「赚不赚钱」说清楚。

第二，它是分层筛选的入口。按净利率可以把企业分成亏损、微利、健康、高利润四层，每层的服务策略不同：亏损企业需要纾困，高利润企业需要扩张服务。

第三，它是对账工具。营收与净利都来自企业年报，若某企业的净利率与同行业、同规模企业差一个数量级，大概率是录入或单位问题——本件正是靠这条规则发现了 586 个异常行。

### 1.3 需求文档是否给出定义方法

**给了公式，没给分母口径与异常处置。** calc-logic 写的是净利率 = 净利润 / 营业收入 × 100%。未给的是：营收为 0 或负时怎么办、净利为负时是否取绝对值、跨年是否可借值、异常值是否剔除。

本件的处置：营收必须为正，否则不出数（不补 0、不用绝对值）；净利为负照算（负净利率是有意义的读数）；不跨年借值（缺就是缺）；异常行（|净利率| > 100%）保留在分布、剔除出名次榜。四条都是本件自定义、待甲方确认，写进产物 `custom_thresholds`。

### 1.4 类似指标权威机构构建方法可行性

净利率是最通用的财务比率之一，官方统计、商业数据库、学术研究三套体系都在用，差别在分母口径与样本范围。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A 企业年报口径 | 会计准则下的利润表 | 净利润 / 营业收入 | 高（本件采用） |
| B 规上工业统计 | 国家统计局规上企业效益指标 | 利润总额 / 营业收入 | 中（利润总额含税，口径略宽） |
| C 商业库比率 | 企业信息服务机构 | 净利 / 营收，含估算值 | 中（估算比例不公开） |

**A 族是本件采用的方法。** 两源的字段语义都是「净利润」与「营业收入」，与利润表同构。差别在精度：财务表是 double，资产表是带「万元」后缀的字符串，后者需要解析，解析失败即弃。

**B 族**用利润总额（税前），比净利率高估，不能与本件混用。若甲方要税前口径，需另立指标，不改本件。

**C 族**常对缺失值做估算，估算比例不公开。本件不做估算，缺就是缺——这也是覆盖率只有 3.45% 的直接原因。

## 二、计算过程

### 2.1 总体思路与数据流

两源分别取「营收 + 净利」都有效的行，算行级净利率；再按企业取最新年，得到企业级一个值；最后算分布与榜单。合并时财务表优先——它是 double，精度高于字符串解析。

不做「先按企业求和再相除」。净利率不是可加的比率：把三年的净利相加除以三年的营收相加，得到的是三年加权平均，语义是「三年整体净利率」，不是「最新年净利率」。本件要的是后者。

| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 财务表 | `annual_financial_info` | 营收 > 0 且净利非空 | 2,095 行 |
| 资产表 | `annual_report_asset` | 正则解析「数值+万元」 | 11,970 行 |
| 合并 | 两源 | 按企业取最大年 | 6,526 家 |
| 分布 | 6,526 个值 | 分位与占比 | 一组统计量 |
| 榜单 | 营收 ≥ 1,000 万 | 剔除异常后排序 | 各 10 家 |

### 2.2 口径定义与公式

净利率是净利润与营业收入的比：

$$m_{i}=\frac{\Pi_{i}}{R_{i}}\times 100\%,\qquad R_{i}>0$$

企业级取值规则是「最新可得年」，同年财务表优先：

$$m_{i}^{*}=m_{i,Y^{*}},\qquad Y^{*}=\max\{Y:\ R_{i,Y}>0,\ \Pi_{i,Y}\ \text{非空}\}$$

异常判据是一条纯工程规则，不是财务判断：

$$\text{anomaly}_{i}=1\iff \lvert m_{i}^{*}\rvert>100\%$$

之所以用 100% 而不是 50% 或 200%，是因为净利率超过 100% 意味着净利大于营收（非经常损益、投资收益、单位错配都可能造成），这类值在排名里没有可比性。阈值写进 `custom_thresholds`，标注「本件自定义、待甲方确认」。

| 量 | 取值 | 含义 |
|---|---|---|
| 净利率中位数 | 0.7205 | 一半企业低于此 |
| 10 分位 | −54.3063 | 尾部亏损 |
| 90 分位 | 14.6658 | 头部盈利 |
| 亏损面 | 30.3708 | 净利率 < 0 的占比 |
| 异常行 | 586 | 8.9795% |

### 2.3 累计口径与年度切分的区别

本件给的是「企业级最新年快照」，不是年度时间序列。两者用途不同：快照回答「这家企业现在赚不赚钱」，时序回答「这家企业的盈利率在变好还是变坏」。

为什么不做时序：能连续两年同时有营收与净利的企业极少（财务表 90,926 行里双值齐的只有 2,095 行，跨年重叠更少）。做时序会得到一个样本量极小的面板，任何趋势都不显著。

| 口径 | 含义 | 本件是否采用 |
|---|---|---|
| 企业最新年 | 每家企业一个值 | 是 |
| 年度横截面 | 每年一组企业 | 否（样本太少） |
| 企业面板 | 同一企业多年 | 否（重叠不足） |
| 行业均值 | 按行业聚合 | 否（覆盖率不足） |

### 2.4 计算步骤（脚本逐步实现）

1）读双源面板快照（未命中则现查并落盘）；2）财务表筛营收 > 0 且净利非空；3）资产表正则解析「数值+万元」并乘 10,000 折成元；4）两源合并，按企业取最大年，同年财务表优先；5）算行级与企业级净利率；6）算分布、异常与榜单。

第 3 步的解析是必要之恶。资产表的 `xsze` / `jlr` 是 varchar，值形如「5199.350128万元」，另有大面积「企业选择不公示」。解析规则是 `^(-?\d+(\.\d+)?)万元$`，不匹配即弃——不用 `CAST` 硬转，因为 `CAST('企业选择不公示' AS DOUBLE)` 会得到 0，而 0 会被当成真实营收。

| 步骤 | 实现 | 校验 |
|---|---|---|
| 财务表筛选 | `rev > 0 AND np IS NOT NULL` | 2,095 行 |
| 资产表解析 | 正则 + ×10,000 | 11,970 行 |
| 企业取值 | max(year) | 6,526 家 |
| 分布 | 分位函数 | 六个统计量 |
| 榜单 | 营收门槛 + 剔异常 | 各 10 家 |

### 2.5 结果与分布

中位数 0.72% 说明一半企业的净利率在 1% 以下——这个数字低得反直觉，但符合样本结构：能出数的企业里大量是小微主体，营收几十万、净利几千，比值天然贴近 0。

亏损面 30.37% 是另一个值得说的数：近三分之一的企业净利率为负。这不是「三成企业亏损」的经济结论，而是「有年报且能算出净利率的企业里三成亏损」——样本偏向有披露义务的主体，不能外推到全库。

异常行 586 个（8.98%）单独统计。它们的净利率绝对值超过 100%，成因有三：单位混用（招商银行营收记成 4,493 万）、极小分母（营收 5 元）、非经常损益（净利远大于营收）。三类都不剔除出分布，只剔除出名次榜。

| 统计量 | 取值 |
|---|---|
| 样本数 | 6,526 |
| 中位数 | 0.7205 |
| 均值 | −10,169.5231 |
| 均值（剔异常） | −0.0117 |
| 10 分位 | −54.3063 |
| 90 分位 | 14.6658 |
| 亏损面 | 30.3708% |
| ±10% 区间 | 67.0549% |

均值 −10,169.52% 与中位数 0.72% 的巨大落差，正是尾部异常值造成的。剔除 586 个异常后均值变成 −0.0117%，几乎归零——这说明「均值」在这个分布里没有解释力，必须用中位数与分位数。

### 2.6 关键中间量与校验

五个中间量：财务表双值 2,095 行、资产表可解析 11,970 行、合并行 12,550、企业级 6,526、底册 189,116。

校验一：2,095 + 11,970 = 14,065 行级候选，去重合并后 12,550 行（同年同企业两源都有时保留财务表），通过。校验二：12,550 行归并到 6,526 家，平均每家 1.92 行，通过。校验三：6,526 / 189,116 = 3.4508%，与 `coverage_pct` 相等，通过。

| 量 | 取值 | 校验方式 |

| 资产表可解析行 | 11,970 | 正则过滤后计数 |
| 合并行 | 12,550 | 去重后计数 |
| 企业级 | 6,526 | 按企业取最新年 |
| 覆盖率 | 3.4508% | 6,526 / 189,116 |

### 2.8 与旧稿的差异

## 三、数据支撑情况

### 3.1 依赖表与可得性

两源都在、都有数，但可用比例差距很大：财务表 90,926 行里只有 2,095 行（2.30%）双值齐；资产表 527,034 行里只有 11,970 行（2.27%）可解析。两源叠加后覆盖率 3.45%，这是本件的核心约束。

成本在扫描：资产表 527,034 行、无可用索引，正则过滤全表约 40 秒。处置是落快照。

| 依赖维度 | 实测状态 | 关键证据 | 缺口与修复路径 |
|---|---|---|---|
| 营业收入 | 部分可用 | 财务 2,191 行 > 0；资产 11,970 行 | 主档补财务字段 |
| 净利润 | 部分可用 | 财务 2,038 行非空；资产 12,967 行 | 同上 |
| 企业名称/城市 | 可用 | 财务行绑定主档 | 无 |
| 行业分类 | 部分可用 | 随财务行 | 主档行业填充率另计 |
| 研发投入 | 不可用 | 两列全为 0 | 需甲方补数 |
| 全库覆盖 | 不足 | 6,526 / 189,116 | 需外部财务源 |

### 3.2 四判定落表

结构过、数据部分过。分叉点在覆盖率：3.45% 的覆盖支撑不了「全库企业净利率」这个说法，只能支撑「有披露企业的净利率」。

| 判定项 | 结论 | 证据 |
|---|---|---|
| 表结构直接支持（开发库+三方库） | 否 | 无净利率结果面 |
| 表数据直接支持（开发库+三方库） | 否 | 同上 |
| 依赖表结构支持（开发库/三方库） | 是 | 两列齐、类型可算 |
| 依赖表数据支持（开发库/三方库） | 部分 | 6,526 家 / 3.45% |
| 聚合结论 | 部分支持 | 覆盖不足 |

### 3.3 数据量、覆盖与代表性

覆盖上，6,526 家分布在 13 个年度（2013—2025），绝大多数落在 2014—2024。这个跨度说明数据不是某一年的一次性快照，而是逐年累积的披露。

代表性上，能算出净利率的企业偏向三类：上市公司与挂牌公司（有强制披露）、规上企业（有统计报送）、以及部分主动公示年报的中小企业。这个偏向决定了本件的结论只能用于「有披露主体」的子population，不能外推全库。

两源的亏损面也不同：财务表 1,255 家里 307 家亏损（24.46%），资产表 5,271 家里 1,675 家亏损（31.78%）。资产表样本更大、更偏中小，亏损面更高，符合直觉。

### 3.4 结构支持判定

结构侧够用：两列都是数值语义（一为 double、一为带单位字符串），公式无歧义，合并键清晰。

局限在单位。财务表标称「元」，但个别行明显是「万元」（招商银行 4,493 万营收）；资产表标称「万元」，解析时统一乘 10,000。两源单位不统一，是 586 个异常行的主要来源。

### 3.5 与开发库 live 的差异

开发库有财务结果面，gkx 只有原始年报行与财务行。上线需把企业级净利率物化成宽表（`org_id, year, margin, rev, np, src`），并保留 `src` 一列，让下游知道这个值来自哪个源。

建议物化时同时存「原始值」与「异常标记」，不要把异常行直接丢掉——丢掉会让分布失真，保留但标记才能既算分布又做榜单。

## 四、数据缺失情况

### 4.1 缺口清单

六个缺口，按影响排序。前三个决定指标能不能用，后三个决定指标能不能细看。

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| 覆盖仅 3.45% | 不能代表全库 | 只对已披露企业出数 | 接外部财务源 |
| 两源单位不一致 | 8.98% 异常行 | 单列异常、榜单剔除 | 源方修单位 |
| 研发两列全 0 | 不能做研发交叉校验 | 不做 | 甲方补数 |
| 90,926 行中 2.30% 双值齐 | 财务表本身稀疏 | 用资产表补 | 提升填报率 |
| 资产表无城市 | 榜单只能来自财务表 | 榜单限财务表 | 补 jgid → 主档映射 |
| 行业分类随财务行 | 行业分位不可算 | 不做行业分位 | 补行业字段 |

### 4.2 逐条影响

**覆盖 3.45%** 是最根本的缺口。它意味着「全库平均净利率」这个数不可交付——样本偏向有披露义务的主体，它们的盈利结构与小微企业完全不同。页面上只能写「已披露企业净利率」，不能写「企业净利率」。

**单位不一致**是第二硬的缺口。招商银行 2022 年营收 44,933,800 元、净利 12,848,400 元，算出 28.59% 的净利率——数值本身「合理」，但与真实营收差两个数量级，说明分子分母同时被缩小了同样的倍数。这类行不影响比率（比率对同比例缩放不敏感），但会影响「营收规模」这一列，所以榜单里必须同时显示营收绝对值，让读的人自己判断。

**研发两列全 0** 让「研发投入强度 vs 净利率」这类交叉分析完全不可做。两列存在（`arch_development_am` / `development_employee`），但没有任何非零值，属结构性空列。

### 4.3 明确不做什么（禁止的替代）

- 不把 0 当缺失——`CAST('企业选择不公示')` 会得 0，直接用会造出大量假亏损。
- 不用净利率的均值做结论——均值被尾部主导，中位数才有解释力。
- 不把资产表 jgid 当 org_id 直接绑城市——两套主键不同源，绑定率未验证。
- 不用研发两列做交叉——全 0 列，任何相关性都是伪相关。
- 不把 6,526 家的分布外推到 189,116 家——样本偏向披露主体。

五条禁令的共同点是「不要把能算的子集说成全库」。能算的是 6,526 家，想说的是 18.9 万家，中间差的是披露覆盖率。

### 4.4 若甲方补齐后的口径升级路径

补齐分两条：一条提覆盖率（接外部财务源或提升年报填报率），一条修单位（源方统一为元）。前者决定能不能代表全库，后者决定异常行会不会消失。

只修单位不提覆盖，档位仍是部分支持——分布干净了，但样本还是 3.45%。只有覆盖率上到能代表全库的量级（经验上过半），才谈得上完全转换支持。

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 接外部财务源 | 覆盖升到双位数 | 视覆盖率而定 |
| 源方统一单位 | 异常行大幅减少 | 仍为部分支持 |
| 补研发两列 | 可做研发交叉 | 仍为部分支持 |
| 补资产表城市映射 | 榜单可扩到 7,452 家 | 仍为部分支持 |

**基期声明**：`base_years_used` = 2013—2025 共 13 个年度（实际出现过的年）；`base_years_missing` = []。本件不构建年度时序，这个字段只说明数据新旧分布，不代表逐年都有可比样本。

## 五、王惠方法对照

王惠原稿把净利率定义为「净利润 / 营业收入」，与本件完全一致。差异在数据侧：原稿假定财务表覆盖足够，本件实测双值齐只有 2.30%，必须引入资产表补齐。

第二处差异是异常处置。原稿没有异常判据，本件加了 |100%| 阈值并单列 586 行。这不是改口径，是加一条工程规则让榜单可比。

**选用建议**：公式、分母必须为正、不跨年借值三项沿用王惠；数据源扩为双源；异常判据与营收门槛作为本件自定义规则，待甲方确认后固化。若甲方不接受 100% 阈值，可改为 200%，但必须在产物里同步改 `custom_thresholds`，不能只改正文。

## 附录 M 开发交接说明

**问：页面怎么展示？**

答：详情页显示百分比 + 营收 + 净利 + 年；无数据的企业显示「未披露」，不显示 0。

答：会。年报逐年披露，覆盖率会慢慢上升。

**问：能对外称「企业净利率」吗？**

答：不能。必须注明「已披露企业」，且样本只覆盖 3.45%。
