## 摘要

UI「企业发展痛难点分析」提供市场拓展/技术研发/管理/融资四维诊断范围勾选（诊断范围码族），本件为「市场拓展」维。需求文档给了痛难点分析模型的功能叶，但未给四维各自的判定口径。本件以「企业招投标活动强度 + 市场类登记」实跑 gkx：招投标公告 **39,962** 条（公告粒度无 org_id），企业维走中标候选人表 **39,520** 行覆盖 **12,528** 家（去重率 31.7004%），市场登记 `dwd_market` 仅 **15** 行。判档部分支持。

## 一、需求定义概述

### 1.1 所属功能模块

科技专题服务系统 → 企业分析 → 企业发展痛难点分析 → 诊断范围（四维勾选）→ 痛难点类型卡。

### 1.2 为什么需要本指标

痛难点诊断把「企业当前经营堵点」拆成市场/技术/管理/融资四维分别勾选分析，市场拓展维回答「这家企业是否打不开市场」——招投标参与度与中标结果是市场拓展能力最直接的可观测证据链。

### 1.3 需求文档是否给出定义方法

**需求文档没提及本维的判定方法。** 三份需求说明书只有「企业发展痛难点分析」模型功能叶与四维名称，未给「何为市场拓展痛难点」的判定规则（无阈值、无分档）。

### 1.4 类似指标权威方法可行性分析概要

企业市场拓展能力的通行观测方法族：①公共采购参与度（招投标公告量/中标量，中国政府采购网及地方平台公开数据）；②市场登记活跃度；③营收增长（财务面）。本件选 ①+②（公开记录计数，无需建模假设）；③列升档路径。完整版见附录 C。

### 1.5 引用来源

- UI 证据：live 30892 企业分析>企业发展痛难点分析>诊断范围「市场拓展」（20261104 盘点实拍）；缺口清单 seq27（1104 科技专题指标重新盘点任务产出，出处登记见主表「挂载来源」列）。
- 需求叶：`agent-delivery/bid-reference/科技专题服务算法库.md` 企业发展痛难点分析模型（**无本维逐项口径**——如实披露）。
- 探针证据：`metrics/repro/out/M_ENT_UI_PAIN_BATCH_PROBE_out.json`（gkx pain/problem/diagnos/difficult 关键词零命中）。

### 1.6 推测原意与推测定义

**推测定义（非甲方闭合）**：市场拓展维可观测面 = 企业招投标活动（中标候选人记录）+ 市场类登记；「是否构成痛难点」的判定留模型层，本件交付可观测原料与分布。

**升档触发器**：甲方给出「市场拓展痛难点」判定规则（如 N 月无中标记录即痛）→ 按同一原料出模型结果，视口径闭合程度升档。
