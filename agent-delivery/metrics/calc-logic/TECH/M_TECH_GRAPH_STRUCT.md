## 摘要

「技术点网图结构」要回答的是：技术图谱作为一个网络，它的形状是什么——是星形、团块、还是多个孤岛；哪些节点是枢纽，哪些节点在边缘；网络是稠密还是稀疏，聚类是强还是弱，连通分量有几个。本报告在 105 的 200 节点共现图上复算结构指标，得到 **200 节点、2,643 条边**；不设阈值时 19,898 对几乎两两相连（密度 0.9999），稀疏化后密度降到 **0.1328**，平均度 **26.43**、最大度 **73**，图从「完全图」变成「可解释的骨干图」。

连通性方面，图有 **4 个连通分量**：最大分量 197 个节点（98.50%），另外三个是孤立节点 A24F（电子烟）、A44C（珠宝）、D06F（洗涤）。聚类方面，平均聚类系数 **0.5782**，属于偏高；但聚类系数为 1.0 的节点大多是度 2—9 的小节点，高聚类是「小三角」的必然结果，不等于「社区结构强」。中心性方面，度最高的是 G05D（73），PageRank 最高的却是 G01N（0.021790，度 49）；两个指标的排序差异说明「连接多」与「连接重要」不是一回事。

必须披露三条限制。第一，**节点不是技术点实体**：本图节点是 IPC4 域，Nebula 的「技术点」实体快照不在本库，不能把这张图直接当成产品图壳的数据源。第二，**图壳属性缺失**：层级、类型配色、布局坐标、交互状态都不在本库，STRUCT 只能给结构指标，不能给可视化配置。第三，**结构指标对阈值敏感**：阈值从 Jaccard 0.05 放到 0.03，边数从 2,643 增到 7,278，密度、度、聚类都会变；报告在 §5.3 把阈值敏感性列为必披露项。按 §〇 判**部分支持**。

## 一、需求定义概述（指标定义）

### 1.1 所属功能模块（要开发什么）

本指标属技术图谱构建族的图结构件（GRAPH，STRUCT），页面挂载 TOPIC-TECH-12 / DS-02-TECHGRAPH。产品面是**技术网络结构分析**：给技术图谱提供「节点数、边数、密度、度分布、中心性、聚类、连通分量、层级分布」等结构指标，供图谱概览、关键节点识别、社区发现、布局算法使用。

在这张产品图里，STRUCT 承担的是「图的性质」：104 定义节点，105 定义边，STRUCT 回答「这张图长什么样、哪些节点重要、图是连通的还是分裂的」。三者是流水线关系：104 的实体表决定节点，105 的边表决定连接，STRUCT 在图上算指标。STRUCT 的输出不改变图，只描述图；它不能替代 105 的边语义，也不能替代 104 的实体属性。

### 1.2 为什么需要「技术点网图结构」这个指标

结构指标的价值有三层。第一层是**概览**：一个 200 节点、2,643 条边的图，读者无法直接看懂，需要密度、平均度、分量数这些「压缩指标」来描述。第二层是**关键节点**：度、PageRank、聚类系数能找出枢纽与桥梁，为「重点技术域」「关键技术连接」提供依据。第三层是**布局与交互**：图的稀疏/稠密、分量数、聚类强弱决定用什么布局（力导向、分层、环形），也决定页面上要不要做「分量切换」。

方法上有两条路径。一条是**代理图**：用 IPC4 域做节点、共现做边，结构指标全部可算，优点是数据可得、可复算；缺点是节点不是产品要的「技术点实体」。另一条是**产品图快照**：直接读 Nebula 的技术点图，优点是节点与产品一致；缺点是需要图数据库快照，本库没有。本报告用第一条路径，第二条因快照缺失未做。

### 1.3 需求文档是否给出定义方法

**需求文档给了任务，但没有给公式。**「分析技术点网图结构」是任务陈述；「结合图数据库与技术分类构建结构指标」是数据清单；「输出节点数、边数、中心性等」是产出要求。三处都没有闭合：节点定义（技术点？IPC4？企业？）、边定义（共现？引用？转让？）、阈值、中心性算法（度/介数/特征向量/PageRank）、聚类算法（局部/全局）、分量处理，原文均未定义。

因此本报告采用推测定义（§1.6）：以 IPC4 域为节点、以同申请人共现为边（阈值 20 / 0.05）、以无向加权简单图建模；度用邻居数、PageRank 用加权迭代（damping 0.85）、聚类系数用无向二值邻接、连通分量用并查集。推测定义不是甲方闭合口径，正式发布前须由需求方确认节点、边与算法。

### 1.6 推测原意与推测定义（仿王惠口径写法）

**推测原意**：把技术点网络当成一张无向图，先看它有多稠密、有多少个孤岛、度分布是长尾还是均匀；再算每个节点的重要性（度、PageRank）与局部聚类，找出枢纽节点与桥梁节点；最后把结构指标接到产品图壳上，决定布局与交互。

**推测定义（本批采用，供后续建模；非甲方闭合口径）**：

$$
\rho=\frac{2E}{N(N-1)},\qquad
\bar{k}=\frac{2E}{N},\qquad
C_i=\frac{2T_i}{k_i(k_i-1)}
$$

其中 $N=200$、$E=2,643$；$T_i$ 为节点 $i$ 的三角形数；$\bar{C}$ 为 $C_i$ 的均值。PageRank 用加权迭代：

$$PR_i=\frac{1-d}{N}+d\sum_{j\in N(i)}\frac{w_{ji}}{s_j}PR_j$$

其中 $d=0.85$、$s_j=\sum_k w_{jk}$、迭代 60 次后归一化。连通分量用并查集按二值邻接计算。

## 二、计算过程（计算步骤）

### 2.1 方法选择：先稀疏化，再算结构

STRUCT 的方法选择有一个前置判断：**不稀疏化就没有结构可算**。200 个节点两两组合有 19,900 对，原始共现有 19,898 对，密度 0.999899；这是一个几乎完全的图，度分布、聚类、中心性都会退化成「大家都一样」。只有先按阈值去掉弱边，图才有「核心—边缘」「枢纽—孤岛」的差异。

第二个前置判断是**结构指标必须与边语义绑定**。这张图的边是「同申请人共现」，所以度高的节点是「与很多域被同一批企业布局的域」，不是「技术上最基础的域」；PageRank 高的节点是「被高权重邻居连接的域」，不是「技术价值最高的域」。报告在 §四把「结构重要性」与「技术重要性」分开写，避免把网络指标当成技术评价。

第三个前置判断是**聚类系数用二值邻接，不用权重**。局部聚类系数衡量「邻居之间是否也相连」，用二值邻接是标准做法；若用权重，会把「共现次数」混进「三角形密度」，解释变得困难。PageRank 则用权重，因为它的目的是「按连接强度分配重要性」。两个指标一个用二值、一个用加权，是刻意的选择。

### 2.2 步骤 1｜建图：200 节点、2,643 边

建图复用 105 的边表：节点取全期（2021—2026）件数前 200 的 IPC4 域，边取「同申请人共现、co≥20 且 Jaccard≥0.05」。图的类型是无向加权简单图，权重为共现申请人数。

| 项 | 数值 | 说明 |
|---|---:|---|
| 节点 N | **200** | IPC4 域 |
| 边 E | **2,643** | 共现骨干 |
| 权重合计 | 1,085,258 | 共现次数求和 |
| 最大权重 | 4,794 | G06F—G06Q |
| 原始对 | 19,898 | 未稀疏化 |

## 四、数据缺失情况与结果解读

### 4.1 缺口归因：往哪偏、偏多少、能否交叉验证

**往哪偏。** 第一个缺口（代理图≠产品图）会让结构指标与页面实际图不一致，方向上无法验证「产品图的密度/分量」是否相同。第二个缺口（无图壳属性）会让 STRUCT 只能给数字、不能给布局，方向上把「结构分析」降级为「指标报表」。第三个缺口（阈值敏感）会让边数、密度、度、聚类随阈值变化，方向上使「第一名」「枢纽」不稳定。第四个缺口（无介数中心性）会让「桥梁节点」缺位，方向上只能用度代理，低估「低度但关键」的节点。

**偏多少。** 可定量的是：原始密度 0.999899 与稀疏后 0.132814 的差距；4 个分量、3 个孤立节点；平均聚类 0.5782；跨部边 1,511 条（57.17%）。阈值敏感性可以定量：Jaccard 从 0.05 放到 0.03，边数从 2,643 增到 7,278；收到 0.10，降到 446。不可定量的是「产品图与代理图的结构差多少」——没有 Nebula 快照，无法算。

**能否交叉验证。** 有两条弱验证。其一，200 节点、2,643 边与 105 的边表逐位一致，说明两张图同源。其二，G05D 的度 73 与 105 的「G05D 是高度节点」一致，G01N 的 PageRank 第一与 105 的「G01N 与 G06F 高共现」一致，说明结构指标不是随机生成。两条都只能验证内部一致性，不能验证「代理图代表产品图」。

### 4.2 结果与解读：四种结构，四种用法

第一层是**整体形状**：200 节点、2,643 边、密度 0.1328、平均度 26.43。这组数字的用法是「概览卡片」：告诉读者图不是完全图、也不是树，而是一张保留 13.28% 可能边的骨干图。它不能回答「哪个节点重要」，只能回答「图有多密」。

第二层是**度分布**：0—10 档 46 个、11—60 档 146 个、61—100 档 8 个。这组数字的用法是「分层」：边缘、主体、枢纽三层。它是布局算法的输入（边缘放外圈、枢纽放中心），也是「关键节点」筛选的初筛。

第三层是**中心性**：度第一 G05D（73）、PageRank 第一 G01N（0.021790）。两个指标的用法不同：度找「连接多」的跨域工具，PageRank 找「被重要邻居连接」的关键域。报告建议页面同时展示两个排名，不要合成一个「重要性分」；如果必须合成，要说明权重，并接受「合成后两类节点都被平均」的代价。

第四层是**连通与聚类**：4 个分量、最大 197、平均聚类 0.5782、跨部边 57.17%。这组数字的用法是「布局与交互」：分量数决定要不要做「孤立节点单列」，聚类强弱决定力导向布局的团块程度，跨部边比例决定「按部类分组」会不会切断太多边。报告的建议是「按社区/产业分组，不按 IPC 部硬切」。

## 附录 C　方法可行性报告（完整版）

### C.1 目的与范围

回答三个问题：技术点网图结构的权威口径是什么；本库能算到哪一步；算出来的结构指标能不能直接驱动产品图。范围限定在 IPC4 共现图与结构指标，不涉及社区发现、链路预测、图神经网络与前端渲染。

### C.2 语义锚定

「技术点网图结构」在产品里通常指「技术点实体之间的网络形状」。判断依据可以是节点数、边数、密度、度分布、中心性、聚类、分量，其中密度与度最常用，因为直观、可复算。本指标的语义边界是「IPC4 域代理图的结构」，不是「Nebula 技术点实体图的结构」。这个边界决定了它只能做「结构分析」，不能做「产品图验证」。

### C.3 方法谱系

C.3.1 社会网络分析。用密度、度、聚类、分量描述图，优点是成熟、可解释；缺点是依赖图的质量。本报告用它做主路径。

C.3.2 加权 PageRank。按权重迭代分配重要性，优点是能区分「连接多」与「连接重要」；缺点是对权重与阻尼敏感。本报告用它做中心性。

C.3.3 社区发现。用 Louvain、标签传播划分社区，优点是能找团块；缺点是需要分辨率参数。本报告未做，只算局部聚类。

C.3.4 图数据库快照。直接读 Nebula 图，优点是节点与产品一致；缺点是需要快照。本库没有，未做。

### C.4 数据可行性

| 方法 | 最小数据 | 本库 | 可行性 |
|---|---|---|---|
| A 社会网络分析 | 节点 + 边 | 200 / 2,643 | 可 |
| B PageRank | 加权边 | 1,085,258 权重 | 可 |
| C 社区发现 | 边 + 分辨率 | 有边、无参数 | 部分 |
| D 图快照 | Nebula 导出 | 无 | 不可 |

### C.5 密度与稀疏化的完整证据

200 个节点两两组合 19,900 对，原始共现 19,898 对，密度 0.999899。这个数字说明「不稀疏化就没有结构」：几乎所有域都与其他域有至少一个共同申请人。稀疏化用「co≥20 且 Jaccard≥0.05」，保留 2,643 条，密度 0.132814。

稀疏化的关键约束是 Jaccard，不是共现。实测：仅 Jaccard≥0.05 保留 2,643 条，与双阈值完全相同；仅共现≥20 保留 18,988 条，几乎没有稀疏化。原因是「大域稀释」：G06F 有 17,599 个申请人，与任何域的共现数都大，但并集更大，Jaccard 低；小域之间共现少，但并集小，Jaccard 高。用 Jaccard 做阈值，才能同时压住大域、保留小域强关联。

### C.6 中心性与聚类的完整证据

度第一是 G05D（73），PageRank 第一是 G01N（0.021790，度 49）。两者的差异来自「邻居质量」：G01N 与 G06F、G01R、G01B、G01M 等高权重邻居相连，PageRank 分到的权重高；G05D 连接多，但很多连接权重低，分配被稀释。这个差异不是算法错误，是「度」与「加权 PageRank」的定义不同。

平均聚类 0.5782，前 10 个高聚类节点的度只有 2—14。这说明「高聚类」在稀疏图里很容易出现：一个度 2 的节点，只要两个邻居相连，聚类就是 1.0。报告在 §2.5 用「度 + 聚类」双列展示，避免读者把「小三角」当成「社区核心」。真正有解释力的高聚类节点是 A23L（度 14、聚类 0.978）。

### C.7 连通性与部类混合的完整证据

4 个连通分量：最大 197、三个孤立节点 A24F/A44C/D06F。孤立节点的原因是「申请人集中 + 跨域布局少」，不是「技术活动少」；A24F 在 2024 年有 4,993 件专利，是深圳电子烟产业的核心域。报告保留孤立节点，并在 §2.6 解释，避免读者把「孤立」读成「不重要」。

部类混合的实测：部内边 1,132 条（42.83%）、跨部边 1,511 条（57.17%）。跨部边最多的是 G—H 330、B—G 214、C—G 172；这说明技术域的共同布局不按 IPC 部隔离。对产品设计的含义是：按 A—H 部硬切会切断 57.17% 的边，布局应按社区或产业分组。

### C.8 推荐方案

1. 短期上线「IPC4 技术域图结构」：概览、度分布、中心性、连通与聚类四块。
2. 标注「节点为 IPC4 域、边为申请人共现」，不与产品技术点图混用。
3. 导出 Nebula 技术点图快照，做代理图与产品图的结构对照。
4. 接图壳元数据，让结构指标能驱动布局与配色。
5. 补介数中心性，识别「低度但关键」的桥梁节点。
