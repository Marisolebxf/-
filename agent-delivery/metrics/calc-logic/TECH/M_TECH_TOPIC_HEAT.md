## 摘要

本件把技术热度拆成四个可分别复核的分量：专利规模、专利增速、论文规模、媒体规模。四个分量各自归一化到 0—100，再按自定权重合成热度分。这样做的目的是让「热度」不是一个黑箱分数，而是四个能单独质疑的读数。

| 读数 | 值 |

| 专利 2021—2024 合计 | 2,009,365 件 |
| 专利命中主题 | 1,106,968 件（55.0904%） |
| 专利未命中 | 902,397 件 |

| 媒体总条数 | 108,052 |

第一个事实是**专利侧覆盖过半，但未命中量很大**。1,106,968 件命中自建字典，902,397 件没有命中。未命中的部分不是「没有技术含量」，而是 IPC 前缀不在 10 个主题的前缀集合里，或该专利没有 IPC。这决定了本榜单只能读作「10 个主题之间的相对热度」，不能读作「全部技术领域的完整排名」。

### 1.2 为什么需要「技术话题热度」

专利和论文的原始分类是给审查员和图书管理员用的：IPC 有数万个子类，中图分类有上千个类目。决策者不会读 H01M10/0525，他们读「电池储能」。技术话题热度的作用就是搭这座桥：把机器可读的分类码，翻译成人可读的主题，再按热度排序。

这座桥有两个天然风险。第一，翻译规则是人定的，换一套规则排名就会变；第二，热度是合成的，权重也是人定的，换一套权重排名也会变。本件不掩盖这两个风险，而是把它们写进产物的顶层字段：`mapping_is_official=false`、`weights.main_is_official=false`，并公开全部前缀与权重。

### 1.3 口径定义

设主题集合 $T=\{t_1,\dots,t_{10}\}$，每个主题有 IPC 前缀集合 $I_t$、中图分类前缀集合 $C_t$、链节点关键词集合 $K_t$。专利 $p$ 归入主题 $t$ 当且仅当它的 IPC4 以 $I_t$ 中某个前缀开头，且按主题顺序取第一个命中（互斥）。论文 $a$ 归入主题 $t$ 当且仅当它的中图分类号以 $C_t$ 中某个前缀开头（互斥）。新闻 $n$ 归入主题 $t$ 当且仅当它挂的链节点名命中 $K_t$（可多主题）。

热度分定义为四分量加权：

$$H_t=0.35\cdot S_t+0.35\cdot G_t+0.15\cdot A_t+0.15\cdot M_t$$

其中 $S_t$ 是专利规模分、$G_t$ 是专利增速分、$A_t$ 是论文规模分、$M_t$ 是媒体规模分，各自在同批 10 个主题内做 min-max 归一化到 0—100。

### 1.4 计算公式与本批实现式

```python
def topic_of_ipc(ipc4):
    for t in TOPICS:                       # 顺序即优先级
        if any(ipc4.startswith(p) for p in t["ipc_prefixes"]):
            return t["topic"]
    return None

def minmax(values):
    lo, hi = min(values), max(values)
    return {k: (v - lo) / (hi - lo) * 100 if hi > lo else 0.0 for k, v in values.items()}

heat = {t: 0.35 * S[t] + 0.35 * G[t] + 0.15 * A[t] + 0.15 * M[t] for t in TOPICS}
```

三个实现要点。第一，IPC 匹配按 `TOPICS` 列表顺序短路，先命中的主题胜出，避免一个 IPC 同时进两个主题造成重复计数。第二，min-max 只在同批 10 个主题内做，不跨批次比较；下一批主题集变化时，历史分不可直接对比。第三，某分量全为 0 时（例如测量与检测主题没有论文命中），该分量整体记 0，不做特殊处理。

## 二、计算过程

### 2.1 三侧数据面与窗口对齐

三侧数据的窗口并不一致，这是本件最先要处理的问题。专利侧有 2021—2026 的年度轴，取 2021—2024 四年；论文分类表没有日期列，只能给截面；链新闻覆盖 2025-02-01 至 2026-07-27，是一个约一年半的单窗。

处理方式不是强行对齐，而是各分量各自归一、再合成。专利规模与增速用四年窗，论文与媒体用截面/单窗，合成时不做时间加权。这意味着热度分是「近四年专利 + 当前论文存量 + 近一年半媒体」的混合读数，不是同窗对比。展示时必须写明这一点，否则读者会以为四个分量是同一时间尺度。

### 2.2 十主题字典的构造

主题字典是按深圳产业政策语境手工划的，不是从任何标准抄的。10 个主题分别是：电池储能与新能源、人工智能与数字技术、生物医药与医疗器械、机器人与智能制造、测量与检测、集成电路与电子元件、通信与网络、新材料与化工、环境与节能、低空经济与航空航天。

每个主题由三组前缀定义：IPC4 前缀（专利侧）、中图分类前缀（论文侧）、链节点关键词（媒体侧）。三组前缀不是一一对应的：有的主题论文前缀为空（测量与检测），有的主题媒体关键词命中为 0（电池储能、测量与检测、通信与网络、新材料与化工、环境与节能）。这些空分量不是遗漏，而是该主题在这三侧的实际覆盖差异。

### 2.3 专利 IPC 前缀匹配

专利侧用 IPC4 前缀匹配，按 `TOPICS` 顺序短路。以电池储能与新能源为例，前缀是 H01M、H02J、B60L、H02S、F03D、H02K、H02P、H02N，覆盖电池、供电、电动车、光伏、风电、电机六类。2021 年命中 21,824 件，2024 年 32,097 件，增速 47.072%，是 10 个主题里增速最高的。

顺序短路有一个副作用：H02J（供电网络）既像「电池储能」又像「通信与网络」的电力侧，本件把它归给电池储能，因为它在 `TOPICS` 里排第一。这类边界归属没有客观答案，换一个顺序，两个主题的专利数都会变。映射规则公开在脚本里，就是为了让这种主观选择可被审视。

### 2.4 论文中图分类匹配

论文侧用中图分类号前缀匹配，每个分类号只归一个主题。生物医药与医疗器械的前缀是 R，命中 9,569 行，占 20,048 行的 79.8015%——这个比例高得异常，原因是中图分类里 R 本来就是医药卫生大类，而论文库里医药类占比本来就高。

这个 79.8015% 不能读成「生物医药占全部论文的八成」。它的分母是「有中图分类的 20,048 行」，不是全库 100,900 篇。在全库口径下，生物医药的论文份额会小得多，但因为另外八成论文没有分类，无法计算。这是本件最容易被误读的一个数，展示时必须把分母写在旁边。

### 2.5 链新闻匹配与字典

媒体侧不用 `industry_code` 数组直接映射，因为 `dwd_industry_chain_news_info` 的 `industry_code` 与 `industry_name` 都是 JSON 数组字符串，且两列数组顺序不一致。按下标 zip 会把 A 链的码配到 B 链的名，得到一张全错的映射表。

正确做法是用 `dwd_industry_chain_info`（1,273 节点）做字典：先从新闻的 `industry_code` 数组取出码，再逐码查字典得到节点名，最后用节点名匹配主题关键词。一条新闻可以挂多个链节点，因此可以命中多个主题；`coverage.media_topic_sum_rows` 为 89,929，大于去重后的 58,520，差额就是多主题重复计数。

### 2.6 四分量归一与权重

四个分量各自在 10 个主题内做 min-max 归一化。专利规模分最高是人工智能（100.0），最低是低空经济（0.0）；专利增速分最高是电池储能（100.0），最低是环境与节能（0.0）；论文分最高是生物医药（100.0），最低是测量与检测（0.0）；媒体分最高是机器人（100.0），最低是五个零命中主题（0.0）。

权重取 0.35 / 0.35 / 0.15 / 0.15，理由是专利侧有两个分量（规模与增速），各占三成五，论文与媒体各占一成五。这不是甲方签发的权重，`weights.main_is_official=false` 已写死在产物里。换一套权重，排名会变：若把媒体权重提到 0.5，机器人会从第 4 升到第 2，人工智能会从第 2 升到第 1。

## 四、数据缺失情况

### 4.1 无官方主题映射（口径缺口）

`dwd_tech_topic` 逐字命中 0 张表。`dwd_industry_analysis_topics` 有 1,052 行，但按主题名分组只有 3 个不同值：Industry、Company、Industry overview and forecasts。这是英文主题残片，不是可用的技术主题字典。

**拒拟理由**：无官方「技术词→主题」对照表。
**替代口径**：本工程自建 10 主题字典，前缀与关键词全部公开在脚本 `TOPICS` 中。
**与原文差别**：主题名、主题边界、IPC 归属全是自定。换一套字典，榜单会重排。

### 4.2 论文分类覆盖不足两成（口径缺口）

`dwd_zh_paper_classification` 只有 20,048 行，对全库 100,900 篇的覆盖率 19.8692%。论文分量只反映这 20,048 行，不能代表全部论文。

**拒拟理由**：覆盖率不足，无法做全库论文主题分布。
**替代口径**：只报「有分类子集」的分布，并在每个份额旁标注分母。
**与原文差别**：论文侧的结论适用范围被限制在五分之一。

### 4.3 媒体侧只有单窗（口径缺口）

链新闻覆盖 2025-02-01 至 2026-07-27，约一年半。媒体分量是单窗密度，不是长期趋势，也不能与专利的四年窗做严格同比。

**拒拟理由**：无更早年份的链新闻。
**替代口径**：媒体只做横向比较（主题之间），不做纵向趋势。
**与原文差别**：媒体分量不能回答「关注度是在上升还是下降」。

### 4.4 权重非官方（口径缺口）

四分量权重 0.35 / 0.35 / 0.15 / 0.15 为本工程自定，`weights.main_is_official=false`。换权重会改变排名，尤其是媒体权重。

### 4.5 专利未命中 902,397 件

未命中主题的专利占 2021—2024 合计的相当一部分，原因是 IPC 前缀不在字典内，或该专利没有 IPC。这批专利不是「无技术」，而是「不在本字典的 10 个主题里」。任何「覆盖率 55.0904%」的表述都必须带这个解释。

### 4.6 不得外推的四件事

1. **不得把热度分当绝对水平**：它是 10 个主题内的相对分，不是跨库可比的标准分。
2. **不得把论文份额当全库份额**：79.8015% 的分母是 20,048 行，不是 100,900 篇。
3. **不得把媒体单窗当趋势**：一年半的窗口看不出长期关注度变化。
4. **不得把主题名当官方分类**：10 个主题名是本工程自拟，不是政策文件或标准分类。

### 4.7 停用与重估条件

出现以下任一情况应重估：① 官方技术主题字典入湖；② 论文分类覆盖率提升到可接受水平；③ 链新闻补齐更早年份；④ 甲方签发权重；⑤ 主题集调整——主题集一变，全部历史分不可比，必须整批重算。

## 五、结论与发布建议

### 5.1 可用结论

第一，10 个自建主题中，电池储能与新能源热度 60.1822 居首，人工智能 56.8378 次之，生物医药 53.1756 第三，机器人 45.4177 第四。第二，专利侧命中 1,106,968 / 2,009,365 件，覆盖 55.0904%。第三，论文侧命中 11,991 / 20,048 行，覆盖 59.8115%，但分类只覆盖全库 19.8692%。第四，媒体侧命中 58,520 / 108,052 条，覆盖 54.1591%，窗口为 2025-02-01 至 2026-07-27。第五，映射与权重均非官方。第六，判部分支持。

旧稿若直接引用某个外部技术分类体系，本版不沿用——gkx 没有该体系的对照表，引用会变成无源之引。本版把字典完全内化到脚本，牺牲了「权威性」，换来了「可复算、可替换」。任何一条前缀被推翻，都能在脚本里定点修改并重跑。

### 5.4 后续

三条路径：① 甲方确认 10 主题字典与权重，转为正式口径；② 补论文分类，把覆盖率从 19.8692% 提上去；③ 补更早的链新闻，把媒体分量从单窗变成序列。第一条是发布前提，第二条决定论文分量能否进入结论，第三条决定媒体分量能否做趋势。

## 附录 C 可行性完整版

### C.1 为什么不让一条专利进多个主题

多归属会让主题专利数之和大于专利总量，读者无法判断「份额」。本件选择互斥归属，代价是边界专利只能进一个主题。若未来要做「技术融合度」，需要另一套多归属口径，与本件不冲突但不能混用。

### C.2 为什么媒体侧允许多主题

链新闻挂的是产业链节点，一条新闻可能同时提到「人工智能」与「机器人」，强制互斥会丢掉真实关联。媒体侧因此允许多归属，并单独给出 `media_topic_sum_rows` 89,929，让读者知道去重前后差多少。

### C.3 热度分的可解释边界

热度分只能回答「在这 10 个主题里，谁的综合信号更强」。它不能回答「这个主题绝对有多热」，因为没有跨库标定；也不能回答「热度涨了多少」，因为四个分量的时间窗不一致。任何超出这两个边界的解读，都需要额外的标定工作。
