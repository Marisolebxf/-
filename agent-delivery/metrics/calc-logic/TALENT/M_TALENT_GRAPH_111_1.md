## 摘要

人才实体关系抽取是本批五件里「节点侧健康、关系侧半空」的第二个样本，与政策图谱同构但失源点不同：政策图谱死在字段真值（`theme` 2 行、`keypoints` 0 行），人才图谱死在**标识符缺失**（机构 ID 整列为空）与**词表缺失**（研究方向无受控词表）。

节点侧是健康的。`dwd_scholar` 21,316 位学者，机构名称填充 20,829 行（0.977153），h 指数大于 0 的 20,914 位，被引大于 0 的同样 20,914 位，论文数大于 0 的 21,301 位。机构层按名称聚合得到 2,097 个不同机构名，前五名是中国科学院 728、上海交通大学 703、北京大学 364、清华大学 323、浙江大学 291。论文层 1,065,385 条「人才—论文」关系覆盖 20,015 位学者，其中被引大于 0 的 780,764 行——这是库内唯一可用的质量代理，但它只存在于人才—论文关系内部，不能外推到机构或产业层。

关系侧的缺口分三类。**第一类是标识符**：`scholar_org_id` 整列为空（0/21316），机构节点只能用名称串，于是「中国科学院」与「中科院」会算两个节点，同名不同校（如两地都有「附属医院」）会合并成一个。机构级结论因此只能作**名称聚合**，不构成机构实体消歧。**第二类是词表**：研究方向是自由文本，20,030 行里 163,470 个标签实例、97,249 个不同值，只出现一次的标签 80,027 个（0.822908），Top100 只覆盖 0.059705。按「出现 ≥ 20 次」建节点只剩 499 个标签、21,022 条边，覆盖 0.128599 的标签实例——也就是说，**八成七的研究方向实例进不了图**。**第三类是整类关系缺席**：企业、产业、服务机构、政策四类，gkx 里没有任何关系表，也没有可映射的字段（主档只有机构名称，无统一社会信用代码或企业 ID）。

## 一、需求定义概述（指标定义与需求原意）

### 1.1 所属功能模块（要开发什么）

本指标支撑人才图谱页的「实体关系」视图。页面形态是：选中一位学者，浮出所属机构、研究方向标签、合作者列表、代表论文；或者选中一个机构，列出旗下学者。产品语义上有三层用法：**其一，检索增强**——按机构、按研究方向筛人；**其二，网络洞察**——谁是高合作度的枢纽学者、哪些机构形成学派；**其三，跨域连接**——把学者接到企业（谁在给企业做技术）、接到产业（谁在研究 20+8 产业的技术）。

三层用法对关系类型的要求递增。检索只要机构与方向标签（本件能交付）；网络洞察要共著图（本件能交付但稀疏）；跨域连接要**企业/产业**两类关系（本件完全没有）。这正是「部分支持」的边界：**图内可查、图外不通。**

### 1.2 为什么需要这个指标

人才数据在库里有 21,316 条，是**表格**不是**网络**。表格能回答「这个人是谁」，不能回答「这个人和谁合作」「这个机构有多少人做同一个方向」。关系抽取把表格变成网络，价值在三处：一是**去重与归并**（同名学者、同一机构的不同写法）；二是**路径查询**（从一位学者走到他的机构、再走到同机构的其他人）；三是**网络指标**（度、连通分量、枢纽识别）。

对本项目而言，它还有一个更实际的作用：**它是人才侧唯一能提供「质量」信号的载体**。人才表里的 h 指数与被引只到个人，接上共著网络后才能算「合作影响力」，接上机构后才能算「机构学术产出」。这两个派生能力都依赖本件先把边建出来。

### 1.3 需求文档是否给出定义方法

**给了关系清单，没给建边规则与消歧规则。** SRS `ALGO-TALENT-GRAPH-111` 点名五类关系：科研机构、技术、企业、服务机构、政策。这五类是验收清单。

但它**没有**给出：① 机构如何消歧（名称串？统一社会信用代码？教育部机构代码？）；② 「技术」用受控词表还是自由标签，阈值多少；③ 共著关系的权重怎么算（一篇论文算 1 还是按作者数摊）；④ 学者的唯一键（`scholar_id` 是否跨库稳定）；⑤ 企业关系是否允许「同名推断」。五项都属建边规则，需甲方裁决。

本件的自定义规则明写为：机构按名称串原样聚合（不归一）、技术标签最小出现次数 20、共著按「同论文即连边」、边权用合著论文数（`co_paper_weight`，合计 43,205）、学者唯一键用 `scholar_id`。

### 1.6 形式定义（本件自定义部分已标注）

设学者节点集 $\mathcal{S}$（$\lvert\mathcal{S}\rvert=21316$），机构节点集 $\mathcal{O}$（按名称串，$\lvert\mathcal{O}\rvert=2097$），技术标签节点集 $\mathcal{T}$（出现 ≥ 20 次，$\lvert\mathcal{T}\rvert=499$），则

$$\mathcal{G}=(\mathcal{S}\cup\mathcal{O}\cup\mathcal{T},\,E),\qquad E=E_{so}\cup E_{st}\cup E_{ss}\cup E_{sp}$$

其中 $E_{so}$ 为人才—机构边（20,829）、$E_{st}$ 为人才—技术边（21,022）、$E_{ss}$ 为共著无向边（8,366）、$E_{sp}$ 为人才—论文边（1,065,385）。共著边权定义为

$$w(u,v)=\bigl\lvert\{p\mid u\in A_p,\ v\in A_p\}\bigr\rvert$$

即两位学者合著的论文数，全图权重和 43,205。覆盖率同样按「强计 1、弱计 ½」折算：

$$\text{Cov}_{\text{strong}}=\frac{1}{5}=0.2,\qquad \text{Cov}_{\text{strong}+\frac{1}{2}\text{weak}}=\frac{1+0.5}{5}=0.4$$

**边界**：① 本件不产出任何「人才评分」，也不做枢纽排名（度最高只作描述）；② 机构节点是同名合并的结果，不是消歧后的实体；③ 共著边只覆盖主档内学者，不能外推为真实合作网络；④ 人才—企业/产业/服务机构/政策四类关系为零边。

## 二、计算过程

### 2.1 总体设计：先建可用骨架，再逐类核关系

本件的边源有两种：**主档字段**（机构名、研究方向）与**关系表**（共著、论文）。前者是「一表生边」，后者是「两表连接」。设计顺序按可靠性排：先建机构边（字段填充 0.977153，最稳），再建技术边（自由文本，需要阈值），再建共著边（关系表但命中率低），最后建论文边（量大但语义最单一）。每建完一层就记一次覆盖数，最后与需求清单对账。

这样排的理由是**故障隔离**：如果先建共著边，99.27% 的行指向库外学者，很容易被误读成「共著数据很差」而放弃整张图；先建机构边则能证明「主档本身是好的，差的只是与外部表的连接」。

## 四、数据缺失情况与结论边界

### 4.1 缺口后果归因

**缺机构 ID → 机构层结论不可作管理口径。** 「中国科学院 728 人」这句话在名称聚合下成立，在机构实体下不成立（研究所被合并）。若甲方要用本件做「机构引才排名」，必须先用 G1 的映射修好，否则排名会把几十个研究所算成一家。

**缺受控词表 → 技术层只能作线索。** 499 个标签覆盖 0.128599 的实例，剩下 87.14% 的实例落在长尾里。用这批标签做「技术领域分布」会把八成七的人算成「无方向」，这个比例太高，不能当缺失值处理，只能承认口径不全。

**缺企业/产业关系 → 跨域链条断在第一跳。** 本项目的人才价值有一半在「学者 → 企业」的转化上，这条边没有，人才图谱就只能停在学术侧，接不上产业链与企业侧的任何指标。

### 4.2 若甲方坚持要五类齐备：最小补齐清单

| 字段/表 | 类型 | 用途 | 必需性 |
|---|---|---|---|
| `scholar_org_id`（或名称→ID 映射表） | varchar | 机构消歧 | 必需 |
| `scholar_orcid` | varchar | 跨库唯一标识 | 高 |
| 技术词表（中英对照） | 维表 | 研究方向→受控标签 | 必需 |
| 人才—企业关系表 | 关系表 | 专利发明人/项目负责人 | 必需 |
| 人才—产业关系表（可由词表派生） | 关系表 | 产业归属 | 高 |
| 服务机构名录 | 维表 | 中介网络 | 中 |
| 政策点名/立项名单 | 关系表 | 人才—政策 | 中 |

前四项缺任一项，五类关系都凑不齐。第五项可从第三项派生，是「先修词表再接产业」的路径。

### 4.3 页面处置建议

**建议一：机构层标注「按名称聚合」。** 页面上「中国科学院 728」应带脚注，说明是同名合并，不是机构实体。否则第一个质疑会是「中科院哪有 728 人」。

**建议二：技术标签只展示 499 个节点，并显示覆盖比例。** 让用户知道这是 12.86% 的覆盖，不是全量。

**建议三：共著网络标注「主档内可见」。** 孤点率 0.612122 会让大量学者显示「无合作者」，这是抽样结果不是事实，必须提示。

### 4.4 能否交叉验证

## 附录 C　无障碍路径说明（替代方案完整版）

### C.1 报告目的与范围

### C.2 需求语义锚定

「人才实体关系抽取」有两种读法：**学术网络**（机构、合作、论文）与**产业网络**（企业、产业、服务机构、政策）。前者本件可交付，后者全断。两者的分界是「学者是否被连接到产业系统」。

### C.3 权威方法谱系

#### C.3.1 族 A：唯一标识驱动

数据要求：ORCID/机构代码。局限：覆盖率低（全球学者 ORCID 普及率有限）。借法：本件无 ORCID 列，不可用。

#### C.3.2 族 B：共著网络投影

数据要求：论文—作者二部图。局限：只反映学术合作。借法：本件采用，命中 0.007305。

#### C.3.3 族 C：发明人—申请人连接

数据要求：专利发明人姓名字段 + 消歧。局限：姓名未消歧时噪声极高。借法：本件不采用（见 §1.4 结论三）。
