## 摘要

人才产业力指数要回答的是「这个人的研究跟深圳的产业有没有关系、关系有多深」。需求在「人才洞察分析」里要「产研对比分析」，在「科技创新评估」里要「专利－发明人－学者－地域－产业知识图谱」，本文把这两句话落成四维：产业关联论文 IND 0.35、学术深度 H 0.25、专利产出 PAT 0.20、产学研触点 LINK 0.20。

产业方向用《深圳市「20+8」产业集群》的 28 类（20 个战略性新兴产业集群 + 8 个未来产业）建中英双语关键词字典，论文命中走「关键词 + 标题」双字段，作者记录先做「姓名 + 机构前缀」双锚定再计簇。全池 20,420 人里，13,955 人有可锚定论文（68.34%），其中 7,219 人至少有 1 篇命中产业簇（35.35%），命中论文合计 17,228 篇，占 62,735 篇锚定论文的 27.46%。

分数分布很靠下：均值 26.13、中位 24.66、P90 40.65、P99 54.98、最高 80.69。分档结果是产业强关联 69 人（0.34%）、产业中关联 6,353 人（31.11%）、产业弱关联 13,998 人（68.55%）。**强关联只有 69 人不是「深圳只有 69 个产业人才」，而是 60 分阈值在四维缺测重归一的分布上切得太高**——四维齐全的只有 2,946 人（14.43%），其余人少一维就少一个满分来源，分数自然上不去。这一点在 §2.6 与 §5.4 都写明：分档应改为分位展示。

Top 5 是李克强（清华大学，80.69，智能网联汽车/网络与通信）、刘建平（北京中医药大学，77.32，大健康/生物医药）、杨军（上海交通大学，76.53，大健康/细胞与基因）、康国政（西南交通大学，74.59，新材料）、程敬亮（郑州大学第一附属医院，73.57，细胞与基因）。榜单里「杨军」池内同名 2 人、「刘超」7 人、「王涛」7 人、「李峰」6 人——这些名字的分数是「某一条记录」的分数，不能当成「某个具体的人」的产业力。

稳健性：单维加倍后 Spearman 0.9602—0.9895、Top 10 重合 7—10 人；但把论文簇从「双锚定」换成「纯姓名匹配」后 Spearman 掉到 0.7891、Top 10 **完全不重合**。这条对照说明 Top 榜对「同名误配」极度敏感，只能当线索不能当结论。

结论：这条指标可以作「产业方向归属 + 簇内人选池」的线索工具，可以支撑「哪些 20+8 方向外部储备多」的统计，不能作「产业贡献排名」，也不能回答「他给深圳产业带来了多少产值」——后者需要技术转让、横向经费、成果转化数据，一列都没有。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技人才态势 → 人才洞察分析 → 产研对比分析**（1.1.1.1.4.3.1.2，第 1539—1541 行），以及 **重点科技人才画像 → 关联画像**（1.1.1.1.4.3.3，第 1971—1990 行）。上游还有「科技创新评估」里的知识图谱表述（第 859 行）。

需求原文写：「产研对比模块结合企业与高校成果，剖析产业与科研力量的协同和差异。」第 859 行写：「结合专利－发明人－学者－地域－产业等知识图谱数据，该功能能够全面分析不同产业领域的技术创新规模、质量和市场潜力。」两句话的共同点是「把人才挂到产业上」，区别是前者要「对比」、后者要「图谱」。

| 页面任务 | 对指标的要求 |
|---|---|
| 产业归属标签 | 一人可多簇，需给主簇 |
| 产业关联度分档 | 0—100 分 + 分档 |
| 簇内榜 | 每簇 Top N |
| 产研对比 | 高校侧 vs 企业侧（当前只有高校侧） |
| 产业贡献 | 需要转让/经费/转化数据 |

### 1.2 为什么需要「人才产业力指数」这个指标

学术力指数按论文与被引排序，排出来的是「学术影响力」，不是「产业相关度」。一个做理论物理的顶尖学者与一个做动力电池的普通教授，在学术榜上前者远高，但对深圳「20+8」的产业价值后者更直接。需求要的「产研对比」就是要把这个差别显性化。

第二个理由是它服务招商与引才的方向匹配。深圳要发展「细胞与基因」，就需要知道全国有哪些人在这条簇上有持续产出；要发展「工业母机」，就需要知道这条簇的人才储备有多薄。簇级计数能直接回答这类问题，且不依赖任何主观权重。

第三个理由是它必须被限制在「关联」而不是「贡献」。论文命中产业关键词只能证明「他做这个方向」，不能证明「他的成果被产业用了」。本文在 §4.3 明确三条不可外推，核心就是防止「产业关联度」被读成「产业贡献度」。

### 1.3 需求文档是否给出定义方法

**需求给了「产研对比」与「知识图谱」；registry seed 点名「专利转化/项目/商业化」，但这三类在库内无承载，本文只能交「关联度」（见 §0.4）。**

原文没有写：产业用哪套分类（国民经济行业分类？20+8？）、关联按论文关键词还是按专利 IPC、一个人多簇怎么处理、簇内怎么排序、贡献用什么衡量。本文补的五条决策是：① 产业分类用深圳「20+8」28 类（本地政策口径，最贴合展示场景）；② 关联判定用「论文关键词 + 标题」命中字典，作者记录双锚定；③ 一人可多簇，主簇取命中最多；④ 簇内按总分排序；⑤ 贡献不交付，只交付关联。

### 1.6 推测原意与推测定义

**推测原意**：产品要一张「人才 × 产业」的对照表：给定一个 20+8 集群，能列出这条簇上有产出的学者；给定一个学者，能看出他属于哪几条簇。它服务招商引才的方向匹配与产业人才储备盘点，不服务科技成果转化考核。

**推测定义（本文采用）**：

> 对学者 $i$，四维原值为产业关联论文数 $I_i=\sum_{p\in \text{anchored}_i}\mathbf{1}[\text{cluster}(p)\neq\varnothing]$、H 指数 $H_i$、专利件数 $P_i$、产学研触点 $L_i=\tfrac13(\text{企业履历}+\text{企业合作论文}+\text{深圳合作论文})$。归一后合成
> $$
> \text{Score}_i=100\times\frac{\sum_{d\in D_i}w_d\tilde x_{d,i}}{\sum_{d\in D_i}w_d},\quad
> w_{IND}=0.35,\ w_H=0.25,\ w_{PAT}=0.20,\ w_{LINK}=0.20
>
$$

**为什么 IND 权重最高**：这条指标的问句是「跟产业有没有关系」，产业关联论文是唯一直接回答该问句的维度；H 是「做得深不深」，PAT 是「有没有技术产出」，LINK 是「有没有和产业界打过交道」。四者里只有 IND 是「产业」本身。

**为什么 LINK 用 0/1 拼装而不是连续值**：需求要的「横向课题经费、技术转让、企业委托合同」三列都不存在；能用的只有「有没有企业履历」「有没有企业合作论文」「有没有深圳机构合作论文」三个布尔信号。三项等权平均后只有 0、0.33、0.67、1 四档，且只有 5,515 人有值——这一维的区分度很低，权重却占 0.20，是本文最不满意的一处设计，已在 §4.1 列为修复项。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是本文 §1.6 的自建口径。降级发生在三处：① IND 维从「产业贡献」降为「产业关键词命中」，因为没有转化数据；② LINK 维从「产学研合作强度」降为三个 0/1 信号，因为没有经费与合同；③ 分档从「绝对分档」降为「参考分档」，因为 60/30 阈值在当前分布上切出 0.34% 的强关联。

本文没有做的降级包括：没有用专利 IPC 反推产业簇（IPC 与 20+8 不是一套码，强行映射会造出 3.5% 级别的错误覆盖）、没有用机构名里的「公司」字样推断「产学研合作」（履历里企业机构只有 137 人命中）、没有把「发过中文论文」当成「产业相关」。

### 2.2 口径拆解：对象、集合、归一

**对象**：学者（`dwd_scholar` 一行，有姓名），全池 20,420 条。不做机构筛选、不做学科筛选。

**集合**：全池 20,420 人。归一池取全池，理由是产业关联论文的分布极度右偏（中位 0、P90 0.3544），按簇内归一会让每簇的第一名都拿 100 分，簇间不可比。

**IND 维**：先用「姓名 + 机构 6 字前缀」双锚定取出每人的论文（合计 62,735 篇、覆盖 13,955 人），再对每篇论文的「关键词 + 中英文标题」跑 28 类字典，命中即计 1（一篇论文可命中多簇，但 IND 只计「是否命中」一次，不重复计）。17,228 篇命中，7,219 人至少 1 篇。`log1p` 后全池 min-max。

**H 维**：`h_index` 直接 `log1p` + 全池 min-max。这一维与学术力指标同源，但这里只用 H 不用被引，因为被引与产业关联的相关性更低。

**PAT 维**：发明人姓名件数，池内同名（2,662 人）、两字姓名（3,670 人）、无命中（4,806 人）判缺测，剩 9,282 人取 `log1p` + 全池 min-max。

**LINK 维**：三个 0/1——履历里有企业机构（137 人）、锚定论文的合作者机构里有企业（3,822 人）、合作者机构里有深圳机构（554 人）。三项平均，只有至少一项可判的人才有值（5,515 人）；1,284 人三项全 0，其余 14,905 人无履历也无合作者信息，判缺测。

### 2.3 依赖分解（两跳停）

| 跳 | 依赖 | 承载 | 状态 |
|---|---|---|---|
| 1 | 产业关联论文 | 论文面板（100,900 篇）+ 28 类字典 | 可算，7,219 人非零 |
| 1 | 学术深度 | `dwd_scholar.h_index` | 可算，100% |
| 1 | 专利 | 发明人姓名快照 | 可算，9,282 人 |
| 1 | 产学研触点 | 履历 + 论文合作者机构 | 可算，5,515 人 |
| 2 | 技术转让 | 无表 | **断在第 1 跳** |
| 2 | 横向课题经费 | 无表 | **断在第 1 跳** |
| 2 | 企业委托合同 | 无表 | **断在第 1 跳** |

「两跳停」在这里的含义是：本文只走到「论文/专利/履历这三类已有产物」这一层，不再去 `dwd_org_industry_tags` 找企业行业标签。原因很直接：该表的 `industry_link_code` 是文本化 JSON 数组，剥壳后只匹配到 23 个 `chain_info` 码，且 `INB13xx` 与 `INB12xx` 不是同一套码域——用它给企业打行业标签，等于在 3.5% 的覆盖率上做统计。

### 2.4 算路 / SQL

本指标**零 SQL**：论文面板读 `a25_paper_panel.json`，专利读 `patent_inventor_counts_gkx.json`，学者与履历读 `probe_a26_20261022.json` 与 `probe_talent21_20261022.json`。

```text
-- 快照的原始形态（已落盘，本文不再发）
SELECT id, zh_name, en_name, keywords, author_info_list
FROM gkx.dwd_zh_paper;                    -- 100,900 行，20,048 条有关键词
```

本地计算：论文作者展开（215,816 条）→ 姓名索引 → 双锚定 → 28 类字典匹配（缓存每篇论文的簇结果）→ 四维归一 → 合成 → 簇级汇总 → 四组权重敏感性 + 一组口径敏感性。耗时 17.6 秒。

**为什么不在 SQL 里算**：`dwd_zh_paper` 的 `author_info_list` 是 JSON 长文本，SQL 侧解析需要 JSON 函数逐行展开，成本远高于本地；28 类字典有 200 多个关键词，SQL 里要写 200 个 `LIKE`，既慢又不可维护。

### 2.5 清洗规则

| 规则 | 处理 | 影响 |
|---|---|---|
| 姓名空 | 排除出池 | 896 |
| 无锚定论文 | IND 记 0（有论文但不命中）或缺失（无论文） | 6,465 人无论文 |
| 论文关键词与标题都空 | 该篇不参与簇判定 | 少量 |
| 池内同名 / 两字姓名 / 无命中 | PAT 缺测 | 2,662 / 3,670 / 4,806 |
| 履历与论文合作者都无 | LINK 缺测 | 13,621 |
| 专利件数为 0 | 保留（真实零产出） | 少量 |
| 总分并列 | 按 `scholar_id` 稳定排序 | — |

清洗原则是「锚定优先、缺测显性」：论文必须姓名 + 机构双锚定才算，宁可少算 6,465 人，也不把同名论文算到别人头上；LINK 三维全无的人判缺测而不是 0，因为「没查到」不等于「没有」。

### 2.6 结果解读

**分布**：20,420 人，均值 26.13、中位 24.66、P10 14.16、P90 40.65、P99 54.98、最高 80.69、最低 0。直方图峰值在 20—30（8,106 人），10—20 有 5,001 人，60 以上合计只有 69 人。这个形状是「IND 中位为 0 + PAT/LINK 覆盖不足」共同造成的：一半人 IND 为 0，四分之一人没有 PAT 或 LINK，分数上不去是结构性的。

**分档**：产业强关联 69 人（0.34%）、产业中关联 6,353 人（31.11%）、产业弱关联 13,998 人（68.55%）。60 分阈值原本是按「四维齐全且表现好」设计的，但四维齐全只有 2,946 人（14.43%），三维 8,905 人、二维 8,569 人——缺维的人被重归一后最多只能拿到三维的满分，跨过 60 分需要三维都接近满分。这是分档人数失衡的直接原因，不是「产业人才少」。

**Top 5**：李克强（清华大学）80.69，四维齐全，IND 15 篇、锚定 24 篇、专利 172 件，主簇智能网联汽车；刘建平（北京中医药大学）77.32，IND 31 篇、锚定 52 篇、专利 102 件，主簇大健康；杨军（上海交通大学）76.53，IND 18 篇、锚定 57 篇，专利缺测（池内同名 2 人），主簇大健康；康国政（西南交通大学）74.59，IND 17 篇、专利缺测，主簇新材料；程敬亮（郑州大学第一附属医院）73.57，IND 49 篇、锚定 132 篇，主簇细胞与基因。

**簇级储备**：28 类里人数最多的是细胞与基因 1,969、新材料 1,807、大健康 1,392、安全节能环保 1,094、智能传感器 610、激光与增材制造 589、新能源 558、生物医药 482；最薄的是可见光通信与光计算 7、现代时尚 24、工业母机 28、高端医疗器械 28、合成生物 30。簇内平均分最高的是智能终端 41.92、工业母机 41.78、可见光通信 41.36，最低的是精密仪器设备 36.24、区块链 36.55、海洋产业 37.12。这些数字可以回答「哪些方向人多」，不能回答「哪些方向缺人」——缺人需要岗位需求侧数据。

**深圳成员**：簇内深圳机构成员数最多的是细胞与基因 14、新材料 9、大健康 8、智能传感器 8、智能机器人 7、激光 6、安全节能环保 5。全池是全国的，深圳成员在每簇里只有个位数到十几人，这说明「深圳在 20+8 各簇的本土学术力量」在 `dwd_scholar` 里非常薄，页面不能把这 14 人当成「深圳细胞与基因人才总量」。

**敏感性与口径风险**：四组权重加倍的 Spearman 0.9602—0.9895、Top 10 重合 7—10 人，排序稳。但把论文簇从「双锚定」换成「纯姓名匹配」后，Spearman 0.7891、Top 10 **完全不重合**——因为纯姓名匹配会把大量同名者的论文算进来，Top 榜立刻换人。这条对照说明：主口径的 Top 榜依赖「机构前缀」这一道闸，闸一松，榜单就不可信。

#### 2.7.3 结果解读与评审

## 四、数据缺失情况

### 4.1 缺失清单

| 技术转让 | 无表 | 产业贡献不可算 | 接入专利转让/许可登记数据 |
| 横向课题经费 | 无表 | 产学研强度不可算 | 接入高校横向合同库或甲方数据 |
| 企业委托合同 | 无表 | 同上 | 同上 |

| 发明人 ID | 姓名匹配 | PAT 缺测 54.5% | 补发明人 ID |
| 论文关键词 | 20,048 / 100,900 篇 | IND 漏配 | 补关键词或改用全文 |
| 企业行业标签 | `industry_link_code` 码域错配 | 企业无法归簇 | 重建行业标签体系 |

### 4.2 对结论的影响边界

缺失把这条指标从「产业贡献度」压成「产业关联度」：它能回答「他做的是不是这条簇的方向」，不能回答「他的成果有没有被产业用」。分档也因此失真——60 分阈值在缺维分布上只切出 0.34% 的强关联，页面若按三档展示，会给人「深圳产业人才极少」的错觉。

企业侧的缺失还让「产研对比」只剩「研」的一侧：3,822 人有企业合作论文、137 人有企业履历，这两个数字都不足以支撑「企业与高校协同」的对比叙述。本文因此只交簇级人数与均分，不交「产研对比图」。

### 4.3 不可外推的三件事

第一，不能把分数当「产业贡献」。论文命中产业关键词只说明研究方向，不说明成果转化；一个 IND 很高但从未与企业合作的人，产业贡献可能低于一个 IND 中等但有三项转让的人。

第二，不能把簇级人数当「人才储备充足度」。人多只说明「学术侧做这个方向的人多」，不说明「产业侧岗位能招到人」；缺人需要岗位需求与薪酬数据。

第三，不能把 Top 榜当「该引进名单」。榜单里同名多记录（刘超 7、王涛 7、李峰 6）会被合并放大，纯姓名口径下 Top 10 完全不重合；页面必须带「同名风险」标并要求人工复核机构。

## 附录 C　人才产业力指数可行性报告（完整版）

### C.1 报告目的与范围

本附录回答：在「关联可算、贡献无数据」的条件下，产业力指数能交付到什么程度，以及为什么分档必须改成分位。范围限定在人才—产业映射，不扩展到产业竞争力评估。

### C.2 需求语义锚定

需求用了「产研对比」「产业分布」「市场潜力」三个词。对比需要企业侧样本，分布需要产业分类，潜力需要交易数据。本库只有学术侧与一套政策分类，因此只能做「学术侧 × 产业分类」的分布。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：主题映射

OECD 与 WIPO 都用「分类码→产业」的对照表做映射。本文用 28 类关键词字典，属于同一族的轻量版；差别是没有权威对照表，靠人工维护。

#### C.3.2 方法族 B：共现网络

论文-专利-企业二分图的共现强度可以刻画「学术—产业」连接。本库企业节点只有 44 个，图会极度稀疏。

#### C.3.3 方法族 C：投入产出

区域投入产出表能算产业间技术流。本库没有投入产出表。

#### C.3.4 方法族 D：转化指标

转让、许可、作价入股是产业贡献的直接计量。本库三列都没有。

### C.4 数据可行性详细分析

#### C.4.1 IND 维

62,735 篇锚定论文里 17,228 篇命中簇（27.46%），覆盖 7,219 人（35.35%）。漏配主要来自关键词缺失（80,852 篇无关键词）与字典覆盖不足。

#### C.4.2 H 维

100% 可算，中位 18。它与 IND 的相关性不高，因此两维并存有意义。

#### C.4.3 PAT 维

9,282 人可算（45.46%），缺测 11,138 人。缺测原因是同名、两字姓名、无命中三类。

#### C.4.4 LINK 维

5,515 人可判（27.01%），三项 0/1 分布为 0:1,284 / 1:3,951 / 2:278 / 3:2。只有 2 人三项齐全，说明「企业履历 + 企业合作 + 深圳合作」同时具备极其罕见。

#### C.4.5 方法—数据对照矩阵

| 方法 | 需要的输入 | 库内状态 | 可行性 |
|---|---|---|---|

### C.5 推荐构建方案（工程可执行）

2. Top 榜带同名风险标，按姓名+机构去重；
