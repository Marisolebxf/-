## 摘要

人才引进吸引力指数要回答的是「这个人值不值得去挖、挖来能不能落」。需求在「人才引进推荐评估」里给了四件事：学科贡献度分析、引进难度预测、引进成本预测、尽调报告与推荐。本文能算的是第一件与第四件的一半：学术力、专利产出、产业方向匹配、与深圳的连接痕迹，合成一个 0—100 的候选分。

候选池是「有姓名、且现机构不含深圳」的 20,238 人（182 名现职深圳学者被排除，因为本指标服务「引进来」）。四维权重按派单给定为 A 0.30、P 0.15、M 0.25、C 0.30；缺维不补 0，按剩余权重重归一。第一版跑出来的分数均值 31.06、中位 29.25、最高 92.01；只保留「至少两维有值」的 16,831 人可排序，均值降到 28.20、中位 27.39，最高 83.16。

Top 5 是赵天寿（南方科技大学）83.16、孙立成（西湖大学）79.41、张金龙（华东理工大学）76.77、吕伟（清华大学）74.21、郑南峰（厦门大学）74.05。这个榜单有一个必须提前说明的结构问题：前三名只有两维（A+P）有值，C 维缺失时权重被重归一，A 与 P 各占 0.30/0.15 → 0.67/0.33；而 C 维有值的人（476 人）会因为拿到 0.30 的权重而整体上移。换言之，**榜单名次在很大程度上由「有没有深圳连接」决定，而不是由学术力决定**。

稳健性验证了这一点：主口径与「纯学术力」口径的 Spearman 只有 0.4479、Top 50 只重合 2 人；与「四维等权」口径的 Spearman 0.38。这不是算法不稳，而是设计使然——需求要的是「引进匹配度」，不是「学术排名」，两者本来就不该一致。真正的问题是 C 维太稀：只有 2.35% 的候选人有深圳合作或履历痕迹，剩下 97.65% 的人在这一维上是「不知道」而不是「没有」，本文按缺测处理，不补 0。

结论：这条指标可以作为「候选池初筛 + 分维解释」的内部工具，不能作为「引进成功率预测」，也不能回答需求里的「引进难度」与「引进成本」——那两件事需要国籍、语言、薪酬、岗位交互数据，本库一列都没有。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技人才态势 → 人才引进推荐评估**（需求 1.1.1.1.4.3.4，第 2305—2465 行），以及其上游的「重点科技人才画像 → 分析画像」（1.1.1.1.4.3.3，第 2041—2055 行）。

需求原文写：「人才引进推荐评估旨在为科技信息展示系统提供多维度、智能化的人才筛选与推荐支持。该模块依托数据挖掘与智能分析技术，全面涵盖学科贡献度分析、学者引进难度预测、引进成本预测、人才尽调报告与推荐等核心功能。」四个子功能里，学科贡献度与尽调推荐有数据可依，难度与成本没有。

| 页面任务 | 对指标的要求 |
|---|---|
| 候选池排序 | 单一 0—100 分，可跨机构比较 |
| 分维雷达 | 四维各自归一分 |
| 筛选条件 | 方向匹配、专利、深圳关联可筛 |
| 尽调报告 | 分维得分 + 原始值可下钻 |
| 难度/成本 | 需要国籍、语言、薪酬、岗位数据 |

### 1.2 为什么需要「人才引进吸引力指数」这个指标

引进决策的第一道关口是「从几万人里挑出几百人」。学术力指数能回答「谁强」，但强的人不一定匹配深圳的产业方向，也不一定愿意来。需求因此要一个「匹配度」而不是「强度」：学术力是必要条件，产业方向与本地连接是充分条件。

第二个理由是它必须可解释。引进推荐如果只给一个黑箱分，评审无法反驳；本文把分数拆成四维并逐维给出原始值，评审可以说「这个人的 C 维只有 1 篇深圳合作论文，不该给 81 分的 C」，这才是可用的推荐工具。

第三个理由是它必须承认「不知道」。深圳连接维只有 2.35% 的人有值，剩下 97.65% 是缺测。缺测不等于「没有连接」——一个从未来过深圳的顶尖学者，与一个来过但没留下论文痕迹的学者，在本库里看起来一样。本文按缺测处理并重归一，代价是「有没有 C」成了隐形的分档开关，这一点在 §2.6 与 §4.3 反复说明。

### 1.3 需求文档是否给出定义方法

**需求给了四个子功能，没给权重、没给归一、没给候选池边界、没给「难度/成本」的数据来源；注册表 seed 补了「与深圳产业方向契合」的定位，但公式未签（见 §0.4）。**

原文只写「全面涵盖学科贡献度分析、学者引进难度预测、引进成本预测、人才尽调报告与推荐」。没有写：四维各占多少权重、学术力用哪些列、专利按件数还是按授权、深圳连接按论文还是按履历、难度用什么变量、成本用什么口径。

本文补的五条决策是：① 权重 A 0.30 / P 0.15 / M 0.25 / C 0.30（派单给定，P 压低是因姓名匹配噪声）；② 学术力复用 `M_TALENT_ACADEMIC_SCORE` 的三维合成；③ 专利按发明人姓名件数、两字姓名与池内同名判缺测；④ 深圳连接 = 锚定论文的共同作者含深圳机构 + 深圳履历，二者取或；⑤ 难度与成本**不交付**，在 §4.1 写明所需字段。

### 1.6 推测原意与推测定义

**推测原意**：产品要一张「可挖名单」，按匹配度排序，点开能看到「为什么他被推荐」——学术够强、方向对口、与深圳有过合作。它服务引才专班的初筛，不服务最终录用决策。

**推测定义（本文采用）**：

> 对候选学者 $i$，四维原值为学术力 $A_i$（0—1）、专利件数 $P_i$、产业方向命中簇数 $M_i$、深圳连接 $C_i$（锚定论文中含深圳机构合作者的篇数 + 深圳履历标记）。归一后合成
> $$
> \text{Score}_i=100\times\frac{\sum_{d\in D_i} w_d\tilde x_{d,i}}{\sum_{d\in D_i} w_d},\quad D_i=\{d:\tilde x_{d,i}\text{ 有值}\}
>
$$
> 权重 $w_A=0.30,w_P=0.15,w_M=0.25,w_C=0.30$。

**为什么 P 只有 0.15**：专利件数靠发明人姓名匹配，池内 1,006 个姓名重名、两字姓名重名概率更高，噪声远大于学术力；按「不确定性高的维度降权」的通行做法压到 0.15，与 OECD/JRC 手册里「质量差的指标不应与高质量指标同权」一致。

**为什么 C 给 0.30**：需求的原意是「引进」，与本地有连接的人落地概率更高，这是这条指标区别于纯学术排名的唯一实质维度。给高权重是产品意图，不是数据质量判断；数据质量恰恰相反——C 维最稀。本文的做法是「意图上给高权重、数据上标缺测」，两者都写进产物。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是本文 §1.6 的自建口径。降级发生在三处：① 需求四子功能只交两个（学科贡献度 → A 维，尽调推荐 → 合成）；② 引进难度与引进成本整块不交，因为没有国籍、语言、薪酬、岗位交互数据；③ 深圳连接维从「关系强度」降级为「0/1 + 篇数」的序数信号，因为论文只能证明「合作过」，不能证明「愿意来」。

本文没有做的降级包括：没有用「是否发过中文论文」推断「中文能力」、没有用「机构所在城市房价」推断「引进成本」、没有用「论文合作国家数」推断「国际化程度」。这三件事都能编出数，但都是代理变量套代理变量，误差不可控。

### 2.2 口径拆解：对象、集合、归一

**对象**：学者（`dwd_scholar` 一行），且现机构名不含「深圳」。排除深圳现职者的理由是这条指标服务「引进来」，已在本地的 182 人不属于候选。

**集合**：20,238 人（20,420 有姓名记录 − 182 深圳现职）。归一池取全池 20,238，不按学科、不按机构层次分组；原因是分组后每组样本降到几十人，min-max 会被单个人拉满。

**A 维**：复用学术力三维（论文/被引/H）各自 `log1p` 后在全池 min-max、再等权平均，得到 0—1 的学术力。这一维与 `M_TALENT_ACADEMIC_SCORE` 的分数严格单调，只是缩放不同。

**P 维**：发明人姓名件数，先做两道剔除——池内同名（1,006 个姓名）判缺测、姓名少于 3 字判缺测（两字姓名在 40 万发明人里重名概率过高），剩下的 9,195 人取 `log1p` 后在全池 min-max。剔除的 11,043 人（2,632 同名 + 3,635 两字 + 4,776 无命中）不补 0。

**M 维**：把学者的研究方向标签与中文论文关键词送入 28 类「20+8」集群字典，命中簇数作为原值。数据来源两条：论文关键词 12,592 人、研究方向标签 1,765 人，合计 14,357 人有值；5,881 人两条都没有，判缺测。

**C 维**：锚定论文（姓名 + 机构前缀双锚定）的共同作者机构里含「深圳」的篇数，加上履历表里深圳机构的任职标记。实测 464 人有深圳合作论文、18 人有深圳履历、13,884 人为 0、5,878 人无任何论文或履历可判（缺测）。C 维非零率 2.35%。

### 2.3 依赖分解（两跳停）

| 跳 | 依赖 | 承载 | 状态 |
|---|---|---|---|
| 1 | 学术力 | `dwd_scholar` 三列 | 可算，100% |
| 1 | 专利件数 | `patent_inventor_counts_gkx.json`（403,743 姓名） | 可算，45.43% |
| 1 | 产业方向 | `research_direction.fields` + 论文关键词 | 可算，70.94% |
| 1 | 深圳连接 | 论文作者机构 + 履历机构名 | 可算，2.35% 非零 |
| 2 | 招聘意向 | `gkx.dwd_job`（10 行） | **断在第 2 跳**：无投递/意向日志 |
| 2 | 引进难度 | 国籍、语言、文化背景 | **断在第 1 跳**：无字段 |
| 2 | 引进成本 | 薪酬、安家费、岗位预算 | **断在第 1 跳**：无字段 |

「两跳停」在这里有两层含义：第一层是「招聘平台真源只有 10 行」，任何「谁投了简历、谁有意向」的分析都做不了；第二层是「难度与成本的原始变量在学者主档里根本不存在」，不是数据稀疏，是结构缺失。

### 2.4 算路 / SQL

本指标**零 SQL**：学术力读 `probe_a26_20261022.json`，专利读 `patent_inventor_counts_gkx.json`，方向读 `probe_talent21_20261022.json` 与 `a25_paper_panel.json`（100,900 篇全量解析），履历读同一份 TALENT-21 快照。

```text
-- 快照的原始形态（已落盘，本文不再发）
SELECT inventor_name, COUNT(*) FROM gkx.dwd_patent_inventors GROUP BY inventor_name;
-- 403,743 个姓名，件数合计 2,939,851 ≈ 表行数 2,939,895（44 条发明人为空）

SELECT COUNT(*) FROM gkx.dwd_job;
-- 实测 10 行，不可用
```

本地计算：四维各自归一 → 逐人记录 `dims_available` → 按剩余权重合成 → 排序 → 只保留 ≥2 维的 16,831 人 → 分维 Top 与簇命中统计 → 三组敏感性。耗时 2 分 16 秒（瓶颈是 20,238 人 × 锚定论文的字符串匹配）。

**为什么不在 SQL 里算**：专利件数与论文作者面都已是落盘快照，SQL 侧再 `GROUP BY` 会触发全表扫描（`dwd_patent` 294 万行、`dwd_zh_paper` 10 万行带长文本），违反派单书「禁止 GROUP BY 大列」；本地 join 用字典，一次 2 分钟可接受。

### 2.6 结果解读

**分布**：20,238 人全池分数均值 31.06、中位 29.25、最高 92.01；去掉只有 1 维的 3,407 人后，16,831 人可排序，均值 28.20、中位 27.39、P10 15.60、P90 42.52、P99 58.74、最高 83.16。均值的两次差异来自「单维人被剔除」——单维人的分往往被重归一到 100，会把均值抬高。

**Top 5**：赵天寿（南方科技大学）83.16（A 89.28 / P 70.92，两维）、孙立成（西湖大学）79.41（A 85.92 / P 66.38）、张金龙（华东理工大学）76.77（A 83.50 / P 63.31）、吕伟（清华大学）74.21（三维）、郑南峰（厦门大学）74.05（A 81.26 / P 59.63）。前三名都是「学术强 + 专利多、但没有深圳连接痕迹」的人；他们的分主要来自 A 与 P 在重归一后占满分母。

**深圳关联子榜**：C 维有值的候选人里，魏锋（中国食品药品检定研究院）73.40、吕伟 73.36、何赟泽（湖南大学）71.24、孙宏斌（清华大学）70.52 居前。魏锋的 C 维 81.55、M 维 77.82、A 维 61.58，属于「方向对口 + 有深圳合作 + 学术中上」的典型；吕伟的 A 维 76.13、C 维 81.55，但锚定论文只有 5 篇，C 维的「81.55」实际是由 1—2 篇深圳合作论文撑起来的，解释时必须回到篇数。

**为什么与学术榜差异大**：主口径与纯学术力的 Spearman 0.4479、Top 50 重合 2 人；与四维等权的 Spearman 0.38。两个数字说明排序被 C 与 M 两维主导，而 C 维只有 476 人非零——榜单实际上在「有深圳痕迹的人」与「学术极强的人」之间做取舍。这是产品意图（引进匹配）的合理结果，但也是「榜单可被单篇合作论文改变」的风险来源。

**簇命中**：候选池里命中最多的是网络与通信 276、智能传感器 255、新材料 252、安全节能环保 229、新能源 171、细胞与基因 142、生物医药 104、大健康 99、激光与增材制造 89、量子信息 70。这个分布可以用来回答「深圳 20+8 里哪些方向的外部人才储备最多」，但不能回答「哪些方向最缺人」——缺人需要岗位需求侧数据，本库没有。

## 四、数据缺失情况

### 4.1 缺失清单

| 缺失项 | 现状 | 影响 | 修复建议 |
|---|---|---|---|
| 招聘交互日志 | `dwd_job` 10 行 | 智能筛选退化 | 接入招聘平台投递/意向/面试日志 |
| 国籍与语言 | 无字段 | 引进难度不可算 | 学者主档补国籍、语言能力 |
| 薪酬与岗位预算 | 无字段 | 引进成本不可算 | 接入岗位薪酬库或甲方预算表 |
| 深圳连接 | 仅 2.35% 非零 | C 维近乎二值 | 补学者-机构任职时间线、项目合作 |
| 专利归属 | 姓名匹配 | 45.43% 可用 | 补发明人 ID（ORCID/身份证哈希） |
| 学科码 | 无 | 学科贡献度不可算 | 补学科分类码 |
| 流动意愿 | 无 | 无法预测「愿不愿意来」 | 需行为数据或问卷 |

### 4.2 对结论的影响边界

缺失把这条指标从「引进预测」压成「匹配排序」：它不能回答「他会不会来」，只能回答「他的学术、专利、方向、深圳痕迹在池内处于什么位置」。C 维的极稀覆盖还带来一个隐性偏移——有 C 值的人会因为多一维而获得额外权重，导致榜单在「学术极强」与「有深圳痕迹」之间摇摆。

难度与成本的缺失不是「数据不够」，是「结构没有」：学者主档里没有国籍、语言、薪酬三列，任何替代变量（比如用机构所在城市房价推成本）都是编数。本文不交这两块，是为了让「部分支持」这个档位名副其实。

### 4.3 不可外推的三件事

第一，不能把分数当「引进成功率」。它不含意愿、薪酬、家庭、平台条件，只含学术、专利、方向、深圳痕迹四个静态特征。

第二，不能把 C 维分当「深圳关联强度」。81.55 是 476 人内部的 min-max 值，一个人只要有 1 篇深圳合作论文就可能拿到高分；要判断强度必须回到「合作论文篇数」与「合作机构层级」。

第三，不能把 Top 榜当「该挖名单」。榜单前三名没有深圳连接痕迹，他们的分来自学术与专利；真正符合「引进匹配」意图的人在中段（如魏锋 73.40、何赟泽 71.24），需要结合 C 维与 M 维人工复核。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

**calc-logic 无实现，registry seed 有身份但公式未签。** calc-logic 目录没有 `M_TALENT_ATTRACT_SCORE`；registry seed 把它定位为「全球库中与深圳产业发展方向契合的外部人才综合推荐分」，与本文四维方向一致，但 `formula: pending_cosign`（见 §0.4）。因此本文没有「王惠原方法」可还原，只能把需求四子功能映射到四维，并把权重、归一、缺测规则显式写出，供后续 calc-logic 修订时对照。

### 5.2 新方法概述

新方法 = A/P/M/C 四维 + `log1p` 池内 min-max + 剩余权重重归一 + ≥2 维才可排序 + 分维解释 + 三组敏感性。难度与成本两块不交付，缺口写进 `§4.1`。

### 5.4 选用建议与理由

**建议：本产物作为引才专班的「候选池初筛 + 分维解释」工具，页面标题写「人才引进匹配度（四维）」，不写「引进成功率」或「引进难度」。** 理由：四维里三维覆盖过半、一维极稀，合成分能排序但不能预测；难度与成本所需变量完全缺失，任何「难度分」都是编造。

**不建议**把 C 维做成「深圳关联概率」，也不建议用「论文合作 + 履历」之外的代理变量补 C。等甲方提供招聘交互日志、国籍语言、薪酬预算三类数据后，再解锁难度与成本，代码结构不变，只需在 `W` 里加两个键。

## 附录 C　人才引进吸引力指数可行性报告（完整版）

### C.1 报告目的与范围

本附录回答：在「三维可用、一维极稀、两子功能无数据」的条件下，引进吸引力指数能否作为推荐工具交付，以及它不能回答什么。范围限定在候选排序与分维解释，不扩展到招聘流程。

### C.2 需求语义锚定

需求用了「引进难度」「引进成本」「尽调」「推荐」四个词。前两个是预测问题，需要意愿与预算变量；后两个是排序与解释问题，只需要静态特征。本库只有静态特征，因此只能做后两个。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：多准则决策

OECD/JRC 手册的复合指数与 AHP/TOPSIS 都走「多维归一后加权」。本文属于这一族，权重由产品给、归一由数据给、缺测由规则处理。

#### C.3.2 方法族 B：协同过滤/相似度

推荐系统的召回-排序需要用户-物品交互矩阵。本库没有任何「谁被引进、谁被拒」的交互记录，协同过滤无法训练。

#### C.3.3 方法族 C：迁移意愿模型

引力模型需要距离、薪酬差、平台吸引力三类变量。本库只有机构名，前两类都没有。

#### C.3.4 方法族 D：规则打分卡

政策引才评分表通常由「学历 + 头衔 + 论文 + 专利 + 年龄」硬条件组成。本文的四维接近打分卡，但没有年龄与头衔，故只能作参考分。

### C.4 数据可行性详细分析

#### C.4.1 学术维

20,238 人 100% 可算，是本指标最稳的一维。

#### C.4.2 专利维

9,195 人可算（45.43%），其余因同名、两字姓名、无命中判缺测。这一维的权重被压到 0.15，正是为了控制噪声。

#### C.4.3 产业方向维

14,357 人可算（70.94%），来源为论文关键词 12,592 人与方向标签 1,765 人。标签是自由文本，靠 28 类字典映射，存在漏配。

#### C.4.4 深圳连接维

476 人非零（2.35%），464 人靠论文合作、18 人靠履历。覆盖率极低，是本指标最大的结构弱点。

### C.5 推荐构建方案（工程可执行）

1. 发布四维匹配分，页面写清「非引进概率」；
2. C 维只展示序数与原始篇数，不展示「概率」；

### C.6 风险与残余不确定性

### C.7 可行性总判（完整版结论）

四维中三维覆盖过半、一维极稀；需求四子功能中两个可交付、两个无数据。按「缺测不补 0、剩余权重重归一」交匹配分，判「部分支持」。它不是引进预测模型，是候选池的静态匹配排序。
