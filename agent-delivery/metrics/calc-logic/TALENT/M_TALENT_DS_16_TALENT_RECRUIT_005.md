## 摘要

需求要「识别国际科技人才在跨语言/跨文化沟通上的障碍，输出可量化、可解释的沟通障碍信号」。本文逐项核查 `gkx` 280 张表后确认：**全库没有个人语言能力字段，没有沟通行为语料，没有障碍标签**。

三个关键计数：13 个 `language` 列分布在 11 张表，全部指向论文语言（`dwd_zh_paper.language_classify` 全表只有 1 个取值）、文档语言、政策语种；`dwd_scholar.bio_zh` 19,109 条非空，其中提到「英语」的仅 28 条（0.1465%）、提到「留学」4 条、「访问学者」0 条，且都是自述、无等级、无证书；`dwd_scholar_talent_flag` 只有 `scholar_id` 与 `academician` 两列，没有任何语言/国际化标签。

唯一可用的替代信号是海外经历：海外学历 628 人、海外履历 896 人、国际合著 1,824 人。但它测的是「接触过境外」，不是「沟通有障碍」，而且方向相反——海外经历越多的人，通常语言障碍越低。用它代替障碍分，会得到系统性反向的结论。因此本件**只落证据计数，不落分数、不分档、不给名单**。这是「完全不支持」，不是「数据少，先凑一版」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

挂在「国际人才引进 → 沟通障碍评估」。前端设想：给每位候选人才一个沟通障碍分（或雷达图），标出语言、文化适应、表达三个维度的强弱，供用人单位在面试前预判风险。后端需要：候选人语言能力等级、沟通行为样本、专家/问卷标签，三者合成一个可解释信号。

需求还要求「可解释」。这意味着不能只给一个黑箱分，必须能说清「因为哪一条证据判他有障碍」。在当前数据下，连一条证据都拿不出来。

### 1.2 为什么需要「沟通障碍智能检测」

国际人才引进的失败，很多不是能力不够，而是沟通与文化适应出问题：语言表达不清、会议跟不上、团队协作摩擦。用人方希望在签约前就知道风险，降低「来了又走」的成本。这个需求在业务上成立，问题在数据侧完全没有落点。

另一个现实是：深圳的海外经历人才池不大。20,420 名有姓名学者中，海外学历 628 人、海外履历 896 人、两者兼有 351 人。即使只对这 351 人做评估，也需要额外的语言测评或面试记录，而库里没有。

### 1.3 需求文档是否给出定义方法

没有。需求只给「跨语言/跨文化」「可量化、可解释」两句，未给维度、量表、阈值、标签体系。算法库无实现。按铁律第 6 条，「文本里出现招聘词不等于企业在招人」，同理「bio 里出现『英语』不等于这个人英语好」——本文按后者从严处理，不把关键词命中当能力。

### 1.4 类似指标权威机构构建方法可行性分析概要

国际上的语言能力评估依赖三类工具：标准化考试（TOEFL/IELTS/CEFR）、结构化面试评级、行为样本分析（录音转写、会议记录）。跨文化适应多用量表（如 CQ、ISS）或问卷。共同点是**都必须对人做测量**，而不是从论文库里推断。

机器学习路线（语音识别 + 文本情感/流畅度）需要音频与转写文本。`gkx` 没有任何音频、没有访谈转写、没有会议记录、没有邮件/即时通讯语料。唯一的大文本是中文论文摘要 268,315 条，属书面学术语体，既不是对话，也不含障碍标签。

### 1.6 推测原意与推测定义

推测原意：给引进人才做一个「沟通风险预警」，让人单位知道该配翻译、该安排文化培训、还是该换人。推测定义应包含三层：

- **L 语言能力**：听说读写四级，CEFR A1—C2 或等效分数。来源应为考试、面试评级或自评量表。
- **B 沟通行为**：真实场景样本（面试对话、会议发言、邮件往来），可算流畅度、词汇多样性、回应延迟。
- **Y 障碍标签**：由专家或问卷给出的 1—5 级障碍程度，含语言、文化、心理三类。

现有数据对 L、B、Y 的覆盖都是 0。唯一能构造的是 **X 跨文化暴露度**（海外学历/履历/国际合著），但 X 与 Y 的关系是负相关：X 越高，Y 通常越低。用 X 反推 Y，等于把「经历丰富」判成「障碍大」，结论完全反了。

## 二、计算过程

### 2.1 公式出处与「不降级」的必要性

无公式可引。常规做法是 `障碍分 = w1·(1-语言分) + w2·(1-适应分) + w3·风险项`。本文不写这个公式，因为三项输入全缺：语言分无、适应分无、风险项无。若强行把「海外经历」塞进 `(1-语言分)`，会得到「海外经历越多，语言分越低」的荒谬结论。

铁律要求「判档先实测后定档，不许抬档」。这里的实测结论是：可计算维度 0 个，任何分数都是编的。因此本文的计算过程是「证据核查过程」，不是「打分过程」。

### 2.2 口径拆解：对象、输入、标签

| 层 | 应有输入 | 库内现状 | 覆盖 |
|---|---|---|---|
| L 语言能力 | CEFR/TOEFL/IELTS/面试评级 | 0 个字段 | 0 / 20,420 |
| B 沟通行为 | 语音、访谈转写、会议、邮件 | 0 张表 | 0 |
| Y 障碍标签 | 专家评分/问卷 | 0 个字段 | 0 |
| X 暴露度（代理） | 海外学历/履历/合著 | 有 | 628 / 896 / 1,824 |
| 对象 | 国际人才 | `dwd_scholar` 20,420 有姓名 | 有池无测 |

四层里只有 X 有数据，而 X 不是 Y 的代理，是 Y 的**反向指标**。这就是「完全不支持」的技术定义：不是样本少，是**测量对象与标签同时缺席**。

### 2.3 依赖分解（两跳停）

第一跳：`dwd_scholar` → 姓名、机构、bio。第二跳：bio → 关键词命中（英语/留学/双语等）。第三跳（不存在）：bio → 语言等级、沟通行为、障碍标签。第三跳缺失，整条链断在这里。

`dwd_scholar_talent_flag` 只有 `scholar_id`、`academician` 两列；`dwd_scholar_edu` 有学历与院校，但没有语言；`dwd_org_recruit_info` 有 7,981,643 条岗位需求，是「企业要什么人」，不是「人有什么能力」。三张表都补不上这一跳。

### 2.4 算路 / SQL

本件零 SQL，读 `code/_snapshots21/zero_source_probe_20261022.json`（由 `code/_probe_zero_source.py` 用 8 条探针 SQL 从 `gkx` 拉取并落盘）。算路：

1. 在 `information_schema.columns` 里按 `language|proficien|toefl|ielts|外语|英语` 匹配，得 13 列 / 11 表。
2. 逐列判定语义：论文语言、文档语言、政策语种，全部非「人的能力」。
3. 在 `information_schema.tables` 里按 `speech|interview|meeting|email|chat|audio|video` 匹配，得 0 表。
4. 在 `dwd_scholar.bio_zh` 里统计关键词命中，得英语 28、日语 0、德语 1、法语 4、俄语 0、留学 4、访问学者 0、双语 13。
5. 检查 `dwd_scholar_talent_flag` 列清单，确认只有两列。
6. 结论：不落分，只落证据。

### 2.5 清洗规则

本件不做清洗，因为没有可清洗的记录级数据。仅做语义甄别：

- `dwd_zh_paper.language_classify` 是 `tinyint`，全表只有取值 1，是「中文」标志，不是能力等级。
- `dwd_patent.language` 是 `json`，存专利文本语种，与发明人语言能力无关。
- `dwd_global_policy_base.language` 是政策原文语种，与人才无关。
- `bio_zh` 的「英语」命中是自述，可能是「英语四级」「英语流利」「英语较差」，文本里没有等级，不能二值化。
- 「海外」命中 10 条、「留学」4 条，是经历描述，不是能力描述。
- 所有命中率分母用非空 bio 19,109，不用全表 21,316，避免把空简介算成「没提英语」。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

王惠系方法在本指标上没有实现。可追溯的做法是「面试 + 试用 + 导师观察」：由用人方在面试中判断语言表达，入职后由团队反馈文化适应，必要时配翻译或语言培训。该方法依赖人，样本小，但能真实测到沟通行为。

### 5.2 新方法概述

本文没有新方法，只有证据核查。可提出的最小可行方案是「问卷 + 面试评级」：对 351 名海外经历人才发 1—5 级自评量表，面试官再给一个 1—5 级他评，两者合成障碍分。这需要业务侧采集，不是数据侧能变出来的。

### 5.3 逐维对照表

| 维度 | 王惠方法 | 本文现状 | 差异与风险 |
|---|---|---|---|
| 语言 | 面试听 | 无 | 无法替代 |

| 标签 | 主观评级 | 无 | 无金标准 |
| 成本 | 人力 | 0 | 采集成本高 |

### 5.4 选用建议与理由

建议**不上线**该指标的自动评分。若业务一定要一个界面，只放「数据未采集」的说明页与采集入口（问卷/面试评级表），不要放分数。理由：可计算维度为 0，任何分数都会把「海外经历多」误判为「障碍大」，直接伤害高价值人才。

若未来接入测评数据，建议先做小样本验证：351 名海外经历人才中抽 50 人做面试评级与自评，看两者一致性，再谈模型。没有金标准之前，不做「智能检测」。
