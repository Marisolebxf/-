## 摘要

本文对外部候选人 20,183 人（当前机构不在深圳）建立三维推荐指数：D1 学术力（复用 162 的口径，0—100，全覆盖）、D2 产业力（所属机构 2021—2026 专利件数，17,093 人有值）、D4 深圳连接度（深圳合著占比 0.6 + 深圳履历/学历 0.4）。D3 产品匹配度因招聘表无技能要求、产品标签表信用代码交集仅 3.5% 而**整维缺失**，按 0.40 / 0.30 / 0.30 归一。

全池得分均值 36.9476、中位 38.1874、p90 47.1737、最大 75.2096；A/B/C/D 为 2,019 / 4,036 / 6,055 / 8,073。推荐榜前五：冯峰（清华大学，75.2096）、刘洪海（哈工大，71.9798）、彭松林（暨南大学，71.3144）、张治国（哈工大，71.3079）、张政军（清华大学，70.7788）。这五人共同点是「学术力中上 + 机构专利强 + 至少 1 篇深圳合著」，不是「学术力最高」——学术力最高的候选人若没有深圳连接，会被 D4 拉低。

最大的数据现实是深圳连接度极度稀疏：20,183 人中只有 468 人（2.32%）有任何信号，其中 455 人有深圳合著、19 人有深圳履历/学历，82 人强于 0.4。也就是说 97.68% 的候选人在这三维上是「零连接」，推荐榜实际上是「学术力 + 机构产业力」的排序，D4 只在头部 400 人里起作用。这一点必须在 UI 上明说，否则会被误读为「深圳对这些人没有吸引力」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

本指标挂在「科技人才态势 → 人才洞察分析 → 招入推荐」。前端呈现三块：外部候选人推荐榜（分数 + 分档 + 推荐理由）、单人匹配分析卡（学术力、产业力、深圳连接度、缺失项）、按城市/机构/方向的筛选。后端需要一张候选人级结果表，字段至少包含 `scholar_id`、姓名、机构、城市、K、机构专利、连接度、总分、档位、缺失维标记。

需求原文给的是「学术力 / 产业力 / 产品匹配度 / 深圳连接度」四维加阈值，输出指数 + 优选清单 + 匹配分析报告。本文只落地三维，第四维缺失，原因见 §1.3 与 §4.1。这个缺口不是「数据少」，是「对象不存在」：没有求职者简历、没有岗位技能要求、没有产品—人才映射。

### 1.2 为什么需要「招入人才推荐模型」这个指标

深圳的招引工作长期依赖两种方式：一是高校院所推荐，覆盖窄、周期长；二是猎头，成本高、只看头衔。推荐模型的价值是把「学术力」「产业平台」「与深圳的连接」拆开，让招引人员看到三类人：学术强但没来过深圳的（需要破冰）、学术中等但在深圳合作过的（转化成本低）、机构平台强的（可能自带资源）。三类人的招引策略完全不同，混成一个分数会丢失策略信息。

它也有明显的伦理与合规风险：推荐榜会把「没来过深圳」的人排低，形成自我实现的偏差；机构专利强的候选人会被平台抬分。本文在 §4.3 列了禁令，并在 §5.4 建议把「连接度」作为筛选器而不是加权项。

### 1.3 需求文档是否给出定义方法

没有。需求给了四维名称与「阈值 + 加权」，没有给字段、权重、阈值、候选人范围、匹配方法。算法库没有实现。本文的三维映射是：学术力 → 162 的 K；产业力 → 机构专利件数；深圳连接度 → 合著 + 履历。产品匹配度无法映射，因为 `dwd_org_recruit_info` 只有岗位名/描述/工作地/发布日期/招聘人数，没有学历、技能、薪资要求；`dwd_org_industry_product_tags` 的 `credit_code` 与机构底册只有 3.5% 交集。

### 1.4 类似指标权威机构构建方法可行性分析概要

国际上人才推荐系统多用于招聘平台，特征是「求职者主动画像 + 岗位要求 + 协同过滤」，如 LinkedIn Talent Insights、SeekOut。学术人才映射常用「文献计量 + 机构地理 + 合作网络」，如 Elsevier Pure、SciVal 的 collaboration map。国内常见做法是「头衔 + 论文 + 专利 + 项目」加权。

本文采用学术映射的思路：没有求职者画像，就用公开文献与履历做「被动画像」；没有岗位要求，就用机构产业平台做「环境匹配」。这与商业推荐系统的差距在于：没有行为数据（点击、投递、面试），所以只能做「谁看起来合适」，不能做「谁会来」。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式无出处。降级有两处：一是四维降三维（产品匹配度缺失）；二是「深圳连接度」用合著与履历代理「来深意愿」，而意愿本身不可测。两处降级都指向同一个事实：库里有「学术履历」，没有「求职行为」。

### 2.2 口径拆解：对象、集合、归一

对象集合 20,183 人。D1 全覆盖；D2 覆盖 17,093 人（84.70%）；D4 覆盖 468 人（2.32%），其余 19,715 人 D4=0（不是缺失，是「无观测连接」）。归一：

```
K   = 100 × (0.5·logminmax(paper) + 0.5·logminmax(cite))
P   = 100 × logminmax(机构专利件数)
Lp  = logminmax(深圳合著占比)        # 仅 np>0
L   = 0.6·Lp + 0.4·hist             # np>0
L   = 0.4·hist                      # np=0
S   = (0.40·K + 0.30·P + 0.30·100·L) / Σw
```

| 维度 | 样本 | 中位 | p90 | 最大 | 权重 |
|---|---:|---:|---:|---:|---:|
| K 学术力 | 20,183 | 52.8525 | 66.2003 | 100.0 | 0.40 |
| P 机构专利 | 17,093 | — | — | — | 0.30 |
| L 深圳连接 | 20,183 | 0.0 | 0.0 | 1.0 | 0.30 |
| S 总分 | 20,183 | 38.1874 | 47.1737 | 75.2096 | — |

### 2.3 依赖分解（两跳停）

第一跳：`dwd_scholar` → 姓名、机构、城市、paper、cite。第二跳：机构名 → `star_applicant_agg_gkx.json` 的 `agg[org][0]`；学者 → 论文面板的锚定论文 → 作者机构含深圳的篇数 `nsz`；履历/学历表 → `work_sz`/`edu_sz`。第三跳（不做）：招聘表与产品标签表本可提供岗位/产品匹配，但字段与主键都不支持，放弃。

### 2.4 算路 / SQL

本件零 SQL，读 `code/_snapshots21/talent22_panel_20261022.json`。算路：

1. 取 20,420 名有姓名学者，剔除 `city=深圳市` 或机构名含「深圳」的 237 人，得 20,183 人。
2. D1：复用 `C.academic_k()`（与 162 同一函数）。
3. D2：读申请人聚合，取 `agg[org][0]`，log-minmax 到 0—100；org 不在聚合里则 None。
4. D4：`lpaper` 只在 `np>0` 的 13,844 人中归一；`L=0.6*lpaper+0.4*hist`；`np=0` 时 `L=0.4*hist`。
5. 总分：`(0.40·K + 0.30·P + 0.30·100·L) / Σw`，Σw 在 P 缺失时为 0.70。
6. 池内 p90/p70/p40 切 A/B/C/D。

**为什么 D4 要设 0.4 上限**：首版把无锚定论文者的 L 直接记为 hist（有深圳履历就是 1.0），结果 19 个「只来过深圳工作/读书、没有任何合著」的人拿到 conn=1.0，把秦庆华（K=80.27、np=0）推到榜首。这不是连接强，是分母缺失。改为 0.4×hist 后，榜首变为冯峰（K=55.63、4 篇深圳合著、3 段深圳履历，conn=1.0），逻辑才顺。

### 2.5 清洗规则

- 候选人剔除深圳：`city=深圳市` 或机构名含「深圳」任一命中即剔除，避免把在深人员当外部候选人。
- 机构专利缺失：不补 0，按 0.70 权重归一；产物标 `dims=2`。
- 无锚定论文：合著分量记 0，连接度上限 0.4，并在 `np=0` 时标 `conn_floor=0.4`。
- 合著占比 1/1：小样本噪声，1 篇论文里有深圳作者就是 100%，本文不设最小篇数门槛，但在 §4.3 披露。
- 机构名精确匹配：`agg` 的键是全名，机构别名/分校会漏；漏者 D2 缺失。
- 海外机构：如香港中文大学的 `org_pat=28`，可能是申请人聚合误配到同名实体，D2 对海外机构不可信。
- 重复姓名：不合并，推荐榜按 (姓名, 机构) 展示，重名会在 UI 上重复出现。

### 4.2 对结论的影响边界

D1 的结论稳健：全覆盖，且与 162 一致。D2 的结论中等稳健：84.70% 覆盖，但平台口径会被大机构抬分，且海外机构可能误配。D4 的结论不稳健：2.32% 覆盖、1 篇合著即 100%、无意愿数据，任何「深圳连接强」的说法都只能当「有合作证据」，不能当「愿意来」。推荐榜的头部由 D4 主导，因此头部名单的说服力弱于 162 的学术力榜。

### 4.3 不可外推的三件事

第一，不可把推荐分当「来深概率」：连接度是过去合作，不是未来意愿。第二，不可把机构专利当个人产业力：大厂普通工程师会被抬分。第三，不可用 1 篇合著判定强连接：1/1=100% 是小样本噪声，至少要 3 篇才能谈强度。

补充三条。第四，不可把 A 档当「已筛选名单」：A 档 2,019 人里多数没有深圳连接，需要破冰。第五，不可对海外机构用 D2：香港中文大学的 28 件专利与其实力不匹配，是聚合误配。第六，不可用本件做「深圳吸引力」论证：97.68% 的零连接是观测缺失，不是人才不愿来。

最后一点是发布纪律：推荐榜的每一行都必须带 `dims` 与 `conn` 来源，不能只给总分。缺少来源标注的榜单，在业务侧一定会被当成「录用建议」，而本件连「意愿」都没有测。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

王惠系方法在本指标上没有直接实现。可追溯的做法是「名单制」：由校友会、学会、驻外机构推荐候选人，再由专家判断「学术水平 + 与深圳的匹配」，最后人工接触。该方法依赖人脉，覆盖窄，但意愿判断准。

### 5.2 新方法概述

本文用公开数据做被动画像：学术力 + 机构产业力 + 深圳连接，池内分位切档。优点是全覆盖、可复现；缺点是没有意愿、没有岗位匹配、连接观测稀疏。

### 5.3 逐维对照表

| 维度 | 王惠方法 | 本文方法 | 差异与风险 |
|---|---|---|---|
| 学术力 | 专家判断 | 162 的 K | 本文可规模化，质量判断弱 |
| 产业力 | 机构调研 | 机构专利 | 本文平台口径，个人被平均 |
| 产品匹配 | 岗位/项目经验 | 缺 | 本文无法回答「能不能干这个岗」 |
| 深圳连接 | 人脉/往来 | 合著 + 履历 | 本文只测合作证据，不测意愿 |
| 意愿 | 直接沟通 | 缺 | 本文最大短板 |

### 5.4 选用建议与理由

建议把本件当**破冰名单生成器**，不是**录用决策器**：A 档 2,019 人按「有连接 / 无连接」二分，有连接的 82 人优先接触，无连接的 1,937 人走学术力 + 产业力筛选。产品匹配度必须由业务方补岗位 JD 后才能做，不能用一个假代理糊弄。若只能保留一个维度做初筛，选学术力 K，因为它全覆盖且与 162 一致；产业力与连接度作为加分项展示，不作为门槛。

对外发布时，标题写「外部候选人参考榜（三维）」，注明「不含岗位匹配与来深意愿」；每个候选人卡片必须显示 `nsz/np` 与 `hist_sz`，让读者知道连接度是怎么来的。

468 人（2.32%）有任何信号。这个比例低到不能做全池统计，只能做头部描述。连接度的两个来源里，合著 455 人、履历 19 人，履历信号几乎可以忽略。合著又依赖中文论文锚定，英文发表为主的候选人完全观测不到，因此「零连接」不等于「没来过深圳」。

#### C.4.4 产品匹配的不可行性

`dwd_org_recruit_info` 798 万行，字段只有岗位名、描述、工作地、发布日期、招聘人数；没有学历、专业、技能、薪资。即使有，岗位是企业招聘需求，不是人才能力，两者需要匹配算法与标注数据才能连起来。产品标签表 32,322 家，但 `credit_code` 与机构底册交集 3.5%，主键不通。两条路都断，所以 D3 缺失，不做假代理。

#### C.4.5 方法—数据对照矩阵

| 维度 | 理想数据 | 现有数据 | 可用度 | 降级方案 |

| 意愿 | 投递/登记 | 无 | 无 | 不做 |

### C.5 推荐构建方案（工程可执行）

1. 落 `talent_recruit_candidate` 表：`scholar_id`、K、org_pat、nsz、np、hist_sz、conn、score、tier、dims、version。
2. A 档切 A1（conn>0.4）/ A2（conn≤0.4），前端分开展示。
3. 每个卡片显示连接度来源（合著篇数/履历段数），禁止只显示 0—1 的小数。
4. 产品匹配度留空，不造代理；待岗位 JD 结构化后再补第四维。
5. 每季度重跑，与 162/163/165 同版本。

### C.6 风险与残余不确定性

最大风险是「连接度决定头部」：2.32% 覆盖的维度主导推荐榜，会让榜单看起来像「与深圳合作过的人」而不是「最值得招的人」。第二风险是「平台抬分」：机构专利强的候选人被高估。第三风险是「意愿缺失」：榜单无法回答「他会不会来」。三项都在 §4.3 有禁令。

### C.7 可行性总判（完整版结论）

三维可算、一维缺失，D4 覆盖极低，个人产业力不可得。按四档定义，判**部分支持**。可发布为「外部候选人参考榜」，不可发布为「招入决策榜」。
