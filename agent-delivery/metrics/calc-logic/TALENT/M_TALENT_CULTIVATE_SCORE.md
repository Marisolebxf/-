## 摘要

人才本地培育力指数要回答的是「深圳现有的人才里，谁扎得深、留得住、值得继续投」。需求没有「培育力」这个专条，最接近的表述是「深圳科技人才集聚态势、发展潜力及关键人才流动动态」与「人才迁徙情况」；本文把这两句话翻译成四维：留深黏性 Po 0.35、学术力 A 0.25、专利产出 P 0.20、平台资源 R 0.20。

打分池是 182 名现机构名含「深圳」的在册学者。四维里最不稳的是 Po：它由三个子信号组成——深圳任职年限（覆盖 21 人）、深圳求学经历（覆盖 **0** 人）、深圳署名论文占比（覆盖 136 人）。学历子表里一条深圳学校的记录都没有，不是深圳没有高校，而是 `dwd_scholar_education_background` 的 `scholar_id` 与主档不同域，池内 182 人只有 28 人能与子表连上，而这 28 人的学历记录恰好都不在深圳。于是一个本来应该有三维支撑的黏性维，实际由单一信号承载。

分数落在 9.26—78.39，均值 43.43、中位 42.48；分档为高黏性强 38 人、培育中 94 人、低黏性/待观察 50 人。Top 5 是李清泉（深圳大学，78.39）、明仲（深圳大学，75.52）、李坚强（深圳大学，73.47）、徐文福（哈尔滨工业大学（深圳），73.20）、饶峰（深圳大学，72.70）。榜首与第 7 名是同一个人——李清泉在 `dwd_scholar` 里有两条记录（「深圳大学，武汉大学」与「深圳大学」），本文按记录打分，页面必须去重。

稳健性方面，四组权重加倍的 Spearman 都在 0.97 以上，但分档穿越率高达 23.63%—38.46%，原因是 Po 维缺测 43 人、P 维缺测 95 人，权重一变就触发重归一分母变化。更严重的一组对照是：把「深圳署名占比」从 Po 维剔掉后，主口径与新口径的 Spearman 只有 **0.4066**、Top 10 只重合 4 人——这说明 Po 维实际上只有一个信号在工作，剔除它等于换了一条指标。

结论：这条指标可以作「深圳人才留存画像」的分维展示与人工复核线索，不能作「培育潜力预测」，也不能用来给人才排座次后直接发政策资源。它的分档边界不稳，Top 榜有重复记录，池子里还混进了专利代理机构的从业人员。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

要支撑的功能模块是：**科技信息展示系统 → 科技人才态势 → 关注地区人才态势 → 深圳科技人才态势**（需求 1.1.1.1.4.3.2.2，第 1787—1811 行），并引用 **人才洞察分析 → 人才迁徙情况展示**（1.1.1.1.4.3.1.2，第 1537—1545 行）。

需求原文写：「动态展示深圳市在人工智能、生物医药、新材料、通信技术、高端制造等重点技术发展领域中的人才分布地图……清晰展现各区、重点园区及产业集聚带的科技人才数量、结构与流动趋势。此外，模块应用智能分析算法，挖掘领域专家学者画像和合作网络，为用户提供深圳科技人才集聚态势、发展潜力及关键人才流动动态的多维洞察。」「发展潜力」与「流动动态」是本指标的上游语义。

|---|---|

### 1.2 为什么需要「人才本地培育力指数」这个指标

引才的对面是留才。深圳每年引进的人不少，但「来了又走」的成本很高；要判断谁留得住，不能只看学术力——一个学术极强但所有论文都署名海外机构的人，与一个学术中等但 90% 论文署名深圳机构的人，对本地培育的价值完全不同。这条指标存在的意义就是把「本地嵌入度」从学术力里拆出来单独计量。

第二个理由是它服务政策资源的差异化配置。高黏性的人适合给长期平台与团队，低黏性但学术强的人适合给短期项目与合作，低黏性且学术弱的人不需要额外投入。三档对应三种政策动作，这是分档存在的理由。

第三个理由是它必须承认自己的边界。需求没有给「培育力」下定义，本文的四维与权重是推测；Po 维又只有一个信号在工作。这两条决定了它只能作画像与线索，不能作拨款依据。本文在 §4.3 把三条不可外推写死，就是为了防止这类分数被直接拿去做资源分配。

### 1.3 需求文档是否给出定义方法

**需求没有「培育力」专条；registry seed 有身份且点名「高成长潜力」，但公式未签，且与派单给定的「留深黏性」权重不是同一件事（见 §0.4）。**

原文只有「发展潜力」「集聚态势」「流动动态」三个词。本文把它们翻译成四维：留深黏性（是否长期在深圳、成果是否署名深圳）、学术力（能不能产出）、专利产出（有没有技术成果）、平台资源（所在机构层次、院士头衔、国家级平台经历）。权重 Po 0.35 / A 0.25 / P 0.20 / R 0.20 为派单给定，不是需求原文。

本文补的口径决策有五条：① 打分池 = 现机构名含「深圳」且有姓名；② Po 维三个子信号池内归一后等权；③ A 维用全池 20,420 人的分位换算，避免小池内 min-max 把 182 人拉满；④ P 维用全池专利标尺；⑤ 缺维不补 0、按剩余权重重归一。

### 1.6 推测原意与推测定义

**推测原意**：产品要一张「深圳自己人」的画像，标出哪些人已经深度嵌入本地、哪些人只是挂了个名。它服务政策资源的差异化配置与引才后的留存监测，不服务个体绩效评价。

**推测定义（本文采用）**：

> 对深圳在册学者 $i$，四维原值为
> $$
> Po_i=\tfrac13(\widetilde{T}_i+\widetilde{E}_i+\widetilde{S}_i),\quad
> A_i=\text{全池学术分位},\quad P_i=\widetilde{\text{专利件数}}_i,\quad
> R_i=\tfrac13(\text{院士}+\text{高校名录}+\text{国家级平台})
>
$$
> 其中 $T$ 为深圳任职年限、$E$ 为深圳求学记录数、$S$ 为深圳署名论文占比；$\widetilde{\cdot}$ 为池内 `log1p` + min-max。合成为
> $$
> \text{Score}_i=100\times\frac{\sum_{d\in D_i}w_d x_{d,i}}{\sum_{d\in D_i}w_d},\quad
> w_{Po}=0.35,\ w_A=0.25,\ w_P=0.20,\ w_R=0.20
>
$$

**为什么 A 维用全池分位而不是池内 min-max**：182 人的池子做 min-max，会把池内第一名直接拉到 100、最后一名压到 0，看起来区分度很好，实际是「小样本拉伸」。用 20,420 人的全池分位，深圳学者的 A 维均值落在 54.83 分位、中位 55.22，说明这个群体整体处于全池中上，而不是「人人 80 分以上」。

**为什么 R 维用 0/1 拼装**：平台资源没有连续变量可用。院士头衔是 0/1，高校名录命中是 0/1，履历里是否出现「国家重点实验室 / 国家工程 / 中科院 / 大学」是 0/1。三项等权平均，取值只有 0、0.33、0.67、1 四档，这是数据结构决定的，不是本文偷懒。

## 二、计算过程

### 2.1 公式出处与降级的必要性

公式出处是本文 §1.6 的自建口径。降级发生在三处：① Po 维从「三维黏性」降为「单信号为主」，因为深圳求学子信号覆盖 0 人、任职年限只覆盖 21 人；② R 维从「平台层级」降为 0/1 拼装，因为没有平台等级字段；③ 流动动态降为截面，因为没有离职事件表。

本文没有做的降级包括：没有用「毕业学校在深圳」以外的线索猜求学经历、没有用机构名里的「研究院」字样推断平台等级、没有用论文合作城市数推断「本地嵌入」。这三件事都能补出数，但都是把「不知道」写成「有/没有」，会系统性高估或低估。

### 2.2 口径拆解：对象、集合、归一

**对象**：`dwd_scholar` 中 `org_name_zh` 含「深圳」且有姓名的记录，共 182 条。注意「记录」不等于「人」：李清泉有两条（「深圳大学，武汉大学」与「深圳大学」），池内同名记录会被各打一次分。

**集合**：182 条记录，不做机构筛选。池内包含深圳大学、南方科技大学、哈尔滨工业大学（深圳）、香港中文大学（深圳）、中国科学院深圳先进技术研究院、深圳湾实验室、深圳理工大学、深圳市妇幼保健院，以及少量企业/服务机构（如深圳市赛恩倍吉知识产权代理有限公司）——最后这一类不是学术机构，但在 `dwd_scholar` 里有记录，本文保留并在 §4.3 提示。

**Po 子信号**：`T` 由履历表深圳机构段累加（结束年减开始年，结束年空按 2026），覆盖 21 人；`E` 由学历表深圳学校计数，覆盖 **0** 人；`S` 为姓名匹配论文里机构含「深圳」的占比，覆盖 136 人。三个子信号各自在「有值的人」内部做 `log1p` + min-max，再对有值的子信号等权平均。

**A 维**：先用全池 20,420 人的论文/被引/H 做 `log1p` + min-max + 等权，得到全池学术分，再用 `bisect` 取每个人在全池的分位，除以 100 得到 0—1。

**P 维**：全池专利件数做 `log1p` + min-max，深圳池内 87 个「姓名唯一且 ≥3 字」的人取对应值；其余 95 人缺测。

**R 维**：院士（池内 2 人）、高校名录（池内 117 人）、国家级平台关键词（履历机构含「国家重点实验室/国家工程/国家实验室/中国科学院/研究院/大学」）三项 0/1 等权。

### 2.3 依赖分解（两跳停）

| 跳 | 依赖 | 承载 | 状态 |
|---|---|---|---|
| 1 | 深圳池 | `dwd_scholar.org_name_zh` 含「深圳」 | 182 条 |
| 1 | 学术力 | `dwd_scholar` 三列 | 182 条全覆盖 |
| 1 | 专利 | 发明人姓名快照 | 87 条可算 |
| 1 | 平台 | 院士标记 + 高校名录 + 履历机构 | 182 条可算 |
| 2 | 深圳任职年限 | `dwd_scholar_work_experience` | **断在 ID**：池内仅 28 人可连，深圳段 21 人 |
| 2 | 深圳求学 | `dwd_scholar_education_background` | **断在 ID**：池内 28 人可连，深圳学校 0 人 |
| 2 | 离职事件 | 无表 | **断在第 1 跳** |

「两跳停」的含义是：本文只做「主档 + 论文面 + 姓名级专利 + 0/1 平台信号」，不再尝试用子表 JOIN 主档补履历。因为池内 182 人只有 28 人能连上子表（15.4%），补出来的履历只覆盖少数人，反而会让 Po 维在「有履历」与「无履历」的人之间制造人为落差。

### 2.4 算路 / SQL

本指标**零 SQL**：深圳池与学术力读 `probe_a26_20261022.json`，履历/学历/院士/高校名录读 `probe_talent21_20261022.json`，论文署名读 `a25_paper_panel.json`，专利读 `patent_inventor_counts_gkx.json`。

```text
-- 快照的原始形态（已落盘，本文不再发）
SELECT scholar_id, name, org_name_zh, paper_nums, citation_nums, h_index
FROM gkx.dwd_scholar
WHERE org_name_zh LIKE '%深圳%';        -- 194 条，有姓名 182 条
```

本地计算：深圳池筛选 → Po 三子信号 → A 全池分位 → P 全池标尺 → R 三项 0/1 → 缺测记录 → 加权合成 → 分档 → 敏感性四组 + 剔除署名占比一组。耗时 2.6 秒。

**为什么不在 SQL 里算**：深圳池只有 194 条，逐条点查比一条 `GROUP BY` 更省；论文署名与专利都是落盘快照，SQL 侧再聚合会触发大表扫描。2.6 秒的本地耗时已包含 20,420 人的学术分位计算。

### 2.5 清洗规则

| 规则 | 处理 | 影响 |
|---|---|---|
| 机构名含「深圳」但姓名为空 | 排除 | 12 条 |
| 同一人多条记录 | 不合并，按记录打分 | 李清泉 2 条 |
| 专利池内同名 / 两字姓名 / 无命中 | P 维缺测 | 30 / 35 / 30 |
| 无深圳履历且无深圳求学且无论文 | Po 维缺测 | 43 |
| 有论文但无深圳署名 | S = 0（不是缺测） | 少量 |
| 非学术机构（专利代理、企业） | 保留，不剔除 | 少量 |
| 分数并列 | 按 `scholar_id` 稳定排序 | — |
| 院士标记缺失 | R 维按 0 处理（有标记表） | 0 |

清洗原则是「零与缺测分开」：有论文但深圳署名占比为 0 的人，Po 维的 `S` 记 0（真实「不在深圳署名」）；完全没有论文的人，`S` 缺测（不知道）。这两类在产物 `coverage.po_sub_coverage` 里分开计数。

**分档**：高黏性强 38 人（20.9%）、培育中 94 人（51.6%）、低黏性/待观察 50 人（27.5%）。

**Top 5**：李清泉（深圳大学，78.39；Po 0.83 / A 0.82 / R 0.67，P 缺测）、明仲（深圳大学，75.52；Po 1.00 / A 0.75 / R 0.33）、李坚强（深圳大学，73.47；四维齐全，P 0.67）、徐文福（哈尔滨工业大学（深圳），73.20；Po 1.00 / A 0.68 / R 0.33）、饶峰（深圳大学，72.70）。第 6 名汪天富 72.35（四维齐全，P 0.52），第 7 名是李清泉的第二条记录 71.92。

**Top 榜的结构特征**：前 15 名里 11 人来自深圳大学，2 人来自哈工大（深圳），1 人来自中科院深圳先进院，1 人来自南方医科大学附属深圳妇幼保健院。这不是深圳大学「一家独大」的结论，而是 `dwd_scholar` 的收录结构：深圳大学的学者记录最全，其他机构（尤其是企业研究院）收录稀疏。页面若按机构分组展示，必须同时展示「该机构在库人数」，否则会被读成机构实力排名。

**Po 维的真实构成**：139 人有 Po 值，其中 136 人靠「深圳署名占比」、21 人靠「任职年限」、0 人靠「深圳求学」（两个信号可叠加）。也就是说，Po 维 97.8% 的信息来自「论文有没有署名深圳机构」。这个信号本身有噪声：一个长期在深圳工作但主要与海外机构合作署名的人，S 会偏低；一个刚来深圳、把单位署名改成深圳的人，S 会立刻变高。

**成长性诊断（补充，不入合成）**：seed 原意是「高成长潜力」，派单给的是「留深黏性」，两者不同。为量化这处偏离，本文另算一个不入合成的成长信号：近 5 年（2021—2025）锚定论文占全部锚定论文的比例，加最近发表年。91 人有可判年份，占比均值 0.68、中位 1.00、P10 0.00（说明有一批人近五年零产出）、P90 1.00；最近发表年分布以 2024 年 35 人为峰，另有 11 人已到 2026。它与主分数（黏性指数）的 Spearman 只有 **0.1145**——也就是「黏性高」与「成长快」在本池里几乎无关。这个数字是本指标最重要的一条自我否定：**分数不能当培育潜力用**。

**敏感性**：Po×2 的 Spearman 0.9834、分档穿越 38.46%；A×2 的 0.9819 / 23.63%；P×2 的 0.9835 / 30.77%；R×2 的 0.9695 / 34.62%。排序稳、分档不稳，原因是分档阈值 60/30 正好落在分布密集区，且缺测维导致重归一分母随权重变化。剔除「深圳署名占比」后 Spearman 掉到 0.4066、Top 10 只重合 4 人——这条对照说明 Po 维不可替代，也说明这条指标对「署名」这一件事高度敏感。

### 4.2 对结论的影响边界

缺失把这条指标从「培育力」压成「本地嵌入度快照」：它能回答「谁的成果署名深圳、谁在深圳机构待得久」，不能回答「谁会被培育出来」「谁会离开」。Po 维的单信号化还带来一个方向性风险——把单位署名改成深圳，分数就会上升，这与「真实嵌入」不是一回事。

分档边界不稳是第二个影响。60/30 两个阈值落在分布密集区，加上缺测维重归一，权重微调就能让 23.63%—38.46% 的人换档。页面如果只展示档位不展示分数与分维，用户会看到「同一个人这周高黏性、下周培育中」。

### 4.3 不可外推的三件事

第一，不能把分数当「留存概率」，也不能当「培育潜力」。它不含离职事件、不含薪酬、不含家庭与年龄，只是静态特征的加权；补算的成长性诊断与它只有 0.1145 的相关，说明它几乎不携带成长信息（见 §0.4 与 §2.6）。

第二，不能把 Top 榜当「深圳最强人才」。榜首李清泉有两条记录，池内还混进了专利代理机构；榜单反映的是「本地署名 + 学术 + 专利 + 平台」的组合，不是学术排名（学术排名见 `M_TALENT_ACADEMIC_SCORE`）。

第三，不能把「深圳求学 0 人」读成「深圳没有培养过这些人」。这是子表 ID 不同域造成的可连性缺口，不是事实；真实情况可能是大量深圳高校毕业生在库，只是学历记录连不上主档。

## 附录 C　人才本地培育力指数可行性报告（完整版）

### C.1 报告目的与范围

本附录回答：在「四维里两维全覆盖、一维过半、一维单信号」的条件下，培育力指数能否作为留存画像交付，以及哪些结论必须撤回。范围限定在本地嵌入度计量，不扩展到人才政策效果评估。

### C.2 需求语义锚定

需求用的是「集聚态势」「发展潜力」「流动动态」。集聚是存量分布，潜力是未来产出，流动是时间序列。本文只能做存量分布与部分产出信号；流动需要离职/任职事件，本库没有。

### C.3 权威与学术构建方法谱系

#### C.3.1 方法族 A：嵌入度/留存指数

job embeddedness 理论把留存拆成「链接、匹配、牺牲」三束。本文的 Po 维对应「链接」（本地任职、本地求学、本地署名），但因为数据可连性，三束只剩一束。

#### C.3.2 方法族 B：多准则加权

OECD/JRC 的复合指数要求每维有值。本文用剩余权重重归一来处理缺测，属于该族的降级用法，代价是维间不可比。

#### C.3.3 方法族 C：生存分析

Cox 模型需要「离职事件 + 观察时长」。本库没有离职记录，也没有观察窗口，无法估计留存曲线。

#### C.3.4 方法族 D：引力模型

城市吸引力模型需要薪酬、房价、平台、距离。本库只有机构名，四个变量一个都没有。

### C.4 数据可行性详细分析

#### C.4.1 Po 维

三子信号覆盖 21 / 0 / 136。求学维因 ID 域问题全空，年限维只覆盖 11.5%，署名占比覆盖 74.7%。Po 实质是「深圳署名度」。

#### C.4.2 A 维

182 人全覆盖，用全池分位避免小池拉伸。池内均值 0.5483、中位 0.5522。

#### C.4.3 P 维

87 人可算，95 人因同名/两字/无命中缺测。缺测率 52.2%，是全指标第二大的洞。

#### C.4.4 R 维

院士 2 人、高校名录 117 人、平台关键词若干，三项 0/1 平均后只有四档。区分度低但不误导。

#### C.4.5 方法—数据对照矩阵

| 方法 | 需要的输入 | 库内状态 | 可行性 |
|---|---|---|---|
| A 嵌入度 | 链接/匹配/牺牲 | 1/3 束 | 降级可行 |
| B 加权复合 | 四维 | 2 全 + 1 半 + 1 单信号 | 可行（披露缺测） |
| C 生存分析 | 离职事件 | 0 | 不可行 |
| D 引力模型 | 薪酬/房价/距离 | 0/3 | 不可行 |

### C.5 推荐构建方案（工程可执行）

1. 发布四维画像，页面写「本地嵌入度」而非「培育潜力」；
2. 分档只作辅助，主展示用分数 + 分维 + 分位；
3. Top 榜按姓名去重，剔除专利代理/企业服务机构；
4. 补齐子表 ID、离职事件、项目经费后，再扩 Po 维与流动分析。

### C.6 风险与残余不确定性

- Po 单信号化，署名变更即分数变更；
- 分档边界不稳（穿越率最高 38.46%）；

四维中两维全覆盖、一维过半、一维单信号；需求语义中的「流动动态」无数据。按缺测重归一交画像分，判「部分支持」。它是本地嵌入度快照，不是培育潜力预测模型。
