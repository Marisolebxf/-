## 摘要

需求要建「高精度成本模型」，测算引进一名国际人才的总成本（薪酬 + 安家 + 搬迁 + 猎头 + 机会成本）。核查 `gkx` 280 张表后：37 个 `cost/income` 列分布在 7 张表，全部是企业财务口径——6 张 `dwd_main_business_composition_*`（area/industry/prod 各带一份 `_bak_20260911`）的 `core_biz_cost/core_biz_income` 及其增长率、占比，共 36 列；另 1 列是 `dwd_en_journal.layout_cost`（期刊排版费）。0 列薪酬、0 列安家费、0 列猎头费。

最容易被误用的是 `dwd_org_recruit_info`：7,981,643 行，字段为 `org_id/name_cn/job_title/job_description/work_place/release_date/hiring_number/data_source`，**没有薪资**。它能告诉你「企业在招什么岗位、招几人、在哪招」，不能告诉你「给多少钱」。

唯一有金额的替代是 `stock_finance`（40,239 行、972 家企业、期间 198912—202603、研发费用非空 19,695）与 `annual_financial`（90,926 行、员工数非空 3,184、营收非空 2,193）。用「研发费用 ÷ 员工数」可得企业人均研发投入，但这是**企业层面**的年度投入，不是**个人引进**的一次性成本，两者量级差 2—3 个数量级（企业研发费用以亿计，个人引进以十万计）。因此本件不输出成本分、不输出区间，只落证据与替代口径说明。判定「完全不支持」。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

挂在「国际人才引进 → 成本测算」。前端设想：输入人才画像（领域、职级、来源国、家庭规模），输出引进总成本区间与分项（年薪、签字费、安家费、搬迁、猎头、机会成本），供单位做预算与谈判。后端需要：个人薪酬记录、补贴申领记录、招聘费用台账、历史收入。

需求写「高精度」，意味着误差要小到可用于预算。当前数据连「有没有金额」都不过关，精度无从谈起。

### 1.2 为什么需要「高精度成本模型」

引进一个国际人才，成本差异极大：顶尖学者与青年博士可能差 10 倍，欧美与东南亚来源国差 2—3 倍，带家属与不带家属差一倍。用人方需要预算锚点，也需要谈判依据。业务上这是刚需。

但成本数据属企业/个人敏感信息，通常只在 HR 系统、个税、社保、猎头合同里。科技文献库天然不采集这些。

### 1.3 需求文档是否给出定义方法

没有。需求只给「高精度成本模型」六字，未给成本项、权重、数据来源、精度目标。算法库无实现。按铁律第 6 条，本文不把「招聘岗位数」当「招聘成本」——岗位多不等于花钱多，更不等于引进一个人贵。

### 1.4 类似指标权威机构构建方法可行性分析概要

成本模型通常用三类数据：薪酬调查（如 Mercer、智联）、行政记录（个税/社保/签证费）、企业台账（猎头合同、搬迁发票）。学术研究多用「薪酬回归 + 生活成本指数」，如 OECD 的税后收入比较、Numbeo 的生活成本。

三类数据 `gkx` 都没有。唯一接近的是企业财务，但它是企业整体，不是个人。这个区别是本质的：企业研发费用包含设备、材料、试验、人员，人员只是其中一部分，且不含引进环节的安家/搬迁/猎头。

### 1.5 引用来源（可核验）

1. OECD. Taxing Wages 2025. https://www.oecd.org/tax/taxing-wages/
2. Mercer. Total Remuneration Survey. https://www.mercer.com/
3. 国家统计局. 城镇非私营单位就业人员年平均工资. https://www.stats.gov.cn/
4. 深圳市人力资源和社会保障局. 人才引进补贴政策. http://hrss.sz.gov.cn/
5. 国家税务总局. 个人所得税税率表. https://www.chinatax.gov.cn/
6. 科技部. 外国人来华工作许可服务指南. https://www.most.gov.cn/

### 1.6 推测原意与推测定义

推测原意：给用人单位一个「引进一个人大概花多少」的预算工具。推测定义：

- **C1 薪酬包**：年薪 + 签字费 + 绩效，按领域/职级/来源国分层。
- **C2 一次性费用**：安家费 + 搬迁 + 签证/认证 + 猎头费（通常为年薪 20%—30%）。
- **C3 机会成本**：放弃原职位收入 + 家庭随迁成本。
- **C4 公共补贴**：人才补贴、住房补贴、科研启动费（可抵扣）。

现有数据对 C1—C4 的覆盖都是 0。唯一有金额的是企业财务，属「企业投入」而非「个人成本」。两者不可换算：企业研发费用里人员费占比未知，且不含引进环节。

## 二、计算过程

### 2.1 公式出处与「不降级」的必要性

无公式可引。常规模型 `Cost = C1 + C2 + C3 - C4`，四项输入全缺。若强行用「企业人均研发费用」代入 C1，会把 8 位数企业研发预算摊到个人头上。举例说明量级：一家企业年研发费用 2 亿元、员工 2,000 人，人均 10 万元；而引进一名海外教授的安家费就可能 100 万—300 万元。两者不是同一口径，也不是同一量级。

铁律要求「先实测后定档」。实测：金额字段 0 个（个人口径），任何成本数都是编的。

### 2.2 口径拆解：因变量、自变量、精度

| 项 | 应有输入 | 库内现状 | 覆盖 |
|---|---|---|---|
| C1 薪酬包 | 年薪/签字费/绩效 | 0 字段 | 0 |
| C2 一次性费用 | 安家/搬迁/签证/猎头 | 0 字段 | 0 |
| C3 机会成本 | 原职位收入 | 0 字段 | 0 |
| C4 公共补贴 | 申领明细 | 0 表（只有政策文本） | 0 |
| 自变量 | 领域/职级/国别/稀缺度 | 论文/机构/引用 | 部分 |
| 精度 | 预算级（±20%） | 无金额 | 不可达 |

因变量缺失是硬伤：没有 Y，回归、分档、区间估计全部无法做。

### 2.3 依赖分解（两跳停）

第一跳：`dwd_scholar` → 姓名/机构/论文。第二跳：机构 → 企业财务（`stock_finance`/`annual_financial`）。第三跳（不存在）：个人 → 薪酬/补贴/猎头。链在第三跳断。`dwd_org_recruit_info` 是「企业要什么人」，不是「企业给多少钱」；`dwd_scholar_talent_flag` 只有院士标志。

### 2.4 算路 / SQL

本件零 SQL，读 `code/_snapshots21/zero_source_probe_20261022.json` 与 `code/_snapshots21/talent22_probe_20261022.json`。算路：

1. `information_schema.columns` 按 `salary|wage|compensation|payroll|remuneration` 匹配 → 0 列。
2. 按 `cost|income|expense|fee` 匹配 → 37 列 / 7 表，逐列判语义。
3. 判语义：36 列 `core_biz_*` 是企业分部财务（含 3 组备份表），1 列 `layout_cost` 是期刊排版费。
4. 查 `dwd_org_recruit_info` 列清单 → 8 列，无薪资。
5. 查 `stock_finance` → 40,239 行、972 家、研发费用非空 19,695、员工数 0。
6. 查 `annual_financial` → 90,926 行、员工数非空 3,184、营收 2,193、研发人员 0。
7. 结论：不落成本分，只落证据与「企业人均研发投入」的可算性说明。

### 2.5 清洗规则

本件无个人金额数据可清洗，仅做语义甄别：

- `core_biz_cost` 是「主营业务成本」，属企业损益表科目，与人才成本无关。
- `core_biz_cost_gr` 是同比增速，`core_biz_cost_prop` 是占比，都不是金额。
- 三组 `_bak_20260911` 是备份表，列与主表重复；统计 37 列时已计入，去重后实际口径只有 19 个不同列名。
- `layout_cost` 是期刊向作者收取的排版费，`varchar(15)`，连数值类型都不是。
- `stock_finance.rd` 是企业研发费用，含材料/设备/人员，不能拆出「引进一个人」的部分。
- `annual_financial.employees` 只有 3,184 家非空，占 90,926 行的 3.50%，做人均时分母严重缺失。
- 招聘记录 `hiring_number` 是计划招聘人数，不是已入职人数，更不是成本。

## 五、王惠方法对照与选用建议

### 5.1 王惠原方法还原

王惠系方法在本指标无实现。可追溯做法是「一案一算」：按人才层次、来源国、家庭情况，由人事部门逐项报价（年薪、安家、启动费、猎头），形成个案预算。样本小，但真实。

### 5.2 新方法概述

本文无新方法。最小可行方案是「薪酬调研 + 补贴台账」：用第三方薪酬报告给分位数，用人才补贴申领明细校准安家费，用招聘费用台账校准猎头费。三步都需要外部数据，不是库内能变的。

### 5.3 逐维对照表

| 维度 | 王惠方法 | 本文现状 | 差异与风险 |
|---|---|---|---|
| 薪酬 | 逐人谈 | 0 字段 | 无法替代 |
| 安家 | 按政策 | 只有政策文本 | 无对象级金额 |
| 猎头 | 合同 | 0 字段 | 无法替代 |
| 机会成本 | 个案评估 | 0 字段 | 无法替代 |
| 精度 | 个案 | 无 | 不可达 |

### 5.4 选用建议与理由

建议把 UI 从「个人成本测算」改为「企业研发投入参考」：用 `stock_finance.rd` 与 `annual_financial.employees` 做企业人均研发费用，明确标注「企业口径、年度流量、非个人引进成本」。若业务坚持要个人成本，只能走「一案一算」+ 外部薪酬数据，不在本指标范围内。

理由：因变量不存在，任何自动成本分都会误导预算。企业人均研发费用可作为「区域创新投入」的参考，但不能用作「引进报价」。
