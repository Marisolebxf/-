判「部分支持」的四条实测依据：

1. **图是真的，规模够跑链接预测**。≤2020 窗口内 39,244 篇论文、34,969 个机构串、37,702 个候选署名对，按「≥2 篇」筛选后得到 7,742 个节点、7,736 条边，密度 0.00025816、平均度 1.9985、巨型分量 4,095 个节点（52.89%）。这个规模不需要近似算法，Personalized PageRank 在全图上 142 秒跑完。
2. **评估是离线可复现的**。用 2021—2026 新出现的 5,801 条机构对作测试正样本，抽 2,000 条正样本 + 200,000 条随机负样本算 AUC：PPR 0.7666、Common Neighbors 0.5517、Jaccard 0.5516、Adamic-Adar 0.5517、Resource Allocation 0.5517。五个分数不是手填的，是同一份候选集上算出来的。
3. **「用户查询行为/兴趣偏好」一路完全没有**。需求点的原文是「基于用户查询行为与兴趣偏好，推荐文献、研究项目、技术方案」。gkx 里没有任何日志表（无曝光、无点击、无查询串），也没有「文献—用户」「项目—用户」「方案—用户」的交互矩阵。这不是样本少，是对象不存在。
4. **推荐对象只剩「机构/专家」一类**。可推荐的边只有「机构—机构共著」与「学者—机构任职」两种，文献、项目、技术方案三类对象在库内没有可对齐的 ID。所以本指标交付的是「图谱关系推荐」，不是需求原文的「个性化内容推荐」。

## 摘要

本指标在真实机构合著网上做链路预测，回答「哪两个机构未来可能合作」。训练图取 ≤2020 的 39,244 篇论文，7,742 个节点、7,736 条边；测试集取 2021—2026 新出现的 5,801 条机构对。

五个打分器的 AUC：PPR 0.7666 明显领先，其余四个（CN 0.5517、Jaccard 0.5516、AA 0.5517、RA 0.5517）几乎完全一样。这不是巧合——四种局部相似度在稀疏图（平均度 1.9985、80.40% 的边权重为 1）上高度相关，二跳邻居携带的信息量极少，换公式不换结果。PPR 之所以高，是因为它用了全局随机游走，能把「远端但结构上接近」的节点排上来。

Top-10 精度很低：AA 的 P@10 是 0.0205、R@10 是 0.0512；PPR 的 P@10 是 0.0258、R@10 是 0.0572。源点命中率（Top-10 里至少命中 1 条真实新边）AA 12%、PPR 14%。这四个数说明：模型能粗排，不能精排；Top-10 里平均只有 0.2—0.3 条是真的。

四个点名案例的推荐结果可读：广州中医药大学第一附属医院（度 78、343 篇）的 Top-10 里 4 条在测试期真的出现了，推荐对象集中在广州/深圳的医院与医科大学；广东电网电力科学研究院的 Top-10 以电网系统内的科研院所为主（深圳供电局、中国电科院、国网上海电科院），这个推荐「看着像对的」，但 Top-10 里 0 条在测试期出现——它反映的是「结构上接近」，不是「即将合作」。

### 1.2 口径定义

需求原文是「基于用户查询行为与兴趣偏好，向用户推荐文献、研究项目、技术方案」。这句话包含三个对象（用户、物品、交互），三者缺一不可。gkx 里三者都不完整：

- **用户**：没有账号体系，没有用户 ID，只有学者与机构；
- **物品**：文献有（中文论文），研究项目有表但无参与方，技术方案没有；
- **交互**：没有曝光、点击、收藏、下载任何一种行为日志。

所以本批把任务重定义为「**机构—机构的链接预测**」：给定训练期的合著图，预测测试期会出现哪些新的合著边。这个重定义保留了「推荐」的核心（给一对节点打分、排序、取 Top-K），但把「用户」换成了「机构」、「物品」换成了「潜在合作者」、「交互」换成了「共著关系」。

重定义之后，评估方式也随之改变：不能用 CTR/NDCG（没有曝光日志），只能用 AUC 与 P@K（有正负样本）。这一点必须写在发布口径里，否则读者会把 AUC 0.7666 误读成「推荐准确率 77%」。

### 1.3 计算公式与本批实现式

五个打分器的定义（$N(u)$ 是 $u$ 的邻居集，$w$ 是边权）：

共同邻居（Common Neighbors）：

$$\text{CN}(u,v)=|N(u)\cap N(v)|$$

Jaccard：

$$\text{Jac}(u,v)=\frac{|N(u)\cap N(v)|}{|N(u)\cup N(v)|}$$

Adamic-Adar：

$$\text{AA}(u,v)=\sum_{z\in N(u)\cap N(v)}\frac{1}{\log |N(z)|}$$

Resource Allocation：

$$\text{RA}(u,v)=\sum_{z\in N(u)\cap N(v)}\frac{1}{|N(z)|}$$

Personalized PageRank（以 $u$ 为源点的随机游走稳态分布）：

$$\pi=(1-\alpha)\,e_u+\alpha P^{\top}\pi,\qquad \alpha=0.85$$

其中 $e_u$ 是源点指示向量，$P$ 是行归一化的邻接矩阵。$\pi_v$ 即 $u\to v$ 的推荐分。

评估指标：

$$\text{AUC}=\frac{1}{|P||N|}\sum_{p\in P}\sum_{n\in N}\mathbb{1}\left[s(p)>s(n)\right]$$

$$\text{P@}K=\frac{1}{|S|}\sum_{s\in S}\frac{|\text{Top}K(s)\cap E_{\text{test}}|}{K}$$

$P$ 是正样本（测试期新边），$N$ 是负样本（随机非边），$S$ 是参与评估的源点集。

## 二、计算过程

### 2.1 语料切分与训练图构造

100,900 篇中文论文按 `year` 切成两段：≤2020 的 39,244 篇建训练图，2021—2026 的 61,656 篇做测试语料。这个切分是时间切分，不是随机切分——随机切分会让训练图里出现「未来」的边，AUC 会虚高。

训练图的构造：从 39,244 篇论文的 `author_info_list` 抽机构串，得到 34,969 个不同机构串、37,702 个候选署名对；按「窗口内 ≥2 篇」筛节点，保留 7,742 个节点；边只在两端都入图时保留，得到 7,736 条。孤立点 2,312 个（29.86%）说明有近三成节点在窗口内只发过 2 篇且没有合作者——它们是「入图但不连边」的节点，会让 PPR 的随机游走在这里泄漏概率质量。

图是加权无向图，边权 = 共著篇数，均值 1.2967，单篇边 6,221 条（80.40%）。这个权重分布意味着大部分边是「一次性合作」，加权与不加权对排序的影响不大——这也是后面四种局部相似度分数几乎相同的原因之一。

### 2.2 测试集与负样本

测试集取 2021—2026 新出现的 5,801 条机构对（训练图里不存在的边），这是「真实发生的未来合作」。正样本从 5,801 条里随机抽 2,000 条（seed 固定），负样本从「训练图里不存在的机构对」里随机抽 200,000 条。

负样本的抽法是「随机非边」，不是「难负样本」。这个选择会让 AUC 偏乐观：随机非边里大量是「两个完全无关的机构」（比如广州的中医院与西安的电子科大），模型很容易把它们排到后面；真实业务里的候选集是「二跳邻居」，相似度分布更接近正样本。§四 把这个偏差列为可量化缺口。

### 2.3 候选集生成与源点筛选

推荐不能在全图 7,742² 对上算，必须先做候选集。本批用「2 跳邻居」生成候选：对源点 $u$，取 $N(N(u))$ 去掉 $u$ 自己与已有邻居，得到候选集。

不是每个源点都有候选：有的节点邻居全是叶子，二跳集为空；有的节点在测试期没有任何新边，评估时无从命中。实测 200 个源点里 151 个有非空候选集（`sources_evaluated = 151`），其余 49 个的 P@10 记 0 但不进分母。这个 151 是「有效评估源点数」，不是「全部节点数」。

### 2.4 五种打分器的实现

CN、Jaccard、AA、RA 都直接在二跳候选集上算：先取 $N(u)\cap N(v)$，再按各自公式聚合。四种算法共用一次邻居交集，所以速度几乎一样，2,000 个正样本 + 200,000 个负样本的打分在秒级完成。

PPR 用幂迭代：从源点 $u$ 出发，按 $\alpha=0.85$ 做 100 轮随机游走，取稳态分布作为分数。200 个源点、每个源点一次全图迭代，总耗时 142 秒——这是本指标 158 秒总耗时的主要部分。PPR 的分数不是「邻居交集」的函数，而是「全局可达性」的函数，这解释了它为什么比局部指标高 0.21 个 AUC。

### 2.5 AUC 的计算与四个局部指标的退化

AUC 按「正样本分数 > 负样本分数」的比例算，正样本 2,000 条、负样本 200,000 条，共 4 亿次比较。为了不爆内存，实现上先对负样本分数排序，再用二分找每条正样本的排名位置，复杂度 $O((|P|+|N|)\log|N|)$。

结果：PPR 0.7666、CN 0.5517、Jaccard 0.5516、AA 0.5517、RA 0.5517。后四个的差异在 0.0001 量级，等于没有差异。原因是这张图太稀：平均度 1.9985，两个节点的共同邻居数大多是 0 或 1；当 $|N(u)\cap N(v)|=1$ 时，CN 恒为 1、Jaccard 恒为 $1/|N(u)\cup N(v)|$、AA 恒为 $1/\log|N(z)|$、RA 恒为 $1/|N(z)|$，四者的排序几乎完全一致。换句话说，**在稀疏图上换局部相似度公式是无效优化**。

AUC 0.5517 只比随机（0.5）高 0.05，说明局部指标几乎没有预测力。这不是实现问题：换成 Jaccard 或 RA 结果一样，说明信息本身不在二跳结构里。

### 2.6 Top-10 精度与源点命中率

AUC 是全局排序指标，P@10 是头部精度指标，两者可以背离。实测 AA 的 P@10 = 0.0205、R@10 = 0.0512；PPR 的 P@10 = 0.0258、R@10 = 0.0572。P@10 = 0.0205 的含义是「平均每个源点的 Top-10 里只有 0.205 条是真实新边」。

源点命中率更能说明问题的分布：AA 有 12% 的源点在 Top-10 里至少命中 1 条，PPR 是 14%。也就是说 86%—88% 的源点，Top-10 推荐全是「没发生」的。这个数看起来很差，但要注意基准：如果一个源点在测试期只有 1—2 条新边，而候选集有 200—300 个，随机猜中的概率是 0.3%—1%，模型做到 2% 已经是随机的 2—7 倍。

| 无「技术方案」表 | 方案推荐不可做 | 库内无此对象 | 需方案库 |
| 负样本随机抽取 | AUC 偏乐观 | 200,000 随机非边 | 需难负样本挖掘 |
| 测试期采集变密 | 新边被高估 | 2024 年 32,379 篇 | 需按采集批次校正 |

### 四.2 结构性缺口（扩量救不了）

1. **没有「用户」这个实体**。需求要的是「向用户推荐」，库内没有用户 ID、没有会话、没有查询串。这不是日志量不够，是产品形态里没有这个对象。任何「个性化」的说法在这份数据上都不成立。
2. **没有三类物品的交互矩阵**。文献有表、项目有表、技术方案无表，但三者都没有「谁看过/谁用过」的字段。没有交互，就没有协同过滤的输入。
3. **图本身碎**。2,805 个连通分量、2,312 个孤立点，跨分量的对无法预测。这不是样本量问题，是合作网络的真实形态。
4. **时间切分与采集强度耦合**。测试期论文量是训练期的 1.57 倍，新边里有采集变密的贡献，无法与「合作真的变多」分离。

### 四.3 本批不采用的数据面

### 四.4 缺口对判档的影响

「完全转换支持」要求「有真实关系图 + 可评估的推荐目标」。本指标有图、有评估，但推荐对象被砍到只剩机构，个性化维度完全缺失。这不是「转换后即得」，而是「转换后只剩一个子任务」。

判「部分支持」的实质是：**能回答「哪两个机构可能合作」，不能回答「该给这个用户推什么」**。

## 五、结果与解读

### 五.1 模型能读出什么

第一，全局指标（PPR）显著优于局部指标（CN/AA/RA/Jaccard）。AUC 0.7666 vs 0.5517，差 0.21。这说明在这张图上，「谁和谁可能合作」更多取决于「在整体网络中的位置」，而不是「有多少共同邻居」。

第二，局部指标在这张图上失效。四种公式的 AUC 都在 0.5517 附近，差异 0.0001。原因在 §2.5 已说明：平均度 1.9985 时共同邻居数大多是 0 或 1，四种公式退化成同一个排序。这是「数据形态决定算法上限」的典型例子。

第三，Top-10 精度低但非零。P@10 0.0205—0.0258，源点命中率 12%—14%。模型能做粗排（把 200—300 个候选压到 10 个，命中率从随机的 0.3%—1% 提到 2%），不能做精排（Top-10 里平均只有 0.2 条是真的）。

第四，效果高度依赖源点所在子图。医院圈（广州中医药大学第一附属医院）Top-10 命中 4 条，电网圈（广东电网电科院）命中 0 条。同一个模型、同一套参数，差异来自子图密度，不是模型。

### 五.2 推荐结果能不能用

如果用途是「给合作拓展部门一份候选名单，让人工去筛」，可以用：Top-10 里有一半以上是「同城同领域」的机构，人工看一眼就能判断。广州中医药大学第一附属医院的 Top-10 全是广州/深圳的医院与医科大学，广东电网电科院的 Top-10 全是电网系统内的科研院所——这些推荐「语义上合理」。

如果用途是「自动发起合作邀约」或「按推荐顺序分配资源」，不能用：P@10 只有 2%，意味着 98% 的推荐不会发生；电网圈的命中率是 0。

### 五.3 稳定性与偏差

| 检验 | 结果 | 结论 |
|---|---|---|
| 五种打分器对比 | PPR 0.7666 / 局部 0.5517 | 全局信息必要 |
| 源点命中率分布 | 12%—14% | 大多数源点无命中 |
| 点名案例 | 4 / 2 / 0 / 0 | 子图密度决定效果 |
| 负样本类型 | 随机非边 | AUC 偏乐观 |
| 时间切分 | ≤2020 / 2021—2026 | 无未来信息泄漏 |

负样本偏差是本指标最大的不确定性：如果换成「二跳难负样本」，AUC 大概率会掉到 0.6 以下。这一点无法用当前数据验证，只能标注。

### 五.4 反常识点与解释

**反常识一：四种局部相似度的 AUC 完全一样（0.5516—0.5517）。** 直觉上 AA 应该比 CN 好（它惩罚高度节点），实际没有差异。原因是图太稀：共同邻居数集中在 0 和 1，惩罚项根本没有发挥空间。这提醒一件事——算法选择要看图的密度，稀疏图上换公式是白费力气。

**反常识二：AUC 0.7666 看着不错，但 P@10 只有 0.0258。** 两个指标不矛盾：AUC 衡量「正样本排在负样本前面的概率」，P@10 衡量「头部 10 个里有多少真的」。一个模型可以整体排序很好、头部很烂——本指标就是这种情况。发布时如果只报 AUC，会严重高估可用性。

**反常识三：广东电网电科院的推荐「看着全对」，命中却是 0。** Top-10 全是电网系统内的机构，语义上非常合理，但测试期一条都没发生。这说明「结构相似」与「即将合作」是两件事：前者是网络位置的函数，后者还取决于项目、资金、人际关系。

**反常识四：医院圈的推荐命中 4/10，远高于平均。** 医院合作的特点是「同城、同专科、高频」，二跳邻居密集，模型容易命中。电网圈是「跨省、低频、项目驱动」，模型的结构信号与真实合作脱节。同一套算法在不同子图上效果差一个数量级，这是图谱推荐的常态。

### 五.5 与其它指标的联动

与 007：007 的社区划分给出「谁和谁一个圈子」，本指标的推荐给出「谁可能和谁新合作」。两者可以组合成「圈内推荐」（只在同社区内推荐），理论上能提升 P@10，但本批没做——因为 007 的图（1,094 节点）与本指标的图（7,742 节点）不是同一张，组合需要先统一节点集。

与 001/002：001 的路径搜索可以回答「这两个机构通过谁连起来」，本指标的推荐可以回答「它们该不该连」。两个指标结合能做「推荐 + 路径解释」，但同样是图口径不同的问题。

## 六、结论与发布建议

### 六.1 可用结论

1. 在 ≤2020 的 7,742 节点 / 7,736 边合著图上，PPR 的链接预测 AUC 为 0.7666，显著高于四种局部指标（0.5516—0.5517）。
2. 局部指标在该图上退化：CN、AA、RA、Jaccard 的 AUC 差异只有 0.0001。
3. Top-10 精度：AA P@10 0.0205、R@10 0.0512；PPR P@10 0.0258、R@10 0.0572；源点命中率 12% / 14%。
4. 效果高度依赖子图：医院圈点名案例 Top-10 命中 4 条，电网圈命中 0 条。
5. 需求的「用户行为/兴趣偏好」一路完全缺失，文献/项目/方案三类对象无交互数据。

### 六.2 不可用结论

1. **不能说「推荐准确率 77%」**。AUC 0.7666 是排序指标，不是准确率。
2. **不能做个性化推荐**。没有用户实体，任何「为你推荐」的说法都不成立。
3. **不能推荐文献/项目/技术方案**。三类对象没有可对齐的交互数据。
4. **不能用 AUC 推断业务收益**。负样本是随机非边，AUC 偏乐观。
5. **不能跨指标对账图规模**。本指标 7,742 节点，007 是 1,094 节点，不是同一张图。

### 六.3 发布口径建议

建议表述：「基于 ≤2020 年 39,244 篇中文论文的机构合著网（7,742 个机构、7,736 条合作边），对 2021—2026 年新增的 5,801 条合作边做链接预测：PPR 的 AUC 为 0.7666，Top-10 精度 0.0258；四种局部相似度指标（CN/AA/RA/Jaccard）的 AUC 均为 0.5517，在该稀疏图上无差异。推荐结果适用于机构合作候选名单的粗排，不适用于个性化内容推荐。」

图表脚注写三个数：训练图 7,742 节点 / 7,736 边、测试边 5,801 条、负样本 200,000 条随机非边。

## 七、王惠方法对照与选用建议

本指标王惠未定义公式（需求只给任务描述），因此不存在「照王惠口径复现」的问题，只有「算法与评估口径」的选择。三处需要说明：

| 选择 | 备选 | 为什么选它 |
|---|---|---|
| 时间切分（≤2020 / 2021+） | 随机切分 | 随机切分会让训练图含未来边，AUC 虚高 |
| PPR 作为主模型 | 只用局部指标 | 局部指标在稀疏图上退化（AUC 0.5517），PPR 高 0.21 |
| 随机负样本 | 难负样本 | 零 SQL 约束下难负样本需要额外采样，本批未做，已标注偏差 |

选用建议：**把本指标定位为「机构合作候选粗排」，不要当「推荐系统」交付**。若甲方要个性化推荐，必须先有用户与行为日志；若甲方要「合作可能性评分」，建议用 PPR + 二跳难负样本重训，并把 P@10 作为主指标（而不是 AUC）。
