## 摘要

度中心性是五个图算法指标里最容易做对、也最容易被误读的一个。做对的部分是算法：$C_D(v)=d_v/(n-1)$ 只有一行，不需要迭代、不需要随机种子、不需要收敛判据，读完边表就能出结果。被误读的部分是语义：一个医学院附属医院在共著图上度 194，只说明它跟 194 个机构一起发过论文，不说明它比一家度 12 的制造企业更重要。本件把这两件事分开写：读数在 §二，语义边界在 §四。

建图口径与已归档的 001 / 002 / 011 完全一致：节点是论文 `author_info_list` 里的**原始机构串**（不做上下级归并），边是同篇论文的共同署名（无向，边权 = 共同署名篇数），门槛是该机构在全语料出现 ≥2 篇。100,900 篇论文给出 84,320 个机构串、126,849 个候选机构对，过门槛后剩 20,436 个节点、38,208 条边。全图含 4,186 个连通分量、3,540 个孤立点（占 17.32%），最大连通片 15,223 节点、36,965 边，占全部节点的 74.49%、全部边的 96.75%。

主口径落在**巨型连通分量 P2**（15,223 节点 / 36,965 边）。理由是度中心性的分母 $(n-1)$ 依赖点集：取全图 n=20,436 时，3,540 个孤立点既不为分子贡献、又把分母抬高 25.51%，所有非零节点的读数会被系统性地压低；取 P2 则与同族 001/002/011 的图口径一致，跨件可对账。

| 读数 | 值 |
|---|---|
| 主点集 | P2 巨型连通分量 15,223 节点 / 36,965 边 |
| 最大度 / 最大度中心性 | 194 / 12.745‰ |
| 最大度节点 | 广州中医药大学第一附属医院（751 篇） |
| 平均度 / 中位度 | 4.8565 / 3 |
| 度=1 节点占比 | 20.13% |
| 基尼 / HHI | 0.51 / 2.151 |
| 前 1% / 前 10% 节点占度总量 | 11.6% / 41.5% |
| 度≥10 节点 | 1,573 个（10.33%） |
| top-100 类型构成 | 高校 69 / 院所 15 / 企业 14 / 其他 2 |
| 判档 | 完全转换支持 |

把读数放到分布上看，这是一张典型的共著网络：20.13% 的节点只连 1 个邻居，79.87% 的节点度 ≥2，29.36% 的节点度 ≥5，10.33% 的节点度 ≥10；度 ≥100 的只有 11 个（0.07%）。度分布的基尼系数 0.51 属于中等偏集中，HHI 2.151（按份额×10000 计）说明没有单一节点垄断连接。k-core 分解的最大核只有 10，即「所有节点都至少连 10 个邻居」的子图最多只能留下 22 个节点——这个数字比最大度 194 更能说明这张图的稀疏本质。

点集敏感性是本件最重要的稳定性证据。把点集换成 P3（P2 内度≥5 的诱导子图，4,469 节点），top-100 与主口径重合 87 个、Jaccard 0.7699、秩相关 0.818892；换成 P4（度≥10，1,573 节点）重合 82 个、Jaccard 0.6949、秩相关 0.744959。也就是说，**门槛越高、头部越稳，但榜尾会换人**。发布时若只给「一个榜单」而不说点集，等于把一次口径选择藏起来。

类型构成上，top-100 里高校 69 个、院所 15 个、企业 14 个、其他 2 个；而全图 15,223 个节点的构成是高校 10,235、企业 2,408、院所 1,655、其他 925。高校在头部被显著放大（占全图 67.24%，占 top-100 69%），企业被压缩（占全图 15.82%，占 top-100 14%）。这不是算法偏差，是共著行为的真实差异：高校的合著面天然更宽。

### 1.2 口径定义

度中心性衡量节点在图中**直接相连的邻居数量**相对于点集规模的比例。它是最基础的图位置指标：只数一跳邻居，不考虑邻居的重要性，也不考虑路径长短。在本件的图里，「邻居」= 与该机构至少共同署名过一篇论文的另一个机构。

这个定义有三个必须一起交代的口径选择：**点集**（分母里的 n 取谁）、**去重**（同一对机构合作多篇算一条边还是多条）、**归并**（机构串要不要合并上下级）。本件按同族基线取：点集用 P2、去重后算一条边但保留边权、不做机构归并。三条都写进 §2.2，任何一条改了读数都会变。

### 1.3 计算公式与本批实现式

标准式：

$$C_D(v)=\frac{d_v}{n-1}$$

其中 $d_v$ 是节点 $v$ 的邻居数，$n$ 是所选点集的节点数。上界 1 出现在星形图的中心，下界 0 出现在孤立点。

本批实现式（写成「千分比」是为了与正文逐字对齐）：

$$C_D^{\prime}(v)=1000\cdot\frac{d_v}{n-1}$$

在主点集 P2 上 $n=15223$，故 $C_D^{\prime}(v)=d_v/15.222$。最大度 194 对应 $194/15.222=12.745$，与产物 `results.top20[0].value` 一致。选千分比而不是百分比，是因为原值量级在 0.0001—0.013 之间，写成 `0.0131` 会与四舍五入、科学计数法纠缠；千分比让正文的 `12.745` 与 JSON 里的 `12.745` 是同一串字符。

## 二、计算过程

### 2.1 图装载与规模校验

读数不来自任何 SQL 聚合，而来自一份族级共享快照：`code/_snapshots21/graph_algo_23_20261023.json`（5.7 MB），由 `code/_build_graph_algo_23.py` 一次构建。本件脚本只做三件事：读快照、把统计块换单位、按规则排序取 top-k。这么做不是偷懒，是为了让五件的图规模只有一个来源：如果每件各自建一次图，节点门槛、去重规则、排序规范化任何一处漂移，五件的读数就无法互相印证。

装载后先校验规模。全图 20,436 节点 / 38,208 边，与已归档的 `M_SYNTH_DS_23_GRAPH_ALGO_001`、`002`、`011` 三件逐项相同；巨连通片 15,223 节点 / 36,965 边，占节点 74.49%、占边 96.75%。这两个数不是本件算出来的新事实，而是本族基线，任何一件对不上就说明缓存或建图层被动过。

校验还包含「孤立点计数」一项：3,540 个节点在全图中度为 0，占 17.32%。这 3,540 个点在 P0 上的度中心性恒为 0（分母 20,435、分子 0），它们的存在会让 P0 的中位数降到 0.098‰、p25 降到 0.049‰。把这批点混进主口径，等于用「没合作过的机构」稀释「合作过的机构」的分数，这是 P2 作为主口径的第一个理由。

第二个理由是可比性。同族 001/002/011 的主口径都在 P2 上，本件若取 P0 或 P1，同一家机构在不同件里会得到不同的度中心性，读者按件对账必然对不上。跨件一致性优先于点集「覆盖全底册」的直觉。

第三个理由在分布形态上。P2 是单一连通分量，任意两个节点之间有路径，度的含义是「在这个连通世界里连了几个」；P1 虽然剔除了孤立点，但仍含 646 个连通分量，一个 2 节点分量的度 1 与巨型分量里的度 1 不是同一件事。把两者混在一个分母下，读数会失去解释力。

### 2.2 建图口径与点集切分

建图规则写死在 `code/_collab_graph21.py`（与 001/002/011 同源），本件不重写、不参数化，只引用。规则是：对每篇论文取 `author_info_list` 的机构串集合，集合内两两连边，边权按共同署名篇数累加；节点保留出现 ≥2 篇的机构；节点与边按名称排序重建，以消除 set 迭代顺序对遍历的影响。

$$w_{uv}=\sum_{p\in P}\mathbb{1}\left[u\in A_p \wedge v\in A_p\right]$$

其中 $P$ 是 100,900 篇论文，$A_p$ 是论文 $p$ 的机构集合。单篇边（权重为 1）有 30,328 条，占全图边数的 79.38%；巨片内 29,710 条。边权均值 1.3263（全图）/ 1.3176（巨片），说明绝大多数合作只发生一次。

点集切分五档，全部落盘在快照的 `point_sets` 数组里，本件原样引用：

| 点集 | 定义 | 节点 | 边 | 分量 | 孤立点 |
|---|---|---|---|---|---|
| P0 | 全图（含孤立点） | 20,436 | 38,208 | 4,186 | 3,540 |
| P1 | 有边子图（度≥1） | 16,896 | 38,208 | 646 | 0 |
| P2 | 巨型连通分量 | 15,223 | 36,965 | 1 | 0 |
| P3 | P2 内度≥5 诱导子图 | 4,469 | 17,160 | 41 | 35 |
| P4 | P2 内度≥10 诱导子图 | 1,573 | 6,963 | 13 | 12 |

这里有处容易被误抄的地方：**P0 的分量数是 4,186，P1 是 646**。已归档的 011 在正文里把「4,186 个连通分量」同时挂在 P1 上，属于笔误——P1 剔除了 3,540 个孤立点，孤立点各自成 1 节点分量，剔除后分量数自然降到 646。本件按快照实测值写，并在 §四 披露这处与 011 的措辞差异。

### 2.3 度分布与集中度

度分布按区间落在 `buckets_giant` 里：

| 度区间 | 节点数 | 占 P2 |
|---|---|---|
| 1 | 3,064 | 20.13% |
| 2 | 3,464 | 22.76% |
| 3—5 | 5,271 | 34.63% |
| 6—10 | 2,069 | 13.59% |
| 11—20 | 922 | 6.06% |
| 21—50 | 370 | 2.43% |
| 51+ | 63 | 0.41% |

分布是右偏的：一半以上的节点度不超过 3（1 与 2 两档合计 6,528 个，占 42.88%；加上 3—5 档的下半），而尾部 63 个节点的度 ≥51。基尼系数 0.51 量化了这个偏斜：若度完全平均，基尼为 0；若全部度集中在一个节点，基尼趋近 1。0.51 意味着「度总量里约一半需要靠后 80% 的节点贡献」，与后续的集中度读数一致。

集中度按「前 k% 节点占全部度数的比例」算：前 1%（152 个节点）占 11.6%，前 10%（1,522 个节点）占 41.5%，前 100 名占 8.87%。三个数放在一起看，读者容易注意到一件事——前 100 名只占 8.87%，比前 1% 的 11.6% 还低。这不是算错，是阈值不同：前 1% 是 152 个节点，前 100 名是 100 个节点，少 52 个节点就少了 2.73 个百分点，说明第 100—152 名这一段仍然很「重」。

HHI 2.151 是另一个角度的读数（按度份额平方和 ×10000）。垄断市场的 HHI 通常 >2500，竞争性的 <1500；2.151 远低于任何垄断阈值，说明这张图不存在「一个机构连了所有人」的形态。最大度 194 对 15,223 个节点，份额 1.27%，与 HHI 的读数互相印证。

### 2.4 点集切换的敏感性

度中心性的分母随点集变，所以「同一节点在不同点集上的分数」不能直接比。本件的处理是：主口径 P2 出榜，P3/P4 只做敏感性检验，并在产物里显式给出覆盖率与秩相关。

| 检验 | P3（度≥5） | P4（度≥10） |
|---|---|---|
| 覆盖率（节点） | 21.87% | 7.7% |
| 节点数 | 4,469 | 1,573 |
| 与 P2 的秩相关 | 0.818892 | 0.744959 |
| top-100 交集 | 87 | 82 |
| top-100 Jaccard | 0.7699 | 0.6949 |
| 子图内最大读数 | 35.363‰ | 60.433‰ |

读这张表要注意两件事。第一，子图内的最大读数（35.363‰、60.433‰）**不能**拿来跟 P2 的 12.745‰ 比大小：分母从 15,222 缩到 4,468 和 1,572，同一个度 158 或 95 换算出来的千分比自然更高。第二，秩相关随门槛升高而下降（0.818892 → 0.744959），说明高门槛子图不是「主口径的抽样」，而是「另一个问题」——它问的是「在高度连接的机构之间谁连得更多」。

Jaccard 与交集一起看才有意义：P4 只有 1,573 个节点（占 7.7%），在这样的子图里 top-100 还能与主口径重合 82 个，说明头部相当稳；但反过来，主口径 top-100 里有 18 个节点在 P4 中不复存在（因为度 <10 被截掉），这 18 个位置由子图内的新面孔填补。**任何「换点集榜单不变」的说法都是错的。**

### 2.5 与其他中心性的秩相关

五个中心性在同一张图上算，秩相关矩阵直接说明它们是不是在讲同一件事：

| 对照 | Spearman | top-100 交集 | Jaccard |
|---|---|---|---|
| 度 ~ 论文数 | 0.605824 | — | — |
| 度 ~ 紧密中心性 | 0.607677 | 60 | 0.4286 |
| 度 ~ 中介中心性 | 0.813618 | 73 | 0.5748 |
| 度 ~ PageRank | 0.937701 | — | — |

度与 PageRank 的相关最高（0.937701），这在数学上是必然的：无向图上的 PageRank 就是「度的阻尼加权版」，阻尼 0.85 时两者排序几乎同构。**这意味着 009 不能当作独立信息源来宣传**，它与本件讲的是同一件事的两种算法表述。

度与紧密中心性只有 0.607677，top-100 只重合 60 个。这是本件最能说明「中心性不可互换」的一组数：一个机构可以连很多人（度高）但都在同一个圈子里（到全体平均距离并不近），也可以连的人不多但位置居中（紧密中心性高）。第 5 名「不详」（度 82、75 篇）在紧密中心性榜上排到第 5（25.945%），就是这个机制的产物。

度与论文数的相关只有 0.605824，比很多人预期的低。原因在边权与去重：一家机构发 300 篇论文，若每篇的合作者都相同，度不会增长；反之发 50 篇但每篇都换一批合作者，度会更高。**度衡量的是合作面的宽度，不是产出量**，这条要在 §四 再说一次。

### 2.6 阈值与 k-core

度数门槛是本件对外最好用的口径，因为它不需要解释「中心性」：「度≥10 的机构有 1,573 个」比「度中心性 0.006 以上」好懂得多。六档门槛的读数：

| 门槛 | 节点数 | 占 P2 |
|---|---|---|
| ≥2 | 12,159 | 79.87% |
| ≥5 | 4,469 | 29.36% |
| ≥10 | 1,573 | 10.33% |
| ≥20 | 477 | 3.13% |
| ≥50 | 66 | 0.43% |
| ≥100 | 11 | 0.07% |

度≥10 的 1,573 个节点，其度中位数 15、论文数中位数 19。这两个中位数放在一起说明一件事：进入「度≥10」这个门槛的机构，通常已经发了近 20 篇论文——**门槛在筛「合作面」，同时也在筛「产出量」**，两者在真实数据里正相关（0.605824），无法完全解耦。

k-core 分解给出另一条曲线：最大核 10，即「每个节点至少连 10 个邻居」的极大子图只剩 22 个节点；核数 ≥5 的有 1,953 个节点，≥3 的有 7,135 个。核数分布（1:3,608、2:4,480、3:3,357、4:1,825、5:1,042、6:593、7:185、8:98、9:13、10:22）比度分布更平缓，说明这张图没有「稠密核心 + 稀疏外壳」的强分层，而是逐步稀释的。

k-core 与本件的关系要说清：k-core 是**子图筛选口径**，不是中心性。一个节点在 10-core 里，不代表它度中心性高（10-core 里的节点度可能刚好 10）；反过来，度 194 的节点必然在所有 ≤10 的核里。把两者混着说，会得出「核心节点就是重要节点」的错误结论。

### 2.8 展示口径（榜单与分页）

`display_spec` 把前端要的四件事写死：入口是「图谱页节点属性面板 / 机构连接度榜单」，排序是「按度中心性降序、同分按机构名升序」，字段是 `rank / name / type / 度数 / papers / value(‰)`，分页提示是「top20 可直接展示；全量 15,223 行见快照 `nodes` 数组」。

排序规则里「同分按机构名升序」不是装饰。度数大量重复（度 1 有 3,064 个、度 2 有 3,464 个），若同分不设次序，同一份数据两次查询会给出不同榜单，前端缓存与截图对账都会出问题。本脚本用 `(-value, name)` 二元组排序，等幂。

分页提示里的「全量 15,223 行」也是口径声明：前端若只翻 top-100，读者会以为图里只有 100 个节点；若把 15,223 行全列，必须同时标注「这是巨型分量内的排序，另有 5,213 个节点不在本口径内（20,436 − 15,223）」。少标这一句，等于把口径差藏进分页里。

## 四、数据缺失情况

### 4.1 度中心性不是企业实力

12.745‰ 只说明「连了 194 个机构」，不说明「比度 12 的企业更强」。反面例子就在榜上：「不详」这个机构串度 82、75 篇论文，排第 19——它是一个**脏值**（机构字段缺失时填的占位串），把所有填「不详」的论文连成了一张巨大的假网络。这类串在 top20 里出现，说明度数只反映「填了同一个串的论文有多少」，不反映任何真实合作关系。

处理方式不是删掉它（删了会让 15,223 变成 15,222，与兄弟件对不上），而是在展示层把它标为「其他」类型并加注释。产物 `top20[18].type` 的值就是「其他」，前端应据此渲染为灰色并附 tooltip。

### 4.2 点集换了，值就变了

同一家机构在三套点集上的读数可以差一倍以上：P2 最大 12.745‰、P1 最大 11.483‰、P0 最大 9.494‰。差异全部来自分母（15,222 / 16,895 / 20,435）与零值稀释。任何一份材料里出现「度中心性 0.0127」而不写点集，都是不完整口径。

更隐蔽的是 P3/P4：子图内最大读数 35.363‰、60.433‰，是 P2 的 2.8 倍和 4.7 倍。如果有人在 P4 上算出 60.433‰ 然后拿到全公司汇报，读者会以为「最大的机构度中心性 6%」，实际那是 1,573 节点子图内的相对值。**子图读数的绝对值没有跨口径意义，只有排序意义。**

### 4.3 机构未归并

节点是论文里的原始机构串。「华南理工大学」与「华南理工大学土木与交通学院」是两个节点，「广州中医药大学」与「广州中医药大学第一附属医院」也是两个。top20 里第 1 名与第 8 名、第 2 名与第 9 名、第 12 名与第 17 名，都是同一所学校的拆分——若不拆，头部会进一步集中。

归并没有做，原因是缺机构主数据：gkx 侧没有「机构别名 / 上下级」表，`dwd_scholar` 的机构字段也未归并。用规则（如「包含关系即合并」）会引入新错误：「中山大学」与「中山大学附属第一医院」合并会把医院和本部混成一个节点。本批统一不归并，读数按原始串出。

### 4.4 业务边缺失

| 边类 | 库内承接 | 后果 |
|---|---|---|
| 供应/采购 | 无表 | 无法算供应链意义的度 |
| 企业合作 | 无表 | 无法算业务合作度 |
| 技术流向 | 无表 | 无法算技术扩散度 |
| 论文共著 | `dwd_zh_paper` | **可用**，本件唯一口径 |

三类缺口的性质是「表不存在」，不是「量不够」，补数救不了。因此本件的度只能读作**共著度**：一个机构与多少个机构一起发过论文。用专利共现顶替也不行——专利共现是「同一申请人名下多件专利共享 IPC」，衡量主题相似，不是机构互动（详见 011 §2.1 的同一条论证）。

### 4.5 度分布重尾的后果

基尼 0.51、p99 是 median 的 11.6 倍，意味着「平均度」这个统计量没有代表性。平均 4.8565 会被头部 63 个度≥51 的节点拉高，中位数 3 才是「典型机构」的度数。任何用「平均度 4.86」描述这张图的说法都不准确，应写成「中位 3、均值 4.8565、右偏」。

同理，HHI 2.151 这个读数只在「按度份额」的定义下成立，不能与产业集中度的 HHI 直接对比（后者的份额基数是市场总额，这里的基数是度总量）。跨领域搬用 HHI 会得出「这张图很竞争」的结论，而它其实只是一张稀疏图。

### 4.6 不得外推的三件事

1. **不得读作企业实力或行业地位**：度是共著宽度，与营收、专利、市占率无关；本件没有做任何加权。
2. **不得读作合作质量**：边权是共同署名篇数，一篇挂 10 个机构的论文会让 10 个机构两两相连，度与边权都不衡量合作深度。
3. **不得跨点集比较**：P0/P1/P2/P3/P4 五套读数的分母不同，绝对值不可比；可比的是各自内部的排序。

### 4.7 停用与重估条件

出现以下任一情况应重估：① 机构主数据入库、可做归并，节点数会显著下降，全部读数需重算；② 引入业务边（供应/合作/技术流）任一类，度的语义从「共著度」变为「协作度」，需重新定义口径；③ 论文语料扩量一倍以上，单篇边占比与度分布会变，基尼与 HHI 需重跑；④ 若前端要做「节点大小映射」，必须固定点集（P2）与缩放函数，否则同一张图两次渲染的节点大小不一致。

## 五、结果与解读

### 5.1 头部是谁，为什么是他们

top20 里高校 11 个、院所 5 个、企业 3 个、其他 1 个。第 1 名广州中医药大学第一附属医院（度 194、751 篇）是典型的「大学附属医院」形态：既挂高校的学科团队，又与大量临床机构、药企、地方医院合作，天然是高连接节点。第 2 名华南理工大学（度 156、334 篇）是综合性工科强校，跨学科合作面宽。

第 3 至第 7 名集中在轨道交通与电力两个产业链：广州地铁设计研究院（131）、中国能源建设集团广东省电力设计研究院（130）、南方电网科学研究院（125）、中南大学土木工程学院（121）、广东电网电力科学研究院（115）。这五个节点的共同点是「一个大型工程体系里的设计院 + 高校院系 + 电网研究院」，与 011 报告的第 1、3 大社群核心成员完全对应。

### 5.2 读数怎么用

如果要做「连接度榜单」，直接用 P2 的 top-100，按 `value` 降序、同分按名称升序。如果要做「筛选高连接机构」，门槛比中心性更好用：度≥10 的 1,573 个节点（10.33%）是一个合理的候选池，度≥20 的 477 个（3.13%）是「核心圈」。

如果要做「节点大小映射」，不要用原始度，用 $\log(1+d_v)$：度从 1 到 194 跨两个数量级，线性映射会让 99% 的节点缩成一个点。对数映射能把 6,528 个度≤2 的节点与 63 个度≥51 的节点同时塞进可视范围。

### 5.3 稳定性与互证

| 检验 | 结果 | 结论 |
|---|---|---|
| 与 001/002/011 图规模对账 | 20,436 / 38,208 / 15,223 / 36,965 全同 | 建图口径一致 |
| P3 子图秩相关 | 0.818892 | 门槛截断后排序基本保持 |
| P4 子图秩相关 | 0.744959 | 高门槛下排序明显变化 |
| 度 ~ PageRank | 0.937701 | 两者近似同一信息 |
| 度 ~ 紧密中心性 | 0.607677 | 两者是不同问题 |

### 5.4 反常识点与解释

**反常识一：度与论文数的相关只有 0.605824。** 直觉上「发得多就连得多」，实际被「合作者是否重复」稀释。一个团队常年只与固定 5 家单位合作，发 300 篇也只有 5 个邻居。

**反常识二：前 100 名占度总量 8.87%，比前 1%（152 个节点）的 11.6% 还低。** 说明第 100—152 名这一段仍然很重，榜单截断在 100 会丢掉一块实质重量。

**反常识三：最高度的节点是一家医院，不是企业。** 共著网络的头部由「临床 + 高校 + 药企」的三角结构占据，制造企业通常只与供应链上的少数伙伴合作，度自然低。

**反常识四：最大 k-core 只有 10，只剩 22 个节点。** 一张 15,223 节点的图，稠密核心小到可以手数，说明它是「稀疏连接 + 少量枢纽」而非「稠密社团」。

### 5.5 与其它指标的联动

与 007：度与紧密中心性相关 0.607677，top-100 只重合 60 个。两张榜一起看，能区分「连接面宽」与「位置居中」两类机构。

与 008：度与中介中心性相关 0.813618，top-100 重合 73 个。中介中心性榜第 2 名是「不详」（5.418%），而它在度榜只排第 19——说明这个脏值串恰好落在图的腰部，是许多跨群体最短路的中转站。这条联动本身就是「脏值如何污染图算法」的证据。

与 009：相关 0.937701，几乎同构。发布时不应把两者并列成「两个独立维度」。

## 六、结论与发布建议

### 6.1 可用结论

第一，这张图是稀疏、右偏、单巨片的机构共著网络：15,223 节点、36,965 边、平均度 4.8565、中位度 3、最大度 194、基尼 0.51。第二，度中心性在 P2 上可精确算得，最大 12.745‰，榜单可复现（同分按名称排序）。第三，点集切换会改变榜尾：P3 重合 87、P4 重合 82，秩相关 0.818892 / 0.744959。

### 6.2 发布口径（逐条写死）

| 项 | 必须写明的口径 |
|---|---|
| 点集 | P2 巨型连通分量 15,223 节点 / 36,965 边 |
| 单位 | 千分比（×1000），12.745 = 12.745‰ = 1.2745% |
| 分母 | n−1 = 15,222 |
| 边 | 仅论文共著，无权计算（边权不参与度） |
| 归并 | 未做机构上下级归并 |
| 脏值 | 「不详」等占位串按「其他」类型标注，不剔除 |

### 6.3 后续

若要把本件从「完全转换支持」推向「完全直接支持」，缺的不是算法而是结果面：需要一张物化的机构级中心性表（含点集版本号），让前端不必每次读 5.7 MB 快照。这张表可以由本件的产物直接落库，但必须带 `point_set` 与 `snapshot_version` 两列，否则点集一换就失去可比性。
