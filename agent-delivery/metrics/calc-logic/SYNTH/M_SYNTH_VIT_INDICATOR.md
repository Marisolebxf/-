## 摘要

本件是四维分（科技/产业/人才/政策）的**分项透视**：把每个维拆到正本规定的 3 个分项，逐项给出原值、标准化得分、以及「有没有进维」。它不合成、不加权、不重算，取数全部来自四个子模型产物。这样做的原因不是偷懒，而是实测发现重算会出错：用 12 分项等权重算出来的四维分，与子模型综合分最大差 23.0 分（人才维广州 100.0 对 77.0），差得不是舍入，是**分项集合与子模型叶子集合不同**。

12 个分项的实际情况是：8 个有标准化得分并进维（专利授权量、高质量论文数量、技术转化成效、高新技术企业数量、创新服务机构绩效、人才成果产出、产业创新政策数量、政策类型覆盖度）；1 个有原值但不进维（高学历人才占比，四城只有两城有值，且归一后被拉成 100 对 0）；3 个四城全缺（新产品销售收入占比、研发人员数量、政策实施效果指数）。覆盖率因此有三个数：按「有得分并进维」算是 0.6667（8/12），按「至少一城有原值」算是 0.75（9/12），按「四城全缺」算是 0.25（3/12）。三个数都对，但回答的问题不同，正文与 UI 必须写清用的是哪一个。

三个全缺分项的成因各不相同，这也是本件最值得读的部分。新产品销售收入占比是**指标码不存在**：`a77234` 在 `dwd_macro_index_data` 里 0 行，`a772*` 家族只有 6 个别的码、各 1 行，拿别的码顶替就是编数。研发人员数量是**整列空**：`dwd_org_annual_financial_info` 90,926 行里 `development_employee` 非空 0 行，这一列存在但没有一个值。政策实施效果指数是**占位值与常数**：`implementation_date`/`expire_date` 20,000 行全部是 `'0000-00-00'`，`link` 列 100% 非空，时效性算不出、可见度归一后整列无定义。**注意这里不是「所有日期都死了」**：`publish_date` 是真实日期，20,000/20,000 全有值，能算「发布至今多少个月」，但「发布多久」不等于「当前日是否落在实施窗口内」，拿它顶替实施效果就是把两个概念混成一个，故不用（该路径已连同数一起锁进 `vit_absence_20261023.json` 的 `policy_date_detail`）。三类缺口的补法完全不同（要数据源、要补采、要换字段），不能笼统写成「数据缺失」。

最后一层是口径警告。本件的 12 分项与 183 的三维结构**不是同一套叶子**：183 的产业维 D1 用「产品名称覆盖数」，本件的产业分项用「新产品销售收入占比」。两者都叫「产业创新」，但一个量产品名、一个量销售收入。所以本件的分项表可以解释四维分的来源，不能用来「校验」四维分——校验会得到 23.0 分的假差异。

| 口径要点 | 取值 |
|---|---|
| 分项总数 | 12（四维 × 3） |
| 有得分并进维 | 8（0.6667） |
| 至少一城有原值 | 9（0.75） |
| 四城全缺 | 3（0.25） |
| 维覆盖率（有得分） | 科技 1.0、产业 0.6667、人才 0.3333、政策 0.6667 |
| 重算 vs 子模型最大差 | 23.0 分（人才维广州） |
| 权重 | 本件不合成（`main=null`），`main_is_official=false` |
| 判档 | 部分支持 |

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

区域创新活力分析的「指标体系构建」页签：把四维分背后的 12 个分项逐条列出，每项给原值（带单位）、标准化得分（0—100）、以及状态标记（直接 / 代理 / 有值未进维 / 缺）。页面上的「分项明细表」「覆盖率提示条」「缺项灰显」三处交互都读本件。总指数不在此页（见 `M_SYNTH_VIT_INDEX`），四维分也不在此页重算（见 `M_SYNTH_VIT_DIM_SCORE`）。

### 1.2 为什么需要这个指标

只有四维分，读者无法判断「56.2 分」是几个分项撑起来的。分项明细承担三件事：一是**可解释性**，让读者看到人才维只剩 2 个分项、政策维只剩 2 个；二是**可核对性**，每个分项都给了原值（专利 128,478 件、高企 15,683 家、政策 879 条），甲方可以拿原始台账对；三是**缺口可见**，3 个全缺分项在表上灰显而不是消失，避免「看不见就当不存在」。第三件事最重要：如果缺项被静默删掉，四维分看起来仍然完整，读者会以为 12 个分项都在跑。

### 1.3 需求文档是否给出定义方法

给了分项清单与取数路径，没给「缺项怎么显示」。正本写明「分项叶子分别见 182/183/184/185」「本指标只汇总展示，不重算、不另选代表指标」，但没有写：① 某分项四城全缺时，是删行、留 null、还是记 0；② 某分项有值但因饱和不进维时，要不要显示原值；③ 12 个分项等权重算出来的分与子模型分不一致时，以哪个为准。本件对三条的选择是：留行并记 null（不删、不记 0）、显示原值但标「未进维」、以子模型分为准且不发布重算值。

### 1.4 类似指标权威机构构建方法可行性分析概要

| 方法 | 做法 | 在本库的可行性 |
|---|---|---|
| 分项原值 + 上游得分 | 逐项展示原值，得分取上游 | **可行**，本件主口径 |
| 12 分项等权重算 | 每维 3 个分项平均，四维再平均 | 可算，但与上游冲突（最大差 23.0 分），会产出第二套四维分 |
| 全部重算 + 替代上游 | 用重算值替掉 182—185 | **不可行**：分项集合与子模型叶子不同，替代会让四维分与总指数脱钩 |
| 缺项补 0 | 四城全缺记 0 | **禁止**：0 是「盘内最低」，缺测是「没有」，同形会误导 |
| 缺项插补 | 用同类城市均值/同比推算 | **不可行**：正本禁止用同比或指数替代，且 n=4 无插补基础 |
| 官方分项权重表 | 读现成配置 | **不可行**：gkx 无分项权重表 |

结论：本件只能做「展示层」。任何重算或插补都会引入上游没有的数，而展示层的价值恰恰在于「你看到的每个数都能追到一张表」。

## 二、计算过程

### 2.1 语义重建：12 个分项从哪来

正本把四维各拆 3 个分项，共 12 个。这 12 个分项不是本件发明的，是王惠口径在方案阶段就定下的清单：科技=专利授权量/高质量论文数量/技术转化成效；产业=高新技术企业数量/新产品销售收入占比/创新服务机构绩效；人才=研发人员数量/高学历人才占比/人才成果产出；政策=产业创新政策数量/政策类型覆盖度/政策实施效果指数。

### 2.3 为什么本件不重算：23.0 分的假差异

如果按「每维 3 个分项等权、四维再等权」重算，会得到与子模型综合分不同的一套数：

|---|---|---|---|---|
| 科技 | 72.7891 / 73.7 / −0.9109 | 65.2354 / 68.96 / −3.7246 | 19.6063 / 7.79 / 11.8163 | 0.0 / 0.0 / 0.0 |
| 产业 | 66.6888 / 77.7925 / −11.1037 | 39.2786 / 39.7686 / −0.49 | 20.8527 / 18.777 / 2.0757 | 11.4073 / 7.6049 / 3.8024 |
| 人才 | 42.06 / 56.2 / −14.14 | 100.0 / 77.0 / 23.0 | 0.43 / 7.1 / −6.67 | 0.0 / 0.0 / 0.0 |
| 政策 | 92.31 / 92.3 / 0.01 | 56.9469 / 57.0 / −0.0531 | 15.84 / 15.8 / 0.04 | 0.0 / 0.0 / 0.0 |

差最大的三处都在「分项集合不同」的地方。人才维广州重算 100.0、子模型 77.0，差 23.0：因为重算只算 D1 与 D4 两个在场分项，而 184 的 D4 内部还等权了授权专利、转移、院士等子项；产业维深圳重算 66.6888、子模型 77.7925，差 11.1037：因为 183 的 D1 用产品名覆盖数（深圳 19,714 个），本件的产业 D1 用新产品销售收入占比（null），重算相当于把深圳最强的子项扔掉了；科技维东莞重算 19.6063、子模型 7.79，差 11.8163：因为重算给了「高质量论文数量」1/3 权重（东莞 6.1224），而 182 的基础科学子维只有 1/3 权重且内部还含机构指标。

政策维几乎是巧合对上（差 0.01 / −0.0531 / 0.04 / 0.0），因为 185 恰好就是「数量 + 类型」两项等权，与本件的政策分项集合一致。这个巧合反过来说明：**只有当分项集合与子模型叶子一致时，重算才与上游相等**。其余三维都不一致，所以重算必然出错。本件因此完全不发布重算值，只把它作为「为什么不能重算」的证据放在 §2.3 与附录 B.4。

### 2.4 三个全缺分项：负证据怎么写

三个缺项都留了可复跑的探针，写在 `code/_snapshots21/vit_absence_20261023.json` 与产物 `absence_probe` 里，每条含 `target`/`table`/`condition`/`rows`/`hit`/`consequence` 六个字段：

| 分项 | 表 | 条件 | 结果 | 后果 |
|---|---|---|---:|---|
| 新产品销售收入占比 | `gkx.dwd_macro_index_data` | `index_code='a77234'` | 0 行 | 指标码不存在，不能用 `a772*` 家族别的码顶替 |
| 研发人员数量 | `gkx.dwd_org_annual_financial_info` | `COUNT(*)`、`SUM(development_employee IS NOT NULL)` | 90,926 行 / 0 行非空 | 整列空，人才数量维只剩学者存量 |
| 政策实施效果指数 | `gkx.dwd_policy_base` | 日期占位计数、`link` 非空计数 | 20,000 行零日期 / 20,000 行 link 非空 | 时效性与可见度都退化为常数 |

写负证据的意义不是「证明我们查过」，而是**锁死替代路径**。比如 `a772*` 家族还有 6 个别的码（各 1 行），如果不写「不能用别的码顶替」，下一个人很容易拿 `a77235` 之类的码算一个数出来交差；研发人员列如果只写「缺失」，下一个人可能用 `employees_number` 乘一个比例推算；政策日期如果只写「不可用」，下一个人可能把 `'0000-00-00'` 当 0 天算时效性。三条都必须写成「查了、结果是空/常数、因此不能算」，而不是「没查到」。

### 2.5 一个有值但不进维的分项：高学历饱和

高学历人才占比是本件唯一「有值但不进维」的分项：深圳 100.0、广州 97.4026、东莞与惠州 null。两城只差 2.5974 个百分点，但四市盘上的 min-max 会把它拉成 100 对 0——因为盘里只有两个值，最小值就是 0 分。184 因此判定这一项「饱和」：它不能在四市盘上区分城市，强行进维会让「2.5974 个百分点的差」变成「100 分的差」，把人才维的第二名直接锁死。

本件对这一项的处理是**显示原值、score 记 null、状态标「有值未进维」**。这三件事必须同时做：只显示原值会让读者以为它进了维；只标 null 会让读者以为没有数据；不显示原值则丢掉了「两城其实只差 2.5974 个百分点」这个关键事实。换一个盘（例如 11 城，且高学历分布不是两城独占）这一项可以恢复，但当前四市盘不行。

### 2.6 覆盖率的三个口径

| 口径 | 分子/分母 | 值 | 回答的问题 |
|---|---|---:|---|
| 有得分并进维 | 8 / 12 | 0.6667 | 有多少分项真的进了四维分 |
| 至少一城有原值 | 9 / 12 | 0.75 | 有多少分项在库里查得到数 |
| 四城全缺 | 3 / 12 | 0.25 | 有多少分项完全无源 |

三个数的差来自「高学历人才占比」：它有原值（9 里有它），但没有得分（8 里没它）。UI 上如果只显示一个覆盖率，必须显示 0.6667 并注明「另有 1 项有值未进维」；只显示 0.75 会高估可用性，只显示 0.25 会低估。

按维拆开是：科技 3/3（1.0）、产业 2/3（0.6667）、人才 1/3（0.3333）、政策 2/3（0.6667）。人才维最低不是偶然——它的三个分项里，研发人员整列空、高学历饱和，只剩人才成果产出一个在跑。这也解释了为什么人才维分（深圳 56.2、广州 77.0）对「成果产出」这一个分项如此敏感。

### 2.9 缺项与缺维的处理定式

本件不合成，但必须把规则交给下游，否则 186_1 与 VIT_INDEX 会各自发明：

1. 分项四城全缺 → 该行保留、`raw=null`、`score=null`、`enters_dim=false`，**不进分子也不进分母**，并在 `absence_probe` 写一条探针；
2. 分项有值但饱和 → `raw` 保留、`score=null`、`status=有值未进维`，**不把原值当得分**；
3. 维级整缺（本批未触发）→ 该维不进加权，下游分母收缩到在场维、`gap_dims` 记下缺的是哪一维，**不静默重归一**；
4. 任何情况下都不把 null 当 0：0 是「盘内最低」，null 是「没有」，两者在产物里必须不同形。

第 3 条与「重归一」的区别要写清：分母收缩是「用 3 维算 3 维的平均」，重归一是「把 3 维的权重按比例放大到 1」。前者保持各维等权，后者会让「只覆盖 3 维的城市」与「覆盖 4 维的城市」看起来同尺度。本件只做前者，且要求分母收缩在产物里可读（`dims_used`/`gap_dims`）。

## 四、数据缺失情况

### 4.1 新产品销售收入占比：指标码不存在

`a77234` 在 `dwd_macro_index_data` 里 0 行，这不是「本年无数据」，是**整个码不在库里**。同家族 `a772*` 只有 6 个别的码、各 1 行，说明这个指标族只被零星采了几条，没有形成年度序列。正本对这一项的定义还要求分母「区域企业主营业务收入合计」，而 `dwd_org_annual_financial_info` 90,926 行里 `main_business_revenue` 只有 2,040 行非空——即便分子有值，分母也撑不起一个占比。

两个缺口叠在一起，这一项在本库**没有任何替代路径**：换码是编数、换分母是换指标、用同比顶替是正本明令禁止的。所以记 null，并在 `absence_probe` 里锁死「不能用 `a772*` 别的码顶替」这条。

### 4.2 研发人员数量：整列空

`development_employee` 在 `dwd_org_annual_financial_info` 里存在，类型也对，但 90,926 行里非空 0 行。这是「列在、值全空」的典型形态，比「列不存在」更危险——因为 `information_schema` 查得到，写 SQL 不会报错，`SUM()` 会安静地返回 NULL。本件的探针特意写了 `COUNT(*)` 与 `SUM(... IS NOT NULL)` 两个数，就是为了把「表有 90,926 行」与「列有 0 个值」同时摆出来。

后果是人才维的「数量」子维只剩学者存量，人才成果产出的「人均」式也失去分母。两条都记在 §3.2 的代理清单里。

### 4.3 政策实施效果：日期占位 + 可见度常数

`dwd_policy_base` 20,000 行，`implementation_date` 与 `expire_date` 全部是 `'0000-00-00'`。MySQL 对 `'0000-00-00'` 直接比较会报 `Incorrect DATE value`，必须 `CAST(... AS CHAR)` 才能数，本件的探针就是这么写的。日期全占位意味着「当前日是否落在实施日与失效日之间」这一句无法求值，时效性整项不可算。

`link` 列则是另一种病：100% 非空，看起来「数据很全」，但归一后整列是常数，没有任何区分度。可见度的定义是「link 非空政策数 ÷ 政策总数」，当分子等于分母时它恒为 1，进维等于给所有城市加同一个常数。所以这一项不是「缺数据」，是「数据太齐以至于无信息」。

### 4.4 高学历饱和：2.5974 个百分点被拉成 100 分

深圳 100.0、广州 97.4026，差 2.5974 个百分点；东莞与惠州 null。四市盘 min-max 只有两个值可用，结果必然是 100 对 0。这不是归一公式的错，是**盘太小 + 覆盖太窄**的必然结果。184 判它饱和、不进维，本件继承该判断，只显示原值。

如果将来覆盖扩到四城且分布不是两城独占，这一项可以恢复；但在恢复之前，任何「人才维学历结构得分」的说法都是把 2.5974 个百分点包装成 100 分。

### 4.5 重算与子模型的 23.0 分差不是误差

见 §2.3。这里补一句方法论：很多人会直觉地认为「12 个分项平均应该等于四维分」，因为正本写了「每维 3 个分项」。但正本的 12 分项是**指标清单**，不是**加权方案**；子模型在清单之外还加了机构指标、专利转移、院士等叶子，并且对饱和项做了剔除。所以两者不相等是设计使然，强行让它们相等反而会破坏子模型的语义。

### 4.6 停用与重估条件

出现以下任一情况应重估：① `a77234` 入库且 `main_business_revenue` 覆盖率提升到可用水平（产业维恢复 3 分项）；② `development_employee` 有非空值（人才数量与人产出恢复人均口径）；③ 政策日期不再是 `'0000-00-00'` 且 `link` 不再是整列常数（政策维恢复 3 分项）；④ 高学历覆盖扩到四城且分布不饱和（人才维恢复学历结构）。四条都不满足时，本件的 12 分项只能作「可解释性附件」，不能作「校验基准」。

### 4.7 与下游的传导

本件的覆盖率会原样传给 VIT_INDEX（`leaf_coverage_share=0.6667`、`leaf_missing_names` 三项），并影响加权维完整度（0.8333）。下游不能用「补 0」把覆盖率抬到 1.0，也不能用「只用有值的分项重算」替代四维分——后者就是 §2.3 的 23.0 分假差异。正确做法是把缺口写在分数旁边，让读者自己判断置信带。

## 五、王惠方法对照

### 5.1 王惠方法在原指标族里的位置

王惠口径在本族承担「分项清单、四维定维、子模型出口」这一支。正本对本件的原话是「分项叶子分别见 182/183/184/185」「本指标只汇总展示，不重算、不另选代表指标」。这句话把本件钉在展示层：它既不是评价模型（不加权），也不是校验工具（不重算），而是**可解释性附件**。

### 5.2 本件与其结构上的相似与差异

相似处有三点：分项清单相同（12 项，四维各 3）；每项都给原值与得分；缺项不补 0。差异有两点：一是本件把「有值但饱和」单列为一类状态（`有值未进维`），原文只有「有/缺」两态；二是本件显式给出「重算会差 23.0 分」的证据，原文没有这一条，因为原文假设分项集合与子模型叶子一致。

### 5.3 选用建议

对外发布用本件主口径（展示层）：分项表 + 三口径覆盖率 + 缺项探针。方法学章节可以引用 §2.3 的重算对照，用来说明「为什么不能拿分项平均替四维分」；不建议发布任何重算值，也不建议把 12 分项当成 12 个独立指标对外（它们不是等权关系）。任何发布都必须带两句限定：8 个分项进维、3 个全缺、1 个有值未进维；四维分以子模型为准。
