## 摘要

紧密中心性（closeness）的直觉很朴素：一个节点离所有人越近，它越「居中」。数学上它是「到其余节点的平均最短距离」的倒数，因此它天然带一个前提——**距离必须有定义**。在一个有 4,186 个连通分量的图里，两个不同分量的节点之间距离是无穷，平均值无意义。这不是实现细节，而是这个指标能不能用的问题。

本件的处理是把点集锁死在**巨型连通分量 P2**（15,223 节点 / 36,965 边）。在 P2 内所有节点两两可达，$r_v=n$，修正因子为 1，读数退化为「平均距离的倒数」，可以逐条解释。P0/P1 的读数照样算出来放在产物里，但只用于标口径差，不作主口径。

| 读数 | 值 |
|---|---|
| 主点集 | P2 巨型连通分量 15,223 节点 / 36,965 边 |
| 最大紧密中心性 | 26.802%（华南理工大学，度 156、334 篇） |
| 最大值的平均距离 | 3.731 跳 |
| 中位数 | 17.747%（5.635 跳） |
| 均值 | 17.587%（5.686 跳） |
| 最小 | 7.134% |
| p99 | 22.946% |
| 平均距离 <10 跳的节点 | 15,153 个（99.54%） |
| 零值节点（P2 内） | 0 个 |
| 判档 | 完全转换支持 |

把 15,223 个节点的读数摊开看，分布比度中心性窄得多：min 7.134%、p25 16.019%、median 17.747%、mean 17.587%、p75 19.319%、p90 20.652%、p99 22.946%、max 26.802%。均值与中位数几乎相等（差 0.16 个百分点），说明这不是重尾分布，而是集中在 16%—20% 的窄带里。原因在定义：平均距离是「对全体取平均」，会被图的连通结构摊平——P2 里最居中的节点平均 3.731 跳，最边缘的节点平均也只有 14.017 跳，全部读数只能落在这条窄带上。

这件事对展示有直接影响：**紧密中心性不适合做「差异放大」的颜色映射**。若把 7.134%—26.802% 线性映射到红蓝，95% 的节点会落在中间两档，看不出结构。正确做法是分位数着色（每 20% 一档），或者干脆只展示 top-100 榜单。

稳定性方面，换点集的影响比度中心性小得多：P3 子图（4,469 节点）与主口径秩相关 0.996947、top-100 重合 98 个；P4 子图（1,573 节点）秩相关 0.986691、重合 92 个。这与度中心性形成对照（0.818892 / 0.744959）——**closeness 的排序对点集截断更稳健**，因为它看的是全局距离，不是局部邻居数。

### 1.2 口径定义

紧密中心性衡量节点到**其余所有可达节点**的平均最短距离的倒数。距离越短，读数越大。在本件里，「距离」是共著跳数：两家机构若共同署名过一篇论文，距离为 1；若需要经过一个中间机构，距离为 2，依此类推。

三个必须一起交代的口径选择与 006 相同：点集（分母与可达集取谁）、去重（多次合作算一条边）、归并（机构串是否合并）。本件全部沿用族基线，唯一的额外选择是**是否做可达性修正**——这一步在 P2 上不产生影响（因为整片连通），但在 P0/P1 上决定了读数有没有意义。

### 1.3 计算公式与本批实现式

标准式（Bavelas）：

$$C_C(v)=\frac{1}{\sum_{u\neq v}d(v,u)}$$

本批实现式（networkx `wf_improved`，对不可达节点做分量修正）：

$$C_C(v)=\frac{r_v-1}{n-1}\cdot\frac{r_v-1}{\sum_{u\in R(v)}d(v,u)}$$

其中 $R(v)$ 是 $v$ 在自身连通分量内可达的节点集合，$r_v=|R(v)|$，$n$ 是所选点集的节点数，$d(v,u)$ 是跳数。当 $r_v=n$（P2 内）时，前一个因子为 1，公式退化为 $C_C(v)=(n-1)/\sum d(v,u)$，于是「平均距离 = 1/C_C」这条读法成立。

正文以百分比报（×100）：26.802 表示 26.802%，即 0.26802，对应平均距离 $1/0.26802=3.731$ 跳。这个换算在前端 tooltip 里应当直接给出，否则读者拿 26.802% 无法形成「几跳」的直觉。

## 二、计算过程

### 2.1 图装载与规模校验

与 006 一样，本件不连库、不建图，只读族级共享快照 `code/_snapshots21/graph_algo_23_20261023.json`。快照里每个 P2 节点带 11 个字段：名称、类型、度、论文数、四个中心性（度/紧密/中介/PageRank）、加权 PageRank、有向 PageRank、社群标号。本件只取 `c_close` 一列。

装载后校验三件事：全图 20,436 节点 / 38,208 边、巨片 15,223 节点 / 36,965 边、孤立点 3,540 个。三项与 001/002/011 及本批 006 逐项相同。如果这一层对不上，后面的读数全部作废——因为紧密中心性的分母就是节点数。

校验里还要看一个本件特有的量：**P2 内零值节点数**。产物里 `n_zero_closeness_giant = 0`，这是必然的：P2 是连通分量，任何节点到任何节点都有有限距离，$C_C>0$。而 P0 有 3,540 个零值（占 17.32%），P3 有 35 个、P4 有 12 个——这些都是「诱导子图把节点切成了孤点」造成的，不是算法出错。零值出现在哪个点集，必须在正文里说清。

### 2.2 全源 BFS 的实现与耗时

closeness 没有 Brandes 那样的 $O(VE)$ 加速，只能对每个源点跑一次 BFS。P2 有 15,223 个节点、36,965 条边，一次 BFS 的复杂度是 $O(V+E)$，全源就是 $15{,}223\times(15{,}223+36{,}965)\approx 8.0\times10^{8}$ 次邻接访问。快照构建日志里这一段耗时 96.1 秒（从 224.9 秒到 321.0 秒），是五件中最费时的一步之一。

P0 的全源 BFS 耗时 113.2 秒（20,436 个源）、P1 耗时 109.2 秒（16,896 个源）。三组加起来约 5 分钟。这个量级说明一件事：**在 15,223 个节点上做精确 closeness 是可行的，但不可高频重算**。若前端要「按筛选条件实时算 closeness」，必须改成抽样近似（$k$ 个源），并把 $k$ 与误差写进 UI。

BFS 用 Python 的 `collections.deque` 实现，距离用列表而非字典（节点先编号后遍历）。这一步是性能关键：字典存距离在 15,223 节点上会让常数因子翻倍。快照构建器里节点按名称排序后编号，保证同一份数据每次跑出同样的遍历顺序。

### 2.3 分量与可达性

P0 有 4,186 个连通分量，其中 3,540 个是孤立点、444 个是 2 节点分量、180 个是 3—5 节点分量、21 个是 6—20 节点分量，只有 1 个是 101+（即 P2 的 15,223）。这个分布说明：**除了巨片，其余全是碎片**，第二大分量只有 14 个节点。

在这样一个图里谈「到全体的平均距离」几乎必然误导。假设某机构在一个 14 节点的分量里，它的 $r_v=14$，`wf_improved` 会把它的读数修正为 $(13/20435)\times(13/\sum d)$，数值极小但非零——看起来像「它离所有人都很远」，实际是「它所在的分量很小，跟别人根本不连通」。这就是为什么主口径必须锁 P2。

P1（16,896 节点 / 646 个分量）的情况稍好但仍然不可比：646 个分量意味着仍有大量节点只能在自己的小块里算距离。P1 的读数（median 15.697%、max 24.148%）与 P2（median 17.747%、max 26.802%）整体低一档，原因就是这个修正因子。

### 2.4 距离分层

把 closeness 换回跳数（$1/C_C$）后分档，读数才可读：

| 平均距离 | 节点数 | 占 P2 |
|---|---|---|
| ≥33.3 跳 | 0 | 0.0% |
| 25.0—33.3 跳 | 0 | 0.0% |
| 20.0—25.0 跳 | 0 | 0.0% |
| 10.0—20.0 跳 | 70 | 0.46% |

这张表是本件最值得记住的一张：**没有一个节点的平均距离超过 20 跳，99.54% 在 10 跳以内**。这就是「小世界」的量化表达。最边缘的节点（closeness 7.134%）平均距离 14.017 跳，仍在 20 跳以内。

## 四、数据缺失情况

### 4.1 只在连通分量内成立

这是本件最硬的一条边界。closeness 的定义依赖「可达」，跨分量的距离是无穷，平均值无定义。P0 有 4,186 个分量、P1 有 646 个，任何在这两个点集上报出的 closeness 都是「修正后的相对值」，不能读成「到全体的平均距离」。

`wf_improved` 的修正因子 $(r_v-1)/(n-1)$ 只是把不可达的情况压缩成一个小于 1 的系数，它不能让读数恢复「全局平均距离」的语义。读者若不知道这一点，会把「分量小」误读成「位置偏远」。

### 4.2 平均距离的读法只在 P2 成立

「平均距离 = 1/C_C」这条换算只在 $r_v=n$ 时成立，也就是只在 P2 内成立。在 P0/P1 上做同样换算会得到偏大的跳数（因为修正因子 <1，$C_C$ 被压低，$1/C_C$ 被抬高）。本件在产物里只对 P2 的 top20 给出 `implied_mean_distance`，就是这个原因。

前端若要做「跳数」展示，必须调 `implied_mean_distance` 字段，而不是自己拿百分比取倒数。后者在 P3/P4 上会错得更离谱。

### 4.3 机构未归并

与 006 相同：节点是原始机构串。「华南理工大学」与「华南理工大学土木与交通学院」是两个节点，两者都进了 top20（第 1 与第 17），说明拆分对 closeness 的影响是双向的——母体因为合作面更宽而更近，院系因为只在自己的圈子里而稍远。

归并需要机构主数据（别名、上下级），gkx 侧没有。用字符串包含规则合并会引入新错误（「中山大学」与「中山大学附属第一医院」不是同一类实体）。本批不做，读数按原始串出。

### 4.4 业务边缺失

| 边类 | 库内承接 | 后果 |
|---|---|---|
| 供应/采购 | 无表 | 无法算供应链意义的「近」 |
| 企业合作 | 无表 | 无法算业务协作距离 |
| 技术流向 | 无表 | 无法算技术扩散距离 |
| 论文共著 | `dwd_zh_paper` | **可用**，本件唯一口径 |

三类缺口是「表不存在」，补数救不了。因此本件的「近」只能读作**共著意义上的近**：两个机构通过若干次共同署名被连起来。业务上「合作紧密」不等于「共著频繁」，这两件事在本件里不可互换。

### 4.5 分布过窄的展示后果

P2 的读数集中在 16%—20%（p25 16.019、p75 19.319），全距只有 7.134—26.802。这意味着：

1. 线性色阶会把 95% 的节点染成同一个颜色；
2. 「中心性 ≥25%」这类阈值只能筛出极少数节点（top20 全部 ≥24.854）；
3. 榜单截断在 100 名之外的部分几乎没有解释力。

处理办法是分位数着色 + 榜单制，而不是阈值筛选。这一点写进 §2.8 的展示口径。

### 4.6 不得外推的三件事

1. **不得读作机构影响力**：closeness 是结构位置，与论文质量、经费、营收无关。
2. **不得跨点集比较**：P0/P1/P2/P3/P4 的分母不同，绝对值不可比；P3/P4 的读数整体上移是分母效应。
3. **不得读作「合作效率高」**：平均距离短说明网络位置居中，不说明合作产出好；一家从不合作的机构根本没有 closeness。

### 4.7 停用与重估条件

出现以下任一情况应重估：① 机构主数据入库、可做归并，节点数与距离结构都会变；② 引入业务边，距离语义改写；③ 语料扩量到十万篇以上，BFS 全源耗时线性增长，需改抽样并重标误差；④ 若前端要求「按筛选条件实时算 closeness」，必须换成 $k$ 源抽样，并给出 $k$ 与近似误差。

## 五、结果与解读

### 5.1 头部是谁

top20 的构成：高校 13 个、院所 5 个、企业 4 个（按类型字段计，部分为混合）。第 1 名华南理工大学（26.802%、3.731 跳、度 156）与第 2 名广州地铁设计研究院（26.533%、3.769 跳、度 131）差距只有 0.269 个百分点——在 3.7 跳这个量级上，差 0.03 跳。

第 3 至第 10 名依次是广东电网电力科学研究院（26.331%）、中国能源建设集团广东省电力设计研究院（26.173%）、不详（25.945%）、广东工业大学（25.88%）、中山大学（25.708%）、广州地铁集团（25.571%）、华南理工大学电力学院（25.446%）、南方电网科学研究院（25.37%）。这一段的特点很清楚：**电力与轨道交通两个体系占了 6 席**，与 011 报告的第 1、3 大社群核心成员高度重合。

值得注意的是「不详」（第 5 名、25.945%、度 82）。它是机构字段缺失时的占位串，把大量不相关论文连成一张假网络，因而获得了极高的中心性。这类脏值在 006 的度榜只排第 19，在 closeness 榜却升到第 5——**说明 closeness 对「跨领域的假连接」更敏感**，因为假连接直接缩短了到全体的距离。

### 5.2 读数怎么用

第一，做榜单：直接取 P2 top-100，按 `value` 降序。第二，做「中心性筛选」：不要用绝对阈值，用分位数（如 top 5% = 排名 ≤761）。第三，做 tooltip：百分比 + 跳数一起给，跳数取 `implied_mean_distance`。

第四，做布局加权：closeness 适合当「向心度」用于力导向布局的中心引力，但不适合当节点大小（节点大小应该用度或论文数，因为 closeness 的差异太小，视觉上分不出来）。

### 5.4 反常识点与解释

**反常识一：closeness 的分布比度中心性窄得多。** 度从 1 跨到 194（两个数量级），closeness 只从 7.134% 到 26.802%（3.76 倍）。原因在最短路的度量性质：绕路的代价是加法，不是乘法。

**反常识二：换点集几乎不改排序（0.996947），却整体抬高读数。** 截断低度节点等于保留骨架，排序结构不动；但分母变小，所有绝对值上移。这两件事同时发生，容易被误读成「节点变近了」。

**反常识三：脏值「不详」在 closeness 榜排第 5，比度榜高 14 位。** 假连接（把不相关论文连成一片）对「平均距离」的缩短效果，比对「邻居数」的增加效果更显著。

**反常识四：99.54% 的节点平均距离 <10 跳，最远也只有 14.017 跳。** 一张 15,223 节点的图，直径只有 14 跳——这是共著网络「少数枢纽 + 大批短链」结构的直接结果。

第一，P2 内 closeness 可精确算得，最大 26.802%（3.731 跳），中位 17.747%（5.635 跳）。第二，这张图是小世界：99.54% 的节点平均距离 <10 跳，最远 14.017 跳。第三，closeness 的排序对点集截断稳健（0.996947 / 0.986691），但绝对值不可跨点集比较。

### 6.2 发布口径（逐条写死）

| 项 | 必须写明的口径 |

| 归并 | 未做机构上下级归并 |
