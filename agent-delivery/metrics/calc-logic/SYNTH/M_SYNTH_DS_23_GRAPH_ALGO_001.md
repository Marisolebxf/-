## 摘要

本指标在真实机构合著网上实现并验证六种路径搜索算法，回答「从 A 机构到 B 机构怎么走」。图是 20,436 个节点、38,208 条边的无向加权图（边权 = 共著篇数），巨型分量 15,223 个节点、36,965 条边。

200 对随机起讫（巨型分量内、跳数 ≥3、固定种子）上的结果：六种算法全部成功；BFS、Dijkstra、A* 的最短跳数 200/200 对一致；Bellman-Ford 在 20 对上与 BFS 一致 20/20。

跳数分布：500 对抽样的均值 5.836、中位数 6、P90 8、最大 13。这个数很小——一个 1.5 万节点的网络，任意两点平均 5.8 跳可达，说明图里有超级枢纽（最大度 194）把远端的机构连了起来。

性能差异很大：BFS 0.065 ms/次、Dijkstra（无权，带目标早停）0.059 ms/次、A*（ALT）10.949 ms/次、DFS 25.479 ms/次、加权 Dijkstra 30.926 ms/次、Bellman-Ford 50.531 ms/次。A* 比无权 Dijkstra 慢 185 倍，原因是无权 Dijkstra 命中目标即停，而 A* 每次扩展要做 8 个地标的启发式计算——在平均 6 跳的短路径上，启发式的开销远大于它省下的扩展。

DFS 的跳数均值比最短路径多 634.2 跳（最大 1,382），这是 DFS 的定义决定的：它只保证可达，不保证最短。这个数不是缺陷，是提醒——DFS 只能用来判连通，不能用来展示路径。

### 1.2 口径定义

需求写的是「路径搜索：BFS / DFS / Dijkstra / Bellman-Ford / A*」。这是五个算法名，不是口径。落地时必须回答三个问题：

**图是什么？** 本批定为「机构合著图」：节点是论文 `author_info_list` 的原始机构串（不做上下级归并），边是同一篇论文的共同署名（无向），边权是共著篇数。节点门槛「全语料 ≥2 篇」——低于 2 篇的机构只出现在单篇论文里，度为 0 或 1，进图只会增加孤立点。

**路径的代价是什么？** 本指标统一用「跳数」（边数）作为代价，加权口径（$c=1/w$）只作为对照，正式的最优路径口径放在 `M_SYNTH_DS_23_GRAPH_ALGO_002`。这样划分是为了避免两个指标给出两套「最短」定义。

**起讫怎么选？** 从巨型分量里随机抽 200 对，要求跳数 ≥3（避免抽到直接相邻的对，那种对任何算法都是一步）。固定种子 20261021，实际尝试 202 次就凑齐 200 对。

### 1.3 计算公式与本批实现式

BFS 的最短跳数：

$$d_{\text{BFS}}(s,t)=\min\{k:\ \exists\, s=v_0,v_1,\dots,v_k=t,\ (v_{i-1},v_i)\in E\}$$

Dijkstra（无权即所有边权为 1）：

$$d(v)=\min_{u\in N(v)}\left[d(u)+1\right]$$

以优先队列维护，命中目标即停。加权版把边代价换成 $c(u,v)=1/w(u,v)$，其中 $w$ 是共著篇数——共著越多，代价越小。

Bellman-Ford：

$$d^{(k)}(v)=\min\left\{d^{(k-1)}(v),\ \min_{u\in N(v)}\left[d^{(k-1)}(u)+c(u,v)\right]\right\}$$

迭代 $|V|-1$ 轮，第 $|V|$ 轮若还能松弛则存在负环（本图无负权，不触发）。

A*（ALT 地标启发式）：

$$f(v)=g(v)+h(v),\qquad h(v)=\max_{l\in L}\left|d(l,t)-d(l,v)\right|$$

$L$ 是 8 个随机地标，$d(l,\cdot)$ 是地标到全图的 BFS 距离。三角不等式保证 $h$ 可采纳（不高估），所以 A* 的最优性与 Dijkstra 相同。若 $h\equiv 0$，A* 退化为 Dijkstra——本批用地标保证非退化。

DFS：

$$\text{path}=\text{first path found by depth-first traversal}$$

只保证「存在路径」，不保证最短。

## 二、计算过程

### 2.1 图装载与规模校验

图由 `code/_collab_graph21.py` 构造，输入是 `code/_snapshots21/a25_paper_panel.json`（100,900 篇）与 `code/_snapshots21/probe_a26_20261022.json`。构造时先按 `min_papers=2` 过滤：84,320 个机构串里只有一部分满足「全语料 ≥2 篇」，入图 20,436 个；126,849 个候选署名对里，两端都入图的保留 38,208 条。

构造完成后立刻校验规模：孤立点 3,540 个（17.32%）、最大度 194、连通分量 4,186 个。4,186 个分量对 20,436 个节点，平均每分量 4.88 个节点——图是「一个巨型分量 + 大量小碎片」的形态。孤立点不进巨型分量，也不参与路径搜索。

### 2.2 巨型分量提取与节点排序

路径搜索只在巨型分量里做，所以第一步是提取 15,223 个节点、36,965 条边的子图。提取后重新编号节点（巨型分量内部的 0..15222），避免在原图的稀疏 ID 上跑 BFS 时出现大量空数组。

节点集在抽样前排序（`sorted(H.nodes())`），再用固定种子 `random.Random(20261021)` 抽。排序是为了消除 Python 集合迭代顺序对抽样的影响——不排序的话，`set` 的迭代顺序随字符串哈希变化，同一份代码两次运行会抽出不同的 200 对。

### 2.3 起讫对抽样

抽样规则是「随机抽两个不同节点，若跳数 <3 则重抽」。跳数 ≥3 的门槛是为了避免「直接相邻」与「两跳可达」的平凡对：这类对任何算法都是一两步，体现不出算法差异。实测尝试 202 次就凑齐 200 对，说明巨型分量里绝大多数随机对的跳数都 ≥3（跳数分布的中位数是 6）。

这里有一个隐含的选择偏差：只抽巨型分量内的对，等于只测「连通的对」。跨分量的对（占全图对的多数）没有路径，任何算法都失败，但它们不是算法的错。本批把成功率的分母限定在巨型分量内，就是为了不让「图不连通」被算成「算法失败」。

### 2.4 六种算法的实现细节

BFS 用 `collections.deque`，逐层扩展，第一次遇到目标即返回。因为是无权图，BFS 的最短性由层序保证。

DFS 用显式栈，栈元素是 `(节点, 路径)`，路径用列表复制。这个实现的问题在复制：深度每增加一层就复制一次路径，15,223 节点的图里 DFS 可能走到很深，复制开销是 DFS 慢（25.479 ms）的主因。另一个问题是 `seen` 是全局的——一旦节点被访问过就不再入栈，所以 DFS 找到的路径可能非常长（均值多 634.2 跳），这是 DFS 的固有性质，不是实现 bug。

Dijkstra（无权）直接用 `networkx` 的 `single_source_dijkstra` 带 `target` 参数，命中目标即停。0.059 ms 的速度来自两点：一是无权图的所有边权为 1，堆操作很少；二是早停，不需要遍历全图。

加权 Dijkstra 把边权换成 $1/w$，用 `weight` 回调传给 networkx。30.926 ms 比无权慢 500 倍，原因是加权后不能早停（堆里可能有更优路径），必须把目标之前的所有节点都处理完。

Bellman-Ford 用 `networkx.bellman_ford_path_length`，复杂度 $O(V\cdot E)$。15,223 × 36,965 ≈ 5.6 亿次松弛，单次 50.531 ms——这个数看起来不慢，是因为实现里有提前退出（一轮无松弛就停），实际迭代轮数远小于 $|V|-1$。

A* 用 ALT：先随机选 8 个地标，算每个地标到全图的 BFS 距离（8 次 BFS，一次性预计算），再在搜索时用 $h(v)=\max_l|d(l,t)-d(l,v)|$。展开节点数均值 2,042.7，占巨型分量的 13.42%——比 Dijkstra 的全图扩展省很多，但单次 10.949 ms 仍比无权 Dijkstra 慢，因为每次扩展要算 8 次绝对值比较，且 Python 层的堆操作比 networkx 的 C 实现慢。

### 2.5 算法互证

三个独立的「最短跳数」实现——BFS、Dijkstra（无权）、A*（ALT）——在 200 对上给出完全一致的跳数（200/200）。这个一致性是本指标最重要的质量证据：如果三者有分歧，说明某一种实现有 bug（比如 A* 的启发式不可采纳，或 Dijkstra 的早停写错）。

Bellman-Ford 与 BFS 在 20 对上一致 20/20。Bellman-Ford 只跑 20 对，是因为 $O(V\cdot E)$ 在 200 对上要 10 秒以上，而它在这里的作用只是「验证加权最短路实现的正确性」，20 对足够。

DFS 不参与互证——它的目标不是最短，是可达。DFS 200/200 都返回了路径，说明巨型分量确实连通，但它返回的路径长度没有可比性。

### 2.6 性能测量与口径

耗时用 `time.perf_counter()` 在每次调用前后取差，单次调用计时、不做预热。这个测法有两个偏差：一是 Python 的首次导入/缓存效应（第一次调用偏慢），二是机器负载波动。本批的数是 200 次调用的均值，偏差被平均掉一部分，但仍不能当基准测试看——不同机器的绝对值会差 2—3 倍。

另一个口径问题：无权 Dijkstra 带早停、加权 Dijkstra 不带早停，两者的耗时不可直接比较。本批在表里并列展示，是为了让读者看到「加权带来的成本」，不是为了排名。

### 2.7 A* 的展开节点与启发式质量

A* 平均展开 2,042.7 个节点，占巨型分量的 13.42%。这个比例说明启发式是有效的：如果 $h\equiv 0$，A* 会退化成 Dijkstra，展开节点数接近全图；现在只展开 13.42%，省了 86.58%。

但展开少不等于快。A* 单次 10.949 ms，比无权 Dijkstra 的 0.059 ms 慢 185 倍。原因是两者的实现层不同：Dijkstra 走 networkx 的 C 实现且带早停，A* 是纯 Python 的堆循环、每次扩展算 8 个地标的启发式。在平均 6 跳的短路径上，启发式省下的扩展抵不过 Python 层的开销。

这个结论对工程选型很重要：**在本图上，A* 不是「更快的最短路」，而是「更省内存的最短路」**。如果目标是延迟，无权 BFS/Dijkstra 更快；如果目标是避免全图扩展（比如图更大、内存受限），A* 才有优势。

## 五、结果与解读

### 五.1 六种算法能读出什么

第一，BFS 与无权 Dijkstra 在本图上等价，都给出最短跳数，200/200 一致。工程上选哪个取决于实现：BFS 更简单、Dijkstra 更通用（换加权图不用改结构）。

第二，A* 的正确性有保证（200/200 与 BFS 一致），但性能不如 BFS/Dijkstra。这是「短路径 + 高启发式开销」的必然结果：平均 6 跳的路径上，启发式省下的扩展抵不过每次扩展的计算成本。

第三，DFS 只能判连通。200/200 都找到了路径，但平均多走 634 跳。它的价值在「快速判断有没有路径」，不在「给出路径」。

第四，Bellman-Ford 是加权最短路的重型实现，50.531 ms/次，比加权 Dijkstra 慢 1.6 倍。在无负权图上它没有优势，本批保留它只是为了验证加权实现。

第五，跳数分布（均值 5.836、最大 13）说明图是小世界。这个性质让「任意两个机构最多 13 跳可达」成为一句可发布的话，但要说清「可达」不等于「有关系」。

### 五.2 性能结论怎么用

如果要做「路径查询服务」，选 BFS 或无权 Dijkstra：0.06 ms 级，单机每秒可处理上万次查询。

如果要支持加权（按合作强度选最优路径），选加权 Dijkstra：30.926 ms，仍在可接受范围；Bellman-Ford 只在有负权或需要检测负环时用。

如果要处理更大的图（比如百万节点），A* 的「少扩展」才有价值——但那时应该换 C/Go 实现，而不是继续用 Python。

### 五.3 稳定性与互证

| 检验 | 结果 | 结论 |
|---|---|---|
| BFS vs Dijkstra vs A* | 跳数 200/200 一致 | 三个实现互相验证 |
| Bellman-Ford vs BFS | 20/20 一致 | 加权实现正确 |
| DFS 可达性 | 200/200 成功 | 巨型分量连通 |
| 固定种子抽样 | 202 次尝试凑齐 200 对 | 可复现 |

这张表说明结果不是「跑一次碰巧对」，而是三个独立实现给出同一个答案。这是本指标判「完全转换支持」的核心证据。

### 五.4 反常识点与解释

**反常识一：A* 比 Dijkstra 慢 185 倍，尽管它展开的节点少 86.58%。** 直觉上「少扩展 = 快」，实际被实现层抵消：Dijkstra 走 C 实现且带早停，A* 是纯 Python 堆循环 + 8 次启发式计算。算法复杂度与常数因子是两件事。

**反常识二：DFS 平均多走 634 跳，是 BFS 的 100 倍。** 这不是 bug，是 DFS 的定义：它不回溯找更短路径，全局 `seen` 让节点一旦访问就不再进入。用 DFS 展示「合作链路」会得到荒谬的长链。

**反常识三：1.5 万节点的图，任意两点平均 5.8 跳。** 直觉上这么大的图应该更远，实际是超级枢纽（最大度 194）把距离压缩了。这也意味着「最短路径」经常是「经过某个巨型节点」，语义上并不具体。

**反常识四：六个算法的成功率都是 100%，但全图的随机对成功率只有 55%。** 差别在抽样：只在巨型分量内抽，等于先排除了「不连通」的情况。发布时如果只报 100%，会让读者以为图是全连通的。

### 五.5 与其它指标的联动

与 002：002 用同一张图比较「跳数最短」与「代价最低」，146/200 对不同。本指标给出跳数口径的基准，002 给出双口径的差异。

与 005：005 的中心性可以解释「为什么路径总经过某几个节点」——最大度节点就是中心性最高的节点。两个指标结合能回答「谁是枢纽、经过枢纽的路径有多长」。

与 007：007 的社区划分可以给路径加「跨社区跳数」的解释，本批没做，因为两张图的节点集不同。

## 六、结论与发布建议

### 六.1 可用结论

1. 在 20,436 节点 / 38,208 边的机构合著图上，六种路径搜索算法全部跑通：BFS、DFS、Dijkstra（无权/加权）、A* 各 200/200，Bellman-Ford 20/20。
2. BFS、Dijkstra、A* 的最短跳数 200/200 对完全一致；Bellman-Ford 与 BFS 20/20 一致。
3. 巨型分量 15,223 节点（74.49%），500 对抽样的跳数均值 5.836、中位数 6、P90 8、最大 13。

### 六.2 不可用结论

1. **不能把路径读成合作关系**。每一跳只是一次论文共著，整条链上的机构可能从未直接合作。
2. **不能用 DFS 路径做展示**。平均多走 634 跳，用户会看到荒谬的长链。
3. **不能说「任意两机构都可达」**。只有巨型分量内可达，全图 25.51% 的节点不在主连通块。
4. **不能用本指标的耗时做跨机器比较**。单次计时、无预热，绝对值受机器影响 2—3 倍。
5. **不能把「5.8 跳」当成「合作距离近」**。跳数少是因为超级枢纽，不是因为关系紧密。

## 七、王惠方法对照与选用建议

本指标王惠未定义公式（需求只列算法名），因此不存在「照王惠口径复现」的问题，只有「算法实现与口径」的选择。四处需要说明：

| 选择 | 备选 | 为什么选它 |
|---|---|---|
| 跳数作为主代价 | 加权代价 $1/w$ | 与 002 分工：本指标管跳数，002 管双口径 |
| ALT 地标 A* | 曼哈顿/欧氏启发式 | 图无坐标，只能用图距离做启发式 |
| 只在巨型分量内抽样 | 全图随机 | 跨分量无路径，失败不是算法问题 |
| Bellman-Ford 只跑 20 对 | 200 对 | $O(V\cdot E)$ 不经济，20 对足够验证 |

选用建议：**把本指标定位为「路径搜索能力底座」**，对外交付时明确「路径 = 共著链」。若甲方要「合作链路」，建议先用 002 的加权口径重排，再用人工标注筛掉语义不合理的路径。若甲方要「关键节点识别」，应改用 005 的中心性，不要用「路径经过次数」代替。
