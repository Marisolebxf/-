## 摘要

本件回答的问题很窄：把一个区域在科技、产业、人才、政策四个维上的**单维分**摆出来，供雷达图、维分排行、以及「哪一维拖后腿」这三处交互使用。它刻意不合成总指数——总指数由 `M_SYNTH_186_1`（等权）和 `M_SYNTH_VIT_INDEX`（自定义权重 + 权重扫描）承担。这样的分工是为了避免「同一批四维分在三个件里算出三个总指数」，读者查一个城市的单维分时只有一处真源。

四城 × 四维的结果是：深圳 73.7 / 77.7925 / 56.2 / 92.3，广州 68.96 / 39.7686 / 77.0 / 57.0，东莞 7.79 / 18.777 / 7.1 / 15.8，惠州 0.0 / 7.6049 / 0.0 / 0.0。深圳在科技、产业、政策三维居首，人才维由广州居首（77.0 对 56.2，差 20.8 分）——这是四维里唯一一次易位，成因是广州的创新人才数量子维拿到 100.0、深圳只有 26.91，而人才维只剩「数量」与「成果产出」两个子维在跑，数量那一项的权重被放大到一半。

这个排名要分两层读。**算术层**：四维分逐格等于上游子模型的综合分，本件没有自由参数，任何人都能拿四个 `_out.json` 复算，产物里也留了 `consistency` 之外的 16 格原值。**口径层**：四维的完整度差得很远——科技 3/3、产业 3/3（但三级指标 4/5）、人才 2/4、政策 2/3，等权平均 0.7917。完整度低不等于分数不可信，但它意味着「人才 56.2 分」这句话背后的证据量只有「科技 73.7 分」的一半，两者的置信带不一样宽。

最后一层是口径敏感性，也是本件最该被引用的限制：若把科技维从「子模型综合分」换成「单叶子直取」（只取专利授权量），深圳会从 73.7 掉到 59.19、广州从 68.96 升到 75.95，科技维的第一名直接换人。这不是算错，而是两种口径量的不是同一件事：综合分里含科研机构与基础科学，单叶子只有专利。**四维分必须带口径引用，不能把 73.7 和 59.19 当成同一把尺子上的两个读数。**

| 口径要点 | 取值 |
|---|---|
| 四维分（深圳/广州/东莞/惠州） | 见 §2.4 |
| 维完整度 | 科技 1.0、产业 1.0、人才 0.5、政策 0.6667，等权均值 0.7917 |
| 有值的维 | 四城均 4/4（但维内子维不全） |
| 权重 | 本件不加权（`main=null`），`main_is_official=false` |
| 缺维策略 | 维级 null → 不输出该维、下传缺口；维内缺子项 → 上游按在场子项等权，不补 0、不重归一 |
| 判档 | 部分支持 |

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

区域创新活力分析的「综合评价模型」页签下第一屏：给出选定区域在统计年度的科技、产业、人才、政策四个单维得分，每维 0—100。页面上的雷达图（四轴）、维分排行（同一维跨城市比）、以及「短板维」高亮（该城四维里最低的一维）三处交互都读本件。总指数、权重调整、权重敏感性不在此页，分别归 `M_SYNTH_186_1` 与 `M_SYNTH_VIT_INDEX`。

### 1.2 为什么需要这个指标

总指数只能回答「谁综合更强」，回答不了「强在哪、弱在哪」。区域创新政策的实际用法是先看短板：如果某城的政策维只有 15.8 而科技维有 73.7，那么「再加专利补贴」不是有效建议，「补政策工具」才是。四维分开输出还承担一个诊断功能——它能暴露「总分接近但结构完全不同」的情况：深圳 74.9981 与广州 60.6822 的差距是 14.3159 分，但拆开看是「深圳政策 +35.3、产业 +38.0239，广州人才 +20.8」，两城的优势维几乎不重叠。

### 1.3 需求文档是否给出定义方法

给了，而且给得很干脆：正本写明「四维得分分别取子模型综合分，不另算叶子」「输出区域一行四列」「不加权成总指数」。这三句把本件的自由度压到接近零——没有归一、没有权重、没有缺测插补的空间。正本没有写的是两件事：一是**四维分本身的精度**（182/184/185 发布值是一位小数，183 是四位小数，下游要不要统一位数）；二是**维级整块 null 时输出什么**（本批四城四维都有值，这条未触发，但 186_1 与 VIT_INDEX 需要它）。本件对第一条选择「继承上游精度、不二次舍入」，对第二条选择「不输出该维 + 下游分母收缩并记缺口」。

### 1.4 类似指标权威机构构建方法可行性分析概要

| 方法 | 做法 | 在本库的可行性 |
|---|---|---|
| 子模型分直接出口 | 四维分逐维取上游综合分，不再加工 | **可行**，本件主口径 |
| 全叶子重算 | 用 12 个正本分项重新归一加权 | 可算但与上游冲突：重算的四维分与子模型综合分最大差 23.0 分（见 `M_SYNTH_VIT_INDICATOR`） |
| 二次极值归一 | 把四维分再在四城盘上拉一次 0—100 | **不建议**：会把「深圳 92.3 对广州 57.0」压成「100 对 0」，抹掉绝对水平 |
| 等权合成总指数 | 四维平均 | 可行，但归 `M_SYNTH_186_1`，本件不做 |
| 熵权 / CRITIC | 按离散度定权 | 可算（熵权 0.2902 / 0.153 / 0.2977 / 0.2591），但 n=4 极不稳定，仅作对照 |
| 官方权重表 | 读现成配置 | **不可行**：gkx 无权重表，也无本件结果面 |

结论：本件唯一站得住的做法是「取上游、不再加工」。任何二次归一或二次加权都会在四维分与总指数之间插入第三套数，让「单维分之和 ≠ 总指数」变成解释不清的事故。

## 二、计算过程

### 2.1 语义重建：四维分不是「四个指标」，是四个子模型

旧稿把四维当成四个可直取的分数列，来源是四张造数表（`tech_power`、`biz_power`、`enterprise_score`、`policy_focus`）。换源到 gkx 之后这四张面全部不可用，四维只能改成「四个子模型的综合分」。这不是简单的换表：四个子模型各自的维数不一样（科技 3、产业 3、人才 4、政策 3），各自的缺测情况也不一样，所以「四维分」这四个字背后的证据量天然不等。

本件的处理原则是**只出口、不加工**。凡是上游已经发布的分，原样继承；凡是要在四维之间做的比较（排序、极差、短板识别），在本件里做，但不改变分数本身。这样做的代价是本件无法修补上游的缺口（例如人才维的学历结构整维 null，本件补不出来），收益是四维分与子模型文档逐格对得上，任何一个数都能顺着引用链回到真表。

### 2.3 为什么本件不重算、不再归一

先说不重算。正本明写「不另算叶子」，而且实测证明重算会造出第二套四维分：用 12 个正本分项等权重算，科技维深圳 72.7891（上游 73.7）、广州 65.2354（上游 68.96），产业维深圳 66.6888（上游 77.7925），人才维广州 100.0（上游 77.0），最大差 23.0 分。差这么大不是算错，而是**分项集合与子模型的叶子集合不同**：183 的综合分里含「产品名称覆盖数」，而正本的 12 分项用的是「新产品销售收入占比」，两者根本不是同一个量。重算等于用一把错的尺子去校一把对的尺子。

再说不做二次归一。四维分已经在各自的子模型里做过一次四市盘 min-max，若在本件再拉一次，等于把「深圳政策 92.3」压成 100、「广州 57.0」压成 0，读者看到的是相对位次，而不是「广州的政策维其实过了及格线」。更麻烦的是这会与总指数打架：186_1 的等权指数用的是未二次归一的四维分，若本件发布二次归一后的分，两件的同名维就对不上。

形式化地，本件只做恒等映射：

$$S_{i,k}=C_{i,k},\qquad C_{i,k}\ \text{为子模型 }k\text{ 在城市 }i\text{ 的综合分}$$

其中 $k\in\{\text{科技},\text{产业},\text{人才},\text{政策}\}$。名次由 $\operatorname{rank}(S_{\cdot,k})$ 给出，四维各自独立排名，不跨维比较。

### 2.6 缺维与缺子项：两种缺口、两种写法

本件不出合成分，所以「缺维」在本件不触发加权，但它必须把规则交代给下游，否则 186_1 与 VIT_INDEX 会各自发明一套。

**第一种，维级整缺（该维四城全 null）。** 处理是「不输出该维」，并在下游把该维从加权里摘出去：`n_dims_available` 减一、分母收缩到在场维、`gap_dims` 记下缺的是哪一维。**不做静默重归一**——也就是说，不允许把「只覆盖 3 维的城市」按 1/3 各维权算出一个与「覆盖 4 维的城市」看起来同尺度的分。分母收缩必须在产物里可读，不能只报一个分数。本批四城四维都有值，这条未触发。

**第二种，维内缺子项（本批全部触发）。** 处理是「该维分由上游按在场子项等权给出」，不把 null 当 0，也不把剩余子项「放大到 1」。人才维就是这样：4 个子维只剩 2 个，两个各占一半；政策维 3 个剩 2 个，两个各占一半；产业维 5 个三级指标剩 4 个，但产业维的分是按三维结构给的，不是按 5 个三级指标平均。

有一条反例值得写在正文里，因为它决定了「0 与 null 不能同形」：惠州在科技、人才、政策三维都是 0.0，若把这三维误记成「缺测」，等权指数会从 1.9012 跳到 7.6049（Δ 5.7037），名次不变但分数翻了四倍。这是 186_1 的 A 场景实测值，本件引用它来说明「0 是真值、null 是缺测」这条边界不能模糊。

### 2.9 权重问题：本件不加权，但必须给对照

正本对本件的要求是「不加权成总指数」，所以 `weights.main=null`、`main_is_official=false`。这句话容易被误读成「本件回避了权重问题」，实际上权重问题被推给了下游两件，本件只负责把「加权前的原料」摆正。

为了让下游的权重选择有客观参照，本件在产物里附了熵权（读自 `M_SYNTH_VIT_INDEX_out.json` 的 `weights.entropy`）：科技 0.2902、产业 0.153、人才 0.2977、政策 0.2591。熵权把产业维压到 0.153，原因是产业维在四城间的离散度最大（极差 70.1876），信息熵最低——按离散度定权的逻辑，离散大的维应该权重高，但这里熵权反而最低，因为熵权用的是 $1-e_d$ 的归一，而产业维的 $e_d=0.799986$ 在四维里最高。这与「离散大 → 权重高」的直觉相反，正好说明 n=4 时熵权不可靠：四个数算出来的熵，本质上是四个数的函数，不是总体分布的估计。

因此本件的建议是：四维分照发，权重留给 186_1（等权，写死）与 VIT_INDEX（自定义 0.30/0.30/0.20/0.20，附熵权对照与单纯形网格）。本件不发布任何加权结果，也不给「推荐权重」——推荐权重必须附翻转阈值，那是 VIT_INDEX 的职责。

## 四、数据缺失情况

### 4.1 人才维：4 个子维只剩 2 个

人才维的正本结构是「创新人才数量 / 学历结构 / 年龄结构 / 成果产出」。实测只有 D1 与 D4 在场：D2 学历结构因硕博学者占比四城只有两城有值、且归一后饱和（深圳 100.0、广州 97.4026，只差 2.5974 个百分点）整维不进；D3 年龄结构因青年学者占比同样只有两城有值、且研发人员数列整列空，整维不进。于是人才维分变成 $(D1+D4)/2$：广州 $(100.0+53.93)/2=77.0$，深圳 $(26.91+85.52)/2=56.2$。

这个结构的后果是**人才维几乎等于「人才数量」单撑**：广州在 D1 上拿满分，就直接锁定了人才维第一。若学历结构与年龄结构在场，广州的 100.0 会被稀释——但稀释成多少，本库无法回答，因为那两列的覆盖只有两城。所以「广州人才第一」这句话只在「数量 + 成果产出」这个口径下成立，不能外推成「广州人才质量第一」。

### 4.2 政策维：3 个里只有 2 个

政策维的正本是「政策数量 / 政策类型 / 政策效果」。政策效果由「实施时效性」与「政策可见度」等权构成，而这两项在本库都无法定义：`implementation_date` 与 `expire_date` 全为 `'0000-00-00'` 占位（100%），时效性算不出；`link` 列 100% 非空，可见度归一后是整列常数，无量纲可分。`publish_date` 虽是 20,000 行真实日期（可算发布至今月数），但「发布多久」不是「是否在实施窗口内」，不作替代。于是政策维只剩数量与类型两项：深圳 $(100.0+84.62)/2=92.3$，广州 $(36.97+76.92)/2=56.945$（上游发布为 57.0，差 0.055 来自上游先舍入再发布）。

政策维的 92.3 因此是「政策供给强度」，不是「政策效果」。这一点在 UI 上必须写清，否则读者会把「深圳政策 92.3 分」理解成「深圳政策最有效」——实际上它只说明深圳的政策文件数量与类型覆盖在四市里最高。

### 4.3 产业维：5 个三级指标缺 1 个

产业维有 3 个子维，但三级指标是 5 个，缺的是「第三产业增加值占比重」：四城只有东莞 2017 上半年存在同期间 `JDZ+DNLJ` 配对（52.9279%），其余三城两码期间不相交。因此产业维的 D1 退化为「产品名称覆盖数」单撑，D1 与产品名归一完全相同（100.0 / 36.9547 / 6.9013 / 0.0）。这一条的详细论证在 `M_SYNTH_183_1` 的 §4.1，本件不重复，只继承结论。

### 4.4 科技维：综合分与单叶子差 14.51

深圳科技维在综合分口径下是 73.7，在单叶子口径（只取专利授权量）下是 59.19，差 14.51。这个差不是误差，是口径差：综合分里含应用科技（深圳 100.0）与科研机构（深圳 87.29），而单叶子只数专利。广州则在两种口径下都是高分（68.96 / 75.95），因为它的基础科学子维是 64.77、科研机构 89.37，专利授权量也不低。

这条缺口的实际含义是：**科技维的结论对口径高度敏感**。若对外发布「深圳科技第一」，必须同时说明用的是综合分口径；若换成单叶子，第一名是广州。本件在 §2.8 给了完整对照，不建议只发一个数。

### 4.5 极值归一的盘内性质

四个子模型的维内归一都在四市盘上做，所以「0 分」等于「盘内最低」，不等于「没有」。惠州三个维是 0.0，但它的科技维在 11 城口径下有值、产业维有 7.6049、政策维有存量政策；东莞的三个维也都在 7.1—18.777 之间，不是空白。任何把 0.0 读成「该城该维为零产出」的解释都是错的。这条限制在 §2.6 已用惠州 1.9012 → 7.6049 的例子量化过。

### 4.6 停用与重估条件

出现以下任一情况应重估：① 人才维的学历结构或年龄结构补齐到四城（人才维从 2 子维恢复到 3—4 子维）；② 政策日期列不再是 `'0000-00-00'`（政策效果可算，政策维恢复 3 子维）；③ 产业维补上四市同期间第三产业占比重（产业维三级指标 5/5）；④ 评估盘从 4 城扩到 ≥10 城（极值归一的端点不再由单城决定，四维分的绝对水平会整体移动）。四条都不满足时，本件的四维分只能作「四市盘内可比的相对位次」，不能作跨区域绝对水平。

### 4.7 与下游两件的传导

本件是 186_1 与 VIT_INDEX 的唯一四维源。两条缺口会原样传下去：人才维 2/4、政策维 2/3 会让加权完整度只有 0.8333（按 VIT_INDEX 的主口径权重加权）；产业维三级指标 4/5 会让 12 分项覆盖只有 8/12。下游两件都不能「补」这些缺口，只能把缺口写进产物并在分数旁边标注。特别提醒：下游若做「缺维重归一」，必须与本件的「维级 null 不输出」规则一致，不能一件收缩分母、另一件补 0。

## 五、王惠方法对照

### 5.1 王惠方法在原指标族里的位置

王惠口径在本族承担「四维定维、子模型出口、不加权」这一支。正本的原话是「四维得分分别取子模型综合分，不另算叶子」「输出区域一行四列」「不加权成总指数」。这三句决定了本件的方法论位置：它是**分维出口**，不是评价模型；评价模型在 186_1（等权）与 VIT_INDEX（可调权重）。

### 5.2 本件与其结构上的相似与差异

相似处有三点：维度集合相同（科技/产业/人才/政策）；取数路径相同（逐维取子模型综合分）；缺测规则相同（不补 0、不用同比替代）。差异有两点：一是本件把「维内缺子项时维分怎么算」写成了显式规则（按在场子项等权，不重归一），王惠原文没有这一条，因为原文假设四维都齐；二是本件额外提供了三套对照（单叶子、留一维、等权合成），原文只要求输出四列。

### 5.3 选用建议

对外发布用本件主口径（四维分原样出口），并在图例上标注每一维的子维在场数（3/3、3/3、2/4、2/3）。方法学章节要同时给出单叶子对照，用来说明「科技维首名随口径翻转」；不建议用单叶子替代综合分，因为单叶子丢掉了科研机构与基础科学两项。任何发布都必须带两句限定：人才维只剩「数量 + 成果产出」，政策维只剩「数量 + 类型覆盖」。缺了这两句，四维雷达图会被读成「四维都完整」。
