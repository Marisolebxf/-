## 摘要

本指标不做打分，只做「协同关系的输入盘点」：按 calc-logic 0.3.2 的三类关系（联合专利 / 合作项目 / 人才流动），把库内原始表折算成事件级计数，并给出区域切片。三类关系里两类可算、一类结构性缺失，类型覆盖率 66.7%。

联合专利：20,000 件专利、28,964 行申请人记录，抽出 6,477 个多申请人事件（32.39%），其中企业 + 高校/院所同现的产学研子事件 502 个（7.75%）。合作项目：58,453 行，事件数 0。人才流动：16,718 名学者，8,801 人有迁移，18,553 次迁移，人均 2.108 次。

### 1.2 口径定义

需求文档写的是「统计联合专利、合作项目、人才流动三类协同关系的事件数，按区域汇总」。这句话里有两个关键词需要落地：

**事件（relation_event）**。不是「一行记录」，而是「一次跨主体关系」。同一专利的两个申请人算 1 个事件，不是 2 个；同一学者的三次迁移算 3 个事件，不是 1 个。事件粒度的选择直接决定计数，本批按 calc-logic 的定义执行，并在 §1.3 写死。

**区域（region）**。事件本身没有城市字段，必须由参与主体反推。反推规则是「主体名 → 底册名 → 城市」，重名按 $1/k$ 摊权。一个事件里多个主体落在不同城市时，事件同时计入多个城市（跨城事件），所以各城市事件数之和会大于事件总数。

三类关系的门槛：

- 联合专利：同一 `pn` 下不同申请人数 ≥2；
- 合作项目：同一项目下不同承担机构数 ≥2；
- 人才流动：同一 `scholar_id` 的任职机构序列（去重后）长度 ≥2，迁移次数 = 长度 − 1。

### 1.3 计算公式与本批实现式

联合专利事件数：

$$E_{\text{jp}}=\left|\{p:\ |\text{applicants}(p)|\ge 2\}\right|$$

产学研子事件：

$$E_{\text{iur}}=\left|\{p\in E_{\text{jp}}:\ \exists a\in\text{applicants}(p),\ \text{ENT}(a)\ \wedge\ \exists b\in\text{applicants}(p),\ \text{UNI}(b)\}\right|$$

其中 $\text{ENT}$ 匹配「有限公司/股份/集团/公司/厂/企业/合伙企业/LLC/LTD/INC/CORP/GMBH」，$\text{UNI}$ 匹配「大学/学院/研究院/研究所/科学院/研究中心/医院/SCHOOL/UNIV/INSTITUT/COLLEGE」。这是名称规则，不是权威分类，误判主要来自「XX 大学附属公司」这类混合名称。

人才流动事件数：

$$E_{\text{tf}}=\sum_{s}\max\left(0,\ |\text{uniq}(\text{orgs}(s))|-1\right)$$

$\text{orgs}(s)$ 按 `start_time` 排序，先去掉连续重复（同一机构连续两段任职算一段），再去重（回到原机构不重复计迁移）。这个处理会让「A→B→A」记 1 次而不是 2 次，与 calc-logic 的「迁移」语义一致。

区域归属：

$$w(c\mid a)=\begin{cases}1 & \text{名称能唯一判城}\\ 1/k & \text{名称对应 }k\text{ 个城市}\end{cases}$$

$$E_{\text{jp}}(c)=\sum_{p\in E_{\text{jp}}}\mathbb{1}\left[\sum_{a\in p}w(c\mid a)>0\right]$$

事件级归属用的是「是否落在该城市」，不是「权重累加」，所以一个事件的多个城市权重不会把计数放大成小数；城市内的件数（`by_city_attribution`）才用权重累加，会出现 56.0 这样的小数。

## 二、计算过程

### 2.1 快照构建与三表装载

三张表在 2026-10-22 13:23 一次性落盘为 `code/_snapshots21/collab_inputs21.json`，构建脚本 `code/_build_collab_inputs21.py` 直连 gkx 只读账号，四条查询分别耗时 1.87 秒（申请人 28,964 行）、0.78 秒（任职 57,117 行）、3.68 秒（项目表计数）、0.04 秒（项目表样本 8 行）。落盘后本指标脚本零 SQL，只读快照。

装载时先做字段体检再看事件：申请人表有 `pn` 与 `applicant_name` 两列，没有年份；任职表有 `scholar_id / org_name / start_time / end_time / is_current`，没有城市；项目表有 `funded_institution / participating_institution / project_host`，其中前两列是机构字段、第三列是人名字段。这个体检结果直接决定了后面能构哪类事件。

### 2.2 联合专利事件的抽取

先把 28,964 行按 `pn` 聚成 20,000 个专利，每个专利内申请人名称去重（同一专利内重复出现的同一名称只算一个主体），再筛「主体数 ≥2」。得到 6,477 个事件，占 20,000 件的 32.39%。

这个比例本身是一个信息：抽样的 20,000 件专利里近三分之一是合作申请，远高于「多数专利为单一申请人」的常识。原因在抽样方式——`dwd_patent_applicants` 很可能是按「有多个申请人」优先抽的，或者抽中的批次偏向外向型技术领域。这一点无法从表内确认，只能标注为口径风险。

产学研子事件用名称规则判：同一专利内至少一个主体匹配企业正则、至少一个匹配高校/院所正则。得到 502 个，占 6,477 的 7.75%。这个比例偏低，与头部主体多为境外企业有关——东芝、Nokia、Baxter 的联合申请对象多为同集团子公司或境外医院，不构成「中国企业 + 中国高校」的产学研关系。

### 2.3 参与主体分布与抽样偏差

参与次数前 10：株式会社东芝 73、NOKIA TECHNOLOGIES OY 63、BAXTER HEALTHCARE SA 61、VANTIVE HEALTH GMBH 61、VANTIVE US HEALTHCARE LLC 61、东芝基础设施系统株式会社 54、BAXTER INTERNATIONAL INC. 51、中国石油化工股份有限公司 50、STRYKER CORPORATION 45、丰田自动车株式会社 43。

前十名里 9 个是境外主体，只有中国石化一个国内主体。这不是「外资企业在中国合作更多」的结论，而是抽样偏差：抽中的 20,000 件专利里境外申请人的联合申请被大量保留。用这批事件算「国内产学研协同强度」，分子会被境外主体稀释。

这一点必须写进披露，因为它直接影响 502 这个数的解释：502 个产学研事件是在「境外主体占多数」的样本里数出来的，真实的国内产学研事件数只会更高，不会更低——但高多少，用当前表无法估计。

### 2.4 任职变迁的抽取与去重

57,117 行任职记录按 `scholar_id` 分组，每组按 `start_time` 升序排序。排序后先合并连续重复（同一机构连续两段任职视为一段），再去重（同一机构在序列里出现两次只保留第一次），得到每个学者的「机构序列」。

16,718 名学者中，8,801 名的序列长度 ≥2，占 52.64%；这 8,801 人累计产生 18,553 次迁移，人均 2.108 次。人均大于 2 说明「换过两次以上机构」的人不少，移动不是一次性的。

机构对的前八名：香港中文大学→香港理工大学 6、卡罗林斯卡学院→卡罗林斯卡大学医院 5、剑桥大学→伦敦大学学院 5、伦敦大学学院→剑桥大学 4、伦敦大学学院→牛津大学 4、香港城市大学→武汉理工大学 4、墨尔本大学→皇家墨尔本理工大学 4、鹿特丹伊拉斯姆斯大学→蒂尔堡大学 3。

这八对里，三对是「大学→同城医院/学院」（卡罗林斯卡、剑桥、墨尔本），两对是「同城高校互跳」（剑桥↔伦敦大学学院、牛津），两对跨境（香港→内地、荷兰内部）。这是一个典型的「学术劳动力市场」形态：迁移多发生在同一城市或同一国家的高校系统内，跨国迁移是少数。

### 2.5 项目表为什么构不出事件

`dwd_zh_project` 58,453 行，字段体检结果：`funded_institution` 非空 0 行（资助机构整列为空），`participating_institution` 非空 58,452 行但 58,453 个项目只对应 1,592 个不同机构名——平均每个机构名对应 36.7 个项目，说明这一列记的是「承担机构」单值，不是「参与机构列表」，`project_host` 非空 58,453 行但存的是人名。

按「跨 ≥2 机构」的事件定义，需要每个项目有 ≥2 个承担机构。当前表每项目只有 1 家，构不出事件。这不是「项目少」，而是「字段形态不对」：如果 `participating_institution` 是逗号分隔的多值字段，58,453 行能直接炸成十几万条参与记录；现在它是单值，只能做「机构→项目数」的统计。

本批的处理是：不构造事件，但在 `event_grain.coop_project` 里保留字段填充率与「事件 0」的原因，并在 §四 把它列为结构性缺口。这样下游拿到 `coop_project.events_national = 0` 时，能立刻看到「不是没查，是构不出来」。

### 2.6 城市归属与四城切片

城市归属走两条路：先试 `S.inst_city()`（机构串里直接含城市名，或命中高校白名单），不命中再走 `S.name_city_weights()`（底册名称字典，重名 $1/k$ 摊权）。两条都不命中记「无城市」，不进四城切片。

联合专利的切片结果：6,477 个事件里 122 个至少一个主体能归到四市（1.88%），其中同城 120、跨城 2。分城件数（权重累加）是深圳 56.0、广州 100.0、东莞 8.0、惠州 4.0，合计 168.0，比 122 多出 46.0——差额来自「一个事件的多主体落在多个四市城市」的重复计数。

人才流动的切片更薄：18,553 次迁移里只有 32 次能归到四市（0.17%），同城 25、跨城 7；流入分城是深圳 17.0、广州 15.0、东莞 0、惠州 0；18,521 次迁移两侧都无法归城。这个比例说明任职经历表的机构名以境外与国内其他城市为主，四市主体在其中占比极低。

### 2.7 类型覆盖率与判档

`type_coverage` 的三个数是：声明类型 3、可算类型 2、覆盖率 66.7%，缺失类型 `coop_project`。这个 66.7% 是判档的直接依据之一：四档定义里「完全转换支持」要求「三类关系都能从库内原始表按事件口径现算」，本指标缺一类，且缺的那一类是字段形态问题、不是样本量问题。

另一个依据是区域可归城率：联合专利 1.88%、人才流动 0.17%。即便类型齐了，只要区域维不可用，本指标也只能交付全国口径。两个依据叠加，判「部分支持」。

## 四、数据缺失情况

### 四.1 缺口清单与修复路径

| 缺口 | 影响 | 实测后果 | 修复路径 |
|---|---|---|---|
| 项目表无参与方列表 | 第三类事件缺失 | 58,453 行 → 0 事件 | 需带多值参与机构的项目表 |
| 申请人表只有 2 万件 | 联合专利规模不可外推 | 6,477 事件 / 20,000 件 | 需 `dwd_patent` 全量共同申请人 |
| 境外主体占比高 | 产学研事件被稀释 | 502 / 6,477 = 7.75% | 按国别过滤后重算 |
| 机构名未标准化 | 归城率低 | 1.88% / 0.17% | 需名称→信用代码映射 |
| 任职表无城市字段 | 区域切片薄 | 18,521 次迁移无城市 | 需机构主数据 |
| 项目表无金额 | 无法做强度 | 只能数事件 | 需合同金额字段 |

### 四.2 结构性缺口（扩量救不了）

1. **项目表的字段形态不对**。`participating_institution` 是单值列，不是列表。哪怕把项目数从 5.8 万扩到 50 万，只要每行还是 1 家机构，「跨 ≥2 机构」的事件仍然是 0。这是 schema 问题，不是数据量问题。
2. **联合专利的抽样方式未知**。20,000 件专利里 32.39% 是多申请人，这个比例远高于常规，说明抽样不是随机的。不知道抽样规则，就无法把 6,477 外推到 293.99 万件全量。
3. **境外主体无法归城**。底册只收四市主体，东芝、Nokia、Baxter 这些主体天然归不了城。这不是映射做得不好，是底册的覆盖范围决定的。
4. **人才流动的「迁移」不等于「引进」**。A→B 记一次迁移，但 B 是否在四市、迁移是否发生在统计年内，都不确定。任职表只有 `start_time`，没有「离开时间」，无法判断迁移是否已完成。

### 四.4 缺口对判档的影响

「完全转换支持」要求三类关系都能现算。本指标缺一类，且缺的是 schema 级缺失（不是补样本能解决的），所以不能判完全转换。但它也不是「完全不支持」：两类事件都算出了真实计数，且事件构造逻辑可复现（同一快照两次运行结果一致）。

判「部分支持」的实质是：**能回答「库内有多少条协同关系」，不能回答「四市的协同网络长什么样」**。

### 四.5 缺口的量化影响

| 缺口 | 可量化的后果 | 量化方式 |
|---|---|---|
| 项目事件 0 | 类型覆盖 66.7% | 2 / 3 |

| 境外主体主导 | 产学研事件仅 7.75% | 502 / 6,477 |

| 无城市迁移 18,521 | 占迁移总数 99.83% | 18,521 / 18,553 |

这些数说明：全国口径的「有没有关系、有多少」可以回答，区域口径的「关系落在哪」基本不能回答。

## 五、结果与解读

### 五.1 三类关系的可得性

三类关系里，联合专利与人才流动是「表在、字段够、能构造」，合作项目是「表在、字段不够、构不出」。这个差异不是数据量造成的，而是 schema 造成的：申请人表有「一个专利多行申请人」的结构，天然支持事件构造；项目表是「一个项目一行」，没有多值参与方。

对下游的直接影响：任何依赖「三类关系齐全」的图谱指标（比如要求产学研三类边都有权重），在本库上都做不了完整版；只能做「专利 + 任职」两路，项目一路留空。

### 五.2 事件规模的含义

25,030 个事件（6,477 + 18,553 + 0）看起来不少，但两个来源的性质完全不同。联合专利事件是「一次性合作」——两个主体在同一件专利上署名，合作深度未知；人才流动事件是「人的移动」——学者从一个机构到另一个机构，是真实的关系变化。前者数量受抽样影响，后者数量受任职记录完整度影响。

把两者相加没有意义（一个是专利级、一个是人级），本批只在总表里并列展示，不做合计解读。

### 五.3 区域切片的可信度

四市可归城事件 154 个（122 + 32），占 25,030 的 0.62%。这个比例太低，低到不能做任何城市间比较：深圳 56.0 vs 广州 100.0 的差距，可能只是「广州的机构名更容易匹配到底册」，而不是「广州的合作更多」。

如果要提升区域切片，必须先把机构名标准化。当前的重名摊权只能处理「同一名称多个城市」，处理不了「同一机构多个名称」（如「中山大学」与「中山大学广州校区」）。

### 五.4 反常识点与解释

**反常识一：联合专利事件里前十名有 9 个是境外企业。** 直觉上「中国的专利申请人表」应该以国内主体为主，实际抽样里东芝、Nokia、Baxter 排在前列。这说明 20,000 件抽样不是按国内主体抽的，可能是按「有多个申请人」抽的，而境外企业的联合申请比例更高。这个偏差直接影响 502 个产学研事件的解释。

**反常识二：合作项目表有 58,453 行，事件数是 0。** 「有表就有数据」是错觉。项目表的 58,453 行是「一个项目一条」，没有参与方列表，按事件定义一条都构不出来。这不是查询写错，是字段不支持。

**反常识三：人才流动人均 2.108 次，但机构对最高频只有 6 次。** 迁移总量不小（18,553），但分布极散，没有形成「通道」。这说明学术迁移是「多对多」的，不是「几所名校之间互跳」。

**反常识四：专利合作 1.64% 跨城，人才流动 21.88% 跨城。** 两个比例差了一个数量级，方向上说明「专利合作更依赖地理邻近，人才流动更不受地理约束」。但样本只有 2 与 7 个跨城事件，这个反差只能当假设，不能当结论。

### 五.5 与其它指标的联动

与 008：008 用的是论文合著图（7,742 节点 / 7,736 边），本指标提供的是专利与任职两路关系。两者可以拼成「论文 + 专利 + 任职」的三路协同输入，但本批没有拼——因为项目一路缺失，拼出来的图仍然是两路半。

与 `M_ORG_COLLAB_CHAIN`：那个指标的边来自论文合著，本指标的联合专利边是另一套数据，两者不能直接合并计数（同一对机构可能在两边都出现）。

## 六、结论与发布建议

### 六.1 可用结论

1. 库内可构造两类协同关系事件：联合专利 6,477 个（20,000 件抽样，多申请人占 32.39%）、人才流动 18,553 次（8,801 名迁移者 / 16,718 名学者）。
2. 产学研子事件 502 个，占联合专利事件的 7.75%，但样本以境外主体为主，不能代表国内产学研强度。
3. 合作项目一路结构性缺失：58,453 行项目、`funded_institution` 非空 0 行、`participating_institution` 每项目 1 家，事件数 0。
4. 类型覆盖率 66.7%（2/3）。
5. 四市切片：联合专利 122 个事件（1.88%）、人才流动 32 次（0.17%），合计 154 个，占全部事件的 0.62%。

### 六.2 不可用结论

1. **不能说「四市协同关系有 154 条」**。这 154 条只是「能归城的」，另外 24,876 条归不了城，不能说它们不在四市。
2. **不能用 6,477 外推全量专利**。抽样只有 20,000 件（全量的 0.68%），且抽样方式未知。
3. **不能说「产学研合作弱」**。502 个事件是在境外主体占多数的样本里数出来的，真实值只会更高。
4. **不能说「合作项目为零」**。项目表有 58,453 行，是字段形态不支持事件构造，不是没有项目。
5. **不能做城市排名**。可归城率 1.88% / 0.17%，深圳与广州的差距在噪声范围内。

## 七、王惠方法对照与选用建议

本指标不是王惠系（`formula_owner` 为 calc-logic 0.3.2），因此不存在「照王惠口径复现」的问题。需要说明的是三处口径选择：

| 选择 | 备选 | 为什么选它 |
|---|---|---|
| 事件粒度「跨主体」 | 按行计数 | 按行会把同一专利的多个申请人重复计，事件语义失真 |
| 人才迁移「去重后相邻」 | 按连续任职段 | 连续段会把「同机构换部门」误计为迁移 |
| 区域归属「事件级布尔」 | 权重累加 | 权重累加会让跨城事件在两个城市各计一次，城市合计大于总数 |

选用建议：**把本指标定位为「输入盘点」，不要当「协同强度」用**。若下游要建图，建议直接用 008 的论文合著边，不要用本指标的联合专利边——后者的抽样偏差太大。若甲方坚持要专利协同，必须先补全量共同申请人。
