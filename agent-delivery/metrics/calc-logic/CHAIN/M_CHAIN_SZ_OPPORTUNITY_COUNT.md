## 摘要

产业机遇数回答的是「深圳在一条链上有多少个值得补的环节」。calc-logic 把机遇分三类：产业发展方向、政策优化、创新方向，每类给出环节清单与条数，总计就是机遇数。gkx 侧没有 `chain_sz_opportunity` 结果表，也没有任何环节级的机遇标注。

本件能重算的只有第一类。方法是用「全国基准份额」做对照：全国 1,714,457 条挂链里深圳 136,326 条，基准份额 7.952%；一个关键叶的深圳份额低于 7.952%，或深圳直接为零，就算一个产业发展方向机遇。463 个关键叶里，52 个为零、202 个份额不足，合计 254 个。

这个数对基准口径敏感。若把分母从「挂链次数」换成「去重企业数」（116,017 / 1,714,457 = 6.767%），机遇数降到 227；若基准放宽到 10%，降到 190；收紧到 5%，升到 285。254 是采用「挂链次数」主口径的结果，与同族 `M_CHAIN_SZ_OPPORTUNITY_SCORE` 的市场维同源。

机遇的分布比问题数更均匀，但仍有重心：生物医药 70 个（27.6%）、集成电路 39 个（15.4%）、人工智能 26 个、传感器 23 个、低空经济 21 个、软件 20 个。数字创意只有 11 个但机遇率 78.57%——它的关键叶只有 14 个，11 个不足，比例极高。这说明「数」和「率」要一起看。

两类机遇无法计数，必须如实说：政策优化需要「政策条文 → 具体环节」的建议配对，879 条深圳政策里只有 13 条能按链命中，没有一条能落到环节；创新方向需要「专利主题 → 环节」的映射，169,226 件专利里只有 23,756 件能映射到链，且只落首个链、无环节级。两类都记 `blocked`，不给数字。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块是**产业链分析 → 深圳产业发展分析 → 产业机遇**。页面是一张 12 行的链级计数表：链名、机遇数、其中空白环节数、薄覆盖环节数，点进去是环节清单，每条含环节名、全国企业数、深圳企业数、深圳份额。

这个指标与「机遇评分」（`M_CHAIN_SZ_OPPORTUNITY_SCORE`）是同一模块的两种表达：计数给「有多少条」，评分给「整体多强」。页面通常先显示评分排名，点进去看该链的机遇清单。两者共享链维、深圳判定与全国基准，但不共享公式——评分是 z 标准化后的相对指数，计数是阈值判定后的绝对条数。

与「问题数」（`M_CHAIN_SZ_PROBLEM_COUNT`）的关系更近，但阈值不同：机遇数用相对份额（< 7.952%），问题数用绝对家数（全国 ≥10 且深圳 ≤2）。两个数不能相加，也不能互相替代，第 9 节专门解释。

### 1.2 为什么需要这个指标

第一个用途是**清单化**。评分只能告诉「哪条链强」，机遇数能告诉「具体补哪几个环节」。254 条清单可以直接分派到招商、补链、政策三个口，每条都有全国与深圳的企业数作为证据。

第二个用途是**优先级**。清单按全国企业数降序，排在前面的环节全国盘子大、深圳缺口明显，优先级天然更高。生物医药的「茶碱和氨茶碱类」全国 334 家、深圳 0 家，是最典型的补链标的。

第三个用途是**口径对照**。机遇数与问题数、覆盖率三个指标从不同角度描述同一批环节。三个都指向同一个环节时（如生物医药的原料药段），结论最硬；只有一个指标指向时，需要复核是不是口径效应。

### 1.3 需求文档是否给出定义方法

**需求文档给出了三类机遇的分类，但没有给出判定阈值。** calc-logic 写的是：从 `chain_sz_opportunity` 取该链的机遇条目，按 `opportunity_type` 分三类，计数。它没有写「什么样的环节算机遇」——因为这个判定本应由上游模型或人工标注给出。

上游的「深圳机遇分析模型」（算法库 1.1.1.1.1.1.1.3.12）要求「融合优势识别结果与问题分析结果，运用机器学习方法进行区域机遇的预测与推荐」。这是一个模型输出，不是 SQL 条件。gkx 侧没有模型结果表；live 侧 `chain_sz_opportunity` 8 行是未来产业种子，`model_version` 带 `-demo`，与 12 链只重名 1 条。

本件因此没有假装复现模型，而是用「全国基准份额」做透明代理：深圳在某环节的份额低于全国平均，说明这个环节深圳相对薄弱，值得作为机遇。这个定义可复现、可解释、与「机遇」语义相关，但它不是模型的「推荐」，只是统计上的「相对薄弱」。这个区别是判档的核心依据。

### 1.4 类似指标权威机构构建方法可行性分析概要

「区域产业机遇识别」在权威实践里有多种做法，从份额对照到模型推荐都有。下表列六条路线，说明本件为何选 A。

| 方法族 | 代表机构/文献 | 口径要点 | 与本指标的差 | 贴合度 |
|---|---|---|---|---|
| A 全国份额对照（本报告） | 父口径延伸 | 深圳份额 < 全国基准即机遇 | 统计薄弱，非模型推荐 | 高（可算） |
| B 模型直读 | calc-logic v0.2.0 | 读 `chain_sz_opportunity` 条目 | 结果表不存在 | 目标口径，不可执行 |
| C 机器学习推荐 | 算法库 1.1.1.1.1.1.1.3.12 | 优势+问题融合，预测推荐 | 无训练样本、无标签 | 不可行 |
| D 区位商（LQ） | 区域经济分析 | 份额比 ≥ 1 为优势，< 1 为劣势 | 与 A 同源，阈值不同 | 高（等价） |
| E 专家清单 | 产业规划 | 专家列补链环节 | 不可复现、成本高 | 低 |
| F 政策文本抽取 | 政策分析 | 从政策文件抽「重点环节」 | 只覆盖政策提及环节 | 中（可补充） |

**A 与 B 的差别是「机遇由谁认定」。** B 由模型/专家认定，语义准确但当前不可得；A 由份额对照认定，可复现但会把「深圳已经很强、只是略低于全国平均」的环节也算进来。用 A 的清单去校验 B 的推荐，会得出「模型漏报很多」的错误结论。

**C 不可行的原因是样本。** 12 条链、254 个候选环节，没有「是否真机遇」的标签，无法训练。**D 就是 A 的另一种写法**：区位商 = 本地份额 ÷ 全国份额，小于 1 即劣势，与 A 的「份额 < 基准」等价，本件用份额差而不是比值，是为了让阈值可直接读成百分比。

**E 的问题是复现与成本。** 954 个环节逐个专家认定不可行，且每次认定会变。**F 是可行的补充，但覆盖窄。** 879 条深圳政策只有 13 条按链命中，抽不出环节级清单，只能作为政策优化类机遇的输入，而这一类本件已判 blocked。

### 1.6 本报告的口径与边界（推测定义，须与甲方会签）

推测定义：**产业发展方向机遇 = 关键叶中，深圳挂链份额低于全国基准（7.952%）或深圳为零的环节**；机遇数 = 这些环节的条数。

边界有五条。第一，只覆盖三类机遇里的一类，政策优化与创新方向记 blocked，不进总数。第二，基准用挂链次数，不是去重企业数；换口径 254 → 227。第三，深圳按登记地 4403 判定，实际经营地不可得。第四，关键叶用逐链中位数，与覆盖率件同源同值（463）。第五，清单按全国企业数排序，但「全国大」不等于「深圳该补」，优先级仍需业务判断。

## 二、计算过程

### 2.1 总体思路与数据流

三步：先算全国基准份额，再逐关键叶算深圳份额，最后按阈值判机遇。数据流是：`chain_firm_index_20261023.json` → 全国挂链 1,714,457、深圳挂链 136,326 → 基准 7.952% → 463 个关键叶的逐叶份额 → 低于基准或为零的进清单 → 按链计数。

关键叶集合直接复用覆盖件的 463 个，不重新定义。这一点很重要：如果机遇件自己定一套关键叶，两个指标的分母会漂移，读者会发现「覆盖率的分母」和「机遇率的分母」不一样。本件在脚本里读同一份 `chain_tree` 与同一份中位数规则，断言 `sum_key_leaves == 463`。

清单分两类：`blank`（深圳 0 家）52 条，`thin_share`（深圳 >0 但份额 < 7.952%）202 条。两类的业务含义不同：blank 是「完全没有」，thin_share 是「有但不够」。页面上要分开显示，因为补链策略不同——blank 要招商从零建，thin_share 要扶持现有企业做大。

### 2.2 口径定义与公式

全国基准份额：

$$
b = \frac{\sum_{\ell \in L} S_\ell}{\sum_{\ell \in L} N_\ell} = \frac{136{,}326}{1{,}714{,}457} = 7.952\%
$$

逐叶深圳份额：

$$
s_\ell = \frac{S_\ell}{N_\ell}
$$

机遇判定（关键叶集合 $K$，$|K| = 463$）：

$$
\mathrm{Opp} = \{\ell \in K : S_\ell = 0 \ \vee\ s_\ell < b\}
$$

机遇数：

$$
\mathrm{Count} = |\mathrm{Opp}| = 52 + 202 = 254
$$

机遇率：

$$
\mathrm{Rate} = \frac{254}{463} = 54.86\%
$$

敏感性口径把 $b$ 换成去重企业基准 $b' = 116{,}017 / 1{,}714{,}457 = 6.767\%$，得 227。

### 2.3 链映射规则（全批一致）

链归属取 INB 码前 7 位，12 条链与全批一致。叶节点用定长分段编码判定，954 个叶、463 个关键叶与覆盖件同源。企业挂链用 `industry_code` 精确匹配叶码，多链企业按链各计一次（§3.55）。

深圳判定用行政码前缀 4403，与 `M_CHAIN_SZ_ENTERPRISE_COUNT` 的 136,326 对齐。这个选择影响基准：若用 `admin_area` 精确匹配，深圳挂链只有 92,930，基准降到 5.42%，机遇数会明显减少。本件不用精确映射，是因为映射表只覆盖 20,000 行，43,396 条深企挂链会被判成未匹配，属于系统性漏计。

份额的分母是叶级全国企业数 $N_\ell$，不是链企业数。这一点是 §3.54 的另一面：如果用链企业数做分母，所有叶的份额之和会超过 100%，因为企业多链挂接。用叶级 $N_\ell$ 做分母，每个叶的份额独立，加总没有意义，但逐叶判定正确。本件从不对份额求和。

### 2.4 计算步骤（脚本逐步实现）

1. 读链树，取 954 个叶，按链归集；逐链取有企业叶的全国企业数中位数，标记 463 个关键叶。
2. 读企业索引，按叶码聚合全国企业数 $N_\ell$ 与深圳企业数 $S_\ell$。
3. 算全国基准 $b = 136{,}326 / 1{,}714{,}457 = 7.952\%$。
4. 遍历 463 个关键叶：$S_\ell = 0$ 记 `blank`；$0 < s_\ell < b$ 记 `thin_share`；其余不算。
5. 按链汇总 `opportunity`、`blank`、`thin_share`、`opportunity_rate_pct`。
6. 按 $N_\ell$ 降序排清单，取前 20 进文档，全量 254 条进产物。
7. 断言：`sum_opportunity == 254`、`blank + thin == 254`、`sum_key_leaves == 463`、`gap_matches_key_node_coverage_gap == true`。

第 7 步的最后一个断言是关键：机遇件的 52 个 blank 必须与覆盖件的 52 个缺口逐条相同。两个件用同一个关键集、同一个 $S_\ell$，若不一致，说明其中一个件的口径漂了。

### 2.6 关键中间量与敏感性

| 参数 | 数值 | 说明 |
|---|---:|---|
| 全国挂链 | 1,714,457 | 清洗后 |
| 深圳挂链 | 136,326 | 4403 |
| 全国基准 | 7.952% | 挂链口径 |
| 去重企业基准 | 6.767% | 116,017 / 1,714,457 |
| 关键叶 | 463 | 与覆盖件同源 |
| 空白型 | 52 | 深圳 0 家 |
| 薄覆盖型 | 202 | 份额 < 7.952% |
| 机遇数 | 254 | 52 + 202 |
| 机遇率 | 54.86% | 254 / 463 |

| 敏感性口径 | 基准 | 机遇数 | 相对主口径 |
|---|---:|---:|---:|
| 份额 5% | 5.000% | 190 | −64 |
| 去重企业 6.767% | 6.767% | 227 | −27 |
| **挂链 7.952%（采用）** | **7.952%** | **254** | **0** |
| 基准 × 1.5 | 11.928% | 220 | −34 |
| 份额 10% | 10.000% | 285 | +31 |

敏感性有两个读法。第一，基准从 7.952% 降到 5%，机遇数减少 64——收紧阈值会把「略低于平均」的环节排除，留下真正薄弱的。第二，基准升到 10%，机遇数增加 31——放宽阈值会把「接近平均」的也算进来。254 处在中间，是「份额低于全国平均」的字面执行。

去重企业口径（227）与挂链口径（254）差 27 个环节。差异来自多链企业：一家深企挂三个叶，在挂链口径里贡献 3 次，在去重口径里贡献 1 次。挂链口径更贴近「环节供给」，去重口径更贴近「企业数量」。本件选挂链，是因为机遇的对象是环节，不是企业。

### 2.7 复现代码与结果展示

```bash
cd code
python3 M_CHAIN_SZ_OPPORTUNITY_COUNT.py
# 期望末行：[ok] M_CHAIN_SZ_OPPORTUNITY_COUNT opportunity=254 blank=52 thin=202
```

脚本只读 5 份快照，零 SQL、零网络。产物 `metrics/repro/out/M_CHAIN_SZ_OPPORTUNITY_COUNT_out.json` 的 `headline` 含 8 个核心量，`by_chain` 含 12 条逐链明细，`opportunities_blank` 含 52 条空白清单，`opportunities_thin` 含 202 条薄覆盖清单，`type_breakdown` 含三类机遇的状态，`sensitivity` 含 5 个基准的对照。

复现时先看 `checks.sum_opportunity` 是否为 254；若企业索引更新，这个值会变。再看 `checks.gap_matches_key_node_coverage_gap` 是否为 true；若为 false，说明覆盖件与本件的关键集不一致，必须先对齐再发。

### 2.8 与旧稿（20261020 目录）的差异

旧稿假设 `chain_sz_opportunity` 可用，直接读条目计数。实际 gkx 侧 0 表；live 侧 8 行是未来产业种子，`opportunity_type` 与 12 链不匹配。旧稿若用这 8 行，会得到「8 条链、若干机遇」的结论，与 463 个关键叶不可比。

第二个差异是阈值。旧稿没有写阈值，隐含「模型给的都算」。本件显式给 7.952%，并把 5 个敏感性口径全部披露，读者能看到阈值选择对结果的影响。这个透明度是旧稿没有的。

第三个差异是分类。旧稿把三类机遇混在一起计数；本件只算产业发展方向一类，另两类记 blocked。混计会让读者以为 254 是总数，实际只是三分之一。这个区别必须在页面上标注。

### 3.3 数据量、覆盖与代表性

链树 954 叶、463 关键叶，与覆盖件同源。企业面 1,714,457 条挂链、136,326 条深圳挂链、116,017 家深圳去重企业。深圳份额 7.95%，这个数决定了基准，也决定了机遇数的绝对水平。

254 条清单的全国企业数分布很偏：前 10 条（软件外包 358,930、信息安全服务 213,031、影视节目制作 110,678、其他中药材种植 101,678、教育应用软件 97,453、车载信息娱乐 95,589、其他数字内容 56,792、中草药种植 47,769 等）占了大头，尾部大量环节全国只有几十家。这意味着清单的「前 20 条」覆盖了大部分产业量，尾部更适合做长尾补链参考。

政策与专利的覆盖不足是两类机遇 blocked 的直接原因。879 条深圳政策里 13 条按链命中（机器人 6、集成电路 3、人工智能 3、智能网联汽车 1），零条落到环节。169,226 件专利里 23,756 件能映射到链（14.04%），且只落首个链、无环节级。两类都无法去重成「环节清单」。

### 3.4 结构支持判定

结构侧支持：份额对照所需的链树、挂链、注册地三表齐全。数据侧部分支持：挂链量足，但政策与专利的环节级标注缺失。语义侧不支持：份额对照不是模型推荐，「相对薄弱」不等于「值得投」。

因此判档是「部分支持」。它比「完全不支持」强，因为 254 条清单可算、可解释、与覆盖件闭合；它比「完全转换支持」弱，因为只覆盖三类机遇的一类，且「机遇」的语义是统计代理。这个定位必须在判档理由里写清，不能用「已出 254 条」掩盖三分之二缺失。

### 3.5 与开发库 live 的差异

live 侧 `chain_sz_opportunity` 8 行，链名是合成生物、光载信息、量子信息、脑科学、深地深海、智能机器人、前沿新材料、未来网络，与 gkx 12 链只重名「合成生物」。`model_version` 带 `-demo`，`sz_enterprise_count` 仅 2—10 家，是手工种子。

本件在 `live_probe` 里记录了 gkx 侧链表 2 张、live 侧各表行数与样例链名。后续件若要复用这些表，必须先读探针，确认链维与数值是否可用。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 影响维度 | 当前处理 | 补齐后变化 |
|---|---|---|---|
| `chain_sz_opportunity` | 全部三类 | 份额对照代理 | 可直读条目 |
| 政策环节标注 | 政策优化类 | blocked | 可计数 |
| 专利环节标注 | 创新方向类 | blocked | 可计数 |
| 机遇优先级 | 清单排序 | 按全国企业数 | 可按模型/专家排序 |
| 机遇价值量 | 可投性 | 缺失 | 可算投入产出 |
| 经营地 | 深圳判定 | 登记地 | 可纳入分支 |

### 4.2 逐条影响

**结果表缺失是根缺口。** 没有 `chain_sz_opportunity`，就没有「机遇」的原始认定，只能用份额对照代理。代理给的是「相对薄弱环节」，不是「推荐投资环节」。两者高度相关但不重合：一个环节可能份额低但不宜投（如高污染、产能过剩），也可能份额不低但战略重要（如 EDA）。

**政策优化类 blocked 影响三分之一。** 这一类需要「政策条文 → 具体环节」的建议配对。879 条深圳政策里 13 条能按链命中，零条落到环节，无法抽出「某环节应出台什么政策」的条目。不是没有政策，是政策文本没有环节级标注。

**创新方向类 blocked 影响另外三分之一。** 这一类需要「专利主题 → 环节」的映射。169,226 件专利里 23,756 件能映射到链，且只落首个链、无环节级，无法去重成「某环节应突破什么技术」。专利申请人名匹配还有重名问题，进一步降低可用性。

**优先级与价值量缺失影响可投性。** 254 条清单只能按全国企业数排序，不能按「投资回报」排序。一个全国 300 家、深圳 0 家的环节，和一个全国 30 家、深圳 0 家的环节，前者优先级高，但后者可能是「小而关键」。这个判断需要产值、利润率、增长率，当前都没有。

### 4.3 明确不做什么（禁止的替代）

**不用 live 的 8 行样例补 12 链。** 链名、粒度、数值三者都不匹配，用它会让 11 条链无数据，属于造数。

**不用政策文件数当政策优化机遇数。** 879 条政策不能除以 12 得「每条链 73 个机遇」，政策与环节不是一对一。本件只用链级命中的 13 条做背景，不进计数。

**不用专利数当创新方向机遇数。** 169,226 件专利不能按链均分，专利与环节不是一对一，且 86% 无法映射到链。本件只披露 23,756 这个可映射数，不进计数。

**不用「叶级企业数合计 ÷ 链企业数」当份额。** §3.54 陷阱，多链企业重复计数，7 条链超 100%。本件份额的分母是叶级全国企业数，从不对份额求和。

### 4.4 若甲方补齐后的口径升级路径

第一步，拿到 `chain_sz_opportunity` 的 12 链条目，替换份额对照代理。第二步，补齐政策环节标注，恢复政策优化类计数。第三步，补齐专利主题到环节的映射，恢复创新方向类计数。第四步，接入产值/利润率，给清单加可投性排序。第五步，把深圳判定从 4403 前缀换成行政区精确匹配。

升级后本件可升为「完全转换支持」；若结果表直接可用且三类齐全，可到「完全直接支持」。当前只能停在部分支持。

## 附录 A 原文摘录（需求文档 / calc-logic）

> 深圳产业机遇数：统计深圳在产业链上可识别的发展机遇条目数。机遇分产业发展方向、政策优化、创新方向三类，按链汇总，取值非负整数。

> 1. 按 `chain_id` 定链，取 `chain_sz_opportunity` 的条目。
> 2. 按 `opportunity_type` 分三类计数。
> 3. 机遇数 = 该链三类条目数之和。

原文还写：「机遇条目由深圳机遇分析模型输出，含环节、类型、描述、优先级。」这句话说明条目是模型产出，不是 SQL 条件。gkx 侧没有这个模型的结果表，本件只能用份额对照代理，这是与原口径最大的语义差。

## 附录 C 可行性完整版

### C.1 六条路线对比

| 路线 | 数据要求 | 可得性 | 输出语义 | 适用 |
|---|---|---|---|---|
| A 份额对照 | 链树+挂链 | 可得 | 相对薄弱环节 | 本报告 |
| B 模型直读 | `chain_sz_opportunity` | 不可得 | 模型推荐 | 目标 |
| C 机器学习 | 标签+样本 | 不可得 | 预测推荐 | 不可行 |
| D 区位商 | 挂链 | 可得 | 劣势环节 | 等价 A |
| E 专家清单 | 专家时间 | 可得但不可复现 | 主观清单 | 不推荐 |
| F 政策抽取 | 政策+环节标注 | 部分可得 | 政策提及环节 | 可补充 |

### C.2 为什么用份额差而不是区位商

区位商 = 本地份额 ÷ 全国份额，小于 1 为劣势。它与「份额 < 基准」在数学上等价，但区位商是比值，读者要心算 0.94 才知道「低 6%」；份额差直接给「深企占 0.89%，全国占 7.95%」，差 7.06 个百分点，一眼能懂。本件用份额差，阈值也写成百分比，是为了可读性。

### C.3 清单怎么用

第一步，看链级计数排序，找机遇最多的链。第二步，看空白与薄覆盖的比例：空白多要招商，薄覆盖多要扶持。第三步，按全国企业数降序取前 20，这些是「大池子里深圳缺」的环节。第四步，与问题数交叉：两个指标都指向的环节优先。第五步，与政策、专利对照，确认是否有政策或技术支撑。

### C.4 结论

产业发展方向一类机遇可算，254 条有清单、有份额证据、与覆盖件的 52 个缺口闭合；但政策优化与创新方向两类因缺环节级标注无法计数，254 只是三分之一。判**部分支持**是准确的：不是「算不出」，而是「只算出了三类里的一类」。
