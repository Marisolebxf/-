## 摘要

区域政策覆盖率想回答「这条链在这个城市被政策覆盖了多少」。旧稿公式是 `Cov(c,r)=Σ hit_i/(hit_i+5)/|L1(c)|×100%`，命中按 L1 环节的实体词在政策标题里做子串匹配，政策池是「城市=r 的政策 ∪ 国家级政策」。公式本身是可执行的，问题全在数据形态。

`gkx.dwd_policy_base` 正好 20,000 行，是存量表，不是增量表；只有 title、date、city、level 等字段，没有正文。`theme` 非零仅 2 行，`keypoints` 全空，所以「主题覆盖」这条路径完全不可用，本件只能做标题词命中。2021 年及以后只有 2,410 行，按年截断会把广州政策池从 2,499 砍到 157，覆盖率整体塌到 2.98%。

实测 12 链 × 4 市 = 48 个格子，覆盖率均值 17.18%、中位 16.67%、最高 58.33%（机器人×深圳），16 个格子为 0。连续值没有触顶，但二值口径已有 20/48 个格子 100%（链路只要命中 1 条就算覆盖），说明区分度主要来自「命中几条」而不是「覆盖/不覆盖」。

## 一、需求定义概述

### 1.1 所属功能模块

政策覆盖率挂在产业链区域对比页，用 12 链 × 4 市的热力图展示「哪条链在哪个城市政策供给更密」。它不评价政策力度，只评价覆盖面；页面上的颜色深浅对应覆盖率，点击格子下钻到命中的政策标题列表。

它同时是「政策供给」子指数的输入之一。覆盖率与政策条数不同：条数看总量，覆盖率看「环节是否被覆盖」，后者更接近「政策是否有针对性」。但两者都受政策库采集范围影响，不能直接跨城市比较绝对水平。

### 1.2 为什么需要政策覆盖率

产业链政策往往按环节出台：集成电路有材料、设备、设计、制造、封测五个环节，某个城市可能只覆盖其中两个。只看政策总数会掩盖结构差异，覆盖率把「覆盖了哪些环节」显性化，帮助判断政策是「全面撒网」还是「重点突破」。

它也能暴露政策空白。合成生物、具身智能、低空经济在 4 市全部为 0，这不是说这些城市没有相关政策，而是说政策标题里没有出现对应实体词。这个区别很重要：0 可能是「真空白」，也可能是「词表没覆盖」，本件在产物里没有把 0 解释成前者。

### 1.3 需求文档是否给出定义方法

需求文档只写「分析区域政策对产业链的覆盖情况」，没有给公式。公式来自 calc-logic v0.2.0：L1 环节词命中、`hit/(hit+5)` 饱和函数、按 L1 数量平均。这个设计的好处是「命中越多边际越低」，避免一个高频词把整条链拉满；坏处是 hit=1 就贡献 1/6，链路少时仍会快速抬高。

本件没有改公式，只改数据源与池定义：国家级政策用 `level=4` 识别（2,174 行，city/province 全 NULL），城市用中文全称精确匹配。旧稿用 `rank` 字段判国家级，但 gkx 没有 `rank`，只有 `level`，这是换源时必须改的。

### 1.4 权威机构方法可行性

政策文本量化通常有三条路：词典/关键词命中、主题模型、人工编码。词典法可解释、可复现，但覆盖受词表限制；主题模型能发现未预设的主题，但结果不稳定、难以解释；人工编码质量高，但 20,000 条规模下成本不可接受。本件选词典法，与旧稿一致。

覆盖率作为「政策供给」的代理，在文献里常见于政策强度/政策注意力研究。它们的共同前提是「有正文可分词」。本件只有标题，等于把「正文覆盖」降级为「标题提及」，这是语义缺口，不是数据量缺口。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A. 词典/关键词命中 | 政策文本量化 | 实体词子串匹配 | 高（本件采用） |
| B. 主题模型 | LDA/BERTopic | 主题概率 | 低（无正文） |
| C. 人工编码 | 专家打分 | 逐条阅读 | 不可行（20,000 条） |
| D. 政策力度评分 | PMC 指数 | 多维度打分 | 不可行（字段不足） |

### 1.6 推测原意与依赖维度

推测原意是给区域政策比较一个「结构覆盖」指标，而不是评价政策好坏。它要回答的是「这个城市在这条链的哪些环节有政策」，不是「政策力度多大」。因此标题命中是可接受的粗口径，但必须披露「只到标题」。

依赖维度拆成四层：D1 政策底表（有，20,000 行）；D2 正文/主题（无，theme 全空）；D3 链树 L1（有，41 个）；D4 城市/级别（有，city 9,706 行为 NULL，level 4 可识别国家级）。D1/D3/D4 可用、D2 缺失，所以判部分支持。

## 二、计算过程

### 2.1 方法选择：标题命中而非正文

第一个决策是「没有正文时还要不要做覆盖率」。若不做，整个指标归零；若做，只能命中标题。本件选后者，因为标题通常包含政策对象与环节（「集成电路设计企业」「低空经济产业园」），比正文更集中；代价是漏掉标题泛化、正文具体的政策。

第二个决策是池定义。旧稿的「城市 ∪ 国家级」是对的，但国家级识别必须换字段：gkx 没有 `rank`，`level=4` 才是国家级（2,174 行，city/province 全 NULL）。若误把 `level=3` 当国家级，会把 9,922 行省级/市级政策混进所有城市池，覆盖率整体虚高。

| 指标 | 实测值 |
|---|---|
| 政策行数 | 20,000 |
| 城市 NULL | 9,706 |
| 国家级 level=4 | 2,174 |
| 主题非零 | 2 |
| 2021+ 行 | 2,410 |
| L1 环节 | 41 |
| 链×城格子 | 48 |
| 深圳/广州/东莞/惠州池 | 3,053 / 2,499 / 2,182 / 2,174 |

### 2.2 步骤 1：L1 环节抽取

链树 1,273 节点，`parent_code` 字段不可靠——它存的是顶层链名，不是直接父节点，按它取子节点会把 91 个后代全算成 L1。本件改用码长：链码 7 位，L1 码 9 位（7+2），取 `len(code)=9` 且前缀匹配链码的节点，12 条链共 41 个 L1。

41 个 L1 分布不均：集成电路 6 个、传感器 4 个、低空经济 4 个，软件/人工智能/机器人各 3 个。L1 数量直接决定分母，链路多的链覆盖率天然更难拉高，这是公式的结构性偏差，产物里保留 `n_links` 供解释。

| 统计量 | 值 |
|---|---|
| 覆盖率均值 | 17.18% |
| 中位 | 16.67% |
| 最高 | 58.33% |
| 最低 | 0% |
| 为 0 格子 | 16 |
| 二值 100% 格子 | 20 |
| 不同覆盖率取值 | 17 |

### 2.3 步骤 2：词表与泛词回退

每个 L1 环节先查 `LINK_SPECIFIC` 词表；没有专属词的泛词环节（基础层/技术层/零部件/整机制造等）回退到链级领域词，并标 `token_source=chain_fallback`。回退会抬高覆盖，因为链级词在标题里更常见；本件另跑 strict（泛词不给词）作下界，深圳从 23.76% 降到 10.39%。

strict 与主口径的差就是「泛词回退」的贡献。这个差不是误差，而是口径选择：如果甲方认为「基础层」不该用「人工智能」代替，就应该用 strict；如果认为「只要标题提到这条链就算覆盖」，就用主口径。本件默认主口径，与旧稿一致。

### 2.4 步骤 3：48 个格子的结果

覆盖率最高的是机器人×深圳 58.33%（3 个 L1、21 次命中），其次是智能网联汽车×深圳 53.28%、人工智能×深圳 50.00%。最低的 16 个格子为 0，集中在合成生物、传感器、具身智能、低空经济——这四条链的 L1 词在 4 市政策标题里几乎没有出现。

城市维度上，深圳池 3,053 条、广州 2,499、东莞 2,182、惠州 2,174；池越大覆盖率不一定越高，因为分母是 L1 数而不是池大小。惠州与东莞的覆盖率经常完全相同，说明两地地方政策差异很小，池差主要来自国家级政策的统一加入。

### 2.5 步骤 4：饱和与区分度

`hit/(hit+5)` 在 hit=1 时给 1/6，hit=5 时给 0.5，hit=20 时给 0.8。链路只有 3 个 L1 时，只要每条各命中 1 条，覆盖率就是 16.67%；这也是大量格子落在 16.67 的原因。连续值最高 58.33%，没有触顶，但二值口径已有 20/48 个格子 100%。

这说明覆盖率主要区分「有没有命中」，而不是「命中多少」。若甲方要更强的区分度，可以把饱和常数从 5 调大（如 20），但这会改变公式，需重新裁定。本件没有擅自改。

### 2.6 步骤 5：时间与截断敏感性

政策库是存量表，按 2021—2024 截断会把广州池从 2,499 砍到 157、深圳从 3,053 砍到 431，四市平均覆盖率从 17.18% 塌到 1.26%—8.04%。这不是政策真实变化，而是把存量表误当增量表。本件在 sensitivity 里复现了这个塌陷，明确拒绝按年截断。

政策库 2021 年后只有 2,410 行（12.05%），2022 年 289 行、2024 年 1 行，采集明显不完整。因此本件不能做「政策增量」或「年度覆盖率趋势」，只能做存量截面。

### 2.7 步骤 6：口径边界

覆盖率不能解释为「政策力度」或「政策效果」。一条标题命中可能只是「提及」，也可能是「专项支持」，两者在标题层面无法区分。它也不能跨城市比较绝对水平，因为政策库采集范围、城市命名、国家级政策的加入方式都会影响池大小。

另一个边界是「0 不等于空白」。合成生物在 4 市为 0，可能是因为政策标题用了「生物制造」「合成生物学」等不同词，而词表只有「合成生物」「生物制造」。产物保留 `tokens` 与 `hits`，就是为了让读者判断 0 是「真没有」还是「没匹配上」。

cd 20261021 批调研区（成果已实物化入 metrics/ 与 METRIC-SRS-GAP-L01/产物/）

### 2.8 步骤 7：复现与产物

脚本只读政策快照与链树快照，不连库；`python3 M_CHAIN_REG_POLICY_COVERAGE.py` 覆盖写产物。`cells` 是 48 行明细（链、城市、池大小、覆盖率、二值率、L1 数、命中数），`per_chain` 是 12 条链的四城均值，`sensitivity` 含 strict、截断、去国家级三组对照。

### 2.8 参数登记与验收

为了让复核者不必读脚本就能判断口径，本件把关键参数、取值与依据集中登记如下。任何一项变更都会改变结果，必须重新跑并更新产物。

| 参数 | 取值 | 依据/影响 |
|---|---|---|
| 覆盖率公式 | Σ hit/(hit+5)/|L1|×100% | calc-logic v0.2.0 |
| 饱和常数 | 5 | hit=1 贡献 1/6 |
| 政策池 | 城市政策 ∪ 国家级 | 国家级 = level 4 |
| L1 识别 | 码长 9 且前缀匹配 | parent_code 不可靠 |
| 命中方式 | 标题子串 | 无正文 |
| 泛词回退 | 链级领域词 | strict 敏感性关闭 |
| 时间口径 | 存量全量 | 拒绝按年截断 |
| 二值口径 | hit≥1 即覆盖 | 仅对照 |

饱和常数 5 是公式里最敏感的参数：hit=1 给 0.167、hit=5 给 0.5、hit=20 给 0.8。它决定了「命中几条算覆盖」的边际；本件没有改，因为改了就与旧稿不可比。

L1 识别用码长而不是 parent_code，是因为后者存的是顶层链名。这个修正会让 L1 数从「91 个后代」降到 41 个，分母更合理；但它依赖链码规则（7+2），若链树改版，规则要同步。

## 三、数据支撑情况

本件按「政策底表 / 正文语义 / 链树 / 城市与级别 / 时间覆盖」五个维度核对。底表与链树可用，正文与时间覆盖是主要缺口。

| 依赖维度 | 实测状态 | 关键证据 | 缺口与修复路径 |
|---|---|---|---|
| 政策底表 | 完整 | 20,000 行，存量 | 无需修复 |
| 正文/主题 | 缺失 | theme 非零 2 行、无正文 | 接政策正文并分词，或接受标题口径 |
| 链树 L1 | 可用 | 41 个，按码长取子节点 | 修正 parent_code 字段 |
| 城市/级别 | 部分 | city NULL 9,706；level 4 国家级 2,174 | 补城市标准化与级别字典 |
| 时间覆盖 | 弱 | 2021+ 仅 2,410 行 | 补采 2021—2024 政策 |

正文缺口的修复成本最高：需要接政策全文、清洗、分词，再重跑覆盖率。若短期做不到，建议把指标名改成「政策标题覆盖率」，并在页面注明「仅标题命中」，避免被读成「政策内容覆盖」。

城市字段的 9,706 行 NULL 里，一部分是国家级（level 4，2,174 行），其余是省级/其他。本件用 `level=4` 识别国家级，但没有把省级政策分到下属城市，因此广州/东莞/惠州的池只含本市 + 国家级，不含广东省政策。这会让地级市覆盖率偏低，是已知缺口。

时间覆盖缺口不影响截面结论，但影响任何「政策增量」用法。建议补采 2021—2024，至少让每年行数接近 2019—2020 的水平（约 2,000 行/年），否则年度覆盖率会剧烈波动。

### 3.9 缺口优先级

缺口不是同等重要。本件按「是否阻断指标成立」把缺口分三档：阻断（指标算不出）、扭曲（算得出但结论会反）、披露（不影响本期结论但影响外推）。优先级如下。

| 优先级 | 缺口 | 阻断/扭曲/披露 | 处理 |
|---|---|---|---|
| P0 | 只有标题 | 阻断（语义） | 改名/接正文 |
| P1 | 2021+ 仅 2,410 行 | 扭曲 | 补采 |
| P1 | 省级政策未归属 | 扭曲 | 建省→市映射 |
| P2 | city NULL 9,706 | 披露 | 补城市字典 |
| P2 | theme 全空 | 披露 | 不声称主题 |
| P3 | 泛词回退 | 披露 | strict 对照 |

只有标题是语义级阻断：它不妨碍算出数，但妨碍把数叫「政策覆盖」。若甲方接受「标题提及」，P0 降为披露；若不接受，指标必须等正文接入。

2021+ 行数少是扭曲级：按年截断会让覆盖率从 17.18% 塌到 1—8%，这不是政策变化，是采集断层。本件拒绝截断，就是为了避免这个假信号。

## 四、数据缺失情况

政策覆盖率的缺失以「字段有但语义不足」为主，不是行数不够。

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| 政策正文 | 只能标题命中 | 标题词表 | 接全文 |
| theme/keypoints | 主题覆盖不可算 | 不声称主题 | 补字段 |
| 省级政策归属 | 地级市池偏小 | 只用本市+国家级 | 建省→市映射 |
| 2021+ 政策 | 无法做增量 | 只用存量 | 补采 |
| 城市标准化 | 9,706 行 NULL | level 4 识别国家级 | 补城市字典 |

最需要警惕的是「0 覆盖率」被当成「政策空白」。本件在 16 个 0 格子里，至少有一部分是词表没覆盖（如合成生物的「生物制造」），不是真的没有政策。产物保留每个 L1 的 tokens 与 hits，读者可以判断。

第二类是国家级政策的双重计入：每个城市的池都包含同样的 2,174 条国家级政策，这会压缩城市间差异，尤其是东莞/惠州这种地方政策很少的城市。若甲方要「地方政策覆盖」，应使用 `local_only` 敏感性（产物已给），而不是主口径。

### 4.9 处置原则

对缺失的处置遵循三条：不补 0、不静默填充、不把模型产物当数据真值。能算的算，不能算的输出 null 并写原因；任何代理都必须在字段名与页面文案上标注「代理」。

第二条是不做「看起来完整」的补齐。缺失年份不插值、缺失城市不摊派、缺失分项不按均值填；这些操作会让下游误以为数据齐全，比 null 更危险。

第三条是可复现优先。所有外部输入都落快照，快照带来源、时间、行数；脚本只读快照，重跑不依赖网络。这样即使源库变化，历史结论仍可复算。

## 附录 G 口径问答

**问：为什么广州/东莞/惠州的覆盖率经常一样？**

答：三城的池都包含同样的国家级政策，地方政策差异又小；机器人/智能网联的 L1 词在四城标题里命中数相同，所以覆盖率相同。

**问：0 覆盖率是不是政策空白？**

答：不一定。合成生物、传感器的词表很窄，标题可能用「生物制造」「感知器件」等词；0 可能是「没匹配上」，产物保留 tokens 供判断。

**问：为什么不用政策条数代替覆盖率？**

答：条数看总量，覆盖率看环节结构。某城可能有 1,000 条政策但只覆盖 1 个环节；条数会把它排前，覆盖率不会。

**问：二值 100% 为什么这么多？**

答：二值只看「有没有命中」，链路只要 1 条命中就是 100%。它适合回答「有没有」，不适合回答「多不多」；主口径用连续值。

**问：能不能做年度趋势？**

答：不能。2021+ 只有 2,410 行，2024 年 1 行；按年截断会造出假下跌。

**问：strict 口径差多少？**

答：深圳从 23.76% 降到 10.39%，四城均值约降一半。差就是泛词回退的贡献；是否采用取决于甲方是否接受「链级词代环节词」。
