## 摘要

「高价值环节占比」的分母很好算：链树叶级 954 个环节，逐链 28—186 个。分子算不了：需求要的是「附加值高、技术门槛高、议价能力强」的那些环节，而这三件事在库内没有任何字段。

gkx 链树共 17 列，其中业务列 8 个：`industry_code`、`industry_name`、`industry_link_code`、`industry_link_name`、`parent_code`、`parent_name`、`level`、`node_company_count`；另 9 列为系统列（主键、时间戳、软删除标记等）。8 个业务列里，`node_company_count` 是唯一带「量」的列，但它**全表 1,273 行恒为 0**（`SUM(>0)=0`、`MAX=0`），不是稀疏而是空壳；`level` 同样恒为 0。也就是说，连「退而求其次用企业数当代理」这条路在数据上也不成立——不是「代理不准」，而是「代理值不存在」。

旧稿尝试用「节点企业数 ≥ 阈值」作高价值代理，结果分子分母都不成立：分子 100% 空、比率无法计算。本报告不重复这条路径。

结论：本指标必须由甲方**报送环节价值标注**（每个环节一个价值等级或附加值率），否则永远算不出。判**完全不支持**，属 B 类。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块是**产业链分析 → 产业链图谱 → 价值链分析**。页面是一个占比环：这条链的高价值环节占多少；点开是环节清单，高价值环节高亮。

配套的是「招商靶点面板」：高价值且本地薄弱的环节优先招引。这个面板的两个条件（高价值、薄弱）里，「高价值」正是本件缺的那一半。

### 1.2 为什么需要这个指标

第一，它是「微笑曲线」的落地形态。产业链上不同环节的附加值差十倍以上（组装 5%、设计 40%），只看环节数量会得出「链条很完整」的错误结论——完整但都在低端。

第二，它是招商决策的依据。「本地缺什么环节」和「本地缺什么高价值环节」是两个完全不同的问题，后者才决定财政投入的回报。

第三，它是政策对账的口径。深圳 20+8 里的「高端化」表述，需要一个可量化的「高价值环节占比」来支撑；没有这个数，「高端化」只能停留在定性描述。

### 1.3 需求文档是否给出定义方法

**没有。** 需求只有指标名与一句「高价值环节占全部环节的比例」。没有定义「高价值」，也没有给出判定规则。

这个缺失比「缺数据」更根本：即使给了一张带 `importance_level` 的表，若不同人对其枚举（如 1=核心、2=重要、3=一般）理解不同，算出的占比也会差一倍。因此本件的第一需求不是数据，是**定义会签**。

### 1.4 类似指标权威机构构建方法可行性分析概要

| 方法族 | 代表机构/文献 | 口径要点 | 与本指标的差 | 贴合度 |
|---|---|---|---|---|
| A 微笑曲线分段 | 施振荣（1992）；Porter 价值链 | 按研发—制造—品牌分段判附加值 | 分段是抽象活动，需人工映射到 954 个环节 | 高（理论）/低（可算） |
| B 附加值率核算 | 国家统计局增加值率；OECD TiVA | 环节增加值 / 环节总产值 | 需环节级产值与中间投入，库内均无 | 高（口径）/零（可得） |
| C 技术密集度 | OECD KET；专利密度 | 按研发强度或专利密度分档 | 无「环节—专利」键，专利挂不到环节 | 中 |
| D 政策清单 | 工信部产业基础再造「卡脖子」清单 | 按官方清单认定关键环节 | 清单不公开到 954 个环节粒度 | 中（可作锚点） |
| E 议价能力指标 | 产业组织学（HHI/CRn） | 集中度高则议价强 | 集中度≠附加值（组装也集中） | 低 |

**三句结论**：① 语义最贴 B 族（附加值率），它是唯一能量化的口径；② B 族需要环节级产值与中间投入，库内两者都没有；③ 因此本件只能落到「甲方报送价值标注」，属 B 类。

### 1.6 本报告的口径与边界（推测定义，须与甲方会签）

推测定义：**高价值环节占比 = 被标注为高价值的叶级环节数 / 该链全部叶级环节数**。「高价值」的判定标准由甲方给定（建议用附加值率 ≥ 某阈值，或政策清单锚定）。

边界：① 不用企业数代理价值（企业多 ≠ 附加值高）；② 不用集中度代理（集中 ≠ 高价值）；③ 不按 L1 大段判价值（粒度太粗，41 个 L1 里几乎全会被标成高价值）；④ 分母固定为叶级 954（与完整度、集中度同源）。

## 二、依赖性质裁定（为什么必须外部数据）

### 2.1 本指标需要什么形态的数据

分子需要一张「环节 → 价值等级」的标注表：每个 `industry_code` 一个等级（或一个附加值率数值）。这张表有两个特点：① 它是**判定结果**，不是可聚合的原始数据；② 它的粒度必须与链树一致（叶级），否则分子分母对不上。

分母已经有了：链树叶级 954 个环节。所以本件缺的不是「数据量」，是「判定」。

### 2.2 gkx 里到底有什么（逐列探测）

`gkx.dwd_industry_chain_info` 的全部列：

| 列 | 类型 | 是否可用于判价值 |
|---|---|---|
| `industry_code` | varchar | 否（标识） |
| `industry_name` | varchar | 否（名称） |
| `parent_code` | varchar | 否（父子关系，且存的是名称） |
| `level` | int | 否（层级） |
| `node_company_count` | bigint | 否（企业数，且全表恒为 0） |

八个业务列里没有一列与「价值」相关。`node_company_count` 是最容易被误用的：它的名字像「这个环节有多少企业」，实际全表恒为 0；退一步说，即便它填满，度量的也是集聚度而非附加值。

### 2.3 最近的替代面为什么不可用

候选替代有三个，逐一排除：

**其一，`node_company_count`。** 实测全表恒为 0，本身不可用；即便假设它填满，用「企业数 ≥ 阈值」判高价值也会得出荒谬结论：组装环节企业最多（因为门槛低），按此规则会把组装判成最高价值环节，与微笑曲线完全相反。

**其二，集中度（HHI/CR1）。** 集中度高说明环节内企业少而大，议价能力可能强；但高度集中的环节也可能是低附加值的资源型环节（如原材料）。集中度与附加值没有稳定对应关系。

**其三，专利密度。** 技术密集度是附加值的重要来源，但需要「环节—专利」键，而库内专利只有 IPC 与申请人名称，没有环节码。前一版报告已证明该键不存在（见 `M_CHAIN_REG_PATENT` §4.1）。

### 2.4 若强行用会得到什么假数

假设用「企业数前 30% 的环节」作高价值，会得到每链约 8—56 个「高价值环节」，占比稳定在 30% 左右。这个数字看起来很合理，但它与「附加值」毫无关系：它是企业集聚度的另一个说法，与 `M_CHAIN_KEY_NODE_COUNT` 高度重复。

更糟的是它会误导招商：按此规则，组装环节会被列为高价值靶点，而真正的设计、材料环节因企业少被列为低价值。这与政策方向完全相反。

### 2.5 裁定

本指标依赖「环节价值判定」，该判定在 gkx、开发库、任何可推导路径中都不存在，且不能用集聚度/集中度/专利密度替代（替代会产生方向性错误）。按依赖性质三分法，属 **B 类（不可重建，须外部报送）**。

表级证据统一引用 `_work_gkx21/TABLE_ABSENCE_EVIDENCE.md`，避免「库内无表」只靠本报告自述：

- **§`industry_chain_metric_fact`**：精确同名不存在，词根候选只有 `dwd_industry_chain_info` 与 `dwd_industry_chain_news_info` 两张——前者 8 个业务列已在本节逐列排除（无价值列），后者是资讯文本。证据块对该簇的提醒是「应用层汇总表库内没有属正常，应先用 gkx 原始表重建」，本件照此把三条替代面（企业数、集中度、专利密度）逐一试过并排除（§2.3），重建路径不成立后才保留下面的裁定。
- **§`chain_market`**：精确同名不存在，词根候选 0 张。这条排除了「用市场规模或市场份额间接反映环节价值」的退路——市场规模是需求侧总量，不区分环节附加值高低。

两条合起来说明：本件缺的不是「一张还没找到的表」，而是「一个尚未被生产出来的判定结果」。这也是它属 B 类而不是 A 类的书面依据。

推翻本裁定的条件：甲方提供叶级环节的价值等级标注（或附加值率），或公开的卡脖子环节清单可细化到 954 个环节粒度。

### 3.2 数据量、覆盖与代表性

分母覆盖完整（954 个叶级、12 条链全有）。分子覆盖为 0：没有任何一个环节带价值标注。这是「零覆盖」而非「低覆盖」，无法计算任何形式的比率。

### 3.3 结构支持判定

结构上，本指标需要的是「标注表」这种形态（环节码 + 等级），而 gkx 的全部表都是「实体 + 属性」结构，属性里没有价值维度。这是数据模型层面的缺失。

### 3.4 与开发库 live 的差异

开发库同样没有环节价值标注。若 live 侧有「高价值环节」结果，其来源必然是外部报送或人工标注，不在本库数据链内。

## 四、数据缺失情况

### 4.1 缺口清单

| 缺口 | 影响面 | 处置 |
|---|---|---|
| 无「高价值」定义 | 无法判定，也无从会签 | 甲方定义（附加值率阈值或清单） |
| 无环节价值标注 | 分子为 0 | 报送叶级标注表 |
| 无环节级产值/中间投入 | 附加值率算不出 | 需企业营收按环节分摊 |
| 无环节—专利键 | 技术密集度算不出 | 见专利件缺口 |

### 4.2 逐条影响

定义缺失是第一位的：没有定义，即使有标注也无法验收（不同人对「高价值」理解不同）。

标注缺失决定分子为 0：比率无法计算，页面只能显示「暂无」。

产值与中间投入缺失决定「附加值率」这条最正的口径走不通；专利键缺失决定「技术密集度」这条次优口径也走不通。

### 4.3 明确不做什么（禁止的替代）

- 不用 `node_company_count` 或企业数代理价值——方向性错误（组装会最高）。
- 不用集中度代理价值——集中不等于高附加值。
- 不用 L1 大段判价值——粒度过粗，几乎全会被标高。
- 不把「占比 30%」这类由阈值造出的数当结果——那是阈值参数，不是数据。

### 4.4 若甲方补齐后的口径升级路径

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 甲方给出叶级价值等级标注 | 分子可算，比率成立 | 可升格至完全转换支持 |
| 甲方给出附加值率阈值 + 环节产值 | 可按附加值率判 | 可升格 |
| 提供可细化到环节的卡脖子清单 | 可用清单锚定，覆盖率有限 | 可升格至部分支持 |
