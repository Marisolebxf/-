## 摘要

链热门资讯数回答的是「这条链最近有多少条真正被市场追着看的资讯」。旧稿把它定义成 heat_score ≥ 全库 P90 的条数，问题是 gkx 的 `dwd_industry_chain_news_info` 只有 pk_id、industry_code、industry_name、title、publish_date、source 六列，heat_score 不是稀疏、而是根本不存在。本件不伪造这个字段，改用三个可观测替代量组成 0—3 分的热度代理：同一归一化标题被 ≥2 个 source 报道、所在 ISO 周全库资讯量 ≥P90、标题命中高显著度词。

实测底表 108,052 行、206 个 source、107,347 个不同标题，覆盖 2025-02-01 至 2026-07-27 共 72 个 ISO 周；周量 P90 为 2,412 条，峰值 3,441 条。三项相加后，全库分布为 0 分 66,148 条、1 分 36,689 条、2 分 5,148 条、3 分 67 条；按「严格大于 P90（≥2）」取热门，共 1,972 条，占 1.83%。

链归属是第二个坑。industry_code 是 JSON 数组，105,407/108,052 行是多值，平均 20.11 个码/行，52,057 行被 varchar(255) 截断；按数组计数时 12 条链里有 3 条直接为 0、非零链最大/最小比 371.24，与标题口径的 Spearman 仅 0.338。本件改用标题命中链级实体词表做主口径，覆盖 31.89% 的资讯，未覆盖部分不进分子也不补 0。

## 一、需求定义概述

### 1.1 所属功能模块

「链热门资讯数」挂在产业链概览页的「热门资讯」卡片和链详情资讯流的排序位。它不展示单条资讯，而是给每条链一个规模数：这条链当前有多少条够热的资讯。页面用它做两件事：一是卡片上的「本期热门 N 条」，二是与「资讯总量」并排，让用户判断这条链的资讯是「多而热」还是「多而冷」。

这也决定了它的口径必须是去重后的资讯条数，而不是转载行数。同一标题被十家媒体转载，只能算一个事件面；但在热度代理里，转载恰恰是「热」的证据。两者不矛盾：计数按归一化标题去重，热度按转载源数加权。本件把这两层分开，避免把「转载多」直接当成「条数多」。

### 1.2 为什么需要这个指标

资讯是产业链监测里更新最快的一层。企业数、专利数、营收这类存量指标按年变，资讯按天变，它能提前反映链上的异动：头部企业发布新品、地方出台专项政策、初创公司拿到融资，都会先在资讯里出现。热门资讯数把这个信号压缩成一个可比较的规模量，供「今天先看哪条链」的排序使用。

它同时是资讯质量的健康检查器。如果一条链资讯总量很高但热门数为 0，说明它的资讯以通稿、转载、低显著度内容为主；反过来，总量不大但热门占比高，说明这条链的报道更集中、更有事件驱动。这个比值比单看总量更有解释力，因此本件在产物里同时落 `n_items`、`n_hot` 与 `hot_share_pct`。

### 1.3 需求文档是否给出定义方法

需求文档只写「展示产业链热门资讯」，没有定义热度，也没有给阈值。旧稿的 heat_score 来自 demo 侧的结果面，gkx 没有对应字段。口径细稿用「≥全库 P90」定义热门，但 P90 的对象是 heat_score，不是资讯条数；把 P90 直接套到条数上会变成「取资讯量最大的 10% 天」，语义完全不同。

本件因此做了两层拆分：先定义每条资讯的可观测热度分，再按分数阈值取热门。分数阈值取 2（三项中至少两项成立），理由是三项全库 P90 都等于 1，严格大于 P90 等价于 ≥2；这样既保留了「高于全库九成」的原意，又避免阈值并列把 38.9% 的资讯都算成热门。三项等权是本件自定义，需甲方确认。

### 1.4 权威机构方法可行性

热度/显著性计数在文献里通常归入「媒体显著性」（media salience）家族：用报道量、版面位置、转载源数、标题强度等可观测变量代理「被关注程度」。它的共同前提是有一个可核验的报道集合，且转载能被识别。gkx 的资讯表满足前者（108,052 条带 source 与日期），部分满足后者（标题可归一化，但同一事件的不同标题无法聚类）。

另一族是「事件研究」（event study）：先聚类成事件，再按事件窗口内的异常报道量打分。本件没有事件簇 id，做不了严格的事件研究，只能退到「单条资讯 + 转载源」的显著性代理。这是方法论上的降级，不是数据量的问题，因此不能判完全转换支持。

| 方法族 | 代表机构/文献 | 核心构架 | 与本指标贴合度 |
|---|---|---|---|
| A. 媒体显著性计数 | 传播学显著性研究 | 报道量/转载源/标题强度合成 | 高（本件采用） |
| B. 事件研究 | 金融事件研究 | 先聚类事件，再看窗口内异常报道 | 中（无事件簇 id） |
| C. 主题模型热度 | LDA/BERTopic | 主题概率加权 | 低（无可解释阈值） |
| D. 结果面直查 | 旧稿 heat_score | 库内现成分数 | 不可行（字段不存在） |

### 1.6 推测原意与依赖维度

推测原意是给「哪条链今天值得看」一个排序键，而不是做严格的传播效果测量。因此它需要的是**相对热度**：同一时点、同一库内，哪些资讯比其他资讯更热。绝对热度（阅读量、转发量）在库内没有任何来源，也不在当前接入范围。

按这个原意，依赖维度可以拆成三层：D1 资讯底表（有，108,052 行）；D2 链归属（部分，标题词表 31.89%）；D3 热度信号（代理，转载/周量/显著度）。三层里只有 D1 是完整的，D2 有覆盖缺口，D3 是语义降级，所以最终判部分支持。

| 代号 | 依赖维度 | 类型 | 本件实测 |
|---|---|---|---|
| D1 | 资讯底表 | A 类 | 108,052 行，6 列，完整 |
| D2 | 链归属 | B 类 | 标题词表 31.89%，数组口径不可用 |
| D3 | 热度信号 | B 类 | 三项代理，权重自定义 |
| D4 | 去重键 | B 类 | 归一化标题，107,347 个 |

## 二、计算过程

### 2.1 方法选择：代理而不是伪造

第一步不是算，而是决定「没有 heat_score 时还能不能叫热门资讯数」。两条路：一是把资讯条数当热度，直接取周量 P90；二是构造单条资讯的可观测热度分。前者会把「某天资讯多」误当「某条资讯热」，后者至少保留了「这条资讯本身是否被多家转、是否在峰值周、标题是否强」三个信号。本件选后者，并把三项等权写进产物，供甲方复核。

代理的边界必须说清：它测的是「报道显著性」，不是「读者触达」。一条被 206 家媒体转载的公关稿会得高分，一条只在行业小站发布但被决策者看到的深度报道会得低分。这个偏差无法用现有数据修正，因为库内没有阅读/转发/停留时长。

| 指标 | 实测值 |
|---|---|
| 资讯行数 | 108,052 |
| 时间窗口 | 2025-02-01 — 2026-07-27 |
| source 数 | 206 |
| 不同标题 | 107,347 |
| ISO 周数 | 72 |
| 周量 P90 / 峰值 | 2,412 / 3,441 |
| 多值 industry_code 行 | 105,407（97.55%） |
| 数组截断行 | 52,057（48.18%） |
| 平均码数/行 | 20.11 |
| 标题词表覆盖 | 34,455 行（31.89%） |

### 2.2 步骤 1：热度三项与阈值

I_reprint 看归一化标题的 distinct source 数，≥2 记 1；I_burst 看该资讯所在 ISO 周的全库条数是否 ≥P90（2,412），是记 1；I_salience 看标题是否命中 19 个高显著度词（突破/首次/全球首/最大/融资/获批等），命中记 1。三项相加得 0—3。

阈值取 ≥2。全库三项的 P90 都等于 1，严格大于 P90 就是 ≥2；这样热门占比 1.83%，不会被阈值并列冲成三成。若甲方要求「Top 10%」，把阈值降到 ≥1 会得到 41,904 条（38.78%），但那是另一个口径，不能混用。

| 热度分 | 资讯数 | 占比 |
|---|---|---|
| 0 | 66,148 | 61.22% |
| 1 | 36,689 | 33.96% |
| 2 | 5,148 | 4.76% |
| 3 | 67 | 0.06% |
| ≥2（热门） | 1,972 | 1.83% |

### 2.3 步骤 2：链归属为什么不用 industry_code

数组口径的实测结果很难看：12 条链里 INB1306、INB1333、INB1209 直接为 0（码根本没进数组），具身智能 82,416、人工智能 52,223、机器人 37,326，非零链最大/最小比 371.24。原因是 industry_code 存的是「这条资讯可能涉及的所有链」，不是「这条资讯属于哪条链」，而且 48.18% 的行被截断。

标题词表按链级实体词匹配，覆盖 31.89% 的资讯；剩余 68.11% 无法归属，产物里单列 `chain_unmapped_rows`，不按比例摊派、也不补 0。多链命中 4,457 行，按链重复计入，与旧稿「一条资讯可属多链」一致。

### 2.4 步骤 3：逐链计数与稳定性

12 条链的 n_items 合计 39,183（含多链重复），热门 1,972 条。人工智能以 20,710 条资讯、1,013 条热门居首；具身智能热门占比最高（7.69%），生物医药次之（10.23%）；数字创意最低（2.07%）。这些差异既反映报道结构，也反映词表覆盖差异，不能直接当「链热度排名」。

稳定性方面，周量峰值出现在 2026-03（11,089 条），谷值 2026-02（11 条），月份分布极不均匀；2025-12 至 2026-02 有明显断档。热门数对窗口敏感，不能做跨期同比。

### 2.5 步骤 4：与资讯总量的关系

热门占比的分母是该链被词表命中的资讯数，不是全库资讯数。因此「热门占比高」可能是分子大，也可能是分母小。生物医药只有 1,075 条命中却出了 110 条热门（10.23%），而人工智能 20,710 条命中出 1,013 条（4.89%）；前者更像「小池子里的高强度报道」，后者是「大池子里的平均热度」。

页面若要把两者并列，应同时展示 `n_items` 与 `n_hot`，不能只给占比。产物已按 `n_hot` 降序排好，并在每条链下保留 top5 热门标题，供人工抽查。

### 2.6 步骤 5：口径边界与不可比项

本件不能回答「哪条链更重要」，只能回答「哪条链在 2025-02—2026-07 的报道更显著」。它也不能做年度趋势：窗口只有 18 个月，且 2026-02 几乎断档。任何跨年比较都会把「采集断档」误读成「热度下降」。

另一个边界是语言与地域：206 个 source 以中文财经/科技媒体为主，没有海外媒体，也没有政务发布。因此它测的是「中文产业媒体显著性」，不是「全球影响力」。

### 2.7 步骤 6：敏感性

三项等权改成「转载 0.5、周量 0.3、显著度 0.2」会改变排序，但库内没有任何权重依据，本件不做无源的加权实验。可做的敏感性只有阈值：≥1 得 41,904 条（38.78%），≥2 得 1,972 条（1.83%），≥3 得 67 条（0.06%）。三条曲线在产物 `heat_proxy.score_dist` 里可直接复算。

链归属的敏感性是数组口径 vs 标题口径，Spearman 0.338，说明两者排序差异很大；本件选标题口径是因为它可解释、可复现，且不会让 3 条链直接归零。

### 2.8 参数登记与验收

为了让复核者不必读脚本就能判断口径，本件把关键参数、取值与依据集中登记如下。任何一项变更都会改变结果，必须重新跑并更新产物。

| 参数 | 取值 | 依据/影响 |
|---|---|---|
| 热门阈值 | 热度分 ≥2 | 三项 P90 均为 1，严格大于 P90 等价于 ≥2 |
| 热度分 | 转载 + 周量 + 显著度 | 三项等权，本件自定义 |
| 转载判定 | 归一化标题 distinct source ≥2 | 标题去空格/标点/大小写 |
| 周量阈值 | 所在 ISO 周全库 ≥2,412 | 全库周量 P90 |
| 显著度词表 | 19 个词 | 突破/首次/全球首/最大/融资/获批等 |
| 链归属 | 标题实体词表 | 覆盖 34,455 行（31.89%） |
| 多链处理 | 按链重复计入 | 与旧稿一致 |
| 去重键 | 归一化标题 | 107,347 个不同标题 |

参数表里最容易被忽略的是「周量阈值」：它按全库周量算，不按链内周量算。链内周量 P90 会低很多，用它会把小链的普通一周算成峰值。本件坚持全库阈值，是为了保持「跨链可比」。

显著度词表是人工选的，没有语料训练。它的作用是捕捉「首次/最大/突破」这类编辑判断词，不是情感分析；因此它不会给「利好/利空」打分，只给「标题强度」打分。

## 三、数据支撑情况

本件按「资讯底表 / 链归属 / 热度信号 / 去重 / 时间窗」五个维度逐项核对。结论是底表完整、去重可用、时间窗偏短，链归属与热度语义是主要缺口。

| 依赖维度 | 实测状态 | 关键证据 | 缺口与修复路径 |
|---|---|---|---|
| 资讯底表 | 完整 | 108,052 行、206 source、72 周 | 无需修复 |
| 链归属 | 部分 | 标题词表 31.89%；数组口径 3 链为 0、flat_ratio 371.24 | 补链级实体词表并人工标注 500 条，目标覆盖 ≥60% |
| 热度信号 | 代理 | heat_score 不存在；三项等权自定义 | 接入阅读/转发/搜索指数，或由甲方确认代理权重 |
| 去重键 | 可用 | 归一化标题 107,347 个；转载 546 个标题 ≥2 源 | 补 URL 规范化，处理同题不同写 |
| 时间窗 | 偏短 | 2025-02—2026-07，2026-02 仅 11 条 | 补采 2024 及更早，至少 36 个月 |

链归属缺口的修复不是「再跑一次 SQL」，而是补词表。当前 12 条链的词表平均 4.2 个词，具身智能只有 2 个词（具身智能/人形机器人），所以它的 2,302 条命中里 177 条热门（7.69%）很可能被低估。建议按链各补 10—20 个产品名、企业名、技术名，再用 500 条人工标注算准召。

热度缺口的修复有两条路：一是接外部传播数据（阅读、转发、搜索指数），二是承认「显著性代理」并把它写进指标名。当前产物已经用 `heat_proxy` 明确标注，不建议在页面上把它叫「热度」而不加说明。

时间窗缺口不影响单期计数，但影响任何「趋势」用法。若甲方要「本月 vs 上月」，2026-02 的 11 条会造成假下跌；应把 2026-01 至 2026-02 标为采集异常，或在趋势图上断线。

### 3.9 缺口优先级

缺口不是同等重要。本件按「是否阻断指标成立」把缺口分三档：阻断（指标算不出）、扭曲（算得出但结论会反）、披露（不影响本期结论但影响外推）。优先级如下。

| 优先级 | 缺口 | 阻断/扭曲/披露 | 处理 |
|---|---|---|---|
| P0 | heat_score 不存在 | 阻断 | 代理 + 标注 |
| P1 | 链归属覆盖 31.89% | 扭曲 | 补词表 + 人工标注 |
| P1 | 标题截断 52,057 行 | 扭曲 | 放弃数组口径 |
| P2 | 时间窗 18 个月 | 披露 | 补采 2024 |
| P2 | 无事件簇 | 披露 | 按标题去重 |
| P3 | 无阅读/转发 | 披露 | 不声称触达 |

P0 是阻断级：没有热度字段，指标只能改名或代理。P1 是扭曲级：链归属错会让排序错，截断会让计数低；两者都不阻断计算，但会让结论反。P2/P3 只影响外推与解释，不影响本期数。

优先级不是永久不变的。若甲方确认「三项代理就是正式热度」，P0 降为披露；若补了全量链标签，P1 消失。每次变更都要重排。

## 四、数据缺失情况

本件没有「缺年补 0」，因为它是截面计数而不是年度序列。缺失主要集中在字段级与语义级。

| 缺失项 | 影响 | 当前处置 | 补齐路径 |
|---|---|---|---|
| heat_score | 无法复现旧稿分数 | 用三项代理替代并标注 | 接传播效果数据或甲方确认代理 |
| event_id/簇 id | 无法按事件去重 | 按标题去重 | 建事件聚类表 |
| industry_code 完整值 | 数组口径不可用 | 改标题词表 | 放宽字段长度并重采 |
| 2024 及更早资讯 | 无法做同比 | 不声明趋势 | 补采至少 36 个月 |
| 阅读/转发量 | 热度语义不完整 | 不声称触达 | 接第三方传播数据 |

字段缺失里最需要警惕的是 industry_code 的截断：52,057 行达到 250 字符上限，数组被切断后仍能解析出部分码，看起来「有值」，实际不完整。这类静默截断不会报错，只会让计数偏低。本件因此完全放弃数组口径，避免把截断值当真值。

语义缺失里最需要写明的是「热度 ≠ 传播效果」。三项代理能区分「被多家转的公关稿」与「单发深度稿」，但区分不了「被多少人真正读到」。页面文案应使用「报道显著性」而不是「热度」，或在旁边加问号提示。

### 4.9 处置原则

对缺失的处置遵循三条：不补 0、不静默填充、不把模型产物当数据真值。能算的算，不能算的输出 null 并写原因；任何代理都必须在字段名与页面文案上标注「代理」。

第二条是不做「看起来完整」的补齐。缺失年份不插值、缺失城市不摊派、缺失分项不按均值填；这些操作会让下游误以为数据齐全，比 null 更危险。

第三条是可复现优先。所有外部输入都落快照，快照带来源、时间、行数；脚本只读快照，重跑不依赖网络。这样即使源库变化，历史结论仍可复算。

## 附录 G 口径问答

**问：为什么不直接用资讯条数当热门数？**

答：条数只反映「某天资讯多」，不反映「某条资讯被追」。一条被 50 家转载的资讯和一条无人转载的资讯在条数口径下同权，会丢掉热度的核心含义。

**问：三项代理为什么等权？**

答：库内没有任何权重依据。等权是最小假设；一旦加权，就必须说明「转载比周量重要多少」，而这需要甲方或标注集支持。本件不做无源加权。

**问：31.89% 覆盖会不会让结论不可用？**

答：会影响绝对值，不影响相对排序的可解释性。产物把未覆盖行单列，不摊派、不补 0；读者能看到「这个数只覆盖三成资讯」。

**问：为什么热门占比最高的不是人工智能？**

答：生物医药 10.23%、合成生物 8.41%，都高于人工智能 4.89%。这不是「生物医药更热」，而是它的命中资讯少（1,075 条）、事件更集中；占比的分母是链内命中数，不是全库。

**问：能否用它做月度趋势？**

答：不能。2026-02 只有 11 条，是采集断档；把它当「热度下跌」会得出错误结论。本件不声明趋势。

**问：数组口径为什么不可用？**

答：三链为 0、flat_ratio 371.24、48.18% 截断。它不是「链归属」，是「可能涉及的所有链」，且被字段长度切断。
