## 摘要

「卡脖子环节数」在产品上是一张清单：链条上哪些环节的关键投入被外部卡住、卡在哪一环、涉及多少家企业。它不是一个可以「数出来」的量——必须先判定每个环节是否受制，再计数。

判定的最小前提是一组「对外依存」的度量：该环节的进口依存度、关键零部件的国产化率、关键专利的对外集中度，或者一份已经判定好的卡脖子环节清单。`gkx` 里这些东西一样都没有：以 `%choke%`、`%self_suff%`、`%import_dep%`、`%customs%`、`%tariff%`、`%hs_code%`、`%input_output%`、`%localization_rate%` 等 14 组列名模式扫全库 6,312 列，命中 **0 列**；以 16 组表名词根扫 280 张表，`choke`/`chokepoint`/`bottleneck`/`customs`/`tariff`/`trade`/`input_output` 等 15 组为 0，唯一命中是 `%import%` 打到的 `dwd_org_important_news_info`——那是企业资讯表，「important」里含「import」子串，与进口无关。

国别这一族我第一轮漏扫了，第二轮补上并逐个核过：全库有 **42 列**含「country」、落在 **28 张表**里，但真正能落到「国别」的只有三张——`dwd_patent.country_code`（2,939,895 件中境外 **90,990** 件，**3.09%**）、`dwd_industry_analysis_countries`（**1,000** 行，列是 `document_id→country`，无金额列、无行业列）、`dwd_forg_base_info`（**20,000** 家，国别只有 GB 19,832 / US 159 / CA 9 三档）。三者都是**主体属性**（专利在哪个局公开、分析文档关联哪个国家、企业注册在哪个国家），不是**环节的对外依存度**。把它们当卡脖子，等于用「企业注册地」解释「技术受制」。

唯一的贸易类序列是 `dwd_macro_index_data` 的 `dwjj_dwmy*` 族：**5,129** 行、**3** 个指数码（`dwjj_dwmy_01` / `_01_01` / `_01_02`），单位只有「元」与「%」两种，维度是 `area_code × occur_period_year`（**180** 个区域码），覆盖 1979—2026。它是「某地区进出口总额及其增速」，没有行业列、没有环节列，落不到链节点。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块是**产业链分析 → 产业链监测 → 卡脖子环节**。页面是一张清单，一行一个环节：环节名、所在链、受制类型（材料/设备/软件/工艺）、受制程度、涉及企业数、替代来源。

清单的下游是「补链强链专题」：受制程度决定攻关优先级，涉及企业数决定攻关主体，替代来源决定是「国产替代」还是「多元采购」。因此这张清单不是展示件，它是政策工具的输入。

### 1.2 为什么需要这个指标

第一，它与「瓶颈」是两个政策动作。瓶颈（有人干但干不够）对应技改与扩产；卡脖子（被外部卡住）对应攻关与替代。两者的责任部门、资金来源、考核周期都不同，合并会把两类问题糊成一个数。

第二，它决定「攻关清单」的长度。如果清单有 200 个环节，等于没有清单；如果只有 5 个，才是可执行的攻关靶点。数量本身就是管理信号。

第三，它是风险监测的锚。国际贸易环境变化时，受制环节会变；清单需要按季度或半年更新，才能反映真实的暴露面。

### 1.3 需求文档是否给出定义方法

**没有。** 需求只在父口径里写了「识别产业链卡脖子环节数量」，没有给受制判据、没有给阈值、没有给数据来源。这三者缺一，指标都不可复现：判据决定「什么算卡」，阈值决定「卡到什么程度算卡脖子」，来源决定「谁来判」。

这也是本件不能走「推测定义 + 自行打分」路线的原因：卡脖子是**合规性强、外部性大**的判断，自行设定判据会把「本地不布局」误报为「被卡住」，直接误导攻关资源投放。

### 1.6 本报告的口径与边界（推测定义，须与甲方会签）

**推测定义**：卡脖子环节数 = 满足「受制判据 + 阈值」的叶级环节计数，其中受制判据为下列任一条成立：

$$\text{choke}(\ell)=1 \iff \big(\text{imp}_\ell \ge \theta_1\big)\ \lor\ \big(\text{loc}_\ell \le \theta_2\big)\ \lor\ \big(\text{pat}^{ext}_\ell \ge \theta_3\big)$$

其中 $\text{imp}_\ell$ 为环节进口依存度、$\text{loc}_\ell$ 为关键投入国产化率、$\text{pat}^{ext}_\ell$ 为关键专利境外主体持有比例，$\theta_{1..3}$ 为会签阈值。

**边界**：① 不把空位环节当卡脖子（空位=没人干，卡脖子=有人干但被卡）；② 不把集中度高当卡脖子（集中可能是效率）；③ 不按企业数少判卡脖子；④ 不输出未经会签的「受制分」；⑤ 不在没有环节级贸易数据的情况下用「区域进出口总额」硬拆。

## 二、依赖性质裁定（为什么必须外部数据）

### 2.1 本指标需要什么形态的数据

形态上必须是**环节 × 度量**的矩阵：行是 954 个叶级环节（或其中一部分），列是进口依存度、国产化率、关键专利对外占比中的至少一列。有了这个矩阵，阈值一卡就能出清单。

注意「环节」这一维是硬要求。区域级的贸易总额再准，也无法回答「哪个环节被卡」；企业级的国别属性再多，也只能回答「哪些企业是外资」。

### 2.2 gkx 里到底有什么（逐族探测）

| 族 | 需要的形态 | gkx 是否有 | 探测证据（计数） |
|---|---|---|---|
| 受制度量 | 环节×进口依存度 | 无 | 14 组列名模式命中 0 列 |
| 海关/关税 | HS 编码级贸易 | 无 | `%customs%`、`%tariff%`、`%hs_code%` 表名 0 命中 |
| 投入产出 | IO 表进口系数 | 无 | `%input_output%`、`%io_table%` 0 命中 |
| 环节标注 | is_choke 类标签列 | 无 | 1,273 节点 × 17 列无标注位 |
| 国别属性 | 主体国别 | **有** | 42 列 / 28 表；可落国别 3 表 |
| 区域贸易 | 地区进出口额 | **有** | 5,129 行 / 3 指数码 / 180 区域 |

这张表是本件判 B 类的全部依据：**有**的两族都做不到「环节」，**缺**的两族恰好是判定必需。

表级证据统一引用 `_work_gkx21/TABLE_ABSENCE_EVIDENCE.md`，本件不重抄证据块：

- **§`chain_bottleneck`**：精确同名不存在（本件复测 0 张）。证据块对该簇的提醒是「应用层表库内没有属正常，正确动作是用原始表重建」。本件遵此提醒做了重建尝试：把受制判据逐条映射到 gkx 原始表，四条里三条（海关、IO、环节标注）在 2.2 表里 0 命中，第四条（国别）有表但只到主体级，重建路径在这里断掉。
- **§`industry_chain_metric_fact`**：精确同名不存在（本件复测 0 张）。这说明连「指标事实表」这一层也没有承载受制分数的位置。
- **§`chain_panorama_nodes`**：精确同名不存在（本件复测 0 张）。

### 2.3 最近的替代面为什么不可用

**其一，空位环节（38 个）。** 空位是「本地没有企业」，卡脖子是「本地有企业但关键投入受制」。两者语义相反：把空位当卡脖子，会把「本地不布局」（可能是有意为之，如上游材料全球采购）误报为「技术受制」，攻关方向直接错。

**其二，境外专利占比（3.09%）。** 全库 2,939,895 件专利里境外 90,990 件，其中 PCT（WO）89,935 件、HK 952 件、JP 79 件。这是「在哪个专利局公开」的属性：PCT 多说明企业愿意做国际保护，**恰恰与「被卡住」相反**。而且它是企业级属性，不是环节级。

**其三，外资企业表（20,000 家）。** 国别分布是 GB 19,832 / US 159 / CA 9，`country` 字段全为 NULL。这是一个以英国注册主体为主的样本，不是中国境内外资企业分布；用它算外资依赖会得出「外资几乎全来自英国」的荒谬结论。

**其四，区域进出口总额（5,129 行）。** 它回答「某地区外贸规模」，不回答「某环节进口依存」。要拆到环节，需要「地区×商品×环节」的映射与商品级贸易额，两者都没有。

### 2.4 若强行用会得到什么假数

假设用「企业数 ≤ 5 的叶级环节」当卡脖子，会得到一批细分环节清单。这些环节本来全球就只有几家企业在做，企业数少是「环节小」，不是「被卡住」。更严重的是，它会与 `M_CHAIN_BREAK_RISK_COUNT` 的 38 个空位高度重叠，让两个指标看起来在说同一件事，实际上都在说「本地企业少」。

假设用「境外专利占比 > 0 的环节」当卡脖子，会把所有做过 PCT 布局的环节标红——那是国际化程度，不是受制程度。

### 2.5 三条否定性证据该怎么读（防止被当成「没认真找」）

本件的否定证据是**计数**，不是形容词。读法如下：

第一，**列名扫描的分母是全库**。6,312 列是 `information_schema.columns` 里 `table_schema='gkx'` 的全部列，不是抽样。换句话说，只要库里有任何一列叫 `import_dependency` 或 `self_sufficiency`，这次扫描必然会看到。

第二，**表名扫描排除了「换名字」这种可能**。16 组词根覆盖了 `choke`/`chokepoint`/`bottleneck`/`self_suff`/`import_dep`/`customs`/`tariff`/`hs_code`/`trade`/`input_output`/`io_table`/`dependency`/`localization` 等写法。如果一张表叫「卡点表」「受制环节表」，它的英文命名大概率落在这 16 组里；落不进的概率存在，但不是零成本可排除的，所以本件同时用「链树有没有标注位列」做了交叉验证。

第三，**标注位的交叉验证是独立的**。即使表名完全另类，只要链树上有 `is_choke` 类列，也能判定；实测 1,273 节点 × 17 列里没有这样一列，且 `level` 与 `node_company_count` 两列整列为 0（说明这张表是「纯目录」，不是「带属性的节点表」）。

三条证据指向同一个结论：**缺的不是命名，是结构**。

### 2.6 裁定

本指标依赖「环节级对外依存度量 + 环节级标注位」，两类前提在 gkx 均不成立，且三个最像的替代面（空位、境外专利、外资企业）都只能产生方向性错误。按依赖性质三分法，属 **B 类（不可重建，须外部数据或人工判定）**。

最短落地路径不是数据工程，而是甲方组织一次行业判定（E 族）：按 12 条链的叶级环节逐条判定「是否受制、受制类型、替代来源」，产出一份会签清单。这条路可在数周内完成，但需要业务方投入。

## 三、数据支撑情况

### 3.1 四判定落表

| 判定项 | 结论 | 证据（可复核） |
|---|---|---|
| 表结构直接支持（开发库+三方库） | 否 | 无卡脖子表/受制字段：精确同名 0 张，受制类列 0 列 |
| 表数据直接支持（开发库+三方库） | 否 | 同上；无字段即无数据 |
| 依赖表结构支持（开发库/三方库） | 否 | 海关/关税/IO/标注位四族 0 命中 |
| 依赖表数据支持（开发库/三方库） | 否 | 唯一可用族（区域贸易）维度不含行业 |
| **聚合结论** | **完全不支持** | 两段前提均不成立 |

### 3.2 数据量、覆盖与代表性

覆盖为 **0/954**：954 个叶级环节里，没有任何一个环节带受制度量。因此不存在「覆盖率」这个概念——不是「部分环节能算」，是一个都算不了。

链树本身是完整的：1,273 个节点、12 个根、954 个叶，其中 916 个叶有企业（空位 38 个）。也就是说「环节」这一维是齐的，缺的完全是「受制」这一维。

### 3.3 结构支持判定

卡脖子是「环节 × 判据」的矩阵，gkx 没有任何矩阵型结构承载它。`dwd_industry_chain_info` 的 17 列是纯层级结构（码、名、父子、企业数、审计字段），没有一列是判据；`dwd_macro_index_data` 是「指标码 × 区域 × 期间」的长表，没有环节键。

这是数据模型层面的缺失，不是填充率问题：即使明天把 5,129 行贸易序列填满，也仍然落不到环节。

### 3.4 与开发库 live 的差异

开发库同样没有受制度量表。若 live 侧已有卡脖子清单，其来源必然是外部判定或人工标注，不在本库数据链内——这一点必须在上线说明里写清，否则会被当成「系统算出来的」。

### 3.5 缺口清单（≥4 条，逐条给补法）

| # | 缺口 | 影响面 | 补法 | 补齐后能否算 |
|---|---|---|---|---|
| G1 | 环节级进口依存度 | 核心判据 | 海关 HS 级贸易额 + 环节—HS 映射表 | 能（需映射维护） |
| G2 | 关键投入国产化率 | 核心判据 | 行业协会调查或企业问卷 | 能（年度更新） |
| G3 | 环节级标注位 | 承载位置 | 新增 `is_choke` 列或独立判定表 | 能 |
| G4 | 判定阈值 | 可复现性 | 甲方会签阈值表 | 能 |
| G5 | 关键专利—环节映射 | 辅助判据 | 专利 IPC 与环节码映射 | 部分（只能做辅助） |

### 3.6 甲方三步复核路径（本件结论可被推翻的唯一方式）

第一步，**推翻「受制类列不存在」**：在只读账号下执行 B.2 的扫描，若出现任何一列 `choke`/`import_dep`/`self_suff` 类字段，本件的 N1 结论立即失效。

第二步，**推翻「国别族不能到环节」**：检查那 28 张含 country 列的表里，是否存在「国别 × 行业 × 金额」的贸易流量表。本件只核到三张能落国别的表，若还有第四张带金额的，本件结论需要重写。

第三步，**推翻「贸易序列无行业维」**：`dwd_macro_index_data` 的 24 列里若有任何一列是行业或环节，区域级序列就能拆到环节，本件应降为部分支持。

三步都不成立时，本件的「完全不支持」才是站得住的。

### 3.7 与相邻指标的边界（防结论互相矛盾）

| 指标 | 问的问题 | 判据 | 本件关系 |
|---|---|---|---|
| `M_CHAIN_BOTTLENECK_COUNT` | 有人干但干不够？ | 五维评分（供需/技术/产能/交付/替代） | 同判完全不支持，但缺的东西不同：它缺五维评分输入，本件缺贸易/依存字段与标注位 |
| `M_CHAIN_BREAK_RISK_COUNT` | 有没有人干？ | 叶级企业数 = 0 | 它数 38 个空位；空位不可当受制 |
| 本件 | 被外部卡住？ | 进口依存/国产化率/专利对外集中 | 需要前两者之外再加一条对外判据 |

三者可以在同一页面并列展示，但**不得合并计数**：合并会把「没人干」「干不够」「被卡住」三种完全不同的政策问题压成一个数。

## 四、数据缺失情况

### 4.1 缺口清单（后果归因）

**缺环节级贸易数据 → 无法判定，且方向不可预测。** 进口依存度既可以高估也可以低估：一个环节可能进口额很大但国内产能也很大（依存度低），也可能进口额很小但国内完全没有（依存度高）。没有分母（环节总需求），分子（进口额）单独没有意义。

**缺国产化率 → 无法区分「买不到」与「买得起但贵」。** 卡脖子的本质是「买不到」，不是「买得贵」。国产化率是唯一能区分这两者的字段。

**缺标注位 → 即使有度量也无处落。** 一条链 954 个叶，判定结果必须落在叶上才能聚合到链；落在链上就失去粒度，落在企业上就变成「企业风险」而非「环节风险」。

**缺阈值 → 结果不可复现。** 同一批数据，阈值 0.3 与 0.5 会给出完全不同的清单长度；清单是政策输入，必须可复现。

### 4.2 逐条影响

- G1 缺失使「受制」无法量化，只能靠专家判断；
- G2 缺失使「受制程度」无法分档，只能二值；
- G3 缺失使结果无法与链树对齐，无法做「链级卡脖子环节数」；
- G4 缺失使结果随人而变，无法审计；
- G5 缺失使专利这条辅助线也只能到企业级。

### 4.3 明确不做什么（禁止的替代）

- 不把空位环节当卡脖子——语义相反（无人 vs 受制）。
- 不把境外专利占比当卡脖子——PCT 布局是国际化，不是受制。
- 不把外资企业数当卡脖子——那是主体属性，且样本以 GB 为主。
- 不把区域进出口总额按企业数比例硬拆到环节——拆出来的数没有分母意义。

### 4.4 数据陷阱（下游复用必读）

- **`%import%` 会打到资讯表**：唯一命中的表是 `dwd_org_important_news_info`，「important」里含「import」。任何按词根找贸易表的脚本都必须把这张表排除，否则会误判「库里有进口数据」。
- **`dwd_industry_analysis_countries` 名字骗人**：它不含行业、不含金额，只是「分析文档—国别」的关联表（1,000 行）。看名字下结论会写错。
- **境外专利占比不是受制指标**：90,990 件境外专利里 89,935 件是 PCT（WO），代表国际保护意愿，方向与「被卡」相反。
- **外资企业表是单一来源样本**：20,000 家里 GB 19,832 家，`country` 字段全为 NULL，不能代表中国境内外资结构。
- **节点名关键词会误匹配**：`%卡%` 命中「卡拉美芬类」这种药品名，任何按名称筛环节的做法都必须人工过一遍。

### 4.5 若甲方补齐后的口径升级路径

| 补齐条件 | 口径变化 | 档位能否升格 |
|---|---|---|
| 提供环节级进口依存度 | 可算进口依赖型卡脖子 | 可升格至部分支持 |
| 追加国产化率 | 可区分「买不到/买得贵」 | 可升格至部分支持 |
| 追加会签阈值 | 清单可复现 | 可升格至完全转换支持 |
| 直接给会签清单 | 本件退化为「清单入库 + 计数」 | 可升格至完全直接支持 |

| severity | tinyint | 是 | 1—5 分会签值 |
| signed_by / date | varchar | 是 | 判定人与日期 |

方案二（成本高、可信度高）：提供 HS 级贸易额 + 环节—HS 映射，由系统按会签阈值自动判定。

方案三（成本居中）：**只报「受制等级」不报清单**。甲方按 12 条链给 1—5 级受制等级，系统据此做链级排序，不做环节级清单。代价是失去环节粒度，收益是把填报成本压到 12 行。

**三方案对比**：

| 维度 | 方案一（环节清单） | 方案二（贸易数据） | 方案三（链级等级） |
|---|---|---|---|
| 填报成本 | 中（954 个叶） | 高（HS 映射 + 年度更新） | 低（12 行） |
| 可复现性 | 高（有判定人） | 最高（数据可重算） | 中（等级主观） |
| 输出粒度 | 环节 | 环节 | 链 |
| 支持的上线功能 | 卡脖子清单页 | 卡脖子清单页 + 监测 | 仅链级排序 |

**验收口径建议**：清单必须同时给出「判据 + 阈值 + 判定人」，否则不可复现；页面应显示「本次清单基于 N 位专家、M 个环节、阈值 θ」。

**与相邻指标的边界**：卡脖子（受制）与空位（没人干）、瓶颈（干不够）分列三个指标，禁止合并展示。
