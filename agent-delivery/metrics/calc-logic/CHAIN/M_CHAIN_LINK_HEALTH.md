## 摘要

「环节健康度」原口径是五维等权：技术成熟度、人才供给、市场容量、融资资本、政策覆盖，各维 min-max 到 0—100 后求均值。真正拿到 gkx 上跑，第一件事不是算分，而是逐维验证「这一维在环节层有没有数」。验证结果是 2/5：技术和资本能算，人才、市场、政策三维算不了。

技术维用「L1 节点下专利申请人申请量 / L1 挂接企业数」。申请人名能对上 21,933 个、专利 949,894 件，占专利表 2,939,895 行的 32.31%；剩下 67.69% 的专利没有链归属，不进分子。资本维用「L1 节点下融资事件数 / L1 挂接企业数」，L1 求和 10,405 起，比去重后的链级 9,937 起多 468 起，差额来自同一企业挂多个 L1 时事件按 L1 各计一次。两维都在同一份 `chain_firm_index_20261023.json` 上取企业数，分子分母同母体。

三维为什么算不了：人才列 `development_employee` 在 `dwd_org_annual_financial_info` 的 90,926 行里 **0 行有值**（不是稀疏，是整列没灌）；营收快照只有 650 家能挂链，落到 L1 后 657 个挂接、最高覆盖率 3.57%，41 个节点没有一个达到 5% 门槛；政策表 20,000 行没有环节码列，标题里也没有 L1 码，按标题硬匹配「原材料」「技术层」这类通用名会造出大量假命中。

于是本件不拍总分。`health_score` 全部 null，只给两维百分位与 `partial_2dim_index`。两维的秩相关是 **0.7003**，说明它们不是同一个东西的两种写法：传感器「生产制造」技术 60.00、资本 100.00；合成生物「平台层」技术 37.50、资本 97.50；集成电路「EDA/IP 核」技术 57.50、资本 1.25。只看一个维度会把这三类节点读反。

| 口径要点 | 取值 |
|---|---|
| L1 节点数 | 41 |
| L1 企业挂接数 / 链企业数 | 1,749,995 / 1,714,457 |
| 可算维度 | 技术成熟度、融资资本（2/5） |
| 不可算维度 | 人才供给、市场容量、政策覆盖（3/5） |
| 专利匹配覆盖 | 949,894 / 2,939,895 = 32.31% |
| 两维部分指数区间 | 0.62—95.00 |
| 两维秩相关 | 0.7003 |
| 判档 | 部分支持 |

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

功能模块是**产业链分析 → 产业关键环节识别 → 环节健康度**。UI 是链全景页的一张热力格：每个 L1 环节一个格子，颜色从红（低健康）到绿（高健康）；点开是五维雷达，五个轴分别是技术、人才、市场、资本、政策。

本件交付的是**节点级子维分数与两维部分指数**，不交付五维总分，也不交付「是否瓶颈」的二值判断（那是 `M_CHAIN_BOTTLENECK_SEVERITY` 的职责）。

### 1.2 为什么需要这个指标

第一，产业链诊断不能只到链级。「人工智能链不健康」这种结论没有行动价值；要说清是「基础层缺技术」还是「应用层缺资本」，必须落到环节。

第二，健康度是正向读数，与堵点评分互补。堵点分回答「哪里堵」，健康度回答「哪里好」；只给堵点会让页面全是红格，没有优先级。

第三，它能把「企业多」与「企业强」分开。信息技术服务 L1 有 537,129 个企业挂接，但每家企业专利只有 0.1282 件、每千家企业融资 2.74 起，两维都低；晶圆制造只有 261 个挂接，但每家企业 11.1686 件专利、每千家 141.762 起融资。企业数与健康度不是一回事。

### 1.3 需求文档是否给出定义方法

给了框架，没给可执行口径。`gkx-orchestration/agent-delivery/metrics/calc-logic/CHAIN/M_CHAIN_LINK_HEALTH.md` 写明五维与等权公式：

$$H=\frac{1}{5}(T+N+M+K+P)$$

但它把每一维都写成「某表聚合后 min-max」，没有写：节点用哪一级（L1 还是叶级）、企业数去重到哪一层、专利怎么归到节点、政策没有环节码时怎么办。这四处是本件必须自己定的。

### 1.4 类似指标权威机构构建方法可行性分析概要

赛迪的产业链现代化评估用「技术/人才/市场/资本/政策」五维，NASA 的 TRL 用技术成熟度分级。两者的共同点是**每维都要有独立的观测源**，而不是用同一张表的不同列硬凑。本件沿用五维框架，但只对「有独立观测源」的两维打分；这与赛迪的做法一致，区别是本件把「无源」明确写出来，不用 0 或 50 填充。

TRL 分级本件没有采用。TRL 需要逐环节的技术阶段标注（实验室/中试/量产），gkx 没有这个字段；用专利密度代理 TRL 只能表达「技术产出强度」，不能表达「成熟阶段」。本件把它命名为「技术成熟度（专利密度代理）」，不冒充 TRL。

### 1.6 推测原意与推测定义（仿王惠口径写法）

原意是「给定环节节点，五维正向打分后等权合成 0—100，分数越高越健康」。本件把「可得的两维」定义为：

$$tech_i=100 \times \frac{\mathrm{rank}(p_i/f_i)}{n-1}, \quad cap_i=100 \times \frac{\mathrm{rank}(k_i/f_i)}{n-1}$$

其中 $p_i$ 是节点 $i$ 的专利申请人申请量，$k_i$ 是节点 $i$ 的融资事件数，$f_i$ 是节点 $i$ 的企业挂接数，$n=41$。$\mathrm{rank}$ 为升序秩（并列取平均秩）。

两维部分指数：

$$partial_i=\frac{tech_i+cap_i}{2}, \quad \text{权重覆盖}=\frac{2}{5}=0.40$$

总分：

$$health_i=\mathrm{null}$$

最后一行不是「暂缺」，是本件明确拒绝输出：五维缺三维时，任何加权都只是在给两维重新赋权，不能叫五维健康度。

## 二、计算过程

### 2.1 为什么先拆维、不拍总分

原口径的等权公式只有在五维都可得时才成立。逐维验证的结果如下：

| 维度 | 源 | 节点级可得性 | 结论 |
|---|---|---|---|
| 技术成熟度 | 专利申请人聚合 | 21,933 个申请人名可映射到 L1 | 可算（专利密度代理） |
| 人才供给 | `development_employee` | 90,926 行中 0 行有值 | 不可算 |
| 市场容量 | 营收快照 | 650 家挂链，L1 最高覆盖 3.57% | 不可算 |
| 融资资本 | 融资事件 | 9,937 起，L1 挂接 10,405 | 可算 |
| 政策覆盖 | 政策表 | 无环节码列，20,000 行无法归节点 | 不可算 |

如果强行拍总分，只有两种写法：把三维填 0（等于说这些环节在这三维上完全不健康），或把三维填 50（等于说全国平均水平）。前者会系统性压低所有节点，后者会抹平差异；两种都是伪造观测。所以本件只交子维。

### 2.2 节点口径：L1 的 41 个节点

节点取 9 位 INB 码（L1），共 41 个。链根是 7 位（12 个），叶级是 11—21 位（954 个）。选 L1 的理由：

1. 叶级 954 个节点里大量只有个位数企业，专利密度会出现「1 家企业 100 件专利 = 密度 100」的极端值；
2. L1 是链详情页实际展示的层级，再往下钻是另一个交互；
3. 政策、营收这些稀疏源在 L1 都已经不够，叶级只会更差。

企业数用 `l1_firms` 的**挂接数**：同一企业挂多个 L1 时，在每个 L1 各计 1 次。41 个 L1 求和 1,749,995，比链企业去重数 1,714,457 多 35,538，差额就是跨 L1 挂接。这个口径与专利、融资的「按 L1 各计一次」一致，所以比值有意义；但它不是「去重企业数」，正文与 UI 都必须写「挂接」。

### 2.3 技术成熟度：专利密度

专利来源是 `star_applicant_agg_gkx.json` 的 `agg[name] = [件数, 授权数]`，件数是申请量（不是授权量）。归节点路径：

1. `chain_firm_index_20261023.json` 的 `name_l1` 把企业名映射到 L1；
2. 用同一个名字去 `agg` 取件数；
3. 按 L1 求和。

结果：21,933 个名字命中，949,894 件专利；专利表总行 2,939,895，覆盖 32.31%。未命中的 67.69% 有两类：申请人名不在链企业名里（高校、科研院所、个人），以及链企业没有专利记录。前者是真实的「非企业申请人」，后者是「企业无专利」，两类都不该硬塞进节点。

技术密度：

$$d_i^{tech}=\frac{\sum_{name \in L1_i} applications(name)}{f_i}$$

不做「专利数 / 企业数」以外的归一。专利有年份，但本件用全量存量（2021—2026 申请合计），不做年度增速——年度增速是 `M_CHAIN_TREND_INDEX` 的职责，两件混用会把「存量强度」与「增长趋势」搅在一起。

### 2.4 融资资本：事件密度

融资事件来自 `chain21_fin_degree_20261022.json`，按本批统一口径去重：`(credit, completion_date, round, amount)` 四元组，剔除 2026 残年，得 9,937 起。归节点路径：`fin_credit_l1[credit]` → L1 列表；一个 credit 挂多个 L1 时事件在每个 L1 各计 1 次。

结果：L1 求和 10,405 起，比链级 9,937 多 468 起（4.71%）。这 468 起不是重复数据，是跨 L1 挂接的重复计数。密度：

$$d_i^{cap}=\frac{k_i}{f_i} \times 1000$$

单位是「每千家企业挂接的融资事件数」。用 1000 而不是 100，是因为 41 个节点的密度从 0 到 202.381，用 100 会让大多数节点落在 0—2 之间，表格难看且不利于排序。

金额不进资本维。原因是融资金额 57.63% 缺失，且头部单笔污染严重（生物医药 54.87% 来自恒大）；用事件数至少不会被一笔大额事件改写节点排序。

### 2.5 市场容量：为什么整维置 null

营收快照 `chain21_revenue_20261022.json` 有 39,395 行（上市主体 + 年报），挂链后只有 650 家能对上 `rev_credit_chain`，落到 L1 是 657 个挂接。41 个 L1 里覆盖率最高的是传感器「生产制造」3.5714%，最低的多个节点为 0；**没有一个节点达到 5% 门槛**（`nodes_with_rev_coverage_ge_5pct=0`）。

5% 门槛是本件自定的：低于 5% 时，节点营收合计由个位数企业决定，第一名换一家公司就变。即使把门槛降到 1%，也只有少数节点能过，且过的节点会集中在上市企业多的深圳，不能代表全链。

所以市场容量维全部 null，不填 0，也不填行业中位数。`rev_latest_sum_yuan` 仍保留在 `l1_rows` 里，供甲方查看「有营收记录的那几家」的量级，但它不是节点市场容量。

### 2.6 人才供给：整列为空的证据

`gkx.dwd_org_annual_financial_info` 有 90,926 行，`development_employee` 有值行数 **0**。这不是「覆盖低」，是列建好了但一行没灌。同一张表的 `arch_development_am`（研发投入）也是 0 行；`operating_revenue` 只有 2,193 行（2.41%）。

因此人才维没有任何可用的节点级代理。专利发明人可以作为替代，但 `dwd_patent` 的发明人字段未结构化到「人—节点」关系，且同名发明人消歧在 gkx 内无法完成；本件不拿发明人数量冒充研发人员数。

### 2.7 政策覆盖：为什么不能按标题硬匹配

`gkx.dwd_policy_base` 有 20,000 行，字段里没有 `node_id`、没有 `industry_link_code`，只有 `title`、`keywords`、`keypoints`、`theme`、`policy_support`、`level`、`city`。其中：

- `keywords` 0 行非空；
- `keypoints` 0 行非空；
- `theme` 只有 2 行非空；
- `policy_support` 20,000 行全是小写字符串 `'null'`。

唯一能用的文本是 `title`。但 L1 名称里有「原材料」「技术层」「应用层」「软件」「整机制造」这类通用词，按标题匹配会把大量无关政策吸进来（例如「原材料工业发展规划」并不等于生物医药链的原材料环节）。本件不做这种匹配，政策维 null；政策维在链级的可算版本见 `M_CHAIN_POLICY_MATCH_SCORE`（那件也只到链级）。

## 四、数据缺失情况与结论边界

### 4.1 缺口的后果归因（往哪偏、偏多少）

1. **人才维缺失 → 无法判断「人」的约束**。一个环节可能专利多、融资多，但没有研发人员，实际是「技术在外、人才在外」。本件只能显示前两维，不能回答人才瓶颈。
2. **市场维缺失 → 无法判断「需求」的约束**。营收覆盖 3.57%，节点营收合计由个位数企业决定；本件不输出市场分，避免把「几家上市公司」当「全节点」。
3. **政策维缺失 → 无法判断「政策是否覆盖到环节」**。链级政策匹配可以算（另一件），节点级不行；这会让「政策精准度」类结论只能停在链级。
4. **专利覆盖 32.31% → 技术分偏向有大企业的节点**。高校/院所专利不进分子，软件链的大量应用型专利可能没有申请人名匹配；技术分对「企业主导、专利多」的节点更友好。
5. **挂接口径 → 大链节点被高估规模**。信息技术服务 537,129 挂接，其中包含跨 L1 重复；它不是 537,129 家去重企业。

### 4.2 可构建但存在缺口（不是「无法构建」）

能稳定构建：

- 41 个 L1 节点的技术分、资本分、两维部分指数与排序；
- 每个节点的挂接企业数、专利密度、融资密度；
- 两维的分歧清单（技术高资本低、资本高技术低）。

不能稳定构建：

- 五维总分 `health_score`；
- 人才、市场、政策任一维的节点分；
- 链级加权健康度（权重没有甲方确认，且企业数分布极不均）；
- 叶级（954 个）健康度（样本更碎）。

### 4.3 数据陷阱（本批实测，须写入任何下游复用说明）

1. **`development_employee` 是整列空，不是稀疏**：`SUM(col IS NOT NULL)=0`，任何「研发人员占比」都不可算。
2. **营收快照只有 650 家挂链**：不能把 39,395 行当全量企业营收；上市主体占比极高。
3. **专利件数是申请量，不是授权量**：`star_applicant_agg_gkx.json` 的 `agg[name][0]` 是件数，`[1]` 才是授权数；两者不能混用。
4. **L1 企业数是挂接，不是去重**：41 个节点求和 1,749,995 > 1,714,457。
5. **政策 `keywords`/`keypoints` 全空、`policy_support` 全为字符串 `'null'`**：不能用它们做节点归属，也不能把 `'null'` 当有效值。
6. **百分位秩不是绝对值**：95.00 只表示「在 41 个节点里排最前」，不表示「健康度 95 分」。

### 4.4 结论与边界

**可以对外说**：

- 41 个 L1 环节里，晶圆制造（95.00）、人工智能技术层（91.25）、低空基建与信息服务（91.25）两维部分指数最高；整车制造（0.62）、信息安全软件与服务（5.00）、数字文化创意活动（6.25）最低。
- 技术维与资本维秩相关 0.7003，不是同一维度；传感器生产制造、合成生物平台层、集成电路 EDA/IP 核是三类典型分歧。
- 技术维覆盖 32.31% 的专利、资本维覆盖 100% 的已挂链融资事件；两维都可复算。

**不可以对外说**：

- 「某环节健康度 95 分」——`health_score` 是 null，95.00 是两维部分指数，权重只覆盖 0.40。
- 「某环节人才供给不足」——人才维整列为空，本件没有观测，不能下方向性结论。
- 「某环节市场容量 10 亿元」——营收覆盖最高 3.57%，节点合计不是市场容量。
- 「链级健康度 = 节点平均」——企业数分布极不均，未加权平均会被小节点主导，加权平均又没有甲方权重。
