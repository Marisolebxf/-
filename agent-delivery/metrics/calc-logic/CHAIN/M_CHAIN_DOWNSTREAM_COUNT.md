## 摘要

本件回答“12 条产业链各有多少个下游环节”。源表没有阶段字段，无法按 `chain_stage='downstream'` 直接筛选；本件改用链树的父子结构：每条链按 `industry_code` 末两位最大的 L1 视为末段分支，数该分支下全部后代节点（含 L1 自身，容器与叶子都计），得 **256 个**。其中 192 个是叶子、64 个是容器；占全库 1,273 个节点的 20.11%，占 954 个末端叶子的 26.83%。

256 的方向性来自“编码序位近似工艺顺序”这一假设。逐链做语义复核，10 条链的末段 L1 确实是整机集成、整机制造、AI 应用、封测、应用层、研发/规划服务等下游语义；传感器链末段是“传感器生产专用装备”、低空经济末段是“低空配套业”，这两条与“下游”相反或存疑。故本件判部分支持，并把 954（全部末端叶子）作为上界、47（只数末段 L1 直接子节点）作为错误示范、41（只数 L1）作为粗粒度对照一并披露。

### 1.2 业务问题与原意

“下游”在产业链语境里指靠近终端需求的一端：整机、应用、服务、封测、渠道。业务问“下游环节数”，通常是想知道这条链的末端有多丰富——末端环节越多，说明应用场景越分散、可招商/可监测的对象越多；末端环节过少，说明链条还停在原材料或制造段，应用侧没展开。

这个原意决定了“下游”不能等同于“叶子”。叶子只表示“没有子节点”，上游原材料、上游设备也可以是叶子。集成电路链的“半导体材料”下面有大量叶子（光刻胶、硅片、电子特气），它们是上游末端，不是下游。把 954 个叶子全叫下游，会把上游的细分全部算进来，方向正好相反。

### 1.3 口径拆解

| 要素 | 注册表口径 | 本件代理口径 |
| --- | --- | --- |
| 判定字段 | `chain_stage='downstream'` | 无字段，改用编码序位 |
| 统计对象 | `DISTINCT node_name` | `industry_code` 唯一节点 |
| 环节粒度 | 未限定 | L1 分支及其全部后代 |
| 是否含容器 | 未说明 | 含，容器与叶子各计 1 |
| 是否去重名称 | 是 | 否，按编码唯一键 |

两个口径的差异不止“字段换没换”：注册表用 `node_name` 去重，本件用 `industry_code`。全库 1,273 个节点只有 1,150 个不同名称，954 个叶子只有 855 个不同名称；若按名称去重，下游数会被跨链同名环节压低。本件选择编码唯一键，是为了让“环节数”可加总、可回查。

### 1.4 与旧稿、同域指标的差异

| 来源 | 口径 | 数值 | 与本件关系 |
| --- | --- | --- | --- |
| 本件主口径 | 末段 L1 子树（含 L1） | 256 | 交付值 |
| 本件上界 | 全部末端叶子 | 954 | 只作上界，不作下游 |
| 本件错误示范 | 末段 L1 直接子节点 | 47 | 说明“不要只数子节点” |
| 本件粗粒度 | 全部 L1 | 41 | 只到一级分支，分不出上下游 |
| 注册表 | `chain_stage='downstream'` | 不可执行 | 字段不存在，0 行不是 0 个 |
| 同域 `M_CHAIN_KEY_NODE_COUNT` | 关键环节 | 另一口径 | 数关键节点，不区分上下游 |

旧稿在 `_staging21_c` 里做过一次 41 个 L1 的语义分类，思路是“看名称里有没有服务/应用/整机”。本件没有沿用名称关键词，而是用编码序位 + 逐链语义复核：名称关键词会漏掉“封测”（不含服务/应用字样，却是典型下游），也会把“低空配套业”误判成下游。编码序位不是完美规则，但它是确定性的，且错误可以被逐条点名；关键词规则连“错在哪”都说不清。

### 1.5 对象、单位与分母

本指标单位是“个环节”，不是“家企业”，也不是“家次”。一个环节下可以挂 10 万家企业，环节数仍然是 1。`dwd_org_industry_tags` 里一家企业可挂多个环节，那是“挂接家次”，既不能当分子，也不能当分母。本件不做任何除法，因此不存在分母选择问题；但正文引用企业数时必须写清是“家”还是“家次”，这也是本件在 §3.4 单独列表的原因。

### 1.6 本件结论先行

1. 可交付：末段分支口径 **256 个下游环节**，12 条链分列见 §2.6。
2. 参照值：全末端叶子 954 个（上界）、L1 41 个（粗粒度）、直接子节点 47 个（错误示范）。
3. 反例：传感器/传感器生产专用装备、低空经济/低空配套业，编码末位但语义不是下游。
4. 判档：**部分支持**；若甲方接受“末段分支=下游”，可升“完全转换支持”，但需书面确认这两条反例的处理方式。

### 2.2 三种候选口径

在动手前先把“下游环节”的三种可能算法摆出来，逐一否掉或保留：

| 候选 | 算法 | 结果 | 问题 |
| --- | --- | --- | --- |
| A. 全部叶子 | 无子节点的节点 | 954 | 含上游材料/设备叶子，方向错 |
| B. 末段 L1 的直接子节点 | 编码最大 L1 的下一层 | 47 | 漏掉孙辈及更深节点，严重低估 |
| C. 末段 L1 的完整子树 | 编码最大 L1 及其全部后代 | 256 | 方向基本对，2 条链有反例 |

A 的问题是“叶子≠下游”。以传感器链为例，叶子包含“原材料”“生产专用装备”这类上游节点；把它们算下游，等于把产业链倒过来看。B 的问题是“只数一层”。12 条链末段 L1 的直接子节点合计只有 47 个，而完整子树有 256 个；封测只有 2 个直接子节点，但其下有测试设备、测试服务、封装材料等 14 个叶子，只数直接子节点会把整个封测段压成 2。C 保留为交付口径，但必须做语义复核。

### 2.3 主计算

对每条链 $k$，取 L1 集合中编码最大的节点 $t_k$，再取所有以 $t_k$ 为前缀的节点：

$$
t_k = \arg\max_{c \in L1_k} \mathrm{code}(c)
$$

$$
D_k = \{c \in C \mid \mathrm{code}(c)\ \text{以}\ \mathrm{code}(t_k)\ \text{为前缀}\}
$$

$$
\mathrm{Downstream} = \sum_{k=1}^{12} |D_k| = 256
$$

其中 $C$ 是 1,273 个节点，$L1_k$ 是第 $k$ 条链的 9 位 L1 节点（合计 41 个）。编码是层级式的：7 位链根、9 位 L1、11 位 L2，依次类推；因此“以 $t_k$ 为前缀”等价于“$t_k$ 的全部后代”，不需要递归查询。

$D_k$ 同时包含容器与叶子：$|D_k| = 容器数 + 叶子数$。12 条链合计 64 个容器、192 个叶子，64 + 192 = 256。这个分解很重要——如果只数叶子，会得到 192，比 256 少 64；如果只数容器，会得到 64，方向完全错。

### 2.4 为什么用编码序位

可用的方向信号只有三个：字段、名称、编码。

字段信号不存在：无 `chain_stage`，`level` 恒 0。名称信号不稳定：41 个 L1 名称里，有的直接写“应用层”“整机集成”“封测”，有的写“原材料”“生产专用装备”，还有“低空配套业”这种方向模糊的词；用关键词规则要么漏“封测”，要么把“配套”判错。编码信号是唯一确定性的：链树按“根—L1—L2……”递增编码，业务建树时通常也按“上游—中游—下游”顺序排列，末位 L1 大概率是末端。

选择编码序位，不是因为它绝对正确，而是因为它**可复现、可逐条反驳**。任何人拿到 12 条链，都能独立算出同一个 256，并对两条反例提出同样的质疑；关键词规则做不到这一点——换一套同义词表就换一个结果，无法审计。

### 2.8 为什么不选另外三种

**不选 954。** 954 是“末端叶子”，不是“下游”。传感器链的叶子包含原材料与专用装备，生物医药链的叶子包含中药材/原料药；把它们算下游，方向反了。954 只能当上界，不能当交付值。

**不选 47。** 47 是末段 L1 的直接子节点数。封测只有 2 个直接子节点，但其下有 14 个叶子；只数直接子节点会把封测段从 21 压到 3（含自身），严重低估。这个错法在树上很常见：把“子节点”当“后代”，漏掉孙辈。

**不选 41。** 41 是 L1 总数。它不分上下游，只说明每条链有 3—6 个一级分支。把 41 当“下游环节数”，等于说每条链的下游就是全部一级分支，方向信息完全丢失。

**不选“按名称关键词筛”。** 名称里含“服务/应用/整机”的 L1 有 7 个，但“封测”“应用层”“具身智能体”不一定命中；同时“低空配套业”含“配套”会被误判。关键词规则换一套词表就换一个结果，无法复现。

## 三、数据支撑情况

### 3.1 直接支撑

| 支撑项 | 源字段 | 实测 | 强度 |
| --- | --- | --- | --- |
| 链树结构 | `industry_code` / `industry_link_code` | 1,273 节点 / 1,261 边 | 强 |
| L1 清单 | 9 位 `industry_code` | 41 个 | 强 |

| 容器/叶子分解 | 是否有子节点 | 64 / 192 | 强 |

这些量都是集合运算，换人换天结果一致；256 本身是可复算的，争议不在“数得对不对”，而在“这个数是不是下游”。

| 支撑项 | 转换方式 | 结果 | 局限 |

| 分链末端宽度 | 子树节点 / 本链节点 | 5.95%—55.00% | 结构差异，不是质量差异 |

## 四、数据缺失情况

### 4.1 官方字段整体缺失

`chain_stage` 不存在，`downstream` 标记不存在，`level` 退化。官方公式 `COUNT(DISTINCT node_name) WHERE chain_stage='downstream'` 在当前源表执行会直接报“未知列”，不是返回 0 行。按 §3.49，这属于“未测/不可执行”，不能写成“下游环节为 0”。

### 4.2 编码序位不是工艺顺序

传感器链是最硬的反例：末段 L1 是“传感器生产专用装备”，属于上游设备；如果按编码序位判下游，会把设备制造算成下游。低空经济的“低空配套业”同样存疑。现有数据无法判断这是建树习惯、录入顺序，还是业务上确实把“配套”视为末端服务；需要甲方或建树人确认。

### 4.3 名称去重会改变结果

全库 1,273 个节点只有 1,150 个不同名称，954 个叶子只有 855 个不同名称。若按注册表的 `DISTINCT node_name` 统计，跨链同名环节会被合并，下游数会小于 256。本件不按名称去重，并在产物 `integrity.duplicate_node_names` 落盘 123，提醒复用者两种口径不可混比。

### 4.4 无版本、无时间轴

链树没有版本列，无法回答“去年下游有多少个”“本月新增几个下游环节”。本指标只能是截面值；若甲方要“下游环节新增数”，需要先补链树版本或生效时间。

### 4.5 与“叶级挂接数”的区别

`dwd_org_industry_tags` 的挂接行是“企业—环节”家次，1,714,457 家去重企业可以挂出更多家次。下游环节数数的是环节，不是家次；把挂接家次当分母或分子都会得到无意义的比率。本件不做除法，正是为了避开这个坑。

### 4.6 边界总结

可交付：末段分支 256 个、分链 12 行、容器/叶子分解、语义复核 12 行。
不可交付：官方 `chain_stage` 口径、严格工艺意义上的下游、下游环节的时间序列。
判档边界：甲方确认“末段分支=下游”后可升“完全转换支持”；若要求严格工艺顺序，则维持“部分支持”并要求补阶段标注字段。

## 五、结论、边界与复现

### 5.1 结论

1. 交付值：**256 个下游环节**（末段 L1 子树，含 L1 自身）。
2. 结构：64 个容器 + 192 个叶子；占全库节点 20.11%，占末端叶子 26.83%。
3. 分链：合成生物 22 个最多（占本链 55.00%），数字创意 3 个最少（8.11%）。
4. 反例：传感器末段是生产装备、低空末段是配套业，不能无条件称下游。

### 5.2 适用与不适用

| 场景 | 是否适用 | 说明 |
| --- | --- | --- |
| 展示各链末端分支丰富度 | 适用 | 256 与分链值可直接用 |
| 比较链的“应用侧厚度” | 有条件适用 | 需剔除传感器/低空两条反例 |
| 回答官方“下游环节数” | 不适用 | 无 `chain_stage` |
| 做下游环节同比 | 不适用 | 无版本/时间 |
| 当下游企业数用 | 不适用 | 单位是环节，不是企业 |

### 5.3 复现步骤

1. 读 `chain_tree_links_20261022.json` 的 `data`。
2. 取 9 位节点为 L1，按前 7 位分组，组内按编码排序取最大者为末段 L1。
3. 取所有以末段 L1 编码为前缀的节点，计数。
4. 用“是否有子节点”拆容器/叶子。
5. 与 `M_CHAIN_DOWNSTREAM_COUNT_out.json` 的 `per_chain` 逐行比对。

### 5.4 发布建议

标题写“下游（末段）环节数”，不要写“下游环节数”；脚注注明“编码序位代理，传感器/低空两条链存疑”。若甲方要严格口径，建议补一张“环节阶段标注表”（`industry_code`、`stage`、`evidence`、`annotator`），由业务逐条标注上游/中游/下游，再按 `stage` 重算；这张表落地前，256 是当前能给的最诚实值。
