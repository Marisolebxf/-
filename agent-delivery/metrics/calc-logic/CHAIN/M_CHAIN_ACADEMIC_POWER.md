## 摘要

本件把 20261020 旧稿的「深圳单点学术生态」改写为 gkx 口径下的「四市学术生态面板」，
并在同一份脚本里证明了链级读数不可算。旧稿依赖演示库汇总层与开发库旧机读数，单点
min-max 退化后触发 0.5 兜底，最终输出恒为 50.0，这个值不含任何城市间差异信息。
本件在 `gkx` 实测得到高校 3,501 行、科研院所 2,074 行、学者 21,316 行、
论文窗口 52,119 行，四市面板得分为广州 79.6、深圳 76.75、东莞 3.0、惠州 0.0。
链轴方面的结论是否定性的：链成员表装的是企业统一社会信用代码，学研机构装的是
事业单位代码，5 万行等距样本对 5,006 个机构 id 零命中，这不是覆盖率低，是键域不同。
因此本件判 `部分支持`，链级学术生态在拿到「机构 → 链」映射表之前一律留白，
不用区域值顶替，也不按全国均值摊派。

## 一、需求定义概述

### 1.1 所属功能模块（要开发什么）

「学术生态」属于产业链评价体系中的创新供给侧指标，回答的问题是：某条产业链在
某个区域内，是否有足够的高校、科研院所与活跃学者支撑其技术攻关。它与专利产出类
指标的区别在于，专利衡量的是「已经发生的创新成果」，学术生态衡量的是「可能持续
产生成果的组织与人员基础」。在产业链招商与强链补链的场景里，这个指标通常与
「链主企业数」「研发投入强度」并列，用于判断一个区域是「有产业无学科」还是
「有学科无产业」。

需求文档对本指标的期待是链级读数：给定 12 条产业链与四个城市，输出「链 × 市」
的学术生态强度，并支持横向排序。这个粒度决定了数据必须具备两个连接键：企业到链的
归属，以及学研机构到链的归属。本件的全部工作，本质上是在验证这两个键在 `gkx`
里是否同时存在。

### 1.2 为什么需要「学术生态」这个指标

深圳的产业结构长期被概括为「应用强、基础弱」，但这句话在链级上是否成立，需要
分链验证。集成电路、生物医药这类链对学科依赖深，智能终端、软件与信息服务对
学科依赖浅，若只看全市总量，会把结构性差异抹平。学术生态指标的价值，是把
「学科供给」拆到链上，让「哪条链缺学科支撑」变成一个可排序的问题。

另一个用途是对比。广州的高校池与深圳的院所池结构完全不同：广州高校密集，
深圳以新型研发机构为主。如果只数机构总数，广州会因高校数量占优而领先；如果把
高校与院所分开看，深圳的 1,014 家科研院所在数量上反而超过广州的 821 家。
指标设计必须让这种结构差异显性化，而不是被一个总数掩盖。

### 1.3 需求文档是否给出定义方法

需求文档给出了指标名、所属模块与期望粒度，但没有给出计算公式，也没有指定
「学术生态」由哪几个维度合成、权重如何分配。旧稿在这一处的处理是：用机构数、
学者数、论文数三个维度，等权或近似等权合成，并对深圳单点做 min-max。
单点 min-max 在数学上必然退化——最大值与最小值是同一个数，分母为 0，
旧稿用一个 0.5 的兜底值把结果锁成 50.0。

本件不继承这个兜底。四市面板有真实分布，min-max 有定义；链级读数没有分布，
就不输出。这是本件与旧稿在方法上最根本的分歧，也是判 `部分支持` 而非
`完全转换支持` 的直接原因。

### 1.4 类似指标权威机构构建方法可行性分析概要

国际上衡量学术供给常用三类口径。第一类是机构口径，以教育部学科评估、
「双一流」名单为代表，按学科评级给机构赋分，优点是语义清晰，缺点是不覆盖
新型研发机构与企业研究院。第二类是人员口径，以科睿唯安高被引学者、
斯坦福全球前 2% 科学家榜单为代表，优点是能识别活跃个体，缺点是榜单年度更新、
覆盖滞后，且不按城市归属。第三类是产出口径，以自然指数（Nature Index）
为代表，按论文计数，优点是可比性强，缺点是学科偏斜严重（医学与物质科学占比高）。

三类口径在本件里都只能部分借鉴。机构口径可以直接落地，因为 `dwd_org_heis_info`
与 `dwd_research_institute_base_info` 都有城市字段；人员口径只能退化为
「机构名含城市名」的代理，因为学者表的机构 id 整列为空；产出口径可以落地，
但机构名匹配率只有 16.6%，英文论文未并入，主题偏斜无法校正。
三者叠加的结果，是一个「方向正确、精度有限」的面板，而不是一个可以直接
对外发布的权威排名。

### 1.6 本报告的口径与边界（推测定义，须与甲方会签）

本件采用「机构 + 学者 + 论文」三维合成，权重 0.4 / 0.3 / 0.3，每维在四市之间做
min-max 归一到 0—100 后加权。这个权重结构是本件自定义，**待甲方确认**，
既不是需求文档给定，也不是旧稿口径。选择论文权重最高的理由，是论文是三维中
唯一有明确统计期、且能按机构名回溯到城市的产出型变量；机构与学者都是存量截面，
不含强度信息。

边界有三条。第一，面板只在广州、深圳、东莞、惠州四市之间可比，跨省比较无意义，
因为底册的城市字典只覆盖广东为主。第二，论文只取 `cover_year_start` 2021—2024，
2025—2026 库内有值但收录不全，不摊进正式值，也不按 0 补。第三，链级读数不输出，
任何声称「某链学术生态得分」的数字，在本件口径下都是伪造。

## 二、计算过程

### 2.1 总体思路与数据流

计算分两条独立的线。第一条是城市面板线：从高校表与院所表取机构，从学者表取
人员，从论文表取产出，按城市汇总后做三维归一。第二条是链轴验证线：从链成员表
取企业信用代码，从学研两表取机构代码，做集合交集，用交集大小判断链级读数是否
可算。两条线互不依赖，第二条线的结论直接决定第一条线的交付范围。

数据流可以概括为：`dwd_org_heis_info` 与 `dwd_research_institute_base_info`
按 `external_id` 去重后合并成机构池；`dwd_zh_paper.author_info_list` 里的机构名
与机构池的 `name_cn` 精确匹配，命中后继承机构所在城市；
`dwd_scholar.scholar_org_name_zh` 用城市名做子串匹配，得到学者归属；
三个维度的城市计数分别归一后加权。链轴验证线单独跑，只做代码集合比对，
不参与任何求和。

之所以把两条线放在同一个脚本里，是因为它们共享同一份机构池与同一份城市字典。
如果分成两个脚本，机构去重规则容易在两边漂移，最终出现「面板用的机构数」与
「键域比对用的机构数」不一致，评审时无法解释。一个脚本、一次加载、两处引用，
是这类「先验证再计算」的指标比较稳妥的组织方式。

### 2.2 口径定义与公式

设城市集合为 $C=\{\text{广州},\text{深圳},\text{东莞},\text{惠州}\}$，
维度集合为 $D=\{\text{papers},\text{institutions},\text{scholars}\}$。
记城市 $c$ 在维度 $d$ 上的原始计数为 $x_{c,d}$，归一值为：

$$
z_{c,d}=\frac{x_{c,d}-\min_{c'\in C}x_{c',d}}{\max_{c'\in C}x_{c',d}-\min_{c'\in C}x_{c',d}}\times 100
$$

综合分为三维加权和：

$$
S_c=0.4\,z_{c,\text{papers}}+0.3\,z_{c,\text{institutions}}+0.3\,z_{c,\text{scholars}}
$$

其中机构维的原始计数按 `external_id` 去重后计，学者维按机构名含城市名的记录计，
论文维按「论文—城市」对计（一篇论文的作者机构分布在多个城市时，每个城市各计一次，
故论文对总数 19,502 大于有城市归属的论文数 19,223）。

链轴的可算性用一个集合交集判据：

$$
H=\left|\{\text{credit\_code}\}\cap\{\text{external\_id}\}\right|
$$

若 $H=0$ 且两边代码前缀分布不重叠，则判定键域不同，链级读数不可算。
本件实测 $H=0$，链成员样本中前缀为 `12` 的记录数也是 0。

### 2.3 城市字典与机构池构造

机构池由两张表合并。高校表 3,501 行，但只有 2,933 个不同的 `external_id`，
568 行是同校重复录入；科研院所表 2,074 行，无重复。两池按 `external_id` 去重后
相加，再扣除跨池重复 1 例（广州中医药大学与广州中医药大学（广州中医药研究院）
指向同一实体），得到 5,006 个机构 id，与链轴验证线里加载的机构 id 集合大小一致。

城市归属直接取表内 `city` 字段，不做地址解析。这样做的前提是两表的 `city`
填充完整，实测两表都能取出城市，未出现空值导致的丢弃。机构池里同时保留
`heis` 与 `research_institutes` 两个子计数，用于面板展示时的结构解释，但归一
只用合并后的总数，避免高校与院所因名单覆盖范围不同而互相压制。

论文的城市归属不直接取论文表字段，而是通过作者机构名反查机构池。论文表的
`author_info_list` 是一个数组，每个元素含 `institution` 名称。脚本把窗口内
52,119 行论文的机构名展开成 237,461 个机构实例，逐个与机构池的 `name_cn`
精确匹配，命中 39,430 个实例，实例级命中率 16.6%。命中后按机构 id 找到城市，
形成「论文—城市」对。

### 2.4 学者维的代理口径与它的代价

学者表 21,316 行，`scholar_org_id` 非空 0 行，这一列是整列为空，不是填充率低。
在没有机构 id 的情况下，唯一可用的连接方式是机构名的子串匹配：机构名含「广州」
计广州，含「深圳」计深圳，依此类推。四市命中数为广州 86、深圳 194、东莞 7、惠州 0，
合计 287，占学者总数的比例很低。

这个代理口径有两个已知偏差。第一，改名机构会漏计，例如「鹏城实验室」的名称里
不含「深圳」，但它显然是深圳的学术机构；类似的还有「松山湖材料实验室」不含「东莞」。
第二，异地校区会误计，例如某高校深圳研究院的名称含「深圳」，但其主体在广州，
按名称计数会把部分资源算到深圳头上。两者方向相反，无法互相抵消，也无法在本件
内校正。脚本把 487 行机构名为空的记录单独计数，不并入任何城市。

### 2.5 计算步骤（脚本逐步实现）

第一步，建立连接。脚本只连 `gkx`（183.240.141.251:3318），连接参数写死，
带 `max_execution_time`，并对超时做 5 次指数退避重试。任何一次超时都不会被
解释为「查了没数据」，只会被记录为 `probe` 的耗时异常。

第二步，加载机构池。分别查高校表与院所表的 `name_cn`、`external_id`、`city`，
按 `external_id` 去重，合并后统计跨池重复。

第三步，加载学者表。一次查询同时取总行数、`scholar_org_id` 非空数、
机构名为空数，以及四个城市名的子串命中数，避免四次全表扫描。

第四步，加载论文窗口。按 `cover_year_start BETWEEN 2021 AND 2024` 取
`id`、`cover_year_start`、`author_info_list`，展开机构名后与机构池匹配。

第五步，汇总面板。按城市汇总论文对、机构数、学者数，做三维 min-max，加权得综合分，
并按分数排序打 `rank`。

第六步，跑链轴验证。取链成员表 5 万行等距样本的 `credit_code`，与机构 id 集合
求交集，同时统计样本中前缀为 `12` 的记录数与前 12 位为公共前缀的记录数，
用三个数共同证明「不是覆盖率低，是键域不同」。

第七步，落盘。所有中间量、面板、探针耗时、缺口清单写入
`code/M_CHAIN_ACADEMIC_POWER_out.json`，正文的每个数字都能在该文件里找到。

### 2.8 与旧稿（20261020 目录）的差异

旧稿是深圳单点：机构 5,003（全国池去重）、学者 16,120（名称匹配 75.6%）、

旧稿的数据来自演示库汇总层与开发库旧机读数，表名带 `demo_` 前缀，

`%scholar_stat%` 三个模式检索 `information_schema.tables`，返回 0 行。
这不是数据缺失，是结果面本就不在源库，详见 `_work_gkx21/TABLE_ABSENCE_EVIDENCE.md`。

### 2.9 敏感性：权重与归一方式会改哪些结论

广州与深圳的综合分只差 2.85 分，权重稍微一动，排名就会翻转。若把机构权重从 0.3
提到 0.4、论文从 0.4 降到 0.3，深圳的机构归一 100 与学者归一 100 会同时加权，
综合分反超广州；若把学者权重降到 0.1，深圳的学者优势被削弱，广州重新领先。
这说明前两名的排序对权重高度敏感，不宜作为强结论对外表述。

东莞与惠州的位置则很稳。两市的三个维度归一值都在 0—4 之间，无论如何加权都
进不了前二；惠州学者为 0 直接锁死该维下限，除非引入新的学者归属口径，否则
惠州在该维上永远是 0。这类「结构性锁定」比排名更值得写进结论。

### 3.3 数据量、覆盖与代表性

论文全库 100,900 行，窗口内 52,119 行，占 51.65%。这个比例说明 2021—2024 是
库内的主要收录区间；2025—2026 虽有值（6,548 / 2,989 行），但收录不全，
若并入会把「收录进度」误读为「产出下降」。窗口内 19,223 行至少有一个机构名
命中四市机构池，形成 19,502 个「论文—城市」对；未命中的部分并非无机构，
而是机构名不在底册里，或机构在其他城市（脚本统计到 20 个四市之外的城市名，
包括上海、北京、武汉、西安等）。

机构池的覆盖有一个结构性偏差：高校表是全国名单，深圳只有 11 所高校入池，
而院所表以广东为主，深圳有 1,014 家院所。两者混加会让「院所多的城市」显得
学术机构密集，深圳的机构归一 100 正是这个机制的结果，而不是深圳高校多。
这一点必须在读数时说明，否则会被误读为「深圳高校资源第一」。

### 3.4 结构支持判定

面板结构支持：城市 × 三维 × 综合分，粒度与需求的城市级一致。
链级结构不支持：需求要的是「链 × 市」，本件只能给「市」，缺链轴。
两者相加，落到 `部分支持`。这里不存在「抬档」空间——若把城市面板改名为
「链学术生态」并按链复制 12 份，数字会变成完全相同，链间差异为零，
那是伪造而不是估算。

### 3.5 与开发库 live 的差异

旧稿读的开发库以 `gkxlumenx_` 为前缀，属演示库体系；本件只读 `gkx`。
两边的机构池规模差异主要来自名单范围：旧稿的 5,003 是全国去重池，
本件的 5,006 是「全国高校去重 + 广东为主院所去重 - 跨池重复」，数量接近
但构成不同。学者数的差异更大（16,120 对 21,316），旧稿的 75.6% 是
「名称匹配率」，本件的 287 是「城市名子串命中数」，两个数的分母不同，
不能相除比较。

### 3.6 缺口清单（≥4 条，详见 §四）

1. 链轴键域不相交，链级读数不可算（决定性）。
2. 学者 `scholar_org_id` 整列为空，只能用机构名代理。
3. 论文机构名匹配率 16.6%，英文论文未并入。
4. 高校表 568 行重复，已去重但反映源表质量问题。
5. 高校池全国、院所池广东为主，混加造成结构偏差。
6. 权重与归一方式为本件自定义，未经会签。

## 四、数据缺失情况

### 4.1 缺口清单与逐条影响

**缺口一：链轴不可闭合。** 链成员表装的是企业统一社会信用代码（前缀 `91`），
学研机构表装的是事业单位代码（前缀 `12`）。5 万行等距样本对 5,006 个机构 id
零命中，样本中前缀为 `12` 的记录数也是 0。这不是覆盖率低，是键域不同：
即使把样本扩大到全表 2,283,762 行，交集仍然只可能来自「某机构恰好有企业信用代码」
这种异常记录。后果是链级学术生态无法计算，任何链级值都是伪造。
补法：甲方或三方提供「机构 → 链」映射表，或在机构表增加 `chain_code` 字段。

**缺口二：学者 id 轨为空。** `scholar_org_id` 非空 0 / 21,316，整列为空。
后果是学者只能按机构名子串归属，改名机构（鹏城实验室、松山湖材料实验室）
漏计，异地校区误计。补法：回填 `scholar_org_id`，或在学者表增加城市字段；
回填后必须重算学者维，不能沿用本件数值。

**缺口三：论文机构名匹配率低。** 237,461 个机构实例只有 39,430 个命中底册，
命中率 16.6%。英文论文 1,387 行未并入，医学与医院类机构在底册缺失。
后果是论文维低估，且低估不是随机的——医学类论文多的城市被压低更多。
补法：扩充机构别名表，补英文机构名与医院名单，再重跑匹配。

**缺口四：高校表重复录入。** 3,501 行只有 2,933 个不同 `external_id`，
568 行是同校重复。本件已按 id 去重，但源表重复说明上游合并逻辑有问题，
若其他指标未去重，会把高校密集市抬高。补法：在源表层面去重，或在所有
引用该表的指标里统一去重规则。

**缺口五：两池覆盖范围不一致。** 高校池是全国名单，院所池以广东为主。
混加会让院所多的城市显得机构密集。补法：分池展示，或对两池分别归一后
再合成，而不是先合并再归一。

**缺口六：权重未会签。** 0.4 / 0.3 / 0.3 与 min-max 都是本件设定，
前两名排序对该权重敏感。补法：由甲方给出权重，或改用等权并披露敏感性。

### 4.2 明确不做什么（禁止的替代）

不做链级读数。不用城市面板按链复制。不用全国均值填充缺失城市。不把
2025—2026 的论文按 0 摊进年度序列。不用学者总数（21,316）代替城市学者数。
不把「机构名含城市名」的比例（287 / 21,316）说成学者覆盖率。
这五条里任何一条被违反，产出的数字都会比留白更有害，因为它看起来像真的。

### 4.3 若甲方补齐后的口径升级路径

第一步，拿到「机构 → 链」映射表后，把机构池按链打标，链级机构维即可成立。
第二步，回填 `scholar_org_id` 后，学者维从名称代理升级为 id 连接，学者维可
按链归属。第三步，扩充机构别名表与英文论文后，论文维匹配率提升，链级论文维
可成立。三步都完成后，本指标可从 `部分支持` 升到 `完全转换支持`，
届时需要重跑全部数值，不能在本件结果上打补丁。

## 附录 C 可行性完整版

若只问「四市学术生态能不能算」，答案是能，本件已算，且每个中间量都落盘。
若问「链级学术生态能不能算」，答案是不能，且不是「暂时不能」——链成员与
学研机构的键域在源表设计上就不同，除非上游增加映射，否则永远闭合不了。

可行性的边界可以写成三句话。第一，城市级面板是确定可算的，误差来自论文
匹配率与学者代理口径，方向已知，可通过扩充底册改善。第二，链级读数是确定
不可算的，误差不是「大小」问题，是「有无」问题。第三，两者之间的桥是
「机构 → 链」映射表，这张表不存在，桥就不存在。

因此本件的交付策略是：把可算的部分算到可复核，把不可算的部分证明到可复核，
中间不做任何平滑或替代。这也是 `部分支持` 这个档位的本意——不是「差一点」，
而是「一部分成立、一部分不成立，且能指清楚哪部分是哪部分」。
