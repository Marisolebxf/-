## 与数据血缘（D9）的关系

**一个指标对象，两套真源，禁止互相冒充。**

| | 梳理（给人全文） | 数据血缘 `data-lineage-policy.md` |
|--|----------------|--------------------------------|
| 回答 | 谁做、按什么类型派、WBS、A/B 轨、8/25 交什么 | 这条指标**是什么**、**现在算不算得出**、ⓘ 怎么展示 |
| 不管 | 不定义 8 件套字段表、不改 D1–D4 枚举 | 不派 A1/A2 单、不定专题维度 Owner |
| 机器落点 | `algo-results/` · `request/` | `registry/` seed + 矩阵 |

同一条 `metric_id`：梳理决定**派给谁、走 STAT 还是 MODEL**；血缘决定**身份证写没写齐、角标亮哪几枚**。

### 对照（梳理概念 → 血缘字段）

| 梳理里说的 | 血缘里是 | 落哪 |
|------------|----------|------|
| 口径 / 适用性 / 8 件套能否过门 | 8 件套第 1–3、6–9 项；`D1=aligned` = 9 项齐 | `registry/cfg_metric-*-seed.yaml` |
| `algorithm.type`（轴 A） | **已是** 8 件套第 5 项 `algorithm_type`（v1.5） | 同上；A1 表2 只当会签底稿，签完回填 seed |
| OPEN / 门 1 | `D1=draft` 合法；类型可 `UNKNOWN` | seed 增量 + 矩阵 D1 |
| 公式会签（唐绍祖） | `formula` + `algorithm_type`≠`UNKNOWN` | seed；矩阵可标 `lifecycle_stage=formula_signed` |
| GDF 贴源 / ODS 够不够 | **D3** 源映射（责任方=甲方/供应方） | `registry/metric-readiness-matrix-*.yaml` |
| 项目内 DWD/ES/图算不算得出 | **D2** 结构支撑（责任方=项目内） | 同上 |

| 「库里有没有这条」 | **D1**（`missing` 则 D2–D4 = `n/a`） | 同上；**不是** 8 件套里的一列 |

### 明确不并进 8 件套（2026-08-22 淮政玮）

8 件套 = 身份（这条指标是什么）。下面这些是**状态 / 过程**，与身份正交，继续放矩阵，ⓘ 主卡下段「就绪度四行」展示：

```
D1 定义对齐   →  库里有没有、口径齐不齐（aligned = 8 件套齐，故 D1 不能再当 8 件套字段，否则自指）
D2 结构支撑   →  项目自研存储算不算得出
D3 源映射     →  三方源喂不喂得饱
D4 接入状态   →  当前线上跑的是什么数据
lifecycle_stage → 填齐流水线走到哪一关（过程位置，不是第五维角标）
```

合法组合不要用 8 件套卡死：`D1=aligned` 且 `D4=mock`（身份证写清了、数还是假的）。

`algorithm_type` **要**进 8 件套：它是身份属性（这段计算是 STAT 还是 MODEL），不随 Mock/真数切换而变。`UNKNOWN` 禁止派实现单，也禁止标 `D1=aligned`。
