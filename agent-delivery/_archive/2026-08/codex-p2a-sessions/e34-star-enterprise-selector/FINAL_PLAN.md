# FINAL_PLAN.md

## 任务定义与边界

修正 E-34“明星企业介绍”的对象模型。明星企业由运营按未来产业维护固定名单，每产业允许 `0..N` 家；前台只允许在当前产业已发布名单内切换，不扩展为全库企业查询、排名、评估、对比或 CMS 编辑。

## 目标与非目标

### 目标

- 同一产业存在多家明星企业时，用户可以明确选择当前介绍对象。
- 当前企业可通过 URL 刷新、分享和返回恢复。
- 0 家、1 家、多家及内容部分缺失时均有稳定行为。
- IA、TRACE、USM、Wireframe 的对象基数、路由、状态和禁止行为一致。

### 非目标

- 不支持名单外自由选企或跨产业混排。
- 不在前端生成明星企业 TopN、评分或排名。
- 不展示内部权重、阈值、敏感证据或 CMS 草稿。

## 关键决定及理由

1. 每产业固定运营名单为 `0..N` 家；“固定表”表示名单由运营维护，不表示固定一家。
2. 2 家及以上使用可搜索下拉框；候选项展示 Logo、企业名称和一句入选标签。
3. CMS `sort_order` 第一家为默认企业；前端不计算展示排名。
4. URL 使用 `enterprise_code` 保存当前企业状态。
5. 0 家显示业务空态；1 家直接展示且隐藏选择器；多家显示选择器和总数。
6. 切换企业后更新 URL、清除旧企业局部状态并返回 E-34 首屏。
7. 名单条目与基础介绍必须发布后才进入前台；其他内容区允许部分缺失并使用业务空态。

## 约束与风险

- Q048 仍需闭合正式候选池、名单维护责任、排序唯一性、标准版本与基础指标 `metric_id`。
- Logo 或入选标签缺失时的具体视觉占位属于非阻塞 UI 细节。
- 当前 E-34 四件套已有未提交修改，修订必须保留其中 `data_time` 等有效调整。

## 执行路径

1. 修订 IA：增加明星企业名单选择层及 0/1/N 边界。
2. 修订 USM：增加选择、URL 恢复、切换和发布准入场景。
3. 修订 Wireframe：增加选择器、字段、交互和异常状态。
4. 修订 TRACE：统一路由状态、验收条件、内容依赖和 Q048 临时默认。
5. 同步客户决策清单 Q048，并进行四件套一致性核对。

## 非阻塞开放问题
