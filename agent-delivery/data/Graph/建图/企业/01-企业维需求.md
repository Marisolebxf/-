# 企业维需求

七要素里，本包只灌企业这一端。其余要素的点可以随 schema 建出来，本批不灌数。

点的 VID 用 `ent:` 加企业稳定 ID `org_id`，整段长度不超过 80。`org_id` 为空，或对端 ID 不在企业主表里，这一行不写。不要用企业名称生成 VID。

## 第一批要写入

| 对象 | 方向 | 源表 | 写入 |
|---|---|---|---|
| 企业点，Tag `enterprise` | — | `enterprise_base` | VID `ent:{org_id}`。属性用 schema 里已有的列：`name`、`node_type`、`enterprise_code`、`chain_role`、`weight`、`props`。源表上多出来的经营字段放进 `props`，不新加 Tag 列 |
| `supply` | 企业 → 企业 | `enterprise_supply_chain` | 两端都要有 `enterprise_base.org_id`。属性 `weight`、`props` |
| `parent_sub` | 母公司 → 子公司 | `enterprise_parent_subsidiary` | 子企业取 `org_id`，母企业取 `parent_org_id`。两端都要在企业主表里。属性 `weight`、`props` |

## 本包范围里，但不进第一批

| 对象 | 原因 |
|---|---|
| `cooperate` 企业 — 企业 | 现有数据能写出本企业 → 对方这一条有向边。必须的是双向：两个方向各写一条。双向规则没落地之前，第一批不写 |
| `participates` 企业 → 产业链环节 | 企业自己的产业表写出的边名不是 `participates`。能对上的路径在产业链数据里，不在本批企业表。本包只保留企业这一端的边名，本批不灌 |

## 不要建

- 企业 — 科研机构
- 企业 — 技术（论文、专利、项目）
- 企业 — 人才
- 投资关系。不要把别的系统里的 `INVESTS_IN` 改名写成 `cooperate` 或 `supply`
- 子公司边不要复用别的系统里的 `SUBSIDIARY_OF`。本包的边名是 `parent_sub`，方向是母公司指向子公司

## 边的方向怎么落

Nebula 的边都是有向的。需求里写「双向」或「无向」时，写入就是两个方向各一条，边名不变。不要为同一对端点再起一个新边名。
