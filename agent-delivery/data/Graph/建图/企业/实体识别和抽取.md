# 企业 · 实体识别和抽取

给燕大配知识图谱引擎脚本时看。这里只整理本侧已经写过的企业点识别。空间写 `gkx_chain`。下文出现的 `demo_gkx_chain` 是本侧 demo 代码里的字面量，不要照抄。

企业维只有一种点：Tag `enterprise`。不另建技术点、人才点、科研机构点。

## 从哪张表抽

库：`gkxlumenx_dwd`。不要读 `demo_gkxlumenx_*`，不要读供应方库。

| 项 | 值 |
|---|---|
| 表 | `enterprise_base` |
| 一行一个企业 | 主键列 `org_id` |
| VID | `ent:` 加 `org_id`。`org_id` 自己已经以 `ent:` 开头时不再加。整段长度超过 80 不写 |
| Tag | `enterprise` |
| 展示名 | `enterprise_name`。名称为空时用 `org_id` |
| 点上的列 | `name`、`node_type`（固定 `enterprise`）、`weight`（固定 `1.0`）、`props`（JSON 字符串） |

`org_id` 为空：跳过，原因 `empty_field`。VID 超长：跳过，原因 `vid_too_long`。不要用企业名称生成 VID。

本侧算子实际读出的列：

| 列 | 放进 props 的键 |
|---|---|
| `org_id` | `org_id` |
| `enterprise_name` | 点的 `name`，不进 props |
| `industry_category` | `industry` |
| `headquarters_city` | `city` |
| `is_high_tech` = 1 | `tags` 加「高新」 |
| `is_listed` = 1 | `tags` 加「上市」 |
| `is_little_giant` = 1 | `tags` 加「专精特新」 |
| `registered_capital`、`revenue_latest`、`rd_staff_count`、`patent_grant_count`、`legal_representative` | 只进 ADS 识别记录的中文属性，不进图上的 `props` |

图上的 `props` 只有 `org_id`、`city`、`industry`、`tags`。经营字段多出来的不要新加 Tag 列。`enterprise_code`、`chain_role` 本侧企业点 INSERT 不写。

## 本侧代码

| 步骤 | 位置 |
|---|---|
| 读表、生成 VID、组 props | `repos/demo-algo-ent-analysis/entan/graph/ops.py`：`_load_orgs`、`ent_vid`、`_ner`。算子 `ENT_NER_ORG` |
| 写入 | 先 ADS `entity_recognition`、`graph_node`，再 `INSERT VERTEX enterprise`。菜单默认 `dry_run=true`，只预览 |
| 批量灌点 | 同仓 `entan/graph/nebula_loader.py` 的 `_load_nodes`。只插入 `node_type=enterprise` 的行，其它类型跳过 |

规则摘成 [脚本/enterprise_rules.py](脚本/enterprise_rules.py) 的 `ent_vid`。那个文件不连库。

## 模型只补短语，不造企业

`mode=llm` 时，`_llm_extra` 最多看 8 家，只收 `alias`、`industry_phrase`，写进识别记录，不写边，也不另造点。没有密钥或调用失败就退回规则。提示语禁止编造 `org_id`。燕大做企业点时按表走即可，不必接这段。

## 不要抽成企业点的东西

- 合作表、供给表、母子表里的对端名称。没有稳定 `org_id` 就跳过，不建点。
- 产业链表上的环节。环节是另一个维度的点。
- 论文、专利、项目。它们是「技术」，不是企业。
