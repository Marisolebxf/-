# 产业链 · 实体识别和抽取

给燕大配知识图谱引擎脚本时看。这里只整理本侧已经写过的环节识别。空间、库账号见企业包的环境文件。空间写 `gkx_chain`。demo 代码里的 `demo_gkx_chain` 不要照抄。

环节只有一种点：Tag `segment`。链不是环节，不写 Tag `chain`。

## 从哪张表抽

库：`gkxlumenx_dwd`。

| 项 | 值 |
|---|---|
| 表 | `industry_chain_node` |
| 一行一个环节 | 列 `node_id` |
| VID | `segment:` 加 `node_id`。已经以 `segment:` 开头时不再加。整段长度超过 80 不写 |
| Tag | `segment` |
| 展示名 | `node_name`。名称为空时用 `node_id` |
| `segment_key` | `node_id`，空则用 `node_code` |
| `chain_id` | 表上的 `chain_id`。这是属性，不是另一个点 |
| `chain_stage` | `stage_code` |
| `weight` | `0` |
| `props` | JSON，现码放 `node_code` |

`node_id` 为空：跳过。不要用环节名称生成 VID。

正式加工把 `level>=2` 的链树行洗进这张表。入图不再按 level 过滤。

同一次菜单识别还会读 `industry_chain`，写成 Tag `chain`、VID `chain:{chain_id}`。那不是本维的点。配到知识图谱引擎的脚本只插入 `segment`。

## 本侧代码

| 步骤 | 位置 |
|---|---|
| 读表、生成 VID | `repos/demo-algo-science/chainan/graph/graph_ops.py` 的 `_ner`。算子 `CHAIN_NER_INDUSTRY` |
| 菜单 | `POST /internal/chain/graph/ner` |

规则摘成 [脚本/chain_rules.py](脚本/chain_rules.py) 的 `segment_vid`。那个文件不连库。

## 不要抽成环节的东西

- `industry_chain` 的一行链。
- 企业、服务机构、论文、专利、项目、人才、政策。
- 关系表里只有名称、没有 `node_id` 的端点。
