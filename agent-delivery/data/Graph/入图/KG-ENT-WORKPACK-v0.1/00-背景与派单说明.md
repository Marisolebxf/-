# 背景与派单说明

## 背景

科技信息展示要读一张图。图上的七类对象是：企业、产业链环节、科研机构、技术、人才、服务机构、政策。技术指论文、专利、项目，不是单独的「技术点」。图库用 NebulaGraph。展示页面只读，不在页面请求里建图。

燕大此前的合规交付是另一件事。那一批按合规口径交算法和结果，不承担本系统上线后的加工链路。本包做的是系统集成：加工要对上应用已经定下的点、边和读表，目标是真正上线会用的那套入图。当前处在这套加工的研发阶段，先把过程调通，再谈切到生产。

超算中心也不是这一阶段的环境。超算是生产环境，跑已经调通的入图。研发阶段不在超算上试，也不把超算上的空间、作业或数据当作本包的加工现场。

这一阶段要调通的是整条入图，不只是建好 Tag 和 Edge：

1. 实体和关系的事实数据从哪张表读，读哪些列，缺稳定 ID 的行怎么跳过。
2. 这些读取和写入规则做成有逻辑的 Python 脚本，不把口径散落在手工语句里。
3. 脚本配置到知识图谱引擎平台，由平台按本包指定的空间执行。

智树在本包里给出：要建哪些点、哪些边、写进哪个空间、第一批用哪些已经能对上的表。燕大按上面三条把入图做出来并回签。

## 两个空间

| 空间 | 谁用 | 本包 |
|---|---|---|
| `gkx_chain` | 燕大加工入图。新建 | 建空间、建 Tag、建 Edge、写入本批数据，都在这里 |
| `demo_gkx_chain` | 智树展示读图，以及现有 demo 写图 | 不要写。不要把这里的点或边拷进 `gkx_chain` |

`gkx_local_1`、`gkx_full_1` 是燕大平台上已有的空间，不是本包的入库目标。

## 本版请燕大做的事

1. 在 `gkx_chain` 执行 [03-schema-gkx_chain.ngql](03-schema-gkx_chain.ngql)。语句可以重复执行。不要 `DROP`。
2. 第一批只写入企业点、企业到企业的 `supply`、企业到企业的 `parent_sub`。源表、VID 和方向见 [01-企业维需求.md](01-企业维需求.md)。读表和写入做成 Python 脚本，配置到知识图谱引擎，空间用 `gkx_chain`。
3. 表洗完之后怎么触发这些作业，见 [06-GDF触发契约.md](06-GDF触发契约.md)。回调还没上线，按该页「现在实际怎么交接」执行。缺 ID 的补法见 [07-gapfill清单.md](07-gapfill清单.md)，本版不建表。
4. 做完后按 [05-回签.md](05-回签.md) 回填：写入了哪些 Tag 和 Edge、大约多少条、哪些行因为没有稳定 ID 没写。填好的回签上传到 [对接文档/燕大](../../../../工程过程/04-系统集成/07-图数据库集成/对接文档/燕大/)，文件名带完成日期。

## 本版先不做

- 不写 `demo_gkx_chain`。
- 不把 demo 里已有的点或边迁过来。
- 企业合作的双向边、企业挂到产业链环节，留到下一批。说明在需求文档里。
- 不建企业到科研机构、企业到技术、企业到人才。
- 账号、口令、API Key 不在本包里。需要连接信息时向白鑫凤索取。
