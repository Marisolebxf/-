# 派单说明

各维共用的背景、空间和连接见企业包 [00-背景与派单说明.md](../KG-ENT-WORKPACK-v0.1/00-背景与派单说明.md)、[03-schema-gkx_chain.ngql](../KG-ENT-WORKPACK-v0.1/03-schema-gkx_chain.ngql)、[04-环境.md](../KG-ENT-WORKPACK-v0.1/04-环境.md)。本页只写产业链环节。

空间仍是 `gkx_chain`。不要写 `demo_gkx_chain`，不要把 demo 的点或边拷过来，不要写入 `gkx_local_1`、`gkx_full_1`。

## 本版请燕大做的事

1. schema 若企业包还没在 `gkx_chain` 执行过，先执行企业包里的初始化语句。可以重复执行。不要 `DROP`。本维不要另建一套 Tag 名。
2. 第一批只写入环节点，Tag `segment`。源表、VID 见 [01-产业链维需求.md](01-产业链维需求.md)。读表和写入做成 Python 脚本，配置到知识图谱引擎。
3. 表洗完之后怎么触发，见 [06-GDF触发契约.md](06-GDF触发契约.md)。回调还没上线，按该页「现在实际怎么交接」执行。缺上下游事实的补法见 [07-gapfill清单.md](07-gapfill清单.md)，本版不建表。
4. 做完后按 [05-回签.md](05-回签.md) 回填。填好的回签上传到 [对接文档/燕大](../../../../工程过程/04-系统集成/07-图数据库集成/对接文档/燕大/)，文件名带完成日期。

## 本版先不做

- 不写 Tag `chain`。链不是环节。
- 不写 `depends_on`。正式关系行目前是父子 `parent_child`，不能改名充上下游。
- 不写服务机构到环节的 `participates`。正式加工不产这种行。
- 不建环节到科研机构、技术、人才、政策。
- 企业点不在本包造。企业到环节的 `participates` 等企业点已经在 `gkx_chain` 上再写，规则在需求文档里，本版触发表不包含它。
