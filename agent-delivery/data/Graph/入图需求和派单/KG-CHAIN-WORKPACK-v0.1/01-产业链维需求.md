# 产业链维需求

七要素里，本包只灌产业链环节这一端。企业点归企业包。服务机构点归服务机构维。其余要素的点可以随 schema 建出来，本批不灌数。

点的 VID 用 `segment:` 加环节稳定 ID `node_id`，整段长度不超过 80。`node_id` 为空不写。不要用环节名称生成 VID。

`chain` 不是环节。不要把链写成 Tag `segment`，也不要为本包再建一个链的点。

## 第一批要写入

| 对象 | 方向 | 源表 | 写入 |
|---|---|---|---|
| 环节点，Tag `segment` | — | `industry_chain_node` | VID `segment:{node_id}`。属性用 schema 里已有的列：`name`、`segment_key`、`chain_id`、`chain_stage`、`weight`、`props`。`name` 取 `node_name`，空则用 `node_id`。`segment_key` 取 `node_id`，空则用 `node_code`。`chain_stage` 取 `stage_code` |

正式加工把 `level>=2` 的链树行洗进 `industry_chain_node`。入图按这张表里已有的行写，不再按 level 重滤。

## 本包范围里，但不进第一批

| 对象 | 原因 |
|---|---|
| `depends_on` 环节 → 环节 | 必须边是上下游。源表 `industry_chain_node_rel` 里，现码只认 `upstream`、`downstream`、`depends`、`depends_on`、`dependency`、`上下游`、`依赖`。正式加工写进这张表的是 `parent_child`，不在这份名单里，现码会跳过。父子不能改名写成 `depends_on` |
| `participates` 企业 → 环节 | 源表 `industry_chain_entity_rel` 能对上：`entity_type=enterprise`，关系类型是 `belongs_to`、`participates`、`participates_in`、`所属`、`参与`，终点 `segment:{node_id}`。两端都要已经在 `gkx_chain` 上，本路径不造企业点。企业包第一批不灌这条边。等企业点写入之后再开 |
| `participates` 服务机构 → 环节 | 同一张关联表，`entity_type=service_institution` 且关系类型在上面的名单里，才能写成这条边。正式加工目前只写企业行。服务机构点也不在本包造 |

`participates` 在 schema 里没有属性列。写入时不要带 demo 代码里的 `chain_role`。

## 不要建

- 环节 — 科研机构
- 环节 — 技术（论文、专利、项目）
- 环节 — 人才
- 环节 — 政策
- 环节 → 链的 `belongs_to`。链不是环节
- 别的系统里的 `CHILD_OF`、`BELONGS_TO_NODE`、`DOWNSTREAM_OF`。不要改名写成 `depends_on` 或 `participates`
