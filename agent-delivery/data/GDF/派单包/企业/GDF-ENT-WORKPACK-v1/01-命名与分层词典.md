# 命名与分层词典（GDF 必读）— v1.2

> 派单第一条必须对齐。混名会导致产线配错源/目标。

## 1. 标准用语

| 说法 | 指什么 | GDF 侧动作 |
|------|--------|------------|
| **承诺表 / doc** | `third-party-source/doc/*.xlsx` 及 `md-extract/` | Wave A **表名真源** |
| 三方 / 供应方表 | `gkx` 库中与承诺英文表名对应的物理表 | Wave A 的**源** |
| 供应方 `ods_*` | 供应方内部层 | **不读、不配产线** |
| `gkxlumenx_ods` | 本项目 ODS 镜像库 | Wave A 的**目标**（同名落盘） |
| 项目自建 `gkxlumenx_dwd.enterprise_*` | 架构师自研 DWD | Wave B 的**目标** |
| live `SOURCE-TABLES` | 运行时 DDL 沙箱清单 | 仅核验；**不得**覆盖承诺表名 |

## 2. 承诺表 vs live 易混名（v1.2 关键）

| 承诺英文表名（用这个） | live 中常见旧名/近似 | 说明 |
|------------------------|----------------------|------|
| `dwd_org_base_info` | `dwd_org_reg_info` | 主数据以承诺为准 |
| `dwd_org_heis_info` | `dwd_org_hels_info` | 拼写以承诺 heis 为准 |
| `dwd_bid_base_out` 等四张 | `dwd_org_bid_info` | 招投标按出库四表镜像 |
| `dwd_forg_shareholder_info` 等 | `dwd_forg_shareholder`（无 _info） | 以后缀承诺名为准 |
| （不贴）`company_base` 等 | `dwd_company_*` | 量子工商簇，本波排除 |

源库若**只有**旧名、无承诺名 → 登记供应方核验，**禁止**自行改清单关单。

## 3. 反例（禁止）

| 错误理解 | 正确做法 |
|----------|----------|
| 「live 有 200+ dwd 表，全都贴」 | 只贴 `02` 承诺 40 张 |
| 「主表肯定是 reg_info」 | 承诺主表是 `dwd_org_base_info` |
| 「量子 company_base 也要贴」 | 明确排除 |
| 「Mapping 报告里的 ODS 是供应方 ods_*」 | 是项目贴源层（承诺 `dwd_*` / 本地 `gkxlumenx_ods`） |

## 4. 主键口径（企业）

| 体系 | 键 | 说明 |
|------|-----|------|
| 国内机构 | 以承诺表字段为准（常见 `org_id` / 信用代码类字段） | Wave A 原样镜像 |
| 归一 | Wave B | Wave A **不做**实体归一 |
