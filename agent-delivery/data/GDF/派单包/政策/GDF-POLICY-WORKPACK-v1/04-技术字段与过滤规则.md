# 技术字段与过滤规则（Wave A）

来源：供应方工作约束。全文：`agent-delivery/data/third-party-source/gkx-mysql-raw/加工/SUPPLIER-WORK-CONSTRAINTS.md`。  
政策另有 `is_history`（`sources/ods-ddl.md`）。

## 1. 取数过滤（默认）

取数 **不加** 行过滤。不要写 `is_deleted = 0`，也不要写 `IFNULL(is_history, 0) = 0`。

`is_deleted`、`is_history` 都原样进入 ODS，Wave B 写入 `policy_base_info` 的同名列。增量同步靠这两列看出哪些行已删除、哪些行已变成历史。  
`is_history`：`0` 当前 / `1` 历史；`NULL` 按当前。`NULL` 原样落库，不在取数时改成 `0`。  
应用读 DWD 时自行加 `is_deleted = 0` 与 `IFNULL(is_history, 0) = 0`。  
源表没有其中一列：登记例外，启动会确认后再灌；不得在取数 SQL 里补条件把行丢掉。

## 2. 六技术字段（不得当业务主字段）

`created_time` / `updated_time` / `creater` / `updater` / `table_data_source`：Wave A 原样镜像，不映射为业务口径。  
`is_deleted`、`is_history`：Wave A 原样镜像，Wave B **直接映射**到 `policy_base_info` 同名列（不是作业写成常量 `0`）。二者都不是业务主键；有效且当前的行由应用过滤。

政策另有 `operator_remarks` / `insert_remark`：贴源原样保留；**不**映射为业务口径。

## 3. 镜像策略

目标表用源 `SHOW CREATE TABLE` 对齐（库名改为 `gkxlumenx_ods`）。首次全量。Wave A **不做**字段改名、**不做**平面切片（`source_plane` 在 Wave B 派生）。

`dwd_policy_base.content` / `dwd_global_policy_base.content` 为 `longtext`，国内合计约百 MB 级：必须流式/分批提交，禁止整表缓冲后一次 commit。禁止截断正文。

## 4. 禁止

写三方 `gkx`；依赖供应方 `ods_*`；把技术字段当业务口径；用旧 v1 37 列 DDL 建 ODS。
