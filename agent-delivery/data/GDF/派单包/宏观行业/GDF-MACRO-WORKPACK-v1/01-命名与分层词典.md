# 命名与分层词典（宏观行业 GDF）— v1.0

> 供应方 `gkx.dwd_*` 是本项目 ODS，不是项目 DWD。混名会配错源 / 目标。

## 1. 标准用语

| 说法 | 指什么 | GDF 动作 |
|------|--------|----------|
| 供应方表 | `gkx.dwd_macro_index_data` 等六张 | Wave A **源**（角色 = 本项目 ODS） |
| 供应方 `ods_*` | 供应方内部层 | **不读** |
| `gkxlumenx_ods` | 本项目贴源 | Wave A **目标**（同名镜像，仍叫 `dwd_*`） |
| `gkxlumenx_dwd.macro_*` | 项目宏观 DWD（六张） | Wave B **目标** |
| `gkxlumenx_ads.macro_city_section` | 城市宏观截面 | ②a **目标** |
| Demo `demo_gkxlumenx_*` | 联调模拟 | **禁止**当正式目标 |
| Demo `ods_sync` | `polan/ods_sync.py` | **禁止**当产线 DAG |

## 2. 六表名对照

| 中文名 | 供应方 / ODS 表名 | 项目 DWD 表名 | 行数（2026-11-09 实测） | 性质 |
|---|---|---|---:|---|
| 数据表（事实） | `dwd_macro_index_data` | `macro_index_data` | 20,000 | 事实 |
| 指标属性表 | `dwd_dim_index_attribute` | `macro_index_attribute` | 867 | 维度 |
| 区划表 | `dwd_dim_admin_area` | `macro_admin_area` | 20,000 | 维度 |
| 计算维度表 | `dwd_dim_index_cal` | `macro_index_cal` | 3 | 维度 |
| 时间维度表 | `dwd_dim_index_dur` | `macro_index_dur` | 7 | 维度 |
| 数据来源表 | `dwd_dim_source_code` | `macro_source_code` | 4 | 维度 |

项目 DWD 表名无 `dwd_` 前缀，统一 `macro_` 前缀。理由：避免与金融包、行业分析包的维度表同名（区划、来源类维度在三个市场研究要素库里都可能出现）。

## 3. 易混名

| 容易混 | 区别 |
|--------|------|
| 事实表 `area_code` vs 区划表 `area_code` | **不是同一个东西**。事实表 `area_code` = 事实所属区划键（国家码 / 省码 / 市码 / 区县码混存，长度 2 / 3 / 4 / 12）。区划表 `area_code` = **区县**编码（第 16 列，「区县编码」）。区划表本行自己的编码是 `cur_code` |
| 事实表 `unit_use` vs 属性表 `unit_use` | 事实表 = 该行数值的真实单位（`元` / `%` …）。属性表 = 指标的**库存单位**，恒为「元」。TB 行真实单位 `%`，只认事实表 |
| `dim_cal` / `dim_dur`（事实表） | 存**代码**（`TB` / `DNLJ`），与维度表同名列按代码 join。不存名称 |
| `source_code`（事实表 / 区划表 / 来源表） | 事实表、区划表里是来源**代码**（`LBS` / `NATIONALSTAT` / `GACC` / `worldbank`）；来源表里是代码主键，名称在 `source_name` |
| `update_time` vs `updated_time` | `update_time` = 供应方业务口径「数据更新时间」；`updated_time` = 供应方技术字段「库内最近更新」。DWD 里前者落 `src_update_time`，后者落 `ods_updated_time`；DWD 自己的 `updated_time` 由作业生成 |

| 对象 | 键 |
|------|-----|
