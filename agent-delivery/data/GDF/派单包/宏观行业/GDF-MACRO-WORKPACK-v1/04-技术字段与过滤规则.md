## 1. 以 live 为准的结构差

2026-11-09 报告对照 Excel：六表都只差一列——Excel 多出 `t_id`（tdsql 分片键），live `gkx` 没有。结论：

- `t_id` **不作源、不建列**。
- Excel 的「是否主键 / 约束字段」是供应方设计意图；live 六表物理主键都是 `dwd_id`（auto_increment），业务键没有物理唯一索引，所以业务键唯一性要在 Wave B 校验（见 §4）。
- Excel 样例里 `update_time` / `occur_period_t` 是 Excel 序列号（如 `46149.72…`），live 是 `datetime` / `varchar(20)`（实测 `occur_period_t` 形如 `2018-06-01`，`update_time` 形如 `2026-07-27 15:50:44`）。按 live 类型取，不做 Excel 序列号换算。
- Excel 把区划类列标成 `longtext`，live 是 `varchar(32/50/100/150)`。按 live。

## 2. 取数过滤（默认）

取数 **不加** 行过滤。不要写 `is_deleted = 0`。  
`is_deleted` 原样进入 ODS，Wave B 写入 DWD 同名列。增量同步靠它看出哪些行已删除。  
应用读 DWD 时自行加 `is_deleted = 0` 与 `index_value IS NOT NULL`。  
实测（2026-11-09）：事实表 `is_deleted` 全为 0、`index_value` 全非空、业务键五列全非空——这是快照，不是保证，不要据此省掉过滤。

## 3. 区划反解（Wave B 事实表派生列；②a 依赖）

### 3.1 为什么要反解

- `dwd_dim_admin_area` 里**没有四个政策城市（深圳 / 广州 / 北京 / 上海）自己的行**：`cur_code` 等于事实键的行数为 0；`cur_level` 为 2 / 3 的只有云南省与 14 个外省市。不能 `fact.area_code = dim.cur_code` 取城。
- 区划表下级行（街道 / 社区 / 区县）带 `city_code` / `city_name` / `province_code` / `province_name`，可以反解城市。
- 事实表 `area_code` **长度不统一**：2（省码 / 直辖市码）、3（境外国家码）、4（国家码如 `0086`）、12（市码 / 区县码）。不得假设 12 位。
- 事实表 `area_code` 无中文，不得 `LIKE '%深圳%'`。

### 3.2 反解规则（按序，首个命中即停；`area_resolve` 取值）

查区划表时只用 `is_deleted = 0` 的行（这是**反解查表**，不是取数过滤）。区划表 `city_code` / `province_code` / `area_code` 都取去重值。

| 序 | `area_resolve` | 命中条件 | 派生 `city_code` / `city_name` / `province_code` |
|---:|---|---|---|
| 1 | `city_by_city_code` | `CHAR_LENGTH(fact.area_code)=12` 且存在区划行 `city_code = fact.area_code` | 取该 `city_code` 对应的 `city_code`、`city_name`、`province_code` |
| 2 | `municipality_by_province_code` | `fact.area_code IN ('11','12','31','50')`（北京 / 天津 / 上海 / 重庆）且存在区划行 `province_code = fact.area_code` | 取该省码下 `city_code`、`city_name`、`province_code`（直辖市在区划表里 `city_name` 实测就是 `北京市` / `天津市` / `上海市` / `重庆市`，`city_code` 为 `110100000000` / `120100000000` / `310100000000` / `500100000000`） |
| 3 | `district_by_area_code` | `CHAR_LENGTH(fact.area_code)=12` 且存在区划行 `area_code = fact.area_code`（区划表第 16 列 = 区县编码） | 取该区县所属 `city_code`、`city_name`、`province_code`（**只作标注，不聚合到城市**，见 OPEN-MACRO-03） |
| 4 | `unresolved` | 以上都不中 | 三列留 NULL（含国家级 `0086`、境外国家码） |

要点：

1. 规则 2 只列四个直辖市。事实表对天津（`12`）、重庆（`50`）也用省码；v1 白名单覆盖核验只做了深圳 / 广州 / 北京 / 上海，**天津 / 重庆未核白名单覆盖**，但反解规则对它们同样成立。
2. 区划表同一 `city_code` 下 `city_name` 唯一（实测 0 个 `city_code` 对应多个 `city_name`），所以取 `MIN(city_name)` 即可。
3. `area_code_type` **不参与反解**。反解对所有 type 一视同仁；是否采用某 type 的行，由使用方决定（②a 只用 `type=1`，见 §3.3）。
4. 反解结果只写**派生列**，**不改** `area_code`。

### 3.3 `area_code_type`

| 值 | Excel 定义 | live 实测（事实表 20,000 行） | v1 处理 |
|---:|---|---:|---|
| 1 | 行政区 | 19,819 | DWD 保留；**ADS 只收 type=1** |
| 2 | 片区 | 0 | — |
| 3 | 园区 | 49（仅一个 12 位码，反解到长沙） | DWD 保留；ADS 不收（含义待澄清，OPEN-MACRO-01） |
| 4 | **未定义** | 132（同一 `area_code` 下与 type=1 平行；如 `'31'` 27 行、`'50'` 12 行；另有沈阳 / 大连 / 武汉 / 海口） | DWD 保留；ADS 不收（OPEN-MACRO-01） |

不带 `area_code_type=1` 取数，会把平行序列混进同一城市同一指标。使用方（含②a）必须带。

断言（任一失败 = 区划口径失效，停 Wave B，交我方）：

1. 四个政策城市的 `fact.area_code` + `area_code_type=1` 行数 > 0，且反解类别与 §3.4 一致。
2. `unresolved` 中不含 §3.4 四个键。
3. 事实表业务键 `(index_code, occur_period, area_code, area_code_type, dim_cal, dim_dur)` 无重复。
4. 事实表 `dim_cal` / `dim_dur` / `index_code` / `source_code` 在对应维度表无孤儿。

## 4. 键唯一与维度 join

- 事实表按**代码**join 维度表：`dim_cal` ↔ `dwd_dim_index_cal.dim_cal`；`dim_dur` ↔ `dwd_dim_index_dur.dim_dur`；`index_code` ↔ `dwd_dim_index_attribute.index_code`；`source_code` ↔ `dwd_dim_source_code.source_code`。按名称 join（`dim_cal_name` 等）全不中。
- 事实表 `source_code` 在同一业务键下只有一个值（`LBS` / `NATIONALSTAT` / `GACC` 不并存），无需来源择优（口径真源 pipeline-macro-effect-proxy §1「键唯一」）。
- Wave B 业务键校验：写 UK 冲突时**计数并丢弃后写之外的行**，不改键。

## 5. 单位

- 属性表 `unit_use` = 库存单位，恒为「元」，不得拿来标注 TB（同比增长）值。
- TB 行真实单位 = 事实表 `unit_use`（四城 TB 行实测全为 `%`）。
- 属性表 `unit_show` = 对外推荐展示单位（如 `元,千元,万元,亿元`）。

## 6. 技术字段（不得当业务主字段）

`created_time` / `updated_time` / `creater` / `updater` / `table_data_source` / `operator_remarks` / `insert_remark`：Wave A 原样镜像，**不映射为业务口径**。  
Wave B 只带 `updated_time` → DWD `ods_updated_time`（增量水位用）；`creater` / `updater` / `table_data_source` / `operator_remarks` / `insert_remark` 不进 DWD。  
`is_deleted`：Wave A 原样镜像，Wave B **直接映射**到 DWD 同名列（不是写成常量 `0`）。

## 7. 镜像策略

目标表用源 `SHOW CREATE TABLE` 对齐（库名改为 `gkxlumenx_ods`）。首次全量。Wave A **不做**字段改名、**不做**区划反解（反解在 Wave B 事实表上做）。无 `longtext` 大字段；六表合计约 4 万行，可一次性全量，不需要流式。

## 8. 禁止

写三方 `gkx`；依赖供应方 `ods_*`；把技术字段当业务口径；用 Excel 的 `t_id` 建列；按名称 join 维度；对事实表不带 `area_code_type` 就当城市序列用。
