## 0. 与 v1.x 的关键纠偏

| 项 | v1.x（旧） | v2.0（对齐在线原型） |
|----|-----------|----------------------|
| 页面结构 | 概览 / 列表 / 对比 / 画像 四视图 | **两个 Tab**：类型与区域分析、领域分布分析 |
| 顶部筛选 | 产业/环节/区划/资质/规模/类型/评分 | **区域 + 时间窗口 + 产业 + 企业类型**（仅类型与区域 Tab） |

## 1. 原型功能点清单（探查结果）

### 1.1 导航与路由

| 项 | 值 |
|----|----|
| 菜单 | 企业分析 → 重点企业分析 |
| 路由 | `/enterprise-center/key-enterprise-analysis` |
| 领域 Tab | `?view=domain` |
| 权限码 | `MENU_ENT_TYPE` / `MENU_ENT_DOMAIN` |

### 1.2 Tab A：类型与区域分析

#### A1. 顶部筛选（专属输入，不与领域 Tab 共享）

| 控件 | 原型表现 | 码值建议 |
|------|---------|---------|
| 区域 | Cascader：全国热门科创城市 / 深圳 / 全部 | 复用 `POST /meta/regions`；热门科创城市为前端分组或字典扩展 |
| 时间 | 窗口下拉（近3年）+ 起止年份（2023—2026） | 前端枚举窗口；接口传 `year_from` / `year_to` |
| 产业 | 多选 Select，默认「全部」 | 复用 `/meta/filters.industry_chains` 或产业链字典 |
| 企业类型 | 多选 Select，默认「全部」 | **此处是资质/标签型企业类型**（高企/上市/小巨人等），不是工商 `company_type`；复用 `POST /meta/tags?category=qualification` |

> ⚠️ **口径注意**：原型「企业类型」选项语义是重点企业标签（高企/上市/专精特新/小巨人…），对应 ES `tags_flat`，**不是** `company_type`（有限责任公司等）。v1.x 把它当成工商类型是错误的。

#### A2. KPI 卡片（3 张）

| KPI | 原型值示例 | 计算口径（临时默认） |
|-----|-----------|----------------------|
| 匹配企业数 | 50 家 | 当前筛选条件下命中企业数 |
| 覆盖企业类型数 | 3 类 | 命中企业 `tags_flat` 中资质类标签去重数 |
| 覆盖区域数 | 10 个 | 命中企业所在区县（或当前下钻层级）去重数 |

#### A3. 重点企业空间分布

| 能力 | 说明 |
|------|------|
| 地图视图 | Leaflet 气泡 + 热力；区县标注「南山区 25家」 |
| 列表视图 | 表头：地域 / 重点企业数 / 所在区域 / 操作「在地图中查看」 |
| 显示热力 | Switch |
| 地图工具 | 放大 / 缩小 / 复位 / 全屏 |
| 返回上一级 | 下钻后可用；顶部区域筛选不因地图下钻反写 |
| 点击区域气泡 | 下钻/聚焦该区；右侧「区域洞察」与清单计数同步（如南山区 → 清单 25） |

#### A4. 区域洞察（右侧）

| 模块 | 说明 |
|------|------|
| 当前区域 + 企业数 Tag | 例：深圳市 / 50 家 |
| 查看企业清单（N） | 打开 Drawer |
| 当前区域企业类型结构 | 环形图（上市 / 小巨人 / 高企…） |
| 同级区域分布 TOP5 | 例：南山 25、福田 4、龙岗 4… |

#### A5. 企业清单 Drawer

| 字段/操作 | 说明 |
|-----------|------|
| 标题 | `{区域}企业清单` |
| 来源上下文 | 顶部范围 + 地图当前区域 + 企业类型 + 数据更新时间 |
| 搜索 | 企业名称 / 统一社会信用代码 / 产业 / 区域 |
| 卡片字段 | 名称、信用代码、区县、产业、标签（高企/上市/专精特新…） |
| 操作 | 查看画像；勾选；全选当前结果；打开对比篮；加入对比篮 |

### 1.3 Tab B：领域分布分析

> 输入与 Tab A **隔离**：只共享「数据更新至」时间。  
> **分析对象来源**：对比篮企业，经本页「分析企业」多选下拉选择（1～N）；可「返回对比篮」调整集合。

#### B1. 空态

- 文案：请先在对比篮选择 1～N 家企业
- 按钮：前往对比篮选择企业 / 返回对比篮

#### B2. 有选中企业后（用户截图 `05f-domain-filled`）

示例：已选「深芯微集成电路股份有限公司」「前海生物医药研究院有限公司」共 2 家。

| 模块 | 原型表现 |
|------|---------|
| 已选企业 | 多选下拉（企业芯片）+「已选 2 家」+「返回对比篮」 |
| 领域布局概览 KPI | 已覆盖领域 **2** / 涉及企业 **2** / 跨领域企业 **0** / 识别依据 **6** 条 |
| 企业领域覆盖 | 矩阵：行=企业，列=领域（集成电路、生物医药）；单元格「3 条依据」（可点开） |
| 跨领域布局 | 关系图：浅蓝=企业，深蓝=产业领域；边连到所属领域 |
| 重点领域分布表 | 产业领域 / 涉及企业 / 识别依据 / 代表企业 / 操作「查看识别依据」 |

#### B3. 识别依据弹框（用户截图 `05g-domain-evidence`）

触发：矩阵单元格「N 条依据」或表行「查看识别依据」。

| 项 | 原型 |
|----|------|
| 标题 | 为什么识别为「{领域}」· {企业名} |
| 证据块（每条） | 类型标题 + 摘要文案 + 来源 + 抽取时间 + 版本号 |
| 证据类型（已出现） | **业务范围** / **产品线** / **技术/专利** |
| 来源示例 | 企业登记信息/经营范围摘要；企业公开产品资料/产品标签；专利与技术数据 |
| 版本示例 | `keyent-domain-fixture-v2`（Mock 批次） |

**底部三按钮 = 跳转已有模块，本菜单不新做接口：**

| 按钮 | 去向 | 说明 |
|------|------|------|
| 企业详情 | 统一企业画像 | 已有 `/profile*` |
| 进入企业评估 | 企业评估模块 | 已有菜单/路由，带入当前 `org_id` |
| 进入风险洞察 | 风险洞察模块 | 已有菜单/路由，带入当前 `org_id` |

> 原型挂载点：`ENT-KEYENT-F04-*`、`ENT-KEYENT-F05-EVIDENCE-REQ`；待甲方口径 Q013（广度/深度/多元化暂不输出伪精确值）。

## 2. 数据源映射

### 2.1 类型与区域分析

| 功能 | 推荐数据源 | 字段/表 |
|------|-----------|---------|
| 筛选-区域 | ES | `region_id` / `province` / `city` / `district` |
| 筛选-时间 | ES | `incorporation_year`（企业成立时间） | ✅ 已确认（P-1） |
| 筛选-产业 | ES | `industry_chain_names_flat` / `industry_chains_flat` | 用 flat 字段避免 nested query |
| 筛选-企业类型 | ES | `tags_flat`（资质标签） |
| KPI / 地图分桶 | ES | `tags_flat=key_enterprise`（或业务认定规则）+ `terms` 聚合 district/city |
| 区域类型结构 | ES | `terms` on `tags_flat`（限定当前区域 filter） |
| 企业清单 | ES | search + `_source` 轻量字段 |
| 码值-区域树 | DWD/Meta | `/meta/regions` ← `dwd_code_region` |
| 码值-标签 | DWD/Meta | `/meta/tags?category=qualification` |

### 2.2 领域分布分析

| 功能 | 推荐数据源 | 说明 |
|------|-----------|------|
| 已选企业基础信息 | ES mget | 名称/标签/区县 |
| 领域归属 | DWD 或算法 ADS | 企业↔领域关系 + 证据条数；当前原型用规则关键词 Mock |
| 识别依据明细 | DWD/ADS | 业务范围片段 / 产品标签 / 专利技术标签 |
| 跨领域企业判定 | 聚合 | 同一企业命中 ≥2 个领域 |

> ✅ 领域归属走 ES `core_tech_tags_flat`；识别依据实时查 5 张 DWD 表（`enterprise_extra` / `enterprise_industry_product` / `enterprise_chain_patent` / `enterprise_fund_project` / `enterprise_patent_history`），不新建表。

## 3. 接口设计（对齐原型）

### 3.1 总览

| # | 接口 | 数据源 | 用途 | 状态 |
|---|------|--------|------|------|
| — | `/meta/regions` `/meta/tags` `/meta/filters` | Meta | 筛选码值 | ✅ 已有，复用 |
| — | Java `/topic/v1/compare-basket/*` | Java | 加入/打开对比篮 | ✅ 已有，复用 |
| — | `/profile` `/profile/card` | ES | 查看画像跳转后的详情 | ✅ 已有，复用 |
| 1 | `/key-analysis/overview-kpi` | ES | TabA KPI 三张卡 | **新增** |
| 2 | `/key-analysis/map-distribution` | ES | 地图/列表区域分桶 + 采样 | **新增**（沿用 v1.1 设计） |
| 3 | `/key-analysis/region-insight` | ES | 右侧区域洞察（类型结构+同级 TOP） | **新增** |
| 4 | `/key-analysis/enterprise-list` | ES | 企业清单 Drawer | **新增**（替代 v1 的 filter-list 语义） |
| 5 | `/key-analysis/brief-card` | ES | 区县级企业点点击轻量卡（若点位层启用） | **保留/可选** |
| 6 | `/key-analysis/domain-overview` | ES | 领域布局概览 KPI | **新增** |
| 7 | `/key-analysis/domain-matrix` | ES | 企业×领域覆盖矩阵 | **新增** |
| 8 | `/key-analysis/domain-graph` | ES | 跨领域关系图数据 | **新增** |
| 9 | `/key-analysis/domain-list` | ES | 重点领域分布表 | **新增** |
| 10 | `/key-analysis/domain-evidence` | DWD | 识别依据弹框 | **新增** |

> **砍掉/降级的 v1 接口**：`compare`、`profile-summary/tech/business/chain/trend` 不再作为本菜单必做；对比走 Java 篮，画像走统一 profile。`district-stats` 能力并入 `region-insight`。

### 9.4 发现的问题

#### P-1 ✅ 时间窗口字段已确认

- **结论**：使用 `incorporation_year`（企业成立时间）做时间筛选，口径明确，无需登记客户决策。
- **ES 字段**：`incorporation_year`（integer），支持 range query。
- **DWD 来源**：`enterprise_base.incorporation_date`。

#### P-2 🟢 产业筛选必须用 flat 字段（已确认无问题）

- **结论**：ES 同时存在 `industry_chains`（nested）和 `industry_chains_flat`（keyword 数组）。本模块产业筛选**必须用 `industry_chains_flat`**，走 terms filter 命中缓存；若误用 nested query 会触发 join 级别开销，2 亿文档下性能不可接受。
- **行动项**：代码评审时强制检查 `industry_chains_flat` 使用；在 `_FIELD_STRATEGY` 文档中已有标注。

#### P-3 ✅「企业类型」下拉口径已确认

- **结论**：顶部「企业类型」下拉**不含 `key_enterprise` 自身**，选项固定为：外企/高企/小微/上市/专精特新/小巨人/链主龙头，对应 ES `tags_flat` 中的 7 个资质类标签。
- **行动**：前端下拉从 `/meta/tags?category=qualification` 获取，后端在返回时排除 `key_enterprise`；`covered_type_count` KPI 自然不含 `key_enterprise`。无需登记客户决策。

#### P-4 ✅ 领域分布分析完全可落地（不建表，实时查现有 DWD 字段）

- **ES 字段**：`core_tech_tags_flat`（keyword 数组）已存在，枚举为集成电路/AI芯片/工业软件/生物医药/储能/智能终端等核心技术标签，**直接作为企业↔领域归属关系使用**。
- **v1 ADS 表**：早期设计已有 `ads.ent_domain_cover`（含 `domain_matrix` JSON），正式阶段可读此表。
- **识别依据（domain-evidence）不建表，实时查 5 张现有 DWD 表**：

  | 证据类型 | DWD 来源表 | 查询方式 | 返回内容 |
  |---------|-----------|---------|---------|
  | 业务范围 | `enterprise_extra.business_scope` | PG `WHERE org_id=?` | 经营范围全文，截取领域相关片段 |
  | 产品线 | `enterprise_industry_product` | PG `WHERE org_id=? AND chain_name LIKE '%{领域}%'` | 产品名称列表（按产业链×环节归类） |
  | 技术/专利 | `enterprise_chain_patent` | PG `WHERE org_id=? AND chain_name LIKE '%{领域}%' LIMIT 5` | 专利名称列表（按产业链维度归类，比企业维度专利更精准） |
  | 技术/专利（补充） | `enterprise_fund_project` | PG `WHERE org_id=? AND domain_code=?` | 科研项目名称（自带领域代码 D-IC/D-BIO…） |
  | 技术/专利（汇总） | `enterprise_patent_history` | PG `WHERE org_id=? ORDER BY data_year DESC LIMIT 1` | 有效专利总数 |

  **关键发现**：`enterprise_industry_product`（企业×产业链×环节×产品）、`enterprise_chain_patent`（产业链维度专利）、`enterprise_fund_project`（领域科研项目，自带 domain_code）这 3 张表本身就按产业链/领域维度存储，是识别依据的最佳来源——不需要关键词 LIKE 猜测，直接按 chain_name/domain_code 精准查询。

  **查不到就没有依据**：每类证据独立查询，某张表查不到数据就不返回该类证据。证据条数 = 实际命中的类型数（0～3 条）。

- **建议**：
  1. domain-overview/matrix/graph/list：ES mget + `core_tech_tags_flat` 内存聚合
  2. domain-evidence：PG 查 5 张 DWD 表拼装 3 类证据
  3. **不新建任何表**

#### P-5 🟢 region_id 前缀匹配支持三级下钻（无问题）

- **结论**：`region_id` 为 keyword，支持前缀匹配（`4403*`=深圳全部区县，`440305`=南山区）。map-distribution 的 `dimension=province/city/district` 可通过 `region_id` 前缀 + terms 聚合实现，无需额外字段。

#### P-6 ✅ brief-card 接口定位已明确

- **结论**：ES 每个企业都有 `addr_lng`/`addr_lat`（经纬度坐标），地图可展示企业点位。brief-card 接口就是点击企业点位时弹出轻量信息卡（名称/标签/区县/产业），ES get `org_id` + `_source.includes` 即可，性能 <10ms。
- **行动**：brief-card 从「可选」改为「必做」，实现方式为 ES single-get。
