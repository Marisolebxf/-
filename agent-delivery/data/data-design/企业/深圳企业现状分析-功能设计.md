| 深圳企业 + 产业链过滤 | ES | `region_id` 前缀 `4403` + `industry_chains` nested / `industry_chains_flat` |

### 9.4 发现的问题

#### P-S1 ✅「重点环节企业」口径已有数据支撑

- **结论**：ODS `dwd_industry_chain_info` 表有 `node_imp_level`（节点重要性等级）字段，可用于定义「重点环节」。
- **临时口径**：`node_imp_level` ≥ 某阈值（如 2 或 3）的节点即为重点环节，落在这些节点上的企业即「重点环节企业」。demo 阶段用此口径，正式上线后由业务确认阈值并调整。
- **ES 映射**：当前 ES `industry_chains` nested 里没有 `node_imp_level` 字段，需 ETL 补充，或 chain-kpi 接口内联查 DWD `enterprise_industry_chain` JOIN `dwd_industry_chain_info`。

#### P-S2 🟢 nested 聚合在深圳子集下性能可接受

- **结论**：chain-stage-stats 需对 `industry_chains` nested 做 terms 聚合。虽然 nested 聚合有开销，但前置 `region_id=4403*` + `industry_chains_flat=指定链` 双重 filter 后，候选文档数通常 ≤1 万，nested terms 在此量级下 80-150ms 可接受。
- **注意**：若未来放开「全国」区域，nested 聚合 2 亿文档会超时，届时需改 ADS。

#### P-S3 ✅ 产业链标准节点字典已有 ODS 源表

- **结论**：ODS `dwd_industry_chain_info` 表本身就是产业链标准节点字典，完整 DDL 包含 `chain_code`/`chain_name`/`node_id`/`node_name`/`node_type`/`node_stage`/`node_imp_level`/`parent_id`/`level`/`node_seq` 等字段。
- **完整度计算**：分子 = 深圳企业实际覆盖的 `node_id` 去重数（从 ES/DWD `enterprise_industry_chain` 聚合）；分母 = `dwd_industry_chain_info` 中该 `chain_code` 的 `node_type=2`（业务节点）总数。
- **行动**：DWD 直接引入 `dwd_industry_chain_info` 作为码表（完整导入非 ETL），无需新建 `dwd_industry_chain_standard_node`。chain-kpi 接口联查此表算完整度。

#### P-S4 ✅「链中角色」枚举已确认

- **结论**：链中角色暂定 4 类：**上游 / 中游 / 下游 / 暂未标注**，不包含「智库标注」等其他类型。
- **数据来源**：ES `industry_chains.node_stage`（1=上游/2=中游/3=下游），无 node_stage 的企业归为「暂未标注」。
- **行动**：chain-stage-stats 接口的 `role_distribution` 按 `node_stage` 聚合，映射为上游/中游/下游/暂未标注四类即可，无需扩展枚举。无需登记客户决策。

#### P-S5 🟡 企业密度分母（面积）已登记为已知问题

- **现状**：v1 设计已明确 `ent_type_dist.density` 和 `ent_sz_status.city_density` 字段，v1 Q012 已登记「密度分母（面积/GDP）」为开放问题，标注来源为 `❌面积/GDP维表`。
- **结论**：这不是新问题，v1 已识别并登记。企业密度 = 企业数 / 城市面积，面积数据需外部导入。
- **建议**：
  1. 新建静态码表 `dwd_code_city_area(city_code, city_name, area_sqkm)`（一次性导入民政部公开数据，码表统一 `code_` 前缀）；
  2. 或在 `ads.ent_sz_status` 预聚合时直接算好 `city_density` 值写入，接口只读结果；
  3. demo 阶段 Mock 密度值，沿用 v1 Q012 已有登记，无需重复登记。

#### P-S6 ✅ `ent_sz_status` ADS 表已在 v1 设计中存在

- **现状**：v1 设计（`企业域数据库设计(v1).md` §13）已有 `ads.ent_sz_status` 表，DDL 包含：
  - `industry`（产业链）、`city`（深圳/对标城市）
  - `sz_count`（纳统相关企业数）
  - `city_avg_tech_power`（平均技术力）
  - `city_density`（企业密度）
  - `chain_completeness`（产业链完整度）
  - `key_node_count`（重点环节企业数）
