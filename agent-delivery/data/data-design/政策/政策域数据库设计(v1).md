## 4. NebulaGraph space `gkx_policy`（政策关联图谱）

> 架构铁律：图谱用 NebulaGraph（`10.50.75.136:9669`），禁 Neo4j；图算法在 Python（algorithm-agent），Java 不直连 nGQL。
> 对接 bid §1.1.1.1.1.1.1.2.5/2.6（政策实体识别构建 + 政策实体关系抽取）。

### 4.1 Tag（7 类实体）


| tag          | 含义        | 关键属性                                                  | 来源                   |
| ------------ | --------- | ----------------------------------------------------- | -------------------- |
| `policy`     | 政策        | policy_id, title, level, region, publish_date, status | dwd.policy_base_info |
| `industry`   | 产业        | industry_code, name                                   | 跨域产业链维表              |
| `tech`       | 技术        | tech_code, name                                       | 跨域技术域                |
| `enterprise` | 企业        | enterprise_id, name                                   | 跨域企业域 dwd.enterprise |
| `talent`     | 人才        | talent_id, name                                       | 跨域人才域                |
| `org`        | 机构(实施/监管) | org_id, name, org_type                                | pubdeptname / 跨域机构域  |
| `service`    | 服务机构      | service_id, name                                      | 跨域服务域                |


```ngql
CREATE SPACE IF NOT EXISTS gkx_policy (partition_num=10, replica_factor=1, vid_type=FIXED_STRING(64));
USE gkx_policy;
CREATE TAG IF NOT EXISTS policy(policy_id string, title string, level int, region string, publish_date date, status int);
CREATE TAG IF NOT EXISTS industry(industry_code string, name string);
CREATE TAG IF NOT EXISTS tech(tech_code string, name string);
CREATE TAG IF NOT EXISTS enterprise(enterprise_id string, name string);
CREATE TAG IF NOT EXISTS talent(talent_id string, name string);
CREATE TAG IF NOT EXISTS org(org_id string, name string, org_type string);
CREATE TAG IF NOT EXISTS service(service_id string, name string);
```

### 4.2 Edge（4 类关系）


| edge           | 语义              | 起点→终点                                           | 来源                    |
| -------------- | --------------- | ----------------------------------------------- | --------------------- |
| `support`（扶持）  | 政策扶持产业/企业/人才/机构 | policy → industry/enterprise/talent/org/service | allfactors 扶持要素抽取     |
| `apply_to`（适用） | 政策适用对象          | policy → enterprise/talent/industry             | elements/keypoints 抽取 |
| `regulate`（监管） | 政策监管/受监管主体      | policy → org/enterprise                         | elements 抽取           |
| `cite`（引用谱系）   | 上位/下位政策引用       | policy → policy                                 | pedigree 谱系           |


```ngql
CREATE EDGE IF NOT EXISTS support(weight double, factor_type string, src_table string);
CREATE EDGE IF NOT EXISTS apply_to(weight double, src_table string);
CREATE EDGE IF NOT EXISTS regulate(weight double, src_table string);
CREATE EDGE IF NOT EXISTS cite(relation string COMMENT '上位/下位', weight double);
```

> 图谱支撑指标：`M_POLICY_RELATION_DEGREE`（加权度中心性）；后续深度模型可在图上跑社群发现/路径分析。
> PG 镜像：按 baseline 方案，图节点/边同步双写 `ads.graph_node` / `graph_edge`（见 registry），供 Java 只读。

## 6. ETL 阶段建议（对齐映射报告 §8）

### 6.1 Phase 1 — 直接映射加载（<1 周）

`dwd.policy_base_info` 约 19 个 ✅ 直接字段：policy_id/title/文号/机构/日期/层级/地区/摘要/关键词/正文/链接/谱系/要素/要点/扶持要素/附件/来源。ADS 基础 5 表（level/type/timeseries/national/sz）可先用 Mock 填充供前端联调。

### 6.2 Phase 2 — 轻量加工（1 周）

- `status`/`level` 枚举映射（docstatus 20/30→1/2；policylevel→1~4）
- `gis_location` 地理编码（region→经纬度）
- `sci_tech_attribute` 科创属性规则判定（keywords+elements）
- `application_conditions` / `related_entities` 结构化要素二次解析
- `implementation_date`/`expire_date`/`execution_cycle` 从要素/正文提取（expire_date 优先取 ODS expiration_date）
- ADS 评分类表（focus/intensity/effect）等待 algorithm-agent 实现 formula（QPOL-02/03 口径确认后）

### 6.3 Phase 3 — 国际政策接入

海外政策读 `dwd_global_policy_base`（`organ` / `year` / `category` / `country` / `region` / `language` / `doc_type` 等），不再使用 `dwd_zck_intl_policy` 的 `translate_title` / `media_type` / `class`。对照 `storage/POLICY/etl/ods-to-dwd-mapping.md`。
