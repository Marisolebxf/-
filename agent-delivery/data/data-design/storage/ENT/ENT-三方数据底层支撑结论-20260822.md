## 0. 一页结论

### 0.0 三类主口径（本次调整）

对外结论只保留三类，业务表和指标各出一张清单。旧的六态（`present_nonempty` / `present_empty` / `missing` / `alias_conflict` / `join_sparse` / `definition_blocked`）降为证据子码，不再当主结论。

| 三类 | 含义 | 业务表怎么判 | 指标怎么判 |
|---|---|---|---|
| **A 结构支持且数据完整支持** | 表/字段在，当前批次有有效行，按现有口径能落地使用 | 该表自身可作为对应 DWD 实体或事件原料 | 所需源表和字段都在，且当前样本能算出业务结果 |
| **B 结构支持、暂无可用数据** | 表/字段在，但空表、全删除，或跨表对不上同一批企业 | 表能建、Mapping 能写，不能验收装数结果 | 公式所需对象在，但缺有效行或无法回连主档 |
| **C 结构不支持** | 缺表，或缺少计算必需的维度/关系 | 承诺表不存在，或该业务对象没有独立维度/关系表 | 缺源表，或缺市场规模、链位、供应关系、分位基准、面积/GDP 等维度 |

落地规则：

- 业务表看“这张表自己能不能用”，不看它能否撑起全部指标。
- 指标看“这个 `metric_id` 按完整口径算不算得出来”。复合指标只要缺一个必需维度，整项落 **C**。
- `join_sparse`（股东/投资/专利/标签对不上主档）对**表**仍可是 A，对**依赖该关联的指标**是 B。
- 公式、阈值、别名未定时加“口径待定”，不单开第四类；有数据则仍标 A/B。
- 历史/Mock ADS 不计 A。

### 0.1 总判定

当前底层数据对企业域的支撑结论不是“166 张表已到，可以直接开发”，而是：

1. **国内企业基础、工商、财务、风险事件主路径具备结构原料，但只能判定为“有条件支撑”。**
2. **国外机构当前不具备可联调的数据面**：Excel 承诺 8 张表，除国外上市企业年报财务表外，其余 7 张在上游为 0 行或有效数据为 0，不能进入本轮正式验收。
3. **产业链到企业的核心关系不具备正式支撑**：产业链字典和资讯有数，但企业标签/产品标签有效行不可用；GDF v2.1 依赖的 `dwd_org_industry_chain_dtl` 未落入当前 demo ODS。
4. **专利原料已到，但企业归属关系不可验收**：专利主表 38,200 行、法律状态/标题等分表有数，但以企业名称关联主表仅命中 14/38,200；这属于“源表存在、当前批次不可关联”，不能误判为无源，也不能宣称指标已可用。
5. **投资、股东、财务等表同样存在跨表样本不一致**：投资仅 67 条、股东仅 145 条可命中企业主表。当前批次高度疑似各表独立样例集合，`representativeness=unknown`，不能用于覆盖率、准确率或正式联调结论；抽样方式仍需供应方确认。
6. **20 个 UI-hit P0 指标中，没有一项满足“源表、稳定关联、DWD、算法、真实结果”五门全绿**。`M_ENT_MARKET_SHARE` 明确无细分市场规模来源；供应商/供应链中心性缺直接供应关系；其余多为结构部分支撑或业务/算法口径阻塞。
7. **项目 DWD 与运行代码存在 P0 契约冲突**：实库 `enterprise_risk_summary` 是 `risk_type` 长表设计，`lumen-topic-py` ORM 明确定义成一企一行宽表；在裁决前不能继续加载风险汇总。
8. **demo/formal 数据拓扑未统一**：`lumen-topic-py` 配置仍可读 `demo_gkxlumenx_dwd`，`lumen-etl-es-py` 默认读 `gkxlumenx_dwd`。同一企业链路可能读取不同实例，必须在联调前关闭该分裂。

## 1. 判定口径

主结论只用 §0.0 的 A/B/C。下列子码只解释证据，不对外并列输出：

| 子码 | 映射 | 含义 |
|---|---|---|
| `present_nonempty` | 表侧 A | 表存在且有有效业务行 |
| `present_empty` | 表侧 B | 表存在但 0 行或 `is_deleted` 后有效行为 0 |
| `missing` | 表侧 C | Excel/GDF 需要，当前基线不存在 |
| `join_sparse` | 表侧仍可为 A；指标侧 B | 结构可关联，当前批次命中极低 |
| `alias_conflict` | 不改 A/B/C | 真名未冻，A/B 表也不得双写 |
| `definition_blocked` | 附加“口径待定” | 公式/阈值/别名未确认 |

仍有效的边界：

- 表非空不等于指标可进 A；
- 指标 A 必须能用当前批次算出，不允许拿 Mock/历史 ADS 充数；
- 本批样例不用于填充率或质量代表性结论，`representativeness=unknown`。

收到 §8 同 cohort 数据；要求至少 30 个国内企业同时命中主档、财务、标签、股东/投资、专利和风险中的 5 类以上，且关键 P0 路径有可重复样例。

### Gate C：Mapping 验证

逐字段验证 ODS→DWD，包含类型、长度、单位、枚举、主键、唯一键、空值和删除规则；输出可重跑 SQL/作业证据。

### Gate D：指标验证

按 60 个唯一 ID、20 个 P0 的矩阵逐项验证；真实结果与 Mock/历史 ADS 隔离。业务公式待甲方或算法负责人确认的指标不得标绿。

### Gate E：运行链路

同一 `batch_id` 下验证 DWD→ADS/ES/Nebula，且 Python、Java、前端只消费同一环境实例。预期数据未出现必须失败，禁止空结果当通过。

## 10. 结论有效性与限制

- 本文件的表存在性、live 行数、实库结构和代码契约冲突属于事实结论；
- 当前批次跨表低命中属于事实，但其原因“独立抽样/非同 cohort”为高置信推论，仍需供应方确认抽样策略；
- 指标业务权重、阈值、类型定义和代理关系属于待决策，不由本文件替甲方或算法负责人拍板；
- 本文件不创建任何实施叶，不改变旧企业任务状态；
- 供应方补表/补数或 GDF Mapping 修订后，需生成新版本并保留本版作为差异基线。
