# 抽取产业：标题与正文切块向量匹配

> **状态**：demo 抽取已按此改（`polan/industry_enrich.py`）。门槛 0.55 / 0.45 仍是探针起点，抽样校准前不当业务口径。  
> **日期**：2026-10-23  
> **对照实现**：`repos/demo-algo-ent-analysis` 的 `polan/industry_enrich.py`、`polan/graph/entity.py`、`polan/industry_embed.py`  
> **现象**：约 20000 条政策跑完，`policy_industry_rel` 按 `update_time` 只看到 17 条。

## 1. 结论

产业链和节点先入向量库，这一步不用改。少，是因为政策侧没有按「标题 + 正文切块，逐块检索」来匹配。

现在每条政策只检索一次，查询文本不含正文；检索结果只当候选。候选名称必须在原文里对得上，才写入 `policy_industry_rel`。向量相似度不决定写不写。政策标题和正文很少原样出现节点正式名称，所以 top 8 里大部分被丢掉，2 万条只剩下名字刚好碰上的十几条。

优化保持「向量库是产业链 / 节点」不变，改政策侧：标题单独一块，正文按句切块，每块检索，用相似度决定落库。名字重合只加分，不再当闸门。

## 2. 现状（和派单包不一致的地方）

派单包 `12-DWD后加工-抽取产业与条款结构化.md` 写明对码文本包含 `content`。代码里的 `query_text` 只用这些字段：

| 字段 | 是否送进向量检索 |
|---|---|
| `title`、`abstract`、`keywords`、`keypoints` | 是，拼成**一条**长查询 |
| 要素里的目标产业、适用对象、支持方式 | 是 |
| `content`（正文） | **否** |
| `theme` / `ext5` | 否（保持，不用主题词当产业） |

随后 `match_industry_anchors` 要求候选名整段出现，或标题里有一段字出现在候选名里。每条政策**只留 1 个**链码（环节优先于链）。对不上就 `name_only`，关联表不增加带链码的行。

因此 17 条不是向量库只召回了 17 条，而是名字闸门放行了 17 条。长摘要揉成一个向量，也会把真正相关的节点挤出 top 8。

## 3. 目标流程

```text
policy_base_info（title + content）
    → 切块（标题 1 块 + 正文句子块，每政策最多 12 块）
    → 每块 embed（bge-base-zh-v1.5，与现库同一模型、同一 COSINE 集合）
    → 每块 search top 5
    → 按 vid 取该政策各块中的最高分
    → 过线的写入 DWD policy_industry_rel，并同步 ADS
```

向量库仍只存产业链（`chain:`）和节点（`segment:`）。不重建集合，不改 `METRIC_TYPE=COSINE`。

### 3.1 怎么切块

块要够一句意思，不要用 2～8 字的滑窗去嵌入。滑窗太碎，余弦分没有区分度，也会把「技术」「产业」嵌进库。

| 块 | 规则 |
|---|---|
| 标题 | 单独 1 块。空标题跳过 |
| 关键词 | 非空则单独 1 块，不并进标题 |
| 正文 | 按 `。；;\n` 切开。短于 8 个字的丢掉。单块超过 120 字再按 120 字截断（不重叠） |
| 没有正文 | 用 `abstract` 当 1 块，避免只有标题 |
| 上限 | 标题和关键词之外，正文最多 12 块。超出的丢掉靠后的句子 |

套话块（整块去掉标点后只剩「通知、办法、自发布之日起施行」一类）不检索。

### 3.2 怎么打分

沿用现有 `search` 的 `score`：COSINE，**越大越像**。同一 `vid` 在多个块里出现时，取最高分，并记下命中块数。

名字重合改为加分，不是准入：

- 候选全名，或用「与 / 和 / 、」切开的一段（不少于 3 字、不是套话），出现在**命中的那一块**里：该 vid 记 `lexical=true`。
- 不加分、不因此单独写入。高分不要求名字出现；低分即使名字出现也不写。

一条政策可以留下多条关联，按分数从高到低，**最多 5 条**。同一政策里环节和它所属的链都过线时两条都留，不再只留环节、把链丢掉。

### 3.3 门槛（探针，待抽样）

尚未用这批政策量过分布。下面只作第一轮探针，校准后改默认值，不写进客户口径。

| 分数 | 动作 |
|---|---|
| `≥ 0.55` | 写入链码 |
| `0.45 ≤ score < 0.55` | 仅当 `lexical=true` 时写入 |
| `< 0.45` | 丢掉 |

没有过线的政策：**不插入** `industry_link_code` 为空的行。现派单包「无链码只留名称行」在本方案里改为不留空行，避免空串把「已抽取」和「已定码」混在一起。

## 4. 不改的部分

- 向量集合仍由 lumen 侧建库；demo 抽取只检索，不 drop / 重建。
- 不写 `policy_base_info`，不改 `related_entities`。
- 命中写入 DWD `policy_industry_rel`，同一事务镜像 ADS。本次没有的有效行 `is_deleted=1`。
- 增量仍跳过「已有 `is_deleted=0` 且链码非空」的政策。未定上码的政策没有这种行，重跑会再次处理，不必先 `force`。已有那 17 条要按新规则重算时才开 `force`。
- 检索失败或 embedding 不可用：不写、不编造链码（保持 `degraded`）。
- 调用链仍是界面 → Java → Python `/internal/industry/jobs/enrich`。Java 已原样转发 `max_count` / `batch_size`，本方案不改 Java。

## 5. 落地顺序

1. 已落地：`industry_enrich.py` 的切块函数和按块检索。`enrich_one` 走切块聚合，不再把整段摘要搜一次后交给 `match_industry_anchors` 当闸门。
2. `policy_industry_rel` **先不加列**。分数和命中块数只进任务日志，表结构仍是现有 7 列。校准稳定后再考虑是否落 `match_score`。
3. 用约 50 条人工看过的政策扫一遍分数，画「定上码 / 定错码」。把 0.55 / 0.45 换成这条曲线上的点，再当默认门槛。
4. 单政策自检：标题含「集成电路」、正文不重复该词时，应命中名称里带「集成电路」的节点或链，且不要求整段节点名出现在正文里。另有一条与产业无关的规章，应 0 行写入。
5. 再跑一批（建议先 `max_count=200`，`batch_size=50`，因为每条最多 13 次检索）。看 `policy_industry_rel` 里带链码的政策数是否明显高于 17/20000 这一量级，并抽 20 条看错配。

## 6. 成本

每条政策最多 13 次检索（1 标题 + 1 关键词 + 12 正文块），嵌入按现有 `EMBED_BATCH=32` 合并。相对「每条 1～2 次检索」，耗时大约按块数上升。日批继续走已有异步任务，不把整批放进一次 HTTP。

正文块上限 12 是为了先把召回做起来。若抽样里相关句子经常落在第 12 块之后，再把上限提高到 20，而不是先放宽分数。
