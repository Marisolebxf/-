| 维度 | 条款值 |

## 2. 判定口径规则（草案，OP-1 确认后定稿）

1. **交付判线 = 标书一.1 业务分档为主**；一.2 传统业务（<2s/<5s）作为平台兜底。两套并存时的取用见 OP-1。
2. **报告指标口径 = 模板表格列**：常规业务表填「实际响应时间 90%（ms）」+ 目标吞吐量 + 成功率；AI 业务表填首 Token / Token 速度 / P99-P95。标书「平均响应」条款以 **90 线达标**承载（90 线 ≤ 目标 ⇒ 平均必 ≤ 目标，判更严一侧）。
3. **压测层级**：只压 **Java REST 对外接口**（`gkxlumen-platform-gateway` 收口）；禁止越层直压 Python `/internal/*`（架构铁律 2）。算法库性能经 Java 收口接口测。
4. **异步任务**（专题分析 Job、算法批量评估）：提交/查询状态接口按交易接口档判；任务本体耗时按「大数据量 ≤2min」档单场景测，不进并发混合场景。
5. **资源阈值**：压测期间服务器 CPU/内存 <80%（模板惯例）；证据从 Grafana（Prom）导出截图。

## 5. 工具与脚本规约（JMeter / Postman）

### 5.1 工程归档

- **jmx 工程、并发参数快照、结果 jtl/csv** 统一归档 `qa/tools/jmeter/`；命名 `{系统码}-{场景}-{YYYYMMDD}.{ext}`（例：`KJZTFWXT-企业查询并发-20261013.jmx`）。
- 同场景多轮执行：日期后缀区分（`…-20261013.jtl` / `…-20261014.jtl`），**不覆盖历史轮次**（报告"第 N 轮整改复测"需要前后对比）。
- Postman collection（接口联调/冒烟辅助）归 `qa/tools/postman/`，环境变量导出须脱敏。

### 5.2 jmx 编写约定

- 每场景一个独立 jmx；线程组参数（并发数 / Ramp-up / 运行时长 / 目标吞吐量）与 §3 基线表场景参数一致，变更须同步基线表。
- 取样器只打 **Java REST 对外路径**（§2 规则 3）；断言含 HTTP 200 + 业务 code 判定（按接口契约，占位契约以现场实测响应为准）。
- 参数化数据（检索词、企业名单等）用 CSV Data Set Config，数据文件随 jmx 同目录归档；**禁止**脚本内硬编码生产数据。
- AI 类场景（如有）：首 Token 时延用 JSR223 后置取 `response.headers` 流式首包时间戳；无法稳定取样时降级为整请求时延并在报告注明口径。
