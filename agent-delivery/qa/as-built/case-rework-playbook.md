# B 线用例返工编排（父控 + 子 agent）

> **用途**：S1 返工或补必修时，父控只读本文件派单和验收。子 agent 提示词以 **§2** 为唯一正文，不要在对话里另写一套。  
> **写法真源**：`prompts/_case.md`。专题新写和重写遵守其中红线 3.1：步骤从落地页 `goto` 写全，登录和关评审不写进用例。本文件不重复红线，只定谁做什么、提示词怎么填、怎样算写完。  
> **索引**：`qa/func-test-playbook-index.md` S1 指向这里。

环境（专题）：`https://edu.itic-sci.com/tts/svcz/`。一入口一子 agent。父控不写用例、不改脚本、不改业务仓。

---

## 1. 父控

1. 确认就绪门（索引 §2）。未锁环境则停。
2. 选定模式：
   - **首写**：该入口还没有可保留的册。子 agent 整册新写，编号从 `code-registry` 新取。
   - **补必修**：册已基本可用，只补 §4 当前补丁单里的格。保留已有编号，不重排、不整册重写。
   - **对照重写**：册还在，但未按 `_case.md` 收口。子 agent 只读本入口旧册，现场重勘后逐条标保留 / 补写 / 重写 / 删除。见 §5。
3. 把 §2 原文交给**一个**子 agent。只替换【】。不要把人工核验记录、retro、招引册正文、或上一轮「建议项」写进提示词。
4. **一批最多 4 个入口，各写各的册。** 开写前父控先把号段切开，并立刻把 `next_seq.KJZTFWXT.FUNC` 抬到本批末尾的下一个号。子 agent **禁止**改 `code-registry.yaml`。每段 100 个号（如 `01472`–`01571`）。用不到的号作废，不归还、不给下一批。下一批从已抬高的 `next_seq` 再切。
5. 子 agent 交卷前，父控不打开 `retro/KJZTFWXT-bline-manual-review-revisions.md`。
6. 按 §3 验收。用例册通过 ≠ 脚本、总集 Excel、retro 已回填。那些是 S2 / S4，不在本步派。

## 3. 父控验收

通过须同时满足：

1. `git diff` 含本入口用例 md 与同目录 `coverage-fp.md`。缺覆盖表即不通过。出现 `as-built/scripts` 或 `prompts/**/full.md` 即不通过。父控预分号段时，`code-registry.yaml` 只应由父控改。
2. 红线 7 扫描为 0。金样不是关评审。
3. 补丁单里的格都有用例，或未覆盖原因属于「造不出终态 / 没有第二种账号 / 数据不够翻页」。原因是「没点、没确定」即不通过。
4. 点名的已有用例已写到终态（重新分析须到新一轮结果，不能停在过程页）。
5. 本页存在的核心主线仍在，且步骤到成功结果页。
6. `coverage-fp.md` 表头号段等于当前册有效编号；「已覆盖」引用的编号都能在册内查到，且不在作废 / 删除清单里。条数与册内有效行一致。

用例册和本入口覆盖表都通过之后才做、且本步不派：

| 后续 | 阶段 |
|------|------|
| 脚本对齐新编号、回填自动化用例ID | S2 |
| 6 号用例簿 xlsx | S4 |
| retro 行状态改为已改待复跑 | 父控验收通过后回填，不交给写用例的子 agent |

本入口 `coverage-fp.md` 就是 S1 交卷的一部分，不是事后另派的可选项。系统级总表、6 号 xlsx 才留到后面。
