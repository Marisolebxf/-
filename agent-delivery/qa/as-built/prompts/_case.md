## 内容红线（2026-10-12 用户复审追加；378 条存量复盘中 5 类问题命中 34%~91%，禁止再犯）

用例是**给人读的验收描述**。以下 5 条是硬红线，违反任何一条 = 该条用例重写。

### 红线 1：正文零内部引用

「测试内容 / 前置条件 / 测试步骤 / 预期结果」四列**禁止出现**任何内部编号引用：

- 禁止出现：`USM AC-xx-yy` / `US-xxx-01` / `Q0xx` / `GAP-*` / `开放项 N` / `归 FUNC-xxxxx` / `coverage #N` / `TRACE-*.yaml` / `metric_id` / 任务 ID / 文件路径。
- 例外（唯一）：用例编号本身（如「与用例 00169 分开验收」这类**同册互指**允许，但优先拆句到备注）。
- 需要引用的信息一律两种去向：
  - **给人看的背景** → 把具体内容直接写进正文（如 ❌「遵守 USM AC-02-02」→ ✅「视口操作不改变已选产业条件」）；
  - **给脚本/追溯用的数据** → 只进右侧扩展列（用户故事编号 / USM验收场景编号 / 功能点ID / TRACE引用 / metric_id / 关联任务ID / 备注）。
- 「开放项 / 待甲方确认」类治理标记：正文最多写**人话**（如「时间控件当前为只读，为已确认的临时形态」），编号与跟踪状态写备注（如 `备注：开放项2，Q068`）。

### 红线 2：observed 不进预期、废弃态不验不可见

- **勘察观测项（observed）禁止写成预期结果**。现场记录的「执行时以现场为准 / 记 observed / 勘察时为 X」都是**输入信息**，不是验收标准。预期只写**可判定的终态**；确实无法判定终态的观测点 → 该校验点从预期中删除，挪备注 `备注：observed-执行时记录（原勘察：…）`。
- **设计后被推翻 / 已移除的形态，不写「不可见」校验**。例：旧方案有断点标记后被砍 → 不要写「页面不显示断点标记」这种反向预期（无法穷举不存在的东西）。已废弃能力只在 coverage 矩阵记 `未覆盖+原因`，不进用例。

### 红线 3：步骤只写操作，校验全进预期

- 「测试步骤」= **人对系统的操作序列**（点击 / 输入 / 选择 / 切换 / 清空 / 上传 / 等待完成）。每步一个动词短语开头。
- **禁止**在步骤里写「核对 / 确认 / 检查 / 校验 / 观察 / 比对 / 验证 / 查看是否」——这些全部是校验动作，改写成预期结果条目（「下拉含 15 个选项」而不是「核对下拉选项」）。
- **禁止**在预期里写操作（「点击切换后」「再次点击」）——预期只描述操作完成后系统**应处于的状态**，不描述怎么到达。
- 边界判不准时的口诀：**做 = 步骤；看 = 预期**。

### 红线 4：一句一事，长度上限

- 步骤 / 预期**每条编号项只含一个操作或一个校验点**。发现「且 / 并 / 同时 / ，且」串联多个点 → 拆成两条。
- 长度上限：单条步骤 ≤ 60 字，单条预期 ≤ 60 字；步骤总数 ≤ 7 步，超出 = 拆用例（拆出的用例在备注互指）。
- 长枚举（如 15 个产业集群全名）不硬塞进步骤：步骤写「展开产业下拉」，预期写「选项与生产环境一致（共 15 个产业集群）」，全量清单放用例册附录或备注。

### 红线 5：场景分层，先主后备选异常

每模块用例必须按以下顺序分组排列，禁止主流程 / 边界 / 异常 / 权限混排：

1. **主流程（P0）**：正常业务路径，默认条件直达终态；
2. **备选场景（P0/P1）**：参数边界、多状态切换、回退往返；
3. **异常场景（P1/P2）**：空态 / 失败态 / 越权 / 非法输入；
4. **权限态（P1）**：无权限、只读角色（有权限体系才写）。

分组方式：用例总表内按序排列 + 「功能项」列体现场景类（如 `异常-空态` / `备选-条件回退`），不另建 sheet。
