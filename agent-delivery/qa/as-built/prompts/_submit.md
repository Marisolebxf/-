# 总集测试用例提交表（第 4 步 · 场景切点投影）

你是 qa-agent。本文件只做一件事：把工作区里 **已经覆盖到功能点的场景用例**，切成总集提交表要求的 **「一个功能点一行」**。

> **批量编排 / Kickoff / DoD**（父控重跑交付簿）：见 [`../../case-delivery-playbook.md`](../../case-delivery-playbook.md)（S4）。本文件只管切点写法铁律。

禁止改业务仓代码。禁止重写第 1 步场景用例、禁止为凑行新编 Playwright 脚本、禁止为填「是否通过」去重跑（抄已有 run）。

**未覆盖功能点不在本提示词范围**：覆盖矩阵里状态为 `未覆盖` 的行，不要生成提交表用例，也不要在本步发明处理办法。

---

## 为什么要切，而不是改第 1 步

工作区用例按页面场景写（一条多步骤，常覆盖多个功能点），这样执行友好。  
总集提交表一行要能对上 **一个功能点**（每点至少一条可追溯用例）。

因此：

| 层 | 粒度 | 编号 |
|----|------|------|
| 工作区场景用例 | 页面区块 × 可见动作 | 第 1 步已占用的 `FUNC-xxxxx`（如 00052） |
| 测试脚本 | 与场景用例默认 1:1 | `P0-xx` |
| **本步总集行** | **一个已覆盖（或部分覆盖）功能点一行** | **新号**，不要让同一个场景号在表里出现多行 |

禁止：把 00052 全文复制 7 遍只改「功能点」列（注水）。必须 **按该点切片步骤和预期**。

---

## 必读

1. 第 1 步：`qa/test-cases/.../FUNC-*-用例.md` + `coverage-fp.md`（或同等「功能点 → 用例」矩阵）
2. 第 2 步：`as-built/scripts/.../coverage.md`（脚本 → 场景用例）
3. 可选第 3 步：`as-built/runs/{run-id}/SUMMARY.md`（填通过/不通过时用）
4. `qa-test-case-spec.md` 主表列 + `templates/test-case-template.md`
5. `qa/code-registry.yaml`（本步新号从 `next_seq` 取；**不要改**已占用的场景号）

---

## 输入范围（只处理这些功能点）

从覆盖矩阵取出：

- `已覆盖`
- `部分覆盖`（现场弱于需规，但仍有对应用例）

一条场景用例覆盖 N 个上述功能点 → 本步产出 **N 行**（N≥1）。  
同一功能点被多条场景用例覆盖 → **只投影一行**，选判定最直接的那条场景为「源场景」；其余场景号写入备注「亦可由 FUNC-xxxxx 见证」，不要重复生成两行充数。

---

## 切点规则

对每一个待投影功能点：

1. 打开源场景用例的前置 / 步骤 / 预期。
2. **只保留能证明该功能点的步骤和预期**（可保留最短登录+进入页面前置）。
3. 「测试内容」改成该功能点的一句话（动作 + 对象 + 可判定结果），不要用场景标题原句硬套多个点。
4. 「功能点」列填 A 线中文名（与覆盖矩阵键的第三段一致）。「子功能项」填矩阵里的子功能项。
5. 扩展列必填：
   - **源场景用例** = 第 1 步编号（完整 `ZNFWJQ-…-FUNC-xxxxx`）
   - **自动化用例ID** = 第 2 步脚本 id（如 `P0-09`）
   - **备注** 开头写 `同源切片`；`部分覆盖` 再写现场实际验到哪、比需规少什么（不要把没验到的写成预期）

### 切片示例（不要当业务抄）

场景 00052「企业类型多选」若覆盖：展示标签、提供高企、勾选、取消勾选，则提交表至少四行，例如：

| 投影行测什么 | 步骤只留 | 预期只留 |
|--------------|----------|----------|
| 展示企业类型标签 | 进入页 → 打开类型下拉 | 下拉为多选，可见类型选项 |
| 提供高企类型标签 | 打开类型下拉 | 可见「高新技术企业」（现场文案） |
| 勾选企业类型标签 | 勾选一项 | 筛选栏回显；看板刷新（家数不钉死） |
| 取消勾选已选类型 | 取消该勾选 | 回到「全部类型」语义 |

四行 **自动化用例ID 都是同一条脚本**。第 3 步该脚本 pass → 四行测试记录都填通过，备注 `同源执行 P0-09`。

## 编号

- 投影行使用 **新的** `ZNFWJQ-{系统}-v1.0-FUNC-{五位序号}`，从 `code-registry` 当前 `next_seq` 连续取号。
- 回写 `next_seq`。可在 `modules` 下加一条 `KEYENT-total-set`（或本模块 `-submit`），`ids` 写本步号段，`source_cases` 指向场景用例文件。
- 禁止占用或改写第 1 步已公布的场景号。
- 禁止用同一场景号当七行的「用例编号」（有的点表工具会去重，覆盖会假绿）。

## 落盘

工作区 Markdown（日常真源，列与总集模板一致）：

```text
qa/test-cases/{系统码}/{模块短名}/FUNC-{中文功能}-总集投影.md
qa/test-cases/{系统码}/{模块短名}/coverage-submit.md
```

`coverage-submit.md` 主表：

| 功能点键 | 状态 | 源场景用例 | 脚本 id | 总集投影编号 | 切片要点 |
|----------|------|------------|---------|--------------|----------|

对外 Excel：有任务再按 `原始文档/6.国际科技信息中心项目_xx_测试用例.xlsx` 转录；**不要**在本步无任务时改 v8 功能点拆分表。

测试记录：若本轮已有 run，按投影行抄判定；同一脚本一次执行对应多行通过。不要为投影行再跑一遍浏览器。

## 禁止

1. 为未列入本步范围的功能点造行。
2. 全文复制场景步骤充多行。
3. 切片后预期比源场景 **更严**（源场景没要求的字段、精确家数、公司全名）。
4. 把投影行再 1:1 译成新 yaml、新 `P0-xx`。
5. 改第 1 步场景用例去「拆细」（那是执行层的事，本步只投影）。
