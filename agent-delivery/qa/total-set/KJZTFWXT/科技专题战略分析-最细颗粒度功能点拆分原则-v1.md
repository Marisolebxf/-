## 一、为什么能从 312 扩到约 1200

v3–v5 只拆「业务能力主语」（分析什么、生成什么报告、点名指标/枚举）。这相当于门户原则里的「功能动作」，平均每条六级约 5 条，66×5≈330。

门户原则要把每条原始功能扩成可开发、可测试、可验收的**最小功能点**，平均约 **10–14 条/原始功能**；专题/决策分析还要按「对象 + 指标 + 维度 + 展示 + 下钻 + 输出」再加**规则层**（空态、加载、失败、默认、校验）。规则层不是新业务，是原功能要能验收必须具备的约束。

本模块 66 条六级 × 约 18 条 = **约 1188 条**，落在 1200±5% 内。不是按模块比例硬摊，复合分析多拆、薄说明少拆。

| 先前口径（v5） | 本原则（对齐门户） |
|---|---|
| 只拆点名业务能力 | 业务能力 + 展示/下钻/输出 + 规则层 |
| 不拆空态/失败/默认 | 有独立验收标准的空态、加载、失败、默认、校验**独立计数** |
| 不拆图表形态 | 需规点名的雷达图/热力图/柱状图/仪表盘/名单/图谱，能独立验收则各计 1 |
| 「等」「如」不补名称 | 仍不补未点名城市/指标；允许补**通用验收规则** |
| 禁止笛卡尔积 | 仍禁止（北京×专利交叉）；不同输入/处理/输出可分别计 |

**仍禁止（相对门户原则第 4.8 / 6.2 / 6.3 条）：**

- 按 `demo-ui-topic` 控件名、路由、Drawer 发明点（不把原型当需求源）
- 原始未涉及的收藏、订阅、分享、评论、点赞、后台运营位
- 只改措辞、写不出不同输入/处理/输出/验收标准的条目
- 纯视觉（悬停变色）、技术实现（LLM/NLP 本身）、公共面包屑重复计

## 三、最小功能点

沿用门户原则：一条最小功能点 = **一个动作 + 一个对象 + 一条可验收规则或结果**。

命名：

> 动作 + 对象 + 条件/字段/维度/规则/状态/输出

一条必须同时能回答：对谁、对哪个对象、做什么、依据什么规则、得到什么结果、如何判过/不通过、追溯到哪条六级和哪段需规。

规则来源只允许三种：

| 来源 | 含义 | 本模块例子 |
|---|---|---|
| 原文直接 | 标题或需规写明的对象、动作、字段、图表、报告 | 计算技术力得分；生成差距分析报告 |
| 原文隐含 | 该功能要成立必须具备 | 选择对比企业；未选企业不能出对比结果 |
| 验收补充 | 保守、通用、不扩大业务范围的边界 | 展示分析结果为空提示；展示计算失败提示；校验权重之和为 100% |

## 四、本模块业务对象

先识别对象，再拆动作和规则。优先这些（与门户原则 4.3 / 5.7 对齐，只保留本 5 个四级用得到的）：

- **分析对象**：产业、产业链环节、区域、城市、企业、企业类型、服务机构、政策、创新要素、创新主体
- **分析维度**：时间、区域、领域、环节、企业类型、地理层级（全国/省级/城市）
- **指标与指数**：技术力、商业力、高端化指数、健康度、创新活力指数、协同指数、覆盖广度/深度、密度/中心性/影响力
- **结果载体**：图谱、雷达图、热力图、柱状图、趋势图、矩阵图、仪表盘、排名表、名单、报告
- **过程对象**：指标库、权重、筛选条件、对比集、时序模型、推荐模型

## 五、本模块标准拆分模板（决策分析类）

门户原则 **§5.7** 定制。每条六级按下面 7 层检查；该层在标题/需规中不存在、也不是该功能成立所必需的，则不拆。

### 5.1 七层检查

| 层 | 查什么 | 可计条目示例 |
|---|---|---|
| 1. 对象选择 | 用户要先选定产业/企业/区域/机构/环节/类型吗 | 选择目标产业；勾选高新技术企业；选择对比区域 |
| 2. 指标与参数 | 点名指标、权重、组合、自定义 | 提供专利数量指标；设置指标权重；校验权重之和 |
| 3. 取数与计算 | 提取、抓取、汇聚、评分、识别、预测 | 提取深圳专利数据；计算环节健康度评分 |
| 4. 结论与识别 | 优势/差距/短板/断点/瓶颈/阶段 | 识别产业链断点；判定产业发展阶段 |
| 5. 展示 | 需规点名的图、表、榜、图谱、字段 | 以雷达图展示技术力对比；展示各区域企业数量 |
| 6. 下钻与联动 | 标题或需规含下钻、节点、多级、地理三级 | 点击环节节点下钻；展开二级供应商 |
| 7. 输出 | 报告、名单、PDF、导出、推荐理由 | 生成周期分析报告；给出推荐理由 |

### 5.2 每条六级必查规则层（本次条数的主要增量）

只要该六级会产生列表、图表、指数、名单或报告，下列规则**有独立验收标准则独立计数**。不因「每条都套一遍」而取消独立性——门户原则明确：空态、加载、失败、默认、输入限制是原功能细化，不是新业务。

| 规则 | 典型功能点 | 来源 |
|---|---|---|
| 输入校验 | 未选择分析对象时不能开始分析 | 原文隐含 |
| 参数校验 | 校验指标权重之和为 100%；时间起点不得晚于终点 | 原文隐含 / 验收补充 |
| 默认规则 | 默认选中预设指标；默认展示最新周期；默认按得分降序 | 验收补充 |
| 结果空态 | 展示无匹配企业提示；展示分析暂无数据 | 验收补充 |
| 处理中状态 | 展示指数计算中；展示报告生成中 | 验收补充 |
| 失败提示 | 展示数据提取失败；展示模型分析失败 | 验收补充 |
| 结果数量/排序 | 展示结果总数；按综合得分降序排列推荐名单 | 原文隐含 / 验收补充 |
| 升序/降序 | 需规或结果为排名表/列表且排序可切换时，升序、降序**分别计数** | 同门户原则 |

**本模块建议的规则层下限：** 每条会出结果的六级，至少落地 **空态、处理中、失败** 三条（能写出不同提示和通过标准）。配置类（只建指标库、不计算）可只保留校验 + 保存/生效失败。

### 5.3 点名枚举（保留 v5 有效部分）

- 顿号/括号里点名的指标、类型、城市、环节、关系类型：各算独立点。
- 「等」「如」**只取已写名称**。深圳市、南山区作举例的，不计「选择南山区」。
- 「或」：产业或技术领域，保留一条「选定目标产业或技术领域」，不拆成必须同时具备的两点。
- **禁止笛卡尔积**：数据类型与对标城市分别计，不出现「提取深圳专利并与北京对比」这种交叉格。

### 5.4 业务步骤拆开（标题里的「与」）

六级标题是「A与B」（提取与对标、下钻与演进、名单与价值）且需规两段都有动词：A、B 都要有独立业务点，再加各自规则层，不要并成一句。

### 5.5 AI / 模型类补齐链路

需规出现大模型、时序模型、招引/培育模型、诊断模型、综合评价模型时，按门户 AI 生命周期**只补该功能必需段**（有则拆、无则不发明）：

接收参数 → 检索/汇聚数据 → 计算或推理 → 过滤/排序 → 生成结论或报告 → 展示依据或理由 → 失败与留痕（留痕仅当验收需要「能追查本次分析」时计 1 条：记录分析任务结果）

不把「调用大语言模型」本身写成功能点。

## 七、可计 / 不计

**可独立计数**（须能写不同验收标准）：

- 点名指标、类型、城市、环节、关系上的每一个计算或展示动作
- 一种点名图表/名单/报告输出
- 一层下钻或一个地理层级展示
- 一条输入校验、一条默认规则、一条空态、一条处理中、一条失败提示
- 排名表上的升序、降序
- 报告中原文列出的章节（问题/成因/实践/方案）各算分析能力，另加「生成完整报告」

**不宜独立计数：**

- 按钮悬停、骨架屏美术细节
- 同一列表里无筛选/排序/跳转/脱敏规则的纯展示列（合并为「展示结果列表字段」）
- 同义：「查询企业」「检索企业」同一条件
- 「支持用户直观查看」这种目的句
- LLM、NLP、中心性算法等实现手段
- 未在需规出现的导出 Excel / 下载图片（需规只写 PDF 报告则只计 PDF）

## 九、批量做法（本次出 v6 时）

1. 以 66 条六级为行，保留五级/六级/需规全文。
2. 判定类型（§六），套七层检查 + 规则层必查。
3. 先落原文直接（继承 v5 业务点），再补原文隐含，最后补验收补充。
4. 给每条写得出「不同验收标准」才保留；写不出就删或合并。
5. 同六级内去重；跨六级只允许「选择目标产业」这类因对象场景不同而分挂，文案要带对象（选择对标城市 / 选择招引产业方向）。
6. 合计落在 1140–1260：低于 1140 则检查规则层是否漏空态/失败/校验；高于 1260 则合并无独立规则的展示列和同义句。
7. 产出仍用总集功能测试用例表：功能点只填到功能点级，测试内容/步骤/预期留空；**需规描述整段复制**；建议在功能点后增加「拆分维度」「规则来源」两列便于抽检（不增加业务范围）。

本原则是拆功能点。写测试步骤仍遵守既有用例文案：前置只写环境可访问，步骤登录测试环境 + 业务名。

## 十一、审计口径

功能点拆分依据功能清单五级/六级名称与需规功能描述，对齐门户原则的对象、动作、字段、规则层与验收补充方法，并按专题决策分析的「对象 + 指标 + 维度 + 展示 + 下钻 + 输出」展开。每条保留原始层级与需规原文，对应可独立测试的最小功能单元。无独立业务结果、无独立处理规则、无独立验收标准或仅属页面视觉的内容，不重复计数。不把演示原型中的控件与路由列为需求源。
