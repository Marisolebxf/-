## catalog 缺口（需规有、本页无 path）

1. **按产业 / 政策主题条件分析**：需规「允许用户在指定区域、产业或政策主题的条件下进行布局推荐分析」，catalog 仅点名 `scope_code`（省/市编码）与 `limit`，无产业、政策主题入参。
2. **机遇与短板权重设定（调用方入参）**：需规「调用参数可包含机遇与短板分析结果的权重设定」，catalog 无权重类入参（工作稿算法行覆盖的是需规算法逻辑「加权评分法」，不能代替调用方权重契约）。
3. **数据库筛选条件、策略适用范围**：需规点名调用参数；catalog 无对应入参。
4. **政策机遇识别结果 / 政策短板识别结果作为本口入参**：需规输入含两侧分析结果；本页仅 layout 一个 GET，无引用上游结果的入参或字段（机遇/短板接口属其它六级，本页不扩挂，合表按 path 去重）。
5. **SDK 调用方式**：需规「支持通过 RestfulAPI 与 SDK 接口调用」，catalog 仅有 REST，无 SDK 契约（属交付形态缺口，非 REST path）。
6. **执行效果预测、优化策略建议的点名结果体**：需规输出三件（布局建议、执行效果预测、优化策略建议），catalog 仅点名顶层 `layout_rec_cnt`（建议数）；工作稿已将后两件挂本接口作输出验收，但无独立点名字段/path。
7. **政策管理系统在线检索与全流程自动化联动**：需规「可联动政策管理系统实现在线检索、布局建议生成、效果预测及反馈优化的全流程自动化」，catalog 无检索/编排/反馈写入 path。
8. **效果评估后的参数/策略写入**：需规「依据评估结果优化算法参数和策略体系」，catalog 仅只读 GET，无写入/版本配置接口（工作稿状态条按「再次查询可读到更新后结果」验收，不代替写入契约）。
