## 一、真源（两份，缺一不可）

| 角色 | 路径 |
|---|---|
| **业务真源** | 功能清单 v1.2 · sheet「深度挖掘算法」· 本轮 **60** 条六级名称 + 需规全文（工作稿从表前「需规原文」引用 `fp-split-run/work/Lxx.md` 已摘录块，不重读算法仓） |
| **接口真源** | `repos/lumen-ui-algo-apiview/src/catalog/*.json`。冻结 SHA 写在 `fp-split-by-api-run/_catalog-snapshot.md`。准备日 SHA：`9c54b9cdd4fcfc93b0c2ba700c72ae04e2819cd2`（2026-09-02） |
| **挂接对照** | `fp-split-by-api-run/_l6-to-catalog-map.yaml`（草案；金样通过后可改 hang/weak） |

拆点时：需规决定「这个模型该有什么能力」；catalog 决定「现在联调台挂了哪些可调用接口」。catalog 有、需规没有 → 标 **契约/未在需规**，不发明成需规原文直接。需规有、catalog 无 → 仍拆，规则来源原文直接，并在 review 写 **catalog 缺口**。

`status=unavailable` / `runtime=local_mock` **仍拆**，功能点须能看出「契约未交付」或「Mock」，不要写成已上线。

## 二、范围

| 项 | 约定 |
|---|---|
| 纳入六级 | 与旧套相同的 **60** 条，不扩 |
| 不纳入 | sheet 其余六级（技术/人才/机构等，已有那份 2400 行拆分清单） |
| catalog 多页 | 创新监测 `innov.*`、工程增强、60 条无对应的分析页 → 对照表 `catalog_skip`，**不另开六级**、不写入本轮合表 |
| `/v1` 与 `/internal` 同 handler | 计 **1** 个接口 |
| 同一 path 多页出现 | 合表按 `METHOD+path` **去重**；主挂语义最近六级 |

页面列：填 **catalog 页 title**（如「企业技术力评估」）。无 catalog 页的弱挂六级：填页 title 或「整模型（需规-only）」。六级列仍填六级名。不表示有用户页面。

## 三、一条功能点（接口级）

一条 = **一个接口动作 + 一个对象 + 一条可验收规则**。主语是 HTTP 接口，不是图表控件。

每个绑定到本六级的 catalog endpoint（去重后的 METHOD+path），有独立验收则分计：

| # | 可计 | 不计 |
|---|---|---|
| 1 | 接收/校验该接口 **点名** 入参（catalog `params` 已写名称） | 未点名 query；把筛选项控件当页面操作 |
| 2 | 调用该 METHOD+path | 同 path 再写一条「网关转发」 |
| 3 | 输出 catalog 点名的主结果体（`responseFields` 顶层，**不**拆嵌套子字段） | 字段级 45 行/口（留给 schema 冻结后的加深，本轮不开） |
| 4 | 空态（无数据） | 维度 × 空态 |
| 5 | 失败（接口失败 / 入参非法，验收不同才分计） | 超时、鉴权未在 catalog/需规出现则不发明 |
| 6 | 处理中 / 异步任务态（仅 catalog 或需规写了异步） | 为凑数给同步 GET 加任务监控 |

规则层挂在 **该接口**，不按点名指标维复制。

规则来源：catalog 字段名 = 原文直接（接口真源）；需规有而 catalog 无 = 原文直接（业务真源）；接口要成立必须有的校验 = 原文隐含；unavailable 的交付态说明 = 验收补充。

拆分维度优先：`校验 / 字段 / 算法 / 输出 / 状态 / 空态 / 异常`。
