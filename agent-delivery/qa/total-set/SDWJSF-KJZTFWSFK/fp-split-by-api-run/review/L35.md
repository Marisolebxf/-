## catalog 缺口（需规有、本页无 path）

1. **分析维度 / 时间区间 / 数据源类型**：需规「调用时可指定分析维度、时间区间及数据源类型」。GET 点名入参仅为 policy_id、region_code、limit；POST 点名入参仅为 mode、title、text、execution、aux。上述调用条件无契约支撑（未发明筛选入参行）。
2. **基于政策标签的在线检索**：需规「提供基于政策标签的在线检索及分析功能」，两 path 均无政策标签点名入参。
3. **关联分析结果 / 关联分析报告**：需规算法阐述「最终生成焦点与堵点清单及关联分析结果」、调用方式「获取焦点与堵点识别结果及关联分析报告」。GET 顶层仅点名 focus_score；POST 顶层点名 focus_list / bottleneck_list / suggestions，无关联分析点名结果体，亦无报告类 path。
4. **SDK 调用方式**：需规「支持通过标准化RestfulAPI及SDK接口调用」，catalog 仅有 REST 接口，无 SDK 契约（属交付形态缺口，非 REST path）。
5. **与政策管理系统对接 / 自动化监测**：需规「支持与政策管理系统对接，实现自动化监测与分析」，catalog 无对接或监测类 path。
6. **评估阈值 / 指标体系写入或配置**：需规「结合历史数据及专家经验设定评估阈值」「支持动态更新数据源与评估阈值」，catalog 仅有只读分析接口，无阈值或指标体系配置/写入接口（若按「只读消费」口径可视为不缺口，此处如实记录）。
