## catalog 缺口（需规有、本页无 path）

1. **优势评分/详细评估指标显式结果体**：需规输出含「优势评分结果、详细指标分析报告」，catalog 该接口顶层仅点名 panorama（enterprise_count、nodes），无显式优势评分（score）或指标分析结果体（部分能力可能由 panorama 内嵌覆盖，但无点名字段）。
2. **SDK 调用方式**：需规「支持通过 RestfulAPI、SDK 方式调用」，catalog 仅有 REST 接口，无 SDK 契约（属交付形态缺口，非 REST path）。
3. **分析报告生成与数据导出服务**：需规调用方式写「支持生成分析报告及数据导出服务」，本页无报告生成或导出类接口（如 report/export/download path）。
4. **按行业类别获取**：需规「可按产业标签或行业类别获取优势产业识别结果」，catalog 入参仅 chainId（产业/链条），无按行业类别（行业分类编码等）的独立入参或查询接口。
5. **多源专题库对接类接口**：需规输入含政策法规库、经济指标库、企业信息库数据，本页无对应数据对接/查询 path（属算法内部数据依赖，如实记录）。
6. **趋势变化可视化**：需规输出含「趋势变化可视化图表」，本页无独立图表/导出 path；本轮禁止按界面操作拆点，故不写入功能点表。

## 抽 3 条不同验收

1. 行 1（校验/输出）：调用 GET `/innov/v1/industry/{chainId}/shenzhen` 传 chainId，验收 = 点名入参被接收校验并返回该产业深圳专题识别结果 —— 与行 2（返回优势产业清单并覆盖资源配置/技术水平/市场扩张等竞争力判定）验收点不同（入参接收/路由 vs 业务对象语义）。
2. 行 6（空态）：指定 chainId 对应产业无深圳优势识别数据，验收 = 返回空态结构而非伪评分/伪清单 —— 与行 7（不存在的 chainId 返回失败态）验收不同（空态 ≠ 失败）。
3. 行 4（算法）：识别结果应为经深圳-全国对应产业数据综合对比、按增长率/占有率/技术创新等维度与定制化计算公式生成优势评分后的清单，而非原始数据透传 —— 属算法维度验收，与输出结构（行 3 panorama 结果体）、状态类验收（行 5 动态更新）均不同。
