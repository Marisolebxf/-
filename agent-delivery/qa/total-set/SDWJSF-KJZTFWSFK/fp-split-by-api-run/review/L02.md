## catalog 缺口（需规有、本页无 path）

- 需规（1）4）「开发API接口……查询重点企业专利数、技术交易额等指标结果」中按企业维度的**专利数、技术交易额单项指标明细查询**：本页仅 key-enterprises 聚合接口，无单独指标查询 path —— 以 key-enterprises 的 key_score 结果体覆盖，不单列缺口；
- 需规（2）3）/（3）3）「通过环比计算增长率计算其趋势」：type-distribution 结果体仅 rows，catalog 未标明含增长率字段，增长率口径以 news/stats 的 growth_rate 有明示、type/domain/new 未明示 —— 按「原文隐含并入 rows 验收」处理；
- 需规（4）4）「根据**时间、行业领域、融资类型、融资阶段、交易对手**等条件查询」：news/stats 仅点名 news_type 入参、news 仅 news_type/keyword/page/size 入参，**行业领域、融资类型、融资阶段、交易对手条件无对应入参 path** —— 真实缺口，需 catalog 侧确认（或由 news_type 语义覆盖部分）；
- 需规开篇「消息队列服务」的数据同步方式：catalog 为纯 REST 页，无 MQ 契约 path —— 属实现机制非接口契约，不拆功能点，不计缺口。

结论：除 news 查询条件面窄于需规外，五类基础指标（重点企业提取/企业类型分布/企业领域分布/企业重点资讯/新增企业数量）均已由 catalog path 覆盖。

## 抽 3 条不同验收

1. **校验/输出**：调用 GET `/entan/v1/key-enterprises` 接收点名入参 industry、city、scale、limit，返回顶层结果体 enterprise_name、key_score —— 入参齐全性与主结果体字段可直接按契约验收（接口契约维度）。
2. **算法**：调用 GET `/entan/v1/new-enterprises` 返回的 rows 含历年新增企业数量及环比增长率，且新增数量按企业注册时间统计并**去除重复注册企业** —— 验收点在计算口径（去重、环比），与第 1 条的入参校验维度不同。
3. **空态**：调用 GET `/entan/v1/news` 指定条件下无符合资讯时返回空 list —— 验收点在无数据时的返回结构，与 1、2 均不同。

（另含异常维兜底条：任一 `/entan/v1/*` 契约未交付调用失败时返回明确失败信息而非业务数据。）
