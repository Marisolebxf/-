六级及需规原文：

政策基础指标模型通过对接政策数据库，建立政策信息数据获取、处理与服务化的全流程机制，对政策进行多维分类与统计分析，并提供在线查询与趋势监测能力。模型与数据融合中枢中的政策数据库建立稳定数据接口，获取包括政策标题、发布时间、发布机构、级别、类型、区域分布、内容摘要等在内的结构化信息，覆盖国家、省、市、区等不同层级，以及产业、人才、企业扶持等多类别政策。
政策基础指标模型构建涵盖政策级别指标、政策类型指标、政策时序指标、全国政策分布、深圳政策分布五大类指标体系。
（1）政策级别指标
通过对接政策数据库，计算发布政策的级别，包括国家、省、市、区四级政策。
1）数据源对接：对接数据融合中枢中的政策数据库，建立数据获取渠道。通过数据源对接，获取政策数据库中的政策信息数据，包括政策标题、政策发布时间、政策级别等信息。
2）数据清洗：根据政策标签及时间进行提取与政策级别相关属性数据。针对政策数据，需要进行数据清洗处理，包括去重、去噪、格式化、补全等操作。同时，需要进行指标业务的分析，例如对政策的颁布时间、颁布机构、颁布范围、行业分类等进行分析，以确保数据准确性和可靠性。
3）数据处理：根据政策级别进行分类汇总，并通过环比计算其趋势。需要对数据进行计算、归纳和统计等处理，得出政策级别指标和趋势指标。同时，需要对计算结果进行有效性验证和调整，确保指标结果准确和可靠。指标业务分析需要考虑政策级别的定义标准，例如不同地区对政策级别的划分标准，不同时间段对政策级别的变化等因素，以确保指标计算的准确性和可靠性。
4）数据服务开发：开发API接口，提供根据政策标签、时间等条件查询对应的政策级别指标和趋势指标。通过API接口，用户可以灵活地查询政策级别指标和趋势指标，并进行相关分析和应用。
5）数据同步：采用API接口、消息队列等方式将计算结果同步到数据服务中，以便用户查询和使用。将计算结果同步到数据服务中，可以方便用户查询、下载和使用政策级别指标和趋势指标，促进政策的制定和应用。同时，需要定期更新数据和指标，并对其进行监测和分析，以确保数据和指标的有效性和可靠性。指标业务分析还需要考虑政策级别与其他指标之间的关联，例如政策级别与行业发展、区域经济发展等的关联，以帮助用户更好地理解和应用指标结果。
（2）政策类型指标
通过对接政策数据库，计算发布政策的类型，包括产业政策、人才政策、企业扶持政策。

## 拆法（字段级 + 呈现层 3.1）

一条 = `endpoint.id` + `field_key` + **算法环节** + **具体描述**（可独立验收）。

| 契约 | 行数 | 算法环节 | 功能点命名提示 |
|------|------|----------|----------------|
| 入参 `params[]` | **1 行/参数** | 查询条件处理 | `算法输入-{name}{中文}` |
| 出参（数值/汇总/比率） | 1 行/字段 | 指标计算 | `算法输出-{name}{中文}` |
| 出参（标识/维度/列表成员） | 1 行/字段 | 结果组装 | `算法输出-{name}{中文}` |
| 哨兵 | 分行 | 分析结果生成 / 异常处理 | 功能点写空态或失败语义 |
| req_only（需规算法，无 catalog 字段） | 按需 | 模型计算 / 结果同步 等 | 功能点写需规短语；**不写数据源对接** |

**具体描述**须写清：针对哪一字段、本环节处理什么、校验失败或空态如何表现（勿空话）。

禁止：sample/viz 发明字段；`metricIds` 逐 id 拆行；同一入参拆成「处理」「传递」两行。
