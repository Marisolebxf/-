## 说明抽检（3 条）

抽检目的：读说明列能知道「哪里有什么」，不能只写「样例 / 有筛选 / US-DS-POL-01」。

### 1. 功能点「集成国家政策数据」（对照句）

- **语义**：要有国家政策**对象**进入检索语料，并能按来源/地区筛出，不是页面上有「筛选」即算。
- **原型判定**：全景「政策来源」Radio 提供「国家政策」；适用地区下拉含「国家层面」；`policyListData` 有 `region:'national'` 的国家级条目（高新区管理办法、专精特新通知）。→ **已实现**（mock 算能力）。
- **原型说明写法**：写清控件名、选项文案、列表里有国家级条目；禁止只写「样例」。
- **原型路径**：`src/pages/policy-tracking/search/displayPolicySearchConfig.js` `POLICY_SCOPE_OPTIONS` `national`；`PolicyPanorama.jsx` 政策来源 Radio / 适用地区 Select；`policyData.js` `region:'national'`（路径列不写评述）。
- **五件套**：用户故事要求检索国家政策；全景线框地区筛选含国家。→ **有设计**。章节：`US-DS-POL-01`；IA §4 科创政策全景；WF `F-DS-POL-10` 地区。

### 2. 功能点「以 NOT 组合多个检索条件」

- **语义**：要看布尔 **NOT** 是否真能排除命中，不能因为有高级检索或 AND/OR 文案就标已实现。
- **原型判定**：`ConditionBuilder.tsx` 单条件 `negate` Checkbox；`queryEngine.ts` `evalSingleWithNegate` 对 eq/contains/in 等求反；`FilterPanel.tsx` 预览含 `NOT(field)`。→ **已实现**。
- **说明写法**：点名 Checkbox「NOT」与求反函数，而不是「有高级检索」。
- **五件套**：主路径 A「高级条件（效力级别、状态、布尔组合）」。→ **有设计**（布尔组合覆盖 NOT，未再拆名）。

### 3. 功能点「按浏览量升序排列检索结果」

- **语义**：对象是浏览量、方向是升序。有「浏览量」排序不等于升序已实现。
- **原型判定**：`SORT_OPTIONS.views` 仅一项「浏览量」；`sortPolicyResults` `case 'views'` 为 `(b.viewCount)-(a.viewCount)` **只降序**，无 `viewsAsc`。→ **未实现**。同组「按浏览量降序」才是已实现。
- **说明写法**：写清「下拉只有浏览量一项、实现只降序、缺升序」；路径仍标所查文件。
- **五件套**：US-DS-POL-01 / TRACE 只写「结果可排序」，WF 未提浏览量。→ **无设计**（不因「可排序」三字记有设计）。
