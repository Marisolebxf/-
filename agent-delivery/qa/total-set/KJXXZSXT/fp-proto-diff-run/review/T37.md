## 说明抽检（3 条）

抽检目的：读说明列能知道「哪里有什么」，不能只写「样例 / 有筛选 / US-DS-POL-02」。

### 1. 功能点「从产业园区网站采集最新政策信息」

- **语义**：对象是**产业园区网站**作为采集源，且最新入库列表能见到该来源条目；来源表有「园区」不等于列表已采到园区政策。
- **原型判定**：权威来源状态表有「国家高新区 / 产业园区资讯」、类型「产业园区网站」；`latestUpdates` 五条均为科技部门或政府官网，无园区来源。→ **部分实现**（枚举有、列表无该来源条目）。
- **原型说明写法**：写清来源表有园区站点、最新入库无对应 `sourceType`；禁止只写「有监控」。
- **原型路径**：`policyData.js` `sources` `src-park`；`latestUpdates`（路径列不写评述）。
- **五件套**：US-DS-POL-02 / TRACE 只写权威来源更新与最新列表，未点名产业园区网站。→ **无设计**。

### 2. 功能点「按每日频率推送政策动态」

- **语义**：动作是**按日推送**，不是界面上能选「每日」。有频率 Radio 不等于已按日调度。
- **原型判定**：`PUSH_FREQUENCY_OPTIONS` 含「每日推送」`daily` 并可写入方案；无定时任务，保存时 `pushDemoNotify` 只写一次收件箱。→ **部分实现**。同组每周/每月同口径。
- **说明写法**：写清「Radio 有每日、保存写入 frequency、缺按日调度」。
- **五件套**：订阅条件可配置 / Mock 推送通道，未写每日/每周/每月档。→ **无设计**。

### 3. 功能点「校验至少设置一项订阅条件」

- **语义**：对象是类别/行业/部门/地区等**订阅条件**至少一项，不是「至少一种推送方式」。
