## 说明抽检（3 条）

抽检目的：读说明列能知道「哪里有什么」，不能只写「样例 / 有筛选 / US-DS-POL-03」。

### 1. 功能点「根据企业或用户登记信息自动匹配适合的政策内容」

- **语义**：要按当前企业画像（规模/行业/阶段）算出适用政策，不是页面上有「匹配」卡片即算。
- **原型判定**：`PolicyMatchPanel` 结果卡有匹配度与理由，但 `matches` 恒等于 `policyMatchResults`，切换企业 Select 只改 Alert 文案、列表不变。→ **部分实现**（mock 算能力，但未随登记信息重算）。
- **原型说明写法**：写清卡片有匹配度/理由，同时写清切换企业不重算；禁止只写「有匹配」。
- **原型路径**：`src/pages/policy-tracking/PolicyPanorama.jsx` `PolicyMatchPanel` `matches=policyMatchResults`；`policyData.js` `policyMatchResults`（路径列不写评述）。
- **五件套**：故事要求按登记信息匹配并推送。→ **有设计**。章节：`US-DS-POL-03`；TRACE `US-DS-POL-03`；IA §2 匹配/推送入口；WF `F-DS-POL-10` 舆情：匹配推送。

### 2. 功能点「校验政策时期起点不得晚于终点」

- **语义**：对象是时期查询的起止约束。验收补充×**校验**按能力评判，不得记拆点加严。
- **原型判定**：高筛「时间（发布年）」range 在 `validateCondition` 中当起始值大于结束值返回「起始值不能大于结束值」。→ **已实现**。
- **说明写法**：点名 range 校验文案，而不是「有高级检索」。
- **五件套**：US-DS-POL-01/03 与全景线框筛选条未写时期起止校验。→ **无设计**。

### 3. 功能点「识别政策优点」

- **语义**：系统要产出「优点」对象，不能因为对比总结里出现「优缺点」三字或标杆报告有「优势」就记已实现。
- **原型判定**：`ComparisonModal` 总结仅写「可据此识别优缺点」，无优点字段；「优势劣势对比」在重点比对 Tab 的标杆报告，非本查询对比工具。→ **未实现**。路径仍标所查文件。
- **五件套**：US-DS-POL-03/09 写差异与共性/冲突，未点名优点识别。→ **无设计**（不因「查询对比」三字记有设计）。
