## 说明抽检（3 条）

抽检目的：读说明列能知道「哪里有什么」，不能只写「样例 / 有指标表 / US-DS-POL-08」。

### 1. 功能点「选择待抽取关键指标的政策」

- **语义**：动作是选定**待抽取对象**，抽取结果随所选政策切换，不是页面上有政策标题就算。
- **原型判定**：顶栏 Select 三条政策；`setPolicyId` 后 `policy.metrics` 进入「关键指标自动提取」表。→ **已实现**（mock 算能力）。
- **原型说明写法**：写清 Select 与表绑定 `metrics`；禁止只写「有拆解页」。
- **原型路径**：`PolicyPcPages.jsx` `PolicyParse` Select / Card「关键指标自动提取」；`policyPcData.js` `parsePolicies`（路径列不写评述）。
- **五件套**：可选政策查看提取指标表；线框政策选择器 + 指标提取表。→ **有设计**。章节：`US-DS-POL-08`；WF `F-DS-POL-PC02` 政策选择器 / 指标提取表。

### 2. 功能点「抽取政策中的时间节点」

- **语义**：对象是政策文本里的**时间节点**（日期/时限），类型文案含「时间节点」不等于已抽出时限。
- **原型判定**：仅 AI 政策 `kind:'时间节点/清单'`，值为「示范场景数 / 30 个」；另两份政策无该 kind。→ **部分实现**。
- **说明写法**：写清「kind 有时间节点/清单、样例是个数不是日期」；禁止只写「有类型列」。
- **五件套**：US-DS-POL-08 / WF PC02 只写关键指标提取与指标提取表，未点名时间节点。→ **无设计**。

### 3. 功能点「输出标准化指标数据集支撑多维对比」

- **语义**：输出物是**标准化指标数据集**进入多维对比，送入政策对象 ≠ 对比消费了 `metrics` 行。
- **原型判定**：`sendToCompare` 只 `saveCompareSlots` 政策 id；对比表/雷达用 `compareScoreMatrix`，未读 `policy.metrics`。→ **未实现**。
- **说明写法**：写清「槽里是 id、分数矩阵未引用 metrics」；路径仍标所查文件。
- **五件套**：TRACE 拆解结果作对比页对象输入；IA 对比典型输入为标准化条款/指标集。→ **有设计**（设计有、原型未把数据集接到对比）。

## 口径摘要

- 先读「动作 + 对象 + 可验收规则」，再在代码/五件套找同一能力。
- mock 的 `kind` 分类算抽取能力；kind 有、样例不是该对象（时间节点/清单→场景个数）→ 部分实现。
