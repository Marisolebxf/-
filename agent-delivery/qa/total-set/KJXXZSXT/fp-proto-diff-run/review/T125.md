## 说明抽检（3 条）

### 1. 功能点「构建政策分类标签体系」

- **语义**：动作是**构建**分类标签体系，不是页面上出现「标签」二字。
- **原型判定**：`PolicyGovernance`「政策库结构化」Tab 有「分类标签体系」只读表（`structureTaxonomy`：产业扶持等及覆盖份数），无新建/编辑/跑批。后台构建无前端对等。→ **不适用**。
- **原型说明写法**：写清只读表有什么、缺构建控件；禁止因表存在就标已实现。
- **原型路径**：`src/pages/policy-tracking/PolicyPcPages.jsx` Tab `struct`；`policyPcData.js` `structureTaxonomy`。
- **五件套**：US-DS-POL-07 / WF PC01 只写结构化库状态与覆盖率卡，未写分类标签构建。→ **无设计**。

### 2. 功能点「统一管理政策数据」

- **语义**：展示侧要能**统一看见/管理**库内政策，不是治理菜单存在即算。
- **原型判定**：治理页 KPI「库内政策数」3256 份 + 库结构化覆盖率 88.5%，并排分类标签表与字段映射表，构成只读管理看板（Mock）。→ **已实现**。
- **原型说明写法**：点名 KPI 与两张表；路径不写评述。
- **五件套**：故事要求查看结构化库状态；线框含库内政策数、结构化覆盖率。→ **有设计**。章节：`US-DS-POL-07`；TRACE `US-DS-POL-07`；WF `F-DS-POL-PC01`。

### 3. 功能点「未转化为结构化数据时不可高效调用政策数据」

- **语义**：对象是调用闸门，条件是**未转化**。有「底座未就绪」不等于按份转化校验。
