### 1. 功能点「对政策文本做意图识别」

- **语义**：动作是对政策文本做**意图识别**并产出意图类目，页面有「政策语义理解」Card 不等于已识别意图。
- **原型判定**：Descriptions「意图识别」Tag 绑定 `intent`（产业扶持 · 要素供给 / 主体培育 · 融资便利 / 财税激励 · 研发投入），随 Select 切换。→ **已实现**（mock 算能力）。
- **原型说明写法**：写清控件名、字段名与三份 mock 文案；禁止只写「有语义卡」。
- **原型路径**：`PolicyPcPages.jsx` Descriptions.Item「意图识别」；`policyPcData.js` `parsePolicies[].intent`（路径列不写评述）。
- **五件套**：POL-08 / TRACE / WF PC02 语义区块只到摘要，未见意图识别。→ **无设计**（不因「语义理解」三字记有设计）。

### 2. 功能点「适配海外政策文本解析」

- **语义**：对象是**海外**政策文本，解析结果能落在语义卡上。有地方/国家样例不等于海外已适配。
- **原型判定**：`parsePolicies` 仅 `市级`×1 + `国家级`×2，无海外/国际 `level` 或 `region`；Select 无海外选项。→ **未实现**。
- **说明写法**：写清已查枚举与缺海外选项；路径仍标所查文件。
- **五件套**：POL-08/PC02 未写适配海外；POL-01 海外范围为全景检索，不计入本五级。→ **无设计**。

### 3. 功能点「未提供政策文本时不可做语义解析」

- **语义**：无政策**文本**时须挡住解析，不是 Select 默认有值就算有闸门。
- **原型判定**：仅政策标题 Select，默认第一条且无 allowClear；无原文输入框、无「解析」按钮或空文本禁用。始终渲染当前 mock 语义卡。→ **未实现**。
- **说明写法**：写清缺原文输入与缺空文本闸；禁止只写「有政策选择器」。
- **五件套**：POL-08/WF 仅选择器+查看摘要；UX-SPEC PC02 empty 为页级空态。→ **无设计**。
