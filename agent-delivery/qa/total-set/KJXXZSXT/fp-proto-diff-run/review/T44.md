- **语义**：用户要能**选出**一份待解析文本再解析，不是解析 Tab 里已经有一份 mock 结果即算。

- **原型路径**：`InterpretWorkbench.jsx` `policyTextAnalysis['1']`；`policyData.js` `policyTextAnalysis`（路径列不写评述）。
- **五件套**：主路径 C / WF 只给「文本解析」子 Tab；PC02 政策选择器属核增拆解页，不计入本五级。→ **无设计**。

### 2. 功能点「以思维导图展示政策重点内容」

- **语义**：形态必须是思维导图（树/导图），有重点内容卡片或柱图不算。
- **原型判定**：Card「政策重点导图」`PolicyFocusMindChart` 用 ECharts `type:'tree'` 左右展开，四枝为政策目标 / 支持领域 / 实施路径 / 资金安排。→ **已实现**（mock 算能力）。
- **说明写法**：点名 tree 控件与四枝节点名，而不是「有可视化」。
- **五件套**：主路径 C / WF「重点可视」入口在，未点名思维导图。→ **部分提及**。同组「以图表展示」因无非导图图表记 **未实现**。

### 3. 功能点「按政策发布、申报受理、评审评估、资金拨付、效果评估展示关键节点」

- **语义**：五个环节名要能对上，有实施 Timeline 不等于五名齐全。
