## 说明抽检（3 条）

抽检目的：读说明列能知道「哪里有什么」；对象是核增 `/display/policy/insight-report` 的洞察四类提炼，不是 DS-11 评价报告、不是 DS-12 推演解读报告。

### 1. 功能点「自动提炼政策分析的核心观点」

- **语义**：要产出**核心观点**这类洞察，不能因为研报页有目录或正文「深度分析」就算已提炼。
- **原型判定**：`reportInsights` 有 `kind:'核心观点'`（ins-1）；目录「七、洞察与建议」List 用 Tag 列出。无独立提炼按钮，mock 结构化结果算能力。未用 `InterpretWorkbench` 推演报告。→ **已实现**。
- **原型说明写法**：写清 `kind` 文案、条目标题与落在哪块 List；禁止只写「有洞察」。
- **原型路径**：`policyPcData.js` `reportInsights` `kind:'核心观点'`；`PolicyPcPages.jsx` `PolicyInsightReport` `activeSection==='insight'` List。
- **五件套**：USM/WF 有洞察结论结果区，未写自动提炼核心观点作业。→ **部分提及**。章节：`US-DS-POL-10`；WF `F-DS-POL-PC04` 洞察结论。

### 2. 功能点「未具备政策分析时不可提炼洞察结论」

- **语义**：闸门是**没有政策分析就不得提炼**，不是「生成研报按钮会禁用」即算。
- **原型判定**：研报页加载即渲染四条 `reportInsights`，不依赖深度分析章节、不读对比 `ran`。对比页「生成研报」`disabled={!ran}` 只挡跳转。→ **未实现**。
- **说明写法**：写清始终渲染洞察、跳转禁用≠提炼闸门；路径仍标所查文件。
- **五件套**：主路径 D / TRACE 只写对比后进入研报；底座未就绪禁研报是治理闸。→ **无设计**。

### 3. 功能点「展示决策建议」

- **语义**：界面要露出**决策建议**条目，有「建议条数」KPI 或笼统洞察列表不等于该字段已设计/已展示要分判。
- **原型判定**：List Tag「决策建议」展示 ins-4；KPI「建议条数」；导出 insight 节含【决策建议】。→ **已实现**。
- **说明写法**：点名 Tag 文案与 KPI，而不是「有洞察列表」。
- **五件套**：WF 建议条数用途即决策建议（`M_POLICY_LAYOUT_REC_COUNT`）。→ **有设计**。同组「展示核心观点」线框未点名该类型，记部分提及，不升有设计。
