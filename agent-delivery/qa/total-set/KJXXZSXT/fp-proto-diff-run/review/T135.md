## 说明抽检（3 条）

抽检目的：读说明列能知道「哪里有什么」；对象是核增 PC03 `/display/policy/compare` 的对比摘要/导出/分享/二次分析，**不是** T140 智能研报「结果智能输出」（PC04 PDF/Word）。

### 1. 功能点「生成核心结论」

- **语义**：动作是**生成**核心结论，有对比摘要句或四类识别条目不等于已单独生成「核心结论」。也不是 PC04 研报洞察结论。
- **原型判定**：`summary` 会点名领先维度与互补/冲突；`buildCompareFindings` 只有共性/差异/互补/冲突；无独立核心结论字段。→ **部分实现**。
- **原型说明写法**：写清「摘要+四类 findings 有、缺核心结论生成」；禁止只写「有智能摘要」。
- **原型路径**：`PolicyPcPages.jsx` `summary`/`findings`；`policyPcData.js` `buildCompareFindings`（路径列不写评述）。
- **五件套**：US-DS-POL-09 / WF PC03 写智能摘要与识别目的，未点名核心结论。→ **部分提及**。

### 2. 功能点「导出对比数据」

- **语义**：对象是**对比**整理产物的导出，不是页面上有任一导出、更不是研报 PDF/Word。
- **原型判定**：PC03「导出摘要」走 `exportCompareSummaryDoc` 下载 `政策对比摘要_*.doc`（摘要+findings）；`exportReportPdf`/`exportReportWord` 在 `PolicyInsightReport`，不计入本叶。→ **已实现**（mock 算能力）。
- **说明写法**：写清按钮名、导出函数与文件形态，并点明非 PC04；禁止只写「有导出」。
- **五件套**：故事/TRACE 智能摘要可导出；WF [导出]；UX-SPEC `export_summary`。→ **有设计**。

### 3. 功能点「对比结果变更后重新整理对比结果」

- **语义**：对象变更后要**重新整理**摘要/结论，清掉旧结果不等于已自动重跑；也不同于「未运行则不整理」闸门。

- **五件套**：已查 US-DS-POL-09 / 主路径 D / UX-SPEC §5 / WF PC03，未见变更后自动重新整理。→ **无设计**。
