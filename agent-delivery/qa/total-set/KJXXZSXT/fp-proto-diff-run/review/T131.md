- **语义**：要把**发布主体**作为实体挂到拆解结果上，页面上有「实体关联」标题不等于四类都关联了。
- **原型判定**：Card extra 含「发布主体」；三条 `parsePolicies` 均有 `category:'发布主体'` 节点（市科技创新局 / 工信部 / 财政部）；List Tag + 力图按 category 成类。→ **已实现**（mock 算能力）。
- **原型说明写法**：写清 Card extra、节点名称、category 字段；禁止只写「有实体图」。
- **原型路径**：`PolicyPcPages.jsx` `PolicyParse` Card「政策实体关联」；`policyPcData.js` `entities` `category:'发布主体'`（路径列不写评述）。
- **五件套**：US-DS-POL-08 / WF PC02 只要查看实体关联图，未点名发布主体。→ **部分提及**。

### 2. 功能点「未结合政策知识图谱时不可关联实体信息」

- **语义**：闸门是**未结合政策知识图谱则不得关联**，有实体节点不等于做了图谱前置校验。
- **原型判定**：实体始终读 `parsePolicies[].entities` 写死数组；无图谱绑定开关；`baseReady` 只禁用对比/研报。PC03 政策间知识图谱不计入本五级。→ **未实现**。
- **说明写法**：写清数据源写死、无闸、所查治理开关；路径仍标所查文件。
- **五件套**：POL-08 / PC02 只写查看实体图。→ **无设计**。

### 3. 功能点「识别政策拆解完整性」

- **语义**：对象是拆解**完整性**（四类是否齐、拆解是否完整），有「关联度」不等于完整性已识别。
