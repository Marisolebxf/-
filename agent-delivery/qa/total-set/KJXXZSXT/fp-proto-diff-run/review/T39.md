## 说明抽检（3 条）

抽检目的：读说明列能知道「哪里有什么」，不能只写「样例 / 有筛选 / US-DS-POL-04」。

### 1. 功能点「自动识别政策内容删除部分」

- **语义**：要在所选新旧版本之间识别出**删除**内容，不是有「变化类型」列就算。
- **原型判定**：对比表有 `type==='removed'` 的删除 Tag/红字删除线/统计「删除 N 项」，但 `policyVersionCompareData` id=1 的 diffs 只有 added/modified，无 removed 行；时间线 `diff.removed` 未接入表。→ **部分实现**（有渲染分支、无删除样例行）。
- **原型说明写法**：写清「表支持 removed，mock 无该行、时间线 removed 未接入」；禁止只写「有差异表」。
- **原型路径**：`PolicyPanorama.jsx` `type==='removed'`；`policyData.js` `policyVersionCompareData` diffs（路径列不写评述）。
- **五件套**：USM-02 只写「高亮差异」，未枚举删除。→ **部分提及**。

### 2. 功能点「未选择对标对象时不可生成对标报告」

- **语义**：零对标对象时生成动作必须被拦住，不是有「一键生成」按钮即已实现。
- **原型判定**：`BenchmarkCompareModal` footer「一键生成对标报告」直接 `setReportVisible(true)`，不检查 `selectedRegions.length`。→ **未实现**。
- **说明写法**：写清按钮不校验已选城市数、零对象仍打开报告弹窗。
- **五件套**：WF §2.3「无对象时生成空报告」为禁止项；UX-SPEC §5「有对象才预览」。→ **有设计**（设计有闸门、原型未做）。

### 3. 功能点「按不同政策查看对标对比结果」

- **语义**：对象是**政策**，不是城市。有雷达/柱状/热力不等于能按政策查看。
- **原型判定**：可视化绑定 `benchmarkRegions` 城市卡片与 `vizType` Radio，无政策选择/切换。→ **未实现**。同组「按不同地区查看」才是已实现。
- **说明写法**：写清对象是城市/地区、缺按政策控件；路径仍标所查弹窗。
- **五件套**：TRACE 对标可视化未写按政策查看；详情对比是另一入口。→ **无设计**（不因「对标结果」三字记有设计）。

- 先读「动作 + 对象 + 可验收规则」，再在全景重点比对 Tab 的四个弹窗里找同一能力。
