## catalog 缺口（需规有、本页无 path）

1. **按企业名称评估**：需规「可按企业标识或名称进行技术力评估」，catalog 仅 orgId 路径入参，无按 name 查询接口（企业名称 → orgId 的检索/映射接口缺失）。
2. **SDK 调用方式**：需规「支持通过 RestfulAPI、SDK 方式调用」，catalog 仅有 REST 接口，无 SDK 契约（属交付形态缺口，非 REST path）。
3. **对标评估**：需规「实现实时查询、对标评估及改进建议」，本页有详情（tech-power/{orgId}）与报告（report），无显式「对标（benchmark，与同行/行业基准比较）」独立接口（部分能力可能由 rank+详情隐含覆盖，但无点名 path）。
4. **数据导出服务**：需规「支持生成可视化报告、对标分析及数据导出服务」，catalog 无导出类接口（如报表/数据导出 download/export path）。
5. **指标体系与权重参数写入/更新**：需规输入含「指标体系与权重参数」，catalog 仅有只读 GET `/entan/v1/eval/weights`，无指标体系定义或权重配置的写入接口（若按「只读消费」口径可视为不缺口，此处如实记录）。

## 抽 3 条不同验收

1. 行 3（rank 入参校验/输出）：调用 GET `/entan/v1/tech-power/rank` 传 industry、city、page、size，验收 = 返回顶层 list 且按技术力指数排序、分页正确 —— 与行 4/5（单维过滤）验收点不同（组合入参 vs 单维过滤语义）。
