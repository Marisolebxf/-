# Bug 正文

编号仍在 `qa/bug-registry.yaml` 取。先占号，再写正文。号的格式是 `BUG-{板块}-{系统}-{YYYYMMDD}-{3位}`，板块现用 `ZNFWJQ`。序号按系统加日期递增，不跳号、不复用。

脚本 blocked 或 fail 本身不是 bug。确认是产品、数据或环境问题后再登记。

## 两种正文

| 种类 | 路径 | 何时用 |
|------|------|--------|
| 历史轮次 | `{系统码}/R{n}-{轮次短名}.md` | 已有轮次。短名是这一轮在测什么，不是缺陷标题。例：`KJZTFWXT/R1-20261023-脚本修订.md`。不再追加 |
| 新登记 | `{系统码}/items/{编号}.md` | 2026-10-29 起，一条一个文件。模板 `_template.md` |

轮次模板留在 `_round-template.md`。同一系统不再把新缺陷按模块拆进轮次文件。

截图不进本仓库。有图时正文写 `飞书附件`，没有写 `无`。图片只在登记当次上传到飞书。

## 登记

| 值 | 含义 |
|----|------|
| `人工` | 对话或 `gkx-bug-record` 提交的。没有脚本编号时都写这个 |
| `轮次` | 这一轮收口时从试跑归集，或提交时指定了脚本编号 |

后补归集不改已经写上的 `人工`。

## 飞书

「GKX 当日进展」里的「缺陷」页是投影，不在那里取号。编号仍以 `bug-registry.yaml` 为准。文字落盘后执行 `node scripts/sync-feishu-bug.mjs --id {编号}`，把 BUG编号、标题、结论、模块、入口、环境、预期、实际、状态、关联用例、发现日期写入该行；有图再加 `--image {对话附件原路径}`。全量同步覆盖这些文字列，不清除已有附件，也不删除已有编号的行。

## 并行

两人同时取号可能撞车。推送被拒后合并远端，把**本地这次新号**往后顺延，并改台账、正文文件名和正文里的编号。已经推送的旧号不改。做法见 `.cursor/skills/gkx-bug-record/reference.md`。
