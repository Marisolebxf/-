## 1. 当前项目里缺的那一段

2026-10-22 的事实：

- 智树交付范围是展示、专题（企业 / 产业链 / 产业服务 / 政策 / 综合）和 Mapping 培训与模板。门户、智库、智算、情报、他队后台不在完成口径里。见 [`scope-baseline.md`](scope-baseline.md)、[`工程过程/02-策划与监控/02-智树工作计划/01-范围.md`](工程过程/02-策划与监控/02-智树工作计划/01-范围.md)。
- 出门日以智谱倒排为准：专题 V2.0、展示 V2.0、算法可接入都压在 **11-05** 前后。对接若等「全部开发完再对端」，这些出门日没有联调窗口。
- 对接材料是散的：门户方案在总集计划夹，0702 接口包在外部接口依赖夹，CMS 在内容运营夹，服务全景在另一夹，页面排期在展示集成工作计划。`04-产品集成.md` 只做指针，没有某一维的沟通流水、约定时点和当日进度。
- 0702 的 B0（8-31）、B1（9-11）、B2（9-30）内部需要日已过，B3 内部需要日是 10-31。表内大量「待评审」、预计提供时间为空。这些日期是智树内部需要日，不是对方承诺。
- 展示集成工作计划已经把统一用户、人才、图谱、全景排进页面长任务。那是页面施工序，不是对端签过的集成方案。
- 任务签收闸门已有：`ready_to_sign → done` 的操作人是 `human:淮政玮`。对接方案还没有用上这道闸门。
- 每天还有一张按人填写的飞书表：[YiwIsN4HjhGs6it3IW8Cvfnn5Tf](https://zhipu-ai.feishu.cn/sheets/YiwIsN4HjhGs6it3IW8Cvfnn5Tf?sheet=GviW3p)。列是负责人、任务内容、完成时间、完成状态、当日任务、当日进展、测试情况、其他备注。行按侯佳伟、李伟（科技发展态势）、徐滕强（科技政策）、淮政玮（数据中台及总集）分组。PM 每天向人收集后再手填。状态用颜色，当日进展里的阻塞用红色。

本稿用同一张列结构生成当日表，PM 不再把进展抄进飞书。飞书那张表在会签后停止手改。

本稿补上的是总过程，不是再写一套 Sprint 门，也不是再写一套过夜跑法。

## 2. 七项工作（按优先级）

### 3. 专题系统集成

1. **基础数据管理。** 智树负责产品链、企业、政策、产业服务机构，通过接口对接。技术链、科研机构、人才不在本块，归第 2 项。任务都在 epic `CMS-JX-INT`，状态为 2026-10-22 注册表快照。同 epic 的专家知识、全要素图谱、门户回写不计入本块。

   设计与落库：`CMS-JX-INT-DESIGN-L01`（done）、`CMS-JX-OVERLAY-A5-L01`（ready_to_sign）、`CMS-JX-OVERLAY-DDL-L01`（ready_to_sign）。

   写侧 11 条均在 integration：`CMS-JX-ENT-CRUD-L01`、`CMS-JX-ENT-NEWS-L01`、`CMS-JX-ENT-SZ-L01`、`CMS-JX-POL-CRUD-L01`、`CMS-JX-SVC-CRUD-L01`、`CMS-JX-SVC-NEWS-L01`、`CMS-JX-SVC-SZ-L01`、`CMS-JX-PROD-CRUD-L01`、`CMS-JX-IND-CUSTOM-L01`、`CMS-JX-PROD-NEWS-L01`、`CMS-JX-PROD-SZ-L01`。

   四类对象的只读接口：integration 有 `CMS-JX-ENT-LIST-L01`、`CMS-JX-ENT-PRODUCT-L01`、`CMS-JX-IND-TREE-L01`、`CMS-JX-IND-LINK-L01`、`CMS-JX-SVC-LIST-L01`、`CMS-JX-POL-EXPIRED-L01`、`CMS-JX-BULK-L01`；仍在 backlog 的有 `CMS-JX-POL-LIST-L01`、`CMS-JX-ENT-PROFILE-L01`。

   已开任务（epic `CMS-JX-INT`，2026-10-22）：`PORTAL-CMS-FIELD-API-L01`（in_progress，四模块字段与读接口契约）、`PORTAL-CMS-METRIC-COVER-L01`（claimed，四模块指标算法覆盖）、`PORTAL-CMS-DWD-WRITEBACK-L01`（blocked，回写总单）、`PORTAL-CMS-DWD-WRITEBACK-ENT-L01`（ready_to_sign，企业发展）、`PORTAL-CMS-DWD-WRITEBACK-CHAIN-L01`（ready_to_sign，专题全景）、`PORTAL-CMS-DWD-WRITEBACK-SVC-L01`（ready_to_sign，专题服务）、`PORTAL-CMS-DWD-WRITEBACK-POL-L01`（claimed，政策扶持确认无 CMS 回写）。这些是契约和回写，不是四菜单的全链路开发叶；全链路叶在方案签收后按本模块另拆。

## 7. WBS

签收当天或下一个工作日，PM 给出 WBS 列表。列表先是草稿。草稿可以写到区块和字段，用来对契约。草稿不是任务。

草稿确认后，留下来的每一行对应 registry 里的一个任务，由 coordinator 建叶。分组标题不是行，不建任务。已经在 registry 里的任务对上某一行就沿用原 ID，不另开一条。确认前不按草稿的细行建任务。

每一行写明：监管人、仓、依赖（`depends_on` 含方案任务 ID）、完成时什么叫可对端。一行是一个可汇报、可联调的子项。

表中的仓只是建议。建叶时由该行监管人确定仓，可以改。已经在 registry 里的叶，仓以注册表现状为准；要改仍由监管人决定。

粒度停在「这一行能单独从认领走到 `done`，并且进度快照能算出一个百分比」。同一监管人、同一可对端条件、同一次联调才算完成的内容，合成一行。字段清单、`metric_id`、`content_type`、单个 `page_key` 写进该任务的 DoD，不各开一行。拆开之后如果两行总是同一天、同一个人、同一次签收，就还是过细，确认时合并。

每个对接维度的 WBS 第一行是技术方案设计，对应 `技术方案.md`。开发叶依赖这一行。已在注册表里开工的叶保持原依赖，不把未签收的方案任务追进去。

2026-10-22 晚拍板：第 2 至第 7 项六份 WBS 草稿确认为建叶底稿。已经写明监管人的行，负责人就是该监管人，按项确定时不再另问。还写着「待指定」的行，按项补人。

建叶时写开始时间。完成日期要求取该任务已有的截至时间。没有截至时间的，由该行负责人在按项确定时写下。智树内部出门日不写成对端承诺，也不直接填进完成日期要求。注册表没有截止日期字段时，两句都写进该任务 `note`：`开始时间：YYYY-MM-DD`、`完成日期要求：YYYY-MM-DD`。

### 7.1 进度百分比

快照时分别调研设计和开发，再合成百分比。不手填，不采用口令里说的百分数。`blocked` 沿用上一次快照的分，不改成 0，也不改成 100。

大 WBS 有两层，每层都要有一个整体百分比：

- 对接维度：第 2 至第 7 项各一份
- 一级工作包：该维 WBS 里的分组（如企业发展、基础数据管理）。分组标题不是任务。其下确认后的行才是任务

设计类任务：`definition`、`tech_task`、方案行。开发类任务：`feature`、`bugfix`。`chore` 不进入百分比。

**设计分**（快照读 MCP，并打开 DoD 点名的产物）：

| 见到的情况 | 分 |
|---|---|
| 未建任务，或 `backlog` / `ready` | 0 |
| `claimed`，产物还没有 | 10 |
| `in_progress` / `needs-revision` | 10 + 40 ×（已落盘且规定章节都在的产物数 ÷ DoD 点名的产物数）。一个产物都没有，就是 10 |
| `integration`，handoff 章节齐 | 60。章节不齐，停在 40 |
| `ready_to_sign` 或 legacy `review`，evidence 已有 | 90。evidence 没有，停在 60 |
| `done` | 100。没有签收记录，停在 90 |

**开发分**（同一快照再看 evidence、`touched_files`、handoff、`note` 里的联调确认词）：

| 见到的情况 | 分 |
|---|---|
| 未建任务，或 `backlog` / `ready` | 0 |
| `claimed`，或 `in_progress` 但 evidence、`touched_files`、handoff 都空 | 10 |
| `in_progress` / `needs-revision`，且上面三项至少有一项 | 10 + 30 ×（DoD 里能在 handoff 或 evidence 对上的条数 ÷ DoD 条数）。DoD 为空则停在 10 |
| 状态已到 `integration` 及以后，但 `note` 没有联调确认词 | 最高 40 |
| `integration` 且有联调确认词 | 60 |
| `pending_test` | 70 |
| `testing` | 80 |
| `ready_to_sign` / legacy `review` | 90 |
| `done` 且 evidence 已有 | 100。`done` 但没有 evidence，停在 90 |

状态写得比证据靠前时，用上表里较低的那一档。

**一条任务的百分比**：设计类 = 设计分。开发类 = 开发分。

**一个大 WBS 的整体百分比** = 设计进度 × 30% + 开发进度 × 70%，四舍五入到整数。

- 设计进度 = 其下设计类任务设计分的平均。一条都没有时，用该维方案任务的设计分
- 开发进度 = 其下开发类任务开发分的平均。确认了但还没建任务的行按 0 计入
- 这个大 WBS 没有开发行：整体 = 设计进度
- 方案任务未 `done`：新的开发行开发分记 0。已在 registry 里开工的存量叶仍按上表调研，不回退成 0

维度和一级工作包都用这一式。不把这个比率再平均成某一个人的完成率。汇总时另写阻塞行数。

展示页面施工序仍以 [`05-展示系统集成工作计划.md`](工程过程/02-策划与监控/02-智树工作计划/02-进度/05-展示系统集成工作计划.md) 为页面排期。它不代替对接维度的 WBS。两边冲突时，未签收的对接子项在页面上用空态，任务可以排，不把对方未承诺的数据写成已接入。

某一叶若要连夜跑，那一叶再按《长任务执行规约》做总控。总控不改变本规约的签收和回写。

## 8. 当日表（代替飞书手填）

飞书表现在的八列保持不变。真源改到仓内一份按日文件，skill 生成，PM 只跑命令、不抄格子。

```text
工程过程/当日进展/YYYY-MM-DD.md
```

同一天只保留这一份。按负责人分节，节内是表。负责人取任务的 `supervised_by`。一个人名下再按模块分块（如李伟 / 科技发展态势），模块名取任务所属系统或对接维度。

| 飞书列 | 从哪来 | 谁维护 |
|---|---|---|
| 负责人 | `supervised_by` | 建叶时写一次 |
| 任务内容 | 任务标题 + 范围一句 | 建叶时写一次 |
| 完成时间 | 建叶时写入的计划完成日 | 改期才改，不每天重填 |
| 完成状态 | 任务状态，见下表颜色 | skill 每天读 MCP |
| 当日任务 | 该叶当天仍在执行则带出标题；监管人另说了「今日做」则用原话 | 不说则用标题 |
| 当日进展 | 监管人当天在 Cursor 说的那一句 | **只有这列每天要人开口**。当天没说，写「今日未报」，不代写 |
| 测试情况 | 联调结论或测试状态 | 没记录就写「未见测试记录」 |
| 其他备注 | 方案、流水、发布证据、阻塞原因的链接 | skill 带链接 |

完成状态颜色与任务状态：

| 任务状态 | 格内文字 | 颜色 |
|---|---|---|
| `done` 且有发布证据 | 完成 | 绿 |
| `done` 无发布证据 | 任务关闭，未见发布 | 黄 |
| `in_progress` / `claimed` / `testing` | 进行中 | 黄 |
| `ready_to_sign` | 待签收 | 黄 |
| `blocked`，或当日进展里人声明数据/对端未到位 | 阻塞 | 红 |
| 当天没有口令 | 状态仍按上一行，当日进展为「今日未报」 | 不另造红 |

`done` 不等于已发布。没有流水线、环境或提交，发布栏写「未见发布证据」。

每个大 WBS 的设计进度、开发进度、整体百分比用 §7.1。快照当时调研产物和证据，不把注册表状态直接当成百分比。口令里若说了百分数，只留在当日进展原话里，不参与汇总，也不改注册表。不把各行百分比再收成一个人的完成率。

阻塞句（如总集承诺的数据未到位、对接方 1%）由监管人或 PM 在口令里说出，skill 把它放进当日进展并标红，同时在该维度 `风险.md` 追加一条。skill 不自己判断该不该标红。

### 8.1 PM 每天做什么

每个工作日 PM 跑一次「今日快照」。skill：

1. 用 MCP 读取执行中的任务（按监管人，不读注册表全文进回答）。
2. 按 §7.1 调研第 2 至第 7 项。每一条任务打开 DoD 点名的产物、handoff、evidence，分别记下设计分或开发分。再算出每个一级工作包和每个对接维度的设计进度、开发进度、整体百分比。
3. 收集当天已经落盘的口令。口令里的百分数不写入上面三个数。
4. 覆盖写入 `工程过程/当日进展/当天日期.md`。每个大 WBS 一行：设计、开发、整体。
5. 把同一组数追加到该维度的 `进度.md`，并刷新该 `README.md` 顶部「当前」。
6. 另写当日 `WBS汇总-YYYY-MM-DD.xlsx`（实现任务明细）。
7. 出站投影飞书多维表格「GKX 当日进展」（八列 + 维度汇总）。命令与配置见 skill `gkx-dev-process` / `feishu-daily-snapshot-board.yaml`。飞书改动不回写 git；下一轮快照覆盖飞书。缺凭据或失败时仓内文件仍保留。

PM 不开口，skill 不写文件。不做定时任务。会签后停止在飞书格子里手改八列；站会看投影表或仓内当日文件。

### 8.2 监管人口令

对接叶：

> 集成进度：{维度} / {子项}。今日做：{一句}。发布：{环境、流水线或提交}。可对端：是/否。测试：{一句或未见}。

自研叶：

> 开发进度：{模块} / {子项}。今日做：{一句}。发布：{证据或未见}。测试：{一句或未见}。

有阻塞时加一句：`阻塞：{原因}`。这句话成为当日进展的红字。

口令落在当日表对应行，并追加到该模块或该维度的进度文件。记录声明人、日期、原话。

## 9. 分项联调

子项同时满足三条，就可以记联调，不必等兄弟任务发布：

1. 边界已经写进已签收方案或我方对接文档
2. 测试环境可调，或 `约定时点.md` 里写了这一段用空态 / 桩
3. 该子项已发布，或监管人声明这一段不依赖发布（例如菜单跳转）

联调记两处：`进度.md` 一节（通过 / 阻塞 / 对方未到），`沟通流水.md` 一条。阻塞升级走现有任务状态 `blocked`，原因与过程夹同一句话。

对方说「无法提供」时，一个工作日内由 PM 写成三选一：替代源、降级空态、范围变更。变更范围仍由项目负责人和 scope-baseline 决定，不在流水里改口径。
