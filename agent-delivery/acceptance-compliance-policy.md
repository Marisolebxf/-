# 甲方验收合规策略

> **工作范围真源（出发点）**  
> `agent-delivery/bid-reference/` 下两份 Markdown 为**原始方案说明**，**所有工作范围以此为准**：
> - `科技信息展示系统和科技专题服务系统.md`
> - `科技专题服务算法库.md`
>
> **实现弹性**：实际交付可依**数据提供情况**调整算法路径、数据源与实现细节（见 `scope-baseline.yaml#implementation_flexibility`）。  
> **功能点总量铁律**：相对 MD 基线叶子功能点 **上下浮动不得超过 10%**（基线 58 项 → 最多 ±6 项）；超出须 PM 审批并登记 `scope-baseline.yaml#change_log`。
>
> **验收对照**：qa-agent 按 MD **标题结构**定位章节，对照 dev 实现写验收意见（`acceptance-review-workflow.md`）。  
> **补充台账**：`2-概要设计/2-1需求分析` 用于澄清与 CSV 索引，**不得扩大** MD 范围超过 ±10%。  
> **不读 PDF**。

## 2. ±10% 功能点浮动规则

```text
基线 total_scope_units = 58（见 scope-baseline.yaml#baseline.units）
允许活跃范围：52 ~ 64（含端点）
计数口径：MD 同级别叶子（展示 DS-01~30、专题 6 模块、战略分析 7 要素、算法 7+1+7）
```

| 情形 | 处理 |
|------|------|
| 仅改算法/数据/接口实现，叶子仍在 | ✅ 允许，handoff 说明 as-built |
| 叶子内 Tab 合并/拆分，总数不变 | ✅ 允许 |
| 新增或删除叶子，总数仍 ±10% 内 | ⚠️ 更新 catalog + change_log |
| 超出 ±10% | ❌ 须 PM 批准后再改 task-registry |
| 数据不足 | DEMO 或降级实现，**不可删菜单** |

## 3. 三级交付口径（Compliance Tier）

| Tier | 含义 | 验收表现 |
|------|------|----------|
| **FULL** | 真实数据 + dev 可测 | ADS/算法产出 |
| **INTEG** | 三方/共建集成 | 外部 API 可用 |
| **DEMO** | 演示兜底 | 须登记 demo-registry |

验收合规 = 基线范围内 100% 叶子有入口（FULL + INTEG + DEMO）。

功能验收遇到计算逻辑已登记、源数据仍缺的字段时，按 `data-lineage-policy.md` §2.4 / 架构基线 D16：只在 `gkxlumenx_gapfill` 使用 `gapfill_` 表灌数（LLM 或其他方式）。口径未闭合时按客户决策清单里的临时默认实算。缺项补齐并实算完成后 D4 不得再是 mock，该叶按 FULL 验收，不留在 DEMO。

## 6. 定开系统交付文档用词与测试真实性（甲方口径，2026-11-12 human:淮政玮 转达）

适用范围：定开系统交付甲方的全部文档（上线部署方案、部署手册、用户/管理员手册、测试用例、测试记录、测试报告等，含 `验收文档/上线验收材料/` 全部产出）。

**用词禁令**

1. 以下词在上述文档中**不得出现**：`超算`、`超算二期`、`生产环境`、`预生产环境`、`开发环境`、`测试环境`、`上线`。
2. 替代口径（尽量模糊化）：
   - 部署目标 → 写「**云环境**」；
   - 需要表达投产动作 → 写「**内测上线**」；
   - 环境区分 → 用「现网 / 云环境」等模糊表述，不展开环境性质。

**测试材料真实性**

3. 定开功能的测试用例、测试记录、测试报告**必须内容真实、准确、有效**——必须是自己实际测试过的结果，禁止编造数据、虚构执行记录、抄模板占位充数。

**执行方式**

4. 文档落盘/套版后跑禁用词扫描（PowerShell：`Select-String -Pattern "超算|超算二期|生产环境|预生产环境|开发环境|测试环境|上线"`），命中清零方可交付；命中记录留在 handoff。
5. 原始要求留档：`验收文档/上线验收材料/0-材料清单与总集要求/沟通流水.md` 2026-11-12 条目。

> ⚠️ 注意：本节禁令只约束**对外交付文档**；仓内过程文件（handoff、task-registry、环境对照留档等内部资产）不受此限，仍按技术准确性优先。
