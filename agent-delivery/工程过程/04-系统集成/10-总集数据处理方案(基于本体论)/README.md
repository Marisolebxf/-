## 一、范围

整体项目涉及系统众多：专题系统的七要素、展示系统、数据治理、科学数据资源、主题数据中心的运营和维护。本项要求各 Team 从「本体」角度写方案，使每个要素的数据和指标都挂在唯一的真源实体与唯一的指标身份证上，各系统的统计数字都能回溯，避免各自建完之后指标对不上。

本项是横切规约性质的方案，不替代第 05、06、07 项的对接方案，也不替代 D9《数据血缘规约》。

## 二、做什么、不做什么

**做**：

- 写清三层真源（实体与关系、指标身份证、业务主键与落表）以及冲突时听谁
- 给各 Team 一张写作契约短表：每份方案必须写明引用的实体类型、`metric_id`、ADS 落表、加工包、禁止自算项
- 用政策要素做一张试点对照表，证明三层能串起来，并暴露缺口
- 给其他要素一份可照抄的索引模板

**不做**：

- 不重做 GDF 三包拆法（`{DIM}-MDC` / `{DIM}-Graph` / `{DIM}-MRC` 沿用既有拆解思路）
- 不另建 Ontology Catalog、不建第二套实体类型表、不建本体库
- 不改 Nebula schema，不嵌图谱管理界面
- 不改 GDF 派单包、指标 seed、就绪度矩阵
- 不扩 ENT / CHAIN / SVC 全量对照表（本期只做政策试点）
- 不替甲方拍板业务口径；口径未闭合项仍以客户决策清单为准
- 不建 registry 任务；方案任务是否建由 PM 另裁
