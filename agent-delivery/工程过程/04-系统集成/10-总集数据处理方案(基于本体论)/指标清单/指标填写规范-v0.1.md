本规范不另起一套指标体系。它把 D9 的「8 件套」原样作为必填核心，只补三件事：**指标挂在哪个实体上、依赖哪些子指标、依赖哪些数据**。这样各系统的统计数字都能追到同一个实体、同一个口径、同一张表。

---

## 一、填写总原则（7 条）

| # | 原则 | 说明 |
|---|---|---|
| 1 | **一个口径一个 ID** | 同一业务口径在任何系统、任何页面只用一个 `metric_id`。按口径命名，不按页面或展示位置命名 |
| 2 | **先查后建** | 填之前先在指标注册表查（仓内用 MCP `metric-registry` 的 `metric-query`；仓外团队把中文名发给唐绍祖代查）。已有就复用该 ID，不另建 |
| 3 | **同名不同口径必须拆开** | 名字一样但统计范围、去重或公式不同，视为两个指标，用 `VARIANT` 后缀区分，并在「口径差异说明」写清差在哪 |
| 4 | **每个指标挂一个主实体** | 主实体只能从第五节的实体类型表里选。论文、专利、项目不是独立实体类型，按第五节映射挂到七要素 |
| 5 | **复合指标先拆子指标** | 公式里用到的其他指标，必须先作为独立行登记，再在父指标里引用其 ID。禁止在公式里写一个没登记的中间量 |
| 6 | **数据依赖写到字段** | 只写「政策库」「企业数据」不算填完。必须写到表名和字段名；没有源就写「无源」并写缺口 |
| 7 | **不确定就标，不要编** | 口径没定写「待甲方」并带客户决策清单编号；表名不清楚写「待查」。不允许为了填满而猜 |

## 二、交付结构：两张表

一条指标要说清楚的内容，分两张表写，避免一格里塞多值。

| 表 | 粒度 | 回答什么 |
|---|---|---|
| **表 A 指标主表** | 一个指标一行 | 是什么、怎么算、挂哪个实体、依赖哪些子指标、结果放哪 |
| **表 B 数据依赖表** | 一个指标 × 一个字段一行 | 这个指标读哪张表的哪个字段、拿来做什么、有没有源 |

两张表用 `metric_id` 关联。一个指标在表 B 通常有 2～6 行。

## 四、metric_id 命名规则（摘自 D9 §3）

格式：`M_{要素码}_{指标主体}_{时间窗口}_{变体}`，后两段可省。全部大写英文、下划线分隔，4～6 段。

| 段 | 取值 |
|---|---|
| 要素码 | `ENT` 企业 / `CHAIN` 产业链 / `ORG` 科研机构 / `TECH` 技术 / `TALENT` 人才 / `SVC` 服务机构 / `POLICY` 政策 / `SS` 软科学 / `IC` 创新生态 / `INNOV` 创新监测 / `SYNTH` 综合 / `COMMON` 通用 |
| 指标主体 | 英文大写蛇形，如 `TOTAL_COUNT`、`GROWTH_RATE`、`INNOVATION_INDEX` |
| 时间窗口 | `D` / `W` / `M` / `Q` / `Y` / `YTD` / `TOTAL` |
| 变体 | 仅用于同名不同口径：`V1`、`STRICT`、`LOOSE` 等 |

禁止：中文 ID、拼音、小写、同一口径在不同页面用不同 ID。高端智库等新增要素码需要时，先报唐绍祖，统一加入码表后再用。

## 五、主实体类型（只能从此表选）

真源是跨系统知识图谱 SAD 的「一张七要素本体」。不允许各系统自造实体类型。

| 实体类型 | 要素码 | 主键语义 | 说明 |
|---|---|---|---|
| 企业 | ENT | 项目归一企业键 | |
| 产业链 / 产业环节 | CHAIN | `chain_id` + `node_id` | 底图。按环节统计的指标挂这里 |
| 科研机构 | ORG | 项目归一机构键 | 高校、院所、实验室 |
| 技术 | TECH | 技术点键 | 技术点、技术方向 |
| 人才 | TALENT | 人才键 | 专家、团队负责人 |
| 服务机构 | SVC | 服务机构键 | 孵化器、检测、金融等中介 |
| 政策 | POLICY | 政策键（`policy_id`） | 含条款包 |
| 区域（空间属性） | COMMON | 行政区划代码 | 区域**不是第八种实体**。按地区统计的指标，主实体仍填被统计的对象，区域写在「统计维度」；只有纯区域宏观量（如 GDP）才填区域 |

常见对象怎么挂（不要新建实体类型）：

| 对象 | 主实体填 | 说明 |
|---|---|---|
| 论文 | 人才或科研机构 | 论文是成果属性，按作者或机构统计 |
| 专利 | 企业或科研机构 | 按权利人统计 |
| 项目 / 课题 / 经费 | 企业或科研机构 | 按承担方统计 |
| 创新载体 | 企业、科研机构或服务机构 | 按运营主体归类，载体归属未定的在备注标「待算法圈定」 |
| GDP / 规模 / 综合指数 | 区域或被评价的对象 | 是统计量，不是图谱实体 |
| 智库报告、舆情等高端智库对象 | 先填最接近的七要素，备注写原对象名 | 七要素都挂不上的，标「待映射」并报唐绍祖，由方案组统一裁定 |

## 六、指标层级

层级决定要不要填「依赖子指标」。按本体做指标统一，核心就是：原子指标只定义一次，其他指标都由它组合出来。

| 层级 | 定义 | 依赖子指标 | 示例 |
|---|---|---|---|
| 原子 | 直接在一个实体的数据上做一次计数、求和、去重等基础计算，不引用其他指标 | 填「无」 | 政策总数；企业专利数 |
| 派生 | 一个原子指标加时间窗口、维度过滤或比率变换得到 | 必填，通常 1～2 个 | 本年新增政策数；深圳政策占比；专利同比增长率 |
| 复合 | 由多个指标经加权、评分、模型计算得到 | 必填，列全部子指标 | 企业创新能力指数；区域创新活力指数 |

派生和复合指标的计算逻辑里只能引用已登记的子指标 ID 或表 B 里列出的字段。

## 七、算法类型枚举（摘自 D9 §2）

| 值 | 含义 | 由谁实现 |
|---|---|---|
| STAT | 计数、求和、占比、排名等统计 | Java 只读 ADS 或离线脚本 |
| COMPUTE | 多步规则计算（归一、加权、阈值分档） | Python |
| MODEL | 机器学习、NLP、大模型推理 | Python |
| GRAPH | 图计算（中心性、路径、社区） | Python / 图谱引擎 |
| third_party | 直接取第三方接口结果 | 接口对接 |
| MIXED | 以上多种混合 | 写明各步类型 |
| LITERATURE | 文献、报告人工梳理得出 | 人工 |
| UNKNOWN | 尚未确定 | 不得派开发 |

MODEL、GRAPH、MIXED 在「计算逻辑」里要分步骤写，每步写输入、输出和所用模型或算法名。

## 十、提交前自检（逐条打勾）

| # | 检查项 |
|---|---|
| 1 | 每行都有 `metric_id`，且已在注册表查过重；新指标用 `TMP_` 临时号 |
| 2 | 口径定义不少于 50 字，四要素（范围、窗口、去重、特殊情况）都写了 |
| 3 | 主实体类型全部取自第五节，没有自造类型 |
| 4 | 派生、复合指标的子指标全部已作为独立行登记 |
| 5 | 计算逻辑可复算，没有「见文档」「同上」；权重、阈值写了具体值或标「待甲方」 |
| 6 | 每个指标在表 B 至少有一行，字段写到字段名 |
| 7 | 「待甲方」的行都带决策编号；「无源」的行都写了缺口说明 |
| 8 | 与其他系统同名的指标，已填同名指标 ID 和口径差异说明 |

## 十一、提交与汇总

| 步骤 | 谁 | 做什么 |
|---|---|---|
| 1 | 各模块负责人 | 按本规范填本模块清单，自检后交本团队汇总人 |
| 2 | 智树侧汇总（唐绍祖） | 合并专题、展示清单；`TMP_` 号转正；把已有指标与注册表核对；输出跨系统同名冲突表 |
| 3 | 仓外团队（如高端智库） | 用 Excel 模板填写，交唐绍祖做 ID 查重与实体映射核对 |
| 4 | 签收（淮政玮） | 按任务 `SYSINT-ONTO-METRIC-INV-L01` 签收 |

清单是梳理工作底稿，**不是**指标真源。会签后由 data-agent 正式化写入指标注册表（`metrics/registry/`），之后以注册表为准，清单不再单独维护。
