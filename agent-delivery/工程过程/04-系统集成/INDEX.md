## 4. 夹内七件套

```text
04-系统集成/
  INDEX.md                          # 本文件：七项登记
  {维度}/
    README.md                       # 主文件，顶部始终是「当前」
    沟通流水.md                     # 只追加
    纪要/YYYY-MM-DD-题目.md
    对接文档/我方/
    对接文档/对端/
    约定时点.md                     # 只 PM 写
    风险.md
    进度.md
```

| 文件 | 谁写 | 纪律 |
|---|---|---|
| README.md | PM | 顶部「当前」+ 范围 + 三份材料入口，不贴流水正文 |
| 沟通流水.md | PM、参会人 | **只追加**。一条含日期、谁、何事、指向哪份纪要或文档 |
| 纪要/ | PM | 一场会一份。结论、未决、下次时间 |
| 对接文档/我方/ | PM 收口 | 我方发出的字段、时序、环境、验收条件 |
| 对接文档/对端/ | PM 落盘 | 对端原文或导出，文件名带收到日期 |
| 约定时点.md | **只 PM** | 双方说过的日期，旁边写出来源。**智树内部需要日单独成节** |
| 风险.md | PM，监管人可追加事实 | 甲方口径仍以 [客户决策清单跟踪表.md](../../客户决策清单跟踪表.md) 为准 |
| 进度.md | skill 写快照；监管人报子项 | 顶部「当前」；下面按日追加，不覆盖旧日 |

空文件也保留标题，避免后来的人另起一份。已有方案正文留在原路径，主文件只链接。

## 6. 当日表（§8）

飞书表八列保持不变，真源改到仓内 `工程过程/当日进展/YYYY-MM-DD.md`，由 skill 生成。

| 飞书列 | 从哪来 |
|---|---|
| 负责人 | 任务 `supervised_by` |
| 任务内容 | 任务标题 + 范围一句 |
| 完成时间 | 建叶时写入的计划完成日，改期才改 |
| 完成状态 | 任务状态映射颜色（规约 §8 表） |
| 当日任务 | 该叶当天仍在执行则带出标题 |
| 当日进展 | **监管人当天在 Cursor 说的那一句**，没说写「今日未报」 |
| 测试情况 | 联调结论或测试状态，没记录写「未见测试记录」 |
| 其他备注 | 方案、流水、发布证据、阻塞原因的链接 |

**当前状态**：`工程过程/当日进展/` **尚未建立**（规约 §14 第 5 项，会签后建）。飞书表仍在手填。

- 在过程夹里修改 scope-baseline 的范围
- 快照之后再手改飞书八列
