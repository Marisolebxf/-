## 1. 范围与分工

### 1.2 调用链（对齐架构基线与技术方案 §2.1）

```
智谱前端（页面属智谱，不进智树仓）
  → gkxlumen-platform-gateway（鉴权/转发）
    → gkxlumen-topic（Java，只读 ADS）
      → 需要计算时 lumen-algo-py /internal/*（Python 写 ADS，Java 只读）
```

- 智谱前端不直连 Python、不直连 ADS；门户后端不代理这组 API（技术方案 §2.1 禁止事项）。
- 菜单相对路径由统一用户中心配置，接口 URL 不写主机名（既有 DoD）。
- 缺数为空态，不伪造数值；指标口径只读 `gkxlumen-metrics` catalog，不新编 metric_id。

## 2. 接口清单（智树出数部分）

统一前缀：`{gateway}/topic/v1/portal/one-map`（挂 gkxlumen-topic；最结名以 Java 实现为准，此为需求草案）。

**对接约定（2026-11-06 增，参照徐滕强 CMS-JX live-1.2 对外接口文档的路由规则）**：

| 约定 | 本组接口取值 |
|---|---|
| 请求方法 | 全部 `POST`，请求体 JSON |
| 路径参数 | 禁止业务 id 走路径；`industry_code`/`district`/`keyword`/分页一律在 body |
| 字段命名 | `snake_case` |
| 分页 | `page` 从 1 起；`size` 默认 20、上限 100（API-5 当前内部实现上限 50，见 §3） |
| 列表信封 | `data: {total, page, size, records}` |
| 统一响应信封 | `{code:0, msg:"ok", data:{}}`（Java `R` 包络同构） |

### API-1 产业维度统计（序号 99 · 产业页签）

| 项 | 内容 |
|---|---|
| 路径 | `POST /industry-stats` |
| 入参 | `{ industry_code: string /* 八大未来产业，枚举待对齐 §5-1 */ }` |
| 出参 | `{ scale: { value: number, unit: '亿元', metric_id }, org_count: { value: number, metric_id }, scale_trend: [{ year: number, value: number }], org_count_trend: [{ year: number, value: number }] }` |
| 原型对应 | 「产业规模（亿元）117.0」「企业机构数量（家）225」「产业指标趋势」双折线 2021-2025 |
| 指标挂靠 | 产业规模：**缺**（候选 M_CHAIN_SZ_ENTERPRISE 口径不含规模值，需 data-agent 定）；企业机构数量：候选 M_ENT_REGIONAL_COUNT_TOPIC / M_ENT_SZ_COUNT（口径待核） |
| 数据面 | ADS 新表或复用链专题 ADS（阶段2 由 data/api 联合定表；**孔东裁定：先不灌数，scale 无源出空态**） |
| 既有链路 | Java 已有 `/topic/v1/stats/overview/industry-trend`（`enterprise_industry_summary`，chain_code=INB*，历年企业数）可直接供 org_count 与 trend；industry-kpi 供链级汇总。复用：Feign 转发+重组，无新算法 |

### API-2 企业指标统计（序号 99 · 企业页签）

| 项 | 内容 |
|---|---|
| 路径 | `POST /enterprise-stats` |
| 入参 | `{ industry_code: string }` |
| 出参 | `{ count: { value: number, unit: '家', metric_id, trend: [{ year: number, value: number }] }, medium_large_ratio: { value: number, unit: '%', metric_id }, employee_count: { value: number, unit: '人', metric_id }, scale_dist: { metric_id, buckets: [{ label: '大型' \| '中型' \| '小型' \| '微型', count: number }] }, employee_dist: { metric_id, buckets: [{ label: '<50' \| '50–199' \| '200–499' \| '≥500', count: number }] } }`（trend 并入 count 块，同 metric_id；每个统计块独立挂 metric_id） |
| 原型对应 | 「企业数量 225」「中大型企业占比 43%」「企业从业人数 15,653」+ 数量趋势 2021-2025 + 规模分布四桶（24/73/91/28 家）+ 人数分布四桶（87/59/48/31 家） |
| 指标挂靠 | 企业数量：M_ENT_SZ_COUNT（口径=深圳，需核是否限定产业维度）；中大型企业占比、企业从业人数、规模/人数分布：**缺**（见 §3-3/9/10，需登记） |
| 既有链路 | Java 已有 `/topic/v1/stats/overview/industry-kpi + industry-trend`（企业数/研发人数/历年趋势，chain_code 维度）供 count 与 trend；`/topic/v1/key-enterprise/type-scale-stats`（`enterprise_type_scale_stats`，enterprise_scale=大/中/小/微）供 scale_dist 与 medium_large_ratio（四桶派生）。employee_dist 无源出空态（先不灌数）。复用：Feign 组装，无新算法 |

### API-3 政策指标统计（序号 100 政策支持专题图 + 序号 101 行政区政策指标）

> 说明：序号 99 原型五页签无政策页签，但序号 100 政策支持图与序号 101 行政区指标均需政策数。归并到此接口统一出行政区级政策统计。范围仅限专题一张图页。

| 项 | 内容 |
|---|---|
| 路径 | `POST /policy-stats` |
| 入参 | `{ industry_code: string, district?: string /* 可选，不传=全深圳 */ }` |
| 出参 | `{ count: { value, metric_id }, trend: [{ year, value }], by_district: [{ district: string, count: number }] }` |
| 原型对应 | 行政区卡「政策 22 条」、政策支持专题图渲染值 |
| 指标挂靠 | 政策数量分布：候选 M_INNOV_PG_COUNT_DIST / M_POLICY_BASE_100_1（口径待核：深圳+产业维度过滤） |
| 既有链路 | **近零成本**。Python 已有 `/internal/policy/indicators?kind=sz&industry_code=INB*`（Java `/topic/v1/policy/indicators` 已透传）：读 ADS `policy_sz_dist`，出九区 `district_name + policy_count`，**已支持 INB 产业码过滤**；kind=timeseries 出年度趋势。复用：直接转发重组 |

### API-4 行政区指标统计（序号 101 · 行政区切换）

| 项 | 内容 |
|---|---|
| 路径 | `POST /district-stats` |
| 入参 | `{ industry_code: string, district: string /* 深圳 9 正式行政区枚举 */ }` |
| 出参 | `{ development_index: { value, metric_id }, enterprise_count: { value, metric_id }, policy_count: { value, metric_id }, research_org_count: { value, source: 'jiuxin' \| null }, talent_count: { value, source: 'jiuxin' \| null } }` |
| 原型对应 | 「当前行政区 南山区」卡：产业发展指数 84 / 企业 68 家 / 科研机构 15 家 / 人才 828 人 / 政策 22 条 |
| 分工 | `development_index` / `enterprise_count` / `policy_count` 智树出；`research_org_count` / `talent_count` 智树接口**不返回**（久新提供），智谱页面自久新接口取——本接口出参不含这两字段，避免空占位 |
| 指标挂靠 | 产业发展指数（区级）：**缺**；区级企业数：M_ENT_REGIONAL_COUNT 候选 |
| 既有链路 | Java 已有 `/topic/v1/stats/overview/district-heat`（`enterprise_region_summary`，region_type=district，出区名+企业数）供 enterprise_count；政策走 `policy_sz_dist`（同 API-3）。development_index 无源出空态（先不灌数） |

### API-5 重点企业检索与定位（序号 101 · 搜索要素定位）

| 项 | 内容 |
|---|---|
| 路径 | `POST /key-enterprises/search` |
| 入参 | `{ keyword: string, district?: string, industry_code?: string, page?: number, size?: number }` |
| 出参 | `{ total, records: [{ enterprise_id, name, district, industry_node?: string, lat?: number, lng?: number, type?: string }] }` |
| 原型对应 | 「企业 / 科研机构 8 条结果」列表中企业部分 + 「定位」按钮 |
| 分工 | 科研机构检索由久新提供；本接口只出企业。**坐标裁定（2026-11-06）：智谱前端为 ECharts 地图，`lat/lng` 恒为 null（契约保留字段），定位按 district 行政区名对应**（需规 100-3 点击查看基本信息由 name/type 等字段承载） |
| 指标挂靠 | 非统计指标（列表检索），无 metric_id 要求；企业库 ADS 既有 |
| 既有链路 | **近零成本**。Java 已有 `/enterprise/topic/v1/search/query`（ES `gkx_enterprise`，keyword+district+industry_chain_code 复合检索+分页）可直接转发；`/topic/v1/shenzhen/key-enterprise-list`（重点企业卡片列表）供 type=重点企业子集。**孔东裁定：ES 无企业级坐标，lat/lng 不提供（恒 null），定位走 district 行政区名**——智谱 ECharts 地图按区名定位，不依赖坐标 |

### API-6 产业专题图渲染数据（序号 100 · 产业发展/企业分布/政策支持三图）

| 项 | 内容 |
|---|---|
| 路径 | `POST /thematic-map` |
| 入参 | `{ industry_code: string, theme: 'development' \| 'enterprise' \| 'policy' }` |
| 出参 | `{ values: [{ district: string, value: number, metric_id }], legend: { min, max, unit } }` |
| 原型对应 | 9 行政区 choropleth 渲染值；产业发展图=发展指数、企业分布图=企业数量（原型企业分布图切到「重点企业/科研机构」子层时含点位，点位数据即 API-5） |
| 分工 | `theme=development|enterprise|policy` 智树出；技术/科研/人才三 theme 不在本接口枚举内（久新） |
| 既有链路 | enterprise/policy 两 theme **近零成本**：`district-heat`（区名+企业数）与 `policy_sz_dist`（区名+政策数）直接映射 values[]，**行政区名称匹配即可渲染，无需坐标**（智谱前端 ECharts 地图）。development theme 无源出空态（先不灌数） |

## 4. 空态与降级策略

- 任一指标无数据：字段返回 `null` + `metric_id` 照带，智谱页面渲染空态；不返回伪造数。
- **孔东裁定（2026-11-06）：阶段2 先不灌数。** §3 全部缺口指标（产业规模、人数分布、全口径从业人数、区级发展指数）一律空态上线；数据点亮作为后续独立任务，不阻塞接口交付。
- 地图渲染只依赖**行政区名称**（ECharts 省市区 name 匹配），接口不提供、不依赖任何坐标字段；API-5 定位同样按 district 区名。
- 指标未对齐（D1≠aligned 或缺口未登记）：接口可以出（空态），但 §3 表必须同步登记缺口任务，不得静默。
- 久新部分（技术/人才/科研）：智树接口不返回字段、不出空接口；智谱页面对接久新接口，联调责任在智谱×久新。
