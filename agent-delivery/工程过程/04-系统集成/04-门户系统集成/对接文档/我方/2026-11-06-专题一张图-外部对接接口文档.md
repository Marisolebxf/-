## 1. 接入约定

### 1.1 服务地址与鉴权

- **Base URL**（dev 联调环境，两种入口等价，推荐用 `/api/open/`）：

```
公网/专线网关：https://edu.itic-sci.com/tts/lumen/api/open/topic/v1/portal/one-map
集群内网：    http://gkxlumen-platform-gateway.{namespace}.svc.cluster.local/api/open/topic/v1/portal/one-map
兼容旧入口：  {上述网关}/topic/v1/portal/one-map（与 /api/open/topic/v1/portal/one-map 完全等价）
```

> `/api/open/` 为对外开放接口统一前缀（与本平台对外文档 CMS-JX 约定一致）。公网入口固定带 `/tts/lumen/api` 前缀，叠加后完整 URL 形如 `.../tts/lumen/api/api/open/topic/v1/...`，属预期。

- 网关按 `/topic/**` 前缀路由至 `gkxlumen-topic` 服务；具体 namespace / 环境地址 / 凭证由项目组随对接通知提供。
- 每个请求须携带：

```
Authorization: Bearer {token}
Content-Type: application/json; charset=utf-8
```

- token 由统一用户中心签发，与门户其他 `/topic/**` 接口同 scope；未带 / 无效 token 时网关直接返回 HTTP 401。

### 1.2 通用约定

| 项 | 约定 |
|---|---|
| 请求方法 | 全部 `POST`，请求体 JSON；body 可整体省略，必填业务字段缺失时返回 `code=1`（见 1.4） |
| 路径参数 | **禁止**业务 id 走路径；`industry_code` / `district` / `keyword` / 分页一律在 body |
| 字段命名 | `snake_case` |
| 分页 | `page` 从 1 起；`size` 上限 50（仅 API-5 有分页） |
| 空态语义 | 缺数指标 `value=null` 且 `metric_id` 照带，**不伪造数值**；单块下游故障仅该块出空态，不影响整包 `code=0` |
| 地图渲染 | 前端 ECharts 按深圳**行政区名称**匹配（`district` 字段，含「区」字全名）；接口不提供坐标，`lat/lng` 恒为 `null` 保留字段 |
| 指标追溯 | 每个统计块带 `metric_id`（指标身份证 ID），供双方联调时对口径 |

### 1.3 统一响应信封

```json
{ "code": 0, "msg": null, "data": { } }
```

- 成功：`code=0`，`data` 为业务对象（结构见各接口明细）。
- 业务失败：`code=1`，`msg` 为原因枚举（见 1.4），`data` 不返回。
- HTTP 层异常（401 鉴权 / 404 路由 / 5xx 故障）由网关返回，无上述信封。

### 1.4 错误码

| code | HTTP | 语义 |
|---|---|---|
| 0 | 200 | 成功 |
| 1 | 200 | 业务校验失败（`msg` 为下方原因枚举） |
| — | 401 | 网关鉴权失败（未带 / 无效 token） |
| — | 404 | 路由不存在（联调时先查网关路由与 Nacos `gkxlumen-topic-dev.yml` 前缀配置） |
| — | 5xx | 服务或下游故障 |

`code=1` 的 `msg` 原因枚举：

| msg | 触发接口 | 说明 |
|---|---|---|
| `INDUSTRY_CODE_REQUIRED` | API-1 / 2 / 3 | `industry_code` 缺失 |
| `INDUSTRY_CODE_AND_DISTRICT_REQUIRED` | API-4 | `industry_code` 或 `district` 缺失 |
| `KEYWORD_REQUIRED` | API-5 | `keyword` 缺失 |
| `INDUSTRY_CODE_AND_THEME_REQUIRED` | API-6 | `industry_code` 或 `theme` 缺失 |
| `THEME_INVALID` | API-6 | `theme` 不在枚举内 |

### 1.5 枚举字典

**industry_code**（INB 产业码）。真源为目录接口 `POST {gateway}/topic/v1/meta/industry-clusters`（匿名可查），当前可用枚举：

| 码 | 名称 | 码 | 名称 |
|---|---|---|---|
| INB1303 | 集成电路 | INB1209 | 智能网联汽车 |
| INB1323 | 传感器 | INB1236 | 低空经济 |
| INB1309 | 人工智能 | INB1502 | 数字创意 |
| INB1333 | 智能终端 | INB1204 | 机器人 |
| INB1306 | 软件与信息服务 | INB1354 | 具身智能 |
| INB2503 | 生物医药 | INB2505 | 合成生物 |

> 同一 INB 码可隶属多个产业集群（如「人工智能」同时在新一代信息技术与未来信息），对接时按码等值过滤即可，无需关心集群归属。

**district**（深圳行政区，9 个，全名含「区」字，匹配精确区分大小写与简繁）：

```
福田区 / 罗湖区 / 盐田区 / 南山区 / 宝安区 / 龙岗区 / 龙华区 / 坪山区 / 光明区
```

## 3. 接口明细

### 3.1 产业维度统计（序号 99 · 产业页签）

`POST /industry-stats`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| industry_code | string | 是 | INB 产业码（枚举见 1.5） |

**响应 `data`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| scale | object\<stat_block\> | 是 | 产业规模（亿元）。**当前空态**：`value=null`；`unit="亿元"`；`metric_id=M_ONE_MAP_INDUSTRY_SCALE`，灌数后自动出数 |
| scale_trend | array\<trend_point\> | 是 | 规模历年趋势。**当前恒 `[]`**（随 scale 数据点亮） |
| org_count | object\<stat_block\> | 是 | 企业机构数量（家）= 所选产业最新年企业数；该产业无数据时 `value=null`；`unit="家"`；`metric_id=M_ENT_REGIONAL_COUNT_TOPIC` |
| org_count_trend | array\<trend_point\> | 是 | 历年企业数趋势（2021–2025 等实际年份，`year` 为整数） |

### 3.2 企业指标统计（序号 99 · 企业页签）

`POST /enterprise-stats`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| industry_code | string | 是 | INB 产业码 |

**响应 `data`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| count | object | 是 | 企业数量块：`{ value, unit:"家", metric_id:"M_ENT_SZ_COUNT", trend: array<trend_point> }`；趋势并入块内（同 metric_id） |
| scale_dist | object\<dist_block\> | 是 | 企业规模四桶，label 枚举：`大型 / 中型 / 小型 / 微型`；`metric_id=M_ENT_GAP_03`。空态语义：下游无数据时四桶 `count=0`（非 null） |
| medium_large_ratio | object\<stat_block\> | 是 | 中大型企业占比（%），口径 `(大型+中型)÷四桶合计`，保留一位小数；四桶全 0 时 `value=null`；`unit="%"`；`metric_id=M_ENT_GAP_09` |
| employee_count | object\<stat_block\> | 是 | 企业从业人数（人）。**当前空态**：`value=null`；`unit="人"`；`metric_id=M_ENT_GAP_10` |
| employee_dist | object\<dist_block\> | 是 | 人数四桶，label 枚举：`<50 / 50–199 / 200–499 / ≥500`（单位人）；`metric_id=M_ENT_GAP_03B`。**当前空态**：各桶 `count=null`，桶边界照给 |

### 3.3 政策指标统计（序号 100 政策支持图 + 序号 101 区级政策）

`POST /policy-stats`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| industry_code | string | 是 | INB 产业码 |
| district | string | 否 | 行政区名（枚举见 1.5）；不传 = 全深圳口径，`count` 为全市该产业政策数 |

**响应 `data`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| count | object\<stat_block\> | 是 | 政策数（条）。传 `district` 时为该区口径，否则全深圳；无数据 `value=null`；`unit="条"`；`metric_id=M_POLICY_SZ_DIST` |
| trend | array\<trend_point\> | 是 | 年度发布趋势（`year` 为整数年份） |
| by_district | array | 是 | 九区分布：`[{ district: string, count: integer }]`；无论是否传 `district` 均返回全量九区 |

### 3.4 行政区指标统计（序号 101 · 行政区切换卡）

`POST /district-stats`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| industry_code | string | 是 | INB 产业码 |
| district | string | 是 | 行政区名（枚举见 1.5） |

**响应 `data`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| development_index | object\<stat_block\> | 是 | 区级产业发展指数。**当前空态**：`value=null`；无单位（块内无 `unit` 字段）；`metric_id=M_ONE_MAP_DISTRICT_DEV_INDEX` |
| enterprise_count | object\<stat_block\> | 是 | 该区企业数（家）；该区无数据 `value=null`；`unit="家"`；`metric_id=M_ENT_REGIONAL_COUNT` |
| policy_count | object\<stat_block\> | 是 | 该区政策数（条）；该区无数据 `value=null`；`unit="条"`；`metric_id=M_POLICY_SZ_DIST` |

> 序号 101 原型卡上的「科研机构数 / 人才数」由久新接口提供，本接口**不返回**这两个字段（不出空占位）。

### 3.5 重点企业检索与定位（序号 101 · 搜索定位）

`POST /key-enterprises/search`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| keyword | string | 是 | 关键词（企业名等），前后空白自动去除 |
| district | string | 否 | 行政区过滤（枚举见 1.5） |
| industry_code | string | 否 | INB 产业码过滤 |
| page | integer | 否 | 页码，从 1 起，缺省 1 |
| size | integer | 否 | 页大小 1–50，缺省 10，超 50 截为 50 |

**响应 `data`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| total | integer | 是 | 命中总数 |
| records | array\<enterprise_record\> | 是 | 企业列表。定位方式：取 `district` 区名在 ECharts 地图定位；`lat/lng` 恒 `null`（契约保留字段）；「查看基本信息」由 `name/type/industry_node` 承载 |

> 科研机构检索由久新提供，本接口只出企业。

### 3.6 产业专题图渲染数据（序号 100 · 产业发展 / 企业分布 / 政策支持三图）

`POST /thematic-map`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| industry_code | string | 是 | INB 产业码 |
| theme | string | 是 | 枚举：`development`（产业发展）/ `enterprise`（企业分布）/ `policy`（政策支持） |

**响应 `data`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| values | array\<thematic_row\> | 是 | 九区渲染值，`district` 为区名全名，直接作 ECharts name 匹配。`development`：**当前空态**，九区 `value=null`（区名照给）；`enterprise`：各区企业数；`policy`：各区政策数 |
| legend | object | 是 | `{ min, max, unit }`；`min/max` 为 values 中数值的最小 / 最大值（供分段设色），全空时 `null`；`unit`：`enterprise="家"`、`policy="条"`、`development` 无 `unit` 字段 |

## 4. 数据模型

### 4.stat_block（统计块）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| value | number \| null | 是 | 统计值；空态为 `null`，**不伪造数值** |
| unit | string | 否 | 单位（家 / 条 / % / 人 / 亿元）；无单位指标省略本字段 |
| metric_id | string | 是 | 指标身份证 ID，双方联调对口径用 |

### 4.trend_point（趋势点）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| year | integer | 是 | 年份（2021 等） |
| value | number \| null | 是 | 当年值 |

### 4.dist_block（分布块）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| metric_id | string | 是 |  |
| buckets | array | 是 | `[{ label: string, count: number \| null }]`；label 枚举随接口（见 3.2）；空态时 `count=null` 但桶边界照给；`scale_dist` 下游无数据时 `count=0` |

### 4.enterprise_record（企业记录）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| enterprise_id | string | 否 | 企业 ID（ES 库 org_id） |
| name | string | 否 | 企业名称 |
| district | string | 否 | 行政区名全名；ECharts 定位用 |
| industry_node | string | 否 | 产业链环节描述 |
| type | string | 否 | 企业类型标签 |
| lat | null | 是 | **恒 `null`**（保留字段；定位走 district 区名） |
| lng | null | 是 | **恒 `null`**（同上） |

### 4.thematic_row（专题图行）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| district | string | 是 | 行政区名全名（ECharts name 匹配） |
| value | number \| null | 是 | 渲染值；空态 `null` |
| metric_id | string | 是 |  |

## 5. 联调注意事项

1. **空态不是故障**：`value=null` / 桶 `count=null` / `values` 全 null 且 `code=0` 属正常空态（数据未灌），页面渲染空态样式即可，勿按错误处理。当前空态字段清单：API-1 `scale`/`scale_trend`；API-2 `employee_count`/`employee_dist`；API-4 `development_index`；API-6 `theme=development`。后续灌数点亮后接口契约不变、无需改造。
2. **单块降级**：任一统计块下游故障时仅该块空态，整包仍 `code=0`；请按块级容错渲染。
3. **地图匹配**：`district` 一律用 1.5 节九区全名；接口不提供任何坐标，`lat/lng` 恒 `null`。
4. **分页回显**：API-5 响应只含 `{total, records}`，不回显 `page/size`，请调用方自行维护。
5. **久新边界**：技术 / 人才 / 科研指标（序号 99 对应三页签、序号 100 技术 / 科研机构 / 人才分布三图、序号 101 科研机构检索与卡上科研 / 人才数）不在本组接口，请对接久新文档。
6. **404 排查**：公网路径返回 404 时，先确认网关 `/api/open/topic/**` 别名路由是否已在当前环境发布（`FORCE_NACOS_REPUBLISH=true` 重跑 `helm:chart`），再查 Nacos `gkxlumen-topic-dev.yml` 前缀还原配置（历史坑：网关剥 `/topic` 前缀后服务侧需还原），仍不通联系项目组。
7. **年份口径**：趋势接口返回实际有数据的年份（当前约 2021–2025），不做插值补齐；缺年直接少一行。
