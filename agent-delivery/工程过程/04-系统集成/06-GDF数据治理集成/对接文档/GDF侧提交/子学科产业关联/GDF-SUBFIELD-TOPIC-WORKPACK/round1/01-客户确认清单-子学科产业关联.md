## 4. 退出码：README 写「1=失败」，脚本实际把失败记成成功（**必须修**）

这是本次核对发现的最严重一处。README 的退出码表为 `0=本趟完成 / 1=失败 / 3=缺环境 / 4=表未建`，但脚本实际行为与之相反：

| # | 现象 | 代码位置 | 后果 |
|---|---|---|---|
| **①** | **全部批次失败仍返回 0** | `cmd_link()` 里模型异常被 `except (RuntimeError, ValueError, KeyError)` 捕获 → 只写 `fail_reason` 列 → `stopped=True` → 循环继续 → 全部跑完后正常返回 → 退出码 0 | 模型服务全挂、一整轮一条都没关联上，作业仍显示"成功" |
| **②** | **模型返回空也返回 0** | 模型给出 `links: []` 时该批不写入、不记失败、`stopped` 不变，整轮结束后退出码 0 | 实际零产出而作业显示成功 |
| **③** | **缺 `LLM_API_KEY` 也返回 0** | `_call_model()` 抛 `RuntimeError("LLM API key not configured")`，被同一处捕获吞掉 | 缺环境本应判 3 |
| **④** | **没有轮数上限或软超时** | `cmd_link()` 一次触发跑完全部待关联（现 122 个待关联 / 每批 20 ≈ 7 批，尚可控；但子学科总量增长后同样会撞平台超时） | 撞超时被强杀 → 退出码非 0 → 正常"未跑完"被记为失败 |

### 请按此调整

| 码 | 含义 | 判定 |
|---|---|---|
| `0` | 本趟正常执行完毕（含无待关联、跑满轮数、软超时保护退出、模型返回空但属正常结论） | 成功 |
| `3` | 缺环境（含缺 `LLM_API_KEY`、缺 `SUBFIELD_CATALOG`、试图写 demo 库） | 失败 |
| `4` | 映射表未建 | 失败 |
| `6` | 目录为空（源端无数据） | 失败 |
| `8` | **全链路不可用**：全部批次失败 / 候选集为空 / 模型全部返回空 | 失败（需人介入） |
| `1` | 未捕获异常 | 失败 |

同时请：

- 加 `--max-rounds` / `--deadline-sec`（软超时取平台超时的 80% 左右），**"未跑完"返回 0**；
- 收尾行固定键值对，建议：`linked=… failed=… untouched=… empty_resp=… candidates=… stopped=… batch=…`。**`empty_resp` 请单独计数**——把"模型返回空"埋在失败或跳过里，事后无法从日志判断是哪种情况；
- 补一句重跑语义：`link` 是"插入前删同 subfield 的空关联行"，请确认重复触发不会产生重复关联行。

> 为什么这条最急：调度只看**退出码**和**运行日志**两样东西。退出码把失败当成功，值班就完全失去判断力——数据没产出，作业却是绿的，只能等业务侧发现。
