## 4. `G31` 退出码与调度可判定（blocking）

**请回答**：README 的退出码表写「0=本趟完成 / 1=失败 / 3=缺环境 / 4=表未建」，但**脚本实际行为与之不符，有 4 处需要修**：
① **全部批次失败仍返回 0**——模型调用失败的批次只写 `fail_reason` 列，跑完所有批次后正常返回，退出码 0。作业会显示“成功”，实际一条没关联上；
② **模型返回空也返回 0**——模型给出空结果时该批次不写、不记失败，整轮下来退出码仍是 0；
③ **缺 `LLM_API_KEY` 也返回 0**——缺密钥被当作批次失败吞掉，应判「缺环境」=3；
④ **没有轮数上限或软超时**：`link` 一次触发跑完全部待关联（252 个子学科 / 每批 20 ≈ 13 批），请明确软超时应小于平台超时，且“未跑完”应返回 **0**（下次继续），不要判失败。
改法建议：全批失败或候选为空 → 返回 8（需人介入）；缺密钥/缺目录 → 3；其余一码一因；末行给固定摘要（`linked/failed/untouched/empty_resp/candidates/stopped`）。

**可接受的材料**：退出码表（码/含义/判定 success|failure）；脚本内 return / sys.exit 分支；实跑收尾行样例
**答清的判定标准**：全批失败/模型全空/候选为空返回非 0（建议 8）；缺环境返回 3；一码一因；未跑完返回 0；末行摘要格式固定
**影响范围**：scripts.deliveries[].exitCodes
