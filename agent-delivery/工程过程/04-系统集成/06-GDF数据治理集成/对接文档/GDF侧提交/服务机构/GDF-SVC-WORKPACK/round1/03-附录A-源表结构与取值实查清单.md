# 附录 A · 源表结构与取值实查清单（服务机构）

> 实查日期：2026-11-03 · 方式：平台只读数据源 `EDW_ODS`（库 `gkxlumenx_ods`，平台贴源层，只读）
> 核对口径：`information_schema` · 未写入、未改库

> **来源层说明**：四张 `dwd_org_*` 已由我方贴源产线接入 `gkxlumenx_ods`（Vota 结构 `ODS_DB_CDC`，四实例状态均 **SUBMITTED**，依赖 `SRC_DB.gkx.<表>`）。本附录按**平台贴源层实际列结构**列示（比供应方库多 3 个贴源技术列 `EDW_SRC_SYSTEM` / `EDW_SYS_DATE` / `EDW_DATA_DATE`，该 3 列不进任何目标表）。数据一致性与来源层选择见 `05-附录C` 第二节。

> 行数为 `COUNT(*)` 精确计数（四表 `is_deleted=0` 与总行数相同，即无逻辑删除行）；`information_schema.table_rows` 是估算值，不作依据。
> 四表在 `gkxlumenx_ods` 的列数分别为 **47 / 29 / 23 / 21**（供应方库为 44 / 26 / 20 / 18，差额为 3 个贴源技术列）。

**四张表全部存在**，无缺表。两处需注意：
- `dwd_org_financing_info` 与 `dwd_org_invest_info` **都没有 `id` 列**（只有 `dwd_id`，BIGINT、唯一、非空）；派单包 `04`§3、`08`§3 要求的 `event_id` 取自源 `id`，此条不可执行。**平台 ODS 镜像同样没有 `id`，改读贴源层不改变该事实。**
- `dwd_org_base_info` **没有 `business_scope`（经营范围）与 `district`（区县）** 两列（供应方库与 ODS 镜像都没有）；派单包 `12`§1 的「经营范围」判定与 `09`§3 的「area 回退 district」两支分支不可达。
