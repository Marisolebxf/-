## 4. 退出码：结构基本可用，但 3 处需要调整

现行退出码为 `0=本趟完成 / 1=失败 / 3=缺环境 / 4=表未建`。框架是对的，问题在三处：

### 4.1 `link` 没有轮数上限或软超时 → 必然被平台超时强杀，却被记成失败

`link` 的逻辑是"一次触发连续跑到没有未映射"（每批 20 个技术节点）。按包内声明的约 1.9 万个技术节点计算，**需要约 950 批**，几乎必然先撞上平台侧超时限制。届时进程被强制终止、退出码非 0，调度会记一条**运行失败**——但业务上这只是"没跑完，下次继续"。

**请调整**：加 `--max-rounds` 与 `--deadline-sec`（软超时取平台超时的 80% 左右），并让"跑满轮数上限""软超时保护退出"这两种结局返回 **0**，由下一次调度继续。

### 4.2 退出码 1 混装了多种原因 → 调度无法只凭码判断

现在下列情形全部返回 1：目录为空、向量调用失败、本批没有写入关联、未捕获的异常。请一码一因，建议：

| 码 | 含义 | 判定 |
|---|---|---|
| `0` | 本趟正常执行完毕（含无增量、跑满轮数、软超时退出） | 成功 |
| `3` | 环境变量或依赖缺失 | 失败 |
| `4` | 映射表不存在 | 失败 |
| `6` | 久新目录为空（源端无数据） | 失败 |
| `7` | 向量服务或依赖不可用（这一批不写入，后续保持未映射） | 失败 |
| `8` | 全链路不可用（全部批次失败 / 候选集为空） | 失败 |
| `1` | 未捕获异常 | 失败 |

### 4.3 收尾摘要行键名不统一 → 无法按日志对账

- `sync`：`pages=… inserted=… updated=… failed=…`
- `link`：`processed=… linked_rows=… failed=…`

请统一为固定键值对，并补 `stopped=`（exhausted / max_rounds / deadline）与批次号，例如：

```
done mode=link processed=9500 linked=10420 failed=0 skipped_batches=0 stopped=max_rounds batch=20261117093000
```

> 为什么值得改：调度只看两样东西——**退出码**和**运行日志**。退出码语义错，作业要么天天显示失败（其实跑完了），要么天天显示成功（其实一条没写），值班就失去判断力，日报与告警全部失真。
