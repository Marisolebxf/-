## 本轮关键新发现

1. `node.chain_id` 按 09 填「直接父级码」→ 1,055/1,220 行（86.5%）是节点码，加上 `parent_node_id` 全空，**层级结构丢失**。
2. 边改为「同父兄弟相邻」，913 行数字自洽（1,220 − 307 父组），但真源父子边是 1,055 行。
3. `stage_code` 实为「同级第几个」派生，分布 958/185/77。
4. 上图接口文档**项目仓库内一直有**（`agent-delivery/designs/亿集知识图谱/`），三节齐全、可查；包内只是没给路径
   （客户待改进项）。实质卡点是文档自述**状态查询不实时**
   （不更新 `RUNNING`/终态，需看 Temporal UI），`12` 要求的"轮询到成功或失败"按现实现做不到。
   另 `definition_id`（燕大工作流 ID）仍缺。
5. `industry_embed.py` 默认 `DB_NAME="default"` 且锚点走 demo 闸门，GDF 必须改源码；改漏会 drop demo 集合。
6. **（11-03 复核，已闭环）** `relation_id` 有 82 条超 64 字符（L6/L7）。09 只给 SHA-256 一种方案、
   **未提截取**；实测源库 MySQL 9.7.0 与目标库 8.0.39 的 `SHA2(x,256)` 均返回 **64 字符**，
   913 条边全部唯一、零重复 → 按 `SHA2(concat(...),256)` 实现即可，不阻塞。
7. **（11-03 复核新增）** `script/` 的 `lumen_common` 整包缺失，含 `ok/error`（契约结构来源）
   与 `demo_guard`（硬拒非 demo 库）；`script/README.md` 只列了 2 处要改，实际远不止。
8. **（11-03 好消息）** DDL 与 09 字段逐列对应、零缺失，宽度全部够用（chain_id 64≥21、name 200≥22）。
