## 1. 链树洗不了（核心，`CHAIN-B1-TREE`）

### 派单包怎么写（09 §3.1–3.3）

- 用 `level` 分：`level∈{0,1}` 进 `industry_chain`，`level≥2` 进 `industry_chain_node`
- `industry_link_code` = 自身码，直接做 `chain_id`
- `industry_link_name` = 自身名，做 `chain_name` / `node_name`
- `parent_code` = 父级 INB 码，直写 `parent_chain_id`
- `parent_name` 不映射

### 源库实际（`dwd_industry_chain_info`，1,273 行）

| 列 | 实际是什么 |
|---|---|
| `level` | **全部为 0**，没有 1、也没有 ≥2 |
| `industry_code` | INB 码，互不重复，长度 7→21（越长越深），**这才是主键** |
| `industry_link_code` | **父节点的码**；12 条根链为空串；互不重复的只有 320 个 |
| `industry_link_name` | **父节点名**；根链为空 |
| `parent_code` | **根链的中文名**（机器人 / 集成电路 / 人工智能 … 共 12 个） |
| `parent_name` | **层级序号 0..7**（根链为 0） |

实际树形：12 条根链，最深 8 层；父级用 `industry_link_code` 表达；层级在 `parent_name`。

### 按 09 洗会得到什么

| 09 规则 | 实际后果 |
|---|---|
| `level∈{0,1}` 进链表 | 全部 1,273 行进链表 |
| `chain_id := industry_link_code` | 12 条根链（空码）被丢；剩下 1,261 行只有 320 个不同值 → **撞唯一键**，Upsert 后链表只剩 320 行 |
| `chain_name := industry_link_name` | 这 320 行的名字是「父节点名」，**953 个叶子节点彻底丢失** |
| `parent_chain_id := parent_code` | 写进中文名，不是码；根链行写自己名字 → 自引用 |
| `level≥2` 进节点表 | **节点表 0 行** |
| 树父子边 | 依赖节点表 → **0 行** |
| `level` 派生 `chain_tier`（L0/L1） | 只剩 L0，8 个真实层级压平 |

### 要客户定

1. 分层口径：链是否只有 12 条？L1–L7 是否都算节点？`chain_tier` 用几级？
2. 主键是否改用 `industry_code`（`industry_link_code` 是父级码，撑不起主键）。
3. 名称是否改取 `industry_name`（`industry_link_name` 是父名）。
4. 父级是否填 INB 码（`parent_code` 现在是中文名）。

## 2. 企业挂接缺输入（`CHAIN-B3-ENTITY-REL`）

09 §3.4 要求 `credit_code` → JOIN `enterprise_base` 取 `org_id`，**对不上就丢弃**。

- 源企业主档 `dwd_org_base_info` 抽样 3 万行，**100% 广东省**；
- 链上企业（tags）抽样 5 万行，广东只占约 **15%**，其余是北京 / 浙江 / 山东 / 江苏等；
- 深圳企业抽样 100 家，能在链上找到的 **10 家**。

即：即便 `enterprise_base` 完整继承源企业主档，链上企业最多覆盖 15% 左右，**约 85% 按规则被丢弃**，链上企业数、分布类指标会系统性偏低。

### 要客户定

链上企业是否**只做广东**？若指标要全国，请给全国企业来源；若只做广东，请书面确认丢 85% 可接受。

> 另：tags 的挂点列是单引号列表（`['INB1333']` 这种，不是标准 JSON），其中空列表 `[]` 占 24.9%。
> 09 写的是"JSON 数组"，解析规则需按实际格式改写；空列表要不要丢弃也要明确。

## 3. `12` 后加工落不成 GDF 作业

派单包把这一环节写成「GDF 只保证顺序、不请求、不执行」（`:37`）、「GDF 不得调 rebuild」（`:76`）。
但 GDF 是调度流，每一步必须由它发起并在作业内阻塞拿到结果，包内没给任何可用入口：

| 缺什么 | 包内情况 |
|---|---|
| 上图（`project_graph`）怎么调 | 只有名词（`:15`、`:49`），无方法/路径/请求/返回 |
| rebuild 契约 | 只有路径 `POST /internal/industry/embed/rebuild`，无请求体、无返回字段 |
| `industry_index_version` 从哪取 | 要求回执写（`:38`、`:87`），未说来源 |
| "点数稳定"怎么判 | 只有四个字（`:35`、`:49`） |
| 超时 / 重试 / 幂等 / GDF 调用许可 | 无 |

包内第 4 行指明的两份外部文件（`01-data-flow.md` §9、`CROSS-VEC-长任务总控.md` §0）已核查：
前者只有 rebuild 路径，**上图接口同样没有**；后者两份接口都没提。

### 要客户定

1. 上图动作的完整接口（方法 / 路径 / 请求 / 响应，含写入点数）。
2. rebuild 的请求体与响应体（`index_version` 字段名与格式）。
3. GDF 是否被允许调用（地址、鉴权、网络可达）；若不允许，说明本环节在 GDF 的落点。
4. `industry_index_version` 从哪个字段取，跳过时写什么。
5. "点数稳定"的判定规则。
6. 正式图空间名——包内写 `demo_gkx_chain`，与「禁止 demo 当正式目标」冲突。
