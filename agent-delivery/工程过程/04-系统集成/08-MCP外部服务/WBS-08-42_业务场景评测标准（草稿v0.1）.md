# 业务场景评测标准（草稿 v0.1）——所有 Skill/MCP 通用部分

> 对应 WBS-08-42（负责人：淮政玮，2026-11-12 出草稿讨论）。本草稿由 agent 按 WBS-08-42 起草，供讨论定稿。
> 与 `GKX-12-04_Skill统一评测与验收规范.md` 的关系：GKX-12-04 是对端完整规范（含评分体系、红线、验收等级、三个专属 Skill 指标），**本文件是它的「通用底座 + GKX 落地补充」**，结构对齐淮政玮 11-09 提出的三类指标（业务指标〔通用 + 纯业务〕/ 技术指标 / 用户反馈）。定稿后两者合并为 `ZMATE-SKILL-MCP-EVAL-L01` 的输入。
> 行业参考：LangSmith 三层评测（最终响应 / 单步 / 轨迹）、Langfuse agent 评测维度、Google Cloud 三支柱方法、TRAJECT-Bench 轨迹指标、NIST AI RMF / ISO 42001（GKX-12-04 已引用）。

## 0. 评测原则（先于一切指标）

1. **分层数指标**：一个 Skill/MCP 的评测分四层——MCP 工具层、Skill 流程层、Agent 组合层、业务价值层（同 GKX-12-04 §2）。通用标准覆盖前三层的「通用底座」，纯业务标准按场景附加。
2. **数据边界先于分数**：评测前必须冻结 D0–D3 数据依赖等级与能力边界卡；结果只对声明的数据版本、覆盖范围、关系质量有效（GKX-12-04 §3）。**D2/D3 在总集真实数据接入前最高评 L1 演示可用**。
3. **三类指标结构**（对齐 11-09 口径）：技术指标（工具层，可自动化）+ 业务指标（通用标准 + 纯业务标准）+ 用户反馈（专家盲评 + 采纳）。
4. **期望先行**：每个用例先写「期望结果」再跑；期望未发生 = 红。禁止跑完再定及格线。
5. **对照组不可省**：人工基线 + 通用大模型基线（不接 MCP 只给任务描述），条件一致才可比。

## 1. 通用技术指标（全部 Skill/MCP 必测，可自动化）

工具层，对齐行业 invocation/selection/argument/trajectory 四类指标：

| # | 指标 | 定义与测法 | 通过线 |
|---|---|---|---|
| T1 | 调用必要性准确率 | 该调工具的任务调了、不该调的没调（防止工具滥用/漏用） | ≥90% |
| T2 | 工具选择准确率 | 从候选工具集中选对工具（同名/近似工具是高频错误源） | ≥90% |
| T3 | 参数正确率 | 参数符合 schema 且语义正确（枚举值、时间范围、区域码） | ≥95% |
| T4 | 接口成功率 | 按协议统计的成功调用占比（GKX-12-03 要求三系统 ≥99%） | ≥99% |
| T5 | P95 时延 | 单工具端到端（含网关），按工具类别分档：查询 ≤3s、分析 ≤30s、报告生成 ≤120s | 分档达标 |
| T6 | 错误自愈率 | 遇结构化错误（`isError`）后模型能按错误提示改参重试成功，或正确转人工 | ≥70% |
| T7 | 轨迹效率 | 完成任务的工具调用步数 vs 参考步数；无死循环、无冗余调用 | ≤参考步数 ×1.5 |
| T8 | 重复一致性 | 同输入重复运行 5 次，核心事实/关键结论一致率（GKX-12-04 L4 要求 ≥90%） | ≥85% |
| T9 | 元数据完整率 | 响应含 GKX-12-03 §6 的 9 项元数据且值合法（D2/D3 强制） | 100% |
| T10 | 安全红线自检 | 越权用例 0 通过、注入用例 0 得手、敏感字段 0 泄漏 | 0 违规 |

测试集配比（每 Skill ≥100 用例，同 GKX-12-04 §3）：常规 60 / 边界复杂 20 / 缺失异常 10 / 对抗风险 10；开发集 30% / 验证集 20% / 盲测集 50%。

## 2. 通用业务指标（所有业务场景必须遵循的「通用标准」部分）

适用于所有 Skill 的结果质量底座（纯业务标准在此基础上叠加，见 §3）：

| # | 指标 | 定义 | 通过线 | 先进线 |
|---|---|---|---|---|
| B1 | 事实正确率 | 输出中可核查事实与数据源一致的比例 | ≥95%（报告类 ≥98% 对齐 GKX-12-03） | ≥98% |
| B2 | 计算正确率 | 指标计算、排名、统计与参考实现一致 | ≥98% | ≥99.5% |
| B3 | 引用可回查率 | 引用能定位到来源且与结论对应 | ≥95% | ≥98% |
| B4 | 输出完整率 | 该场景「标准输出」字段（清单 I 列）逐项齐备 | 100% 必需字段 | 100% |
| B5 | 样本限定语合规 | D2/D3 输出全部带数据边界声明，无越界表述 | 100% | — |
| B6 | 降级诚实性 | 数据缺失/冲突时输出「信息不足/待验证/多情景」，0 例编造 | 100% | — |
| B7 | 证据覆盖率 | 关键结论有证据支撑的比例（`evidence` 数组非空且有效） | ≥90% | ≥95% |

**B5/B6 为 GKX 特有强制项**：与评测红线（GKX-12-04 §6）联动——任何一例把 mock/样本结果表述为全量真实结论，直接判不通过。

## 3. 纯业务标准（按场景定制的方法）

每个业务场景在通用底座之上，按以下模板补充专属指标（参考 GKX-12-04 §11 已给出的三个示例：政策对比 / 技术趋势 / 报告溯源）：

```markdown
### 场景：XX（对应 HV-xx，D 等级）
| 指标 | 通过线 | 先进线 |
|---|---|---|
| 〈领域准确性：如抽取 F1 / 分类准确率 / 排名一致性〉 | ≥85% | ≥92% |
| 〈领域召回：如关键差异召回 / 热点 Top-K 召回〉 | ≥75% | ≥85% |
| 〈专家一致率：与专家基准判断一致〉 | ≥80% | ≥90% |
| 〈效率：相对人工基线节省时间〉 | ≥50% | ≥70% |
```

补充规则：
1. 每个场景至少 1 个「领域准确性」+ 1 个「领域召回」+ 1 个「专家一致率」指标；
2. 通过线不得低于 GKX-12-04 §11 同类能力已定线的 90%；
3. 场景专属指标连同测试集在该批启动前冻结，评后不得改线。

## 4. 用户反馈指标

| # | 指标 | 定义 | 通过线 |
|---|---|---|---|
| U1 | 专家盲评可用率 | ≥2 名独立专家盲评（非开发者），意见不合第 3 人裁决；达到「可直接使用/少量修改」占比 | ≥75% |
| U2 | 人工修改量 | 专家把输出改为可用所需编辑幅度 | ≤30% |
| U3 | 采纳率（试点期） | 用户在真实任务中采纳输出的比例 | ≥60%（观测项，首批不设卡） |
| U4 | 评审一致性 | 专家间 Cohen's Kappa | ≥0.70（低于先修评分标准再评） |

## 5. 综合评分与验收等级

- 权重沿用 GKX-12-04 §5：任务完成 20 / 事实计算 20 / 证据可信 15 / 专业判断 15 / 业务可用 10 / 稳定异常 8 / 性能成本 5 / 安全权限 4 / 可运维 3（各 Skill 可调 ≤10pp，建设前冻结）。
- 本草稿 §1–§4 指标按此权重归并：T1–T7 → 任务完成+稳定异常；T8–T10 → 安全权限；B1–B7 → 事实计算+证据可信；U1–U4 → 业务可用。
- 验收等级 L0–L4 及「真实数据接入前 D2/D3 封顶 L1」规则直接沿用 GKX-12-04 §7，不重复。

## 6. 评测执行要求

1. **期望先行**：用例库含期望输出/期望轨迹（gold trace），盲测集答案供应商不可见。
2. **可自动化优先**：T1–T10、B1–B4、B7 尽量代码判定（schema 校验、数值比对、引用存在性检查）；LLM 评审只作辅助，上线前须验证 LLM 评审与人工标签一致性（供应商不得自评）。
3. **回归触发**：模型/提示词/schema/数据版本任一变更即回归；每批交付附回归结论。
4. **持续评测**：上线后按月从真实日志补失败用例，监控错误率、修改量、放弃率、成本漂移。
5. **报告必备**：按 GKX-12-04 §12 清单（版本族谱、数据口径、用例分布、失败样例、红线检查、对照结果、成本耗时、整改计划）。
