# Skill 与 MCP 建设范围公示及确认

## 1. 公示目的

本次公示用于让所有参与建设者共同确认四件事：功能是否真实存在、系统归属是否正确、能力边界是否准确、是否具备MCP化和Skill组合的条件。公示通过后形成建设范围基线。

## 3. 统一能力边界

### 业务系统

负责真实数据和业务功能。建设者需说明当前功能是已完成、需改造、新建还是暂不具备，并提供页面、接口、代码或测试证据。

### MCP

负责把已有功能封装成可调用工具。每个MCP必须明确参数、输出结构、认证权限、超时、错误码、版本和日志。工具不得把未建设能力包装成已具备能力。

### Skill

负责完成业务任务的方法和流程。每个Skill需明确触发条件、步骤、使用的MCP、判断规则、人工确认点、失败处理、证据要求和输出规范。

## 4. 逐项确认事项

每项功能必须回答：

1. 功能名称和系统归属是否准确。
2. 功能当前是否真实存在，有何证据。
3. 输入、输出和不适用范围是什么。
4. 数据来自哪里，覆盖范围、更新频率和质量如何。
5. 是否已有API；没有API时需要怎样改造。
6. 依赖哪些系统、数据、模型或知识图谱。
7. 无数据、数据冲突、超时或权限不足时如何处理。
8. 哪些结论必须人工确认。
9. 能否按统一评测规范提供测试结果。
10. 建议保留、合并、调整、暂缓还是不建设。

## 5. 公示结论状态

| 状态 | 定义 |
| --- | --- |
| 确认建设 | 边界清楚，数据和接口条件基本具备 |
| 调整后建设 | 需要修改名称、边界、输入输出或系统归属 |
| 合并建设 | 与其他能力高度重复，统一为一个Skill/MCP |
| 条件具备后建设 | 依赖数据、接口或底座尚未到位 |
| 暂缓 | 价值或可行性不足，当前批次不投入 |
| 不建设 | 不属于本项目范围或无法形成可验证价值 |
