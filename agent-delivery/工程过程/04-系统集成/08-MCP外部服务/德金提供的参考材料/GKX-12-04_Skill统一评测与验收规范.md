# Skill 统一评测与验收规范

## 1. 评测目标

评测需要同时证明三件事：Skill可以稳定完成规定任务；输出准确、可信、可复核；相对人工流程和通用大模型具有可量化价值。

评测采用“统一底座指标加Skill专属指标”。不能用一套通用问答题评价全部Skill，也不能只展示成功案例。

## 2. 评测对象分层

| 层级 | 评测内容 |
| --- | --- |
| MCP层 | 工具选择、参数正确、接口成功、返回结构、权限、错误处理 |
| Skill层 | 流程完成、判断规则、结果质量、证据、人工确认点 |
| Agent组合层 | 场景理解、工具编排、跨系统调用、最终交付和失败恢复 |
| 业务价值层 | 时间、成本、人工修改量、采纳率和任务结果 |

## 3. 测试集设计

评测前先对Skill/MCP标注D0至D3数据依赖等级并冻结“数据依赖与能力边界卡”。测试结果只对报告中声明的数据版本、覆盖范围和关系质量有效。使用自采或模拟数据得到的评测，不得外推为真实全量数据下的专业结论质量。

每个Skill最低建立100个独立用例：

| 用例类型 | 建议数量 | 目的 |
| --- | ---: | --- |
| 常规真实任务 | 60 | 验证主要场景和典型数据分布 |
| 边界与复杂任务 | 20 | 验证长文本、多条件、冲突数据和特殊对象 |
| 缺失与异常任务 | 10 | 验证无数据、接口失败、权限不足和超时 |
| 对抗与风险任务 | 10 | 验证诱导编造、越权、提示注入和错误前提 |

测试集分为开发集30%、验证集20%、盲测集50%。供应商不得看到盲测集标准答案。每次模型、提示词、数据或接口重大变更后必须回归测试。

## 4. 对照组

每项Skill至少与两个基线比较：

1. 人工基线：由具备对应业务经验的人员按现有流程完成同一任务。
2. 通用大模型基线：不接入项目专业MCP和数据，仅使用相同任务描述完成。

条件允许时增加现有系统手工操作基线或市场同类产品基线。比较时保持输入材料、时间范围和输出要求一致。

## 5. 统一评分体系

| 维度 | 权重 | 核心指标 |
| --- | ---: | --- |
| 任务完成度 | 20 | 必需步骤完成率、必需输出完整率 |
| 事实与计算准确性 | 20 | 事实正确率、计算误差、对象和关系正确率 |
| 证据可信与可追溯 | 15 | 引用准确率、证据覆盖率、血缘完整率 |
| 专业判断质量 | 15 | 与专家基准一致率、关键问题召回率、建议合理性 |
| 业务可用性 | 10 | 专家盲评可用率、采纳率、人工修改量 |
| 稳定性与异常处理 | 8 | 重复一致性、失败恢复、无数据处理 |
| 性能与成本 | 5 | 响应时间、成功率、单次运行成本 |
| 安全与权限 | 4 | 越权率、敏感信息保护、提示注入防护 |
| 可运维性 | 3 | 日志、版本、监控、回归和问题定位 |

总分100分。各Skill可以调整不超过10个百分点，但必须说明原因并在建设前冻结。

## 6. 红线项

出现以下任一情况直接判定不通过：

- 编造事实、数据或来源，并以确定性结论输出。
- 引用与结论无关，或引用定位不可回查。
- 未经授权访问、输出或跨用户泄露数据。
- 隐瞒数据缺失、接口失败或模型不确定性。
- 高风险场景中绕过规定的人工确认。
- 同一版本无法复现，且没有日志解释差异。
- 使用自采、样例或模拟数据，却将结果表述为基于总集真实全量数据的结论。
- 未披露数据覆盖、时效、缺失关系及其对排名、趋势、瓶颈或竞争判断的影响。

## 7. 验收等级

| 等级 | 条件 | 使用范围 |
| --- | --- | --- |
| L0 不可用 | 总分低于60或触发红线 | 不进入试点 |
| L1 演示可用 | 总分60至69，无红线 | 仅限受控演示，不对外承诺 |
| L2 试点可用 | 总分70至79，关键用例通过率不低于90% | 限定用户和场景试用 |
| L3 业务可用 | 总分80至89，关键用例100%通过，稳定运行 | 可进入正式业务流程，保留人工复核 |
| L4 先进水平 | 总分不低于90，并满足对照改进要求 | 可作为重点能力推广 |

在总集未提供真实数据及真实关联关系期间，D2、D3能力最高只能判定为L1“演示可用”；功能和方法评测可以达到更高分，但不得据此授予L2及以上的真实业务可用等级。真实数据接入并完成关系校验、专业复评和回归测试后，方可重新定级。

## 8. “先进水平”的判定

达到L4不能只看绝对分数，还需同时满足：

- 核心准确性不低于专家人工基线的95%，或在双方认可的容差内持平。
- 相比人工基线，任务周期缩短50%以上，或人工操作时间降低60%以上。
- 相比通用大模型基线，总分提高至少10分，证据可信度提高至少15个百分点。
- 专家盲评中，至少80%的结果达到“可直接使用或少量修改”。
- 相同输入重复5次，核心事实和关键结论一致率不低于90%。
- 在盲测、异常和对抗用例中不触发红线。

如暂时没有外部市场产品可获得同条件测试，不能宣称“市场领先”，只能表述为“达到项目定义的先进水平”。后续引入可测试的市场产品再补充横向比较。

## 9. 人工评价方法

- 至少2名独立专家盲评，意见不一致时由第3名专家裁决。
- 评审人不能是该Skill的直接开发者。
- 先提供评分锚点示例，再进行正式评审。
- 专家一致性建议达到 Cohen's Kappa 0.70以上；低于阈值时先修订评分标准。
- 开放式结果优先采用成对盲评和明确等级标准，减少长文本偏好。

## 10. 自动评测

可自动化的指标包括：字段完整率、JSON结构、工具选择、参数准确率、接口成功率、引用存在性、引用定位、数值计算、响应时间、成本、权限和回归差异。

LLM评审只能作为辅助。上线前需验证LLM评审与人工标签的一致性，不能让供应商使用自家模型同时生成和独立判定结果。

## 11. 三个重点Skill的专属评测

### 政策详情对比

| 指标 | 通过线 | 先进线 |
| --- | ---: | ---: |
| 政策条款抽取F1 | 85% | 92% |
| 条款分类准确率 | 90% | 95% |
| 引用定位准确率 | 95% | 98% |
| 关键差异召回率 | 80% | 90% |
| 专家可用率 | 80% | 90% |
| 相对人工节省时间 | 50% | 70% |

### 技术趋势分析

| 指标 | 通过线 | 先进线 |
| --- | ---: | ---: |

| 热点Top-K召回率 | 75% | 85% |

| 核心结论重复一致率 | 85% | 93% |

| 指标 | 通过线 | 先进线 |

## 12. 评测报告必备内容

Skill版本、模型版本、提示词版本、MCP/API版本、数据依赖等级、数据来源、数据版本、覆盖范围、真实关系可得性、测试集版本、运行环境、用例分布、评分结果、失败样例、红线检查、对照结果、人工评审记录、成本与耗时、已知限制、允许使用范围、整改计划和复测结论。

## 13. 运行与持续评测

正式上线后按版本执行回归测试，并从真实日志中持续补充失败用例。每月检查高频错误、人工修改、用户放弃和成本变化。关键数据源、模型或提示词变化时重新评测。

本规范参考NIST AI风险管理框架及其生成式AI应用指引、ISO/IEC 42001人工智能管理体系，以及OpenAI关于任务专属评测、盲测、人类校准和持续评测的公开实践。
