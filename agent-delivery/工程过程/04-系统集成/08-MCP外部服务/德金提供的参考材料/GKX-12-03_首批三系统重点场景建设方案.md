# 首批三系统重点场景建设方案

> 建设周期：2026-11-10至2026-12-10｜12月5日前形成可演示版本｜示例主题：固态电池战略咨询报告

## 1. 建设目标

三家业务系统供应商各建设一个高价值、中低难度的重点场景。三个场景既能单独验收，又能通过MCP接入高端智库报告工作台，形成完整的固态电池战略咨询报告。

## 2. 三个重点场景

| 系统 | 重点场景 | 核心问题 | 纳入能力 |
|---|---|---|---|
| 科技信息展示系统 | 全球—湾区—深圳创新态势与区域对标 | 固态电池全球如何发展，深圳处于什么位置 | HV-01、02、03、21、22、23 |
| 科技专题服务系统 | 技术链、产业链全景与瓶颈定位 | 产业卡在哪里，深圳可以布局哪些环节 | HV-13、14、31 |
| 新型高端智库系统 | 趋势与竞争研判及可信报告生成 | 应形成什么判断、战略和行动建议 | HV-07、08、11、12 |

## 3. 固态电池报告与Skill对应关系

| 报告模块 | 主要Skill/MCP | 系统 |
|---|---|---|
| 全球、湾区、深圳态势 | 科技全域态势、全球/湾区/深圳创新监测 | 展示系统 |
| 区域比较与政策环境 | 科技指数与区域对标、政策详情对比 | 展示系统 |
| 技术路线与关键环节 | 未来产业技术链全景 | 专题系统 |
| 材料、设备、电芯、应用产业链 | 科技产业链全景图 | 专题系统、知识图谱支撑 |
| 良率、成本、材料、设备和标准瓶颈 | 产业瓶颈堵点识别 | 专题系统 |
| 产业阶段、趋势和关键拐点 | 技术趋势分析 | 高端智库 |
| 国家、机构与企业竞争位置 | 国内外竞争格局报告 | 高端智库 |
| 核心观点、情景推演和行动建议 | 战略咨询报告生成 | 高端智库 |
| 事实、指标、图表和文献回查 | 一键报告与引用溯源 | 高端智库 |

## 4. 演示主线

1. 用户提出“深圳应如何布局固态电池产业”的研究任务。
2. 展示系统给出全球、湾区和深圳态势，识别深圳相对位置与政策环境。
3. 专题系统构建技术链和产业链，定位材料、设备、良率、成本与标准瓶颈。
4. 高端智库研判产业阶段、路线格局、竞争位置和商业化窗口。
5. 报告工作台生成正式报告，展示核心观点、反方意见、证伪条件和行动建议。
6. 用户点击任一关键结论，可回查三系统结果、原始数据和引用材料。

## 5. 建设约束

- 第一批可使用已有固态电池离线材料和可核验数据形成受控测试集。
- 第一批总集未提供真实业务数据及真实关联关系，当前结果来自项目组和供应商自采、自建数据；本阶段定位为功能验证和受控演示，不等同于真实生产数据验收。
- 演示数据必须标注来源、时间和覆盖范围，不得宣传为实时全量数据。
- 三系统使用统一的主题、区域、主体和时间口径。
- 各MCP必须返回结构化结果、证据标识、数据版本和异常信息。
- 报告工作台不能直接复制系统页面文本，应调用结构化结论和证据。

## 6. 数据依赖与能力边界管理

所有Skill/MCP按D0方法论型、D1低依赖、D2中依赖、D3高依赖标识。具体定义以《GKX-12-02 Skill四批建设计划》为准。

首批13项能力中，HV-11报告编排以方法论为主，HV-12主要依赖输入材料与引用关系；其余态势、对标、监测、技术链、产业链、瓶颈、趋势和竞争能力均显著依赖数据覆盖、时效或真实关系。界面、MCP返回和最终报告必须同步返回以下元数据：

- `data_dependency_level`：D0至D3依赖等级；
- `data_sources`、`data_version`、`as_of_date`：来源、版本和截止时间；
- `coverage_scope`：地域、主体、时间、数据类型及样本规模；
- `known_gaps`：已知缺失、未验证关系和潜在偏差；
- `confidence`：基于当前数据条件的置信等级及其理由；
- `allowed_use`：可用于演示、研究参考或正式业务的范围；
- `refresh_required`：接入真实数据后是否必须重算、复核和重新评测。

当前统一能力边界如下：

1. 可以证明Skill/MCP接口可调用、处理逻辑可运行、报告流程可贯通、已有证据可回查。
2. 可以输出基于已披露样本的候选趋势、候选瓶颈、主体清单和分析假设。
3. 不承诺样本覆盖完整，不承诺企业、机构、技术和上下游关系与总集真实关系完全一致。
4. 不以当前排名、指数、竞争位置、瓶颈严重程度或战略优先级替代基于真实数据的正式判断。
5. 数据不足或相互冲突时必须降级为“信息不足”“待真实数据验证”或多情景结果，不得生成确定性结论。
6. 总集真实数据接入后，必须执行实体对齐、关系校验、口径重算、结论复核和全量回归测试。

## 7. 供应商分工要求

每家供应商在11月14日前提交：场景负责人、功能边界、MCP清单、接口定义、样例输入输出、数据清单、逐项数据依赖与能力边界卡、开发计划、测试集、降级方案和需要其他供应商配合的事项。

高端智库供应商承担端到端报告编排责任；展示系统和专题系统对各自返回结果的准确性、证据和接口稳定性负责；项目组统一维护报告目录、测试集、评分规则和版本基线。

## 8. 成功标准

- 12月5日前可现场跑通完整流程，不使用人工替换接口结果。
- 12月10日前完成上线、回归测试和阶段验收。
- 报告至少包含态势、区域对标、政策、技术链、产业链、瓶颈、趋势、竞争格局、战略建议和证据清单。
- 关键事实正确率不低于98%，引用准确率不低于95%。
- 三系统调用成功率不低于99%，主流程失败时能返回可解释的部分结果。
- 13项能力全部具有数据依赖标识和机器可读的限制元数据，报告关键结论能够显示其数据范围和置信说明。
- D2、D3能力只按样本内结果验收；总集真实数据未接入前，不得验收或宣传为全量、实时、正式业务结论。
