## 一、两套鉴权并列

| 项 | 段 A · zwrite-backend（v1.1） | 段 B · topic-system（docx） |
|---|---|---|
| 请求头 | `Authorization: Bearer <access_token>` | `X-Portal-Access-Token: <UC_ACCESS_TOKEN>` |
| 凭证来源 | 统一用户中心（门户）`access_token` | 门户 UC `access token` |
| 复用性 | 与门户登录态同源，**两者本质是同一个 UC 令牌，仅传递头名不同** | 同左 |
| 失败表现 | HTTP `401` + body `code=10001` | HTTP **`200`** + body `code=401` |
| UC 不可用 | HTTP `503` + `code=50004`（非令牌问题，退避重试） | body `code=401` + `msg=门户登录凭证无效或已过期` |
| 限流 | HTTP `429` + `code=10004` | 未单列，按 body `code=400` 处理 |

> **关键结论**：两家共用统一用户中心颁发的同一枚 UC 令牌，**不需要申请两套独立凭证**。差异仅在请求头名与失败判定方式。

## 三、续期与失效处理

| 场景 | 判定 | 处置 |
|---|---|---|
| 令牌过期 | 段 A `code=10001` / 段 B body `code=401` + `msg=...过期` | 清除缓存令牌 → 重新向 UC 获取 → **同一请求重试 1 次**；仍失败则返回展示统一错误码 `ZK_AUTH_EXPIRED`，前端提示"请重新登录" |
| UC 暂不可用 | 段 A `code=50004` / 段 B 无对应码，按 `401` 处理 | **不重试业务**，指数退避重试取令牌（建议 3 次 / 1s、2s、4s），超时返回 `ZK_UC_UNAVAILABLE` |
| 限流 | 段 A `code=10004` | 退避 1 次（建议 2s），超时返回 `ZK_RATE_LIMITED` |
| 参数非法 | 段 A `code=10002` / 段 B `code=400` | **不重试**，原样透传 `message`/`msg` 供前端提示 |
| 令牌无权限访问某接口 | 段 B `code=401` + msg 提到凭证无效 | 记录日志（含接口路径，不含令牌），返回 `ZK_AUTH_EXPIRED` |

**令牌缓存约定**：网关侧内存缓存，键为 `uc_token` 的哈希前 8 位（不存明文键），有效期取 UC 返回的 `expires_in`，提前 60s 失效。**禁止**把令牌写入日志、响应体、前端。

## 四、网关双头转发契约（供 D 段 05 号单实现）

```
展示前端  →  展示 Java 网关  →  ┬→ zwrite-backend：Authorization: Bearer <ZK_UC_TOKEN>
                                └→ topic-system  ：X-Portal-Access-Token: <ZK_UC_TOKEN>
```

| 规则 | 内容 |
|---|---|
| 单令牌双头 | 网关只持有一枚 `ZK_UC_TOKEN`，按目标系统自动装配对应请求头名 |
| 路由判定 | 路径前缀 `/admin-api/v1/**` → 段 A；`/topic-system/uc-open-api/v1/portal/**` → 段 B |
| 出站不带用户 token | 前端不直连对端，不自带 token；网关统一注入 |
| 信封规范化 | 段 A `{code,message,data}` / 段 B `{code,success,data,msg}` → 展示标准信封；**对外保留原始 `code` 与 `msg`** 供排查 |
| 超时 | 连接 3s / 读 10s（列表类）；问卷详情、专家分页同 |
| 重试 | 仅对 `50004`、`10004`、UC 取令牌失败重试；**不对** `10001`/`401`/`10002`/`400` 重试 |
| 日志 | 记 `trace_id`、目标系统、路径、耗时、原始 code；**禁记令牌与个人敏感字段** |
