# 门户消息中心 · 消息推送开放接口文档

> 来源：智谱门户消息中心对接文档（飞书 wiki）
> https://zhipu-ai.feishu.cn/wiki/X0rcwvemmiqS28kjthPcjVylnCe
> 落盘日期：2026-11-04
> 展示系统凭证：`systemCode=TECH_INFO_DISPLAY` / `systemName=科技信息展示系统`（`systemSecret` 属敏感信息，**不入库**，见对端 README 铁律）

## 1. 接入约定

### 1.1 请求地址

| 环境 | 完整地址 |
| --- | --- |
| 测试环境 | `https://edu.itic-sci.com/portal/zp/api/open/messaging/topics/{topic}/messages?key=<分区键>` |
| 生产环境 | `https://<门户网关域名>/api/open/messaging/topics/{topic}/messages?key=<分区键>` |

- 方法：`POST`
- 路径参数：`{topic}` 消息主题（见 §2 白名单）
- 查询参数：`key` 分区键（见 §2，不同 topic 取不同字段）
- `Content-Type: application/json`

### 1.2 鉴权（请求头）

消息中心为系统级开放接口，**不走 OAuth2 Bearer**，通过两个自定义请求头鉴权：

| 请求头 | 值 |
| --- | --- |
| `X-System-Code` | `TECH_INFO_DISPLAY`（系统编码，门户侧分配） |
| `X-System-Secret` | 系统密钥（门户侧分配，敏感，不入库） |

报文体中的 `systemCode` 必须与请求头 `X-System-Code` **一致**，否则返回 `221006`。

### 1.3 通用约束

- 请求体大小上限 **512KB**（超限返回 `221004`）。
- `messageId` 必须以 `<系统编码>-` 为前缀（如 `TECH_INFO_DISPLAY-xxx`），门户按 `messageId` 去重；同一条消息发给多个接收人时，**每个接收人独立生成 messageId**。
- `sendTime` 为 epoch **毫秒**时间戳。

## 2. Topic 白名单与分区键

| topic | 用途 | `key`（分区键） |
| --- | --- | --- |
| `portal_notice_msg` | 通知消息 | `data.businessId`（不传时用 `messageId` 兜底） |
| `portal_todo_msg` | 待办消息 | `data.ticketNo` |

topic 不在白名单时返回 `221001`。

## 3. 通知报文 `portal_notice_msg`

| 字段 | 类型 | 必填 | 校验 / 说明 |
| --- | --- | --- | --- |
| `version` | string | 否 | 建议 `1.0` |
| `messageId` | string | 是 | `<系统编码>-` 前缀 + UUID；门户按它去重 |
| `systemCode` | string | 是 | 必须与请求头 `X-System-Code` 一致 |
| `systemName` | string | 否 | 系统名称，门户展示用 |
| `msgCategory` | string | 是 | 固定 `NOTIFY` |
| `receiverId` | string | 是 | 接收人用户 ID（统一用户中心） |
| `sendTime` | number | 是 | epoch 毫秒 |
| `data.title` | string | 是 | 最长 256 |
| `data.content` | string | 否 | 正文 |
| `data.linkUrl` | string | 否 | 最长 512 |
| `data.linkText` | string | 否 | 链接文案 |
| `data.linkDesc` | string | 否 | 链接描述 |
| `data.tags` | string[] | 否 | 标签列表 |
| `data.businessId` | string | 否 | 业务 ID，作为分区键 |

## 4. 待办报文 `portal_todo_msg`

| 字段 | 类型 | 必填 | 校验 / 说明 |
| --- | --- | --- | --- |
| `version` | string | 否 | 建议 `1.0` |
| `messageId` | string | 是 | `<系统编码>-` 前缀 + UUID |
| `systemCode` | string | 是 | 必须与请求头 `X-System-Code` 一致 |
| `msgCategory` | string | 是 | 固定 `TODO` |
| `receiverId` | string | 是 | 接收人用户 ID |
| `sendTime` | number | 是 | epoch 毫秒 |
| `data.ticketNo` | string | 是 | 最长 64；格式 `TK_<系统代码>_<yyyyMMdd><4位流水>`，作为分区键 |
| `data.title` | string | 是 | 最长 256 |
| `data.status` | string | 是 | `PENDING`（待处理）/ `PROCESSED`（已处理） |
| `data.submitTime` | number | 否 | epoch 毫秒 |
| `data.submitContent` | string | 否 | 提交内容 |
| `data.handleUrl` | string | 否 | 处理跳转链接，最长 512 |

## 5. 统一响应

成功（`code=0`）：

```json
{
  "code": 0,
  "message": "success",
  "data": { "topic": "portal_notice_msg", "key": "xxx", "partition": 0, "offset": 123 },
  "traceId": "xxx"
}
```

失败（`code != 0`），`message` 为原因，`traceId` 便于排查。

## 6. 错误码一览

| code | HTTP | 含义 | 处理建议 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | — |
| 221001 | 400 | topic 不在白名单 | 检查 topic 拼写 |
| 221003 | 400 | 请求体不是合法 JSON | 检查序列化 |
| 221004 | 400 | 请求体超过 512KB | 缩减报文 |
| 221005 | 400 | 预校验失败 | 检查必填/长度/格式 |
| 221006 | 400 | systemCode 与请求头不一致 | 对齐 systemCode |
| 221007 | 400 | messageId 前缀不符 | 加 `<系统编码>-` 前缀 |
| 101001 | 400 | 参数不合法 | 检查参数 |
| 224001 | 401 | 凭证无效 | 检查 systemSecret / 系统编码 |
| 225001 | 503 | 队列投递失败 | **可安全重试**（同 messageId 去重，不重复） |
| 109001 | 500 | 内部错误 | 重试或告警 |
