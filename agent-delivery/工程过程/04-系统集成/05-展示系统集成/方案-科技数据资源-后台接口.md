## 1. 架构签收条件

签收本方案的条件是**按稿可以落地**。这是 `architecture-baseline.md` **D18**（2026-11-03）的原话，也是本方案的验收条件：

真查做得到的，接口读真实查询结果。真查做不到的，只接受一种替代：

1. 新建 ADS 表。
2. 由 Python 把 mock 行写入该表。
3. Java 接口只读该表，再组装成前端数据集。

不允许 Java 或 Python 在接口里直接返回写死的 mock JSON、常量列表或内存 fixture。不允许前端用 fixture 充当该接口的返回。这种表不建在 ODS、DWD、供应方库。表名以 `gapfill_` 开头（2026-11-03 口令）。读到 mock 表的数，D4 仍是 mock，界面保留 MockBadge。

表名、灌数方、读取接口，三样缺一，本方案不能签收。具体灌哪些行，由 data-agent 在后续灌数任务里执行。本方案只定表和任务槽，不灌数。

组装允许做的只有：按行汇总、算占比、算同比、把行收成前端已有的数组或对象。算出的数必须能从当次读到的行还原。颜色、名称、涨跌方向写在行上，不写在 Java 常量里。

## 3. 调用链

```text
页面 fetchDataResources*
  → request()（@/utils/request，与态势相同）
  → 网关 {VITE_APP_BASE_API}/display/v1/data-ops/{overview|access|theme|application}/dataset
  → gkxlumen-display  /v1/data-ops/.../dataset
  → 展示侧 Java 只 SELECT，组装成 Dataset
       → 久新只读：仅 entityStock、columnCatalog
       → demo_gkxlumenx_ads：本方案的新表，表名以 gapfill_ 开头
```

`gkxlumen-display` 不直连数据库（D15）。Java 不写这些表（D3）。Python 写表，Java 读表（D7、D18）。前端不直连久新，也不直连 ADS。

库只使用验收库 `demo_gkxlumenx_ads`。不写正式库 `gkxlumenx_ads`，不写 ODS、DWD、久新库，也不写入库 `gkxlumenx_gapfill`。D16 把 `gapfill_` 定在那个缺项库、不进 ADS；D18 写明这类 mock 表不算缺项表。本次口令改的是表名，库仍用验收 ADS。基线那两句要另改才算闭合。

行上的批次号：

| 前缀 | 含义 |
|---|---|
| `snap_` | Python 从久新查询写入的快照。查询失败就失败，禁止改成手填数字 |
| `mock_` | 为满足需规而造的行。D4 = mock，页面带 MockBadge |

Java 若暂时连不上久新，`entityStock` 和 `columnCatalog` 改读 `snap_` 批次。这仍是快照，不是 mock。连不上时这两个键的 `origin=snap`，其余键不变。

## 5. 对接前端的四个接口

对外只有这四个 GET。没有查询参数。筛选、导出、分页都在浏览器里对整包做。不要再提供 `/sources`、`/themes`、`/usage` 这类资源路径，现有四页不会调。

| 方法与路径 | 响应 `data` 的类型 | 页面 |
|---|---|---|
| `GET /display/v1/data-ops/overview/dataset` | `DataResourcesOverviewDataset` | 总体视窗 |
| `GET /display/v1/data-ops/access/dataset` | `DataResourcesAccessDataset` | 接入视窗 |
| `GET /display/v1/data-ops/theme/dataset` | `DataResourcesThemeDataset` | 主题视窗 |
| `GET /display/v1/data-ops/application/dataset` | `DataResourcesApplicationDataset` | 应用视窗 |

网关前缀与态势相同：浏览器实际请求 `{VITE_APP_BASE_API}/display/v1/data-ops/...`，展示服务上的映射是 `/v1/data-ops/...`。

HTTP 体是 PigX 信封，不是数据集本身：

```json
{ "code": 0, "msg": "ok", "data": { } }
```

`code` 为 `0` 时，`data` 才是数据集。这与 `src/utils/request.ts` 的拆包一致。空库也返回 `code=0`：数组为 `[]`，数字为 `0`，对象键仍在。不要用 404 表示没数据。

键名与 `src/types/dataResources.ts` 一致，缺一个键页面就会空图表。允许多出 `origin`、`entityStock`、`columnCatalog`。不允许少键，也不允许改键名。

每个统计块带 `origin`，取值 `jiuxin`、`snap`、`mock`。KPI 写在元素上，并保留已有的 `key`。列表写在行上。整块 mock 的对象写在对象根上。页面按 `origin=mock` 挂 MockBadge。现有组件还不读这个字段，由接线任务补上，不改键名。

应用页「实时监控」不另开接口。它用本响应里的 `usageCallTrend` 在浏览器里按秒跳动。`gapfill_dr_api_probe` 只填 `resourceUsageStats` 和 `interfaceStatusMetrics`，不制造当前时刻的告警。

主题页顶部四张卡的涨跌写在 `theme/index.vue` 里，接口只给 `themeDatabaseCount`、`tableCount`、`recordCountLabel`、`storageLabel`。`recordCountLabel`、`storageLabel` 是纯数字字符串（如 `10.2`、`18.6`），单位「亿条」「TB」在页面上。
