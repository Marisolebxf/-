## 2. 核心问题：载体名怎么跟系统 ID 结合

载体名录天然无我方主键，必须建**三层 ID**，各自职责与可信度不同：

```
carrier_id（载体主键）
   ├── institution_id（我方机构，可空）
   └── district_location_id（区级位置，可空/推断）
```

### 2.1 `carrier_id`：用「名称+公告+年份」做稳定指纹

- 规则：`eco_carrier_` + `md5(载体名称|公告名称|立项年份)[:16]`
- 理由：政府名单无官方唯一码；同一载体跨年度重复公告用「名称+依托单位」去重，保留 `carrier_level` 最高者（国家级 > 省级 > 市级）。
- 同时原样保留 `org_id`、`social_credit_code`、`source_url`、`publish_org`、`publish_date` 作溯源列——**任何页面展示都能回到公告原文**。

### 2.2 `institution_id`：三级匹配，未命中就留空（不猜）

| 优先级 | 规则 | 预期 |
|---|---|---|
| 1 | 统一社会信用代码 ↔ 机构库信用代码 | 若 `ads_institution_profile` 无该列需数据组确认；有则最强 |
| 2 | 依托单位名规范化（去括号后缀、「有限公司/股份」变体）后精确匹配 | 实测约 20/296（6.8%） |
| 3 | 别名映射表（人工/AI 辅助，落 `ads_eco_carrier_org_map`） | 逐批追加，先覆盖深圳 Top50 依托单位 |
| — | 未命中 | `institution_id=NULL`、`match_status='UNMATCHED'`，页面显示「暂无关联机构数据」，**不补 0 不编造** |

> 这是「A 级数据 vs B 级数据」的分水岭：只有匹配上的载体才能带论文/专利/人才数，其余列留「—」。

### 2.3 `district_location_id`：官方优先，推断必标注

名录只有市级区划码，区级归属按优先级补，**每行留 `district_source`**：

| 优先级 | 来源 | 可覆盖率（估） | `district_source` |
|---|---|---|---|
| 1 | 市级/区级公告原文（按区发布的批次） | 深圳市科创局名单按区抓 | `ANNOUNCEMENT` |
| 2 | 依托单位地址所在区（机构库 `district_name`） | 20 家已匹配机构可定 | `ORG_ADDRESS` |
| 3 | 载体名/地址关键词 + 大模型推断（你提的「丢给豆包补齐」） | 兜底 | `INFERRED` |
| 4 | 人工核对 | 演示关键点位 | `MANUAL` |

**红线**：①`INFERRED` 不得在页面写成官方认定；② 页面统一口径「区级归属为辅助推断，供检索定位，不作为认定结果」；③ 区归属不明进「未分区」桶，不硬塞进某个区。

久新 `ads_location` 已有 9 个区（南山/福田/罗湖/宝安/龙岗/盐田/龙华/坪山/光明），**缺前海、大鹏**——需规要求「8 区 + 前海」，建议前海按「南山区·前海」合并展示，避免动公共字典。

### 方案 A（正规，依赖数据组）

```sql
CREATE TABLE ads_innovation_carrier (
  carrier_id            VARCHAR(48)  NOT NULL,      -- eco_carrier_<md5>
  carrier_name          VARCHAR(256) NOT NULL,
  carrier_type          VARCHAR(64),                -- 重点实验室/工程研究中心/科技企业孵化器…
  carrier_layer         VARCHAR(16),                -- innovation | incubation（派生）
  carrier_level         VARCHAR(32),                -- 国家级/省级/地方(城市)级
  approve_year          SMALLINT,
  publish_org           VARCHAR(128),
  publish_date          DATE,
  announcement          VARCHAR(512),
  area_name             VARCHAR(64),
  area_code             VARCHAR(24),
  district_location_id  VARCHAR(64),                -- 关联 ads_location DISTRICT
  district_source       VARCHAR(16),                -- ANNOUNCEMENT/ORG_ADDRESS/INFERRED/MANUAL
  institution_id        VARCHAR(64),                -- 关联 ads_institution_profile
  org_name_raw          VARCHAR(256),
  social_credit_code    VARCHAR(32),
  org_id_src            VARCHAR(64),                -- 前海 org_id
  match_status          VARCHAR(16),                -- MATCHED/UNMATCHED
  source_url            VARCHAR(512),
  first_seen            DATE,

  PRIMARY KEY (carrier_id)
);
```

## 7. 红线与风险

1. **不伪造坐标**：区级聚合是口径；单点必须 geocoding 且标注推断；
2. **不伪造区归属**：`INFERRED` 必须带标记并在页面声明；
3. **不伪造多媒体**：图片/视频/新闻全空态，不互相替代；
4. **不补 0**：未匹配机构的企业数/专利/人才留「—」，给覆盖数；
5. **563 模拟调用不作证据**：接口目录固定声明「前端演示目录」；
6. **数据源标注**：页面固定脚注（来源域名 + 取得日期 + 记录数），任何数字可回溯到公告；
7. **久新只读**：本轮不写久新库；方案 A 的 DDL/ETL 由数据组执行，我方只提供脚本与校验 SQL。
