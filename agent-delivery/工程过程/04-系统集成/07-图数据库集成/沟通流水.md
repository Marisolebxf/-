展示系统原型宣讲后，燕大反馈图查询接口文档：[图查询接口](https://zhipu-ai.feishu.cn/docx/OGSTdtI5notjzdx0ZKKc5z8an4f)，并提供测试凭据（`client_id` / `api_key`）。

**凭据处理**：按仓内铁律「口令不进 git」，凭据**不写入本仓**；已通过安全通道持有。

### 该版接口要点（我方已读）

| 端点 | 用途 |
|---|---|
| `GET /schema` | 返回全部生效的实体类型与关系类型定义（类型编码、显示名、属性清单、关系端点 `sourceType`/`targetType`），附参考计数 |
| `GET /entity-types/{name}/entities` | 按实体类型分页枚举实体，返回完整属性；**只返回点，不返回边** |
| `GET /relation-types/{name}/edges` | 按关系类型分页枚举边，`includeEntities=true` 时附带两端实体 |

关键约定：

- 外层响应壳 `code` / `success` / `data` / `msg`，`data` 内含生效 `space`
- `id` 为原样使用的 VID，**不要从中解析业务信息**；`types` 保留全部标签，`name` 优先取属性 `name`，其次 `title`
- 关系 `id` 是服务端返回的完整标识（`["类型","source","target",rank]`），**调用方原样保存，不要自行拼接**；去重键为 `(type, source, target, rank)`
- `source` → `target` **始终为存储方向**，入向查询不会反转；悬挂边返回 `null`，**不伪造实体**
- 分页：`cursor` 翻页为主（绑定空间/接口/类型，换类型须从头开始），`offset` 为旧兼容参数；`hasMore` 是翻页结束的唯一依据，**不要用 `total` 判断**（`total` 是 SHOW STATS 快照，约 300 秒缓存，`countIsEstimate` 恒为 true）
- 认证 Header：`X-Client-Id` / `X-API-Key`；权限 `kg-open:read`
- 错误码：422 参数校验（HTTP 200 包装）、400 非法类型名/无效游标、401 凭据问题、403 权限或空间门禁、404 类型不存在、429 队列满（`Retry-After: 1`）、502 图服务失败、503 认证库/目录库/索引未就绪。**不对 400/401/403/404 盲目重试**

**对我方需求清单的影响**：该版已含 `Paper` 实体（示例中约 92,000 条）与 `AUTHORED_BY`、`CITED_BY`、`ACTUAL_CONTROLLER_OF` 等关系，可用于回答 Q-KG03（paper 是否独立节点）——**倾向已是独立节点**，需燕大书面确认。

### 图谱构建规则共识

- 抽取：自研 Python 脚本 + 大模型；**高置信度直接入库、低置信度人工审核**
- 政策抽取：本次仅涉及 1 份政策文档，需 Python 脚本结合大模型完成要素提取
- 实体消歧：测试阶段由燕大统一审核，无法确定的交业务方；线上数据量增大后再调机制
- 数据来源：抽取自总集 MySQL 势力数据库，补充部分产业链数据；**政策类关联关系不足待核对**

### 存储方案共识

多跳关联查询存图谱性能更优；单点少量查询可直接存普通数据库。图谱展示效果更直观。

### 业务需求要点

- 四大模块：分析展示、指标展示、算法展示、服务展示
- 子图族为**固定查询条件的卡片包装**，点击携带条件进入图谱页面，**并非子图存储功能**
- 视图：列表、网络两类；存在节点过多加载问题；实体活跃度倾向用实体自身属性而非用户访问数据判定
- 合规：需满足 9 个图谱接口能力要求（专家人才职业关系、科技产业链等图谱推理服务）
- 图谱维护需支持节点与关系增删改查 + 修改历史；**删除需配套审批机制**
- 风险处理：专家规则 + 黑名单规则识别，触发删除、拦截检索，支持历史审计与主体通知
