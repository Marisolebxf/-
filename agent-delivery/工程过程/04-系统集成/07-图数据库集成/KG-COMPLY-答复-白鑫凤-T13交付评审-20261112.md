## 五、附：开工前六条坑（保留备查，多数你已避开）

### 5.1 对账模板必须写进「分组铁律四条」——这是全手册最核心的部分

这批数据最大的坑是：**一个边型里装着好几条不同的业务关系**。不分组对账，总数永远对不上。四条必须逐条写：

**① `cooperate` 一个边型装了四条关系，必须四行分组**

| 端点 | 对应关系 | 条数 |
|---|---|---:|
| `person`→`person` | M01 人才合作 | 2,525,789 |
| `research`→`research` | M02 机构合作 | 3,442,271 |
| `person`→`research` | M03 | 0 |
| `enterprise`→`enterprise` | M22 企业合作 | 94,824 |

**合计 6,062,884 不能当任何一条关系的成果。** 这是已经发生过误报的地方（有同事拿全表合计当成某一项，导致对账显示 ❌）。

**② `participates` 要分三层**

| 端点 | 归属 | 条数 |
|---|---|---:|
| `enterprise`→`segment` | M17 | 178,731 |
| `institution`→`segment` | M18 | 0 |
| `institution`→`institution` | **不属 M17 也不属 M18** | 34,769 |

第三层这 34,769 条**不能塞进 M17 或 M18**，必须单列。

**③ `participate`（单数）和 `participates`（复数）是两个不同边型**，只差一个 `s`：

- `participate` → M07 / M08（科研机构参与项目）
- `participates` → M17 / M18（企业归属产业链环节）

写手册时务必把这两个名字标出来，这是最容易手滑的地方。

**④ `cite` 一个边型覆盖两条关系**（M06 论文→论文、M16 论文→专利），当前都是 0。将来若只建了其中一条，必须按端点拆开核。

### 5.2 批号筛选一律用 `CONTAINS`，不要用 `STARTS WITH`

这个坑已经实际踩过：T02 的 `props` 里 `batch` **不在 JSON 首位**，照抄 T03 的 `STARTS WITH '{"batch"...'` 写法会返回 **0 条**（看起来像「没灌进去」，其实是查法错了）。

**手册里统一写**：

```
e.props CONTAINS "comply-20261111-t02"
```

**不要写**：

```
e.props STARTS WITH '{"batch":"...'
```

### 5.3 T06 四项裁定要写进参数表与对账模板

T06 今天刚签收，四项裁定会直接影响手册能不能用：

| 项 | 手册要怎么写 |
|---|---|
| `apply_to` vs `support` | 两条边端点 100% 重合，但权重分别恒为 **0.6** / **0.8**（每条边全图就一个常数，**不是强度**）。手册写「**停读 `support`、单读 `apply_to`**，权重不作强度用」 |
| `institution`→`institution` 34,769 | 本期**不改名**；`service_relate` 只是正式线将来可能用的备选名；**不得映射** M02 / M19 / M17 / M18 |
| `belongs_to` 359 | 覆盖 359 / 1,414 个环节，未挂链 1,055 个。属**结构归属**，不映射 M01–M24，**缺口本期不补**。注意：1,055 是「没挂链的环节数」，**不是「可以补 1,055 条边」** |
| `apply_to` 不记 M12–M14 | 只作「政策适用范围」参照边 |

### 5.4 M08 / M09 的 `weight` 恒为 1.0

若手册里写加权步骤，必须注明这两条**没有强度信息**。不能拿 `Σweight` 当业务量（现在算出来就等于条数，会被误读成「每条关系都是 1 分强度」）。

### 5.5 「换 space 名就能跑」这句要改口径

T11 今天实测：**正式线 `gkx_chain` 目前根本不存在**——`SHOW SPACES` 只返回 `demo_gkx_chain`。这跟架构基线的说法一致（有意不建正式名）。

所以手册**不要**写成「现在换个 space 名就能跑」，而要写成：

> 正式线空间建成后，换 `space` 名 + 按 T11 对照清单补齐 9 个 Tag / 24 条边，方可复跑。

这样既满足 DoD（写清「换 space 名即可复跑到 gkx_chain」的路径），又不会让人误解成现在就能跑。

### 5.6 复跑步骤必须写「Tag 锚定 + 分批 LIMIT」

图库 `10.50.75.136:9669` 已经触发**内存高水位**（`Used memory hits the high watermark(0.800000)`）：

- 按 Tag 锚定的查询正常（1–30 秒）；
- **无锚定的全表扫描基本失效**，大聚合会被拒（`sum(e.weight)` 跑了 518 秒后被拒）。

所以手册里所有取数示例都要写成「按端点 Tag 锚定 + `LIMIT` 分批」，**不要写全表扫描**。否则别人照着跑会卡死，然后来问你「手册是错的」。
