## 三、根因判读：认同

你写的根因是「`inner` 是社群内有向邻居计数（本身 = 2E），原式 `2 × inner ÷ N` 算成 4E/N」。
我对着改后的脚本读了，三处都对：

```python
inner   += 1                    # 有向计数，合计 = 2E
inner_e  = inner // 2           # 无向边数 E
"avg_deg" = round(inner / len(members), 2)                        # = 2E/N
"density" = round(2 * inner_e / (len(members)*(len(members)-1)), 6)  # = 2E/(N(N-1))
```

这与验收推测的「networkx 无向图双向边未去重」同源，判读一致，无需再解释。

## 四、一处以后要注意（不返工）

`inner_e = inner // 2` 隐含「所有邻接都双向成对」。当前技术点层确实是双向的
（社群 55 `inner` = 9,970，偶数；若存在单向边，全局 `inner` 的奇偶会暴露出来），所以本批数据不受影响。

但**将来若允许单向 `tech_rel`**，`inner // 2` 会把单向边按半条计，E 会偏小、密度跟着偏小。
建议改成按无序点对去重：

```python
pairs = set()
for u in members:
    for v in adj[u]:
        if v in members and u != v:
            pairs.add((u, v) if u < v else (v, u))
E = len(pairs)
```

这条只写进备注，不影响本次结案，也不用改表。
