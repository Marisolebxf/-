## 三、三项裁定

### 3.1 `support` 停读 + 权重口径 → **同意停读，权重一律不用**

| 项 | 裁定 |
|---|---|
| 读哪条 | **只读 `apply_to`**，`support` 保留存量、不再双读 |
| 删 / 改名 / 迁移 | **都不做** |
| 权重怎么处理 | **0.6 和 0.8 都不当强度**：不相加、不取最大、不回写、不暴露为强度 |
| 能否记 M12–M14 | **不能**，只作政策适用范围参照 |
| 旧文档 | 11-07 裁定里「M02/M19 均为 0」「weight / props 为空」作废 |

**这里我要往回改一句我自己说过的话。** 我 15:10 给你的开局事实里说「100% 重合、不存在需要保留的独有子集」——**端点层面这句是对的，但我漏了 weight**。你把它补出来了，这个补充是本次报告最有价值的部分。

但你留「权重口径待裁定」我觉得**可以再往前走一步**：你实测的取值集合是 `apply_to = {0.6}`、`support = {0.8}`——**每条边全量只有一个常数**。

一个「全边型唯一值」的字段，**不可能承载逐边的强度信息**。所以：

- 10,957 / 10,957「weight 不同」不是 10,957 个强度差异，而是**同一个常数从 0.6 变成 0.8**；
- 它更像是两个装载器各自的默认值，不是业务强度；
- 因此**它不构成「两条边语义不同」的理由**，也不改变「停读一条」的结论。

**你要知道的一点**：这类「常数字段当强度」的坑不止这一处——M08 `participate` / M09 `author_of` 的 weight **恒为 1.0**，T10 那边 `relation_confidence_score` 也是。整张图的 weight 大部分是占位常数，谁把它当排序依据谁就得出假结论。

**给下游的一句话**：政策边读 `apply_to`、读端点、**不读权重**。接口若非要暴露 weight，必须写「常数占位、非强度」，否则前端早晚拿它做粗细渲染。
