## 算法口径及待确认事项

图按技术点关系构建无向图，同一无向端点对多条证据时取最大置信度。本次实测重复数为 0。

代价使用 `1 / e.relation_confidence_score`。这是本批明确采用的公式。旧材料只给出置信度字段和算法名称，未发布代价转换公式，因此本批结果保留方法差异，供唐绍祖确认。读取字段使用 `e.relation_confidence_score`。

BFS 求最少跳数，Dijkstra 求最小累计代价。5 条备选路径使用无权最短简单路径枚举。不可达返回 `status=empty`；基线端点缺失、悬空边或仅平局换路都会进入复核，权重异常终止计算。

11 月 7 日 Markdown 写了 4 对加权跳数更大，其 JSON 实际为 3 对，分别是第 2、7、9 对。本批这三对的 Dijkstra 跳数与旧 JSON 不同。全部 BFS 跳数与旧 JSON 一致。旧 JSON 没有加权路径序列、总代价和公式，故本批无法证明与旧加权实现完全等价。

脚本质量检查结果为通过，业务算法口径及任务签收待负责人确认。
