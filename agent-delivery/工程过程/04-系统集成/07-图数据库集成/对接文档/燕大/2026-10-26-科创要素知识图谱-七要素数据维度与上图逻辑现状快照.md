## 一、范围与口径

### 1.1 目的

按科创**七要素**（产业 / 企业 / 技术（论文）/ 人才 / 科研机构 / 政策 / 服务机构）说明当前图谱已支持的数据维度（实体 ← 哪张源表 ← 哪些字段）与上图逻辑（关系起终点字段  非直连时的分析逻辑  统一抽取链路）。

### 1.3 口径说明

1. **现状基准**：图空间 `gkx_local_1` / `gkx_full_1` 的平台 Schema 注册目录（17 实体 TAG  33 关系 EDGE  46 脚本  867 属性  155 来源绑定，实测导出）。
2. **字段口径**：第二/三章「数据表字段名」列 = 抽取脚本**实际取数的源表列**（对脚本做 AST 提取 `row.get`/规格列得到）；DWD 适配为同构映射，图属性与源列同名，个别派生列以括注说明。全部实体另附 15 条平台公共治理列（id/name/createtime/updatetime/vid  溯源组 sourcesystem、sourcetable、sourcerecordid、sourceurl、ingestbatch、ingesttime、sourceupdatetime、confidence、matchmethod、matchevidence），正文不再重复。
3. **机构分类现状**：企业/科研机构/服务机构统一 `Organization` 单 TAG，`org_kind` 7 值枚举（domesticuniversity / domesticresearchinstitute / hongkongcompany / taiwancompany / macaocompany / foreignorganization / domesticorganization）中**没有「企业」也没有「服务机构」专属值**——内地企业主体落默认桶 `domestic_organization`；`org_type` 本地实测基本为空（3,689 行中 3,639 NULL），连文本区分都不可用。
4. **上图逻辑**统一走平台抽取链（第四章）；`dev` 空间九大业务模块 legacy ETL 不在范围。
5. **量级锚点**引自外部 gkx 样例库 e2e 验证值（`docs/gkx生产库抽取适配绑定清单.md`）；零边/改道关系显式标注。

## 四、上图逻辑（统一抽取链）



### 4.1 链路总览

全要素统一走平台喂数批次抽取（Temporal workflow `kg.schema.extract`，`backend/service/temporal_workflows.py`）：

```Plain Text
来源绑定分批读取 → @step 转换脚本（子进程）→ 写前消歧/改写 VID
  → nGQL 批量 INSERT VERTEX / INSERT EDGE → 逐行失败进审核
  → 批级实体索引 upsert → 水位推进 → 链尾 SUBMIT JOB STATS
```

- 任务形态：单 Schema 抽取（extract）与多 Schema 串行链（chain，2–20 个严格串行）；e2e 部署形态 = 实体链（17）先行 → 关系链 A/B（1413）串行，图匹配器边依赖实体链先入库。
- 新图空间由模板空间 `gkx_verify_1` 克隆 Schema 目录（definition/property/script/source 四表，绑定改指目标数据源）再执行 DDL。



### 4.2 读取模式（三模式）

querySql  pk keyset / timeColumn 水位（`WHERE time > :wm`）/ LIMITOFFSET（主键不唯一表）；水位与 pkCursor 持久化于业务库 `kg_script_watermark`（键 `source:{绑定uuid}`），定点重跑 `recordIds IN`。

### 4.3 写图（幂等批量写）

实体一律 nGQL 多行批量 `INSERT VERTEX`（64 行/语句、限步调 500 行/05s；列级 upsert 幂等；unknowncolumn 自愈剔列；NOT NULL 溯源列平台补默认）；REST `/nodes/merge` 显式弃用（身份键剥离问题）。写前守卫（`entity_write_guard.py`） 同名微锁根治并行批双盲双写；专利 B 富集只补空防 Nonewipe。

### 4.4 消歧与人工审核

写前消歧（`entity_disambiguation.py`）：同名图库召回 ∪ Milvus `kg_entity` 稠密召回 → 打分（名称 06  属性 04，RapidFuzz）→ **≥085 且分差 ≥008** 改写 vid 并入；**065–085** 灰区建 TLINK 人工审核 case；**065** 新实体。挂实体改道（专利发明人/申请方/权利人）：pendingReview 实体  边暂存人裁后补写。机构域另有 BM25稠密离线对齐 → SAMEAS，用于论文域机构桩认领。

### 4.5 失败与重跑

逐行失败 → TEXTRACTFAIL 审核 case（队列 category=C）；平台点重跑生成 `triggerSource=RERUN` 新执行，可按 pkCursor 回拨定向重抽。

### 4.6 索引与统计

实体检索索引按环批级增量 upsert（writerecords 留档 vid 清单 → EntitySearchServiceupsert，冻结 BM25 词表）；索引失败=整链 FAILED 不降级；链尾 SUBMIT JOB STATS。大载荷走 RustFS S3 claimcheck（批预算 8MB）。

### 4.7 验证口径

e2e 驱动 `gkx_dwd_local_e2e.py`：prepare（建空间克隆目录DDL）→ purge（CLEAR SPACE清水位）→ run（3 条 chain 串行）→ verify（SHOW STATS 对照锚点，实体锚点自动连源库 COUNT）。
