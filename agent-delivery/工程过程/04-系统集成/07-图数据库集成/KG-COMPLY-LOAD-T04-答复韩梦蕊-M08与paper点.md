## 二、M07 本期不建（前提纠正）

### 事实

`ads_talent_project`（人才-项目关系表）共 **7,702,366 行**。按关系类型分组后只有一种：

```
relation_type = funded_output_author : 7,702,366   （全部）
is_lead = 1 的行数                    : 0
is_direct_investigator = 1 的行数      : 0
```

### 这些行是什么意思

「这个人**参与的项目产出了论文**」——是受资助论文的署名结果，不是「这个人参与了这个项目」。

### 为什么不能当 M07

M07 要的是「谁参与了哪个项目」。而这批数据的语义是「谁的成果挂在这个项目下」，两者不是一回事。而且表示「直接参与」「担任负责人」的两个字段全是 0，连一个真实参与人都取不到。

### 处置

**M07 本期不建，对账单里列成「无源缺口」。** 不得用 `funded_output_author` 冒充参与关系。
若要补，需久新提供真实参与/负责人关系数据，或在正式线由我方加工层沉淀。

## 三、M08 灌多少：只灌 17,426 行

### 数据实况（我方复核，与韩梦蕊所报一致）

`ads_project_institution` 共 **22,571,355 行**，按关系类型分三种：

| relation_type | 行数 | 实际含义 | 算不算 M08 |
|---|---:|---|---|
| `funded_output_affiliation` | 22,553,929 | 某机构是某篇受资助**论文**的署名单位 | **不算** |
| `affiliation_exact_name` | 17,399 | 机构按名称精确匹配到项目 | 算 |
| `affiliation_ror` | 27 | 机构按 ROR 编号匹配到项目 | 算 |

按角色字段看：

| institution_role_code | 行数 |
|---|---:|
| 空 | 22,553,929 |
| `lead_affiliation` | 17,393 |
| `investigator_affiliation` | 33 |

### 结论

**只灌 `institution_role_code` 非空的 17,426 行**（lead 17,393 + investigator 33），`relation_type` 原值写进 `props` 便于溯源。

### 为什么那 2,255 万行绝对不能灌

`funded_output_affiliation` 说的是「这个机构是这篇**论文**的单位」，**终点是论文，不是项目**。灌进 M08 等于断言「这个机构参与了这个项目」，属于把结论说错，不是口径宽严问题，抽查一验即露。

两条路差 1,300 倍：

```
全量灌 22,571,355 行  ← 其中 22,553,929 行语义不对
只灌真隶属    17,426 行  ← 正确
```

## 四、paper 点本期灌 0 个

### 三个选项的取舍

| 选项 | 判定 | 理由 |
|---|---|---|
| 不灌，对账单注明 | ✅ **采用** | 本期没有任何必须边落在 paper 上 |
| 只灌被引用的 120,160 篇 | ❌ | 同样「没有边」，只是把孤立点从 400 万减到 12 万，无收益，且易让人误以为论文层已灌 |
| 全灌 4,000,000 | ❌ | 400 万孤立点污染点总数统计、拖慢全图遍历，对账说不清 |

### 补充事实

`ads_patent_cited_paper` 322,951 行，去重后 **120,160 篇论文 / 228,110 件专利**，且 120,160 篇全部能在 `ads_paper_profile` 里对上 —— 数据本身是干净的。

但它的语义是「**专利引用论文**」，而 M06 要的是「**论文引用论文**」，两者不是同一关系，所以**不能靠它把 paper 点救活**，M06 本期仍不建。

## 五、附带：项目和专利点也不按源表全灌

同一原则，韩梦蕊没问，但必须一并定，否则后面返工。

| 点类型 | 源表行数 | 本期要灌 | 依据 |
|---|---:|---:|---|
| 项目 `project` | 1,838,841 | **17,402** | 只有 M08 用到，涉及去重项目 17,402 个 |
| 专利 `patent` | 1,768,955 | **70,496** | 只有 M09 专利段用到，涉及去重专利 70,496 件 |
| 论文 `paper` | 4,000,000 | **0** | 无任何必须边 |
| 人才 `person` | 100,000 | **100,000（全量）** | 七要素主数据，需支持按类型筛选，量小 |
| 科研机构 `research` | 83,745 | **83,745（全量）** | 七要素主数据，T03 也要用 |

### 规则一句话

**一个点要不要灌，看本期有没有必须边落在它身上；只有七要素主数据例外，允许存在暂时不连边的点。**

理由：孤立点会让点总数统计失真、拖慢全图遍历、让 T07 对账无法解释。而七要素主数据本身是「可被筛选展示的资产清单」，现在没边不等于以后没边。

## 六、对账口径要改

**分母不要用源表行数，用「应灌子集数」。**

否则会出现：

```
项目点：灌了 17,402 个  vs  源表 1,838,841 行  →  永远显示「缺 99%」，任务永远关不掉
专利点：灌了 70,496 个  vs  源表 1,768,955 行  →  同上
```

正确写法：

| 项 | 应灌 | 实灌 | 差异说明 |
|---|---:|---:|---|
| M08 边 | 17,426 | ? | 差额需逐个说明（端点缺失等） |
| 项目点 | 17,402 | ? | |
| 专利点 | 70,496 | ? | |
| 论文点 | 0 | 0 | 明确写「本期不灌」 |
| M07 边 | 0 | 0 | 明确写「无源缺口」 |
