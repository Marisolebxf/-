## 一、一句话

**那不是「搬到一半停电」，是「压根没正式搬过」。** 图里技术点层那点数据是别人早期灌的**预览版**（无批号、只覆盖 361 个技术点），我们这轮（T01–T14）只搬了七要素层，技术点层从来没进过正式装载。

## 二、打个比方

七要素层＝主楼，我们按图纸一层层浇完了。
技术点层＝裙楼，现在立着的几根柱子是**别人先搭的样板间**：样板间只有 361 个技术点连了机构，全楼有 19,430 个技术点。
所以不是「裙楼浇到一半」，是「裙楼还没正式开工，你先看到的是一间样板房」。

## 三、术语小词典

| 词 | 大白话 |

## 四、四项逐条说清（都有实测）

### 4.1 技术点 ↔ 机构：差的不是 2,477,802，是「从没正式搬」

| 实测项 | 结果 | 说明 |
|---|---|---|
| 图里边数 | 51,000 | |
| 有机构边的技术点 | **361 / 19,430（1.9%）** | 不是每条边少一半，是**98% 的技术点一条都没有** |
| 这些边带批号吗 | **0 条带批号** | 我按 `e.batch` / `e.props` 查，全空 → **不是我们这轮灌的**，是早期预览 |
| 源表非企业行 | **2,428,981 行**（33,026 家机构） | 另有 99,821 行（6,732 家）`is_company=1`，属企业不是机构 |
| 源表涉及的机构 | 33,026 家 | 图里 `tech_institution` 只有 **17,542** 个 |
| 其中能立刻写的 | **2,304,967 行**（15,799 家机构在图里都有点） | 端点齐全，可以马上灌 |
| 因端点缺失暂写不了 | **124,014 行**（17,227 家机构图里没有点） | 需先建这 17,227 个机构点 |

**结论**：这不是漏灌一部分，是「正式装载没启动」。今天就能写 230 万条；剩下 12.4 万条要先补 1.72 万个机构点（建点比建边简单，半小时级）。

### 4.2 技术点 ↔ 技术点 关系边：图里是上一版快照

| 实测项 | 结果 |
|---|---|
| 源表行数 | 587,252（全部唯一有序对，无自环、无重复） |
| 是否单一版本 | 是，全部来自 `eto_mvp_cluster_chain_v1_20261016`，同一时刻（2026-10-26 06:00） |
| 图里边数 | 541,428（**92.2%**） |
| 图里带批号吗 | **0 条** → 同属早期预览，不是本轮灌的 |

**判断**：源表是同一份快照，图里少 45,824 条（7.8%）。最大可能是当时装载中断或分批没跑完——因为它既不是去重少算（源表本来就无重复），也不是端点缺失（涉及的 18,567 / 18,860 个技术点都在图里）。**解法是差分补齐**：把图里现有 541,428 对导出来，跟源表做集合差，只补缺的。

### 4.3 技术演化路径步：不是数据缺陷，是「边」这种结构表达不了起点

| 实测项 | 结果 |
|---|---|
| 源表行数 | 47,909，来自 **12,891 条路径** |
| 缺口 | 47,909 − 35,018 = **12,891**，正好等于路径条数 |
| 为什么正好相等 | `step_order=1` 的行恰好 12,891 条，且这些行的 `previous_technology_node_id` **全部为 NULL** |
| 图里为什么没这些 | 图里 `tech_path_step` 是「上一步 → 这一步」的边；第一步没有上一步，**没有能连的起点**，所以写不成边 |

**结论**：**35,018 就是这条路径网络里的全部跳数**，不是缺 27%。缺的 12,891 条是「每条路径的第一个节点」，它在图里作为 `tech_point` 本来就存在，只是没有一条边指向它。

**解法（两选一，我倾向 A）**：
- **A（推荐，零补数）**：把对账分母改成「跳数 35,018」，本项按 100% 关闭；若页面要标「路径起点」，把 `path_id` 与 `is_head` 写进该技术点的 `props`（改属性，不加边、不建结构）。
- **B（要显式起点）**：为每条路径建一个虚拟起点节点（12,891 个点 + 12,891 条边）。结构与对账都会变复杂，且虚拟点是「造出来的实体」，我不建议。

### 4.4 社群归属字段：从没写过

`ads_technology_community_member` 每技术点一行，共 19,430 行；图里 `tech_point.community_id` 全是**空串**（不是 NULL）。这是单纯的字段回填，19,430 条 `UPDATE VERTEX`，按 2 万条一批一次跑完。

## 五、要顺带定的一条口径（不然分母永远吵不清）

源表 2,528,802 行里有 **99,821 行是「企业」不是「机构」**（`is_company=1`，6,732 家）。这跟 M03 那次一模一样：数据有值，但端点类型不符。

**裁定**：`tech_has_institution` 只收**非企业**（`is_company=0`）。企业关联属另一类关系，本期不塞进这条边，也不为它新建编号——若要展示企业关联，走企业侧现有的边，不在这条边上凑数。

→ 对账分母由 2,528,802 改为 **2,428,981**；缺口由 2,477,802 改为 **2,377,981**。
