## 2. 三种集成方式对比

| 对比维度 | iframe + 反向代理 | 微前端 wujie（推荐） | 微前端 qiankun | 接口对接 + 门户重建 |
|---|---|---|---|---|
| 无感体验 | 中（有边界感、白屏） | **最高**（同源同布局） | 高 | 高 |
| 改造成本 | 低 | 中 | 中 | 高 |
| 部署独立性 | 高 | 高 | 高 | 高 |
| 认证传递 | postMessage/URL | **props 下发** | globalState | 后端网关代理 |
| 跨域处理 | Nginx 代理 | 原生支持 | 需配置 CORS | 无（后端调） |
| Vue 3 + Vite 支持 | 原生 | **原生友好** | 需额外插件，有坑 | N/A |
| 沙箱隔离 | 天然 | iframe + Web Component | JS 沙箱有边界 case | 无 |
| 预加载/保活 | 不支持 | **支持，更平滑** | 支持 | N/A |
| 通信 | postMessage | **props + bus** | globalState | 无 |
| 是否浪费已有产出 | 否 | 否 | 否 | **是**（UI 全重建） |

### 选 wujie 的理由

1. **Vue 3 + Vite 场景下 wujie 比 qiankun 省心**：qiankun 对 Vite 子应用需 `vite-plugin-qiankun`，有 HMR 模式冲突等已知问题
2. **wujie 基于 iframe + Web Component**，天然沙箱，样式/JS 隔离更彻底
3. **通信通过 props 下发 + bus 双向**，比 qiankun 的 globalState 更直观
4. **支持保活模式**，切换菜单不重新渲染，体验最无感
5. **不浪费智树已有产出**：智树页面已建好，接口对接方式要求门户重建全部 UI，与前提矛盾

## 3. wujie 是什么

wujie（无界）是腾讯开源的微前端框架。在不同框架下形态不同：

| 包 | 形态 | 用法 |
|---|---|---|
| `wujie`（核心包） | **函数** | `import { startApp, preloadApp } from 'wujie'`，框架无关，手动调函数启动子应用 |
| `@tencent/wujie-vue3` | **Vue 组件** | `import WujieVue from '@tencent/wujie-vue3'`，`app.use(WujieVue)`，模板里 `<WujieVue url="..." />` |
| `@tencent/wujie-react` | **React 组件** | 同理，React 版封装 |

**本项目用 `@tencent/wujie-vue3`，以组件形式使用。** 核心包的函数 API 适合需要精细控制生命周期时用，常规嵌入直接用组件即可。

## 4. 两个系统的改造清单

### 4.1 智谱门户侧（主应用）

```
1. 安装 wujie-vue3：npm i @tencent/wujie-vue3
2. 在 main.ts 注册 wujie：
   import WujieVue from '@tencent/wujie-vue3'
   app.use(WujieVue)
3. 在 4 个路由组件中用 <wujie> 替换当前 Mock 占位：
   <WujieVue
     name="topic-industry"
     url="https://topic.zhi-shu.com/industry-center/overview"
     :sync="true"           // 路由同步，前进后退正常
     alive                   // 保活，切换不重渲染
     :props="{ token, user, theme }"  // 下发认证
   />
4. 删除 4 个 Mock 占位页面（或保留为降级 fallback）
5. 配置 SSO token 下发：登录后存入 Pinia，通过 props 传给子应用
6. Nginx 配置子应用资源 CORS（允许门户域加载智树 JS/CSS）
```

### 4.2 智树科技专题服务侧（子应用）

```
1. 确认 lumen-ui-topic 的 Vite 配置允许跨域加载：
   server: { headers: { 'Access-Control-Allow-Origin': '*' } }
   build: { chunkSizeWarningLimit: 1500 }
2. 导出子应用入口 HTML（Vite 默认即可，wujie 加载的是 HTML）
3. 路由 base 适配：若门户路径与子应用路径一致则无需改；
   若不一致，子应用 router 需 read props 里的 base path
4. 接收 token：从 wujie props 取 token，设置到 axios 拦截器
5. 接收主题：从 props 取 theme，应用到 Element Plus / 自定义样式
6. 错误降级：子应用加载失败时，门户侧 fallback 到 Mock 占位
```

## 6. 页签处理（智树每个专题页有多个页签）

智树每个专题页有 2-5 个内部页签，如 E-33 重点企业概览的 Tab（重点 / 明星 / 深圳）。页签是 **URL 参数驱动**（`?tab=key-enterprises` 等）。

### 需处理的 4 个技术点

| # | 问题 | 解法 |
|---|------|------|
| 1 | URL 同步深度 | wujie `sync=true`，子应用 URL（含 `?tab=`）同步到浏览器，刷新可恢复页签 |
| 2 | 页签状态保持 | wujie `alive` 保活，子应用实例不销毁，页签状态保留 |
| 3 | 两层导航层次 | 门户菜单=全局导航（左侧/顶部），页签=页面内导航（内容区顶部 Tab 栏），视觉层次区分 |
| 4 | 深层链接直达 | URL 带 `?tab=xxx` 参数，wujie 加载子应用时自动定位到该页签 |

### 推荐配置

```vue
<WujieVue
  name="topic-industry"
  url="https://topic.zhi-shu.com/industry-center/overview"
  :sync="true"              <!-- 页签 URL 同步到浏览器 -->
  alive                      <!-- 保活，切走再回来页签不丢 -->
  :props="{ token, user, theme }"
/>
```

- `sync=true` + 页签 URL 参数化 = 刷新/前进/后退正常
- `alive` = 切换门户菜单时子应用不销毁，回来还在原页签
- 重交互页（如图谱类）保活，列表页可用默认 destroy 省内存

### 与智树对齐的硬要求

**页签状态必须 URL 化**（query 或 path），这是微前端集成的最低要求。纯组件 state（不进 URL）会导致刷新丢页签。

## 7. 认证链路（不违反架构铁律）

```
用户登录智谱门户
  → 门户拿 JWT (gkxx 平台 SSO)
  → wujie props 下发 token
  → 智树子应用拿 token
  → 调智树自己的 Java Facade (gkx-innov)
  → Java Facade 验签 + 读 ADS / 调 Python /internal/*
  → 不绕过 E-31 真源分治
```

**关键：智树子应用直连自己的 Java Facade，不经门户后端代理。** 门户只是壳，不碰智树的数据。

## 8. 风险与注意事项

1. **CORS 配置**：智树子应用的静态资源（JS/CSS）需允许门户域跨域加载。生产环境建议同部署域或 CDN 同源。
2. **Vite 开发模式 HMR**：wujie 嵌入 Vite dev server 时 HMR 可能失效，需用 `vite-plugin-wujie` 或开发时直连子应用端口调试。
3. **公共依赖共享**：两边都用 Vue 3 + Element Plus，可通过 wujie 的 `degrade` 配置 externals 共享，减少体积。但需版本对齐，否则样式冲突。
4. **路由 prefix 冲突**：若智树子应用路由有 `/industry-center` 前缀，门户也有同前缀，需 `sync` 模式 + `prefix` 处理。
5. **保活内存**：4 个页面都 alive 会常驻内存，移动端或低配设备需评估。可只对重交互页面保活，列表页用 destroy。
6. **总集对齐**：需确认总集是否对"多系统集成方式"有统一要求（如指定 qiankun/wujie/iframe），避免与其他供应商方案冲突。

## 附：不要做的事

- ❌ 不要让门户后端代理智树的所有 API（变成接口对接，违背"页面已建好"前提）
- ❌ 不要让门户前端直连智树 Python `/internal/*`（违反架构铁律"前端 → Java → Python"）
- ❌ 不要用 iframe 还让智树后端 session 校验（session 在 iframe 嵌入场景下有 Cookie SameSite 问题）
- ❌ 不要让智树页签用纯组件 state（不进 URL），会导致刷新丢页签
