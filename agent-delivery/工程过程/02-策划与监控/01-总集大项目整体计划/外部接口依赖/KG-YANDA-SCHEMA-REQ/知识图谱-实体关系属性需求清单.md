## 二、方法与判定标准

### 2.1 两级筛选 + 精判

| 级 | 动作 | 结果 |
|---|---|---|
| 第一级：模块级 | 按已确认 8 模块纳入、7 模块排除 | 751 → 618 叶 |
| 第二级：叶级召回 | 关键词（图谱/知识图谱/节点/关系网络/关联关系/中心性/社群/路径/影响力/三元组/拓扑/子图等）召回 | 618 → 134 候选 |
| 精判 | 逐叶读 `desc`（需规功能描述）与 `bid_desc`（招标描述），判定是否真依赖图谱实体/关系本体 | 134 → 保留 72 / 剔除 62 |
| 补漏 | 科技知识图谱模块（55 叶）为图谱核心模块，全量复核召回缺口 | +25 叶（保留 18 / 剔除 7） |
| 全覆盖复核 | 2026-10-22 将判定从 134 候选扩为 **618 叶全覆盖**：未命中关键词的 484 叶判「不相关」；同时按郭万迎 a/b/c 拍板对原"飞书多收 37 条"重分类 | 618 → 保留 81 / 转背景 15 / 剔除 47 / 不相关 475 |

> **a/b/c 分类规则（2026-10-22 郭万迎拍板）**：图谱或实体、实体关系的增删改查操作、交互展示也与知识图谱系统有关，需提供接口。
> - **a 类（转背景）**：图谱实体/关系的增删改、构建、版本管理 → 归 §十 图谱写入与构建（06 M2），不进只读契约，15 叶。
> - **b 类（收回清单）**：读+图计算（实体检索/详情/筛选/排序、关键路径、时序演化、实时监控、多源数据接入）→ 收回 §六 计算能力清单，8 叶（seq20/24/25/27/31/33/301/452；seq449 归 §十 数据接入）。
> - **c 类（维持剔除）**：纯前端交互（缩放/拖拽/聚焦/高亮）、平台能力（权限审计/分享通知/收藏/可视化图表构建）、业务决策联动 → 与燕大图谱接口无关，10 叶。

### 2.3 为什么飞书 113 行不能单独作基座

| 问题 | 事实 | 后果 |
|---|---|---|
| 覆盖不全 | 113 行 vs 纳入范围 618 叶，覆盖率 18.3%；**科技成果展示 0/102、科技服务全景 1/45、政策对比 2/17、科技数据资源 4/70、科技人才态势 13/87、科技政策跟踪 1/46、科技发展态势 37/196** | 只按飞书封装会漏掉成果展示、人才、数据资源、政策对比的大部分图谱需求 |
| 粒度不齐 | 行粒度混有写入（seq17～47）、交互（seq19/23/286/298）、权限（seq454）、愿景（seq449/451～453） | 把非本体需求误当图谱查询契约，接口边界失真 |
| 三列全空 | 审核状态、预计提供时间、接口文档 **113 行全空** | 无法判断燕大已确认/可供状态，不能作为契约基线 |
| 只有功能级 | 无字段、无类型、无方向、无基数、无必选/可选 | 燕大无法据此封装字段级接口 |
| 口径冲突 | 部分行与 06d 结论不一致（seq448/442/443 归智树；seq17～47 归 06 M2；seq449/451～453 愿景） | 直接采用会与既有契约冲突 |
| 无计算能力面 | 只列功能，不区分「实体属性」与「图算法产物」 | 中心性/社群/路径/影响力无法按接口归类 |

结论：**以需规为第一基座逐叶判定**，飞书表只作锚点做三态核对（§七 与 `需规-飞书差异核对表.csv`）。

### 7.3 接口封装建议（供燕大参考）

1. **统一实体视图**：所有实体共用 `entity_id/name/type/field/region/institution/year/value/updated_at`，类型差异用 `attrs{}` 扩展，避免 14 套结构。06d 已按此思路（`nodes[]` 扁平字段）；新增类型只需扩字典，不改包络。
2. **关系边统一视图**：`relation_id/source_entity_id/target_entity_id/type/weight/year/start_time/end_time/confidence/evidence_refs`；子类型放 `relation_subtype`，避免为每个 NEW 关系开一套出参。
3. **实体详情与邻接拆两个子资源**：`POST /v1/graph/entities/{entity_id}` 与 `POST /v1/graph/entities/{entity_id}/neighbors`；比在 KG-01 全量结果集里过滤更稳，也便于缓存。
4. **图计算结果与图结构分离**：中心性/社群/路径/影响力返回 `metric_rows[]` + `graph_ref`，不要把算法分数写回实体属性表（06d 已按此分 KG-03/04/07）。
5. **空态与截断**：沿用 06d `empty_reason` 与 `truncated`；新增实体/关系类型无数据时返 `no_source`，不返空对象冒充。
6. **字典外置**：实体类型/关系类型/属性枚举的中文名与色值仍由展示系统后台字典注入；燕大只返编码，避免新增 8 类实体时改接口。
