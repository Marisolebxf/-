# 关系定义层 · 功能关联与方案说明（供拍板）

> 2026-10-27 · 基于**最新原型**（kejizhuantifuwu.netlify.app，kg-mgmt-page.js v20261027）源码级分析

---

## 一、原型里的完整模型（两层结构）

原型「全要素图谱管理」的关系链是**两层设计**，不是一层：

```
第 1 层：关系定义（类型模板，XX 链定义按钮管理）
   ├─ 作用：定义"这一类关系叫什么、什么含义、有什么特征字段"
   ├─ 每类实体一套独立清单（如企业的"联合研发/供应链协作"）
   └─ 每条定义有富字段：名称 + 定义 + 该类专属字段（见下表）
        │ 实例化
        ▼
第 2 层：关系实例（两个具体实体挂上某条定义，即"新建关系链"弹窗）
   ├─ 弹窗里的"关系类型"下拉 → 应该从第 1 层的定义清单选
   └─ 现在：类型是手填自由文本 → 没有第 1 层，只能瞎填
```

## 二、六类实体的定义清单与专属字段（原型源码实证）

| 实体 tab | 定义区块名 | 预置类型（原型自带） | 每条定义的专属字段 |
|---|---|---|---|
| 科研机构实体（暂树） | 合作关系定义 | 联合攻关、平台共建 | name / definition / **achievement** 合作成果 / **influence** 影响力 |
| 人才实体（暂树） | 人才流动关系定义 | 机构间流动、柔性引进 | name / definition / **reason** 流动原因 / **impact** 流动影响 |
| **企业实体** | **企业合作链定义** | 联合研发、供应链协作 | name / definition / **mode** 合作模式 / **terms** 合同条款 |
| **政策实体** | **政策传导关系定义** | 纵向政策传导、跨部门政策传导 | name / definition / **effect** 执行效果 / **feedback** 反馈 |
| **服务机构实体** | 服务机构引扶建议（service 家族） | 客户服务关系、合作伙伴关系 | name / definition / **content** 服务内容 / **effect** 服务效果 |
| **产业实体** | 产业链关系定义 | 上游供给关系、下游应用关系 | name / definition / **participants** 参与方 |

> 注：科研/人才两 tab 标注"暂树"，本期范围是四类（企业/政策/服务机构/产业）。

## 三、三选项在同一模型下的含义

### 方案 A：完整定义层（推荐给产品的方案）

新建「关系定义」管理（每个 tab 一个"XX 链定义"按钮，增删改查定义条目），字段按上表**每类实体独立**：

- 数据模型：`cms_kg_rel_def` 表，公共列（entity_type/name/definition/order）+ **专属列用 JSON**（`extra: {"mode":…,"terms":…}` 按类存，与 CMS overlay 的 JSON 惯例一致）
- 关系实例弹窗的「关系类型」改为下拉选**定义条目**（name 展示，关联定义 id）
- 关系实例列表/详情可联动显示定义的 definition/mode/terms 等富信息
- **收益**：与原型完全一致；运营可自助维护类型与语义；关系数据可解释
- **代价**：约 1 天（表+4 端点+实例联动），前端弹窗改下拉

### 方案 B：简化定义层

定义层只存 name + definition 两个通用字段，**专属字段（mode/terms/participants 等）不落库**。

- **收益**：半天搞定
- **损失**：原型可见的「合作模式」「合同条款」「参与方」「流动原因」等信息**无处可填**——久新前端已渲染的这些输入框要删，或接受数据丢失。**大概率会被久新打回**

### 方案 C：不做

关系类型维持手填自由文本。

- **后果**：类型命名不可控（"政策扶持"/"扶持政策"同一语义两种写法），后续按类型统计/检索全部失准；与原型不一致，验收时会被质疑

## 四、关联到拍板的判断题

1. 原型上这些定义区块和专属字段**是否属于本期交付范围**？——原型就是产品给的需求载体，区块可见且字段完整，**按"原型即需求"惯例应属本期**
2. 若属本期 → 方案 A（B 的信息损失大概率验收不过）
3. 变更记录/多版本/批量导入三项**维持不做**（最新原型确认无此三功能，与关系定义无关）

## 五、一句话给拍板人

> 原型里每个实体 tab 都有"链定义"管理区块（含定义/模式/条款/参与方等字段），这是关系类型的字典层；现在后端没建这一层，导致久新前端新建关系时类型只能手填。方案 A 按原型补齐（约 1 天），与原型完全一致；B/C 都会产生与原型的偏差，需要产品签字确认。
