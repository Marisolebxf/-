# 内容运营中心_智树接口需求20261008-评估


## 一、总体评估

针对内容运营中心提出的智树接口需求，基于既有 [E-31 消费契约](../../../../agent-handoffs/产品整体定义/E-31-企业发展/CMS-read-contract-E31.md) 的架构铁律，评估结论为：智树提供**只读查询接口**，不提供对智树真源数据的 CRUD 接口。

## 二、架构依据

依据已冻结的 E-31 消费契约与真源分治规约：

| 铁律 | 说明 |
|---|---|
| 真源分治 | 工商/标签/专利/论文/财报/政策原文属客观事实，走 ODS→DWD→ADS 链路；叙事/排序/媒体/入选理由属运营内容，存 CMS 库 |
| 禁止反写 | CMS 不写智树库；智树不反向写 CMS 库 |
| Java 聚合 | 对前端暴露的接口由智树 Java Facade 聚合 ADS（智树）+ CMS（久新） |
| 失败隔离 | CMS 超时/空发布 → 业务空态文案；ADS 失败 → 统计区骨架；互不拖垮 |
| 禁止手填冒充 | 禁止 CMS 手填数覆盖 ADS 统计；禁止算法 TopN 冒充明星名单 |

基于以上铁律，智树提供**只读查询接口**供 CMS 引用真源数据；运营态数据（资讯/深圳专项/榜单评注/介绍/历程/图谱关系）由 CMS 自建库存管理。

## 三、智树提供的接口清单（16 个，全部只读）

### 第一批（基础查询类）

| # | 接口 | 形态 | 数据源 |
|---|---|---|---|
| 1 | 企业列表/详情/下拉 | GET /api/v1/enterprise + /{id} + /suggest | DWD `dwd_org_base_info` |
| 2 | 政策列表/详情/下拉 | GET /api/v1/policy + /{id} + /suggest | DWD `dwd_policy_base` |
| 3 | 服务机构列表/详情/下拉 | GET /api/v1/service-org + /{id} + /suggest | ADS `svc_org_card` |
| 4 | 标准产业分类树 | GET /api/v1/industry-class/tree | DWD `dwd_industry_chain_info` |
| 5 | 标准产业链环节 | GET /api/v1/chain-link | DWD `dwd_industry_chain_info` |
| 6 | 实体批量查询（图谱初始化） | POST /api/v1/bulk/entities | DWD 多表 |
| 7 | 企业基础档案查询 | GET /api/v1/enterprise/{id}/profile | DWD |
| 8 | 企业产品名称查询 | GET /api/v1/enterprise/{id}/products | DWD `enterprise_industry_product` |

**实体批量查询接口约定**：
```
POST /api/v1/bulk/entities
入参：{entity_type, updated_after, limit: ≤500, offset}
出参：[{id, name, type, region, industry, update_time}]
限流：每分钟 ≤ 10 次
```

```

超时降级：CMS 次日 02:00 调用接口 15 全量校对
```

## 四、CMS 自建接口清单（26 类）

智树不提供以下接口，由 CMS 自建库存管理：

| 类别 | 数量 | 明细 |
|---|---|---|
| 动态资讯 | 3 | 企业/服务机构/产业动态资讯（标题/摘要/来源/风险等级） |
| 深圳专项 | 2 | 深圳本地企业专项/深圳服务机构专项（重点标识/专项说明） |
| 产品型号/技术参数 | 1 | 产品型号/技术参数（产品名称由智树只读提供，型号/技术参数智树 DWD 无，CMS 自建） |
| 自定义产业分类/环节 | 2 | 运营扩展分类与环节 |
| 图谱运营 | 8 | 实体生命周期/关系链/属性/阶段/状态历史 |
| 门户内容 | 8 | 介绍/档案/现状/历程/榜单评注/封面图 |
| 文件管理 | 1 | 图片/附件上传下载 |
| 发布/下架动作 | 1 | CMS 运营门闩 |

**依据（谁生产谁存原则）**：
- 上述 26 类数据均由 CMS 运营人员人工创建/编辑/发布，不是智树从真源算出的统计
- 智树提供这些数据的 CRUD 相当于代管其不生产的数据，违反真源分治
- CMS 自建库可自由设计 schema，通过业务 ID（如 `enterprise_code`）与智树真源做关联引用

## 五、通用接口约定

针对需求文档表 4 的 8 类通用接口：

| 接口类型 | 智树提供？ | 说明 |
|---|---|---|
| 列表查询 | ✅ 提供 | 分页/关键词/筛选/排序，返回列表 + 总数 |
| 详情查询 | ✅ 提供 | 按业务 ID 返回真源字段 |
| 新增 | ❌ 不提供 | 真源新增违反分治；运营新增由 CMS 自建 |
| 编辑 | ❌ 不提供 | 真源编辑违反分治；运营编辑由 CMS 自建 |
| 删除 | ❌ 不提供 | 真源删除违反分治；政策失效走 webhook |
| 下拉与关联 | ✅ 提供 | 企业/产业/政策/服务机构/区域关键词搜索 + 分页回显 |
| 文件 | ❌ 不提供 | 图片/附件属运营内容，CMS 自建文件管理 |
| 发布动作 | ❌ 不提供 | 发布/下架是 CMS 运营动作；政策失效 webhook 是唯一例外 |

## 六、交付内容

按需求文档第六节要求，智树交付：

1. **OpenAPI 文档**：上述 16 个接口的完整 OpenAPI 3.0 定义
2. **字段规则**：字段类型、必填规则、枚举值、状态值、请求响应示例
3. **测试环境**：测试地址、测试账号、基础测试数据、接口负责人
4. **交付计划**：分两批交付（基础查询类先行，榜单/统计/全景类随后），具体节奏以项目计划为准；字段或接口变更时提前同步影响范围
