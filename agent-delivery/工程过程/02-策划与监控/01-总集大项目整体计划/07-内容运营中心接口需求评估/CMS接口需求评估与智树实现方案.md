# CMS 接口需求评估与智树实现方案

> 内部存档。评估久新《内容运营中心_智树接口需求20261008.docx》中各接口对智树合同范围的匹配度与实现方案。

## 一、背景与范围

### 1.1 评估对象
久新（伙伴）于 2026-10-08 发来《内容运营中心_智树接口需求20261008.docx》，要求智树提供科技专题服务系统-内容运营中心（CMS）模块所需接口。

原文件路径：`d:\深圳市国际科技信息中心\2、项目文档\内容运营中心_智树接口需求20261008.docx`（不入仓）。

### 1.2 久新要求范围（docx 表 0）

| 模块 | 智树负责 | 不包含 |
|---|---|---|
| 基础数据管理 | 产品链、企业、政策、产业服务机构 | 技术链、科研机构、人才 |
| 全要素图谱管理 | 产业、企业、政策、服务机构四类实体的生命周期、关系链和属性管理 | 技术、科研机构、人才，以及图谱绘制工具 |
| 门户内容管理 | 产业全景、企业发展、产业服务、政策新闻 | 新兴科技、科研力量、领军人才、产研报告、平台介绍 |

### 1.3 智树合同范围（评估基准）
科技专题服务系统五维：企业分析、产业链分析、服务机构分析、政策分析、综合智能分析。

### 1.4 评估维度
- **匹配度**：智树是否负责/拥有该类数据
- **实现方案**：智树应提供何种接口、数据源、边界
- **边界声明**：智树提供 vs CMS 自建的清晰分治
- **交付节奏**：分批交付计划

## 二、核心评估结论

### 2.1 架构冲突点

本需求把智树定位成"基础数据 CRUD 供应商"，与既有 [E-31 消费契约](../../../agent-handoffs/产品整体定义/E-31-企业发展/CMS-read-contract-E31.md) 架构铁律冲突：

| E-31 铁律 | 本需求要求 | 冲突 |
|---|---|---|
| 真源分治：工商/标签/专利走 ODS→DWD→ADS | 智树提供"企业实体新增/编辑/删除" | ⚠️ CMS 直接写 DWD 真源 |
| 禁止反写：CMS 不写智树库 | 智树提供 CRUD 接口给 CMS 调 | ⚠️ 反向耦合 |
| Java Facade 聚合 ADS+CMS | 智树直暴露 CRUD | ⚠️ 绕过 Facade |
| 失败隔离：CMS 空→空态文案 | CMS 依赖智树 CRUD 才能运营 | ⚠️ 强耦合 |

### 2.2 核心原则：谁生产谁存

| 数据类型 | 谁生产 | 存哪 | 谁提供接口 |
|---|---|---|---|
| 客观事实（工商/专利/论文/政策原文） | 智树数据中台 | ODS→DWD→ADS | 智树提供**只读查询** |
| 统计结果（榜单分数/统计值） | 智树算法算子 | ADS | 智树提供**只读查询** |
| 运营内容（资讯/专项/介绍/历程） | CMS 运营人员 | CMS 库 | CMS 自建 CRUD |
| 图谱运营（关系/阶段/属性） | CMS 运营人员 | CMS 图库 | CMS 自建 CRUD |

**结论**：智树应提供**只读查询接口**（基于 DWD/ADS），不应提供**对真源的 CRUD**。运营态数据（资讯/榜单介绍/档案/图谱关系）应由 CMS 自建库存管理。

## 三、5 个关键问题的结论

### Q1：CRUD 边界
**结论**：智树只提供只读查询，不提供真源 CRUD。
**理由**：违反 E-31 真源分治铁律；CMS 反写真源会污染智树数据链路。

### Q2：榜单数据
**结论**：智树 ADS 实时出数，CMS 引用 + 加专家评注。
**理由**：榜单分数是统计事实（智树），评注是运营内容（CMS）；避免快照与真源不一致。
**降级**：CMS 缓存上一版榜单，智树 ADS 故障时回退展示（标注"数据更新中"）。

### Q3：图谱节点初始化
**结论**：智树提供"实体基础信息批量查询"接口。
**接口形态**：
```
POST /api/v1/bulk/entities
入参：{entity_type: "enterprise", updated_after: "2026-09-01", limit: 500, offset: 0}
出参：[{id, name, type, region, industry, update_time}, ...]
```
**边界**：智树只提供实体基础信息（ID/名称/类型/区域/产业），不提供关系数据；关系/属性/生命周期由 CMS 图谱库自管。支持 `updated_after` 做增量同步。每批 ≤ 500 条，每分钟 ≤ 10 次。

### Q4：政策失效回调
**结论**：智树主动 webhook 通知 + CMS 每日全量校对作兜底。
**webhook 约定**：
```
POST {CMS回调地址}
Body: {policy_id, reason: "失效", effective_date, source: "dwd_policy_base"}
失败重试：3 次，间隔 1/5/15 分钟
超时降级：次日 02:00 全量校对
```
**边界**：智树只通知"政策失效"事件，不指挥 CMS 做什么；webhook 是单向通知，不构成反写。

### Q5：交付节奏
**结论**：分两批交付。

**第一批（2 周内，基础查询底座）**：
- 企业列表/详情/下拉关联
- 政策列表/详情/下拉关联
- 服务机构列表/详情/下拉关联
- 标准产业分类树 / 标准产业链环节
- 实体批量查询（图谱初始化用）
- 企业基础档案查询

**第二批（4 周内，榜单/统计/全景）**：
- 企业 TopN 榜单（技术力/商业力）
- 服务机构 TopN 榜单
- 政策力度榜单
- 政策统计与区域关联
- 企业全景 facts 包（E-33 契约）
- 明星/深圳企业基础信息（E-34/E-35 契约）
- 政策失效 webhook 通知
- 已失效政策列表查询

**理由**：第一批是 CMS 运营底座，接口形态简单；第二批依赖 ADS 算子就绪且有冻结契约，需联调。
