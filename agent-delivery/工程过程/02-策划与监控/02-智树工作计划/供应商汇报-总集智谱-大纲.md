## P0 封面

**三条**

- 智树 · 科技信息展示系统与科技专题服务系统
- 供应商技术汇报（总集 / 智谱协同）
- 时长承诺：20 分钟内讲完，预留问答

**口播（~30″）**  
今天按「理解边界 → 技术方案（规范驱动）→ 团队工期 → 质量售后 → 为什么选智树」汇报，技术为主，管理只证明可持续、不绑架。

---

## P1 项目理解与边界

**三条**

- 双系统一体底座：展示 + 专题，共用数据标准层与平台 API
- 智树做：主链路界面、专题五维、小屏裁剪、报价内算法接入、供数映射
- 智树边界：他队能力对接 API / 部分菜单跳转；未确认大屏与超报价深度模型不进完成口径

**口播（~30″）**  
我们把项目理解成「可集成的双前台 + 可接入的算法面 + 可移交的数据供数」，先把边界画清，后面方案才站得住。

---

## P2 重难点（总集 / 智谱视角）

**三条**

- 口径与数据能否撑住界面数字（先身份与缺项，再铺页面）
- 多供应商供数窗与业务联调窗要对齐
- 算法要契约化接入：平台编排，模型可换版本

**口播（~30″）**  
难的不是画屏，是数字诚实、接口窗口和算法接入面——这三件事决定总集好不好集成、智谱好不好对接。

---

## P3 总体技术架构

**三条**

- 前端 → 平台网关/REST → 标准数据层；算法经平台调推理服务
- 图谱走约定引擎；演示仓与正式仓隔离
- 禁止前端直连算法或他队演示服务

**口播（~30″）**  
拓扑固定、实现可换——总集认调用链，智谱认接入点，甲方认正式交付面。

---

## P4 规范驱动开发（方法页 · 重点）

**三条**

- 主轴：规范 → 契约 → 实现 → 联调 → 验收；无规范增量不进正式主路径
- 四层：架构 / 产品交互与小屏 / 指标与数据身份 / 接口与算法契约
- 「不绑架」：规范与契约可移交、可对照验收，不依赖现场「会的人」

**口播（~30″）**  
我们用规范驱动开发：先锁定可验收的规范与接口，再分批实现。后面三页分别落实数据规范、算法契约、产品交互规范。

### 规范四层（口播可展开，总控 ≤2′）

| 层 | 对外名称 | 管什么 |
|---|---|---|
| L0 | 架构规范 | 调用链、仓隔离、算法边界 |
| L1 | 产品与交互规范 | UI/交互/小屏裁剪 |
| L2 | 数据与指标规范 | 指标身份、口径、就绪与缺口 |
| L3 | 接口与算法契约 | OpenAPI、算法入参出参、任务态 |

现场勿念内部文件名与编号；说「UI 规范 / 指标血缘规范 / 接口契约」即可。

---

## P5 数据与指标方案（落实规范 L2）

**三条**

- 标准表先行，映射与供数分批支撑联调
- 每个统计数字有指标身份；就绪与缺口明示，不伪闭合
- 口径与就绪度进入可移交资产，不锁个人脑中

**口播（~30″）**  
对总集——页面上的数都能追溯到身份与数据态；缺什么看得见，不靠演示粉饰。

---

## P6 算法接入方案（落实规范 L3 · 对智谱）

**三条**

- 报价内能力按「可接入门」交付：统一入参/出参/任务态
- 平台编排、前端只消费平台 API；模型版本可迭代
- 超报价深度能力单列分析，不混进必交范围

**口播（~30″）**  
对智谱——我们要的是稳定契约和联调样例，不是把模型绑死在某个页面里；换版本不换前台约定。

---

## P7 产品实现路径（落实规范 L1）

**三条**

- 专题：五维模块化，先前后端收口门，再接算法门
- 展示：智树主链路优先；对接类菜单走契约对接
- 小屏：壳与断点 + 中屏核心裁剪样板，再分批扩页（非 PC 整页搬迁）

**口播（~30″）**  
产品按交互与裁剪规范推进，保证总集看到的是可验收增量，而不是一次性不可拆的大包。

---

## P8 联调与交付流水线（复述规范门）

**三条**

- 五门：规范门 → 契约门 → 实现门 → 联调门 → 签收门
- CI 发布到约定环境；链路可复现，避免「演示机特例」
- 向总集提供接口清单与变更窗口；向智谱提供契约与联调样例

**口播（~30″）**  
跳过规范门不上实现主路径——用门禁保证可持续交付，而不是人盯人跟场。

---

## P9 团队配置与工期（脱敏）

**三条**

- 角色矩阵：总控 / 数据中台 / 指标血缘 / 算法接入 / 展示 / 专题 / 小屏 / 质量联调
- 六阶段门：基线 → 口径与数据 → 实现联调 → 送智谱 → 送总集 → 预生产
- 旁注相对顺序：指标责任门、供数就绪门、算法可接入门、专题前后端门（无具体日历）

**口播（~30″）**  
人按角色可替换，进度按阶段门对外对齐；具体排期在协同会上用接口窗对齐，此处不报死日期。

---

## P10 质量、售后与可移交

**三条**

- 契约验收：对照规范清单与接口面，不靠口头
- 可运维：追踪、日志、版本回滚；缺陷分级响应
- 可移交：正式仓代码 + 规范/契约资产；不绑单一演示机或私有协议

**口播（~30″）**  
售后的本质是把交付面留在甲方与总集能接手的资产上——这就是不绑架。

---

## P11 为什么选智树 + 协同请求

**三条**

- 范围准、底座统一、对智谱契约友好、**规范驱动可验收**
- 请总集：确认接口清单、集成环境、变更窗口
- 请智谱：确认算法契约样例与联调责任面

**口播（~30″）**  
选智树 = 选一套可集成、可替换、可验收的交付体系。请总集与智谱按契约面协同，我们按规范门分批交付。

---

## 现场禁忌

- 不报真实日期、人名、内部任务号 / agent / MCP
- 不贬他队；只说「对接契约 / 跳转边界」
- 智谱定位为**协同接入方**，非下属
- 规范页 ≤2′；管理每点最多一句「门禁 / 可移交」
- 不吹「已全部上线」；可提「规范驱动分批 + 可演示样板节奏」
