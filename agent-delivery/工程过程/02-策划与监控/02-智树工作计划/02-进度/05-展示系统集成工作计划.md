## 0. 怎么拆

规范驱动，再编码。

1. 每个模块先一条规范叶：只消费已有详设、USM、已评审原型，冻本版范围、空态、Mock 开关、发布后人验清单。详设仍是 v0.1 草案。规范叶完成 = 可派单，不是架构会签。
2. 一个菜单页 = 一条长任务：该页 Java 读接口 + 整页复刻 + 发布后人工走查。不把每个 REST 拆成一行。
3. 结束日当天收口后，下一条才动页面编码。两页不并行。
4. 供数或对端接口未到：该图层 / 该块空态，任务照排，不取消。
5. `USE_MOCK=false` 时不拿 fixture 填数。统计数字带 ⓘ；缺口用角标，不手改就绪度。
6. 每版末尾一条金路径（E），只点当时已经发布的页。

已有单收进本表，不另开一套：`FE-TS-S01`、`FE-TS-01A` 已认领，`BE-TS-CONTRACT-01` 待认领，都落在 DS-01。政策五张 `DS-POL-TRACK-*` 提案仍不入库。

日历含周末，长跑可过夜。

插队顺序（已确认）：统一用户 + DS-01 → 政策三页 + 核增四页 → 其余态势 → 成果、人才 → 资源、图谱、全景。同仓串行，所以后段会冲出开发出门日。冲出的叶照写，出门日不后移。
