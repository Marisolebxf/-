## 0. 规范怎么选（CMMI 3 不是唯一）

CMMI-DEV ML3 适合回答「组织有没有定义过程」。本项目更常要回答的是「生存周期做到哪、交付哪类文档、总集核什么」。并列可用、建议叠用如下，**不另起第二套目录编号**。

| 规范 | 适合什么 | 不太适合 | 对本项目 |
|---|---|---|---|
| **CMMI-DEV ML3** | 过程域分家：需求 / 设计 / 验证 / 确认 / CM | 不规定文档叫什么名字；甲方总集不一定认 CMMI 卷号 | 内部索引骨架（当前 `00`～`09`） |
| **GB/T 8566 ≈ ISO/IEC 12207** | 软件生存周期：需求→设计→构造→集成→测试→安装→维护 | 目录仍抽象 | 和招标「研制/试运行/验收」对阶段用语 |
| **GB/T 8567 文档编制** | 文档种类：SRS、概要/详细设计、测试计划、测试分析报告、用户手册… | 不是过程成熟度模型 | **总集核验包封面用这类名称**（总集最熟） |
| **IEEE 29119 / 1012** | 测试过程、V&V | 不管架构/需求全库 | 映射到索引卷 `05`/`06` 的写法 |
| **ISO/IEC 25010** | 质量特性（功能适合、性能、安全、可维护…） | 不是目录 | 验收结论维度，不建卷 |
| **SWEBOK** | 知识域教科书 | 弱于交付/总集 | 不采用为目录 |
| **ISO 9001** | 质量管理体系 | 过粗 | 不单独建卷 |
| **GJB 5000A** | 军工过程 | 本项目非军标强制则过重 | 除非合同要求，否则不采用 |
| **PMBOK / 政务「初设–详设–竣工验收」** | 计划与甲方阶段名 | 不管设计/测试工作产品分类 | 阶段名挂 `02`；竣工材料出 `06` |

**建议叠法（不换树）**

- 内部检索：继续用 CMMI 形状的 `00`～`09`（验证 ≠ 确认）。
- 对外/总集目录页：用 **GB/T 8567 文档名** 指向同一批现网文件。
- 阶段汇报：用 **8566/12207** 或合同阶段名（研制 / 试运行 / 总集核验）。

不另建「8567 物理树」与 CMMI 树并列，避免两套编号。

## 5. 铁律（本阶段）

1. **只索引、不搬家、不复制正文**（工作产品仍留现网路径）。**例外：** 卷 `02` 已升为计划夹，索引在 `02-策划与监控/INDEX.md`；计划正文只进该夹子目录，不搬 `project-plan` / WBS / Sprint。卷 `04` 的对接过程记录可生在 `04-系统集成/`，不搬回 `04-产品集成.md`。
2. 每个工作产品一个家 = 现网路径；本文件只允许链接。
3. 未会签详设在跟踪表标 `draft`；总集清单不得写成已基线。
4. 完成度措辞 PM 终审。
