# 多身份会签 · 审稿硬清单

真源：`agent-delivery/产品实现规程.md` §4.2.4。每个审稿身份开自己的会话，逐条回答本身份清单。**异议数为零的会签无效**：至少写出一条风险或一条需确认项；确实无问题时写明逐条核过的依据。

每条异议写成：`[身份] 编号 · 问题 · 依据（文件/行/铁律） · 建议`。起草身份逐条回 `采纳` 或 `驳回 + 理由`。

## product-agent

1. 需规原文每个分句是否都有功能点编号？
2. 每个功能点是否写了「界面上必须看见什么」，能否被截图验证？
3. 状态清单是否覆盖：未选、未命中、停用、无数据、失败？
4. 设计稿是否把功能点落到了某个区块、接口字段或表列？漏的点名。
5. 影响清单是否清零，旧口径是否已标「已被取代」？

## arch-agent

1. 调用链：前端 → Java → Python `/internal/*`，有无越层？
2. Java 读的是不是 ADS？读 ODS / DWD / 供应方库的，点名并标停机。
3. D12：lumen 是否调用任何 demo 服务？
4. 有无接口直接返回写死 mock（D18）？
5. 档位判断是否成立（轻 / 中 / 重）？

## data-agent

1. 每个界面值能落到哪张表、哪一列？给出库.表.列。
2. 该表现在有没有行？没有行时界面显示什么？
3. 是否需要新表、新列、新同步？新表落哪个库，是否触 D16 / D18？
4. 有无写 ODS / DWD / ADS / 供应方库的风险？

## api-agent

1. 界面每个条件是否对应一个请求参数（含多值）？
2. 响应能否给出每个功能点要看见的字段？缺的点名。
3. 同步还是 Job？空态返回什么（空数组，不造 0）？
4. 是否复用已有路径，避免新开平行资源？

## algorithm-agent

1. 本叶有没有统计数字？有则 `metric_id` 是谁、D4 是什么。
2. 是否新造了 `metric_id` 或改了 D4？
3. 有无把非本叶口径的指标挂过来？

## doc-agent

1. 说明书该叶的调用链、数据流、状态、界面区块是否都有图？图与正文是否一致？
2. 文末变更记录是否写了本次：日期、任务、改了什么、为什么、影响到哪？
3. 二级 DATA 稿出现的每张表、每列，在 `storage/{域}/stores/*.md` 是否已登记（新表标 draft），流图和 `etl/` 是否画到？
4. 说明书、DATA 稿、Storage 三处表名列名是否一致？域 `CHANGELOG.md` 是否记了一行？

## ux-agent / ui-agent

1. 控件是否用 Arco 同类组件，键盘可达、有无障碍语义？
2. 线框是否覆盖全部状态？
3. 与已冻结高保真差在哪，是否已升版本号？
