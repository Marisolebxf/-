# 展示系统 · 需规分句闭合（gkx-display-srs-cover）

输入一个**展示系统功能模块**，只读跑完「需规分句 → 界面必见物 → 契约 → 用例 → live」矩阵；有缺口且需人拍板时切 Plan。确认前**不改**说明书、四单、代码、注册表。

流程锚点：`产品实现规程.md` §4.2.0 / §4.2.3 / §4.2.5 / §6.4；`templates/fe-replica-visual-dod.md` R5；`gkx-fde-design-change`（确认后的完善链）。矩阵模板见同目录 [matrix-template.md](matrix-template.md)；模块解析见 [module-resolve.md](module-resolve.md)。

## 0. 触发与输入

| 用户说 | 动作 |
|---|---|
| `需规分句闭合：{模块}` / `形态覆盖：{模块}` / `对照需规：{模块}` | 本技能全流程 |
| 只点模块名且上下文是「严格对照需规」 | 同左 |
| 已有矩阵、说「按此计划开始」 | 跳到 §5 开工，不重审计 |

`{模块}` 可为：一级页（如「科创政策全景」）、二级 level5（如「政策重点比对」「政策动向跟踪」）、序号区间（如「213–218」）、DS 码（如「DS-10」）。歧义时按 [module-resolve.md](module-resolve.md) 列候选，**停问一次**再继续。

专题系统不在默认范围；用户点名专题后才扩。

## 1. 立刻停（只解释）

- 用户还在讨论「为什么缺图」，没有要跑闭合：只答根因，不建矩阵文件、不建单。
- 解析不到任何 SRS 叶子：列候选，等人选，不猜。
- 未获「按此计划开始」：不 `task-create`，不改说明书/四单/代码。

## 2. 自动审计（只读，可连续跑完）

按顺序收集，缺哪层写「还没有」，不编造。

| 步 | 读什么 | 产出列 |
|---|---|---|
| 2.1 需规 | `bid-reference/srs/02-科技信息展示系统/...` 该叶「需规功能描述」；按**分句**拆功能点 `{序号}-{n}` | 分句原文、界面必见物草案 |
| 2.2 说明书 | 模块 `agent-handoffs/**/sdd/` 对应行；无则「还没有」 | 设计是否写过该分句 |
| 2.3 二级四单 | `sdd/l2/{前缀}-ARCH/API/METRIC/DATA.md` | 读面/501/gapfill 是否覆盖 |
| 2.4 原型 | `repos/demo-ui-science` 对应页/弹窗（矩阵热力、图表、优缺点等） | 原型区块清单 |
| 2.5 live | `repos/lumen-ui-science-pc`（或该模块正式前端仓）；区分 `USE_MOCK=true` 与 `false` | live 有无区块；是否 mock 独有 |
| 2.6 用例 | `工程过程/04-系统集成/05-展示系统集成/合规演示用例/` 对应文件 | 是否只验字段、不验形态 |
| 2.7 任务 | MCP `task-query`（module/epic），禁止整读 `task-registry.yaml` | 相关单状态一句 |

填表：复制 [matrix-template.md](matrix-template.md) 结构，在聊天里给出完整矩阵（可同时写入 `agent-handoffs/{域}/sdd/简报/{日期}-{模块}-需规分句闭合.md`，**仅简报、不改说明书**）。

### 缺口归类（每行必标一类）

| 码 | 含义 | 默认下一跳 |
|---|---|---|
| G1 | 设计未写（ARCH/说明书无「界面必见」） | 需求 → FDE |
| G2 | 有设计但 live 砍了（仅 mock 有 / 改成别的形态） | 问题；若设计本就没收 → 改判 G1 |
| G3 | 验收盲区（实现/原型有，用例不验形态） | 补用例行；可并行轻改 |
| G4 | 数据/契约不够（无二维矩阵、无优缺点列等） | 中档 FDE：补读面或 gapfill |
| G5 | 需规歧义（「热力图」=矩阵还是地图） | **决策卡** → Plan |
| G6 | 已明确 501/空态且产品接受 | 记「有意空」，不派实现 |

形态关键词（分句命中则「界面必见」必须含形态，用例必须有形态期望）：`热力图` `雷达图` `柱状图` `趋势图` `时间轴` `三维地图` `对比表格和图表` `优缺点` `优势劣势` `PDF` `Word` `高亮` `变化统计`。

## 3. 人决策 → 切 Plan 模式

出现任一项时，**先** `SwitchMode` → `plan`（explanation 写清模块与卡点数），再在 Plan 里出决策卡；**不要**在 Agent 里直接改方案或开工：

1. 存在 G5（形态/口径歧义）
2. 同一分句 ≥2 种可行修法（如地图热力 vs 矩阵热力；优缺点挂 214 vs 217）
3. 建议档位中/重，或将触铁律（D12/D18/新表/改主键）
4. 用户输入是一级页且二级 >1，需人选「先跑哪几个二级」

决策卡格式（规程 §4.2.5）：

1. 背景一句：哪个 `{序号}-{n}`、卡在什么。
2. 选项 2–4 个：做法 / 影响层 / 代价 / 风险。
3. 推荐项第一并标「（推荐）」+ 一句理由。
4. 请人选：**可行（按推荐）** / **改用选项 N** / **先改计划** / **本次只出矩阵不修**。

无 G5、且缺口全是 G3 或已裁定的 G2 单路径时：可留在 Agent，直接出 §4 执行计划请确认，不必强切 Plan。

## 4. 一屏执行计划（确认前只读）

矩阵 + 决策结果齐后，按规程 §4.2.5 六块写一屏计划：

| 块 | 写什么 |
|---|---|
| 现在到哪 | 说明书/四单/实现/用例各一句 |
| 这次改什么 | 闭合哪些 `{序号}-{n}`；不扩 |
| 建议档位 | 轻/中/重 + 一句理由；重档写「退回定义规程」 |
| 将要跑的波次 | 只列真要跑的；已齐写「跳过」 |
| 预计会停下来问的 | 铁律/新表/口径；看不清写「跑起来才知道」 |
| 请确认 | 「按此计划开始」/「先改计划」/「本次只归档矩阵」 |

确认前禁止：改说明书、改四单、改代码、`task-create`。

## 5. 确认后的分流

| 人选 | 动作 |
|---|---|
| 按此计划开始 | G2 且设计已写清 → `bugfix` 派修；G1/G4/G5 已裁定 → 读 `gkx-fde-design-change`，建 FDE 总单并开 A 波次；G3 → 改合规用例形态期望（可与实现并行） |
| 先改计划 | 只改计划六块，不开工 |
| 本次只归档矩阵 | 只保留简报矩阵；不建单 |
| 停 | 计划作废 |

开工后停机条件仍遵守规程 §4.2.5；再停再出决策卡（可再切 Plan）。

## 6. 与邻技能边界

| 技能 | 关系 |
|---|---|
| `gkx-fde-design-change` | 本技能负责**发现与定方案**；人选「开始」后才进 FDE |
| `gkx-demo-sample-loop` | LOOP 验「有数可演」；本技能验「需规分句/形态有着落」。可先后跑，不互相替代 |
| `gkx-bug-record` | 仅当用户要求记缺陷台账时用；本技能默认出矩阵+计划 |

## 7. 不做

- 不替人选定形态（G5）或甲方口径
- 不把 mock 轨有、live 轨无当成「已实现」
- 不把「字段可演」当成「形态闭合」
- 不整读 `task-registry.yaml` / 指标 seed；任务与指标走 MCP
- 不在确认前推前端仓
