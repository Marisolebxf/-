# gkx-dev-process 打分与落盘

规约正文优先。这里只把快照要执行的表抄出来。

## 行怎么认

- 分组标题不是任务，不进平均的分母以外的「一行一任务」。它是一级工作包。
- 表里的数据行才是一行。自研文件里「排除对照」及之后不读。
- 从该行格子里提取任务号（如 `FE-TS-01A`、`CMS-JX-ENT-CRUD-L01`、`WBS-02-00` 不是任务号）。一行多个任务号：各算分后取平均，四舍五入到整数，作为该行完成百分比。
- 方案行（WBS 第一行「技术方案设计」）算设计类。
- `task-get` 的 `task_type`：`definition`、`tech_task` 用设计分；`feature`、`bugfix` 用开发分；`chore` 不进入百分比。没有 `task_type` 的方案行用设计分。
- 没有任务号的开发行记 0，并计入开发进度的平均。方案任务未 `done` 时同样记 0。已经有任务号的存量叶照下表打，不回退成 0。
- `blocked`：该维 `进度.md` 里上一份已写下的分沿用，不改成 0，也不改成 100。没有上一份时，按证据用下表打一档（结果不会是 0 或 100 的，就用表内档），工作结果写「blocked，无上一份快照」。

## 设计分

| 见到的情况 | 分 |
|---|---|
| 未建任务，或 `backlog` / `ready` | 0 |
| `claimed`，产物还没有 | 10 |
| `in_progress` / `needs-revision` | 10 + 40 ×（已落盘且规定章节都在的产物数 ÷ DoD 点名的产物数）。一个产物都没有，就是 10 |
| `integration`，handoff 章节齐 | 60。章节不齐，停在 40 |
| `ready_to_sign` 或 legacy `review`，evidence 已有 | 90。evidence 没有，停在 60 |
| `done` | 100。没有签收记录，停在 90 |

## 开发分

| 见到的情况 | 分 |
|---|---|
| 未建任务，或 `backlog` / `ready` | 0 |
| `claimed`，或 `in_progress` 但 evidence、`touched_files`、handoff 都空 | 10 |
| `in_progress` / `needs-revision`，且上面三项至少有一项 | 10 + 30 ×（DoD 里能在 handoff 或 evidence 对上的条数 ÷ DoD 条数）。DoD 为空则停在 10 |
| 状态已到 `integration` 及以后，但 `note` 没有联调确认词 | 最高 40 |
| `integration` 且有联调确认词 | 60 |
| `pending_test` | 70 |
| `testing` | 80 |
| `ready_to_sign` / legacy `review` | 90 |
| `done` 且 evidence 已有 | 100。`done` 但没有 evidence，停在 90 |

联调确认词：`联调通过` / `联调完成` / `联调确认` / `会签通过` / `会签完成` / `集成测试通过`。

状态写得比证据靠前时，用较低的那一档。

## 整体百分比

- 设计进度 = 其下设计类行设计分的平均。一条都没有时，用该维方案行的设计分。
- 开发进度 = 其下开发类行开发分的平均。没有开发行：整体 = 设计进度。
- 整体 = 设计进度 × 30% + 开发进度 × 70%，四舍五入到整数。
- 第 2 至第 7 项：每个一级工作包、每个维度都算。
- 领导简报里第 1 项同样算。今日快照的维度合成只含第 2 至第 7 项；自研行若出现在当日八列表，只带出任务状态和口令，不把自研卷进对接维度的 30/70。

## 当日进展八列

`agent-delivery/工程过程/当日进展/YYYY-MM-DD.md`

按 `supervised_by` 分节。一个人名下再按对接维度分块。

| 列 | 填法 |
|---|---|
| 负责人 | `supervised_by`。格里没有监管人的写「待指定」，不从邻行抄 |
| 任务内容 | 任务标题或 WBS 子项一句 |
| 完成时间 | `note` 里的「完成日期要求」。没有就空 |
| 完成状态 | `done` 且有发布证据→完成；`done` 无发布证据→任务关闭，未见发布；`in_progress` / `claimed` / `testing`→进行中；`ready_to_sign`→待签收；`blocked` 或口令声明未到位→阻塞 |
| 当日任务 | 监管人说了「今日做」用原话，否则用标题 |
| 当日进展 | 当天口令原话。没说写「今日未报」 |
| 测试情况 | 口令里的测试句。没有写「未见测试记录」 |
| 其他备注 | 方案、流水、发布证据、阻塞原因的仓内链接 |

每个对接维度和每个一级工作包在文末各加一行：设计、开发、整体、阻塞行数。

## Excel 列（两份导出共用）

在 2026-10-22 调查表的列上增加「WBS」「工作细项任务号」「任务说明」「任务状态」。一行一个实现任务。

工作项、工作目标、子目标、WBS、工作细项任务号、任务说明、任务状态、智谱/智树负责人、智谱/智树工作内容、涉及指标多少项、对端工作、对端负责人、截止时间、完成百分比、已实现指标多少项、实现风险系数（1-10）、工作细项目标、工作结果。

### 收哪些任务

本端实现任务都进表。定义轨不进表。

- 定义轨：`delivery_phase` 是 `definition`，或 `task_type` 是 `definition`。方案任务、回写定义单、调研如果落在这两类里，不进表。
- 其余都进：`implementation`、`crosscut`，以及 `feature` / `bugfix` / `tech_task` / `spike` / `chore` 里不属于定义轨的。`chore` 进表，不进 §7.1 百分比，完成百分比留空。
- 只认注册表里已有的任务。WBS 上写了「智谱」「待指定」但没有任务号的行，不是本端任务，不进表。
- 不读 `task-registry.yaml`。用 MCP `task-query` 按状态分批把 `limit` 放到能收回该状态，再丢掉定义轨。WBS 上已写明的任务号用 `task-get`。

### 列

| 列 | 填法 |
|---|---|
| 工作项 | 七个短名，同一短名合并。第 1 项只写「自研模块」，不写「第 1 项 自研模块」，也不拆成展示自研、专题四要素、算法、自研收口。第 2 至第 7 项依次是：对接三要素、专题系统集成、门户系统集成、展示系统集成、GDF 数据治理集成、图数据库集成。挂在第 2–7 项某份 `WBS.md` 上的任务归进对应短名。出现在 [`01-自研模块WBS.md`](../../../agent-delivery/工程过程/02-策划与监控/02-智树工作计划/02-进度/01-自研模块WBS.md) 实现行、或没有挂上第 2–7 项草案号的本端实现任务，一律归进「自研模块」。排除对照里已写明归第 2–7 项的，不重复归进自研模块 |
| WBS | 挂上第 2–7 项：草案号，如 `WBS-03-10`，同一草案号合并。归进「自研模块」且没有草案号：填 `bid-reference/srs/` 下的目录，去掉文件名，例如 `04-科技专题服务系统/科技专题内容运营中心/基础数据管理`，同一目录在自研模块内再合并。路径只认任务的 `design_refs`、`touched_files`、`note` 里已经写明的 srs 路径。没有路径时，只对照 [srs/INDEX.md](../../../agent-delivery/bid-reference/srs/INDEX.md) 的八个系统目录，能对上系统就填系统目录，不再猜页签。对不上写「SRS 未挂上」 |
| 工作细项任务号 | 一行一个任务号。同一草案号拆出的多个任务号分行写，不写进同一格 |
| 任务说明 | 注册表 `title`。没有标题就空着。放在任务状态前面 |
| 任务状态 | 注册表 `status` 原文 |
| 完成百分比 | 该任务自己的开发分。定义轨不在表里。挂在 WBS 上、但因方案未 `done` 记 0 的新开发任务，这里仍记 0 |
| 截止时间 | 只填 `note` 的「完成日期要求」 |
| 工作细项目标 | 原文保留。`note` 有「开始时间」时，放在该格第一句 `开始时间：YYYY-MM-DD` |
| 涉及指标多少项、已实现指标多少项、实现风险系数 | 留空 |
| 工作结果 | 任务状态原文。第 2 至第 7 项每个工作项的首行再写该项整体百分比，只来自该维 WBS 的 §7.1，不把归进「自研模块」的任务卷进去。领导简报里「自研模块」首行另写第 1 项整体百分比，分母只算 `01-自研模块WBS.md` 的实现行，不算仅靠 SRS 归进来的任务。今日快照不给「自研模块」写整体百分比 |

分 sheet：第一个 sheet 名「自研模块」，只放归进自研模块的行。后面六个 sheet 按顺序各放一项，sheet 名用短名：对接三要素、专题系统集成、门户系统集成、展示系统集成、GDF 数据治理集成、图数据库集成。列在每个 sheet 相同。

合并：每个 sheet 内，连续相同的工作项、工作目标、WBS 各自合并。工作细项任务号、任务说明、任务状态不合并。不覆盖 2026-10-22 的调查表。用仓内已能调用的 openpyxl 写 xlsx。
