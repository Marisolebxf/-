# PLAN.md

## Current Version

v0.1

## Goal

建立跨模块、跨会话可复用的“产品定义文档 → Demo 实现 → 可验证验收证据”自动闭环。Skill 接收任意模块标识或定义包路径；定义包冻结后由 AI 自动建立覆盖契约、实施 Demo、运行验证并输出遗漏清单，减少状态、字段、交互或边界的大面积遗漏。E-31 企业发展仅作为首个运行实例。

## Non-goals

- 不替代 IA、TRACE、USM、Wireframe 的既有职责。
- 不把 E1 企业查询作为改造对象；它仅作为已完成人工核对的参考样本。
- 不以增加人工评审轮次作为唯一解决方案。

## Core Mechanism

创建一个可跨会话调用的“定义包驱动 Demo 交付”Skill。它从 IA、TRACE、USM、Wireframe（及必要的产品决策）生成机器可读的实施覆盖契约；每个验收项绑定来源、页面状态、代码/路由位置、自动检查或截图证据、负责人和未实现状态。该契约复用《角色AI协作对比手册》的职责边界：UI 自检与截图基线、前端复刻与代码检查、QA 持续验收、coordinator DoD/交接门禁。

## Workflow

候选流程为“定义包冻结 → Skill 生成覆盖契约与实现任务 → 按页面包/文件集形成 Convoy → Agent 在独立 worktree 实施 Demo → 自动检查 + 预览截图 → Skill 输出覆盖/遗漏报告与 handoff → QA/UE 仅处理无法自动判定项 → coordinator 依据报告决定 review/done”。同一文件集仅允许一个写入 Agent；仅无交叉文件集的 Convoy 才并行。

## Outputs

- 实现覆盖清单规范与模板
- 任意模块的覆盖契约与实施/遗漏报告（E-31 为首个实例）
- 可跨会话调用的个人 Skill
- 持久化覆盖契约、handoff 与 Convoy/文件集清单，使新会话无需依赖聊天历史
- 任务 DoD、静态检查和视觉验收的接入规则

## Current Risks

- 契约过粗会继续遗漏；过细会成为重复维护。
- 自动检查只能覆盖可判定行为，不能替代视觉和语义验收。
- 若不绑定任务 DoD、任务认领和验收门，契约会再次沦为说明文档。
- 若按需求条目盲目并发而不按文件集隔离，会产生覆盖冲突或验证结果不可归因。
