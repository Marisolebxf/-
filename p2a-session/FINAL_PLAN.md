# FINAL_PLAN.md

## 任务定义与边界

创建通用个人 Skill `$gkx-definition-to-demo`，让任意已冻结模块的 IA、TRACE、USM、Wireframe 与已确认决策驱动 Demo 实施和验证。Skill 不绑定具体需求编号；E-31 仅为后续首个运行实例。

## 目标与非目标

- 目标：降低页面、字段、状态、交互、边界与证据遗漏；让新会话从持久化产物续跑。
- 非目标：替代产品/UE对语义、视觉取舍和业务范围的最终判断；重写上游定义包。

## 关键决策

- 冻结时生成覆盖契约，定义或实现变更后增量更新。
- 可机器判断的 P0 缺失、冲突、构建/检查失败必须阻断。
- 默认自动实施；仅在 P0 定义问题、范围变化、文件集冲突或人工语义/视觉判断时暂停。
- 同一文件集单写入；无交叉文件集可在独立 worktree 并行。
- 使用 `$gkx-task-claim-supervision` 的登记规则管理新建、认领、交接和释放任务。

## 执行路径

1. 输入 `{module-id}` 或 `{definition-package-path}`，自动发现定义包、任务、Demo 仓库和现有实现。
2. 检查冻结条件并生成机器可读的 `implementation-coverage.yaml`：每项含来源、需求、状态、交互、字段、代码位置、验证、证据与排除项。
3. 根据实现文件集形成 Convoy；创建或更新任务与 worktree。
4. 实施 Demo，逐项回写实现位置和验证结果。
5. 运行静态/行为检查、构建、可访问预览和关键截图。
6. 输出覆盖率、遗漏、待人工判断项与 handoff；仅满足门禁时推进任务状态。

## 风险与开放项

- 文档间冲突和未关闭 P0 开放项将暂停自动实施。
- 视觉质量仍需要人工会签；首版以关键截图作为持久化证据。
- 首个实例的模块路径、截图工具和完整录屏承载可在运行时发现或补充。

## 下一步

由 Codex 创建并验证 Skill；之后用户用 `$gkx-definition-to-demo {模块ID或定义包路径}` 启动任意模块的覆盖驱动交付。
